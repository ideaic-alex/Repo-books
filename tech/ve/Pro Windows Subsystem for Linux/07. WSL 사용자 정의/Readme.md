# 7장. WSL 사용자 정의 (Customizing WSL)

WSL의 구조와 기본 설정을 익혔다면 이제 용도에 맞게 직접 손볼 차례다. 이 장은 리눅스 GUI 앱을 Windows 화면에 띄우는 방법과, 전통적인 init이 없는 WSL에서 서비스를 자동으로 시작하는 여러 방법을 다룬다.

---

## 1. 핵심 요점

- 공식 GUI 지원(WSLg)은 아직 프리뷰 단계다. 당분간은 Windows에 서드파티 X 서버를 설치하고, 그쪽으로 화면을 보내는 방식을 쓴다.
- WSL 1과 WSL 2는 `DISPLAY` 값이 다르다. WSL 2는 호스트 Windows의 IP로 화면을 보내야 하고, 방화벽도 열어 줘야 한다.
- 방화벽을 열 때는 포트 6000과 WSL 가상 서브넷으로 범위를 좁혀서, 외부에 노출되는 부분을 줄인다.
- WSL에는 서비스를 시작해 주는 전통적인 init이 없다. 그래서 셸 스크립트, Windows 서비스, 작업 스케줄러, `[boot]` 명령 중 하나로 그 역할을 대신한다.
- 서비스 시작 스크립트에는 중복 실행 방지와 `sudoers` 예외 등록이 필요하다.
