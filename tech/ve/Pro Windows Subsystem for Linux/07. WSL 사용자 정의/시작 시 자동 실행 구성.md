# 시작 시 자동 실행 구성

WSL에는 SysVinit, systemd, OpenRC 같은 전통적 init이 없다. WSL 자체의 init은 Windows 상호운용, 파일 공유, 네트워킹 같은 기본 작업만 맡고 서비스를 시작해 주지 않는다. WSL을 열 때마다 서비스를 띄우려면 셸 스크립트나 Windows 쪽 도구를 써야 한다. 이 문서는 셸 기반 방법을 다룬다.

---

## 1. .bashrc 활용

- **.bashrc**: Bash가 새 창을 열 때마다 실행하는 파일이다. 기존 배포판 설정 아래에 필요한 내용을 덧붙이면 되며 `DISPLAY` 같은 환경 변수 설정에 알맞다.
- 위치는 홈 폴더(`~/.bashrc`)이고 `nano ~/.bashrc`로 편집한다.
- Bash 전용이므로 fish, zsh, csh, ksh 등으로 바꾸면 각 셸의 설정 파일에 따로 적어야 한다.
- 사용자별 파일이므로 `wsl.exe -u`나 기본 사용자 변경으로 다른 사용자가 되면 그 사용자의 `.bashrc`에도 넣어야 한다.

---

## 2. 모든 사용자에게 적용

- **/etc/profile.d/**: 여기에 스크립트를 두면 모든 사용자에게 적용된다. 셔뱅(shebang)을 쓰고 `chmod`로 실행 권한을 줘야 한다.
- 이 스크립트는 터미널에서 띄운 대화형(interactive) 셸에서만 실행된다. VS Code WSL 원격 확장처럼 백그라운드로 띄울 때는 실행되지 않는다.
- 그런 경우 내용을 `/etc/bash.bashrc`에 넣고, Windows 환경 변수 `WSLENV`에 `BASH_ENV/u`를 지정해 매번 읽게 한다.
- fish 같은 비 POSIX 셸은 위 파일들을 읽지 않을 수 있으므로 해당 셸 문서를 따른다.

```bash
# /etc/profile.d/displayvar.sh 예시
#!/bin/bash
export DISPLAY=$(awk '/nameserver / {print $2; exit}' /etc/resolv.conf 2>/dev/null):0
export LIBGL_ALWAYS_INDIRECT=1
```

---

## 3. 서비스 중복 실행 방지

- 백그라운드 서비스를 시작하는 스크립트는 터미널을 열 때마다 실행되므로 중복 실행이나 멈춤이 생길 수 있다.
- 따라서 `pgrep`으로 프로세스가 이미 도는지 확인한 뒤 없을 때만 시작하도록 쓴다.
- 전통적인 `/etc/init.d/` 스크립트는 WSL에서도 유용하다. `service` 명령은 systemd 전용이 아니라 필요하면 init.d 스크립트를 호출하는 도우미라서 WSL에서도 동작한다.

---

## 4. sudoers 예외 등록

- 스크립트가 `sudo`를 부르면 매 실행마다 암호를 묻는다. 특정 명령만 암호 없이 허용하도록 `sudoers`에 예외를 추가한다.
- **visudo**: `sudoers`는 반드시 `sudo visudo`로만 편집한다. 다른 편집기로 직접 고치면 설정이 깨져 배포판을 초기화해야 하거나 데이터를 잃을 수 있다. Ubuntu에서는 기본 편집기가 nano다.

```
ALL ALL=NOPASSWD: /etc/init.d/dbus start
```

---

## 5. Windows 10 빌드 21286 이상의 boot 명령

- `/etc/wsl.conf`의 `[boot]` 명령으로 시작 명령을 등록할 수 있고, root 권한으로 실행된다.
- 최소한의 init처럼 쓸 수 있지만 WSL 배포판을 터미널로 열 때만 동작한다. 예약 작업이나 Windows 서비스처럼 백그라운드에서 자동으로 시작하지는 않는다.
- `.bashrc`에 넣기엔 복잡한 서비스 실행에 적합하다. 옵션 상세는 5장(WSL 배포판 구성)에 있다.
