# WSL 1과 WSL 2 비교

두 버전은 구조가 전혀 달라 장단점도 갈린다. 이 문서는 지원 Windows 버전, 각 버전을 고를 이유, 네트워크 차이를 비교 기준으로 정리한다.

---

## 1. 구조 요약

| 항목 | WSL 1 | WSL 2 |
|---|---|---|
| 방식 | 리눅스 바이너리 변환 계층 | Hyper-V 기반 경량 가상화 + 실제 리눅스 커널 |
| 파일·포트 처리 | NT 커널이 직접 처리 | 리눅스 커널이 가상 장치와 상호작용 |
| 네트워크 | 호스트 Windows 설정을 그대로 사용 | 가상 환경 안의 NAT 네트워크 |
| 커널 교체 | 불가 | 직접 빌드한 커널 사용 가능 |

---

## 2. 지원 Windows 버전

- **WSL 1**: 더 많은 Windows 10 버전과 Windows Server 2019에서 쓸 수 있다. Windows 10 1709~1809에서는 유일한 선택지다.
- **WSL 2**: Windows 10 1903(2019년 5월판)에 최신 업데이트가 적용된 빌드 18362.1049 이상에서 쓸 수 있다. 원래 2004 버전에서 출시됐고 이후 1903으로 백포트됐다. 저자는 해당 버전 이상이면 WSL 2를 써 보라고 권한다.

---

## 3. WSL 1을 고를 이유

- **낮은 시스템 오버헤드(overhead)**: Surface Go처럼 자원이 적고 성능보다 전력 소모가 중요한 기기에 어울린다.
- **단순한 네트워크**: 호스트 Windows의 네트워크 구성을 그대로 따른다.
- **폭넓은 앱 호환성**: 여전히 쓸 만한 선택지지만, 새 기능이 추가될 예정은 없다.

---

## 4. WSL 2를 고를 이유

- **필수 요구**: Docker나 microk8s 같은 앱이 WSL 2를 요구한다.
- **성능**: WSL 1보다 상당히 빠르다.
- **커스텀 커널**: 기본 커널에 없는 기능이 필요하면 직접 컴파일해 실행할 수 있다.

---

## 5. 네트워크 차이와 주의점

- **NAT(Network Address Translation)**: WSL 2의 각 배포판은 자기 IP 주소를 가지며, 이는 실행 중인 Windows 기기에서만 접근된다. 밖으로 나가는 연결은 Windows 기기에서 온 것처럼 변환된다.
- WSL 2는 가상 환경 안에 NAT 네트워크 전체를 구현하므로, 다른 기기에서 WSL 2 서비스에 접속하려면 추가 설정이 필요하다.
- WSL 1에서 WSL 2로 이전하거나 배포를 계획할 때 이 점을 미리 고려해야 한다.
