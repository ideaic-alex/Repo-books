# 1장. WSL 아키텍처 (WSL Architecture)

WSL을 제대로 활용하거나 회사 환경에 배포하려면 내부 구조와 개발 배경을 알아 두어야 한다. 이 장은 WSL 1과 WSL 2가 각각 어떤 방식으로 리눅스와 Windows를 함께 동작하게 만드는지 설명한다. 그다음 앞으로 추가될 GPU, GUI 같은 최신 기능까지 살펴본다.

---

## 1. 이 장의 핵심 요점

- **WSL 1**: 피코 프로세스(pico process)와 `LxCore.sys`가 리눅스 시스템 콜을 NT 시스템 콜로 바꿔 준다. 리눅스 프로그램과의 호환성은 약 90%다.
- **WSL 2**: Hyper-V 기반 경량 가상화 환경에서 실제 리눅스 커널이 동작한다. 그래서 시스템 콜 호환성 문제가 사라진다.
- **가상 장치**: WSL 2는 Hyper-V 가상 블록 장치와 가상 어댑터로 파일과 네트워크를 처리한다.
- **선택 기준**: WSL 1은 오버헤드가 낮고 네트워크가 단순하다는 점이 장점이다. WSL 2는 성능이 좋고 Docker 등과 호환되며 커널을 직접 바꿀 수 있다는 점이 장점이다.
- **GPU 컴퓨트**: `/dev/dxgkrnl`을 통한 준가상화 GPU로 DirectML, Direct3D, CUDA 등을 지원한다.
- **GUI와 오디오**: Wayland 컴포지터, RDP, PulseAudio를 바탕으로 한 공식 지원이 예고되어 있다.
