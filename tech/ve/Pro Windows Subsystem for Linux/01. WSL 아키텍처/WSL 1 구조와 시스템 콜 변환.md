# WSL 1 구조와 시스템 콜 변환

WSL 1은 리눅스 커널을 싣지 않는다. 대신 리눅스 프로그램이 보내는 요청을 Windows NT 커널이 이해하는 형태로 바꿔 준다. 이 문서는 WSL 1을 이루는 드라이버, 프로세스, 서비스와 시스템 콜 처리 흐름을 정리한다.

---

## 1. 커널 드라이버

- **Lxss.sys**: 부팅 초기에 먼저 로드되는 스텁(stub) 드라이버다.
- **LxCore.sys**: 부팅 후반에 로드되는 실제 WSL 드라이버다. 리눅스 환경을 흉내 내고 시스템 콜 변환을 맡는다.
- WSL을 켜면 이 두 NT 커널 드라이버가 Windows 10에 함께 올라온다.

---

## 2. 피코 프로세스와 LxssManager

- **피코 프로세스(pico process)**: Windows 사용자 공간에 만들어지는 가벼운 가상 공간이다. 리눅스 앱은 이 안에서 실행되며, 자신이 Windows 위에서 돌고 있다는 사실을 알지 못한다.
- **피코 제공자(pico provider)**: LxCore.sys가 이 역할을 한다. 피코 프로세스 안에서 리눅스 환경처럼 동작하게 해 준다.
- 같은 기술이 다른 곳에도 쓰였다. Windows 10 IoT는 이 기술로 옛 Windows CE 앱을 실행하고, 반대로 SQL Server를 리눅스로 옮기는 데도 활용했다.
- **LxssManager**: LxCore.sys 앞에서 중개자(broker) 역할을 하는 Windows 서비스다. 리눅스 바이너리를 실행하라는 NT 호출을 LxCore.sys로 넘긴다. 또 WSL 사용자 상태를 감시하고, 배포판을 설치하거나 제거하는 작업이 매끄럽게 진행되도록 돕는다.

---

## 3. 시스템 콜 변환

- **시스템 콜(system call)**: 컴파일된 프로그램이 커널에 메모리 할당, 파일 열기, 장치 읽기 같은 일을 요청하는 저수준 호출이다.
- 리눅스 앱이 어떤 시스템 콜을 호출하는지 직접 보려면 `strace`를 쓴다.

```bash
sudo apt install strace -y
strace -o output.txt echo 'hello world'
cat output.txt
```

- 단순한 `echo` 명령만 실행해도 실행 파일 로드, 파일 열기, 메모리 할당, 콘솔 출력 같은 호출이 여러 번 일어난다.
- **두 커널의 배경**: 리눅스(1991년, 리누스 토르발스)와 NT(1993년, 데이비드 커틀러 팀)는 구현 방식이 다르다. 그래도 둘 다 1990년대 초중반의 비슷한 운영체제 이론과 흐름에서 영향을 받았다. 둘 다 원래 POSIX 호환을 염두에 두고 만들었고, 특권 모드와 비특권 모드를 구분한다. 이런 공통점 덕분에 시스템 콜을 서로 바꿔 줄 수 있다.

---

## 4. 변환의 세 가지 경우

리눅스 시스템 콜을 NT에서 처리하는 방식은 NT 쪽에 대응하는 호출이 있느냐에 따라 세 가지로 나뉜다.

1. **1대1로 대응하는 호출이 있는 경우**: LxCore.sys가 리눅스 호출을 NT 커널에 그대로 넘긴다.
2. **비슷한 NT 호출이 있는 경우**: 호출 순서나 구조를 재배열해서 NT 호출로 바꾼다.
3. **대응하는 호출이 없는 경우**: LxCore가 직접 처리한다. 이때는 리눅스 커널 코드를 쓰지 않고 처음부터 새로 구현한다(클린룸, clean room 방식).

- 모든 리눅스 시스템 콜이 구현된 것은 아니다. 아주 특이한 일부 호출은 앞으로도 구현되지 않는다.
- WSL 1의 바이너리 호환성은 약 90% 수준이다. 개발 초기에는 Linux Test Project로 호환성을 검증했다.
