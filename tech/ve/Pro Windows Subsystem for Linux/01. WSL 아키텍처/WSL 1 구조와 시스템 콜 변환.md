# WSL 1 구조와 시스템 콜 변환

WSL 1은 리눅스 커널을 싣지 않고, 리눅스 프로그램이 내보내는 요청을 Windows NT 커널이 이해하는 형태로 바꿔 주는 방식으로 동작한다. 이 문서는 WSL 1을 이루는 드라이버, 프로세스, 서비스와 시스템 콜 처리 흐름을 정리한다.

---

## 1. 커널 드라이버

- **Lxss.sys**: 부팅 초기에 먼저 로드되는 스텁(stub) 드라이버.
- **LxCore.sys**: 부팅 후반에 로드되는 실제 WSL 드라이버. 리눅스 환경을 흉내 내고 시스템 콜 변환을 맡는다.
- WSL을 켜면 이 두 NT 커널 드라이버가 Windows 10에 함께 올라온다.

---

## 2. 피코 프로세스와 LxssManager

- **피코 프로세스(pico process)**: Windows 사용자 공간에 만들어지는 가벼운 가상 공간. 리눅스 앱은 이 안에서 실행되며 자신이 Windows 위에 있다는 사실을 알지 못한다.
- **피코 제공자(pico provider)**: LxCore.sys가 이 역할을 하며 피코 프로세스 안에 리눅스 환경을 시뮬레이션한다.
- 같은 기술이 다른 곳에도 쓰인다. Windows 10 IoT가 옛 Windows CE 앱을 돌리는 데, 거꾸로 SQL Server를 리눅스로 옮기는 데 활용됐다.
- **LxssManager**: Windows 서비스로서 LxCore.sys 앞의 중개자(broker) 역할을 한다. 리눅스 바이너리를 실행하라는 NT 호출을 LxCore.sys로 보내고, WSL 사용자 상태를 감시하며 배포판 설치·제거를 매끄럽게 돕는다.

---

## 3. 시스템 콜 변환

- **시스템 콜(system call)**: 컴파일된 프로그램이 커널에 메모리 할당, 파일 열기, 장치 읽기 같은 일을 요청하는 저수준 호출.
- 리눅스 앱이 호출하는 시스템 콜을 직접 보려면 `strace`를 쓴다.

```bash
sudo apt install strace -y
strace -o output.txt echo 'hello world'
cat output.txt
```

- 단순한 `echo`만 해도 실행 파일 로드, 파일 열기, 메모리 할당, 콘솔 출력 같은 호출이 발생한다.
- **두 커널의 배경**: 리눅스(1991, 리누스 토르발스)와 NT(1993, 데이비드 커틀러 팀)는 구현은 달라도 1990년대 초중반의 비슷한 운영체제 이론과 흐름에서 영향을 받았다. 둘 다 원래 POSIX 호환을 염두에 뒀고, 특권 모드와 비특권 모드를 구분한다.

---

## 4. 변환의 세 가지 경우

1. **1대1 대응이 있는 경우**: 리눅스 호출을 LxCore.sys가 NT 커널로 그대로 전달한다.
2. **비슷한 NT 호출이 있는 경우**: 호출의 순서나 구조를 재배열해 NT 호출로 바꾼다.
3. **대응물이 없는 경우**: LxCore가 직접 처리한다. 리눅스 커널 코드를 쓰지 않은 클린룸(clean room) 구현이다.

- 모든 리눅스 시스템 콜이 구현된 것은 아니며, 아주 특이한 일부는 앞으로도 구현되지 않는다.
- WSL 1의 바이너리 호환성은 약 90% 수준이며, 개발 초기에는 Linux Test Project로 호환성을 검증했다.
