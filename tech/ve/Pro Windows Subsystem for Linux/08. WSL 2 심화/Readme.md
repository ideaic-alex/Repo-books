# 8장. WSL 2 심화 (Going Further with WSL 2)

GUI 앱과 자동 시작 서비스까지 갖췄다면 WSL 2로 한 단계 더 깊은 작업을 할 수 있다. 이 장은 systemd 실행, 커널 직접 빌드, 중첩 가상화(KVM)와 QEMU로 다른 운영체제 띄우기, WSL 2 고급 네트워킹을 다룬다. 리눅스를 어느 정도 알고 있으면 따라가기 수월하다.

---

## 1. 핵심 요점

- WSL은 systemd를 기본으로 지원하지 않는다. systemd는 PID 1로 실행되어야 하므로, 별도의 프로세스 네임스페이스를 만들어 그 안에서 실행하는 방법으로 우회한다.
- Microsoft가 공개한 WSL 2 커널 소스를 받아 설정을 바꿔 다시 빌드하고 `.wslconfig`에 지정하면 직접 만든 커널을 쓸 수 있다.
- KVM을 커널 모듈로 빌드하면 중첩 가상화를 쓸 수 있다. 그 위에서 minikube나 QEMU 게스트 OS를 실행할 수 있다.
- WSL 2는 자체 NAT 서브넷의 IP를 쓰므로, 외부(LAN)에서 접근하려면 포트 프록시와 방화벽 규칙이 필요하다.
- WSL 2의 IP는 실행할 때마다 바뀌므로 포트 포워딩 설정은 자동화해야 한다.
