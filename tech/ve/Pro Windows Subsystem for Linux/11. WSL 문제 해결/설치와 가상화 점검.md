# 설치와 가상화 점검

WSL을 켜거나 배포판을 설치하다가 막혔을 때 순서대로 확인할 항목을 정리한다. 원인은 대부분 네 가지 중 하나다. Windows 기능이 꺼져 있거나, 보안 프로그램이 막고 있거나, 배포판 런처가 오래되었거나, 가상화를 지원하지 않는 환경이다.

---

## 1. Windows 선택 기능 확인

- **필요한 두 기능(Optional Features)**: Virtual Machine Platform과 Windows Subsystem for Linux가 필요하다. 두 기능이 모두 켜져 있어야 WSL 1과 WSL 2를 다 쓸 수 있다.
- **GUI로 켜는 방법**: "Windows 기능 켜기/끄기" 대화상자에서 두 항목에 체크한다.
- **PowerShell로 켜는 방법**: 관리자 권한으로 PowerShell을 열고 아래 두 명령을 실행한다. 대화상자를 거치지 않아서 가장 빠르다.

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux
```

- **관리자 권한으로 여는 요령**: 시작 메뉴에서 powershell을 검색한 뒤 "관리자 권한으로 실행"을 선택한다.

---

## 2. 보안 프로그램 확인

- **차단되는 구성요소(Blocked components)**: 일부 서드파티 백신은 WSL이 꼭 필요로 하는 `lxcore`와 `lxsys`에 접근하지 못하게 막는다.
- **조치(Action)**: 이 두 구성요소가 차단되었는지 확인한다. 차단되어 있다면 백신의 허용 목록(Allow-list)에 추가한다.

---

## 3. 배포판을 최신 상태로 유지

- **런처(Launcher)**: Microsoft Store에서 내려받는 것이 배포판 런처다. 따라서 이 런처가 최신인지 확인해 두는 것이 좋다.
- **방법(How)**: 해당 배포판의 Store 페이지에서, 설치되어 있지 않으면 Install을 누르고 업데이트가 있으면 Update를 누른다. Store의 "다운로드 및 업데이트" 페이지에서도 확인할 수 있다.

---

## 4. 가상화 제약

- **가상 머신 안의 Windows(Nested case)**: VirtualBox 같은 프로그램으로 만든 가상 머신 안에서 Windows를 실행하는 경우다. 이때는 가상화 플랫폼이 중첩 가상화(nested virtualization)를 지원해서 그 Windows에 노출해 주어야만 WSL 2가 실행된다.
- **WSL 1은 예외**: WSL 1은 하드웨어 가상화 기술(Intel의 VT-x, AMD의 SVM)에 의존하지 않는다. 그래서 같은 환경에서도 쓸 수 있는 경우가 있다.
- **정리(Rule of thumb)**: 가상 머신 위에서 WSL 2가 안 되면 먼저 중첩 가상화가 노출되는지 확인한다. 노출할 수 없다면 WSL 1을 대안으로 고려한다.
