# 설치와 가상화 점검

WSL을 켜거나 배포판을 설치하는 단계에서 막힐 때 순서대로 확인할 항목을 정리한다. 대부분은 Windows 기능 활성화, 보안 프로그램, 배포판 런처 상태, 가상화 지원 여부의 네 가지로 압축된다.

---

## 1. Windows 선택 기능 확인

- **필요한 두 기능(Optional Features)**: Virtual Machine Platform과 Windows Subsystem for Linux. 둘 다 켜져 있어야 WSL 1과 2를 모두 쓸 수 있다.
- **GUI 방법**: "Windows 기능 켜기/끄기" 대화상자에서 체크한다.
- **PowerShell 방법**: 관리자 권한으로 PowerShell을 열고 아래 두 명령을 실행한다. 메뉴를 거치지 않아 가장 빠르다.

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux
```

- **관리자 실행 요령**: 시작 메뉴에서 powershell을 검색한 뒤 "관리자 권한으로 실행"을 고른다.

---

## 2. 보안 애플리케이션 확인

- **차단 대상(Blocked components)**: 일부 서드파티 백신은 WSL이 필수로 쓰는 `lxcore`와 `lxsys`에 대한 접근을 막는다.
- **조치(Action)**: 해당 구성요소가 차단되지 않았는지 보고, 필요하면 백신의 허용 목록(Allow-list)에 추가한다.

---

## 3. 배포판 최신 상태 유지

- **런처(Launcher)**: Microsoft Store에서 내려받는 것이 배포판 런처이므로, 이것이 최신인지 확인하는 것이 좋다.
- **방법(How)**: 해당 배포판의 Store 페이지에서 설치되어 있지 않으면 Install, 업데이트가 있으면 Update를 누른다. Store의 "다운로드 및 업데이트" 페이지에서도 확인할 수 있다.

---

## 4. 가상화 제약

- **VM 안의 Windows(Nested case)**: VirtualBox 등으로 만든 가상 머신 안에서 Windows를 돌리면, 가상화 플랫폼이 중첩 가상화(nested virtualization)를 노출해 주지 않는 한 WSL 2는 실행되지 않는다.
- **WSL 1의 예외**: WSL 1은 하드웨어 가상화 기술(Intel의 VT-x, AMD의 SVM)에 의존하지 않으므로 같은 환경에서도 쓸 수 있는 경우가 있다.
- **정리(Rule of thumb)**: 가상 머신 위에서 WSL 2가 안 되면 중첩 가상화 노출 여부를 먼저 확인하고, 불가능하면 WSL 1을 대안으로 고려한다.
