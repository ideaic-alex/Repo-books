# 리눅스 구성요소 의존성

리눅스 앱은 systemd, DBUS, 커널 모듈 같은 다른 구성요소가 동작한다는 전제 위에서 움직이는 경우가 많다. WSL에서는 이 전제가 깨지는 지점이 있어 앱이 오류를 내거나 시작을 거부한다. 각 구성요소별로 증상과 대처를 정리한다.

---

## 1. systemd

- **역할(Role)**: 보통 부팅 시 가장 먼저 시작되는 프로세스로, 리눅스 배포판의 서비스 관리를 맡는다.
- **WSL의 제약**: WSL 1에서는 실행이 막히고, WSL 2에서는 프로세스 네임스페이스(Process Namespaces)를 쓰는 우회 방법이 필요하다.
- **증상(Symptom)**: `systemctl`로 서비스를 다루려 하면 systemd를 사용할 수 없다는 오류가 출력된다. 이는 systemd가 동작하지 않으니 다른 방식으로 앱을 실행해야 한다는 신호다.
- **스냅(Snap)**: Snap 패키지를 관리하는 snapd 데몬은 systemd를 통해서만 시작되려 하므로, 우회책 없이는 WSL에서 Snap을 쓸 수 없다.

---

## 2. dbus

- **역할(Role)**: GUI 앱에서 흔히 쓰이며, 애플리케이션 간 메시지를 일관된 방식으로 전달한다. 원래는 systemd가 세션에 맞춰 시작·종료한다.
- **증상(Symptom)**: systemd가 기본 비활성이므로 앱이 DBUS에 접속하지 못해 콘솔에 오류를 내거나 시작을 거부한다.
- **해결(Fix)**: WSL에 들어올 때마다 아래 명령으로 DBUS를 수동 기동한다. `.bashrc`에 넣어 두면 셸 시작 시 자동 실행된다.
- **UUID 오류**: 처음 실행하면 고유 DBUS UUID가 없다는 오류가 나는데, 한 번만 UUID를 생성하면 된다.

```bash
dbus-launch --exit-with-x11
sudo dbus-uuidgen --ensure
```

---

## 3. 커널 모듈

- **전제(Requirement)**: 특정 커널 모듈이 필요한 앱은 실제 리눅스 커널을 가진 WSL 2에서만 쓸 수 있다.
- **함정(Pitfall)**: Microsoft가 제공하는 커널에 필요한 모듈이 포함되어 있지 않을 수 있다.
- **진단(Diagnosis)**: 앱 실행 출력의 경고·오류에서 모듈 누락 단서를 찾거나, 커널 로그를 보여 주는 `dmesg`의 출력을 확인한다.
