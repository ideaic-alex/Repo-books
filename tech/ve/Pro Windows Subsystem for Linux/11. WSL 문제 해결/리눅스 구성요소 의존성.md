# 리눅스 구성요소 의존성

리눅스 앱은 systemd, DBUS, 커널 모듈 같은 다른 구성요소가 이미 동작하고 있다고 가정하고 만들어진 경우가 많다. WSL에서는 이 가정이 맞지 않는 부분이 있어서, 앱이 오류를 내거나 시작을 거부하기도 한다. 구성요소별로 증상과 대처 방법을 정리한다.

---

## 1. systemd

- **역할(Role)**: 보통 부팅할 때 가장 먼저 시작되는 프로세스이며, 리눅스 배포판의 서비스를 관리한다.
- **WSL의 제약**: WSL 1에서는 systemd를 실행할 수 없다. WSL 2에서는 프로세스 네임스페이스(Process Namespaces)를 쓰는 우회 방법이 필요하다.
- **증상(Symptom)**: `systemctl`로 서비스를 다루려 하면 systemd를 사용할 수 없다는 오류가 나온다. systemd가 동작하지 않으니 다른 방식으로 앱을 실행해야 한다는 신호다.
- **스냅(Snap)**: Snap 패키지를 관리하는 snapd 데몬은 systemd를 통해서만 시작하려 한다. 그래서 우회 방법 없이는 WSL에서 Snap을 쓸 수 없다.

---

## 2. dbus

- **역할(Role)**: GUI 앱에서 흔히 쓰며, 애플리케이션끼리 메시지를 일정한 방식으로 주고받게 해 준다. 원래는 systemd가 세션에 맞춰 시작하고 종료한다.
- **증상(Symptom)**: WSL에서는 systemd가 기본으로 꺼져 있어서 앱이 DBUS에 접속하지 못한다. 그러면 콘솔에 오류를 내거나 시작을 거부한다.
- **해결(Fix)**: WSL에 들어올 때마다 아래 명령으로 DBUS를 직접 시작한다. `.bashrc`에 넣어 두면 셸을 열 때 자동으로 실행된다.
- **UUID 오류**: 처음 실행하면 DBUS의 고유 UUID가 없다는 오류가 나온다. 이 경우 UUID를 한 번만 생성하면 된다.

```bash
dbus-launch --exit-with-x11
sudo dbus-uuidgen --ensure
```

---

## 3. 커널 모듈

- **전제(Requirement)**: 특정 커널 모듈이 필요한 앱은 실제 리눅스 커널이 있는 WSL 2에서만 쓸 수 있다.
- **함정(Pitfall)**: Microsoft가 제공하는 커널에 필요한 모듈이 들어 있지 않을 수 있다.
- **진단(Diagnosis)**: 앱을 실행했을 때 나오는 경고나 오류에서 모듈이 없다는 단서를 찾는다. 커널 로그를 보여 주는 `dmesg`의 출력도 확인한다.
