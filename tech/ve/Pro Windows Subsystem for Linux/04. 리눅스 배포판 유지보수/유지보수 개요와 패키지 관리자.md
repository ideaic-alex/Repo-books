# 유지보수 개요와 패키지 관리자

WSL에 설치한 리눅스 배포판은 설치한 뒤에 직접 관리해야 한다. 이 문서는 Microsoft가 갱신해 주는 부분과 사용자가 직접 갱신해야 하는 부분을 구분한다. 이어서 배포판마다 다른 패키지 관리자의 기본 개념을 정리한다.

---

## 1. 누가 무엇을 갱신하는가

- **Microsoft 담당**: WSL 2의 리눅스 커널과 Windows 10의 WSL 플랫폼은 Windows Update로 갱신된다.
- **사용자 담당**: 배포판 안의 모든 것은 사용자가 갱신한다. Store 앱이 업데이트되어도 이미 설치한 배포판은 자동으로 업그레이드되지 않는다. Store와 Windows Update는 배포판 안의 패키지까지는 갱신하지 않기 때문이다.
- **자동 업그레이드 없음**: 현재 WSL 배포판에는 자동 업그레이드 기능이 없다. 직접 명령을 실행하거나, 직접 만든 Windows 서비스, 작업 스케줄러, 빌드 21286 이상의 `[boot]` 옵션으로 자동화해야 한다. 자동화 방법은 커스터마이징을 다루는 장의 init 부분에서 설명한다.
- **중요성**: 업그레이드를 하면 새 기능과 보안 패치를 받을 수 있다. 그래서 배포판별 업그레이드 방법을 알아 두어야 한다.

---

## 2. 패키지와 저장소

- **패키지(package)**: 리눅스에서 소프트웨어와 그 업데이트를 배포하는 단위다. 온라인 저장소(repository)나 아카이브에서 내려받는다.
- **선택 기준**: 어떤 배포판을 주로 쓸지 정할 때 패키지 관리자도 중요한 기준이 될 수 있다.
- **이 책의 초점**: WSL에서 가장 흔한 `apt` 계열을 중심으로 설명한다. 다른 배포판은 각 배포판의 문서를 참고하면 된다. 업데이트를 확인하고 업그레이드를 적용한다는 기본 원칙은 대부분 같다.

| 배포판 | 패키지 파일 | 패키지 관리자 |
|--------|-------------|---------------|
| Ubuntu, Debian, Pengwin, Kali | `.deb` | `apt` |
| Fedora | `.rpm` | `dnf` |
| OpenSUSE, SUSE Enterprise | `.rpm` | `zypper` |
| RHEL, Oracle Linux, Pengwin Enterprise | `.rpm` | `yum` |
| Alpine | `.apk` | `apk` |

---

## 3. 의존성 (dependencies)

- **개념**: 한 패키지가 다른 패키지(주로 `lib`로 시작하는 라이브러리)의 기능을 필요로 하는 관계다.
- **설치할 때**: 의존하는 패키지도 함께 설치된다.
- **업그레이드할 때**: 의존 관계가 바뀌면 새 패키지가 추가로 설치될 수 있다. 더는 필요 없어진 패키지가 있다고 알려 줄 수도 있다.

---

## 4. 관리자 권한 (sudo)

- **권한이 필요하다**: 패키지를 설치하고 업그레이드하는 일은 관리자 권한이 필요한 작업이다.
- **sudo 그룹**: Store에서 설치하고 사용자 계정을 만들었다면 대부분 `sudo`나 `wheel` 그룹에 속해 있다. 이 경우 명령 앞에 `sudo`를 붙이고 비밀번호를 입력해 실행한다.
- **권한 없이 실행하면**: permission denied 오류가 난다.
- **`--import`로 가져온 배포판**: 사용자를 만들지 않았다면 기본 사용자가 root이므로 `sudo`를 생략해도 된다.
