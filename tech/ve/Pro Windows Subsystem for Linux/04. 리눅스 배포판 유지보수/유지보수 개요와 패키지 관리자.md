# 유지보수 개요와 패키지 관리자

WSL에 설치한 리눅스 배포판은 설치 후 직접 관리해야 한다. 무엇을 Microsoft가 갱신해 주고 무엇이 사용자 몫인지, 그리고 배포판마다 다른 패키지 관리자의 기본 개념을 정리한다.

---

## 1. 누가 무엇을 갱신하는가

- **Microsoft 담당**: WSL 2의 리눅스 커널과 Windows 10 쪽 WSL 플랫폼은 Windows Update로 유지된다.
- **사용자 담당**: 배포판 내부의 모든 것. Store 앱이 업데이트되어도 이미 설치된 배포판은 자동으로 업그레이드되지 않으며, Store와 Windows Update는 배포판 안의 패키지까지 건드리지 않는다.
- **자동 업그레이드 없음**: 현재 WSL 배포판에는 자동 업그레이드 장치가 없다. 직접 명령으로 하거나, 사용자 정의 Windows 서비스, 작업 스케줄러, 빌드 21286 이상의 `[boot]` 옵션으로 자동화해야 한다. 방법은 사용자 정의 장의 init 부분에서 다룬다.
- **중요성**: 업그레이드는 기능과 보안 갱신을 가져오므로, 배포판별 방법을 알아 두는 것이 중요하다.

---

## 2. 패키지와 저장소

- **패키지(package)**: 리눅스에서 소프트웨어와 그 업데이트를 전달하는 단위다. 온라인 저장소(repository)나 아카이브에서 받는다.
- **선택 기준**: 패키지 관리자는 어떤 배포판을 주력으로 쓸지 결정하는 큰 요소가 될 수 있다.
- **책의 초점**: WSL에서 가장 흔한 `apt` 계열을 중심으로 설명한다. 다른 배포판은 각 문서를 참고하되, 업데이트 확인과 업그레이드 적용이라는 일반 원칙은 대부분 같다.

| 배포판 | 패키지 파일 | 패키지 관리자 |
|--------|-------------|---------------|
| Ubuntu, Debian, Pengwin, Kali | `.deb` | `apt` |
| Fedora | `.rpm` | `dnf` |
| OpenSUSE, SUSE Enterprise | `.rpm` | `zypper` |
| RHEL, Oracle Linux, Pengwin Enterprise | `.rpm` | `yum` |
| Alpine | `.apk` | `apk` |

---

## 3. 의존성 (dependencies)

- **개념**: 한 패키지가 다른 패키지(주로 `lib`로 시작하는 라이브러리)의 기능을 필요로 하는 관계다.
- **설치 시**: 의존 패키지가 함께 설치된다.
- **업그레이드 시**: 의존 관계가 바뀌면 새 패키지가 추가로 설치되거나, 더는 필요 없는 패키지가 보고될 수 있다.

---

## 4. 관리자 권한 (sudo)

- **권한 필요**: 패키지 설치와 업그레이드는 관리자 수준 작업이다.
- **sudo 그룹**: Store에서 설치하고 사용자 계정을 만들었다면 대부분 `sudo`나 `wheel` 그룹에 속해 있어, 명령 앞에 `sudo`를 붙이고 비밀번호를 입력해 실행한다.
- **권한 없이 실행하면**: permission denied 오류가 난다.
- **`--import` 배포판**: 사용자를 만들지 않았다면 기본이 root이므로 `sudo`를 생략해도 된다.
