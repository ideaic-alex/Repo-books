# 상호운용성과 환경 변수 공유

WSL의 큰 특징은 리눅스에서 Windows 프로그램을, Windows에서 리눅스 프로그램을 실행하고 환경 변수를 공유할 수 있다는 점이다. 이 문서는 `[interop]` 섹션과 `WSLENV` 변수를 다룬다. 더 깊은 활용은 9장에서 이어진다.

---

## 1. interop 활성화

- **`enabled`**: 리눅스에서 Windows 프로그램을 실행할 수 있게 하는 설정으로 기본 `true`다. 예를 들어 WSL에서 메모장을 띄울 수 있다.
- **확장 기능**: Windows 빌드 20190부터 UWP 앱 같은 Windows 앱 실행 별칭(app execution alias)도 WSL에서 실행된다.
- **끄는 이유**: Windows와 WSL 양쪽에 git, python이 설치된 경우 충돌이 생길 수 있어 배포판을 가두고 싶을 때다.
- **일시 전환**: `wsl.conf`를 건드리지 않고 한 세션 동안만 `/proc/sys/fs/binfmt_misc/WSLInterop`에 0 또는 1을 써서 끄고 켠다. 세션이 끝나면 원복되므로 영구 변경은 `wsl.conf`에서 한다.

```bash
echo 0 > /proc/sys/fs/binfmt_misc/WSLInterop
echo 1 > /proc/sys/fs/binfmt_misc/WSLInterop
```

---

## 2. Windows PATH 덧붙이기

- **`appendWindowsPath`**: Windows의 PATH 항목들을 WSL 배포판의 PATH 뒤에 붙여 양쪽 실행 파일을 모두 쓸 수 있게 한다. 기본 `true`다.
- **권장 방식**: 끌 수는 있지만 interop은 켜 둔 채로 두라고 한다. 그러면 WSL에서 접근 가능한 Windows 프로그램이 배포판 PATH에서 찾을 수 있는 것으로 한정된다.

```ini
[interop]
enabled = true
appendWindowsPath = true
```

---

## 3. WSLENV 개념

- **`WSLENV`**: Windows와 WSL 양쪽에 존재하는 메타 환경 변수로, 어떤 환경 변수를 공유할지 목록으로 정의한다.
- **구분자**: WSL에서는 콜론(`:`), Windows에서는 세미콜론(`;`)으로 이름을 나열하고, 각 이름 뒤에 해석 방식을 알려 주는 플래그를 붙인다.
- **확인 방법**: Windows는 "시스템 환경 변수 편집" 화면, 리눅스는 `printenv`로 본다.
- **필요성**: 같은 프로젝트를 리눅스와 Windows 양쪽에서 작업할 때 경로 등을 공유하면 두 환경의 장점을 함께 쓸 수 있다.
- **전파 시점**: 경계를 넘을 때만 전달된다. WSL 변수는 WSL 세션에서 interop으로 Windows 명령을 실행할 때, 반대 방향은 새 터미널을 열거나 `wsl.exe`로 명령을 실행할 때 반영된다.

---

## 4. WSLENV 플래그

| 플래그 | 의미 |
|---|---|
| `/p` | Windows 경로와 WSL 경로를 서로 변환 |
| `/l` | 경로 목록(리스트)임을 표시 |
| `/u` | Windows에서 WSL 방향으로만 공유 |
| `/w` | WSL에서 Windows 방향으로만 공유 |

- **경로 공유 예**: WSL에서 `PATHTOPROJECT`를 정의하고 `WSLENV`에 `/p`를 붙여 넣으면, Windows의 `cmd.exe`에서 `set PATHTOPROJECT`로 변환된 경로를 읽을 수 있다.
- **기존 값 보존**: 이미 `WSLENV`에 값이 있으면 새 항목 뒤에 `:$WSLENV`를 이어 붙여 덮어쓰지 않는다.
- **팁**: X 서버용 `DISPLAY` 변수를 `WSLENV`에 넣으면 다른 WSL 배포판에도 공유할 수 있다.

```bash
export PATHTOPROJECT=~/project
export WSLENV=PATHTOPROJECT/p
export WSLENV=PROJECTLIST/l:$WSLENV
```
