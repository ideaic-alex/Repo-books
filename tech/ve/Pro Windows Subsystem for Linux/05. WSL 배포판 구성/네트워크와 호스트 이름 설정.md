# 네트워크와 호스트 이름 설정

`/etc/wsl.conf`의 `[network]` 섹션은 hosts 파일, DNS 설정, 호스트 이름을 WSL이 자동 생성할지 정한다. 기본적으로 WSL은 Windows의 네트워크 정보를 기반으로 이 파일들을 부팅 때마다 만들어 주며, 필요할 때만 이를 끄고 직접 관리한다.

---

## 1. hosts 파일 생성

- **hosts 파일(name resolution file)**: 도메인 이름을 수동으로 IP에 매핑하는 파일이다. 이름 조회 순서는 hosts 파일, 최근 조회 캐시, 네트워크 DNS 서버 순이다.
- **용도**: 자체 DNS 서버 없이 장치를 호스트 이름으로 부르거나, 로컬에서 웹사이트를 테스트할 때 링크를 로컬 사이트로 돌리는 데 쓴다.
- **`generateHosts`**: 기본 `true`이며, 실행할 때마다 Windows의 hosts 파일을 WSL의 `/etc/hosts`에 복사한다. 두 OS의 hosts 형식은 호환된다.
- **단방향 동기화**: Windows에서의 추가는 WSL로 반영되지만, WSL에서 고친 내용은 Windows로 돌아가지 않고 다음 실행 때 덮어써진다.
- **끄는 경우**: WSL 전용 hosts 파일을 따로 유지하고 싶을 때 `false`로 둔다.

---

## 2. DNS 설정 파일 생성

- **`/etc/resolv.conf`**: hosts와 캐시에 없는 이름을 어디에 물을지 지정한다.
- **`generateResolvConf`**: 기본 `true`이며 Windows 네트워크 설정에서 자동 생성한다.
- **구조**: WSL 네트워크는 Host Networking Service라는 Windows 서비스가 Hyper-V 가상 이더넷 어댑터 위에서 관리한다. 네임서버 IP는 이 가상 어댑터의 IP와 같다.
- **수동 지정이 필요한 경우**: VPN으로 Windows를 연결해 DNS 서버를 직접 정해야 하는 제한적 상황 등이다.

---

## 3. 호스트 이름 설정

- **기본 동작**: WSL은 부팅 시 `/etc/hostname`을 Windows 장치 이름으로 덮어쓴다(hosts와 같은 방식).
- **`hostname` 키**: Windows 10 빌드 20180 이상에서 WSL 인스턴스에 별도 호스트 이름을 지정할 수 있다.
- **효과**: 배포판마다, 그리고 Windows와도 서로 다른 호스트 이름을 가질 수 있어 일부 고급 네트워크 구성에 유용하다.

```ini
[network]
generateHosts = true
generateResolvConf = true
hostname = Biswa96
```

---

## 4. 정리

| 키 | 기본값 | 의미 |
|---|---|---|
| `generateHosts` | true | Windows hosts를 `/etc/hosts`로 복사 |
| `generateResolvConf` | true | `/etc/resolv.conf` 자동 생성 |
| `hostname` | Windows 장치 이름 | WSL 인스턴스 호스트 이름 지정 |
