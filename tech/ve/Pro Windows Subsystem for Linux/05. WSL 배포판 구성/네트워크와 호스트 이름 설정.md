# 네트워크와 호스트 이름 설정

`/etc/wsl.conf`의 `[network]` 섹션은 hosts 파일, DNS 설정, 호스트 이름을 WSL이 자동으로 만들지 정한다. 기본적으로 WSL은 Windows의 네트워크 정보를 바탕으로 이 파일들을 시작할 때마다 만들어 준다. 직접 관리해야 할 때만 이 기능을 끄면 된다.

---

## 1. hosts 파일 생성

- **hosts 파일(name resolution file)**: 도메인 이름을 IP에 직접 연결해 두는 파일이다. 이름을 조회하는 순서는 hosts 파일, 최근 조회 캐시, 네트워크의 DNS 서버 순이다.
- **용도**: DNS 서버가 없어도 장치를 호스트 이름으로 부를 수 있다. 로컬에서 웹사이트를 테스트할 때 도메인을 로컬 사이트로 연결하는 데도 쓴다.
- **`generateHosts`**: 기본값은 `true`이며, WSL을 실행할 때마다 Windows의 hosts 파일을 WSL의 `/etc/hosts`에 복사한다. 두 OS의 hosts 파일 형식은 서로 호환된다.
- **단방향 동기화**: Windows에서 추가한 내용은 WSL에 반영된다. 반대로 WSL에서 고친 내용은 Windows로 돌아가지 않고, 다음 실행 때 덮어써진다.
- **끄는 경우**: WSL 전용 hosts 파일을 따로 관리하고 싶을 때 `false`로 둔다.

---

## 2. DNS 설정 파일 생성

- **`/etc/resolv.conf`**: hosts 파일과 캐시에 없는 이름을 어느 DNS 서버에 물어볼지 지정하는 파일이다.
- **`generateResolvConf`**: 기본값은 `true`이며, Windows 네트워크 설정을 바탕으로 이 파일을 자동으로 만든다.
- **구조**: WSL 네트워크는 Host Networking Service라는 Windows 서비스가 Hyper-V 가상 이더넷 어댑터 위에서 관리한다. 네임서버 IP는 이 가상 어댑터의 IP와 같다.
- **직접 지정해야 하는 경우**: Windows가 VPN에 연결되어 있어 DNS 서버를 직접 정해야 하는 경우처럼 제한적인 상황이다.

---

## 3. 호스트 이름 설정

- **기본 동작**: WSL은 시작할 때 `/etc/hostname`을 Windows의 장치 이름으로 덮어쓴다. hosts 파일과 같은 방식이다.
- **`hostname` 키**: Windows 10 빌드 20180 이상에서는 WSL 인스턴스에 별도의 호스트 이름을 지정할 수 있다.
- **효과**: 배포판마다, 그리고 Windows와도 서로 다른 호스트 이름을 가질 수 있다. 일부 고급 네트워크 환경을 구성할 때 유용하다.

```ini
[network]
generateHosts = true
generateResolvConf = true
hostname = Biswa96
```

---

## 4. 정리

| 키 | 기본값 | 의미 |
|---|---|---|
| `generateHosts` | true | Windows hosts를 `/etc/hosts`로 복사 |
| `generateResolvConf` | true | `/etc/resolv.conf` 자동 생성 |
| `hostname` | Windows 장치 이름 | WSL 인스턴스 호스트 이름 지정 |
