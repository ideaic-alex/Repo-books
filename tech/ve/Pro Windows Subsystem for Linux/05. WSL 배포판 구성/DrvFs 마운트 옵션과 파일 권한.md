# DrvFs 마운트 옵션과 파일 권한

Windows 드라이브를 WSL에 붙이는 파일 시스템이 DrvFs이며, `[automount]`의 `options` 문자열로 그 동작을 조절한다. 핵심은 NTFS 권한과 리눅스 권한 사이의 변환을 어떻게 다룰지, 그리고 새 파일에 어떤 권한을 줄지 정하는 것이다. 이를 이해하려면 리눅스 권한 표기와 umask 개념이 필요해 함께 정리한다.

---

## 1. options 문자열 기본

- **DrvFs(Windows drive file system)**: WSL이 Windows 파일에 접근하고 권한을 처리하게 해 주는 파일 시스템이다.
- **`options`**: 쉼표로 옵션을 나열한다.
- **기본 동작**: Windows 쪽 파일은 NTFS 권한이 리눅스 권한으로 해석되어 보이고, WSL에서 새로 만든 파일은 부모 폴더의 권한을 상속한다.

```ini
[automount]
options = "metadata,umask=22,fmask=11"
```

---

## 2. metadata 옵션

- **`metadata`**: 리눅스 권한 정보를 NTFS 확장 속성에 따로 저장하고 읽는다. NTFS 권한을 건드리지 않고 WSL에서만 읽기 전용으로 만드는 식의 제어가 가능하다.
- **새 파일 권한**: 이 옵션이 켜지면 WSL의 umask 값에 따라 권한이 정해진다.
- **소유자 기본값**: 기본적으로 기본 사용자의 UID/GID(보통 1000/1000)로 마운트된다.
- **수동 마운트 동등 명령**: 같은 효과를 `mount -t drvfs C: /mnt/c -o metadata,uid=1000,gid=1000,umask=22,fmask=11`로 낼 수 있다.

---

## 3. UID와 GID 바꾸기

- **`uid`(user ID)**: 사용자별 고유 번호다. root는 0, 낮은 번호는 시스템 계정용이며 일반 사용자는 보통 1000부터 시작한다(일부 배포판은 500). `/etc/passwd`에 저장된다.
- **`gid`(group ID)**: 그룹 번호다. root 그룹은 0, 낮은 번호는 시스템 그룹용이다. 사용자는 주 그룹 하나와 여러 보조 그룹을 가질 수 있다.
- **확인 방법**: `id`로 내 값을, `id <사용자명>`으로 다른 사용자의 값을 본다.
- **주의**: 마운트의 UID/GID를 바꾸면 기존 파일과 폴더에 대한 접근성이 달라진다.

---

## 4. 리눅스 권한 표기 복습

- **세 부류(class)**: 소유자(user), 그룹(group), 그 외(other). 각각 읽기 `r`, 쓰기 `w`, 실행 `x`, 없음 `-`의 조합을 갖는다.
- **기호 표기**: 9글자로 표현한다. 예를 들어 `rwxr-xr--`는 소유자 전체 권한, 그룹 읽기·실행, 그 외 읽기 전용이다.
- **`ls -l` 해석**: 권한 앞 글자가 `d`면 디렉터리, `l`이면 심볼릭 링크, `b`는 블록 장치, `c`는 문자(직렬) 장치다. 뒤에 소유자, 그룹, 크기, 날짜가 이어진다. 폴더 크기 4096은 내용물이 아니라 메타데이터 최소 단위(ext4)다.
- **숫자(8진수) 표기**: r=4, w=2, x=1을 더한다. 7은 rwx, 6은 rw-, 5는 r-x, 4는 r--, 0은 없음이다. `rwxr-xr--`는 `754`가 된다.
- **앞자리 숫자**: `0754`처럼 붙는 접두 숫자는 suid, sgid, sticky 비트 설정이며 이 책의 범위 밖이다.

---

## 5. umask, fmask, dmask

- **umask(user file creation mask)**: 새 파일·폴더 권한에서 빼 낼 비트를 정하는 마스크다. 기본 출발점은 파일 666, 폴더 777이다.
- **계산 예**: Ubuntu 기본 umask 022를 적용하면 새 파일은 644, 새 폴더는 755가 된다.
- **fmask 계산 주의**: 마스크는 십진 뺄셈이 아니라 비트 제거다. 따라서 `fmask=11`은 파일에서 실행 비트만 빼므로 새 파일은 666이 된다(원문은 655로 적었으나 계산 오류로 보인다).
- **세분화 옵션**: `umask`는 파일과 폴더에 같은 값을 쓰고, `fmask`는 파일만, `dmask`는 폴더만 따로 지정한다. fmask나 dmask를 주면 해당 대상에서는 umask를 대신한다.
- **활용 아이디어**: 다른 디렉터리의 읽기 접근은 강하게 제한(높은 dmask)하고 사용자 자신의 영역은 넓게 허용(낮은 fmask)하는 식으로 나눌 수 있다.

---

## 6. 정리

- **`metadata`**: 리눅스 권한을 NTFS 확장 속성에 따로 보관한다.
- **`uid` / `gid`**: 마운트된 파일의 소유자와 그룹을 지정한다.
- **`umask` / `fmask` / `dmask`**: 새 파일·폴더 권한에서 제거할 비트를 정한다.
- **한계**: `mount`의 그 밖의 플래그는 `wsl.conf`에 넣을 수 없고 `/etc/fstab`에서 설정한다.
