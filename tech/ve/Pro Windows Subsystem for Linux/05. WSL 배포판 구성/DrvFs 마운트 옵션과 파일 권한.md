# DrvFs 마운트 옵션과 파일 권한

Windows 드라이브를 WSL에 마운트해 주는 파일 시스템이 DrvFs이며, `[automount]`의 `options` 문자열로 DrvFs의 동작을 조절한다. 핵심은 NTFS 권한과 리눅스 권한을 어떻게 변환할지, 그리고 새 파일에 어떤 권한을 줄지 정하는 것이다. 이를 이해하려면 리눅스 권한 표기와 umask 개념을 알아야 해서 이 문서에서 함께 정리한다.

---

## 1. options 문자열 기본

- **DrvFs(Windows drive file system)**: WSL이 Windows 파일에 접근하고 파일 권한을 처리할 때 쓰는 파일 시스템이다.
- **`options`**: 옵션을 쉼표로 구분해 나열한다.
- **기본 동작**: Windows 쪽 파일은 NTFS 권한이 리눅스 권한으로 해석되어 보인다. WSL에서 새로 만든 파일은 부모 폴더의 권한을 그대로 물려받는다.

```ini
[automount]
options = "metadata,umask=22,fmask=11"
```

---

## 2. metadata 옵션

- **`metadata`**: 리눅스 권한 정보를 NTFS 확장 속성에 따로 저장하고 읽는다. 덕분에 NTFS 권한은 그대로 두고 WSL에서만 읽기 전용으로 만드는 식의 제어가 가능하다.
- **새 파일 권한**: 이 옵션을 켜면 새 파일의 권한이 WSL의 umask 값에 따라 정해진다.
- **소유자 기본값**: 기본 사용자의 UID/GID(보통 1000/1000)가 파일의 소유자로 표시된다.
- **수동 마운트 명령**: 같은 효과를 `mount -t drvfs C: /mnt/c -o metadata,uid=1000,gid=1000,umask=22,fmask=11`로 낼 수 있다.

---

## 3. UID와 GID 바꾸기

- **`uid`(user ID)**: 사용자마다 부여되는 고유 번호다. root는 0이고 낮은 번호는 시스템 계정용이며, 일반 사용자는 보통 1000부터 시작한다(일부 배포판은 500). 이 값은 `/etc/passwd`에 저장된다.
- **`gid`(group ID)**: 그룹 번호다. root 그룹은 0이고 낮은 번호는 시스템 그룹용이다. 사용자는 주 그룹 하나와 여러 개의 보조 그룹에 속할 수 있다.
- **확인 방법**: `id`로 내 값을, `id <사용자명>`으로 다른 사용자의 값을 확인한다.
- **주의**: 마운트의 UID/GID를 바꾸면 기존 파일과 폴더에 접근할 수 있는지 여부가 달라질 수 있다.

---

## 4. 리눅스 권한 표기 복습

- **세 가지 대상(class)**: 소유자(user), 그룹(group), 그 외(other)로 나뉜다. 각 대상에 읽기 `r`, 쓰기 `w`, 실행 `x`, 권한 없음 `-`를 조합해 지정한다.
- **기호 표기**: 9글자로 표현한다. 예를 들어 `rwxr-xr--`는 소유자는 모든 권한, 그룹은 읽기와 실행, 그 외는 읽기만 가능하다는 뜻이다.
- **`ls -l` 읽는 법**: 권한 맨 앞 글자가 `d`면 디렉터리, `l`이면 심볼릭 링크, `b`면 블록 장치, `c`면 문자(직렬) 장치다. 그 뒤로 소유자, 그룹, 크기, 날짜가 이어진다. 폴더 크기로 보이는 4096은 폴더 안 내용물의 크기가 아니라 ext4의 메타데이터 최소 단위다.
- **숫자(8진수) 표기**: r=4, w=2, x=1로 계산해 더한다. 7은 rwx, 6은 rw-, 5는 r-x, 4는 r--, 0은 권한 없음이다. `rwxr-xr--`는 `754`가 된다.
- **앞자리 숫자**: `0754`처럼 앞에 붙는 숫자는 suid, sgid, sticky 비트를 설정하는 값이며, 이 책에서는 다루지 않는다.

---

## 5. umask, fmask, dmask

- **umask(user file creation mask)**: 새 파일이나 폴더의 권한에서 뺄 비트를 정하는 마스크다. 계산은 파일 666, 폴더 777에서 시작한다.
- **계산 예**: Ubuntu의 기본 umask 022를 적용하면 새 파일은 644, 새 폴더는 755가 된다.
- **fmask 계산 시 주의**: 마스크는 십진수 뺄셈이 아니라 비트를 제거하는 연산이다. 그래서 `fmask=11`은 파일에서 실행 비트만 빼므로 새 파일은 666이 된다. 원문에는 655로 적혀 있으나 계산이 잘못된 것으로 보인다.
- **세분화 옵션**: `umask`는 파일과 폴더에 같은 값을 쓰고, `fmask`는 파일에만, `dmask`는 폴더에만 따로 지정한다. fmask나 dmask를 지정하면 해당 대상에서는 umask 대신 그 값이 적용된다.
- **활용 아이디어**: 다른 디렉터리에 대한 읽기 접근은 강하게 제한하고(높은 dmask), 사용자 자신의 영역은 넓게 허용하는(낮은 fmask) 식으로 나눠 쓸 수 있다.

---

## 6. 정리

- **`metadata`**: 리눅스 권한을 NTFS 확장 속성에 따로 보관한다.
- **`uid` / `gid`**: 마운트된 파일의 소유자와 그룹을 지정한다.
- **`umask` / `fmask` / `dmask`**: 새 파일과 폴더의 권한에서 뺄 비트를 정한다.
- **한계**: `mount`의 그 밖의 플래그는 `wsl.conf`에 넣을 수 없고 `/etc/fstab`에서 설정한다.
