# 대소문자 구분 처리

리눅스와 Windows는 파일 이름의 대소문자를 다르게 취급한다. WSL이 Windows 폴더를 마운트할 때 이 차이를 어떻게 메우는지, 그리고 Windows 프로그램과 폴더를 함께 쓸 때 어떤 도구로 폴더 단위 설정을 바꾸는지 정리한다.

---

## 1. 두 세계의 차이

- **리눅스(case sensitive)**: `FILE.TXT`와 `file.txt`는 서로 다른 파일로 한 디렉터리에 공존할 수 있다.
- **Windows(case insensitive, 기본값)**: 대소문자를 무시하므로 같은 이름으로 취급해 둘을 함께 만들 수 없다.
- **Windows의 잠재 기능**: NT 계열은 POSIX 호환 성격 때문에 대소문자 구분 능력을 원래 갖고 있으나 과거 응용 프로그램과의 호환을 위해 꺼져 있다.
- **전역 레지스트리 변경의 위험**: Windows 전체에서 켤 수는 있지만 타사 프로그램이 오작동하거나 데이터가 손실될 수 있다.

---

## 2. 폴더 단위 대소문자 구분

- **배경**: WSL은 레지스트리 키를 우회하는 별도 방식으로 대소문자만 다른 파일 접근을 지원한다. 다만 WSL에서 수정한 대소문자 구분 폴더를 Windows 프로그램이 열면 문제가 생길 수 있다.
- **해결책**: Windows 10 빌드 17107에서 폴더별(per-directory) 대소문자 구분이 도입되었다. 예컨대 WSL과 Windows가 함께 쓰는 `C:\WSLworkspace` 한 곳에서만 구분을 켤 수 있다.
- **도구**: `fsutil.exe`로 Windows에서 조회·설정한다. 설정은 관리자 권한 PowerShell이 필요하다.
- **상속 안 됨**: 부모 폴더의 설정은 기존·신규 하위 폴더에 전파되지 않는다.

```powershell
fsutil.exe file queryCaseSensitiveInfo C:\WSLworkspace\
fsutil.exe file setCaseSensitiveInfo C:\WSLworkspace\ enable
fsutil.exe file setCaseSensitiveInfo C:\WSLworkspace\ disable
```

---

## 3. 마운트 옵션 case

- **`case=dir`**: 기본값. WSL이 Windows 파일 시스템에 새로 만드는 디렉터리는 대소문자를 구분한다.
- **`case=off`**: 새 디렉터리가 전통적인 Windows 방식(구분 안 함)을 따른다.
- **실무 감각**: WSL에서 Windows 프로그램과 호환되어야 하는 디렉터리를 대량으로 만들 일은 드물지만 필요할 수 있다.

```ini
[automount]
options = "metadata,case=off,umask=22,fmask=11"
```

---

## 4. WSL 1 전용 방식

- **확장 속성 방식**: WSL 1의 Windows 빌드 17692 이상에서는 WSL 안에서 `getfattr`/`setfattr`로 `system.wsl_case_sensitive` 속성을 조회·변경할 수 있었다. 값 1이 켜기, 0이 끄기다.
- **차이점**: 이 방식은 설정이 하위로 상속되었으나, WSL 2에서는 지원이 중단(deprecated)되었다.

```bash
getfattr -n system.wsl_case_sensitive <path>
setfattr -n system.wsl_case_sensitive -v 1 <path>
```
