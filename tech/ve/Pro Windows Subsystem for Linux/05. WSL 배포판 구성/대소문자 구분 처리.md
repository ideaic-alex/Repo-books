# 대소문자 구분 처리

리눅스와 Windows는 파일 이름의 대소문자를 다르게 취급한다. 이 문서에서는 WSL이 Windows 폴더를 마운트할 때 이 차이를 어떻게 메우는지 살펴본다. 또 Windows 프로그램과 폴더를 함께 쓸 때 폴더 단위로 설정을 바꾸는 도구도 정리한다.

---

## 1. 두 OS의 차이

- **리눅스(case sensitive)**: `FILE.TXT`와 `file.txt`를 서로 다른 파일로 취급하므로 한 디렉터리에 함께 둘 수 있다.
- **Windows(case insensitive, 기본값)**: 대소문자를 구분하지 않고 같은 이름으로 취급하므로 두 파일을 함께 만들 수 없다.
- **Windows가 원래 가진 기능**: NT 계열 Windows는 POSIX와 호환되도록 설계되어 대소문자를 구분하는 기능을 원래 갖고 있다. 다만 오래된 응용 프로그램과의 호환성 때문에 꺼져 있다.
- **레지스트리를 바꿀 때의 위험**: 레지스트리로 Windows 전체에서 이 기능을 켤 수는 있다. 하지만 서드파티 프로그램이 오작동하거나 데이터가 사라질 수 있다.

---

## 2. 폴더 단위 대소문자 구분

- **배경**: WSL은 레지스트리 키를 쓰지 않는 별도의 방식으로, 이름이 대소문자만 다른 파일에도 접근할 수 있게 한다. 다만 WSL에서 대소문자를 구분하도록 바꾼 폴더를 Windows 프로그램으로 열면 문제가 생길 수 있다.
- **해결책**: Windows 10 빌드 17107에서 폴더별(per-directory) 대소문자 구분 기능이 도입되었다. 예를 들어 WSL과 Windows가 함께 쓰는 `C:\WSLworkspace` 한 곳에만 구분을 켤 수 있다.
- **도구**: Windows의 `fsutil.exe`로 설정을 조회하고 바꾼다. 설정을 바꾸려면 관리자 권한으로 PowerShell을 실행해야 한다.
- **상속되지 않음**: 부모 폴더에 설정해도 기존 하위 폴더와 새로 만드는 하위 폴더에는 적용되지 않는다.

```powershell
fsutil.exe file queryCaseSensitiveInfo C:\WSLworkspace\
fsutil.exe file setCaseSensitiveInfo C:\WSLworkspace\ enable
fsutil.exe file setCaseSensitiveInfo C:\WSLworkspace\ disable
```

---

## 3. 마운트 옵션 case

- **`case=dir`**: 기본값이다. WSL이 Windows 파일 시스템에 새로 만드는 디렉터리는 대소문자를 구분한다.
- **`case=off`**: 새로 만드는 디렉터리가 Windows의 전통적인 방식을 따른다. 즉 대소문자를 구분하지 않는다.
- **실무에서는**: WSL에서 Windows 프로그램과 호환되어야 하는 디렉터리를 대량으로 만드는 일은 드물지만, 필요한 경우가 있을 수 있다.

```ini
[automount]
options = "metadata,case=off,umask=22,fmask=11"
```

---

## 4. WSL 1 전용 방식

- **확장 속성 방식**: Windows 빌드 17692 이상의 WSL 1에서는 WSL 안에서 `getfattr`/`setfattr`로 `system.wsl_case_sensitive` 속성을 조회하고 바꿀 수 있었다. 값이 1이면 켜기, 0이면 끄기다.
- **차이점**: 이 방식은 설정이 하위 폴더로 상속되었다. 하지만 WSL 2에서는 지원이 중단(deprecated)되었다.

```bash
getfattr -n system.wsl_case_sensitive <path>
setfattr -n system.wsl_case_sensitive -v 1 <path>
```
