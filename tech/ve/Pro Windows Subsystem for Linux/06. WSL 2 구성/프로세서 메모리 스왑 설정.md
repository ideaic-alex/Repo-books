# 프로세서 메모리 스왑 설정

`.wslconfig`로 WSL 2가 쓰는 자원의 양을 제한하거나 늘릴 수 있다. 고사양 워크스테이션에서는 성능을 높이고, 저사양 기기에서는 Windows가 쓸 자원을 남기려고 조절한다. 이 문서는 CPU 코어, 메모리, 스왑, 스왑 파일 위치, 쓰지 않는 메모리를 돌려주는 기능(page reporting)을 정리한다.

---

## 1. 프로세서(processors)

- **기본 동작**: Windows 기기의 모든 코어를 사용한다.
- **`processors=`**: WSL 2가 쓸 코어 수를 제한해서 나머지 코어를 Windows 작업용으로 남긴다. 기기의 코어 수는 작업 관리자의 성능 탭에서 확인한다.
- **확인 방법**: 설정한 뒤 `wsl.exe --shutdown`으로 종료하고 다시 연다. `/proc/cpuinfo`에서 `processor`를 grep하면 적용된 결과를 볼 수 있다. 예를 들어 8코어 기기에서 4개로 나온다.

```ini
[wsl2]
processors=4
```

---

## 2. 메모리(memory)

- **기본 동작**: 필요한 만큼 할당하고 작업이 끝나면 회수한다. Windows 빌드 20175부터는 기본 상한이 쓸 수 있는 RAM의 50%와 8GB 중 작은 값이다.
- **늘리는 경우**: RAM이 32GB인 기기에서 16GB를 쓰게 하려면 `memory=`를 직접 지정해야 한다.
- **줄이는 경우**: 저사양 기기에서는 1GB로도 작은 셸이나 터미널 작업은 충분하다. 하지만 GUI 앱, NodeJS 같은 큰 프레임워크 개발, 대규모 컴파일은 느려지거나 실패할 수 있다. Chromium을 소스에서 빌드하려면 최소 4GB가 필요하다.
- **표기**: 정수 뒤에 `GB` 또는 `MB`를 붙인다.

```ini
[wsl2]
memory=12GB
```

---

## 3. 스왑(swap)

- **의미**: 메모리 수요가 실제 RAM을 넘을 때 쓰는 디스크 기반 보조 메모리다. `memory=` 값을 낮게 잡았거나 하드웨어 한계에 걸렸을 때 필요하다.
- **기본값**: Windows 기기 RAM의 25%를 가장 가까운 정수 GB로 올림한 크기다.
- **조정**: `swap=`으로 크기를 지정한다. Chromium 빌드처럼 RAM을 많이 쓰는 작업이나 RAM이 8GB 미만인 기기에서는 더 크게 잡는 것이 도움이 된다. 스왑은 디스크에 쓰기 때문에 RAM보다 느리다.
- **끄기**: `swap=0`으로 끌 수 있지만 보통은 권장하지 않는다. 일부 앱에서 메모리 부족 문제가 생길 수 있기 때문이다. 다만 Kubernetes 개발에서는 스왑을 끄기도 한다. Kubernetes가 아직 스왑을 지원하지 않아서 배포 환경과 같은 조건을 만들려는 것이다.

```ini
[wsl2]
swap=6GB
```

---

## 4. 스왑 파일 위치(swapfile)

- **기본 경로**: `%USERPROFILE%\AppData\Local\Temp\swap.vhdx`이다. WSL 2가 알아서 만들기 때문에 미리 만들어 둘 필요가 없다.
- **`swapfile=`**: 스왑 파일이 저장될 위치를 바꾼다. 커널 경로와 마찬가지로 절대 경로로 적고 역슬래시를 이스케이프해야 한다.

```ini
[wsl2]
swap=4GB
swapfile=C:\\wslswap.vhdx
```

---

## 5. 페이지 보고(page reporting)

- **기본 동작**: WSL 배포판이 쓰지 않는 메모리를 풀어서 Windows에 돌려준다. 이 기능은 Microsoft가 WSL 2 커널에 적용한 패치에 의존한다. 그래서 직접 만든 커널도 공식 소스를 바탕으로 빌드하길 권한다.
- **원리**: 리눅스 커널은 메모리를 페이지 단위로 나누어 프로세스에 연결한다. 가상 머신의 게스트로 실행될 때는 쓰지 않는 페이지를 하이퍼바이저에 알리는 API를 쓸 수 있다. 이렇게 알려 주면 그 메모리를 Windows 응용 프로그램이나 다른 WSL 프로세스가 다시 쓸 수 있다.
- **조건**: CPU가 거의 놀고 있을 때만 일어난다. 디버그 콘솔로 이 과정을 볼 수 있다.
- **수동 compaction**: root 권한으로 `/proc/sys/vm/compact_memory`에 1을 쓰면 직접 실행할 수 있다.
- **끄기**: `pageReporting=false`로 설정하면 WSL이 한번 확보한 메모리를 돌려주지 않고 계속 가지고 있는다.

```bash
echo 1 | sudo tee /proc/sys/vm/compact_memory
```
