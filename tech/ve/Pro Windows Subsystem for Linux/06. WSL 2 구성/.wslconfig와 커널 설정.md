# .wslconfig와 커널 설정

WSL 2는 가벼운 가상 머신 구조라서, Hyper-V나 VirtualBox처럼 메모리와 프로세서 수 같은 자원을 직접 지정할 수 있다. 이런 WSL 2 전용 설정은 모든 배포판에 공통으로 적용되는 `.wslconfig` 파일에 적는다. 이 문서는 파일의 위치와 성격, 커널 교체 방법, 커널 명령줄을 정리한다.

---

## 1. .wslconfig 파일

- **위치**: Windows 사용자 홈 폴더의 `.wslconfig`다.
- **적용 범위**: WSL 2의 모든 배포판에 똑같이 적용된다. 배포판마다 따로 쓰는 `/etc/wsl.conf`와는 다르다.
- **기본값**: 파일이 없으면 WSL 2 기본값이 쓰인다. 기본값을 바꾸고 싶을 때만 만들면 된다.
- **요구 조건**: 이 장의 설정은 WSL 2 전용이며 Windows 10 빌드 18980 이상에서 쓸 수 있다.
- **섹션**: 모든 항목은 `[wsl2]` 아래에 적는다.

---

## 2. 커널(kernel) 교체

- **기본 커널**: Microsoft가 제공하는 공식 WSL 2 커널이 `%SystemRoot%\system32\lxss\tools\kernel`에 있다. Windows Update나 `wsl.exe --update`로 갱신된다.
- **공식 커널의 특징**: WSL 2에 맞춘 최적화(예: 메모리 compaction)가 들어 있다.
- **교체 방법**: `.wslconfig`의 `kernel=`에 직접 만든 커널의 경로를 적는다. 일반적인 리눅스 커널은 대부분 쓸 수 있다.
- **권장 사항**: 공식 소스를 바탕으로 수정해서 빌드한 커널을 쓰는 것이 좋다. 그러면 Microsoft가 넣은 최적화가 그대로 유지된다. 그렇지 않으면 WSL 전용 최적화를 쓰지 못할 수 있다.
- **오픈소스**: 공식 커널 소스는 GitHub의 `microsoft/WSL2-Linux-Kernel`에 공개되어 있다. 특정 파일 시스템처럼 필요한 기능을 넣어 직접 빌드할 수 있다.
- **한계**: 드라이버를 추가해도 해당 하드웨어는 WSL 2에서 보이지 않는다. WSL 2가 경량 가상화 컨테이너 안에서 실행되기 때문이다.
- **경로 규칙**: 절대 경로로 적어야 한다. 환경 변수는 쓰지 말고, 역슬래시는 `\\`로 이스케이프한다.
- **파일명**: 커널 파일 이름으로는 압축 커널인 `bzImage`와 비압축 커널인 `vmlinux`가 흔하며, WSL 2는 둘 다 부팅할 수 있다.

```ini
[wsl2]
kernel=C:\\Users\\Hayden\\bzImage
```

---

## 3. 커널 명령줄(kernel command line)

- **의미**: 커널을 시작할 때 넘기는 매개변수다. AppArmor 같은 보안 기능을 켜거나, 디버깅하거나, 드라이버 옵션을 조정하는 등 커널의 세부 동작을 설정할 때 쓴다.
- **WSL 2에서의 제약**: WSL 2는 가상 머신이라 하드웨어와 관련된 드라이버 옵션은 쓸 수 없다. 대신 스레딩, 시스템 콜 처리, 네트워킹, RAM 디스크와 관련된 최적화는 할 수 있다. 어떤 옵션을 쓸 수 있는지는 커널에 내장되었거나 모듈로 추가된 기능에 따라 다르다.
- **`kernelCommandLine=`**: 기본 커널과 init를 읽어 들이는 내장 명령줄이 이미 있으므로, 거기에 더할 매개변수만 적는다. 예를 들어 `vsyscall=emulate`는 오래된 리눅스 배포판을 지원할 때 쓴다.
- **표기**: 따옴표 없이 `=` 뒤에 그대로 적는다.

```ini
[wsl2]
kernelCommandLine= vsyscall=emulate
```

---

## 4. 정리

| 키 | 기본값 | 의미 |
|---|---|---|
| `kernel` | 내장 공식 커널 | 사용자 지정 커널 절대 경로 |
| `kernelCommandLine` | 내장 명령줄 | 추가 커널 매개변수 |
