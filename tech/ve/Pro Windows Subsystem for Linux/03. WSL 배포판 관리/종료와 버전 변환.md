# 종료와 버전 변환

WSL 2 환경 전체를 내리는 종료(shutdown), 특정 배포판만 강제로 멈추는 종료(terminate), 그리고 배포판을 WSL 1과 WSL 2 사이에서 바꾸는 변환 방법을 다룬다.

---

## 1. WSL 2 환경 종료 (shutdown)

- **언제 필요한가**: `.wslconfig`에서 사용자 지정 커널을 지정하거나 메모리 한도를 바꾼 뒤에는 WSL 2 가상 머신 환경을 재시작해야 설정이 반영된다.
- **불안정할 때**: 특히 Insider 빌드에서, 또는 서브시스템을 이리저리 만져 보다가 환경이 불안정해졌을 때도 재시작이 해결책이 된다.
- **동작 방식**: 실행 중인 리눅스 프로세스에 `SIGTERM`으로 종료를 알린 뒤 WSL 인스턴스를 끝낸다. 이후 아무 배포판이나 시작하면 환경이 다시 올라온다.

```powershell
wsl.exe --shutdown
```

---

## 2. 배포판 강제 종료 (terminate)

- **용도**: 배포판이나 그 안의 프로세스가 응답하지 않을 때 극히 드물게 쓰는 수단이다.
- **위험**: 실행 중인 모든 프로세스를 즉시 멈춘다. 중요한 데이터를 쓰고 있을 가능성이 있으면 피해야 한다.
- **범위**: shutdown이 전체 환경인 것과 달리, 이름으로 지정한 배포판 하나만 대상이다.

```powershell
wsl.exe --terminate Ubuntu-20.04
```

| 구분 | shutdown | terminate |
|------|----------|-----------|
| 대상 | WSL 2 환경 전체 | 지정한 배포판 하나 |
| 종료 방식 | SIGTERM으로 알린 뒤 종료 | 즉시 중단 |
| 주 용도 | 설정 반영, 환경 재시작 | 먹통 상태 복구 |

---

## 3. WSL 1과 WSL 2 사이 변환

- **명령**: `wsl.exe --set-version <이름> <1 또는 2>`.
- **소요 시간**: 용량에 비례한다. 책의 예시로는 500MB 환경이 중간 사양 PC에서 1분 정도, 10GB 이상이면 최대 1시간까지 걸릴 수 있다.
- **진행 표시 없음**: 진행률이 보이지 않으므로 멈춘 듯 보여도 기다려야 한다. 책은 멈춘 것 같을 때 Enter를 눌러 보라고 조언한다.
- **참고**: 두 버전의 파일 저장 방식 차이는 2장의 설치 원리 부분에서 다룬 내용과 연결된다.

```powershell
wsl.exe --set-version Ubuntu-20.04 1
wsl.exe --set-version Ubuntu-20.04 2
```
