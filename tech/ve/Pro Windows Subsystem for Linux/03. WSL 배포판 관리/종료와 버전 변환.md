# 종료와 버전 변환

WSL 2 환경 전체를 내리는 종료(shutdown), 특정 배포판만 강제로 멈추는 종료(terminate), 배포판을 WSL 1과 WSL 2 사이에서 바꾸는 버전 변환 방법을 다룬다.

---

## 1. WSL 2 환경 종료 (shutdown)

- **언제 필요한가**: `.wslconfig`에서 직접 만든 커널을 지정하거나 메모리 한도를 바꿨다면, WSL 2 가상 머신 환경을 재시작해야 설정이 반영된다.
- **불안정할 때**: Insider 빌드를 쓰거나 서브시스템을 이것저것 만져 보다가 환경이 불안정해졌을 때도 재시작하면 해결되는 경우가 많다.
- **동작 방식**: 실행 중인 리눅스 프로세스에 `SIGTERM`으로 종료를 알린 뒤 WSL 인스턴스를 끝낸다. 이후 아무 배포판이나 시작하면 환경이 다시 올라온다.

```powershell
wsl.exe --shutdown
```

---

## 2. 배포판 강제 종료 (terminate)

- **용도**: 배포판이나 그 안의 프로세스가 응답하지 않을 때만 쓰는, 아주 드문 수단이다.
- **위험**: 실행 중인 모든 프로세스를 즉시 멈춘다. 중요한 데이터를 쓰고 있을 수 있으면 사용하지 않는다.
- **범위**: shutdown은 환경 전체를 내리지만, terminate는 이름으로 지정한 배포판 하나만 멈춘다.

```powershell
wsl.exe --terminate Ubuntu-20.04
```

| 구분 | shutdown | terminate |
|------|----------|-----------|
| 대상 | WSL 2 환경 전체 | 지정한 배포판 하나 |
| 종료 방식 | SIGTERM으로 알린 뒤 종료 | 즉시 중단 |
| 주 용도 | 설정 반영, 환경 재시작 | 먹통 상태 복구 |

---

## 3. WSL 1과 WSL 2 사이 변환

- **명령**: `wsl.exe --set-version <이름> <1 또는 2>`
- **소요 시간**: 배포판 용량에 비례한다. 책의 예에서는 500MB 환경이 중간 사양 PC에서 1분 정도 걸렸고, 10GB 이상이면 최대 1시간까지 걸릴 수 있다.
- **진행 표시 없음**: 진행률이 나오지 않으므로 멈춘 듯 보여도 기다려야 한다. 책은 멈춘 것 같을 때 Enter를 눌러 보라고 조언한다.
- **참고**: 두 버전이 파일을 저장하는 방식의 차이는 2장에서 설치 원리를 설명한 부분과 이어진다.

```powershell
wsl.exe --set-version Ubuntu-20.04 1
wsl.exe --set-version Ubuntu-20.04 2
```
