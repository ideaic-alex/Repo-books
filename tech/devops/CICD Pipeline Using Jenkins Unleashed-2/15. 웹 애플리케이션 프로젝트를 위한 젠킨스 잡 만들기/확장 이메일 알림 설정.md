# 확장 이메일 알림 설정

테스트가 끝났을 때 결과 보고서를 메일로 받으면 젠킨스 화면을 계속 들여다볼 필요가 없다. 앞 장에서는 Mailer 플러그인의 기본 이메일 설정을 썼는데, 이 방식은 메시지를 꾸미거나 파일을 첨부할 수 없다. 이 장에서는 Email Extension 플러그인으로 사용자 지정 메시지와 첨부 파일을 보낸다.

이 문서는 플러그인 설치, 전역 설정, 잡별 설정, 첨부 파일 패턴, 발송 조건을 정리한다. 설정은 크게 "전체에 적용되는 기본값"과 "잡 하나에만 적용되는 값"으로 나뉜다는 점을 기억하면 쉽다.

---

## 1. 기본 메일과 확장 메일의 차이

| 구분 | Mailer 플러그인 | Email Extension 플러그인 |
| --- | --- | --- |
| 메시지 | 기본 형식 | 사용자 지정 가능 |
| 첨부 파일 | 불가 | 가능 |
| 설정 위치 | E-mail Notification 섹션 | Extended E-mail Notification 섹션 |

Extended E-mail Notification 섹션은 Email Extension 플러그인을 설치해야만 나타난다.

## 2. 플러그인 설치와 전역 설정

1. Email Extension 플러그인을 설치한다. 설치 방법은 5장을 참고한다.
2. Manage Jenkins(젠킨스 관리) 메뉴에서 Configure System으로 들어간다.
3. 아래로 내려가 Extended E-mail Notification 섹션을 찾는다.
4. 앞 장에서 기본 이메일용으로 입력한 Gmail 설정을 같은 값으로 채운다(원서 Figure 15-16).
5. 필요한 기본값을 채우고 Save를 누른다.

자주 쓰는 전역 설정 항목은 아래와 같다.

| 항목 | 역할 |
| --- | --- |
| Default Recipients | 기본으로 알림을 받을 이메일 목록. 저자는 자기 이메일 두 개를 넣었다 |
| Excluded Recipients | 기본 목록에 있어도 알림을 받지 않을 이메일 |
| Default Subject | 기본 제목. 환경 변수 `PROJECT_NAME`(잡 이름), `BUILD_NUMBER`(현재 빌드 번호), `BUILD_STATUS`(성공, 실패 같은 상태)를 사용한다 |
| Default Content | 메일 본문 기본 메시지 |

여기서 설정한 값은 이메일 알림을 쓰는 모든 잡에 적용되는 전역 설정이다. 그래서 특정 잡이나 특정 애플리케이션에만 해당하는 내용은 전역 설정에 넣지 말라는 것이 원서의 주의 사항이다.

## 3. 잡에 이메일 알림 추가하기

`TestCalculatorWebApplication` 잡의 Configure 메뉴로 들어가 설정을 연다.

1. Post-Build Actions 섹션까지 내려가 Add Post-Build Action 버튼을 누른다.
2. Editable Email Notification을 고른다.
3. 아래 표의 필드를 채운다(원서 Figure 15-17).
4. Advanced Settings 버튼을 눌러 Triggers 섹션을 연다.
5. Add Trigger 버튼에서 Always를 고른다.
6. Save를 누른다.

| 필드 | 입력 내용 | 설명 |
| --- | --- | --- |
| Project Recipient List | 저자의 이메일 | 여기에 값을 넣으면 전역 Default Recipients를 덮어쓴다 |
| Default Subject | 계산기 앱 이름 + 전역 기본 제목 | 기본 제목에 앱 이름을 앞에 붙인다 |
| Default Content | `Please find E-E Selenium scripts report file: ${TestType}Result.html attached with this email` | 본문에 파라미터 값을 넣는다 |
| Attachments | `**/${TestType}Result.html` | 첨부할 파일 패턴 |

원서 본문은 `$(TestType)`처럼 소괄호로 보이는 곳이 있지만, 바로 이어서 `${TestType}`으로 참조한다고 밝히므로 중괄호가 맞는 표기로 보인다.

## 4. 첨부 파일 패턴 읽는 법

Attachments 칸에는 워크스페이스 기준 상대 경로를 적는다. 저자는 `**/${TestType}Result.html`을 썼다.

| 부분 | 의미 |
| --- | --- |
| `**/` | 현재 디렉터리(워크스페이스)와 그 하위 폴더 모두에서 찾는다 |
| `${TestType}` | 테스트 종류 파라미터의 값으로 바뀐다 |
| `Result.html` | 결과 파일 이름의 고정 부분 |

파일 이름에 파라미터를 넣었기 때문에, 파일 이름을 하드코딩하지 않고도 `AllTestsResult.html`, `RegressionTestResult.html`, `SmokeTestResult.html` 중 실제로 만들어진 파일을 첨부한다. 앞 문서의 일곱 번째 배치 스텝이 이 이름 규칙으로 결과를 저장한다.

## 5. 발송 조건 정하기

Triggers 섹션의 Add Trigger 버튼으로 어떤 경우에 메일을 보낼지 고른다. 원서는 성공과 실패에 상관없이 메일을 보내려고 Always를 골랐다.

## 6. 전역 설정과 잡 설정 비교

| 구분 | 전역(Configure System) | 잡 단위(Post-Build Actions) |
| --- | --- | --- |
| 적용 범위 | 이메일 알림을 쓰는 모든 잡 | 해당 잡 하나 |
| 수신자 | Default Recipients | Project Recipient List(전역을 덮어씀) |
| 넣어도 되는 내용 | 서버 설정, 공통 기본값 | 잡과 앱에 관련된 세부 내용 |

원칙은 공통은 전역에, 개별은 잡에 두는 것이다.
