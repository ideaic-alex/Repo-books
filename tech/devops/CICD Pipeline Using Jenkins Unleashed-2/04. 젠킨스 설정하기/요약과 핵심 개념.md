# 요약과 핵심 개념

이 장은 Jenkins 서버를 켜고, 로그인하고, 전역 설정을 확인하고, 비밀번호를 잃었을 때 복구하는 방법을 다뤘다. 원서의 Summary는 서버로 시작하는 방법, 서비스로 사용하는 방법, 분실한 사용자 이름과 비밀번호를 복구하는 방법, 여러 설정 옵션을 배웠다는 내용으로 짧게 마무리한다. 이 문서는 그 내용을 장 전체의 핵심 개념과 함께 다시 묶는다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 핵심 |
|---|---|---|
| 1 | 서버 시작 | .WAR, Windows 서비스, Docker, Linux 서비스 네 가지 |
| 2 | 로그인 | 시작할 때 쓴 IP와 포트로 접속 |
| 3 | 시스템 설정 | Home directory, Jenkins URL, 관리자 이메일 |
| 4 | 비밀번호 복구 | config.xml의 보안 끄기, 계정 삭제 |
| 5 | 사용자 추가 | 자체 사용자 DB와 로그인 사용자 권한 |

각 주제는 앞 단계가 끝나야 의미가 있다. 서버가 떠야 로그인하고, 로그인해야 설정을 본다.

---

## 2. 핵심 개념 정리

- **JENKINS_HOME**: 잡, 설정 파일 등 Jenkins 관련 파일이 모이는 폴더다. 위치는 환경 변수 등으로 바꿀 수 있고, 옮겼다면 옛 위치의 파일을 정리한다.
- **jenkins.xml**: Windows 서비스의 주소와 포트를 정하는 설정 파일이다. `<arguments>` 태그에 옵션을 넣고 서비스를 재시작한다.
- **포트 포워딩**: Docker의 `-p` 옵션으로 포트 번호를 서로 이어 주는 설정이다. 원서는 콜론 오른쪽 포트로 접속한다고 설명하는데 일반 규칙과 반대로 읽히니 확인이 필요하다.
- **HTTP_PORT**: Linux에서 `/etc/default/Jenkins`에 적는 포트 설정이다.
- **Jenkins URL**: 다른 컴퓨터에서 접속할 수 있도록 localhost 대신 IP 주소를 쓰는 값이다.
- **useSecurity**: `config.xml`의 보안 스위치다. 기본 `true`이고, 복구 때 `false`로 바꿨다가 이후 보안을 다시 설정한다.
- **Authorization 옵션**: Anyone Can Do Anything은 복구용 임시 설정이고, Logged-in Users Can Do Anything은 로그인한 사용자만 허용한다.

---

## 3. 자주 쓰는 명령 모음

| 목적 | 명령 |
|---|---|
| WAR로 시작 | `java -jar <war 경로> --httpListenAddress=<IP> --httpPort=<포트>` |
| Docker로 시작 | `docker run -p 8080:8080 --name=Jenkins-server jenkins/jenkins` |
| Linux에서 시작 | `sudo systemctl start jenkins` |
| Linux 상태 확인 | `sudo systemctl status jenkins` |

명령은 원서의 깨진 표기를 문맥으로 복원한 형태다. 이미지 이름과 서비스 이름의 대소문자는 원문과 다를 수 있다.
