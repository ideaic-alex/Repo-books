# 젠킨스 파이프라인 이해하기

이 장은 프리스타일 잡으로 하던 빌드 자동화를 코드로 옮기는 방법, 곧 젠킨스 파이프라인을 다룬다. 파이프라인이 무엇이고 왜 쓰는지, 선언형과 스크립트형 문법이 어떻게 다른지, 문자열 보간과 환경 변수는 어떻게 쓰는지를 정리한다.

실습에서는 간단한 Hello World 파이프라인을 만든 뒤, 스니펫 생성기로 git과 bat 스텝을 만들어 CalculatorAPI 7.0.jar를 Nexus 저장소에 릴리스하는 파이프라인을 완성한다. 이 노트는 책의 서술 시점을 따르므로 젠킨스 화면과 메뉴 이름은 이후 바뀌었을 수 있다.

---

## 1. 핵심 요점

- 젠킨스 파이프라인은 지속적 전달 과정을 코드로 쓰는 스크립트 모음이며, 플러그인에 작업을 지시하는 방법이다.
- 코드로 관리, 내구성, 일시정지, 다재다능함, 확장성이 프리스타일 잡 대비 장점이다.
- 파이프라인 안에 스테이지가 있고, 스테이지 안에 스텝이 있으며, 노드는 이를 실행하는 머신이다.
- 선언형은 pipeline 블록과 agent, stages, steps 틀을 쓰고, 스크립트형은 node 블록 안에 바로 쓴다.
- Speed/Durability 옵션은 속도를 높이면 복구 능력이 줄어드는 맞교환 관계다.
- Unsupported class file major version 오류는 Java 11 또는 8로 맞추고 젠킨스를 재시작해 해결한다.
- 큰따옴표 문자열에서만 ${변수} 보간이 일어나고, env.BUILD_ID 같은 환경 변수도 이렇게 출력한다.
- 스니펫 생성기로 스텝 코드를 만들고, tool과 withEnv로 Maven을 호출해 Nexus에 deploy한다.
