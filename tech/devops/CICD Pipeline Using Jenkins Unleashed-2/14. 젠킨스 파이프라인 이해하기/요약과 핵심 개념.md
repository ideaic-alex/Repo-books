# 요약과 핵심 개념

이 장은 젠킨스 파이프라인이 무엇인지, 프리스타일 잡보다 어떤 점이 좋은지, 선언형과 스크립트형이 어떻게 다른지를 설명했다. 이어서 스니펫 생성기로 스텝을 만드는 법을 배우고, 마지막에 Java API를 빌드해 Nexus 저장소에 새 버전을 릴리스하는 파이프라인을 직접 만들었다. 이 문서는 장 전체를 한 번에 복습할 수 있게 핵심을 모았다.

| 7 | API 릴리스 파이프라인 | CalculatorAPI 7.0.jar를 Nexus에 배포 |

## 2. 핵심 개념 정리

- 젠킨스 파이프라인은 지속적 전달 과정을 코드로 구현하는 스크립트 모음이며, 플러그인에 작업을 지시하는 방법이다.
- 장점은 코드로 관리, 재시작에도 살아남는 내구성, 사람의 승인을 기다리는 일시정지, 분기와 반복과 병렬 같은 다재다능함, 다른 플러그인과의 확장성이다.
- 스테이지는 빌드, 테스트, 배포 같은 큰 단계이고 스텝은 그 안의 단일 작업이다.
- 선언형 파이프라인은 agent, stages, stage, steps 순서의 정해진 틀을 따른다.
- 스크립트형 파이프라인은 node 블록 안에 쓰며, node를 쓰면 큐 등록과 작업 공간 생성이 따라온다. stage는 선택이지만 쓰면 화면에서 보기 좋다.
- Speed/Durability 설정은 속도와 내구성을 맞바꾸는 옵션이다.
- 문자열 보간은 큰따옴표 문자열 안의 ${변수}를 값으로 바꾸는 것이다.
- 스니펫 생성기는 Sample Step을 골라 값을 채우면 스텝 코드를 만들어 준다.

## 3. 용어 복습 표

| 용어 | 한 줄 풀이 |
|---|---|
| 파이프라인 | 전체 빌드 과정을 정의한 코드 |
| 노드 | 파이프라인을 실행하는 머신 |
| 스테이지 | 빌드, 테스트, 배포 같은 단계를 묶는 블록 |
| 스텝 | 스테이지 안의 단일 작업 |
| 선언형 파이프라인 | pipeline 블록으로 전체를 정의하는 방식 |
| 스크립트형 파이프라인 | node 블록으로 전체를 정의하는 방식 |
| 문자열 보간 | 문자열 속 변수를 값으로 바꿔 넣는 일 |
| 스니펫 생성기 | 스텝 코드를 화면에서 만들어 주는 도구 |
| withEnv | 블록 안에서 환경 변수를 설정하는 스텝 |
| tool | Global Tool Configuration에 등록한 도구의 설치 경로를 얻는 스텝 |

이 표는 이 장에서 새로 나온 용어를 모은 것이다. 코드를 읽다 막히면 이 표로 돌아와 확인하면 된다.

---

## 4. 실습에서 기억할 점

1. 파이프라인 잡은 New Item에서 Pipeline 옵션으로 만들고, 코드는 설정 페이지의 Pipeline 섹션 편집기에 쓴다.
2. 실행은 대시보드의 시계 아이콘, 결과 확인은 Console Output 메뉴다.
3. Unsupported class file major version 오류는 Java 버전 문제이므로 Java 11 또는 8로 맞추고 젠킨스를 재시작한다.
4. 릴리스 전에는 테스트 기댓값이 맞는지, pom.xml의 version을 올렸는지, 변경이 master에 병합됐는지 확인한다.
5. 결과는 콘솔 출력과 Nexus 저장소 양쪽에서 확인한다.
