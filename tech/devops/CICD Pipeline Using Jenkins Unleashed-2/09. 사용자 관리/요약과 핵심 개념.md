# 요약과 핵심 개념

이 장은 Jenkins를 여러 사람이 함께 쓸 때 필요한 사용자 관리를 다뤘다. 사용자 계정을 만들고, 역할 기반 접근 제어로 사용자에게 권한을 나눠 주고, 매트릭스 방식으로 사용자와 권한을 직접 체크하는 방법까지 이어졌다. 원서의 요약은 팀에서 맡은 역할에 따라 서로 다른 권한을 주는 방법과, 프로젝트 기반 매트릭스 권한 전략과 매트릭스 기반 전략이 Jenkins의 접근 제어를 탄탄하게 해 준다는 점을 짚는다. 이 문서는 장 전체를 한 번 더 훑어 정리한다.

---

## 1. 장 전체 흐름

| 순서 | 내용 | 주요 화면 |
|---|---|---|
| 1 | 사용자 만들기 | Manage Jenkins → Manage Users → Create User |
| 2 | 역할 플러그인 설치 | Manage Plugins → Available 탭 |
| 3 | 역할 기반 전략 켜기 | Configure Global Security → Authorization |
| 4 | 전역 역할 만들고 붙이기 | Manage and Assign Roles → Manage Roles, Assign Roles |
| 5 | 프로젝트 기반 역할 만들고 붙이기 | Item Roles 섹션, 패턴 입력 |
| 6 | 매트릭스 기반 보안 | Authorization 섹션의 매트릭스 옵션 |
| 7 | 프로젝트 기반 매트릭스 | 잡 Configure 화면의 프로젝트 보안 설정 |

1번에서 3번까지는 준비 단계이고, 4번 이후가 실제 권한 설계다. 5번과 7번은 모두 잡 단위로 접근을 좁힌다는 점에서 닮았지만 방법이 다르다. 5번은 이름 패턴을, 7번은 잡 설정 화면의 개별 표를 쓴다.

---

## 2. 핵심 개념

- 사용자 관리: Jenkins에서는 팀원이 관리자도 되고, 최소 권한의 조회 및 실행 사용자도 된다. 계정은 Manage Users의 Create User로 만든다.
- 역할 기반 접근 제어: 권한을 역할에 담고 역할을 사용자에게 붙이는 방식이다. Role-Based Authorization Strategy 플러그인을 설치하고 Configure Global Security에서 Role-Based Strategy를 선택해야 쓸 수 있다.
- 전역 역할(Global Roles): Jenkins 전체에 적용된다. 사용자가 대시보드에서 무엇이든 보려면 Overall 유형의 접근 권한이 필요하다.
- 프로젝트 기반 역할(Item Roles): 패턴에 맞는 이름의 잡에만 적용된다. 원서의 `.*Testing` 패턴은 이름이 Testing으로 끝나는 잡을 걸러 낸다.
- 매트릭스 기반 보안: 표에서 사용자별로 권한을 직접 체크한다. Anonymous Users와 Authenticated Users 그룹이 기본으로 있다.
- 프로젝트 기반 매트릭스 권한 전략: 매트릭스 기반을 확장해 잡마다 별도 표를 정의할 수 있다. Inheritance Strategy로 다른 ACL의 권한을 물려받을지 정한다.
- 접근하지 못하는 메뉴는 사용자 화면에서 보이지 않는다. Configure와 Delete Project가 그 예다.

---

## 3. 용어 정리

| 용어 | 풀이 |
|---|---|
| Anonymous Users | 로그인하지 않은 사용자 |
| Authenticated Users | 로그인에 성공한 모든 사용자 |
| Global Roles | Jenkins 전체에 적용되는 역할 표 |
| Item Roles | 잡 이름 패턴에 따라 적용되는 역할 표 |
| Pattern | 대상 잡을 고르는 이름 규칙(정규 표현식) |
| Inheritance Strategy | 잡이 다른 접근 제어 목록의 권한을 물려받는 방식을 정하는 드롭다운 |
| Overall | 대시보드 접근 같은 전체 범위의 권한 항목 |

---

## 4. 실습 때 자주 놓치기 쉬운 점

1. 역할을 만든 뒤 Save를 누르고, 사용자에게 붙인 뒤에도 Save를 한 번 더 눌러야 한다.
2. 프로젝트 기반 역할만 붙이고 Overall 권한이 있는 전역 역할을 안 붙이면 사용자가 대시보드에서 아무것도 보지 못한다.
3. 프로젝트별 보안 설정은 Project-based Matrix Authorization Strategy를 켜 두었을 때만 잡 설정 화면에 나타난다.
4. 설정을 마친 뒤 해당 사용자 계정으로 직접 로그인해 결과를 확인하는 것이 가장 확실하다.
