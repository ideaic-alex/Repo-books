# 요약과 핵심 개념

이 장은 자바 API 프로젝트가 거치는 빌드 라이프사이클 단계를 정리하고, 그 단계를 Maven으로 자동화하는 방법을 다뤘다. Eclipse에서 Maven 프로젝트를 만들고, 명령줄에서 Maven 명령을 실행해 아티팩트(.JAR 파일)를 만들었으며, settings.xml로 기본 설정을 바꾸는 방법도 익혔다.

다음 장에서는 Maven과 Nexus를 연결해 이 아티팩트를 Nexus라는 아티팩트 저장소에 릴리스하는 방법을 다룬다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 핵심 |
|---|---|---|
| 1 | 개발 흐름 | 라이브러리 내려받기부터 릴리스까지 반복 작업이 많아 빌드 도구가 필요 |
| 2 | Eclipse 프로젝트 생성 | maven-archetype-quickstart로 CalculatorAPI 생성 |
| 3 | 디렉터리와 pom.xml | src/main/java, src/test/java, pom.xml의 역할 |
| 4 | 빌드 라이프사이클 | clean, 컴파일, 테스트, package, install, deploy |
| 5 | 명령줄 사용 | M2_HOME, PATH, JAVA_HOME 설정 후 mvn package |
| 6 | settings.xml | 로컬 저장소 위치와 프록시 변경 |

## 2. 핵심 개념 정리

| 용어 | 의미 |
|---|---|
| 빌드 도구 | 라이브러리 내려받기, 컴파일, 테스트, 패키징, 배포를 자동화하는 도구. Ant, Maven, Gradle 등 |
| 서드파티 라이브러리 | 다른 개발자가 만들어 아티팩트 저장소에 올려 둔 라이브러리 |
| CLASSPATH | 자바가 클래스와 라이브러리를 찾는 경로 목록 |
| 아키타입 | 프로젝트 종류에 맞는 디렉터리 구조를 만들어 주는 Maven 플러그인 |
| GroupId, ArtifactId, Version | 아티팩트 저장소에서 프로젝트를 유일하게 가리키는 세 값 |
| POM(pom.xml) | Project Object Model. 프로젝트 정보와 빌드 설정을 담는 Maven의 핵심 파일 |
| scope | 의존성이 생명주기의 어느 단계에서 필요한지 정하는 설정 |
| 로컬 저장소 | Maven이 플러그인과 의존성을 내려받아 두는 폴더. 기본은 .m2\repository |
| settings.xml | 로컬 저장소 위치, 프록시 같은 기본 설정을 바꾸는 파일 |
| TestNG | 애너테이션으로 테스트 흐름을 제어하고 보고서를 만드는 단위 테스트 도구 |

표의 용어는 이후 장의 젠킨스 잡 설정에서 그대로 다시 나온다. 특히 GroupId, ArtifactId, Version은 Nexus에 릴리스할 때 아티팩트를 구분하는 기준이 된다.

## 3. 꼭 기억할 점

- 자바 API는 JAR 파일로, 웹 애플리케이션은 WAR 파일로 묶여 서로 다른 곳에 배포된다.
- Maven은 pom.xml 하나로 의존성과 빌드 단계를 정의한다.
- 의존성은 로컬 저장소에 있으면 재사용하고, 없으면 중앙 저장소에서 내려받는다.
- mvn package처럼 뒤쪽 단계를 실행하면 앞 단계가 모두 먼저 실행된다.
- Maven 명령은 pom.xml이 있는 프로젝트 디렉터리에서 실행한다.
- 기본값을 바꾸려면 사용자 홈의 .m2 폴더에 settings.xml을 만든다.

## 4. 해석이 불확실한 부분

- 원서가 사용자 홈 경로를 ${use.homer}로 적었으나 변수명이 잘못된 표기로 보인다.
- 원서의 로컬 저장소 설명에서 TestNG의 ArtifactId가 testing으로 적혀 있으나 pom.xml에는 testng로 되어 있다.
- 원서의 중앙 저장소 URL 변경은 settings.xml로 가능하다고만 언급할 뿐 예제가 없다.
