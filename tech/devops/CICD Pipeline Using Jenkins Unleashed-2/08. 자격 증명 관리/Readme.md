# 자격 증명 관리

이 장은 Jenkins가 Git 저장소나 Nexus 같은 외부 도구에 접속할 때 쓰는 인증 정보를 어떻게 저장하고 관리하는지 다룬다. 자격 증명이 무엇인지, 스코프와 도메인으로 사용 범위를 어떻게 나누는지, 항목을 만들고 고치는 절차와 공급자 설정까지 차례로 정리한다. 화면 구성은 책이 쓰인 시점의 Jenkins 기준이다.

핵심 메시지는 하나다. 비밀번호와 개인 키를 파이프라인 코드에 적지 말고 자격 증명 항목으로 저장해 ID로 불러 쓰라는 것이다.

---

## 1. 핵심 요점

- 자격 증명은 외부 도구 접속에 필요한 인증 정보를 Jenkins에 저장한 항목이며, 항목마다 고유한 Credentials ID가 붙는다.
- 도구의 인증 방식에는 기본 인증, SSH 인증, API 토큰 등이 있고 방식에 맞는 종류(Kind)의 항목을 만든다.
- Global 스코프는 모든 잡과 Jenkins 서버가 쓰고, System 스코프는 Jenkins와 노드 전용이라 잡에서는 보이지 않는다.
- 항목의 스코프는 Update 화면에서 나중에 바꿀 수 있고, System으로 바꾸면 잡 설정의 목록에서 사라진다.
- 도메인은 비슷한 항목을 묶고, Hostname 조건을 걸면 접속 주소가 맞는 잡에서만 항목이 보인다.
- Configure Credential Providers의 Providers 설정으로 사용자 전용 자격 증명을 쓸 수 있다.
- 같은 화면의 Types 설정으로 Kind 드롭다운에 나올 종류를 제한할 수 있다.
