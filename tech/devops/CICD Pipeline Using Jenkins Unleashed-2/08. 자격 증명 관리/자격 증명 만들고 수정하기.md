# 자격 증명 만들고 수정하기

이 문서는 가장 기본이 되는 실습을 따라 한다. 기본 도메인과 Global 스코프에 사용자 이름과 비밀번호 항목을 만들고, 이어서 그 항목의 스코프를 System으로 바꾸면 잡 설정 화면에서 어떻게 달라지는지 확인한다.

예제는 GitLab.com에 접속하는 계정을 기준으로 한다. 책은 화면 스크린샷을 곁들이지만 이 노트에서는 메뉴 이름과 입력 값을 글로 풀어 적는다. 화면 구성은 책이 쓰인 시점의 Jenkins 기준이므로 버전에 따라 메뉴 이름이 조금 다를 수 있다.

---

## 1. Global 스코프 항목 만들기

기본 도메인(원문 표현으로 global domain)에 Global 스코프로 기본 인증용 항목을 만드는 절차다.

1. Jenkins 대시보드에서 Manage Jenkins(Jenkins 관리) 링크를 눌러 관리 페이지로 간다.
2. Manage Credentials 링크를 누른다. Credentials 페이지가 열린다.
3. Stores Scoped to Jenkins 영역의 Domain 열에서 (global) 링크를 누른다. Global Credentials (Unrestricted) 페이지가 열린다.
4. 왼쪽의 Add Credentials 링크를 눌러 생성 화면을 연다.
5. Kind 드롭다운에서 만들 종류를 고른다. 이번에는 기본 인증용인 Username with Password를 그대로 둔다.
6. Scope 필드에서 Global을 그대로 둔다.
7. Username 필드에 접속할 도구의 사용자 이름을 넣는다. GitLab.com에 연결할 항목이라면 GitLab 계정의 사용자 이름이다.
8. Password 필드에 같은 계정의 비밀번호를 넣는다.
9. ID 필드에 아무 문자열이나 넣는다.
10. Description 필드에 설명을 넣는다. 비워 둬도 된다.
11. OK 버튼을 눌러 저장한다.

저장하면 Global Credentials (Unrestricted) 페이지의 목록에 항목이 나타난다. 이렇게 Global 스코프와 기본 도메인에 만든 항목은 잡을 설정할 때 자격 증명 선택 목록에 뜬다.

### 입력 필드 정리

| 필드 | 넣는 값 | 비워도 되는가 |
|---|---|---|
| Kind | 자격 증명 종류. 예: Username with Password는 기본 인증용, SSH Username with private key는 SSH 인증용 | 아니오 |
| Scope | Global 또는 System | 아니오(둘 중 선택) |
| Username | 접속 대상 도구에서 쓰는 사용자 이름 | 아니오 |
| Password | 접속 대상 도구에서 쓰는 비밀번호 | 아니오 |
| ID | 잡에서 이 항목을 가리킬 이름 | 예. 비우면 Jenkins가 임의의 고유 ID를 만든다 |
| Description | 항목 설명 | 예 |

표에서 눈여겨볼 곳은 ID다. 나중에 파이프라인이나 잡에서 ID로 항목을 부르므로, 직접 의미 있는 이름을 붙여 두면 알아보기 쉽다. 비워 두면 임의의 값이 생성되어 어떤 항목인지 ID만 보고 알기 어렵다. 이 추천은 해설자의 판단이며 원문은 비워도 된다고만 말한다.

## 2. 항목 수정하기: 스코프를 System으로 바꾸기

항목을 만든 뒤에도 고칠 수 있다. 책은 방금 만든 항목의 스코프를 Global에서 System으로 바꾸는 예를 든다.

1. Manage Jenkins 페이지로 가서 Manage Credentials 링크를 누른다. 만든 항목이 목록에 보인다.
2. Name 열에 있는 항목 이름을 누른다. 책의 예에서 이름은 Pranodayd/******로 표시되며, GitLab 저장소 접근용 자격 증명이다. 이름은 사용자 이름과 가려진 비밀번호 모양으로 보인다.
3. 왼쪽의 Update 링크를 누른다.
4. Scope 필드에서 System (Jenkins and nodes only)을 고른다.
5. Save 버튼을 누른다.

이제 이 항목의 스코프는 Global에서 System으로 바뀌었다.

## 3. 바꾼 뒤에 일어나는 일

잡 설정 화면으로 돌아가 자격 증명 드롭다운을 열면 방금 바꾼 항목이 사라져 있다. 스코프가 System이 되었으니 Jenkins 시스템과 노드만 쓸 수 있고, 잡에서는 보이지 않기 때문이다.

| 상태 | 잡 설정 화면의 자격 증명 목록 | 이유 |
|---|---|---|
| Global 스코프 | 항목이 보인다 | 모든 잡에서 사용 가능 |
| System 스코프로 변경 | 항목이 사라진다 | 시스템과 노드 전용이 되었다 |

항목이 갑자기 잡의 목록에서 안 보일 때, 삭제된 게 아니라 스코프가 System으로 되어 있는지부터 확인하면 된다. 반대로 시스템 관리용 자격 증명이 잡 쪽 목록에 불필요하게 노출되지 않는다는 점은 장점이다.
