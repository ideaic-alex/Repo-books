# 요약과 핵심 개념

이 장은 Jenkins가 외부 도구에 접속할 때 쓰는 인증 정보를 어떻게 저장하고 나누는지 다뤘다. 스코프와 도메인으로 항목의 사용 범위를 조정하는 법, 공급자와 종류 설정으로 만들 수 있는 항목을 제한하는 법을 익히면 외부 도구에 접속하는 잡을 만들 준비가 된 셈이다.

원서는 짧은 요약으로 마무리하고, 다음 장에서 사용자와 접근 권한을 관리하는 법을 다룬다고 예고한다.

---

## 1. 핵심 개념 한눈에 보기

| 개념 | 한 줄 설명 | 관련 화면과 값 |
|---|---|---|
| 자격 증명(credential) | 외부 도구 접속용 인증 정보를 Jenkins에 저장한 항목 | Manage Jenkins → Manage Credentials |
| Credentials ID | 항목의 고유 이름. 잡에서 이 ID로 부른다 | ID 필드. 비우면 자동 생성 |
| 스코프 | 항목을 쓸 수 있는 범위 | Global, System |
| 도메인 | 비슷한 시스템용 항목의 묶음 | Add Domain, Specification의 Hostname |
| 공급자 | 자격 증명을 제공하는 저장 위치 | Jenkins Credentials Provider, User Credentials Provider |
| 종류(Types) | 만들 수 있는 항목의 형태 | Configure Credential Providers의 Types |

## 2. 상황별 선택 기준

| 상황 | 선택 |
|---|---|
| 잡에서 GitLab에 접속할 계정을 쓰고 싶다 | Global 스코프로 만든다 |
| 이메일 인증이나 에이전트 연결처럼 Jenkins 시스템만 쓸 정보다 | System 스코프로 만든다 |
| 항목이 많아서 목록에서 고르기 어렵다 | 도메인으로 묶는다 |
| 특정 호스트에서만 보이게 하고 싶다 | 도메인의 Specification에서 Hostname을 쓰고 Include에 호스트를 넣는다 |
| 나만 쓰는 개인 인증 정보다 | User Credentials Provider에 만든다 |
| 특정 인증 방식 항목을 만들지 못하게 하고 싶다 | Types에서 해당 종류 체크를 해제한다 |

## 3. 장 전체 요점

- Jenkins는 Nexus, Git 같은 도구에 접속하려고 기본 인증, SSH 인증, API 토큰 인증 정보를 가지고 있어야 한다. 책은 인증서도 인증 방식으로 나열한다.
- 항목을 Jenkins에 저장하면 파이프라인 코드에 비밀번호나 개인 키를 그대로 적지 않아도 되고 여러 잡이 공유할 수 있다.
- Global 스코프는 모든 잡과 Jenkins 서버가 쓰고, System 스코프는 Jenkins와 노드만 쓰며 잡에서는 보이지 않는다.
- 도메인은 항목을 용도별로 묶고, Hostname 조건을 걸면 접속 주소가 맞을 때만 목록에 나타난다.
- Configure Credential Providers에서 공급자와 종류를 제한할 수 있고, 사용자 공급자의 항목은 만든 사용자의 잡에서만 쓸 수 있다.
- 항목을 쓰는 방법은 Credentials Binding 플러그인(14장)과 잡 만들기(10장)에서 이어진다.
