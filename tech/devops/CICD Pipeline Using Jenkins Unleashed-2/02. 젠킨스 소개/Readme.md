# 젠킨스 소개

이 장은 CI/CD를 자동으로 돌려 주는 서버인 Jenkins를 처음 소개한다. 수작업으로 CI/CD를 돌릴 때 생기는 부담에서 출발해, Jenkins의 정의와 역사, 빌드 생명주기 단계를 파이프라인으로 구현하는 방식, 변경이 올라온 뒤 잡이 실행되는 전형적인 흐름을 차례로 정리한다.

이 장은 개념 소개가 중심이라 따라 할 실습이나 코드는 나오지 않는다. 설치와 실습은 다음 장부터 시작한다.

---

## 1. 핵심 요점

- Jenkins는 소스 가져오기, 컴파일, 단위 테스트, 패키징, 배포를 자동화하는 무료 오픈 소스 서버다.
- Java로 만들었고 Apache Tomcat 같은 서블릿 컨테이너 안에서 돈다.
- 2004년 Kohsuke Kawaguchi가 빌드 깨짐을 막으려던 데서 Hudson이 시작됐다. 2011년 Oracle과의 분쟁 뒤 Jenkins가 갈라져 나왔고 Hudson은 2020년 1월 종료됐다.
- 빌드 생명주기 단계는 DSL로 구현하며, 플러그인으로 Git, Maven, SonarQube 같은 도구를 연결한다.
- 파이프라인은 각 단계의 작업 순서를 정의한 스크립트다. 앞 단계가 실패하면 그 결과에 의존하는 뒤 단계는 실행하지 않는다.
- 전형적인 흐름은 변경 푸시, Jenkins 알림, 잡 트리거 순이다. 잡은 가져오기, 컴파일, 테스트, 정적 분석, 패키징, 배포, 종단 간 테스트, 이메일 알림을 수행한다.
- Jenkins를 쓰면 변경마다 바로 통합 테스트를 하므로, 마지막 성공 빌드 이후의 변경만 의심하면 되어 오류 원인을 찾기 쉽다.
