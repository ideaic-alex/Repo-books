# 젠킨스 잡 이해하기

이 장은 젠킨스에서 실제 일을 하는 단위인 잡(작업)을 다룬다. 잡이 무엇이고 빌드와 어떻게 다른지 알아본 뒤, 프리스타일 잡을 직접 만들면서 잡 설정 페이지의 섹션을 차례로 훑는다. 만든 잡을 실행해 결과를 확인하고, 수정하고, 작업 공간을 정리하고, 삭제하는 방법까지 이어진다.

원서는 이 장에서 잡 일반을 설명하고 구체적인 잡 유형은 뒤 장에서 다룬다. 이 노트도 같은 순서를 따른다. 원서가 윈도우 환경 화면을 기준으로 쓰였으므로 일부 경로와 명령은 윈도우 기준이다.

---

## 1. 핵심 요점

- 잡은 "언제(트리거), 무엇을(빌드 스텝), 끝나고(빌드 후 조치)"를 적은 지시 묶음이며 프로젝트라고도 부른다.
- 빌드는 잡을 한 번 실행한 것이다. 실행마다 빌드 번호가 붙고 아티팩트와 콘솔 로그가 번호에 묶여 저장된다.
- 오래된 빌드 삭제(Discard old builds)는 일수와 개수로 설정하며, 아티팩트는 따로 더 짧게 보관할 수 있다. 디스크 절약에 중요하다.
- 기본은 잡당 빌드 하나씩 실행한다. Quiet Period, 재시도, 업스트림·다운스트림 차단, 사용자 지정 작업 공간 같은 고급 옵션이 있다.
- 비공개 Git 저장소는 Global 유형 자격 증명을 만들어 연결한다. 윈도우 자격 증명 관리자 때문에 오류가 가려질 수 있다.
- 트리거는 원격 URL 호출, 다른 프로젝트 후 실행, 주기적 빌드(cron 식), SCM 폴링 네 가지다.
- 실행 결과는 Build History의 Console Output에서 확인하고, 잡 수정은 Configure, 작업 공간 정리는 Wipe Out Current Workspace, 삭제는 Delete Project로 한다.
