# 머리말과 이 책에 대하여

이 문서는 Pranoday Pramod Dingare가 쓴 'CI/CD Pipeline Using Jenkins Unleashed: Solutions While Setting Up CI/CD Processes'(Apress, 2022)의 머리말과 책 소개를 정리한 것이다. 책이 누구를 위해 쓰였는지, 저자는 어떤 사람인지, 20개 장이 어떤 순서로 이어지는지, 따라 하려면 무엇을 준비해야 하는지를 먼저 훑어 둔다. 본격적인 내용으로 들어가기 전에 전체 지도를 손에 쥐는 용도다.

이 책은 젠킨스(Jenkins, 빌드와 배포를 자동으로 돌려 주는 오픈소스 자동화 서버)를 처음부터 끝까지 다룬다. 설치와 설정 같은 기초에서 시작해 잡, 파이프라인, 분산 빌드, AWS 연동, 명령줄과 REST API 활용까지 이어진다. 이 노트는 장별로 같은 형식으로 정리하며, 이 문서는 그 첫머리에 해당한다.

---

## 1. 책의 목적과 대상 독자

머리말에 따르면 이 책의 목표는 젠킨스로 CI/CD를 구현하는 방법을 익히게 하는 것이다. CI/CD는 지속적 통합(CI, Continuous Integration)과 지속적 전달/배포(CD, Continuous Delivery/Deployment)를 묶어 부르는 말이다. 코드를 합칠 때마다 자동으로 빌드하고 테스트하고 배포하는 흐름이라고 보면 된다. 저자는 이런 과정이 있으면 개발자와 관리자가 소프트웨어에 문제가 끼어든 순간 바로 잡아낼 수 있다고 설명한다.

책이 다루는 범위는 넓다. 머리말이 밝히는 주제를 묶어 보면 다음과 같다.

| 영역 | 머리말에 나온 내용 |
|---|---|
| 젠킨스 기본 | 구조와 CI/CD에서의 역할, 설치와 설정 |
| 도구와 보안 | 도구 설정, 플러그인, 자격 증명 같은 보안 수단 |
| 잡과 파이프라인 | 잡의 종류와 구성 요소, 파이프라인 작성, 웹 애플리케이션 관리, 분산 파이프라인 |
| 프로젝트 실습 | Java API 프로젝트, 잡, 설정 |
| 버전 관리 | 분산 버전 관리 시스템인 Git과 SSH 같은 여러 인증 방식 |
| 테스트 | TestNG 단위 테스트, Selenium Python 기반 종단 간(end-to-end) 테스트 |
| 환경 | 물리 서버와 Docker 환경에서의 젠킨스 구축, AWS 같은 클라우드 연동 |
| 확장 | 파이프라인용 재사용 라이브러리, 젠킨스 CLI와 REST API로 서버 제어 |

표를 보면 이 책이 젠킨스 화면 설명서에 그치지 않고, Git, 테스트, 클라우드까지 한 흐름으로 묶어 보여 주려는 것을 알 수 있다. 저자는 예제와 시나리오를 많이 넣었다고 밝힌다.

머리말이 꼽은 학습 목표는 네 가지다.

- 젠킨스로 처음부터 끝까지 이어지는 파이프라인을 만든다.
- 젠킨스를 AWS, Docker, Git 같은 여러 도구와 연동한다.
- Selenium 자동화로 종단 간 테스트를 한다.
- 분산 파이프라인을 만든다.

대상 독자는 CI/CD 파이프라인을 만드는 일에 관여하는 개발자와 테스트 자동화 전문가, 그리고 DevOps 전문가로 길을 열고 싶은 사람이다. DevOps는 개발(Development)과 운영(Operations)을 한 흐름으로 묶어 배포를 빠르고 안정적으로 만드는 일하는 방식을 가리킨다. 이 책의 목표는 독자가 자기 프로젝트에 젠킨스 기반 CI/CD를 바닥부터 적용하고, 나아가 DevOps 실무 전반을 준비하게 하는 것이다.

## 2. 저자 소개

저자 Pranoday Pramod Dingare는 인도 마하라슈트라주 푸네에 사는 소프트웨어 테스트 전문가다. 원서에 적힌 이력을 정리하면 다음과 같다.

| 항목 | 내용 |
|---|---|
| 경력 | 소프트웨어 테스트 15년 이상, 그중 자동화 테스트 10년 이상 |
| 전문 분야 | 최근 8년 동안 모바일 애플리케이션 테스트 자동화를 이끎 |
| 활동 | 테스트 자동화 도구 전파, 연구개발, 개념 검증(PoC), 시범 프로젝트 |
| 컨설팅 | 인도와 해외의 스타트업, 중견 IT 기업에서 프리랜서 테스트 자동화 컨설턴트로 일함 |
| 성과 | 오픈소스 테스트 자동화 도구로 유료 자동화 도구를 대체해 큰 비용 절감을 이룸 |
| DevOps 업무 | Jenkins, GitLab, Nexus, Docker 같은 도구를 도입해 조직의 테스트 자동화에 DevOps 방식을 접목함 |
| 현재 | 최근 풀타임 DevOps 직무로 전환해 약 1년째 리드 DevOps 전문가로 근무 |
| 교육 | 9년 넘게 테스트와 DevOps 교육을 했고 일반 및 기업 교육을 200회 넘게 진행, 블로그 운영 |

저자가 다뤄 본 DevOps 도구로는 Docker, Maven, Kubernetes, Git, Nexus, Azure DevOps, AWS, SonarQube, Jenkins 등이 소개되어 있다(원문 표기는 Kubernetese로 되어 있으나 Kubernetes를 가리키는 것으로 보인다). 여러 애플리케이션의 빌드와 배포 과정을 자동화하는 데 기여했다고 한다.

이 이력은 책의 구성과 잘 맞는다. 테스트 자동화에서 출발한 저자라서 Selenium 종단 간 테스트와 TestNG 단위 테스트가 파이프라인 안에 자연스럽게 들어가고, 교육자 경력 덕분에 단계별 실습 중심으로 설명이 짜여 있다. 기술 감수는 Prasanth Sahoo가 맡았다. 블록체인, DevOps, 클라우드, 애자일 분야의 실무자이자 강연자로 소개된다.

## 3. 책의 구성

책은 20개 장으로 이루어진다. 앞쪽 장은 개념, 설치, 설정을 다루고, 중간은 잡과 실습 프로젝트, 뒤쪽은 파이프라인과 확장 주제를 다룬다. 장 제목은 이 노트에서 쓰는 한국어 이름이다.

| 장 | 한국어 제목 | 한 줄 요약 |
|---|---|---|
| 1 | CI-CD 이해하기 | 개발 워크플로와 CI/CD가 무엇인지, 코드가 합쳐지고 빌드되고 배포되는 흐름을 사례로 본다 |
| 2 | 젠킨스 소개 | 젠킨스가 무엇이고 어떤 역사를 거쳤는지, CI/CD에서 어떻게 쓰이는지, 구조는 어떤지 다룬다 |
| 3 | 젠킨스 설치하기 | Windows의 하드웨어·소프트웨어 요구 사항과 설치 방법을 살펴보고, 설정 파일과 디렉터리 구조, Jenkins.xml의 주요 설정을 익힌다 |
| 4 | 젠킨스 설정하기 | 로그인, 시스템 설정 옵션, 계정 비밀번호 재설정, 사용자 추가를 다룬다 |
| 5 | 플러그인 관리하기 | 플러그인의 개념과 자주 쓰는 플러그인, 설치 방법, 플러그인 관리자, 설치 문제 해결을 다룬다 |
| 6 | 글로벌 도구 설정 페이지 이해하기 | JDK, Maven 같은 도구를 젠킨스에 등록하는 글로벌 도구 설정 화면을 살펴본다 |
| 7 | 젠킨스 보안 관리 | 글로벌 보안 설정과 LDAP 연동을 다룬다 |
| 8 | 자격 증명 관리 | 자격 증명의 개념, 범위(scope)와 도메인, 항목 생성과 수정, 공급자 설정을 다룬다 |
| 9 | 사용자 관리 | 사용자 생성, 역할 기반 권한, 프로젝트 기반 역할, 매트릭스 기반 보안을 다룬다 |
| 10 | 젠킨스 잡 이해하기 | 잡과 빌드의 개념, 프리스타일 잡의 생성과 설정 항목, 실행과 삭제를 다룬다 |
| 11 | Maven으로 Java API 프로젝트 준비하기 | Maven 빌드 도구, 프로젝트 디렉터리 구조, pom.xml, CLI 사용, settings.xml을 다룬다 |
| 12 | Maven과 Nexus 연동 및 프리스타일 잡으로 릴리스하기 | Git, GitLab, Nexus 저장소를 준비하고 프리스타일 잡으로 CalculatorAPI.jar를 릴리스한다 |
| 13 | 자동 트리거 프리스타일 잡으로 릴리스 관리하기 | 협업자 초대, SSH 인증, 새 기능 추가를 거쳐 자동 트리거와 이메일 알림이 있는 잡을 만든다 |
| 14 | 젠킨스 파이프라인 이해하기 | 파이프라인의 개념, 선언형과 스크립트형, 문자열 보간, Java API 릴리스 파이프라인 잡을 다룬다 |
| 15 | 웹 애플리케이션 프로젝트를 위한 젠킨스 잡 만들기 | 계산기 웹 애플리케이션을 빌드·배포하고 Selenium으로 테스트하는 매개변수 잡과 파이프라인을 만든다 |
| 16 | 파이프라인 애즈 코드 이해하기 | API 토큰 인증, 젠킨스파일 작성, GitLab과 GitHub 웹훅 트리거를 다룬다 |
| 17 | 젠킨스 분산 빌드 | 컨트롤러와 에이전트를 SSH 또는 JNLP로 연결해 분산 빌드를 구성한다 |
| 18 | 젠킨스와 AWS 연동하기 | AWS의 EC2 인스턴스를 만들고 계산기 웹 애플리케이션을 배포하는 잡을 만든다 |
| 19 | 기타 주제 1 | 젠킨스 CLI로 잡을 만들고 빌드하며, 인증 방식과 잡 내보내기·가져오기를 다룬다 |
| 20 | 기타 주제 2 | 원격 접근 API, Python-Jenkins, 파이프라인용 공유 라이브러리를 다룬다 |

표는 책이 네 덩어리로 나뉘는 것을 보여 준다. 1~2장은 개념, 3~9장은 설치와 관리, 10~16장은 잡과 파이프라인 실습, 17~20장은 확장 주제다. 12장부터는 CalculatorAPI라는 하나의 Java 프로젝트를 계속 키워 가며 쓰고, 15장부터는 계산기 웹 애플리케이션이 이어서 등장한다. 그래서 중간에 한 장을 건너뛰면 뒤 장의 실습 상태가 맞지 않을 수 있다.

## 4. 읽는 순서 안내

처음 공부하는 사람은 1장부터 순서대로 읽는 편이 가장 안전하다. 책의 뒤 장이 앞 장의 설치, 설정, 프로젝트를 그대로 이어받기 때문이다. 이미 일부를 아는 독자라면 아래 표를 기준으로 필요한 구간부터 들어가도 된다.

| 독자 상황 | 권장 읽기 범위 | 이유 |
|---|---|---|
| CI/CD와 젠킨스를 처음 접한다 | 1장부터 끝까지 순서대로 | 개념, 설치, 실습이 차례로 쌓이는 구조다 |
| 젠킨스는 써 봤지만 관리 쪽이 약하다 | 4~9장 | 설정, 플러그인, 도구, 보안, 자격 증명, 사용자 관리가 모여 있다 |
| 잡과 빌드 흐름이 궁금하다 | 10~13장 | 프리스타일 잡으로 빌드, 릴리스, 자동 트리거까지 단계별로 본다 |
| 파이프라인으로 넘어가고 싶다 | 14~16장 | 선언형과 스크립트형, 젠킨스파일, 웹훅을 다룬다 |
| 여러 서버로 빌드를 나누려 한다 | 17장 | 컨트롤러와 에이전트 연결 방법 두 가지를 설명한다 |
| 클라우드 배포가 목표다 | 18장 | EC2 인스턴스에 배포하는 잡을 만든다 |
| 자동화와 운영 편의가 필요하다 | 19~20장 | CLI, REST API, 공유 라이브러리를 다룬다 |

12장 이후의 실습은 앞 장의 Git 저장소, Maven 설정, Nexus 저장소가 준비되어 있다고 가정한다. 건너뛰어 읽는다면 해당 준비 단계가 어느 장에 있는지 먼저 확인해야 한다.

## 5. 실습에 필요한 준비물

머리말은 준비물 목록을 따로 두지 않는다. 대신 머리말과 목차에서 확인되는 소프트웨어와 환경을 아래에 모았다. 각 도구의 버전은 이 자료에서 확인되지 않으므로 적지 않는다. 정확한 설치 방법은 해당 장에서 다룬다.

| 준비물 | 쓰이는 곳 | 다루는 장 |
|---|---|---|
| Windows 환경과 Jenkins | 젠킨스를 Windows에 설치하고 Jenkins.xml 설정을 확인한다 | 3장 |
| Maven, JDK | Java API 프로젝트의 빌드 도구와 실행 환경 | 6장, 11장 |
| Git, GitLab, GitHub | 로컬 저장소와 중앙 저장소, 브랜치, 병합 요청 | 12~13장, 15장 |
| SSH 키 | 저장소 인증, 에이전트 연결 | 13장, 15장, 17장 |
| Nexus 저장소 | Java API 아티팩트(빌드 결과물)를 릴리스할 저장소 | 12장 |
| TestNG | Java API의 단위 테스트 | 12~13장 |
| Python과 Selenium | 웹 애플리케이션의 종단 간 UI 테스트 | 15장 |
| 이메일 확장 플러그인과 Parameterized Trigger 플러그인 | 알림 메일과 매개변수 전달 트리거 | 13장, 15장 |
| 별도 서버 한 대 이상 | 분산 빌드의 에이전트(노드) | 17장 |
| AWS 계정, EC2 인스턴스, IIS 웹 서버 | 계산기 웹 애플리케이션을 클라우드에 배포 | 18장 |
| Python-Jenkins 패키지 | 파이썬에서 젠킨스 서버 제어 | 20장 |

머리말은 젠킨스를 물리 환경과 Docker 환경 모두에 설치하는 사례를 다룬다고 밝히고 있다. 다만 목차에서 확인되는 설치 장은 Windows 설치이므로, Docker 관련 세부 내용이 어느 장에 나오는지는 해당 장을 정리할 때 확인한다.

## 6. 이 노트의 읽는 법

이 노트는 원서를 장별 폴더로 나누어 한국어로 새로 풀어 쓴 학습 노트다. 번역서가 아니라 설명 노트이므로 원문 문장을 그대로 옮기지 않고, 개념과 실습 절차, 설정 값, 주의점을 같은 정보량으로 다시 구성한다.

읽을 때 알아 두면 좋은 점은 다음과 같다.

- 각 장 폴더에는 Readme.md가 있고, 그 안에 핵심 요점과 문서 목록이 있다. 장에 들어가면 Readme.md를 먼저 읽고 필요한 문서로 이동한다.
- 문서는 주제별로 나뉘며 각각 독립해서 읽을 수 있게 썼다.
- 영어 용어는 처음 나올 때 한국어 풀이를 붙인다. 파이프라인, 잡(작업), 스테이지(단계), 에이전트(노드, 빌드를 실행하는 서버), 컨트롤러(마스터) 같은 용어는 노트 전체에서 같은 말로 통일한다.
- Jenkins, Maven, Nexus, Git, Docker, AWS 같은 제품 이름과 메뉴 이름, 코드, 명령어, 경로는 영어 그대로 둔다.
- 원서의 스크린샷은 싣지 않는다. 화면이 보여 주는 내용은 글과 표로 풀어 설명한다.
- 원서에는 젠킨스 화면 스크린샷이 많고, 그 화면은 젠킨스 버전에 따라 달라질 수 있다. 이 노트는 책이 쓰인 시점을 기준으로 정리하므로, 실제 화면의 메뉴 위치나 이름이 다르면 최신 공식 문서를 함께 확인한다.
- 코드 예제는 핵심 줄만 짧게 옮긴다. 책의 PDF에서 글자가 깨진 부분은 문맥으로 복원하고, 불확실하면 그렇게 밝힌다.

이 문서에서 다룬 머리말과 소개 부분만 읽어도 책의 전체 흐름은 잡힌다. 다음 단계는 1장 'CI-CD 이해하기'다. 코드가 합쳐지고 배포되기까지의 흐름을 먼저 이해하면 2장 이후의 젠킨스 설명이 훨씬 쉬워진다.
