# 요약과 핵심 개념

이 장은 젠킨스를 화면이 아닌 명령어로 다루는 방법을 설명했다. jenkins-cli.jar를 내려받고, HTTP 연결과 SSH 인증으로 접속하고, 코드 조각으로 잡을 내보내고 가져오는 일상 작업을 실습했다. 이 문서는 장 끝의 요약을 풀어 쓰고 핵심 개념을 다시 모은 것이다.

---

## 1. 장 요약

원서의 끝 요약은 세 가지로 정리된다. 젠킨스 CLI로 서버와 상호작용할 수 있고, jenkins-cli.jar로 HTTP URL 연결과 SSH 인증 두 방식을 쓸 수 있으며, 잡 내보내기 같은 반복 작업을 코드 조각으로 처리할 수 있다.

## 2. 핵심 개념 표

| 개념 | 설명 |
| --- | --- |
| 젠킨스 CLI | 셸이나 배치 파일에서 젠킨스를 조작하는 명령줄 인터페이스 |
| jenkins-cli.jar | CLI 클라이언트. Manage Jenkins의 Jenkins CLI 페이지에서 내려받는다 |
| 익명 사용자 오류 | 인증 없이 보내면 Overall/Read 권한이 없다는 오류가 난다 |
| API 토큰 | 비밀번호 대신 쓰는 권장 인증 수단. 사용자 Configure 페이지에서 만든다 |
| -auth | 사용자이름:토큰 형식으로 기본 인증 정보를 보내는 옵션 |
| SSH 키 쌍 | ssh-keygen -m PEM -t rsa로 만든다. 공개 키는 SSH Public Keys에 등록 |
| SSH Server 설정 | Configure Global Security에서 포트를 Fixed 또는 Random으로 정한다 |
| 인바운드 규칙 | 방화벽에서 SSH 포트(원서는 9090)로 들어오는 연결을 허용한다 |
| build 옵션 | -c, -f, -p, -s, -v, -w |
| list-jobs, get-job, create-job | 잡 내보내기와 가져오기에 쓰는 명령 조합 |

## 3. 인증 방식 비교

| 구분 | API 토큰 | SSH |
| --- | --- | --- |
| 준비물 | 토큰 | 키 쌍, SSH 서버 설정, 방화벽 규칙 |
| 옵션 | -auth 사용자:토큰 | -i 개인 키 (jar는 -ssh -user도 필요) |
| 연결 | 웹소켓(-webSocket)과 URL(-s) | ssh 클라이언트 또는 jar의 SSH 모드 |
| 장점 | 설정이 간단하다 | 키 기반이라 비밀번호를 보내지 않는다 |

표의 장점 칸은 원서 문장이 아니라 일반적인 이해에 따라 정리한 것이다. 원서는 API 토큰이 비밀번호보다 안전하고 선호된다는 점만 명시한다.

## 4. 이 장에서 쓴 명령 한눈에 보기

| 목적 | 명령 | 문서 |
| --- | --- | --- |
| 잡 만들기 | create-job 잡이름 < XML | CLI 시작과 잡 만들기 |
| 빌드 실행(OpenSSH) | ssh 사용자@주소 -p 포트 -i 키 build 잡 | SSH로 빌드 실행하기 |
| 빌드 실행(jar, SSH) | java -jar jenkins-cli.jar -s URL -ssh -user 이름 -i 키 -p 포트 build 잡 | SSH로 빌드 실행하기 |
| 잡 목록 | list-jobs | 잡 내보내기와 가져오기 |
| 잡 설정 내보내기 | get-job 잡 > 잡.xml | 잡 내보내기와 가져오기 |

## 5. 자주 실수하는 곳

- 긴 줄표(–)가 아니라 일반 하이픈(-)을 쓴다.
- ssh-keygen에서 -m PEM을 빼먹으면 젠킨스 CLI 클라이언트가 지원하는 RSA 형식이 되지 않는다.
- SSH 포트를 따로 정했다면 jar 명령에 -p를 꼭 넣는다.
- 비기본 IP로 띄운 젠킨스는 SSHD.hostName 인자가 필요하다.
- 비밀번호나 토큰을 스크립트에 그대로 적지 않는다.
