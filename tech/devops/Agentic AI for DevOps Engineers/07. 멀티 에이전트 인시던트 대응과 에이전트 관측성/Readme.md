# 멀티 에이전트 인시던트 대응과 에이전트 관측성

이 장은 고급 에이전틱 AI 주제의 마지막으로, 인시던트 대응을 위한 멀티 에이전트 오케스트레이션과 에이전트를 책임 있게 운영하는 데 필요한 관측성을 다룬다. 전문화가 정당한 경우를 가리고, 순차, 병렬, 하이브리드 오케스트레이션을 비교한 뒤, 멀티 에이전트 인시던트 대응 워크플로를 만들어 실행한다.

이어서 워크플로에 OpenTelemetry를 계측하고 출력을 평가하며, 독립 실행형 Aspire Dashboard에서 로그, 트레이스, 지표를 확인한다. 실습 값(저장소 커밋, 포트, 패키지 버전)은 책의 예시를 따르고 비밀 값은 자리표시자로 바꿨다.

---

## 1. 핵심 요점

- 멀티 에이전트는 전문화가 실제로 이득일 때만 쓴다. 인시던트 대응은 접수, 증거, 원인 분석, 복구, 커뮤니케이션으로 책임이 자연스럽게 갈린다.
- 오케스트레이션 패턴은 순차, 병렬, 하이브리드 팬아웃/팬인이다. 긴급한 운영 경로에서는 자유 형식 그룹 채팅을 피하고 명시적 계약, 구조화 출력, 사람 승인 관문을 쓴다.
- 안전 경계는 기본 읽기 전용, 사람 승인, 역할별 도구와 자격 증명 제한, 감사 가능한 기록, 타임아웃과 재시도 한도다.
- 실습은 파이프라인, 애플리케이션 상태, 런북 세 전문가를 병렬로 돌리고 지휘관 에이전트가 타입 결과를 만든 뒤, 필수 필드를 결정론적으로 검증한다.
- 실행은 .NET 10 파일 기반 앱(`dotnet run --file`)으로 하며 Azure OpenAI 엔드포인트, 키, 배포 이름을 환경 변수로 넣는다.
- 관측성은 트레이싱, 모니터링, 평가의 세 축이다. 모니터링은 빠르기와 비용을, 평가는 정확성과 안전성을 본다.
- OpenTelemetry로 로그, 트레이스, 지표를 OTLP로 내보내고 Aspire Dashboard(포트 18888, 4317, 4318)에서 확인한다. 이 대시보드는 메모리 저장이라 개발용이고, 운영은 Azure Monitor나 Grafana로 보낸다.
- 평가 점수 80점 통과 기준은 구조 점검일 뿐이다. 민감 텔레메트리 수집 설정은 합성 데이터에서만 켠다.
