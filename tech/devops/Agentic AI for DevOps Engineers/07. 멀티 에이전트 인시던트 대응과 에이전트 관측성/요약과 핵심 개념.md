# 요약과 핵심 개념

이 장은 세 덩어리로 이뤄진다. 여러 전문 에이전트로 인시던트에 대응하는 설계와 구현, 그 워크플로를 운영하기 위한 관측성과 평가의 개념, 그리고 OpenTelemetry와 Aspire Dashboard로 직접 확인하는 실습이다. 이 문서는 세 덩어리를 한 번에 되짚고 핵심 용어를 정리한다.

원서의 요약은 이렇게 이어진다. 멀티 에이전트가 정당화되는 때와 책임을 전문가에게 나누는 법을 배웠고, 순차, 병렬, 하이브리드 팬아웃/팬인을 비교하며 안전 경계를 살폈다. 그다음 .NET 10 워크플로로 세 전문가가 합성 인시던트를 동시에 분석하고, 결과를 모아 타입이 정해진 지휘관 응답으로 만든 뒤 결정론적 검증을 거쳤다. 마지막으로 로그, 트레이스, 지표를 계측하고 평가 점검을 더해 독립 Aspire Dashboard에서 봤다. 운영 교훈은 모델 출력을 검증하고, 영향이 큰 조치에는 사람 승인을 유지하며, 민감한 텔레메트리를 보호하고, 프롬프트와 평가 데이터를 버전 관리하며, 자율성을 높이기 전에 효과적인 관측성을 요구하는 것이다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 멀티 에이전트의 정당성과 패턴, 안전 경계 | 하이브리드 팬아웃/팬인과 읽기 전용, 승인 관문 원칙 |
| 2 | 샘플 인시던트 파일 5개와 프롬프트 4개 | OrderService SEV-2 시나리오와 JSON 출력 계약 |
| 3 | C# 오케스트레이션 워크플로 구현 | 병렬 전문가 3명, 지휘관 타입 결과, 필수 필드 검증 |
| 4 | 자격 증명 설정과 실행 | 환경 변수 3개, `dotnet run --file`, 뒤섞인 스트리밍과 취합 출력 |
| 5 | 관측성과 평가 이론 | 트레이싱, 모니터링, 평가의 세 축과 운영 모델 |
| 6 | OpenTelemetry 계측과 Aspire 시험 | 지표 5종, 80점 통과 평가, Docker로 대시보드 확인 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 오케스트레이션 | 여러 에이전트의 실행 순서와 결과 취합을 조율하는 일 |
| 순차 / 병렬 / 팬아웃·팬인 | 차례로 인수인계 / 동시에 증거 수집 / 동시에 돌린 뒤 모아 종합 |
| 이벤트 라우터 | 구독과 필터, 전달과 재시도, 실패 메시지의 데드레터링을 맡는 구성 요소 |
| 지휘관(commander) 에이전트 | 전문가 출력을 받아 최종 타입 응답을 만드는 조율 에이전트 |
| 구조화 출력과 결정론적 검증 | JSON 필드를 정해 두고 코드로 빈 값을 걸러 내는 이중 안전장치 |
| 프롬프트 주입 방어 지시 | 로그 속 지시를 따르지 않고 입력을 신뢰하지 않게 하는 프롬프트 문장 |
| 트레이스 / 로그 / 지표 | 실행 경로 / 상관 ID가 붙은 구조화 이벤트 / 요청 수, 토큰, 지연, 성공률 |
| 모니터링 대 평가 | 빠른가, 실패하나, 비싼가 / 정확한가, 근거가 있나, 안전한가 |
| OTLP | OpenTelemetry 데이터를 보내는 규약. gRPC(4317)와 HTTP(4318)를 쓴다 |
| Aspire Dashboard | 로컬 개발용 독립 대시보드. 메모리 저장이라 운영용이 아니다 |
| EnableSensitiveData | 메시지 내용을 텔레메트리에 싣는 설정. 합성 데이터에서만 true |
| 점진적 자율성 | 텔레메트리와 증거를 근거로 권한을 단계적으로 늘리는 방식 |

## 3. 자주 놓치는 점

- 멀티 에이전트는 유행이 아니라 전문화가 필요할 때만 쓴다. 역할이 겹치면 쪼갠 의미가 없다.
- 긴급한 운영 경로에서 자유 형식 그룹 채팅은 피한다. 계약, 구조화 출력, 승인 관문이 필요하다.
- 병렬 전문가의 스트리밍 출력은 뒤섞이고 순서가 매번 다르다. 정상이다.
- 지휘관 응답은 필수 필드 검증을 통과해야 성공으로 친다. 모델 출력은 검증 전까지 신뢰하지 않는다.
- 평가 80점 통과는 구조 점검이다. 사실 정확성, 주입 저항성, 정책 준수는 별도 평가가 필요하다.
- Aspire 독립 대시보드는 개발용이다. 이 대시보드는 메모리 저장이라 운영 모니터링에 쓰지 않는다.
- 민감 텔레메트리 설정(`EnableSensitiveData`)은 합성 데이터에서만 켠다. 실제 운영에서는 데이터 거버넌스 정책의 명시적 허용이 없으면 false다.
- 패키지 버전은 한 묶음이다. 하나만 올리면 API가 바뀌어 전체를 재시험해야 한다.
- 참조 커밋(`05c9cf0266de60bc8f3dee8c16af62812c94c0ed`)과 finish 디렉터리에서 실행해야 상대 경로가 맞는다.
