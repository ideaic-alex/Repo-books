# DevOps에서 생성형 AI의 실무 활용

이 장은 생성형 AI를 실제 DevOps 활동에 적용하는 방법을 다룬다. 장 전체를 관통하는 수명주기는 생성(generate), 검증(validate), 모니터링(monitor)이다. AI가 인프라 템플릿, CI 워크플로, 풀 리퀘스트(PR) 요약, 릴리스 문서, 인시던트 노트의 초안을 만들 수 있지만, 모든 출력은 검토하고 테스트하고 필요하면 고쳐서 기존 엔지니어링 절차에 통합해야 한다.

다섯 가지 실습(Bicep IaC, CI 파이프라인, PR 검증, 릴리스 노트, 인시던트 분류)이 이어지며, 모두 GitHub Copilot을 AI 비서로 쓴다. 공통 메시지는 AI가 초안과 설명을 가속하되 검증, 승인, 최종 결정은 사람이 쥔다는 것이다. 책의 코드는 start 폴더(시작 기준선)와 finish 폴더(완성본)로 나뉘어 제공된다.

---

## 1. 핵심 요점

- IaC는 텍스트 기반이고 패턴이 많아 AI의 자연스러운 첫 진입점이다. 다만 AI가 만든 인프라가 자동으로 맞지는 않는다.
- 파일과 폴더 구조는 엔지니어가 직접 만들고 AI에게는 내용만 채우게 한다.
- 프롬프트는 작게 나누고(금지 항목도 명시) 매번 what-if나 CI 실행으로 검증하며 조금씩 키운다.
- AI는 틀린 결정도 한다. ACR 이름 중복, 잘못된 ID 설정, `dotnet restore`에 잘못 붙은 구성 인자 같은 문제는 엔지니어가 진단하고 고쳤다.
- PR 요약은 메타데이터와 템플릿에 근거한 결정론적 규칙으로 만들고, AI가 말하지 않은 세부를 추론하지 못하게 한다.
- 릴리스 노트는 PR 메타데이터와 레이블로 묶고, 초안(draft) 릴리스로 남겨 사람이 게시한다. 초안이 거버넌스 통제다.
- 인시던트 분류에서 AI는 조사 범위를 좁히고 구조화된 노트를 만들 뿐 문제를 고치거나 배포를 승인하지 않는다.
