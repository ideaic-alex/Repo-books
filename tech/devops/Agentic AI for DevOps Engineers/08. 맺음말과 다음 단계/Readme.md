# 맺음말과 다음 단계

이 장은 책 전체를 돌아보는 마무리 장이다. 생성형 AI를 DevOps에 책임 있게 적용하기 위해 이 책이 다진 개념과, 도구가 바뀌어도 남는 엔지니어링 원칙을 정리한다. 이어서 운영으로 승격하기 전의 점검 질문과 권한을 단계적으로 늘리는 도입 경로를 제시한다.

마지막으로 성과를 재는 방법, 책을 덮은 뒤 실천할 단계, 학습을 이어 갈 영역, 새 워크플로를 승인하기 전에 던질 다섯 가지 질문을 다룬다. 새 실습은 없다.

---

## 1. 핵심 요점

- 이 책의 데모는 Azure OpenAI, GitHub, .NET, C#을 썼지만 원칙은 모델 접근, 워크플로 확장성, ID 관리, 비밀 값 처리, 결정론적 검증, 관측성을 갖춘 어느 플랫폼에나 적용된다.
- 보조와 제한된 자율성은 다른 설계 선택이다. 에이전트의 권한, 중단 조건, 승인 요건은 명시적으로 설계한다.
- 모델 출력은 신뢰할 수 없는 입력이다. 결정론적 통제가 다음 단계 사용 가능성을 확인해야 한다.
- 변하지 않는 원칙은 모호한 곳에만 AI 사용, 모든 응답 불신, 최소 컨텍스트와 권한, 관측 가능하고 되돌릴 수 있는 행동, 근거 기반 자율성 확대, 메모리와 도구의 통제된 관리다.
- 운영 준비 체크리스트는 과업 적합성, 컨텍스트, 출력 계약, 검증, 권한, 승인, 관측성, 비용, 실패 처리, 변경 관리의 열 가지다.
- 점진적 자율성은 보조, 제안, 승인 후 실행, 제한된 자율성의 네 단계이며, 다음 단계로 오르는 기준은 근거다.
- 성과는 사용량이 아니라 효율, 수용과 수정, 품질과 안전, 신뢰성, 비용, 운영 영향으로 잰다.
- 승인 전 다섯 질문은 왜 AI인가, 무엇에 접근하는가, 어떤 근거가 필요한가, 어떻게 멈추고 복구하는가, 누가 책임지는가이다.
