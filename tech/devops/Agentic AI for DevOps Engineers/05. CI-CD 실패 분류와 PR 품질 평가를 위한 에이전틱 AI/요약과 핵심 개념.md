# 요약과 핵심 개념

이 장은 세 덩어리로 이뤄진다. 에이전트가 무엇이고 CI/CD에서 어떻게 안전하게 쓰는지, 로그를 분류하는 실패 분류 에이전트, 그리고 PR을 평가하고 리스크 게이트로 연결하는 PR 품질 평가 에이전트다. 사이에 운영 실패 모드와 점진적 자율성이 들어가 두 에이전트를 어느 수준까지 믿을지 정하는 기준을 준다. 이 문서는 전체를 한 번에 되짚고 용어를 정리한다.

원서의 요약은 이렇게 이어진다. 에이전틱 AI가 일반 AI 보조와 다르고 에이전트가 추론, 계획, 메모리, 도구, 검증을 결합함을 배웠고, 안전과 위험 사용 사례를 살핀 뒤 검증된 JSON 분류를 돌려주는 실패 분류 에이전트를 만들었다. 운영 실패 이유를 보고 점진적 자율성을 적용했으며, 마지막으로 MCP 경계로 PR 파일을 가져와 리스크 게이트를 갖춘 PR 품질 평가 에이전트를 워크플로에 통합했다. 다음 장은 메모리, MCP, 멀티 에이전트, 관측 가능성을 다룬다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 에이전트의 정의와 구성 요소 | 추론, 계획, 메모리, 도구, 자기 비판의 다섯 부품 이해 |
| 2 | CI/CD 안전 사용과 가드레일 | 안전, 위험 사용 사례 구분과 네 가지 기본 가드레일 |
| 3 | 실패 분류 에이전트 실습 | 로그 신호 추출, JSON 분류와 검증, CI 워크플로에서 실행 |
| 4 | 운영 실패 모드와 점진적 자율성 | 실패 다섯 유형, 수준 0~3, 신뢰도 임계값 게이트 |
| 5 | 에이전트 패턴과 PR 품질 평가 에이전트 | 패턴 네 가지, MCP 경계와 DiffTools, 응답 검증 |
| 6 | PR 분석 워크플로 통합 | 아티팩트 업로드, 댓글 갱신, high 위험과 신뢰도 0.70 이상이면 게이트 실패 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 에이전트 | 환경을 인식하고 추론, 계획하며 도구로 행동해 목표를 이루는 자율 소프트웨어 시스템 |
| 계획 계층 | 맥락 수집, LLM 호출, 도구 사용, 출력 검증과 거부를 결정해 LLM의 예측 불가능성을 막는 층 |
| 자기 비판 | 자기 출력을 정책과 비교하고 구조를 확인하는 단계. 이 장에서는 코드로 강제한다 |
| 가드레일 | 결정론적 안전 장치. 스키마 검증, 최소 권한, 허용 목록, 사람 검토 |
| 정책 게이트 | 워크플로의 통과, 실패, 사람 검토를 정하는 최종 결정론적 관문 |
| continue-on-error | 단계가 실패해도 워크플로를 계속 진행시키는 설정. 실패 후 에이전트를 돌리려고 쓴다 |
| 맥락 손실 | 로그가 길어 컨텍스트 창을 넘고 잘리면서 중요한 신호를 잃는 실패 모드 |
| 거짓 확신 | 도구가 조용히 실패했는데 에이전트가 성공을 가정하고 보고하는 상태 |
| 점진적 자율성 | 관찰, 제안, 통제된 행동, 준자율 실행 순으로 신뢰를 입증하며 권한을 넓히는 방식 |
| 승격 신호 | 제안 수락률, 오탐률, 조치 후 테스트 통과율, 평균 해결 시간, 재정의 빈도 |
| 검증 루프 | 에이전트가 수정을 제안하고 테스트를 다시 돌려 승격 또는 되돌림을 정하는 패턴 |
| MCP 서버 | GitHub 접근을 감싸는 호스트 쪽 통제 경계. 모델에는 노출한 도구만 보인다 |
| 리스크 게이트 | 위험도 high이고 신뢰도가 0.70 이상일 때만 워크플로를 실패시키는 별도 작업 |
| 댓글 upsert | 숨은 표지로 기존 봇 댓글을 찾아 갱신하고 없으면 새로 만드는 방식 |

## 3. 자주 놓치는 점

- 에이전트의 출력은 권고일 뿐이다. 통과 여부는 모델이 아니라 코드로 된 정책 게이트가 정한다.
- 테스트 단계에 continue-on-error를 쓰면 워크플로가 실패로 끝나지 않으므로, 마지막에 `exit 1` 단계로 실패를 확정해야 한다.
- 로그에서 신호를 뽑는 도구는 LLM이 아니라 일반 코드로 만든다. 같은 입력에는 같은 결과가 나온다.
- 로그가 길면 100,000자 제한과 truncated 표시로 컨텍스트 창을 지키되, 잘리면서 신호를 잃을 수 있다는 위험을 안다.
- 모델의 JSON이 틀릴 때를 대비해 안전한 대체 JSON을 준비해야 뒤의 jq 파싱이 깨지지 않는다.
- PR의 diff, 주석, 제목, 커밋 메시지는 모두 신뢰할 수 없는 데이터이고, 거기 박힌 지시는 따르지 않는다.
- 에이전트에게는 필요한 도구만 준다. 이 장의 PR 에이전트는 도구가 세 개이고 GetFileDiff는 12,000자로 제한된다.
- workflow_dispatch로 PR 워크플로를 시험할 때는 PR 컨텍스트가 없어서 MCP_PR_* 값을 따로 줘야 한다.
- 시크릿과 쓰기 가능한 토큰을 쓰므로 신뢰할 수 있는 내부 PR에서 먼저 쓰고, pull_request_target은 피한다.
- 실습의 패키지는 릴리스 후보와 베타가 섞여 있으니 실행 전에 릴리스 노트로 호환성을 확인한다.
