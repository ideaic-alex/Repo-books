# 요약과 핵심 개념

이 장은 두 덩어리로 이뤄진다. 하나는 GitHub 이슈를 장부로 쓰는 오래 남는 메모리이고, 다른 하나는 MCP로 도구 접근을 표준화해 GitHub 도구를 서버로 노출하고 PR 품질 에이전트에 연결하는 일이다. 두 덩어리에 공통으로 흐르는 원칙은 검증과 최소 권한이다. 이 문서는 전체를 한 번에 되짚고 용어를 정리한다.

원서의 요약은 이렇게 이어진다. 메모리를 쓰는 ChatOps 워크플로는 이슈에서 승인된 선호를 불러오고, PR 내용을 신뢰하지 않으며, 메모리 후보를 뽑아 스키마, 길이, 범위, 비밀 금지 목록을 통과한 것만 쓴다. 이후 ModelContextProtocol 1.0.0으로 .NET 10 MCP 서버를 만들어 Postman으로 검증하고 McpClient로 PR 품질 에이전트에 연결했으며, 최종 워크플로는 JSON 검증, 댓글 갱신, 리스크 게이트, 아티팩트 보관을 수행한다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 메모리 이론 | 종류(단기, 장기, 이벤트 기반), 저장 대상과 금지 대상, 운영 안전장치 |
| 2 | 이슈 장부 메모리 실습 | Agent Memory Ledger 이슈, 첫 실행 로드 0개와 쓰기 1개, 둘째 실행 로드 1개와 쓰기 0개 |
| 3 | 도구와 MCP | 모델은 판단, 실행은 모델 밖 코드. MCP는 발견과 호출만 표준화 |
| 4 | MCP 서버 구축 | 도구 3개(읽기 2, 쓰기 1), stdio, 토큰은 PR_ANALYSIS_TOKEN |
| 5 | Postman 시험 | 도구 발견, 정상 호출, 잘못된 번호나 토큰의 오류 확인 |
| 6 | 에이전트에 MCP 연결 | PR 파일의 출처가 MCP로 바뀌고 DiffTools와 검증은 유지 |
| 7 | 워크플로 검증 | 첫 시험은 403(권한), 수정 후 성공하고 댓글이 발견 사항 표로 나타남 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 단기 / 장기 / 이벤트 기반 메모리 | 임시 맥락과 상태 / 과거 상호작용, 사실, 정책 / 시스템 이벤트와 결과의 믿을 만한 기록 |
| 메모리 장부 | 메모리 항목을 댓글로 쌓는 GitHub 이슈(Agent Memory Ledger). 비용 없는 개념 증명용 |
| 메모리 후보 JSON | 모델 응답 끝의 `memory_writes` 블록. 코드가 검증한 뒤에만 장부에 씀 |
| CHATOPS_MEMORY_* 변수 | 장부 이슈 번호, 항목 최대 글자 수(데모 500, 대체값 800), 최대 항목 수(10) |
| 금지 패턴 | api_key, secret, token, password, connection string, -----BEGIN이 들어간 항목을 거부 |
| 도구 | 에이전트가 외부 시스템과 상호작용하는 능력. 실행은 모델 밖에서 일어남 |
| MCP | 도구 발견, 인자 전달, 결과 수신을 표준화하는 규약. 인가, 감사, 검증은 앱의 책임 |
| stdio 전송 | 클라이언트가 서버를 자식 프로세스로 띄워 표준 입출력으로 통신. stdout은 프로토콜 전용, 로그는 stderr |
| McpServerToolType / McpServerTool | 클래스와 메서드를 MCP 도구로 등록하는 특성. WithToolsFromAssembly가 발견 |
| github_get_pull_request 외 2개 | PR 조회, PR 파일 목록 조회, PR 댓글 추가(쓰기)의 정확한 도구 이름 |
| PR_ANALYSIS_TOKEN / secrets.GITHUB_TOKEN | MCP 서버용 토큰 / 워크플로 댓글 단계용 기본 제공 토큰 |
| PR_RISK_GATE | 리스크 게이트 임계값. 기본 high이고 전체 위험도나 이슈 심각도가 이 이상이면 실패 |

## 3. 자주 놓치는 점

- 메모리에는 검증되지 않은 모델 출력을 쓰지 않는다. 모델이 규칙을 어길 수 있으므로 워크플로의 검증이 한 번 더 막아야 한다.
- 장부 이슈 번호는 미리 수동으로 만들어 CHATOPS_MEMORY_ISSUE_NUMBER 변수로 넣어야 한다. 비어 있으면 메모리가 꺼진다.
- 이슈 장부는 운영용이 아니다. 출처, 보존, 동시성, 삭제 통제가 필요하다.
- MCP 서버는 stdout을 프로토콜 전용으로 쓰므로 로그를 stdout에 찍으면 JSON-RPC가 깨진다.
- 쓰기 도구는 토큰과 워크플로가 의도적으로 허용할 때만 켠다. 빌드 성공만으로는 프로토콜 동작이 검증되지 않는다.
- 환경 변수 이름에 GITHUB_ 접두어를 쓰지 않는다. Actions 예약어이므로 서버 토큰은 PR_ANALYSIS_TOKEN으로 부른다.
- Postman에서 Connect 때 허용하는 것은 로컬 프로세스 실행에 대한 신뢰 결정이다. 명령 경로와 환경 변수를 먼저 확인한다.
- 경로에 공백이 있으면 명령과 인자를 하나의 문자열로 취급하는 클라이언트에서 연결 실패가 날 수 있다.
- stdio 자식 프로세스는 워크플로 환경 변수를 물려받는다. 운영에서는 필요한 변수만 넘긴다.
- 403 오류가 댓글 단계에서 나면 MCP나 에이전트가 아니라 워크플로 권한 문제일 수 있다. 도구 실행과 뒤쪽 권한을 따로 진단한다.
- 5장의 게이트(high와 신뢰도 0.70 이상)와 6장의 게이트(PR_RISK_GATE 임계값 이상, 신뢰도 미사용)는 방식이 다르다.
