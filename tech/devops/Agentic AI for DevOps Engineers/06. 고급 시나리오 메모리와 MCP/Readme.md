# 고급 시나리오 메모리와 MCP

이 장은 DevOps 에이전트가 반복되는 워크플로에서 더 쓸모 있어지게 하는 두 능력, 오래 남는 메모리와 표준화된 도구 접근을 다룬다. 에이전트가 무엇을 기억해야 하고 무엇을 기억하면 안 되는지 따진 뒤, GitHub 이슈 장부로 워크플로 수준 메모리를 구현한다. 이어 MCP(Model Context Protocol, 에이전트가 도구를 발견하고 호출하는 표준 규약)를 소개하고, 좁게 범위를 정한 GitHub 도구를 노출하는 C# MCP 서버를 만든다.

그다음 서버를 Postman으로 시험하고, 5장의 PR 품질 에이전트를 MCP에 연결하고, GitHub Actions 워크플로를 MCP 통합 에이전트에 맞게 고쳐 검증한다. 실습 값(패키지 버전, 변수 기본값, 임계값)은 원서의 예시를 따르며 비밀 값은 자리표시자로 둔다.

---

## 1. 핵심 요점

- 메모리가 없으면 에이전트는 이전 실패를 추적하거나 반복 패턴을 알아채지 못한다. DevOps는 단기, 장기, 이벤트 기반 메모리를 쓴다.
- 비밀과 개인정보, 임시 추론, 검증되지 않은 모델 출력은 저장하지 않는다. 운영용에는 출처, 검증, 범위, 보존, 삭제, 중복 제거, 동시 쓰기 통제가 필요하다.
- 이슈 장부 실습은 이슈 댓글의 JSON 블록으로 메모리를 쌓고, 허용 키, 길이, scope, 비밀 금지 패턴을 코드로 검증한 항목만 쓴다.
- 도구는 외부 시스템과 상호작용하는 능력이며, 모델은 필요 여부만 판단하고 실행은 모델 밖의 코드가 한다.
- MCP는 도구 발견과 호출을 표준화한다. 인가, 감사, 검증, 에이전트 간 조율은 대신하지 않는다.
- MCP 서버는 stdio로 동작하는 .NET 10 앱이고, 도구는 읽기 둘과 쓰기 하나다. 토큰과 요청과 부작용은 서버가 쥔다.
- Postman으로 도구 발견, 인자 바인딩, 인증, 오류 전달을 에이전트와 분리해 검증한다.
- 최종 워크플로는 MCP 맥락으로 에이전트를 돌리고, 댓글을 갱신하고, PR_RISK_GATE 게이트를 적용하며, 실패해도 아티팩트를 올린다. 첫 시험의 403은 MCP가 아니라 워크플로 권한 문제였다.
