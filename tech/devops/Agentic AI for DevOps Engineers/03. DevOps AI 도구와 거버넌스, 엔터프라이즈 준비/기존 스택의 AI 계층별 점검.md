# 기존 스택의 AI 계층별 점검

거버넌스를 세우기 전에 지금 개발과 배포 과정 어디에 AI가 참여하는지 먼저 파악해야 한다. 원서는 이 과정에서 실습한 도구들을 앞 문서의 계층에 하나씩 대응시켜 실제로 어떻게 동작했는지 되짚는다.

비유하면 건물 보안 점검 전에 출입문 목록부터 만드는 일이다. 어느 문이 어디로 통하는지 알아야 잠금장치를 달 수 있다.

---

## 1. IDE 수준 AI

실습에서는 Visual Studio Code와 GitHub Copilot Chat을 썼다. 조직에 따라 다른 IDE 어시스턴트나 CLI 도구를 쓸 수도 있다. 개발자 입장에서 Copilot은 코드 작성을 돕는다. 앞서 DevOps 모자를 쓰고 인프라를 다룰 때도 그랬다.

예제 Program.cs에는 단순한 API가 있고, 엔드포인트가 아직 쓸 만한 정보를 돌려주지 않는다. 더미 데이터를 돌려주는 엔드포인트가 필요하면 Copilot Chat에 프로그램 맥락을 주고 샘플 사용자를 돌려주는 엔드포인트를 만들어 달라고 요청한다. Copilot은 관련 파일을 훑은 뒤 코드를 제안하고, 사용자가 변경을 수락하면 바뀐 코드를 모두 보여 준다. 새 코드에 대한 테스트도 함께 만든다.

생산성 면에서는 시간을 아끼고, 엔드포인트를 어떻게 추가할지 틀을 준다. 하지만 품질 검토는 여전히 필요하다. 생성된 코드가 틀리지는 않아도 사람이 직접 짰을 방식과 다를 수 있다. 예를 들어 기존 orders API 구현 스타일을 따랐어야 하는데 샘플 사용자를 가져오는 새 메서드를 통째로 만들 수 있다. AI는 다른 관점을 줄 뿐이고, 개발자는 프로젝트에 맞게 고치면 된다. 생산성은 좋지만 엔터프라이즈 표준을 맞출 만큼 꼼꼼히 보지 않는 개발자가 있을 수 있어 위험은 여전히 중간이다.

## 2. 풀 리퀘스트 AI

가장 최근 PR에서 AI는 여러 곳에 쓰였다.

1. PR 요약 생성: 직접 쓰면 번거롭고 무엇이 바뀌었는지 정확히 기억하기 어렵다. GitHub Copilot 내장 PR 요약은 편리하고 생산성에 도움이 되며 꽤 정확하다.
2. ChatOps(채팅이나 PR 댓글로 운영 작업을 하는 방식) 봇: PR의 일부를 평가하는 봇을 만들었다. 봇 응답을 LLM에 곧바로 보내 받아 오고 PR에 다시 게시했다.

이 구성은 설정한 가드레일 덕분에 편리하면서도 결정적이다. 수락 전에 검증이 이뤄져 완전히 통제되고, 동작을 이끄는 엔진은 여러 워크플로에서 재사용된다.

## 3. 파이프라인 수준 AI

파이프라인 AI는 봇과 같은 LLM을 쓰지만 놓인 자리가 다르다. 더는 PR이 아니라 머지(병합)이고, 파이프라인은 실제 운영 환경일 수 있는 곳에 배포한다. 이 배포 파이프라인에서 AI가 릴리스 노트를 만들고, 말이 되는지 검증하고, 게시한다.

보안 경계도 이미 설정했다. 시크릿(비밀 값)을 구성했고 AI에게는 일에 필요한 것만 준다. 관측성(observability, 내부 상태를 로그와 지표로 들여다볼 수 있는 성질)은 워크플로 실행 중에 찍는 텔레메트리로 확보하고, 산출물은 조직 정책이 통제한다.

## 4. 클라우드 AI 계층

스택의 마지막 계층이다. 실습은 Microsoft Azure OpenAI를 썼는데 조직이 선호하는 서비스면 무엇이든 되고 원칙은 같다. Azure에 배포했기 때문에 역할 기반 권한 부여, 중앙 집중 과금, 활동 로그, 네트워크 통제, 더 넓은 엔터프라이즈 통합 옵션을 쓸 수 있다.

## 5. 경계를 묻는 질문

핵심은 경계를 아는 것이다. 조직은 어떤 도구가 생태계에서 무슨 일을 하는지 알아야 한다. 팀이 풀어 볼 질문은 다음과 같다.

| 구분 | 질문 |
|---|---|
| 위치 | 어떤 도구가 로컬에서 동작하고 어떤 도구가 네트워크 접근을 요구하는가 |
| 자격 | 어떤 도구가 시크릿이나 토큰을 요구하는가, 기업 수준 인증과 인가를 요구하는가 |
| 영향 | 어떤 도구가 운영에 직접 영향을 줄 수 있는가, 어떤 도구가 순수하게 조언만 하는가 |

시나리오 질문도 유용하다. 내일 Azure OpenAI가 사라지면 무엇이 깨지는가. Copilot 사용을 멈추면 무엇이 달라지는가. 이런 질문은 "AI를 쓴다"는 말에서 한 걸음 더 나아가 생각하게 만든다.

## 6. 핵심 정리

- IDE, PR, 파이프라인, 클라우드 네 계층에 실습 도구를 하나씩 대응시켜 점검한다.
- IDE는 생산성이 좋지만 검토를 건너뛰는 개발자가 있어 위험이 중간이다.
- PR 봇과 파이프라인 AI는 검증 후 수락하는 가드레일로 결정성을 확보했다.
- 파이프라인 AI는 최소 권한 시크릿과 텔레메트리, 조직 정책으로 경계를 둔다.
- 도구별 위치, 자격, 영향 범위를 묻는 질문과 시나리오 질문으로 의존성을 드러낸다.
