# 요약과 핵심 개념

이 장은 네 덩어리로 이뤄진다. AI 도구 지형과 위험 분류, 기존 스택 점검, 가드레일과 감사, 도입 플레이북과 ROI다. 이 문서는 네 덩어리를 한 번에 되짚고 핵심 용어를 정리한다.

원서의 요약은 이렇다. 엔터프라이즈 AI 도구 지형을 살폈고 DevOps에서 책임 있는 AI 사용을 다뤘으며, 거버넌스와 가드레일, AI가 영향을 주는 모든 것의 감사와 책임, 그리고 조직이 AI에 준비됐는지 판단하는 엔터프라이즈 준비 프레임워크를 봤다. AI 통합은 쉽지만 미묘한 문제가 있어 신중하고 전략적으로 다뤄야 하며 직원 교육이 필요하다. 다음 장은 구현으로 넘어간다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 도구 지형 다섯 계층 | 계층별 목적과 위험 수준 분류 |
| 2 | 기존 스택 점검 | IDE, PR, 파이프라인, 클라우드에 실습 도구 대응, 경계 질문 정리 |
| 3 | 가드레일 | 관련성, 안전, PII, 도구 안전장치로 범위 통제 |
| 4 | 감사와 책임 | 추적성, 승인 강제, 정책 검증 우선 |
| 5 | 도입 플레이북 | 범위, 사람 검토, 가드레일, 역할, 성숙도 5단계 |
| 6 | ROI 측정 | 기준선, 전후 비교, 가치 증명 후 확대 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 그림자 AI | 조직이 파악하지 못한 채 퍼진 비공식 AI 사용 |
| 위험 매트릭스 | 계층별 예시, 위험 수준, 엔터프라이즈 적합 여부 표 |
| 클라우드 네이티브 AI | 기업용 LLM 호스팅, 모델 거버넌스, 데이터 거주지 통제를 주는 계층 |
| 가드레일 | 관련성, 안전, PII, 도구 안전장치로 AI를 범위 안에 묶는 장치 |
| 프롬프트 인젝션 | 댓글이나 주석에 숨긴 지시로 AI를 조작하는 공격 |
| 아티팩트 추적성 | AI 산출물을 버전 관리, PR 이력, 승인 기록, 배포 이력으로 추적 |
| 정책 검증 우선 | AI 제안은 조언이고 컴플라이언스 집행은 결정적 정책 엔진이 한다 |
| AI 도입 플레이북 | 사용 범위, 사람 검토, 가드레일, 역할을 정한 운영 지침서 |
| 성숙도 모델 | 비공식에서 엔터프라이즈 최적화까지 5단계 |
| ROI | 파이프라인, 인프라, 운영, 컴플라이언스, 문서화, 유용성 지표로 측정 |
| MTTR | 장애 발생부터 복구까지 평균 걸린 시간 |

## 3. 자주 놓치는 점

- AI를 쓰기 시작하면 위험이 낮다고 볼 수 없다. 최소 중간이다.
- AI는 배포를 직접 트리거할 수 없고, 운영 배포에 자율 동작은 없다.
- AI가 컴플라이언스 게이트를 뒤집으면 안 된다. 집행은 결정적 정책이 한다.
- AI가 만든 워크플로는 자동 머지하지 않고, 브랜치 보호와 환경 승인 게이트를 유지한다.
- 책임은 사람에게 있다. 소유자가 불분명하면 도입이 실패한다.
- 속도가 빨라져도 품질과 거버넌스가 퇴보하면 ROI가 아니다.
- 확대는 기준선 측정과 통제된 시범 뒤에, 가치가 증명된 경우에만 한다.
