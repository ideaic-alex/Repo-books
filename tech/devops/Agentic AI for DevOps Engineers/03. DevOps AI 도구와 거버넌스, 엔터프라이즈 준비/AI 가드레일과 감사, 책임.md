# AI 가드레일과 감사, 책임

AI 출력은 기껏해야 확률적이고, 정책 준수보다 그럴듯함에 맞춰 최적화된다. 그런데 DevOps는 인프라, 파이프라인, 신원, 컴플라이언스, 릴리스 시스템을 다룬다. 블로그 초안이나 마케팅 문구와 달리 실수의 값이 크다. 그래서 가드레일은 선택이 아니라 기본이다. 이 문서는 가드레일의 종류와 적용 대상, 그리고 가드레일이 제대로 작동했음을 증명하는 감사와 책임을 정리한다.

---

## 1. 가드레일이 필요한 이유

- 운영 시스템에는 실제 폭발 반경(blast radius, 사고가 번지는 범위)이 있다.
- 인프라 오류는 장애를 일으킬 수 있다.
- 파이프라인 설정 실수는 시크릿을 유출시킬 수 있다.
- 신원 관련 실수는 권한 상승을 낳을 수 있다.
- 환각(hallucination, 사실이 아닌 내용을 지어냄)은 그럴듯해 보인다.

## 2. 가드레일의 네 가지 형태

| 종류 | 역할 | DevOps 예 |
|---|---|---|
| 관련성 통제 | AI를 범위 안에 묶는다 | 테스트 브랜치 검토 중 운영 YAML을 수정하지 않는다 |
| 안전 통제 | 악성 입력이 AI를 조종하지 못하게 한다 | PR 댓글, 코드 주석, 파이프라인 지시문 속 프롬프트 인젝션 차단 |
| PII와 민감 데이터 보호 | 민감 정보가 AI로 새지 않게 한다 | 프롬프트에 시크릿 금지, Key Vault 연동, 로그 정제 후 전달 |
| 도구 안전장치 | 도구 위험을 평가해 동작을 제한하거나 승인한다 | AI는 워크플로를 제안하되 배포를 직접 트리거하지 못한다 |

### 2-1. 관련성 통제

위험의 예는 AI가 무관한 파이프라인 단계를 고치는 것, 대상 환경 밖의 인프라를 수정하는 것, 의도한 저장소 밖의 변경을 제안하는 것이다. 테스트 브랜치를 검토하는 동안 운영 YAML을 건드리거나 무관한 인프라를 끼워 넣어서는 안 된다. 프롬프트는 의도적으로 범위를 좁혀야 한다. 범위 봉쇄가 첫 번째 엔터프라이즈 안전장치다.

### 2-2. 안전 통제

DevOps에서 프롬프트 인젝션(입력에 숨긴 지시로 AI를 조작하는 공격)은 CI 로직을 바꾸려는 악성 PR 댓글, 코드 주석에 심은 지시, 시크릿을 빼내려는 파이프라인 지시로 나타날 수 있다. 가드레일은 AI가 위험한 내용을 실행하거나 증폭하지 못하게 막아야 한다.

### 2-3. PII와 민감 데이터

PII(개인 식별 정보) 필터는 민감한 정보를 보호한다. 기업 환경에서는 프롬프트에 시크릿이 노출되지 않게 하고, 인프라용 키 보관소(Key Vault) 연동을 빈틈없이 하고, AI 분석에 넘기기 전에 로그를 정제해야 한다.

### 2-4. 도구 안전장치

필수 안전 경계다. AI 도구가 워크플로를 제안할 수는 있지만 배포를 직접 트리거할 수는 없어야 하고, 파이프라인 실행은 시스템이 통제해야 한다.

## 3. 영역별 적용

- 코드형 인프라(IaC): AI가 어울리지 않는 곳에 인프라를 도입하면 안 된다. 인프라 변경 동료 검토, 배포 전 정책 검증, AI 관련 인프라의 자동 머지 금지, 정적 분석과 린팅을 쓴다. AI는 뼈대 작성을 빠르게 하지만 정확성은 사람이 보장한다.
- 파이프라인: 워크플로 전반에 안전한 자동화를 세운다. PR 리뷰 필수, 모든 PR을 한두 명이 검토, 상태 검사 강제, 브랜치 보호가 포함된다. 위험이 악의적 개발자에서 오든 검증 안 된 AI에서 오든 사람이 루프 안에 남도록 정책으로 강제한다.
- 보안과 컴플라이언스: AI가 코드와 환경 설정을 검토하고 취약점을 찾고 일부 환경에서 정책을 집행할 수는 있다. 그러나 발견 사항과 정책의 집행은 결정적이고 정책 기반이어야 한다. 확률적 AI가 컴플라이언스 게이트를 뒤집게 해서는 안 된다.

실용 예로 GitHub Copilot 거버넌스는 다음을 뜻할 수 있다. 생성된 모든 파이프라인 변경을 검토한다. AI가 만든 워크플로는 자동 머지하지 않는다. 브랜치 보호 규칙으로 PR 검사를 우회한 머지를 막는다. 환경에는 승인 게이트를 요구한다. 조직은 현재 AI 태세를 평가해 AI가 감독 없이 움직일 여지가 없도록 해야 한다.

## 4. 감사와 책임

AI는 IaC 초안, 워크플로 제안, PR 리뷰, 컴플라이언스와 취약점 평가, 로그 분석, 관측성 요약, 인시던트(운영 중 장애나 사고) 사후 문서 초안 등에 참여한다. 참여하는 순간 감사, 책임, 운영 감독이 필요해진다.

1. 아티팩트 추적성: AI가 만든 산출물은 모두 버전 관리에 둔다. PR 이력 보존, 리뷰어 승인 기록, 머지 이벤트 추적, 배포 이력 기록이 필요하다. AI가 영향을 준 산출물은 사람이 쓴 코드와 같은 거버넌스 경로를 거친다.
2. 강제된 승인 워크플로: 가드레일이 정한 안전 경계를 유지한다. 승인 워크플로 필수, 브랜치 보호 강제, 환경 배포 전 명시적 승인이 필요하다.
3. AI 판단보다 정책 검증: AI 제안이 컴플라이언스를 우회하지 못하게 하는 원칙이다. AI가 설정을 검토하고 취약점을 짚어도 정책 엔진은 AI 제안과 무관하게 엄격히 준수를 강제한다. AI 분석은 컴플라이언스 엔진을 대체하지 않는다. AI 제안은 조언이고 정책 집행은 결정적이다.

핵심은 가드레일이 AI 위험을 줄이고 감사가 그것이 작동했음을 증명한다는 점이다. 책임은 언제나 사람에게 있다. AI는 DevOps를 가속하지만 소유하지 않는다. 엔터프라이즈 준비에는 모든 수준의 추적성과 집행이 필요하다. Copilot은 돕고, GitHub와 조직 정책이 견제와 균형으로 AI 생성 코드를 통제한다는 원서의 당부를 기억할 만하다.

## 5. 핵심 정리

- 가드레일은 관련성, 안전, PII, 도구 안전장치의 네 형태다.
- IaC, 파이프라인, 보안 각각에 동료 검토, 브랜치 보호, 결정적 정책 집행을 둔다.
- AI 산출물은 버전 관리, PR 이력, 승인 기록, 배포 이력으로 추적한다.
- 정책 집행은 결정적이며 AI가 컴플라이언스 게이트를 넘을 수 없다.
