# 요약과 핵심 개념

이 장은 AI를 파이프라인의 통제된 부분으로 만드는 과정이다. 엔진 준비, 결정적 릴리스 워크플로, 재사용 액션, 입력 다듬기, 비용과 성능, 관측성, 보안, ChatOps 순서로 하나씩 쌓아 올렸다.

원서의 요약은 이렇다. 실제 Azure OpenAI 모델을 프로비저닝해 GitHub Actions에 연결했고, 재사용 컴포지트 액션을 만들고, 결정적 출력 계약을 강제하고, 자동화 전에 모델 동작을 검증하고, 텔레메트리와 관측성을 달고, 보안 경계를 강화하고, 워크플로를 ChatOps로 확장했다. 핵심 사고 전환은 AI가 유용하지만 마법이 아니라 또 하나의 운영 의존성이라는 점이다. 관측성, 가드레일, 적절한 권한, 행동을 제약하는 명확한 계약으로 다뤄야 한다. 다음 장은 한정된 AI 워크플로 단계에서 워크플로 상태를 추론하고 도구를 쓰며 명시적 안전 경계 안에서 동작하는 에이전트로 넘어가고, 이 장의 가드레일이 자율성을 안전하게 높이는 기준선이 된다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | Azure OpenAI 프로비저닝 | gpt-4o-mini 배포, 시크릿 4개를 devops-dev 환경에 저장 |
| 2 | 결정적 워크플로 | release-ai.yml의 수집, 생성, 검증, 초안 게시 사슬 |
| 3 | 컴포지트 액션 | azure-openai-chat 액션으로 호출 로직 재사용 |
| 4 | 입력 복잡도 줄이기 | 자르기, 정화, 필드 축소, 25000바이트 한도 |
| 5 | 비용과 성능 | pr_count 조건, 재시도와 백오프, 토큰 추적, 텔레메트리 |
| 6 | 관측성과 피드백 | 액션 출력, 소프트 경고, 잡 요약 |
| 7 | 보안 패턴 | 시크릿 경계, 인젝션 방어, 최소 권한 |
| 8 | ChatOps | @bot 댓글에 AI 응답을 PR에 게시 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 결정적 AI 단계 | 고정 입력, 버전 관리 프롬프트, 낮은 temperature, 검증, 명확한 실패 동작으로 예측 가능하게 만든 AI 단계 |
| 버전 관리 프롬프트 | 저장소에 들어 있는 프롬프트 파일. 코드처럼 이력이 남는 의존성 |
| temperature | 출력의 무작위성을 정하는 값. 낮을수록 사실적이다(기본 0.1) |
| 컴포지트 액션 | 여러 단계를 묶어 하나의 액션처럼 부르는 GitHub Actions 기능 |
| 생성, 검증, 자동화 | 모델이 만든 출력을 검증한 뒤에만 다음 자동화로 넘기는 패턴 |
| 컨텍스트 엔지니어링 | 모델에 주는 입력을 자르고 정화하고 줄여 통제하는 일 |
| 지수 백오프 | 재시도마다 대기 시간을 두 배로 늘리는 방식(2초에서 시작, 최대 3회) |
| 소프트 임계값 | 넘어도 실패시키지 않고 경고만 하는 기준(토큰 2000, 10초 예) |
| 텔레메트리 | 호출 시간, HTTP 상태, 프롬프트와 완성과 총 토큰, 입력 크기를 담은 ai-telemetry.json |
| 최소 권한 | 워크플로와 잡에 필요한 가장 좁은 권한만 주는 원칙 |
| ChatOps | 채팅이나 PR 댓글로 DevOps 작업을 하는 관행 |

## 3. 자주 놓치는 점

- 결정적이라는 말은 모델이 컴파일된 코드처럼 똑같이 동작한다는 뜻이 아니다.
- 검증 로직은 프롬프트 출력 템플릿과 함께 바꿔야 한다. 하나만 바꾸면 계약이 깨진다.
- 로컬 액션 경로는 `./.github/azure-openai-chat`이어야 한다. 틀리면 워크플로가 처음에 실패한다.
- main에 직접 푸시하면 PR 메타데이터가 없어 초안 릴리스가 비어 있다. pr_count 조건으로 AI 호출을 건너뛴다.
- 액션 출력을 선언만 하고 GITHUB_OUTPUT에 쓰지 않으면 값이 비어 요약에 나오지 않는다(http_status 사례).
- 후속 단계가 steps.aoai.outputs를 읽으므로 단계 ID를 바꾸면 경고와 요약도 고쳐야 한다.
- ChatOps 워크플로는 기본 브랜치에 머지된 뒤에야 테스트할 수 있다.
- 토큰은 만든 직후에만 보이고, 이름은 워크플로가 참조하는 GH_CHATOPS_TOKEN과 정확히 같아야 한다.
- 안전한 통합의 핵심은 AI가 배포, YAML 수정, 자동 머지, 검증 우회를 하지 못하게 경계를 설계하는 것이다.
