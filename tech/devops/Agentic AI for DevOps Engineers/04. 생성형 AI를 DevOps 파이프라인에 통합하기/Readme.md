# 생성형 AI를 DevOps 파이프라인에 통합하기

이 장은 3장의 거버넌스를 실제 구현으로 옮긴다. Azure OpenAI 모델을 프로비저닝해 GitHub Actions에 연결하고, AI가 만드는 릴리스 노트를 결정적(예측 가능한) 단계로 통제한다. AI 호출은 재사용 가능한 컴포지트 액션 하나로 모은다.

이어서 입력 복잡도 줄이기, 비용과 성능 관리, 관측성과 피드백, 안전한 통합 패턴을 차례로 더하고, 마지막으로 PR 댓글에서 동작하는 AI 증강 ChatOps 봇까지 확장한다. 핵심 관점은 AI가 마법이 아니라 또 하나의 운영 의존성이라는 것이다. 실습 코드는 Packt 저장소의 finish 디렉터리를 따르며 비밀 값은 자리표시자로만 다룬다.

---

## 1. 핵심 요점

- 엔진은 Azure OpenAI(gpt-4o-mini 배포)이며, 배포 이름, 엔드포인트, 키를 devops-dev 환경 시크릿에 넣어 하드코딩을 피한다.
- 결정적이란 고정 입력, 버전 관리 프롬프트, 낮은 temperature(0.1), 통제된 맥락, 명시적 검증, 명확한 실패 동작의 조합이다.
- 릴리스 워크플로는 수집, 생성, 검증, 초안 게시의 잡 사슬이며, 생성 후 검증을 통과해야 자동화가 이어진다.
- 컴포지트 액션 `.github/azure-openai-chat`이 모델 호출, 재시도, 파일 쓰기, 텔레메트리를 한곳에 모아 릴리스와 ChatOps가 함께 쓴다.
- 입력은 제목 200자, 본문 1200자로 자르고 백틱을 정화하며 25000바이트 한도를 호출 전에 강제한다.
- 처리할 PR이 없으면 AI 잡을 건너뛰고, 실패는 최대 3회 지수 백오프로 재시도하고, 토큰과 호출 시간을 기록한다.
- 텔레메트리는 액션 출력, 소프트 경고, 잡 요약으로 노출해 AI를 관찰 가능한 의존성으로 만든다.
- 보안 통제는 시크릿 경계, 프롬프트 인젝션 방어, 입력 크기, 결정적 출력, 최소 권한이며 AI는 배포, 자동 머지, 검증 우회를 할 수 없다.
- ChatOps는 `issue_comment` 트리거와 `@bot` 조건으로 돌고, 응답 게시용 토큰은 단일 저장소와 최소 권한으로 만든다.
