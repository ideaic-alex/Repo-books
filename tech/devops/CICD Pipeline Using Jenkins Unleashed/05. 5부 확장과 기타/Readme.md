# 5부 개요 (Part V): 확장과 기타

프라노데이 딩가레(Pranoday Pramod Dingare)의 『CI/CD Pipeline Using Jenkins Unleashed』 5부는 17장부터 20장까지 네 개 장으로, 앞 부분에서 만든 Jenkins 환경을 넓히고 자동화하는 방법을 다룬다. 한 대의 머신에서 벗어나 여러 머신으로 빌드를 나누고(17장), 클라우드 서버에 배포하며(18장), 화면 없이 명령줄과 API, 파이썬으로 Jenkins를 조작하고(19~20장), 파이프라인 코드를 공유 라이브러리로 재사용하는 방법(20장)까지 이어진다.

이 노트는 번역이 아니라 책의 내용을 풀어 다시 정리한 학습 노트다. 화면과 설정은 2021년경의 Jenkins, AWS 기준이고, 책에 없는 보충은 `참고(노트 작성자)`로 따로 표시했다.

> **이 부를 한 문장으로**
> 한 대짜리 Jenkins를 여러 머신과 클라우드로 넓히고, 사람의 손 대신 명령줄·API·라이브러리로 움직이게 만드는 확장 편이다.

---

## 0. 먼저 알아 둘 것

- **Jenkins job**: 앞 부분에서 만든 프리스타일 job과 파이프라인 job. 5부는 이들을 다른 머신, 다른 도구로 실행하는 방법을 다룬다.
- **SSH 키 쌍**: 공개키와 개인키 한 쌍. 17장(에이전트 연결), 18장(EC2 접속), 19장(CLI 인증)에서 반복해 쓴다.
- **API 토큰**: 비밀번호 대신 사용자를 인증하는 값. 19~20장의 CLI와 REST 호출에서 쓴다.
- **보안 값 주의**: 책의 예제에는 IP, 토큰, 시크릿 같은 값이 나오지만 이 노트에서는 모두 자리표시자로 적었다.

## 2. 5부에 자주 나오는 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 컨트롤러(마스터) | Jenkins가 설치되어 작업을 분배하는 머신(책은 master라 부른다) |
| 에이전트(슬레이브) | 컨트롤러가 맡긴 빌드 단계를 실행하는 머신 |
| 라벨(Label) | 여러 에이전트를 묶어 job이 고를 수 있게 하는 이름 |
| JNLP | 에이전트가 컨트롤러에 먼저 접속하는 연결 방식 |
| EC2 | AWS에서 시간 단위로 빌리는 가상 서버 |
| 보안 그룹 | EC2로 들어오는 포트를 허용하거나 막는 규칙 모음 |
| `scp` | SSH로 파일을 원격 머신에 복사하는 명령 |
| CLI | 명령줄로 Jenkins를 조작하는 인터페이스, 클라이언트는 `jenkins-cli.jar` |
| REST API | HTTP로 Jenkins 기능을 호출하는 방식 |
| 공유 라이브러리 | 여러 파이프라인이 가져다 쓰는 Groovy 코드 모음 |

## 3. 5부의 흐름

1. **규모 키우기(17장)**: 빌드를 여러 에이전트에 나누어 시간, 설치 부담, 환경 다양성 문제를 푼다.
2. **클라우드로 나가기(18장)**: 에이전트가 아니라 배포 대상 서버를 AWS에 두고, 파일 복사와 테스트를 job 하나의 흐름으로 잇는다.
3. **손을 떼기(19~20장)**: 화면 조작을 CLI, REST API, 파이썬으로 바꿔 스크립트에서 Jenkins를 제어한다.
4. **중복 없애기(20장)**: 파이프라인의 공통 단계를 공유 라이브러리로 모아 여러 프로젝트에 재사용한다.
