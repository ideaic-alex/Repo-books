# 핵심 정리

이 문서는 3부(10장부터 13장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 책의 화면은 2021년경 Jenkins 기준이며, 노트 작성자의 보충은 각 장에 `참고(노트 작성자)`로 표시했다.

---

## 1. 한눈에 보는 요점

- **잡은 트리거, 빌드 단계, 빌드 후 동작으로 이루어진다**: 언제 시작하고, 무엇을 실행하고, 끝난 뒤 무엇을 할지를 정하며, 한 번 실행한 기록이 빌드다.
  - *쉽게 말하면*: 잡은 지시서, 빌드는 그 지시서를 한 번 수행한 결과다.
  - → 자세히: [10장 잡 이해](10%EC%9E%A5%20%EC%9E%A1%20%EC%9D%B4%ED%95%B4.md)
- **General 설정과 트리거 선택이 잡의 성격을 정한다**: 오래된 빌드 삭제, 동시 실행, 조용한 기간, 작업 공간, 그리고 원격 호출, 선행 잡 완료, 주기 실행, SCM 폴링 중 어떤 트리거를 쓸지가 핵심이다.
  - *쉽게 말하면*: 몇 개의 체크박스와 입력 칸이 잡이 언제 어떻게 돌지를 좌우한다.
  - → 자세히: [10장 잡 이해](10%EC%9E%A5%20%EC%9E%A1%20%EC%9D%B4%ED%95%B4.md)
- **비공개 저장소는 Jenkins에 자격 증명을 명시해야 한다**: 내 PC의 Windows 자격 증명에 기대면 설정이 맞는 것처럼 보이다가 원인을 알기 어려운 오류가 난다.
  - *쉽게 말하면*: 내 컴퓨터에서 되는 것과 Jenkins가 되는 것은 별개다.
  - → 자세히: [10장 잡 이해](10%EC%9E%A5%20%EC%9E%A1%20%EC%9D%B4%ED%95%B4.md)
- **Maven은 생명주기 단계를 순서대로 자동화한다**: 컴파일, 테스트 컴파일, 단위 테스트, 패키징, 설치, 배포 순이며, 한 단계를 실행하면 앞 단계가 모두 실행된다.
  - *쉽게 말하면*: `mvn package` 한 줄이 컴파일부터 JAR 생성까지 맡는다.
  - → 자세히: [11장 Maven으로 Java API 프로젝트 준비](11%EC%9E%A5%20Maven%EC%9C%BC%EB%A1%9C%20Java%20API%20%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%20%EC%A4%80%EB%B9%84.md)
- **`pom.xml`과 `settings.xml`이 빌드의 설정을 담는다**: `GroupId`, `ArtifactId`, `Version`으로 산출물을 식별하고, 의존성과 플러그인은 `pom.xml`에, 로컬 저장소 위치와 프록시, 서버 계정은 `settings.xml`에 둔다.
  - *쉽게 말하면*: 프로젝트 설정은 `pom.xml`, 내 환경 설정은 `settings.xml`이다.
  - → 자세히: [11장 Maven으로 Java API 프로젝트 준비](11%EC%9E%A5%20Maven%EC%9C%BC%EB%A1%9C%20Java%20API%20%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%20%EC%A4%80%EB%B9%84.md)
- **소스는 Git, 산출물은 Nexus에 보관한다**: 분산 버전 관리인 Git으로 브랜치와 병합을 다루고, 조직 내부용 Nexus의 호스티드 저장소에 JAR를 올린다. Maven의 배포 대상 `id`는 `pom.xml`과 `settings.xml`이 일치해야 한다.
  - *쉽게 말하면*: 코드의 서랍과 결과물의 서랍을 따로 두고 Maven이 둘을 오간다.
  - → 자세히: [12장 Maven·Nexus 연동과 프리스타일 잡 릴리스](12%EC%9E%A5%20Maven%C2%B7Nexus%20%EC%97%B0%EB%8F%99%EA%B3%BC%20%ED%94%84%EB%A6%AC%EC%8A%A4%ED%83%80%EC%9D%BC%20%EC%9E%A1%20%EB%A6%B4%EB%A6%AC%EC%8A%A4.md)
- **프리스타일 잡이 `mvn deploy`로 릴리스를 대신한다**: Maven 설치 경로를 `Global Tool Configuration`에 등록하고 `Invoke top-level Maven targets`의 `Goals`에 `deploy`를 넣는다.
  - *쉽게 말하면*: 사람이 하던 배포 명령을 Jenkins가 대신 입력한다.
  - → 자세히: [12장 Maven·Nexus 연동과 프리스타일 잡 릴리스](12%EC%9E%A5%20Maven%C2%B7Nexus%20%EC%97%B0%EB%8F%99%EA%B3%BC%20%ED%94%84%EB%A6%AC%EC%8A%A4%ED%83%80%EC%9D%BC%20%EC%9E%A1%20%EB%A6%B4%EB%A6%AC%EC%8A%A4.md)
- **SSH 인증은 키 쌍으로 접속 기기를 제한한다**: 공개 키만 GitLab에 등록하고, Jenkins에는 `SSH Username with private key` 자격 증명으로 개인 키를 넣는다.
  - *쉽게 말하면*: 열쇠(개인 키)를 가진 기기만 문(저장소)을 연다.
  - → 자세히: [13장 자동 트리거 프리스타일 잡](13%EC%9E%A5%20%EC%9E%90%EB%8F%99%20%ED%8A%B8%EB%A6%AC%EA%B1%B0%20%ED%94%84%EB%A6%AC%EC%8A%A4%ED%83%80%EC%9D%BC%20%EC%9E%A1.md)
- **폴링과 메일 알림으로 병합에서 배포까지 자동화한다**: `Poll SCM`이 5분마다 `master`를 확인해 변경이 있으면 빌드하고, 테스트가 실패하면 `E-mail Notification`이 알린다.
  - *쉽게 말하면*: 병합하면 알아서 배포되고, 깨지면 메일로 알려 준다.
  - → 자세히: [13장 자동 트리거 프리스타일 잡](13%EC%9E%A5%20%EC%9E%90%EB%8F%99%20%ED%8A%B8%EB%A6%AC%EA%B1%B0%20%ED%94%84%EB%A6%AC%EC%8A%A4%ED%83%80%EC%9D%BC%20%EC%9E%A1.md)

## 2. 3부를 관통하는 질문

| 질문 | 3부가 보여 주는 답 |
|------|-------------------|
| 잡은 무엇으로 구성되나? | 트리거, 빌드 단계, 빌드 후 동작 |
| Java 라이브러리는 어떻게 빌드하나? | Maven 생명주기: 컴파일, 테스트, 패키징 |
| 완성된 JAR는 어디로 가나? | `mvn deploy`로 Nexus 호스티드 저장소에 |
| 사람 손 없이 릴리스하려면? | `Poll SCM` 트리거와 Maven `deploy` 단계 |
| 실패는 어떻게 알리나? | 이메일 알림 (SMTP 설정 필요) |
