# 3부 개요 (Part III) 잡과 Java 릴리스

프라노데이 딩가레(Pranoday Pramod Dingare)의 『CI/CD Pipeline Using Jenkins Unleashed』 3부는 10장부터 13장까지 네 개 장으로, 앞부분에서 익힌 Jenkins 개념을 실제 프로젝트에 적용하기 시작하는 부분이다. 프리스타일 잡의 설정 항목을 익히고, Maven으로 Java 라이브러리를 빌드하고, Git과 Nexus를 붙여 릴리스하고, 마지막으로 코드 병합만으로 자동 배포되는 잡을 완성한다.

이 노트는 번역이 아니라 책의 내용을 풀어 다시 정리한 학습 노트다. 책의 화면과 설정은 2021년경 Jenkins 기준이므로 최신 버전과 다를 수 있고, 노트 작성자의 보충은 `참고(노트 작성자)`로 따로 표시했다.

> **이 부를 한 문장으로**
> 잡이라는 작업 지시서를 이해한 뒤, 코드 저장소에서 소스를 받아 Maven으로 빌드하고 Nexus에 JAR를 올리는 일을 손으로 한 번, 자동으로 한 번 해 보는 이야기다.

---

## 0. 먼저 알아 둘 것

- **잡(job)과 빌드(build)**: 잡은 설정 묶음, 빌드는 그 잡을 한 번 실행한 기록이다.
- **프리스타일 잡**: 화면에서 항목을 채워 만드는 가장 기본적인 잡 유형이다.
- **Maven**: Java 프로젝트의 컴파일, 테스트, 패키징, 배포를 순서대로 처리하는 빌드 도구다.
- **Git과 GitLab**: 소스 코드의 버전을 관리하는 도구와 그 중앙 저장소 서비스다.
- **Nexus**: 빌드 산출물(JAR 등)을 보관하고 배포하는 아티팩트 저장소다.

## 2. 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 트리거(trigger) | 잡을 언제 시작할지 정하는 조건 |
| 빌드 단계(build step) | 잡이 실제로 실행하는 명령 |
| 작업 공간(workspace) | 빌드가 실행되고 소스가 체크아웃되는 디렉터리 |
| 산출물(artifact) | 빌드 결과로 나온 파일(JAR, WAR 등) |
| 업스트림/다운스트림 | 산출물을 주는 잡과 받아 쓰는 잡 |
| 아키타입(archetype) | 프로젝트 유형별 폴더 구조를 만들어 주는 Maven 틀 |
| POM | Maven 프로젝트 정보를 담은 `pom.xml` |
| 호스티드 저장소 | 조직이 직접 운영하며 산출물을 올리는 Nexus 저장소 |
| SCM 폴링 | Jenkins가 일정 간격으로 저장소 변경을 확인하는 방식 |
| SSH 키 쌍 | 개인 키와 공개 키로 접속자를 확인하는 인증 방식 |

## 3. 이 부의 흐름

3부 전체는 다음 순서로 흐른다.

1. **코드**: 개발자가 Eclipse에서 코드와 단위 테스트를 만들고 Git으로 GitLab에 올린다(11장, 12장).
2. **빌드**: Jenkins 잡이 코드를 내려받아 Maven으로 컴파일, 테스트, 패키징한다(10장, 11장).
3. **저장소 릴리스**: 테스트가 통과하면 JAR를 Nexus에 배포하고, 13장에서는 병합이 이 모든 과정을 자동으로 시작시킨다.
