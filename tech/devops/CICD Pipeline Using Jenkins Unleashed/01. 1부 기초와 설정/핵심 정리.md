# 핵심 정리

이 문서는 1부(1장부터 6장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 책의 Jenkins 버전과 화면은 2021년경 기준이다.

---

## 1. 한눈에 보는 요점

- **병합을 한꺼번에 하면 문제가 커진다**: 애자일에서 하루치 변경을 몰아서 합치면 회귀·통합 결함과 충돌이 생기고 원인 찾기가 오래 걸린다.
  - *쉽게 말하면*: 숙제를 마지막 날 몰아 내면 어디서 틀렸는지 찾기 어렵다.
  - → 자세히: [1장 CI·CD 이해](01%EC%9E%A5%20CI%C2%B7CD%20%EC%9D%B4%ED%95%B4.md)
- **CI는 병합, 컴파일, 테스트, 배포 준비를 자주 반복한다**: 테스트 먼저 쓰는 TDD, 병합 후 컴파일과 통합 테스트, 아티팩트 배포, E2E 테스트가 한 흐름이다.
  - *쉽게 말하면*: 조금씩 합치고 그때마다 자동 점검한다.
  - → 자세히: [1장 CI·CD 이해](01%EC%9E%A5%20CI%C2%B7CD%20%EC%9D%B4%ED%95%B4.md)
- **Jenkins는 여러 도구를 엮어 이 흐름을 자동으로 돌린다**: Hudson에서 갈라져 나온 오픈소스 서버이며, 잡이 가져오기부터 알림까지 순서대로 수행하고 한 단계가 실패하면 뒤는 실행되지 않는다.
  - *쉽게 말하면*: 사람이 하던 빌드와 검증 심부름을 자동화한 지휘자다.
  - → 자세히: [2장 Jenkins 소개](02%EC%9E%A5%20Jenkins%20%EC%86%8C%EA%B0%9C.md)
- **설치는 세 갈래, 살림은 JENKINS_HOME에 모인다**: MSI, WAR, Docker 중 고르고, 지원 Java는 JDK 8/11이다. 설정, 플러그인, 잡, 빌드 로그가 JENKINS_HOME에 있고 `jenkins.xml`로 Java 경로를 바꿀 수 있다.
  - *쉽게 말하면*: 어떻게 깔든 모든 자료는 한 폴더에 쌓인다.
  - → 자세히: [3장 Jenkins 설치](03%EC%9E%A5%20Jenkins%20%EC%84%A4%EC%B9%98.md)
- **서버 시작 방법마다 주소·포트 바꾸는 곳이 다르다**: WAR는 명령 옵션, Windows 서비스는 jenkins.xml, Docker는 포트 포워딩, Linux는 HTTP_PORT 설정이다.
  - *쉽게 말하면*: 켜는 방식이 다르면 포트를 고치는 곳도 다르다.
  - → 자세히: [4장 Jenkins 설정](04%EC%9E%A5%20Jenkins%20%EC%84%A4%EC%A0%95.md)
- **계정을 잊으면 보안을 잠시 끄고 복구한다**: `config.xml`의 `useSecurity`를 false로 하고 들어가 사용자를 지운 뒤 새 관리자를 만들고, 권한을 다시 `Logged-in users can do anything`으로 닫는다.
  - *쉽게 말하면*: 문을 잠시 열고 들어가 열쇠를 새로 만든 뒤 다시 잠근다.
  - → 자세히: [4장 Jenkins 설정](04%EC%9E%A5%20Jenkins%20%EC%84%A4%EC%A0%95.md)
- **플러그인은 Plugin Manager 네 탭으로 관리한다**: `Updates`, `Available`, `Installed`, `Advanced`로 갱신, 설치, 삭제·비활성화, 프록시·수동 업로드를 한다.
  - *쉽게 말하면*: 부품 갈아 끼우는 창구다.
  - → 자세히: [5장 플러그인 관리](05%EC%9E%A5%20%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8%20%EA%B4%80%EB%A6%AC.md)
- **설치 오류는 원인별로 풀 수 있다**: SHA-1 오류는 `Check Now`와 프록시 설정, PKIX 오류는 http 전환·Java 최신화·최신 JDK에서 WAR 실행으로 푼다. 지원 외 Java는 설치 후 JDK 8/11로 되돌린다.
  - *쉽게 말하면*: 오류 메시지가 원인을 알려 준다.
  - → 자세히: [5장 플러그인 관리](05%EC%9E%A5%20%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8%20%EA%B4%80%EB%A6%AC.md)
- **Maven과 JDK는 Global Tool Configuration에 등록한다**: 있으면 경로를, 없으면 설치기를 설정한다. Maven의 사용자 `settings.xml` 값이 전역 값보다 우선한다.
  - *쉽게 말하면*: 도구가 어디 있는지, 없으면 어디서 받을지 적어 둔다.
  - → 자세히: [6장 전역 도구 설정](06%EC%9E%A5%20%EC%A0%84%EC%97%AD%20%EB%8F%84%EA%B5%AC%20%EC%84%A4%EC%A0%95.md)

## 2. 1부를 관통하는 질문

| 질문 | 1부가 보여 주는 답 |
|------|-------------------|
| CI/CD는 왜 필요한가? | 변경을 몰아서 합칠 때 생기는 결함과 원인 찾기 부담을 줄이려고 |
| Jenkins는 무엇을 하나? | 가져오기, 컴파일, 테스트, 패키징, 배포, 알림을 순서대로 자동화 |
| 한 단계가 실패하면? | 그 결과에 의존하는 뒤 단계는 실행되지 않고 빌드가 실패 |
| Jenkins의 자료는 어디에? | `JENKINS_HOME` 폴더 |
| 외부 도구는 어떻게 연결하나? | 플러그인과 전역 도구 설정 |

> **1부 한 줄 요약**
> CI/CD로 변경을 자주 검증하자는 생각을 Jenkins로 구현하기 위해, 설치, 서버 시작과 계정 관리, 플러그인, Maven·JDK 등록까지 기본 환경을 준비하는 단계다.
