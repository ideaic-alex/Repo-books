# 핵심 정리

이 문서는 4부(14장부터 16장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 화면 이름과 설정은 책이 쓰인 2021년경 Jenkins 기준이다.

---

## 1. 한눈에 보는 요점

- **파이프라인은 빌드 절차를 코드로 적은 것이다**: 코드 공유, 재시작 내구성, 일시 정지, 분기와 병렬, 확장성이 프리스타일 잡보다 나은 점이다.
  - *쉽게 말하면*: 클릭 설정을 글로 적은 레시피로 바꾼 것이다.
  - → 자세히: [14장 Jenkins 파이프라인 이해](14%EC%9E%A5%20Jenkins%20%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8%20%EC%9D%B4%ED%95%B4.md)
- **선언형은 `pipeline`, 스크립트형은 `node` 블록이다**: 선언형은 정해진 틀 안에 `agent`, `stages`, `steps`를 두고, 스크립트형은 Groovy를 자유롭게 쓴다. 개념은 pipeline > node > stage > step의 포함 관계다.
  - *쉽게 말하면*: 양식이 있는 신청서와 자유 서술 보고서의 차이다.
  - → 자세히: [14장 Jenkins 파이프라인 이해](14%EC%9E%A5%20Jenkins%20%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8%20%EC%9D%B4%ED%95%B4.md)
- **`Snippet Generator`가 문법 부담을 덜어 준다**: 화면에서 `git`, `bat` 같은 step의 값을 채우면 코드 줄을 만들어 준다.
  - *쉽게 말하면*: 문법을 외우지 않고 양식에 값만 채우면 코드가 나온다.
  - → 자세히: [14장 Jenkins 파이프라인 이해](14%EC%9E%A5%20Jenkins%20%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8%20%EC%9D%B4%ED%95%B4.md)
- **배포 잡과 테스트 잡을 나누고 매개변수로 잇는다**: 상위 잡이 폴링으로 시작해 웹 앱을 배포하고, `TestType` 값을 하위 잡에 넘겨 전체, 회귀, 스모크 중 돌릴 테스트를 정한다.
  - *쉽게 말하면*: 배포 담당이 테스트 담당에게 "이번엔 어떤 테스트를 하자"고 쪽지를 넘긴다.
  - → 자세히: [15장 웹 애플리케이션 프로젝트 잡](15%EC%9E%A5%20%EC%9B%B9%20%EC%95%A0%ED%94%8C%EB%A6%AC%EC%BC%80%EC%9D%B4%EC%85%98%20%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%20%EC%9E%A1.md)
- **UI 테스트와 보고서 메일이 자동화 흐름의 끝을 맺는다**: Selenium과 `pytest`로 화면 테스트를 하고, `Email Extension`으로 HTML 보고서를 첨부해 보낸다. 파이프라인에서는 `try`/`finally`로 실패해도 알림을 보장한다.
  - *쉽게 말하면*: 테스트가 끝나면 결과 보고서가 알아서 메일함에 도착한다.
  - → 자세히: [15장 웹 애플리케이션 프로젝트 잡](15%EC%9E%A5%20%EC%9B%B9%20%EC%95%A0%ED%94%8C%EB%A6%AC%EC%BC%80%EC%9D%B4%EC%85%98%20%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%20%EC%9E%A1.md)
- **API 토큰은 비밀번호 자리에 쓰는 비밀 문자열이다**: GitHub와 GitLab에서 만들고, Jenkins에서는 `Username with password` 자격 증명에 넣는다.
  - *쉽게 말하면*: 비밀번호 대신 쓰는 출입증이며 한 번만 보여 주므로 따로 보관해야 한다.
  - → 자세히: [16장 Pipeline as Code](16%EC%9E%A5%20Pipeline%20as%20Code.md)
- **Jenkinsfile은 빌드 절차를 소스와 함께 관리하게 한다**: 리뷰, 변경 이력, 공유가 쉬워지고, 잡은 `Pipeline script from SCM`으로 저장소의 파일을 읽는다. 선언형의 `post` 블록으로 성공과 실패 후처리를 나눈다.
  - *쉽게 말하면*: 레시피를 주방 벽이 아니라 소스 저장소 안에 넣어 둔다.
  - → 자세히: [16장 Pipeline as Code](16%EC%9E%A5%20Pipeline%20as%20Code.md)
- **웹훅은 저장소가 먼저 Jenkins를 부르는 방식이다**: 폴링과 달리 푸시 같은 이벤트가 URL로 요청을 보내 즉시 빌드를 시작하게 한다. 외부 저장소가 Jenkins에 닿으려면 공인 IP와 포트 포워딩이 필요하다.
  - *쉽게 말하면*: 주기적으로 확인하는 대신 초인종이 울리면 나가 본다.
  - → 자세히: [16장 Pipeline as Code](16%EC%9E%A5%20Pipeline%20as%20Code.md)

## 2. 4부를 관통하는 질문

| 질문 | 4부가 보여 주는 답 |
|------|-------------------|
| 왜 파이프라인인가? | 빌드 절차를 코드로 공유하고 재사용하며 복잡한 흐름까지 담을 수 있다 |
| 두 문법은 어떻게 고르나? | 정해진 틀이 필요하면 선언형, 자유로운 제어가 필요하면 스크립트형이다 |
| 여러 잡은 어떻게 잇나? | 상위 잡이 하위 잡을 호출하며 매개변수로 값을 넘긴다 |
| 절차를 어디에 두나? | 화면 대신 저장소의 Jenkinsfile에 두면 리뷰와 이력이 따라온다 |
| 빌드는 언제 시작되나? | 수동, 폴링, 상위 잡 호출, 웹훅 푸시 이벤트 중에서 고른다 |

---

> **4부 한 줄 요약**
> 화면 클릭으로 만들던 빌드를 코드로 옮기고, 그 코드를 저장소에 함께 두어 푸시 한 번이 배포와 테스트와 알림까지 이어지게 만드는 것이 4부의 큰 줄기다.
