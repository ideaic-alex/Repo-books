# 연습 문제

18장 끝에 실린 실습 다섯 가지를 풀어 쓴 것이다. 모두 직접 손으로 해 봐야 감이 오는 문제라서, 각 문제마다 문제의 취지와 풀이 방향을 함께 적는다. 실습은 되도록 버려도 되는 연습용 저장소에서 한다.

---

## 1. 실패한 셸 호출 추적하기

`transcript.jsonl` 같은 세션 기록을 열어서, `jq`로 `run_shell` 도구 호출만 모두 뽑아 보자. 그중 어떤 호출이 실패했는지 찾고, 에이전트가 그 실패를 알아챘는지까지 확인하는 것이 목표다.

풀이 방향은 `tool_call`에서 `name`이 `run_shell`인 항목을 거른 다음, `id`와 `call_id`로 짝지어 `tool_result`의 `ok` 값을 보는 것이다. `ok: true`인데 출력에 에러가 들어 있는 조용한 실패도 놓치지 않도록, 출력 내용까지 같이 본다. 에이전트가 실패 직후 어떻게 반응했는지는 다음 호출 내용으로 판단한다.

## 2. 중첩된 AGENTS.md 로딩 확인하기

저장소 루트와 하위 디렉터리에 서로 겹치는 내용의 AGENTS.md를 각각 만든다. 하위 디렉터리에서 `RUST_LOG=codex_core=debug codex`를 실행해, 두 파일이 모두 로드되는지 확인한다.

풀이 방향은 출력의 `agents_md: found ...` 줄이 두 파일을 모두 가리키는지, 마지막 `loaded N file(s)` 줄의 개수가 맞는지 보는 것이다. 한쪽만 나오면 경로와 파일 이름 대소문자, 인코딩부터 의심한다.

## 3. 불충분한 프롬프트에서 회복하기

일부러 모호하게 쓴 프롬프트를 연습용 저장소에서 Codex CLI에 준다. 두세 턴쯤 돌게 둔 뒤 중단하고, 기록을 살펴서 더 나은 프롬프트를 써 본다.

풀이 방향은 먼저 Ctrl-C를 한 번만 눌러 깨끗하게 멈추고, 변경이 생겼다면 `git stash`로 보관하는 것이다. 롤아웃에서 에이전트가 무엇을 짐작해서 채웠는지(파일 선택, 가정한 기술 등)를 찾아 그 부분을 새 프롬프트에 명시한다.

## 4. 어긋난 지점 찾기

`RUST_LOG=debug`로 실패할 것 같은 작업을 추적한다. 디버그 출력을 저장하고, 에이전트의 판단이 잘못된 정확한 지점을 짚는다. 도구 호출 순서와 실패로 이어진 결정을 함께 기록한다.

풀이 방향은 로그를 `2>debug.log`로 저장한 뒤 `grep 'ERROR\|WARN'`과 도구 호출 디스패치 줄을 시간순으로 읽는 것이다. 기대한 결과가 마지막으로 나온 호출을 찾고, 그다음 호출에서 에이전트가 무엇을 믿고 움직였는지 적는다.

## 5. 모델 사용 가능 여부 확인하기

`codex debug models`를 실행해 출력과 `config.toml`에 지정한 모델을 비교한다. 모델이 없다면 설정을 사용 가능한 모델로 바꾸고, 세션이 정상적으로 시작되는지 확인한다.

풀이 방향은 `codex debug models | grep <모델 이름>`으로 존재 여부를 확인하는 것이다. 없으면 목록에서 대체 모델을 골라 `config.toml`을 고치고, `codex doctor`나 짧은 세션으로 시작이 되는지 확인한다.
