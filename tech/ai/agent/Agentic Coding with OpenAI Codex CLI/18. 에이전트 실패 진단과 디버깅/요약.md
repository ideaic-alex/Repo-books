# 요약

18장의 핵심을 열 가지로 묶은 것이다. 세션 기록 읽기부터 진단 체크리스트까지, 장 전체를 빠르게 되짚을 때 쓴다.

---

## 1. 장 요약 열 가지

1. **세션 기록이 가장 기본적인 도구다.** `~/.codex/sessions/`의 JSONL 롤아웃 파일에는 일어난 일이 전부 기록된다. 끝에서부터 거꾸로 읽어 어긋난 지점을 찾고, `jq`로 도구 호출 분포를 세거나 승인 결정을 뽑는다.
2. **TUI 안에서 바로 하는 진단.** `/status`, `/debug-config`, `/feedback`은 각각 세션 설정, 해석된 설정 스택, 제출 가능한 진단 맥락을 TUI를 떠나지 않고 보여 준다. `-a untrusted -s read-only`로 실행하면 에이전트가 아무것도 실행하기 전에 의도를 확인할 수 있다.
3. **AGENTS.md는 조용히 실패한다.** 로드 여부를 가장 믿을 만하게 확인하는 방법은 debug 수준의 `RUST_LOG` 추적이다. 흔한 원인은 잘못된 디렉터리, 인코딩 문제, 너무 깊이 묻힌 지침이다.
4. **세션 전에 오프라인으로 검증한다.** `codex sandbox`는 에이전트와 똑같은 제한 아래에서 명령을 돌려 보고(macOS는 `--log-denials`), `codex execpolicy check`는 Starlark `.rules` 파일이 제안된 명령에 어떤 결정을 내리는지 확인한다. 둘 다 세션을 시작하지 않는다.
5. **추적과 모델 점검.** `codex_core`, `codex_exec`, `codex_sandbox` 같은 모듈별 `RUST_LOG` 대상으로 한 서브시스템부터 전체 debug 추적까지 단계적으로 볼 수 있다. `codex debug models`는 기업 프록시나 조직 제한 뒤에서 내 자격 증명으로 닿는 모델을 알려 준다.
6. **컨텍스트 과부하와 품질 저하.** 주제 이탈, 도구 호출 루프, 지어낸 파일 이름은 컨텍스트 윈도가 찼다는 신호이고, 긴 세션에서는 코드 품질이 떨어진다. 주기적인 `/compact`, PostToolUse 품질 점검 훅, 세션 길이 제한으로 대응한다.
7. **깨끗하게 중단하고 신중하게 복구한다.** Ctrl-C는 한 번만 누르고, `git stash`로 에이전트의 변경을 보존해 필요한 것만 골라 되살린다.
8. **에이전트의 로깅 공백.** 에이전트는 기본적으로 로그를 적게 남긴다. 사람 개발자는 일하는 과정에서 콘솔 출력과 커밋 메시지가 부수적으로 남지만, 에이전트는 작업 완료에 최적화되어 있어서 지시하지 않으면 관측성을 건너뛴다. AGENTS.md 지침('주요 결정은 모두 stdout에 기록하라')과 PostToolUse 훅으로 로깅을 강제한다.
9. **3단계 관측 스택.** 로컬 롤아웃 파일, OpenAI Platform Traces, OTLP 내보내기는 서로 보완한다. 로컬 파일은 감사와 재생, 플랫폼 트레이스는 시각적 탐색, OTLP는 팀 단위 대시보드와 알림에 쓴다.
10. **체크리스트는 위에서 아래로.** 다 안 풀리면 싼 점검부터 한다. 설정, 인증, 샌드박스, 규칙, 모델, 추적, 롤아웃, 피드백 순이다.
