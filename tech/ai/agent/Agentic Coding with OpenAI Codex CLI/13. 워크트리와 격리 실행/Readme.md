# 워크트리와 격리 실행

12장이 에이전트를 어떤 순서로 돌릴지 다뤘다면, 이 장은 에이전트를 어디서 돌릴지를 다룬다. 두 에이전트가 같은 소스 트리에 동시에 쓰면 병합 충돌을 넘어 작업 상태 자체가 망가질 수 있다. git 워크트리는 별도 클론이나 컨테이너 없이 이 문제를 푼다.

이 장은 워크트리의 개념, 에이전트 워크플로에 잘 맞는 이유, Codex CLI와 조합하는 방법, 전체 수명주기 관리를 설명한다. 원서의 병합 전략 결정 트리 그림도 함께 실었다.

이 장을 마치면 다음을 할 수 있어야 한다.

1. 커맨드 라인에서 워크트리를 직접 만들고, 쓰고, 지운다.
2. 에이전트마다 워크트리 하나를 맡기고 결과를 main에 병합하는 멀티 에이전트 워크플로를 설계한다.
3. 워크트리를 자동으로 만들고 정리하는 CI 작업을 구성한다.

---

## 1. 핵심 요점

- 워크트리는 객체 데이터베이스를 공유하면서 브랜치, 인덱스, HEAD는 따로 갖기 때문에 클론보다 훨씬 빠르고 가볍다.
- 에이전트 하나는 워크트리 하나에서만 일한다. 파일 격리, 인덱스 격리, 브랜치 잠금이 이 규칙에서 나온다.
- 워크트리는 코드 상태만 격리한다. 포트, 데이터베이스, 환경 변수, Docker, 브라우저 상태는 따로 격리해야 한다.
- Codex CLI에는 전용 워크트리 명령이 없다. `git worktree add`로 만들고 `codex --cd`로 에이전트를 보낸다.
- 병합은 순차 병합, 리베이스 병합, 머지 큐 중에서 동시성과 히스토리 정책에 따라 고른다.
- 설정 스크립트로 환경을 준비하고, CI에서는 `trap ... EXIT`와 `if: always()`로 정리를 보장한다.
- 규모가 커질수록 수명주기를 자동화하지만 "브랜치 하나, 워크트리 하나, 에이전트 하나"는 그대로다.
