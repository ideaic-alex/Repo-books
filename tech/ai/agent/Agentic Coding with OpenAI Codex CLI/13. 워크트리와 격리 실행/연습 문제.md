# 연습 문제

13장 끝의 연습 문제 다섯 개를 풀이 방향과 함께 정리한다. 앞의 여러 문서에서 배운 내용을 직접 손으로 확인해 보는 문제들이다.

---

## 1. 기본 워크트리 실습

`git worktree add`로 워크트리 두 개를 만들고, 각각에서 `codex --cd`로 Codex 에이전트를 돌린다. 두 에이전트는 같은 파일을 논리적으로 서로 무관한 방식으로 고친다. 둘이 간섭 없이 끝나는지 확인한 뒤 두 브랜치를 main에 병합하고, git log에서 병합 커밋 두 개를 찾아낸다.

풀이 방향: 병합할 때 `git merge --no-ff`를 쓰면 작업마다 병합 커밋이 남는다. `git log --graph --oneline`으로 두 병합 커밋을 쉽게 찾을 수 있다.

## 2. 충돌 해결 실습

두 에이전트 워크트리가 같은 함수를 고치는 상황을 만든다. 첫 브랜치가 main에 들어간 뒤 두 번째 브랜치를 리베이스하고, `codex --cd <워크트리 경로> "resolve the rebase conflict against main"`으로 충돌을 풀게 한다. 에이전트가 푼 결과를 직접 풀었을 때의 결과와 비교한다.

풀이 방향: 에이전트가 두 변경의 의도를 모두 살렸는지, 한쪽을 조용히 버리지는 않았는지 확인하는 것이 비교의 핵심이다. 의미상 충돌은 이 단계에서 드러난다.

## 3. CI 파이프라인 실습

GitHub Actions 워크플로를 쓴다. 병렬 워크트리 세 개를 만들고, 각각에서 Codex 에이전트를 돌리고, 테스트를 통과한 브랜치만 푸시한다. 실패해도 워크트리가 지워지도록 `if: always()`가 붙은 정리 단계를 넣는다.

풀이 방향: 매트릭스 작업 세 갈래에 `max-parallel: 3`을 주고, 푸시 단계에는 테스트 성공 조건을 붙인다. 정리 단계는 `git worktree remove --force`와 `git branch -D` 뒤에 `|| true`를 둔다. 체크아웃에는 `fetch-depth: 0`을 잊지 않는다.

## 4. 수명주기 점검 실습

`git worktree list`와 `git branch --list 'codex/*'`의 출력을 비교한다. 낡은 브랜치를 지우고 `git worktree prune`을 실행하는 셸 스크립트를 작성한 뒤 주간 cron 작업으로 예약한다.

풀이 방향: 워크트리 목록에 없는데 `codex/*` 브랜치만 남은 것이 정리 대상 후보다. 단, 병합되지 않은 브랜치를 지우지 않도록 `git branch -d`(병합된 것만 삭제)를 쓰는 편이 안전하다.

## 5. 팀 확장 설계 실습

표 13-1을 출발점으로 개발자 5명에서 20명으로 커지는 팀의 워크트리 전략을 설계한다. 워크트리 이름 규칙, CI 작업 구조, 머지 큐 설정, 정리 자동화를 다룬다.

풀이 방향: 이름은 `codex/<작업ID>`처럼 일관되게 잡는다. 규모가 커지는 구간에서는 "팀 규모별 워크트리 패턴" 문서의 중규모 줄(PR마다 워크트리, 머지 큐, CI 정리 단계)을 기준으로 삼고, 런타임 격리(포트와 데이터베이스 분리)도 설계에 넣는다.
