# 워크트리 기초와 필요성

12장이 에이전트를 어떤 순서로 돌릴지 다뤘다면, 13장은 에이전트를 어디서 돌릴지를 다룬다. 두 에이전트가 같은 소스 트리에 동시에 글을 쓰면 단순한 병합 충돌을 넘어 작업 중인 상태 자체가 망가질 수 있다. git worktree(워크트리)는 별도 클론이나 컨테이너 없이 이 문제를 풀어 준다.

이 문서는 워크트리가 무엇인지, 공유 작업 트리에서 실제로 어떤 일이 벌어지는지, 클론과 비교해 왜 유리한지를 정리한다.

---

## 1. 워크트리 복습

git worktree는 Git 2.5(2015년 7월)에 들어온 기능이다. 하나의 객체 데이터베이스에 작업 트리(working tree)를 여러 개 붙일 수 있다. 워크트리마다 따로 갖는 것과 함께 쓰는 것이 나뉜다.

| 구분 | 내용 |
|---|---|
| 워크트리마다 따로 | 체크아웃한 브랜치, 인덱스(스테이징 영역), HEAD 포인터 |
| 모든 워크트리가 공유 | 객체 데이터베이스, packed refs, 저장소 설정 |

기본 명령은 세 가지다.

```bash
git worktree add ../feature-auth -b feature/auth # 만들기
git worktree list # 확인
git worktree remove ../feature-auth # 지우기
```

핵심 제약이 하나 있다. git은 워크트리 하나에 브랜치 하나만 허용한다. 같은 브랜치를 두 워크트리에서 동시에 체크아웃하려 하면 오류가 난다. 원래는 인덱스 충돌을 막으려는 장치인데, 병렬 에이전트에게는 오히려 안전장치가 된다. 각 에이전트가 작업 중에 쓴 내용은 명시적으로 병합하기 전까지 다른 에이전트에게 보이지 않기 때문이다.

## 2. 격리 없이 병렬로 돌리면 생기는 일

Codex CLI 에이전트 둘이 격리 없이 같은 저장소에서 일하는 상황을 따라가 보자.

1. 에이전트 A가 main을 체크아웃하고 `src/auth/login.ts`를 고치기 시작한다.
2. 에이전트 B도 같은 main(같은 파일들)을 체크아웃하고 `src/auth/session.ts`를 고치기 시작한다.
3. 에이전트 A가 `src/auth/utils.ts`에 헬퍼 함수를 쓴다.
4. 같은 순간 에이전트 B가 `src/auth/utils.ts`를 읽는데, 절반만 쓰인 파일을 보게 된다.

기능이 논리적으로 서로 무관해도 작업 트리를 공유하는 한 쓰는 도중의 내용이 곧바로 서로에게 보인다. 결과는 매번 다르게 터지는 실패이고, 재현하기가 거의 불가능하다.

## 3. 클론 방식의 한계

가장 단순한 해법은 에이전트마다 클론을 따로 주는 것이다.

```bash
git clone https://github.com/acme/app agent-clone-1
git clone https://github.com/acme/app agent-clone-2
```

동작은 하지만 낭비가 크다. 클론할 때마다 전체 객체 데이터베이스(수 GB가 될 수도 있다)를 내려받아야 한다. 또 한 클론에서 한 커밋은 push하고 pull하기 전까지 다른 클론에서 보이지 않는다.

## 4. 워크트리가 두 문제를 푸는 방식

워크트리는 두 문제를 한꺼번에 해결한다.

- 객체 데이터베이스를 공유하므로 중복 다운로드가 없다.
- 공유 ref 저장소를 통해 커밋이 즉시 다른 워크트리에서도 보인다.
- 워크트리마다 서로 다른 브랜치를 체크아웃하므로 디스크 위의 파일은 완전히 분리된다.

파일이 분리되니 에이전트는 자기가 쓴 내용만 보게 되고, 공유 작업 트리에서 나던 비결정적 실패가 사라진다.

속도 차이도 크다. 보통 규모의 모노레포에서 `git worktree add`는 1초 안에 끝나지만, `git clone`은 수십 초에서 수 분이 걸린다. 머지 큐 한 배치마다 워크트리를 수십 개 만들어야 하는 CI 규모에서는 이 차이가 눈덩이처럼 커진다.

## 5. Git LFS를 쓰는 저장소

Git LFS를 쓰더라도 워크트리는 LFS 포인터 파일을 공유한다. 실제 LFS 객체는 체크아웃할 때 받아 `.git/lfs`에 저장되는데, 이 위치도 공유된다. 그래서 LFS 파일이 든 브랜치를 두 번째 워크트리에서 체크아웃할 때는 체크아웃 비용만 들고 다시 다운로드하지 않는다.
