# 연습 문제

24장 끝의 연습 문제 다섯 개다. 각 문제의 취지를 풀어 쓰고, 풀이 방향을 한두 문장으로 덧붙였다.

---

## 1. 인프라용 AGENTS.md 작성하기

이미 있는 인프라 저장소 하나를 골라 AGENTS.md를 쓴다. 테스트 명령, 이름 규칙, `apply`와 `destroy`를 명시적으로 막는 금지 사항을 넣는다. 그다음 Codex CLI를 `-a untrusted -s read-only`로 실행해서 기존 테라폼 코드가 모범 사례를 어기는 곳을 검토해 달라고 한다.

풀이 방향: 이 장의 AGENTS.md 예시처럼 테스트 명령, 관례, 금지 사항 세 덩어리로 나누고, 모노레포라면 루트가 아닌 `infra/` 같은 하위 디렉터리에 둔다. 읽기 전용 실행이라 에이전트는 파일을 고치지 못하고 지적만 하므로, 나온 지적이 맞는지 직접 확인해 본다.

## 2. 보드 버킷 생성과 검증

Run or Relax 보드용 Cloud Storage 정적 사이트 모듈을 생성하고 전체 순서를 돌린다. `terraform fmt`, `terraform init -backend=false`, `terraform validate`, `tflint --init`, `tflint`, `checkov -d infra --compact` 순이다. 남은 checkov 지적이 모두 표 24-1의 어느 행과 맞는지 확인하고 각각에 정당화한 인라인 예외를 단다. 표에 없는 지적은 실제로 고친다.

풀이 방향: `#checkov:skip` 주석을 리소스 블록 본문의 첫 줄에 두는 것이 핵심이다(블록 위에 두면 무시된다). 예외마다 사유를 읽을 수 있게 쓰고, 표에 없는 지적을 예외로 덮지 않는다.

## 3. 계획 검토 파이프라인 만들기

풀 리퀘스트에서 `codex exec`로 테라폼 계획을 검토하는 CI/CD 파이프라인을 구성한다. 풀 리퀘스트 다섯 건에 대해 에이전트의 검토를 팀의 수작업 검토와 비교한다.

풀이 방향: 계획 생성, 읽기 전용 검토, PR 댓글 게시의 세 단계로 구성하고 에이전트에게 apply 권한을 주지 않는다. 비교할 때는 에이전트가 삭제, IAM 변경, 비용 영향을 잡았는지와 놓치거나 과하게 지적한 것이 무엇인지 기록한다.

## 4. Terraform MCP 서버의 범위 정하기

프로젝트의 `.codex/config.toml`에 Terraform MCP 서버를 설정하되 `enabled_tools`를 레지스트리 조회로 제한한다. Codex CLI에게 Cloud Run 서비스 모듈을 쓰게 하고, 세션 로그에서 속성 이름을 짐작하지 않고 `google_cloud_run_v2_service`에 대해 레지스트리를 실제로 조회했는지 확인한다.

풀이 방향: 이 장의 설정처럼 검색과 상세 조회 도구만 나열하고, 워크스페이스 실행이나 apply 관련 도구는 목록에서 뺀다. 로그에서 `get_provider_details` 같은 조회 호출이 보이는지 찾아본다.

## 5. 두 서비스 연결하기

테라폼의 출력과 변수로 배포된 조각들을 잇는다. Cloud Run 모듈이 서비스 URL을 출력하고, 보드가 그 값을 `NEXT_PUBLIC_DEPARTURES_API_URL`로 빌드되며, API의 `RUN_OR_RELAX_CORS_ORIGIN`이 보드의 버킷 URL로 설정되게 한다. 계획을 돌리고 Codex에게 검토시킨 뒤, 두 모듈에 걸쳐 하드코딩된 값이 없음을 확인한다.

풀이 방향: 버킷 모듈의 origin 출력(스킴과 호스트만)을 Cloud Run 모듈의 `cors_origin` 변수에 넘기고, 서비스 URL 출력은 보드 빌드의 입력으로 쓴다. 전체 페이지 URL이 아니라 경로 없는 origin이 들어갔는지 특히 확인한다.
