# 사용 한도와 요금 체계

에이전트(agent)가 여러 단계를 거쳐 일하는 방식을 쓰면 할 수 있는 일은 늘지만, 그만큼 API 호출도 늘어난다. 앞 장들에서는 한 스레드(thread, 대화 기록 한 묶음) 안에서 컨텍스트 윈도(context window)를 얼마나 쓰는지 다뤘다. 이 장은 또 다른 예산인 돈을 다룬다. 컨텍스트와 비용은 관련이 있지만 같은 문제가 아니다. 컨텍스트 윈도 한도 안에서 얌전히 돌던 세션이 청구서에서는 놀라운 숫자를 만들 수 있다.

이 문서는 Codex CLI를 쓸 때 사용 한도(쿼터, quota)가 어떻게 돌아가는지, 모델별 가격이 어떻게 다른지, 그리고 토큰이 실제로 어디서 소모되는지를 정리한다.

---

## 1. 접근 방식에 따라 달라지는 사용 한도

Codex CLI의 사용 한도는 어떤 경로로 서비스를 쓰느냐에 따라 달라진다. 크게 구독(ChatGPT Plus, Pro)과 API 키 두 갈래다.

### 구독 한도 (ChatGPT Plus, Pro)

ChatGPT Plus와 Pro 구독에는 Codex CLI 사용량이 크레딧(credit) 단위로 들어 있다. 입력, 캐시된 입력, 출력마다 100만 토큰당 몇 크레딧이 드는지 모델별로 정해져 있다. gpt-5.5는 gpt-5.4보다 토큰당 크레딧을 더 많이 쓰고, gpt-5.4는 gpt-5.4-mini보다 더 많이 쓴다.

구독에는 서로 다른 두 주기가 있다. 헷갈리지 않게 따로 기억해 두는 것이 좋다.

1. 결제 주기: 구독 요금 자체는 월 단위(또는 연 단위)로 좌석당 고정 요금이 나간다. 이 요금은 토큰 사용량과 무관하다.
2. 사용 한도 주기: 구독 안에서 Codex CLI 사용량은 5시간짜리 롤링 윈도(rolling window)로 측정된다. 로컬 메시지와 클라우드 작업이 같은 5시간 풀을 같이 쓰고, 그 위에 주간 한도가 붙을 수 있다.

그 밖의 특징은 다음과 같다.

- 한도는 크레딧 단위이고 모델마다 비율이 다르다. 이미 좌석 요금을 냈기 때문에 구독 사용분에는 토큰당 달러 가격이 따로 없다.
- 한도는 다음 윈도로 이월되지 않는다.
- 한도를 다 쓰면 Plus와 Pro 사용자는 크레딧을 추가로 사서 계속 쓰거나, API 키 결제로 넘어가 표준 토큰 단가를 낼 수 있다.

Pro 요금제는 같은 윈도 구조에서 Plus의 5배 또는 20배 한도를 준다. Enterprise와 Edu 요금제는 유연한 가격 체계라 고정된 사용 한도가 없고, 워크스페이스가 구매한 크레딧만큼 사용량이 늘어난다.

개인 개발자라면 구독 한도로 보통 충분하다. 팀은 대개 부족하다. 사용자별 구독 계정은 팀원끼리 합산되지 않기 때문이다.

### Codex 전용 좌석

전체 ChatGPT 구독 없이 API 수준 접근만 필요한 팀을 위해 OpenAI는 Codex 전용 좌석(Codex-only seat)을 둔다. 좌석당 월 요금은 없고, 공개된 API 단가대로 토큰 사용분만 낸다. 사용량은 관리자가 조직 대시보드에서 모니터링한다.

정확한 크레딧 비용, 모델별 한도, 5시간 윈도, 주간 한도, 요금제 구조는 OpenAI의 Codex 요금 문서가 기준이다. 팀 규모를 잡기 전에 현재 값을 확인해야 한다.

## 2. 사용 수준별 비용 비교

아래 표는 현재 API 단가 기준으로 사용 유형별 하루 비용과 한 달 비용을 어림한 것이다(한 달 22일 근무 기준). 재무 계획에 쓰기 전에 실제 요금 페이지와 대조해야 한다.

| 사용 유형 | 하루 토큰 | 하루 비용(추정) | 한 달 비용(추정) |
|---|---|---|---|
| 가벼움(코드 탐색, 질문) | 5만~15만 | $1~$3 | $22~$66 |
| 보통(기능 개발, 리뷰) | 30만~60만 | $4~$8 | $88~$176 |
| 무거움(멀티 에이전트, CI 파이프라인) | 100만~300만 | $10~$25 | $220~$550 |
| 5명 팀(조율자/작업자 구조) | 합계 500만~1,500만 | $50~$125 | $1,100~$2,750 |
| 50명 팀(기업) | 합계 5,000만~1억 5,000만 | $500~$1,250 | $11,000~$27,500 |

이 추정은 조율자(orchestrator)에 gpt-5.4, 작업자(worker)에 gpt-5.4-mini를 쓴다고 가정한다. 모든 작업을 gpt-5.5로 돌리면 조율 부분 비용이 대략 2배가 된다. 다만 GPT-5.5의 토큰 효율 개선이 그 일부를 상쇄한다. 반대로 모든 작업을 gpt-5.4로 돌리면 작업자 부분 비용이 3~5배로 뛴다.

커뮤니티에서 가끔 언급되는 "주당 10억 토큰"은 팀 전체 합계 수치다. 표준 워크플로를 쓰는 개발자 한 명이 그 근처에 가는 일은 없다.

## 3. API 단가와 모델별 비용 비율

API 키로 Codex CLI를 쓰면 공개된 단가대로 토큰마다 과금된다. 아래 값은 대략적인 수치이고 바뀔 수 있으므로, 재무 계획 전에 반드시 최신 가격을 확인한다.

| 모델 | 입력(100만 토큰당) | 출력(100만 토큰당) | gpt-5.4 대비 비용 |
|---|---|---|---|
| gpt-5.5 | $5.00 | $30.00 | 약 2배 |
| gpt-5.4 | $2.50 | $15.00 | 1.0배 |
| gpt-5.4-mini | $0.75 | $4.50 | 0.3배 |
| gpt-5.4-mini(추론 모드) | $1.10 | $4.40 | 약 0.6배(추론 토큰 별도) |
| gpt-5.4(높은 추론 강도) | $10.00 | $40.00 | 약 5배 |

GPT-5.5는 입력과 출력 모두 GPT-5.4의 약 2배 가격이다. 겉보기 가격은 높지만, OpenAI는 토큰 효율이 좋아져 같은 결과를 더 적은 토큰으로 낸다고 밝힌다. 예를 들어 두 번 시도할 문제를 한 번에 풀거나, 출력 1,500토큰이 들던 일을 800토큰에 끝내면 작업당 실제 비용은 비슷하게 유지될 수 있다. 업그레이드하기 전에 대표 작업을 돌려 GPT-5.4와 총 토큰 사용량을 비교해 보는 것이 좋다. 일상 작업에는 더 싼 GPT-5.4가 여전히 가성비가 낫다.

핵심 관찰은 gpt-5.4-mini가 gpt-5.4의 약 3분의 1 비용이면서 에이전트 작업의 상당 부분을 잘 처리한다는 점이다. 목표가 분명한 에이전트 코딩 작업에서 gpt-5.4-mini는 공개된 벤치마크 기준으로 gpt-5.4 성능의 85~90% 정도를 약 30% 비용으로 낸다고 한다. 라우팅 규칙을 확정하기 전에 자기 작업으로 검증해야 한다.

## 4. Fast 모드와 크레딧 배수

Codex CLI에는 처리량이 높은 추론 경로가 있다. gpt-5.4와 gpt-5.5에서 출력이 약 1.5배 빠르지만 크레딧을 더 빨리 쓴다.

OpenAI 문서는 이 기능을 Fast 모드라고 부르지만, 런타임에서는 서비스 티어(service tier)로 노출되며 값은 priority이고 대안은 default다.

- 세션 중에는 `/fast`로 둘 사이를 전환한다. 전환하면 새 상태가 출력된다(예: `Service tier set to priority`).
- 설정으로 유지하려면 `~/.codex/config.toml`에 `service_tier = "fast"`를 넣는다. 내부적으로 priority 요청 티어에 대응한다.

크레딧 배수는 구독 결제에서만 의미가 있다. priority 서비스는 gpt-5.5에서 표준 비율의 2.5배, gpt-5.4에서 2배 크레딧을 소모한다. ChatGPT 요금제로 로그인한 사용자의 IDE 확장, CLI, Codex 앱에서 쓸 수 있다. API 키 결제에서는 쓸 수 없다. 그 경우 표준 토큰 단가가 그대로 적용되고 슬래시 명령은 아무 효과가 없다.

결국 작업당 크레딧은 대략 본전이고 대기 시간만 줄어드는 거래다. 초당 크레딧 소모율은 2~2.5배인데 약 1.5배 빨리 끝나니, 들어가는 크레딧은 비슷하고 개발자가 기다리는 시간은 줄어든다. 개발자 대기 시간에도 비용이 있는 대화형 세션에는 맞는 선택이고, 지연 시간이 중요하지 않은 배치나 백그라운드 작업에는 맞지 않는다.

요금 문서에는 별도 모델인 Codex-Spark(gpt-5.3-codex-spark)도 나온다. Fast 모드보다 한 단계 아래에 놓인 모델로, 능력은 낮지만 거의 즉각적인 실시간 반복에 쓴다. 자체 사용 한도가 있다. 집필 시점에 ChatGPT Pro 전용이고 하위 요금제의 모델 선택기에는 나타나지 않는다. 그래서 대부분의 독자는 gpt-5.4/gpt-5.5의 Fast 모드를 쓰게 된다. Codex CLI의 모델 선택기는 기본으로 gpt-5.5, gpt-5.4, gpt-5.4-mini 세 모델을 보여 준다.

## 5. 토큰은 어디서 소모되는가

에이전트 세션에서 토큰은 다섯 군데에서 나간다.

1. 시스템 프롬프트: AGENTS.md 내용, 활성 프로필 설정, Codex CLI 자체의 시스템 프롬프트를 포함한다. 세션 안의 모든 API 호출마다 과금된다.
2. 대화 기록: 컨텍스트 윈도에 남아 있는 이전 메시지, 도구 호출, 도구 결과가 모든 API 호출마다 입력 토큰으로 과금된다.
3. 작업 설명: 사용자가 쓴 프롬프트.
4. 도구 호출 결과: 파일 내용, 명령 출력, 검색 결과가 다음 API 호출의 입력 토큰으로 돌아온다.
5. 모델 출력: 에이전트의 응답, 추론 토큰(추론 모델의 경우), 생성된 모든 내용.

비싼 부분은 모델 출력이 아니라 쌓여 가는 대화 기록이다. 7장에서 말한 제곱 증가 문제가 바로 이것이다. 매 턴마다 이전 기록 전체를 다시 보내므로, 세션 동안 누적해서 보낸 토큰 수는 턴 수의 제곱에 가깝게 늘고 긴 세션은 비중이 훨씬 커진다.

그래서 7장의 컨텍스트 관리 수단은 모두 비용 절감 수단이기도 하다.

- `/compact`는 길고 자세한 기록을 짧은 요약으로 바꿔 이후 모든 API 호출의 토큰 비용을 줄인다.
- 서브에이전트(subagent) 위임은 토큰을 많이 쓰는 하위 작업을 별도 윈도에서 돌리고 간단한 요약만 부모에게 돌려줘, 과금되는 앞부분을 가볍게 유지한다.
- Plan Mode의 새 컨텍스트 경계는 구현 세션이 계획 세션에 쌓인 무게를 물려받지 않게 막는다.

두 장은 하나의 원리에서 나온 두 가지 결과를 다룬다. 윈도를 계속 쓸 만하게 유지하는 이유와 지출이 한정되는 이유가 같다.
