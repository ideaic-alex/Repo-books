# 훅으로 비용 모니터링

Stop 훅(hook)은 턴이 멈출 때 실행된다. Codex CLI 세션을 나가기 직전의 마지막 턴도 포함한다. 훅의 생명주기, 등록 방식, 전체 페이로드 구조는 9장에서 다뤘다. 이 문서는 바로 가져다 쓸 수 있는 설정과 그 변형 세 가지를 정리한다.

---

## 1. 기본 Stop 훅

훅은 `~/.codex/hooks.json`(또는 프로젝트 루트의 `.codex/hooks.json`)에 등록한다. 두 위치, 신뢰 검토 흐름, `/hooks`로 로드된 훅을 확인하는 방법은 9장에 있다.

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [ {
        "type": "command",
        "command": "bash ~/.codex/scripts/cost-log.sh",
        "statusMessage": "Logging session cost...",
        "timeout": 10
      } ] }
    ]
  }
}
```

짝이 되는 스크립트는 `~/.codex/scripts/cost-log.sh`에 저장하고 `chmod +x`를 준다. 이 스크립트는 멈춘 턴마다 JSONL 한 줄을 덧붙인다. Stop 페이로드에는 `session_id`, `turn_id`, `model`, `cwd`, `transcript_path`가 들어 있고, 토큰 합계는 `transcript_path`가 가리키는 롤아웃 트랜스크립트(rollout transcript) 안에 있다. 그래서 스크립트가 그 파일을 훑어 합산한다.

아래는 스크립트의 핵심 구조다. 전체 스크립트는 입력 파싱, 사용량 합산(jq), 기록의 세 부분으로 나뉜다.

```bash
set -euo pipefail
LOG_DIR="${HOME}/.codex/cost-logs"
mkdir -p "$LOG_DIR"
PAYLOAD="$(cat || echo '{}')"
TIMESTAMP="$(date -u +%FT%TZ)"
SESSION="$(jq -r '.session_id // "unknown"' <<<"$PAYLOAD")"
TURN="$(jq -r '.turn_id // "unknown"' <<<"$PAYLOAD")"
MODEL="$(jq -r '.model // "unknown"' <<<"$PAYLOAD")"
TRANSCRIPT="$(jq -r '.transcript_path // empty' <<<"$PAYLOAD")"
```

사용량 합산 부분은 트랜스크립트 안에서 `input_tokens` 또는 `prompt_tokens` 키가 있는 객체를 모두 찾아 input, output, total로 합친다. 버전에 따라 필드 이름이 조금씩 달라서 `input_tokens`/`output_tokens`/`total_tokens`와 `prompt_tokens`/`completion_tokens` 두 계열을 모두 처리한다. 마지막으로 `jq -nc`로 `ts`, `session`, `turn`, `model`, `cwd`, `branch`, `usage` 필드를 가진 JSON 한 줄을 만들어 `$LOG_DIR/cost-log.jsonl`에 덧붙인다. 브랜치는 `git rev-parse --abbrev-ref HEAD`로 얻고 실패하면 `none`을 쓴다.

Codex CLI 세션을 한 번 돌리고 종료해 보자. Stop 훅이 실행될 때마다 `~/.codex/cost-logs/cost-log.jsonl`이 늘어나야 하고, 각 줄에는 타임스탬프, 세션 ID, 턴 ID, 모델, cwd, 브랜치, 트랜스크립트에서 합산한 usage 객체가 들어 있다. 세션당 레코드를 정확히 하나만 원하면, 나중에 세션 기준으로 모아서 세션마다 마지막 값이나 가장 큰 합계를 남기면 된다.

---

## 2. jq로 집계하기

최근 7일 동안의 모델별 합계(입력, 출력 토큰 포함)는 다음처럼 뽑는다.

```bash
SINCE="$(date -u -v-7d +%FT%TZ 2>/dev/null || date -u -d '7 days ago' +%FT%TZ)"
jq -c --arg since "$SINCE" 'select(.ts > $since)' ~/.codex/cost-logs/cost-log.jsonl \
  | jq -s 'group_by(.model) | map({model: .[0].model,
      turns: length, sessions: (map(.session) | unique | length),
      input: (map(.usage.input // 0) | add),
      output: (map(.usage.output // 0) | add),
      total: (map(.usage.total // 0) | add)})'
```

---

## 3. 알아둘 한계

Stop 훅의 stdin 페이로드에는 지금 토큰 수가 직접 들어 있지 않다. 그래서 스크립트가 `transcript_path`의 롤아웃 트랜스크립트를 읽어 토큰 수를 복원한다. 이 방식은 튼튼하지만 버전에 민감하다. Codex는 `transcript_path`를 편의 필드로 문서화했을 뿐 안정적인 훅 인터페이스로 보장하지 않으며, 롤아웃 트랜스크립트는 릴리스마다 `input_tokens/output_tokens`와 `prompt_tokens/completion_tokens`를 오갔다. jq 리듀서가 두 형태를 모두 처리한다. 9장도 훅 페이로드 전반에 대해 같은 단서를 달았다.

첫 실행 뒤에는 `jq .usage ~/.codex/cost-logs/cost-log.jsonl | tail`로 합계가 채워지는지 확인한다. 값이 계속 0이면 설치된 버전의 필드 이름이 바뀐 것이므로 리듀서에 별칭을 하나 더 넣어야 한다.

## 4. 변형 1: 웹훅으로 팀 단위 집계

jq로 파일에 덧붙이는 대신 curl로 웹훅에 보내는 방식이다. URL이 소스 관리에 들어가지 않게 `CODEX_COST_WEBHOOK`를 셸 프로필에 한 번 설정해 둔다.

```bash
#!/usr/bin/env bash
# ~/.codex/scripts/cost-webhook.sh
set -euo pipefail
[ -z "${CODEX_COST_WEBHOOK:-}" ] && exit 0
PAYLOAD="$(cat || echo '{}')"
curl -sS -m 5 -X POST "$CODEX_COST_WEBHOOK" \
  -H 'content-type: application/json' \
  -d "$(jq -nc --arg user "${USER:-unknown}" \
        --argjson payload "${PAYLOAD:-null}" \
        '{user:$user, payload:$payload}')" > /dev/null || true
```

(실제 스크립트에는 `ts`, `session`, `turn`도 함께 담지만 여기서는 줄였다.) Stop 훅의 command를 이 스크립트로 바꾼다. 끝의 `|| true`와 `exit 0` 가드는 9장의 "누락된 의존성을 우아하게 처리하라"는 조언을 따른 것이다. 웹훅 장애가 났을 때 exit 2로 끝나 턴 마무리 단계에서 오류로 보이는 것보다, 조용히 exit 0으로 넘어가는 편이 낫다.

## 5. 변형 2: 토큰 임계값 초과 시 알림

폭주 세션이 비용을 쌓기 전에 잡는 임계값 검사다. `CODEX_COST_ALERT_TOKENS`로 값을 조절하며 기본값은 500000이다.

```bash
THRESHOLD="${CODEX_COST_ALERT_TOKENS:-500000}"
# TOTAL: 트랜스크립트의 input+output 토큰 합 (jq로 계산)
if [ "${TOTAL:-0}" -gt "$THRESHOLD" ]; then
  MSG="Codex session $SESSION used $TOTAL tokens (threshold $THRESHOLD) in $(pwd)"
  command -v notify-send >/dev/null && notify-send "Codex cost alert" "$MSG"
  [ -n "${CODEX_SLACK_WEBHOOK:-}" ] && curl -sS -X POST "$CODEX_SLACK_WEBHOOK" \
    -H 'content-type: application/json' \
    -d "$(jq -nc --arg t "$MSG" '{text:$t}')" > /dev/null || true
fi
```

데스크톱 알림(`notify-send`)과 Slack 웹훅(`CODEX_SLACK_WEBHOOK`)으로 알린다. 합계 계산 방식은 기본 스크립트와 같은 jq 합산이다.

---

## 6. 세 가지를 함께 쓰기

세 스크립트를 모두 쓰려면 `"Stop"` 배열에 항목을 여러 개 등록한다. 같은 이벤트에 걸린 command 훅은 동시에 실행될 수 있으므로 등록 순서에 기대면 안 된다. 기록이 웹훅 전송이나 알림보다 먼저 일어나야 한다면, 래퍼 스크립트 하나에서 스크립트들을 순서대로 호출하고 그 래퍼만 훅으로 등록한다.

---

## 7. 압축 단위 관측

압축별 관측이 필요하면 이 Stop 훅 패턴에 `PreCompact` 훅을 더한다. JSON 모양은 같고 `"Stop"` 대신 `"PreCompact"`를 쓰며, 타임스탬프와 페이로드 필드를 기록한다. 15분 안에 자동 압축이 세 번 일어나면 루프에 빠진 것이므로 세션을 나눠야 한다. 9장에 이 훅의 stdin 필드(`session_id`, `turn_id`, `cwd`, `model`, `transcript_path`, 그리고 값이 `manual` 또는 `auto`인 `trigger`)와 저장 후 복원 패턴의 예가 있다. 비용에 맞춘 형태가 필요하면 이곳으로 돌아오면 된다.
