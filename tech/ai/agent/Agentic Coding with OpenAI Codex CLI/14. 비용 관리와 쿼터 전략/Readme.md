# 비용 관리와 쿼터 전략

멀티 에이전트 패턴은 능력을 키우는 만큼 API 호출도 늘린다. 컨텍스트 윈도 예산은 한 스레드 안에서 세션이 얼마나 차는지의 문제였고, 이 장은 또 다른 예산인 돈을 다룬다. 컨텍스트와 비용은 관련이 있지만 같은 문제가 아니어서, 컨텍스트 한도 안에서 돌던 세션도 놀라운 청구서를 만들 수 있다.

이 장은 Codex CLI의 사용 한도(쿼터)가 어떻게 돌아가는지, 팀 워크플로 비용을 어떻게 추정하는지, 비용 제어를 어떻게 설정하는지, 청구서 충격을 피하려면 모니터링을 어떻게 짜는지를 설명한다. 프롬프트 캐싱과 모델 라우팅, Plan Mode와 Goal Mode, 클라우드 결제 경로와 로컬 추론, 커뮤니티 압축 도구까지 다룬다.

---

## 1. 핵심 요점

- 구독은 좌석당 월 고정 요금에 5시간 롤링 윈도 한도가 붙고, API는 토큰당 과금이다. 둘은 별개의 결제 방식이다.
- 비용의 주범은 모델 출력이 아니라 매 호출마다 다시 보내는 누적 대화 기록이다.
- 엔지니어 5명의 조율자/작업자 팀은 gpt-5.4와 gpt-5.4-mini 조합으로 월 약 $397 정도가 든다. 작업자를 gpt-5.4로 올리면 약 $707이 된다.
- 모델 라우팅과 프로필이 가장 큰 설정 레버이고, 프롬프트 캐싱은 단일 레버로는 가장 크다(캐시된 입력 최대 90% 할인).
- 추론 강도는 비용을 가파르게 올린다. `xhigh`는 `medium`의 약 12배이고 소비의 75% 이상이 보이지 않는 추론 토큰이다.
- Stop 훅으로 세션 토큰을 기록, 집계, 경보하고, 압축 한도 키와 60% 수동 압축으로 폭주를 막는다.
- 에이전트 PR의 28.5%가 머지되지 못하므로 PR을 작게 하고 SLM 선별 계층과 2개 모델 리뷰 루프로 낭비를 줄인다.
- Plan Mode로 컨텍스트 사용량을 미리 보고, Goal Mode로 장기 작업의 반복과 낭비를 막는다.
