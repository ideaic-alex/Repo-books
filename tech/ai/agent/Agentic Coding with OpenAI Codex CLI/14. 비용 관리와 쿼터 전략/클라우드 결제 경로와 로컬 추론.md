# 클라우드 결제 경로와 로컬 추론

Codex CLI가 꼭 OpenAI API를 직접 호출해야 하는 것은 아니다. 클라우드 지출이 이미 AWS나 Azure에 모여 있는 기업이라면, 해당 클라우드 제공자를 거쳐 추론하게 하면 Codex CLI 비용이 같은 청구서에 올라가고, 직접 API 결제에는 없는 약정 할인도 받을 수 있다. 집필 시점에 Codex CLI가 공식 지원하는 제공자는 두 곳이다. AWS Bedrock(내장)과 Azure OpenAI Service(커스텀 제공자로 설정)다. GCP Vertex AI와 Anthropic Claude는 현재 기본 제공자로 지원되지 않는다.

이 문서는 두 클라우드 경로의 설정과 장단점, 그리고 사용량이 아주 큰 팀을 위한 온프레미스(자체 서버) 추론의 손익분기를 정리한다.

---

## 1. Amazon Bedrock

Bedrock은 Codex CLI에 내장된 모델 제공자 중 하나다. 이 경로의 이점은 세 가지다.

1. 약정 사용 할인: AWS 프로비저닝 처리량(provisioned-throughput) 가격과 약정 지출 계약을 쓰면, 사용량이 예측 가능한 팀은 공개된 온디맨드 단가보다 실효 토큰 단가를 낮출 수 있다.
2. AWS 청구 통합: Codex CLI 추론이 컴퓨트, 스토리지 등 다른 인프라와 같은 AWS 청구서에 나온다. 비용 귀속이 단순해지고 OpenAI와 별도 결제 관계를 맺지 않아도 된다.
3. 엔터프라이즈 가격 체계: AWS Enterprise Discount Program이 있는 조직은 Bedrock 추론에서 OpenAI API 직접 결제로는 받을 수 없는 추가 할인을 받을 수 있다.

내장 `amazon-bedrock` 제공자로 프로필을 라우팅하는 설정은 다음과 같다.

```toml
# ~/.codex/bedrock.config.toml
model = "openai.gpt-5.4"
model_provider = "amazon-bedrock"

[model_providers.amazon-bedrock.aws]
profile = "my-aws-profile"   # optional; falls back to default credential chain
region = "us-west-2"
```

인증은 표준 AWS 자격 증명 체인(SigV4)을 쓴다. 모델 식별자는 OpenAI 기본 슬러그가 아니라 Bedrock 규칙(`openai.gpt-5.4`, `openai.gpt-5.5`)을 따른다. 런타임이 Bedrock을 OpenAI 호환 엔드포인트로 취급하기 때문에 프롬프트 캐싱은 그대로 유지된다.

---

## 2. Azure OpenAI Service

Azure OpenAI Service는 내장 제공자는 아니지만 일반 `[model_providers.*]` 설정으로 완전히 지원된다. TOML 모양은 다음과 같다.

```toml
# ~/.codex/azure.config.toml
model = "gpt-5.4"
model_provider = "azure-openai"

[model_providers.azure-openai]
name = "Azure"
base_url = "https://YOUR-RESOURCE.openai.azure.com/openai"
env_key = "AZURE_OPENAI_API_KEY"
wire_api = "responses"
query_params = { "api-version" = "2025-04-01-preview" }
```

환경 변수 `AZURE_OPENAI_API_KEY`를 설정해 둔다. `name = "Azure"` 줄은 빠져서는 안 되는 값이다. 런타임이 프롬프트 캐싱을 쓸 수 있는지 판단할 때 Azure 형태의 제공자인지 확인하고, 이 문자열 일치가 캐시 경로를 켜 준다. 모델 식별자는 Azure 배포 이름과 같아야 하며, `gpt-5.4`라는 이름의 배포를 Azure 포털에서 해당 모델에 연결해 둔다.

Azure 라우팅은 Codex CLI 추론을 기존 Azure 구독에 올린다. 이 구독에는 이미 Enterprise Agreement 할인이나 약정 지출 가격이 있을 수 있고, 이는 OpenAI 직접 결제와는 별개다.

---

## 3. 트레이드오프

두 제공자 모두 부담은 운영 쪽이다. 클라우드 호스팅 엔드포인트는 OpenAI 직접 API보다 지연이 더 길 수 있고, 새 모델 출시를 늦게 따라올 수 있다. 고른 제공자에서 프롬프트 캐싱 동작을 끝까지 확인해야 한다. Bedrock과 Azure 모두 캐시가 동작하지만, 캐시 히트율은 제공자마다 다른 인프라에 좌우된다.

경험칙은 이렇다. Codex CLI 추론 비용이 월 약 $5,000을 넘으면 클라우드 제공자의 약정 할인만으로도 운영 부담을 상쇄할 수 있고, 청구 통합의 이점은 충분히 본전을 한다. 그 아래에서는 OpenAI API 직접 결제가 더 단순하고 새 기능도 빨리 쓴다.

---

## 4. 온프레미스 추론: GB10 손익분기

Codex CLI API 사용량이 큰 팀이라면 자체 서버 추론으로 토큰 비용을 아예 없앨 수 있다. 진입점은 NVIDIA의 GB10급 하드웨어(DGX Spark 라인, 통합 메모리 128GB, Blackwell GPU)다.

공개된 하드웨어 가격을 기준으로 자릿수 수준의 손익분기를 계산하면, 월 API 지출이 $800일 때 회수 기간이 약 6개월이고 $400이면 12개월 가까이 된다. GB10에서는 일상적인 코딩 작업에 경쟁력 있는 오픈 웨이트 모델을 돌릴 수 있다. 예를 들어 Qwen3.6-35B-A3B는 SWE-bench Verified에서 73.4%를 내고 초당 약 240토큰을 처리한다고 보고된다. 다만 프런티어 벤치마크에서는 GPT-5.5에 못 미친다.

대부분의 기업에 가장 비용 효율적인 형태는 계층형 라우팅이다. 린트, 테스트 생성, 문서화 같은 일상 작업은 오픈 웨이트 모델이 도는 로컬 GB10으로 보내고, 아키텍처 추론이나 다중 파일 리팩터링 같은 복잡한 작업은 클라우드 API의 프런티어 모델로 보낸다. 배포 토폴로지는 17장에서 자세히 다룬다.

```toml
# ~/.codex/local.config.toml: 일상 작업은 로컬 하드웨어
model = "qwen3.6-35b-a3b"
model_provider = "local_gb10"

# ~/.codex/cloud.config.toml: 복잡한 작업은 프런티어 모델
model = "gpt-5.5"
model_provider = "openai"
```

손익분기 계산은 쉬운 부분이고, 진짜 문제는 운영상의 트레이드오프다. 온프레미스 추론은 지출을 운영비(opex)에서 자본 지출(capex)로 옮기고, 하드웨어 교체 주기를 더하며, 모델 업데이트, GPU 드라이버 호환성, 추론 서버 가동 시간을 맡을 운영 담당자를 당직표에 올려야 한다. 손익분기에 못 미치는 API 지출이라면 거의 맞는 답이 아니다. 그 기준을 넘은 뒤에는 결정이 계산보다는 비용 외 제약에 좌우되는 경우가 많다. 코드나 프롬프트가 네트워크 밖으로 나가는 것을 금지하는 데이터 거주 규정, 클라우드에 닿을 수 없는 망 분리 환경, 프런티어 모델의 추가 성능이 송출 비용이나 지연만큼의 가치가 없는 작업이 그런 예다.

대부분의 팀에는 위 두 프로필 파일이 보여 주는 하이브리드 패턴이 맞다. 로컬 용량이 일상 부하를 흡수하고, 프런티어 성능이 필요한 호출은 클라우드가 맡으며, 프로필 체계가 라우팅을 명시적이고 감사 가능하게 만든다. 네트워킹, 모델 수명주기, 하이브리드 패턴이 기업 보안 통제와 어떻게 맞물리는지는 17장에서 다룬다.
