# 요약

14장의 핵심을 여덟 가지로 정리한다. 각 항목의 자세한 근거와 숫자는 장 안의 다른 문서에 있다.

---

## 1. 여덟 가지 요점

1. 결제 방식이 둘이다. ChatGPT 구독은 좌석당 월 고정 요금을 내고, 그 안에서 Codex CLI 사용량이 크레딧 단위로 5시간 롤링 윈도에 맞춰 측정되며 그 위에 주간 한도가 붙을 수 있다. API 결제는 이와 별개로 공개된 달러 단가대로 토큰마다 과금된다. 엔지니어 5명의 조율자/작업자 팀은 API 결제에서 보통 월 $350~$450 범위에 놓이며, gpt-5.4-mini 작업자는 gpt-5.4의 약 3분의 1 토큰 단가로 돈다.
2. 가장 큰 비용 요인은 출력이 아니라 쌓인 기록이다. `/compact`를 비롯한 컨텍스트 관리는 재정적 결정이다. 7장의 제곱 증가 관점이 모양과 수단을 설명해 준다.
3. 비용 제어는 라우팅에 있다. 이름 있는 프로필(6장)로 하는 모델 라우팅이 가장 효과적인 레버다. 탐색 작업은 gpt-5.4-mini로, 복잡한 작업은 추론세가 값을 하는 높은 추론 강도의 gpt-5.4로 보낸다. Fast 모드는 크레딧 소모율 2~2.5배(구독 전용)를 내고 처리량 약 1.5배를 얻는 거래이므로, 개발자 대기 시간에도 비용이 있는 대화형 세션에 쓰고 배치 작업에는 쓰지 않는다.
4. 프롬프트 캐싱이 단일 레버로는 가장 크다. 캐시된 입력 토큰에 최대 90% 할인이 붙고, 라우팅과 합치면 안정 상태의 입력 비용이 캐시 없는 기준 단가의 작은 일부가 된다.
5. 훅으로 감시한다. Stop 훅이 기본 수단이다. 세션 페이로드를 로컬에 기록하거나, 웹훅으로 팀 집계를 하거나, 임계값 초과 시 알린다. `PreCompact`와 `PostCompact` 훅은 비용 텔레메트리로도 쓰여 압축 루프를 잡아 준다. `model_auto_compact_token_limit`을 컨텍스트 용량의 80~85%로 두고, `tool_output_token_limit`을 제한하며, 자동 트리거를 기다리지 말고 60%에서 직접 압축한다. 구현은 9장에 있다.
6. 비용 낭비는 코드보다 워크플로에 숨어 있다. 연구에 따르면 에이전트 PR의 약 28.5%가 머지되지 못하고, 주된 원인은 리뷰어의 포기, 중복 제출, 원치 않는 기능이다. 뒤따르는 숨은 비용은 사람의 리뷰 시간이며, 개념적 실패가 쌓이면서 에이전트 산출물이 늘수록 커진다. 교차 모델 리뷰 루프에 SLM 선별 계층을 두면 리뷰 비용만 약 3배 줄고, 2개 모델 리뷰 루프가 비용 대비 품질의 최적점이며 세 번째 리뷰어는 품질보다 비용을 더 빨리 늘린다. 완화책은 제출 규율을 조이고, 위험이 낮은 변경은 자동 리뷰로 돌리고, 사람의 리뷰는 위험이 높은 변경에 남기는 것이다.
7. 장기 작업에는 Plan Mode와 Goal Mode가 필요하다. Plan Mode는 구현 전에 컨텍스트 사용량을 보여 주므로 토큰을 쓰기 전에 부푼 작업을 나눌 수 있다. Goal Mode는 목표를 세션을 넘어 보존하므로 같은 일을 반복하는 실패를 없애고, 목표별 토큰 추적과 예산을 아는 이어가기를 더한다.
8. 결제와 압축에는 대안 경로가 있다. AWS Bedrock(내장)과 Azure OpenAI Service(커스텀 제공자)는 추론을 기존 클라우드 청구서로 합치고 약정 지출 할인을 열어 준다. 커뮤니티 압축 도구는 두 계층(RTK 같은 도구 출력 프록시, squeez의 원시인 모드 같은 출력 스타일 페르소나)에 있고, 배포 전에 작업 하나로 조사해 볼 가치가 있다. 헤드라인 입력 절감이 아니라 작업당 총비용을 재야 하며, 지나친 압축은 추가 설명이나 후속 호출을 부를 수 있다.
