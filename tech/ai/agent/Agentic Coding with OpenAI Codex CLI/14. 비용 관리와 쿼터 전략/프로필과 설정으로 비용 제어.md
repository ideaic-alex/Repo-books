# 프로필과 설정으로 비용 제어

Codex CLI의 가장 중요한 비용 제어 수단은 모델 라우팅이다. 어떤 작업을 어떤 모델에, 어떤 추론 강도(reasoning effort)로 보낼지 정하는 일이다. 런타임에는 세션당 토큰 상한을 거는 하드 캡 설정 키가 없다. 그래서 비용 관리는 6장에서 다룬 프로필(profile) 체계와, 아래에서 설명할 압축 관련 한도 키로 이루어진다.

---

## 1. 프로필로 모델 라우팅하기

6장에서 이름 있는 프로필의 동작 방식을 자세히 다뤘다. 프로필은 `~/.codex/<이름>.config.toml` 파일 하나이고 최상위 키로 값을 적는다. `--profile <이름>`을 주면 이 파일이 `~/.codex/config.toml` 위에 덮어씌워진다. 우선순위는 다음과 같다.

```text
CLI 플래그 > 프로필 > 프로젝트 설정 > 사용자 설정 > 기본값
```

이 장은 같은 체계를 비용 관점에서 쓴다. 프로필마다 저렴한, 균형 잡힌, 또는 고성능 설정을 고정해 두면 알맞은 비용 구조를 플래그 하나로 고를 수 있다.

```toml
# ~/.codex/config.toml
model = "gpt-5.4"
model_reasoning_effort = "medium"

# ~/.codex/explore.config.toml
model = "gpt-5.4-mini"
model_reasoning_effort = "low"
```

```toml
# ~/.codex/commit.config.toml
model = "gpt-5.4"
model_reasoning_effort = "medium"

# ~/.codex/reason.config.toml
model = "gpt-5.4-mini"
model_reasoning_effort = "high"
```

프로필을 부를 때는 `--profile`(또는 `-p`)을 쓴다.

```bash
codex --profile explore "browse the auth module and explain how the session middleware works"
codex -p commit "implement the new user authentication flow"
codex -p reason "design a back-pressure scheme for the ingest pipeline"
```

각 프로필의 역할은 다음과 같다.

- 최상위 `model`과 `model_reasoning_effort`는 프로필을 지정하지 않았을 때의 기본값이다.
- `explore` 프로필은 가장 싼 설정이다. 코드를 훑거나 빠르게 실험할 때 적합하다.
- `commit` 프로필은 실제 결과물을 만들 작업에 쓰는 전체 성능 모델이다.
- `reason` 프로필은 gpt-5.4-mini에서 추론 비용(추론세, 이 장 뒤에서 설명)을 치르는 설정이다. 확장된 추론이 도움이 되는 작업을 같은 강도의 gpt-5.4보다 낮은 토큰 비용으로 처리한다.

작업 종류가 나뉘는 만큼 프로필을 더 만들어도 된다. 바꾸는 데 드는 것은 플래그 하나다.

---

## 2. 도구 출력과 압축을 제한하는 키

세션 하나가 부풀어 오르는 것을 막는 키가 세 개 있다.

1. `tool_output_token_limit`: 도구 결과 하나가 쓸 수 있는 토큰 예산의 상한이다. 이 제한이 없으면 브라우저 스냅샷이나 모노레포 grep 결과 하나가 한 번의 호출로 컨텍스트 윈도의 20%를 차지할 수 있다.
2. `model_auto_compact_token_limit`: 자동 압축이 시작되는 임계값이다. 컨텍스트 용량의 80~85%로 낮추면 요약기에게 더 여유가 생겨 요약 품질이 좋아지고, 뒤따르는 추가 압축이 줄어든다.
3. `compact_prompt`: 기본 압축 요약 프롬프트를 덮어쓴다. 파일 경로, 함수 시그니처, 결정 이유를 보존하는 구조화된 인수인계 프롬프트를 쓰면, 모델이 파일을 다시 읽지 않고도 요약만으로 이어서 작업할 수 있다.

이 세 키는 "폭주 세션에 돈이 새지 않게 막아 줘"에 가장 가까운 설정 방식의 수단이다. 진짜 상한이 필요하다면 다음 문서의 모니터링 훅으로 폭주 소비를 사후에 감지하고, 다음 세션 전에 프로필을 조정해야 한다.

---

## 3. 조용히 새는 비용

서드파티 에이전트 프레임워크에서 비용이 조용히 쌓인 사례가 문서화돼 있다. 한 커뮤니티 제작 하니스는 백그라운드 하트비트 장치가 작업이 없는데도 토큰을 계속 소비해서, 유휴 세션 하나에 월 $86이 청구됐다고 보고했다. 이 하니스를 추천하는 것은 아니고, 능동적인 비용 텔레메트리가 왜 필요한지 보여 주는 예다.

어떤 런타임을 쓰든 비용 가시화 루프는 직접 만들어야 한다. 훅으로 이를 구성하는 방법은 다음 문서에서 다룬다. 텔레메트리가 없다는 것은 조용한 소모가 있을 가능성이 크다는 뜻으로 받아들여야 한다.
