# 연습 문제

14장 끝의 연습 문제 네 개를 풀이 방향과 함께 정리한다. 모두 자기 팀의 실제 사용 데이터로 해 보는 실습이라, 정답보다 측정과 비교 과정이 중요하다.

---

## 1. 우리 팀 비용 추정 만들기

팀 비용 추정 문서의 5명 팀 계산을 틀로 삼아, 지난 한 주 동안의 자기 팀 Codex CLI 사용량으로 추정치를 만든다. 실제 사용 데이터가 없으면 대표적인 세션 다섯 개를 골라 `--debug` 출력으로 세션 종류별 평균 토큰 수를 잰다. 그런 다음 추정치를 OpenAI 사용량 대시보드의 실제 비용과 비교하고, 틀의 가정 중 현실과 가장 많이 달랐던 것을 적는다.

풀이 방향: 조율자와 작업자의 입력, 출력 토큰 평균, 작업당 작업자 수, 하루 작업 수를 자기 값으로 바꿔 같은 식에 넣는다. 오차가 가장 큰 항목은 대개 세션 깊이(입력 토큰)이거나 작업자 수이므로 그 둘부터 의심한다.

---

## 2. 프로필 기반 라우팅 설정

`~/.codex/explore.config.toml`, `~/.codex/commit.config.toml`, `~/.codex/reason.config.toml` 세 파일로 프로필 셋을 만든다. 탐색용은 gpt-5.4-mini, 커밋용은 gpt-5.4, 추론 작업용은 높은 강도의 gpt-5.4-mini다. 세션 비용 데이터를 로컬 로그 파일에 덧붙이는 Stop 훅도 추가한다. 이틀 동안 작업마다 알맞은 프로필로 최소 열 번의 세션을 돌린다. 끝나면 로그를 분석해, 모든 세션에 commit 프로필을 썼다면 총비용이 얼마였을지 계산한다.

풀이 방향: 세션마다 쓴 프로필과 토큰 합계를 로그에서 모으고, 같은 토큰을 gpt-5.4 단가로 다시 곱해 실제 합계와 비교한다. 차이가 곧 라우팅으로 아낀 금액이다. 입력과 출력 단가가 다르므로 입력, 출력을 나눠 계산한다.

---

## 3. 팀 비용 귀속 체계 만들기

팀이 API 키를 공유하거나 Codex Cloud를 쓴다면 비용 귀속 체계를 설계한다. 용도 세 가지 이상(대화형 개발, CI 파이프라인, 자동 리뷰)마다 별도 API 키를 만들거나 OpenAI API의 metadata 필드로 비용 태그를 붙인다. 상황에 맞는 키나 태그를 설정해 주는 짧은 스크립트나 셸 별칭도 쓴다. 한 주 뒤 OpenAI 사용량 대시보드에서 사용 내역을 가져와 귀속이 제대로 되는지 확인하고, 용도별 비용을 계산해 토큰당으로 가장 비싼 용도와 총액으로 가장 비싼 용도를 가려낸다.

풀이 방향: 키를 용도별로 나누는 것이 가장 단순하고 확실하다. 토큰당 단가가 높은 용도와 총액이 큰 용도는 다를 수 있으므로 두 지표를 따로 계산해 비교한다.

---

## 4. 가장 비싼 세션 감사

사용량 대시보드나 로컬 비용 로그에서 이번 달 가장 비쌌던 Codex CLI 세션을 찾는다. `~/.codex/sessions/` 아래 그 세션의 트랜스크립트 `.jsonl`을 열어 토큰 구성을 분석한다. 시스템 프롬프트가 얼마, 끝 시점의 대화 기록이 얼마, 도구 호출 결과가 얼마인지 본다. 가장 큰 기여 요인을 찾고, 비슷한 세션의 비용을 최소 20% 줄일 워크플로 변경 하나(프롬프트, 컨텍스트 관리, 설정 중 하나)를 설계한다.

풀이 방향: 대개 도구 결과나 누적된 기록이 가장 크다. 도구 결과가 크면 `tool_output_token_limit`, 기록이 크면 60%에서의 수동 압축이나 작업 분할, 서브에이전트 위임을 후보로 삼고, 줄어들 토큰을 계산해 20% 목표에 맞는지 확인한다.
