# 멀티 에이전트 조율 패턴

11장에서 익힌 서브에이전트 부품을 어떻게 엮어 여러 단계 작업으로 만드는지 다루는 장이다. 현장에서 반복되는 네 가지 조율 패턴과, 한 세션 안에서 감독자처럼 일하게 해 주는 대화 분기 명령, 어떤 패턴이든 감싸는 지속 목표 `/goal`, 외부에서 세션을 모는 `codex remote-control`을 설명한다.

새 부품을 더하는 장이 아니라 이미 아는 부품을 조합하는 방법을 배우는 장이다. 게이트, 상한, 격리, 기록이라는 규율이 핵심이며, 조율을 조용히 망가뜨리는 안티패턴과 디버깅 기법도 함께 정리한다. 원서의 그림 다섯 장은 각 문서에 그대로 실었다.

---

## 1. 핵심 요점

- 랄프 루프는 단순하고 유용하지만, 성공 판정이 작업과 한 몸이고 감사 기록이 없으며 한 모델이 모든 단계를 맡는다는 약점이 있다. 네 패턴은 그 대안이다.
- 순차 게이트 체인은 넘김 지점마다 결정적 검증(`output_schema` 등)을 두어 실패가 아래로 번지는 것을 막는다.
- 웨이브 기반 혼합은 의존 작업을 병렬 가능한 웨이브로 묶고, 웨이브 경계를 품질 게이트로 삼는다. 의존 그래프를 먼저 그리는 것이 핵심이다.
- 교차 모델 리뷰 루프와 반복 수리 루프는 반복 상태를 스크립트가 쥐고, 읽기 전용 리뷰어, 구조화된 출력, 정지 조건(상한, 개선 없음, 사람 검토)을 갖춘다.
- `/fork`, `/side`, `/btw`는 하니스 없이 세션 안에서 하는 가벼운 감독 수단이고, 작업이 많고 균질하면 프로그램적 조율로 넘어간다.
- `/goal`은 토큰 예산과 감사 기반 완료 확인을 갖춘 지속 목표다. 좋은 목표 문장은 결과, 검증 명령, 쓰기 범위, 정지 조건, 멈춤 트리거를 담는다.
- `codex remote-control`은 외부 오케스트레이터가 컨텍스트를 공유하는 세션을 여러 단계로 몰게 해 주는 실험적 표면이다.
- 안티패턴은 게이트 없는 넘김, 집계 없는 팬아웃, 끝없는 반복, 쓰기 가능한 리뷰어, 공유 가변 상태다. 모든 팬아웃에는 `max_concurrency`를 명시한다.
