# openai-codex 저장소 사례

Codex CLI를 움직이는 Rust 워크스페이스인 openai/codex 저장소는 자기 자신의 AGENTS.md를 갖고 있다. 실제 운영 중인 파일이라 다른 프로젝트에도 옮겨 쓸 만한 패턴이 많다. 이 문서에서는 원문이 뽑아낸 여섯 가지 패턴을 설명한다.

---

## 1. 여섯 가지 패턴

원문은 이 파일에서 어느 프로젝트에도 적용되는 패턴 여섯 가지를 꼽는다. 출처는 GitHub의 openai/codex 저장소에 있는 AGENTS.md다.

### 1.1 직관에 어긋나는 관례를 적는다

코드만 봐서는 알 수 없고 모델이 틀리기 쉬운 규칙이 여기에 해당한다. 원문의 예는 async trait의 정확한 시그니처, 그리고 프로토콜 필드는 camelCase인데 설정은 snake_case를 쓰는 식의 이름 규칙 분리다. 앞 문서의 포함 기준 중 "추론할 수 없다"를 그대로 실천한 사례다.

### 1.2 구체적인 명령으로 품질을 관문 처리한다

"테스트를 잘 돌려라"가 아니라 정확한 명령을 적는다. UI를 바꾼 뒤에는 `just test -p codex-tui`를 돌리고, `Cargo.toml`을 바꾼 뒤에는 `just bazel-lock-update`를 돌리는 식이다. 어떤 변경 뒤에 어떤 명령을 실행해야 하는지 짝으로 적혀 있다.

### 1.3 모듈 크기 제한을 둔다

모듈은 테스트를 빼고 500줄 아래로 유지하고, 800줄을 넘는 파일은 분리 대상으로 표시한다. 에이전트가 한 파일에 계속 코드를 쌓는 경향을 숫자로 막는 방법이다.

### 1.4 손대면 안 되는 구역을 선언한다

샌드박스 격리를 담당하는 코드는 수정하지 못하게 금지한다. 어떤 영역이 금지인지 분명히 적어 두는 것이 핵심이다.

### 1.5 중력 우물식 성장에 저항한다

중심이 되는 거대한 크레이트(Rust의 패키지 단위) 쪽으로 새 코드가 자꾸 빨려 들어가는 현상을 막는다. 새 코드를 덩치 큰 중앙 크레이트가 아니라 다른 곳으로 돌리도록 지시한다.

### 1.6 API 관례를 표로 적는다

표는 토큰이 적게 들고 해석이 모호하지 않다. 규칙이 여러 항목에 걸쳐 일관된 구조를 가질 때는 문장보다 표가 낫다.

## 2. 이 사례에서 가져갈 것

여섯 패턴에는 공통점이 있다. 모두 구체적이고 검증 가능하며, 모델이 스스로 알 수 없는 프로젝트 고유 사정을 담는다. 일반론이나 구조 설명은 없다. 이는 앞서 본 ETH Zurich 연구가 효과 있는 내용이라고 가려낸 것과 겹친다.

원문은 이 여섯 패턴 외에 openai/codex 파일의 전체 내용은 소개하지 않는다. 각 패턴의 세부 수치(500줄, 800줄)와 명령 이름만 원문에 나온 그대로 옮겼고, 이 이상은 원문에서 확인되지 않는다.
