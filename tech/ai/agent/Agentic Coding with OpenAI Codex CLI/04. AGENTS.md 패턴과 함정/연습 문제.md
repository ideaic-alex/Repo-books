# 연습 문제

4장 끝에는 다섯 개의 연습 문제가 있다. 모두 실제 프로젝트에 AGENTS.md를 적용하고 다듬어 보는 실습이다. 각 문제의 취지를 풀어 쓰고 풀이 방향을 덧붙인다.

---

## 1. 내 프로젝트의 AGENTS.md 쓰기

지금 일하는 프로젝트 하나를 골라 AGENTS.md를 처음부터 써 본다. 특히 명령(Commands) 섹션을 가장 먼저 채운다.

풀이 방향: 설치, 빌드, 테스트, 린트, 타입 검사처럼 에이전트가 자기 작업을 검증할 때 쓸 명령을 실제로 돌아가는 형태로 적는다. Docker 같은 선행 조건이 있으면 그 줄에 같이 적고, 이 섹션을 파일 맨 위에 둔다.

## 2. 검증 시험 돌려 보기

원문은 "세 질문 검증 시험"이라고 부르는데, 이 장 본문에는 이 이름의 시험이 따로 정의되어 있지 않다. 가장 가까운 것은 본문의 진단 방법이다. Codex CLI에게 이번 세션에 어떤 AGENTS.md 파일을 어떤 순서로 불러왔는지 물어보는 것이다. 이 방식으로 새로 쓴 파일을 검증하고, 답이 내가 쓴 내용과 일치하는지 본다.

풀이 방향: `codex --ask-for-approval never`로 불러온 파일 목록과 전체 경로를 물어보고, 내가 의도한 파일이 의도한 순서로 나오는지 확인한다. 어긋나면 파일 이름, 빈 파일 여부, 크기 제한, 실행 위치를 점검한다.

## 3. 모노레포 구조 그려 보기

모노레포 하나를 떠올려서 계층형 AGENTS.md 구조를 스케치한다. 어떤 규칙이 저장소 루트에 가고, 어떤 규칙이 서비스 수준에 가는지 나눈다.

풀이 방향: 모든 서비스에 공통인 것(저장소 구성, 전체 CI 명령, 공통 관례)은 루트에 둔다. 특정 서비스에만 해당하는 것(언어별 규칙, PCI 같은 규제 규칙, 인프라 state 파일 주의)은 해당 디렉터리에 둔다. 위쪽의 느슨한 규칙을 반드시 덮어야 하는 곳은 `AGENTS.override.md`를 고려한다.

## 4. 가지치기 실습

기존 AGENTS.md 하나에 가지치기 점검표를 적용한다. 각 지침을 네 종류로 분류한다. 아키텍처 설명(삭제), 일반 모범 사례(삭제), 프레임워크 관례(삭제), 추론할 수 없는 팀 결정(유지)이다.

풀이 방향: 줄마다 "에이전트가 저장소를 읽으면 알 수 있는가", "모델이 원래 아는가", "README와 겹치는가"를 묻는다. 특정 디렉터리에만 해당하는 규칙은 아래로 내리고, 특정 워크플로에서만 쓰이는 것은 스킬로 옮긴다. 남은 줄은 포함 기준 네 가지를 다시 통과하는지 본다.

## 5. 제거 실험

유용하다고 믿는 지침 하나를 일부러 지워 본다. 그리고 대표적인 작업 다섯 개를 돌려 본다. 에이전트의 행동이 달라지는가.

풀이 방향: 지우기 전에 다섯 작업을 정하고, 지운 뒤 같은 작업을 돌려 결과를 비교한다. 달라지지 않는다면 그 지침은 불필요했을 가능성이 높다. 달라진다면 그 지침이 실패에 근거한 것이라는 증거이므로 되살린다. 이 실험은 지침이 실제로 값어치를 하는지를 확인하는 방법이다.
