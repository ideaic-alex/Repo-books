# 요약

4장의 핵심을 여덟 항목으로 다시 묶는다. 각 항목이 어느 문서에서 자세히 다뤄지는지도 함께 적는다.

---

## 1. 장 요약

1. AGENTS.md가 있으면 Codex CLI가 믿을 만한 협업자가 된다. 없으면 에이전트는 유능하지만 기억을 못 한다. Codex CLI는 `~/.codex/`, 저장소 루트, 현재 작업 디렉터리 순서로 AGENTS.md를 이어 붙여 지침 체인을 만들고, 충돌하면 더 가까운 파일이 이긴다. 자세한 내용은 [AGENTS.md가 읽히는 방식](AGENTS.md%EA%B0%80%20%EC%9D%BD%ED%9E%88%EB%8A%94%20%EB%B0%A9%EC%8B%9D.md)에 있다.
2. 꼭 필요한 섹션은 네 가지다. 명령(Commands), 커밋 규칙, 코드 스타일, 제약이다. [꼭 들어갈 섹션과 보안](%EA%BC%AD%20%EB%93%A4%EC%96%B4%EA%B0%88%20%EC%84%B9%EC%85%98%EA%B3%BC%20%EB%B3%B4%EC%95%88.md)에서 다룬다.
3. 크기 제한은 조용히 작동한다. `project_doc_max_bytes`(기본 32 KiB)를 넘으면 경고 없이 잘리므로 중요한 규칙을 앞에 둔다.
4. 모노레포에서는 계층을 나눈다. 하위 디렉터리의 AGENTS.md 덕분에 각 서비스가 딱 필요한 지침만 받는다. [모노레포와 CI 설정](%EB%AA%A8%EB%85%B8%EB%A0%88%ED%8F%AC%EC%99%80%20CI%20%EC%84%A4%EC%A0%95.md)을 본다.
5. AGENTS.md는 폭넓은 지원을 받는 개방 표준이다. 리눅스 재단 산하에서 운영되며 30개가 넘는 에이전트 제품이 지원한다.
6. LLM이 생성한 컨텍스트는 성능을 해친다. ETH Zurich 연구에 따르면 표준에서 벗어난 도구 사용법과 추론할 수 없는 팀 결정만이 긍정적인 효과를 냈다. [흔한 실수와 정리](%ED%9D%94%ED%95%9C%20%EC%8B%A4%EC%88%98%EC%99%80%20%EC%A0%95%EB%A6%AC.md)에서 다룬다.
7. 지침을 추가하기 전에 네 가지 시험을 통과해야 한다. 실패에 근거하는가, 추론할 수 없는가, 항상 관련 있는가, 발동 장면을 말할 수 있는가다.
8. AGENTS.md를 코드처럼 다룬다. 변경은 풀 리퀘스트로 리뷰하고, 의미 있는 커밋 메시지를 쓰고, 분기마다 가지치기하는 주기를 잡는다.

## 2. 덧붙이는 맥락

이 장에서 소개한 [3단 지식 구조](3%EB%8B%A8%20%EC%A7%80%EC%8B%9D%20%EA%B5%AC%EC%A1%B0.md), [openai-codex 저장소 사례](openai-codex%20%EC%A0%80%EC%9E%A5%EC%86%8C%20%EC%82%AC%EB%A1%80.md), [함께 쓰는 Markdown 파일들](%ED%95%A8%EA%BB%98%20%EC%93%B0%EB%8A%94%20Markdown%20%ED%8C%8C%EC%9D%BC%EB%93%A4.md)은 요약 항목 여덟 개에 직접 나오지 않지만 같은 원칙에서 나온다. 지침은 작고 구체적이며 필요한 곳에 있어야 한다는 원칙이다. 그리고 AGENTS.md는 어디까지나 부드러운 지침이므로, 실제로 행동을 막는 단단한 장치는 5장의 승인 정책과 샌드박스에서 다룬다.
