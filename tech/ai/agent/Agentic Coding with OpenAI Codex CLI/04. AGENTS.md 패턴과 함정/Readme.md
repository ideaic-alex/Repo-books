# AGENTS.md 패턴과 함정

프롬프트는 세션이 끝나면 사라지지만, 팀이 Codex CLI에게 늘 요구해야 하는 것들은 매번 같다. AGENTS.md는 그 상시 규칙, 프로젝트 관례, 넘지 말아야 할 선을 저장소에 Markdown으로 적어 두고 모든 세션에서 자동으로 읽히게 하는 방법이다. 이 장은 프롬프트 한 번을 잘 쓰는 기술에서 한 걸음 나아가, 모든 프롬프트를 반복 없이 더 낫게 만드는 기반 시설을 다룬다.

장을 마치면 AGENTS.md를 처음부터 써 보고, 모노레포에 계층형으로 배치하고, 규칙이 안 먹을 때 원인을 추적하고, 부풀어 오른 파일을 가지치기하고, 코드처럼 관리하는 방법을 알게 된다. 또 AGENTS.md가 PLANS.md, SKILL.md, DESIGN.md, SOUL.md 같은 다른 Markdown 파일과 어떻게 어울리는지도 본다.

---

## 1. 핵심 요점

- Codex CLI는 `~/.codex/`, git 루트, 중간 디렉터리, 현재 디렉터리 순으로 AGENTS.md를 이어 붙여 읽고, 충돌하면 가까운 파일이 이긴다. 같은 단계에서는 `.override.md`가 우선한다.
- 불러오는 전체 크기는 `project_doc_max_bytes`(기본 32 KiB)로 제한되며, 넘는 부분은 경고 없이 잘린다. 중요한 규칙은 위쪽에 둔다.
- 꼭 필요한 섹션은 명령, 커밋 규칙, 코드 스타일, 제약이다. 명령은 맨 위에 두고 선행 조건까지 적는다.
- AGENTS.md는 보안 경계가 아니라 안내일 뿐이다. 진짜 보호는 파일시스템 권한, 브랜치 보호 규칙으로 하고, 공급망 주입 위험에는 락 파일, 리뷰, 해시 검증 훅으로 대비한다.
- 모노레포는 디렉터리별 AGENTS.md로 나누고, 규모가 커지면 헌법, 전문가, 지식 창고(MCP)의 3단 구조를 쓴다.
- LLM이 생성한 컨텍스트 파일은 성공률을 낮추고 비용을 올렸다. 효과가 있는 것은 표준에서 벗어난 도구 사용법과 추론할 수 없는 팀 결정뿐이다.
- 지침은 실패에 근거하고, 추론할 수 없고, 항상 관련 있고, 발동 장면을 말할 수 있을 때만 넣고, 가지치기 점검표로 정기적으로 덜어낸다.
- 필요하면 PLANS.md, SKILL.md, DESIGN.md, SOUL.md, WORKFLOW.md를 곁들이되, 대부분의 팀은 AGENTS.md 하나로 충분하다.
