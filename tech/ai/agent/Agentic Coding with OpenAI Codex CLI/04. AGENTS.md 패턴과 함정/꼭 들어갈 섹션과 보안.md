# 꼭 들어갈 섹션과 보안

잘 쓰인 AGENTS.md는 대부분 비슷한 섹션으로 수렴한다. 모델이 소스 코드만 보고는 알아내기 어려운 정보가 거의 같은 종류이기 때문이다. 이 문서에서는 Commands, 커밋 규칙, 금지 영역을 어떻게 쓰는지 보고, AGENTS.md가 보안 장치가 아니라는 점과 공급망 공격 위험을 정리한다.

---

## 1. Commands: 가장 중요한 섹션

에이전트가 자기 작업을 검증하려고 실행할 수 있는 명령을 모두 적는다. 원문의 예시는 다음 항목들이다.

```markdown
## Commands
- Install dependencies: `npm ci`
- Build: `npm run build`
- Unit tests: `npm test`
- Integration tests: `npm run test:integration` (requires Docker; skip in CI if not available)
- Lint: `npm run lint -- --fix`
- Type-check: `npm run typecheck`
- Local dev server: `npm run dev` (port 3000)
```

핵심은 선행 조건을 명시하는 것이다. 통합 테스트 줄에 "Docker 필요"라고 적어 두면 Docker가 없는 환경에서는 그 명령을 돌리지 않아야 한다는 것을 Codex CLI가 안다. 개발 서버처럼 포트 번호가 있는 명령은 포트까지 적어 두면 헷갈릴 일이 없다.

## 2. 커밋 규칙

프로젝트가 Conventional Commits 같은 커밋 메시지 형식을 따른다면 여기에 적는다. 적지 않으면 평범하고 밋밋한 메시지가 나온다. 원문의 예시는 이렇다.

- 형식은 `<type>(<scope>): <description>`
- type은 feat, fix, docs, style, refactor, test, chore
- scope는 필수이며 모듈 또는 패키지 이름을 쓴다
- description은 명령형, 소문자, 끝에 마침표 없음

## 3. 제약과 금지 영역

선의로 한 변경이 파괴적인 결과를 낳는 일을 막는 곳이다. 원문의 예는 `src/generated/`, `schema/migrations/`, `package-lock.json`을 수정하지 말 것, 승인 없이 패키지를 설치하지 말 것, 배포 설정이 참조하는 환경 변수 이름을 바꾸지 말 것이다.

표현을 "Do NOT"으로 쓰는 것은 일부러 고른 방식이다. 넘지 말아야 할 선에는 부정형 지시가 더 믿을 만하다고 원문은 설명한다.

## 4. AGENTS.md는 보안 경계가 아니다

중요한 경고가 하나 있다. AGENTS.md는 보안 경계가 아니다. 프롬프트에서 "그 파일은 무시해"라고 하면 Codex CLI는 그렇게 할 수 있다. 정말 지켜야 하는 파일이 있다면 파일시스템 권한이나 저장소의 브랜치 보호 규칙을 써야 한다. AGENTS.md는 안내이지 강제가 아니다. 이 구분은 5장에서 다룰 승인 정책과 샌드박스가 실제 강제 수단이라는 이야기로 이어진다.

## 5. 공급망 주입 위험

AGENTS.md는 최고 수준의 신뢰를 받으며 로드되고 세션을 넘어 계속 남기 때문에 공급망 공격의 매력적인 목표가 된다. 의존성 해석 과정에서 임의 코드를 실행하는 빌드 시스템은 모두 취약하다. 원문이 든 예는 Go의 `init()`, Python의 `setup.py`, Node.js의 `postinstall`, Rust의 `build.rs`다.

원문은 NVIDIA AI Red Team이 2026년 4월에 낸 "Indirect AGENTS.md Injection via Malicious Dependencies"를 근거로 든다. `go mod tidy`를 실행하는 동안 악성 AGENTS.md를 써 넣는 Go 모듈로 개념 증명을 했다고 한다.

방어 방법은 세 가지다.

- 락 파일로 의존성을 고정한다.
- AGENTS.md를 코드 리뷰 체크리스트에 넣고, CI 설정을 바꿀 때와 같은 엄격함으로 변경을 본다.
- 세션 시작 시점에 AGENTS.md 내용이 알려진 정상 해시와 같은지 확인하는 PreToolUse 훅 사용을 고려한다.

공급망 위험과 검증 훅은 16장에서 더 깊이 다룬다.
