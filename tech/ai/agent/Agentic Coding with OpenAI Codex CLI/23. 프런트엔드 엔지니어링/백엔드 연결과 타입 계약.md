# 백엔드 연결과 타입 계약

전광판이 그릴 데이터는 22장 백엔드가 준다. 그래서 백엔드부터 띄워 응답 모양을 확인하고, 브라우저의 교차 출처 호출이 막히지 않게 CORS를 열고, 그 응답을 프런트엔드 타입으로 옮긴다. 이 문서는 그 세 단계와, 타입 계약이 보장하는 것과 보장하지 못하는 것을 정리한다.

---

## 1. 백엔드 띄우고 응답 확인

run-or-relax/ 저장소에서 프런트엔드와는 다른 터미널을 열어 실행한다.

```bash
uv run uvicorn departures.app:app --reload   # localhost:8000
curl 'http://localhost:8000/departures?station=audley-end'
```

응답은 다음과 같은 JSON 배열이다. 필드 이름은 camelCase다.

```json
[
  {"service": "07:02", "platform": "2", "delayMinutes": 0,
   "minutesUntil": 10, "verdict": "RUN"}
]
```

## 2. CORS 열기

전광판은 localhost:3000에서, API는 localhost:8000에서 돈다. 브라우저의 fetch가 다른 출처로 나가므로 백엔드가 CORS 헤더를 보내지 않으면 브라우저가 응답을 막는다. 22장 서비스에 한 줄 추가하는 일이라서 에이전트에게 이렇게 시킨다. src/departures/app.py에 FastAPI의 CORSMiddleware를 넣되, 개발 중에는 http://localhost:3000을, 운영에서는 배포된 전광판의 출처를 환경 변수로 읽어 허용하고, AGENTS.md를 따르라고 한다.

## 3. 계약 타입 만들기

백엔드가 닿는 것을 확인하면 프런트엔드 코드베이스에 가장 먼저 들어가는 것은 계약 타입이다. AGENTS.md의 "API 응답 모양에는 모두 명시적 타입" 규칙이 요구하는 일이다. 22장의 camelCase JSON을 그대로 거울처럼 옮긴다. 파일은 lib/departures.ts다.

```ts
const API_BASE =
  process.env.NEXT_PUBLIC_DEPARTURES_API_URL ?? "http://localhost:8000"
export interface Departure {
  service: string        // 예: "07:02"
  platform: string
  delayMinutes: number; minutesUntil: number
  verdict: "RUN" | "relax"
}
export async function fetchDepartures(station: string, now?: string): Promise<Departure[]> {
  const params = new URLSearchParams({ station })
  if (now) params.set("now", now)
  const res = await fetch(`${API_BASE}/departures?${params}`)
  if (!res.ok) throw new Error(`departures: ${res.status}`)
  return res.json()
}
```

몇 가지 설계 이유가 있다.

- `URLSearchParams`가 station과 선택 인자 now를 인코딩하므로, 이상한 역 ID가 와도 URL이 깨지지 않는다.
- 기본 주소를 `NEXT_PUBLIC_DEPARTURES_API_URL`에서 읽기 때문에, 같은 빌드가 개발에서는 localhost:8000을, 운영에서는 배포된 API를 가리킨다.
- `now` 덮어쓰기는 22장이 노출한 ISO 8601 파라미터와 같다. 운영 전광판은 이걸 생략하지만, 테스트와 데모는 고정값을 넘겨서 전광판을 결정적으로 만든다.

## 4. 타입 계약의 한계

솔직히 짚어야 할 한계가 있다. Departure 인터페이스는 백엔드 계약을 비춘 거울일 뿐, 런타임 보증이 아니다. TypeScript는 코드가 기대하는 모양을 검사할 뿐 네트워크로 실제 들어온 바이트를 검사하지 않는다. 그래서 응답이 어긋나거나 에러 응답이 와도 타입 검사기는 잡지 못한다.

그래도 공유 유니온 `verdict: "RUN" | "relax"`는 값을 한다. 이 값에 switch로 분기하는 컴포넌트는 구성상 빠짐없이(exhaustive) 처리하게 되고, 백엔드에 세 번째 판정이 생기면 `pnpm tsc --noEmit`이 실패한다. 경계를 런타임에도 강제하고 싶으면 Codex에게 응답을 Zod 스키마나 손으로 쓴 `isDeparture` 가드로 검증한 뒤 반환하게 하라고 시키면 된다.
