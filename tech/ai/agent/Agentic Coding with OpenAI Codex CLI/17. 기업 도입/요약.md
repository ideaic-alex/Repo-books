# 요약

17장의 핵심 열 가지를 정리한다. 각 항목은 해당 주제 문서에서 자세히 다룬 내용을 한 문단으로 압축한 것이다.

---

## 1. 장 전체 요약

1. **진짜 제약은 설정이 아니라 신뢰다.** 설정 배포는 쉬운 부분이다. 기업의 과제는 책임, 증거, 그리고 리뷰 용량을 생성 용량과 보조를 맞추는 일이다.
2. **설정은 배포하되 기준선은 최소로 둔다.** MDM, 도트파일 저장소, 구성 관리 중 어느 것으로도 `config.toml`을 퍼뜨릴 수 있다. 꼭 잠가야 하는 것만 잠그고 나머지는 팀 재량에 맡긴다. 지나친 중앙 집중은 우회로를 낳는다.
3. **관리형 정책은 로컬에서 덮어쓸 수 없다.** 클라우드 관리형 `requirements.toml`은 로컬 `config.toml`이 약화시킬 수 없는 조직 제약을 강제하고, 기업 계정 인증 때 자동으로 적용된다.
4. **RBAC과 SCIM으로 접근 통제를 확장한다.** IdP의 Codex Admins 그룹을 동기화하면 엔지니어를 팀에 넣는 것만으로 알맞은 접근 등급이 부여된다.
5. **3단계 온보딩이 신뢰를 단계적으로 쌓는다.** 관찰, 안내된 자율, 자율 운영 순서로 가고, 단계가 바뀔 때마다 회고를 한다.
6. **ROI 지표는 객관적이고 관찰 가능해야 한다.** 지어낸 절약 시간 대신 개입 없이 끝난 작업, 리뷰 통과율, 저작 방식별 결함 유출률을 본다.
7. **멀티 클라우드 라우팅이 팀별 제약을 맞춘다.** 정책 등급별로 제공자를 정하면 사업 부문이 거주 요건, 비용, 성능 요구에 따라 Azure OpenAI, Bedrock, 직접 OpenAI API 중 고를 수 있다.
8. **거버넌스에는 코드로서의 정책, 감사 추적, 승인 워크플로가 필요하다.** 버전 관리되는 정책, 변경 불가능한 세션 로그, 작업을 시작한 개발자와 독립된 사람의 검토 지점이다.
9. **3계층 모니터링 모델이 담당을 분명히 한다.** 도입 현황은 분석, 지금 벌어지는 일은 관측, 변경 불가능한 기록은 컴플라이언스 내보내기가 맡는다.
10. **도입이 어떻게 실패하는지 안다.** 섀도 AI, 정책 연극, 리뷰 병목, 라이선스 낭비, 책임 공백이 기업 프로그램을 멈추게 하며, 각각 도구가 아닌 구조적 해법이 있다.
