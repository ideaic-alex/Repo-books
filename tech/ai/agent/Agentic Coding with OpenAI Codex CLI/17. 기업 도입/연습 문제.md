# 연습 문제

17장의 연습 문제 세 개를 우리말로 풀어 쓰고, 어떻게 접근하면 좋을지 방향을 덧붙인다.

---

## 1. 연습 17-1: 조직용 requirements.toml 설계

조직에 맞는 `requirements.toml`을 설계한다. 정책 등급은 최소 세 개로 하고, 등급마다 무엇을 제한하는지와 그 이유를 적는다. 그다음 baseline 등급을 자기 컴퓨터에서 테스트해서, 관리형 제약을 로컬 `config.toml`로 덮어쓸 수 없는지 확인한다.

풀이 방향: baseline, engineering, restricted처럼 장에서 본 네 등급(admin 포함)을 출발점으로 삼아 `allowed_sandbox_modes`, `allowed_approval_policies`, 허용 도메인, 접두어 규칙을 등급별로 다르게 둔다. 로컬 `config.toml`에 더 느슨한 값(예를 들어 다른 승인 정책)을 써 넣고 세션을 시작해, CLI가 남기는 적용된 관리형 정책 로그와 실제 동작이 관리형 값을 따르는지 본다.

## 2. 연습 17-2: 10명 팀 온보딩 계획

열 명으로 이뤄진 팀을 위한 3단계 온보딩 계획을 만든다. 단계별 구체적인 작업, 다음 단계로 넘어가는 성공 기준, 단계 전환마다 던질 회고 질문을 정한다.

풀이 방향: 1단계는 테스트 픽스처 갱신이나 의존성 버전 올리기처럼 위험이 낮은 작업, 2단계는 모든 diff를 리뷰하는 범위 지정 작업, 3단계는 테스트 묶음이 성공 기준인 작업으로 잡는다. 성공 기준에는 개입 없이 끝난 작업 비율 같은 지표를 쓰고, 회고 질문은 "에이전트가 딱 맞게 한 사례와 엉뚱하게 간 사례를 하나씩 가져오라"를 바탕으로 만든다.

## 3. 연습 17-3: CI에서 저작 태깅 설정

CI 파이프라인에서 에이전트가 도운 풀 리퀘스트에 저작 태그를 붙이도록 설정한다. 스프린트 하나가 지난 뒤, 에이전트가 도운 PR과 사람이 직접 쓴 PR의 리뷰 통과율을 비교한다.

풀이 방향: 커밋 트레일러(`Agent-Assisted: codex`)를 검사하거나, Codex CLI 세션 ID를 감지했을 때 PR 라벨을 붙이는 방식으로 구현한다. 비교할 때는 첫 라운드에 수정 요청 없이 리뷰를 통과한 PR의 비율을 양쪽에서 구한다.
