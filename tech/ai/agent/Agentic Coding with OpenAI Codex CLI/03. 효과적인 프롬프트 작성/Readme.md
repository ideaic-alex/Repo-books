# 효과적인 프롬프트 작성

Codex CLI는 코드베이스를 읽고 명령을 실행하며 몇 분씩 혼자 일하는 도구라서, 프롬프트를 쓰는 일은 검색창에 입력하는 일보다 외주 개발자에게 업무를 브리핑하는 일에 가깝다. 이 장은 그런 에이전트형 도구에서 실제로 통하는 프롬프트 패턴을 다룬다.

목표, 맥락, 제약, 완료 기준이라는 네 요소를 시작으로 추론 강도와 플랜 모드, 작업별 패턴, 문서 생성, 지속 맥락(AGENTS.md와 프로필), 출력 제어, 메타프롬프팅, OpenAI의 공식 워크플로 레시피까지 순서대로 정리했다.

---

## 1. 핵심 요점

- 에이전트형 도구에서는 모호한 지시가 비싸다. 실행이 시작된 뒤에는 이미 여러 파일을 건드렸을 수 있다.
- 좋은 프롬프트는 목표, 맥락, 제약, 실행 가능한 완료 기준을 갖춘다. 작업 크기는 동료가 오후 한나절이면 끝낼 수준이 적당하다.
- model_reasoning_effort로 추론 깊이를 조절한다. 높다고 항상 좋지 않고 작업에 맞춰 고른다.
- 모호하거나 세 모듈 이상에 걸친 작업은 플랜 모드로 시작하고, 긴 작업은 PLANS.md와 체크포인트 패턴으로 쪼갠다.
- 엉뚱한 방향으로 가면 Esc로 끊는다. 해석이 둘로 갈린 프롬프트는 정정을 쌓지 말고 다시 쓴다.
- 모든 세션에 적용되는 규칙은 AGENTS.md에, 작업 모드별 태도는 프로필에 둔다.
- 메타프롬프팅은 사람이 검토해야 효과가 있고, 반복되는 실패만 규칙으로 남긴다.
- 공식 레시피 여덟 가지와 레시피별 프로필로 반복 작업을 표준화한다.
