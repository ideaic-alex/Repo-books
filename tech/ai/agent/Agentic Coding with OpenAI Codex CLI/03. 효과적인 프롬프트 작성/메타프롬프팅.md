# 메타프롬프팅

메타프롬프팅(metaprompting)은 LLM 호출 한 번을 써서, 이후 호출들이 쓸 프롬프트를 개선하는 방법이다. Codex CLI에서는 에이전트에게 자기 실패를 분석하게 하고, 세션이 끝나도 남는 세 가지 지시 파일에 구체적인 수정안을 내게 하는 일을 말한다. 세 가지는 AGENTS.md, 스킬(SKILL.md), config.toml이다. 원서는 OpenAI의 Codex Prompting Guide와 Best Practices 문서를 근거로 든다.

---

## 1. 사람이 승인 경로에 남는다

메타프롬프팅은 스스로를 수정하는 에이전트 루프가 아니다. 사람이 승인 과정에 계속 있다. Codex CLI는 제안하고, 사람이 검토해서 커밋한다. 이 구분이 중요한 이유는 연구 결과 때문이다. 원서에 따르면 사람이 가려내지 않은, 모델이 스스로 만든 지시 개선은 측정 가능한 이득이 없었고, 사람이 가려낸 개선은 통과율을 크게 끌어올릴 수 있었다.

## 2. 패턴 1: 세션 후 회고

가장 단순한 패턴은 일이 꼬였던 세션 끝에 돌리는 것이다. 실수를 구체적으로 나열하고 AGENTS.md의 최소 diff를 요청한다.

```text
You just completed a task but made two mistakes:
1. You ran `npm test` instead of `pnpm test`
2. You created a CommonJS module in an ESM-only project

Review the current AGENTS.md and propose a minimal diff
that would prevent both mistakes in future sessions.
Output the diff as a fenced apply_patch block.
```

'최소한의 diff'라고 요청하는 점이 요점이다. 그래야 AGENTS.md가 불필요하게 부풀지 않는다. 출력은 apply_patch 블록으로 받는다.

## 3. 패턴 2: codex exec로 일괄 분석

여러 저장소에서 Codex CLI를 쓰는 팀이라면 codex exec로 일괄 분석을 할 수 있다. 최근 세션 기록 다섯 개를 읽고, 사람이 에이전트의 첫 접근을 뒤집은 정정 패턴 중 가장 흔한 세 가지를 찾아, 각각을 없앨 AGENTS.md 추가안을 내게 한다.

```bash
codex exec "Read AGENTS.md and the last 5 session transcripts \
in ~/.codex/sessions/. Identify the three most common correction \
patterns where I overrode your initial approach. For each, propose \
a concrete AGENTS.md addition that would eliminate the correction. \
Output as a single Markdown file." \
 --sandbox read-only \
 -o /tmp/metaprompt-report.md
```

읽기 전용 샌드박스로 돌리고 결과는 -o 옵션의 파일에 받는다. 분석이 파일을 바꿀 일이 없다.

## 4. 패턴 3: 스킬 다듬기

스킬(skill, 필요할 때 불러 쓰는 작업 지침 묶음)은 점진적 공개(progressive disclosure) 방식으로 동작한다. Codex CLI는 처음에는 이름과 설명만 보고, 스킬이 활성화될 때 전체 지시를 불러온다. 그래서 설명이 정확해야 올바른 때에 켜진다.

```text
I have a skill at ~/.agents/skills/api-scaffold/SKILL.md.
It should activate when I ask to create a new REST endpoint
but NOT when I'm debugging an existing endpoint.
Review the current name, description, and trigger terms.
Propose updated frontmatter that improves activation precision.
Include three match examples and three non-match examples
I can use as manual test cases.
```

이 프롬프트는 켜져야 할 때와 켜지면 안 될 때를 둘 다 말해 주고, 수정된 frontmatter(파일 맨 위 메타데이터)와 함께 직접 시험해 볼 수 있는 일치 사례 세 개, 불일치 사례 세 개를 요청한다.

## 5. 피해야 할 안티패턴

메타프롬프팅은 장황하고 지나치게 세부적인 규칙을 만들어 AGENTS.md를 32 KiB 한도 너머로 부풀릴 수 있다. 모든 규칙은 간단한 시험을 통과해야 한다. 이 규칙이 반복되는 실패를 막는가, 아니면 한 번뿐인 실수를 막는가. 한 번뿐인 정정은 설정이 아니라 프롬프트에 속한다.

## 6. 세 패턴 한눈에 보기

| 패턴 | 언제 | 대상 | 방식 |
|---|---|---|---|
| 세션 후 회고 | 세션이 꼬인 직후 | AGENTS.md | 실수를 나열하고 최소 diff를 apply_patch 블록으로 받는다 |
| codex exec 일괄 분석 | 여러 저장소를 쓰는 팀 | AGENTS.md | 세션 기록에서 반복된 정정 패턴 세 개를 찾아 추가안을 낸다 |
| 스킬 다듬기 | 스킬이 엉뚱할 때 켜지거나 안 켜질 때 | SKILL.md 설명 | frontmatter 개선안과 일치/불일치 사례를 받는다 |
