# 연습 문제

3장 끝의 연습 문제 다섯 개를 풀이 방향과 함께 정리한다. 모두 직접 해 보는 실습이므로 정답은 없고, 무엇을 확인하면 되는지를 한두 문장으로 덧붙였다.

---

## 연습 3-1. 네 요소 프롬프트 쓰기

최근에 끝낸 작업 하나를 골라, 목표, 맥락, 제약, 완료 기준을 모두 갖춘 Codex CLI 프롬프트로 다시 써 본다.

풀이 방향은 이렇다. 목표는 결과 동사로 한 문장, 맥락에는 본보기 파일 경로를 넣는다. 완료 기준은 실제로 실행할 수 있는 명령과 기대 결과로 적는다. 완료 기준을 쓰기 어렵다면 작업이 아직 덜 정리된 것이다.

## 연습 3-2. AGENTS.md 점검하고 보강하기

팀에서 아직 문서화하지 않은 관례 세 가지를 구체적인 예시와 함께 AGENTS.md에 추가한다. 그다음 세션을 하나 돌려서 에이전트의 기본 행동이 바뀌는지 관찰한다.

풀이 방향은 이렇다. '코드를 깔끔하게 쓴다' 같은 추상적 문장 대신 '금액은 정수로 저장한다' 같은 검증 가능한 규칙을 고른다. 추가 전과 후에 같은 작업을 시켜 결과를 비교하면 변화가 보인다.

## 연습 3-3. 여러 곳에 걸친 변경에 플랜 모드 쓰기

다섯 개 이상의 파일에 걸친 변경을 골라 /plan을 실행한다. 실행을 승인하기 전에 계획을 검토한다.

풀이 방향은 이렇다. 계획에서 빠진 파일이나 잘못 짚은 가정을 찾아 승인 전에 고친다. 플랜 모드의 쓰기 금지는 프롬프트 수준이므로 버리는 브랜치에서 연습하는 것이 안전하다.

## 연습 3-4. 병렬 가능한 작업 표시하기

서로 독립적인 하위 작업을 명시적으로 표시한 프롬프트를 쓴다. 같은 일을 순차로 시켰을 때와 세션 소요 시간을 비교한다.

풀이 방향은 이렇다. 하위 작업이 같은 파일을 건드리지 않아야 독립적이라고 할 수 있다. 공통 도우미와 본보기 경로를 한 번만 주고 작업을 나열한 뒤 시간을 재 본다.

## 연습 3-5. 문서 생성과 신선도 점검

문서화가 안 된 모듈에 Codex CLI로 문서 주석을 달게 한다. 그다음 문서와 실제 API 표면을 비교하는 신선도 점검을 돌려서, 점검이 잡아낸 불일치를 기록한다.

풀이 방향은 이렇다. 주석 작업에서는 스타일과 본보기 파일을 지정한다. 점검은 codex exec를 읽기 전용 샌드박스로 돌리고 -o 옵션으로 결과 파일을 받는다. 문서에는 있지만 코드에서 사라진 항목과 그 반대 항목을 구분해서 적는다.
