# 요약

3장 전체를 여덟 가지 핵심 메시지로 정리한 노트다. 각 항목 뒤에는 어느 문서에서 자세히 다루는지 덧붙였다.

---

## 1. 여덟 가지 핵심

1. 에이전트 프롬프트는 미리 분명해야 한다. 모호한 프롬프트 하나가 몇 분짜리 실행을 시작시키고 여러 파일을 건드릴 수 있다. 대화형 AI는 모호하게 말해도 되지만 에이전트형 AI는 그럴 여유가 없다. (에이전트 프롬프트의 특징과 네 요소)
2. 좋은 프롬프트는 네 요소를 갖춘다. 목표, 맥락, 제약, 그리고 실행해서 확인할 수 있는 완료 기준이다. (에이전트 프롬프트의 특징과 네 요소)
3. 지속되는 맥락은 AGENTS.md에 둔다. 모든 프롬프트에 해당하는 규칙은 매번 반복해 적지 말고 파일에 넣는다. (반복 맥락을 프롬프트 밖으로)
4. 플랜 모드와 체크포인트를 쓴다. 플랜 모드는 코드를 바꾸기 전에 검토할 수 있는 전략을 내놓고, 체크포인트는 긴 작업을 검증된 증분으로 나눈다. (추론 강도와 플랜 모드)
5. 계속 정정하기보다 다시 구성한다. 세션이 잘못 흘러갈 때는 멈추고 프롬프트를 다시 짜는 편이 보통 정정을 밀어붙이는 것보다 싸다. (중간 수정과 작업별 프롬프트 패턴)
6. 메타프롬프팅에는 사람의 선별이 필요하다. 모델이 자기 지시 파일을 개선하게 할 때, 사람이 검토하면 결과가 좋고 자동으로 커밋하면 그렇지 않다. (메타프롬프팅)
7. 레시피와 프로필을 함께 쓴다. OpenAI의 공식 워크플로 레시피 여덟 가지는 목표, 맥락, 제약, 완료 조건 구조 위에 반복 패턴을 정리한 것이다. 이름 붙인 프로필로 레시피 범주를 바꿔 가며 쓰면 설정을 다시 하지 않아도 된다. (공식 워크플로 레시피 여덟 가지)
8. 문서 생성에도 쓴다. Codex CLI는 코드 주석, ADR, README를 만들고 관리할 수 있고, 문서 신선도 점검을 CI 작업으로 돌릴 수 있다. (문서 생성에 활용하기)

## 2. 설정 키 한눈에 보기

| 키 | 용도 |
|---|---|
| model_reasoning_effort | 추론 깊이 (minimal, low, medium, high, xhigh) |
| model_verbosity | 응답의 말 길이 (low, medium, high) |
| model_reasoning_summary | 추론 요약 표시 여부 |
| hide_agent_reasoning, show_raw_agent_reasoning | 추론 숨김과 원문 노출 |
| tool_output_token_limit | 도구 결과 하나의 토큰 상한 |
| model_auto_compact_token_limit | 자동 압축 시작 기준 |
| model_instructions_file | 프로필이 가리키는 사용자 지시 파일 |
| sandbox_mode, approval_policy | 레시피별 샌드박스와 승인 정책 |
