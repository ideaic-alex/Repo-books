# 플러그인과 마켓플레이스

스킬은 절차 지식을 담는다. 플러그인(plugin)은 그 지식을 앱 커넥터, MCP 서버 설정과 함께 설치하고 배포할 수 있는 한 덩어리로 묶는다. Codex 플러그인 마켓플레이스는 그 유통 경로로, 스킬, 앱 연동, MCP 서버 설정을 설치하고 갱신하는 관리형 워크플로를 제공한다. 이 문서는 플러그인 구조, 마켓플레이스 탐색 순서, 설치 정책, 수명 주기 명령을 다룬다.

---

## 1. 플러그인의 구조

플러그인은 `.codex-plugin/plugin.json` 매니페스트와 선택적인 구성 요소 묶음을 가진 디렉터리다. 매니페스트는 구성 요소를 최대 세 종류까지 선언한다.

1. 스킬: `skills/` 하위 디렉터리의 SKILL.md 파일. 이 장 앞에서 설명한 점진적 공개 모델 그대로 맥락에 따라 로딩된다.
2. 앱: 외부 서비스 커넥터(GitHub, Slack, Gmail, Google Drive). OAuth나 API 토큰으로 인증된 데이터 접근을 제공한다.
3. MCP 서버: `.mcp.json` 파일에 선언하는 Model Context Protocol 서비스. 외부 시스템의 도구와 공유 컨텍스트를 노출한다.

어떤 조합도 유효하다. 플러그인은 AGENTS.md 조각, config.toml의 MCP 섹션, OAuth 설정, 보조 자산을 설치 가능한 하나의 단위로 묶는다. 예시 구조는 다음과 같다.

```
my-review-tools/
├── .codex-plugin/
│   └── plugin.json       # 필수 매니페스트
├── skills/
│   ├── security-review/SKILL.md
│   └── perf-review/SKILL.md
├── .mcp.json             # 선택: MCP 설정
├── .app.json             # 선택: 앱 커넥터
└── assets/logo.png
```

가장 작은 `plugin.json`은 이렇게 쓴다.

```json
{
  "name": "my-review-tools",
  "version": "1.0.0",
  "description": "Code review patterns for the platform team",
  "skills": "./skills/",
  "mcpServers": "./.mcp.json",
  "interface": {
    "displayName": "Review Tools",
    "shortDescription": "Automated code review against team standards",
    "category": "Code Quality"
  }
}
```

매니페스트 안의 모든 경로는 `./`로 시작하고 플러그인 루트 기준 상대 경로여야 한다. `name` 필드는 안정적인 kebab-case여야 한다. Codex CLI가 마켓플레이스 작업 전반에서 이 값을 플러그인 식별자로 쓰기 때문이다.

## 2. 마켓플레이스 탐색 순서

Codex CLI는 플러그인 카탈로그를 세 곳에서 읽으며, 우선순위 순서로 해석한다.

1. openai/skills 선별 카탈로그: 검증된 플러그인의 공식 디렉터리다. 시작할 때 가져와 로컬에 캐시한다. `/plugins` TUI 브라우저의 'Featured'에 나타난다.
2. 저장소 범위 마켓플레이스: `$REPO_ROOT/.codex/plugins/marketplace.json`이 특정 저장소에 플러그인을 한정한다. 이 파일을 커밋하면 협업자 모두가 같은 플러그인 세트를 자동으로 받는다.
3. 개인 마켓플레이스: `~/.codex/plugins/marketplace.json`은 개발자 한 사람에게 한정된 플러그인을 담는다. 개인 워크플로 자동화나 개발 중인 플러그인에 쓸 만하다.

같은 플러그인 이름이 여러 마켓플레이스에 있으면 우선순위가 가장 높은 출처가 이긴다. 그래서 조직이 선별 플러그인을 저장소 범위 포크로 덮어쓸 수 있다.

플러그인을 부르는 방식은 두 가지다. 암묵적 호출은 원하는 결과를 말하는 방식이다("읽지 않은 Gmail 스레드를 요약해 줘"). 그러면 Codex CLI가 알맞은 플러그인 도구를 자동으로 고른다. 명시적 호출은 `@` 다음에 플러그인이나 스킬 이름을 쳐서 특정 기능을 직접 지정한다. 스크립트로 돌리는 워크플로나 결정성이 중요한 AGENTS.md 지시문에서는 명시적 호출이 낫다.

## 3. 설치 정책과 기업 거버넌스

marketplace.json의 각 플러그인 항목에는 설치 정책(installation policy)이 붙는다. 기업 IT 거버넌스 패턴과 곧바로 대응된다.

| 정책 | 동작 | 기업에서의 용도 |
| --- | --- | --- |
| INSTALLED_BY_DEFAULT | 저장소를 여는 팀원 모두에게 즉시 활성화 | 표준 도구 배포 |
| AVAILABLE | `/plugins`에 보이지만 직접 설치해야 한다 | 승인된 선택 도구 |
| NOT_AVAILABLE | 디렉터리에서 완전히 숨겨진다 | 미승인, 지원 종료, 제한 도구 |

별도의 인증(authentication) 필드는 외부 서비스와 자격 증명을 주고받는 시점을 정한다. `ON_INSTALL`은 설치 도중 곧바로 인증을 시작하고, `ON_FIRST_USE`는 플러그인을 처음 호출할 때까지 미룬다. 원서의 예시 marketplace.json은 세 항목을 둔다. `internal-review-bot`은 `INSTALLED_BY_DEFAULT` + `ON_INSTALL`(카테고리 Code Quality), `slack-integration`은 `AVAILABLE` + `ON_FIRST_USE`(Communication), `untrusted-community-tool`은 `NOT_AVAILABLE`(Experimental)이다. 핵심 줄만 옮기면 다음과 같다.

```json
{
  "name": "internal-review-bot",
  "source": { "source": "local", "path": "./plugins/review-bot" },
  "policy": { "installation": "INSTALLED_BY_DEFAULT", "authentication": "ON_INSTALL" },
  "category": "Code Quality"
}
```

최상위에는 마켓플레이스 `name`("acme-team-plugins")과 `interface.displayName`("Acme Engineering Plugins"), 그리고 위와 같은 항목들을 담은 `plugins` 배열이 있다.

이 구조는 모바일 기기 관리(MDM)나 IDE 확장 거버넌스의 허용 목록 패턴을 닮았다. marketplace.json을 저장소 루트에 커밋하면 플러그인 정책이 그 정책이 다스리는 코드와 함께 버전 관리된다.

주의할 점은 `INSTALLED_BY_DEFAULT`를 아껴 쓰라는 것이다. 기본 설치된 플러그인은 모든 세션의 컨텍스트를 늘린다. 코드 리뷰 기준이나 보안 정책처럼 정말로 팀 전체에 보편적인 워크플로에만 쓰고, 있으면 좋은 정도의 도구에는 쓰지 않는다.

## 4. 설치와 제거 수명 주기

플러그인 시스템은 설치, 탐색, 제거, 갱신의 전체 수명 주기를 지원한다.

| 단계 | 기능 | CLI 접점 |
| --- | --- | --- |
| 설치 | 마켓플레이스를 등록하고 Git, 로컬 경로, URL에서 플러그인을 설치 | `codex plugin marketplace add`, `/plugin install` |
| 탐색 | 탭이 있는 마켓플레이스 TUI, 인라인 토글, 생성된 설명이 붙은 저장소 간 플러그인 조회 | `/plugins` |
| 제거 | 마켓플레이스 출처와 캐시된 플러그인을 깔끔하게 삭제 | `codex plugin marketplace remove` |
| 갱신 | 설정된 마켓플레이스를 최신 상류(upstream)로 자동 업그레이드 | `codex plugin marketplace upgrade` |

제거 로직은 `codex_core::plugins::remove_marketplace()`에 있다. CLI와 app-server RPC 계층 양쪽에서 부를 수 있는 공용 함수다. CLI는 이 코어 함수를 얇게 감싼 래퍼일 뿐이라서, VS Code 확장, 데스크톱 앱, JetBrains 플러그인, app-server 프로토콜로 만든 맞춤 연동 같은 어떤 클라이언트도 같은 코드 경로로 플러그인을 설치, 탐색, 제거할 수 있다.

원격 마켓플레이스에서 아직 설치하지 않은 플러그인은 소스 Git URL, 경로, ref, SHA 정보가 들어 있는 생성된 설명을 보여 준다. 팀이 설치를 결정하기 전에 플러그인을 평가할 수 있게 하려는 것이다.
