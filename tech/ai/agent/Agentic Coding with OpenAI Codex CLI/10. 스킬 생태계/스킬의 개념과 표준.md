# 스킬의 개념과 표준

9장의 훅(hook)은 에이전트의 생애 주기에 끼어들어 흐름을 제어하는 도구였다. 하지만 훅은 제어 로직일 뿐 재사용 가능한 지식은 아니다. 팀의 커밋 메시지 규칙을 강제하는 훅을 만들었다 해도, 다른 프로젝트의 동료에게 그 워크플로를 넘기려면 스크립트와 설정 파일을 손으로 복사해야 한다. 이런 번거로움을 풀려고 나온 것이 스킬(skill)이다. 스킬은 에이전트가 하는 일을 가로채는 것이 아니라, 새로운 일을 하는 방법을 가르치는 도구다.

이 문서는 스킬이 무엇이고 어떻게 불러와지는지, 어떤 표준 위에 서 있는지, 그리고 왜 설치 전에 내용을 꼭 살펴봐야 하는지를 정리한다.

---

## 1. 이 장에서 다루는 것

10장은 스킬 생태계를 두 방향에서 본다. 하나는 쓰는 쪽(소비자)의 관점으로, 커뮤니티 스킬을 찾고 설치하고 조합하는 일이다. 다른 하나는 만드는 쪽(생산자)의 관점으로, 직접 스킬을 쓰고 설명(description)을 잘 다듬고, 호출 정책을 정하고, 남들이 설치할 수 있게 배포하는 일이다.

이 장을 마치면 다음을 할 수 있어야 한다.

- `$skill-installer`와 `npx skills`로 스킬을 설치하고 설정하고 끈다.
- 올바른 frontmatter(파일 맨 위 메타데이터)와 보조 자료를 갖춘 SKILL.md를 쓴다.
- 참조용 검증기(validator)로 실제 스킬을 만들어 시험한다.
- 영향이 큰 워크플로에는 `allow_implicit_invocation: false`를 걸어 자동 실행을 막는다.
- Codex 플러그인 마켓플레이스로 플러그인을 만들고 배포한다. 설치 정책이 들어간 로컬 마켓플레이스 설정도 포함한다.
- 스킬과 플러그인을 엮어 반복 가능한 에이전트 워크플로를 만든다.

## 2. 스킬의 정체

스킬은 `SKILL.md` 파일이 들어 있는 디렉터리다. 이 파일은 YAML frontmatter로 이름(name)과 설명(description)을 선언하고, 그 아래에 자유로운 Markdown 지시문을 적는다. 에이전트는 이 지시문을 컨텍스트로 읽어 들이고, 지시문이 시키면 SKILL.md 옆에 놓인 스크립트나 참고 문서를 불러 쓴다.

여기서 중요한 점은 스킬 자체가 자동으로 실행되는 코드가 아니라는 것이다. 에이전트가 지시문을 읽고, 사용자의 프롬프트에 맞춰 어떻게 행동할지 스스로 판단한다. 스킬은 "읽을 거리"이고, 실행은 에이전트가 자기 도구로 한다.

가장 작은 구조는 아래와 같다. SKILL.md만 필수이고 나머지는 모두 선택이다.

```
incident-triage/
├── SKILL.md        # 필수
├── scripts/        # 런북 명령, 알림 쿼리, 호출 도우미
├── references/     # 사후 분석 템플릿, 심각도 기준표
└── assets/         # 장애 JSON 스키마, 메시지 템플릿
```

## 3. 점진적 공개(progressive disclosure)

스킬 설계의 중심 철학은 점진적 공개다. 필요할 때만 필요한 만큼 읽는다는 뜻이다.

- Codex CLI는 시작할 때 모든 스킬의 name과 description만 읽는다. 스킬 하나당 대략 100 토큰이다.
- 본문 전체는 에이전트가 그 스킬이 지금 작업과 관련 있다고 판단했을 때만 읽는다. 프롬프트가 description과 맞아떨어지는 경우(암묵적 호출)도 있고, 사용자가 스킬 이름을 직접 부르는 경우도 있다.
- `scripts/`, `references/`, `assets/` 아래 파일은 SKILL.md 지시문이 가리킬 때에만 읽는다.

그래서 팀이 스킬 스무 개를 저장소에 올려도 시작 비용은 약 2,000 토큰 정도다. 요즘 모델의 컨텍스트 윈도 예산에는 크게 부담이 없고, 상세 지시문은 지금 작업과 관련된 스킬 하나만 불러온다.

## 4. agentskills.io 표준

Agent Skills 사양은 agentskills.io에서 관리하는, 에이전트 지식을 담는 이식 가능한 포맷이다. 형식을 처음 만든 곳은 Anthropic이고, 지금은 열린 표준이다. 채택한 제품은 CLI 에이전트, IDE 에이전트, 데스크톱·클라우드 제품, 특정 분야 플랫폼까지 수십 개에 이르며, agentskills.io의 clients 디렉터리가 최신 목록을 추적한다. agentskills.io 레지스트리는 스킬을 찾고 배포하는 중심 거점이다.

이 표준의 가장 큰 장점은 플랫폼 간 호환이다. 저장소에 커밋한 SKILL.md 하나가 개발자가 어떤 에이전트를 쓰든 똑같이 동작한다. Codex CLI용으로 쓴 스킬을 고치지 않고 Claude Code, Cursor, Roo Code, Gemini CLI 등에서 그대로 쓸 수 있다. 따로 옮기는 과정도, 도구마다 다른 방언도, 에이전트별 설정 파일도 필요 없다. 사양을 일부러 최소한으로 설계한 덕이다. 상호운용이 되도록 충분히 엄격하면서도 어떤 에이전트 런타임이든 구현할 수 있을 만큼 단순하다.

AGENTS.md(4장)와 마찬가지로 SKILL.md는 Codex 전용 파일 형식이 아닌 열린 표준이다. 둘 다 Linux Foundation 산하 Agentic AI Foundation(AAIF)이 관리하므로, AGENTS.md를 믿고 쓸 수 있게 해 주는 거버넌스 보장이 스킬에도 똑같이 적용된다. 두 형식은 서로 보완한다.

| 형식 | 담는 것 |
| --- | --- |
| AGENTS.md | 프로젝트의 상시 규칙과 제약 |
| SKILL.md | 특정 워크플로의 절차 지식 |

둘을 합치면 한 번 쓰면 어디서든 배포되는 계층이 되어, 두 표준 중 하나라도 구현한 에이전트 런타임에서 돌아간다.

## 5. 보안 경고

보안 연구자들은 `scripts/` 디렉터리를 악용하거나 SKILL.md 안에 프롬프트 인젝션(prompt injection, 에이전트를 속이려고 심어 둔 명령문) 페이로드를 숨긴 악성 스킬을 이미 찾아냈다. 설치한 스킬은 외부 서드파티 코드처럼 다뤄야 한다. 활성화하기 전에 모든 파일을 검토하고, 믿을 수 없는 출처에서는 설치하지 않는다.
