# 요약

10장의 핵심을 아홉 가지로 되짚는다. 각 항목 뒤에는 어느 문서에서 자세히 다루는지 덧붙였다.

---

## 1. 장 전체 요약

1. 스킬은 디렉터리다. SKILL.md(name과 description이 든 YAML frontmatter와 Markdown 지시문)가 중심이고, 필요하면 `scripts/`, `references/`, `assets/`가 받친다. 에이전트는 지시문을 컨텍스트로 읽고 지시가 가리킬 때만 보조 파일을 불러 쓴다. 자동으로 실행되는 것은 없다. (스킬의 개념과 표준)
2. 이식 가능한 열린 표준이다. Agent Skills(agentskills.io)는 AGENTS.md와 함께 Linux Foundation의 Agentic AI Foundation 아래에서 관리되고, 호환되는 에이전트 제품에서 고치지 않고 동작한다. (스킬의 개념과 표준)
3. 세 층, 하나의 워크플로다. 스킬은 3단계 점진적 공개로 절차 지식을 담고, MCP 서버는 상태가 있는 연결로 실시간 연동을 제공하며, 훅은 생애 주기 이벤트에서 런타임 정책을 강제한다. 성숙한 에이전트 워크플로는 셋을 모두 쓰고, 예전에 비대한 AGENTS.md에 있던 "X를 하는 법"은 스킬이 맡는다. (스킬 찾기와 설치와 관리)
4. description은 라우팅 규칙이다. 사람이 읽는 문서이면서 에이전트가 스킬을 불러올지 정하는 트리거다. 분명한 핵심 동작, 트리거 동의어, 명시적 제외를 넣어 쓴다. (SKILL.md 작성 규칙)
5. agents/openai.yaml이 다리 역할을 한다. 외부 MCP 서버 의존성을 선언하고, 아무 프롬프트에나 켜지면 안 되는 스킬에는 `allow_implicit_invocation: false`를 건다. (openai.yaml과 스킬 만들어 배포하기)
6. 탐색 순서는 프로젝트, 사용자, 관리자, 시스템이다. 팀 스킬은 `.agents/skills/`에 커밋해 팀 전체가 일관되게 동작하게 한다. (스킬 찾기와 설치와 관리)
7. 복잡도는 5단계다. 10단어 프롬프트에서 공식 평가를 갖춘 프로덕션 산출물까지 있다. 되는 가장 낮은 단계에서 시작하고, 구체적인 불편이 생길 때만 올린다. (openai.yaml과 스킬 만들어 배포하기)
8. 먼저 만들고 나중에 옮긴다. 작업을 손으로 끝까지 해 보고, SKILL.md로 인코딩하고, 실패 유형에 맞춰 반복해서 다듬는다. 이렇게 하면 성급한 복잡도 없이 2~3단계 스킬이 자연스럽게 나온다. (openai.yaml과 스킬 만들어 배포하기)
9. Codex 플러그인 마켓플레이스는 스킬, 앱 커넥터, MCP 서버 설정을 설치 가능한 하나의 단위로 배포한다. marketplace.json의 설치 정책(INSTALLED_BY_DEFAULT, AVAILABLE, NOT_AVAILABLE)이 기업 거버넌스를 제공하고, 수명 주기(설치, 탐색, 제거, 업그레이드)는 `codex plugin marketplace` 하위 명령과 app-server RPC 계층 양쪽에서 다룬다. (플러그인과 마켓플레이스)

## 2. 함께 보기

4장(AGENTS.md)과 연결된다. AGENTS.md가 불어나 다루기 힘들어졌다면 스킬이 올바른 리팩터링 대상이다. 4장은 절차 지식을 이식 가능한 스킬로 뽑아낼 때가 됐음을 알리는 비대화 패턴을 다룬다.
