# 연습 문제

10장 끝의 연습 문제 세 개를 풀이 방향과 함께 정리했다. 모두 직접 손으로 해 봐야 감이 오는 과제라서, 취지와 확인할 지점을 중심으로 풀어 썼다.

---

## 1. 팀 관례 스킬을 처음부터 만들기

팀의 AGENTS.md에서 스킬로 옮길 만큼 전문화된 부분을 하나 고른다. 예를 들어 데이터베이스 마이그레이션 실행 방법, 통합 테스트 구조 잡는 법, 릴리스 변경 이력 생성 같은 절차다. 그 부분을 `.agents/skills/` 아래 스킬로 추출하고, 트리거 문구 두 개 이상과 명시적 제외 조건 하나가 들어간 description을 쓴다. `skills-ref`로 검증한 뒤, 해당 부분을 AGENTS.md에서 지워도 에이전트 동작이 달라지지 않는지 확인한다.

풀이 방향: 지시문이 길면 `references/`로 나누고, name이 디렉터리 이름과 같은지 먼저 본다. 제거 후 확인은 AGENTS.md에서 해당 절을 빼고 같은 프롬프트로 새 세션을 열어, 스킬이 암묵적으로 활성화되어 같은 결과가 나오는지 비교하면 된다. 제외 조건부터 쓰면 description을 잡기 쉽다.

## 2. 과하게 반응하는 description 바로잡기

작업 분야와 관련된 커뮤니티 스킬을 하나 설치한다. 활성화되어야 하는 프롬프트 다섯 개와 활성화되면 안 되는 프롬프트 다섯 개를 보내 본다. 오탐이 보이면 트리거 조건이 좁아지도록 description을 고친다. 수정 전과 수정 후 description을 기록하고, 고친 버전이 왜 더 잘 맞는지 설명한다.

풀이 방향: 트리거 프롬프트와 비트리거 프롬프트를 쌍으로 만들어 두는 것이 description 평가의 기본이다. 너무 넓은 표현을 구체적인 동작 동사로 바꾸고, 오탐이 난 프롬프트의 성격을 "Do NOT use for ..." 문장으로 옮겨 넣는다. 고친 뒤에는 열 개 프롬프트를 다시 돌려 오탐이 줄었고 정탐은 유지되는지 확인한다.

## 3. 로컬 플러그인 마켓플레이스 만들기

관련된 스킬 두 개(예: 리뷰 스킬과 수정 스킬)를 하나의 설치 단위로 묶는 플러그인을 만든다. 저장소 루트에 `.codex/plugins/marketplace.json`을 만들고 설치 정책을 `AVAILABLE`로 둔다. `/plugins` 브라우저에 플러그인이 나타나는지 확인하고, 설치한 뒤 두 스킬을 모두 시험한다. 그다음 정책을 `INSTALLED_BY_DEFAULT`로 바꾸고, 새 Codex CLI 세션이 수동 설치 없이 플러그인을 활성화하는지 확인한다.

풀이 방향: `.codex-plugin/plugin.json`의 경로를 모두 `./`로 시작하게 쓰고, name은 kebab-case로 정한다. marketplace.json 항목의 `source`는 `local`과 플러그인 경로를 가리키게 한다. 정책 변경 후에는 반드시 새 세션에서 확인하고, 기본 설치 플러그인이 모든 세션의 컨텍스트를 늘린다는 점도 체감해 본다.
