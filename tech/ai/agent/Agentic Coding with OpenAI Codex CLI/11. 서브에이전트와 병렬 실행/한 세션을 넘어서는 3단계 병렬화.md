# 한 세션을 넘어서는 3단계 병렬화

한 세션 안의 서브에이전트(앞 문서들에서 다룬 방식)만으로 모자라는 작업도 있다. Codex CLI의 병렬화는 3단계로 쌓인 구조이고, 1단계가 지금까지 설명한 내용이다. 이 문서는 2단계와 3단계, 그리고 어느 단계로 올라갈지 정하는 기준을 설명한다.

---

## 1. 세 단계 한눈에 보기

그림(원서의 Figure 11.2)은 왼쪽에서 오른쪽으로 세 단계가 이어지는 모습을 보여 준다. 1단계에서 여섯 스레드 한도에 부딪히면 2단계로, 로컬 컴퓨팅 자원이 병목이 되면 3단계로 올라간다.

| 단계 | 방식 | 동시 규모 | 사용 한도와 자원 |
|---|---|---|---|
| 1단계 | 프로세스 안 서브에이전트 | 한 세션에서 max_threads까지 | 세션의 사용 한도 예산을 공유 |
| 2단계 | 로컬 셸 팬아웃 | 10~30개 `codex exec` 프로세스 | worker마다 git 워크트리로 격리 |
| 3단계 | 클라우드 팬아웃 | Codex Cloud Tasks 세션 단위 | 세션마다 자기 컴퓨팅, 컨텍스트 윈도, 사용 한도 할당 |

## 2. 1단계: 프로세스 안 서브에이전트

단일 Codex CLI 세션 안에서 max_threads까지 동시에 worker를 돌린다. 세션의 사용 한도 예산을 함께 쓴다. 부모가 worker와 긴밀히 조율해야 하고, 취합된 결과를 같은 대화에서 읽어야 하는 작업에 가장 잘 맞는다.

## 3. 2단계: 로컬 셸 팬아웃

외부 스크립트가 독립된 Codex CLI 프로세스를 여러 개 띄운다. 프로세스마다 자기 git 워크트리에서 돌아 파일시스템이 격리된다. 워크트리는 같은 저장소를 별도 브랜치로 체크아웃한 복사본인데, 메인 체크아웃과 같은 `.git` 디렉터리를 공유한다. 그래서 여러 프로세스가 같은 저장소의 파일을 고쳐도 쓰기가 충돌하지 않는다.

셸 스크립트, GNU Parallel, xargs, 직접 만든 파이썬 하니스(harness, 에이전트를 돌리는 틀)로 `codex exec`를 10~30개 동시에 띄우고, 각각 다른 파일이나 모듈을 맡긴다. 이를 가능하게 하는 핵심이 워크트리 격리(13장)다. 인스턴스마다 자기 브랜치와 작업 디렉터리에서 동작하므로 worker 사이의 파일 수준 충돌이 없어진다.

대표적인 2단계 스크립트의 핵심 부분은 이렇다.

```bash
MAX_WORKERS=20
TASK_FILE="files-to-process.txt"

process_file() {
  local file="$1"
  local worktree
  worktree="$(mktemp -d)"
  git worktree add "$worktree" -b "worker-$(basename "$file")" HEAD --quiet
  cd "$worktree" || exit 1
  codex exec -m gpt-5.4-mini -s workspace-write \
    "Lint and fix $file according to the project style guide" \
    2>"$worktree/codex.log"
}
export -f process_file
xargs -P "$MAX_WORKERS" -I {} bash -c 'process_file "$@"' _ {} < "$TASK_FILE"
```

이 스크립트의 동작은 다음과 같다.

- 처리할 파일 목록(`files-to-process.txt`)을 한 줄씩 읽어 xargs가 최대 20개씩 병렬로 `process_file`을 실행한다.
- 함수는 임시 디렉터리를 만들고 거기에 새 워크트리와 `worker-<파일명>` 브랜치를 만든 뒤, 그 안에서 `codex exec`를 gpt-5.4-mini 모델과 workspace-write 샌드박스로 돌린다. 로그는 워크트리 안의 `codex.log`에 남긴다.

원서에 따르면 보통의 개발 머신에서 동시 worker 20~30개까지 확장된다. 각 worker가 격리된 워크트리에서 일하므로 파일 쓰기는 충돌하지 않는다. worker가 모두 끝난 뒤 메인 브랜치가 머지나 체리픽으로 결과를 모은다. 전체 워크트리 워크플로는 13장에서 다룬다.

## 4. 3단계: 클라우드 팬아웃

Codex Cloud Tasks는 작업 단위마다 클라우드에 호스팅된 세션을 하나씩 돌린다. 세션마다 자기 컴퓨팅, 컨텍스트 윈도, 사용 한도 할당이 있다. 로컬 머신 자원이 병목일 때, 또는 노트북을 켜 두지 않고도 밤새 일이 돌아야 할 때 알맞은 단계다.

## 5. 어느 단계에서 시작하나

- 1단계에서 시작한다.
- 여섯 스레드 한도에 계속 부딪히면 2단계로 옮긴다.
- 로컬 컴퓨팅 자원이나 연결 상태가 발목을 잡으면 3단계로 옮긴다.
