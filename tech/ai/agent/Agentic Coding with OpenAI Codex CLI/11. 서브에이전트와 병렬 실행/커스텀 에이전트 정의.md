# 커스텀 에이전트 정의

기본 에이전트로 부족할 때는 TOML 파일 하나로 나만의 에이전트를 정의한다. 이 문서는 파일 위치, 필수·선택 필드, 실제 예시(마이그레이션 감사 에이전트), 별명 설정, 호출 방법을 다룬다.

---

## 1. 파일 위치와 형식

커스텀 에이전트는 단일 테이블 TOML 파일이다. 위치는 두 곳 중에서 고른다.

- `~/.codex/agents/<name>.toml`: 모든 프로젝트에서 쓰는 개인용
- `.codex/agents/<name>.toml`: 프로젝트와 함께 배포하는 용도

테이블 배열 형식은 없다. **파일 하나에 에이전트 하나**이고, 파일 이름은 그 에이전트가 하는 일을 따서 짓는다.

## 2. 필수 필드 세 개

| 필드 | 설명 |
|---|---|
| name | 에이전트를 부를 때와 출력에 라벨을 붙일 때 쓰는 고정 식별자 |
| description | 짧은 요약. 에이전트 선택기에 표시된다 |
| developer_instructions | 에이전트의 시스템 지침. 여러 줄 문자열로 쓴다 |

## 3. 선택 필드 다섯 개

선택 필드는 부모 세션에서 물려받는 값을 덮어쓴다. 쓰지 않으면 부모 값을 그대로 이어받는다.

| 필드 | 설명 |
|---|---|
| model | 모델 식별자(gpt-5.5, gpt-5.4, gpt-5.4-mini) |
| model_reasoning_effort | 추론 강도. low, medium, high, xhigh 중 하나 |
| sandbox_mode | read-only, workspace-write, danger-full-access 중 하나 |
| mcp_servers | 이 에이전트가 쓸 수 있는 MCP 서버 이름 배열 |
| nickname_candidates | 같은 에이전트가 여러 개 동시에 돌 때 표시할 별명 후보 |

## 4. 예시: migration-auditor

운영 DB에 적용하기 전에 SQL 마이그레이션 스크립트를 감사하는 에이전트다. 메인 브랜치에 들어가기 전에 점검하는 역할이다. 앞부분 필드는 이렇게 쓴다.

```toml
name = "migration-auditor"
description = "Reviews SQL migration scripts for irreversibility, lock-heavy operations, and unsafe ordering."
model = "gpt-5.4"
model_reasoning_effort = "high"
sandbox_mode = "read-only"
nickname_candidates = ["Codd", "Stonebraker", "Hellerstein", "DeWitt", "Widom"]
```

`developer_instructions`에는 읽은 파일마다 세 가지 제목 아래에 발견 사항을 보고하도록 적는다.

- **Irreversible(되돌릴 수 없음)**: DROP, RENAME, NOT NULL 추가, 컬럼 타입을 좁히는 변경처럼 롤백 경로가 없는 것
- **Lock-heavy(락이 무거움)**: 큰 테이블에 배타 락을 오래 잡아 쓰기를 막을 수 있는 문장. DROP COLUMN, Postgres 11 미만에서 기본값이 있는 ADD COLUMN, 일부 인덱스 작업이 예다
- **Order-sensitive(순서에 민감함)**: 마이그레이션을 처음부터 끝까지 돌릴 때와 일부 실패 후 다시 돌릴 때 결과가 달라질 수 있는 작업

지침은 모든 발견 사항에 파일과 줄 번호를 붙이라고 하고, 수정안은 내놓지 말라고 못 박는다. 어떻게 고칠지는 마이그레이션을 맡은 팀이 정하기 때문이다. 이 에이전트는 `.codex/agents/migration-auditor.toml`에 두고, 부모가 몇 개를 띄우든 항상 `migration-auditor`라는 이름으로 부른다.

## 5. 별명(nickname_candidates)

별명은 같은 에이전트의 인스턴스가 여러 개 동시에 돌 때 보여 줄 표시용 이름이다. 기본값은 앞서 말한 약 100개의 역사 인물 목록이다. `nickname_candidates`를 주면 **그 에이전트에 한해** 기본 목록을 덮어쓴다. 위 예시에서는 Codd, Stonebraker, Hellerstein 같은 이름이 배열 순서대로 쓰인다.

지켜야 할 점은 다음과 같다.

- 목록의 항목은 서로 달라야 한다(중복 금지).
- 값은 화면 표시용일 뿐이다. Codex는 여전히 `name`으로 에이전트를 식별하고 띄우기 때문에, "migration-auditor를 띄워 줘"라는 프롬프트는 어떤 별명이 붙든 똑같이 동작한다.

## 6. 호출하는 법

부모에게 에이전트 이름을 넣어 프롬프트를 쓰면 된다. 예를 들면 이렇다.

```text
Spawn the migration-auditor against every file under db/migrations/2026-06/
and return a Markdown report grouped by file, with severity ranked
irreversible first.
```

부모는 `migration-auditor`를 커스텀 정의에 대한 참조로 읽는다. 그리고 TOML에 적힌 모델, 샌드박스, 지침으로 스레드를 띄우고, 끝나면 결과를 대화로 취합해 돌려준다. 똑같은 문장 형태가 설정 파일이 필요 없는 worker와 explorer에도 그대로 통한다.
