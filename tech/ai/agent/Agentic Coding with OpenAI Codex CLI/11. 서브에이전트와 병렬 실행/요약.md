# 요약

11장의 핵심 내용을 일곱 가지로 정리한 문서다. 각 항목이 어느 문서에서 자세히 다뤄졌는지도 함께 적는다.

---

## 1. 장 요약

1. **서브에이전트는 한 세션 안의 특화 스레드다.** 기본 제공 세 개가 일회성 위임 대부분을 해결한다. default는 세션 자신, worker는 실행, explorer는 읽기 위주 탐색이다. (서브에이전트 기본 개념)
2. **커스텀 에이전트는 단일 테이블 TOML이다.** `~/.codex/agents/` 또는 `.codex/agents/`에 두며, 필수 필드 셋(name, description, developer_instructions)과 부모에게서 물려받은 값을 덮어쓰는 소수의 선택 필드가 있다. (커스텀 에이전트 정의)
3. **세션 전체 한도가 셋 있다.** `agents.max_threads`(기본 6), `agents.max_depth`(기본 1), `agents.job_max_runtime_seconds`는 개별 에이전트가 아니라 세션 전체를 묶는다. (모델 선택과 세션 한도)
4. **배치 작업은 CSV 팬아웃으로 한다.** `spawn_agents_on_csv`는 CSV, `{column_name}` 자리표시자를 쓰는 지시문 템플릿, 작업 제어 매개변수를 받는다. 각 worker는 `report_agent_job_result`를 한 번 호출한다. 결과는 job_id, item_id, status, last_error, result_json이 덧붙은 내보내기 CSV에서 취합한다. 책을 쓴 시점에 실험 단계여서 매개변수는 바뀔 수 있다. (CSV 팬아웃)
5. **병렬화는 세 단계다.** 한 세션 안의 서브에이전트, git 워크트리 속 `codex exec`를 여럿 띄우는 로컬 셸 팬아웃(13장), 로컬 자원과 무관하게 클라우드 컴퓨팅과 사용 한도 할당을 쓰는 Codex Cloud Tasks다. (한 세션을 넘어서는 3단계 병렬화)
6. **운영상 위험이 둘 있다.** stdio 전송 MCP 서버를 부르는 서브에이전트는 긴 세션에서 자식 프로세스를 샐 수 있다. 이때는 HTTP 전송으로 바꾸거나, 프로세스 수를 감시하거나, 배치 사이에 재시작해서 영향을 줄인다. 또 병렬화가 늘 정답은 아니어서, 정답이 하나뿐인 작업은 추론 강도를 높인 에이전트 하나가 낫다. (운영상 주의점과 병렬화가 해로운 경우)
7. **어려운 부분은 작업 분해다.** TOML 문법은 배우기 쉽다. 병렬화가 도움이 되는 곳과 취약하고 비싼 워크플로를 만드는 곳을 가르는 판단력이 기르기 어렵고 훨씬 값지다. (병렬화할 작업 고르기)
