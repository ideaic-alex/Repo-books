# 서브에이전트 기본 개념

10장에서는 컨텍스트 윈도가 가득 찰 때 새 스레드(대화 기록 한 묶음)를 열어 일을 넘기는 방법을 간단히 다뤘다. 이 장은 그 방법을 본격적으로 푼다. 서브에이전트(sub-agent)는 한 세션 안에서 돌아가지만 저마다 자기 컨텍스트, 모델, 샌드박스, 도구 권한을 가진 에이전트 스레드다.

이 문서는 서브에이전트가 왜 필요한지, Codex CLI에 기본으로 들어 있는 에이전트가 무엇인지, 여러 스레드를 어떻게 오가며 승인을 처리하는지를 설명한다.

---

## 1. 서브에이전트가 필요한 순간

작업 성격에 따라 한 스레드로는 부족해지는 경우가 세 가지 있다.

- **자연스럽게 병렬인 작업**: 파일 100개 린트, 모듈 12개 번역, 일주일치 풀 리퀘스트 설명 요약처럼 항목끼리 서로 상관이 없으면 한 스레드가 병목이 된다.
- **컨텍스트 윈도 하나를 넘는 작업**: 일을 나눠서 넘길 방법이 필요하다.
- **일부 실패가 전체를 죽이면 안 되는 작업**: 하위 작업마다 격리가 필요하다.

Codex CLI는 이 세 가지를 모두 서브에이전트 시스템으로 해결한다.

## 2. 기본 제공 에이전트 세 개

Codex CLI에는 default, worker, explorer 세 에이전트가 들어 있다. 지금 타이핑하고 있는 세션 자체가 default 에이전트다. 나머지 둘은 설정 없이 바로 일을 넘길 수 있는 특화 스레드다.

| 에이전트 | 성격 | 이럴 때 쓴다 |
|---|---|---|
| default | 지금 대화 중인 세션 | 일반 작업, 계획, 결과 취합 |
| worker | 실행 중심 | 구현 작업. 계획 대화로 오염되지 않은 새 컨텍스트가 필요할 때 |
| explorer | 읽기 위주 | 코드베이스 탐색. 탐색기가 읽은 파일을 부모가 전부 떠안지 않게 할 때 |

중요한 점은 **Codex가 먼저 알아서 서브에이전트를 띄우지 않는다**는 것이다. 사용자가 부모 에이전트에게 자연어로 부탁해야 한다. 예를 들어 "explorer를 띄워서 저장소 전체에서 payment_service를 참조하는 곳을 정리해 줘", "worker를 써서 패치를 적용하고 테스트를 돌려 줘" 같은 식이다. 어느 기본 에이전트가 맞는지는 부모가 판단해서 스레드를 시작한다. 작업을 살펴보고 worker나 explorer를 자동으로 골라 주는 라우터는 없다.

기본 에이전트만으로도 일회성 위임 대부분을 처리할 수 있다. 커스텀 에이전트는 특정 지침 세트, 다른 모델, 더 좁은 샌드박스, 제한된 도구 목록을 항상 똑같이 적용하고 싶을 때만 만들면 된다.

## 3. 스레드 사이 오가기: /agent

REPL에서 `/agent`를 입력하면 활성 스레드 목록이 뜨고, 스레드를 바꾸거나 진행 중인 스레드를 들여다볼 수 있다. 부모 하나와 worker 하나가 있을 때 선택기는 다음과 같이 보인다.

```text
Subagents
Select an agent to watch.  + ← previous,  + → next.
' 1. • Main [default] (current)  019eb02d-9b91-7370-b503-7179f1ed731d
  2. • Boyle [worker]            019eb02e-b7a1-7dc0-8b38-f7ff725e00d3
```

각 줄에는 세 가지 정보가 들어 있다. 별명(Main, Boyle), 대괄호 안의 에이전트 역할(default, worker), 그리고 스레드의 UUID다. Main은 세션 자신의 스레드에 예약된 이름이다. 나머지 스레드는 과학, 수학, 철학 분야의 유명한 역사 인물 이름(Boyle, Euclid, Hypatia, Lovelace, Turing 등)을 따서 붙는다. Codex는 약 100개의 이름 목록을 내장하고 있어서, worker 3개를 한꺼번에 띄워도 똑같은 worker 항목 3줄이 아니라 서로 다른 이름 3줄로 보인다.

## 4. 다른 스레드의 승인 요청 처리

지금 보고 있지 않은 스레드가 승인이 필요한 일(확인을 요구하는 도구 호출 등)을 만나면, Codex는 어느 스레드가 묻는지 알 수 있도록 출처 라벨을 붙여 요청을 띄운다. 이때 `o` 키를 누르면 그 스레드를 열 수 있다. 승인하기 전에 요청이 나온 맥락을 직접 확인하라는 뜻이다.

권한과 샌드박스 설정은 부모에서 자식으로 전달된다. 부모 턴에 적용된 권한·샌드박스 덮어쓰기는 그 부모가 띄운 자식에게도 그대로 적용된다. 예를 들어 부모가 읽기 전용(read-only) 모드로 바꿨다면, 쓰기 가능한 자식이 새 샌드박스를 몰래 받는 일은 없다. 부모가 잠가 둔 권한이 자식을 통해 풀리지 않는다는 점이 안전상 핵심이다.
