# 서브에이전트와 병렬 실행

일을 여러 갈래로 나눠 동시에 처리하고 싶을 때, 또는 한 컨텍스트 윈도에 다 들어가지 않는 작업을 넘겨야 할 때 Codex CLI는 서브에이전트 시스템을 쓴다. 서브에이전트는 한 세션을 공유하지만 저마다 컨텍스트, 모델, 샌드박스, 도구 권한을 따로 가진 에이전트 스레드다.

이렇게 여러 에이전트를 나누어 맡기고 조율하는 일(오케스트레이션)의 바탕을 다지는 장이다. 기본 제공 에이전트와 커스텀 TOML 정의, 세션 전체 한도, CSV 팬아웃, 세션을 넘는 3단계 병렬화, 운영상 함정과 병렬화가 해로운 경우를 다룬다. 어디까지 병렬화하고 어디서 멈출지 판단하는 힘을 기르는 것이 장의 목표다.

---

## 1. 핵심 요점

- 기본 제공 에이전트는 default(세션 자신), worker(실행), explorer(읽기 위주 탐색) 셋이다. Codex는 사용자가 부탁해야만 서브에이전트를 띄운다.
- 커스텀 에이전트는 TOML 파일 하나에 에이전트 하나다. name, description, developer_instructions는 필수이고, model과 sandbox_mode 등은 부모 값을 덮어쓰는 선택 필드다.
- `[agents]`의 max_threads(기본 6), max_depth(기본 1), job_max_runtime_seconds가 세션 전체를 제한한다. 기본값을 올리기 전에 사용 한도부터 따져 본다.
- 독립적이고 입력이 안정적이며 출력이 떨어지는 작업은 병렬화가 잘 된다. 공유 상태나 순서 의존이 있으면 순차로 둔다.
- `spawn_agents_on_csv`는 행마다 worker 하나를 띄우고, 결과는 status와 result_json 등이 덧붙은 CSV로 취합한다. 실험 단계라 매개변수는 바뀔 수 있다.
- 병렬화는 3단계다. 세션 안 서브에이전트, 워크트리를 쓴 로컬 셸 팬아웃, Codex Cloud Tasks 순으로 올라간다.
- stdio MCP 서버는 서브에이전트가 많을수록 프로세스가 샐 수 있다. HTTP 전송, 감시, 재시작, max_threads 낮추기로 대응한다.
- 정답이 하나뿐인 작업은 추론 강도를 높인 에이전트 하나가 낫고, 출력 다양성이 목표일 때 팬아웃이 값을 한다.
