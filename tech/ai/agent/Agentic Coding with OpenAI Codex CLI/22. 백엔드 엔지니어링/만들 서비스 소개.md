# 만들 서비스 소개: Run or Relax 출발 안내판

앞선 몇 장은 이미 있는 코드를 리뷰하고, 옮기고, 새 방식으로 고치는 이야기였다. 22장부터 24장까지는 아무것도 없는 상태에서 서비스를 만들어 운영 환경까지 올린다. 22장에서 백엔드 서비스와 API를 만들고, 23장에서 프론트엔드를 붙이고, 24장에서 코드형 인프라(infrastructure as code)로 전체를 배포한다. 세 장에 예제 하나와 질문 하나가 이어진다. 백엔드, 프론트엔드, 인프라는 각각 에이전트가 잘하는 일과 못하는 일이 다르다. 그렇다면 Codex CLI가 각 일을 잘하도록 어떻게 도울 것인가가 그 질문이다.

이 문서는 22장에서 만들 서비스의 정체와 설계 결정을 정리한다. 이후 문서의 모든 설정과 레시피가 이 서비스를 겨냥하므로, 에이전트에게 맡기기 전에 목표부터 분명히 해 두자는 취지다.

---

## 1. 예제가 무엇인가

예제는 일부러 작게 잡았다. 저자가 사는 Audley End 역에서 Liverpool Street 역으로 가는 열차의 출발 안내판이다. 이 책 첫머리에 나온 07:02 열차의 노선이다. 지금 시각과 시간표를 주면, 곧 출발하는 열차 몇 개와 판정 하나를 돌려준다. 판정은 RUN(뛰어라) 아니면 relax(여유 부려도 된다) 두 가지다. 집을 나서면서 산책하듯 가도 되는지, 뛰어야 하는지를 알려 주는 셈이다.

작지만 백엔드 작업이 에이전트에게 어려운 이유를 다 담고 있다. 데이터 모델, 애매한 경계가 있는 업무 규칙(몇 분 전부터 너무 늦은 것인가), 테스트, 그리고 23장 프론트엔드가 의존하고 24장 배포가 올릴 HTTP 계약(contract)까지 갖췄다.

기술 스택은 Python과 FastAPI다. 이 장의 질문은 "FastAPI 서비스를 어떻게 짜는가"가 아니라 "우리 팀이 짜는 방식대로 Codex CLI가 쓰게 하려면 어떻게 설정하는가"이다. Python은 컴파일되는 정적 타입 언어보다 에이전트가 받는 피드백이 약하다. 빌드가 잡아 줄 오류가 런타임이나 리뷰 단계에서야 드러난다. 이 장 대부분은 그 틈을 메우는 설정이며, 설정을 하나씩 얹으면서 서비스를 완성한다.

## 2. 학습 목표

- 가장 흔한 "엉뚱한 도구" 실수를 없애 주는 Python용 AGENTS.md를 완성한다.
- 파일을 쓸 때마다 린트를 돌리고, 세션이 끝나기 전에 전체 테스트를 돌리는 훅을 설정한다.
- 타입이 붙은 FastAPI 엔드포인트와 테스트된 판정 규칙으로 Run or Relax 서비스를 처음부터 끝까지 만든다.
- pyproject.toml을 uv, ruff, mypy 도구 체인의 단일 기준 문서로 삼아, 생성된 코드가 첫 시도에 린트와 타입 검사를 통과하게 한다.
- 에이전트가 Python에서 자주 틀리는 방식을 알아보고 각각에 맞는 방어책을 설정한다.

## 3. 판정 규칙의 두 가지 까다로운 경계

판정은 이 서비스의 핵심이므로 요청 핸들러 안에 묻어 두지 않고, 작고 순수하며 테스트하기 쉬운 함수 하나로 둔다. 이 함수는 현재 시각, 예정 출발 시각, 지연 시간을 받아 두 단어 중 하나를 돌려준다. 규칙에는 까다로운 경계가 둘 있다.

- **여유 부려도 되는 한계**는 0분이 아니다. 현관에서 역까지 걸어가는 시간이 기준이다. 열차가 지연되면 출발이 뒤로 밀리므로 그만큼 시간을 번다.
- **뛰어도 못 타는 한계**는 더 빡빡한 두 번째 기준이다. 전력 질주해도 닿지 못하는 열차는 안내판에 아예 올리지 않는다.

시간표와 지연 정보는 코드가 아니라 데이터다. 그래서 시드(seed) JSON 파일에 두어 테스트가 마음대로 바꿀 수 있게 한다. 서비스는 읽기 전용 엔드포인트 하나만 노출한다. 안내판은 읽기만 하기 때문이다.

## 4. HTTP 계약

계약은 이 엔드포인트 하나다.

```text
GET /departures?station=audley-end&now=<ISO 8601, 생략하면 현재 시각>
200 OK
[
  {"service": "07:02", "platform": "2", "delayMinutes": 0,
   "minutesUntil": 10, "verdict": "RUN"},
  {"service": "07:32", "platform": "2", "delayMinutes": 4,
   "minutesUntil": 44, "verdict": "relax"}
]
```

계약 속에는 결정 두 가지가 숨어 있고, 에이전트가 짐작하지 않도록 글로 못 박아 둔다.

1. 지연은 실제 출발을 뒤로 민다. 그래서 예정 시각이 이미 지났더라도, 지연을 반영한 실제 출발이 달려가 탈 수 있을 만큼 남았다면 안내판에 남겨야 한다. 필터는 예정 시각이 아니라 지연을 더한 실제 출발 시각을 기준으로 건다. 뛰는 기준(run threshold)보다 가까운 열차는 뺀다.
2. `minutesUntil`도 같은 지연 반영 출발 시각에서 센다. 그래야 독자가 보는 숫자가 실제로 탈 수 있는 열차와 일치한다.

## 5. 프로젝트 구조

다음 구조를 계획한다. 다음 문서에서 쓸 AGENTS.md가 이 구조를 에이전트에게 설명한다.

```text
run-or-relax/
├── pyproject.toml
├── AGENTS.md
├── .codex/
│   ├── hooks.json          # PostToolUse, Stop, UserPromptSubmit
│   └── scripts/block-legacy-pip.sh
├── data/
│   ├── timetable.json      # 역별 시드 시간표
│   └── delays.json         # 모의 지연 정보
├── src/departures/         # 아래에 이어서 설명
└── tests/
    ├── conftest.py         # timetable 픽스처
    ├── test_verdict.py
    ├── test_timetable.py
    └── test_api.py
```

`src/departures/` 안에는 파일이 넷 있다.

```text
models.py     # Pydantic 응답 모델
timetable.py  # 시간표와 지연을 읽고 다음 출발을 계산
verdict.py    # RUN/relax 규칙 (순수 함수)
app.py        # FastAPI 앱과 /departures 라우트
```

`data/` 아래 두 파일은 서비스가 체크아웃된 폴더에서 돌 때 프로젝트 루트에서 읽는 실행 시점 시드 데이터다. wheel 패키지에 넣는 애플리케이션 자산이 아니다. 가르치기 위한 서비스라면 괜찮지만, 말해 두지 않으면 배포 뒤에 조용히 깨지는 종류의 결정이다. 그래서 지금 이름을 붙여 둔다. 이 파일들이 배포된 서비스에 어떻게(혹은 과연) 따라가는지는 24장에서 정한다.

## 6. 응답 모델: 계약의 단일 기준

응답 형태는 Pydantic 모델로 정의한다. 23장 프론트엔드가 이 모델을 그대로 따라 그리므로, 계약의 단일 기준(single source of truth)이 된다.

```python
# src/departures/models.py
from typing import Literal
from pydantic import BaseModel, ConfigDict
from pydantic.alias_generators import to_camel

class Departure(BaseModel):
    model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True)
    service: str          # 예정 시각, 예: "07:02"
    platform: str
    delay_minutes: int
    minutes_until: int
    verdict: Literal["RUN", "relax"]
```

여기서 눈여겨볼 점이 두 가지 있다.

- 별칭 생성기(alias generator)는 JSON을 camelCase(`delayMinutes`, `minutesUntil`)로 내보낸다. 그래서 23장의 TypeScript 쪽에서 계약이 자연스럽게 읽히고, Python 코드는 계속 snake_case를 쓴다.
- `Literal["RUN", "relax"]`도 조용히 일을 한다. 프론트엔드가 분기할 두 상태 유니온과 똑같은 모양이므로, 세 번째 판정이 실수로 API 밖으로 새어 나갈 수 없다.

이 장은 처음부터 끝까지 따라 하면 서비스가 완성되도록 짜여 있다. AGENTS.md 절은 에이전트가 따를 규칙을 쓰고, pytest와 타입 절은 판정 로직과 테스트를 만들고, 도구 체인 절은 환경을 고정하고, 마지막 절은 FastAPI 라우트를 조립해 띄운다. 끝에는 localhost에서 `GET /departures`에 답하는 서비스가 남는다.
