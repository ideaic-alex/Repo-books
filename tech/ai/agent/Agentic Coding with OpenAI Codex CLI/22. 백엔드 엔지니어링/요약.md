# 요약

22장의 결론을 일곱 가지로 정리한다. 각 항목은 앞 문서에서 자세히 다룬 내용을 한 번 더 압축한 것이다.

---

## 1. 장 전체 요약

1. **Python은 피드백 루프를 약하게 만든다.** 정적 타입 언어보다 정답 신호가 약하다. 늦게 드러나는 타입 오류, 떠 있는 환경, import 시점의 부수 효과, 쉬운 목, 소리 없는 비동기 모서리가 다섯 가지 틈이고, 이 장의 레시피는 하나하나가 그중 하나를 막는다.
2. **AGENTS.md에 도구 이름을 적는다.** `uv run pytest`, `uv run ruff check --fix`, `uv run ruff format`을 적어 두면 엉뚱한 도구를 쓰는 실수 대부분이 생기기 전에 사라진다. 완료 게이트(린트, 포맷, 타입 검사, 테스트)는 전체 품질 사이클을 에이전트의 "끝났다"의 정의로 만든다.
3. **pytest는 픽스처와 마커를 이름으로 알려 줘야 한다.** Codex CLI가 픽스처가 어디 있는지, 어떤 마커가 있는지, 커버리지 기준이 얼마인지 알면 테스트 통합이 크게 좋아진다. 픽스처 찾기와 마커 규율은 설정이 부족한 프로젝트에서 가장 자주 빠지는 두 관례다.
4. **타입 생성에는 스타일이 필요하다.** 스타일을 정확히 정하면 타입 힌트와 독스트링은 자동 생성에 잘 맞는다. 설명 없는 `Any` 금지와 Google 스타일 독스트링이 가장 일관된 결과를 내는 두 지시다.
5. **도구 체인은 하나, 설정 파일도 하나다.** uv와 ruff는 예전에 여섯 개쯤 되던 도구를 합치고, 타입 검사 게이트는 mypy가 맡는다. pyproject.toml을 단일 기준으로 삼고 모든 실행을 `uv run`으로 거치게 하면, Codex CLI와 CI와 팀의 모든 개발자가 똑같이 공유하는 재현 가능한 환경이 된다.
6. **FastAPI와 비동기는 말로 적어야 한다.** async 라우트 핸들러, `Depends()` 주입, 명시적인 `response_model`, async 함수 안에서 블로킹 I/O 금지는 모두 AGENTS.md에 들어가야 한다. 안 그러면 Codex CLI가 라우트마다 다르게 즉흥으로 처리한다.
7. **Run or Relax의 보상.** 관례가 갖춰지면 서비스는 짧은 프롬프트로 만들어진다. 리뷰할 가치가 있는 부분은 판정 규칙과, 그 까다로운 경계를 못 박는 테스트다. `GET /departures` 계약은 23장이 화면에 그리고 24장이 배포하는, 세 장에 걸쳐 이어지는 하나의 예제다.

## 2. 한 줄로 줄이면

에이전트가 짐작해야 하는 것을 줄일수록 결과가 좋아진다. 도구, 규칙, 환경, 완료 기준을 AGENTS.md와 pyproject.toml과 훅에 한 번씩 적어 두면, 생성된 코드가 첫 시도에 맞게 나온다.
