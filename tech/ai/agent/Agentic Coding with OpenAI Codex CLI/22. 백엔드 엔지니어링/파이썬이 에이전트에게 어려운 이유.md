# 파이썬이 에이전트에게 어려운 이유

설정 레시피를 보기 전에, 왜 Python에는 정적 타입 언어보다 레시피가 더 많이 필요한지부터 짚는다. 이유를 알고 나면 뒤에 나오는 설정이 취향이 아니라 구멍을 막는 장치라는 것이 보인다.

---

## 1. 에이전트의 진짜 피드백 루프

에이전트에게 피드백 루프란, 방금 한 수정이 맞았는지 빠르고 자동으로 알려 주는 신호의 집합이다. Python은 TypeScript나 Rust보다 이 루프가 약하다. 이 장의 설정 대부분은 그 루프를 튼튼하게 만드는 일이고, 약해지는 원인은 언어와 생태계의 특성 다섯 가지로 거의 설명된다.

## 2. 다섯 가지 틈과 방어책

### 2.1 오류가 늦게 드러난다

컴파일되는 정적 타입 언어에서는 빌드 실패가 빠르고 공짜인 정답 신호가 된다. Python은 이 신호를 대부분 런타임이나 리뷰로 미룬다. mypy나 ty를 연결해 두지 않으면 에이전트는 타입 오류를 보지 못하고 자신 있게 내보낸다. 방어책은 타입 검사를 나중에 챙기는 일이 아니라 루프 안에 넣는 것이다. 엄격한 타입 검사기를 완료 기준(completion gate)에 두면, 에이전트가 컴파일러에게 받는 실패를 그대로 느낀다.

### 2.2 환경이 떠 있고 흘러간다

Python은 지금 활성화된 환경에 설치된 것을 기준으로 import를 해석한다. 이 환경은 에이전트 세션, CI, 개발자 각자의 노트북마다 다르다. 에이전트가 떠 있는(ambient) 환경에 `pip install`을 하면 자기 세션에서는 돌고 다른 사람 환경에서는 깨지는 코드가 나온다. 방어책은 락 파일이 뒷받침하는 단일 환경을 두고 모든 실행이 그곳을 거치게 하는 것이다. 이 장이 모든 명령을 `uv run`으로 감싸는 이유가 이것이다.

### 2.3 import 시점의 부수 효과가 동작을 숨긴다

Python은 import할 때 코드를 실행한다. 모듈 최상위 상수, 데코레이터, 레지스트리 등록, 때로는 네트워크나 파일 접근까지 일어난다. 함수 하나만 떼어 보는 에이전트는 모듈이 import되기만 해도 터지는 효과를 볼 수 없어서, 시작 동작을 슬며시 바꾸는 테스트와 리팩터링을 만든다. 방어책은 AGENTS.md에 적어 둔 규칙이다. 모듈은 import해도 깨끗하게 유지하고, 부수 효과는 함수 뒤로 밀어 두며, 모듈 최상위에는 새 작업을 얹지 않는다.

### 2.4 목(mock)이 너무 쉽다

동적 타입 덕분에 무엇이든 쉽게 패치할 수 있다. 빨리 초록불을 보고 싶은 에이전트는 제대로 된 픽스처를 만드는 대신 `unittest.mock.patch`로 세상을 덮어 버린다. 19장에서 다룬 과도한 목 사용 패턴, 곧 통과하지만 아무것도 증명하지 못하는 테스트가 나온다. Python이 이 실패가 가장 심한 곳이라서 목 사용 방침은 Python용 AGENTS.md에 꼭 들어가야 한다.

### 2.5 비동기에는 날카롭고 소리 없는 모서리가 있다

async 함수 안에서 블로킹 호출을 해도 예외가 나지 않는다. 대신 이벤트 루프가 멈추고, 증상은 원인과 멀리 떨어진 부하 시 지연으로 나타난다. 팀의 동시성 모델을 모르는 에이전트는 블로킹 코드와 비동기 코드를 섞어서, 모든 테스트를 통과하면서 운영에서는 느려지는 코드를 만든다. 방어책은 AGENTS.md의 명시적인 async 규칙과, 동기와 비동기 경계에 대한 리뷰 집중이다.

## 3. 정리해서 보는 표

| 틈 | 에이전트가 하는 일 | 방어책 |
|---|---|---|
| 늦게 드러나는 오류 | 타입 오류를 못 보고 확신에 차서 제출 | 엄격한 타입 검사를 완료 기준에 포함 |
| 떠 있는 환경 | 전역 환경에 pip install | 락 파일 기반 단일 환경, 모든 실행을 uv run으로 |
| import 부수 효과 | 시작 동작을 바꾸는 테스트와 리팩터링 | import-clean 규칙을 AGENTS.md에 기록 |
| 쉬운 목 | 패치로 초록불만 만든 테스트 | 목 방침을 Python AGENTS.md에 명시 |
| 비동기의 소리 없는 모서리 | async 안에서 블로킹 호출 | async 규칙 명시, 동기/비동기 경계 리뷰 |

이 장의 나머지는 이 렌즈로 읽으면 된다. 각 레시피는 임의의 사내 스타일이 아니라 이 다섯 틈 중 하나를 막는다. 에이전트가 볼 수 없던 속성을 무시할 수 없는 신호로 바꾸는 작업이다.
