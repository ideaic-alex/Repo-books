# 타입 힌트와 독스트링 자동화

Python의 타입 힌트 생태계는 3.10에서 3.12 사이에 성숙했다. 문법은 깔끔해졌고(`Optional[str]` 대신 `str | None`), 도구는 빨라졌으며(strict 모드의 ty와 mypy), 타입을 붙여 배포하는 팀은 운영 중 런타임 오류가 줄었다고 보고한다. Codex CLI는 타입 힌트 도입을 앞당길 수 있지만, 일관된 스타일 가이드가 있을 때만 그렇다.

---

## 1. AGENTS.md의 타입 스타일

```markdown
## Type hints
- Use Python 3.10+ union syntax: `str | None`, not `Optional[str]`
- Use `from __future__ import annotations` at the top of every module
- All public functions must have full type annotations (parameters and return type)
- Prefer `TypeAlias` and `NewType` over bare type aliases for domain concepts
- Use `TypedDict` for structured dictionaries passed between functions
- Do not use `Any` without a comment explaining why
```

맨 마지막 줄, 설명 없는 `Any` 금지는 엄격하게 지켜야 한다. Codex CLI는 타입이 불확실하면 기본값으로 `Any`를 고르는데, 바로 그 상황이 명시가 가장 값진 순간이다.

참고로 `X | Y` 유니온 문법은 PEP 604에서 들어왔고 Python 3.10에서 받아들여졌다. 3.9에서도 `from __future__ import annotations`를 쓰면 쓸 수 있다. mypy는 PEP 484를 따르는 정적 타입 검사기이며 strict 모드로 가장 폭넓게 검사한다.

## 2. 독스트링 생성

독스트링 지시에는 형식, 필수 섹션, 적용 범위를 적는다.

```markdown
## Docstrings
- Format: Google style (Args, Returns, Raises sections)
- All public functions, methods, and classes require docstrings
- Every public module needs a one-line module docstring too: Ruff's `D` set includes D100
- Include a one-line summary, then a blank line, then detail if needed
- `Args` section: one entry per parameter with type and description
- `Raises` section: only for exceptions that callers are expected to handle
```

모듈 독스트링 줄은 놓치기 쉽다. Ruff에서 `D` 규칙을 켜 두면, `app.py`, `models.py`, `timetable.py`, `verdict.py`에 첫 린트를 돌릴 때 각 모듈에 짧은 독스트링이 붙을 때까지 `D100 Missing docstring in public module`로 실패한다. `--fix`를 돌리며 하나씩 알아가는 것보다 처음부터 적어 두는 편이 낫다.

이 규칙이 자리 잡으면 "src/departures/timetable.py에서 독스트링이 없는 공개 함수에 Google 스타일 독스트링을 추가해 줘" 같은 프롬프트가 일관된 결과를 낸다. 결과는 손질 없이 독스트링 스타일 검사(pydocstyle 또는 Ruff의 D 규칙)를 통과한다.

## 3. 정리

- 타입 힌트는 스타일 가이드가 있어야 자동 생성이 일관된다.
- 가장 효과가 큰 지시는 "설명 없는 Any 금지"와 "Google 스타일 독스트링 고정"이다.
- 이 규칙들은 뒤의 pyproject.toml에서 `mypy strict`와 Ruff의 `D` 규칙으로 도구가 강제한다. AGENTS.md는 에이전트가 처음부터 맞게 쓰도록 안내하고, 도구는 어긋난 것을 잡아낸다.
