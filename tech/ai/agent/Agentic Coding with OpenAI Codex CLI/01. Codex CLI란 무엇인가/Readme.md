# Codex CLI란 무엇인가

설정 파일을 만지거나 AGENTS.md를 쓰거나 첫 작업을 돌리기 전에, Codex CLI가 어디서 왔고 어떤 문제를 풀려는 도구인지 알아 두면 좋다. 이 장은 2021년의 Codex 모델과 GitHub Copilot의 자동완성 시대에서 출발해, 2023~2024년의 에이전트 전환을 거쳐 지금의 Codex CLI가 만들어진 설계 결정까지를 따라간다.

이 장을 읽고 나면 책 전체가 기대는 기본 그림이 잡힌다. 자동완성, 채팅, 에이전트의 차이를 설명하고, 여러 AI 코딩 도구 사이에서 Codex CLI의 위치를 짚고, 저장소 읽기, 테스트 실행, 커밋, AGENTS.md 준수라는 핵심 능력 네 가지를 말할 수 있게 된다. 이 장의 원문 범위에는 본문에 들어간 그림이 없고 비교표 하나(Table 1-1)만 있어서, 표는 내용을 한국어로 새로 구성해 담았다.

---

## 1. 핵심 요점

- 2021년 Codex 모델은 코드로 추가 학습한 언어 모델이 설명만 보고 구현을 만들 수 있음을 보였고, HumanEval 164문제에서 28.8%를 통과했다.
- GitHub Copilot의 자동완성은 반응형이고 국소적이라, 테스트 실행이나 여러 파일에 걸친 추론에서 한계가 있다. 이는 모델이 아니라 인터페이스의 문제다.
- 에이전트 방식은 모델에게 환경에 접근하는 도구를 주어 사람의 중계를 없앤다. 다만 무감독을 뜻하지 않으며 승인 모드로 사람의 감독이 유지된다.
- AI 코딩 도구는 IDE 통합, 터미널, 클라우드·호스팅 세 범주로 나뉘고 Codex CLI는 터미널 에이전트다.
- Codex CLI는 2025년 4월 16일 공개된 Apache 2.0 오픈 소스 도구로, 터미널 우선, `codex exec` 헤드리스 실행, 커널 수준 샌드박스, AGENTS.md 인식이 특징이다.
- 터미널 기반이라 Unix 도구와 조합되고, API 키와 `codex exec` 한 줄로 CI/CD에 들어가며, SSH나 컨테이너 같은 곳에서도 쓸 수 있다.
- 핵심 제안은 저장소를 읽고, 테스트를 돌리고, 커밋을 만들고, AGENTS.md를 따른다는 네 가지다.
- macOS(Seatbelt)와 Linux(bubblewrap/seccomp)의 샌드박스는 동작이 다르므로 CI에 쓰기 전 양쪽에서 시험해야 한다.
