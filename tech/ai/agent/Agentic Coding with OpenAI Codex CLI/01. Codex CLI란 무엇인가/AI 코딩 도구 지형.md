# AI 코딩 도구 지형

대부분의 전문 개발자는 이미 AI 코딩 도구를 여러 개 함께 쓴다. 이 시장에는 하나의 승자가 있는 것이 아니라 범주가 있다. 그래서 Codex CLI가 어디에 놓이는지 알려면 범주부터 이해해야 한다. 이 문서는 에이전트가 어디에서 도는지를 기준으로 도구를 세 갈래로 나누어 살펴본다.

---

## 1. 세 가지 범주

기준은 "에이전트가 어디에 사는가"다. 편집기 안, 터미널 안, 클라우드 안, 셋 중 하나다.

### 범주 1. IDE 통합 에이전트

개발자가 이미 일하는 곳, 즉 코드 편집기 안으로 찾아가는 도구다. IDE는 Integrated Development Environment(통합 개발 환경)의 약자로, 코드를 실행하고 테스트하고 디버깅하는 도구가 들어 있는 편집기를 말한다. 전문 개발자 사이에서 가장 인기 있는 IDE는 Visual Studio Code(VS Code)다.

**GitHub Copilot**은 지금도 가장 널리 배포된 AI 코딩 도구로, 인지도와 직장 내 사용률이 가장 높다. 자동완성(흐린 글씨, Tab으로 수락)에서 시작해 더 넓은 플랫폼으로 자랐다.

- Copilot Chat: 대화형 보조
- Copilot Coding Agent: 풀 리퀘스트를 통해 비동기로 작업을 끝내는 에이전트
- 확장(extension) 생태계

기업 입장에서는 코드, 풀 리퀘스트, CI가 이미 모여 있는 GitHub와의 통합이 구조적인 장점이다. 제품 기능만 놓고 비교하는 글들은 이 장점을 과소평가하는 경우가 많다.

**Cursor**는 Anysphere가 만들었고 IDE 통합 에이전트 중 대표 주자다. 확장 프로그램을 만드는 대신 VS Code를 포크해서 모든 화면에 AI를 넣었다. 특징은 다음과 같다.

- Composer로 여러 파일을 한 번에 수정
- Background Agents로 자율 세션을 병렬 실행
- 깊은 코드베이스 인덱싱으로, 프롬프트에 끼워 넣는 방식보다 풍부한 구조 정보를 모델에 제공

편집기를 떠나고 싶지 않은 개발자를 겨냥한다. 시각적인 diff, 줄 안에서 수락/거절하는 흐름, 익숙한 확장 생태계가 장점이라 변경이 반영되기 전에 에이전트가 무엇을 하는지 눈으로 확인하고 싶은 사람에게 맞는다. 터미널 네이티브가 아니고 오픈 소스도 아니다.

**Cline**(원래 이름은 Claude-Dev)은 오픈 소스 VS Code 확장이다. 모델에게 파일 읽기, 셸 실행, Playwright를 통한 브라우저 제어 같은 도구를 주고, 편집기 안에서 여러 단계 작업을 계획하고 실행하게 한다. Cursor와 달리 포크가 아니라 표준 VS Code 안에서 돌기 때문에 확장 생태계를 그대로 쓸 수 있다. 특정 모델에 묶이지 않고(model-agnostic), 기여자 커뮤니티가 활발하게 유지보수한다.

### 범주 2. 터미널 에이전트

터미널 에이전트는 셸에서 돈다. 셸은 명령을 입력하고 출력을 보는 텍스트 기반 인터페이스다. 그래픽 화면이 생기기 전부터 개발자가 컴퓨터와 소통해 온 방식이고, 지금도 전문 소프트웨어 개발의 뼈대다.

터미널 에이전트는 Unix 도구와 잘 어울리고, CI/CD 파이프라인(코드를 자동으로 빌드·테스트·배포하는 체계)에 자연스럽게 들어가며, 터미널만 있으면 어디서든 돈다. SSH 세션, Docker 컨테이너, 화면 없는 서버가 그 예다. Codex CLI가 이 범주에 속한다.

**Claude Code**는 Anthropic이 2025년 5월에 낸 도구로, Codex CLI의 가장 직접적인 경쟁자이고 함께 마주칠 가능성이 가장 높다. 터미널 우선이고 에이전트형이며, `CLAUDE.md`라는 프로젝트 지침 파일을 쓴다. 이 파일은 Codex CLI의 AGENTS.md와 기능이 거의 같다. 샌드박스 환경에서 돌고, 서브에이전트와 에이전트 팀으로 병렬 실행을 지원하며, Anthropic의 Model Context Protocol(MCP, AI 도구가 외부 서비스와 데이터에 연결하게 해 주는 표준)과 깊게 통합되어 있다. Codex CLI도 MCP를 지원한다.

두 도구는 설계 철학이 많이 겹쳐서 쓰는 요령이 서로 쉽게 옮겨 간다. 주된 차이는 다음과 같다.

| 차이점 | Claude Code | Codex CLI |
|---|---|---|
| 모델 계열 | Claude | GPT |
| 서브에이전트 구조 | 우편함(mailbox) 방식의 Agent Teams | TOML로 정의하는 서브에이전트, 경로 주소 지정 |
| 생태계 | Anthropic 쪽 | OpenAI 쪽 |

Claude Code를 쓰는 팀에 속해 있거나 두 도구를 비교 평가한다면, 한쪽의 설계 결정을 이해하는 것이 다른 쪽을 이해하는 데 도움이 된다. 자세한 비교는 26장에서 다룬다.

**Aider**는 Paul Gauthier가 2023년에 만든 도구로, 가장 이른 오픈 소스 터미널 에이전트 가운데 하나이고 이후 도구들의 설계에 영향을 주었다. 핵심 혁신은 구조화된 편집 형식이다. 원시 코드를 줄줄이 내보내게 하는 대신, 결정적으로(deterministic) 적용할 수 있는 diff 블록을 모델이 만들게 했다. 모델에 묶이지 않고(500개 이상의 LLM 제공자 지원) 지금도 활발히 개발된다. 데이터 보관 위치 요건이 엄격해서 특정 모델 제공자만 써야 하는 조직에는, 인터페이스와 모델을 분리한 Aider의 구조가 실질적인 장점이다.

### 범주 3. 클라우드·호스팅 에이전트

클라우드 환경에서 비동기로 돌며, 풀 리퀘스트 흐름에 붙어 있는 경우가 많다.

- **GitHub Copilot Coding Agent**: GitHub 이슈와 직접 연결된다. 이슈를 Copilot에 배정하면 에이전트가 계획을 제안하고, 샌드박스 환경에서 구현을 만든 뒤 검토용 초안(draft) 풀 리퀘스트를 연다. 일을 맡기고 자리를 떠났다가 돌아오면 풀 리퀘스트가 있는 방식이다. 코드가 이미 리뷰되고 병합되는 워크플로 안에 에이전트를 넣는 것이 맞다는, 플랫폼 소유자의 선택이다.
- **Devin**: Cognition Labs가 2024년 3월에 발표했다. '최초의 AI 소프트웨어 엔지니어'로 홍보된, 브라우저·셸·편집기에 접근하는 완전 호스팅형 자율 에이전트다. 사람 개입 없이 오랜 세션 동안 엔지니어링 작업을 끝내도록 설계되었다.
- **Google Jules**와 **Codex Cloud Tasks**(OpenAI 자체 클라우드 서비스): 작업을 제출하면 에이전트가 격리된 클라우드 환경에서 일하고, 끝났을 때 결과만 검토하는 "던져 놓고 잊는(fire-and-forget)" 실행 흐름이 늘고 있음을 보여 준다.

## 2. 한눈에 보는 비교표

원문은 글을 쓴 시점의 지형을 표로 정리하고, 시장 위치 열은 JetBrains 개발자 설문을 바탕으로 했다고 밝힌다. 아래는 내용을 새로 정리한 표다.

| 도구 | 범주 | 인터페이스 | 시장 위치 | 샌드박스 | 오픈 소스 |
|---|---|---|---|---|---|
| GitHub Copilot | IDE 에이전트 | VS Code / JetBrains 확장 | 인지도와 도입률 최고 | 확장을 통해 | 아니오 |
| Cursor | IDE 에이전트 | VS Code 포크 | 상당한 도입 | 편집기를 통해 | 아니오 |
| Claude Code | 터미널 에이전트 | 터미널(CLI)과 데스크톱 | 상당한 도입 | OS 수준 | 소스 공개(source-available) |
| Cline | IDE 에이전트 | VS Code 확장 | 활발한 오픈 소스 커뮤니티 | 도구 권한을 통해 | 예(Apache 2.0) |
| Copilot Coding Agent | 클라우드 에이전트 | GitHub 웹 + Actions | GitHub PR 흐름에 기본 내장 | Actions 샌드박스 | 아니오 |
| Devin | 클라우드 에이전트 | 호스팅 웹 VM | 'AI 엔지니어' 개념을 개척 | 호스팅 VM | 아니오 |
| Aider | 터미널 에이전트 | 터미널(CLI) | 오픈 소스 틈새, 모델 무관 | 셸을 통해 | 예(Apache 2.0) |
| Codex CLI | 터미널 에이전트 | 터미널(CLI) | 성장 중 | 커널 수준(Seatbelt / bubblewrap) | 예(Apache 2.0) |

## 3. 도구를 고르는 기준

시장 점유율이 곧 내 상황에서의 품질은 아니다. 어떤 도구가 맞는지는 선호하는 모델, 쓰는 편집기, 배포 제약, 터미널과 조합해 쓸 필요가 있는지에 달려 있다. 이 책은 선택지 중 하나인 Codex CLI를 깊이 아는 상태에서 그 판단을 내리도록 돕는 것을 목표로 한다.
