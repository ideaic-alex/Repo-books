# Codex 이전의 역사

Codex CLI라는 이름은 2025년에 나온 도구보다 훨씬 먼저 있었다. 이 문서는 2021년의 Codex 모델에서 시작해 GitHub Copilot의 자동완성 시대, 2022년 ChatGPT의 등장까지를 차례로 훑는다. 이 흐름을 알면 Codex CLI가 왜 지금의 모습으로 만들어졌는지 이해하기 쉽다.

---

## 1. 2021년의 Codex 모델

2021년 7월 OpenAI는 Mark Chen 등이 쓴 연구 논문(arXiv:2107.03374)을 공개했다. GitHub에 공개된 코드로 GPT 계열 언어 모델을 추가 학습(파인튜닝)한 모델 묶음을 설명한 논문이다. 가장 큰 모델은 파이썬 코드만 159GB를 학습했다.

논문이 보여준 핵심은 이렇다. 충분히 큰 모델을 충분한 코드로 학습시키면, 도구도 테스트 실행기도 검색 장치도 없이 함수 설명(docstring)만 보고도 경쟁 프로그래밍 문제의 상당 부분을 풀 수 있다는 것이다.

이때 함께 소개된 것이 HumanEval이라는 벤치마크다.

| 항목 | 내용 |
|---|---|
| 문제 수 | 사람이 직접 쓴 프로그래밍 문제 164개 |
| 문제 형태 | 함수 시그니처와 docstring |
| 통과 기준 | 한 번에 올바른 구현을 내놓으면 통과 |
| 원조 Codex 모델의 통과율 | 28.8% |

28.8%는 지금 보면 옛날 얘기처럼 느껴지는 숫자다. 하지만 2021년에는 "언어 모델의 규모를 코드에 적용하면 질적으로 새로운 능력이 생긴다"는 사실을 보여준 수치였다.

## 2. 이후를 결정한 두 가지 성질

원조 Codex 모델의 성질 두 가지가 그 뒤의 모든 흐름을 정했다.

- **생성형이다.** 프롬프트를 받아 토큰을 하나씩 만들어 낸다. 그래서 미완성 함수를 이어서 완성하고, 언어 사이를 옮겨 쓰고, 자기가 만든 코드를 자연어로 설명하는 일이 모두 가능했다.
- **완성(completion) 은유에 맞춰 최적화되었다.** docstring을 주면 구현을 돌려주는 방식이다. 이 상호작용 모델이 AI 코딩 보조의 첫 번째 상업 시대를 규정했다.

## 3. GitHub Copilot과 자동완성 패러다임 (2021년 6월)

2021년 6월 29일 GitHub는 Codex 모델을 엔진으로 삼아 GitHub Copilot을 기술 프리뷰로 내놓았다. 사용 방식은 단순하고 깔끔했다. 코드를 치면 흐린 글씨(ghost text)로 제안이 뜨고, Tab을 누르면 받아들이고, 계속 치면 무시된다. 모델은 열려 있는 파일, 함수 이름, 주변 코드, docstring을 단서로 삼아 꽤 자주 쓸 만한 제안을 만들어 냈다.

Copilot은 거의 모든 이전 개발자 도구보다 빠르게 퍼졌다. "어깨 너머에서 지켜보다가 문장을 끝내 주는 AI"라는 자동완성 패러다임이 본격적으로 시작된 것이다. 정식 출시는 2022년 6월에 모든 개발자를 대상으로 이루어졌다(원문 각주).

### 자동완성의 한계

이 패러다임의 한계는 그 안에 있을 때는 잘 보이지 않았다. 자동완성은 반응형이고 국소적이다. 모델은 지금까지 친 내용만 보고 다음에 올 것을 예측한다.

- 테스트 스위트를 읽지 않는다.
- 빌드 시스템을 이해하지 않는다.
- 제안이 린터를 통과할지 신경 쓰지 않는다.

한 줄씩 끝내 주는 도구일 뿐이다. 상용구(boilerplate)나 잘 알려진 패턴에는 이것만으로 충분할 때가 많다. 하지만 여러 파일에 걸친 추론, 테스트 결과를 보며 반복해서 고치는 일, 아키텍처 제약을 지키는 일에서는 벽에 부딪힌다.

## 4. ChatGPT의 충격 (2022년 11월)

전용 Codex API 모델은 2023년 3월에 폐기되었다. 그보다 앞선 2022년 11월 30일에 더 큰 사건이 있었다. ChatGPT의 출시다. 닷새 만에 사용자 100만 명, 두 달 만에 1억 명을 넘겨 당시까지 가장 빠르게 성장한 소비자 앱이 되었다.

개발자에게 ChatGPT는 상호작용 방식을 한 줄 완성에서 대화로 바꿔 놓았다. 문제를 설명하고, 답을 받고, 후속 질문을 하며 다듬는다. 탭 자동완성보다 느리지만 복잡한 문제에는 훨씬 강하다. 스택 트레이스를 붙여 넣고, 설명을 듣고, 수정안을 요청하고, 왜 그 수정이 동작하는지 묻고, 변형안을 부탁하는 일이 한 스레드 안에서 이어진다.

ChatGPT는 코딩 도구로 설계된 것이 아니었다. 그러나 자동완성이 가려 두었던 사실을 드러냈다. 모델이 여러 단계에 걸친 추론, 제약 적용, 작업 쪼개기를 할 수 있다는 점이다. 필요한 것은 대화가 여러 번 오갈 수 있는 인터페이스뿐이었다. 이렇게 채팅 기반 코딩 보조의 시대가 열렸고, 이 시대는 다음 전환인 "에이전시(agency, 스스로 행동하는 능력)"가 올 때까지 이어졌다.
