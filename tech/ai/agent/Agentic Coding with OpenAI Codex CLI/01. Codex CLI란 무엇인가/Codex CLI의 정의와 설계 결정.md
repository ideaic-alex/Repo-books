# Codex CLI의 정의와 설계 결정

Codex CLI는 한 줄로 "OpenAI가 만든 오픈 소스 터미널 코딩 에이전트"다. 이 문서는 도구가 언제 어떻게 나왔는지, 그리고 다른 도구와 갈라지는 다섯 가지 설계 결정을 하나씩 설명한다. 이 결정들은 모두 의도적이다. 이유를 알아야 도구를 제대로 쓸 수 있다.

---

## 1. 공개 시점과 분위기

2025년 4월 16일 OpenAI는 Codex CLI를 공개했다. Apache 2.0 라이선스의 오픈 소스 터미널 에이전트이고, 만든 사람은 Fouad Matin과 Michael Bolin이다. AI 발표치고는 조용한 공개였다. 'AI 소프트웨어 엔지니어' 같은 거창한 이름표 없이, README는 터미널에서 일하고 싶은 개발자를 위한 도구라고만 설명했다.

## 2. 카르파시의 관점: Software 3.0

Andrej Karpathy는 Codex CLI를 Software 3.0 플랫폼으로 바라봤다. 이 관점에서는 이렇게 정리된다.

- 컨텍스트 윈도가 지렛대다.
- AGENTS.md가 프로그램이다.
- 하니스(harness)가 생산적인 사용과 혼란을 가르는 요소다. 하니스란 에이전트를 설정하고, 제약하고, 검증하는 일 전체를 말한다.

이 틀이 이 책의 중심 주장이다. 27장에서 본격적으로 전개한다.

## 3. 다섯 가지 설계 결정

### 3-1. 터미널 우선

Codex CLI는 셸에서 돈다. VS Code 확장도 아니고, 호스팅 웹 서비스도 아니고, 주로 GUI 애플리케이션인 것도 아니다. (다만 병렬 세션을 관리하는 보조 macOS 앱은 있다.)

터미널 도구는 Unix 생태계와 조합된다. 파이프, 리다이렉트, 환경 변수, 셸 스크립트, cron 작업, CI 파이프라인이 모두 해당한다. 셸 명령을 실행할 수 있는 것이면 무엇이든 Codex CLI를 호출할 수 있고, 이것이 15장 CI 연동 패턴의 바탕이다.

### 3-2. 헤드리스와 스크립트 실행

`codex exec` 명령은 에이전트를 비대화형으로 돌린다. 프롬프트를 인자나 stdin으로 받고, 작업이 끝나면 종료한다. 자동화 파이프라인에서 Codex CLI를 쓸 수 있게 하는 인터페이스가 바로 이것이다. GitHub Actions 작업에서 pytest나 eslint를 부르듯 `codex exec`를 워크플로의 한 단계로 호출하고, 구조화된 출력을 받아 다음 단계로 넘길 수 있다.

### 3-3. 커널 수준 샌드박스

Codex CLI가 '샌드박스'되어 있다는 말은 에이전트가 도는 동안 운영체제가 할 수 있는 일을 제한한다는 뜻이다.

| 운영체제 | 사용하는 장치 | 제한 대상 |
|---|---|---|
| macOS | Apple Seatbelt | 파일 시스템과 네트워크 접근 |
| Linux | bubblewrap과 seccomp | 파일 시스템과 네트워크 접근 |

둘 다 커널 수준의 보안 장치다. 제한을 강제하는 것이 애플리케이션이 아니라 OS이므로, 에이전트가 실수로 우회할 수 없다. 프롬프트 인젝션(입력 텍스트에 숨겨진 악의적 지시)으로 모델이 "나에게 더 높은 권한이 있다"고 믿게 되더라도 커널 수준에서 막힌다.

샌드박스는 의도적으로 넓힐 수 있다. `~/.codex/config.toml`에 정의하는 승인 모드와 샌드박스 프로필을 쓰면 된다. 다만 기본값은 제한된 상태이고, 그 제한은 실제로 작동한다.

### 3-4. AGENTS.md 인식

Codex CLI는 저장소 루트와 하위 디렉터리의 AGENTS.md 파일을 읽어 프로젝트별 지침을 불러온다. 어떤 테스트 명령을 돌릴지, 어떤 툴체인을 쓸지, 어떤 관례를 따를지, 어떤 함정(footgun)을 피할지가 여기에 들어간다.

이 형식은 지금은 Linux Foundation 산하 Agentic AI Foundation이 관리하는 열린 표준이고, 주요 에이전트 도구 대부분이 채택했다. AGENTS.md 작성법은 4장에서 깊이 다룬다.

### 3-5. Apache 2.0 오픈 소스

소스 코드가 GitHub에 공개되어 있고 커뮤니티 기여를 받는다. 내 셸 명령을 대신 실행하는 도구에게 이 투명성은 신뢰 모델의 중요한 부분이다.

## 4. 설계 결정 요약

| 결정 | 얻는 것 |
|---|---|
| 터미널 우선 | Unix 도구, 스크립트, cron, CI와 자연스럽게 결합 |
| 헤드리스(`codex exec`) | 자동화 파이프라인의 한 단계로 호출 |
| 커널 수준 샌드박스 | OS가 강제하는 제한이라 에이전트가 우회할 수 없음 |
| AGENTS.md 인식 | 프로젝트 지식을 에이전트에게 전달하는 표준 통로 |
| Apache 2.0 오픈 소스 | 투명성과 신뢰, 커뮤니티 기여 |
