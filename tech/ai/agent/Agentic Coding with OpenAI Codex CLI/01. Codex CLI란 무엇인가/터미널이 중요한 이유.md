# 터미널이 중요한 이유

Codex CLI를 IDE 확장이나 호스팅 웹 앱이 아니라 터미널 도구로 만든 것은 옛 명령줄에 대한 향수 때문이 아니다. 조합 가능성(composability)에 대한 선택이다. 이 문서는 터미널 기반이 가져다주는 이점 세 가지와, 운영체제별 샌드박스 차이에서 오는 주의점을 정리한다.

---

## 1. Unix 도구와 조합된다

Unix 도구는 서로 잘 이어진다. 한 프로그램의 출력이 다음 프로그램의 입력이 되고, 필터와 변환기와 집계기가 파이프라인으로 연결된다. 셸은 표준 입력과 표준 출력으로 서로 대화하는 프로그램들을 묶어 주는 조율 계층이다.

이런 환경에 사는 에이전트는 이 조합 능력을 공짜로 물려받는다. 예를 들면 이런 일이 가능하다.

- Codex CLI 출력을 `jq`로 넘겨 구조화된 결과만 뽑는다.
- `codex exec`를 셸 스크립트로 감싸 cron으로 매일 밤 돌린다.
- Makefile 타깃 하나에서 빌드, 테스트, 수정, 커밋을 순서대로 이어 여러 세션을 연결한다.
- 설정 파일을 건드리지 않고 환경 변수만 넘겨 동작을 바꾼다.

이 중 어느 것도 Codex CLI가 따로 지원을 만들어야 하는 기능이 아니다. stdin에서 읽고, stdout에 쓰고, 의미 있는 종료 코드로 끝나는 터미널 도구라는 사실에서 자연스럽게 따라 나오는 결과다.

## 2. 의식 없이 CI/CD에 들어간다

CI 파이프라인은 결국 셸 스크립트다. GitHub Actions 워크플로는 셸 명령을 설명하는 YAML 파일이고, Jenkins, CircleCI, GitLab CI도 다 같다. "이 명령들을, 이 순서로, 이 환경 변수와 함께, 이 컨테이너에서 실행하라"로 요약된다.

터미널 네이티브 에이전트는 다른 명령줄 도구와 똑같이 자연스럽게 끼어든다. GitHub App도, OAuth 연동도, 웹훅 핸들러도, 전용 클라우드 환경도 필요 없다. 시크릿 저장소에 API 키 하나를 넣고 워크플로 파일에 `codex exec` 호출을 적으면 된다.

규제가 있는 환경이나 사내 방화벽 안에서는 새 서비스 연동마다 보안 심사를 받아야 한다. 이런 곳에서는 기존 API 호출과 같은 네트워크 경로를 쓰는 CLI 도구가 새 SaaS 연동보다 훨씬 승인받기 쉽다.

### CI에 쓰는 조합

`codex exec`에 `--ask-for-approval never`와 제한적인 샌드박스 모드(`workspace-write` 또는 `read-only` 등)를 함께 쓰는 것이 CI용으로 설계된 조합이다. 자동화 환경에서 샌드박스 범위를 정하는 방법을 포함한 GitHub Actions 연동 전체 패턴은 15장에서 다룬다.

## 3. GUI가 필요 없다

개발 환경은 제각각이다. VS Code를 쓰는 사람도, Neovim, Emacs, Helix를 쓰는 사람도 있다. GUI를 띄울 수 없는 SSH 원격 서버에서 일하는 사람도 있다. Electron 앱을 설치하기 어려운 컨테이너 환경도 있다.

터미널 도구는 이 모든 곳에서 동작한다. SSH 세션, Docker 컨테이너, 원격 개발 환경, 화면 없는 CI 러너에는 모두 셸이 있다. 셸에 사는 에이전트는 셸이 있는 곳이라면 어디서든 쓸 수 있다.

---

## 4. 주의: macOS와 Linux의 샌드박스는 다르게 움직인다

대화형 세션에서 Codex CLI를 안전하게 만드는 샌드박스는 OS 수준에서 동작한다. 그래서 macOS(Seatbelt)와 Linux(bubblewrap/seccomp)에서 동작이 서로 다르다.

macOS에서 개발하고 Linux에서 CI 자동화를 배포하는 조합이 흔하다. 이 경우 샌드박스 프로필을 운영 파이프라인에서 믿고 쓰기 전에 두 플랫폼 모두에서 먼저 시험해야 한다. 한쪽에서 통과했다고 다른 쪽에서도 같은 결과가 나온다고 가정하면 안 된다.

## 5. 정리

| 이점 | 이유 |
|---|---|
| Unix 조합 가능성 | stdin/stdout/종료 코드를 쓰는 프로그램이라 파이프, 스크립트, cron, Makefile과 연결된다 |
| CI/CD 연동 | 별도 앱이나 웹훅 없이 API 키와 `codex exec` 한 줄이면 된다 |
| 보안 심사 | 기존 API와 같은 네트워크 경로라 승인받기 쉽다 |
| 환경 범용성 | SSH, 컨테이너, 원격 개발 환경, 헤드리스 러너 어디에나 셸이 있다 |
