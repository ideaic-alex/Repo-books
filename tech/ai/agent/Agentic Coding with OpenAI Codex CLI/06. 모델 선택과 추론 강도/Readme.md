# 모델 선택과 추론 강도

승인 모드가 Codex CLI가 할 수 있는 일을 정한다면, 이 장은 그 안에서 에이전트가 얼마나 잘 일하고 한 번 돌리는 데 얼마가 드는지를 정하는 두 가지 설정을 다룬다. 어떤 모델이 일을 맡을지, 그리고 그 모델이 답하기 전에 얼마나 깊이 생각할지다. 둘 중 하나를 잘못 잡으면 사용 한도(쿼터)가 낭비된다.

모델을 이름이 아니라 역할로 나누는 법, 추론 강도 설정, 프로필, 모델 라우팅, 클라우드와 로컬 공급자, 속도 제한에 대비한 복원력 설계, 모델 폐기 점검까지 순서대로 정리한다.

이 장을 마치면 다음을 할 수 있다.

- `config.toml`에 기본 모델과 추론 강도를 정하고, 실행할 때마다 덮어쓴다.
- 프로필을 만들어 일상용, 깊은 조사용, 쿼터 절약용 구성을 플래그 하나로 바꾼다.
- 세션 중에 단축키로 추론 강도를 바꾼다.
- 추론 예산이 가장 값지게 쓰이는 곳에 배분하는 다중 모델 워크플로를 설계한다.

---

## 1. 핵심 요점

- 모델 이름은 자주 바뀌므로 플래그십, 범용, 빠른/미니, 코딩 특화라는 역할로 생각한다.
- 모델은 능력의 천장을, 추론 강도(minimal, low, medium, high, xhigh)는 그 천장에 얼마나 다가갈지를 정하는 독립된 손잡이다.
- 모델은 `-m`, `config.toml`의 `model`, `/model`로, 추론 강도는 `model_reasoning_effort`, `-c`, `Alt+,` / `Alt+.`로 바꾼다.
- 프로필(`~/.codex/<이름>.config.toml`)로 모델, 강도, 권한을 묶고 `--profile`로 전환한다. 우선순위는 CLI 플래그 > 프로필 > 프로젝트 설정 > 사용자 설정 > 기본값이다.
- 결정 트리와 조율자-작업자 패턴, 세션 단계별 라우팅으로 비싼 모델은 꼭 필요한 곳에만 쓴다.
- `[model_providers]`로 Azure, Bedrock, Vertex AI와 Ollama 같은 로컬 모델까지 연결할 수 있다.
- 재시도 설정, 독립된 쿼터 풀을 쓰는 프로필 전환, AI 게이트웨이 자동 전환으로 429 오류에 대비하되 중간 실패의 한계를 이해한다.
- 모델 폐기는 인증 방식에 따라 시점이 다르므로 설정을 정기 점검하고 CI/CD에서는 모델을 명시적으로 고정한다.
