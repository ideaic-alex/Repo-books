# 요약

6장은 Codex CLI에서 어떤 모델을 쓰고 얼마나 깊이 생각하게 할지를 정하는 방법을 다뤘다. 이 문서는 장 끝의 요약 일곱 가지를 풀어 쓰고, 다음 장으로 이어지는 흐름을 덧붙인다.

---

## 1. 일곱 가지 핵심

1. 모델은 이름이 아니라 범주로 기억한다. 플래그십, 범용, 빠른 모델, 코딩 특화 모델이라는 범주는 모델 이름이 몇 달마다 바뀌어도 그대로 쓸 수 있다. 바뀌는 이름을 외우는 것은 오래가지 못한다.
2. 추론 강도는 모델과 별개의 손잡이다. low, medium, high 같은 단계가 모델 선택과 따로 생각의 깊이를 조절한다. 세션 중에는 `Alt+,`와 `Alt+.`로 바꿀 수 있다.
3. 이름 붙인 프로필이 선택을 묶어 준다. 모델, 추론 강도, 권한 설정을 하나로 포장해 전환 가능한 구성으로 만든다.
4. 조율자-작업자 라우팅을 쓴다. 계획은 플래그십이나 범용 모델에 맡기고, 범위가 정해진 하위 작업은 빠른 모델에 보낸다.
5. OpenAI 밖으로도 넓힐 수 있다. Azure, Bedrock, Vertex AI 같은 클라우드 공급자와 Ollama, vLLM 같은 로컬 추론이 OpenAI 계열 밖으로 선택지를 확장한다.
6. 다중 공급자로 복원력을 확보한다. 프로필, 게이트웨이, 서로 독립된 속도 제한 풀이 세션을 죽이는 429 오류를 막아 준다.
7. 정기적으로 점검한다. 설정에 폐기된 모델 참조가 남아 있지 않은지 확인한다.

## 2. 이 장의 설정 한눈에 보기

| 하고 싶은 일 | 방법 |
|---|---|
| 기본 모델 지정 | `config.toml`의 `model`, 실행 시 `-m`, 세션 중 `/model` |
| 기본 추론 강도 지정 | `model_reasoning_effort`, 실행 시 `-c model_reasoning_effort=high` |
| 세션 중 강도 조절 | `Alt+,`(낮춤), `Alt+.`(높임) |
| 구성 묶음 전환 | `--profile <이름>` 또는 `-p`, 파일은 `~/.codex/<이름>.config.toml` |
| 클라우드나 로컬 연결 | `model_provider`와 `[model_providers.<이름>]` |
| 로컬 단축 | `oss_provider`와 `--oss`, `--local-provider` |
| 재시도 조절 | `request_max_retries`, `stream_max_retries` |
| 폐기 모델 점검 | `grep -rn --include='*.toml' 'model = ' ~/.codex .codex` |

## 3. 다음 장으로

승인 정책, 샌드박스 모드, 모델, 추론 강도는 에이전트가 무엇을 할 수 있는지, 누가 돌리는지, 얼마나 깊이 생각하는지를 정한다. 그러나 이 설정 중 어느 것도 에이전트가 얼마나 기억할 수 있는지는 바꾸지 못한다. 긴 세션은 다른 벽, 곧 컨텍스트 윈도에 부딪힌다. 7장은 컨텍스트가 어떻게 차는지, 왜 선형이 아니라 제곱으로 차는지, 오래 도는 세션을 맥락을 잃지 않고 유지하는 방법을 다룬다.
