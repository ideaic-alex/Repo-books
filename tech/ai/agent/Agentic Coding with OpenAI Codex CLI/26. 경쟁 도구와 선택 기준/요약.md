# 요약

26장 전체를 열 가지 요점으로 줄인 정리다. 각 항목이 앞선 문서의 어느 내용에 해당하는지 함께 적었다. 장을 읽은 뒤 복습용으로 쓰기 좋다.

---

## 1. 열 가지 요점

1. **하나의 구조적 축이 시장을 가른다.** 시장은 CLI 대 IDE로 나뉘고, 한쪽은 사람 없이 돌리는 실행과 스크립트화에, 다른 쪽은 짧은 피드백 루프와 시각적 diff에 최적화되어 있다. 제품 이름은 범주의 대표 예로만 읽는다. 범주가 브랜드보다 오래간다.
2. **차이는 모델보다 하니스에서 난다.** 인터페이스, 메커니즘, 확장의 3층이 비슷한 모델을 쓰는 도구들 사이의 차이 대부분을 설명한다. 모델은 천장을 정하고 하니스는 그 천장에 얼마나 닿는지를 정한다. 27장이 이 주장을 본격적으로 다룬다.
3. **CLI 에이전트는 자동화에 강하다.** CI/CD, 커널 수준 샌드박스, 토큰 효율에서 앞선다. 헤드리스 터미널 운영이 IDE 프로토콜 계층의 오버헤드를 피하기 때문이다. Codex CLI의 강점은 메커니즘 층에 몰려 있다.
4. **Claude Code가 가장 가까운 경쟁자다.** 추론 품질과 훅의 프로그램 표현력에서 앞서고, Codex CLI는 토큰 효율과 기본 커널 수준 격리에서 앞선다. 순위가 아니라 트레이드오프이며, 같은 작업을 두 도구에서 돌려 토큰 수를 비교하는 것이 정직한 평가다.
5. **IDE 에이전트는 대화형 작업에 강하다.** Cursor류는 시각적 diff 리뷰와 작업 흐름의 연속성에서 앞선다. GitHub Copilot은 맡기고 자리를 뜨는 비동기 모델과 작업별 모델 선택이 특징이다. 둘 다 같은 편집에 헤드리스 에이전트보다 토큰을 더 쓴다.
6. **수렴 계층이 부담을 낮춘다.** AGENTS.md, Agent Skills, MCP가 도구를 가로질러 쓰이므로 멀티 도구 스택은 만들기도 바꾸기도 싸다. 종속은 가장 아팠을 계층에서 약해지고 있다.
7. **충성보다 멀티 도구 패턴이 낫다.** 도구마다 구조적 강점에 맡긴다. 한 에이전트가 만들고 다른 에이전트가 감사하는 이중 도구 리뷰는 단일 모델이 놓치는 버그를 잡는다. 한 도구 안에서 적대적 리뷰가 통하는 것과 같은 이유다.
8. **샌드박스가 가장 날카로운 차별 요소다.** 시스템 호출 계층의 커널 수준 강제는, 에이전트가 자신에게 강제하고 프롬프트 인젝션으로 우회될 수 있는 애플리케이션 계층 정책과 범주가 다르다. 도구는 가장 약한 경계로 분류한다.
9. **트레이드오프가 비용을 정당화할 때만 바꾼다.** 학습 곡선, 설정 이전, 팀 정렬은 실제 비용이다. 현재 도구가 사용 사례의 80퍼센트를 처리하면 스택을 갈아엎지 말고 남은 20퍼센트를 최적화한다.
10. **도구를 바꾸는 일은 대부분 기계적이다.** AGENTS.md, 스킬, MCP가 에이전트 사이를 오가므로 Claude Code에서 Codex CLI로 옮기는 일은 다섯 요소(지침, 스킬, 서브에이전트, 훅, 설정)의 설정 작업이다. externalAgentConfig의 detect/import API와 Microsoft APM 같은 패키지 매니저가 나머지를 자동화한다.

## 2. 한눈에 보는 연결

- 1~2번은 도구 선택의 기준과 판단 틀 문서에 해당한다.
- 3~5번은 CLI 에이전트 비교, IDE 에이전트와 에디터 문서에 해당한다.
- 6번은 수렴 계층 문서에, 7번과 9번은 멀티 도구 패턴 문서에 해당한다.
- 8번은 샌드박스 지형 문서에 해당한다.
- 10번은 Claude Code에서 옮기기와 이식 도구 문서에 해당한다.
