# 에이전트 간 이식 도구와 도구 종료 대응

한 도구에서 다른 도구로 옮기는 일은 Claude Code와 Codex CLI 사이만의 문제가 아니다. 대부분의 팀은 설정, 스킬, MCP 서버, 세션 기록이 여러 하니스에 흩어져 있다. 이 문서는 그 파편화를 줄여 주는 두 가지, 즉 Codex CLI의 감지/가져오기 API와 Microsoft의 APM을 설명하고, Gemini CLI 종료 소식에 대응하는 방법도 정리한다.

---

## 1. 감지/가져오기 API

Codex CLI는 파편화에 대한 일급 해법으로 externalAgentConfig/detect와 externalAgentConfig/import라는 JSON-RPC API를 제공한다. 비동기 백그라운드 세션 가져오기가 이를 받친다.

**externalAgentConfig/detect**는 다른 에이전트 하니스에서 가져올 수 있는 산출물을 파일 시스템에서 찾는다. 입력으로 includeHome(홈 디렉터리의 전역 설정까지 스캔할지)과 cwds(스캔할 프로젝트 디렉터리들)를 받고, 유형이 붙은 migrationItems를 돌려준다.

| 항목 유형 | 포함 범위 |
|---|---|
| AGENTS_MD | AGENTS.md로 대응시킬 수 있는 CLAUDE.md, .cursorrules 같은 지침 파일 |
| CONFIG | 전역 설정(모델 기본값, 승인 모드, 제공사 키) |
| SKILLS | SKILL.md가 든 스킬 디렉터리 |
| PLUGINS | 마켓플레이스 플러그인 참조 |
| MCP_SERVER_CONFIG | MCP 서버 연결 정의 |

감지는 멱등적이고 점진적이다. AGENTS.md가 이미 있고 비어 있지 않으면 AGENTS_MD 항목은 건너뛰며, 스킬 가져오기는 기존 스킬 디렉터리를 덮어쓰지 않는다.

**externalAgentConfig/import**는 선택한 마이그레이션 항목을 적용한다. 호출 즉시 돌아오고 실제 처리는 비동기로 한다. 끝나면 externalAgentConfig/import/completed 알림을 보낸다. 가장 무거운 작업인 세션 기록 가져오기는 중복을 막으려고 직렬 처리하며 전부 백그라운드에서 돈다.

원서의 표 26-2는 주요 출처 에이전트별 파일 대응을 보여 준다. 새로 정리하면 다음과 같다.

| 산출물 | Claude Code | Cursor | Codex CLI 대상 |
|---|---|---|---|
| 에이전트 지침 | CLAUDE.md | .cursor/rules/*.mdc | AGENTS.md |
| 스킬 | .claude/skills/<n>/SKILL.md | .cursor/skills/ | .agents/skills/ |
| MCP 서버 | .mcp.json | .cursor/mcp.json | config.toml의 [mcp_servers] |
| 전역 설정 | ~/.claude/settings.json | ~/.cursor/settings.json | ~/.codex/config.toml |

여러 에이전트를 병행해서 쓰는 팀에는 일회성 이전보다 동기화 방식이 낫다. 기준이 되는 단일 파일(보통 AGENTS.md)을 두고, 도구별 변형 파일은 빌드 스크립트로 생성한다.

## 2. Microsoft APM

Microsoft의 Agent Package Manager(APM)는 MIT 라이선스 오픈소스로, 개별 도구 위에 놓이는 설정 관리 계층을 도입한다. 하나의 매니페스트 파일로 GitHub Copilot, Claude Code, Cursor, OpenCode, Codex CLI, Gemini CLI, Windsurf, Kiro까지 여덟 가지 코딩 에이전트를 지원한다.

APM의 apm.yml은 Node 프로젝트의 package.json과 같은 역할을 한다. 에이전트에게 필요한 모든 것을 선언적으로 적는 명세다.

```yaml
name: subscriptions-api
version: 1.0.0
dependencies:
  apm:
    - acme/agent-skills/skills/migration-auditor
    - acme/agent-skills/plugins/release-notes
  mcp:
    - name: io.github.github/github-mcp-server
      transport: http
```

apm install을 실행하면 어떤 git 호스트에서든 의존성을 해석해 에이전트별로 올바른 위치에 배치한다. apm.lock.yaml이 해석된 출처와 내용 해시를 고정해서 결정적 재현을 보장한다. 컴파일 대상 이름은 APM README에 문서화되어 있다.

Codex CLI 팀에게 APM의 현재 가치는 세 가지다.

- 여러 저장소에 걸친 AGENTS.md 내용 표준화(APM은 전이적 지침 의존성까지 해석한다)
- 스킬 배포
- Codex CLI와 Claude Code 또는 Copilot을 함께 쓰는 팀의 에이전트 간 일관성

보안 기능도 있다. 설치 중 콘텐츠를 스캔해서 프롬프트 인젝션에 쓰이는 숨은 유니코드 문자를 막고, 내용 해시로 락파일 무결성을 지키며, apm audit로 드리프트(설정이 기준에서 어긋난 것)를 감지한다.

엔터프라이즈 팀을 위해 apm-policy.yml은 에이전트 설정에 조직 제약을 강제한다. 상속 모델은 조이기만 하는 방식이다. 엔터프라이즈 정책이 가장 엄격하고 저장소 정책은 그보다 더 좁히기만 할 수 있다. 이것은 Codex CLI의 requirements.toml 강제와 서로 보완한다. APM은 설정 공급망을 통제하고, 권한 프로필은 런타임 샌드박스를 통제한다.

한 가지 주의할 점이 있다. Codex CLI는 streamable HTTP로 원격 MCP 서버를 지원한다(서버 url과 bearer 토큰 또는 OAuth 인증으로 설정). 그런데 일부 에이전트 간 패키지 매니저는 아직 지원하지 않는다는 낡은 가정을 갖고 있어서 transport: http 의존성에 대해 Codex 대상을 건너뛸 수 있다. 이 격차는 줄어드는 중이므로 쓰는 패키지 매니저의 릴리스 노트를 확인한다.

## 3. Gemini CLI 종료

구글은 I/O 2026에서 Gemini CLI를 2026년 6월 18일에 종료하고 Antigravity CLI로 대체한다고 발표했다(원서 각주의 공지 날짜는 2026년 5월 19일이다). 현재 Gemini CLI를 쓰는 팀은 기한 전에 설정을 Antigravity CLI나 Codex CLI로 옮겨야 한다. 대응 관계는 단순하다.

| Gemini CLI | Codex CLI |
|---|---|
| .gemini/ 설정 | ~/.codex/config.toml |
| .gemini/agents/의 커스텀 에이전트 YAML | .codex/agents/의 TOML 파일 |
| @agent 호출 | /agent |

MCP 서버 설정은 프로토콜이 호환되므로 설정 파일만 옮기면 된다.

## 4. 이 문서에서 기억할 것

- detect는 다른 하니스의 지침, 설정, 스킬, 플러그인, MCP 설정을 찾고 import가 비동기로 가져온다. 이미 있는 AGENTS.md나 스킬은 덮어쓰지 않는다.
- 여러 도구를 병행한다면 AGENTS.md를 기준으로 삼고 변형 파일을 생성하는 동기화가 낫다.
- APM은 apm.yml과 락파일로 설정 공급망을 관리하며, 정책은 조이는 방향으로만 상속된다.
- Gemini CLI는 2026년 6월 18일에 종료되므로 그 전에 이전해야 한다.
