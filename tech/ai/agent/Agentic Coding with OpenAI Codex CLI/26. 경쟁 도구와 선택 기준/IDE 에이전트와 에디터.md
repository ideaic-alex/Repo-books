# IDE 에이전트와 에디터

IDE 에이전트는 AI를 에디터 안에 직접 넣은 도구다. 이 문서는 대표 주자인 Cursor와 GitHub Copilot의 성격, 토큰 비용이라는 약점, 그리고 에디터가 여러 에이전트를 한꺼번에 띄우는 화면으로 바뀌고 있는 흐름을 설명한다. 마지막에는 Codex CLI 사용자가 에디터로 옮겨 갈 때 설정이 그대로 이어지는 이유도 다룬다.

---

## 1. 작업 흐름이 끊기지 않는다는 장점

IDE 에이전트의 가장 큰 장점은 작업 흐름의 연속성이다. 제안된 변경을 시각적 diff로 보고, 그 자리에서 수락하거나 거절하며, 편집하던 맥락을 떠나지 않는다.

**Cursor**는 이 범주를 가장 잘 해낸 예이자 지배적인 IDE 에이전트다. 시장 위치가 마케팅이 아니라 사용 경험의 질에서 나온다고 원서는 평가한다.

- 변경이 수락되기 전에 시각적 diff가 먼저 나온다.
- 에디터 확장 생태계가 그대로 유지된다.
- 터미널로 전환할 필요가 없다.

에이전트가 코드를 건드리기 전에 정확히 무엇을 하려는지 눈으로 확인하고 싶고 작업 방식이 에디터 중심이라면 압도적으로 유리하다.

## 2. 트레이드오프: 토큰 비용

대가는 토큰이다. 풍부한 시각적 스캐폴딩, 즉 에디터 상태, 열려 있는 파일의 컨텍스트, 인라인 diff 스트림이 같은 작업에도 헤드리스 에이전트보다 토큰을 더 쓴다. 독립 테스트에서 CLI 에이전트가 같은 일에 IDE 에이전트보다 몇 배 적은 토큰을 쓰는 것으로 측정되었다. 이 배수는 작업에 따라 달라지므로 팀 규모에서는 자기 대시보드로 확인하라는 것이 원서의 단서다.

또 하나, Cursor는 CLI 에이전트가 아니다. CI/CD 파이프라인, 스크립트 자동화, 헤드리스 운영 같은 터미널 중심 흐름에는 구조상 맞지 않는다. 인라인 diff를 매번 보고 싶은 사람에게 헤드리스 에이전트가 맞지 않는 것과 똑같다.

## 3. GitHub Copilot

GitHub Copilot은 시장에서 인지도가 가장 높다. 자동 완성으로 시작했지만 지금은 대화형, 비동기, CLI 모드를 갖춘 여러 구성 요소의 플랫폼이다. 두 가지가 특징이다.

**비동기 코딩 에이전트.** 이슈를 배정하면 호스팅된 CI 샌드박스가 뜨고, 드래프트 풀 리퀘스트에 커밋을 올리고, 끝나면 리뷰를 요청한다. 자리에 없어도 된다. 이렇게 맡기고 잊는 모델은 Codex CLI나 Claude Code가 쓰는 대화형 루프와 구조가 다르며, 이슈 분류와 단순한 버그 수정에 잘 맞는다.

**모델 유연성.** 작업마다 여러 제공사의 모델 중에서 고를 수 있다. 한 제공사만 쓰는 도구에는 없는 장점이다.

약점은 순수 에이전트 능력이 최전선 CLI 에이전트에 못 미친다는 점이다. 강점은 생태계 통합이며, 이미 GitHub를 쓰는 팀이라면 에이전트 기능을 추가하는 데 드는 추가 비용이 거의 없다.

## 4. 에디터가 멀티 에이전트의 화면이 된다

IDE 층에서 더 흥미로운 변화는 개별 에이전트가 아니라 에디터가 여러 에이전트를 한꺼번에 받아 주는 자리가 되는 것이다. 일부 에디터는 한 창에서 여러 에이전트를 대등하게 돌린다. 에이전트마다 자기 스레드에서 코드베이스의 다른 부분을 맡고, 열린 에이전트-에디터 프로토콜로 조율한다. 그래서 호환되는 에이전트라면 Codex CLI를 포함해 모두 일급 시민이 된다.

이런 에디터 안에서 Codex CLI를 돌리면 순수 터미널에서는 얻기 어려운 세 가지를 얻는다.

1. **공유 파일 컨텍스트**: 에디터가 작업 디렉터리와 열린 파일을 알아서 넘겨 주므로 @ 멘션을 일일이 달 필요가 없다.
2. **병렬 조율**: 여러 Codex 스레드를 다른 에이전트와 나란히 돌린다.
3. **통합 승인 화면**: 도구 실행이 터미널 창 하나를 놓고 다투지 않고 에디터 안의 대화형 승인으로 나타난다.

같은 수렴 현상이 주류 에디터에도 보인다. 일부 에디터는 Codex, Claude, Copilot을 한 사이드바에 대등한 에이전트로 보여 주고, 로컬, 백그라운드, 클라우드 실행 모드를 제공한다.

## 5. 설정이 그대로 이어진다

Codex CLI 사용자에게 실질적으로 좋은 점은 설정 이식성이다. 에디터 통합은 같은 엔진을 감싸고 같은 ~/.codex/config.toml을 읽는다. 그래서 이미 만들어 둔 프로필, 모델 선호, 권한 설정이 그대로 따라온다. CLI 설정에 쏟은 투자가 에디터 중심 작업 흐름으로 옮겨도 버려지지 않는다. 같은 하니스를 다른 표면으로 보여 줄 뿐이다.

## 6. 이 문서에서 기억할 것

- IDE 에이전트의 강점은 시각적 diff와 에디터를 떠나지 않는 흐름이고, 약점은 토큰 비용이다.
- Cursor는 에디터 중심 작업에 강하고, CI나 스크립트 자동화에는 맞지 않는다.
- Copilot은 맡기고 자리를 뜨는 비동기 모델과 모델 선택이 특징이다. 순수 에이전트 능력은 최전선 CLI에 못 미친다.
- 에디터는 여러 에이전트를 올리는 화면이 되는 중이며, Codex CLI 설정은 그대로 이어진다.
