# 경쟁 도구와 선택 기준

코딩 에이전트 시장은 석 달마다 판이 바뀌므로, 이 장은 제품 이름보다 구조적 범주로 도구를 고르는 방법을 가르친다. 앞 장에서 본 하니스 관점을 구매자의 눈으로 적용해서, 터미널(CLI) 에이전트와 IDE 에이전트가 각각 무엇에 최적화되어 있는지, Codex CLI가 이기는 자리와 그렇지 않은 자리가 어디인지 짚는다.

도구를 바꾸는 방법도 다룬다. AGENTS.md, 스킬, MCP가 도구 사이를 오가는 덕분에 Claude Code에서 Codex CLI로 옮기는 일은 대부분 설정 이전이다. 마지막에는 여러 도구를 작업 성격에 따라 나눠 쓰는 패턴과, 도구를 가르는 가장 날카로운 기준인 샌드박스를 정리한다.

---

## 1. 핵심 요점

- 시장은 CLI 대 IDE라는 축으로 갈리고, 각각 사람 없이 돌리는 실행과 시각적 diff에 최적화되어 있다. 제품 이름은 범주의 대표 예일 뿐이다.
- 비슷한 모델을 쓰는 도구들의 차이는 하니스(인터페이스, 메커니즘, 멀티 에이전트 확장의 3층)에서 난다.
- Codex CLI는 커널 수준 샌드박스, 토큰 효율, CI/CD 친화성에서 강하고, Claude Code는 추론 품질과 훅의 표현력에서 강하다. 둘은 순위가 아니라 트레이드오프다.
- IDE 에이전트는 시각적 diff와 에디터 안 작업 흐름이 강점이고 토큰을 더 쓴다. Copilot의 맡기고 자리를 뜨는 비동기 모델은 구조가 다르다.
- AGENTS.md, Agent Skills, MCP가 도구를 가로질러 쓰여서 종속이 줄었고, Claude Code에서 Codex CLI로 옮기는 일은 다섯 요소를 옮기는 기계적 작업이다.
- 한 에이전트가 만들고 다른 에이전트가 검토하는 이중 도구 리뷰와 작업별 도구 분담이 단일 도구 충성보다 낫다.
- 도구는 가장 약하게 강제되는 경계로 분류하고, 샌드박스 수준은 벤치마크가 아니라 위협 모델로 정한다.
- 현재 도구가 사용 사례의 80퍼센트를 잘 처리하면 갈아타지 말고 나머지 20퍼센트를 최적화한다.
