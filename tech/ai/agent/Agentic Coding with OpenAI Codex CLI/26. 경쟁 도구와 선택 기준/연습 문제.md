# 연습 문제

26장의 연습 문제 다섯 개를 문제 취지와 풀이 방향으로 풀어 쓴 정리다. 각 문제는 앞선 문서의 내용을 직접 손으로 해 보도록 설계되어 있다.

---

## 1. 문제 26-1: 한 작업을 두 도구에서 돌려 보기

현재 프로젝트에서 범위가 분명한 작업을 하나 고른다. 원서의 예는 사용자 등록 엔드포인트에 입력 검증을 추가하는 일이다. 이 작업을 Codex CLI와 경쟁 도구 하나에서 각각 돌린다. 토큰 수, 승인 프롬프트가 뜬 횟수, 결과물의 품질(컴파일이 되는지, 경계 사례를 다루는지), 실제 걸린 시간을 기록한다. 마지막으로 그 작업 유형에는 어느 도구를 고를지, 이유와 함께 문서로 남긴다.

풀이 방향: 같은 프롬프트와 같은 시작 상태(같은 커밋)에서 출발해야 비교가 공정하다. 표 하나에 네 가지 지표를 도구별로 적고, 토큰 수는 도구가 제공하는 사용량 표시로 확인한다. 결론은 "무엇이 더 낫다"가 아니라 "이 작업 유형에는 이것"으로 쓴다.

## 2. 문제 26-2: 내 작업을 판단표에 대응시키기

AI 코딩 도구로 가장 자주 하는 작업 유형 다섯 가지를 적는다. 각각에 표 26-1을 적용해서 어울리는 구조적 범주를 찾는다. 다섯 개가 모두 같은 범주라면 멀티 도구 구성은 필요 없을 가능성이 높다. 답이 갈린다면 층층이 쌓은 워크플로가 어떤 모습일지 스케치한다.

풀이 방향: 각 작업에 "샌드박스가 필수인가, 시각적 diff가 필요한가, 맡기고 자리를 뜨는가, 예산이 제약인가" 같은 질문을 붙이면 범주가 쉽게 갈린다. 갈린 결과를 IDE, CLI, 비동기 에이전트 세 칸에 배치해 보면 스케치가 된다.

## 3. 문제 26-3: 멀티 도구 워크플로 설계

팀을 위해 IDE 에이전트, CLI 에이전트, 클라우드나 비동기 에이전트를 각각 어떤 작업 범주에 배정할지 워크플로를 설계한다. 배정마다 근거를 적고, 수렴 계층을 통해 도구들이 공유할 AGENTS.md, 스킬, MCP 설정이 무엇인지 명시한다.

풀이 방향: 배정표(작업 범주, 도구, 이유)를 만들고, 공유 대상은 파일 경로까지 적는다. 예를 들어 지침은 저장소 루트의 AGENTS.md, 스킬은 .agents/skills/, MCP는 서버 설정 한 벌로 정한다. 이중 도구 리뷰를 넣을지도 함께 결정한다.

## 4. 문제 26-4: 요구 사항 기준 샌드박스 점검

세 가지 도구의 샌드박스 모델을 조직의 보안 요구 사항에 견주어 평가한다. 비교 매트릭스를 만들고, 도구마다 가장 약하게 강제되는 경계로 분류하고, 보안 기준선을 충족하는 도구가 무엇인지 가려낸다.

풀이 방향: 행에는 도구, 열에는 셸 실행, 파일 읽기와 쓰기, 네트워크 같은 경계를 둔다. 칸마다 커널, 컨테이너, VM, 애플리케이션 계층, 없음 중 어디에 속하는지 적고, 가장 약한 칸이 그 도구의 등급이다. 기준선은 위협 모델(16장)에서 끌어낸다.

## 5. 문제 26-5: 워크플로를 Codex CLI로 옮기기

Claude Code(또는 다른 에이전트)로 돌아가는 프로젝트가 있다면 다섯 요소 마이그레이션 지도를 따라 옮긴다.

- CLAUDE.md의 공통 내용으로 AGENTS.md를 만든다.
- 스킬을 .agents/skills/로 복사한다.
- 서브에이전트를 TOML로 다시 쓴다.
- 쓰던 훅을 옮긴다.
- 이름 붙은 프로필을 두 개 이상 넣은 ~/.codex/config.toml을 만든다.

마지막으로 codex --profile strict "summarize the codebase"가 파일을 수정하지 않고 성공적으로 실행되는지 확인한다.

풀이 방향: 한 번에 하나씩 옮기고 단계마다 확인한다. strict 프로필은 sandbox_mode를 workspace-write 등으로 두되, 요약 요청이 파일을 바꾸지 않았는지는 git status로 검증한다. 훅은 Bash는 matcher를 Bash로, 파일 편집은 apply_patch로 옮기고, 서브에이전트를 쓴다면 features.multi_agent = true도 잊지 않는다.
