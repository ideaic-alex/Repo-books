# 연습 문제

21장 끝에 있는 연습 문제 다섯 개를 정리한다. 문제 취지를 풀어 쓰고 풀이 방향을 한두 문장 덧붙였다.

---

## 1. 실제 코드베이스에서 계획 세션 돌리기

조직 안의 JavaScript나 TypeScript 프로젝트 중 클래스 컴포넌트가 있거나, 오래된 API를 쓰거나, 범위가 분명한 마이그레이션 거리가 있는 것을 고른다. Codex CLI를 읽기 전용으로 열고 파일 목록, 의존성 그래프, 복잡도 등급, 배치 순서를 요구하는 프롬프트를 던진다. 결과에서 에이전트의 분석이 직관과 맞는 곳과 의외인 곳을 비교하고, 만들어진 MIGRATION_PLAN.md를 커밋한다.

풀이 방향: 의외인 곳이 목록에서 빠진 파일이나 잘못 포함된 생성 파일이라면 프롬프트의 범위 지정이 약했다는 뜻이다. 이 차이를 기록해 두면 다음 계획 세션의 프롬프트를 고칠 근거가 된다.

## 2. 배치 검증 루프 구현하기

이 장의 migrate-batch.sh를 자기 프로젝트의 테스트 실행기와 커밋 관례에 맞게 고친다. 계획에서 복잡도가 가장 낮은 배치에 돌려 본다. 일부러 오류를 넣어(함수 이름을 바꿔 테스트를 깨뜨린다) 스크립트가 커밋하지 않고 롤백하는지 확인한다.

풀이 방향: 테스트 명령, 커밋 메시지, 롤백 방식(`git checkout -- .` 또는 `git stash`)을 프로젝트에 맞게 바꾼다. 시작 전에 기준선이 초록인지부터 확인해야 롤백 동작을 제대로 판단할 수 있다.

## 3. 복잡도 등급 분석 설계하기

마이그레이션을 돌리기 전에 무엇을 옮기는지 알아야 한다. 코드베이스에 맞는 마이그레이션 유형(API 버전 업그레이드, 의존성 교체, 코딩 패턴 현대화 등)을 하나 골라, 읽기 전용 Codex CLI 프롬프트로 복잡도 등급 평가를 만든다. 파일을 최소 세 등급(단순, 보통, 복잡)으로 나누고 각 등급의 기준을 명시하게 한다. 등급마다 파일 다섯 개를 직접 검토해서 분류의 품질을 평가한다.

풀이 방향: 프롬프트에 등급 기준을 수치나 관찰 가능한 특징(줄 수, 의존 개수, 테스트 유무 등)으로 적게 하면 직접 검토하기 쉽다. 틀리게 분류된 파일이 있으면 기준 표현을 고쳐 다시 돌린다.

## 4. 마이그레이션 배치 롤백 검증하기

이 장의 테스트 실패 시 롤백 패턴을 배치 하나에 구현한다. 배치 안의 테스트 하나를 일부러 깨뜨려, 스크립트가 일부만 커밋하지 않고 배치 전체를 롤백하는지 확인한다. 그다음 테스트를 고치고 다시 돌려 배치가 정상 커밋되는지 본다. 롤백 패턴이 막아 주는 실패 양상이 구체적으로 무엇인지 문서로 남긴다.

풀이 방향: 롤백이 없으면 깨진 변경이 일부 파일에 남은 채 다음 배치가 쌓여서 실패 원인을 특정할 수 없게 된다. 이 점을 기록하면 된다.

## 5. 레거시 고고학 수행하기

낯설거나 오래된 모듈 하나를 고른다. `-s read-only`로 Codex CLI에게 현대화 보고서를 만들게 한다. 쉬운 말로 된 동작 설명, 모듈별 동작, 데이터 모델, 그리고 날짜, 반올림, 인코딩, 정렬, 전역 상태 버릇을 담은 위험 목록이 들어가야 한다. 가장 큰 위험 세 개를 제약으로 AGENTS.md에 추가한다. 이 모듈을 재작성한다면 돌릴 층 검증(동작 일치, 건전성, 관용구, 보안, 성능)도 스케치해 본다.

풀이 방향: 위험 세 개는 위험 목록에서 파일과 줄 번호까지 확인된 것을 고르고, 제약은 "~는 바꾸지 않는다"처럼 에이전트가 지킬 수 있는 문장으로 쓴다. 층 검증은 층마다 확인 방법 한 줄만 적어도 충분하다.
