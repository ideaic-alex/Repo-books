# 코드베이스 마이그레이션과 현대화

마이그레이션은 사람이 손으로 하면 지루하고 실수하기 쉬운 일이다. 하지만 에이전트는 지치지 않고 규칙을 일관되게 적용하므로 Codex CLI가 가장 잘 맞는 영역 중 하나다. 이 장은 마이그레이션이 왜 효과가 큰 작업인지, 레거시를 건드리기 전에 어떻게 파악하는지, 에이전트가 길을 벗어나지 않게 마이그레이션을 어떻게 구성하는지, 결과를 어떻게 검증하는지를 다룬다.

범위는 배치 하나짜리 작업부터 모놀리스 분해, 언어 전체를 바꾸는 재작성까지 이어진다. 원서의 그림 21.1(마이그레이션 패턴 결정 트리)도 함께 실었다.

---

## 1. 핵심 요점

- 마이그레이션은 기계적이고, 범위가 분명하고, 테스트할 수 있고, 병렬화할 수 있어서 에이전트와 잘 맞는다.
- 바꾸기 전에 읽기 전용 탐색으로 현대화 보고서와 위험 목록을 만들고, 결과를 AGENTS.md에 남긴다.
- 읽기 전용 계획 세션으로 MIGRATION_PLAN.md를 만들어 커밋하고, 변환 규칙은 스킬로 굳힌다.
- 파일 단위, 모듈 단위, 스트랭글러 피그, 병렬 서브에이전트 중 하나를 결정 트리로 고른다.
- 이전 배치가 테스트를 통과하기 전에는 다음으로 가지 않는다. 이 관문은 셸 스크립트로 강제하고, 초록 기준선에서 시작한다.
- 모놀리스는 결합도 분석, 계약 우선 추출, 기능 플래그 라우팅으로 쪼개고 기존 통합 테스트로 검증한다.
- 큰 재작성은 직역과 재설계를 의식적으로 고르고 탈출구 예산을 정한다.
- 테스트 통과는 바닥일 뿐이므로 동작 일치, 건전성, 관용구, 보안, 성능의 층으로 검증한다.
