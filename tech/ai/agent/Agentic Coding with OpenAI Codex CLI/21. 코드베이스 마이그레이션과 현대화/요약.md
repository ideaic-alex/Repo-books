# 요약

21장의 핵심을 여덟 가지로 정리한다. 각 항목이 어느 문서에서 자세히 다뤄지는지도 함께 적었다.

---

## 1. 장의 요약 여덟 가지

1. **마이그레이션은 에이전트 실행에 잘 맞는다.** 기계적이고, 범위가 분명하고, 테스트할 수 있고, 병렬화할 수 있다. 이 성질들은 Codex CLI가 컨텍스트를 다루고 작업을 실행하는 방식과 잘 맞물린다.
2. **바꾸기 전에 이해한다.** 읽기 전용 탐색으로 현대화 보고서와 위험 목록을 만든다. 날짜, 반올림, 인코딩, 정렬, 전역 상태 같은 다른 코드가 기대고 있는 버릇을 짚고, 결과를 AGENTS.md에 남겨 세션을 넘어서도 이어지게 한다.
3. **읽기 전용 계획 세션으로 시작한다.** 에이전트가 만든 파일 목록, 의존성 그래프, 복잡도 등급, 배치 순서가 코드 변경 전에 검토하고 승인할 문서다.
4. **세 패턴이 대부분을 덮는다.** 감사 가능성이 최우선이면 파일 단위, 결합이 강한 모듈이면 모듈 단위, 기능 개발을 완전히 멈출 수 없는 큰 코드베이스면 스트랭글러 피그다.
5. **진행은 테스트로 막는다.** 이전 배치가 통과하기 전에는 다음 배치로 가지 않는다. 이 관문은 선의가 아니라 셸 스크립트에 새긴다.
6. **프레임워크 마이그레이션도 같은 패턴을 따른다.** React 클래스에서 훅으로, Python 2에서 3으로, AngularJS에서 Angular로 모두 통한다. 변환 규칙을 정의하고, 스킬로 굳히고, 전체 CI 관문으로 검증하고, 에이전트가 추측하지 않고 표시해 준 애매한 경우에만 사람의 주의를 쓴다.
7. **모놀리스 분해는 큰 규모의 스트랭글러 피그다.** 결합도 분석으로 이음새를 찾고, 구현 전에 서비스 계약을 정하고, 뒤집을 수 있는 기능 플래그 게이트웨이로 라우팅하고, 추출한 모든 엔드포인트가 모놀리스의 기존 통합 테스트를 통과하게 한다.
8. **테스트 통과가 건전한 재작성의 증명은 아니다.** 직역과 재설계를 의식적으로 고르고, unsafe나 any 같은 탈출구에 예산을 두고, 동작 일치, 타입과 메모리 건전성, 관용구, 보안과 공급망, 성능의 층으로 검증한다.

## 2. 함께 보면 좋은 장

8장(MCP)은 이 장과 이어진다. 이 장은 Codex CLI를 가장 레버리지 높은 엔지니어링 문제 중 하나에 적용했다. 8장은 Codex CLI가 MCP 엔드포인트를 쓰기도 하고 내놓기도 하는 Model Context Protocol 연결을 다룬다. 마이그레이션한 코드베이스가 의존하는 도구와 서비스와 더 풍부하게 연동하는 길이 거기 있다.
