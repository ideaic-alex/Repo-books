# 마이그레이션 계획과 변환 스킬

최악의 시작 방법은 에이전트에게 코드베이스를 가리키며 "전부 마이그레이션해"라고 하는 것이다. 에이전트는 어느 모듈이 위험한지, 어떤 테스트가 있는지, 어떤 파일이 생성물이고 어떤 파일이 손으로 쓴 것인지 모른다. 이 문서는 읽기 전용 계획 세션으로 계획서를 만들고, 변환 규칙을 스킬로 굳히는 방법을 다룬다.

---

## 1. 읽기 전용 계획 세션

먼저 읽기 전용 모드(`sandbox_mode = "read-only"`)로 계획 세션을 연다. 코드를 바꾸기 전에 에이전트가 코드베이스를 분석하게 하는 것이다. 원문의 예시는 React 클래스 컴포넌트를 훅으로 옮기는 마이그레이션이다.

```bash
codex --profile read-only "Analyze this codebase for a React class-
component-to-hooks migration. Produce a migration plan with:
1. File inventory: every file with class components, line count,
   and test coverage flag
2. Dependency graph: which components extend others, used where
3. Complexity tiers: High / Medium / Low, with your criteria
4. Proposed batch order, starting with leaf nodes
5. Risk register: files where the transformation is ambiguous"
```

(원문 프롬프트를 줄여 옮겼다.)

프롬프트 하나로 코드가 바뀌기 전에 검토할 수 있는 문서가 나온다. 이 문서는 어색한 경우를 버그가 되기 전에 드러낸다. getSnapshotBeforeUpdate를 쓰는 클래스 컴포넌트나, 호환되지 않는 API를 가진 서드파티 라이브러리를 직접 건드리는 컴포넌트가 그런 예다.

## 2. 계획서를 저장하고 커밋한다

결과를 저장소 루트에 MIGRATION_PLAN.md로 저장하고, 변환 작업이 시작되기 전에 커밋한다. 이 파일은 범위를 정하는 공식 기록이면서, 배치가 끝날 때마다 갱신하는 진행 현황판이 된다.

계획 세션에는 에이전트의 이해도를 검증하는 효과도 있다. 목록이 컴포넌트의 절반을 놓쳤거나 생성된 파일을 포함하고 있다면, 코드가 바뀌기 전에 그 사실을 알 수 있다.

## 3. 변환 규칙을 스킬로 만든다

계획이 마음에 들면 변환 규칙을 스킬로 굳힌다. 스킬은 모든 배치에서 규칙을 일관되게 유지하고, 에이전트가 열두 번째 배치에서 프롬프트를 첫 번째 배치와 다르게 해석하는 일을 막아 준다. 원문의 스킬은 다음과 같다.

```markdown
---
name: react-class-to-hooks
description: Migrate a React class component file to function components with hooks
allowed-tools:
 - Read
 - Edit
 - Bash
---
```

본문은 다음과 같다.

```markdown
Migrate the file at $ARGUMENTS from React class components to function components.
Rules:
- Convert state to useState hooks
- Convert lifecycle methods: componentDidMount -> useEffect(fn, []), componentDidUpdate -> useEffect with deps, componentWillUnmount -> useEffect cleanup
- Do NOT convert components that use getSnapshotBeforeUpdate; flag in a comment and leave unchanged
- Do NOT refactor logic unrelated to the component lifecycle
- Preserve all prop types and default props exactly
- After editing, run: npx tsc --noEmit src/$ARGUMENTS
```

(원문의 화살표와 줄바꿈을 줄여 옮겼다.)

이 스킬의 규칙에서 볼 점은 세 가지다.

- 변환할 대상(상태, 생명주기 메서드)을 구체적으로 짚는다.
- 변환하면 안 되는 경우(getSnapshotBeforeUpdate)는 건드리지 말고 표시만 하라고 명시한다.
- 관련 없는 로직을 리팩터링하지 말라고 막고, 끝에 타입 검사를 붙여 스스로 확인하게 한다.

이 파일은 `.agents/skills/react-class-to-hooks/SKILL.md`에 저장한다. 그러면 각 배치 세션은 규칙을 다시 설명하지 않고 `/react-class-to-hooks src/components/Button.tsx`처럼 호출하기만 하면 된다.
