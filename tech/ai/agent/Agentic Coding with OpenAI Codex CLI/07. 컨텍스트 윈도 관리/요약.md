# 요약

7장의 핵심을 여덟 가지로 모았다. 각 항목이 어느 문서의 내용인지도 함께 적었다.

---

## 1. 장 요약

1. 컨텍스트 비용은 이차로 늘어난다. 매 턴이 전체 기록을 다시 보내기 때문이다. 창은 비대칭으로 찬다. 토큰은 계속 들어오지만 `/compact`나 위임을 통해서만 빠져나간다. (이차 증가와 세션 이어가기)
2. resume과 fork는 컨텍스트를 보존한다. `codex resume --last`는 끊긴 세션을 이어 가고, `codex fork`는 원본을 잃지 않고 세션을 갈라낸다. 위험한 작업 전에는 fork하고, 끊긴 작업은 resume으로 계속한다. (이차 증가와 세션 이어가기)
3. `/compact`는 손실 압축이다. 파일 전체 내용과 정확한 오류 문구는 남기지 못하고, 저장하지 않은 변경은 먼저 디스크에 써야 한다. 내부적으로 Codex CLI는 2단계(세션 메모리 우선, 필요하면 서버 쪽)로 압축하고, 안정된 초반 턴의 요약을 미리 데워 둔다. PreCompact/PostCompact 훅(9장)은 경계를 넘는 상태 보존을 자동화한다. (컴팩션)
4. 서브에이전트 위임은 컨텍스트 전략이다. 토큰이 많이 드는 하위 작업은 별도 창에서 돌고 간결한 요약만 돌려주어 부모 세션을 가볍게 유지한다. (위임과 대형 코드베이스 전략)
5. Plan Mode는 계획과 구현을 분리한다. 서로 다른 컨텍스트 수명을 쓰고, 계획이 끝난 뒤 표시되는 사용률이 같은 세션에서 계속할지 새로 시작할지를 알려 준다. (위임과 대형 코드베이스 전략)
6. 프롬프트 캐싱은 입력 비용을 줄인다. GPT-5 계열에서 캐시된 입력 토큰은 표준 요금의 약 10%(90% 할인)로 청구된다. 구조화된 프롬프팅(안정된 시스템 지시, 결정적인 도구 순서, 늦춘 압축)으로 전형적인 세션에서 캐시 적중률 80~90%, 입력 비용 절감 70~80%를 얻는다. (프롬프트 캐싱)
7. 대형 코드베이스의 규율은 다음과 같다. 대상 파일만 읽기, 단계 경계마다 요약하기, 잘 관리한 AGENTS.md, 선택적인 MCP 서버 로딩이다. 좁은 스크립트 작업에는 `project_doc_max_bytes = 0`을 쓰고, 관찰과 임계값 조절에는 `/status`와 `-c model_auto_compact_token_limit=<N>`을 쓴다. (위임과 대형 코드베이스 전략)
8. 2단계 메모리 파이프라인이 지식을 세션 너머로 나른다. 추출 뒤 통합이 이어지고, 비밀 정보 정리, diff 기반 망각, 사용 빈도 기반 선택이 약 5,000토큰의 주입 예산을 최신으로 유지한다. MCP 메모리 서버는 평면 파일 모델로 부족한 곳에 의미 검색과 클라이언트 간 공유를 더한다. 개발자 간 팀 메모리는 여전히 빈틈이며, git 기반 SessionStart/Stop 훅 패턴이 네이티브 팀 메모리가 나오기 전까지 가장 현실적인 우회책이다. (세션을 넘는 메모리)

## 2. 다음 장으로

컨텍스트 윈도는 세션이 자신에 대해 아는 것이다. 다음 장은 에이전트가 그 밖의 무엇과 이야기할 수 있느냐로 넘어간다. MCP(Model Context Protocol)는 Codex CLI가 외부 도구를 쓰게 하고, 자신도 하나의 도구로 내놓게 한다. 서버를 하나 더할 때마다 새 능력과 새 컨텍스트 비용이 함께 생긴다. 이 장에서 관리법을 익힌 그 균형이, 어떤 MCP 서버가 자리를 차지할 만한지 정하는 기준이 된다.
