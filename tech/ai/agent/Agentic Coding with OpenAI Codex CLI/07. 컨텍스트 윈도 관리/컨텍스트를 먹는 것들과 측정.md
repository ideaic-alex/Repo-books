# 컨텍스트를 먹는 것들과 측정

컨텍스트를 관리하려면 토큰이 어디에 쓰이는지부터 알아야 한다. 이 문서는 컨텍스트를 차지하는 소비처와 대략의 크기, 실제 크기를 재는 방법, 그리고 시스템 프롬프트를 손보는 설정 키를 정리한다.

---

## 1. 두 종류의 소비처

컨텍스트 윈도는 두 부류가 채운다.

- 고정 접두부(static prefix): 세션 시작 때 한 번 올라가는 것들. 시스템 프롬프트, 프로젝트 문서, 도구 스키마, 훅이 주입한 컨텍스트, 영속 메모리.
- 런타임 누적분: 턴마다 쌓이는 것들. 대화 기록, 파일 읽기, 셸 출력, 서브에이전트 호출.

## 2. 소비처별 토큰 비용

아래 표는 원서의 Table 7-1 내용을 다시 정리한 것이다. GPT 계열 토크나이저 기준 어림값이라서 청구서가 아니라 계획용 가이드로 보면 된다. 모델 제공사마다 토크나이저가 다르다.

| 소비처 | 대략의 토큰 | 참고 |
|---|---|---|
| 시스템 프롬프트 | 2,000~4,000 | Codex CLI 기본값. 일부 바꿀 수 있다 |
| 프로젝트 루트 AGENTS.md | 1,000~3,000 | 세션 시작 때 한 번 로드 |
| 스킬(켜 둔 SKILL.md 하나당) | 500~4,000 | skills 설정으로 제어. 많이 켜면 금방 불어난다 |
| 생성된 메모리(memory_summary.md) | 최대 약 5,000 | 시작 때 주입. `/memories`로 켜고 끈다 |
| MCP 서버 도구 스키마 | 서버당 500~35,000 | 도구 하나에 약 150 토큰. GitHub급 큰 서버가 지배적 |
| 앱/커넥터 스키마 | 커넥터당 3,000~35,000 | 고정 소비처 중 가장 큰 경우가 많다. `include_apps_instructions = false`로 억제 |
| 훅이 주입한 컨텍스트 | 훅당 0~5,000 | SessionStart 훅이 additionalContext에 쓸 수 있다 |
| 활성 `/plan`, `/goal` 상태 | 200~2,000 | 지우기 전까지 턴을 넘어 유지 |
| 대화 기록(사용자+어시스턴트) | 한 주고받기당 500~2,000 | 계속 누적 |
| 파일 읽기(도구 결과) | KB당 약 250 | 파일 크기에 비례 |
| 셸 명령 출력 | 호출당 100~5,000 이상 | 상한이 없다. 컴파일러 출력이 클 수 있다 |
| 서브에이전트 호출 기록 | 200~600 | 호출 기록만의 크기. 결과 요약은 따로 |
| 오류 메시지와 스택 트레이스 | 200~2,000 이상 | JVM, .NET처럼 장황한 런타임은 더 크다 |
| 인라인 이미지/스크린샷 | 1,000~4,000 | 해상도와 인코딩에 따라 다르다 |

## 3. 컨텍스트를 먹지 않는 것들

먹지 않는 것도 똑같이 중요하다. 읽지 않은 파일은 비용이 0이다. 디렉터리 목록은 목록 글자만큼만 들고 파일 내용은 들지 않는다. 서브에이전트 세션은 자기만의 컨텍스트 윈도에서 돌기 때문에 부모에는 위임 호출 기록과 돌려받은 요약만 나타난다. 이 비대칭이 "위임을 컨텍스트 관리 수단으로 쓴다"는 발상의 바탕이다.

## 4. 실제 구성 요소별로 재 보기

표의 값은 어림값이라서 진짜 분해가 필요하면 `codex debug prompt-input "hello"`를 쓴다. 모델에게 보이는 프롬프트의 모든 구성 요소를 JSON으로 출력한다. 시스템·개발자 메시지, 도구 정의, 합쳐진 AGENTS.md, 훅이 넣은 컨텍스트가 모두 들어 있다.

이 JSON을 작은 Python 스크립트에 파이프해서 항목별로 토큰을 세면 된다. GPT-5 계열은 `o200k_base` 인코딩을 쓰므로 모델 이름 대신 이 인코딩을 직접 지정한다. 핵심 부분은 이렇다.

```python
import sys, json, tiktoken
enc = tiktoken.get_encoding("o200k_base")
total = 0
for i, item in enumerate(json.load(sys.stdin)):
    text = "".join(c.get("text", "") for c in item.get("content", []))
    n = len(enc.encode(text))
    total += n
    print(i, item.get("role", "?"), n, "tokens")
print("total:", total)
```

이 스크립트는 `codex debug prompt-input "hello" | python3 -c '...'` 형태로 실행한다. 기본 설정에 MCP 서버를 하나도 올리지 않은 작업 공간의 출력 예는 developer 항목 9,667토큰, user 항목 944토큰, user 항목 1토큰, 합계 10,612토큰이었다.

눈여겨볼 점은 분포가 심하게 한쪽으로 쏠려 있다는 것이다. 고정 접두부 거의 전부가 developer 항목 하나에 들어 있다. 이 항목이 시스템 프롬프트, 프로젝트 문서, 스킬, 권한 안내를 한데 조립하기 때문이다. 공간을 확보하고 싶으면 이 항목을 공략해야 한다. 빈 작업 공간에서 한 번 재고, 설정 키 하나를 켜거나 끈 뒤 다시 재면 어떤 키가 접두부의 어느 조각을 만드는지 분명히 보인다.

## 5. 도구 스키마가 접두부를 지배한다

대부분의 환경에서 고정 접두부의 주역은 도구 스키마다. 도구 열 개짜리 작은 MCP 서버는 약 1,500토큰이지만, 도구가 예순 개인 GitHub 클라이언트 같은 큰 서버는 세션이 시작되기도 전에 30,000~40,000토큰을 쓴다. 앱과 커넥터는 더하다. 내용이 꽉 찬 커넥터 하나가 보통 10,000~35,000토큰을 쓰고, GitHub, 캘린더, 메일, 채팅, 문서 커넥터를 갖춘 일반적인 데스크톱 설치는 스키마만으로 100,000토큰을 훌쩍 넘길 수 있다.

쓰지 않는 커넥터가 있다면 `include_apps_instructions = false`로 스키마를 억제하거나 `config.toml`에서 그 커넥터를 꺼 둔다. 필요한 것만 선택해서 올리는 일은 성능 관리이면서 동시에 컨텍스트 규율이다.

## 6. 시스템 프롬프트 바꾸기

표에서 시스템 프롬프트가 "일부 바꿀 수 있음"으로 표시된 것은, 기본값이 대부분 잘 맞지만 Codex CLI가 그 자리에 들어갈 내용을 조절하는 설정을 제공하기 때문이다. 기본 프롬프트가 내 작업에 낭비일 때(OpenAI 제품용 지시가 필요 없는 로컬 오픈소스 모델을 쓸 때 등), 또는 잘 다듬은 자체 프롬프트로 기본값을 통째로 바꾸고 싶을 때 쓴다.

Ollama로 띄운 Qwen3에 Codex CLI를 붙이는 실제 로컬 모델 프로필 예시는 다음과 같다.

```toml
# ~/.codex/local.config.toml
model = "qwen3:32b"
model_provider = "local"
model_instructions_file = "~/prompts/minimal-codex.md"
include_apps_instructions = false
include_permissions_instructions = false
```

프로필은 `config.toml` 안의 `[profiles.<name>]` 표가 아니라 최상위 키를 가진 별도 파일이다. `codex --profile local`을 실행하면 `~/.codex/config.toml`을 먼저 읽고 그 위에 `~/.codex/local.config.toml`을 덮어쓴다. 모든 세션이 공유할 기본 키는 `config.toml`에 둔다.

여기서 일하는 키는 네 가지이고, 같은 표면에 속하는 관련 설정이 하나 더 있다.

1. `model_instructions_file`: 기본 모델 지시문을 통째로 대체할 Markdown 파일을 가리킨다. 시스템 프롬프트가 기본과 전혀 달라야 하는 비OpenAI 백엔드를 쓰거나, 공들여 다듬은 최소 프롬프트를 전역에 적용하고 싶을 때 쓴다.
2. `developer_instructions`: 기본값을 대체하지 않고 앞쪽에 덧붙이는 추가 지침 문자열이다. 기본 동작과 나란히 두고 싶은 프로젝트 전반 규칙 한두 개에 알맞다.
3. `include_apps_instructions`, `include_permissions_instructions`: 기본 프롬프트의 하위 구간을 빼는 불리언이다. 앱을 안 쓰거나 기본 흐름 밖에서 권한을 설정했다면 그 구간은 죽은 무게다.
4. `personality`(none, friendly, pragmatic): 기본 프롬프트의 소통 스타일 블록을 바꾼다. 컨텍스트 예산을 줄이는 키는 아니지만 같은 표면이라 알아 둘 만하다.

위 예시의 네 키는 기본 지시문을 다듬은 최소 프롬프트로 바꾸고, 안 쓰는 두 구간을 떨어낸다. AGENTS.md도 "프롬프트 앞에서 Codex가 읽는 모든 것"의 일부인데, 이 키들은 AGENTS.md보다 한 층 위에서 프로젝트 문서가 아니라 시스템 프롬프트 자체에 작용한다.

참고로 `include_apps_instructions`와 `include_permissions_instructions`는 Codex CLI가 받아들이는 것을 실제 동작하는 설정으로 확인했지만, 공개 설정 레퍼런스에는 아직 올라 있지 않다. 의지하기 전에 최신 문서로 확인해야 한다.
