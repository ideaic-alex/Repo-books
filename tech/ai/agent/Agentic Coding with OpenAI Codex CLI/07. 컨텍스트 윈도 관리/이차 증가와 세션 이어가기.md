# 이차 증가와 세션 이어가기

컨텍스트 윈도(context window)는 지시문, 대화 기록, 도구 결과, 코드가 함께 쓰는 고정 크기의 메모리다. 앞 장에서 다룬 모델 선택이나 추론 강도(reasoning effort)를 아무리 조정해도 이 한계는 달라지지 않는다. 파일을 읽을 때마다, 도구를 부를 때마다, 오류 메시지가 찍힐 때마다 남은 공간이 줄고, 창이 가득 차면 정보를 잃거나 세션이 멈춘다.

이 문서는 컨텍스트가 왜 생각보다 빨리 차는지 설명하고, 세션을 새로 시작하지 않고 이어 가는 방법인 resume과 fork를 정리한다.

---

## 1. 이차 증가 문제

Codex CLI는 턴(turn)을 모델에 보낼 때마다 지금까지의 대화 전체를 함께 보낸다. 내 프롬프트, 에이전트의 이전 답변, 도구 호출 기록, 읽은 파일, 셸 출력이 전부 포함된다. 그래서 턴마다 프롬프트는 방금 덧붙은 분량만큼 커지고, 세션 전체에서 모델에 보낸 토큰의 누적 합은 턴 수에 대해 대략 이차(제곱)로 늘어난다.

원서가 든 어림값은 다음과 같다.

| 턴 | 그 턴의 프롬프트 | 누적 전송량 |
|---|---|---|
| 1턴 | 약 2k 토큰 | 약 2k |
| 5턴 | 약 15k 토큰 | 약 40k |
| 20턴 | 약 80k 토큰 | 약 800k |
| 50턴 | 약 250k 토큰 | 수백만 |

세션 길이가 두 배가 되면 누적 전송량은 대략 네 배가 된다. 긴 세션이 비례 이상으로 비싸지고, 컨텍스트 압박이 직선이 아니라 가속하며 커진다는 뜻이다. 다만 실제로는 자동 압축(auto-compaction)이 턴당 프롬프트를 모델의 한계 아래로 눌러 준다. 위 수치는 Codex가 막아 내려고 애쓰는 "추세"를 보여 주는 것이지, 항상 그 상태로 돌아간다는 뜻은 아니다.

세션이 느려지거나 비용이 부풀 때 사람들은 보통 지금 입력한 프롬프트를 의심한다. 그러나 진짜 원인은 지난 턴 전부가 쌓인 무게인 경우가 많다. 특히 `apply_patch` 호출이 많은 편집 위주 세션은 읽기만 하는 가벼운 탐색 세션보다 컨텍스트를 훨씬 빨리 소진한다.

## 2. 기본으로 제공되는 완화책 세 가지

1. `/compact`: 지금까지의 대화를 짧은 표현으로 요약해서 여유 공간을 만들되 작업의 맥락은 유지한다.
2. 서브에이전트 위임: 서브에이전트를 띄우면 새 컨텍스트 윈도에서 시작한다. 조율을 맡은 부모 세션은 작게 유지되고, 일꾼 서브에이전트들이 각자 컨텍스트를 쌓는다.
3. `codex fork --last`: 위험하거나 비용이 큰 단계에 들어가기 전, 깨끗한 중간 상태에서 세션을 갈라 둔다.

설계 원칙은 단순하다. 세션 하나에는 집중된 작업 하나만 맡기고, 단계가 바뀌는 지점에서 일부러 컨텍스트를 리셋한다.

## 3. 스레드 이어가기와 갈라내기

Codex CLI의 세션은 스레드(thread)다. 스레드는 UUID가 붙은 JSONL 파일에 저장되는 턴의 연속이다. 컨텍스트 압박이 심하거나 세션이 끊겼을 때는 처음부터 다시 하는 것 말고 두 가지 선택지가 있다.

### resume: 기존 스레드 다시 열기

resume은 JSONL 기록으로 상태를 복원해서 기존 스레드를 다시 연다.

```bash
codex resume              # 대화형 세션 선택기
codex resume --last       # 가장 최근 세션
codex resume <SESSION_ID> # UUID로 특정 세션
```

Ctrl+C로 실행 중에 끊었거나, 시간 초과가 났거나, 다음 날 이어서 해야 할 때 쓴다. 에이전트가 마지막 턴부터 이어 가므로 맥락을 처음부터 다시 설명할 필요가 없다.

### fork: 원본은 두고 새 스레드 만들기

fork는 기존 스레드를 바탕으로 새 스레드를 만들고 원본은 손대지 않는다.

```bash
codex fork --last         # 가장 최근 세션을 복제
codex fork <SESSION_ID>   # 특정 세션을 복제
```

활성 세션 안에서는 `/fork` 슬래시 명령이 같은 일을 한다. TUI를 떠나지 않고 현재 대화를 새 스레드로 복제한다.

fork가 어울리는 경우는 세 가지다.

- 위험한 작업을 시도하기 전: 잘못되면 fork 이전 상태로 돌아갈 수 있다.
- 두 가지 접근법을 동시에 탐색할 때.
- 부모 세션의 맥락을 잃지 않고 전문 작업을 다른 쪽에 넘길 때.

resume과 fork의 세션 선택기는 위/아래 화살표로 이동하고 Enter로 고르며, `m` 키로 정렬 기준을 생성 시각과 마지막 갱신 시각 사이에서 바꾼다.

### CI에서는 codex exec resume

`codex fork`는 갈라낸 세션을 TUI로 열기 때문에 `--json`이나 `--output-schema` 모드가 없다. 스크립트나 CI에서 쓰려면 `codex exec resume`을 쓴다. 이 명령은 세션 ID와 프롬프트를 받고, JSONL 이벤트를 표준 출력으로 내보내는 `--json`과 구조화된 출력을 위한 `--output-schema <FILE>`을 모두 지원한다.
