# 연습 문제

7장 끝에 있는 연습 문제 네 개를 자기 말로 풀어 쓰고, 풀이 방향을 한두 문장씩 덧붙였다. 모두 실제 프로젝트에서 직접 재 보는 실습이다.

---

## 1. 연습 7-1 소비처 하나의 비용 재기

평소 쓰는 프로젝트에서 Codex CLI 세션을 새로 연다. 작업 지시를 내리기 전에 `/status`로 컨텍스트 윈도 사용량의 기준값을 적어 둔다. 그다음 `config.toml`에서 MCP 서버나 커넥터 하나를 끄고 Codex CLI를 재시작한 뒤 `/status`를 다시 실행한다.

풀이 방향: 두 값의 차이가 그 소비처 하나의 비용이다. 이 차이를 바탕으로 다른 커넥터와 MCP 서버 중 접두부에서 자리를 차지할 만한 것이 무엇인지 가려낸다. 정밀한 분해가 필요하면 `codex debug prompt-input`도 쓸 수 있다.

## 2. 연습 7-2 압축 뒤에 남는 것 확인하기

사소하지 않은 작업과 관련된 소스 파일 다섯 개에서 열 개를 읽은 다음 `/compact`를 실행한다. 파일 하나의 정보를 다시 읽지 않고 쓰려고 해 본다. 모델이 기억하는 것과 새로 읽어야 하는 것을 기록한다. 이 결과는 파일을 일찍 읽을지, 쓰기 직전에 읽을지에 대해 무엇을 말해 주는지 생각한다.

풀이 방향: 요약은 파일 이름과 대략의 역할은 남기지만 내용 전체는 남기지 않는다. 그러므로 정확한 내용이 필요한 파일은 압축이 지나간 뒤 쓰기 직전에 읽는 편이 안전하다.

## 3. 연습 7-3 단일 세션과 모듈별 위임 비교

모듈 세 개 이상을 건드리는 작업을 고른다. 한 번은 단일 세션으로, 한 번은 모듈마다 서브에이전트 하나씩 써서 구현한다. `/status`로 최대 컨텍스트 사용량을 비교한다. 작업이 어느 정도 크기일 때부터 위임이 분명히 유리해지는지 찾는다.

풀이 방향: 위임에도 지시문과 요약만큼의 오버헤드가 있으니, 하위 작업이 큰 파일 서너 개 읽기, 셸 명령 대여섯 번, 오류 수정 사이클 두 번을 넘는 지점을 기준으로 판단한다. 측정한 최대 사용량 차이로 자기 작업의 분기점을 직접 확인한다.

## 4. 연습 7-4 Plan Mode로 계획과 구현 나누기

계획과 구현이 모두 필요한 작업을 고른다. 먼저 단일 세션으로 실행하면서 계획과 구현의 경계에서 컨텍스트 사용량을 기록한다. 그다음 같은 작업을 한 세션에서 Plan Mode(`/plan`)로 계획하고 구현은 새 세션에서 한다. 두 방식에서 구현 중 확보되는 여유 공간을 비교한다.

풀이 방향: 새 세션 방식에서는 계획서만 경계를 넘으므로 구현 시작 시점의 사용률이 훨씬 낮을 것이다. 계획 단계에서 Plan Mode가 보여 준 사용률이 30%였는지 70%였는지에 따라 분리의 이득이 얼마나 컸는지 해석한다.
