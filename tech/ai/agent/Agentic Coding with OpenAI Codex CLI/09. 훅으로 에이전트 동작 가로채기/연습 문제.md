# 연습 문제

9장 끝에는 세 가지 실습 과제가 있다. 각 문제의 취지를 풀어 쓰고, 풀이 방향을 한두 문장씩 덧붙인다.

---

## 1. 브랜치를 읽는 컨텍스트 주입

SessionStart 훅을 만들어 현재 git 브랜치 이름을 읽고, 거기서 Jira나 GitHub 이슈 번호를 뽑아낸다. 예를 들어 `feat/GH-1234-add-login`이라는 브랜치에서 `GH-1234`를 찾는다. 그다음 `gh issue view`를 호출해 이슈를 한 문단으로 요약해 컨텍스트에 넣는다. 이슈 번호가 있는 브랜치와 없는 브랜치 양쪽에서 시험한다.

풀이 방향: 이 장의 `inject-context.sh`를 뼈대로 삼아 정규식으로 번호를 추출한다. 번호가 없으면 `gh`를 부르지 않고 "none detected"만 출력하도록 분기한다. `gh`가 없거나 호출이 실패해도 exit 0으로 조용히 끝나게 만들면 의존성 부재 원칙도 지킨다. 출력은 한 문단으로 제한해 컨텍스트 소비를 줄인다.

## 2. 저장 시 테스트 관찰자

파일을 쓸 때마다 `pytest -q --tb=line`을 돌리고 요약 한 줄을 stdout에 쓰는 PostToolUse 훅을 구현한다. 에이전트가 파일을 쓴 직후 "지금 테스트 상태가 어때?"라고 물어서 그 요약이 컨텍스트에 실제로 들어갔는지 확인한다.

풀이 방향: 이 장의 `post-tool-test-runner.py`에서 `pytest` 옵션을 바꾸고 출력을 마지막 한 줄로 줄이면 된다. `apply_patch` 호출일 때만 실행하도록 `tool_name`을 거르고, 타임아웃을 두고 exit 0으로 끝낸다. 에이전트가 요약을 정확히 말하면 stdout 주입이 동작하는 것이다.

## 3. 전체 생애 주기 통합

SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop을 하나의 `hooks.json`에 합친다. 타임아웃은 보수적으로 잡고, 각 bash 스크립트에 `set -euo pipefail`을 넣고, `.codex/scripts/` 안의 README에 훅마다 설명을 적는다. 세션을 세 번 돌려 보고 감사 로그를 검토한다. 훅이 예상 밖의 지연을 일으킨 사례를 최소 하나 찾아내고, 어떻게 줄일지 설명한다.

풀이 방향: `/hooks` 브라우저로 다섯 이벤트가 모두 Installed인지 먼저 확인한다. 지연의 원인은 대개 매 프롬프트마다 전체 테스트를 도는 UserPromptSubmit 훅이나 느린 PostToolUse 테스트 러너다. 해결로는 타임아웃 단축, 테스트 범위 축소, 출력 길이 제한, 필요할 때만 켜기를 생각할 수 있다. 훅 스팬을 OpenTelemetry로 내보내면 지연 원인을 숫자로 찾을 수 있다.
