# 실전 패턴 모음

앞에서 본 이벤트를 조합하면 바로 쓸 수 있는 작은 레시피가 된다. 각 레시피는 `.codex/scripts/`에 스크립트 하나를 두고 서너 줄의 JSON으로 연결하면 끝날 만큼 작다. 이 문서는 린트 상태 덧붙이기, 비밀 값 검사, 중간자 공격(MITM) 탐지, 감사 로그, Slack 알림을 다룬다.

---

## 1. 프롬프트마다 스타일 검사 결과 붙이기

UserPromptSubmit에 린터를 연결하면 모델이 코드를 고치기 전에 현재 린트 상태를 항상 알고 있게 된다.

```bash
#!/usr/bin/env bash
# Append ruff output to every prompt
OUTPUT=$(ruff check . --output-format=concise 2>&1 | head -20)
if [ -n "$OUTPUT" ]; then
  echo ""
  echo "### Linter state (ruff)"
  echo "$OUTPUT"
fi
```

출력을 `head -20`으로 자르는 것에 주목한다. 린트 경고가 수백 줄이어도 컨텍스트에는 20줄만 들어간다. 린트가 깨끗하면 출력이 비어 아무것도 붙지 않는다.

## 2. 파일을 쓸 때마다 비밀 값 검사

PostToolUse로 에이전트가 파일을 쓴 직후 비밀 값을 검사한다. 도구는 gitleaks를 쓴다. 원서는 gitleaks를 하드코딩된 비밀 값(API 키, 비밀번호, 토큰)을 git 저장소에서 찾아 주는 오픈소스 SAST 도구라고 소개하며, 2026년 초 기준 GitHub 별 1만 9천 개 이상, Docker 다운로드 2천만 회라고 적는다.

```bash
#!/usr/bin/env bash
# ~/.codex/scripts/secret-scan.sh
if ! command -v gitleaks &>/dev/null; then
  exit 0
fi
OUTPUT=$(gitleaks detect --source . --no-git -q 2>&1)
if [ $? -ne 0 ]; then
  echo "### Secret scan warning"
  echo "$OUTPUT" | head -20
fi
```

gitleaks가 설치돼 있지 않으면 조용히 `exit 0`으로 빠진다. 앞 문서에서 본 "의존성이 없으면 막지 말고 물러난다"는 원칙을 그대로 적용한 것이다. 검출되면 경고를 stdout에 내보내 에이전트가 컨텍스트에서 보게 한다.

## 3. 네트워크 작업에서 MITM 탐지

보안에 민감한 환경에서는 PostToolUse 훅으로 에이전트의 네트워크 작업 중 중간자 공격을 탐지할 수 있다. 대상은 `curl`, `wget`, API 호출 같은 네트워크 관련 도구이며, SSL 인증서 체인에서 가로채기나 DNS 조작을 의심할 만한 이상을 살핀다. 예상 밖의 발급자, 짧아진 체인, SAN 불일치 같은 의심스러운 인증서를 발견하면 stderr에 경고를 쓰고 exit 2로 세션에 표시한다.

```bash
#!/usr/bin/env bash
# ~/.codex/scripts/mitm-detect.sh
TOOL_CMD="$(jq -r '.tool_input.command // empty')"
echo "$TOOL_CMD" | grep -qiE 'curl|wget|http|fetch|requests' || exit 0
HOST=$(echo "$TOOL_CMD" | perl -pe 's#.*https?://##; s#[:/ ].*##' | head -1)
[ -z "$HOST" ] && exit 0
CERT_INFO=$(echo | openssl s_client -connect "$HOST:443" -servername "$HOST" 2>/dev/null)
ISSUER=$(echo "$CERT_INFO" | openssl x509 -noout -issuer 2>/dev/null)
DEPTH=$(echo "$CERT_INFO" | grep -c "^ [0-9]")
if echo "$ISSUER" | grep -qiE 'mitmproxy|burp|charles|fiddler|zscaler'; then
  echo "Suspicious issuer for $HOST: $ISSUER" >&2; exit 2
fi
[ "$DEPTH" -lt 2 ] && { echo "Short chain for $HOST" >&2; exit 2; }
```

위 코드는 지면 때문에 원서의 경고 문구를 줄여 옮겼다. 원서는 경고 앞에 "### MITM warning" 줄을 출력한다. 동작 순서는 다음과 같다.

1. stdin JSON의 `tool_input.command`에서 실행된 명령을 꺼낸다.
2. 네트워크와 관련 없는 명령이면 바로 종료한다.
3. 명령에서 대상 호스트를 뽑는다. 못 찾으면 종료한다.
4. `openssl s_client`로 인증서 정보를 받아 발급자와 체인 깊이를 확인한다.
5. 발급자에 `mitmproxy`, `burp`, `charles`, `fiddler`, `zscaler` 같은 가로채기 도구 이름이 있거나 체인 깊이가 2 미만이면 경고하고 exit 2로 끝낸다.

이 훅은 Bash matcher를 걸어 PostToolUse에 연결하면 에이전트가 실행하는 모든 셸 명령을 검사한다. 비밀 값 검사 훅과 같이 쓰면 자격 증명 유출과 전송 계층 가로채기를 함께 막을 수 있다.

## 4. 감사 로그

한 번의 도구 호출마다 JSON 한 줄을 `~/.codex/audit.jsonl`에 덧붙이는 간단한 훅이다. 인라인 Python으로 UTC 시각(`ts`), 사용자(`user`), git 브랜치(`branch`), 현재 디렉터리(`cwd`)를 담은 JSON을 만들어 `echo "$ENTRY" >> ~/.codex/audit.jsonl`로 쌓는다. 한 줄에 한 객체를 쓰는 JSON Lines 형식이라 나중에 `jq`나 로그 도구로 다루기 쉽다.

## 5. 세션 종료 시 Slack 알림

```bash
#!/usr/bin/env bash
[ -z "$CODEX_SLACK_WEBHOOK" ] && exit 0
BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null || echo "unknown")
MSG="Codex session ended | branch: \`$BRANCH\` | user: $USER"
curl -s -X POST "$CODEX_SLACK_WEBHOOK" \
  -H 'Content-type: application/json' \
  --data "{\"text\":\"$MSG\"}" > /dev/null
```

`CODEX_SLACK_WEBHOOK`이 없으면 조용히 끝난다. Stop 이벤트에 연결해서 쓴다.

## 6. 패턴과 이벤트 짝짓기

| 패턴 | 알맞은 이벤트 | 막는가 |
|---|---|---|
| 린트 상태 덧붙이기 | UserPromptSubmit | 아니오 (정보 제공) |
| 비밀 값 검사 | PostToolUse | 아니오 (경고를 컨텍스트로) |
| MITM 탐지 | PostToolUse (Bash matcher) | exit 2로 세션에 표시 |
| 감사 로그 | PostToolUse 등 | 아니오 |
| Slack 알림 | Stop | 아니오 |
