# 훅 시스템 개요

훅(hook)은 에이전트가 일하는 도중 정해진 지점에 끼어들어 실행되는 셸 명령 콜백이다. MCP가 에이전트의 손을 바깥으로 뻗게 해 준다면, 훅은 에이전트 자신의 생애 주기(세션이 열리고 닫히기까지의 흐름)를 제어하게 해 준다. 세션 시작부터 서브에이전트 종료까지 열 군데에서 스크립트를 돌려 컨텍스트를 넣고, 정책을 강제하고, 동작을 기록하고, 알림을 보낼 수 있다. 이 모든 일을 AGENTS.md는 한 줄도 고치지 않고 할 수 있다.

이 문서는 훅이 무엇이고 어떻게 설정하는지, 열 가지 이벤트가 각각 어떤 성격인지를 먼저 훑는다. 이벤트별 상세 동작과 예제는 뒤따르는 문서에서 다룬다.

---

## 1. 이 장의 학습 목표

이 장을 마치면 다음을 할 수 있어야 한다.

- `.codex/hooks.json`에 열 가지 훅 이벤트를 모두 설정한다.
- 컨텍스트 주입, 프롬프트 정책 강제, 테스트 실행, 비밀 값 검사를 하는 셸·Python 훅 스크립트를 쓴다.
- 훅의 타임아웃, 오류 처리, 동기 실행이 갖는 장단점을 따져 판단한다.

## 2. 훅의 기본 성질

훅은 동기(synchronous)로 실행된다. 즉 훅이 끝날 때까지 에이전트는 기다린다. 훅은 stdout, stderr, 종료 코드(exit code) 세 가지로 결과를 전달한다.

- 훅은 기본적으로 켜져 있다. 활성 설정 레이어에서 `hooks.json`이 발견되거나 `config.toml`에 훅 정의가 인라인으로 들어 있으면 동작한다.
- 관리형 환경(회사에서 설정을 중앙 관리하는 경우)에서는 `requirements.toml`로 훅을 중앙에서 끌 수 있다.
- Windows에서도 완전히 지원한다. 같은 `hooks.json`이 macOS, Linux, Windows에서 플랫폼별 수정 없이 동작한다.
- 설정은 hot-read 방식이다. 파일을 고치면 재시작 없이 바로 반영된다.

Codex CLI는 훅 설정을 두 곳에서 읽는다. 프로젝트 루트의 `.codex/hooks.json`과, `config.toml` 안의 인라인 `[[hooks]]` 정의다.

## 3. 열 가지 이벤트 한눈에 보기

아래 표는 각 이벤트가 언제 발생하는지, stdout이 어떻게 쓰이는지, 종료 코드 2가 무엇을 뜻하는지, 동작을 막을 수 있는지를 정리한 것이다.

| 이벤트 | 발생 시점 | stdout의 효과 | exit 2의 효과 | 막을 수 있나 |
|---|---|---|---|---|
| SessionStart | 세션이 열릴 때 | 모델 컨텍스트에 주입 | 오류만 기록, 세션은 계속 | 아니오 |
| PreToolUse | 도구 호출을 실행하기 직전 | 기록되거나 무시됨 | 도구 호출 거부, 오류 표시 | 예 |
| PermissionRequest | 확장 기능이나 도구가 더 높은 권한을 요청할 때 | 승인 시스템이 결정 JSON을 읽음 | 요청 거부, TUI 승인 화면으로 넘어감 | 예 |
| UserPromptSubmit | 프롬프트 제출 후, 모델이 보기 전 | 프롬프트 뒤에 덧붙음 | 프롬프트 거부, 사용자에게 stderr 표시 | 예 |
| PostToolUse | 도구 호출이 끝난 직후 | 기록되거나 무시됨 | 오류만 기록, 실행은 계속 | 아니오 |
| PreCompact | 컨텍스트 압축(compaction) 시작 전 | 기록되거나 무시됨 | 오류만 기록, 압축은 계속 | 아니오 |
| PostCompact | 컨텍스트 압축 완료 후 | 압축 이후 컨텍스트에 주입 | 오류만 기록, 세션은 계속 | 아니오 |
| SubagentStart | 서브에이전트가 만들어진 직후, 첫 모델 요청 전 | 자식 컨텍스트 앞에 붙음 | 오류만 기록, 서브에이전트는 계속 | 아니오 |
| SubagentStop | 서브에이전트의 턴이 끝나갈 때 | 기록되거나 무시됨 | 완료를 막음(계속 작업하게 함) | 예 |
| Stop | 세션이 닫힐 때 | 없음 | 오류만 기록, 정리 절차는 계속 | 아니오 |

표에서 눈여겨볼 점은 "막을 수 있는" 이벤트가 PreToolUse, PermissionRequest, UserPromptSubmit, SubagentStop 네 개뿐이라는 것이다. 나머지는 알림과 관찰, 컨텍스트 주입이 용도다.

## 4. hooks.json의 구조

`hooks.json`은 이벤트 이름을 키로 갖는 객체다. 각 이벤트는 훅 그룹의 배열로 이어지고, 각 그룹 안에 다시 개별 훅 객체의 `hooks` 배열이 있다.

```json
{
  "hooks": {
    "SessionStart": [
      { "hooks": [ {
        "type": "command",
        "command": "bash ~/.codex/scripts/inject-context.sh",
        "statusMessage": "Loading project context…",
        "timeout": 15
      } ] }
    ]
  }
}
```

배열이 한 겹 더 중첩된 것은 실수가 아니다. 바깥 배열이 그룹을, 안쪽 배열이 개별 훅을 담는다. 이런 구조 덕분에 그룹 단위로 조건(matcher)을 걸어 선택적으로 활성화할 수 있다.

주요 필드는 다음과 같다.

| 필드 | 뜻 |
|---|---|
| `type` | 훅 종류. 여기서는 항상 `"command"` |
| `command` | 실행할 셸 명령 |
| `statusMessage` | TUI에 보여 줄 진행 메시지 |
| `timeout` | 제한 시간(초) |
| `matcher` | 그룹을 적용할 대상(도구 이름, 에이전트 타입 등)을 고르는 조건 |

## 5. config.toml에 인라인으로 정의하기

훅을 `config.toml`에 직접 적으면 두 파일로 나뉘던 설정을 한 곳에 모을 수 있다.

```toml
# .codex/config.toml
[[hooks.SessionStart]]
[[hooks.SessionStart.hooks]]
type = "command"
command = "bash ~/.codex/scripts/inject-context.sh"
statusMessage = "Loading project context..."
timeout = 15
```

PostToolUse도 같은 방식으로, 예를 들어 `[[hooks.PostToolUse]]` 아래 `[[hooks.PostToolUse.hooks]]`에 `command = "bash ~/.codex/scripts/auto-test.sh"`, `statusMessage = "Running tests..."`, `timeout = 60`을 적는다.

`hooks.json`과 인라인 정의는 동시에 쓸 수 있다. 둘 다 있으면 모든 출처의 훅이 발견된 순서대로 실행된다. 인라인 형식은 기업 환경에서 정책을 중앙 강제하는 `requirements.toml`에서도 쓸 수 있다.

## 6. MCP 도구와 apply_patch도 관찰한다

PreToolUse와 PostToolUse는 Bash 도구뿐 아니라 MCP 도구 호출(`mcp__<server>__<tool>` 형태의 이름)과 `apply_patch`도 관찰한다. 그래서 `"mcp__docs__search"` 같은 matcher를 건 PreToolUse 훅으로 특정 MCP 호출을 실행 전에 가로채 감사하거나 막을 수 있다.

이를 이용하면 모든 MCP 도구 호출의 요청과 응답 전체를 남겨 규정 준수 검토에 쓰는 MCP 감사 훅을 만들 수 있다. 설정은 PostToolUse에 `"matcher": "mcp__*"`를 걸고 `bash ~/.codex/scripts/mcp-audit.sh`를 `timeout` 5초로 실행하게 하는 식이다.

## 7. 정리

- 훅은 동기 실행 셸 콜백이고, 결과는 stdout·stderr·종료 코드로 전달한다.
- 설정 위치는 `.codex/hooks.json`과 `config.toml` 인라인 두 곳이며 함께 쓸 수 있다.
- 열 이벤트 중 실행을 막을 수 있는 것은 네 개다.
- MCP 호출과 `apply_patch`도 PreToolUse, PostToolUse로 잡을 수 있다.
