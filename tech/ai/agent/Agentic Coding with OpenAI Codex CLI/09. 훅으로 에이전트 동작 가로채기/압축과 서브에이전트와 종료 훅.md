# 압축과 서브에이전트와 종료 훅

세션이 길어지면 컨텍스트가 압축되고, 여러 서브에이전트가 만들어졌다 사라지고, 마지막에는 세션이 닫힌다. 이런 경계 지점에도 훅이 걸려 있다. 이 문서는 PreCompact와 PostCompact, SubagentStart와 SubagentStop, 그리고 Stop을 다룬다. 이 지점의 훅은 장시간 자율 작업과 멀티 에이전트 운영의 관측성과 안정성을 높이는 데 쓰인다.

---

## 1. PreCompact와 PostCompact: 압축 전후의 훅

`/compact`가 실행되면(직접 입력했든 자동 압축 조건에 걸렸든) 세션 기록이 요약되고 자세한 도구 호출 흔적은 사라진다. PreCompact는 압축이 시작되기 전에, PostCompact는 끝난 뒤에 발생한다. 두 훅은 모든 command 훅처럼 stdin으로 JSON 객체를 받는다. 압축 관련 필드는 아래와 같다.

| 필드 | 설명 |
|---|---|
| `session_id` | 현재 세션 식별자 |
| `turn_id` | 압축이 시작된 턴 |
| `trigger` | 압축이 시작된 방식. `manual`(사용자가 `/compact` 입력) 또는 `auto`(컨텍스트 윈도 임계치 도달) |

이 훅들은 감사용(audit-only)이다. 압축을 막을 수 없고, 압축 전 컨텍스트의 전체 내용에도 접근하지 못한다. PreCompact는 알림으로만 발생하고, PostCompact의 stdout은 압축 후 컨텍스트에 주입된다. 즉 압축 때문에 사라질 정보를 다시 넣어 주는 통로가 PostCompact다.

## 2. 압축 메모리 패턴

대표적인 활용은 압축 전에 중요한 상태를 저장하고, 압축 후에 다시 주입하는 것이다.

PreCompact 훅은 stdin JSON에서 `session_id`, `turn_id`, `trigger`를 `jq`로 읽고, `$HOME/.codex/compact-state` 디렉터리에 세션별 JSON 파일을 저장한다.

```bash
#!/usr/bin/env bash
# ~/.codex/scripts/pre-compact.sh
INPUT="$(cat)"
SESSION_ID="$(printf '%s' "$INPUT" | jq -r '.session_id // "unknown"')"
TURN_ID="$(printf '%s' "$INPUT" | jq -r '.turn_id // 0')"
TRIGGER="$(printf '%s' "$INPUT" | jq -r '.trigger // "unknown"')"
COMPACT_DIR="$HOME/.codex/compact-state"
mkdir -p "$COMPACT_DIR"
# 이어서 cat > "$COMPACT_DIR/session-${SESSION_ID}.json" << EOF 로
# 상태 JSON을 저장한다
```

저장하는 JSON에는 `session_id`, `turn`, `trigger`, 현재 `branch`, 커밋하지 않은 파일 수(`uncommitted_files`), `python -m pytest --tb=no -q`의 마지막 줄(`test_status`)이 들어간다.

PostCompact 훅은 같은 입력 방식으로 값을 읽고, 저장해 둔 `session-${SESSION_ID}.json`이 있으면 다음과 같은 내용을 stdout으로 출력한다.

- "## Post-Compaction Context Recovery"라는 제목
- 세션이 몇 번째 턴에서(`trigger`가 무엇이었는지와 함께) 압축됐다는 안내
- 압축 전에 저장한 상태 파일 내용
- 이 상태에서 작업을 이어 가라는 지시와, 자세한 도구 호출 기록은 더 이상 없다는 안내

두 스크립트는 `hooks.json`에 각각 PreCompact와 PostCompact로 연결한다. 명령은 `bash ~/.codex/scripts/pre-compact.sh`와 `bash ~/.codex/scripts/post-compact.sh`, 상태 메시지는 "Saving state before compaction..."과 "Restoring context after compaction...", 둘 다 `timeout`은 5초다.

몇 시간씩 자율적으로 일하는 긴 세션에서는 이 훅 덕분에 중요한 맥락이 압축 경계를 넘어 살아남는다. 어떤 파일을 작업 중이었는지, 테스트 상태가 어땠는지, 어떤 설계 결정을 내렸는지 같은 것들이다. 보완적인 컨텍스트 보존 전략은 7장에서 다룬다.

## 3. SubagentStart와 SubagentStop: 서브에이전트 경계 훅

이 두 훅은 최상위 생애 주기 훅만으로는 볼 수 없는 멀티 에이전트의 관측 공백을 메워 준다.

SubagentStart는 Codex CLI가 스레드로 서브에이전트를 만들 때, 자식이 첫 모델 요청을 보내기 전에 한 번 발생한다. 컨텍스트를 주입하는 훅이다. 핸들러가 `hookSpecificOutput.additionalContext`를 돌려주면 그 내용이 자식 대화의 맨 앞에 붙은 뒤 첫 모델 호출이 일어난다. 훅은 자식의 `agent_id`(스레드 식별자)와 `agent_type`(`spawn_agent` 호출에서 정해진 타입)을 받는다.

SubagentStop은 서브에이전트의 턴이 끝나갈 때 발생하며, 자식 에이전트에 대해서는 일반 루트 에이전트의 Stop 훅을 대신한다. 같은 `agent_id`와 `agent_type`에 더해 `agent_transcript_path`(자식의 전체 대화 로그)와 `last_assistant_message`(자식의 마지막 출력)를 받는다. 완료 제어도 지원한다. 이유를 달아 막으면 자식이 계속 일하게 되고, 사용자 지정 종료 사유를 줄 수도 있다.

두 훅은 `agent_type` matcher로 타입별 라우팅을 한다. 조율된 워크플로 안에서 `researcher`, `implementer`, `reviewer` 같은 서브에이전트 타입마다 다른 훅을 걸어 각자의 컨텍스트 주입과 품질 관문 로직을 둘 수 있다.

```json
{
  "hooks": {
    "SubagentStart": [ { "matcher": "reviewer",
      "hooks": [ { "type": "command", "timeout": 5,
        "command": "bash ~/.codex/scripts/inject-review-context.sh" } ]
    } ],
    "SubagentStop": [ { "matcher": "implementer",
      "hooks": [ { "type": "command", "timeout": 10,
        "command": "bash ~/.codex/scripts/check-implementation-quality.sh" } ]
    } ]
  }
}
```

원서 예제에는 각 훅에 `statusMessage`("Injecting reviewer context...", "Checking implementation quality...")도 들어 있다. 위 예제는 리뷰어 서브에이전트가 시작될 때 리뷰 컨텍스트를 넣고, 구현자 서브에이전트가 끝나려 할 때 품질을 검사한다.

### 3.1 세 가지 거버넌스 패턴

1. 생성 시점 컨텍스트 주입. SubagentStart 훅이 팀 고유 제약, 규정 준수 지침, 역할별 AGENTS.md 내용을 자식이 만들어질 때 넣는다. 부모의 프롬프트에 모든 것을 굽지 않아도 된다.
2. 서브에이전트 출력의 품질 관문. SubagentStop 훅이 자식의 마지막 메시지와 대화 기록을 검사해 승인, 거부, 계속 진행 중에서 고른다. 정책 검사에 실패하면 완료를 막아 자식이 계속 일하게 한다.
3. 자식별 감사 기록. SubagentStop의 `agent_transcript_path`가 각 자식의 전체 대화를 가리키므로, 멀티 에이전트 실행을 사후에 분석하고 자식별 토큰 수를 세어 비용을 배분할 수 있다.

스레드 산출물(artefact) 보존 기능과 합치면 서브에이전트의 전체 생애 주기가 완성된다. 시작할 때 컨텍스트를 넣고, 실행 중에 산출물을 만들고, 끝날 때 결과를 점검한다. 이 훅들이 다스리는 서브에이전트 구조는 11장에서 다룬다.

## 4. Stop: 정리와 마무리

Stop은 세션이 끝날 때 발생한다. 모델 컨텍스트에는 아무것도 주입하지 않으며, exit 2는 오류를 기록할 뿐 종료 절차를 막지 못한다. 설정은 `"Stop"` 이벤트에 `bash ~/.codex/scripts/on-stop.sh`, `statusMessage`는 "Wrapping up…", `timeout`은 10초를 거는 식이다.

전형적인 `on-stop.sh`는 세 가지 일을 한다.

- 감사 로그. UTC 시각, 브랜치, 사용자 이름을 `~/.codex/session-audit.log`에 한 줄 추가한다.
- 데스크톱 알림. `notify-send`(Linux)가 있으면 그것을, `osascript`(macOS)가 있으면 그것을 써서 "Session complete on 브랜치"를 띄운다. 플랫폼마다 다르다.
- Slack 웹훅. 환경 변수 `CODEX_SLACK_WEBHOOK`가 설정돼 있으면 `curl`로 세션이 끝났다는 메시지를 보낸다.

```bash
TIMESTAMP=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null || echo "unknown")
echo "$TIMESTAMP branch=$BRANCH user=$USER" >> ~/.codex/session-audit.log
if [ -n "$CODEX_SLACK_WEBHOOK" ]; then
  curl -s -X POST "$CODEX_SLACK_WEBHOOK" \
    -H 'Content-type: application/json' \
    --data "{\"text\":\"Codex session ended on \`$BRANCH\` at $TIMESTAMP\"}" > /dev/null
fi
```

## 5. 정리

| 이벤트 | 입력으로 받는 값 | 출력의 효과 | 대표 용도 |
|---|---|---|---|
| PreCompact | `session_id`, `turn_id`, `trigger` | 알림용 | 중요한 상태 저장 |
| PostCompact | 위와 동일 | 압축 후 컨텍스트에 주입 | 저장한 상태 다시 넣기 |
| SubagentStart | `agent_id`, `agent_type` | `additionalContext`를 자식 앞에 붙임 | 역할별 제약 주입 |
| SubagentStop | 위 + `agent_transcript_path`, `last_assistant_message` | 막으면 자식이 계속 작업 | 품질 관문, 비용 계산 |
| Stop | 없음(원문에 별도 필드 언급 없음) | 없음 | 로그, 알림 |
