# 세션 시작과 프롬프트 훅

세션이 열리는 순간과 사용자가 프롬프트를 제출하는 순간은 에이전트에게 정보를 밀어 넣거나 요청을 걸러내기에 가장 좋은 지점이다. SessionStart는 AGENTS.md에 적으면 금방 낡아 버리는 동적인 정보를 넣는 곳이고, UserPromptSubmit은 입력을 덧붙이거나 거부하는 곳이다. 이 문서는 두 이벤트의 계약과 예제 스크립트를 다룬다.

---

## 1. SessionStart: 환경 설정하기

SessionStart는 모델이 사용자 입력을 처리하기 전에 딱 한 번 실행된다. 현재 브랜치, 진행 중인 티켓처럼 AGENTS.md에 적어 두면 금세 틀려지는 동적 컨텍스트를 넣기에 알맞다.

종료 코드 0이면 Codex CLI가 스크립트의 stdout을 첫 턴 전에 모델 컨텍스트에 주입한다. 출력은 구조적으로 짧게 유지해야 한다. 출력에 들어간 토큰은 모두 컨텍스트 윈도를 차지하기 때문이다(7장 참고).

```bash
#!/usr/bin/env bash
# ~/.codex/scripts/inject-context.sh
BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null || echo "unknown")
TICKET=$(echo "$BRANCH" | grep -oE '[A-Z]+-[0-9]+' | head -1)
DIRTY=$(git status --porcelain 2>/dev/null | wc -l | tr -d ' ')
echo "## Session Context"
echo "- Branch: $BRANCH"
echo "- Jira ticket: ${TICKET:-none detected}"
echo "- Uncommitted files: $DIRTY"
```

원서의 전체 스크립트는 여기에 더해, `.codex/project-notes.md` 파일이 있으면 빈 줄을 하나 출력한 뒤 그 내용을 `cat`으로 이어 붙인다. 스크립트가 하는 일을 풀어 보면 이렇다.

- 현재 git 브랜치 이름을 구한다. git 저장소가 아니면 `unknown`이 된다.
- 브랜치 이름에서 `ABC-123` 형태의 Jira 티켓 번호를 정규식으로 뽑는다. 없으면 "none detected"로 표시한다.
- `git status --porcelain`의 줄 수를 세어 커밋하지 않은 파일 수를 얻는다.
- 프로젝트 메모 파일이 있으면 그 내용도 함께 보여 준다.

이 스크립트를 `hooks.json`의 SessionStart에 `bash ~/.codex/scripts/inject-context.sh`, `statusMessage`는 "Loading branch context…", `timeout`은 10으로 연결한다.

SessionStart에서 exit 2는 오류만 기록하고 세션은 계속 진행한다. UserPromptSubmit에서는 exit 2가 프롬프트를 막는 것과 다르다. 따라서 컨텍스트 주입이 실패하면 세션은 주입된 정보 없이 그냥 열린다.

SessionStart는 stdin으로 `source` 필드를 받는다. 값은 `startup`, `resume`, `clear`, `compact` 중 하나다. 새로 시작한 경우와 이어서 시작한 경우, `/clear` 뒤에 다시 연 경우에 스크립트가 다르게 동작하길 원하면 이 값으로 분기하면 된다.

## 2. UserPromptSubmit: 에이전트가 움직이기 전에 입력 다듬기

UserPromptSubmit은 Enter를 누른 뒤, 모델이 텍스트를 보기 전에, 그리고 프롬프트가 세션 기록에 들어가기 전에 실행된다. 프롬프트에 정해진 문구를 덧붙이거나, 정책을 어기는 프롬프트를 거부하는 데 쓴다.

### 2.1 프롬프트 보강하기

종료 코드 0이면 훅의 stdout이 프롬프트 뒤에 덧붙는다. 다음은 지금 실패 중인 테스트 현황을 항상 에이전트가 알게 하는 스크립트다.

```bash
#!/usr/bin/env bash
# ~/.codex/scripts/append-test-status.sh
FAILING=$(python -m pytest --tb=no -q 2>&1 | tail -5)
if [ -n "$FAILING" ]; then
  echo ""
  echo "### Current test status"
  echo "$FAILING"
fi
```

보강 로직이 복잡하면 Python으로 짜는 편이 낫다. 같은 일을 하는 Python 버전은 `subprocess.run`으로 `python -m pytest --tb=no -q`를 실행하고, `returncode`가 0이 아니면 출력의 마지막 5줄을 "### Current test status" 제목과 함께 `print`한다. 테스트가 모두 통과하면 아무것도 출력하지 않으므로 컨텍스트가 늘지 않는다.

### 2.2 프롬프트 막기

exit 2는 프롬프트를 통째로 거부한다. 프롬프트는 모델에 가지 않고 기록에도 남지 않는다.

```bash
#!/usr/bin/env bash
# ~/.codex/scripts/prompt-policy.sh
set -euo pipefail
PROMPT="$(jq -r '.prompt // empty')"
if printf '%s' "$PROMPT" | grep -qi 'push.*main\|force.push\|--force'; then
  echo "Prompt blocked: direct push to main is prohibited. Open a PR instead." >&2
  exit 2
fi
```

이 스크립트는 main에 직접 push하라는 요청을 걸러낸다. 사용자는 stderr에 쓴 메시지를 화면에서 보게 된다.

UserPromptSubmit 훅은 제출된 프롬프트를 stdin으로 JSON 객체 형태로 받는다. 텍스트는 `prompt` 필드에 있고, `session_id`, `cwd`, `hook_event_name` 같은 공통 필드가 같이 들어 있다. 위처럼 `jq -r '.prompt'`로 꺼내면 된다. 환경 변수에서 찾으려 하지 말고, 문서화된 통로인 stdin JSON을 써야 한다.

## 3. 타임아웃을 짧게 잡아라

UserPromptSubmit은 프롬프트의 진행을 막는 훅이므로 느린 스크립트는 에이전트가 고장 난 것처럼 느끼게 만든다. 정책 검사라면 5초면 보통 충분하다. 모델이 움직이기 전에 테스트 결과가 꼭 필요한 경우에 한해 테스트 러너는 30초 정도가 합리적이다.

## 4. 두 이벤트 비교

| 항목 | SessionStart | UserPromptSubmit |
|---|---|---|
| 실행 시점 | 세션 열릴 때 한 번 | 프롬프트를 제출할 때마다 |
| stdout | 모델 컨텍스트에 주입 | 프롬프트 뒤에 덧붙음 |
| exit 2 | 오류 기록, 세션 계속 | 프롬프트 거부 |
| stdin | `source` 필드 등 | `prompt`, `session_id`, `cwd`, `hook_event_name` |
| 적합한 용도 | 브랜치·티켓·메모 같은 동적 컨텍스트 | 린트·테스트 상태 덧붙이기, 정책 차단 |
| 권장 타임아웃 | 10~15초 | 정책 검사 5초, 테스트 러너 30초 |
