# 기업 거버넌스와 자기 진화 루프

기업 환경에서 훅은 편의 기능이 아니라 거버넌스(통제) 계층이 된다. PreToolUse와 PostToolUse가 짝을 이뤄 모든 도구 실행에 조직 정책을 강제한다. 이 문서는 그 패턴과, 한 걸음 더 나아간 자기 진화 에이전트 재학습 루프를 설명한다.

---

## 1. PreToolUse 거버넌스 패턴

1. 위험한 도구 차단. 도구 이름을 금지 목록(denylist)과 비교해 설명과 함께 거부 판정을 돌려준다. 데이터베이스 삭제, force push, 운영 배포 같은 파괴적 명령을 승인 모드와 상관없이 막는다.
2. 규정 준수 게이트. 파일을 고치기 전에 대상 경로가 에이전트에게 허용된 범위 안인지 확인한다. 기능 브랜치에서 일하는 에이전트가 공유 인프라 파일, `/etc/` 설정, 배정받은 모듈 밖의 파일을 건드리지 못하게 강제할 수 있다.
3. 실행 전 감사 기록. 제안된 모든 도구 호출을 실행 전에 변경 불가능한(immutable) 감사 로그에 남긴다. 도구 이름, 입력 매개변수, 시각, 세션 맥락을 기록하므로 호출의 성공 여부와 무관한 포렌식 흔적이 생긴다.

위험한 도구 차단 설정은 다음처럼 `matcher`에 `"^Bash$"`를 걸고 사내 정책 스크립트를 연결한다.

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "^Bash$",
      "hooks": [{
        "type": "command",
        "command": "/usr/local/bin/enterprise-tool-policy.sh",
        "timeout": 10
      }]
    }]
  }
}
```

원서는 이 내용의 출처로 Codex CLI 훅 설정 문서(developers.openai.com/codex/hooks)를 든다.

## 2. PostToolUse 거버넌스 패턴

1. 규정 준수 스캔. 파일을 쓸 때마다 라이선스 헤더 확인, import 제한, 이름 규칙 검사 같은 자동 점검을 돌리고, 고치라는 안내를 stdout으로 에이전트 컨텍스트에 넣는다.
2. 변경 귀속. 파일을 바꿀 때마다 에이전트 세션 ID와 작업 식별자를 태그로 붙인다. 바뀐 한 줄에서 그것을 만든 에이전트 실행까지 추적할 수 있다.
3. 지표 수집. 도구 실행 결과(성공·실패율, 소요 시간 분포, 자원 소비)를 팀 단위 대시보드로 모아 용량 계획에 쓴다.

## 3. 여러 계층의 훅은 함께 돌아간다

일치하는 모든 설정 레이어의 훅은 동시에(concurrently) 실행된다. 기업의 플랫폼 팀은 `requirements.toml`로 거버넌스 훅을 의무화할 수 있고, 개별 개발자는 이를 덮어쓸 수 없다. 프로젝트 팀은 저장소 수준에서 자기 훅을 추가한다. 두 훅 집합은 충돌하지 않고 합쳐진다.

## 4. 자기 진화 에이전트 재학습 루프

더 야심 찬 활용으로, OpenAI Cookbook의 재학습 루프에서 가져온 자기 진화 에이전트 패턴이 있다. 닫힌 피드백 루프다. PostToolUse 훅이 도구 실행 뒤마다 복합 채점을 돌리고, 점수가 기준 아래로 떨어지면 메타프롬프트 에이전트가 개선된 지시문을 만들어 현재 AGENTS.md를 교체한다. 원서는 이 참조 아키텍처를 기준선, 평가, 최적화, 배포의 네 단계 재학습 루프로 소개한다.

복합 채점은 한 지표만 최적화하는 일을 막기 위해 서로 다른 채점기 네 개를 쓴다.

| 채점기 | 방식 | 목적 |
|---|---|---|
| 핵심어 보존 | 규칙 기반 | 중요한 용어가 변환 뒤에도 남아 있는지 확인 |
| 길이 절제 | 결정론적 | 출력 크기를 목표 허용 범위 안에 유지 |
| 의미 일관성 | 코사인 유사도 | 내용이 엉뚱하게 흘러가는 것을 감시 |
| 종합 품질 | LLM이 심사(LLM-as-judge) | 규칙이 놓치는 미묘한 신호 포착 |

훅은 Bash matcher를 건 PostToolUse에서 실행된다. 평균 점수가 임계값(보통 0.85) 아래로 내려가면 메타프롬프트 최적화 단계가 돌아 AGENTS.md를 고친다. 개선본은 git에 커밋되며, 평가 점수가 커밋 메시지에 남아 프롬프트가 어떻게 진화했는지 감사 가능한 이력이 생긴다.

## 5. 이 패턴은 누구에게 맞는가

이 패턴은 평가 인프라에 큰 초기 투자가 필요하다. 평가 비용(벤치마크 한 번에 약 74,000 토큰)이 정당화되는, 위험이 크고 처리량이 많은 워크플로에만 어울린다. 대부분의 팀에게는 앞에서 소개한 단순한 훅 패턴이 올바른 출발점이다.

## 6. 정리

| 주제 | 핵심 |
|---|---|
| PreToolUse 거버넌스 | 금지 목록 차단, 경로 범위 게이트, 실행 전 감사 |
| PostToolUse 거버넌스 | 규정 스캔, 변경 귀속, 지표 수집 |
| 계층 합성 | 모든 계층의 훅이 동시 실행, `requirements.toml` 훅은 덮어쓸 수 없음 |
| 자기 진화 루프 | 4개 채점기, 임계값 0.85, 개선된 AGENTS.md를 git에 커밋 |
| 비용 | 벤치마크 한 번에 약 74,000 토큰, 고위험·대량 워크플로 한정 |
