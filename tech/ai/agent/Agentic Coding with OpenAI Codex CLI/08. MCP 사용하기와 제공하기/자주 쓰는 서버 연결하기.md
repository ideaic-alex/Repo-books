# 자주 쓰는 서버 연결하기

실무에서 가장 먼저 붙이게 되는 MCP 서버는 GitHub, 문서 조회(Context7), 브라우저 자동화(Playwright), 데이터베이스(Postgres) 네 가지다. 이 문서는 각 서버의 설정 블록과, 서버마다 도구를 어떻게 골라 켜야 하는지를 정리한다.

네 서버에 공통으로 적용되는 원칙은 하나다. 필요한 도구만 켠다. 도구를 많이 열어 둘수록 컨텍스트 윈도를 먹고, 에이전트가 건드릴 수 있는 범위도 넓어진다.

---

## 1. GitHub

GitHub는 대표적인 첫 MCP 서버다. 설정은 앞 문서의 예시와 같다. 워크플로에 따라 켜 둘 만한 도구는 다음과 같다.

- 이슈 분류와 관리: list_issues, create_issue, get_issue
- 저장소를 가로지르는 코드 검색: get_file_contents, search_code
- PR 자동화: create_pull_request, list_pull_requests

enabled_tools로 필요한 도구만 허용 목록(whitelist)에 올린다. 제한 없이 GitHub MCP 서버를 켜면 수십 개의 도구가 노출되는데, 에이전트가 한 번도 안 써도 도구 정의가 컨텍스트 윈도 자리를 차지한다.

## 2. Context7로 문서 조회하기

@upstash/context7-mcp는 Upstash가 만든 MCP 서버로, 에이전트가 마주친 라이브러리의 최신 버전별 문서를 가져다 준다. 이게 없으면 에이전트는 학습 데이터에 기대어 라이브러리 질문에 답하는데, 그 내용은 몇 달 묵었을 수 있다. 연결하면 내가 쓰는 버전의 실제 문서를 찾아본다.

```toml
[mcp_servers.context7]
enabled = true
command = "npx"
args = ["-y", "@upstash/context7-mcp"]
enabled_tools = ["resolve-library-id", "query-docs"]
```

도구는 두 개다. resolve-library-id는 "Next.js", "MongoDB" 같은 자유 형식 이름을 Context7이 쓰는 정식 ID로 바꿔 준다. query-docs는 구체적인 질문에 맞는 문서 조각을 가져온다. 이 장의 저자는 거의 모든 세션에서 Context7을 켜 둔다고 밝힌다.

## 3. Playwright로 브라우저 자동화하기

@playwright/mcp는 Microsoft가 공식으로 내놓은 Playwright MCP 서버다. 비전 모델 없이도 실제 브라우저를 조작한다. 화면 이미지를 보는 대신 접근성 스냅샷(accessibility snapshot)이라는 구조화된 정보를 노출하고, 에이전트가 그 위에서 추론한다. 그래서 폼 입력, 페이지 이동, CI에서의 DOM 수준 검증에 잘 맞는다.

```toml
[mcp_servers.playwright]
enabled = true
command = "npx"
args = ["-y", "@playwright/mcp@latest"]
```

기본 도구 모음은 이동, 클릭, 입력, 스냅샷, 탭 관리를 다룬다. 네트워크 모킹, 스토리지 조작, 영상 녹화, PDF 생성, 좌표 기반 마우스 조작, 테스트 단언(assertion) 같은 추가 기능은 명령줄의 `--caps=...` 옵션으로 직접 켜야 한다. 기능 그룹마다 자기 도구가 컨텍스트에 더해지므로, 워크플로에 필요한 것만 나열한다.

## 4. 데이터베이스 접근

데이터베이스 서버는 에이전트가 관계형 저장소를 조회하고, 필요하면 쓰기도 하게 해 준다. 대표 예시는 Postgres용 @modelcontextprotocol/server-postgres다.

```toml
[mcp_servers.postgres]
enabled = true
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres", "${DATABASE_URL}"]
enabled_tools = ["query"]
```

운영(production) 데이터베이스에는 읽기 전용 연결 문자열을 쓰고 query 도구만 열어 둔다. MCP 서버를 통해 운영 데이터에 쓰기 권한을 주려면, 다른 운영 DB 변경과 똑같은 변경 관리 절차를 거치게 해야 한다.

위 예시의 `${DATABASE_URL}`처럼 셸식 자리 표시자가 config.toml 안에서 자동으로 치환된다고 가정하면 안 된다. 이 문제는 기업 환경 문서의 자격 증명 격리 항목에서 다시 다룬다.

## 5. 서버별 요약

| 서버 | 패키지 | 켜 둘 도구 | 비고 |
|---|---|---|---|
| GitHub | @modelcontextprotocol/server-github | 이슈, 코드 검색, PR 관련 도구 | enabled_tools로 반드시 제한 |
| Context7 | @upstash/context7-mcp | resolve-library-id, query-docs | 버전별 최신 문서 조회 |
| Playwright | @playwright/mcp | 기본 도구 + 필요한 --caps | 접근성 스냅샷 기반 |
| Postgres | @modelcontextprotocol/server-postgres | query | 운영 DB는 읽기 전용 연결 |
