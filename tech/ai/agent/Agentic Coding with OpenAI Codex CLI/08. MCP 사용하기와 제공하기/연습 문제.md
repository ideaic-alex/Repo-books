# 연습 문제

8장 끝의 연습 문제 세 개를 풀이 방향과 함께 정리한다. 각 문제는 이 장의 한 축(도구 제한, 서버 제작, 서버 제공)에 대응한다.

---

## 1. 연습 8-1. GitHub 도구 제한과 컨텍스트 비교

**문제.** GitHub MCP 서버를 enabled_tools로 도구를 제한해 설정한다. GitHub 접근이 필요한 작업을 실행해 에이전트가 어떤 도구를 호출하는지 관찰한다. 그런 다음 enabled_tools를 지우고 컨텍스트 윈도 사용량이 어떻게 달라지는지 비교한다.

**풀이 방향.** 사용량은 7장에서 배운 `codex debug prompt-input` 출력을 토크나이저로 세어서 비교할 수 있다. 도구를 제한했을 때는 이슈 목록 같은 작업에 필요한 도구만 호출되고, 제한을 풀면 수십 개의 도구 정의가 모두 컨텍스트에 올라가 사용량이 눈에 띄게 커진다. 호출하지 않은 도구도 비용을 낸다는 점을 확인하는 것이 목적이다.

## 2. 연습 8-2. 읽기 도구와 쓰기 도구를 가진 서버 만들기

**문제.** Python으로 도구가 두 개인 MCP 서버를 만든다. 하나는 읽기 전용(query), 하나는 쓰기 가능(create)이다. 각각에 알맞은 위험 어노테이션을 달고, Codex CLI에 연결해서 쓰기 도구만 승인을 요구하고 읽기 도구는 요구하지 않는지 확인한다.

**풀이 방향.** query에는 readOnlyHint를 true로, create에는 readOnlyHint를 false로 달고 필요하면 destructiveHint도 건다. 먼저 `mcp dev server.py`로 Inspector에서 두 도구가 보이는지 확인한 뒤 config.toml에 연결한다. 승인 모드가 on-request일 때 읽기 도구는 자동 승인될 수 있고, 쓰기 도구는 승인 창이 뜨는지 본다.

## 3. 연습 8-3. Codex CLI를 서버와 클라이언트로 연결하기

**문제.** Codex CLI를 MCP 서버로 띄우고, 두 번째 Codex CLI 인스턴스를 클라이언트로 연결한다. 클라이언트 쪽에서 서버 쪽으로 코딩 작업을 위임하고, 프로토콜이 도구 발견, 호출, 결과 전달을 어떻게 다루는지 관찰한다.

**풀이 방향.** 서버 쪽은 `codex mcp-server`를 실행하는 mcp_servers 블록을 오케스트레이터의 config.toml에 둔다. 도구 목록에 codex와 codex-reply가 나타나는 것이 도구 발견이고, codex 호출이 새 세션을 열어 threadId와 content를 돌려주는 것이 호출과 결과 전달이다. 후속 지시를 codex-reply로 보내서 같은 세션이 이어지는지도 확인한다.
