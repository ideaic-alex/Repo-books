# 요약

8장의 핵심 내용을 아홉 가지로 정리한다. 각 항목 뒤에 어디서 자세히 다뤘는지 덧붙였다.

---

## 1. 장 요약

1. **MCP는 표준 프로토콜이다.** 서비스마다 따로 연동 코드를 짜지 않고도 에이전트를 외부 도구와 서비스에 연결해 준다. (MCP 기본 개념)
2. **3단 구조.** 호스트, 클라이언트, 서버가 에이전트 로직과 도구 구현을 갈라 놓는다. (MCP 기본 개념)
3. **도구 어노테이션은 위험을 나타내는 어휘다.** 승인 시스템이 이 값을 보고 호출을 어떤 경로로 보낼지 정한다. (MCP 기본 개념)
4. **필요한 것만 허용 목록에 올린다.** enabled_tools는 컨텍스트 비용을 줄이고 공격 표면도 줄인다. (컨텍스트 비용 관리)
5. **서버 만들기는 어렵지 않다.** 도구를 정의하고 로직을 구현하면 나머지는 프로토콜이 처리한다. (간단한 MCP 서버 만들기)
6. **쓰기 연동에는 규율이 필요하다.** 명시적 어노테이션, 승인 통제, 멱등성, 감사 로그를 갖춘다. (운영 환경의 MCP)
7. **기업용 MCP는 통제를 더한다.** 서버 허용 목록, 자격 증명 격리, 엘리시테이션 제어가 있다. (기업 환경의 MCP)
8. **Codex CLI는 MCP 서버가 될 수 있다.** 에이전트 간 위임과 도구 조합을 가능하게 한다. (Codex CLI를 MCP 서버로 쓰기)
9. **복원력 패턴.** 기능을 줄여서라도 계속하기(graceful degradation), 타임아웃, 더미 도구가 MCP 실패 때문에 워크플로가 막히는 일을 막는다. (운영 환경의 MCP)

## 2. 한 줄로 줄이면

서버를 연결할 때마다 능력과 컨텍스트 비용이 함께 늘어나므로, 필요한 서버와 도구만 켜고, 쓰기 작업은 승인과 기록으로 묶어 둔다.
