# 연습 문제

15장 끝의 연습 문제 여섯 개다. 각 문제의 취지를 풀어 쓰고, 풀이 방향을 한두 문장 덧붙였다.

---

## 1. 경로 필터를 단 리뷰 워크플로

PR 리뷰 워크플로가 `src/`와 `lib/` 아래가 바뀐 경우에만 돌도록 만든다. 문서나 설정만 바뀐 PR에 에이전트 비용을 쓰지 않게 하는 연습이다.

풀이 방향: `on.pull_request` 아래에 `paths` 필터를 추가해 `src/**`와 `lib/**`를 나열한다. 실제로 해당 경로 밖의 파일만 고친 PR을 열어서 잡이 건너뛰어지는지 확인한다.

## 2. 구조화된 리뷰 출력

리뷰 프롬프트를 고쳐서 결과가 `logic_errors`, `security_concerns`, `missing_tests`, `summary` 네 키를 가진 JSON으로 나오게 한다.

풀이 방향: 이 네 키를 가진 JSON Schema 파일을 만들고 `--output-schema`로 지정한 뒤 `-o`로 결과를 파일에 저장한다. 댓글 게시 단계는 이 JSON을 읽어 항목별로 마크다운으로 바꾼다.

## 3. 범위를 좁힌 테스트 생성

테스트 생성 워크플로를 매트릭스(matrix) 잡으로 바꿔서 바뀐 파일 하나당 Codex CLI 세션 하나를 쓰게 한다. 한 세션이 모든 파일을 처리하던 기존 방식과 품질을 비교한다.

풀이 방향: 변경 파일 목록을 JSON 배열로 만들어 `strategy.matrix`에 넘기고, 잡마다 한 파일만 프롬프트에 준다. 생성된 테스트의 통과율과 기존 관례와의 일치도를 두 방식에서 나란히 본다.

## 4. 세션 유지

`src/`의 해시(SHA)를 키로 `thread_id`를 캐시한다. 이후 실행에서 토큰 절감량을 잰다.

풀이 방향: 첫 실행에서 `--json` 출력의 `thread.started`로 `thread_id`를 뽑아 캐시에 저장하고, 키가 같은 다음 실행은 `codex exec resume`으로 이어 간다. `turn.completed`의 `usage`를 두 경우에 비교해 절감량을 계산한다.

## 5. 결정적 CI 실행

기존 CI 워크플로에 `--ignore-user-config`와 `--ignore-rules`를 더한다. `~/.codex/` 디렉터리가 채워져 있고 프로젝트 execpolicy `.rules` 파일이 있는 러너에서 같은 프롬프트를 이 옵션이 있을 때와 없을 때로 돌려 출력을 비교한다. 두 실행 모두에서 AGENTS.md는 여전히 적용된다는 점도 기록한다.

풀이 방향: 두 실행의 차이가 사용자 설정과 규칙에서만 나오는지 확인하고, AGENTS.md의 지시는 양쪽에서 똑같이 반영된다는 점을 메모한다.

## 6. 호스트 이름 패턴 샌드박스 정책

최상위 `allowed_sandbox_modes`가 `["read-only"]`이고, `dev-*` 러너와 맞는 `hostname_patterns`를 가진 `[[remote_sandbox_config]]` 항목이 `workspace-write`도 허용하는 관리형 `requirements.toml`을 쓴다. 다른 호스트는 `read-only`로 되돌아가는지 확인한다.

풀이 방향: 본문의 `dev-runner-*` 예시에서 패턴만 `dev-*`로 바꾼다. 이름이 맞는 호스트와 맞지 않는 호스트에서 각각 `-s workspace-write`를 시도해 후자가 막히는지 본다. 호스트 매칭은 보안 경계가 아니라는 점도 같이 떠올린다.
