# 재현 가능한 실행과 샌드박스 제한

CI 러너는 시간이 지나면 조금씩 달라진다. 캐시된 홈 디렉터리, Docker 레이어, 공유 이미지에 묵은 설정이 남아 있기 때문이다. 같은 커밋과 프롬프트인데 어느 러너에서 도느냐에 따라 결과가 달라지면 CI로서 쓸모가 떨어진다. 이 문서는 실행을 최대한 격리해서 재현되게 만드는 옵션과, 환경(개발·스테이징·운영)별로 샌드박스 허용 범위를 제한하는 방법을 다룬다.

---

## 1. 결정적(hermetic) 실행을 만드는 세 가지 옵션

세 옵션을 같이 쓰면 실행이 외부 상태와 거의 단절(hermetic)된다. 같은 커밋, 같은 프롬프트, 같은 모델이면 어느 러너가 맡든 같은 동작이 나온다.

| 옵션 | 하는 일 |
| --- | --- |
| `--ignore-user-config` | `~/.codex/config.toml`을 무시한다. 개발자 개인 설정이 CI에 스며들지 않는다. |
| `--ignore-rules` | 사용자·프로젝트의 execpolicy `.rules` 파일을 모두 건너뛴다. |
| `--sandbox workspace-write` | 파일 시스템 접근을 현재 작업 디렉터리 안으로 가둔다. |

### --ignore-rules 자세히

execpolicy `.rules` 파일은 Starlark(파이썬 비슷한 설정 언어)로 쓴 규칙 묶음이다. 에이전트가 제안한 명령이 실행 정책과 어떻게 맞는지 판정한다. 작성과 검증 방법(`codex execpolicy check`)은 18장에서 다룬다. `--ignore-rules`를 주면 저장소 수준의 execpolicy가 빠진다.

이 옵션은 서브에이전트에도 전달된다. 그래서 여러 에이전트를 나누어 맡기고 조율하는 일(오케스트레이션)을 하더라도 격리가 일관되게 유지된다.

주의할 점이 있다. AGENTS.md의 지시는 여전히 읽힌다. 그러니 이 옵션이 주는 것은 설정과 execpolicy로부터의 격리이지 프로젝트 지침으로부터의 격리가 아니다. 완전히 단절된 실행을 원하면 체크아웃된 저장소에 어떤 AGENTS.md가 들어 있는지도 직접 관리해야 한다.

### 가장 재현성 높은 조합

```bash
codex exec --ignore-user-config --ignore-rules --model gpt-5.4-mini "your prompt"
```

모델 고정, 사용자 설정 무시, 규칙 무시를 모두 합친 형태다. 로컬 개발과 CI 사이, 러너 이미지 사이, 시간이 흐른 파이프라인 실행 사이의 설정 드리프트(조금씩 어긋나는 현상)를 없앤다.

## 2. 환경별 샌드박스 모드 상한 두기

회사에서는 러너마다 허용할 권한 수준이 다르다. 개발 러너는 자동 수정(autofix)을 위해 `workspace-write`를 쓰게 하고, 스테이징과 운영 러너는 `read-only`로 묶고 싶을 수 있다. 이를 위해 호스트 이름 패턴 기반 샌드박스 정책을 쓴다.

이 정책은 관리형 설정 파일 `requirements.toml`에 `[[remote_sandbox_config]]` 항목으로 쓴다. 각 항목의 `hostname_patterns`가 러너의 호스트 이름과 맞으면 그 항목의 정책이 적용된다.

```toml
# requirements.toml
allowed_sandbox_modes = ["read-only"]

[[remote_sandbox_config]]
hostname_patterns = ["dev-runner-*"]
allowed_sandbox_modes = ["read-only", "workspace-write"]
```

### 매칭 규칙

- 패턴은 대소문자를 구분하지 않는다.
- `*`는 임의 길이의 문자열, `?`는 문자 하나와 맞는다.
- 한 requirements 출처 안에서는 처음 맞는 `[[remote_sandbox_config]]` 항목이 이긴다.
- 어느 항목에도 맞지 않으면 맨 위의 `allowed_sandbox_modes`가 적용된다. 그래서 이름이 맞지 않는 러너는 자동으로 가장 엄격한 정책을 받는다.
- 항목은 그 호스트에서 허용되는 모드를 정할 뿐이다. 실제로 어떤 모드로 돌릴지는 여전히 실행 때 `-s`로 고른다.

### 보안 경계로 믿지 말 것

호스트 이름 매칭은 정책을 고르는 용도일 뿐 인증된 기기 증명이 아니다. 호스트 이름은 흉내 낼 수 있으므로 이것만 보안 경계로 의존하면 안 된다.

## 3. 두 방법을 합치기

두 방법은 역할이 다르다. `--ignore-user-config`와 `--ignore-rules`는 설정과 execpolicy 드리프트를 없애고, 호스트 패턴 정책은 환경마다 쓸 수 있는 샌드박스 모드의 상한을 정한다. 둘을 합치면 결정적이면서 환경을 의식하는 CI가 된다.
