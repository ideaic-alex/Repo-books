# 요약

15장의 열 가지 핵심 결론을 정리한다. 각 항목은 앞선 문서에서 자세히 다룬 내용을 한 문단으로 압축한 것이다.

---

## 1. 헤드리스 진입점

`codex exec`는 에이전트를 끝까지 돌리고 종료 코드로 결과를 알린다. CI에서 중요한 표면은 `--sandbox`, `--json`, `--output-schema`, `codex exec resume`이다. 승인 정책은 `-c approval_policy=...`로 넘긴다.

## 2. 결정적이고 격리된 실행

`--ignore-user-config`와 `--ignore-rules`는 개발자 설정과 프로젝트 execpolicy `.rules` 파일을 걷어 낸다. 뒤쪽 옵션은 서브에이전트에도 전달된다. 단, AGENTS.md는 여전히 읽힌다. 관리형 `requirements.toml`의 호스트 이름 패턴 정책은 환경별로 허용되는 샌드박스 모드의 상한을 정한다.

## 3. openai/codex-action으로 GitHub에 붙이기

이 액션은 CLI를 시크릿 주입과 출력 노출로 감싼다. 핵심 패턴은 세 가지다. PR 리뷰(`untrusted`), 테스트 생성(`on-request`), 의존성 업데이트(`on-request`).

## 4. codex exec로 GitLab에 붙이기

Duo Agent Platform(`@codex` 멘션), `.gitlab-ci.yml` 안의 `codex exec`(마커 기반 출력 추출), GitLab API 접근을 위한 MCP로 구성된다.

## 5. 자가 치유 성숙도 모델

Observer(읽기 전용, `untrusted`), Gatekeeper(`workspace-write`, `on-request`), Healer(`approval_policy=never`)의 세 단계다. Pipeline Doctor와 CI 자동 수정은 PR을 통해 자율 복구를 구현하고, 일회용 러너에서는 PR을 열기 전에 인라인 테스트로 검증한다. 대부분의 팀은 완전 자율을 주기 전에 Gatekeeper에서 몇 달 머물러야 한다.

## 6. CI 에이전트를 신뢰하지 않기

승인 모드를 피해 범위에 맞춘다. PR 내용은 프롬프트에 끼워 넣지 말고 파일로 쓴다. 토큰 범위를 줄이고 네트워크 접근을 샌드박스한다. Codex 액세스 토큰은 헤드리스 실행을 워크스페이스 신원, RBAC, 규정 준수 로그에 묶는다(17장 참고).

## 7. 구조화된 출력이 통합의 계약

`--json`과 `--output-schema`는 뒤 단계에 기계가 읽고 스키마로 검증된 결과를 준다. 토큰 사용량, 조향 메타데이터, 스레드 맥락은 비용 귀속과 감사를 돕는다. 비TTY 환경에서는 `write_stdin` 도구를 쓸 수 없다.

## 8. 프로젝트 통합 패턴이 리뷰를 키운다

`codex-pr-body` 같은 프로젝트 수준 스킬, `gh stack`과 에이전트 생성 설명을 결합한 스택 PR, AutoLoop의 한도 있는 최적화 순환은 모두 자동화를 대상 코드와 함께 버전 관리한다.

## 9. 오래 도는 세션과 원격 감독

WebSocket keepalive ping이 기업 프록시와 로드 밸런서 뒤에서 세션을 살려 둔다. 원격 연결은 개발자가 ChatGPT 모바일 앱에서 파이프라인이 일으킨 에이전트 동작을 승인하거나 거부하게 해 준다. 데스크톱 접근이 필요 없는 3단계 승인 체인이다.

## 10. 에이전트 PR 933,000건 이상의 증거

MSR 2026의 AIDev 데이터셋 연구는 실패가 코드 품질보다 워크플로 문제에서 주로 나온다고 본다. 리뷰어 이탈(38퍼센트)과 중복(23퍼센트)이 코드 수준 실패보다 크다. 그래서 중복 감지, 방치 모니터링, 원자적 변경 강제를 파이프라인에 넣어 설계한다.
