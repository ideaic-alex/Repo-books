# 요약

19장의 핵심 아홉 가지를 정리한다. 테스트 스위트를 믿을 만한 신호로 만드는 일부터, 단위 테스트를 넘어 에이전트 역량을 측정하는 평가 하니스까지 이어진다.

---

## 1. 장의 핵심 아홉 가지

1. **에이전트 친화적 스위트의 세 성질.** 격리돼 있고(외부 의존 없음), 결정적이며(매번 같은 결과), 명령 하나로 돌릴 수 있어야 한다. 에이전트는 진짜 실패와 잡음을 구별하지 못하므로, 가끔 깨지는 테스트는 에이전트에게 유난히 해롭다.
2. **모든 테스트를 격리한다.** 시드 픽스처, 메모리 내 서비스, 데이터베이스 트랜잭션 롤백, 환경 변수 주입으로 테스트를 격리하고 실행 순서에 의존하지 않게 만든다.
3. **TDD는 에이전트 피드백 루프와 잘 맞는다.** 실패하는 테스트를 먼저 쓰고 Codex CLI에 "테스트 파일을 고치지 말고 통과시켜라"라며 넘긴다. 미리 쓴 실패 테스트는 모호함 없는 실행 가능한 완료 기준이 된다.
4. **TDD를 AGENTS.md에 적는다.** '테스트를 수정하지 말 것' 제약을 명시한 팀 관례로 만든다. 더해 둘 수 있는 가장 값진 가드레일 중 하나다.
5. **'테스트 통과'는 증명이 아니라 대리 지표다.** 린트, 타입 검사, 테스트를 단일 게이트 명령으로 묶는다. 줄 커버리지보다 분기 커버리지 기준이 더 의미 있는 대리 지표다.
6. **믿기 전에 스위트를 감사한다.** 에이전트 피드백 신호로 쓰기 전에 Codex CLI로 스위트를 점검한다. 테스트 안의 네트워크 호출, 하드코딩된 절대 경로, sleep() 호출, 전역 상태 변경을 믿을 만하게 찾아 준다.
7. **4개 파일 메모리 패턴이 장기 상태를 나른다.** PLAN.md, PROGRESS.md, DISCOVERIES.md, DECISIONS.md가 체크포인트처럼 이어받을 수 있는 진행 상황, 감사 가능한 결정 기록, 세션 바깥에서 복구할 수 있는 상태를 준다. 여러 세션에 걸친 평가 작업에 쓴다.
8. **품질은 단위 테스트 너머에서 확인한다.** 통합 테스트는 시스템 수준 검증, 속성 기반 테스트는 구조적 불변식, 표본 추출 평가는 정성적 결과가 나오는 긴 작업을 맡는다.
9. **최소 평가 하니스로 역량을 추적한다.** 프롬프트, 준비, 채점, 정리라는 네 요소로 에이전트 역량을 재고, 모델이나 설정이 바뀔 때 회귀를 잡아낸다.

## 2. 함께 기억할 것

- 평가 하니스는 에이전트의 피드백 루프 밖에 둔다. 안에 두면 하니스를 통과하는 쪽으로 최적화될 수 있다.
- 에이전트는 사람보다 모킹을 더 많이 쓴다. AGENTS.md의 모킹 정책, 모킹 비율 훅, 게이트의 통합 테스트로 균형을 잡는다.
- 코드 리뷰 에이전트는 합쳐서도 문제의 약 40%만 잡는다. 체크리스트를 AGENTS.md에 넣어 유지보수성 영역을 보강한다.
- MCP 서버 상태 점검은 에이전트 수준 평가보다 먼저 돌린다.
