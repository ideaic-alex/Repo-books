# 에이전트 실행을 위한 테스트 설계

테스트가 에이전트 친화적이려면 성질만 갖춘 것으로는 부족하고, 구체적인 설계 패턴이 필요하다. 이 문서는 고정 데이터(시드 픽스처)와 메모리 내 서비스, 테스트 격리 패턴 세 가지, 그리고 환경 변수를 에이전트에게 자동으로 주입하는 방법을 정리한다.

---

## 1. 훅과의 관계

9장에서 다룬 훅(특정 시점에 자동으로 실행되는 스크립트)과 이 장은 짝을 이룬다. 파일을 쓸 때마다 PostToolUse 훅이 `pytest -q --tb=line`을 돌리게 하면, 테스트 스위트가 세션 내내 살아 있는 피드백 신호가 된다. 훅은 방아쇠를 제공하고, 이 장은 그 방아쇠가 쓸모 있도록 테스트 스위트를 어떻게 만들지 알려 준다.

## 2. 시드 픽스처와 모킹 서비스

에이전트용 테스트는 실제 서비스를 다음 두 가지로 대체해야 한다.

**시드 픽스처.** 스위트가 시작될 때 불러오고 실행 사이에 초기화하는 결정적 데이터 묶음이다. 아래는 pytest에서 세션 범위 픽스처로 데이터베이스를 한 번 채우는 예다.

```python
@pytest.fixture(scope="session", autouse=True)
def seed_database(test_db):
    test_db.execute_file("tests/fixtures/seed.sql")
    yield
    test_db.rollback()
```

**메모리 내 서비스.** SQL 저장소에는 SQLite 메모리 모드, 키-값 저장소에는 dict로 만든 가짜, 프로세스 안의 큐를 쓴다. 실제 서비스보다 빠르고 네트워크도 필요 없다. 지원하지 않는 동작을 코드가 하면 시끄럽게 실패하므로 통합 버그가 일찍 드러난다는 장점도 있다.

## 3. 테스트 격리 패턴

모든 테스트는 어떤 순서로 돌려도 되고, 알려진 상태에서 시작하며, 부작용을 남기지 않아야 한다. 이를 강제하는 패턴은 세 가지다.

- **데이터베이스 트랜잭션 롤백.** 테스트마다 트랜잭션으로 감싸고 끝날 때 되돌린다. 테이블을 비우고 다시 채우는 것보다 훨씬 빠르고, 격리도 완벽하다.
- **환경 변수 복원.** 테스트가 환경 변수를 바꿔야 한다면 정리 단계에서 원래대로 돌려 놓는다.
- **모듈 상태 초기화.** 연결 풀이나 싱글턴처럼 초기화 때 부작용이 있는 모듈은 테스트 프레임워크의 모듈 리셋 기능으로 테스트마다 새 상태를 받는다.

환경 변수 복원은 jest에서 이렇게 쓴다.

```javascript
let originalEnv;
beforeEach(() => { originalEnv = { ...process.env }; });
afterEach(() => { process.env = originalEnv; });
```

## 4. 에이전트에게 환경 변수 주입하기

에이전트는 운영 데이터베이스나 실제 API 키가 아니라 통제된 환경에서 테스트를 돌려야 한다. 환경 변수 주입이 이를 해결하는데, 핵심은 자동이어야 한다는 점이다.
AGENTS.md에는 이렇게 적는다.

```markdown
## Running tests
Always run tests with `npm test`. Do not run tests against the production
database.
The test configuration is loaded automatically from `.env.test` when `npm
test` is invoked.
Do not modify `.env.test` unless the task specifically requires it.
```

그리고 package.json의 test 스크립트가 설정 파일을 알아서 불러오게 한다.

```json
{
  "scripts": {
    "test": "dotenv -e .env.test -- jest"
  }
}
```

이렇게 하면 에이전트는 `npm test`만 실행해도 올바른 환경에서 도는 결과를 받는다. `.env.test`의 존재를 몰라도 된다.
