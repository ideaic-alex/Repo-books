# 연습 문제

19장 끝의 연습 문제 네 개를 풀어 쓴 것이다. 각 문제마다 무엇을 해야 하는지와 풀이 방향을 덧붙였다.

---

## 1. 내 테스트 스위트 감사하기

**문제.** 이 장의 '테스트 스위트 감사' 프롬프트를 내 프로젝트의 테스트에 적용한다. 실행은 untrusted 승인 모드와 읽기 전용 샌드박스로 한다. 나온 문제 목록에서 에이전트 신뢰성에 미치는 영향이 가장 큰 세 가지를 골라 고치고, 감사를 다시 돌려 그 문제들이 사라졌는지 확인한다.

**풀이 방향.** `-a untrusted -s read-only`로 돌려서 보고서만 받는다. 우선순위는 네트워크 호출, 절대 경로, sleep() 순으로 매기면 무난하다. 고친 뒤 같은 프롬프트로 재감사해서 목록에서 빠졌는지 대조한다.

## 2. 최소 평가 하니스 만들기

**문제.** 프로젝트의 최근 백로그에서 뽑은 작업 세 개 이상으로 하니스를 만든다. 작업마다 테스트 스위트를 돌려 종료 코드를 돌려주는 grade.sh를 쓰고, `codex exec`로 각 작업을 돌려 통과·실패를 기록한다. 그다음 활성 모델을 바꿔서(예: gpt-5.5에서 gpt-5.4-mini로) 다시 돌린다. 모델에 따라 결과가 달라진 작업을 기록하고, 그 데이터를 6장의 모델 라우팅 결정에 활용한다.

**풀이 방향.** 작업마다 prompt.txt, setup.sh, teardown.sh, grade.sh를 만들고 run_eval.sh로 묶는다. 결과 폴더에 모델별 score.txt가 쌓이게 하고, 모델 간 점수가 다른 작업을 표로 비교한다. 작은 모델로 충분한 작업 유형이 보이면 그쪽으로 라우팅하는 근거가 된다.

## 3. 버그 수정에 TDD 적용하기

**문제.** 지금 프로젝트에서 운영이나 기능 브랜치에서 실패하고 있는 실제 버그 하나를 고른다. 고치기 전에 버그를 재현하는 테스트를 쓰고, 현재 코드에서 실패하는지 확인한다. 그런 뒤 Codex CLI에 "이 버그를 고쳐라. `<파일>::<테스트 이름>` 테스트가 재현한다. 테스트 파일은 수정하지 말고 통과시켜라"라고 맡긴다. 수정 내용을 리뷰하고, 테스트가 통과하는지 확인하고, 전체 스위트로 회귀를 점검한다. 이후 커밋에서 버그가 다시 나타났는지, 테스트가 그것을 잡았는지도 기록한다.

**풀이 방향.** 테스트가 임포트 오류가 아니라 단언에서 실패하는지 먼저 확인한다. 수정 후 diff에서 테스트 파일이 바뀌지 않았는지 본다. 장기적으로는 이 테스트가 회귀 방지 장치로 남았는지를 관찰한다.

## 4. 4개 파일 메모리 패턴 구현하기

**문제.** 최소 세 개 파일을 바꿔야 하고 직접 하면 두 시간 이상 걸릴 만한 중간 복잡도의 기능을 고른다. `.codex/` 디렉터리를 만들고, 기능을 구체적인 단계 다섯 개 이상으로 쪼갠 PLAN.md를 쓴다. 각 단계에는 명시적인 파일 경로와 검증 기준을 적는다. AGENTS.md에는 단계가 끝날 때마다 PROGRESS.md를 갱신하라는 관례를 추가한다. Codex CLI 세션으로 처음 두 단계를 진행시킨 뒤 중간에 끊는다. PROGRESS.md가 완료한 작업을 정확히 반영하는지 확인하고, 새 세션으로 재개해서 이전 세션이 멈춘 곳에서 이어받는지 검증한다.

**풀이 방향.** PLAN.md의 단계마다 '완료 조건'을 적어 두면 PROGRESS.md 갱신이 명확해진다. 새 세션에서는 프롬프트에 별다른 설명 없이 시작해 보고, AGENTS.md 참조만으로 3단계부터 이어가는지 본다. 이어받지 못한다면 PROGRESS.md에 현재 상태와 막힌 점이 충분히 적혔는지 점검한다.
