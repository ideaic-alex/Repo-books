# 인증 방법

설치를 마쳤으면 Codex CLI가 OpenAI를 쓸 수 있도록 인증해야 한다. 어떤 방식으로 OpenAI에 접근하느냐에 따라 길이 세 가지로 나뉜다. ChatGPT 구독, API 키, 기업용 설정이다. 이 문서는 세 방식의 절차와 주의점을 비교해서 설명한다.

---

## 1. 길 1: ChatGPT 구독 (디바이스 코드 방식)

ChatGPT 구독으로 쓰는 경우의 가장 간단한 방법이다.

```
codex login
```

명령을 실행하면 CLI가 짧은 코드를 출력하고 URL을 연다. 브라우저에서 로그인하고 그 코드를 입력하면 된다. 그러면 Codex가 자격 증명 토큰을 `~/.codex/auth.json`에 저장한다. 이 파일은 소유자만 읽고 쓸 수 있도록 권한이 걸린다.

이 방식은 Codex 사용량이 ChatGPT Plus, Pro 구독의 한도 안에서 처리된다. 한도는 OpenAI 가격 페이지에 나와 있다.

## 2. 길 2: API 키

```
export OPENAI_API_KEY="sk-..."
```

쉘을 새로 열어도 유지되려면 이 줄을 쉘 프로필(`~/.bashrc` 같은 시작 파일)에 넣는다. API 키를 쓰면 토큰 사용량만큼 요금이 부과된다. 그래서 세션 하나에 비용이 어느 정도 드는지 감이 올 때까지는 사용 한도(쿼터)를 낮게 걸어 두고 시작하라고 책은 권한다.

## 3. 길 3: 기업용 설정

기업 환경에서는 `~/.codex/config.toml`을 직접 편집한다. 책의 예시는 Azure를 쓰는 조직을 가정한다.

```
api_base_url = https://your-org.openai.azure.com/...
api_key_source = "azure_ad"
```

여기에 덧붙일 내용이 두 가지 있다.

- **관리자 강제 설정.** 관리자가 사용자 설정과 무관하게 강제해야 하는 값은 `requirements.toml`을 쓴다.
- **일회성 덮어쓰기.** 명령줄에서 한 번만 값을 바꾸려면 `-c` / `--config` 플래그를 쓰고, 키는 점(.) 표기법으로 적는다. 예를 들어 `codex -c api_base_url=https://... exec "your task"` 형태다.

기업 배포는 8장에서 자세히 다룬다.

## 4. 세 방식 비교

| 구분 | 길 1: 구독 | 길 2: API 키 | 길 3: 기업 설정 |
|---|---|---|---|
| 방법 | `codex login` | `OPENAI_API_KEY` 환경 변수 | `config.toml` 편집 |
| 자격 증명 위치 | `~/.codex/auth.json` | 쉘 환경 변수 | 조직 설정(예: Azure) |
| 비용 | 구독 한도 안 | 토큰당 과금 | 별도 안내 없음 |
| 적합한 경우 | 개인이 구독으로 쓸 때 | API로 직접 쓸 때 | 관리형 배포 |

## 5. 기억할 점

- 어느 방식이든 인증이 끝나야 첫 세션을 시작할 수 있다.
- API 키 방식은 쓴 만큼 돈이 나가므로 초반에 한도부터 거는 습관이 안전하다.
- 자동화(codex exec)에 쓰는 환경 변수 `CODEX_API_KEY`나 `CODEX_ACCESS_TOKEN`은 '설정 위치와 환경 변수' 문서에서 정리한다.
