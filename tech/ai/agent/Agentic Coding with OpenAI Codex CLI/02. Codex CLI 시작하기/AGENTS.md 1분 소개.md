# AGENTS.md 1분 소개

AGENTS.md는 저장소에 두는 일반 마크다운 파일로, Codex CLI가 세션을 시작할 때마다 자동으로 읽는다. 이 문서는 AGENTS.md가 무엇을 담는 파일인지, 최소 예시는 어떤 모양인지, 여러 위치의 파일이 어떻게 합쳐지는지 정리하고, 이 장이 마무리하며 3장으로 넘기는 이야기를 덧붙인다.

---

## 1. AGENTS.md가 하는 일

저장소 루트에 두면 Codex CLI가 세션 시작 때 읽는다. 여기에는 에이전트가 소스 코드만 봐서는 알아낼 수 없는 프로젝트 고유의 지식을 적는다.

- 테스트 명령어
- 패키지 매니저
- 따라야 할 규칙(컨벤션)
- 건드리면 안 되는 파일

앞서 첫 주 실수 3에서 본 것처럼, 이게 없으면 에이전트는 어떤 테스트 명령어를 돌릴지, 어떤 규칙을 지킬지 추측해야 한다.

## 2. 최소 예시

```
# Project: Payment Service
## Build and test
- Install: `npm install`
- Test: `npm test`
## Conventions
- async/await throughout; no `.then()` chains
- Monetary amounts are integers (pence), never floats
## Do not modify
- `src/legacy/` — deprecated, read-only
- Any file matching `*.generated.ts`
```

결제 서비스 프로젝트를 가정한 예시다. 구성을 풀어 보면 이렇다.

- **빌드와 테스트.** 설치는 `npm install`, 테스트는 `npm test`다.
- **컨벤션.** 비동기 코드는 전부 async/await로 쓰고 `.then()` 체인은 쓰지 않는다. 금액은 소수(float)가 아니라 정수(페니 단위)로 다룬다. 부동소수점 오차를 피하려는 규칙이다.
- **수정 금지.** `src/legacy/`는 더 이상 쓰지 않는 코드라 읽기 전용이다. `*.generated.ts`에 맞는 파일은 자동 생성물이라 손대지 않는다.

짧아도 이 정도면 에이전트가 가장 자주 하는 추측 세 가지(어떻게 테스트하나, 어떤 스타일인가, 어디를 건드리면 안 되나)를 막아 준다.

## 3. 파일이 합쳐지는 방식

AGENTS.md는 여러 위치에 둘 수 있고, 서로 합성된다.

| 위치 | 역할 |
|---|---|
| `~/.codex/AGENTS.md` | 개인 기본값 |
| 저장소 루트 | 프로젝트 기본값 |
| 하위 디렉터리 | 위 둘을 덮어쓸 수 있음 |

경로를 따라 더 안쪽으로 갈수록 지시가 더 구체적이라는 원칙이다. 한 서비스 폴더에만 해당하는 규칙을 그 폴더의 AGENTS.md에 두면 된다.

## 4. 이 책에서의 위치

AGENTS.md는 책 전체에서 계속 언급된다. 4장이 이것만 다루며, 무엇을 넣고 무엇을 넣지 말아야 하는지, 프로젝트가 변해 갈 때 쓸모를 유지하는 방법을 설명한다. 연습 문제 2-2에서는 이 장의 최소 예시를 바탕으로 직접 하나를 만들어 본다.

## 5. 이 장을 마치며

이제 Codex CLI가 설치되어 있고, 인증된 세션이 있고, 실제 저장소에서 첫 실행도 해 봤고, 설정과 프로젝트 맥락이 어디에 있는지도 안다. 책은 이것을 "바닥"이라고 부른다. 이후의 모든 내용이 이 위에 쌓인다.

다음으로 효과가 큰 기술은 프롬프트 작성이다. Codex CLI는 구체적으로 쓸수록 보답하는 도구다. 모호한 프롬프트가 모호한 답을 만드는 게 아니라, 몇 분짜리 실행을 일으켜서 예상치 못한 파일까지 건드릴 수 있기 때문이다. 3장은 효과적인 프롬프트의 네 가지 요소, 실행 도중 세션을 조종하는 슬래시 명령, 흔한 작업별로 잘 통하는 패턴을 다룬다. 사소하지 않은 다음 세션을 시작하기 전에 3장을 읽어 두라는 것이 이 장의 마지막 권유다.
