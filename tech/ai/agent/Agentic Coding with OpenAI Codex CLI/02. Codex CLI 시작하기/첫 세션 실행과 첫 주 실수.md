# 첫 세션 실행과 첫 주 실수

앞에서 본 시연을 이번에는 직접 해 본다. 이 문서는 퀵스타트 저장소를 클론해서 Codex CLI를 띄우고, 같은 과제를 입력하고, 무엇이 나오는지 기대치를 맞추는 과정을 다룬다. 이어서 대부분의 사용자가 첫 주에 저지르는 세 가지 실수와 피하는 방법을 정리한다.

---

## 1. 첫 세션 직접 해 보기

저장소를 클론하고, 폴더로 들어가서 Codex CLI를 실행한다.

```
git clone https://github.com/danielvaughan/codex-quickstart-example
cd codex-quickstart-example
codex
```

프롬프트가 뜨면 시연에서 쓴 과제를 그대로 입력한다.

```
Find the bug in main.js and fix it. Run the tests before and after to
confirm the fix.
```

## 2. 어떤 모습이 나와야 하나

시연에서 본 것과 비슷한 흐름이 나오면 정상이다.

- 파일을 읽는다.
- 테스트를 돌린다.
- 수정을 한 번 이상 한다.
- 틀린 방향으로 갔다가 스스로 되돌릴 수도 있다.
- 마지막에는 테스트가 모두 통과한다.

결과는 파일 시스템에 실제로 반영된 diff이고, 통과한 테스트로 확인된 것이다. 사람이 일일이 적용해야 하는 제안이 아니다. 이게 대화형 챗봇과 에이전트의 가장 큰 차이다.

## 3. 에이전트가 승인을 물어봐도 고장이 아니다

에이전트가 파일을 읽거나 명령을 실행하기 전에 허락을 묻는 경우가 있다. 이것은 오류가 아니라 승인 모드가 동작하는 것이다. 승인 모드의 종류와 기본값을 바꾸는 방법은 5장에서 다룬다.

## 4. 첫 주에 하기 쉬운 세 가지 실수

거의 모두가 첫 주에 비슷한 실수를 한다. 심각한 것은 없지만, 미리 알고 피하는 쪽이 겪으면서 배우는 것보다 빠르다.

### 4-1. 챗봇처럼 대하면서 과제를 모호하게 주는 것

"인증 코드를 정리해 줘" 같은 지시는 에이전트가 확인할 기준을 주지 않는다. 그러면 에이전트가 자기 나름대로 '정리'를 정의하고 몇 분 동안 그 방향으로 달려간다. 해결책은 완료 기준을 적는 것이다. 어느 파일에서, 무엇을 바꾸고, 어떤 테스트가 통과해야 하는지를 이름까지 적는다. 이 주제는 3장 전체가 다룬다.

### 4-2. 마음에 안 드는 첫 수정을 바로 끊어 버리는 것

시연에서 봤듯이 첫 수정은 탐침일 때가 많다. 자기가 하지 않을 법한 행동을 한다고 에이전트를 곧바로 중단하면, 테스트하고 고치는 순환이 사라져서 에이전트의 장점이 없어진다. 한 턴이 끝날 때까지 기다린 다음 diff를 읽는다.

### 4-3. 테스트도 AGENTS.md도 없이 돌리는 것

테스트가 없으면 에이전트는 성공했는지 알 수 없다. AGENTS.md가 없으면 어떤 테스트 명령어를 돌려야 하는지, 어떤 규칙을 따라야 하는지 모르기 때문에 둘 다 추측한다. 이 장 뒤에서 설명하는 최소 AGENTS.md를 만드는 데 드는 10분은 첫 실전 세션에서 바로 본전을 뽑는다.

## 5. 세 실수 요약

| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| 모호한 지시 | 확인 기준이 없어 에이전트가 제멋대로 해석한다 | 파일, 변경 내용, 통과할 테스트를 적는다 |
| 첫 수정을 중단 | 테스트-수정 순환이 끊긴다 | 한 턴이 끝난 뒤 diff를 읽는다 |
| 테스트와 AGENTS.md 없음 | 성공 여부와 규칙을 추측해야 한다 | 빠른 테스트 명령어와 최소 AGENTS.md를 준비한다 |
