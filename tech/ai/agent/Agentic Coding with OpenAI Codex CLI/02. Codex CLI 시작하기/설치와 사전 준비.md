# 설치와 사전 준비

Codex CLI를 쓰려면 먼저 실행 환경을 맞추고, 설치 방법을 고르고, 설치가 잘 됐는지 확인해야 한다. 이 문서는 네 가지 실행 표면(surface) 중 CLI의 위치, 필요한 Node.js 버전, 운영체제별 지원 상황, 설치 방법 세 가지, 확인 명령어, 쉘 자동 완성 설정까지 한 번에 정리한다.

---

## 1. 네 가지 표면, 하나의 에이전트

Codex CLI는 같은 에이전트를 공유하는 네 가지 표면 가운데 하나다. 나머지는 데스크톱 앱, IDE 확장, 클라우드다. 설정, 스킬, 메모리는 네 표면에 걸쳐 이어진다. 그중 CLI는 기반이 되는 표면이고, 오픈 소스이며, 로컬에서 먼저 도는 방식이다. 이 책은 CLI를 중심으로 다룬다. 네 표면 구조는 OpenAI 개발자 문서에 설명되어 있다.

## 2. 사전 준비

### 2-1. Node.js 22 이상

Codex CLI는 Node.js 22.0.0 이상이 필요하다. macOS와 Linux에서는 nvm이나 fnm으로 Node 버전을 관리하면 편하다.

```
fnm install 22 && fnm use 22
node --version # v22.x.x or later
```

### 2-2. 운영체제 지원

- **macOS:** 13 Ventura 이상이 필요하다. Apple Silicon과 Intel 모두 지원한다.
- **Linux:** 지원한다. 샌드박스(명령 실행 범위를 제한하는 격리 장치)는 bubblewrap(bwrap) 기반이다. 따로 설치할 필요가 없다. Codex가 번들 사본을 갖고 있어서 자동으로 쓰고, PATH에 더 새로운 시스템 bwrap이 있을 때만 그것을 우선한다.
- **Windows:** 네이티브(AppContainer 샌드박스)와 WSL2 두 방식이 있다. 책을 쓴 시점에 네이티브 지원은 실험적이지만 동작한다. 실무용으로는 WSL2를 권한다. 네이티브 Linux 설치와 같은 커널 수준 샌드박스를 쓰기 때문이다.
- **WSL1:** 샌드박스에 필요한 사용자 네임스페이스(user namespace)를 만들 수 없어서 지원하지 않는다.

## 3. 설치 방법

### 3-1. npm (권장)

```
npm install -g @openai/codex
codex --version
```

권한 오류가 나면 npm이 홈 폴더 안의 디렉터리를 쓰도록 바꾼다. `npm config set prefix ~/.npm-global`을 실행하고, `~/.npm-global/bin`을 PATH에 추가한다.

Codex CLI에는 업데이트 명령이 내장되어 있다.

```
codex update # self-update via the package manager used to install
```

`update` 하위 명령은 설치 방식(npm, Homebrew, 바이너리)을 알아내서 알맞은 갱신 방법을 실행한다. 수동으로 올리고 싶다면 `npm install -g @openai/codex@latest`를 쓴다.

### 3-2. Homebrew (macOS, Linux)

```
brew install --cask codex
```

Homebrew cask는 미리 빌드된 바이너리를 바로 설치하므로 Node.js가 필요 없다. 업데이트는 평소처럼 `brew upgrade`로 한다.

### 3-3. 바이너리 직접 내려받기

npm도 Homebrew도 맞지 않는 환경이라면 GitHub 릴리스 페이지에서 미리 빌드된 바이너리를 받는다. 자기 플랫폼용 압축 파일을 내려받아 풀고, 바이너리 이름을 codex로 바꿔서 PATH에 있는 위치에 둔다.

```
tar xzf codex-aarch64-apple-darwin.tar.gz
mv codex-aarch64-apple-darwin /usr/local/bin/codex
chmod +x /usr/local/bin/codex
```

## 4. 설치 확인

```
codex --version
codex --help
```

`--version`은 설치된 버전을 보여 준다. `--help`는 모든 하위 명령과 플래그를 나열하고, CLI가 응답하는지도 확인해 준다. 연습 문제 2-1에서 이 도움말을 활용한다.

## 5. 쉘 자동 완성

탭 자동 완성이 있으면 플래그와 하위 명령을 훨씬 쉽게 찾는다. Codex CLI는 bash, zsh, fish용 완성 파일을 만들 수 있고, PowerShell과 Elvish도 지원한다. 쓰는 쉘에 맞춰 완성 파일을 만든다.

```
# bash
mkdir -p ~/.local/share/bash-completion/completions
codex completion bash > ~/.local/share/bash-completion/completions/codex
# zsh
mkdir -p ~/.zsh/completions
codex completion zsh > ~/.zsh/completions/_codex
# fish
codex completion fish > ~/.config/fish/completions/codex.fish
```

bash와 fish는 위 디렉터리에 있는 파일을 자동으로 읽는다. zsh만 한 단계가 더 필요하다. `~/.zshrc`에서 `compinit`보다 앞서 완성 디렉터리를 fpath에 추가한다.

```
fpath=(~/.zsh/completions $fpath)
autoload -Uz compinit
compinit
```

`codex completion` 하위 명령이 지원하는 쉘은 bash, zsh, fish, powershell, elvish다.

## 6. 정리

| 항목 | 내용 |
|---|---|
| Node.js | 22.0.0 이상 (Homebrew cask나 바이너리는 불필요) |
| macOS | 13 Ventura 이상, Apple Silicon과 Intel |
| Windows | 네이티브(실험적) 또는 WSL2(권장), WSL1은 불가 |
| Linux | 번들 bwrap으로 샌드박스, 별도 설치 불필요 |
| 설치 | npm, Homebrew cask, 바이너리 중 선택 |
| 확인 | codex --version, codex --help |
