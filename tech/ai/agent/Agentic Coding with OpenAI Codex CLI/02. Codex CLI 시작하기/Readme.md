# Codex CLI 시작하기

1장에서 Codex CLI가 무엇이고 왜 에이전트 방식이 중요한지 살펴봤다. 2장은 실용적인 질문에 답한다. 어떻게 설치하고, 인증하고, 실제 첫 세션을 돌리는가. 이 장을 마치면 동작하는 설치 환경과, 이후 내용을 따라갈 자신감이 생긴다.

장은 실제 저장소에서 테스트 실패를 고치는 첫 세션을 먼저 보여 주고, 설치와 인증, 직접 해 보기, 실행 방식, 설정, AGENTS.md로 이어진다. 마지막에는 요약과 연습 문제가 있다.

---

## 1. 핵심 요점

- CLI는 CLI, 데스크톱 앱, IDE 확장, 클라우드 네 표면 중 하나이고, 같은 에이전트와 설정, 스킬, 메모리를 공유한다.
- 에이전트는 바꾸기 전에 테스트부터 돌리고, 첫 수정이 틀려도 테스트 결과를 보고 스스로 고친다. 중간 수정이 아니라 테스트 결과와 마지막 요약, diff를 봐야 한다.
- Node.js 22 이상이 필요하고, macOS 13 이상, Linux, Windows(WSL2 권장)에서 쓴다. 설치는 npm, Homebrew cask, 바이너리 중에서 고른다.
- 인증은 ChatGPT 구독(`codex login`), API 키(`OPENAI_API_KEY`), 기업용 설정 세 가지다.
- 첫 주 실수는 모호한 지시, 첫 수정 중단, 테스트와 AGENTS.md 없이 쓰는 것이다.
- `codex`는 대화형 REPL, `codex exec`는 스크립트와 CI/CD용 비대화형 실행이다.
- 설정은 내장 기본값, `~/.codex/config.toml`, 프로젝트 `.codex/config.toml`, 명령줄 플래그 순으로 해석되고 뒤가 이긴다.
- AGENTS.md는 테스트 명령어, 컨벤션, 수정 금지 파일을 적는 프로젝트 규칙 파일이다.
