# 연습 문제

16장 끝의 연습 문제 세 개다. 문제 취지를 풀어 쓰고, 어디서부터 손대면 좋을지 풀이 방향을 한두 문장씩 덧붙였다.

---

## 1. 민감한 경로 읽기 막기

**문제.** 도구 호출 인자에 `**/.ssh/**` 또는 `*.pem`에 맞는 경로가 들어 있으면 그 호출을 막는 PreToolUse 훅을 작성한다. 에이전트에게 내 SSH 키를 읽어 보라고 시켜서 실제로 막히는지 확인한다.

**풀이 방향.** '프롬프트 인젝션 공격과 방어' 문서의 훅 뼈대에서 패턴 목록만 경로 패턴으로 바꾸면 된다. glob 표기를 그대로 정규식에 쓰면 맞지 않으니 정규식으로 옮기고, 거부할 때는 `permissionDecision = "deny"`와 사유를 출력한다. 시험은 에이전트에게 SSH 키를 읽어 보라고 시켜서 훅이 호출을 거부하는지 확인한다.

## 2. CI 파이프라인 보안 강화

**문제.** CI 파이프라인용으로 완전한 보안 자세를 구성한다. 샌드박스 모드, 디렉터리 제한, 읽기 거부 규칙, 네트워크 허용 목록, CI 격리 플래그가 모두 들어가야 한다. 에이전트를 실행해, 허용 범위 밖의 행동을 시켜 보면서 제한이 하나하나 작동하는지 확인한다.

**풀이 방향.** 샌드박스는 read-only 또는 workspace-write, 디렉터리는 `[permissions.ci]` 같은 최소 프로필, 읽기 거부와 네트워크는 관리형 requirements.toml, 실행은 `--ignore-user-config --ignore-rules`로 구성한다. 검증은 제한마다 위반하는 요청을 하나씩 만든다. 예를 들어 허용되지 않은 디렉터리에 쓰기, .env 읽기, 허용 목록 밖 도메인 호출을 시켜 보고 모두 막히는지 본다.

## 3. 자동 리뷰 신뢰 사다리 기준선 잡기

**문제.** 기존 프로젝트에서 자동 리뷰(`approvals_reviewer = "auto_review"`)를 켜고 L0(관찰) 단계로 돌린다. L0에서는 결정을 기록만 하고 강제하지 않는다. 대표적인 작업 열 개를 실행한 뒤 기록된 결정을 살펴보고, L2(관문)였다면 막혔을 도구 호출을 찾아낸다. L2로 올리기 전에 어떤 정책 조정을 할지 초안을 쓴다.

**풀이 방향.** 열 개 작업은 평소 실제로 하는 일을 골고루 섞어야 기준선이 믿을 만하다. 기록에서 위험도가 높게 분류된 호출을 모아, 정당한 작업을 막을 법한 것은 정책 예외나 문구 조정 후보로, 막혀야 마땅한 것은 그대로 두는 식으로 나눈다. 이 결과가 L1, L2로 올라갈 때의 근거 데이터가 된다.
