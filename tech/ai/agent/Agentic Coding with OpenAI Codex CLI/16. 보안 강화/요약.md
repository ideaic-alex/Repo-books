# 요약

16장의 내용을 여덟 가지로 압축한 정리다. 각 항목 끝에는 자세한 설명이 있는 문서를 적었다.

---

## 1. 핵심 정리

1. **에이전트의 위협 모델은 다르다.** 일반 애플리케이션은 데이터베이스를 바깥의 요청에서 지킨다. 에이전트는 위험에 놓인 자산이 더 넓고, 조작된 요청이 아니라 콘텐츠로 공격받으며, 설정을 잘못하면 스스로 위협이 되기도 한다. (에이전트 위협 모델)

2. **프롬프트 인젝션이 대표 위협이다.** 에이전트 시스템에만 있는 위협 중 영향이 가장 크고, 단일 통제로는 없앨 수 없다. 검증 훅, 출력 리뷰, 좁은 컨텍스트, 권한 제한을 겹쳐 쌓는 심층 방어가 필요하다. (프롬프트 인젝션 공격과 방어)

3. **파일 시스템 제한이 피해 범위를 줄인다.** 읽기 거부 정책, 디렉터리 범위 제한, 운영체제 수준 샌드박스가 에이전트가 건드릴 수 있는 곳을 좁힌다. 커널 수준 강제는 인젝션으로도 우회할 수 없다. (샌드박스와 파일 시스템 제한)

4. **자동 리뷰에 신뢰 사다리를 더한다.** 자동 리뷰어(`approvals_reviewer = "auto_review"`)가 위험한 행동을 평가한다. 저자가 제안한 L0~L3 사다리(관찰, 조언, 관문, 강제)로 텔레메트리를 보며 보정하면서 도입한다. L0에서 시작해 리뷰 주기마다 한 단계씩 올린다. 사다리는 도입 프레임워크이지 Codex에 내장된 기능이 아니다. (자동 리뷰와 신뢰 사다리)

5. **CI 격리가 재현 가능한 실행을 만든다.** `--ignore-user-config`와 `--ignore-rules`가 상주하는 사용자 설정과 execpolicy `.rules` 파일을 걷어 낸다. AGENTS.md와 관리형 requirements.toml은 계속 로드되므로 완전히 밀폐된 것이 아니라 재현 가능한 수준이다. (CI 격리와 네트워크 허용 목록)

6. **네트워크 허용 목록은 기본 거부다.** 관리형 `[experimental_network]`에 `managed_allowed_domains_only = true`를 걸면 유출을 막고, 주입된 페이로드가 공격자 호스트에 닿지 못하게 한다. (CI 격리와 네트워크 허용 목록)

7. **시크릿 관리에는 세 규칙이 있다.** 설정에 시크릿을 저장하지 않고, 실행 시점에 환경 변수로 주입하며, 상주 배포에서는 시크릿 매니저의 짧은 수명 자격 증명을 쓴다. (시크릿 관리)

8. **감사 로그는 컴플라이언스 프레임워크와 이어진다.** 구조화된 PostToolUse 훅이 내보내는 이벤트는 SOC 2, GDPR, ISO 27001의 통제 범주에 대응해, 컴플라이언스 팀에 문서화된 출발점을 준다. (감사와 컴플라이언스)
