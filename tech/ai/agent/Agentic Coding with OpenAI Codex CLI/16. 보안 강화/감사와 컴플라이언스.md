# 감사와 컴플라이언스

사고가 났을 때 무슨 일이 있었는지 증명하려면 에이전트의 행동이 구조화된 기록으로 남아 있어야 한다. 이 문서는 PostToolUse 훅으로 만드는 감사 로그, Codex CLI 통제와 컴플라이언스 프레임워크의 대응, 데이터 거주지 요건에 대응하는 방법을 다룬다.

---

## 1. 구조화된 감사 로그

Codex CLI는 모든 도구 호출에 대해 구조화된 이벤트를 낸다. PostToolUse 훅이 이 이벤트를 조직의 감사 형식으로 바꿔 준다.

```python
# hooks/audit_logger.py
import json, sys, datetime
payload = json.load(sys.stdin)
tool_response = payload.get("tool_response", {})
audit_event = {
    "timestamp": datetime.datetime.now(datetime.UTC).isoformat(),
    "event_type": "agent_tool_execution",
    "tool": payload.get("tool_name"),
    "session_id": payload.get("session_id"),
    "exit_code": tool_response.get("exit_code")
        if isinstance(tool_response, dict) else None,
}
with open("/var/log/codex-audit.jsonl", "a") as f:
    f.write(json.dumps(audit_event) + "\n")
```

이벤트에는 시각, 이벤트 종류(agent_tool_execution), 도구 이름, session_id, 종료 코드가 들어간다. 세부 사항이 하나 있다. Bash의 종료 코드 같은 값은 최상위가 아니라 tool_response 안에 들어 있어서, 딕셔너리인지 확인한 뒤 꺼낸다. 위 예는 로컬 파일에 JSON Lines로 덧붙이지만, 운영에서는 이 자리에서 SIEM(보안 정보 및 이벤트 관리 시스템)으로 보내야 한다.

## 2. 컴플라이언스 프레임워크 대응

Codex CLI의 통제가 SOC 2, GDPR, ISO 27001의 어느 항목에 해당하는지를 보여 준다.

| 통제 | SOC 2 | GDPR | ISO 27001 |
|---|---|---|---|
| 샌드박스 파일 시스템 제한 | CC6.1 (논리적 접근) | 32조 (처리의 보안) | A.9.4 (시스템 접근 통제) |
| 네트워크 허용 목록 | CC6.6 (네트워크 보안) | 32조 | A.13.1 (네트워크 보안) |
| 훅을 통한 감사 로깅 | CC7.2 (시스템 모니터링) | 30조 (처리 활동 기록) | A.12.4 (로깅과 모니터링) |
| 시크릿 관리 | CC6.1 | 32조 | A.10.1 (암호 통제) |
| 자동 리뷰 | CC8.1 (변경 관리) | 25조 (설계 단계의 데이터 보호) | A.14.2 (개발 보안) |
| 에이전트 신원 (Codex Access Tokens) | CC6.1 | 32조 | A.9.2 (사용자 접근 관리) |

이 대응표는 출발점일 뿐 완전한 평가가 아니다. 조직의 위험 프로필과 규제 의무에 비추어 구체적인 통제를 검토하는 일은 컴플라이언스 팀의 몫이다.

## 3. 데이터 거주지

에이전트가 코드를 추론 API로 보내는 순간 그 코드는 내 네트워크 밖으로 나간다. 데이터 거주지 요건이 있다면 네 가지를 한다.

1. Azure OpenAI나 Amazon Bedrock을 쓰고, 지리적 제약을 보장하는 데이터 처리 계약을 맺는다.
2. 네트워크 허용 목록으로 승인된 리전 밖의 엔드포인트에 에이전트가 닿지 못하게 한다.
3. 읽기 거부 정책으로 개인정보나 규제 대상 데이터가 든 파일을 에이전트가 읽지 못하게 한다.
4. 모델 API 호출을 감사해, 민감하지 않은 내용만 추론 엔드포인트에 도달하는지 확인한다.
