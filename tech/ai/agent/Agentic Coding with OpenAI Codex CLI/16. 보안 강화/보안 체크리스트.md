# 보안 체크리스트

보안에 민감한 환경에 Codex CLI를 배포할 때 하나씩 짚어 볼 열두 가지 항목이다. 각 항목이 앞선 어느 문서의 내용과 이어지는지도 덧붙였다.

---

## 1. 12개 항목

| 번호 | 점검 항목 | 관련 문서 |
|---|---|---|
| 1 | 샌드박스 모드를 read-only 또는 workspace-write로 둔다. 운영에서는 절대 danger-full-access를 쓰지 않는다 | 샌드박스와 파일 시스템 제한 |
| 2 | 관리형 requirements.toml의 deny-read(`[permissions.filesystem]`)에 민감한 파일 패턴(.env, credentials, SSH 키)을 설정한다 | 샌드박스와 파일 시스템 제한 |
| 3 | 권한 프로필로 에이전트를 최소 작업 집합에 가둔다 | 샌드박스와 파일 시스템 제한 |
| 4 | 관리형 `[experimental_network]`와 `managed_allowed_domains_only = true`로 네트워크 허용 목록을 구성한다 | CI 격리와 네트워크 허용 목록 |
| 5 | PreToolUse 훅이 도구 인자를 인젝션 패턴과 대조해 검증한다 | 프롬프트 인젝션 공격과 방어 |
| 6 | PostToolUse 훅이 출력에서 자격 증명처럼 생긴 문자열을 검사한다 | 시크릿 관리 |
| 7 | 시크릿은 환경 변수나 시크릿 매니저로 주입하고 설정 파일에는 두지 않는다 | 시크릿 관리 |
| 8 | shell_environment_policy가 자격 증명을 담은 변수를 하위 프로세스에서 제거한다 | 시크릿 관리 |
| 9 | CI 파이프라인은 결정적 실행을 위해 `--ignore-user-config`와 `--ignore-rules`를 쓴다 | CI 격리와 네트워크 허용 목록 |
| 10 | 자동 리뷰(`approvals_reviewer = "auto_review"`)를 켜되, 도입 신뢰 단계는 배포 성숙도에 맞춘다. 시작은 L0다 | 자동 리뷰와 신뢰 사다리 |
| 11 | 감사 로그가 도구 호출, 승인, 세션 메타데이터를 담는다 | 감사와 컴플라이언스 |
| 12 | MCP 서버 소스 코드를 검토하고, 그 서버가 쓰는 외부 도메인만 허용 목록에 추가한다 | CI 격리와 네트워크 허용 목록 |

## 2. 쓰는 요령

이 목록은 방어를 한 겹에 몰지 않고 계층별로 나눠 둔 것이다. 파일 시스템(1~3), 네트워크(4, 12), 훅(5, 6), 시크릿(7, 8), 재현성(9), 사람과 모델의 승인(10), 사후 증거(11)로 묶이므로 한두 항목이 뚫려도 다른 계층이 받쳐 주는지를 기준으로 점검하면 된다.
