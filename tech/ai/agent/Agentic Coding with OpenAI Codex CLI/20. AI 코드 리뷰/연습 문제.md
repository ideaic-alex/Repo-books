# 연습 문제

20장 끝의 연습 문제 여섯 개를 풀이 방향과 함께 정리한다. 직접 손으로 해 봐야 설정의 감이 잡히는 문제들이다.

---

## 1. pre-commit 훅 만들기

`.git/hooks/pre-commit` 스크립트를 작성한다. 이 스크립트는 스테이징된 변경에 대해 `codex exec`를 읽기 전용 모드로 돌리고, P0 지적이 하나라도 나오면 커밋을 막으면서 지적 제목을 stderr에 출력해야 한다. 하드코딩된 비밀번호가 든 파일을 스테이징해서 시험해 본다.

풀이 방향: `git diff --cached`를 `codex exec --sandbox=read-only`에 넘기고 `--output-schema`로 JSON을 받는다. 우선순위가 0인 지적이 있으면 제목을 stderr로 찍고 0이 아닌 값으로 종료하면 git이 커밋을 중단한다.

## 2. AGENTS.md 리뷰 지침 쓰기

실제로 일하는 프로젝트를 고른다. 리뷰 이력에서 자주 반복되지만 기존 린터가 잡지 못하는 문제 범주 세 가지를 찾아, 각각에 알맞은 우선순위를 붙여 `## Review guidelines` 섹션으로 옮긴다.

풀이 방향: 스타일이나 포매팅은 후보에서 뺀다. 보안, 정확성, 프로젝트 고유 규약처럼 린트 규칙으로 표현하기 어려운 것만 고르고, 얼마나 위험한지에 따라 P0, P1, P2를 정한다.

## 3. codex-action 워크플로 추가하기

저장소에 PR마다 Codex 리뷰를 돌리는 GitHub Actions 워크플로를 추가한다. P0 지적은 차단하는 리뷰 코멘트로, P1은 차단하지 않는 제안으로 올린다. 테스트 PR에서 제대로 도는지 확인한다.

풀이 방향: 본문의 워크플로를 바탕으로 게시 단계의 `priority` 필터를 둘로 나눈다. 0은 변경 요청 성격의 리뷰로, 1은 일반 코멘트로 올리면 된다. 마지막에 테스트 PR로 실제 게시를 확인한다.

## 4. 보정 감사

최근 PR 하나에 `/review`를 돌려 AI 지적과 실제 사람 리뷰 코멘트를 비교한다. 각 지적을 참 양성, 오탐, 놓침(사람 리뷰엔 있었는데 AI 리뷰엔 없는 것)으로 분류하고, 오탐은 AGENTS.md 지침을 고치는 데, 놓침은 추가할 범주를 찾는 데 쓴다.

풀이 방향: 표를 만들어 지적마다 세 분류 중 하나를 적는다. 오탐이 몰린 범주는 지침을 좁히거나 예외를 적고, 놓침이 몰린 범주는 체크리스트 항목으로 올린다.

## 5. 협업 패턴 설계

엔지니어 네 명이 주 20건 이상의 PR을 처리하는 고빈도 저장소의 리뷰 워크플로를 설계한다. 어떤 리뷰 표면이 어떤 범주를 맡는지, AI 지적을 어떻게 분류하는지, 이의가 있는 지적의 에스컬레이션 경로가 무엇인지를 정하고, 팀 위키에 올릴 한 쪽짜리 엔지니어링 프로세스 문서로 쓴다.

풀이 방향: 기계적 정확성은 자동 PR 리뷰, 의도와 아키텍처는 사람이 맡도록 나눈다. AI 지적은 해결됨과 이의 있음으로 표시하고, 이의가 반복되는 범주는 별도 논의로 올리며 결론은 AGENTS.md에 기록하는 흐름을 넣는다.

## 6. 다중 AI 거버넌스 구성

작은 보안 민감 서비스를 대상으로 3단계 리뷰 파이프라인을 구성한다. CodeRabbit 플러그인과 Claude Code용 Codex 플러그인을 설치하고, `codex exec --sandbox=read-only`를 쓰는 PostToolUse 리뷰 훅을 설정한다. 일부러 SQL 인젝션 취약점과 아키텍처 안티패턴을 넣은 테스트 커밋에 세 리뷰어를 모두 돌려, 어느 리뷰어가 어떤 이슈를 잡는지 비교하고 겹치는 정도를 문서로 남긴다.

풀이 방향: 취약점 두 개를 심은 커밋 하나를 만들고 세 리뷰어의 결과를 표로 비교한다. 본문의 관찰대로라면 훅은 프로젝트 관례, CodeRabbit은 폭넓은 보안 규칙, 제공자 간 조합은 구조적 문제에서 강할 것이므로 그 예상이 맞는지 확인한다.
