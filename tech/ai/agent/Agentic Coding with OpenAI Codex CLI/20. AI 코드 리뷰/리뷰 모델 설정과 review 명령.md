# 리뷰 모델 설정과 /review 명령

로컬에서 AI 리뷰를 돌릴 때 손볼 곳은 크게 둘이다. `config.toml`의 모델 선택, 그리고 AGENTS.md의 리뷰 지침이다. 이 둘을 맞춰 두면 대화형으로 돌리든 CI에서 돌리든 같은 모델과 같은 팀 기준이 적용된다. 이 문서는 모델 선택, 엄격도 조정, 그리고 `/review` 명령의 네 가지 모드를 설명한다.

---

## 1. 리뷰 전용 모델 지정하기

`~/.codex/config.toml`의 `review_model` 키는 리뷰 세션에 쓸 모델을 평소 대화 세션 모델과 별도로 고정한다. 리뷰는 읽기가 많은 추론 작업이라 속도보다 깊이와 정확성이 중요하기 때문이다.

```toml
[model]
model = "gpt-5.4"        # fast model for interactive work
review_model = "gpt-5.5" # heavier model for /review passes
```

비용 때문에 평소엔 저렴한 모델로 세션을 돌리는 팀이라면, 대화 경험은 그대로 두고 리뷰만 성능이 높은 모델로 보낼 수 있다. 같은 키를 CI의 `codex exec`도 따르므로 파이프라인과 로컬 세션의 동작이 일관된다.

## 2. 엄격도 조정하기

가장 흔한 실수는 다른 도구가 이미 처리하는 문제를 AI 리뷰가 또 지적하게 두는 것이다. 프로젝트가 ESLint, Prettier, 타입 체커를 CI에서 돌린다면, 스타일 불일치나 암묵적 `any` 타입을 Codex CLI가 보고해 봐야 가치가 없다. 쓸데없는 지적 하나하나가 신뢰를 갉아먹는다.

조정은 두 방향으로 한다.

1. AGENTS.md 리뷰 지침은 린터보다 모델이 더 잘하는 영역에 집중한다. 보안, 정확성, API 계약 위반, 린트 규칙으로 옮기기엔 너무 프로젝트에 특화된 규칙 등이다.
2. 표면마다 심각도 문턱을 다르게 둔다. 자동 PR 코멘트는 P0와 P1만, 사람이 옆에서 맥락을 해석해 줄 수 있는 대화형 세션은 더 넓은 범위의 지적을 허용한다.

린팅이 전혀 없는 코드베이스를 물려받았더라도 AI 리뷰로 정적 분석을 대신하려는 유혹은 참아야 한다. 린터를 먼저 도입해 기계적 문제를 걸러내고, 그 위에 AI 리뷰를 얹어 더 높은 수준의 문제를 보게 한다.

## 3. /review 명령의 네 가지 모드

활성 Codex CLI 세션에서 `/review`를 입력하면 프리셋 메뉴가 열리고 네 가지 모드가 나온다. 모든 모드는 읽기 전용이다. 세션 기록에 새 턴을 만들 뿐 작업 트리는 건드리지 않는다. 작업을 반복하면서 리뷰를 연이어 돌리고 결과를 나란히 비교해도 된다.

| 모드 | 하는 일 | 언제 쓰나 |
| --- | --- | --- |
| Branch comparison (브랜치 비교) | 현재 브랜치를 기준 브랜치와 비교하며 merge base를 자동 계산 | 기능을 끝내고 PR에 들어갈 전체 모습을 보고 싶을 때 |
| Uncommitted changes (미커밋 변경) | 스테이징된 것, 안 된 것, 추적되지 않는 파일까지 리뷰 | 커밋 직전 마지막 점검 |
| Commit review (커밋 리뷰) | 특정 SHA 또는 로그에서 고른 최근 커밋을 대상으로 함 | 변경 하나를 따로 점검하거나, 남의 브랜치를 커밋 단위로 볼 때 |
| Custom instructions (사용자 지정) | 위 모드 중 하나에 집중 프롬프트를 결합 | 걱정되는 영역을 이미 알 때 |

사용자 지정 모드는 범위를 좁혀 토큰을 아끼고 신호를 또렷하게 만든다. 예를 들어 이런 식이다.

```text
/review
> Branch comparison, focus on data-validation gaps in the new API
endpoints
```

## 4. 리뷰 결과 읽고 이어가기

리뷰 결과는 세션 기록에 새 턴으로 나타난다. 각 지적에는 파일 경로, 줄 범위, 제목, 심각도, 설명이 붙는다. 같은 세션에서 "3번 지적의 수정안을 보여 줘"처럼 이어서 요청하면 Codex CLI가 리뷰 맥락을 벗어나지 않고 패치를 제안한다.

`/review`는 세션 범위 안에 있는 모든 AGENTS.md의 `## Review guidelines` 섹션을 따른다. 예를 들어 `payments/AGENTS.md`에 PCI 관련 리뷰 규칙을 써 두었다면, 그 디렉터리에서 세션을 열기만 해도 별도 플래그 없이 규칙이 적용된다.

## 5. 커밋 전 훅과의 조합

미커밋 변경 리뷰는 커밋 직전 마지막 점검이다. 원문은 이를 이 장 뒷부분의 3단계 성숙도 모델에서 다루는 pre-commit 훅 패턴과 짝지어 로컬 작업 흐름을 겹겹이 만들라고 권한다. 요약에서는 `codex exec --sandbox=read-only`를 쓰는 pre-commit 훅이 P0 지적을 원격에 올라가기 전에 막아 준다고 설명한다. 원문 본문에는 이 훅의 완성 스크립트가 실려 있지 않으며, 연습 문제 1에서 직접 작성해 보도록 되어 있다.
