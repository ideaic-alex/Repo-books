# 구조화 출력과 교차 모델 리뷰

앞에서 본 CI 패턴은 자유 형식 출력을 뒤쪽 스크립트가 파싱하는 방식이다. 이 문서는 한 걸음 더 엄격한 방식, 즉 `codex exec --output-schema`로 JSON 출력을 강제하는 방법과, 그 위에서 여러 모델의 리뷰를 합치는 교차 모델 적대적 리뷰를 다룬다.

---

## 1. 구조화 출력 스키마

OpenAI의 공식 Codex SDK 코드 리뷰 쿡북은 `codex exec`에 `--output-schema`를 줘서 구조화된 JSON 출력을 강제하는 방법을 소개한다. 사람이 읽는 글 대신 신뢰도 점수가 붙은, 기계가 처리할 수 있는 지적 목록을 얻는다. 스키마의 모양은 다음과 같다.

```json
{
  "findings": [{
    "title": "string",
    "body": "string",
    "confidence_score": 0.0-1.0,
    "code_location": {
      "absolute_file_path": "string",
      "line_range": {"start": 1, "end": 1}
    }
  }],
  "overall_correctness": "patch is correct|patch is incorrect",
  "overall_confidence_score": 0.0-1.0
}
```

지적마다 있는 `confidence_score`로 문턱 필터링을 할 수 있다. 예를 들어 0.7을 넘는 지적만 PR에 올리고 나머지는 추적용으로 기록해 둔다. `overall_confidence_score`는 개별 지적을 파싱하지 않고도 머지 관문 판단에 쓸 수 있는 요약 신호다.

## 2. 플랫폼별 구현

- **GitHub Actions**: `openai/codex-action`의 `output-schema-file`에 스키마 JSON을 지정한다. 액션이 스키마를 강제하고 `final-message` 출력으로 구조화된 지적을 돌려준다.
- **GitLab CI/CD**: `codex exec`를 `--output-schema`와 함께 직접 실행한다. 지적은 GitLab API를 통해 머지 리퀘스트 토론에 diff의 특정 위치 인라인 코멘트로 올라간다.
- **Jenkins**: 멀티 스테이지 파이프라인에서 API 키는 `withCredentials`로 관리한다. 구조화 JSON은 다음 단계에서 파싱해 GitHub API로 PR 코멘트를 단다.

## 3. 교차 모델 적대적 리뷰

구조화 출력이 있으면 여러 모델로 리뷰하는 전략이 가능해진다. 같은 diff에 Codex와 Claude Code 리뷰를 독립적으로 돌린 뒤 지적을 합치는 것이다. 현업 사례도 이 방식을 뒷받침한다. Mejba Ahmed는 같은 코드베이스에 Codex 적대적 리뷰와 Claude Code Opus 4.6을 나란히 돌린 통제 실험에서, 두 모델의 사각지대가 서로 보완적이며 합치면 어느 한쪽보다 눈에 띄게 더 많은 이슈가 나온다는 것을 확인했다. 비용은 API 토큰 기준으로 크지 않았다.

사각지대는 무작위가 아니라 구조적이다.

| 모델 | 잘 잡은 것 |
| --- | --- |
| Codex (GPT-5.x) | 런타임과 실행 수준의 문제. 중복 제거 로직의 경쟁 상태, 폴링 타임아웃 처리 오류, 스키마 검증 구멍, 배포 설정 문제 |
| Opus 4.6 | 시스템 차원의 아키텍처 우려. 인증 토큰 갱신 경쟁, 부하 급증 때 큐가 무한히 커지는 문제, 민감 데이터 로깅, 서킷 브레이커 부재 |

두 모델 모두 가장 우선순위가 높은 이슈인 폴링 버그는 독립적으로 짚어냈지만, 나머지 지적은 거의 겹치지 않았다. 단일 모델 리뷰는 그래서 잘못된 안심감을 준다.

## 4. 5단계 워크플로

Ahmed가 권하는 순서는 다섯 단계다.

1. Opus로 코드를 생성한다. 1M 토큰 컨텍스트 윈도를 활용한다.
2. Codex로 표준 리뷰를 한다.
3. Codex로 적대적 리뷰를 한다.
4. Opus로 적대적 리뷰를 한다.
5. 지적을 교차 대조해 우선순위를 정한다.

CI/CD로 자동화할 때는 2~5단계를 구조화 JSON 출력과 함께 병렬로 돌리고, 머지 시점에 신뢰도 점수로 중복을 제거한다.

> 원서 그림 설명(약 422쪽, 글로 풀어 씀): 교차 모델 적대적 리뷰 흐름도. 1단계 Opus 코드 생성에서 1M 토큰 컨텍스트로 2단계 Codex 표준 리뷰가 이어지고 이어서 3단계 Codex 적대적 리뷰로 간다. 1단계에서 곧바로 4단계 Opus 적대적 리뷰도 시작된다. 3단계와 4단계의 지적이 5단계 교차 대조로 모이고, 신뢰도 점수 기반 중복 제거를 거쳐 서로 보완되는 사각지대가 드러난다.

그림 20.1은 이 흐름을 보여 준다. Opus가 코드를 만들면 Codex가 표준 리뷰와 적대적 리뷰를 차례로 하고, Opus는 병렬로 자기 적대적 리뷰를 한다. 두 모델의 지적은 5단계에서 교차 대조되고 신뢰도 점수로 중복이 제거되어, 어느 한 모델만으로는 못 잡는 사각지대가 드러난다.

## 5. Claude Code용 Codex 플러그인

Claude Code용 Codex 플러그인은 Claude Code 세션 안에서 Codex를 돌려 이 교차 제공자 패턴을 자동화한다. `/codex:review`, `/codex:adversarial-review`, `/codex:rescue` 같은 슬래시 명령을 제공한다. 뒤에 나오는 다중 AI 거버넌스 논의(3단계 성숙도)와 이어진다.

## 6. CI에서 두 리뷰 합치기

원문의 CI 예시는 두 리뷰를 모두 돌려 문턱 이상의 지적을 합치는 구성이다.

```yaml
- name: Codex review
  uses: openai/codex-action@v1
  with:
    prompt: "Review the diff. Focus on correctness and security."
    output-schema-file: review-schema.json
    output-file: codex-findings.json
    sandbox: read-only
- name: Claude review
  run: |
    claude exec --json "Review the diff for architectural issues" \
      > claude-findings.json
```

마지막 단계는 `node scripts/merge-review-findings.js codex-findings.json claude-findings.json --threshold 0.7 --post-to-pr`로 두 결과를 합치고 0.7 문턱을 넘는 것만 PR에 올린다.
