# 요약

20장의 핵심을 열 가지로 정리한다. 각 항목은 앞선 문서들의 내용을 압축한 것이다.

---

## 1. 장 전체 요약

1. **AI 리뷰의 강점과 한계**: AI 코드 리뷰는 보안 안티패턴, 정확성 문제, AGENTS.md에 담은 팀 관례를 믿을 만하게 잡는다. 아키텍처, 의도, 조직 내 트레이드오프에 대한 사람의 판단은 대신하지 못한다. 프로젝트 유형별 권장 설정은 표 20-1에 정리되어 있다.
2. **`/review` 명령**: 대화형 세션에서 네 가지 모드(브랜치 비교, 미커밋 변경, 커밋 리뷰, 사용자 지정 지침)를 제공한다. 항상 읽기 전용이며, 세션 범위의 AGENTS.md 지침을 따른다.
3. **`## Review guidelines`**: AGENTS.md의 이 섹션은 팀 기준을 모든 리뷰 표면에 자동으로 전파한다. 민감한 패키지의 전문 규칙은 디렉터리 트리의 더 깊은 곳에 겹쳐 쓴다.
4. **엄격도 조정**: AI 리뷰는 린터가 다루지 않는 범주로 한정하고, 자동 PR 코멘트는 P0와 P1로 제한해 신호의 품질을 지킨다.
5. **codex-action**: `openai/codex-action`에 `sandbox: read-only`를 주면 어떤 SCM 플랫폼에서든 구조화 JSON 출력과 CI 수준의 리뷰를 얻는다. 우선순위는 0(치명적)에서 3(제안)까지이며 PR 코멘트는 P1에서 거른다.
6. **pre-commit 훅**: `codex exec --sandbox=read-only`를 쓰는 pre-commit 훅은 P0 지적이 원격에 올라가기 전에 막아, CI를 기다리지 않고 빠른 로컬 피드백을 준다.
7. **사람과 AI 협업 패턴**: AI 1차 검토, 관심사별 병렬 리뷰, 대화형 리뷰는 사람의 판단을 루프에 두면서, 사람만 내릴 수 있는 결정에 판단력을 집중시킨다.
8. **3단계 성숙도**: 수동 리뷰(1단계), PostToolUse 리뷰 관문이 있는 자율 stop 훅(2단계), CodeRabbit과 리뷰 관문 훅과 Claude Code용 Codex 플러그인을 결합한 다중 AI 거버넌스(3단계)로 나아간다. 프로젝트의 위험 특성에 맞춰 단계를 고른다.
9. **에이전트 PR 신뢰 문제**: PR 23,247건 연구에서 에이전트 PR의 1.7%가 설명과 코드의 불일치가 컸고, 그 결과 수락률이 51.7% 낮았으며 머지 시간은 3.5배 길었다. CodeRabbit 자료에서는 AI PR이 로직, 품질, 보안, 가독성 전반에서 이슈가 1.7배 많았다. PR 설명은 계획이 아니라 diff에서 `codex exec --output-schema`로 만들고, PostToolUse 훅으로 설명과 코드의 일치를 검증한다.
10. **PR에 남는 에이전트의 지문**: 현업 관찰에 따르면 AI가 만든 코드는 변수 이름 습관, 일관된 포매팅 선택, 선호하는 관용구, 독특한 주석 스타일 같은 탐지 가능한 흔적을 남기며 PR 수준에서 식별되는 경우가 많다. 전문 팀에는 두 가지 시사점이 있다.
    - git 위생: 에이전트가 쓴 커밋은 사람의 이력에 섞지 말고 `Co-Authored-By` 트레일러 등으로 분명히 표시한다. 지적 정직성과 감사 추적의 무결성을 위해서다.
    - 리뷰 보정: 변경이 에이전트 작성이라는 걸 아는 리뷰어는 에이전트가 꾸준히 약한 영역(아키텍처 트레이드오프, 경계 사례 추론, 설계 선택의 보안 영향)에 주의를 더 쏟을 수 있다.

이 10번 항목은 Vaughan 본인의 2026년 4월 실무 분석에 근거하며, 동료 검토를 거친 1차 연구가 아니라고 원문이 밝히고 있다.
