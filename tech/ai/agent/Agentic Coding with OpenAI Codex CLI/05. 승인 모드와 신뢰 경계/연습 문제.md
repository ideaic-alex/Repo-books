# 연습 문제

5장 끝에 있는 연습 문제 세 개를 풀이 방향과 함께 정리한다. 모두 직접 실행해 보고 차이를 관찰하는 실습형이다.

---

## 1. 연습 5-1: 권한 프로필 세 개 만들기

config.toml에 이름 붙인 권한 프로필을 세 개 만든다. 코드 리뷰용 읽기 전용, 대화형 개발용, CI/CD용이다. 그다음 같은 작업을 세 프로필로 각각 돌려 보고 에이전트의 행동이 어떻게 달라지는지 관찰한다.

풀이 방향은 이렇다. 리뷰용에는 `untrusted`와 `read-only`(또는 `:read-only`), 개발용에는 `on-request`와 `workspace-write`, CI용에는 `never`와 `workspace-write`를 둔다. `~/.codex/<name>.config.toml` 파일로 만들었다면 `--profile`로 고른다. 같은 프롬프트에서 승인 질문이 뜨는 횟수와, 쓰기 시도가 막히는지 여부를 비교하면 된다.

## 2. 연습 5-2: 예행연습과 실제 실행 비교

한 작업을 `-a untrusted -s read-only`로 먼저 예행연습처럼 돌린다. 그다음 같은 작업을 `-a on-request -s workspace-write`로 돌린다. Codex CLI가 제안한 것과 실제로 한 것을 비교하고, 예행연습을 못 봤다면 거절했을 행동을 하나 찾아낸다.

풀이 방향은 두 실행의 제안 목록과 실제 변경 내역(예를 들어 git diff와 실행된 명령)을 나란히 놓고 차이를 보는 것이다. 예행연습에서 미리 보인 파일 수정이나 명령 중 의도와 다른 것이 있었는지 짚어 본다.

## 3. 연습 5-3: 항목별 승인 설정

샌드박스 작업은 자동 승인하고 MCP 엘리시테이션은 승인을 요구하도록 granular 승인 정책을 설정한다. MCP 서버를 쓰는 작업을 돌려 보고, 일괄 `never` 정책과 승인 흐름이 어떻게 다른지 관찰한다.

풀이 방향은 `[approval_policy.granular]` 아래에서 `sandbox_approval = false`, `mcp_elicitations = true`처럼 항목별 값을 정하는 것이다. 각 키가 해당 항목이 실행을 멈추고 승인을 요청할 수 있는지를 켜고 끈다는 점을 기준으로 값을 정한다. 실행하면 MCP 서버가 사용자 입력을 요청하는 순간에만 멈추고, `never`에서는 멈추는 일이 없다는 점이 드러난다.
