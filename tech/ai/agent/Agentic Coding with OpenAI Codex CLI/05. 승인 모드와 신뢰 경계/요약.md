# 요약

5장의 핵심을 일곱 가지로 정리한다. 각 항목 끝에는 자세한 내용이 있는 문서를 적었다.

---

## 1. 장 전체 요약

1. 서로 독립인 레버가 둘이다. 승인 정책은 에이전트가 언제 물어보는지를, 샌드박스 모드는 운영체제가 무엇을 허용하는지를 정한다. (신뢰 모델과 두 가지 제어)
2. 승인 모드는 세 개이며 사다리를 이룬다. untrusted는 모든 것을 묻고, on-request는 경계에서만 묻고, never는 묻지 않는다. (승인 모드 세 가지)
3. 샌드박스 모드도 세 개이며 기술적 경계를 정한다. `read-only`, `workspace-write`, `danger-full-access`다. (샌드박스와 네트워크)
4. 강제는 커널 수준에서 일어난다. macOS는 Seatbelt, Linux는 bwrap과 seccomp, Windows는 제한된 토큰을 쓴다. 사용자 공간에서는 우회할 수 없다. (운영체제별 샌드박스)
5. 이름 붙인 권한 프로필로 설정을 재사용 가능한 묶음으로 만들 수 있고, 상속도 된다. 충돌하면 deny가 이긴다. (프로필과 권한 설정)
6. 신뢰는 단계적으로 넓힌다. 제한적으로 시작해 확신이 쌓이면 넓히고, 그 진행 경로가 권한 사다리다. (권한 사다리)
7. 방어는 겹으로 한다. 어떤 행동이든 실행되려면 두 층이 모두 동의해야 하므로, 보안을 서로 독립인 두 차원에서 따질 수 있다. (신뢰 모델과 두 가지 제어)

## 2. 외워 둘 조합

| 상황 | 승인 | 샌드박스 |
|---|---|---|
| 낯선 저장소 감사 | untrusted | read-only |
| 로컬 대화형 개발 | on-request | workspace-write |
| CI/CD | never | workspace-write |
| 일회용 컨테이너 | never | danger-full-access |
