# 샌드박스와 네트워크

`--sandbox` 플래그는 Codex CLI나 사용자가 무엇을 원하든 상관없이 운영체제가 무엇을 허용하는지를 정한다. 승인 모드가 "언제 물어볼까"라면 샌드박스는 "물어보든 말든 애초에 가능한 일이 무엇인가"다. 이 문서는 샌드박스 값 세 가지, config.toml 설정, 네트워크와 웹 검색의 분리, 그리고 두 제어를 한 번에 끄는 `--yolo` 플래그를 설명한다.

---

## 1. 샌드박스 값 세 가지

허용 범위가 점점 넓어지는 세 값이 있다.

| 값 | 허용 범위 | 비고 |
|---|---|---|
| `read-only` | 파일 쓰기 불가, 명시적 승인 없이는 명령 실행 불가 | 에이전트는 접근 가능한 것은 읽을 수 있지만 아무것도 바꾸지 못한다 |
| `workspace-write` | 현재 작업 디렉터리와 기본적으로 `/tmp`, `$TMPDIR` 안에서 읽기와 쓰기 | 바깥으로 나가는 네트워크는 꺼져 있다. 대화형 개발의 권장 기본선이다 |
| `danger-full-access` | 파일 시스템과 네트워크 제한을 모두 해제 | 컨테이너 자체가 격리를 제공하는 환경용. 작업이 끝나면 폐기되는 일회용 CI 러너가 예다 |

## 2. config.toml에서 설정하기

기본 두 줄은 다음과 같다.

```toml
approval_policy = "on-request"
sandbox_mode    = "workspace-write"
```

`sandbox_mode`가 `workspace-write`일 때는 쓰기 범위를 더 조정할 수 있다.

```toml
[sandbox_workspace_write]
writable_roots = ["/home/dan/shared-fixtures"]
```

`writable_roots`는 현재 작업 디렉터리 밖으로 쓰기 권한을 넓힌다. 실행할 때 한 번만 쓰고 싶다면 같은 기능을 하는 옵션이 `--add-dir <path>`다.

## 3. 네트워크 접근

`network_access`는 켜짐과 꺼짐뿐인 스위치다. 이 층에서는 도메인별 허용 목록이 없다. 샌드박스 안 프로세스가 보내는 바깥 요청이 전부 허용되거나 전부 막히거나 둘 중 하나다. `workspace-write`에서는 기본이 꺼짐이며, 대부분의 대화형 세션은 그대로 둬도 된다. 필요한 실행에서만 켠다.

```toml
[sandbox_workspace_write]
network_access = true
```

패키지 설치, API 스키마 가져오기, 저장소 클론이 작업에 들어 있다면 `network_access = true`를 명시하거나, 실행 중에 뜨는 권한 상승 질문을 수락해야 한다. `workspace-write`에서 네트워크가 기본으로 꺼져 있다는 사실은 사람들이 자주 헷갈리는 부분이다.

## 4. 웹 검색은 따로 제어한다

웹 검색은 네트워크 접근과 별개의 설정이다. 에이전트가 실행 중에 공개 웹에서 오류 메시지, 라이브러리 문서, 버전별 문법, 최신 보안 공지를 찾아볼 수 있게 한다. 예를 들어 "최신 React 릴리스 노트에서 깨지는 변경점을 찾아 마이그레이션 계획을 갱신해 줘" 같은 프롬프트는 `web_search`가 켜져 있어야만 동작한다. 꺼져 있으면 에이전트는 학습 데이터와 이미 읽은 로컬 파일 안에서만 답할 수 있다.

```toml
web_search = "cached"   # "cached" | "live" | "disabled"
```

`cached`(기본값)는 미리 색인된 검색 인덱스를 쓰므로 프롬프트 주입에 노출될 위험이 줄어든다. `live`는 실시간 검색을 켜지만 공격당할 수 있는 지점이 늘어난다. 대부분의 작업에는 `cached`가 맞다.

## 5. 두 제어를 한 번에 끄는 --yolo

두 레버의 이름을 알았으니 흔한 조합을 정리할 수 있다. 로컬 개발에서 대부분의 세션이 쓰는 조합은 `-a on-request -s workspace-write` 한 쌍이다. 승인과 샌드박스를 모두 꺼야 하는, 단단히 격리된 파이프라인에는 합성 플래그 하나가 있다.

```bash
# 로컬 개발: 마찰이 적은 설정
codex -a on-request -s workspace-write
# 격리된 컨테이너 안의 CI/CD: 승인도 샌드박스도 없음
codex --dangerously-bypass-approvals-and-sandbox   # 별칭: --yolo
```

`--yolo`는 두 제어를 모두 우회한다. 실행 환경 자체가 격리를 제공할 때만 써야 한다. 파이프라인이 끝나면 폐기되는 일회용 컨테이너가 그런 경우다. 개발자 워크스테이션에서 `--yolo`를 쓰는 것은 의도된 용도가 아니다.
