# 연습 문제

이 장의 연습 문제 다섯 개는 모두 같은 방향이다. 남이 낸 점수를 의심해서 읽는 연습에서 시작해, 내 팀의 작업으로 직접 측정하는 연습으로 넘어간다. 문제마다 취지를 풀어 쓰고 풀이 방향을 덧붙인다.

---

## 1. 벤치마크 주장 감사하기

AI 연구소의 최근 보도자료나 블로그 글에서 코딩 벤치마크 점수를 인용한 곳을 찾는다. 다음을 확인한다.

- (a) 어떤 벤치마크 변형을 인용했는가
- (b) 벤더 자체 스캐폴딩인가, 표준화된 하니스인가
- (c) 같은 모델의 SEAL 리더보드 항목이 있는가

두 수치가 모두 있으면 스캐폴드 프리미엄(두 점수의 차이)을 계산한다. 없다면 어떤 비교가 빠졌는지 정확히 적는다. 마지막으로 인용된 수치가 내 업무에서 모델의 성능에 대해 실제로 알려 주는 바를 두 문단으로 정리한다.

풀이 방향: 프리미엄은 벤더 점수에서 SEAL 점수를 빼면 된다. 이 장의 예로 Pro는 56.8%와 41.8%라서 약 15점 차이였다. 짝이 되는 수치가 없다면 "비교 불가"라고 쓰는 것이 정직한 결론이다.

## 2. 다섯 작업짜리 마이크로 벤치마크 만들기

팀의 최근 스프린트 이력에서 대표 작업 다섯 개를 고른다. 지어낸 시나리오가 아니라 실제 이슈나 PR이어야 한다. 이 장의 `.benchmarks/` 구조를 쓰고, 작업마다 결정적 성공 테스트(성공하면 0, 실패하면 1로 끝나는 셸 스크립트)를 쓰고 시작 환경을 Docker로 컨테이너화한다. 현재 설정으로 Codex CLI를 각 작업에 돌려 해결률과 작업당 비용을 기록한다. 그다음 변수 하나(모델 선택, AGENTS.md 내용, 훅 설정)를 바꿔서 다시 돌리고, 어느 설정이 이겼는지와 이유를 문서화한다.

풀이 방향: 한 번에 하나만 바꿔야 원인을 해석할 수 있다. 해결률만이 아니라 비용도 같이 비교해서 결론을 낸다.

## 3. Terminal-Bench 2.0 일부 돌리기

Harbor 프레임워크를 설치하고 `harbor datasets list`를 실행한 뒤, `harbor run --help`로 현재의 필터링 플래그를 파악한다. 내 업무와 관련된 분야에서 Terminal-Bench 2.0 작업 10~15개를 골라 Codex CLI 모델 설정 두 가지, gpt-5.5와 gpt-5.4로 돌린다. 해결률과 총비용을 비교한다. 결과가 [Terminal-Bench 2.0과 직접 실행](Terminal-Bench%202.0%EA%B3%BC%20%EC%A7%81%EC%A0%91%20%EC%8B%A4%ED%96%89.md) 문서의 순위표(원서 표 25-2)에 실린 공개 수치와 크게 다르면 이유를 따져 본다. AGENTS.md 설정, 네트워크 환경, 고른 작업 분야가 모델의 학습 강점과 맞는지를 생각한다. 결과를 팀과 공유하고 앞으로의 기본 모델 선택의 근거로 쓴다.

풀이 방향: 표본이 10~15개로 작으니 몇 점 차이는 우연일 수 있다. 분야별 해결률을 같이 본다.

## 4. 작은 프로젝트에서 직접 벤치마크하기

백로그에서 직접 하면 15~30분 걸릴 실제 버그나 기능 요청을 고른다. 이슈 본문을 로컬 벤치마크 작업 파일에 넣거나, 프롬프트에서 이슈를 가져오는 방법을 정확히 알려 준다. 예를 들면 `codex "Fix issue #N. Use gh issue view N to read the issue, then run the project tests."` 같은 식이다. 소요 시간을 재고, 내 테스트를 통과했는지, 몇 턴이 걸렸는지, 토큰 비용이 얼마인지 기록한다. 이를 이 장의 공개 벤치마크 점수와 비교하고, 실제 결과가 연구소 결과와 어긋나는 부분과 이유(코드베이스 복잡도, 테스트 커버리지, AGENTS.md에 담은 도메인 지식)를 적는다.

풀이 방향: 어긋남의 원인을 코드베이스, 테스트, 컨텍스트 세 갈래로 나누어 적으면 정리하기 쉽다.

## 5. 내 워크플로의 스캐폴드 프리미엄 재기

스캐폴드 프리미엄은 기반 모델이 아니라 스캐폴딩(프롬프트, AGENTS.md, 훅, 승인 모드, 작업 설계)에서 오는 성능 차이다. 백로그의 대표 작업 하나를 변수를 하나씩만 바꿔 두 번 돌린다. 같은 모델과 승인 모드로 먼저 최소 설정, 다음에 프로덕션 AGENTS.md와 훅을 적용한다. 출력 품질, 토큰 수, 걸린 시간을 기록한다. 스캐폴드 효과와 모델 효과를 분리하고 싶으면 다른 모델로 한 번 더 반복한다. 이 데이터는 모델을 올릴지, 더 나은 스캐폴딩에 투자할지를 판단할 때 값지다.

풀이 방향: 모델은 고정하고 스캐폴딩만 바꾼 두 결과의 차이가 곧 내 프리미엄이다. 모델만 바꾼 결과와 크기를 견주어 투자 우선순위를 정한다.
