# 요약

25장의 결론은 하나로 모인다. 벤치마크 숫자는 후보를 좁히는 데 쓰고, 최종 판단은 내 코드베이스에서 직접 잰 결과로 내린다. 이 문서는 장 끝의 요약 열 가지를 풀어서 다시 정리한다.

---

## 1. 열 가지 핵심 정리

1. **SWE-bench Verified는 최상위 모델에서 오염됐다.** 약 60%를 넘는 점수에는 부분적인 암기가 섞여 있다. 같은 모델 기준으로 SWE-bench Pro가 30~40점 낮게 나오며, Pro가 더 정직한 척도다.
2. **GPT-5.5가 Terminal-Bench 2.0 앞쪽에 있다.** OpenAI는 82.7%를 보고했고, 이는 Claude Mythos Preview를 근소하게 앞서는 벤더 측정치다. 독립 리더보드에서는 Codex CLI + GPT-5.5가 82.2%로, 현재 최고 하니스인 NexAU-AHE + GPT-5.5(84.7%) 바로 뒤에 있다. SWE-bench Pro는 58.6%, SWE-bench는 88.7%다.
3. **Terminal-Bench 2.0이 Codex CLI 사용자에게 가장 관련 깊다.** 터미널 작업 전체를 Docker 샌드박스에서 수행하게 해서, 터미널 중심 업무에 가장 가까운 공개 대용물이다.
4. **SlopCodeBench는 완료가 아니라 품질을 잰다.** 작업이 끝났는지가 아니라 코드의 질을 점수화해서 기존 벤치마크의 맹점을 채운다. 본문에서 설명한 구체적 지표는 장황함과 구조 침식이다.
5. **스캐폴드 부풀림은 4~12점이다.** 벤더가 보고한 점수는 표준화된 기준선보다 높으니, 벤더 점수를 SEAL 리더보드 점수와 직접 비교하지 않는다.
6. **모델 선택과 스캐폴딩이 모두 중요하다.** 모델을 올리면 천장이 올라가고, AGENTS.md, 훅, 승인 모드, 작업 설계가 내 워크플로가 그 천장에 얼마나 가까워지는지를 정한다.
7. **가장 좋은 벤치마크는 내 코드베이스다.** Terminal-Bench의 작업 형식을 틀로 삼고 결과는 버전 관리로 추적한다.
8. **PRDBench는 PRD에서 코드까지의 격차를 드러낸다.** 명세에서 만드는 일은 버그 수정보다 훨씬 어렵다. 가장 강한 모델이 60%대 초중반이고 SWE-bench 성적에는 한참 못 미친다(상하이 교통대와 메이퇀 팀, 2025년 10월 arXiv, AAMAS 2026).
9. **멀티 에이전트 작업에서는 조율 구조가 모델 선택을 이긴다.** MAESTRO가 이를 보여 주며, 12장의 오케스트레이션 패턴에 투자할 근거가 된다.
10. **프로덕션 코드 품질은 완료와 다른 이야기를 한다.** 보고서들은 취약점 비율 14.3%(Sourcery Intel), 리뷰 대기 4.6배 지연(Opsera), 코드 중복 10.5%에서 13.5%로 증가를 전한다. PR-MCI 연구(MSR 2026)는 에이전트 PR의 1.7%가 오해를 부르는 설명을 달고 있고, 수락률이 51.7% 낮고 병합이 3.5배 오래 걸린다고 한다. 벤치마크 완료는 프로덕션 품질의 필요조건이지 충분조건이 아니다.

## 2. 한 줄로 줄이면

공개 점수는 어떤 변수(벤치마크 종류, 스캐폴딩, 오염)에서 나온 숫자인지 확인하고 읽는다. 그 위에 하니스와 훅, 품질 검사를 얹고, 작은 자체 벤치마크로 내 설정을 검증한다.
