# 실무 코드 품질 보고서

벤치마크는 에이전트가 작업을 끝낼 수 있는지를 잰다. 2026년 초의 산업 보고서 두 건은 질문을 바꿔서, 에이전트가 코드를 쓴 뒤 그 코드가 어떻게 되는지를 묻는다. 답은 씁쓸하며, 어떤 벤치마크 점수든 해석할 때 필요한 맥락을 준다. 이 문서는 Opsera와 Sourcery Intel 보고서, PR 설명과 코드의 불일치를 연구한 PR-MCI, CodeRabbit의 분석을 정리하고 벤치마크 해석에 주는 의미를 짚는다.

---

## 1. Opsera와 Sourcery Intel 2026 보고서

Opsera의 AI Coding Impact 2026 Benchmark Report는 60개 이상 기업의 개발자 25만 명 이상을 분석했다. Sourcery Intel의 State of AI Coding Agents 2026은 에이전트 전체 지형의 시장, 벤치마크, 보안 데이터를 종합했다. 두 보고서가 그리는 에이전트 산출물 품질은 일관적이다.

| 발견 | 수치 | 출처 |
|---|---|---|
| AI 생성 코드의 취약점 비율 | 14.3%, 사람 코드는 9.1%(상대적으로 57% 증가) | Sourcery Intel(스탠퍼드-MIT 연구, 코드 조각 200만 개 이상) |
| 줄당 취약점 | 사람 코드보다 15~18% 많음 | Opsera(개발자 25만 명 이상) |
| 리뷰 대기 지연 | AI 생성 PR이 4.6배 더 길다 | Opsera |
| 코드 중복 | 표본에서 10.5%에서 13.5%로 | Opsera |
| PR까지 걸리는 시간 감소 | 48~58% 빨라짐 | Opsera |
| 시니어와 주니어의 생산성 향상 | 약 5배 차이 | Opsera |
| 쓰지 않는 AI 코딩 라이선스 | 21% | Opsera |

역설이 두드러진다. AI 보조 워크플로는 풀 리퀘스트(PR)까지 걸리는 시간을 48~58% 줄이지만, 만들어진 PR은 리뷰 대기열에 4.6배 더 오래 머문다. 코드를 만드는 속도가 리뷰하는 역량을 앞질렀다. 팀은 PR을 더 많이 만들지만 리뷰어는 따라가지 못하고, 리뷰되지 않은 채 취약점이 있을 수도 있는 코드의 적체가 커진다.

## 2. PR-MCI: 설명이 거짓말을 할 때

MSR 2026에 채택된 연구는 AI 코딩 에이전트 5종이 낸 PR 23,247건을 분석했고, 자동화된 PR-MCI(PR Message-Code Inconsistency, PR 메시지와 코드의 불일치) 탐지 파이프라인을 검증하려고 974건을 사람이 직접 주석했다. 리뷰어들이 직관적으로 느끼던 신뢰 결손을 수치로 보여 준다.

1. 에이전트 PR의 1.7%가 높은 메시지-코드 불일치를 보였다. 설명은 변경을 했다고 주장하는데 diff에는 구현되지 않은 경우다.
2. 가장 흔한 유형(높은 MCI 사례의 45.4%)은 "설명이 구현되지 않은 변경을 주장한다"였다.
3. 높은 MCI PR은 수락률이 51.7% 낮았다(28.3% 대 80.0%).
4. 병합까지 3.5배 오래 걸렸다(55.8시간 대 16.0시간).

CodeRabbit이 오픈소스 PR 470건을 분석한 결과도 다른 각도에서 같은 방향이다. AI가 공동 작성한 PR은 사람만 쓴 PR보다 이슈가 약 1.7배 많았다(PR당 10.83건 대 6.45건). 격차는 영역별로 논리와 정확성 1.75배, 코드 품질 1.64배, 보안 2.74배, 가독성 3.0배였다.

## 3. 벤치마크 해석에 주는 의미

이 결과가 벤치마크 점수를 무효로 만들지는 않는다. 맥락을 줄 뿐이다. Terminal-Bench 2.0에서 82%를 받은 모델은 복잡한 작업을 정말로 끝낼 수 있다. 그러나 그 모델이 낸 코드는 14.3%의 취약점 비율을 안고 있을 수 있고, 기존 추상화를 중복해서 만들 수 있으며, 실제 변경과 맞지 않는 PR 설명을 달고 올 수 있다. 벤치마크 완료는 프로덕션 품질 산출물의 필요조건이지 충분조건이 아니다.

Codex CLI 사용자에게 실용적인 결론은 이렇다. 벤치마크 점수는 어느 모델이 문제를 풀 수 있는지 알려 준다. 그 해법이 내 코드베이스에 들어올 자격이 있는지는 다음 수단이 알려 준다.

- PostToolUse 훅(9장)
- 자동 리뷰 `auto_review`(20장)
- AGENTS.md의 품질 제약(4장)
- 구조화된 출력 스키마(22장)
