# 벤치마크와 실전 성능

AI 연구소들은 홍보 자료 맨 앞에 벤치마크 점수를 내건다. 그런데 그 점수가 무엇을 재고 무엇을 일부러 재지 않는지, 어떤 스캐폴딩으로 나온 숫자인지를 모르면 비교가 의미 없다. 이 장은 벤치마크 주장을 의심해서 읽는 어휘와, Codex CLI가 현재 지형 어디에 있는지, 그리고 내 코드베이스에서 직접 평가를 돌리는 방법을 다룬다.

후반부에서는 에이전트가 어디서 실패하는지(탐색, 멀티모달 조합, 도움 요청 판단)와, 작업을 끝낸 뒤 코드 품질이 어떻게 되는지를 보여 주는 최신 연구와 산업 보고서를 소개한다. 결론은 공개 점수는 후보를 좁히는 데만 쓰고 최종 판단은 내 평가로 내리라는 것이다.

---

## 1. 핵심 요점

- SWE-bench Verified는 최상위 모델에서 오염됐다. 약 60%를 넘는 점수는 의심하고, 같은 모델이 Pro에서 훨씬 낮게 나오는 것이 암기의 증거다.
- Terminal-Bench 2.0은 Docker 샌드박스에서 터미널 작업을 끝까지 수행하게 하는 벤치마크로, Codex CLI 사용자에게 가장 관련 깊고 Harbor로 직접 돌릴 수 있다.
- 벤더 자체 스캐폴딩의 점수는 표준화 평가보다 4~12점 높다. 벤더 점수와 SEAL 점수를 직접 비교하지 않는다.
- 하니스(AGENTS.md, 훅, 서브에이전트)가 모델만큼 성능을 좌우한다. 모델은 천장을, 설정은 천장에 닿는 정도를 정한다.
- 에이전트의 주된 실패 원인은 도구 사용이 아니라 탐색이다. 파일 지도와 좁은 작업 범위, 알맞은 승인 모드로 대응한다.
- 벤치마크 완료는 프로덕션 품질의 필요조건일 뿐이다. 취약점, 중복, 리뷰 병목, PR 설명 불일치는 훅과 자동 리뷰로 막는다.
- 가장 좋은 벤치마크는 `.benchmarks/` 같은 내 작업 묶음이며, 해결률과 비용을 함께 기록해 버전 관리한다.
