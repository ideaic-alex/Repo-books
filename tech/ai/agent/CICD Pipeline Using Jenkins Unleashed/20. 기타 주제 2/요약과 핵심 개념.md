# 요약과 핵심 개념

이 장은 Jenkins를 프로그램으로 제어하는 방법과 파이프라인 코드를 재사용하는 방법을 다뤘다. 원서의 마지막 요약은 두 가지를 짚는다. 하나는 REST API와 파이썬으로 기존 잡의 설정을 가져오고 잡을 실행하는 법이고, 다른 하나는 재사용 라이브러리를 만들어 파이프라인에서 쓰는 법이다.

저자는 이 책이 Jenkins 관리자와 사용자가 알아야 할 중요한 기능을 모두 다뤘다고 말하며, 독자가 실제 프로젝트에서 Jenkins를 쓰는 데 도움이 되기를 바란다는 말로 책을 맺는다.

---

## 1. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 원격 접근 API | Jenkins 기능을 HTTP로 호출하는 REST 비슷한 API. XML, JSON, Python 형식 제공 |
| `.../api/` 주소 | API 진입점. 앞의 `...`가 다룰 대상 |
| GET / POST | 자원 조회 / 자원 생성과 동작 실행 |
| 쿼리, 경로, 헤더 파라미터 | 값을 URL 뒤, URL 경로, 요청 헤더로 보내는 세 방법 |
| curl | 명령줄 REST 클라이언트 |
| `config.xml` | 잡 설정 파일. 조회하거나 새 잡의 틀로 사용 |
| `createItem?name=` | 새 잡을 만드는 엔드포인트 |
| `build` / `buildWithParameters` | 파라미터 없는 잡 / 있는 잡을 실행하는 엔드포인트 |
| Python-Jenkins | Jenkins REST API를 파이썬 함수로 감싼 래퍼 |
| 공유 라이브러리 | 여러 잡이 같이 쓰는 파이프라인 코드를 담은 Groovy 파일 |
| `call` 함수 | 라이브러리가 호출될 때 실행되는 진입 함수 |
| `@Library` | 등록한 공유 라이브러리를 잡으로 불러오는 표기 |

위 표는 이 장의 어휘 목록이다. 앞의 네 문서를 훑은 뒤 이 표로 빠진 개념이 없는지 점검하면 좋다.

---

## 2. 자주 쓰는 호출 모음

| 목적 | curl 엔드포인트 | Python-Jenkins |
|---|---|---|
| 설정 가져오기 | GET `/job/<잡>/config.xml` | `get_job_config` |
| 잡 만들기 | POST `/createItem?name=<이름>` | `create_job` |
| 파라미터 있는 잡 실행 | POST `/job/<잡>/buildWithParameters` | `build_job(잡, 딕셔너리)` |
| 파라미터 없는 잡 실행 | POST `/job/<잡>/build` | `build_job(잡)` |

curl은 한 번 확인하거나 스크립트에서 간단히 호출할 때 편하다. 응답을 가공하거나 흐름 제어가 필요하면 Python-Jenkins 같은 래퍼가 낫다. 이 판단은 책의 설명을 바탕으로 한 정리다.

---

## 3. 공유 라이브러리 체크리스트

| 확인 항목 | 기억할 점 |
|---|---|
| 파일 위치 | `vars` 또는 `src` 폴더 안 |
| 파일 이름 | 카멜 케이스(예: buildJavaAPI), 확장자 `.groovy` |
| 함수 | 반드시 `call` |
| 등록 위치 | Manage Jenkins → Configure System → Global Pipeline Libraries |
| 호출 | 잡 스크립트에서 `@Library('등록 이름')` 후 파일 이름으로 호출 |

이 중 하나만 어긋나도 라이브러리가 동작하지 않는다. 문제가 생기면 위치, 파일 이름, `call` 함수, 등록 이름의 철자를 차례로 확인한다.

---

## 4. 기억할 점

- 인증 정보에는 앞 장에서 만든 API 토큰을 쓴다. 토큰은 비밀번호처럼 보호한다.
- 같은 단계가 여러 잡에 반복되면 공유 라이브러리로 뽑아 중복을 줄인다.
- 프로젝트마다 다른 값은 `call` 함수의 인자로 넘긴다.
- 책의 예제 코드에는 `StringBranch`, `@Liabrary` 같은 오타가 있다. 따라 칠 때는 `String Branch`, `@Library`로 바로잡아야 한다.
