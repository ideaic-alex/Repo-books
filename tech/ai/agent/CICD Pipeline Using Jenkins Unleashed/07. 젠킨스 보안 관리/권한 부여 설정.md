# 권한 부여 설정

로그인에 성공한 사용자가 Jenkins 안에서 무엇까지 할 수 있는지는 Configure Global Security 화면의 Authorization(권한 부여) 영역에서 정한다. 이 영역의 선택지는 "모두 허용"에서 "로그인한 사람만 허용"까지 폭이 넓다. 어떤 선택이 어떤 상황에 맞는지 알아 두면 설정할 때 헷갈리지 않는다.

비유하자면 인증이 건물 출입문이라면, 권한 부여는 출입 후 어느 층 어느 방까지 열어 줄지 정하는 규칙이다. 규칙을 느슨하게 하면 편하지만, 누구나 서버실에 들어가는 일이 생길 수 있다.

---

## 1. Authorization 선택지 비교

원서가 다루는 세 가지 선택지를 표로 비교한다.

| 선택지 | 로그인한 사용자 | 익명 사용자 | 원서의 권장 |
|---|---|---|---|
| Anyone can do anything | 전체 권한 | 전체 권한 | 일반적으로 권장하지 않음 |
| Legacy mode | Admin 역할이면 전체 권한, 아니면 읽기 전용 | 읽기 전용 | 권장하지 않음 |
| Logged-in users can do anything | 전체 권한 | 읽기 전용(체크박스로 조절) | 따로 언급 없음 |

표에서 보듯 익명 사용자에게 쓰기 권한까지 주는 것은 첫 번째뿐이다. 두 번째와 세 번째는 익명 사용자를 읽기 전용으로 묶는다.

### Anyone can do anything

이 옵션을 고르면 로그인하지 않은 익명 사용자까지 포함해 모두가 Jenkins를 완전히 제어한다. 회사 인트라넷처럼 믿을 수 있는 환경에서 매번 로그인하지 않고 빠르게 설정을 바꾸고 싶을 때 쓰기도 한다. 그래도 원서는 일반적으로 권장하지 않는다고 분명히 밝힌다.

### Legacy mode

Admin 역할을 가진 사용자는 시스템 전체를 제어한다. Admin이 아닌 사용자와 익명 사용자는 읽기 전용이다. 이 동작은 Jenkins 1.164 이전 버전의 기본 동작과 같다고 원서는 설명한다. 이름처럼 옛 방식이라 권장하지 않는다.

### Logged-in users can do anything

모든 사용자가 로그인해야 하는 방식이다. 로그인한 사용자는 전체 권한을 갖고, 익명 사용자는 읽기 전용 접근만 얻는다.

이 옵션 아래에는 Allow anonymous read access(익명 읽기 접근 허용) 체크박스가 있다.

| Allow anonymous read access | 익명 사용자가 접속하면 |
|---|---|
| 체크함 | 로그인하지 않아도 읽기 전용으로 Jenkins를 볼 수 있다 |
| 체크 해제 | Jenkins에 접근할 수 없고 로그인을 요구하는 화면이 나온다 |

외부에 노출된 Jenkins라면 체크를 해제해 로그인하지 않은 사람이 빌드 목록조차 보지 못하게 하는 편이 안전하다. 이 마지막 문장은 원서 설명을 바탕으로 한 해석이다.

## 2. 로그인 설정과 권한 설정 조합

Security Realm과 Authorization은 서로 독립된 선택이지만 함께 동작한다. 원서에 나온 경우를 조합해 보면 다음과 같다.

| Security Realm | Authorization | 결과 |
|---|---|---|
| None | (기본 설정) | 익명 접속이 되지만 Overall/Read 권한이 없다는 로그가 남는다 |
| None, `denyAnonymousReadAccess=false` | (기본 설정) | 로그인 없이 대시보드가 열리며 읽기 전용이다 |
| Jenkins' own user database | Logged-in users can do anything | 로그인한 사용자만 전체 권한을 가진다 |

세 번째 줄은 사용자를 직접 만들고 로그인한 사람에게만 쓰기를 허용하는 조합이다. 원서가 이 조합을 따로 추천한다고 말하지는 않지만, 모두 허용하는 쪽보다 훨씬 덜 위험하다.

---

## 3. 정리

- Authorization은 로그인 후 허용 범위를 정한다.
- Anyone can do anything과 Legacy mode는 원서가 권장하지 않는다.
- Logged-in users can do anything을 고르면 익명 사용자는 읽기 전용이고, Allow anonymous read access를 해제하면 익명 접근 자체가 막힌다.
- 사용자별로 세밀하게 권한을 나누는 역할 기반 접근 제어(role-based access)는 이 장에서 다루지 않는다. 여기서 말하는 Admin 역할은 Legacy mode에서의 관리자 역할만 뜻한다.
