# 젠킨스 분산 빌드

이 장은 Jenkins 서버 한 대로 모든 빌드를 처리할 때의 한계를 짚고, 빌드를 여러 머신에 나눠 맡기는 분산 빌드를 설정하는 방법을 정리한다. 컨트롤러와 에이전트의 역할, 둘을 잇는 두 가지 방식, 노드 설정 항목의 의미를 먼저 익힌다. 그다음 SSH와 JNLP로 에이전트를 실제로 연결하고, 프리스타일 잡을 특정 노드에서 실행하는 실습을 따라 한다.

원서는 Windows 머신 두 대로 실습하며 CalculatorAPI 프로젝트를 Nexus에 배포하는 잡을 예로 쓴다. 이 노트는 그 절차와 설정 값을 표와 번호 목록으로 풀어 쓴다.

---

## 1. 핵심 요점

- 한 대짜리 구성은 빌드가 느리고, 소프트웨어를 모두 한 머신에 깔아야 하고, 고장 나면 복구가 힘들며, 다양한 환경을 테스트할 수 없다.
- 분산 빌드는 컨트롤러(마스터)가 빌드 단계를 여러 에이전트(노드)에 나눠 실행시키는 구조다.
- 컨트롤러가 에이전트에 닿을 수 있으면 SSH로, 닿을 수 없으면 에이전트가 먼저 접속하는 JNLP로 연결한다.
- 노드 설정의 핵심 항목은 실행기 수, Remote root directory, Labels, Launch method, Availability다.
- SSH 방식은 키 쌍 생성, 자격 증명 등록, 노드 추가, authorized_keys 등록, 접속 확인, Relaunch Agent 순서로 진행한다.
- Known hosts 검증 오류는 `ssh -o HostKeyAlgorithms=ssh-rsa`로 항목을 다시 만들어 풀 수 있고, Non verifying 전략은 피한다.
- JNLP 방식은 Global Security 포트(7070)와 Jenkins URL을 지정하고, 에이전트에서 `agent.jar`를 실행해 연결한다.
- 잡은 Label Expression에 노드 이름이나 라벨을 넣어 원하는 에이전트에서 실행한다.
