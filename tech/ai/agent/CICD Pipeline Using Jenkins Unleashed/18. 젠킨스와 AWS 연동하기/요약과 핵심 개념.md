# 요약과 핵심 개념

이 문서는 18장에서 다룬 내용을 한 번에 훑어볼 수 있게 정리한 것이다. 장의 흐름은 EC2 인스턴스 생성, IIS 웹 서버 준비, SSH 연결, 젠킨스 잡 배포 순서였다. 그리고 지금까지 젠킨스를 화면으로만 다뤘다면, 다음 장에서는 명령줄(CLI)로 젠킨스를 제어하는 방법을 배운다.

---

## 1. 장 요약

- EC2 인스턴스가 무엇인지 배우고 AWS에서 직접 만들었다.
- 인스턴스에 IIS 웹 서버를 설치하고, 웹 별칭(가상 디렉터리)을 만들어 Calculator 웹 애플리케이션을 배포할 자리를 마련했다.
- 인스턴스가 SSH로 접속되도록 SSH 공개 키를 설정했다.
- 인스턴스에 붙은 보안 그룹에 인바운드 규칙을 만들어 HTTP와 SSH 접속을 허용했다.
- 소스를 받아 scp 명령으로 Calculator.html을 인스턴스에 복사하는 젠킨스 잡을 만들었다.

## 2. 핵심 개념 표

| 용어 | 쉬운 풀이 |
| --- | --- |
| EC2 인스턴스 | AWS에서 시간 단위로 빌리는 가상 서버 |
| 키 쌍(Key pair) | 인스턴스 접속에 쓰는 인증용 파일 쌍. .pem 파일을 내려받는다 |
| RDP | Windows 서버에 원격 데스크톱으로 접속하는 방식 |
| IIS | Windows 서버의 웹 서버 |
| 가상 디렉터리 | 웹 주소 별칭을 실제 폴더에 연결한 것 |
| SSH 공개/개인 키 | 개인 키는 로컬이, 공개 키는 인스턴스의 authorized_keys가 가진다 |
| 보안 그룹 / 인바운드 규칙 | 인스턴스로 들어오는 접속을 허용하는 방화벽 규칙 |
| scp | SSH를 이용한 파일 복사 명령 |
| 다운스트림 잡 | 앞선 잡이 끝난 뒤 이어 실행되는 잡 |

표에서 가장 헷갈리기 쉬운 쌍은 RDP용 .pem 키와 SSH용 id_rsa 키다. .pem은 AWS가 만들어 주고 처음 접속할 때 비밀번호를 푸는 데 쓰며, id_rsa는 ssh-keygen으로 로컬에서 직접 만들어 scp와 ssh 접속에 쓴다.

## 3. 배포 파이프라인 흐름

| 순서 | 일어나는 일 |
| --- | --- |
| 1 | 배포 잡이 CalculatorWebApplication 저장소에서 소스를 가져온다 |
| 2 | scp가 Calculator.html을 EC2의 C:\DeployedCalculatorApp로 복사한다 |
| 3 | IIS가 CalculatorWebApp 별칭으로 그 파일을 서비스한다 |
| 4 | 다운스트림 잡 TestCalculatorWebApplication이 시작된다 |
| 5 | Selenium 테스트가 ApplicationURL의 EC2 주소로 접속해 테스트한다 |

## 4. 다시 확인할 점

- 인바운드 규칙은 SSH와 HTTP 두 번 만든다. 하나라도 빠지면 복사나 브라우저 접속이 막힌다.
- EnvVars.csv의 ApplicationURL 변경은 커밋하고 푸시까지 해야 테스트 잡에 반영된다.
- 원서의 scp 명령은 인쇄 과정에서 옵션과 경로가 깨져 있으니, 형식은 `scp -i 개인키 로컬파일 사용자@호스트:경로`로 확인한다.
- 사용하지 않는 인스턴스는 종료해서 비용을 줄인다.
