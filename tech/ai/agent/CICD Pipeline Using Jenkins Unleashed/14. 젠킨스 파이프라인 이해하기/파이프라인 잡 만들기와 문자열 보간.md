# 파이프라인 잡 만들기와 문자열 보간

이 문서는 젠킨스 화면에서 가장 간단한 파이프라인 잡을 만들어 실행하는 과정과, 파이프라인 코드에서 변수 값을 문자열에 끼워 넣는 문자열 보간(string interpolation)을 다룬다. 중간에 실습 중 자주 만나는 Java 버전 오류와 해결법도 정리한다. 뒤에 나오는 Nexus 릴리스 파이프라인을 만들기 전에 기본 조작을 익히는 단계다.

문자열 보간은 우편물 양식과 비슷하다. "안녕하세요 ___님"이라는 양식에 받는 사람 이름을 채워 넣어 각자에게 다른 편지를 만드는 것처럼, 문자열 안의 변수 자리를 실제 값으로 바꿔 넣는 일이다.

---

## 1. 젠킨스 화면에서 간단한 파이프라인 만들기

사전 준비로 Pipeline: Job과 Pipeline 플러그인이 설치되어 있어야 한다. 설치 방법은 원서 5장에 있다.

1. 젠킨스에 로그인한다.
2. Pipeline: Job과 Pipeline 플러그인을 설치한다.
3. 젠킨스 대시보드로 이동한다.
4. 화면 왼쪽의 New Item(새 아이템) 링크를 눌러 잡 만들기 화면을 연다.
5. 잡 이름을 입력하고 Pipeline 옵션을 고른다.
6. OK 버튼을 누르면 잡 설정 페이지(Job Configuration)로 넘어간다.

설정 페이지에는 파이프라인 잡에만 있는 항목이 있다. 아래 두 항목이 대표적이다.

| 설정 항목 | 의미 |
|---|---|
| Do not allow the pipeline to resume if the controller restarts | 체크하면 젠킨스 컨트롤러가 재시작된 뒤 파이프라인 실행을 이어 가지 않는다 |
| Pipeline Speed/Durability Override | 파이프라인이 디스크에 기록하는 데이터의 양을 바꿔 속도와 내구성의 균형을 조절한다 |

첫째 항목은 앞 문서에서 본 내구성(재시작해도 이어서 실행)을 끄는 스위치로 이해하면 된다.

### 속도와 내구성 옵션 비교

기본 상태에서 실행 중인 파이프라인은 디스크에 데이터를 많이 기록한다. 젠킨스가 장애로 멈췄다가 다시 시작할 때 진행하던 실행을 이어 가기 위해서다. 대신 이 기록 때문에 파이프라인이 느려진다. Speed/Durability Override 드롭다운(Custom Pipeline Speed/Durability Level)에서 이 기본 동작을 바꿀 수 있다.

| 옵션 | 동작 | 장단점 |
|---|---|---|
| Performance-optimized: Much faster (requires clean shutdown to save running pipelines) | 꼭 필요한 데이터만 기록한다 | 실행이 가장 빠르다. 실행 중인 파이프라인을 저장하려면 깨끗한 종료(clean shutdown)가 필요하다 |
| Less durability, a bit faster (specialty use only) | 데이터를 많이 기록하지 않는다 | 약간 빨라지지만 내구성이 떨어진다. 특수한 경우에만 쓴다 |
| Maximum durability but slowest | 기록 가능한 데이터를 최대한 기록한다 | 젠킨스 장애 때 가장 잘 복구되지만 실행이 매우 느리다. 예전에는 이것이 유일한 선택지였다 |

표에서 보듯 빠를수록 복구 능력이 약해진다. 속도와 안전은 서로 맞바꾸는 관계이므로, 중요한 배포 파이프라인이라면 기록을 많이 남기는 쪽을, 잠깐 쓰고 버리는 빌드라면 빠른 쪽을 고려할 수 있다. 이 선택 기준은 표의 의미를 풀어 쓴 해석이다. 원서의 예제 잡은 이 옵션을 선택하지 않고 기본값 그대로 둔다.

### 코드 입력과 실행

7. 설정 페이지를 아래로 내려 Pipeline 섹션을 찾는다. 여기 편집기에 파이프라인 코드를 직접 쓴다. 원서는 간단한 선언형 파이프라인을 입력했다(Figure 14-3). 이 코드는 Hello World를 출력하는 것으로, 원서에 코드 본문은 글로 실려 있지 않다.
8. Save 버튼을 눌러 저장한다.
9. Back to Dashboard 링크로 대시보드에 돌아간다.
10. 잡 목록에서 SamplePipelineJob 옆의 시계 모양 아이콘을 누르면 파이프라인 잡이 실행된다.
11. 실행 결과를 보려고 Console Output(콘솔 출력) 메뉴를 누른다.

콘솔에는 "Hello World"가 찍힌다. 즉 파이프라인이 에이전트에서 실행되어 echo 스텝이 문자열을 출력한 것이다.

## 2. 자주 만나는 오류 해결

파이프라인 잡을 실행하면 다음 오류를 만날 수 있다.

```text
java.lang.IllegalArgumentException: Unsupported class file major version
```

| 항목 | 내용 |
|---|---|
| 원인 | 젠킨스가 지원하지 않는 Java 버전을 쓸 때 나는 오류다. 원서는 지원 버전을 Java 1.11과 1.8로 적었다(Java 11과 Java 8을 가리키는 표기로 보인다) |
| 해결 | 시스템 환경 변수 PATH가 Java 11 또는 Java 8을 가리키게 한다 |
| 저자의 환경 | JAVA_HOME 환경 변수가 JDK 11을 가리킨다 |
| 주의 | 환경 변수를 바꾼 뒤에는 젠킨스 서버를 반드시 재시작한다 |
| 다른 방법 | 젠킨스의 Global Tool Configuration(전역 도구 설정)에서 JDK 11 또는 JDK 1.8을 설정한다. 원서 6장의 Figure 6-10 참조 |

환경 변수 방식은 컴퓨터 전체에 적용되고, Global Tool Configuration 방식은 젠킨스 안에서만 적용된다는 차이가 있다. 뒤의 설명은 일반 지식에 기반한 해석이다. 핵심은 젠킨스가 쓰는 Java 버전이 지원 범위 안이어야 한다는 점이다.

## 3. 문자열 보간

문자열 보간은 문자열 안에 있는 변수 자리를 변수의 값으로 바꿔 넣는 과정이다. 원서의 예에서는 username이라는 변수에 Pranoday라는 값이 들어 있고, 이 값을 문자열에 넣고 싶다.

```groovy
def Username = 'Pranoday'
echo 'Hello Mr. ${Username}'
echo "How are you ? Mr. ${Username}"
```

원서가 제시한 출력은 다음 두 줄이다.

```text
Hello Mr. $(Username)
How are you ? Mr. Pranoday
```

첫 줄 출력은 원서에 `$(Username)`으로 인쇄되어 있다. 작은따옴표 문자열은 변수를 바꾸지 않고 글자 그대로 출력하므로 실제로는 `${Username}`이 그대로 나올 것이고, 소괄호는 인쇄 오타로 보인다. 확신이 없어 원문 표기를 그대로 적었다.

### 따옴표별 동작

| 문자열 종류 | 예 | 결과 |
|---|---|---|
| 큰따옴표 | "How are you ? Mr. ${Username}" | 변수 값으로 바뀌어 Pranoday가 출력된다 |
| 작은따옴표 | 'Hello Mr. ${Username}' | 변수가 바뀌지 않은 채 글자 그대로 출력된다 |

원서 본문은 이 규칙을 설명하면서 큰따옴표에서는 `${VariableName}` 형식이고, 작은따옴표에서는 `$VariableName` 형식이라고 적었고, `echo 'Hello Mr. $Username'`이 Hello Mr. Pranoday를 낸다고 했다. 그런데 이 설명은 바로 앞의 예제 결과와 맞지 않는다. 일반적인 Groovy 규칙은 큰따옴표 문자열만 보간한다는 것이므로, 위 표는 예제 결과와 Groovy 규칙을 따랐다. 실제로 확인한 뒤 쓰는 것이 안전하다.

### 젠킨스 환경 변수와 보간

파이프라인은 전역 변수로 여러 환경 변수(environment variable)를 제공한다. BUILD_ID, BUILD_NUMBER, JENKINS_URL, JOB_NAME 등이 그 예다.

| 환경 변수 | 의미 |
|---|---|
| BUILD_ID | 현재 빌드의 ID |
| BUILD_NUMBER | 현재 빌드 번호 |
| JENKINS_URL | 젠킨스 접속 주소 |
| JOB_NAME | 잡 이름 |

전체 목록은 브라우저에서 다음 주소로 볼 수 있다.

```text
${YOUR_JENKINS_URL}/pipeline-syntax/globals#env
```

${YOUR_JENKINS_URL}은 젠킨스의 호스트 IP 주소와 포트다. 저자의 젠킨스는 localhost:8080에서 시작하므로 주소는 http://localhost:8080/pipeline-syntax/globals#env가 된다.

BUILD_ID와 JENKINS_URL을 echo로 콘솔에 찍으려면 문자열 보간이 필요하다. 원서의 선언형 예제는 다음과 같다.

```groovy
pipeline
{
    agent any
    stages
    {
        stage('Example')
        {
            steps
            {
                echo "Running ${env.BUILD_ID} on ${env.JENKINS_URL}"
            }
        }
    }
}
```

echo 문자열이 큰따옴표로 감싸져 있고 환경 변수는 env.변수이름 형태로 쓴다. 원서에는 이 문장이 줄바꿈으로 나뉘어 인쇄되어 있었으나 한 줄 문장으로 이해하면 된다. 이렇게 하면 실행할 때마다 현재 빌드 ID와 젠킨스 주소가 자동으로 출력된다.
