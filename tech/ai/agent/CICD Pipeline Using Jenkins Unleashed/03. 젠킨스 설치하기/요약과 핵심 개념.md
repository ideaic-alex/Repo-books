# 요약과 핵심 개념

이 장은 젠킨스를 윈도에 설치하는 방법과 설치 후 폴더 구조, 그리고 Jenkins.xml 설정을 다뤘다. 이 문서는 장 끝의 Summary를 바탕으로 전체 흐름과 핵심 개념을 다시 묶는다.

---

## 1. 장의 흐름

원서의 요약은 이 장의 내용을 이렇게 정리한다. MSI 파일을 실행해 설치 마법사로 젠킨스를 설치하는 방법을 봤고, 젠킨스를 윈도 서비스로 시작하는 방법과 Jenkins.war로 시작하는 방법도 살폈다. 서버가 켜진 뒤에는 젠킨스 설정 마법사(setup wizard)로 인스턴스를 구성할 수 있다. 마지막으로 설치 폴더의 구조와 중요한 설정 파일인 Jenkins.xml을 확인했다. 다음 장에서는 젠킨스 인스턴스를 구성하는 여러 설정을 다룬다.

| 순서 | 주제 | 핵심 |
|------|------|------|
| 1 | 요구 사항 | RAM 256MB, 디스크 1GB, JDK 8 또는 11 |
| 2 | 설치 방법 | MSI, WAR, Docker 이미지 |
| 3 | 디렉터리 구조 | JENKINS_HOME 아래 설정, 플러그인, 잡, 빌드 기록 |
| 4 | Jenkins.xml | 서비스 태그의 `<executable>`로 자바 지정 |

표처럼 이 장은 "무엇이 필요한가, 어떻게 설치하는가, 설치 후 무엇이 어디에 있는가, 자바는 어떻게 바꾸는가" 순서로 구성된다.

---

## 2. 핵심 개념 정리

| 용어 | 뜻 |
|------|----|
| JDK | 자바 개발 키트. 젠킨스는 JDK 8과 11만 지원 |
| MSI | 윈도용 설치 파일 형식. 마법사로 설치 |
| WAR | 자바 웹 애플리케이션을 묶은 파일(Web Application Archive). 젠킨스 서버를 이것으로 실행 가능 |
| Docker | 코드와 의존성을 컨테이너로 묶어 배포하는 도구 |
| JENKINS_HOME | 젠킨스 설치 디렉터리. 기본은 사용자 홈의 .jenkins |
| Jenkins.xml | JENKINS_HOME 안의 서비스 설정 파일. Java.exe 위치 등 포함 |
| PATH | 기본으로 젠킨스가 자바를 찾는 환경 변수 |

표는 이 장에서 처음 나온 용어를 한곳에 모은 것이다. 설치 방식이 달라도 설치 결과는 JENKINS_HOME 폴더로 모인다는 점이 공통 개념이다.

---

## 3. 꼭 기억할 점

- 젠킨스는 JDK 8과 11만 지원하며, 11은 2.164 계열부터 지원된다.
- 윈도에서는 MSI, WAR, Docker의 세 방식으로 설치할 수 있다.
- 서버를 띄우는 방법은 서비스 방식과 WAR 방식이 있고, 켠 뒤에는 설정 마법사로 구성한다.
- 설정은 JENKINS_HOME 안의 config.xml과 각 잡의 config.xml에 파일로 저장된다.
- 젠킨스가 쓰는 자바를 바꾸려면 Jenkins.xml의 `<executable>`에 Java.exe 전체 경로를 적는다.
- 다음 장에서는 젠킨스 인스턴스를 구성하는 여러 설정을 다룬다.
