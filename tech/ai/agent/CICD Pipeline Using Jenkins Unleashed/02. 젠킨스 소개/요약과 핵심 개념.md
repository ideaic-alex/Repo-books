# 요약과 핵심 개념

이 문서는 2장의 결론과 핵심 개념을 한곳에 모은다. 원문 Summary는 짧다. 성공적인 CI/CD를 구현하는 데 필요한 단계를 설명했고, 널리 쓰이는 자동화 서버인 Jenkins를 소개했다는 내용이다.

---

## 1. 원문 Summary가 말하는 것

- 이 장은 CI/CD 과정을 성공적으로 구현하려면 어떤 단계가 필요한지 설명했다.
- 널리 쓰이는 자동화 서버 Jenkins를 소개했다.
- Jenkins가 나오기 전에는 테스트와 배포를 자주 하려면 노력이 아주 많이 들었다.
- 다음 장은 Jenkins의 기능을 깊이 다룬다. 그 기능이 있어야 CI/CD를 성공적으로 구현할 수 있다.

원문 안내상 다음 3장은 설치를 다룬다. 다만 이 노트의 범위는 2장까지다.

---

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
| --- | --- |
| Jenkins | 빌드, 테스트, 배포를 자동화하는 무료 오픈 소스 서버. Java로 만들었다 |
| 서블릿 컨테이너 | Jenkins가 그 안에서 도는 Java 웹 실행 환경. Apache Tomcat이 예다 |
| Hudson | Jenkins의 전신. 2011년 분쟁 뒤 Jenkins가 갈라져 나왔고 2020년 1월 종료됐다 |
| DSL | 빌드 생명주기 단계를 표현하는 특정 분야 전용 언어 |
| 플러그인 | Git, Maven, SonarQube 같은 도구를 Jenkins와 잇는 확장 모듈 |
| 파이프라인 | 각 빌드 단계의 작업과 하위 작업의 순서를 정의한 Jenkins 스크립트 |
| 잡(작업) | 빌드 릴리스 생명주기 단계를 순서대로 수행하는 작업 묶음 |
| 트리거(실행 조건) | 브랜치 변경 알림을 받고 잡이 시작되는 계기 |
| 아티팩트(빌드 결과물) | .JAR, .WAR 같은 라이브러리 파일 |

---

## 3. 꼭 기억할 점

1. Jenkins는 서로 다른 도구를 하나의 흐름으로 엮는 지휘자다. 도구 하나하나는 플러그인으로 연결한다.
2. 파이프라인의 각 단계는 앞 단계의 결과를 받아 처리하고 다음 단계로 넘긴다. 앞 단계가 실패하면 뒤 단계는 실행하지 않는다.
3. 변경은 작게, 자주 합치고 그때마다 테스트한다. 그래야 오류가 났을 때 마지막 성공 빌드 이후의 변경만 살피면 된다.
4. CI/CD 흐름은 변경 푸시, 알림, 잡 실행, 결과 이메일 순으로 이어진다.
5. 이 장은 개념 소개가 중심이고, 화면에서 따라 할 실습은 없다.
