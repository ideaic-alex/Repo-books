# 요약과 핵심 개념

10장은 젠킨스의 핵심 개념인 잡을 소개하고, 프리스타일 잡을 만들어 가며 설정 항목을 훑은 장이다. 잡을 실행하고 실행 로그를 확인하는 절차도 함께 배웠다. 이 문서는 장 전체를 개념과 설정 위치별로 다시 정리한다.

이후 장에서는 여기서 익힌 지식을 가지고 자바 API나 웹 애플리케이션 같은 여러 애플리케이션을 빌드하는 젠킨스 잡을 실제로 구현한다.

---

## 1. 핵심 개념

| 용어 | 정리 |
|---|---|
| 잡(Job, 프로젝트) | 젠킨스가 무엇을 언제 할지 적은 지시 묶음 |
| 트리거 | 잡을 시작하는 조건 |
| 빌드 스텝 | 잡이 실행하는 작업 단계 |
| 빌드 후 조치 | 작업이 끝난 뒤의 처리(알림, 파일 복사 등) |
| 빌드 | 잡을 한 번 실행한 것. 번호가 붙고 로그와 아티팩트가 저장된다 |
| 프리스타일 잡 | 테스트, 패키징, 리포트 발송 같은 단순 작업용 잡 |
| 아티팩트 | 빌드가 만든 결과물(예: .JAR 파일) |
| 작업 공간 | 빌드가 실행되고 코드가 내려받아지는 디렉터리 |
| 업스트림/다운스트림 | 내가 의존하는 잡 / 나에게 의존하는 잡 |

## 2. 설정 섹션별 정리

| 섹션 | 주요 설정 |
|---|---|
| General | 설명, 오래된 빌드 삭제, 매개변수, 비활성화, 동시 빌드, 대기 시간, 재시도, 차단, 사용자 지정 작업 공간, 표시 이름 |
| Source Code Management | Git 저장소 URL, 자격 증명, 빌드할 브랜치 |
| Build Triggers | 원격 트리거, 다른 프로젝트 후 실행, 주기적 빌드, SCM 폴링 |
| Build Step | 순차 실행되는 작업 단계 |
| Post-build Actions | 작업 후 이메일 알림 등 |

## 3. 기억해 둘 요점

- 오래된 빌드 삭제 설정은 디스크 공간을 지키는 데 중요하다. 일수와 개수, 그리고 아티팩트 전용 기준을 따로 둘 수 있다.
- 기본값은 한 번에 하나의 빌드만 실행한다. 병렬 실행이 필요하면 동시 빌드 옵션을 켠다.
- 잡 이름과 표시 이름은 다르다. 작업 공간 폴더와 원격 트리거 URL에는 잡 이름이 쓰인다.
- 비공개 저장소에는 Global 유형 자격 증명을 만들어 Credentials 드롭다운에서 고른다. 윈도우 자격 증명 관리자에 저장된 정보 때문에 오류가 가려지거나 나타날 수 있다.
- 기본 브랜치는 master이고, 다른 브랜치는 Branches to Build에 적는다.
- 트리거는 URL 호출, 다른 잡 후 실행, 주기, 폴링 네 가지다. 폴링 식 예는 `H/5 * * * *`, 주기 식 예는 `45 8 * * *`다.
- 실행 결과는 Build History와 Console Output에서, 정리는 Workspace와 Delete Project에서 한다.

## 4. 이 장의 실습 흐름

1. New Item에서 이름을 넣고 Freestyle Project를 골라 OK를 누른다.
2. General, SCM, 트리거, 빌드 스텝, 빌드 후 조치를 설정하고 Save를 누른다.
3. 시계 아이콘으로 실행하고 Build Executor Status에서 진행을 본다.
4. Build History에서 빌드를 고르고 Console Output으로 로그를 확인한다.
5. 필요하면 Configure로 수정하거나 Workspace를 비우거나 잡을 삭제한다.
