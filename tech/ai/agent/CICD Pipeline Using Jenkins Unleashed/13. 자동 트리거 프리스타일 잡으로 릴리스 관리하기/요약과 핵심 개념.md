# 요약과 핵심 개념

이 장은 한 개발팀이 Java API를 협업으로 개발하고, master에 병합되는 순간 Jenkins가 스스로 릴리스까지 해 주는 흐름을 처음부터 끝까지 따라갔다. 마지막 요약과 함께 장 전체의 핵심 개념을 한 번에 복습한다.

이 문서는 다른 문서를 읽지 않고도 장의 줄기를 잡을 수 있도록 순서, 용어, 설정값을 표로 모아 두었다. 자세한 절차는 각 주제 문서를 참고한다.

---

## 1. 장 전체 요약

- 저장소 관리자는 GitLab의 Members 페이지에서 새 팀원을 초대하고 Developer 같은 역할을 줄 수 있다.
- 사용자 이름과 비밀번호 방식 대신, 공개 키와 개인 키 한 쌍으로 접근을 제한하는 SSH 인증을 쓸 수 있다.
- ssh-keygen으로 키 쌍을 만들고, 공개 키를 GitLab의 SSH Keys에 등록한다.
- 개인 키는 SSH 주소로 복제하고 push할 때 쓴다. 위치를 알려 주는 방법은 known_hosts, config 파일, Git 전역 설정 세 가지다.
- Jenkins에는 SSH Username with private key 종류의 자격 증명을 만들어 저장소에 접근시킨다.
- Poll SCM으로 5분마다 master를 확인하게 하면, 병합 후 Jenkins가 빌드를 자동으로 시작한다.
- Jenkins의 이메일 알림을 설정해 두면 빌드가 실패했을 때 메일이 온다.
- 원서는 마지막에 다음 장이 Jenkins 파이프라인을 다루며 빌드 과정을 더 세밀하게 제어하는 방법을 소개한다고 안내한다.

## 2. 핵심 용어

| 용어 | 쉬운 풀이 |
| --- | --- |
| 협업자(contributor) | 저장소에 초대되어 코드에 기여하는 팀원 |
| 역할(role) | 팀원에게 허락된 권한의 크기. Reporter, Developer 등 |
| 기본 인증 | 사용자 이름과 비밀번호로 확인 |
| SSH 인증 | 공개 키와 개인 키 한 쌍으로 확인 |
| 복제(clone) | 저장소 전체를 내 컴퓨터로 내려받기 |
| 병합 요청(merge request) | 내 브랜치를 master에 합쳐 달라는 요청 |
| Poll SCM | Jenkins가 주기적으로 저장소의 변경을 확인하는 트리거 |
| SMTP | 이메일을 보내는 규약. 그 서비스를 하는 서버가 SMTP 서버 |

## 3. 전체 작업 순서

| 단계 | 작업 | 위치 |
| --- | --- | --- |
| 1 | 새 팀원 초대(Developer) | GitLab Members |
| 2 | SSH 키 쌍 생성 | ssh-keygen |
| 3 | 공개 키 등록 | GitLab Preferences → SSH Keys |
| 4 | 개인 키 위치 알려 주기 후 복제 | known_hosts, config, core.sshCommand |
| 5 | 곱셈 함수, 단위 테스트, 버전 3.0 | Eclipse, pom.xml |
| 6 | mvn test, 브랜치 커밋과 push | 명령 프롬프트 |
| 7 | 병합 요청 생성(병합은 보류) | GitLab |
| 8 | 프리스타일 잡 생성, SSH 자격 증명, Poll SCM, Maven deploy | Jenkins |
| 9 | 이메일 설정과 시험 메일 | Manage Jenkins → Configure System |
| 10 | 병합 후 자동 빌드와 Nexus 배포 확인 | Jenkins, Nexus |
| 11 | 일부러 실패시켜 알림 확인 | Jenkins, 메일함 |

병합을 보류하는 이유가 순서의 핵심이다. 잡을 먼저 만들어 두어야 병합이 일으키는 변경을 잡이 감지해 릴리스할 수 있다.

## 4. 주요 설정값 모음

| 항목 | 값 |
| --- | --- |
| 저장소 이름 | JenkinsBookCalculatorAPI |
| 새 브랜치 | MultiplicationFunction |
| 릴리스 버전 | 3.0 (pom.xml의 version) |
| 잡 이름 | ReleaseCalculatorAPIAutoTrigger |
| 자격 증명 ID | MyGitSSHCredentials |
| 확인 대상 브랜치 | Master |
| Maven 목표 | deploy |
| SMTP 서버, 포트 | smtp.gmail.com, 465(SSL) |

## 5. 알아 둘 점

- 원서의 설명은 2022년 시점이다. Gmail의 Less secure app 설정과 GitLab, Jenkins 화면은 이후 바뀌었을 수 있다.
- Poll SCM은 정해진 주기로 확인하는 방식이라 병합 직후 바로 빌드가 시작되지는 않는다.
- 이메일 알림은 빌드가 불안정하거나 실패했을 때를 위한 설정이다.
