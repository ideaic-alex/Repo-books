# 자동 트리거 프리스타일 잡으로 릴리스 관리하기

이 장은 지난 장에서 만든 Java Calculator API 프로젝트를 여러 개발자가 함께 다루는 상황에서 출발한다. 저장소 관리자가 새 팀원을 초대하고, SSH 키로 접근을 제한하고, 새 기능을 브랜치로 올려 병합하는 흐름을 따라간다. 그리고 병합되는 순간 Jenkins가 스스로 빌드해서 새 버전을 Nexus에 배포하도록 프리스타일 잡을 만든다.

마지막에는 빌드가 깨졌을 때 이메일로 알려 주는 알림 설정까지 확인한다. 이 노트는 책의 서술 시점(2022년)을 따르므로 GitLab, Jenkins, Gmail 화면과 정책은 이후 바뀌었을 수 있다.

---

## 1. 핵심 요점

- 저장소 관리자는 GitLab의 Members 페이지에서 새 팀원을 초대하고 Reporter, Developer 같은 역할을 붙인다.
- SSH 인증은 개인 키와 공개 키 한 쌍으로 접근을 확인한다. 특정 컴퓨터에서만 저장소에 접근하게 만들고 싶을 때 쓴다.
- ssh-keygen으로 키 쌍을 만들고 공개 키를 GitLab의 SSH Keys에 등록한다. 개인 키 위치는 known_hosts, config 파일, core.sshCommand 중 하나로 알려 준다.
- 새 기능은 브랜치에 커밋해 올린 뒤 병합 요청으로 master에 합친다. 이 장에서는 곱셈 함수를 넣고 pom.xml 버전을 3.0으로 올린다.
- Jenkins에는 SSH Username with private key 종류의 자격 증명을 만들어 SSH 주소의 저장소에 접근시킨다.
- Poll SCM(소스 코드 관리 저장소를 주기적으로 확인해 변경이 있으면 빌드하는 트리거, 즉 실행 조건)을 5분마다로 설정하고 Maven 목표를 deploy로 두면, 병합 후 자동으로 빌드와 Nexus 배포가 일어난다.
- Manage Jenkins에서 관리자 이메일과 SMTP 서버를 설정하고, 잡에 E-mail Notification을 붙이면 실패한 빌드의 알림을 받는다.
- 잡을 먼저 만든 뒤에 병합해야 병합이 만든 변경을 잡이 감지해 릴리스한다.
