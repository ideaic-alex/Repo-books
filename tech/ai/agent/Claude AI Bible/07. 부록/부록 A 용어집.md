# 부록 A 용어집 (Glossary)

부록 A는 책 전체에 나오는 용어를 알파벳순으로 모아 둔 사전이다. 저자는 연구 논문의 엄밀한 뜻보다 "일하는 독자가 실제로 쓰는 뜻"을 우선했고, 두 뜻이 크게 다를 때만 차이를 짚는다. 이 노트는 정의를 옮기지 않고, 같은 계열의 용어를 묶어 쉬운 말로 다시 풀었다. 책에 실린 용어만 다룬다.

> **쉽게 말하면**
> 낯선 말이 나오면 여기서 한 줄로 확인하고 본문으로 돌아가라는 휴대용 사전이다. 결국 "Claude가 말만 하느냐, 일까지 하느냐"를 가르는 말들이 핵심이다.

> **참고(노트 작성자)** 모델 버전, 베타·리서치 프리뷰 표시, 컨텍스트 창 크기는 책이 쓰인 2026년 기준 서술이며 이 노트가 검증하지 않았다. 최신 내용은 공식 문서로 확인해야 한다. 아래 "관련 장"은 책이 직접 언급한 부 또는 부록만 적었고, 장 번호를 확인하지 못한 곳은 `-`로 두었다.

## 1. 에이전트와 도구

| 용어 | 쉬운 설명 | 관련 장 |
|------|-----------|---------|
| Agent, Agentic | 한 번 답하고 끝내지 않고 목표를 받아 단계를 짜고, 도구를 쓰고, 결과를 스스로 확인하며 끝까지 가는 시스템. 그런 성질을 가리키는 형용사가 agentic | 4~5부 |
| Agent SDK | 에이전트를 코드로 만들 때 쓰는 개발 도구 모음. 모델을 돌리고 도구를 연결하는 반복 구조를 대신 제공한다 | 5부 |
| Tool use, Function calling | 모델이 필요할 때 외부 기능을 부르겠다고 정하고, 실제 실행은 내 쪽 프로그램이 하는 방식. 두 이름은 같은 개념 | 5부 |
| Computer use | 사람처럼 화면을 보고 마우스와 키보드를 조작하는 능력. 강력한 만큼 위험해서 확인 절차가 따른다 | 5부 |
| MCP, MCP client, MCP server | 외부 도구와 AI를 잇는 공통 규격. 도구를 감싸 제공하는 쪽이 서버, 가져다 쓰는 앱이 클라이언트 | 4부, 부록 D |
| Connector | 메일, 일정, 파일 저장소 같은 서비스와 Claude를 클릭으로 잇는 다리. 안쪽 배관이 MCP | 3부 |
| Hook | 도구 실행 전, 파일 수정 후 같은 정해진 순간에 자동으로 끼어드는 장치 | 4부 |
| Plugin, Marketplace | 명령·스킬·훅·MCP 연결을 한 묶음으로 설치하게 한 꾸러미와 그것을 찾는 장터 | 4부 |
| Skill, SKILL.md | 반복 작업을 한 번 가르쳐 두는 재사용 능력. 그 핵심 파일이 SKILL.md | 4부, 부록 C |

## 2. 제품과 요금

| 용어 | 쉬운 설명 | 관련 장 |
|------|-----------|---------|
| Claude Code | 터미널에서 파일을 읽고 고치고 명령을 실행하는 코딩용 도구 | 4부 |
| Cowork | 내 컴퓨터에서 파일 작업, 커넥터, 예약 작업을 맡기는 데스크톱 환경 | 3부 |
| Claude in Chrome, Claude in Excel | 브라우저와 엑셀 안에서 일하는 에이전트 | 3부 |
| Artifact | 대화 옆 별도 창에 만들어지는 문서, 코드, 작은 앱 등 결과물 | 2부 |
| Project, Memory | 지침과 자료를 묶은 작업 공간, 그리고 대화 사이에 정보를 기억하는 기능 | 2부 |
| Workspace | 파일, 도구, 권한의 경계가 정해진 작업 구역 | 3부 |
| CLAUDE.md | 프로젝트 규칙과 빌드 명령을 적어 두면 세션 시작 때 자동으로 읽히는 파일 | 4부 |
| Free, Pro, Max, Team, Enterprise | 무료부터 개인 유료, 대량 사용 개인, 소규모 조직, 대기업용까지의 요금 단계 | 1부 |
| Beta | 쓸 수는 있지만 아직 미완성이라 바뀌거나 사라질 수 있는 기능 | - |

## 3. 모델과 동작 원리

| 용어 | 쉬운 설명 | 관련 장 |
|------|-----------|---------|
| Opus, Sonnet, Haiku | 가장 강한 모델, 균형 잡힌 기본 모델, 빠르고 싼 모델 | 1부 |
| LLM, Transformer, Parameter | 방대한 글로 훈련된 언어 모델, 그 바탕 구조, 훈련으로 굳은 내부 수치 | - |
| Training, Inference | 모델을 만드는 과정과 만들어진 모델을 쓰는 과정 | - |
| Token, Context window | 모델이 읽고 쓰는 글의 단위, 한 번에 담을 수 있는 총량 | 1부 |
| Embeddings, RAG | 뜻을 숫자로 바꿔 비슷한 것끼리 찾는 방법, 찾은 자료를 질문과 함께 넣어 답하게 하는 기법 | - |
| Multimodal, Vision | 글 외에 이미지도 다루는 성질과 이미지를 읽는 능력 | 5부 |
| Extended thinking, Reasoning | 답하기 전에 단계별로 오래 생각하는 모드. 정확도를 얻는 대신 시간과 토큰을 쓴다 | 2부 |
| Constitutional AI, RLHF, HHH | 원칙에 비추어 스스로 고치게 하는 훈련, 사람 평가로 다듬는 훈련, 유용·무해·정직이라는 목표 | - |
| Fine-tuning | 특정 자료로 추가 훈련하는 것. 대개 프롬프트와 검색으로 충분하다 | - |
| Hallucination | 틀린 내용을 맞는 말처럼 자신 있게 지어내는 현상. 검증은 사용자 몫 | 전반 |

## 4. 프롬프트와 API 설정

| 용어 | 쉬운 설명 | 관련 장 |
|------|-----------|---------|
| Prompt, Prompt engineering | 입력과 그것을 잘 쓰는 기술 | 2부 |
| Zero-shot, Few-shot | 예시 없이 시키기, 예시 몇 개를 보여 주고 시키기 | 2부 |
| System prompt | 대화 시작 전에 역할과 규칙을 정하는 상위 지침 | 2부, 5부 |
| Prompt injection | 읽는 문서에 숨긴 악성 지시로 모델을 가로채는 공격 | 4~5부 |
| API, Batch API, Streaming, Prompt caching | 프로그램이 Claude를 부르는 통로, 대량 비실시간 처리, 글자를 이어 받는 응답, 반복 입력 재사용 | 5부 |
| Temperature, Rate limit | 출력의 다양성 조절값, 사용량 상한 | 5부 |

## 핵심 정리

- 에이전트의 핵심은 도구를 쓰고 결과를 확인하며 끝까지 가는 것이고, MCP와 커넥터가 그 도구 연결을 맡는다.
- 모델은 Opus(최고 성능), Sonnet(기본), Haiku(속도와 비용)로 나뉘고, 요금 단계와 버전은 바뀐다.
- 환각과 프롬프트 인젝션이 가장 중요한 두 위험이다.
