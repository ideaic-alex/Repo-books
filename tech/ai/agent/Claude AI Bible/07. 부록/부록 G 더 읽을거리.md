# 부록 G 더 읽을거리 (Further Resources)

부록 G는 책을 덮은 뒤 계속 배우는 방법을 알려 준다. 저자는 이 분야 책은 인쇄되는 순간부터 낡기 시작한다고 인정하고, 먼저 권위 있고 최신인 공식 자료를 소개한 뒤 그 밖의 글을 판단하는 습관으로 마무리한다. 이 노트는 URL을 옮기지 않고 자료의 종류와 용도만 정리한다.

> **쉽게 말하면**
> 숫자와 기능은 공식 문서에서 확인하고, 그 밖의 글은 날짜와 이해관계를 따져 읽으라는 안내다.

## 1. 공식 자료와 쓰임

| 자료 | 무엇을 알려 주나 |
|------|-----------------|
| 공식 문서(docs 사이트) | API, SDK, 모델 목록, Claude Code, MCP, 스킬 등 전 제품의 최신 기준. 책과 다르면 문서가 이긴다 |
| 지원 센터(support 사이트) | 요금제와 결제, 계정과 개인정보 설정, 요금제별 포함 내용, 앱 사용법. 개발자보다 사용자를 위해 쓰였다 |
| API·개발자 레퍼런스 | 엔드포인트, 요청·응답 형식, 모델별 API 문자열, 속도 제한, 프롬프트 캐싱, Batch API, 도구 사용. 책이 일부러 느슨하게 둔 세부를 확인할 유일하게 안전한 곳 |
| 릴리스 노트와 변경 기록 | 모델과 기능의 출시·변경 소식. 몇 주에 한 번 훑으면 가장 싸게 최신을 유지한다 |
| 책임 있는 사용·안전 자료 | 사용 정책, 안전 연구, Constitutional AI와 "유용·무해·정직" 접근. 사업이나 규제 분야에 배포한다면 꼼꼼히 읽는다 |
| Anthropic의 발표와 연구 | 새 모델 계열, 주요 기능 출시와 그 배경. 1차 출처라 왜곡이 적다 |

> **참고(노트 작성자)** 사이트 이름과 자료 종류는 책이 쓰인 2026년 기준이며 노트가 접속해 확인하지 않았다.

## 2. 공식이 아닌 글을 읽는 다섯 가지 습관

| 습관 | 이유 |
|------|------|
| 날짜부터 확인 | 1년 반 전 튜토리얼은 사라진 모델, 바뀐 가격, 이름이 바뀐 기능을 말할 수 있다. 날짜 없는 글은 그 자체로 경고 신호 |
| 수치는 공식으로 재확인 | 제3자가 말한 토큰 한도나 가격은 확인하러 갈 단서이지 사실이 아니다 |
| 누가 돈을 받는지 보기 | 경쟁사의 비교, 제휴 링크가 있는 리뷰, 업체의 "독립" 벤치마크는 각자 이해관계가 있다 |
| 시연과 결과 구분 | 한 번 멋지게 된 영상은 안정적으로 된다는 증거가 아니다. 백 번째 시도와 지저분한 실제 입력에서 어떤지를 묻는다 |
| 한계를 밝히는 글 선호 | 안 된 것과 경계, 불확실한 점을 말하는 글이 오래 간다. AI를 마찰 없는 마법으로 파는 글은 경계한다 |

## 3. 활용 순서 제안

1. 공식 문서와 지원 센터를 북마크한다.
2. 몇 주에 한 번 릴리스 노트를 훑는다.
3. 사업이나 규제 환경에 쓴다면 사용 정책을 정독한다.
4. 외부 글은 위 다섯 습관으로 걸러 읽고, 숫자는 꼭 공식 자료로 확인한다.

## 핵심 정리

- 가격, 한도, 모델 이름, 기능은 공식 문서와 지원 센터가 정답이다.
- 변경 기록을 꾸준히 읽는 습관이 전문가처럼 보이게 하는 가장 간단한 방법이다.
- 비공식 글은 날짜, 이해관계, 시연과 실제 결과의 차이를 따져 읽는다.
