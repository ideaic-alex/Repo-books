# 부록 F 자주 묻는 질문 (Frequently Asked Questions)

부록 F는 저자가 가장 자주 받는 질문에 답한 모음이다. 답은 2026년 기준이고, 바뀔 수 있는 수치는 고정하지 않고 확인할 곳을 알려 준다. 이 노트는 질문을 주제별로 묶고 답을 압축했다.

> **쉽게 말하면**
> "무엇을, 얼마나, 어디까지 믿고 맡길까"에 대한 현실적인 답변집이다. 숫자는 공식 사이트가 정답이다.

> **참고(노트 작성자)** 요금제 구성, 모델 이름, 컨텍스트 창 크기, 베타·프리뷰 표시는 책이 쓰인 시점 기준이며 노트가 검증하지 않았다.

## 1. 요금과 모델

| 질문 | 답 |
|------|-----|
| 무료인가, 유료는 무엇이 다른가 | 무료 플랜은 사용 한도가 있어 입문에 충분하다. Pro, Max는 한도와 고급 기능을 늘리고, Team과 Enterprise는 조직용이다. 가격은 공식 사이트에서 확인 |
| 어떤 모델을 쓸까 | 기본은 Sonnet, 가장 어렵고 중요한 일에는 Opus, 속도와 물량이 중요하면 Haiku. 헷갈리면 Sonnet부터 써 보고 부족할 때만 바꾼다 |
| 사용 한도에 걸리면 | 한도가 풀릴 때까지 멈춘다. 자주 걸리면 상위 요금제로 올리거나 프로그램 사용이면 API로 간다 |
| 채팅 구독과 API는 뭐가 다른가 | 구독은 앱에서 쓰는 것, API는 내 소프트웨어에 붙이는 것으로 따로 과금된다. 하나가 다른 것을 대신 지불하지 않는다 |

## 2. 신뢰, 보안, 데이터

| 질문 | 답 |
|------|-----|
| 내 데이터가 학습에 쓰이나 | 모델 개선에 쓰일지는 사용자가 설정하는 항목이다. 소비자 제품은 광고가 없고 데이터를 팔지 않는다고 책은 적는다. 현재 설정과 정책을 직접 확인 |
| 기밀 업무에 써도 되나 | 많은 사람이 쓰지만 "충분한지"는 내 의무에 달렸다. 데이터 설정, 요금제(Team·Enterprise는 관리·컴플라이언스 기능 추가), 보안 문서를 확인하고 규제 데이터는 직접 약관을 확인한다 |
| 얼마나 정확한가 | 강하지만 틀리지 않는 것은 아니다. 환각이 있으므로 사실, 인용, 숫자는 검증한다. 신탁이 아니라 결과를 점검해야 하는 빠른 조수로 본다 |
| 왜 요청을 거절하나 | 해로울 수 있는 출력을 피하도록 훈련됐기 때문이다. 잘못된 거절 같으면 정당한 목적과 맥락을 설명하면 도움이 되고, 계속되면 공식 채널로 알린다 |
| 안전한가, Constitutional AI란 | 안전을 핵심으로 두며, 명시된 원칙에 비추어 스스로 출력을 점검하도록 훈련하는 방법이라고 설명한다. 완벽한 시스템은 없다 |
| 대신 메일을 보내거나 파일을 고칠 수 있나 | 에이전트 기능과 커넥터로 가능하다. 그래서 최소 권한, 보내기·삭제·지출 앞의 사람 확인, 프롬프트 인젝션 주의가 필요하다 |

## 3. 기능과 제품

| 질문 | 답 |
|------|-----|
| Cowork가 필요한가 | 필수는 아니다. 파일 작업, 다단계 작업, 커넥터, 예약 작업을 하는 데스크톱 환경이며 책 기준 리서치 프리뷰다 |
| Claude Code는 개발자만 쓰나 | 개발자 대상이지만 안내를 따르고 막히면 다시 시도할 의지가 있는 비개발자도 쓴다 |
| MCP를 한 문장으로 | Claude를 외부 도구와 데이터에 공통 규격으로 연결하는 개방형 표준 |
| 스킬이란 | 반복 작업을 매번 같은 방식으로 하게 가르치는 재사용 능력 |
| 이미지와 문서를 읽나 | 읽는다. 사진 속 글자, 차트, 스크린샷, 첨부 문서를 다룬다 |
| 웹을 검색하나 | 도구가 주어질 때만 가능하다. 브라우저 에이전트나 검색 연결이 필요하며 기본 채팅 모델은 스스로 검색하지 않는다 |
| 오프라인에서 되나 | 안 된다. Anthropic 서버에서 돌기 때문에 인터넷이 필요하다 |
| 컨텍스트 창이 왜 중요한가 | 한 번에 다룰 자료의 양을 정한다. 크지만 유한해서 아주 큰 자료는 선별하거나 검색 기법이 필요하다 |
| 과거 대화를 기억하나 | 제품과 설정에 따라 메모리와 프로젝트로 가능하다. 지속적인 작업은 프로젝트가 가장 안정적이다 |

## 4. 활용과 전망

| 질문 | 답 |
|------|-----|
| 내 일자리를 대체하나 | 대체보다 일을 바꾼다. 반복 작업이 줄고 판단, 관계, 결정이 남는다 |
| 개발자를 대체하나 | 아니다. 코드를 빠르게 쓰고 고치지만 결과가 맞고 안전한지 판단하는 사람이 필요하다 |
| 사업에 쓸 수 있나 | 쓸 수 있다. 업종별 사용 정책과 약관을 확인하고 작고 범위가 분명한 용도부터 시작한다 |
| 초보자는 어떻게 시작하나 | 무료 계정으로 실제 업무(메일 초안, 문서 요약)를 한 시간 해 보고, 프롬프트 장을 일찍 읽고, 매일 쓰게 되면 Pro로 올린다 |
| 다른 AI 비서와 차이는 | 주요 비서들의 격차는 광고보다 좁다. 책은 안전 접근, 추론과 코딩 성능, 에이전트 생태계를 Claude의 강조점으로 든다 |
| 정보가 낡았으면 | 공식 문서와 지원 센터가 최신 기준이며, 책과 숫자가 다르면 공식 사이트를 믿는다 |

## 핵심 정리

- 모델은 Sonnet으로 시작하고, 필요할 때 Opus나 Haiku로 옮긴다.
- 데이터 정책, 한도, 가격은 바뀌므로 공식 사이트에서 직접 확인한다.
- 행동을 맡길수록 최소 권한과 사람의 확인이 필요하고, 결과는 항상 검증한다.
