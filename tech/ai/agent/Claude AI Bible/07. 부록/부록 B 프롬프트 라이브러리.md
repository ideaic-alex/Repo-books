# 부록 B 프롬프트 라이브러리 (The Prompt Library)

부록 B는 바로 채워 쓸 수 있는 프롬프트 모음이다. 모든 프롬프트는 `[대괄호]` 자리에 내 사정을 채워 넣게 만들어져 있고, 대괄호를 구체적으로 채울수록 결과가 좋아진다고 저자는 말한다. 실제 자료(문서, 데이터, 원하는 결과의 견본)를 프롬프트 바로 뒤에 붙이면 더 정확해진다. 이 노트는 원문 프롬프트를 옮기지 않고, 분류와 설계 원리를 정리한 뒤 새로 쓴 예시를 보여 준다.

> **쉽게 말하면**
> 자판기 버튼이 아니라 대화의 첫 마디다. 한 번 돌려 보고, 결과에서 어긋난 한 가지만 고쳐 달라고 이어 가는 것이 사용법이다.

## 1. 사용법

1. 프롬프트를 읽고 내 상황에 맞게 대괄호를 채운다.
2. 실행한다.
3. 첫 결과는 초안이지 판결이 아니므로 비판적으로 읽는다.
4. 어긋난 점 하나를 지적해 고치게 한다.

## 2. 분류별 한눈에 보기

| 분류 | 책에 실린 대표 용도 |
|------|--------------------|
| 글쓰기·편집 | 분량 줄이기, 내 문체 따라 쓰기, 독자에 맞춰 다시 쓰기, 제목 후보, 교정 |
| 분석·조사 | 긴 문서를 결정용 요약으로, 선택지 비교표, 논리 약점 찾기, 진짜 질문 찾기, 메모 구조화 |
| 코딩 | 코드 설명, 명세대로 함수 작성, 오류 디버깅, 리팩터링, 테스트 작성 |
| 사업·전략 | 계획의 사후 부검, 한 장 제안서, 가격 점검, 30일 계획, 회의 준비 |
| 마케팅 | 고객이 쓰는 말 추출, 랜딩 페이지 초안, 한 글을 여러 채널로, 캠페인 각도, 내 카피 비평 |
| 생산성·이메일 | 내 말투로 답장, 정중한 거절, 받은편지함 분류, 머릿속 정리, 주간 회고 질문 |
| 학습·교육 | 세 가지 수준으로 설명, 학습 계획, 소크라테스식 튜터, 퀴즈, 문서를 수업으로 |
| 데이터·스프레드시트 | 데이터 해석, 수식 작성, 지저분한 데이터 정리 계획, 피벗식 요약, 차트 제안 |
| 에이전트·자동화 | 자동화 흐름 설계, 스킬 초안, 도구 명세, MCP 연결의 안전 점검, 에이전트 시스템 프롬프트 |

## 3. 잘 만든 프롬프트의 공통점

책의 항목들을 훑으면 같은 틀이 반복된다.

| 요소 | 어떻게 드러나나 |
|------|----------------|
| 역할과 독자 지정 | 비판적인 회의론자, 바쁜 임원처럼 누구의 눈으로 볼지 정한다 |
| 출력 형식 요구 | 표, 단계별 계획, 번호 목록 등 모양을 미리 정한다 |
| 모를 때의 행동 지정 | 지어내지 말고 "불명확"으로 따로 표시하라고 시킨다 |
| 반대 의견·위험 요청 | 추천과 함께 반박할 이유, 실패 가능성을 같이 묻는다 |
| 승인 후 실행 | 데이터 정리처럼 되돌리기 어려운 일은 계획부터 보여 달라고 한다 |

## 4. 새로 쓴 예시

다음은 책의 틀을 참고해 이 노트가 새로 만든 한국어 예시다.

**분량 줄이기**
> 아래 글을 [20]퍼센트 줄여 줘. 중복과 군더더기는 빼되 논점은 하나도 버리지 말고 말투는 유지해. 줄인 뒤, 지운 것 중 되살리고 싶을 만한 부분을 한 줄로 알려 줘. [글 붙여넣기]

**계획의 사후 부검**
> [목표]를 위한 내 계획이다: [계획]. 석 달 뒤 크게 실패했다고 가정하고 원인을 가능성 높은 순서로 써 줘. 그다음 가장 큰 위험 둘을 막을 수정안을 제안해.

**오류 디버깅**
> 이런 오류가 난다: [오류 메시지]. 관련 코드는 [코드]다. 기대한 동작은 [A]인데 실제로는 [B]였다. 가장 가능성 높은 원인과 수정안, 고쳐졌는지 확인하는 방법을 알려 줘.

**데이터 정리 계획**
> 아래 표에는 [날짜 형식이 제각각, 중복 행] 문제가 있다. 무엇이 잘못됐는지 짚고 단계별 정리 규칙을 제안해 줘. 내가 승인하기 전에는 아무것도 바꾸지 말고 계획만 보여 줘.

**MCP 연결 안전 점검**
> [서비스]를 MCP로 Claude에 연결해 [목적]을 하려 한다. 필요한 권한, 그 권한을 최소로 줄인 형태, 악성 지시가 들어왔을 때의 위험, 켜기 전 설정할 안전장치를 알려 줘.

## 핵심 정리

- 라이브러리는 대괄호를 채워 쓰는 시작점이며, 결과는 초안으로 보고 한 가지씩 고쳐 간다.
- 좋은 프롬프트는 독자, 형식, 모를 때의 행동, 위험 점검을 명시한다.
- 되돌리기 어려운 작업(데이터 수정, 외부 연결)은 계획 확인과 최소 권한을 먼저 요구한다.
