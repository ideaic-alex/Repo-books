# 핵심 정리

이 문서는 2부(5장부터 8장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 기능 이름, 한도, 모델 동작은 책이 쓰인 시점 기준이며 노트 작성자가 검증하지 않았다.

---

## 1. 한눈에 보는 요점

- **강한 프롬프트는 다섯 재료로 이뤄진다**: 역할·맥락, 과제, 제약, 형식, 예시. 실패는 대개 이 중 하나가 빠진 탓이다.
  - *쉽게 말하면*: 상대가 추측할 일을 줄여 주면 결과가 좋아진다.
  - → 자세히: [5장 기술로서의 프롬프팅](05%EC%9E%A5%20%EA%B8%B0%EC%88%A0%EB%A1%9C%EC%84%9C%EC%9D%98%20%ED%94%84%EB%A1%AC%ED%94%84%ED%8C%85.md)
- **말로 안 통하면 견본을 보여 주고, 부정 지시에는 긍정 지시를 붙인다**: few-shot 예시, 태그는 구분이 필요할 때만, 길이와 형식은 확인 가능하게.
  - *쉽게 말하면*: 설명보다 보여 주기가 빠르다.
  - → 자세히: [5장 기술로서의 프롬프팅](05%EC%9E%A5%20%EA%B8%B0%EC%88%A0%EB%A1%9C%EC%84%9C%EC%9D%98%20%ED%94%84%EB%A1%AC%ED%94%84%ED%8C%85.md)
- **깊은 사고와 모델 등급은 난이도에 맞춘다**: 쉬운 일에 최대 깊이나 최상위 모델을 쓰면 낭비이고, 어려운 일에 얕게 쓰면 틀린다.
  - *쉽게 말하면*: 쉬운 일은 빠르게, 어려운 일은 깊게.
  - → 자세히: [6장 고급 프롬프팅과 추론 제어](06%EC%9E%A5%20%EA%B3%A0%EA%B8%89%20%ED%94%84%EB%A1%AC%ED%94%84%ED%8C%85%EA%B3%BC%20%EC%B6%94%EB%A1%A0%20%EC%A0%9C%EC%96%B4.md)
- **구조화 출력과 컨텍스트는 설계한다**: 실제 스키마, 허용값, null, 빈 경우를 고정하고, 지시는 긴 입력 끝에 둔다.
  - *쉽게 말하면*: 출력의 틀을 미리 박아 두고 입력은 알짜만 넣는다.
  - → 자세히: [6장 고급 프롬프팅과 추론 제어](06%EC%9E%A5%20%EA%B3%A0%EA%B8%89%20%ED%94%84%EB%A1%AC%ED%94%84%ED%8C%85%EA%B3%BC%20%EC%B6%94%EB%A1%A0%20%EC%A0%9C%EC%96%B4.md)
- **반복 프롬프트는 점수로 관리하고, 외부 텍스트는 데이터로만 본다**: 작은 시험지로 평가하고, 인젝션에는 경계 표시와 최소 권한으로 대비한다.
  - *쉽게 말하면*: 감이 아니라 측정, 남이 쓴 글은 명령이 아니다.
  - → 자세히: [6장 고급 프롬프팅과 추론 제어](06%EC%9E%A5%20%EA%B3%A0%EA%B8%89%20%ED%94%84%EB%A1%AC%ED%94%84%ED%8C%85%EA%B3%BC%20%EC%B6%94%EB%A1%A0%20%EC%A0%9C%EC%96%B4.md)
- **Project는 반복 맥락을 상시 맥락으로 바꾼다**: 지침과 지식 베이스를 한 번 만들면 모든 대화가 물려받는다. 지식은 선별하고 낡은 문서는 지운다.
  - *쉽게 말하면*: 매번 처음부터 설명하지 않는다.
  - → 자세히: [7장 프로젝트·메모리·지식](07%EC%9E%A5%20%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%C2%B7%EB%A9%94%EB%AA%A8%EB%A6%AC%C2%B7%EC%A7%80%EC%8B%9D.md)
- **custom instructions, Memory, Project는 서로 다른 세 겹이다**: 전반적 선호, 쌓인 기억, 한정된 작업 공간이며 함께 작동한다. 공유 링크는 대화 전체를 노출할 수 있다.
  - *쉽게 말하면*: 무엇을 기억시키고 공유할지는 내가 정한다.
  - → 자세히: [7장 프로젝트·메모리·지식](07%EC%9E%A5%20%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%C2%B7%EB%A9%94%EB%AA%A8%EB%A6%AC%C2%B7%EC%A7%80%EC%8B%9D.md)
- **아티팩트는 제자리에서 고치는 결과물이다**: 요청으로 생성·억제하고, 수정은 바꿀 것과 둘 것을 함께 말하며, 코드는 시험-보고-수정 루프로 다듬는다.
  - *쉽게 말하면*: 결과물이 대화 옆 책상 위에 놓인다.
  - → 자세히: [8장 아티팩트와 긴 글 출력](08%EC%9E%A5%20%EC%95%84%ED%8B%B0%ED%8C%A9%ED%8A%B8%EC%99%80%20%EA%B8%B4%20%EA%B8%80%20%EC%B6%9C%EB%A0%A5.md)
- **긴 글은 단계로, 한계는 미리 안다**: 개요, 절별 작성, 목적별 퇴고. 크기, 저장소, 라이브러리, 격리 한계가 있으며 완성본은 내보낸다.
  - *쉽게 말하면*: 작업실은 작업실로 쓰고, 배포는 다른 곳에서.
  - → 자세히: [8장 아티팩트와 긴 글 출력](08%EC%9E%A5%20%EC%95%84%ED%8B%B0%ED%8C%A9%ED%8A%B8%EC%99%80%20%EA%B8%B4%20%EA%B8%80%20%EC%B6%9C%EB%A0%A5.md)

## 2. 2부를 관통하는 질문

| 질문 | 2부가 보여 주는 답 |
|------|-------------------|
| 결과가 밋밋한 이유는? | 입력이 막연해서. 재료를 채우고 견본을 준다 |
| 어려움에 따라 무엇을 조절하나? | 사고 깊이, 모델 등급, 온도, 입력의 양과 순서 |
| 반복되는 설명은 어디에 두나? | 시스템 프롬프트, Project 지침, 지식 베이스 |
| 결과물은 어디서 다듬나? | 아티팩트에서 제자리 수정 |
| 외부에서 온 글은? | 데이터로만 취급하고 명령으로 따르지 않는다 |

> **2부 한 줄 요약**
> 분명하게 말하고, 난이도에 맞춰 조절하고, 반복 맥락을 Project에 붙잡고, 아티팩트 위에서 함께 다듬는 네 가지를 규율 있게 겸해 쓰는 것이 대화의 기술이다.
