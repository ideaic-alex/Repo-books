# 핵심 정리

이 문서는 4부(13장부터 16장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 명령어, 설정 키, 모델 이름은 책이 쓰인 시점 기준이며 노트가 검증하지 않았다.

---

## 1. 한눈에 보는 요점

- **`Claude Code`는 손이 달린 에이전트다**: 파일을 읽고 쓰고 명령을 실행하며, 탐색, 계획, 편집, 실행, 반복의 루프로 일한다. 큰 작업은 계획을 먼저 승인한다.
  - *쉽게 말하면*: 말로 시키면 알아서 하지만, 먼저 계획서를 보여 달라고 해야 안전하다.
  - → 자세히: [13장 Claude Code](13%EC%9E%A5%20Claude%20Code.md)
- **`CLAUDE.md`와 훅이 에이전트를 길들인다**: `CLAUDE.md`는 상시 맥락, 훅은 모델 판단에 기대지 않는 자동 규칙과 차단 장치다.
  - *쉽게 말하면*: 매번 말하지 않아도 되는 사내 규정과 자동 경보장치다.
  - → 자세히: [13장 Claude Code](13%EC%9E%A5%20Claude%20Code.md)
- **git이 되돌리기 버튼이다**: 작업마다 커밋하고, 커밋 전에 전체 diff를 직접 읽는다. 익숙해져도 검토를 멈추지 않는다.
  - *쉽게 말하면*: 에이전트는 타이핑을, 사람은 판단을 맡는다.
  - → 자세히: [13장 Claude Code](13%EC%9E%A5%20Claude%20Code.md)
- **`Skill`은 설명이 트리거다**: `SKILL.md` 폴더의 설명은 상시, 본문은 트리거 시, 스크립트와 리소스는 필요 시 로드된다. 설명에 실제 요청 표현을 담는다.
  - *쉽게 말하면*: 언제 꺼낼지는 설명 한 줄이 정한다.
  - → 자세히: [14장 Skills](14%EC%9E%A5%20Skills.md)
- **`Skill`은 작게, 정확한 곳은 코드로**: 한 `Skill`은 한 가지 일만 하고, 정확해야 하는 계산은 스크립트, 형식은 예시 파일로 번들하며, 트리거와 출력을 따로 테스트한다.
  - *쉽게 말하면*: 판단은 모델이, 정밀함은 코드가 맡는다.
  - → 자세히: [14장 Skills](14%EC%9E%A5%20Skills.md)
- **플러그인은 가장 작은 용기를 쓴다**: `Skill`, MCP 서버, 명령, 에이전트를 함께 배포할 때만 플러그인이 필요하다. 유통만 해결할 뿐 품질은 해결하지 못하므로 조각을 먼저 검증한다.
  - *쉽게 말하면*: 부품이 먼저 작동해야 조립품도 작동한다.
  - → 자세히: [15장 플러그인과 마켓플레이스](15%EC%9E%A5%20%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8%EA%B3%BC%20%EB%A7%88%EC%BC%93%ED%94%8C%EB%A0%88%EC%9D%B4%EC%8A%A4.md)
- **설치 전에 점검하고 최소 권한만 준다**: 출처, 내용, 요청 권한을 확인하고, 쓰지 않는 플러그인의 자격 증명은 회수한다. 팀은 내부 마켓플레이스와 소유자 지정, 주기적 정리로 관리한다.
  - *쉽게 말하면*: 진열대는 믿을 수 있는 곳 하나로, 열쇠는 필요한 만큼만.
  - → 자세히: [15장 플러그인과 마켓플레이스](15%EC%9E%A5%20%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8%EA%B3%BC%20%EB%A7%88%EC%BC%93%ED%94%8C%EB%A0%88%EC%9D%B4%EC%8A%A4.md)
- **`MCP`는 AI의 만능 어댑터다**: 호스트가 서버별 클라이언트로 서버와 대화하고, 서버는 도구, 리소스, 프롬프트를 제공한다. 전송은 로컬 `stdio`와 원격 HTTP 기반이 있다.
  - *쉽게 말하면*: 한 번 만든 연결을 어느 AI에서나 꽂아 쓴다.
  - → 자세히: [16장 MCP](16%EC%9E%A5%20MCP.md)
- **연결은 곧 권한이다**: 도구 출력은 믿지 말고(프롬프트 인젝션), 연결은 읽기 전용 등 좁게, 비밀은 환경으로, 중대한 행동은 사람 승인으로, 서버 출처는 확인한다.
  - *쉽게 말하면*: 권한 벽은 방해물이 아니라 안전장치다.
  - → 자세히: [16장 MCP](16%EC%9E%A5%20MCP.md)

## 2. 4부를 관통하는 질문

| 질문 | 4부가 보여 주는 답 |
|------|-------------------|
| 에이전트를 어떻게 통제하나? | 계획 승인, 권한 설정, 훅, git 커밋과 diff 검토 |
| 반복 업무의 방식은 어디에 적나? | `Skill`(작업별), `CLAUDE.md`(프로젝트별) |
| 여러 조각은 어떻게 나누나? | 플러그인과 마켓플레이스, 버전 계약 |
| 외부 시스템은 어떻게 잇나? | `MCP` 서버 연결 |
| 모든 장에 공통된 안전 원칙은? | 신뢰할 수 있는 출처, 최소 권한, 사람의 검토 |

---

> **4부 한 줄 요약**
> 에이전트에게 일을 맡기고(`Claude Code`), 방식을 가르치고(`Skill`), 묶어 나누고(플러그인), 외부와 잇는(`MCP`) 방법을 배우되, 매 단계에서 출처 확인, 최소 권한, 사람의 검토를 놓치지 않는 것이 이 부의 핵심이다.
