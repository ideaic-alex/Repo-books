# 핵심 정리

이 문서는 5부(17장부터 20장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 모델 ID, 파라미터, 가격, 한도는 책이 쓰인 시점 기준이며 노트가 검증하지 않았으니 공식 문서로 확인하기를 권한다.

---

## 1. 한눈에 보는 요점

- **API는 사람 없이, 소프트웨어 안에서, 대량으로 돌릴 때 쓴다**: 한 번에 한 대화씩 사람과 하는 일은 채팅 제품이 낫고, API는 구독의 싼 버전이 아니라 별도 종량제다.
  - *쉽게 말하면*: 매일 아침 자동으로 돌았으면 하는 일이 API의 영역이다.
  - → 자세히: [17장 Anthropic API](17%EC%9E%A5%20Anthropic%20API.md)
- **키는 은행 비밀번호처럼 지킨다**: 환경 변수나 비밀 관리 서비스에 두고, 앱마다 따로 발급하고, 지출 한도를 먼저 건다.
  - *쉽게 말하면*: 키가 새면 내 돈이 나간다.
  - → 자세히: [17장 Anthropic API](17%EC%9E%A5%20Anthropic%20API.md)
- **요청은 네 필드, API는 상태가 없다**: `model`, `messages`, `system`, 필수 `max_tokens`로 요청하고 기록은 내가 쥐며 매번 다시 보내는 비용도 내 몫이다.
  - *쉽게 말하면*: 대화의 기억은 내가 들고 다닌다.
  - → 자세히: [17장 Anthropic API](17%EC%9E%A5%20Anthropic%20API.md)
- **비용은 모델 선택이 가장 크다**: 그 밖에 `max_tokens`, 기록 다듬기, `stop_sequences`, 프롬프트 캐싱, `Batch API`로 줄이고, 429와 5xx는 백오프로 재시도하며 400번대는 고친다.
  - *쉽게 말하면*: 쉬운 일에 비싼 모델을 쓰지 않는다.
  - → 자세히: [17장 Anthropic API](17%EC%9E%A5%20Anthropic%20API.md)
- **에이전트는 네 박자 루프**: 모델이 결정하고, 도구가 실행되고, 모델이 관찰하고, 반복한다. 단계를 미리 알 수 없을 때만 쓴다.
  - *쉽게 말하면*: 경로가 아니라 목표와 도구를 정해 준다.
  - → 자세히: [18장 Claude Agent SDK](18%EC%9E%A5%20Claude%20Agent%20SDK.md)
- **안전장치는 기반이다**: 도구 범위 제한, 위험한 행동의 승인, 좁은 샌드박스, 반복과 예산 상한을 두고 로컬에서 읽으며 검증한 뒤 좁게 배포한다.
  - *쉽게 말하면*: 없는 도구로는 사고를 칠 수 없다.
  - → 자세히: [18장 Claude Agent SDK](18%EC%9E%A5%20Claude%20Agent%20SDK.md)
- **도구 사용은 협상이고 실행은 내 코드가 한다**: 품질은 도구 이름과 설명, 파라미터 제한이라는 글쓰기에서 나온다.
  - *쉽게 말하면*: Claude는 부탁만 하고 손은 내가 움직인다.
  - → 자세히: [19장 도구 사용·컴퓨터 사용·비전](19%EC%9E%A5%20%EB%8F%84%EA%B5%AC%20%EC%82%AC%EC%9A%A9%C2%B7%EC%BB%B4%ED%93%A8%ED%84%B0%20%EC%82%AC%EC%9A%A9%C2%B7%EB%B9%84%EC%A0%84.md)
- **컴퓨터 사용은 최후의 수단**: 느리고 비싸고 위험하므로 샌드박스, 사람 확인, 프롬프트 인젝션 경계를 지키고 API가 없을 때만 쓴다. 비전은 위험이 낮지만 그럴듯한 오류가 있어 검증이 필요하다.
  - *쉽게 말하면*: 화면 클릭은 API가 없을 때만 꺼낸다.
  - → 자세히: [19장 도구 사용·컴퓨터 사용·비전](19%EC%9E%A5%20%EB%8F%84%EA%B5%AC%20%EC%82%AC%EC%9A%A9%C2%B7%EC%BB%B4%ED%93%A8%ED%84%B0%20%EC%82%AC%EC%9A%A9%C2%B7%EB%B9%84%EC%A0%84.md)
- **가장 단순한 것부터**: 단일 호출, 워크플로, 에이전트 순으로 정당화하고, 여섯 패턴 중 가장 단순한 조합을 고른다.
  - *쉽게 말하면*: 복잡함은 비용이다.
  - → 자세히: [20장 AI 에이전트와 자동화 만들기](20%EC%9E%A5%20AI%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%EC%99%80%20%EC%9E%90%EB%8F%99%ED%99%94%20%EB%A7%8C%EB%93%A4%EA%B8%B0.md)
- **믿을 만하게 만들고 좁게 출시한다**: 재시도, 검증, 폴백, 멱등성, 평가 세트, 모니터링으로 신뢰를 만들고, 피해 범위를 줄인 뒤 사람 게이트 뒤에서 시작해 점진적으로 넓힌다.
  - *쉽게 말하면*: 최악의 경우를 견딜 수 있게 만든다.
  - → 자세히: [20장 AI 에이전트와 자동화 만들기](20%EC%9E%A5%20AI%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%EC%99%80%20%EC%9E%90%EB%8F%99%ED%99%94%20%EB%A7%8C%EB%93%A4%EA%B8%B0.md)

## 2. 5부를 관통하는 질문

| 질문 | 5부가 보여 주는 답 |
|------|-------------------|
| 언제 API를 쓰나? | 사람 없이, 다른 소프트웨어 안에서, 대량으로 할 때 |
| 에이전트가 정말 필요한가? | 단일 호출, 고정 워크플로로 안 될 때만 |
| 안전은 어떻게 확보하나? | 도구 범위, 승인, 샌드박스, 한도, 작은 피해 범위 |
| 비용은 어떻게 줄이나? | 모델 선택, 캐싱, 배치, 반복 상한, 라우터 |
| 믿을 수 있는지 어떻게 아나? | 평가 세트와 로그, 알림 |

---

> **5부 한 줄 요약**
> API로 시작해 에이전트와 도구, 비전으로 확장하되, 언제나 가장 단순한 방법을 고르고 검증과 사람 게이트와 작은 피해 범위로 안전을 설계하는 개발자 가이드다.
