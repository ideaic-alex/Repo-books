# 핵심 정리

이 문서는 6부(21장과 22장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 수치와 사례, 정책 관련 서술은 책의 주장이며 노트가 검증하지 않았다.

---

## 1. 한눈에 보는 요점

- **분업이 공통 구도다**: 열두 업종 모두 에이전트가 분량 많은 기계적 일을, 사람이 판단과 검증과 책임을 맡았다.
  - *쉽게 말하면*: 타이핑은 기계가, 서명은 사람이 한다.
  - → 자세히: [21장 산업별 플레이북](21%EC%9E%A5%20%EC%82%B0%EC%97%85%EB%B3%84%20%ED%94%8C%EB%A0%88%EC%9D%B4%EB%B6%81.md)
- **도구는 일의 모양으로 고른다**: 웹 앱 템플릿, Skills, Batch API, Claude Code, 비전을 쓰는 API 파이프라인이 각각 맞는 일이 다르다.
  - *쉽게 말하면*: 못 박는 데 굴착기를 쓸 필요는 없다.
  - → 자세히: [21장 산업별 플레이북](21%EC%9E%A5%20%EC%82%B0%EC%97%85%EB%B3%84%20%ED%94%8C%EB%A0%88%EC%9D%B4%EB%B6%81.md)
- **검증은 싸게 설계한다**: 근거 인용, 출처 표기, 불확실성 표시로 확인이 몇 초 만에 끝나게 하면 실제로 지켜진다.
  - *쉽게 말하면*: 다시 하라고 하지 말고 한 줄만 대조하게 하라.
  - → 자세히: [21장 산업별 플레이북](21%EC%9E%A5%20%EC%82%B0%EC%97%85%EB%B3%84%20%ED%94%8C%EB%A0%88%EC%9D%B4%EB%B6%81.md)
- **Claude에게는 구조적 한계가 있다**: 실시간 지식, 사실 보장, 대화 간 기억, 결과 이해, 되돌림 판단, 결정론적 일관성이 없다.
  - *쉽게 말하면*: 아는 것은 많지만 창문 없는 방의 사람이라 사람이 책임을 쥐어야 한다.
  - → 자세히: [22장 한계와 위험, 그리고 솔직한 미래](22%EC%9E%A5%20%ED%95%9C%EA%B3%84%EC%99%80%20%EC%9C%84%ED%97%98%2C%20%EA%B7%B8%EB%A6%AC%EA%B3%A0%20%EC%86%94%EC%A7%81%ED%95%9C%20%EB%AF%B8%EB%9E%98.md)
- **환각은 그럴듯함의 부산물이다**: 인용, 수치, 이름에 몰리므로 자료에 근거시키고 핵심 사실을 검증하며 모른다고 말할 권한을 준다.
  - *쉽게 말하면*: 매끄러운 문장이 아니라 핵심 사실을 확인한다.
  - → 자세히: [22장 한계와 위험, 그리고 솔직한 미래](22%EC%9E%A5%20%ED%95%9C%EA%B3%84%EC%99%80%20%EC%9C%84%ED%97%98%2C%20%EA%B7%B8%EB%A6%AC%EA%B3%A0%20%EC%86%94%EC%A7%81%ED%95%9C%20%EB%AF%B8%EB%9E%98.md)
- **보안은 세 겹으로**: 데이터 최소화, 조직 규칙 준수, 민감도에 맞는 계층 선택이며 최신 조건은 공식 문서로 확인한다.
  - *쉽게 말하면*: 꼭 필요한 정보만 넣고, 규칙을 먼저 알아본다.
  - → 자세히: [22장 한계와 위험, 그리고 솔직한 미래](22%EC%9E%A5%20%ED%95%9C%EA%B3%84%EC%99%80%20%EC%9C%84%ED%97%98%2C%20%EA%B7%B8%EB%A6%AC%EA%B3%A0%20%EC%86%94%EC%A7%81%ED%95%9C%20%EB%AF%B8%EB%9E%98.md)
- **사람 검토의 값은 최악의 오류 비용으로 잰다**: 사소한 건은 자동, 중대하거나 모호한 건은 사람에게 넘기는 단계 설계가 과잉 자동화를 막는다.
  - *쉽게 말하면*: 평소엔 할 일이 없어 보여도 드문 재난에 대비한 보험이다.
  - → 자세히: [22장 한계와 위험, 그리고 솔직한 미래](22%EC%9E%A5%20%ED%95%9C%EA%B3%84%EC%99%80%20%EC%9C%84%ED%97%98%2C%20%EA%B7%B8%EB%A6%AC%EA%B3%A0%20%EC%86%94%EC%A7%81%ED%95%9C%20%EB%AF%B8%EB%9E%98.md)
- **미래는 추측과 구분해서 본다**: 컨텍스트 확대, 에이전트 발전, 도구 연동, 비용 하락은 보이는 흐름이고, 검증과 책임의 필요는 사라지지 않는다. 오래 쓸 기술은 판단력과 실제 사용 경험이다.
  - *쉽게 말하면*: 기능 이름이 아니라 위임하고 확인하는 감각을 키운다.
  - → 자세히: [22장 한계와 위험, 그리고 솔직한 미래](22%EC%9E%A5%20%ED%95%9C%EA%B3%84%EC%99%80%20%EC%9C%84%ED%97%98%2C%20%EA%B7%B8%EB%A6%AC%EA%B3%A0%20%EC%86%94%EC%A7%81%ED%95%9C%20%EB%AF%B8%EB%9E%98.md)

## 2. 6부를 관통하는 질문

| 질문 | 6부가 보여 주는 답 |
|------|-------------------|
| 무엇을 맡기고 무엇을 지키나? | 기계적이고 분량 많은 일은 맡기고, 판단과 검증과 책임은 사람이 지킨다 |
| 확인이 실제로 지켜지려면? | 근거 인용 등으로 확인을 몇 초짜리로 설계한다 |
| 그럴듯한 오답은 어떻게 막나? | 자료에 근거시키고 핵심 사실을 검증한다 |
| 언제 사람을 뺄 수 있나? | 최악의 미검증 오류가 싼 사소한 건에 한해서 |
