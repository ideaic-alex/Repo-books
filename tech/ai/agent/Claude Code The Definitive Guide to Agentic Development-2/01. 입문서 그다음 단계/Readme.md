# 입문서 그다음 단계

Claude Code를 쓰는 개발자 다수는 사용 3일 차쯤 기본기에서 멈춘다. 이 장은 그 너머의 층으로 들어가는 입구를 보여 준다. Claude Code를 질문에 답하는 도구가 아니라 읽고, 계획하고, 실행하고, 검증하는 루프를 도는 에이전트 시스템으로 이해하는 것이 출발점이다.

이 장에서는 에이전트 루프와 컨텍스트 윈도, 탐색부터 커밋까지의 4단계 흐름, 자율 실행과 사람의 판단 사이의 균형, 작업 분류 기준, 세션과 반복 전략을 차례로 다룬다. 완전히 위임할 수 있는 일은 전체의 0~20%뿐이라는 불편한 수치도 정면으로 다룬다. 이를 무시하고 전부 맡기면 겉으로 드러나지 않는 실패가 생기고, 그 뒤처리에 드는 시간이 아낀 시간보다 커진다.

---

## 1. 핵심 요점

- **루프로 이해한다**: Claude Code는 읽기, 계획, 행동, 검증을 반복하는 루프다. 프롬프트 하나가 30~40회 반복을 일으킬 수 있고, 최소 구현은 약 350줄이다.
- **컨텍스트 윈도가 유일한 제약이다**: 가득 차면 성능이 절벽처럼 떨어진다. 서브에이전트로 격리하고, CLAUDE.md를 500줄 아래로 유지하고, 선제적으로 압축한다.
- **탐색, 계획, 구현, 커밋**: 탐색과 계획은 싸고 구현과 디버깅은 비싸다. 플랜 모드에서 먼저 이해를 맞춘 뒤 구현한다.
- **권한 모드는 작업 방식 선택기다**: 플랜, 기본, 자동 수락, 전체 자동 수락을 단계에 맞게 Shift+Tab으로 오간다.
- **협업의 역설**: 업무의 약 60%에서 AI를 쓰지만 완전 위임은 0~20%다. 제안, 반응, 조정, 승인을 반복하는 파트너 모델로 접근한다.
- **작업을 분류한다**: 성공 기준이 분명하고 패턴이 확립된 일은 맡기고, 보안·핵심 로직·성능처럼 판단이 필요한 일은 지켜본다. Claude가 프로덕션 스택의 약 70~80%를 만들 수 있다.
- **한 방에 시도하고, 안 되면 협업한다**: 첫 시도 성공률은 약 3분의 1이다. 자주 커밋하고, 틀리면 고치기보다 revert한다.
- **제약을 준다**: 후속 제안은 힌트로 활용하고, 과설계는 단순함 지시로 막는다.
