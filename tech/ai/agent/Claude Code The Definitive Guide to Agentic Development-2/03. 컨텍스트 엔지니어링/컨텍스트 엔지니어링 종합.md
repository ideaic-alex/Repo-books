# 컨텍스트 엔지니어링 종합

컨텍스트 엔지니어링은 하나의 기법이 아니라 서로 맞물린 결정의 체계다. 앞선 문서들에서 다룬 도구들을 이 문서에서 한 장면으로 묶어 어떤 도구를 언제 쓸지 정리한다.

책이 말하는 결론은 단순하다. 이 체계를 익힌 개발자는 더 열심히 일하는 것이 아니라, 매 세션을 앞 세션보다 나은 컨텍스트로 시작한다.

---

## 1. 여덟 가지 구성 요소

1. **CLAUDE.md**: 영구적이고 항상 필요한 지식을 담는다. 500줄 이내로 유지하고 Claude가 추론할 수 없는 것에 집중한다. `/init`으로 시작하고, `@path` import로 확장하고, 세션 종료 시 업데이트로 다듬는다.
2. **스킬**: 필요할 때 로딩되는 참고 자료를 담는다. 계속 로딩하면 컨텍스트가 낭비되는 작업별 지침에 쓴다. 직접 호출만 하는 스킬은 `disable-model-invocation: true`로 설정한다.
3. **훅**: 지속적인 비용 없이 동적 컨텍스트를 주입한다. 환경별 상태에는 SessionStart 훅을, 압축 준비에는 PreCompact 훅을 쓴다.
4. **스펙**: 복잡한 프로젝트의 의도를 세션과 압축을 넘어 보존한다. 두 세션 넘게 이어지는 작업에 쓴다.
5. **서브에이전트**: 비싼 작업을 메인 컨텍스트에서 격리한다. 장황한 탐색과 분석은 위임해서 주 대화를 또렷하게 유지한다. 서브에이전트 열네 개를 돌려도 메인 세션의 컨텍스트가 바닥나지 않는다.
6. **CLAUDE.md의 Compact Instructions**: 자동 압축에서 핵심 규칙을 지킨다. 방향을 준 압축에는 초점 지시를 붙인 `/compact`를, 정밀한 컨텍스트 정리에는 `/rewind`의 "Summarize from here"를 쓴다.
7. **세션 종료 시 업데이트**: CLAUDE.md를 세션마다 개선되는 지식 축적기로 만든다. 지식 추가뿐 아니라 Claude가 워크플로 개선을 제안하게 해서 지속적 개선 루프로 확장한다.
8. **페르소나 적응형 CLAUDE.md**: 홈 디렉터리에 두면 개발자가 아닌 사용자도 자기 숙련도에 맞춘 자세한 설명과 점진적 작업 방식을 얻는다.

## 2. 한눈에 보는 선택표

| 필요한 것 | 알맞은 수단 | 이유 |
|-----------|-------------|------|
| 매 턴 필요한 규칙 | CLAUDE.md | 항상 로딩됨 |
| 특정 작업의 절차 | 스킬 | 호출할 때만 전체 로딩 |
| 사람이 직접 실행할 절차 | `disable-model-invocation: true` 스킬 | 비용 0 |
| 파일을 많이 읽는 탐색 | 서브에이전트 | 요약만 돌아옴 |
| 컨텍스트 없이 동작 확장 | 훅 | 외부 프로세스로 실행 |
| 시점별 상태(PR, 커밋) | SessionStart 훅 | 한 번만 주입 |
| 장기 프로젝트의 의도 | 스펙 문서 | 압축과 재시작에 영향 없음 |
| 압축 후에도 지킬 규칙 | Compact Instructions | 압축에서 보존됨 |

## 3. 마무리 생각

이 체계를 익힌 개발자의 Claude Code는 대부분의 사람 팀원보다 프로젝트를 더 잘 안다. 지식이 글로 적혀 있고, 버전 관리되고, 자동으로 로딩되기 때문이다. 책은 이것을 프롬프트 요령이 아니라 인프라라고 부른다.
