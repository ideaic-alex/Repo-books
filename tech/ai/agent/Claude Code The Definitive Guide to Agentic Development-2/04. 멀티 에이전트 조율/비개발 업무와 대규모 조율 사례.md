# 비개발 업무와 대규모 조율 사례

서브에이전트는 코드 작업에만 쓰는 도구가 아니다. 컨텍스트를 분리하고 전문 지시를 주는 것이 도움이 되는 일이라면 어디에나 같은 구조가 통한다. 이 문서는 광고 문구 생성 파이프라인과 채용 업무 플랫폼의 대규모 조율 사례를 소개하고, 비개발 업무에 공통으로 쓰이는 패턴을 정리한다.

---

## 1. 마케팅 서브에이전트 파이프라인

비개발자 한 명으로 이루어진 그로스 마케팅 팀이 광고 소재 생성을 위한 에이전트 워크플로를 만들었다. 이 워크플로는 성과 지표가 붙은 기존 광고 수백 개가 담긴 CSV 파일을 처리한다. 성과가 낮은 광고를 골라 개선 대상으로 삼고, 엄격한 글자 수 제한(헤드라인 30자, 설명 90자)을 지키는 새 변형을 만든다.

핵심 설계 선택은 범용 에이전트 하나가 아니라 전문 서브에이전트 둘을 둔 것이다.

- **헤드라인 서브에이전트**: CSV를 처리하고, 글자 수 제한과 성과 데이터를 반영해서 헤드라인 변형을 만든다.
- **설명 서브에이전트**: 같은 일을 설명 문구에 대해 한다.

관심사를 분리하면 각 에이전트의 일이 좁아지고, 출력 품질이 높아지고, 문제가 생겼을 때 디버깅하기 쉬워진다.

### 1.1 결과

- 여러 캠페인에 걸쳐 수작업으로 만들던 광고 수백 개를 몇 분 만에 생성한다.
- 글쓰기와 복사·붙여넣기로 두 시간 걸리던 일이 15분짜리 자동화 파이프라인이 됐다.
- 소수의 소재만 시험하던 팀이 수백 개를 시험하게 됐다.
- 모든 변형이 형식 제약을 지킨다. 수작업에서는 이 제약이 자주 어겨졌다.

## 2. 대규모 계층형 조율: 채용 플랫폼

한 인력 관리 플랫폼은 지원자 처리에 계층형 멀티 에이전트 조율을 써서 눈에 띄는 성과를 냈다. 중앙 조율 에이전트가 지원자 선별, 문서 자동 생성, 감정 분석을 맡는 전문 서브에이전트들을 이끄는 구조였다.

결과는 다음과 같다.

- 선별 속도 50% 향상
- 온보딩 40% 단축
- 지원자 전환율 2배
- 한 물류 고객은 새 풀필먼트 센터에 인력을 모두 채우는 데 일주일 이상 걸리던 것이 72시간 안으로 줄었다.

이 사례가 멀티 에이전트 구조가 경제적으로 정당화되는 지점이다. 구조화된 작업을 대량으로 처리하고, 서브에이전트마다 전문 분야가 분명하며, 조율에 드는 부담이 수천 건에 나뉘어 상대적으로 작아지는 경우다. 지원자 한 명을 선별하는 일에는 멀티 에이전트 조율이 필요 없다. 수천 명을 선별할 때 필요하다.

---

## 3. 공통 패턴

비개발 업무에서도 패턴은 항상 같다.

1. 시스템 프롬프트에 에이전트의 역할을 정의한다.
2. 도구를 필요한 것으로 제한한다.
3. 집중된 작업을 준다.
4. 결과를 모은다.

에이전트가 코드를 쓸 필요는 없다. 입력을 읽고, 판단을 적용하고, 구조화된 출력을 만들면 된다.

커스텀 에이전트 정의가 이것을 쉽게 만든다. 시스템 프롬프트, 사용할 도구, 모델 선호를 적은 YAML frontmatter가 붙은 Markdown 파일 하나면 충분하다. 팀은 반복되는 비개발 업무용 전문 에이전트 라이브러리를 만들고 플러그인 시스템(11장)으로 공유할 수 있다.

비용 최적화 원칙도 그대로 적용된다. 평가나 분석을 하는 에이전트는 더 싼 모델에서도 잘 돌아가는 경우가 많다. 비싼 모델은 미묘한 추론이나 복잡한 조율이 필요한 일을 위해 아껴 둔다.

---

## 4. 정리

- 마케팅 사례는 헤드라인과 설명을 서브에이전트 둘로 나눠서 품질과 디버깅 용이성을 얻고, 2시간 작업을 15분으로 줄였다.
- 채용 플랫폼 사례는 대량의 구조화된 작업에서 계층형 조율이 선별 50% 향상, 온보딩 40% 단축, 전환율 2배라는 성과를 냈다.
- 역할 정의, 도구 제한, 집중된 작업, 결과 수집이라는 패턴은 코드 작업이든 비개발 업무든 같다.
