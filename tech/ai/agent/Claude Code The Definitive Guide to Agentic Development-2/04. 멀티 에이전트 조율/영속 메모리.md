# 영속 메모리

서브에이전트는 세션이 끝나도 사라지지 않는 메모리 디렉터리를 가질 수 있다. 이 문서는 메모리를 켜는 방법, 세 가지 범위(scope)의 차이, 디렉터리 구성과 MEMORY.md의 200줄 규칙, CLAUDE.md와의 차이를 설명한다. 이어서 메모리가 너무 커졌을 때 쓰는 벡터 기반 경험 검색 사례도 소개한다.

---

## 1. 메모리 범위 세 가지

에이전트 정의의 `memory` 필드에 범위를 지정해서 켠다.

| 범위 | 저장 위치 | 공유 범위 | 어울리는 에이전트 |
|---|---|---|---|
| user | `~/.claude/agent-memory/{agent-name}/` | 모든 프로젝트 | 어디서나 통하는 지식: 코딩 스타일 선호, 흔한 디버깅 패턴, 개인 작업 규칙 |
| project | `~/.claude/projects/{project}/agent-memory/{agent-name}/` | 한 프로젝트 안 | 프로젝트 전용 에이전트: 이 코드베이스의 관례를 익히는 코드 리뷰어, 이 프로젝트의 테스트 패턴을 아는 테스트 에이전트 |
| local | (한 작업 디렉터리에 한정) | 한 작업 디렉터리 | 같은 프로젝트의 브랜치나 워크트리마다 에이전트 지식이 달라야 할 때 |

---

## 2. 디렉터리 구성과 MEMORY.md

메모리 디렉터리에는 `MEMORY.md`라는 진입점 파일과 선택적인 주제별 파일이 들어간다.

```
~/.claude/projects/{project}/agent-memory/code-reviewer/
├── MEMORY.md          # Concise index, loaded into every session
├── style-patterns.md  # Detailed notes on code style observations
└── common-issues.md   # Recurring problems this codebase has
```

`MEMORY.md`는 색인 역할을 한다. 앞의 200줄이 서브에이전트가 호출될 때마다 시스템 프롬프트에 로드된다. 200줄을 넘는 내용은 자동으로 로드되지 않는다. 그래서 Claude는 색인을 간결하게 유지하고 자세한 메모는 별도 주제 파일로 옮기도록 지시받는다. 서브에이전트는 실행하는 동안 이 디렉터리의 파일을 읽고 쓰며, `MEMORY.md`로 무엇이 어디에 저장됐는지 추적한다.

---

## 3. 쌓이는 지식의 효과

여러 번 호출되는 동안 서브에이전트는 지식을 축적한다. 관찰한 패턴, 효과가 있었던 결정, 피해야 할 오류가 쌓인다. 팀의 관례를 익힌 코드 리뷰 에이전트는 열 번째 실행에서 첫 번째보다 더 나은 리뷰를 한다. 어떤 테스트 패턴이 실제 버그를 잡았는지 기억하는 테스트 생성 에이전트는 가치 높은 테스트 케이스에 집중한다.

---

## 4. CLAUDE.md와의 차이

영속 메모리는 3장에서 다룬 CLAUDE.md와 다르다. CLAUDE.md는 메인 세션에 항상 켜져 있는 컨텍스트다. 영속 메모리는 특정 에이전트에 한정되고, 그 에이전트가 실행될 때만 로드된다. 메인 세션의 컨텍스트를 부풀리지 않으면서 특화된 에이전트에게 도메인 지식을 주는 방법이다.

---

## 5. 벡터 기반 경험 검색

자율 트레이딩 시스템을 만든 한 실무자는 평문 파일 메모리보다 한 걸음 더 나갔다. 에이전트의 경험을 벡터 데이터베이스에 저장하고, 새로운 상황을 만났을 때 유사도 검색으로 관련된 과거 시나리오를 가져오게 했다. 모든 이력을 컨텍스트에 넣는 대신, 에이전트가 현재 시장 상황과 비슷한 경험을 질의해 그것만 불러온다.

이 방식은 벡터 유사도로 과거 결정을 찾는 것이며, 선형적인 MEMORY.md 파일과 대비된다. 쌓인 경험의 양이 200줄 색인으로는 감당이 안 될 때 의미가 있다. 수천 건의 결정을 내린 트레이딩 에이전트는 그걸 전부 요약 파일에 담아 둘 수 없다. 하지만 벡터 데이터베이스가 있으면 새 시나리오마다 가장 관련 있는 과거 결정 다섯 개를 찾을 수 있고, 이 정도면 서브에이전트의 컨텍스트에 넉넉히 들어간다.

이 접근은 트레이딩 밖에도 적용된다. 반복되지만 조금씩 다른 일을 하는 에이전트, 예를 들어 장애 대응, 여러 저장소에 걸친 코드 리뷰, 고객 이슈 분류 같은 일은 과거 작업량에 맞춰 확장되는 경험 검색이 도움이 된다.

---

## 6. 정리

- `memory` 필드의 범위는 user, project, local 세 가지이고 저장 경로가 다르다.
- `MEMORY.md`는 색인이며 앞 200줄만 자동 로드되므로, 자세한 내용은 주제 파일로 분리한다.
- 영속 메모리는 해당 에이전트가 실행될 때만 로드되어 메인 컨텍스트를 아낀다.
- 경험이 너무 많으면 벡터 유사도 검색으로 관련된 몇 건만 불러오는 방식이 대안이다.
