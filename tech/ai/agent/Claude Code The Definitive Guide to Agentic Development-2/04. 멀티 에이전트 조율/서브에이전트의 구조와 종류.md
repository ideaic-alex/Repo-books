# 서브에이전트의 구조와 종류

작업이 컨텍스트 윈도 하나에 다 들어가지 않을 때 선택지는 둘이다. 그 한계와 씨름하거나, 일을 나눠 맡기는 것이다. 여러 에이전트를 나누어 맡기고 조율하는 일(오케스트레이션)이 바로 후자의 방법이다.

Claude Code에는 서브에이전트(subagent) 기능이 기본으로 들어 있다. 서브에이전트는 자기만의 컨텍스트 윈도, 자기만의 시스템 프롬프트, 제한된 도구 권한을 가진 AI 작업자다. 이 문서는 서브에이전트의 기본 구조, 기본 제공 여섯 종류, 직접 만드는 방법을 설명한다.

---

## 1. 서브에이전트는 세션 안의 세션

서브에이전트는 세션 안에서 돌아가는 또 하나의 Claude Code 세션이다. 컨텍스트 윈도와 시스템 프롬프트를 따로 갖고, 쓸 수 있는 도구도 제한된다. 일이 끝나면 부모 세션에 요약을 돌려주고, 그 서브에이전트의 컨텍스트 윈도는 버려진다.

가장 중요한 제약은 서브에이전트가 다른 서브에이전트를 만들 수 없다는 점이다. 그래서 계층은 딱 두 단계다. 위에는 조율하는 쪽(오케스트레이터, 곧 내 메인 세션)이 있고 아래에는 일하는 쪽(서브에이전트)이 있다. 중간 관리자도, 위임이 꼬리를 무는 체인도, 재귀적으로 뻗어 나가는 에이전트 트리도 없다.

이것은 한계가 아니라 의도한 설계다. 책은 재귀적인 에이전트 계층이 우아해 보이지만 실제로는 혼란을 만든다고 말한다.

---

## 2. 기본 제공 서브에이전트 여섯 종류

Claude Code에는 여섯 종류가 기본으로 들어 있다.

| 종류 | 모델 | 쓰기 가능 여부 | 용도 |
|---|---|---|---|
| Explore | 더 작고 싼 모델 (속도에 최적화) | 읽기 전용 | 결정하기 전에 코드베이스를 파악 |
| Plan | 메인 세션의 모델을 그대로 상속 | 읽기 전용 | 복잡한 조사와 계획 |
| General-purpose | - | 읽기, 쓰기, 명령 실행(모든 도구 사용 가능) | 구현 작업의 주력 |
| Bash | - | 명령 실행 | 셸 명령 연속 실행 |
| Claude Code Guide | - | - | Claude Code 자체에 관한 질문 응답 |
| Statusline-setup | - | - | 터미널 상태 표시줄 설정 |

각 종류의 쓰임새를 풀어 보면 다음과 같다.

- **Explore**: 파일을 검색하고 코드를 읽으며 코드베이스를 돌아다닐 수 있지만 아무것도 고치지 못한다. 빠르고 싸서 가볍게 자주 띄워도 부담이 없다. 무언가를 이해해야 다음 행동을 정할 수 있을 때 쓴다.
- **Plan**: Explore와 마찬가지로 읽기 전용이지만, 오케스트레이터 모델의 추론 능력을 그대로 조사와 계획에 쓴다. 계획 자체가 복잡해서 전용 컨텍스트를 줄 만할 때 쓴다.
- **General-purpose**: 모든 도구를 쓸 수 있다. 읽고, 쓰고, 명령을 실행하고, 여러 단계의 작업을 해낸다. 구현을 맡기는 주력 일꾼이다.
- **Bash**: 명령 실행에 특화돼 있다. 장황한 출력이 메인 컨텍스트를 어지럽히지 않게 하면서 셸 명령을 연달아 돌릴 때 쓴다.
- **Claude Code Guide**: Claude Code의 기능, 설정, 모범 사례에 관한 질문에 답한다. 제품 자체 문서를 찾아보고 답한다.
- **Statusline-setup**: 터미널 상태 표시줄 연동을 설정하는 좁은 일만 맡는다. 설정 과정이 까다로워서 따로 컨텍스트를 분리할 만하기 때문에 만들어졌다.

## 3. 커스텀 서브에이전트 만들기

직접 서브에이전트를 정의할 수도 있다. YAML frontmatter가 붙은 Markdown 파일로 만들고, 시스템 프롬프트, 도구 제한, 모델 선호, 턴 제한을 적는다. 파일은 다음 위치에 둔다.

- `.claude/agents/`: 프로젝트 범위
- `~/.claude/agents/`: 사용자 범위
- 플러그인도 서브에이전트를 제공할 수 있지만 우선순위가 가장 낮다.

시스템 프롬프트와 도구 제한 외에도 동작을 크게 바꾸는 필드가 여럿 있다.

### 3.1 maxTurns

서브에이전트가 멈추기 전까지 돌 수 있는 에이전트 턴(agentic turn)의 수를 제한한다. 일종의 안전 밸브다. 코드베이스를 탐색하던 서브에이전트가 점점 곁가지 검색으로 빠지는 일이 생기는데, `maxTurns: 20`처럼 상한을 두면 탐색이 거기서 끊기고 결과를 내놓게 된다. 상한이 없으면 막다른 길에 든 서브에이전트가 컨텍스트가 다 찰 때까지 토큰을 태운다.

### 3.2 mcpServers

서브에이전트마다 쓸 수 있는 MCP 서버를 따로 정한다. `.mcp.json`에 정의된 서버를 이름으로 참조해도 되고, 서버 설정 전체를 인라인으로 적어도 된다. 그래서 데이터베이스를 읽는 서브에이전트에는 DB용 MCP 서버를 주고, 코드 리뷰 서브에이전트에는 아무것도 주지 않는 식으로 쓴다. 도구 접근이 세션이 가진 전체 능력이 아니라 서브에이전트의 역할에 맞춰진다.

### 3.3 skills

서브에이전트가 시작할 때 스킬 내용을 컨텍스트에 미리 넣어 둔다. 메인 세션에서는 스킬이 필요할 때만 로드되고, Claude가 호출하기 전까지는 설명(description)만 컨텍스트에 있다. 서브에이전트는 다르다. 대화형으로 스킬을 불러오는 과정 없이 곧바로 일을 시작해야 하므로, 넘겨받은 스킬이 시작 시점에 통째로 주입된다. 따라서 미리 넣는 스킬 하나하나가 첫 턴부터 컨텍스트를 차지한다.

### 3.4 memory

서브에이전트에 영속 메모리를 켜는 필드다. 자세한 내용은 같은 장의 영속 메모리 문서에서 다룬다.

## 4. --agents 플래그로 JSON 직접 넘기기

빠르게 시험하거나 CI에서 자동화할 때는 Markdown 파일을 만들지 않고 Claude Code를 실행하면서 JSON으로 서브에이전트를 정의해 넘길 수 있다.

```bash
claude --agents '{
  "code-reviewer": {
    "description": "Reviews code for style and correctness",
    "prompt": "You are a code reviewer. Check for bugs, style violations, and security issues.",
    "tools": ["Read", "Glob", "Grep"],
    "model": "sonnet"
  },
  "debugger": {
    "description": "Debugs failing tests",
    "prompt": "You are a debugging specialist. Analyze test failures and suggest fixes.",
    "tools": ["Read", "Glob", "Grep", "Bash"],
    "model": "sonnet",
    "maxTurns": 30
  }
}'
```

`--agents`가 받는 필드는 파일 기반 정의와 같다. `description`, `prompt`, `tools`, `disallowedTools`, `model`, `permissionMode`, `mcpServers`, `hooks`, `maxTurns`, `skills`, `memory`다. 저장소에 Markdown 파일을 커밋하지 않고도 특화된 에이전트를 정의할 수 있어서, 헤드리스(headless) 파이프라인, 즉 화면 없이 터미널에서 도는 자동화에서 특히 쓸모가 있다.

---

## 5. --agent 플래그: 메인 스레드로 실행하기

이름이 비슷하지만 다른 플래그가 `--agent`다. 커스텀 에이전트 정의를 서브에이전트가 아니라 메인 스레드로 실행한다. 예를 들어 `.claude/agents/code-reviewer.md`에 `code-reviewer` 에이전트가 있다면, `claude --agent code-reviewer`로 실행했을 때 그 에이전트의 시스템 프롬프트, 도구, 설정으로 세션이 시작된다. 다른 세션 안의 일꾼이 아니라 최상위 에이전트로 도는 것이다.

이때 `Task(agent_type)` 문법으로 이 최상위 에이전트가 만들 수 있는 서브에이전트를 제한할 수 있다. 리뷰 에이전트가 explorer 유형 서브에이전트에게만 일을 맡기게 하는 식으로, 통제된 계층을 만든다.

---

## 6. 정리

- 서브에이전트는 자기 컨텍스트, 시스템 프롬프트, 제한된 도구를 가진 세션 속의 세션이며, 서브에이전트가 또 다른 서브에이전트를 만들 수는 없다.
- 기본 제공은 Explore, Plan, General-purpose, Bash, Claude Code Guide, Statusline-setup 여섯 종류다.
- 직접 정의할 때는 `maxTurns`로 폭주를 막고, `mcpServers`로 도구 범위를 좁히고, `skills`로 필요한 지식을 미리 넣는다.
- 파일 없이 `--agents` JSON으로 정의할 수 있고, `--agent`는 정의를 메인 스레드로 실행한다.
