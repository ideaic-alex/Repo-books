# 서브에이전트 운영 방법

서브에이전트를 만드는 방법을 알았다면 이제 어떻게 굴릴지가 문제다. 이 문서는 서브에이전트의 진짜 가치인 컨텍스트 격리, 포그라운드와 백그라운드 실행의 차이, 기록 보존과 재개, 자동 압축, 훅, 그리고 현장에서 자주 쓰는 세 가지 패턴을 다룬다.

---

## 1. 핵심은 병렬이 아니라 컨텍스트 격리

서브에이전트가 주는 가장 중요한 장점은 병렬 실행이 아니라 컨텍스트 격리(context isolation)다.

메인 세션에게 큰 파일을 읽히거나, 장황한 테스트 출력을 분석시키거나, 넓은 디렉터리 트리를 뒤지게 하면 그 내용이 전부 메인 컨텍스트 윈도에 쌓인다. 이런 일이 반복되면 1장에서 설명한 한계에 닿는다. 지시를 잊고, 작업을 빠뜨리고, 품질이 떨어진다.

서브에이전트는 이 지저분한 작업을 안에 가둔다. 파일 쉰 개를 읽고, 테스트 출력 천 줄을 분석하고, 저장소의 모든 디렉터리를 뒤져도 메인 세션에는 요약만 보인다. 중간 과정은 서브에이전트의 컨텍스트에 남았다가 작업이 끝나면 버려진다.

그래서 숙련된 사용자는 병렬이 필요 없을 때도 컨텍스트를 많이 먹는 작업을 서브에이전트로 보낸다.

- 큰 코드베이스 모듈을 읽을 때: 서브에이전트
- 전체 테스트 스위트를 돌리고 실패를 분석할 때: 서브에이전트
- 수백 개 파일에서 사용 패턴을 찾을 때: 서브에이전트

목표는 오케스트레이터의 컨텍스트를 가볍게 유지해서 수십 개 작업을 조율해도 흐름을 잃지 않게 하는 것이다.

### 1.1 대가: 요약은 정보를 잃는다

요약에는 손실이 있다. 게다가 서브에이전트가 자세한 결과를 돌려주면 그 길이만큼 메인 컨텍스트가 소모된다. 서브에이전트 열 개가 각각 한 페이지짜리 결과를 내면 메인 윈도에 열 페이지가 쌓인다. 해법은 서브에이전트에게 간결하게 돌려주라고 지시하는 것이다. 종합 보고서가 아니라 구체적인 답을 요구한다.

## 2. 포그라운드와 백그라운드

서브에이전트는 포그라운드나 백그라운드에서 실행할 수 있고, 이 차이는 생각보다 중요하다.

| 구분 | 포그라운드 | 백그라운드 |
|---|---|---|
| 메인 대화 | 막는다(끝날 때까지 기다림) | 계속 진행된다 |
| MCP 도구 | 전부 사용 가능 | 사용 불가 |
| 되묻기 | 막히면 질문할 수 있음 | 질문 불가 |
| 권한 | 권한 시스템과 자연스럽게 연동 | 실행 전에 미리 합의해야 함 |
| 언제 쓰나 | 결과가 다음 단계를 결정할 때 | 다른 일을 하는 동안 돌려도 될 때 |

### 2.1 포그라운드

오케스트레이터가 결과를 기다린 뒤에 다음으로 넘어간다. 사람의 확인이 필요한 상황에서도 정상적으로 처리된다.

### 2.2 백그라운드

진짜 병렬은 여기서 일어난다. 코드베이스의 서로 다른 부분을 탐색하거나 서로 다른 컴포넌트를 구현하는 서브에이전트 여러 개를 동시에 돌릴 수 있다. 대신 제약이 있다. MCP 도구를 못 쓰고, 되물을 수 없고, 권한은 실행 전에 미리 정해 둬야 한다. 사람의 승인이 필요한 상황을 만났는데 미리 승인된 것이 아니라면 자동으로 거부하고 다음으로 넘어간다.

### 2.3 포그라운드로 전환해서 재개

백그라운드 서브에이전트가 풀지 못한 질문이나 부분 결과를 남기고 끝났다면 포그라운드로 이어서 재개할 수 있다. 처음엔 백그라운드 탐색으로 시작했는데 대화로 풀어야 할 문제가 나왔을 때 유용하다. 권한이 부족해서 백그라운드 서브에이전트가 실패했을 때도 포그라운드로 재개하면 대화형 프롬프트로 다시 시도할 수 있다.

`Ctrl+B`를 누르면 실행 중인 포그라운드 작업을 백그라운드로 보낸다. 작업은 계속 돌고 메인 세션은 다시 내가 쓸 수 있다.

### 2.4 실전 감각

결과가 당장 필요하면 포그라운드, 다른 일을 하는 동안 돌려도 되면 백그라운드를 쓴다. 흔한 흐름은 이렇다. 백그라운드 서브에이전트 세 개를 띄워 세 모듈을 탐색시키고, 그동안 메인 세션에서 다른 작업을 하다가, 끝나면 결과를 검토한다.

## 3. 서브에이전트 기록과 재개

서브에이전트의 대화 기록(transcript)은 메인 대화와 따로 저장된다. 경로는 `~/.claude/projects/{project}/{sessionId}/subagents/`다. 메인 대화가 압축(compact)되어도 이 기록은 영향을 받지 않는다. Claude Code를 껐다 켠 뒤에도 같은 세션을 재개해서 "그 코드 리뷰 이어서 해줘"라고 하면 저장된 기록에서 이어간다.

덕분에 메인 세션이 초기화되어도 서브에이전트가 한 일은 사라지지 않는다. 인증 모듈을 20분 동안 분석한 서브에이전트의 전체 기록이 디스크에 있으므로, 재개하면 분석을 처음부터 다시 하지 않고 그 컨텍스트를 되살릴 수 있다.

---

## 4. 서브에이전트 자동 압축

서브에이전트도 메인 대화와 같은 논리로 자동 압축(auto-compaction)을 지원한다. 기본값은 용량의 약 95%에서 압축이 발동한다. 테스트 출력 수천 줄을 파싱하거나 파일 수십 개를 읽는 서브에이전트는 컨텍스트 윈도보다 많은 내용을 다룰 수 있다. 중간중간 요약하며 계속 진행하기 때문이다.

환경 변수 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`를 더 낮은 퍼센트(예: `50`)로 설정하면 압축이 더 일찍 시작된다. 이 값은 메인 대화와 서브에이전트에 모두 적용된다. 일찍 압축하면 컨텍스트 사용량의 최고점은 낮아지지만 앞쪽 턴의 세부 내용을 잃을 수 있다. 넓게 훑는 탐색용 서브에이전트라면 일찍 압축해도 대개 괜찮고, 세부 하나하나가 중요한 정밀 분석 서브에이전트라면 용량에 가깝게 쓰다가 압축하게 두는 편이 낫다.

---

## 5. 서브에이전트 훅

커스텀 서브에이전트는 실행 중 특정 시점에 도는 라이프사이클 훅을 지원한다. 에이전트의 YAML frontmatter에 정의하고, 세션 수준 훅(2장)과 같은 이벤트 모델을 쓰되 범위가 해당 서브에이전트로 한정된다.

### 5.1 서브에이전트 안에서 발생하는 이벤트

- **PreToolUse**: 도구를 쓰기 전에 실행된다. 호출을 막거나 바꿀 수 있다.
- **PostToolUse**: 도구가 끝난 뒤에 실행된다. 출력을 변환하거나 부수 효과를 일으킬 수 있다.
- **Stop**: 서브에이전트가 끝날 때 실행된다. 다만 런타임에서는 자동으로 `SubagentStop` 이벤트로 바뀐다.

### 5.2 프로젝트 수준 이벤트

서브에이전트 컨텍스트 밖, 프로젝트 수준에서 발생하는 이벤트도 두 개 있다.

- **SubagentStart**: 아무 서브에이전트나 생성될 때 발생한다.
- **SubagentStop**: 아무 서브에이전트나 끝날 때 발생한다.

이 둘은 서브에이전트 정의가 아니라 프로젝트나 사용자 설정에 적는다. `SubagentStart` 훅은 `additionalContext`로 서브에이전트에 지시나 데이터를 주입할 수 있다. 에이전트 정의를 고치지 않고 시스템 프롬프트를 보강하는 셈이다. `SubagentStop` 훅은 종료 코드 2로 서브에이전트가 멈추지 못하게 막을 수 있다. 끝내기 전에 반드시 특정 산출물을 만들게 강제할 때 쓴다.

### 5.3 예시: 읽기 전용 DB 서브에이전트

데이터베이스를 읽는 서브에이전트의 Bash 도구에 `PreToolUse` 훅을 걸어, 명령에 SQL 쓰기 작업(INSERT, UPDATE, DELETE, DROP)이 있는지 검사한다. 쓰기 구문이 보이면 거부(deny) 결정을 돌려줘서, 지시문에 뭐라고 적혀 있든 운영 데이터를 건드리지 못하게 한다.

이것이 다층 방어(defense in depth)다. 시스템 프롬프트는 "읽기 전용"이라고 말로 지시하고, 훅은 그것을 기계적으로 강제한다.

## 6. 자주 쓰는 세 가지 패턴

실제 운영에서 반복해서 나오는 패턴 세 가지에는 이름을 붙일 만하다. 각각 특정한 조율 문제를 풀어 준다.

### 6.1 체인(chain)

서브에이전트를 순서대로 실행한다. 각 서브에이전트가 일을 마치고 결과를 오케스트레이터에게 돌려주면, 오케스트레이터가 필요한 정보만 다음 서브에이전트에게 넘긴다. 예를 들어 서브에이전트 A가 인증 모듈을 분석해 취약점 목록을 돌려주고, 오케스트레이터가 그 목록을 B에게 넘겨 수정안을 만들게 하고, B의 결과를 C에게 넘겨 테스트를 쓰게 한다. 각 서브에이전트는 필요한 정보만 담은 깨끗한 컨텍스트로 일한다. 체인 구조는 컨텍스트가 쌓이는 것을 막으면서 정보는 계속 흐르게 한다.

### 6.2 대량 출력 작업 격리

출력이 큰 작업은 전부 서브에이전트로 보낸다. 전체 테스트 스위트는 수천 줄을 쏟을 수 있고, API 문서를 가져오면 수백 페이지일 수 있고, 로그 파일을 처리하면 수 메가바이트를 훑어야 한다. 메인 세션에서 하면 다른 모든 것을 밀어낸다. 서브에이전트가 그 양을 받아내고 "테스트 14개 실패, 전부 auth 모듈, 전부 세션 만료 관련"처럼 짧은 요약만 돌려준다.

### 6.3 병렬 조사

문제의 여러 측면을 조사하는 서브에이전트 여러 개를 동시에 띄운다. 인증 모듈, 데이터베이스 계층, API 엔드포인트를 서브에이전트 세 개가 병렬로 탐색하고 각자 결과를 돌려주면, 오케스트레이터가 이를 종합해 전체 그림을 만든다. 순차 탐색보다 빠르고, 오케스트레이터의 컨텍스트에서 중간 탐색 과정이 빠진다.

---

## 7. 정리

- 서브에이전트의 본질적인 가치는 컨텍스트 격리이고, 병렬은 그다음이다.
- 결과가 지금 필요하면 포그라운드, 아니면 백그라운드로 돌린다. 백그라운드는 MCP, 되묻기, 즉석 권한 승인이 안 된다.
- 서브에이전트 기록은 디스크에 따로 저장되어 메인 압축이나 재시작 뒤에도 재개할 수 있다.
- 훅은 지시문으로 말한 규칙을 기계적으로 강제하는 장치다.
- 체인, 대량 출력 격리, 병렬 조사가 기본 패턴이다.
