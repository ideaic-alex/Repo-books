# 에이전트 도구를 위한 프롬프트 작성법

Claude Code 같은 에이전트 도구에 쓰는 프롬프트는 챗봇에게 하는 질문과 다르다. 에이전트는 파일을 읽고 코드를 쓰고 테스트를 돌리면서 수십 가지 작업을 이어서 하므로, 프롬프트는 질문이 아니라 작업 지시서로 봐야 한다. 이 장은 결과를 가르는 요인이 문장력이 아니라 엔지니어링이라는 관점에서 실전 패턴을 정리한다.

가장 효과가 큰 방법은 Claude가 스스로 결과를 검증할 기준을 주는 것이다. 그 위에 위임하는 태도, 풍부한 입력, 중간 개입, 스펙 주도 개발, 백프레셔, 계획 먼저 세우기, 제약과 질문 같은 패턴을 쌓는다. 확장 사고 설정과 분석 업무용 프롬프트, 스킬 활용도 함께 다룬다.

---

## 1. 핵심 요점

- **검증 기준이 가장 중요하다**: 테스트 명령, 기대 출력, 스크린샷, 동작 설명을 주면 "만들고 기대하는" 방식이 "만들고, 시험하고, 고치는" 루프로 바뀐다.
- **탐색은 모호하게, 구현은 구체적으로**: 파일 지목, 제약, 예시로 구체성을 높이고, 스크립트가 아니라 동료에게 맡기듯 목표와 맥락 중심으로 쓴다.
- **입력과 개입을 활용한다**: `@` 파일 참조, 이미지, URL, 파이프 입력을 쓰고, 작업 도중에 구체적으로 끼어들어 방향을 바꾼다. 과하게 복잡해지면 "더 단순하게 해 봐"로 끼어든다. 역할을 정해 주면 작업 방식도 달라진다.
- **스펙 주도 개발**: 조사, 스펙, 다듬기, 작업 분할, 완료 순서로 가며, 스펙 파일이 컨텍스트 압축과 세션 재시작을 넘어 남는 기준 문서가 된다.
- **린트 설정도 프롬프트다**: 엄격한 린트, 타입 검사, 테스트, 프리커밋 훅이 백프레셔로 Claude의 실수를 바로잡고, 사람의 피드백은 아키텍처와 도메인 로직에 쓴다.
- **계획이 싸다**: 계획은 약 10,000 토큰, 잘못된 구현은 약 500,000 토큰이 든다. `Ctrl+G`로 계획을 직접 편집한다.
- **가정을 드러낸다**: 제약 명시, 출력 형식 지정, 자기 비평, 철저한 질문, 초안 제안으로 Claude의 추측을 줄인다.
- **마법의 문구는 없다**: "think harder" 같은 문구는 사고 예산에 영향이 없고, `MAX_THINKING_TOKENS`와 `CLAUDE_CODE_EFFORT_LEVEL`로 조절한다.
