# 시스템 프롬프트와 출력 제어 플래그

Claude Code의 기본 지시문(시스템 프롬프트)을 바꾸는 플래그와, 헤드리스 모드에서 결과를 어떤 형태로 받을지 정하는 플래그를 정리한다. 자동화 스크립트에서 Claude Code를 부품처럼 쓰려면 꼭 알아야 하는 부분이다.

헤드리스(headless) 모드는 화면 없이 터미널에서 실행하는 방식이며 `-p`로 켠다. 사람이 읽기보다 다른 프로그램이 결과를 받아 쓰는 경우가 많아서, 출력 형식을 고르는 일이 중요해진다.

---

## 1. 시스템 프롬프트 플래그

시스템 프롬프트는 사용자의 프롬프트와 별도로 Claude에게 기본 행동 방식을 알려 주는 지시문이다. 이를 바꾸는 방법은 두 갈래로, 통째로 교체하거나 기본 지시문 뒤에 덧붙이는 것이다.

| 플래그 | 동작 | 사용 가능한 모드 |
|--------|------|------------------|
| `--system-prompt <text>` | 시스템 프롬프트를 주어진 텍스트로 완전히 교체한다 | 헤드리스 모드만 |
| `--system-prompt-file <path>` | 시스템 프롬프트를 파일 내용으로 완전히 교체한다 | 헤드리스 모드만 |
| `--append-system-prompt <text>` | 기본 시스템 프롬프트 끝에 지시를 덧붙인다 | 대화형과 헤드리스 |
| `--append-system-prompt-file <path>` | 파일 내용을 기본 시스템 프롬프트 끝에 덧붙인다 | 대화형과 헤드리스 |

### 1.1 교체와 덧붙이기의 차이

교체(`--system-prompt`, `--system-prompt-file`)는 기본 지시문을 모두 버리고 내가 준 내용만 쓴다. 그래서 헤드리스 모드에서만 허용된다. 반대로 덧붙이기(`--append-system-prompt`, `--append-system-prompt-file`)는 기본 지시문을 살려 두고 뒤에 내 규칙을 추가하므로 대화형에서도 쓸 수 있다.

실무에서는 덧붙이기가 안전한 편이다. 통째로 교체하면 Claude Code가 원래 갖고 있던 기본 지시가 모두 사라지므로, 필요한 내용을 직접 채워 넣어야 한다.

### 1.2 텍스트와 파일

같은 동작이라도 짧은 문장이면 `<text>`, 길거나 팀이 공유하는 지침이면 `<path>`로 파일을 넘기는 쪽이 낫다. 파일은 git으로 관리할 수 있어서 변경 이력을 남기기 좋다.

```bash
claude -p "변경 사항 리뷰" --append-system-prompt "한국어로 답한다"
claude -p "변경 사항 리뷰" --system-prompt-file ./review.md
```

## 2. 출력 제어 플래그 (헤드리스 모드)

| 플래그 | 설명 |
|--------|------|
| `--output-format text` | 일반 텍스트 출력 (`-p`의 기본값) |
| `--output-format json` | 결과, 비용, 소요 시간, 세션 ID를 담은 JSON 객체 |
| `--output-format stream-json` | 실시간 처리용 줄바꿈 구분 JSON 스트림 |
| `--max-turns <n>` | 에이전트가 진행할 턴 수를 제한한다 |
| `--budget-tokens <n>` | 세션의 토큰 예산을 정한다 |
| `--fallback-model <model>` | 주 모델을 쓸 수 없을 때 대신 쓸 모델 |

### 2.1 세 가지 출력 형식

**text.** 헤드리스 모드의 기본값이다. 응답 문장만 평범하게 찍어 주므로, 다른 CLI 도구로 파이프(pipe)해서 넘기기에 알맞다.

**json.** 실행이 끝났을 때 JSON 객체 하나를 돌려준다. 담기는 키는 다음과 같다.

| 키 | 내용 |
|----|------|
| `result` | 응답 텍스트 |
| `cost` | 토큰 비용 |
| `duration` | 실행 시간 |
| `session_id` | 세션 식별자 |
| `is_error` | 오류 여부(불리언) |

응답뿐 아니라 비용과 오류 여부를 함께 받아야 하는 자동화에 쓴다. `session_id`를 저장해 두면 `claude -r <id>`로 같은 세션을 다시 열 수도 있다.

**stream-json.** 실행하는 동안 줄바꿈으로 구분된 JSON 메시지를 계속 내보낸다. 한 줄이 JSON 객체 하나이고, `type` 필드가 이벤트 종류를 알려 준다. 종류로는 assistant 메시지, 도구 사용, 도구 결과, 시스템 메시지가 있다. 실시간 모니터링이나 다른 시스템과의 연동에 적합하다.

```bash
claude -p "린트 오류 고쳐 줘" --output-format json
claude -p "마이그레이션 진행" --output-format stream-json
```

### 2.2 실행 한도와 대비책

`--max-turns <n>`은 에이전트가 도구를 쓰고 판단하는 반복 횟수의 상한이다. 자동화에서 에이전트가 끝없이 돌지 않도록 막는 안전장치가 된다. `--budget-tokens <n>`은 세션 전체의 토큰 예산을 정한다. 비용 통제가 필요한 배치 작업에서 쓴다.

`--fallback-model <model>`은 주 모델을 쓸 수 없을 때 대신 쓸 모델을 지정한다. 야간 작업이 모델 장애 때문에 멈추는 일을 줄여 준다.

## 3. 기타 플래그

| 플래그 | 설명 |
|--------|------|
| `--verbose` | 자세한 로그를 켠다 |
| `--no-cache` | 프롬프트 캐싱을 끈다 |
| `--version` | 버전을 출력하고 종료한다 |
| `--help` | 도움말을 출력하고 종료한다 |

프롬프트 캐싱은 반복해서 보내는 컨텍스트(CLAUDE.md, 시스템 프롬프트 등)의 비용을 줄여 주는 기능이다. `--no-cache`로 끄면 그 장점이 사라지므로 특별한 이유가 없다면 켜 두는 쪽이 좋다. 앞 장의 핵심 요점에서도 캐싱이 풍부한 컨텍스트를 경제적으로 만든다고 정리한다.
