# 권한 플래그와 권한 모드

Claude Code가 파일을 고치거나 셸 명령을 실행할 때 사용자에게 물어볼지, 그냥 진행할지를 정하는 설정을 모았다. 권한 플래그, 권한 모드 다섯 가지, 권한 규칙에 쓰는 도구 이름과 패턴 문법이 여기에 들어간다.

권한(permission)은 에이전트가 할 수 있는 일의 범위를 정하는 장치다. 느슨하면 빠르지만 위험하고, 엄격하면 안전하지만 자꾸 멈춘다. 상황에 맞는 지점을 고르는 것이 핵심이다.

---

## 1. 권한 플래그

| 플래그 | 설명 |
|--------|------|
| `--allowedTools <tools>` | 물어보지 않고 허용할 도구를 쉼표로 나열한다 |
| `--disallowedTools <tools>` | 거부할 도구를 쉼표로 나열한다 |
| `--dangerously-skip-permissions` | 모든 권한 확인을 건너뛴다 (샌드박스 환경에서만 사용) |
| `--permission-prompt-tool <mcp_tool>` | 권한 결정을 MCP 도구에 맡긴다 |

`--allowedTools`와 `--disallowedTools`는 허용 목록과 거부 목록이다. 헤드리스 실행에서는 중간에 사람이 승인할 수 없으므로, 필요한 도구를 미리 허용해 두는 방식이 흔하다. `--dangerously-skip-permissions`는 이름부터 경고를 담고 있다. 모든 확인을 건너뛰기 때문에 샌드박스(sandbox), 즉 외부와 격리된 환경에서만 써야 한다. `--permission-prompt-tool`은 권한 판단을 사람 대신 MCP 도구가 내리게 하는 옵션이다.

```bash
claude -p "테스트 돌려 줘" --allowedTools "Bash(npm test)"
```

## 2. 권한 모드 다섯 가지

| 모드 | 동작 |
|------|------|
| Plan | 읽기 전용이다. 파일을 수정하거나 쓰기 명령을 실행하지 못한다 |
| Default | 파일 수정과 셸 명령을 실행하기 전에 권한을 묻는다 |
| Auto-accept edits | 파일 수정은 묻지 않고 진행한다. 셸 명령은 여전히 묻는다 |
| Full auto-accept | 모든 작업을 묻지 않고 진행한다 |
| Bypass permissions | 모든 확인을 건너뛴다. CLI 플래그로만 켤 수 있고 샌드박스 환경이 필요하다 |

모드는 위에서 아래로 갈수록 자율성이 커진다. 플래그로 시작할 때는 `--permission-mode`에 default, plan, auto-edit, full-auto, bypassPermissions 중 하나를 넘긴다. 표의 이름과 플래그 값이 조금 다르게 보이는데, Auto-accept edits가 `auto-edit`, Full auto-accept가 `full-auto`에 해당한다고 읽으면 된다.

### 2.1 모드를 고르는 기준

- 낯선 코드베이스를 먼저 파악할 때는 플랜 모드(Plan)가 알맞다. 아무것도 바뀌지 않으니 마음 놓고 계획만 세울 수 있다.
- 평소에는 Default가 무난하다. 변경이 일어나기 전에 사람이 한 번 확인한다.
- 수정이 많지만 셸 명령은 통제하고 싶다면 Auto-accept edits가 좋다.
- 전부 맡기려면 Full auto-accept를 쓰되, 결과를 검증할 수단을 갖춰 두어야 한다.
- Bypass permissions는 CLI 플래그로만 켜며, 반드시 격리된 환경에서만 쓴다.

### 2.2 모드 바꾸기

실행 중에는 Shift+Tab으로 모드를 순환시킬 수 있고, 슬래시 명령 `/plan`으로 플랜 모드에 곧바로 들어갈 수도 있다. 자세한 키 조합은 「키보드 단축키와 여러 줄 입력」 문서에 있다.

## 3. 권한 규칙에 쓰는 도구 이름

권한 규칙은 도구 이름으로 대상을 지정한다. 원문이 정리한 도구는 다음과 같다.

| 도구 | 설명 |
|------|------|
| `Bash` | 셸 명령 실행 |
| `Read` | 파일 읽기 |
| `Write` | 파일 생성 및 덮어쓰기 |
| `Edit` | 파일 편집(문자열 치환) |
| `Glob` | 파일 패턴 매칭 |
| `Grep` | 내용 검색 |
| `WebFetch` | URL 가져오기 |
| `WebSearch` | 웹 검색 |
| `Task` | 서브에이전트 생성 |
| `Skill` | 스킬 호출 |
| `NotebookEdit` | 노트북(.ipynb) 셀 편집 |
| `TodoRead` | 작업 목록 읽기 |
| `TodoWrite` | 작업 목록 쓰기/갱신 |

### 3.1 규칙 문법

규칙은 `Tool` 또는 `Tool(specifier)` 형태로 쓰고, specifier에는 glob 패턴을 쓸 수 있다. 예를 들어 `Bash(git *)`는 모든 git 명령에 맞는다. 도구 이름만 쓰면 그 도구 전체가, 괄호로 범위를 좁히면 일부 사용만 대상이 된다.

### 3.2 MCP 도구 패턴

MCP 도구는 `mcp__<server>__<tool>` 형태의 이름을 가지며, 여기에도 glob 패턴이 통한다.

| 패턴 | 의미 |
|------|------|
| `mcp__myserver__query` | 특정 서버의 특정 도구 |
| `mcp__myserver__*` | 특정 서버의 모든 도구 |
| `mcp__*__*` | 모든 MCP 도구 |

범위가 좁을수록 안전하다. `mcp__*__*`는 편하지만 연결된 모든 MCP 서버의 도구를 한꺼번에 허용하는 셈이므로 조심해서 써야 한다.

```text
Bash(git *)
mcp__myserver__*
```

현재 설정된 규칙을 보고 관리하는 방법은 슬래시 명령 `/permissions`이며, 「슬래시 명령 모음」 문서에서 다룬다.
