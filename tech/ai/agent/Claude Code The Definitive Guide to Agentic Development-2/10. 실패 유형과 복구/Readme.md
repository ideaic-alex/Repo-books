# 실패 유형과 복구

Claude Code는 정기적으로 실패한다. 문제는 에러 메시지로 알려 주지 않고, 조용히 품질이 떨어지거나 작업을 흘리거나 확신에 차서 틀린 코드를 만든다는 점이다. 이 장은 실패를 피하라고 경고하는 대신, 도구를 효과적으로 쓰기 위한 현장 안내서로 실패 유형을 정리한다.

컨텍스트 고갈의 징후, bash가 만드는 보이지 않는 문제, 체크포인트가 되돌리지 못하는 것, 고치기와 되돌리기 사이의 판단 기준을 다룬다. 33일 동안 자율 트레이딩을 시킨 실험 사례와 숙련자들이 정리한 이름 붙은 안티패턴도 함께 살펴본다.

---

## 1. 핵심 요점

- **컨텍스트 문제는 조용하다**: 고갈, 오염, 건망증은 에러 없이 품질만 떨어뜨린다. CLAUDE.md, 서브에이전트, /compact로 구조적으로 막고, 이상 행동이 보이면 지시를 반복하지 말고 새 세션을 연다.
- **bash는 명령마다 새 셸이다**: 작업 디렉터리만 유지되고 환경 변수와 가상 환경은 사라진다. 변수 설정과 실행을 한 줄에 쓰거나 settings.json을 이용한다.
- **체크포인트에는 구멍이 있다**: Write, Edit, NotebookEdit만 추적하고 bash로 한 변경은 추적하지 못한다. 위험한 세션 전에 커밋하는 것이 진짜 안전망이다.
- **안티패턴 다섯 가지**: 주방 싱크대 세션, 수정에 수정 거듭하기, 지나치게 긴 CLAUDE.md, 믿고 나서 검증하는 간극, 끝없는 탐색. 각각 고치는 방법이 있다.
- **자신감은 정확성의 증거가 아니다**: 환각과 바이브 코딩은 검증과 이해로 막는다. 검토 깊이는 걸린 위험에 맞춘다.
- **첫 시도 성공률은 약 3분의 1이다**: 중요한 것은 올바른 결과까지의 총 시간이고, 테스트·타입·린터 같은 검증 인프라가 성공률을 높인다.
- **슬롯머신 복구**: 커밋하고, 20~30분 시간을 제한해 돌리고, 받아들이거나 되돌려서 다시 시작한다. 수정이 두 번 수렴하지 않으면 되돌린다.
- **모든 복구의 바탕은 git**: 검증된 상태로 되돌리고 더 나은 프롬프트로 다시 시도하는 것이 모든 실패 유형의 최종 복구다.
