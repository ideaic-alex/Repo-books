# 핵심 정리

이 장의 원문이 마지막에 꼽은 요점 여덟 가지를 풀어 쓴 문서다. 팀 도입을 준비할 때 체크리스트처럼 훑어보면 된다.

---

## 1. 한눈에 보는 요점

- **안내된 도입 경로를 따른다**: 코드베이스 Q&A, 작은 수정, 플랜 모드, 완전 자율의 순서로 2~4주에 걸쳐 올라간다. 처음부터 완전 자율로 가면 신뢰가 쌓이기 전에 실패 경험부터 하게 되므로, 단계를 밟는 것이 결과적으로 더 빠르다.
- **CLAUDE.md는 버전 관리에 커밋한다**: 팀이 배운 것을 한 줄씩 보태 갈수록 가치가 불어난다. 한 사람이 겪은 오류를 이후 모든 개발자가 피하게 해 주기 때문이다.
- **팀마다 쓰는 방식이 근본적으로 다르다**: 보안 팀은 자주 커밋하며 자율로 돌리고, 프로덕트 개발 팀은 핵심 비즈니스 로직을 실시간으로 지켜본다. 그러니 한 가지 사용법을 전사에 강요하지 말고 일의 성격에 맞는 모드를 고르게 해야 한다.
- **비개발 팀은 질적으로 다른 가치를 얻는다**: 변호사가 한 시간 만에 접근성 도구를 만들고, 마케팅 팀이 광고 제작을 2시간에서 15분으로 줄이고, 디자이너가 코드베이스의 상태 관리를 직접 바꾼다. 개발 속도만 재면 이 가치가 보이지 않는다.
- **엔터프라이즈 배포는 세 가지를 정해야 한다**: 좌석당 과금과 클라우드 제공자 과금 중 하나를 고르고, LLM 게이트웨이로 사용량을 한곳에서 추적하며, 조직 전체용 CLAUDE.md를 시스템 디렉터리에 배포한다. 비용 통제와 규칙 일관성이 여기서 나온다.
- **유지보수에서 확장으로 이어지는 흐름을 지킨다**: 1~3개월은 MVP 유지보수, 3~6개월은 기능 확장, 6개월 이후는 다지기와 리팩터링이다. 이 순서가 너무 이른 최적화도, 너무 이른 포기도 막아 준다.
- **서지 인력 운용이 가능해진다**: 낯선 코드베이스에 적응하는 시간이 몇 주에서 몇 시간으로 줄면, 엔지니어를 생산성 저하 없이 필요한 곳으로 옮길 수 있다. 일정과 인력 배치의 기준이 코드 지식에서 판단력으로 옮겨 간다.
- **커스텀 슬래시 명령은 팀 워크플로를 규약으로 만든다**: 누구나 찾아 쓸 수 있고 재사용된다. 한 보안 팀이 조직 모노레포 전체 커스텀 슬래시 명령의 절반을 만들었다는 사례가 이 수단의 효과를 보여 준다.
- **프로젝트 설정은 VCS로 공유한다**: .claude/settings.json을 커밋하면 저장소를 클론하는 것만으로 팀 전체의 Claude Code 환경이 맞춰진다. 신규 팀원의 설정 부담이 사라진다.
