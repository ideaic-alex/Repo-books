# 스킬과 슬래시 명령으로 만드는 팀 표준

CLAUDE.md가 "항상 켜져 있는 맥락"이라면, 스킬과 커스텀 슬래시 명령은 "필요할 때 불러 쓰는 팀의 작업 방식"이다. 한 번 만들어 두면 팀 전원이 계속 같은 방식으로 일하게 된다.

이 문서는 스킬이 팀 표준으로 왜 알맞은지, 커스텀 슬래시 명령이 어떻게 팀 관행을 담는지, 그리고 팀 간 시연 공유가 왜 가장 효과적인 확산 방법인지를 설명한다.

---

## 1. 스킬: 이식 가능한 워크플로 표준

스킬은 필요할 때만 로드되는, 폴더 형태의 지시 꾸러미다. 프로젝트에 묶이는 CLAUDE.md 항목과 달리, 스킬은 플러그인으로 배포하면 여러 프로젝트와 여러 팀원에게 그대로 통한다.

팀이 만들어 둘 만한 스킬의 예는 다음과 같다.

- **코드 리뷰 기준**: 리뷰를 어떤 구조로 쓸지, 무엇을 점검할지, 결과를 어떤 형식으로 정리할지 정한 스킬.
- **마이그레이션 패턴**: 이름 짓기, 테스트, 롤백 요건까지 포함한 팀의 데이터베이스 마이그레이션 관례를 담은 스킬.
- **릴리스 절차**: 팀의 릴리스 체크리스트를 따라가며 각 단계를 프로그램으로 검증하는 스킬.

스킬에는 팀 도입 관점에서 뚜렷한 장점이 있다. 에이전트 간 호환(cross-agent compatible)이 된다는 점이다. Claude가 터미널에서 돌든, IDE 확장에서 돌든, CI 파이프라인에서 돌든 스킬은 똑같이 동작한다. 어느 화면(surface)에서 쓰든 워크플로가 같다. 이 이식성 덕분에 스킬은 팀 전체의 워크플로 표준화에 알맞은 수단이 되고, 항상 켜진 맥락을 맡는 CLAUDE.md(3장)의 역할을 보완한다.

| 구분 | CLAUDE.md | 스킬 |
| --- | --- | --- |
| 로드 방식 | 항상 켜져 있음 | 필요할 때 로드 |
| 범위 | 프로젝트별 | 플러그인으로 여러 프로젝트에 배포 |
| 역할 | 코드베이스의 규칙과 지식 | 반복되는 워크플로 절차 |

---

## 2. 커스텀 슬래시 명령: 팀 관행을 한 번의 호출로

커스텀 슬래시 명령은 팀 고유의 워크플로를 명령 하나로 담는다. 한 보안 중심 팀은 조직 모노레포 전체 커스텀 슬래시 명령의 절반을 혼자 만들었는데, 슬래시 명령이 팀 실무에 얼마나 깊이 스며들 수 있는지 보여 주는 지표다.

팀 전용 슬래시 명령의 예는 이렇다.

- `/security-review`: 팀의 점검 목록으로 보안 중심 코드 리뷰를 실행한다.
- `/migration-plan`: 팀의 관례를 따르는 데이터베이스 마이그레이션 계획을 만든다.
- `/deploy-checklist`: 배포 전 확인 단계를 차례로 안내한다.
- `/onboard`: 신규 팀원에게 코드베이스 아키텍처를 소개한다.

슬래시 명령은 찾기 쉽다. 신규 팀원이 `/`를 입력하면 팀의 워크플로 어휘가 목록으로 뜬다. 명령마다 제도화된 지식이 들어 있다. 이런 지식은 보통 아무도 읽지 않는 문서나 시니어 엔지니어의 머릿속에만 있다.

복리 효과는 CLAUDE.md와 같다. 슬래시 명령은 한 번 만들면 팀 전체가 무기한 쓴다. 만드는 데 드는 비용은 한 시간 정도다. 만들지 않았을 때의 비용은 팀원 모두가 같은 워크플로를 각자 새로 만드는 일이다.

---

## 3. 팀 간 지식 공유: 시연 세션

팀들이 가장 효과적이라고 꼽는 도입 패턴은 구조화된 지식 공유, 즉 팀끼리 Claude Code 사용법을 서로 보여 주는 시연 세션이다.

- 백엔드 팀은 멀티 에이전트 테스트 워크플로를 보여 준다.
- 디자인 팀은 스크린샷으로 프로토타입을 만드는 방법을 보여 준다.
- 보안 팀은 자체 슬래시 명령 라이브러리를 발표한다.
- 데이터 팀은 분석 파이프라인을 처음부터 끝까지 따라가 본다.

이런 세션은 모범 사례를 자연스럽게 퍼뜨린다. 다른 팀이 생각하지 못했던 활용처도 드러난다. 법무 팀이 백엔드 팀의 코드 리뷰 스킬을 보고 계약 검토에 응용할 수 있겠다고 깨닫는다. 마케팅 팀이 데이터 팀의 분석 워크플로를 보고 캠페인 데이터에 똑같이 쓸 수 있겠다고 깨닫는다.

사내 시연은 문서보다 설득력이 강하다. 동료가 도구를 능숙하게 쓰는 모습을 직접 보면, 시작 가이드로는 만들 수 없는 도입의 추진력이 생긴다.
