# 대규모 기술 부채 해소

큰 코드베이스에는 아무도 손대지 못하는 기술 부채 백로그가 있다. 중요하지 않아서가 아니라 투자 대비 효과를 따져 보면 늘 계산이 안 맞았기 때문이다. 이 문서는 에이전트 코딩 도구가 그 계산을 어떻게 바꾸는지, 그리고 그것을 무작정 맡기지 않고 구조화해서 진행하는 방법을 설명한다.

---

## 1. 왜 부채가 쌓이는가

원문이 드는 예는 이렇다.

- 숙련 엔지니어가 3주를 써야 하는 리팩터링이 빌드당 2분을 줄여 주는 정도다.
- 지원이 끝난 의존성을 현대화하는 마이그레이션이 파일 200개를 건드려야 한다.
- 분기마다 나는 프로덕션 장애를 막아 줄 테스트 커버리지 개선에는 테스트 프레임워크와 비즈니스 로직을 모두 아는 사람이 필요하다.

## 2. 경제성이 바뀐다

에이전트 코딩 도구는 기술 부채의 경제성을 체계적으로 바꾼다. 에이전트가 오랫동안 자율적으로 일할 수 있으면 예전에는 실행 불가능했던 프로젝트가 가능해진다.

| 예전 | 에이전트를 쓰면 |
|---|---|
| 3주짜리 리팩터링 | 리뷰를 포함해 3시간짜리 작업 |
| 파일 200개 마이그레이션 | 병렬 서브에이전트로 돌리는 구조화된 실행 계획 |
| 테스트 커버리지 개선 | 주말 동안 자율 운영하고 월요일에 사람이 리뷰 |

파일 200개 마이그레이션은 앞에서 설명한 작업 의존성 관리 방식으로 처리한다.

## 3. 구조화된 방식으로 진행한다

원문은 분명히 선을 긋는다. 백로그에 에이전트를 풀어놓는 것이 아니다. 진행은 구조적이어야 한다.

1. 부채를 식별한다.
2. 명확한 스펙을 쓴다.
3. 검증 기준을 세운다. 통과해야 하는 테스트와 만족해야 하는 린트 규칙이 그 예다.
4. 그다음에 에이전트가 항목을 체계적으로 처리하게 한다.

자동 검증이 주는 백프레셔(backpressure: 기준에 못 미치면 되돌려 보내는 압력)가 에이전트가 만든 수정이 실제로 동작하도록 보장한다. 이 부분은 8장에서 다루었다. 그리고 작업 의존성 시스템은 서로 의존하는 변경이 올바른 순서로 실행되도록 보장한다.

## 4. 선순환 효과

이 변화를 일찍 알아챈 조직은 효과가 복리로 쌓이는 이점을 얻는다. 기술 부채를 하나 없앨 때마다 코드베이스는 사람과 에이전트 모두에게 다루기 쉬워진다. 코드가 깨끗해지면 에이전트의 결과물이 좋아지고, 결과물이 좋아지면 더 많은 부채가 치워진다. 이 고리가 돌수록 속도가 붙는다.

## 5. 크고 오래된 코드베이스를 위한 전략

이 장의 기법은 결국 두 가지 한정된 자원, 곧 컨텍스트와 이해를 관리하는 일로 모인다.

- **컨텍스트 관리**: 탐색은 적극적으로 서브에이전트에 맡기고, 파일은 필요한 것만 골라 읽고, 메인 대화는 시스템을 이해하는 일이 아니라 지금 할 작업에 집중시킨다. Explore 서브에이전트에 맡길 수 있는 파일을 메인 컨텍스트에 읽어 들이지 않는다. 좁게 검색할 수 있으면 넓게 뒤지지 않는다.
- **이해 관리**: 이해를 조금씩 쌓고 그것을 남겨 둔다. 스펙 문서와 CLAUDE.md에 Claude Code가 알아낸 내용을 적어 두고, 복잡한 마이그레이션은 작업 의존성으로 구조화하며, 병렬 조사로 순차적으로 읽을 때보다 빨리 이해한다.

다루기 불가능해 보이는 코드베이스는 불가능한 것이 아니라 이해하는 데 비용이 많이 드는 것일 뿐이다. Claude Code는 더 빨리 읽고, 더 넓게 검색하고, CLAUDE.md에 적은 것은 잊지 않아서 그 비용을 크게 낮춘다.

## 6. 정리

- 부채가 쌓이는 이유는 중요도가 낮아서가 아니라 경제성이 맞지 않아서였다.
- 에이전트가 장시간 자율 작업을 하면 3주 일이 3시간으로, 주말 작업이 월요일 리뷰로 바뀔 수 있다.
- 부채 식별, 스펙, 검증 기준을 먼저 갖춘 뒤 에이전트에게 맡긴다.
- 자동 검증과 의존성 순서 관리가 에이전트 수정의 신뢰성을 받쳐 준다.
