# 파일시스템 기반 분석과 3입력 워크스페이스

레거시 코드베이스에는 레거시 데이터가 따라온다. 형식이 제각각인 CSV, 세 가지 포맷으로 흩어진 설정 파일, 이미 없어진 시스템의 로그, 2년째 갱신되지 않은 문서가 그렇다. 이 문서는 Claude Code가 파일시스템 자체를 데이터 원천으로 다루는 방식과, 한 실무자가 문서화한 3입력 워크스페이스 패턴을 설명한다.

---

## 1. 파일시스템을 데이터 원천으로 쓴다

Claude Code는 파일시스템 자체를 데이터 원천으로 삼는다. 파일이 곧 분석 대상이라는 뜻이다. 지저분한 데이터가 든 디렉터리를 가리키고 목표를 주면 된다. 예를 들어 "이 파일들을 정규화해라", "중복을 찾아라", "요약을 뽑아라", "마이그레이션 계획을 세워라" 같은 목표다. 그러면 스스로 파싱하고, 비교하고, 내용을 정리한다.

이게 가능한 이유는 도구 접근 범위에 파일 읽기, 디렉터리 목록 보기, 명령 실행이 들어 있기 때문이다. 파일을 처리하는 스크립트를 쓰고, 실행하고, 출력을 확인하고, 반복할 수 있다. 한 번에 파일 하나만 이해하는 데 그치지 않고, 파일 모음에 대한 모델을 머릿속에 만들어 모음 전체를 대상으로 작업한다.

## 2. 고치기 전에 이해한다

레거시 시스템에서 이 능력은 특정한 작업 흐름을 열어 준다. 코드를 한 줄도 건드리기 전에 시스템의 설정, 데이터, 문서 디렉터리를 Claude Code에게 보여 주는 것이다. 누군가 한때 "이렇게 동작한다"고 말한 모습이 아니라 시스템이 실제로 어떻게 동작하는지를 그리게 한다.

그렇게 얻은 이해를 스펙 문서나 CLAUDE.md 추가분으로 내보내면, 이후 모든 재작성의 토대가 된다.

---

## 3. 3입력 워크스페이스 패턴

가장 효과적인 파일시스템 기반 분석은 정해진 구성을 따른다. 한 실무자가 전문 자문가에게 맡기면 수천 달러가 들었을 포트폴리오 최적화 계획을 만들면서 이 방식을 기록했다. 이 패턴은 금융에 한정되지 않고, 지저분한 데이터를 구조적으로 분석해야 하는 모든 분야에 적용된다.

워크스페이스에는 입력 세 가지가 들어간다.

### 입력 1. 원본 데이터 내보내기

CSV 파일, 데이터베이스 덤프, 설정 내보내기처럼 시스템이 기본으로 만들어 내는 것들이다. 보통 지저분하다. 열 이름이 일관되지 않고, 인코딩 문제가 있고, 내보내기끼리 데이터가 겹치고, 표준에서 벗어난 항목이 섞여 있다. 그 지저분함이 핵심이다. 정제된 버전이 아니라 시스템의 현실을 그대로 먹이는 것이다.

### 입력 2. 보충 텍스트 파일

내보내기 파일로는 얻을 수 없는 정보가 항상 있다. 조직의 암묵지, 문서화되지 않은 설정, 수동으로 덮어쓴 값, 누군가의 머릿속에만 있는 맥락이 그렇다. 이런 내용을 불릿 목록으로 일반 텍스트 파일에 적는다. 구조는 필요 없다. 날것의 사실만 있으면 된다.

### 입력 3. 상세한 목표 프롬프트

가장 중요한 입력이다. 다음을 담는다.

- 어떤 데이터가 어디에 있는지
- 원하는 출력 형식
- 내 선호와 원칙
- 알려진 제약
- 무엇이 잘못됐다고 의심하는지(Claude가 반박할 여지를 남긴다)
- 모델이 백지에서 시작하지 않고 반응할 수 있도록 던져 주는 초안 제안(strawman)

## 4. 진행 순서

1. 세 입력이 모두 들어 있는 디렉터리를 가리켜 Claude Code 세션을 시작한다.
2. Claude가 데이터 파일을 파싱하는 스크립트를 스스로 쓴다. 인코딩 문제를 처리하고, 겹치는 내보내기를 중복 제거하고, 항목을 목표 범주로 분류하고, 그대로 두면 잘못 분류될 비표준 항목도 처리한다.
3. 문제를 만날 때마다 반복하며 해결한다.
4. 이렇게 나온 기준선 분석(전체 격차 분석, 구조화된 요약, 목표와의 비교)은 보통 바로 작업에 쓸 만큼 충분히 좋다.

## 5. 반복 단계

그다음부터는 반복이 중심이 된다. 제약을 명확히 하고, 가정을 다시 짜고, Claude에게 자기 결과물을 스스로 비판하게 한다. 명확히 한 내용은 계획 안의 모든 계산, 표, 권고에 즉시 반영된다. 보충 텍스트 파일과 CLAUDE.md에는 그 과정에서 발견한 결정 사항과 데이터의 특이점이 쌓인다. 그래서 다음 세션은 지난 세션이 끝난 지점에서 이어진다.

## 6. CLAUDE.md를 일찍 만든다

초기에 CLAUDE.md를 만들고, 세션이 끝날 때마다 Claude가 배운 내용을 갱신하게 한다. 발견한 데이터의 특이점, 내린 전략 결정, 다듬은 목표 파라미터가 그 대상이다. 이렇게 하면 여러 세션에 걸친 분석이 복리로 쌓이는 과정이 된다. 이후 세션은 이전의 모든 것 위에서 시작한다.

원문이 소개한 실무자는 이 결과를 스프레드시트로 일주일 걸렸을 작업, 혹은 전문 자문 서비스 수천 달러어치에 해당한다고 설명했다. 그것을 AI 에이전트와 몇 번의 저녁 동안 주고받으며 만들어 냈다.

## 7. 정리

- 지저분한 데이터 디렉터리와 명확한 목표만 주면 Claude Code는 스크립트를 쓰고 돌리고 확인하며 분석한다.
- 레거시 작업은 고치기 전에 시스템이 실제로 어떻게 동작하는지 먼저 파악하는 데서 시작한다.
- 3입력은 원본 내보내기, 보충 텍스트, 상세한 목표 프롬프트다.
- CLAUDE.md에 세션마다 배운 내용을 쌓으면 분석이 누적된다.
