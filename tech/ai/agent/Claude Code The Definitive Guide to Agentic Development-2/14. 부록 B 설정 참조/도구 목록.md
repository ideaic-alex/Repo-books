# 도구 목록

Claude Code는 파일을 읽고 쓰고, 명령을 실행하고, 웹을 검색하고, 서브에이전트를 띄우는 일을 모두 도구(tool)로 한다. 권한 규칙과 훅의 매처가 가리키는 대상도 바로 이 도구 이름이다. 이 문서는 부록 B의 도구 목록을 용도별로 묶어 정리한다.

---

## 1. 기본 파일과 셸 도구

| 도구 | 설명 |
|---|---|
| `Bash` | 셸 명령을 실행한다. 작업 디렉터리는 명령 사이에 유지되지만 환경 변수는 유지되지 않는다 |
| `Read` | 파일 내용을 읽는다. 이미지, PDF, 노트북 파일도 지원한다 |
| `Write` | 파일을 만들거나 덮어쓴다 |
| `Edit` | 파일 안의 문자열을 정확히 찾아 바꾼다. 일치하는 부분이 하나뿐이어야 한다 |
| `Glob` | 파일 이름 패턴으로 찾는다. 수정 시간 순으로 정렬해 경로를 돌려준다 |
| `Grep` | 정규식으로 내용을 검색한다. 파일 종류 필터와 문맥 줄 출력을 지원한다 |
| `NotebookEdit` | 노트북(.ipynb)의 셀을 바꾸거나 넣거나 지운다 |
| `LSP` | Language Server Protocol 기능을 쓴다. 진단, 정의로 이동, 참조 찾기 |

`Bash`에서 헷갈리기 쉬운 부분이 있다. 한 명령에서 `cd`로 옮긴 디렉터리는 다음 명령에도 남아 있지만, `export`로 만든 환경 변수는 남지 않는다. 환경 변수를 이어 가야 한다면 훅 문서에서 설명하는 `CLAUDE_ENV_FILE`을 쓴다.

`Edit`은 바꾸려는 문자열이 파일 안에서 유일해야 한다. 같은 문자열이 여러 곳에 있으면 앞뒤 문맥을 더 넣어서 하나만 가리키게 해야 한다.

## 2. 웹 도구

| 도구 | 설명 |
|---|---|
| `WebFetch` | URL의 내용을 가져와 처리한다. HTTP는 자동으로 HTTPS로 올린다 |
| `WebSearch` | 도메인 필터를 지원하는 웹 검색. 정리된 결과를 돌려준다 |

## 3. 서브에이전트와 스킬

| 도구 | 설명 |
|---|---|
| `Task` | 격리된 컨텍스트를 가진 서브에이전트를 띄운다. 포그라운드와 백그라운드 실행을 지원한다 |
| `Skill` | 대화 안에서 스킬 기반 워크플로를 호출한다 |

`Task`로 띄운 서브에이전트는 자기만의 컨텍스트에서 일하므로, 메인 세션의 컨텍스트 윈도를 아끼면서 일을 나눠 맡길 수 있다.

## 4. 에이전트 팀 도구 (실험 기능)

에이전트 팀은 실험 기능이며, 환경 변수 `CLAUDE_CODE_ENABLE_AGENT_TEAMS`로 켠다. 팀을 만들고, 작업 목록으로 일을 나누고, 팀원끼리 메시지를 주고받는 데 쓰는 도구들이다.

| 도구 | 설명 |
|---|---|
| `TeamCreate` | 에이전트 팀을 만든다 (실험) |
| `TaskCreate` | 에이전트 팀의 작업 목록에 작업을 만든다 |
| `TaskUpdate` | 에이전트 팀 안의 작업 상태를 갱신한다 |
| `TaskList` | 에이전트 팀의 작업 목록을 본다 |
| `SendMessage` | 팀원끼리 메시지를 보낸다 |
| `TeamDelete` | 에이전트 팀을 삭제한다 |

## 5. 할 일 도구

| 도구 | 설명 |
|---|---|
| `TodoRead` | 현재의 작업(할 일) 목록을 읽는다 |
| `TodoWrite` | 할 일 항목을 쓰거나 갱신한다 |

## 6. 도구 이름을 쓰는 곳

이 이름들은 그대로 권한 규칙과 훅 매처에 쓰인다.

- 권한 규칙에서는 `Bash(npm test)`, `Write(*.env)`, `Read`처럼 도구 이름 뒤에 선택적으로 괄호로 범위를 붙인다.
- 훅 매처에서는 도구 이름을 그대로 쓰거나, 모든 도구를 가리키는 `*`를 쓴다.
- MCP로 추가한 도구는 `mcp__servername__toolname` 형식의 이름을 갖는다.

규칙과 매처는 이 이름을 기준으로 걸리므로, 도구 이름을 정확히 적어야 한다.
