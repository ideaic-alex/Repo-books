# 훅 종료 코드와 결정 제어

훅이 실행된 뒤 Claude Code에 결과를 알리는 방법은 두 가지다. 하나는 종료 코드(exit code)이고, 다른 하나는 종료 코드 0일 때 stdout으로 내보내는 JSON이다. 이 문서는 종료 코드별 효과, JSON 출력 필드, 이벤트별 결정 값, 그리고 훅 안에서 쓰는 환경 변수를 정리한다.

---

## 1. 종료 코드의 의미

| 종료 코드 | 의미 | 효과 |
|---|---|---|
| 0 | 성공 | 동작이 진행된다. stdout은 JSON 출력 필드로 해석된다. 자세한 출력 모드(Ctrl+O)에서는 stdout이 보이지만, `UserPromptSubmit`과 `SessionStart`에서는 stdout이 컨텍스트가 된다 |
| 2 | 차단 오류 | 동작이 막힌다. stdout과 JSON은 무시된다. stderr 텍스트가 Claude에게 오류 메시지로 전달된다 |
| 그 밖의 값 | 비차단 오류 | stderr는 자세한 출력 모드에서 보인다. 실행은 계속된다 |

가장 중요한 값은 2다. 훅이 어떤 동작을 막고 싶고, 그 이유를 Claude가 알고 고치게 하고 싶다면 stderr에 이유를 적고 코드 2로 끝낸다. 0이나 2가 아닌 다른 값은 오류가 났다는 사실만 남기고 흐름은 막지 않는다. 그래서 검증 스크립트가 예기치 못하게 실패해도 작업이 멈추지는 않는다.

## 2. 종료 코드 0일 때의 JSON 출력 필드

| 필드 | 타입 | 효과 |
|---|---|---|
| `continue` | boolean | false이면 이 이벤트에 대한 이후 훅 처리를 멈춘다 |
| `stopReason` | string | 멈출 때 보여 줄 메시지 |
| `suppressOutput` | boolean | true이면 기본 훅 출력을 숨긴다 |
| `systemMessage` | string | 시스템 컨텍스트로 대화에 주입되는 메시지 |
| `additionalContext` | string | 이벤트에 덧붙일 추가 컨텍스트 |
| `updatedInput` | object | 실행 전에 도구 입력을 수정한다 (PreToolUse, PermissionRequest) |
| `updatedPermissions` | object | 권한 설정을 수정한다 (PermissionRequest). "항상 허용"과 같은 효과 |
| `permissionDecision` | string | PreToolUse 훅에서 `"allow"`, `"deny"`, `"ask"` 중 하나. `hookSpecificOutput` 안에 둔다 |
| `decision` | string | `"block"`이면 동작을 멈춘다 (UserPromptSubmit, PostToolUse, PostToolUseFailure, Stop, SubagentStop) |

## 3. PreToolUse 결정 제어

PreToolUse는 `hookSpecificOutput.permissionDecision`으로 결정을 돌려준다.

| 결정 | 효과 |
|---|---|
| `"allow"` | 사용자에게 묻지 않고 진행한다 |
| `"deny"` | 실행을 막는다. 이유가 Claude에게 보인다 |
| `"ask"` | 권한 프롬프트를 띄운다. `updatedInput`과 함께 쓰면 수정된 입력을 보여 줄 수 있다 |
| 생략 또는 출력 없음 | 일반 권한 평가로 넘어간다 |

출력을 생략하면 훅이 개입하지 않은 것으로 보고 평소의 권한 규칙대로 처리한다는 점이 핵심이다. 훅은 특정 상황에서만 allow나 deny를 말하고, 나머지는 기존 규칙에 맡길 수 있다.

## 4. PermissionRequest 결정 제어

| 결정 | 효과 |
|---|---|
| `"approve"` | 사용자에게 묻지 않고 자동 승인한다 |
| `"deny"` | 사용자에게 묻지 않고 자동 거부한다 |
| 생략 또는 출력 없음 | 일반 권한 프롬프트를 보여 준다 |

`updatedInput`과 `updatedPermissions`도 지원하며, `updatedPermissions`는 "항상 허용" 선택지와 같은 효과를 낸다.

## 5. TeammateIdle과 TaskCompleted 결정 제어

두 이벤트는 JSON 결정 제어를 쓰지 않고 종료 코드만 쓴다.

| 종료 코드 | 효과 |
|---|---|
| 0 | 동작을 허용한다. 팀원이 쉬게 되고, 작업이 완료로 표시된다 |
| 2 | 동작을 막는다. stderr가 피드백으로 전달되어 계속 일하게 된다 |

예를 들어 작업 완료 훅이 테스트를 돌려 보고 실패하면 코드 2로 끝낸다. 그러면 작업이 완료로 처리되지 않고, 실패 내용이 피드백으로 돌아가 팀원이 이어서 고친다.

## 6. 훅 안에서 쓰는 환경 변수

| 변수 | 설명 |
|---|---|
| `$CLAUDE_PROJECT_DIR` | 프로젝트 루트 디렉터리. 경로에 공백이 있을 수 있으니 따옴표로 감싼다 |
| `${CLAUDE_PLUGIN_ROOT}` | 플러그인 루트 디렉터리. 플러그인에 번들된 스크립트용 |
| `$CLAUDE_ENV_FILE` | (SessionStart 전용) 환경 변수를 유지할 파일 경로. 여기에 export 문을 쓰면 이후 모든 Bash 명령에서 그 변수를 쓸 수 있다 |

`CLAUDE_ENV_FILE`은 도구 문서에서 말한 "Bash 명령 사이에 환경 변수가 유지되지 않는다"는 한계를 푸는 방법이다. SessionStart 훅에서 이 파일에 export 문을 적어 두면 된다. 예시는 다음과 같다.

```bash
#!/bin/bash
if [ -n "$CLAUDE_ENV_FILE" ]; then
  echo 'export NODE_ENV=production' >> "$CLAUDE_ENV_FILE"
  echo 'export DEBUG_LOG=true' >> "$CLAUDE_ENV_FILE"
fi
exit 0
```

먼저 변수가 비어 있지 않은지(SessionStart 이벤트에서 실행되는지) 확인한 뒤, 두 줄의 export 문을 파일에 덧붙이고 종료 코드 0으로 끝난다.
