# 훅 이벤트와 핸들러

훅(hook)은 Claude Code가 일하는 중간의 특정 시점에 내 스크립트나 판단 로직을 끼워 넣는 장치다. 도구 실행 전에 검사하거나, 프롬프트를 제출할 때 걸러내거나, 세션이 시작될 때 환경을 준비하는 식으로 쓴다. 이 문서는 훅이 받는 입력, 이벤트 종류, 핸들러 세 가지 유형, 그리고 공통 필드를 정리한다. 훅이 돌려주는 결과를 다루는 방법은 다음 문서에서 설명한다.

---

## 1. 모든 훅이 받는 공통 입력

모든 훅 이벤트는 stdin으로 JSON을 받고, 그 안에는 아래 필드가 들어 있다.

| 필드 | 설명 |
|---|---|
| `session_id` | 현재 세션의 식별자 |
| `transcript_path` | 대화 JSON 파일의 경로 |
| `cwd` | 훅이 호출될 때의 현재 작업 디렉터리 |
| `permission_mode` | 활성 권한 모드. `"default"`, `"plan"`, `"acceptEdits"`, `"dontAsk"`, `"bypassPermissions"` 중 하나 |
| `hook_event_name` | 발생한 이벤트의 이름 |

이벤트마다 고유한 필드가 더 붙는다. 예를 들어 PreToolUse에는 `tool_name`과 `tool_input`이 들어온다.

## 2. 이벤트 종류

"차단 가능" 열은 훅이 해당 동작을 막을 수 있는지를 나타낸다. "decision으로 가능"은 JSON의 `decision` 값으로 막는다는 뜻이다.

| 이벤트 | 발생 시점 | 차단 가능 | 이벤트 고유 필드 |
|---|---|---|---|
| `PreToolUse` | 도구가 실행되기 전 | 가능 | `tool_name`, `tool_input` |
| `PostToolUse` | 도구가 실행된 후 | decision으로 가능 | `tool_name`, `tool_input`, `tool_output` |
| `PostToolUseFailure` | 도구 실행이 실패했을 때 | decision으로 가능 | `tool_name`, `error`, `is_interrupt` |
| `UserPromptSubmit` | 사용자 프롬프트를 처리하기 전 | 가능 | `prompt` |
| `Notification` | 상태 알림이 올 때 (`permission_prompt`, `idle_prompt`, `auth_success`, `elicitation_dialog`) | 불가 | `message`, `type` |
| `Stop` | Claude가 생성을 멈출 때 | decision으로 가능 | `stop_hook_active` |
| `SessionStart` | 세션을 초기화할 때 | 불가 | `source`(startup, resume, clear, compact), `model`, 선택적으로 `agent_type` |
| `SessionEnd` | 세션이 끝날 때 | 불가 | `reason`(clear, logout, prompt_input_exit, bypass_permissions_disabled, other) |
| `PermissionRequest` | 권한 대화상자를 보여 주기 전 | 가능 | `tool_name`, 권한 상세. `updatedInput`, `updatedPermissions` 지원 |
| `PreCompact` | 컨텍스트 압축 전 | 불가 | `trigger`(manual 또는 auto), `custom_instructions` |
| `PostCompact` | 컨텍스트 압축 후 | 불가 | 압축된 컨텍스트 |
| `SubagentStart` | 서브에이전트가 생길 때 | 불가 | `agent_id`, `agent_type` |
| `SubagentStop` | 서브에이전트가 끝날 때 | decision으로 가능 | `agent_id`, `agent_type`, `agent_transcript_path`, `stop_hook_active` |
| `TeammateIdle` | 에이전트 팀 팀원이 막 쉬려 할 때 | 가능 (종료 코드 2) | `teammate_name` |
| `TaskCompleted` | 작업이 완료로 표시될 때 | 가능 (종료 코드 2) | `task_id`, `task_subject` |

표를 보면 패턴이 있다. 일을 하기 전에 일어나는 이벤트(`PreToolUse`, `UserPromptSubmit`, `PermissionRequest`)는 막을 수 있고, 이미 끝난 일을 알려 주는 이벤트(`SessionEnd`, `PostCompact`, `SubagentStart` 등)는 막을 수 없다. `PostToolUse`나 `Stop`은 이미 일어난 일이라도 `decision`으로 Claude에게 계속 작업하도록 되돌릴 수 있다.

## 3. 핸들러 세 가지 유형

핸들러는 훅이 발생했을 때 실제로 무엇을 실행할지 정한다. 유형은 command, prompt, agent 세 가지다.

### 3.1 Command 핸들러

셸 명령을 실행한다. 이벤트 JSON을 stdin으로 받고, 결과는 종료 코드와 stdout JSON으로 돌려준다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "handler": {
          "type": "command",
          "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/validate.sh"
        }
      }
    ]
  }
}
```

### 3.2 Prompt 핸들러

컨텍스트와 프롬프트를 Claude 모델(기본은 Haiku)에게 보내 한 번의 턴으로 평가하게 한다. 결과는 `{"ok": true/false, "reason": "..."}` 형태의 구조화된 결정이다. 프롬프트 안에서 `$ARGUMENTS` 자리표시자를 쓰면 이벤트 데이터가 들어간다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write(*.sql)",
        "handler": {
          "type": "prompt",
          "prompt": "Review this SQL file write for safety. Allow or deny."
        }
      }
    ]
  }
}
```

### 3.3 Agent 핸들러

여러 턴에 걸쳐 도구를 쓸 수 있는 서브에이전트를 띄워 복잡한 검증을 맡긴다. 최대 50턴까지 돈다.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "handler": {
          "type": "agent",
          "agent": "security-reviewer",
          "tools": ["Read", "Grep"]
        }
      }
    ]
  }
}
```

세 유형은 처리 방식이 다르다. command는 스크립트를 실행하고, prompt는 모델이 한 턴으로 판단하고, agent는 도구를 써 가며 여러 턴에 걸쳐 검증한다. 제한 시간 기본값(10초, 30초, 60초)도 이 순서로 길어진다.

## 4. 핸들러 공통 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| `timeout` | 아니오 | 제한 시간(초). 기본값은 command 10, prompt 30, agent 60 |
| `statusMessage` | 아니오 | 훅이 실행되는 동안 스피너에 보여 줄 메시지 |
| `once` | 아니오 | true이면 세션당 한 번만 실행하고 제거한다. 스킬에서만 쓸 수 있다 |
| `async` | 아니오 | true이면 막지 않고 백그라운드에서 실행한다. 출력은 다음 턴에 `systemMessage`나 `additionalContext`로 전달된다. 동작을 차단할 수는 없다 |

`async`를 켠 훅은 결과를 기다리지 않으므로, 막는 용도로는 쓸 수 없다. 로그 남기기나 알림처럼 흐름을 방해하지 않는 작업에 어울린다.

## 5. 매처(matcher) 문법

매처는 훅이 어떤 도구에 반응할지 정한다.

- 정확한 도구 이름: `Bash`, `Write`, `Edit`
- 지정자가 붙은 도구: `Bash(npm *)`, `Write(*.env)`
- MCP 도구: `mcp__servername__toolname`
- 지정자 안에서는 정규식 패턴을 쓸 수 있다.
- `*`는 모든 도구와 일치한다.

## 6. 훅의 보안 모델

훅은 세션을 시작할 때의 모습으로 스냅샷을 찍어 둔다. 세션 도중에 훅 설정이 외부에서 바뀌면 Claude Code가 경고를 띄우고, `/hooks` 메뉴에서 검토해야 변경이 적용된다. 세션 중간에 누군가 악의적으로 훅을 바꿔치기하는 일을 막기 위한 장치다.
