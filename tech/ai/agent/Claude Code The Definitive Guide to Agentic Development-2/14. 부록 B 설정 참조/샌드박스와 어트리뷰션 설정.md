# 샌드박스와 어트리뷰션 설정

이 문서는 settings.json 중에서 bash 명령을 격리하는 샌드박스(sandbox) 키와, git 커밋과 PR에 남는 문구를 바꾸는 어트리뷰션(attribution) 키를 다룬다. 샌드박스는 보안과 직결되는 설정이고, 어트리뷰션은 팀의 커밋 규칙과 관련된다.

---

## 1. 샌드박스 키

샌드박스는 bash 명령을 제한된 환경에서 실행해서, 명령이 건드릴 수 있는 파일과 네트워크 범위를 좁히는 기능이다.

| 키 | 타입 | 설명 |
|---|---|---|
| `sandbox.enabled` | boolean | bash 샌드박싱을 켠다(macOS, Linux, WSL2). 기본값 false |
| `sandbox.autoAllowBashIfSandboxed` | boolean | 샌드박스 안에서 도는 bash 명령을 자동 승인한다. 기본값 true |
| `sandbox.excludedCommands` | string[] | 샌드박스 밖에서 실행할 명령. 예: `["git", "docker"]` |
| `sandbox.allowUnsandboxedCommands` | boolean | `dangerouslyDisableSandbox`로 샌드박스를 우회하는 것을 허용한다. 엄격하게 막으려면 false로 둔다. 기본값 true |
| `sandbox.network.allowUnixSockets` | string[] | 샌드박스 안에서 접근할 수 있는 유닉스 소켓 경로. 예: SSH 에이전트 소켓 |
| `sandbox.network.allowAllUnixSockets` | boolean | 모든 유닉스 소켓 연결을 허용한다. 기본값 false |
| `sandbox.network.allowLocalBinding` | boolean | localhost 포트 바인딩을 허용한다(macOS만). 기본값 false |
| `sandbox.network.allowedDomains` | string[] | 샌드박스에서 접근할 수 있는 도메인. 기본값은 흔한 패키지 레지스트리 |
| `sandbox.network.httpProxyPort` | number | 샌드박스 네트워크 필터링에 쓸 HTTP 프록시 포트 |
| `sandbox.network.socksProxyPort` | number | 샌드박스 네트워크 필터링에 쓸 SOCKS 프록시 포트 |
| `sandbox.enableWeakerNestedSandbox` | boolean | 권한이 없는 Docker 환경용으로 약한 샌드박스를 켠다(Linux/WSL2만). 보안이 약해진다. 기본값 false |

## 2. 키를 읽는 요령

몇 가지는 서로 연결해서 이해해야 한다.

- **자동 승인과 격리는 한 쌍이다.** `autoAllowBashIfSandboxed`가 true이면 샌드박스 안에서 도는 bash 명령은 매번 물어보지 않는다. 격리가 되어 있으니 위험이 낮다고 보고 확인을 줄이는 구조다.
- **우회 통로는 닫을 수 있다.** `allowUnsandboxedCommands`가 true(기본값)이면 명령이 `dangerouslyDisableSandbox`로 샌드박스를 벗어날 수 있다. 엄격한 격리가 필요하면 false로 둔다.
- **샌드박스에 어울리지 않는 명령은 제외한다.** `git`이나 `docker`처럼 샌드박스 안에서 제대로 동작하기 어려운 명령은 `excludedCommands`에 넣어 밖에서 실행한다.
- **네트워크는 허용 도메인 방식이다.** `allowedDomains`에 적힌 도메인만 접근할 수 있고, 기본값은 흔한 패키지 레지스트리다.
- **약한 샌드박스는 마지막 수단이다.** `enableWeakerNestedSandbox`는 권한이 없는 Docker 안에서 샌드박스를 억지로 돌릴 때만 쓰며, 보안 수준이 떨어진다.

## 3. 샌드박스 전체 예시

원문의 예시는 샌드박스 설정과 민감 파일을 막는 deny 규칙을 함께 보여 준다. 샌드박스를 켜고, docker는 밖에서 실행하며, 두 개의 도메인만 허용하고, localhost 바인딩을 연다.

```json
{
  "sandbox": {
    "enabled": true,
    "autoAllowBashIfSandboxed": true,
    "excludedCommands": ["docker"],
    "network": {
      "allowedDomains": ["registry.npmjs.org", "api.github.com"],
      "allowLocalBinding": true
    }
  },
```

이어서 같은 JSON 안의 `permissions.deny`에 `.env`와 `secrets/` 경로의 읽기와 쓰기를 모두 막는 규칙을 둔다.

```json
  "permissions": {
    "deny": [
      "Read(.env)",
      "Read(.env.*)",
      "Read(secrets/**)",
      "Write(.env)",
      "Write(.env.*)",
      "Write(secrets/**)"
    ]
  }
}
```

샌드박스로 실행 범위를 좁히고, 비밀 값이 든 파일은 권한 규칙으로 따로 막는 이중 구조다. 샌드박스 설정과 deny 규칙을 한 파일에 함께 두는 것이 이 예시의 요점이다.

## 4. 어트리뷰션 설정

어트리뷰션은 Claude Code가 만든 커밋이나 PR에 어떤 문구를 남길지 정한다.

| 키 | 타입 | 설명 |
|---|---|---|
| `attribution.commit` | string | git 커밋에 붙일 문구. 여러 줄 트레일러는 `\n`으로 쓴다 |
| `attribution.pr` | string | PR 설명에 붙일 문구. `""`로 두면 PR 어트리뷰션을 끈다 |

기본 커밋 문구는 "Generated with Claude Code" 한 줄과, 그 아래에 `Co-Authored-By: Claude <noreply@anthropic.com>` 줄이 붙는 형태다.

문구를 바꾸는 예시는 다음과 같다. 커밋 문구는 직접 정하고, PR 어트리뷰션은 끈다.

```json
{
  "attribution": {
    "commit": "Generated with AI\n\nCo-Authored-By: AI <ai@example.com>",
    "pr": ""
  }
}
```

어트리뷰션은 프로젝트 범위에서 공유하는 팀 규칙으로 두는 경우가 많다. 범위별 용도는 설정 범위 문서에서 설명한다.
