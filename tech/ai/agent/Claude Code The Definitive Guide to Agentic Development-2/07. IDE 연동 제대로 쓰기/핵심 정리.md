# 핵심 정리

이 장의 원문이 마지막에 짚은 요점을 한곳에 모았다. 어떤 화면에서 일하든 엔진은 같고, 화면마다 잘하는 일이 다르다는 점이 중심이다. 각 요점에는 왜 중요한지도 함께 적었다.

---

## 1. 한눈에 보는 요점

- **엔진은 화면과 무관하다**: CLAUDE.md, 설정, MCP 서버, 권한이 터미널, 에디터 확장, 데스크톱, 웹, 모바일에서 똑같이 동작한다. 화면을 바꿔도 환경을 다시 맞출 필요가 없어서 부담 없이 옮겨 다닐 수 있다.
- **데스크톱 앱은 검토와 병렬 작업에 강하다**: 인라인 코멘트가 달린 시각적 diff 검토, 워크트리로 격리된 병렬 세션, 여러 권한 모드, SSH 연결, 외부 서비스 커넥터를 제공한다. 변경 내용을 눈으로 확인하며 여러 작업을 동시에 돌릴 때 쓸모가 크다.
- **클라우드 세션은 닫아도 계속된다**: 관리형 VM에서 돌기 때문에 브라우저를 닫아도 세션이 남고, 어느 기기에서든 지켜볼 수 있다. & 접두사로 일을 클라우드에 맡기고 /teleport로 다시 가져오면, 오래 걸리는 작업 동안 내 컴퓨터가 묶이지 않는다.
- **PR 상태가 터미널 하단에 보인다**: 초록은 승인, 노랑은 대기, 빨강은 수정 요청을 뜻하고 60초마다 갱신된다. 브라우저로 넘어가지 않고도 리뷰 진행을 알 수 있어서 흐름이 끊기지 않는다.
- **스킬은 여러 도구가 함께 쓰는 표준이다**: npx skills add로 설치한 스킬은 다른 AI 코딩 도구에서도 동작한다. 도구에 묶이지 않고 쌓아 둔 작업 방식을 계속 재사용할 수 있다는 점이 중요하다.
- **자동완성 공백은 구조적이다**: 인라인 자동완성이 없는 것은 우연이 아니라 설계의 결과다. 에이전트 작업은 Claude Code로, 편집 중 자동완성은 전용 도구로 나누는 하이브리드 구성이 안정된 최종 형태라서, 억지로 한 도구에 맞추지 않아도 된다.
- **숙련자는 터미널을 중심에 둔다**: 터미널이 더 빠르고 유연하며 IDE에 얽매이지 않기 때문이다. 터미널 작업 방식을 먼저 익히면 어느 화면과 어느 IDE에서도 그대로 통하므로, 학습 시간을 가장 먼저 여기에 투자하는 것이 효율적이다.
