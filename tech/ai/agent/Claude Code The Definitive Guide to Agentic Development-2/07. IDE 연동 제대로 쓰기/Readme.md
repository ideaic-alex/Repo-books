# IDE 연동 제대로 쓰기

Claude Code는 터미널, 코드 에디터 확장, 데스크톱 앱, 웹, 모바일 앱에서 같은 엔진으로 돌아간다. CLAUDE.md, 설정, MCP 서버가 모든 화면에서 똑같이 적용되고, 달라지는 것은 화면과 그 화면이 잘 받쳐 주는 작업 방식이다. 이 장은 각 화면의 강점과 한계, 화면 사이로 작업을 옮기는 방법을 정리한다.

또한 Claude Code가 경쟁하지 않는 영역인 인라인 자동완성의 공백을 짚고, 팀들이 터미널 우선에 IDE를 보조로 쓰는 이유를 설명한다.

---

## 1. 핵심 요점

- **엔진과 화면 분리**: 엔진이 에이전트 루프, 컨텍스트, 도구 실행, 권한을 맡고 화면은 표현 계층이다. 화면을 바꿔도 CLAUDE.md, 권한, MCP 설정이 그대로 따라온다.
- **터미널이 기본**: 모든 기능이 터미널에서 동작하고, 세션 관리와 자동화를 완전히 통제할 수 있다. IDE에 의존하지 않아서 팀원의 에디터가 달라도 작업 방식을 통일할 수 있다.
- **에디터 확장과 데스크톱 앱**: 확장은 인라인 diff, @-멘션, 플랜 체크리스트를 준다. 데스크톱 앱은 시각적 diff 검토, 워크트리로 격리된 병렬 세션, Ask/Code/Plan/Act 권한 모드를 준다.
- **클라우드 세션**: 웹에서는 Anthropic 관리 VM에서 돌고, 네트워크는 limited, full, none 중 고른다. 모바일에서는 같은 세션을 지켜보고 지시한다.
- **화면 간 이동**: /teleport는 클라우드를 터미널로, & 접두사는 터미널을 클라우드로, /desktop은 터미널을 데스크톱 앱으로 옮긴다. 로컬에서 계획하고 원격에서 실행하는 패턴이 가능하다.
- **자동완성 공백**: 스트리밍 인라인 자동완성은 없다. 설계상 결과이고, 인라인 자동완성 전문 도구를 함께 쓰는 하이브리드 구성이 안정된 최종 형태다.
- **스킬은 공통 표준**: 스킬은 여러 AI 코딩 에이전트가 지원하는 표준이라 npx skills add로 설치해서 도구가 바뀌어도 재사용한다.
- **터미널 우선 철학**: 터미널부터 익히면 모든 화면에서 통하는 기술이 된다. IDE는 검토가 필요할 때 꺼내 쓰는 보조 화면이다.
