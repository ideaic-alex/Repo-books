# 에디터 확장과 IDE 플러그인

코드 에디터 확장과 IDE 플러그인은 Claude Code 엔진 위에 시각적인 계층을 얹은 것이다. 터미널의 텍스트 출력으로 보던 변경 내용을 에디터 화면 안에서 보고 승인하게 해 준다. 이 문서는 에디터 확장의 핵심 기능 세 가지와 IDE 플러그인의 차이, 그리고 코드 인텔리전스를 더해 주는 LSP 플러그인과 브라우저 확장을 정리한다.

---

## 1. 코드 에디터 확장의 핵심 기능

인기 있는 코드 에디터용 확장에서 중요한 기능은 인라인 diff 보기, @-멘션 파일 참조, 플랜 검토 화면, 대화 기록이다. 대화 기록은 이전 대화를 에디터 안에서 다시 열어 볼 수 있게 해 주는 기능이다. 나머지 세 가지를 하나씩 본다.

### 인라인 diff

가장 대표적인 기능이다. Claude가 파일 수정을 제안하면 에디터 안에서 diff가 구문 강조와 함께 표시된다. 변경을 수락하거나 거절하는 버튼이 있고, 일부만 수락할 수도 있다. 파일 여러 개에 걸친 큰 변경이라면 터미널에서 diff를 읽는 것보다 눈에 띄게 빠르다.

### @-멘션

프롬프트 안에서 파일, 심볼, 선택 영역을 바로 가리키는 기능이다. 함수 이름을 클릭하고 @를 입력하면 파일 경로가 컨텍스트에 들어간다. 터미널에서 경로를 직접 타이핑해도 같은 결과를 얻을 수 있으니 편의 기능일 뿐이지만, 번거로움이 줄어드는 정도가 사용 습관을 바꿀 만큼 크다. 책은 @-멘션을 쓰는 개발자가 구체적인 컨텍스트를 더 자주 지정하고, 그 결과 범위가 잘 잡힌 프롬프트를 쓰게 된다고 설명한다.

### 플랜 검토

Claude가 실행하기 전에 세운 접근 방식을 구조화된 시각 형식으로 보여 준다. 터미널에서는 플랜이 대화 속 텍스트 블록이다. 에디터에서는 항목마다 승인, 수정, 거절할 수 있는 체크리스트가 된다. 단계가 많은 큰 리팩터링에서 어느 단계를 진행할지 세밀하게 통제하고 싶을 때 특히 쓸모 있다.

### 강점과 약점

에디터 확장은 하나의 코드베이스에서 작업하면서 Claude의 출력과 내 편집 흐름을 촘촘하게 엮고 싶을 때 가장 강하다. 반대로 터미널에만 있는 기능이 필요할 때는 약하다. 예를 들면 특정 CLI 플래그, 파이프를 쓴 작업 흐름, 여러 인스턴스를 병렬로 관리하는 일이다.

## 2. IDE 계열 플러그인

주요 IDE 계열에는 플러그인 형태로 제공된다. 인터랙티브 diff 보기와 컨텍스트 공유가 핵심이다. 구현 방식은 에디터 확장과 다르다. IDE 구조를 따르기 때문이다.

- diff는 IDE에 내장된 diff 뷰어와 통합된다.
- 컨텍스트 참조는 IDE가 가진 심볼 인덱스를 사용한다.
- 상호작용 방식은 해당 IDE의 관습을 따른다.

그런데 구조 차이가 커 보이는 것에 비해 실제 사용 차이는 작다. 둘 다 인라인 diff 검토를 제공하고, 둘 다 컨텍스트 참조를 지원하며, 둘 다 같은 엔진에 같은 능력으로 연결된다. 둘 중 무엇을 쓸지는 거의 항상 이미 쓰고 있는 IDE가 무엇이냐로 정해지고, Claude Code 연동 기능의 차이로 정해지지 않는다.

## 3. LSP 플러그인

플러그인 시스템에는 LSP(Language Server Protocol, 언어 서버 프로토콜) 서버가 포함된다. 진단(diagnostics), 정의로 이동(go-to-definition), 코드 탐색, 심볼 해석 같은 코드 인텔리전스 기능을 제공한다. 이것은 Claude Code의 에이전트 능력과는 별개이고, 전통적인 LSP 기능을 플러그인으로 구현한 것이다.

주의할 점이 있다. LSP 플러그인은 핵심 기능보다 새롭고, 아직 많이 검증되지 않았다. 가치는 IDE가 기본으로 잘 지원하지 못하는 언어나 프레임워크에 코드 인텔리전스를 채워 주는 데 있다.

| 상황 | LSP 플러그인의 효과 |
|---|---|
| IDE가 내 스택을 이미 훌륭하게 지원한다 | 거의 더해 주는 것이 없다 |
| 덜 흔한 언어나 자체 프레임워크를 쓴다 | 빈틈을 메워 줄 수 있다 |

설정해 두면 자동으로 시작되고 IDE의 일반 기능처럼 보인다. IDE의 기본 언어 서비스를 대체하지 않고 보완하는 역할이다.

## 4. 크롬 확장

브라우저 확장은 Claude Code를 실행 중인 웹 애플리케이션에 연결한다. 코드베이스와 돌아가는 앱 사이의 간격을 메워 준다. Claude는 DOM을 읽고, 네트워크 요청을 관찰하고, 작업 중인 코드가 만들어 낸 렌더링 결과를 살펴볼 수 있다.

가장 가치 있는 곳은 프론트엔드 디버깅이다. 증상(브라우저에서 보이는 시각적 버그)과 원인(코드의 CSS나 JavaScript 문제)이 서로 다른 맥락에 있기 때문이다. 이 확장이 두 맥락을 한곳에 모아 준다.
