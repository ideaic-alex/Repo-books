# 핵심 정리

이 문서는 6장 전체를 여덟 가지 요점으로 줄여 다시 짚는다. 각 요점이 왜 중요한지를 함께 적었으므로, 장을 다 읽은 뒤 복습용으로 쓰거나 팀에 헤드리스 자동화를 설명할 때 개요로 쓰면 된다.

---

## 1. 한눈에 보는 요점

- **`-p`는 Claude Code를 유닉스 도구로 만든다.** stdin으로 읽고 stdout으로 쓰므로 어떤 파이프라인에도 끼워 넣을 수 있다. `cat error.log | claude -p 'explain' > output.txt` 한 줄이 진단 작업 흐름이 된다. 별도 통합 코드가 필요 없다는 점이 도입 장벽을 크게 낮춘다.
- **시스템 프롬프트 플래그는 네 가지다.** `--system-prompt`, `--system-prompt-file`, `--append-system-prompt`, `--append-system-prompt-file`이 바로 쓰는 덮어쓰기부터 버전 관리되는 추가 프롬프트까지 폭을 만든다. CI에서는 파일 기반을 권한다. 프롬프트가 저장소에 남아 누가 언제 바꿨는지 추적되고 실행마다 같은 결과를 기대할 수 있기 때문이다.
- **팬아웃은 안전한 일괄 처리의 기본형이다.** 파일을 하나씩 돌면서 호출마다 `--allowedTools`로 권한을 좁히고 JSON 결과를 모은다. 한 번의 실수가 번지는 범위를 제한하면서 많은 파일을 처리할 수 있다.
- **훅이 테스트와 검증을 맡는다.** 비동기 훅은 파일을 쓸 때마다 백그라운드에서 테스트를 돌린다. TaskCompleted 훅은 테스트가 통과할 때까지 작업 완료를 막는다. 에이전트형 Stop 훅은 Claude가 끝내기 전에 서브에이전트를 띄워 품질을 확인한다. 사람이 일일이 확인하지 않아도 품질 기준이 지켜진다.
- **프리커밋 훅은 자동 압력이 된다.** 타입 검사, 린트, 테스트를 커밋 시점에 걸어 두면 Claude가 실패를 보고 스스로 고친다. 사람이 품질의 병목에서 벗어난다는 점이 가장 큰 이득이다.
- **무인 실행의 표준은 격리된 devcontainer다.** 네트워크를 차단한 컨테이너 안에서 `--dangerously-skip-permissions`를 쓰는 것이 CI의 정석이다. 권한 확인을 건너뛰는 위험한 옵션을 컨테이너 경계가 감싸 주므로 피해가 밖으로 나가지 않는다.
- **`--from-pr`은 PR 단위로 대화를 잇는다.** 특정 풀 리퀘스트에 연결된 세션을 다시 열어 리뷰가 몇 번 오가도 전체 맥락을 이어 간다. 리뷰 의견을 반영할 때마다 처음부터 설명하지 않아도 된다.
- **CI 자동 수정은 아직 오지 않았다.** 빌드 실패를 자동으로 고치는 기능은 2026년 중반쯤 나올 것으로 기대되는 전망이며, 그때까지는 로그를 파이프로 넘기는 수동 방식을 쓴다. 지금 가능한 범위와 아직 안 되는 범위를 구분해야 헛된 기대를 피한다.
- **작게 시작해서 넓혀 간다.** 인터랙티브로 쓰다가 반복 패턴을 찾아 하나씩 헤드리스로 옮긴다. 한 번에 완전 자동화를 노리면 실패하기 쉽고, 단계마다 얻는 이득이 있어 중간에 멈춰도 손해가 없다.
