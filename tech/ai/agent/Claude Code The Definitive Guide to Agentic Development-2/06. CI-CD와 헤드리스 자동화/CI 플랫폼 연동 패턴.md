# CI 플랫폼 연동 패턴

주요 버전 관리 플랫폼은 이제 Claude Code를 위한 CI 통합 기능을 제공한다. 가장 성숙한 두 곳은 대표적인 코드 호스팅 플랫폼의 내장 CI 워크플로 시스템과, 또 다른 주요 플랫폼의 파이프라인 시스템이다. 둘 다 Claude Code를 나중에 덧붙인 도구가 아니라 CI의 정식 참여자로 다룬다.

이 문서는 실제 운영에서 효과를 본 세 가지 패턴(PR 자동 수정, 이슈 자동 처리, 자동 코드 리뷰)과 이를 돕는 `/commit-push-pr` 스킬, `--from-pr` 플래그, 메신저 연동을 정리한다.

---

## 1. PR 자동 수정

PR에 변경을 요청하는 리뷰 코멘트가 달리면 워크플로가 시작된다. Claude Code가 코멘트를 읽고, 브랜치를 체크아웃하고, 요청된 수정을 한 뒤, 새 커밋을 푸시한다. 사람 리뷰어의 피드백이 그대로 프롬프트가 되어 구현을 이끄는 구조다.

흐름은 이렇다. PR 코멘트에서 웹훅(이벤트 알림)이 발생하고, CI 작업이 devcontainer를 띄우고, PR 브랜치를 체크아웃한 다음, 저장소에 관한 맥락과 함께 리뷰 코멘트를 Claude Code에 파이프로 넘기고, 결과로 나온 변경을 푸시한다. 리뷰어는 PR 작성자가 아무것도 하지 않았는데도 자기 피드백을 반영한 새 커밋을 보게 된다.

---

## 2. 이슈 자동 처리

특정 레이블이 붙은 새 이슈가 생기면 워크플로가 시작된다. Claude Code가 이슈 설명을 읽고, 브랜치를 만들고, 해결책을 구현하고, PR을 연다. 이슈가 프롬프트가 되고 PR이 결과물이 된다.

한 디자인 팀은 이 패턴에서 특히 세련된 변형을 찾아냈다. 디자이너가 여백 조정, 색상 수정, 애니메이션 손보기 같은 UI 다듬기 작업을 이슈로 올린다. 그러면 CI 워크플로가 아무도 Claude Code를 열지 않아도 코드 변경을 제안한다. 디자이너는 결과 PR을 검토하고, PR 코멘트로 조정을 요청하며(이 코멘트가 다시 자동 Claude Code 실행을 일으킨다), 만족하면 머지한다. 예전에는 엔지니어가 기능 개발을 멈추고 맥락을 바꿔야 했던 디자인 다듬기 작업이 다른 작업과 똑같은 이슈에서 PR로 가는 파이프라인을 타게 된 것이다.

---

## 3. 자동 코드 리뷰

모든 PR에서 헤드리스 Claude Code 세션이 실행된다. diff를 읽고, CLAUDE.md에 적힌 프로젝트 규칙과 대조한 뒤, 리뷰 코멘트를 단다.

이것은 사람 리뷰를 대체하지 않는다. 사람이 코드를 보기 전에 스타일 위반, 빠진 테스트, 뻔한 버그를 걸러 주는 첫 번째 검토다. 사람 리뷰어는 더 깨끗해진 PR을 받아서 서식과 컨벤션 지적이 아니라 아키텍처와 설계 문제에 시간을 쓸 수 있다.

---

## 4. 세 패턴의 공통 구조

세 패턴은 같은 구조를 따른다. 이벤트가 발생하고, 맥락을 모으고, 헤드리스 Claude Code를 실행하고, 결과를 게시한다.

- 이벤트가 프롬프트를 제공한다.
- 저장소가 맥락을 제공한다.
- Claude Code가 구현을 제공한다.
- CI 시스템이 조율(여러 단계를 순서대로 이어 주는 일, 오케스트레이션)을 맡는다.

이 패턴들은 지금도 쓸 수 있지만 범위가 분명하고 한정된 작업에서 가장 잘 동작한다. "이 함수에 null 검사를 추가해 달라"는 리뷰 코멘트는 믿을 만한 결과를 낸다. "인증 시스템을 다시 설계하라"는 티켓은 그렇지 못하다. 작업 범위가 헤드리스 세션 하나 안에 들어와야 한다.

자동화 워크플로에서는 시스템 프롬프트 파일에 작업 범위를 명시적으로 제한해 두는 것이 좋다. Claude Code가 시도할 일, 사람의 검토를 위해 표시만 해야 할 일, 건드리지 말아야 할 일을 구분해서 적는다.

---

## 5. /commit-push-pr 스킬

PR로 끝나는 대화형 작업에서는 `/commit-push-pr` 스킬이 커밋, 푸시, PR 열기라는 세 단계를 한 번에 해 준다. 팀 채팅 MCP 서버를 설정해 두고 CLAUDE.md에 알림 채널을 적어 두었다면(예: "post PR URLs to #team-prs") 스킬이 PR 링크를 팀 채널에 자동으로 올리기도 한다.

그 결과 "커밋, 푸시, 브라우저 열기, PR 설명 작성, 채팅에 공유"로 이어지던 작업이 명령 하나로 줄어든다.

---

## 6. --from-pr 플래그

PR을 Claude Code로 만들었다면(`/commit-push-pr`을 쓰든, 플랫폼 CLI로 PR을 만들어 달라고 Claude에게 시키든) 그 세션은 자동으로 PR 번호와 연결된다. 나중에 어느 기기에서든 아래 명령으로 그 세션을 이어갈 수 있다.

```bash
claude --from-pr 123
```

PR을 만든 세션의 전체 대화 맥락이 복원된다. 코드베이스에 대한 이해, 설계 결정, 제약 조건이 모두 Claude가 멈췄던 그대로다. 구현하고 며칠 뒤에 리뷰어가 수정을 요청하는 PR 리뷰 주기에서 특히 유용하다.

---

## 7. 메신저 연동

Claude Code는 MCP 커넥터를 통해 팀 메시징 플랫폼과 연동된다. 가장 흔한 패턴은 팀 채팅의 버그 제보를 곧바로 풀 리퀘스트로 이어 주는 것이다. 팀원이 채널에서 Claude Code 봇을 멘션하며 버그를 설명하면, Claude Code가 메시지를 읽고, 브랜치를 만들고, 수정을 구현하고, PR을 열고, PR 링크를 채널에 다시 올린다. 버그 제보에서 PR까지의 전 과정이 누구도 IDE를 열지 않은 채 진행된다.

덕분에 팀 메시징은 조율 도구에서 작업 배정 시스템으로 바뀐다. 버그 제보가 프롬프트가 되고, 코드베이스가 맥락을 주고, Claude Code가 구현하고, 메시징 플랫폼이 결과를 게시해서 고리를 닫는다.
