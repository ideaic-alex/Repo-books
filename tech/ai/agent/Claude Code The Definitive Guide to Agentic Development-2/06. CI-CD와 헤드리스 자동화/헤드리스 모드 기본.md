# 헤드리스 모드 기본

터미널 앞에 사람이 앉아서 Claude Code와 대화하는 것과, CI 파이프라인 안에서 새벽 3시에 티켓을 처리하거나 깨진 빌드를 고치는 것은 전혀 다른 도구를 쓰는 일에 가깝다. 인터랙티브에서 헤드리스로 넘어가는 일은 플래그 하나 붙이는 정도로 끝나지 않는다. 권한 모델, 출력 형식, 실패 복구 방식, 자동화의 경제성까지 모두 달라진다.

이 문서는 헤드리스(headless) 모드의 기본기를 다룬다. 헤드리스 모드란 화면과 사람의 입력 없이 명령 한 번으로 실행하고 결과만 받아 가는 방식이다. 핵심 플래그, 출력 형식, 파이프 사용법, 빌드 스크립트에 끼워 넣는 방법, 그리고 Claude Code가 왜 유닉스 도구처럼 쓰이는지를 설명한다.

---

## 1. -p 플래그: 대화형에서 명령 처리기로

`-p` 플래그를 붙이면 Claude Code는 대화형 REPL(입력하고 결과를 보는 반복 환경)이 아니라 비대화형 명령 처리기로 바뀐다. 프롬프트를 넘기면 Claude가 실행하고, 결과는 stdout(표준 출력)으로 나온다. 터미널 UI도, 권한 확인 창도, 사람의 입력을 기다리는 시간도 없다.

```bash
claude -p "Refactor the auth module to use dependency injection"
```

이것이 가장 단순한 형태다. 실제로는 아래 플래그로 동작을 세밀하게 조절한다.

| 플래그 | 역할 |
|---|---|
| `--output-format` | 출력 형식을 고른다. `text`(사람이 읽기 좋은 글), `json`(기계가 파싱하기 좋은 구조화 데이터), `stream-json`(작업이 진행되는 대로 한 줄씩 나오는 JSON) 중 하나다 |
| `--max-turns` | 에이전트 루프(생각하고 도구를 쓰는 반복)의 횟수 상한이다. 통제 없이 계속 도는 일을 막는다 |
| `--budget` | 세션의 비용 한도를 정한다 |
| `--model` | 이번 실행에 쓸 모델을 지정한다 |

사람이 없으니 "너무 오래 돈다", "돈이 너무 든다"를 알아채고 끊어 줄 존재가 없다. `--max-turns`와 `--budget`은 그 빈자리를 메우는 안전장치다.

---

## 2. stream-json 형식

`stream-json`은 줄마다 독립된 JSON 객체 하나가 나오는 형식(줄바꿈으로 구분된 JSON)이다. 한 줄이 Claude의 작업 한 단계를 나타낸다. 도구 호출, 도구 결과, 생각 단계, 최종 응답이 각각 한 줄씩 나온다.

이 형식은 파이프라인이 읽도록 설계되었다. 모니터링 시스템이나 로그 수집기, 혹은 Claude의 행동에 실시간으로 반응하는 다른 프로그램에 그대로 흘려보낼 수 있다. 작업이 끝날 때까지 기다렸다가 결과를 한꺼번에 받는 `json`과 달리, 진행 상황을 바로바로 보고 싶을 때 적합하다.

---

## 3. 파이프로 입력 받기

헤드리스 모드는 파이프로 들어오는 입력도 받는다. 파일 내용이든 다른 명령의 출력이든 텍스트 스트림이면 된다.

```bash
git diff HEAD~1 | claude -p "Review this diff for security issues" --output-format json
```

이것은 편의 기능 정도가 아니다. Claude Code를 유닉스 생태계의 한 구성원으로 만드는 핵심 기능이다.

---

## 4. 파이프 in, 파이프 out

헤드리스 모드에서 가장 저평가된 패턴은 양방향 파이프다. 어떤 출처에서든 데이터를 넣고, 출력은 원하는 곳 어디로든 돌릴 수 있다.

```bash
cat build-error.txt | claude -p 'concisely explain the root cause of this build error' > output.txt
```

한 줄로 진단 작업이 끝난다. 빌드가 실패했고 에러 로그가 파일에 있다. Claude가 그 로그를 읽고 근본 원인을 설명해서 `output.txt`에 써 준다. 대화형 세션을 열지 않고, 복사해서 붙여넣지 않고, 화면을 오가며 맥락을 바꾸지도 않는다.

출력 형식 플래그에 따라 반대쪽 끝에서 받는 결과가 달라진다.

```bash
cat data.txt | claude -p 'summarize this data' --output-format text > summary.txt
cat code.py | claude -p 'analyze this code for bugs' --output-format json > analysis.json
cat log.txt | claude -p 'parse this log file for errors' --output-format stream-json
```

text는 사람이 읽는 용도다. json은 하위 도구에 넘기거나 DB에 저장하거나 다른 명령으로 다시 파이프할 수 있다. stream-json은 단계마다 바로 나오므로 모니터링 시스템이 실시간으로 반응해야 할 때 쓴다.

---

## 5. 빌드 스크립트에 끼워 넣기

파이프 패턴은 프로젝트의 빌드 스크립트에도 그대로 쓸 수 있다. 패키지 설정에 Claude Code를 하나의 작업으로 등록하면 된다.

```json
{
  "scripts": {
    "lint:claude": "claude -p 'Review src/ for code style violations and suggest fixes' --output-format text",
    "review": "git diff main | claude -p 'Code review this diff' --output-format text"
  }
}
```

이렇게 해 두면 `npm run lint:claude`로 AI 기반 린트를 평소 작업 흐름 안에서 돌릴 수 있고, `npm run review`로 main 대비 변경분에 대한 코드 리뷰를 받을 수 있다. 특별한 통합 기능이 아니다. 다른 도구를 빌드 스크립트에 추가할 때와 똑같이 CLI 명령 하나를 적었을 뿐이다.

---

## 6. 유닉스 조합성

Claude Code의 명령줄 인터페이스는 유닉스 철학을 따른다. stdin에서 읽고, stdout으로 쓰며, 파이프나 리다이렉트(출력 방향 바꾸기), 다른 도구와 잘 어울린다. GUI 기반 도구는 흉내 내기 어려운 조합이 가능해진다.

**분석 도구와 연결하기.** 구조화된 출력을 `jq` 같은 도구에 넘겨 필요한 필드만 뽑거나 결과를 걸러 내고 형식을 바꾼다.

```bash
claude -p "List all API endpoints in this project" --output-format json | \
  jq '.result' > endpoints.json
```

**순차 처리.** 더 큰 파이프라인의 한 단계로 Claude Code를 넣는다. 예를 들어 최근 7일 안에 바뀐 파이썬 파일 목록을 넘겨 변경 내용을 요약시킬 수 있다.

```bash
find . -name "*.py" -mtime -7 | \
  claude -p "Summarize the recent changes in these files" --output-format text
```

**빌드 스크립트 통합.** 프로젝트의 빌드 스크립트나 태스크 러너 설정에 직접 넣는다. Makefile 같은 곳에 아래처럼 적는 식이다.

```text
lint-ai:  claude -p 'Review src/ for code style violations and suggest fixes' --output-format text
review:   git diff main | claude -p 'Code review this diff' --output-format text
```

이렇게 하면 Claude Code가 하나의 빌드 단계가 된다. 리뷰 스크립트를 돌리면 평소 작업 흐름 안에서 AI 코드 리뷰가 따라 나온다. 출력은 사람이 읽는 텍스트, 파싱할 수 있는 JSON, 조금씩 처리할 수 있는 스트리밍 JSON 중에서 고른다.

---

## 7. 핵심 정리

헤드리스 모드에는 별도의 통합 계층이 필요 없다. 이미 CLI 도구이기 때문이다. 명령을 호출하고 출력을 읽을 수 있는 것이라면 무엇이든 Claude Code를 쓸 수 있다.

이것은 Claude Code가 유닉스 철학을 비유로 빌려 온 것이 아니라는 점을 짚어 둘 만하다. Claude Code는 정말로 유닉스 유틸리티다. 다만 처리 엔진이 정규식 엔진이나 텍스트 포매터가 아니라 언어 모델이라는 점이 다를 뿐이다.
