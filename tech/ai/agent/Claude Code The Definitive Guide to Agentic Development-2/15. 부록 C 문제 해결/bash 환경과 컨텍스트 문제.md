# bash 환경과 컨텍스트 문제

Claude Code를 쓰다 보면 가장 자주 만나는 문제가 두 가지다. 하나는 bash에서 설정한 환경 변수가 다음 명령에서 사라지는 문제이고, 다른 하나는 대화가 길어지면서 Claude가 앞서 정한 규칙을 잊는 문제다. 두 문제 모두 원인은 "무엇이 어디까지 기억되는가"에 있다.

이 문서는 증상, 원인, 해결 방법 순서로 정리한다. 컨텍스트 윈도(Claude가 한 번에 기억할 수 있는 대화 분량)와 자동 압축(auto-compaction)이 어떻게 동작하는지 알면 대부분 쉽게 풀린다.

---

## 1. bash 환경 변수가 유지되지 않을 때

**증상.** 한 bash 명령에서 설정한 환경 변수가 다음 명령에서는 보이지 않는다. `export`에 기대는 스크립트가 에러 없이 조용히 실패한다.

**원인.** Claude Code는 bash 명령을 실행할 때마다 새 셸 환경을 만든다. 작업 디렉터리만 다음 명령까지 이어진다. 변수, 별칭(alias), 셸 함수는 모두 사라진다. 터미널을 직접 열어 쓸 때와 달리 "같은 셸 안에서 계속 이어서 작업한다"는 가정이 통하지 않는 것이다.

**해결 방법.**

- 서로 의존하는 명령은 `&&`로 이어서 bash 호출 한 번에 실행한다.
- 변수를 파일에 적어 두고 `source`로 읽어 들인다. 한 번의 호출 안에서 쓰는 예시는 아래와 같다.
- CLAUDE.md에 필요한 환경 변수를 적어 두면, Claude가 명령을 실행할 때마다 그 변수를 설정한다.

```bash
echo "export FOO=bar" > .env && source .env && echo $FOO
```

핵심은 "환경은 매번 초기화된다"는 사실을 전제로 명령을 짜는 것이다. 설정과 사용을 한 호출에 묶거나, 설정을 문서에 남겨 두면 된다.

---

## 2. 컨텍스트가 가득 차서 Claude가 지시를 잊을 때

**증상.** Claude가 CLAUDE.md의 규칙을 따르지 않는다. 결과물이 들쭉날쭉하다. 여러 단계로 짠 계획에서 일부 작업이 빠진다. 대화 초반에 내린 결정을 "잊은" 것처럼 행동한다.

**원인.** 컨텍스트 윈도가 가득 찼거나 거의 찼다. 이때 자동 압축이 앞부분 대화를 요약하면서 세부 내용이 사라진다. CLAUDE.md에 없는 지시는 압축을 거치며 보존되지 않는다. 즉 대화 중에 말로만 한 지시는 요약 과정에서 가장 먼저 떨어져 나갈 수 있다.

**해결 방법.**

- 꼭 지켜야 할 규칙은 CLAUDE.md의 "Compact Instructions" 섹션에 옮긴다. 이 섹션은 압축 후에도 살아남는다.
- 항상 컨텍스트를 차지하는 비용을 줄인다. CLAUDE.md를 다듬고, 안 쓰는 MCP 서버를 제거하고, 참고 자료는 스킬(skill)로 바꾼다.
- 새 작업은 이어 붙이지 말고 새 세션에서 시작한다. 한 세션을 끝없이 끌고 가지 않는다.
- 중요한 작업 직전에 `/compact`를 직접 실행한다. 요약 과정을 내가 통제하면서 공간을 확보할 수 있다.
- 출력이 길어지는 작업은 서브에이전트에 맡긴다. 서브에이전트는 별도의 컨텍스트 윈도를 쓰기 때문이다.

---

## 3. 자동 압축이 너무 늦거나 너무 이를 때

**증상.** 압축이 시작되기 전에 이미 세션 품질이 떨어진다. 반대로 아직 작업할 공간이 남았는데 압축이 일어난다.

**원인.** 자동 압축의 기본 기준은 컨텍스트 용량의 약 95%다. 이 값이 작업 스타일에 맞지 않을 수 있다.

**해결 방법.** `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 환경 변수로 기준을 바꾼다.

| 설정 | 예시 값 | 효과 |
|------|---------|------|
| 낮은 값 | `80` | 압축이 일찍 일어난다. 여유 공간이 늘지만 보존되는 세부 내용은 줄어든다. |
| 높은 값 | `98` | 압축이 늦게 일어난다. 세부 내용이 더 남지만 압축 전에 품질이 떨어질 위험이 있다. |

결국 여유 공간과 세부 정보 중 무엇을 더 챙기느냐의 선택이다. 길고 복잡한 작업이 많으면 낮은 값을, 세부 맥락이 중요하면 높은 값을 고려한다.

---

## 4. 서브에이전트 결과가 메인 컨텍스트를 잡아먹을 때

**증상.** 서브에이전트를 여러 개 돌린 뒤 메인 대화의 컨텍스트가 빠르게 찬다. 예상하지 못한 시점에 압축이 시작된다.

**원인.** 서브에이전트는 작업을 마치면 결과를 메인 컨텍스트로 돌려보낸다. 상세한 결과를 내는 서브에이전트가 여럿이면 메인 컨텍스트가 금방 찬다. 컨텍스트를 아끼려고 서브에이전트를 쓰는데, 결과가 너무 길면 효과가 줄어드는 셈이다.

**해결 방법.**

- 서브에이전트에게 상세 내용 대신 간결한 요약만 돌려주도록 지시한다.
- 동시에 돌리는 서브에이전트 수를 줄인다.
- 결과를 대화로 돌려받지 말고 파일에 쓰게 한다.
- 결과를 처리한 뒤 더는 필요 없으면 `/compact`로 정리한다.

---

## 5. 정리

| 증상 | 한 줄 원인 | 대표 해결책 |
|------|-----------|-------------|
| 환경 변수가 사라진다 | 명령마다 새 셸이 뜬다 | `&&`로 묶거나 파일에 쓰고 `source` |
| Claude가 규칙을 잊는다 | 컨텍스트가 가득 차 압축되었다 | "Compact Instructions"에 규칙 이동 |
| 압축 시점이 안 맞는다 | 기본 기준이 약 95%다 | `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 조정 |
| 서브에이전트 때문에 컨텍스트가 찬다 | 결과가 메인으로 돌아온다 | 요약만 반환, 파일로 저장 |
