# 진단과 디버깅 도구

Claude Code가 이상하게 동작할 때 무엇부터 봐야 할지 모르면 시간을 많이 쓴다. 이 문서는 상태를 점검하는 `claude doctor`, 프록시와 게이트웨이 설정을 확인하는 방법, 그리고 상세 출력으로 내부 동작을 들여다보는 방법을 정리한다.

세 가지는 쓰임새가 다르다. `claude doctor`는 환경 전반을 훑어보는 첫 단계이고, `/status`는 프록시와 게이트웨이 설정을 보는 용도이며, 상세 출력(verbose)과 `--debug`는 Claude의 판단과 훅 실행 과정을 추적하는 용도다.

---

## 1. claude doctor로 상태 점검하기

**증상.** Claude Code가 예상과 다르게 동작하거나, 시작되지 않거나, 연결이 실패한다.

**실행.** 터미널에서 `claude doctor`를 실행한다.

**점검 항목.**

- 인증 상태와 토큰 유효성
- API 엔드포인트로의 네트워크 연결
- 설정 파일의 문법 오류
- MCP 서버 사용 가능 여부
- 환경 변수 충돌
- 바이너리 버전과 업데이트 상태

**언제 쓰나.** 컨텍스트나 프롬프트 문제라고 분명하게 말할 수 없는 모든 문제의 첫 단계로 쓴다. 대화 내용 때문이 아니라 설치나 설정, 연결 때문에 생긴 문제를 빠르게 걸러낼 수 있다.

---

## 2. 프록시와 게이트웨이 설정 확인

**증상.** 회사 프록시나 LLM 게이트웨이를 쓸 때 API 호출이 실패한다. 인증 에러가 나거나, 모델이 예상과 다른 곳으로 연결된다.

**원인.** 프록시 URL, 기본 URL(base URL), 인증 헤더가 잘못 설정됐거나 서로 충돌한다.

**해결 방법.**

- `/status`를 실행해 현재 프록시와 게이트웨이 설정을 확인한다.
- 환경 변수 `ANTHROPIC_BASE_URL`, `HTTP_PROXY`, `HTTPS_PROXY`를 점검한다.
- 프록시 인증서를 시스템이 신뢰하는지 확인한다.
- 게이트웨이가 인증을 대신 처리한다면 해당하는 인증 건너뛰기 변수를 설정한다. Bedrock이면 `CLAUDE_CODE_SKIP_BEDROCK_AUTH=1`, Vertex면 `CLAUDE_CODE_SKIP_VERTEX_AUTH=1`을 쓴다.

게이트웨이가 이미 인증을 맡고 있는데 Claude Code도 자체 인증을 시도하면 충돌이 생긴다. 건너뛰기 변수는 이 중복을 없애는 역할을 한다.

---

## 3. 상세 출력으로 디버깅하기

**증상.** Claude가 왜 그런 결정을 했는지, 도구 호출이 왜 실패했는지, 훅이 어떤 데이터를 받았는지 알 수 없다.

**원인.** 기본 출력은 도구 사용, 훅 실행, 내부 처리 정보를 자세히 보여 주지 않는다. 화면을 단순하게 유지하려는 설계라서, 문제 추적에는 정보가 부족하다.

**해결 방법.**

- `Ctrl+O`를 눌러 상세 출력(verbose)을 켜고 끈다. 도구 사용과 실행 내용이 자세히 나온다.
- `claude --debug`로 실행하면 훅 실행 세부 정보가 나온다. 어떤 훅이 매칭됐는지, 종료 코드는 무엇인지, 출력은 무엇인지 볼 수 있다.
- 차단하지 않는 에러의 경우 훅의 stderr 출력을 확인한다. 상세 모드에서 볼 수 있다.
- 훅의 JSON 파싱을 확인하려면 `Ctrl+O`를 켠 상태에서 원본 stdout을 살펴본다.

훅 문제의 구체적인 사례는 별도 문서 「훅 문제 해결」에서 다룬다.

---

## 4. 어떤 도구를 언제 쓰나

| 상황 | 먼저 쓸 도구 |
|------|--------------|
| 시작이 안 되거나 연결이 실패한다 | `claude doctor` |
| 프록시나 게이트웨이 때문에 API 호출이 실패한다 | `/status`, 환경 변수 점검 |
| Claude의 도구 호출 과정을 보고 싶다 | `Ctrl+O` |
| 훅이 어떻게 매칭되고 실행됐는지 보고 싶다 | `claude --debug` |
