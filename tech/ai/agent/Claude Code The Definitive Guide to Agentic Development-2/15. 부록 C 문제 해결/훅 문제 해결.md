# 훅 문제 해결

훅(hook)은 Claude Code가 특정 시점에 자동으로 실행하는 스크립트다. 잘 쓰면 편하지만, 설정이 조금만 어긋나도 아무 소리 없이 동작하지 않는다. 이 문서는 훅이 아예 실행되지 않는 경우와, 실행은 됐는데 결과가 반영되지 않는 경우를 나누어 정리한다.

두 문제 모두 에러 메시지가 거의 나오지 않는다는 점이 까다롭다. 그래서 `claude --debug`와 `Ctrl+O` 같은 상세 출력을 함께 써서 원인을 좁혀 가야 한다.

---

## 1. 훅이 실행되지 않을 때

**증상.** 설정한 훅이 기대한 시점에 실행되지 않는다. 출력도 에러도 없다.

**원인.** 흔한 원인은 세 가지다. 스크립트에 실행 권한이 없는 경우, 매처(matcher)가 도구 이름과 맞지 않는 경우, 세션이 시작된 뒤 훅이 수정되었는데 검토를 거치지 않은 경우다.

**해결 방법.**

- 스크립트를 실행 가능하게 만든다: `chmod +x script.sh`
- 셔뱅(shebang) 줄을 확인한다. 첫 줄이 `#!/bin/bash` 또는 `#!/usr/bin/env bash`여야 한다.
- 매처가 도구 이름과 정확히 일치하는지 본다. 예를 들어 `Bash`는 맞고 `bash`는 맞지 않는다. 대소문자를 구분한다.
- 세션 중에 훅을 수정했다면 `/hooks` 메뉴에서 변경 내용을 검토한다.
- 설정에서 `disableAllHooks`가 `true`로 되어 있지 않은지 확인한다.
- `claude --debug`로 어떤 훅이 평가되고 매칭되는지 확인한다.

원인이 눈에 띄지 않으면 `claude --debug` 출력으로 훅이 평가되고 매칭되는 과정을 직접 확인한다.

---

## 2. 훅의 JSON 파싱 오류

**증상.** 훅이 종료 코드 0으로 끝나는데 JSON 출력이 처리되지 않는다. Claude가 훅이 내린 결정을 무시한다.

**원인.** stdout에 JSON이 아닌 텍스트가 섞여 JSON 파싱을 방해한다. 흔히 셸 프로파일 스크립트가 시작할 때 출력하는 문구가 원인이다. JSON 앞뒤에 문자열이 한 줄이라도 붙으면 전체가 JSON으로 읽히지 않는다.

**해결 방법.**

- 종료 코드 0일 때 stdout에는 JSON 객체만 나가도록 한다.
- 꼭 필요하지 않은 출력은 stderr로 돌린다.
- `.bashrc`, `.zshrc` 같은 셸 프로파일이 시작할 때 텍스트를 출력해 stdout을 오염시키지 않는지 확인한다.
- 스크립트를 직접 실행해 보고 원본 출력을 살펴본다.

stderr로 돌리는 예시는 다음과 같다.

```bash
echo "debug info" >&2
```

---

## 3. 증상별 점검 요약

| 증상 | 점검할 것 |
|------|-----------|
| 훅이 전혀 실행되지 않는다 | 실행 권한, 셔뱅, 매처 이름의 대소문자, `disableAllHooks` |
| 세션 중 수정한 훅이 안 먹힌다 | `/hooks` 메뉴에서 변경 검토 |
| 종료 코드 0인데 결정이 무시된다 | stdout에 JSON 외 텍스트가 섞였는지, 셸 프로파일 출력 |
| 원인을 모르겠다 | `claude --debug`로 매칭 여부, 종료 코드, 출력 확인 |
