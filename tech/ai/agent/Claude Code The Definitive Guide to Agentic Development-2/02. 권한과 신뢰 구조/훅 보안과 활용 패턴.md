# 훅 보안과 활용 패턴

훅은 강력한 만큼 그 자체가 보안 대상이다. 훅은 내 머신에서 내 권한으로 도는 임의의 명령이기 때문이다. 이 문서는 먼저 훅의 보안 모델(스냅숏, 전체 권한, 조직용 제한)을 설명하고, 이어서 원문이 소개하는 대표적인 활용 패턴을 하나씩 살펴본다.

---

## 1. 훅은 시작할 때 스냅숏으로 고정된다

Claude Code는 세션을 시작할 때 설정된 모든 훅의 상태를 캡처하고, 세션 내내 그 스냅숏을 쓴다. 누군가 또는 무언가가 세션 도중 디스크의 훅 파일을 수정하면 Claude Code가 변화를 감지하고 경고를 표시한다. 수정된 훅은 `/hooks` 메뉴에서 검토하기 전에는 적용되지 않는다. 악의적이거나 우발적인 훅 수정이 활성 세션 중에 에이전트 동작을 슬쩍 바꾸는 일을 막기 위한 장치다.

## 2. 훅은 전체 사용자 권한으로 실행된다

훅은 내 자격 증명, 내 파일 시스템 접근, 내 네트워크 접근을 그대로 갖고 실행되는 임의의 명령이다. 훅 주위에는 샌드박스가 없다.

따라서 훅 코드에는 내 권한으로 도는 다른 모든 코드와 같은 수준의 보안 검토가 필요하다. 원문이 꼽는 항목은 다음과 같다.

- 입력 검증
- 셸 따옴표 처리(quoting)
- 경로 탐색(path traversal) 방지

도구 입력을 셸 명령에 그대로 끼워 넣는 훅은 코드 인젝션 취약점이다. 도구 입력은 에이전트가 만들거나 외부 내용의 영향을 받을 수 있으므로 신뢰할 수 없는 값으로 다뤄야 한다.

## 3. 조직용 제한: `allowManagedHooksOnly`

기업은 Managed 설정의 `allowManagedHooksOnly`로 훅을 Managed 범위에서 정의된 것만 허용하도록 제한할 수 있다. 개별 개발자와 프로젝트 수준 설정은 훅을 추가할 수 없다. 침해된 프로젝트가 데이터를 빼돌리거나 도구 동작을 바꾸는 훅을 설치하는 일을 막아 준다.

## 4. 활용 패턴: 파괴적 명령 차단

Bash 대상 PreToolUse 훅이 JSON 입력에서 명령을 읽고, 위험한 패턴을 검사하고, deny 결정을 반환한다.

```bash
#!/bin/bash
COMMAND=$(jq -r '.tool_input.command')
if echo "$COMMAND" | grep -q 'rm -rf'; then
  jq -n '{
    hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: "Destructive rm -rf blocked by hook"
    }
  }'
  exit 0
fi
exit 0  # allow the command
```

Claude가 파괴적 명령을 실행하려 하면 훅이 가로채 deny 결정을 돌려주고, Claude는 그 사유를 컨텍스트에서 본다. 그러면 대안을 찾거나 그 명령이 왜 필요한지 설명한다. 이 예시는 deny를 JSON으로 반환한 뒤 종료 코드 0으로 끝난다는 점에 주목하자. 앞 문서의 종료 코드 2 방식 대신 JSON 결정 방식을 쓴 것이다.

## 5. 활용 패턴: 쓸 때마다 린트

Claude가 파일을 편집할 때마다 린터를 실행하는 PostToolUse 훅이다.

```json
{
  "PostToolUse": [{
    "matcher": "Edit|Write",
    "hooks": [{
      "type": "command",
      "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/check-style.sh"
    }]
  }]
}
```

편집할 때마다 린트 스크립트가 돌고, 실패는 Claude의 컨텍스트에 나타나서 다음 작업으로 넘어가기 전에 스타일 문제를 고치게 만든다. 린터가 에이전트 루프의 실시간 품질 게이트가 되는 셈이다.

## 6. 활용 패턴: 소리로 세션 상태 알리기

모든 훅이 보안용은 아니다. 창의적인 사례로, 수명 주기 이벤트마다 소리를 재생하는 훅이 있다. 세션이 시작될 때, 프롬프트를 제출할 때, Claude가 끝났을 때, 컨텍스트가 압축될 때 각각 소리가 난다. 구현은 이벤트마다 한 줄짜리 명령 훅이고, 시스템 오디오 플레이어를 백그라운드로 실행한다. 막히지 않도록 명령 끝에 `&`를 붙인다. macOS에서는 `afplay`, Linux에서는 `aplay`나 `paplay`를 쓴다.

가벼워 보이지만 쓰는 개발자들은 다른 일을 하면서 자율 실행을 돌릴 때 Claude의 상태를 계속 알아차리는 데 도움이 된다고 보고한다. 끝나면 소리가 들리고, 컨텍스트가 압축되면 소리가 나서 중요한 지시가 살아남았는지 확인하라는 신호가 된다. 탭을 오가며 확인하는 수고가 수동적인 감각 채널로 바뀐다.

## 7. 활용 패턴: 스킬에 넣는 보안 검증 훅

스킬은 frontmatter에 훅을 넣을 수 있다. 보안 중심 스킬이라면 스킬이 활성화된 동안 Bash 명령 실행 전마다 검증 스크립트를 돌리는 PreToolUse 훅을 포함할 수 있다.

```yaml
---
description: Security review workflow
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/security-check.sh"
---
```

이 훅은 스킬의 수명 주기에 묶인다. 스킬이 활성일 때만 실행되고 스킬이 끝나면 스스로 제거된다.

## 8. 활용 패턴: 여러 기준을 보는 Stop 프롬프트 훅

Stop 이벤트에 프롬프트 훅을 달아, Claude가 끝내기 전에 세 가지 조건을 평가하게 할 수 있다.

```json
{
  "Stop": [{
    "hooks": [{
      "type": "prompt",
      "prompt": "You are evaluating whether Claude should stop working. Context: $ARGUMENTS\n\nAnalyze the conversation and determine if:\n1. All user-requested tasks are complete\n2. Any errors need to be addressed\n3. Any follow-up actions were mentioned but not completed\n\nIf ALL conditions are satisfied, return {\"ok\": true}. If ANY are not met, return {\"ok\": false, \"reason\": \"specific explanation\"}."
    }]
  }]
}
```

세 조건은 사용자가 요청한 작업이 모두 끝났는지, 해결할 오류가 남았는지, 언급만 하고 끝내지 않은 후속 조치가 있는지다. 빠른 모델이 Claude의 작업이 실제로 끝났는지 평가하고, 미완료로 판단하면 Claude는 그 사유를 받고 계속 일한다.

## 9. 활용 패턴: 감사 로그, 파일 접근 제어, MCP 도구 통제

**감사 로그(audit logging).** PreToolUse 훅이 모든 도구 호출을 타임스탬프, 입력, 결정과 함께 파일이나 모니터링 서비스에 기록한다. 개발자에게는 실행 시간 영향이 없고, 보안 팀에는 완전한 가시성을 준다.

**파일 접근 제어.** Write와 Edit 대상 PreToolUse 훅이 수정 가능한 범위를 특정 디렉터리 트리로 제한해서 Claude Code가 현재 프로젝트 코드만 건드리게 강제한다. 읽기 제한은 `permissions.deny`가 맡으므로, 둘을 합치면 파일 수준의 접근 경계가 완성된다.

**MCP 도구 통제.** `mcp__server__tool` 패턴에 맞는 PreToolUse 훅으로 외부 서비스 연동에 대한 접근을 기록하거나 제한한다. MCP 도구 이름은 `mcp__<server>__<tool>` 형식이고, 매처에 정규식을 쓸 수 있다. `mcp__memory__.*`는 memory 서버의 모든 도구에, `mcp__.*__write.*`는 모든 MCP 서버의 쓰기 작업에 맞는다.

## 10. 정리

- 훅은 시작 시점에 고정되고, 세션 중 파일이 바뀌면 `/hooks`에서 검토해야 적용된다.
- 훅은 내 권한으로 도는 코드이므로 입력 검증과 따옴표 처리를 소홀히 하면 인젝션 구멍이 된다.
- 조직은 `allowManagedHooksOnly`로 Managed 훅 외에는 막을 수 있다.
- 보안, 품질 게이트, 감사, 알림까지 같은 훅 구조 하나로 해결한다.
