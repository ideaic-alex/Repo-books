# 훅 이벤트 목록

훅(hook)은 에이전트가 일하는 과정의 특정 순간에 내가 만든 검사나 동작을 끼워 넣는 장치다. 권한 규칙이 "이 호출을 허용할까"를 패턴으로만 판단한다면, 훅은 코드로 얼마든지 복잡한 판단을 할 수 있다. 그래서 원문은 훅을 권한 시스템의 확장 층이라고 부른다.

대부분의 개발자는 훅 이벤트 두 개만 알고 쓴다. 하지만 에이전트 수명 주기의 중요한 순간마다 이벤트가 있고, 전부 알아야 권한 규칙만으로는 안 되는 제어를 할 수 있다. 이 문서는 이벤트마다 언제 발생하고, 막을 수 있는지를 정리한다.

---

## 1. 도구 실행 전후 이벤트

**PreToolUse**는 모든 도구가 실행되기 전에 발생한다. 도구 호출을 막을 수도 있고, 확인 없이 허용할 수도 있고, 사용자에게 넘길 수도 있다. 도구가 실행되기 전에 입력을 수정하는 것도 가능하다. 훅 시스템의 주력이다.

**PostToolUse**는 도구가 성공한 뒤 발생한다. 도구가 이미 실행되었으므로 막을 수는 없지만, 결과에 관한 맥락을 Claude에게 줄 수 있다. 로깅, 린트, 추가 정보 주입에 쓴다.

**PostToolUseFailure**는 도구 실행이 실패한 뒤 발생한다. 에러 정보와, 실패 원인이 사용자 중단이었는지를 받는다. 맞춤 에러 보고나 대체 동작을 실행할 때 쓸 만하다.

**PermissionRequest**는 Claude Code가 사용자에게 권한 대화상자를 막 띄우려 할 때 발생한다. PreToolUse와 다른 점은 사용자에게 실제로 물어야 하는 경우에만 발생한다는 것이다. 이 훅은 자동 승인, 자동 거부, 도구 입력 수정이 가능하고, 사용자가 대화상자에서 볼 "항상 허용" 선택지와 같은 권한 규칙을 적용할 수도 있다. 결과적으로 대화형 프롬프트를 프로그램의 판단으로 대체한다.

## 2. 알림과 서브에이전트 이벤트

**Notification**은 Claude Code가 알림을 보낼 때 발생한다. 알림 종류(권한 프롬프트, 대기(idle) 프롬프트, 인증 이벤트, 정보 요청 대화상자)로 매칭한다. 알림을 막을 수는 없고 대화에 맥락을 넣을 수 있다.

**SubagentStart**는 서브에이전트가 생성될 때 발생한다. 생성을 막을 수는 없지만, 서브에이전트의 시작 상태에 맥락을 주입할 수 있다. 에이전트 종류로 매칭하며, 기본 제공 에이전트와 `.claude/agents/` 디렉터리의 사용자 정의 에이전트 이름이 모두 대상이다.

**SubagentStop**은 서브에이전트가 끝날 때 발생한다. 서브에이전트가 멈추지 못하게 막아서 계속 일하게 할 수 있다. 결과를 받아들이기 전에 검증하는 품질 게이트로 쓴다.

## 3. 에이전트 팀과 작업 이벤트

**TeammateIdle**은 에이전트 팀의 팀원이 대기 상태로 들어가려 할 때 발생한다. 종료 코드 2를 반환하면 대기에 들어가지 못하고, stderr 메시지가 피드백으로 전달된다. 매처(matcher)를 지원하지 않아서 발생할 때마다 실행된다. 빌드 산출물이 있는지 확인한 뒤에야 팀원이 멈추게 하는 식의 품질 게이트에 쓴다.

**TaskCompleted**는 작업이 완료로 표시될 때 발생한다. 명시적으로 상태를 갱신했을 때도, 진행 중인 작업이 있는 채로 팀원이 끝났을 때도 해당한다. 종료 코드 2로 완료를 막고 stderr를 피드백으로 돌려준다. 테스트 스위트 실행, 린트 통과 확인, 산출물 존재 확인 같은 완료 기준을 강제하는 데 쓴다.

## 4. 컨텍스트와 세션 이벤트

**PreCompact**는 컨텍스트 압축(compaction, 컨텍스트 윈도가 차서 내용을 줄이는 작업) 직전에 발생한다. 트리거 종류로 매칭하는데, `manual`은 사용자가 `/compact`를 실행한 경우이고 `auto`는 컨텍스트 윈도가 가득 찬 경우다. 사용자가 `/compact`에 넘긴 사용자 지정 지침도 받는다. 압축을 막을 수는 없지만, 로깅, 상태 저장, 압축 후에도 살아남아야 할 맥락 주입 같은 준비 작업을 할 수 있다.

**SessionEnd**는 세션이 끝날 때 발생한다. 종료 사유 코드를 받는데, 값은 `clear`, `logout`, `prompt_input_exit`, `bypass_permissions_disabled`, `other`다. 종료를 막지는 못하지만 정리 작업, 세션 요약 기록, 세션 후 워크플로 실행에 유용하다.

## 5. 막을 수 있는지 한눈에 보기

| 이벤트 | 시점 | 막을 수 있는가 | 주요 용도 |
|---|---|---|---|
| PreToolUse | 도구 실행 전 | 가능 (입력 수정도 가능) | 위험 명령 차단, 입력 재작성 |
| PostToolUse | 도구 성공 후 | 불가 | 로깅, 린트, 정보 주입 |
| PostToolUseFailure | 도구 실패 후 | 원문에 막을 수 있다는 언급 없음 | 에러 보고, 대체 동작 |
| PermissionRequest | 권한 대화상자 직전 | 자동 승인/거부 가능 | 프롬프트의 프로그램화 |
| Notification | 알림 전송 시 | 불가 | 맥락 주입 |
| SubagentStart | 서브에이전트 생성 | 불가 | 시작 맥락 주입 |
| SubagentStop | 서브에이전트 종료 | 가능 (계속 일하게 함) | 결과 검증 게이트 |
| TeammateIdle | 팀원 대기 직전 | 가능 (종료 코드 2) | 품질 게이트 |
| TaskCompleted | 작업 완료 표시 | 가능 (종료 코드 2) | 완료 기준 강제 |
| PreCompact | 컨텍스트 압축 전 | 불가 | 상태 저장 |
| SessionEnd | 세션 종료 | 불가 | 정리, 로그 |

원문은 이 외에도 UserPromptSubmit와 Stop 이벤트를 이후 설명에서 사용한다. 이 둘은 이 장의 이벤트 목록 절에는 설명이 없으나, 프롬프트 훅과 에이전트 훅이 지원하는 이벤트와 Stop 훅 예시에서 이름이 나온다.

## 6. /hooks 메뉴

`/hooks` 명령은 설정된 모든 훅을 보여 주는 대화형 메뉴를 연다. 훅마다 출처를 나타내는 라벨이 붙는다. 라벨은 `[User]`, `[Project]`, `[Local]`, `[Plugin]`이다. 이 메뉴에서 훅 상세를 보고, 새 훅을 추가하고, 기존 훅을 삭제하고, `disableAllHooks` 설정을 켜고 끌 수 있다. 어떤 훅이 어디서 와서 활성화되어 있는지 점검하는 가장 빠른 방법이다.
