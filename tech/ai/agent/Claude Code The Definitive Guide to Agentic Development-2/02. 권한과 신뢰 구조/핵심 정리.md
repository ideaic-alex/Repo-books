# 핵심 정리

이 문서는 2장 끝에 실린 요점 목록을 풀어 쓴 것이다. 설정 범위, 권한 규칙, 체크포인트, 데브컨테이너, 훅, MCP, 보안 흐름까지 장 전체의 결론을 한 곳에 모았다. 각 요점마다 왜 중요한지를 함께 적었으니, 장을 다 읽은 뒤 점검용으로 쓰면 된다.

---

## 1. 한눈에 보는 요점

- **설정 범위의 위계는 엄격하다.** Managed 설정은 모든 것을 덮어쓰고, 조직 정책에서 빠져나갈 길은 없다. 개인이 편하게 바꾼 설정이 조직의 보안 기준을 깨뜨릴 수 없다는 점이 이 구조의 핵심이다.
- **권한 규칙은 deny, ask, allow 순으로 평가되고 먼저 맞는 규칙이 이긴다.** 그래서 deny 규칙은 좁게, allow 규칙은 넓게 쓴다. 순서를 모르고 규칙을 쓰면 막으려던 것이 열려 버릴 수 있다.
- **체크포인트는 파일을 직접 편집한 변경만 되돌린다.** bash 명령이 일으킨 부수 효과는 되돌리지 못하므로 진짜 안전망은 git이다. 위험한 작업 전에 커밋해 두는 습관이 필요한 이유다.
- **데브컨테이너는 네트워크를 격리하지만 악성 프로젝트 코드의 자격 증명 유출까지는 막지 못한다.** 방어를 여러 겹으로 쌓아야 하고, Anthropic이 제공하는 참조 구현을 출발점으로 삼는 것이 좋다. 한 가지 장치만 믿으면 그 장치의 빈틈이 곧 사고가 된다.
- **훅 이벤트는 열세 개로, 에이전트 수명 주기 전체를 덮는다.** PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, Notification, SubagentStart, SubagentStop, Stop, TeammateIdle, TaskCompleted, PreCompact, SessionEnd 등이 있다. 어느 시점에든 검사나 개입을 끼워 넣을 수 있다는 뜻이다.
- **훅은 세 종류가 있고 검증 필요에 따라 고른다.** 명령 훅은 결정적인 검사에, 프롬프트 훅은 모델이 내리는 판단에, 에이전트 훅은 파일에 접근하며 여러 차례 조사하는 검증에 맞는다. 목적에 맞지 않는 종류를 고르면 느리거나 부정확해진다.
- **비동기 훅은 백그라운드에서 돌아 에이전트를 막지 않는다.** 테스트 묶음이나 오래 걸리는 검증에 쓴다. 에이전트가 기다리느라 멈추는 일 없이 검증을 붙일 수 있다.
- **훅은 시작할 때 스냅숏으로 고정된다.** 세션 도중 훅을 고치면 경고가 뜨고, `/hooks` 메뉴에서 검토해야 적용된다. 실행 중에 훅이 슬쩍 바뀌는 사고나 공격을 막는 장치다.
- **PreToolUse 훅은 `updatedInput`으로 도구 입력을 실행 전에 바꿀 수 있다.** 명령 재작성, 안전 플래그 추가, 모니터링 하네스 씌우기에 쓴다. 강력한 만큼 재작성 로직의 결함이 곧 취약점이 되므로 보안 검토가 필요하다.
- **민감한 데이터에 접근할 때는 bash 명령보다 MCP 서버가 보안 가시성이 좋다.** 민감한 데이터 소스에는 직접 MCP 서버를 만들어 인증, 로그, 쿼리 제한을 붙인다. 권한과 훅과 로그를 모두 거치기 때문이다.
- **에이전트 도구 덕분에 보안 지식이 대중화된다.** 전문가만 하던 보안 리뷰를 어떤 엔지니어든 할 수 있게 되지만, 공격자도 같은 능력을 얻는다. 그래서 방어는 상대도 좋은 도구를 쓴다는 가정 위에서 세워야 한다.
- **가장 엄격한 제한과 페이퍼 트레이딩 환경에서 시작하고, 에이전트 동작을 검증한 만큼 제약을 푼다.** 신뢰는 한 번에 주는 것이 아니라 쌓아 가는 것이라는 장 전체의 태도를 요약한 문장이다.
