# 샌드박스와 체크포인트

권한 규칙이 "무엇을 하게 둘 것인가"를 정한다면, 샌드박스는 "하게 둔 일이 최대 어디까지 번질 수 있는가"를 운영체제 수준에서 제한한다. 체크포인트는 사고가 났을 때 되돌리는 안전망이다.

이 문서는 두 장치가 각각 무엇을 막아 주고, 어디에 빈틈이 있는지 설명한다.

---

## 1. 샌드박스란

Claude Code는 bash 명령에 대해 OS 수준의 샌드박스(sandbox, 프로세스가 할 수 있는 일을 운영체제가 강제로 제한하는 격리 환경)를 제공한다. 개념상의 경계가 아니라 운영체제가 실제로 집행하는 장치라서, Claude Code가 띄운 프로세스가 실제로 할 수 있는 일을 제한한다.

샌드박스가 제한하는 주요 항목은 다음과 같다.

- **네트워크 접근**: 설정한 도메인 허용 목록(allowlist)에 있는 곳만 접속할 수 있다. 기본 상태에서도 Claude Code 자체 동작에 필요한 도메인에는 갈 수 있지만, 임의의 외부 접속은 막힌다. 패키지 레지스트리, 사내 API, 클라우드 제공자 엔드포인트처럼 워크플로에 필요한 도메인은 직접 추가한다.
- **Unix 소켓 경로 허용 목록**: 접근할 수 있는 소켓 경로를 목록으로 정한다.
- **로컬 포트 바인딩 제어**: 프로세스가 로컬 포트를 열 수 있는지 제어한다.
- **명령 단위 예외**: 특정 명령을 샌드박스 규칙에서 따로 빼는 설정이다. 원문은 이 항목의 세부 동작까지 설명하지 않는다.

설정 단위가 충분히 세밀해서 "`npm install`은 허용하되 임의 URL로 가는 `curl`은 막는다" 같은 정책을 표현할 수 있다.

## 2. 샌드박스 아래의 자동 승인

샌드박스가 켜져 있으면 신뢰를 계산하는 방식이 바뀐다. 이때 Claude Code는 bash 명령을 자동 승인할 수 있다. 피해 범위(blast radius)가 갇혀 있기 때문이다.

- 샌드박스 안에서 `rm -rf /`를 실행하면 로컬 파일은 여전히 망가진다. 하지만 데이터를 외부 서버로 빼돌리지는 못한다.
- 샌드박스 안의 `curl`은 허용 목록 밖의 도메인에 닿지 못한다.

이것이 샌드박스의 설계 의도다. 에이전트를 묶어 두는 대신 환경을 묶어서 자율 동작을 안전하게 만든다. 권한 확인창을 줄이는 대신 격리 경계를 얻는 교환이며, 많은 워크플로에서는 이 교환이 맞다.

주의할 점은 자동 승인이 안전한 것은 샌드박스라는 조건이 있을 때뿐이라는 것이다. 같은 자동 승인이라도 샌드박스가 없는 환경에서는 위험해진다. 샌드박스 격리가 자동 승인을 안전하게 만드는 맥락과 위험하게 만드는 맥락을 구분하는 것이 이 장이 강조하는 포인트다.

## 3. 샌드박스의 탈출구

샌드박스에는 탈출구가 있다. 기본 설정에서는 Claude Code가 샌드박스 밖에서 명령을 실행해야 할 때 사용자에게 물어볼 수 있다. 편리한 장치지만, 이 경로가 열려 있으면 격리가 완전하지 않다.

Managed 설정으로 이 탈출구를 완전히 비활성화할 수 있다. 강한 보장이 필요한 기업 환경에서 원문이 말하는 "기업 입장에서 올바른 설정"이 이것이다. 앞 문서에서 본 대로 Managed 설정은 개발자가 덮어쓸 수 없으므로, 탈출구를 닫는 일도 조직 차원에서 강제할 수 있다.

## 4. 체크포인트: 구멍 있는 안전망

Claude Code는 파일을 편집하기 전에 대상 파일을 스냅숏으로 저장한다. 문제가 생기면 Escape를 두 번 눌러 코드와 대화를 모두 체크포인트 시점으로 되감을 수 있다. 일종의 실행 취소 시스템이고, 보장하는 범위 안에서는 꽤 좋다. 그 범위는 Claude Code의 Write와 Edit 도구로 직접 한 파일 편집이다.

문제는 빈틈이다. 가장 큰 것은 bash 명령으로 일어난 파일 변경을 체크포인트가 보지 못한다는 점이다. 체크포인트 한계의 전체 목록과 그 영향은 원문 10장에서 다루며, 이 장에서는 보안 관점의 결론만 짚는다.

- 파일 시스템을 bash로 바꾸는 작업을 할 때 안전망은 체크포인트가 아니라 git이다.
- 작업을 시작하기 전에 먼저 커밋한다.
- 자주 커밋하고, 필요하면 되돌린다.

## 5. 두 장치의 역할 정리

| 장치 | 막아 주는 것 | 한계 |
|---|---|---|
| 샌드박스 | bash 프로세스의 네트워크 접근 등 실제 행동 범위 | 탈출구를 열어 두면 격리가 약해진다. 로컬 파일 파괴는 막지 못한다 |
| 체크포인트 | Write/Edit 도구로 한 편집을 되돌림 | bash로 바뀐 파일은 보지 못한다 |
| git | 모든 파일 변경(커밋해 둔 시점까지) | 커밋하지 않은 작업은 보호하지 못한다 |

샌드박스 하나나 체크포인트 하나로 충분하다고 생각하면 안 된다. 하나는 밖으로 새는 것을 막고, 하나는 안에서 생긴 변경을 되돌리며, 둘 다 못 잡는 영역은 git이 메운다.
