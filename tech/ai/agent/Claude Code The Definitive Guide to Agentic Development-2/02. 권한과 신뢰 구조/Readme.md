# 권한과 신뢰 구조

Claude Code는 명령 실행, 파일 수정, 네트워크 요청, 서브에이전트 조율까지 코드베이스 전체에서 할 수 있다. 그만큼 위험도 크기 때문에 권한 시스템은 단순한 스위치가 아니라, 다섯 단계 설정 범위와 세 단계 규칙 평가, 샌드박스, 훅, 체크포인트가 겹쳐진 구조로 되어 있다.

이 장은 확인창을 눌러 넘기는 것에서 벗어나, 이 구조가 실제로 어떻게 동작하는지 설명한다. 조직 정책이 개인 설정을 덮는 방식, glob 패턴이 호출을 막는 방식, 샌드박스가 자동 승인을 안전하게 만드는 조건, 훅 이벤트 전체, 그리고 에이전트 시대의 보안 흐름까지 다룬다.

---

## 1. 핵심 요점

- **설정 범위는 다섯 단계**: Managed, CLI 인자, Local, Project, User 순으로 우선한다. Managed는 개발자가 덮어쓸 수 없고, 막혀도 아무 안내가 없다.
- **규칙은 deny, ask, allow 순으로 평가**: 먼저 맞는 규칙이 이기므로 deny는 좁게, allow는 넓게 쓴다. 비밀 파일은 `permissions.deny`로 읽기부터 막는다.
- **샌드박스는 환경을 묶어 자동 승인을 안전하게 한다**: 네트워크 허용 목록 등으로 피해 범위를 가둔다. 샌드박스 밖 실행이라는 탈출구는 Managed 설정으로 닫을 수 있다.
- **체크포인트는 bash 변경을 보지 못한다**: Write와 Edit 도구의 편집만 되돌린다. bash로 파일을 바꾸는 작업 전에는 git 커밋이 안전망이다.
- **데브컨테이너도 유출은 못 막는다**: 허용된 통로로 나가는 자격 증명 유출은 방화벽이 막지 못한다. `permissions.deny`와 컨테이너 격리를 함께 써야 한다.
- **훅은 에이전트 수명 주기 전체를 제어한다**: 이벤트가 열세 개이고, 명령, 프롬프트, 에이전트 세 종류가 있으며, 종료 코드 2로 차단한다. 훅은 전체 권한으로 돌므로 스스로도 보안 대상이다.
- **MCP는 CLI보다 통제하기 쉽다**: 구조화된 입출력, 권한 시스템, 훅, 로그를 모두 거친다. 민감한 데이터 소스는 MCP 도구로 감싼다.
- **보안 도구는 이중 용도다**: 방어와 공격 모두에 쓰이므로 보안을 처음부터 워크플로에 넣고, 합성 데이터 환경에서 먼저 검증한 뒤 경계를 넓힌다.
