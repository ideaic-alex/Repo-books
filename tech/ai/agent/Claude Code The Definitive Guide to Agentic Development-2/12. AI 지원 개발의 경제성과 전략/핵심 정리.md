# 핵심 정리

이 문서는 12장의 마지막 요점 목록을 풀어 쓴 것이다. 비용 구조, 일정 단축, 역할 변화, 도구 선택, 앞으로의 우선순위가 한 줄기로 이어진다는 점을 다시 확인하는 용도로 읽으면 된다.

---

## 1. 한눈에 보는 요점

- **프롬프트 캐싱이 풍부한 컨텍스트를 가능하게 한다.** CLAUDE.md, MCP 도구, 시스템 프롬프트 같은 긴 앞부분은 세션에서 한 번만 전액을 낸다. 그래서 컨텍스트를 아낌없이 채워도 비용 부담이 크지 않고, 그만큼 결과 품질이 오른다.
- **일에 맞춰 모델을 고른다.** 설계는 Opus, 구현은 Sonnet, 탐색은 Haiku가 맞고, 서브에이전트를 쓰면 한 세션 안에서 모델을 섞을 수 있다. 추론 비용은 노력 수준(낮음, 중간, 높음)과 CLAUDE_CODE_EFFORT_LEVEL 환경 변수로 조절한다. 쉬운 일에 비싼 모델과 깊은 추론을 쓰지 않는 것이 비용 관리의 핵심이다.
- **세 가지 배수가 곱해진다.** 에이전트 능력, 조율 개선, 쌓이는 사람의 경험이 서로 곱해지므로 개선이 직선이 아니라 계단식으로 나타난다. 한 요소만 보고 기대치를 잡으면 실제 성과를 낮게 본다.
- **일정이 70~90% 줄면 프로젝트의 타당성이 바뀐다.** 석 달에서 여섯 달 걸리던 운영 플랫폼이 8주로, 2~3주 걸리던 기능이 2~3일로 줄어든다. 예전에는 시작조차 못 하던 일이 해볼 만한 일이 된다는 점이 중요하다.
- **하이브리드 툴체인이 한 도구보다 낫다.** 저장소 규모의 추론은 Claude Code가, 키 입력 수준의 자동완성은 전용 인라인 도구가 맡는다. 두 도구가 일하는 상호작용 규모가 달라서 나눠 쓸 때 마찰이 줄어든다.
- **Claude Code의 강점과 약점을 안다.** 큰 코드베이스에서의 계획과 패치 생성이 강점이고, 인라인 자동완성, 시각적인 멀티 에이전트 관리, CI 통합은 다른 도구가 앞선다. 강점에 맞는 일을 맡겨야 도구가 제값을 한다.
- **모두가 더 풀스택에 가까워진다.** 백엔드 개발자가 몇 시간 만에 프런트엔드 앱을 만들고, 디자이너가 상태 관리를 고치고, 비개발 팀이 전혀 새로운 능력을 만든다. 직군 사이의 벽이 낮아져서 조직이 할 수 있는 일의 범위가 넓어진다.
- **기술 부채를 체계적으로 갚을 수 있다.** 에이전트가 낮아진 비용으로 밀린 작업을 처리하므로, 우선순위 문턱을 넘지 못해 방치되던 일이 처리 대상이 된다. 쌓아 두기만 하던 부채를 계획적으로 줄일 길이 열린다.
- **2026년의 우선순위는 네 가지다.** 멀티 에이전트 조율을 익히고, 자동 리뷰로 사람의 감독을 확장하고, 에이전트 코딩을 엔지니어링 밖으로 넓히고, 처음부터 보안 설계를 넣는 것이다. 이 네 가지가 에이전트 개발을 전략 역량으로 다루는 조직과 단순 도구로 쓰는 조직을 가른다.
