# 장 마무리와 앞으로의 개선

이 장의 끝부분에서 책은 아직 부족한 기능이 앞으로 어떻게 채워질지 전망하고, 지금 무엇을 만들고 무엇을 기다릴지 판단하는 기준을 제시한다. 이 문서는 그 마무리 부분과 장 전체의 핵심 요점을 표로 정리한다.

내용은 크게 두 가지다. 부족한 기능이 어떻게 채워질지에 대한 기대, 그리고 지금 무엇을 만들고 무엇을 기다릴지에 대한 판단이다.

---

## 1. 앞으로 기대되는 개선

### 1.1 더 오래 도는 프로젝트 단위 작업

체크포인트와 진행 상황 대시보드가 있는 프로젝트 단위의 장시간 작업이 지원되면, 에이전트가 맡을 수 있는 작업의 길이가 몇 시간에서 며칠로 늘어난다. 이를 위해 필요한 것으로 원문은 다음을 든다.

- 더 나은 재개(resume)와 재시도 지원
- 작업 식별자(job ID)
- 다시 열 수 있는 세션
- 웹과 데스크톱 화면에서의 시각적인 진행 추적

이런 기능이 갖춰지면 밤샘 작업이나 여러 날에 걸친 에이전트 작업이 현실적인 선택지가 된다.

### 1.2 공식 스킬 팩 확대

Anthropic이 CI, 테스트, 마이그레이션, 보안 스캔용 공식 스킬 팩을 더 내놓으면 흔한 워크플로의 준비 비용이 줄어든다. 지금은 각 팀이 모범 사례를 따로 찾아내야 하는데, 공식 팩이 그 기준을 세워 준다.

## 2. 지금 무엇을 만들고, 무엇을 기다릴까

원문은 질문을 바꾸자고 한다. "이것들을 기다려야 하나?"가 아니라 "지금 무엇을 만들고, 무엇을 기다릴까?"를 물으라는 것이다.

- 지금 Claude Code로 만들 만한 일: 저장소 전체에 걸친 리팩터링, 에이전트 워크플로, 깊은 추론이 필요한 작업, 큰 코드베이스를 이해하는 일이 병목인 모든 상황.
- 하이브리드 도구 구성: 에디터 안에서의 인라인 자동 완성과 빠른 반복에는 별도 도구를 함께 쓴다.
- 가까운 시일에 보완될 가능성이 큰 부분: 멀티 에이전트 UI, CI 연동 레시피, 더 오래 도는 작업 지원.

## 3. 핵심 요점

| 주제 | 내용 |
|------|------|
| 프롬프트 캐싱 | 세션당 한 번만 전체 요금을 내므로 CLAUDE.md, MCP 도구, 시스템 프롬프트 같은 풍부한 컨텍스트를 쓸 만해진다 |
| 모델 선택 | 아키텍처에는 Opus, 구현에는 Sonnet, 탐색에는 Haiku. 서브에이전트로 한 세션 안에서 모델을 섞을 수 있다. 추론 비용은 effort 수준(low/medium/high)과 `CLAUDE_CODE_EFFORT_LEVEL` 환경 변수로 조절한다 |
| 세 가지 배수 효과 | 에이전트 능력, 조율(오케스트레이션) 개선, 쌓이는 사람의 경험이 곱해져 선형이 아니라 계단식 성과를 낸다 |
| 일정 단축 | 70~90% 단축은 프로젝트의 타당성을 바꾼다. 3~6개월 걸릴 프로덕션 플랫폼을 8주에, 2~3주 걸릴 기능을 2~3일에 끝내는 식이다 |
| 하이브리드 도구 | 저장소 단위 추론은 Claude Code, 키 입력 단위 자동 완성은 전용 인라인 도구가 맡는 구성이 한 도구만 쓸 때보다 낫다. 두 도구는 상호작용 규모가 다르기 때문이다 |
| 경쟁력 | Claude Code의 강점은 큰 코드베이스의 저장소 단위 계획과 패치 생성이다. 인라인 자동 완성, 시각적 멀티 에이전트 관리, CI 연동은 다른 도구가 앞선다 |
| 풀스택화 | 백엔드 개발자가 몇 시간 만에 프론트엔드 앱을 만들고, 디자이너가 상태 관리를 바꾸고, 비개발 팀이 완전히 새로운 기능을 만든다 |
| 기술 부채 | 에이전트가 낮아진 비용으로 백로그를 처리하면, 우선순위 기준을 넘지 못하던 작업까지 체계적으로 해결할 수 있다 |
| 2026년 우선순위 | 멀티 에이전트 조율 익히기, 자동 리뷰로 감독 확장하기, 에이전트 코딩을 엔지니어링 밖으로 넓히기, 처음부터 보안 설계 넣기 |

### 3.1 배수 효과 풀이

여러 에이전트를 나누어 맡기고 조율하는 일(오케스트레이션)이 좋아지고, 에이전트 자체도 좋아지고, 사람의 경험도 쌓이면 이 셋이 서로를 키운다. 그래서 개선이 한 칸씩 더해지지 않고 한 번에 크게 뛰는 계단식 성과로 나타난다는 것이 원문의 설명이다.

### 3.2 모델 배치 요령

한 세션 안에서도 모델을 섞을 수 있다. 설계처럼 판단이 무거운 일은 Opus, 코드 작성은 Sonnet, 코드 탐색처럼 가볍고 반복적인 일은 Haiku에 맡기고, 이를 서브에이전트로 나누면 된다. 추론에 쓰는 노력은 effort 수준으로 조절하며, 환경 변수로 지정할 수도 있다.

```bash
CLAUDE_CODE_EFFORT_LEVEL=medium claude
```

위 값은 low, medium, high 중 하나라는 점만 원문이 밝히고 있으며, 위 예시는 사용 형태를 보여 주기 위한 것이다.
