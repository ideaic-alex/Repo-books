# AI 지원 개발의 경제성과 전략

Claude Code 이야기는 보통 생산성에서 시작한다. 얼마나 빨리 낼 수 있느냐는 것이다. 이 장은 그 질문이 첫 질문으로는 틀렸다고 보고, "예전에는 만들 수 없던 무엇을 만들 수 있나"로 시각을 옮긴다. 속도 향상에서 능력 확장으로 경제성을 다시 보는 장이다.

토큰 단위의 비용 구조(프롬프트 캐싱, 모델 선택, 컨텍스트 최적화)가 어떻게 돈으로 이어지는지, 세 가지 배수가 왜 계단식 성과를 만드는지, 포트폴리오 최적화와 3년 걸린 UI 재작성과 10시간 풀스택 앱과 8주 플랫폼 같은 사례, 경쟁 도구와 하이브리드 툴체인, 2026년 전략 우선순위까지 다룬다.

---

## 1. 핵심 요점

- **프롬프트 캐싱은 기본으로 켜져 있다.** 풍부한 CLAUDE.md와 도구 정의처럼 Claude Code를 잘 쓰게 하는 요소가 캐싱의 혜택을 가장 크게 받는다. 세션이 길수록 초기 비용이 더 많은 턴에 나뉜다.
- **모델은 일에 맞춰 나눠 쓴다.** 계획과 조율은 Opus, 구현은 Sonnet, 탐색은 Haiku로 서브에이전트마다 모델을 지정하면 품질을 지키면서 평균 비용이 낮아진다. 추론 수준도 같은 원칙으로 조절한다.
- **일정은 70~90% 줄어든다.** 지식 습득 단계가 사라지고, 코드 생산이 빠르고, 컨텍스트 전환이 없기 때문이다. 이 수치는 프롬프트 작성과 검토 오버헤드를 뺀 순효과다.
- **진짜 이득은 속도보다 산출량이다.** AI 지원 작업의 약 27%는 AI 없이는 하지 않았을 일이다. 시간 절약만으로 ROI를 계산하면 가치를 낮게 잡는다.
- **세 배수가 곱해진다.** 에이전트 능력, 조율 개선, 쌓이는 사람의 경험이 서로 영향을 주며 직선이 아닌 계단식 개선을 만든다.
- **개발자의 역할이 코드 생산에서 설계, 조율, 품질 평가로 옮겨 간다.** 병목은 코딩 처리량에서 의사결정 처리량으로 이동하고, 일인 팀의 가능성이 커진다.
- **하이브리드 툴체인이 현실적이다.** 저장소 단위 추론과 실행은 Claude Code, 키 입력 수준의 자동완성은 전용 인라인 도구가 맡는다.
- **2026년 우선순위는 네 가지다.** 멀티 에이전트 조율, AI 자동 리뷰, 비엔지니어링 직군으로의 확장, 처음부터 넣는 보안 설계다.
