# 머리말과 이 책에 대하여

이 노트는 『Claude Code: The Definitive Guide to Agentic Development』의 머리말(About This Book)을 한국어로 풀어 정리한 것이다. 이 책은 사람이 아니라 Claude Code가 직접 쓴 책이며, 지시와 설계는 Vladimir Korostyshevskiy가 맡았다. 머리말에는 책이 만들어진 과정, 책이 겨냥하는 독자, 글의 분위기, 그리고 내용을 읽을 때 조심할 점이 담겨 있다.

본문을 읽기 전에 이 머리말을 먼저 훑어 두면 책 전체를 어떤 태도로 읽어야 하는지 감이 잡힌다. 특히 AI가 쓴 책이라는 점과 내용이 최신과 다를 수 있다는 점은 뒤의 모든 장을 읽을 때 염두에 둘 만하다.

---

## 1. 이 책은 어떻게 만들어졌나

### 처음부터 끝까지 AI가 썼다

머리말은 첫머리에서 분명하게 선을 긋는다. 사람이 쓴 글을 AI가 다듬은 것도 아니고, AI가 옆에서 도운 것도 아니다. Anthropic의 에이전트형 코딩 도구인 Claude Code가 모든 장을 직접 썼다. 다만 아무 지시 없이 쓴 것은 아니다. Korostyshevskiy가 구조에 관한 상세한 지시문과 품질 기준(quality gate: 이 기준을 통과해야 다음 단계로 넘어가는 관문)을 미리 설계했고, Claude Code는 그 틀을 따라 썼다.

### 자료 수집 단계

글을 쓰기 전에 먼저 자료를 모았다. 이 단계에서는 Claude 하나만 쓴 것이 아니라 Claude, Gemini, Perplexity 같은 여러 AI 시스템이 함께 조사에 동원되었다. 이들이 훑은 자료는 크게 네 종류다.

- Anthropic이 공개한 Claude Code 공식 문서
- 공개된 사용 사례
- 기술 분석 글
- 에이전트 방식 개발(agentic development: AI 에이전트가 스스로 계획하고 도구를 쓰며 개발을 진행하는 방식)에 관한 업계 보고서

사용 사례를 모을 때는 특히 금융권 프런트 오피스 환경에 신경을 썼다고 한다. 증권사 같은 매도 측(sell-side)과 운용사 같은 매수 측(buy-side) 현장을 말하는데, 트레이딩 화면(UI) 개발, 주문 관리 시스템, 실시간 데이터 플랫폼처럼 납기 압박이 끊이지 않는 가운데 만들고 유지하는 핵심 업무용 데스크톱·웹 애플리케이션이 대상이다. 그래서 사용 사례에는 이런 현장의 성격이 반영되어 있다.

### 집필 단계

이렇게 모은 날것의 조사 자료를 Claude Code에 넘기면서 과제 파일(assignment file)을 함께 주었다. 이 파일에는 책의 구조, 문체, 대상 독자, 중복 제거 규칙, 법적 제약이 적혀 있었다. 이후의 작업은 Claude Code의 멀티 에이전트 구조가 맡았다. 여러 에이전트가 역할을 나누어 일했다는 뜻이다.

| 단계 | 맡은 에이전트 | 하는 일 |
| --- | --- | --- |
| 조사 | 리서치 에이전트 | 자료를 병렬로 읽고 요약한다 |
| 집필 | 작성 에이전트 | 각 장을 쓴다 |
| 편집 | 편집 에이전트 | 품질 기준에 맞는지 검토한다 |
| 최종 검수 | 검토 패널 | 일관성, 완결성, 규정 준수를 확인한다 |

이 검수를 통과한 뒤에야 원고가 하나로 합쳐져 EPUB(전자책 파일 형식)으로 만들어졌다. 이 책은 에이전트 여러 개가 역할을 나누어 일하는 방식으로 만들어졌다. 책 제목이 말하는 에이전트 방식 개발을 책 자신이 제작 과정에서 직접 쓴 셈이다.

### 저작권을 피하려고 둔 규칙

머리말은 책을 자유롭게 나눌 수 있도록 의도적으로 몇 가지 제약을 걸었다고 밝힌다.

- 출처 자료의 문장을 그대로 베낀 곳이 없다. 모든 아이디어를 바꿔 쓰고 종합해서 다시 썼다.
- Anthropic 외에는 어떤 회사 이름도 본문에 나오지 않는다.
- 경쟁 제품의 이름도 나오지 않는다.
- 특정인의 말을 인용하거나 누구의 발언인지 밝히지 않는다.
- 본문에 URL이 없다.

그래서 이 책에서 구체적인 회사나 사람 이름을 찾을 수 없는 것은 정보가 빠진 것이 아니라 의도한 설계다. 책은 누구나 읽고 나누어 줄 수 있어야 한다는 것이 이 모든 규칙의 목적이다.

## 2. 누가 읽는 책인가

### 입문서가 아니다

머리말은 이 책이 초보자용이 아니라고 못 박는다. Claude Code를 한 번도 써 보지 않았다면 공식 문서부터 보라고 권한다. 이 책은 독자가 이미 몇 달 동안 도구를 써 왔다고 가정한다. 그래서 입문 단계보다 한 단계 위의 내용을 다룬다.

### 무엇을 다루나

책이 다루는 내용은 다음 네 갈래다.

- **사고방식(mental model):** 도구를 어떤 관점으로 바라보아야 하는가
- **고급 기능:** 기본 사용을 넘어서는 기능들
- **실전 패턴:** 현장에서 통하는 사용 방식
- **조직 차원의 전략:** 팀과 회사에서 도입하고 운영하는 방법

책이 그리는 목표는 "가끔 쓰는 사용자"와 "에이전트 방식 개발 도구로 정말 생산성을 내는 사람" 사이의 차이를 메우는 것이다. 그래서 이 노트를 읽을 한국 개발자도 Claude Code를 이미 써 본 경험이 있다는 전제에서 읽는 편이 좋다.

## 3. 문체와 정확성에 대한 주의

### 원서의 글투

머리말은 원서가 어떤 목소리로 쓰였는지도 밝힌다. 이야기를 끌고 가는 Malcolm Gladwell식 서술과, 직설적이고 건방진 구석이 있는 Michael Lopp의 기술 글을 섞은 문체를 목표로 했다. 문서처럼 읽히는 문단이 있다면 뭔가 잘못된 것이고, "자, 시작해 보자" 식의 블로그 도입부처럼 읽힌다면 크게 잘못된 것이라고 스스로 못 박는다. 원서의 영어 문체는 이런 의도로 쓰였지만, 이 노트는 한국 개발자가 읽기 쉽도록 설명 중심의 담백한 한다체로 다시 구성했다는 점을 알아 두면 된다.

### 정확성에 대한 경고

가장 중요한 주의사항은 이것이다. 정확하게 쓰려고 노력했지만, 이 책은 빠르게 변하는 AI 도구를 AI가 쓴 책이다. 그래서 글을 쓴 시점과 독자가 읽는 시점 사이에 세부 내용이 바뀌었을 수 있다. 기능의 이름, 동작, 설정 값이 달라졌을 가능성이 있다는 뜻이다. 어떤 기능이나 기능의 현재 상태가 의심스러우면 Anthropic의 공식 문서를 확인하라는 것이 저자의 당부다.

이 노트를 읽을 때 지킬 만한 요령은 다음과 같다.

- 개념과 사고방식은 비교적 오래 가므로 믿고 읽어도 좋지만, 명령어와 설정 키는 직접 실행해서 확인한다.
- 수치나 한도처럼 바뀌기 쉬운 값은 현재 공식 문서와 대조한다.
- 책의 내용과 실제 동작이 다르면, 책이 틀린 것이 아니라 도구가 바뀐 것일 수 있음을 염두에 둔다.

### 공유에 대하여

저자는 이 책을 누구나 자유롭게 공유하고 배포하고 읽을 수 있다고 밝힌다. 머리말은 "그것이 이 책의 존재 이유였다"고 맺는다. 서명은 Vladimir Korostyshevskiy, 날짜는 2026년 2월이다.

## 4. 이 노트의 구성

이 노트는 원서의 장 순서를 따라 폴더를 나누었다. 각 폴더는 한 장에 해당하며, 안에 주제별 문서가 들어 있다. 부록 세 장(13~15)은 명령어, 설정, 문제 해결을 모은 참고용이다.

| 번호 | 장 제목 |
| --- | --- |
| 00 | 머리말과 이 책에 대하여 (지금 읽는 문서) |
| 01 | 입문서 그다음 단계 |
| 02 | 권한과 신뢰 구조 |
| 03 | 컨텍스트 엔지니어링 |
| 04 | 멀티 에이전트 조율 |
| 05 | MCP로 외부 도구 연결하기 |
| 06 | CI/CD와 헤드리스 자동화 |
| 07 | IDE 연동 제대로 쓰기 |
| 08 | 에이전트 도구를 위한 프롬프트 작성법 |
| 09 | 대규모·레거시 코드베이스 다루기 |
| 10 | 실패 유형과 복구 |
| 11 | 팀 도입 패턴 |
| 12 | AI 지원 개발의 경제성과 전략 |
| 13~15 | 부록 (명령어, 설정, 문제 해결) |

순서대로 읽어도 되고, 필요한 장만 골라 읽어도 된다. 각 문서는 독립해서 읽을 수 있게 썼다. 처음 읽는다면 01장에서 책이 말하는 사고방식의 전환을 잡은 뒤, 02장 권한과 03장 컨텍스트로 이어 가는 흐름을 권한다. 팀에 도입하려는 사람은 11장과 12장을, 문제가 생긴 사람은 10장과 부록을 먼저 찾아보면 된다.
