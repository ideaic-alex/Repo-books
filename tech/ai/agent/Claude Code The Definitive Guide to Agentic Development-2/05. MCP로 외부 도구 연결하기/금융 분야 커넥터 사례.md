# 금융 분야 커넥터 사례

MCP를 가장 잘 배울 수 있는 곳은 외부 데이터가 많이 필요한 분야다. 그중 금융 데이터 분석은 좋은 사례다. 데이터 출처가 여러 곳이고, 실시간 피드가 있고, 정형 데이터와 비정형 데이터가 섞여 있고, 보안 요구 사항도 엄격하기 때문이다. 이 문서는 금융 서비스 분야의 커넥터 구성, 그 위에 얹는 사전 제작 에이전트 스킬, 그리고 공개된 두 가지 대규모 사례(국부펀드, 신경망 트레이딩 플랫폼)를 정리한다.

---

## 1. 커넥터 생태계

금융 서비스의 운영 수준 분석 플랫폼은 MCP로 열두 개가 넘는 데이터 커넥터 범주를 연결할 수 있다. 아래 표는 그중 대표 11개다. 각 커넥터는 특정 데이터 제공자를 감싼 별도의 MCP 서버다.

| 범주 | 내용 |
|---|---|
| 기본 주식 데이터 | 기업 재무, 순위, 종목 스크리닝 도구 |
| 대체 데이터 | 여러 곳에서 모은 비전통 데이터셋 |
| 펀드 리서치 | 등급, 분석, 펀드 비교 데이터 |
| 비상장 시장 데이터 | 벤처, 사모펀드, M&A 정보 |
| 실적 발표 녹취록 | 실시간 콜 녹취록과 투자자 행사 자료 |
| 전문가 인텔리전스 | 인터뷰 녹취록, 기업 조사, 산업 분석 |
| 문서 거버넌스 | 권한 통제가 있는 보안 데이터룸 접근 |
| 실시간 시장 데이터 | 채권, 외환, 주식, 거시 지표의 실시간 가격 |
| 신용 등급 | 수백만 개체에 대한 등급과 리서치 |
| 뉴스 피드 | 전 세계 멀티에셋 뉴스를 실시간으로 |
| 규제 공시 | SEC 공시, 해외 규제 제출 자료 |

### 모든 커넥터가 따르는 공통 패턴

각 커넥터는 자기 데이터 소스를 조회하는 도구를 내놓는 MCP 서버이며, 구조는 모두 같다.

1. MCP 서버가 데이터 소스의 API 클라이언트를 감싼다.
2. 도구는 도메인에 맞는 질의를 노출한다. 가격 이력 조회, 공시 검색, 재무제표 가져오기 같은 것들이다.
3. 인증은 서버 수준에서 처리하고, Claude를 거쳐 넘기지 않는다.
4. 응답 스키마는 Claude가 따로 파싱하지 않고도 해석할 수 있게 구조화한다.

이 구조 덕분에 자격 증명이 Claude의 컨텍스트 밖(MCP 서버의 환경)에 머문다. 원시 API 호출 대신 구조화된 접근 패턴을 쓰게 되고, 모든 데이터 접근을 훅으로 감사할 수 있게 된다.

## 2. 도메인 워크플로용 사전 제작 에이전트 스킬

원시 커넥터 위에 한 단계 더 올린 것이 사전 제작 에이전트 스킬이다. MCP 데이터 접근과 표준화된 분석 절차를 묶은 것으로, 금융 서비스에는 다음과 같은 스킬이 있다.

- **비교 기업 분석**: 가치평가 배수와 영업 지표로 벤치마크 데이터셋을 만든다.
- **현금흐름할인(DCF) 모델링**: 추정, 할인율 계산, 민감도 표를 다룬다.
- **실사 데이터 처리**: 문서 보관실(데이터룸)에서 구조화된 데이터를 뽑아낸다.
- **실적 분석**: 녹취록에서 지표, 가이던스 변화, 경영진 발언을 추출한다.
- **커버리지 개시 보고서**: 산업 분석과 가치평가 틀을 결합한다.

이 스킬들은 MCP 서버 자체가 아니다. MCP 커넥터에서 데이터를 받아 구조화된 결과를 만드는, 패키지로 묶인 워크플로다.

이 패턴은 일반화할 수 있다. 반복되는 분석 업무가 있는 분야라면 어디서든 절차는 표준화하고 데이터는 MCP 커넥터에서 가져오는 스킬을 만들 수 있다. 역할 분담은 단순하다. MCP 서버는 데이터 접근을 맡고, 스킬은 분석 과정을 맡는다.

## 3. 국부펀드: 기관 규모의 MCP

공개된 기록 중 가장 인상적인 MCP 배포 사례는 1조 달러가 넘는 자산을 운용하는 국부펀드(sovereign wealth fund)다. 이 펀드는 Claude를 내부 포트폴리오 기업 데이터 시스템에 연결하는 맞춤 MCP 연동을 만들었다. 약 9,000명의 포트폴리오 매니저가 매일 이 연동에 질의해서, 포트폴리오 기업의 실적, 지표, 추세에 대한 AI 생성 인사이트를 받는다.

규모가 시사하는 바가 크다. 개발자 도구나 프로토타입이 아니라, 규제를 받는 금융 환경에서 수천 명이 쓰는 인프라다. MCP 구조가 이를 가능하게 한 이유는 다음과 같다.

- 자격 증명과 데이터 접근 정책이 서버 쪽에 있다.
- 모든 질의를 감사할 수 있다.
- 연동 지점이 구조화되어 있다. 포트폴리오 매니저는 Claude와 대화하고, Claude는 MCP 도구와 상호작용하고, MCP 도구는 펀드의 내부 시스템을 조회한다.
- 자격 증명이 대화 컨텍스트를 지나가지 않는다.
- 구조 없이 날리는 API 호출 때문에 운영 데이터베이스에 잘못된 질의가 들어갈 위험이 없다.

## 4. 운영 중인 신경망 트레이딩 플랫폼: MCP 도구 41개

MCP 연동으로 어디까지 갈 수 있는지는 신경망 예측과 실시간 시장 분석을 결합한 운영 트레이딩 플랫폼에서 볼 수 있다. 이 시스템은 여러 영역에 걸쳐 MCP 도구 41개를 통합한다.

| 영역 | 내용 |
|---|---|
| 실시간 분석 | 시장 데이터 피드, 가격 이력, 거래량 분석 |
| 신경망 예측 | GPU 가속 예측 모델과의 인터페이스 |
| 백테스팅 | 몬테카를로 시뮬레이션, 과거 전략 평가 |
| 리스크 관리 | 포지션 크기 결정, 낙폭(drawdown) 분석, 상관관계 모니터링 |
| 뉴스와 감성 분석 | 실시간 뉴스 분석과 감성 점수 |

신경망 예측 엔진은 최신 시계열 모델을 돌리며 예측 지연 시간이 10ms 미만이다. CUDA 최적화로 GPU 가속을 얻어 6,250배의 속도 향상을 냈다. 예측 엔진 코드와 MCP 연동 계층은 Claude Code가 생성했다.

여기서 MCP 도구는 Claude의 추론과 GPU 가속 추론 사이의 구조화된 인터페이스 역할을 한다. 무엇을 예측하고 예측 결과에 어떻게 행동할지는 Claude가 정하고, 무거운 수치 계산은 GPU 가속이 의미를 갖는 서버 쪽에서 돈다.

### 이 규모에서는 설정 규율이 필수다

이 장에서 앞서 설명한 설정 규율이 이 규모에서는 모두 필수가 된다.

- 서버를 도메인별로 나눠야 장애가 한쪽에 갇힌다.
- 지연 로딩으로 컨텍스트 고갈을 막는다.
- 이름 규칙으로 도구 41개를 탐색 가능하게 유지한다.
- 상태 점검으로 연결 끊김이 연쇄 장애로 번지기 전에 잡는다.

각 항목의 구체적 방법은 '대규모 MCP 구성과 아키텍처 패턴' 문서에서 다시 정리한다.

## 5. 규제 환경의 접근 방식 선택

규제가 엄격한 환경에서는 모든 데이터를 MCP로 연결할 필요가 없다. 데이터의 민감도를 먼저 분류하고, 그 결과에 따라 접근 방식을 고르면 된다.

- **민감한 데이터는 로컬 파일 시스템에 둔다.** 재무 데이터, 고객 기록, 자체 데이터셋은 로컬 컴퓨터에 남긴다. Claude Code는 일반 파일 작업으로 이를 읽는다. 대화에 필요한 범위를 넘어서는 데이터가 외부 API로 나가지 않는다.
- **제한된 시스템 연동에는 MCP를 쓴다.** 데이터베이스 질의, 사내 API, 통제되는 데이터 플랫폼은 MCP 서버가 중간에서 연결을 맡는다. 자격 증명은 서버 쪽에 남고, 접근 방식은 구조화되어 감사할 수 있다. 서버가 호출 횟수 제한, 질의 제한, 데이터 필터링을 결과가 컨텍스트에 들어오기 전에 적용할 수도 있다.
- **민감하지 않은 조사는 컨텍스트 윈도에 직접 넣는다.** 토큰 10만 개 이상의 큰 컨텍스트 윈도는 논문, 공개 공시, 오픈소스 문서 같은 자료를 처리할 때 유용하다. MCP를 거치지 않고 바로 불러오면 된다.

원칙은 분류가 먼저이고 구조는 그다음이라는 것이다. 모든 일에 MCP가 필요한 것도 아니고, 모든 일에서 MCP를 피해야 하는 것도 아니다. 데이터 분류가 아키텍처를 정하며, 그 반대가 되면 안 된다.
