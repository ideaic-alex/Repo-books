# 핵심 정리

이 장에서 다룬 MCP 연결의 핵심을 열 가지로 간추린 문서다. 비용 관리, 연결 상태 점검, 보안, 팀 설정, 대규모 운영, 데이터 분류까지 실무에서 바로 쓰는 판단 기준을 한 곳에 모았다. 자세한 내용은 각 문서에서 확인한다.

---

## 1. 한눈에 보는 요점

- **도구 정의는 세션 시작부터 토큰을 쓴다.** MCP 도구마다 정의가 컨텍스트에 올라가므로 서버를 많이 붙일수록 시작 비용이 커진다. `/mcp`로 비용을 재고, 도구 검색으로 당장 필요 없는 도구는 나중에 불러오게 해야 컨텍스트 윈도를 아낄 수 있다.
- **MCP 리소스는 로컬 파일처럼 참조한다.** `@서버:리소스` 문법으로 외부 데이터를 프롬프트에서 바로 가리킬 수 있다. 외부 데이터를 따로 복사해 붙여 넣는 수고가 없어진다.
- **MCP 연결은 조용히 실패한다.** 오류 메시지 없이 도구가 사라질 수 있으므로 세션을 시작할 때와 Claude의 동작이 갑자기 달라졌을 때 `/mcp`로 상태를 확인한다. 이 습관 하나로 원인을 모른 채 헤매는 시간을 줄인다.
- **백그라운드 서브에이전트는 MCP 도구를 쓰지 못한다.** MCP가 필요한 작업은 포그라운드로 돌리거나, 메인 에이전트가 데이터를 미리 가져와 넘겨주도록 설계한다. 모르고 맡기면 작업이 중간에 막힌다.
- **훅으로 MCP 호출을 다룬다.** `mcp__서버__도구` 형태의 이름으로 매처를 걸면 호출을 기록하고, 입력을 검증하고, 결과를 변환할 수 있다. 밑줄 두 개로 잇는 이름이 Claude Code가 내부에서 쓰는 정확한 형식이라 틀리면 훅이 동작하지 않는다.
- **자격 증명을 컨텍스트 밖에 둔다.** MCP 서버는 인증 정보를 서버 환경에 두므로, 같은 일을 하는 bash 명령보다 민감한 데이터 접근에서 구조적으로 안전하다. 키가 대화에 노출되지 않는다는 점이 핵심이다.
- **서버 승인은 사용자 수준과 조직 수준으로 나뉜다.** `enableAllProjectMcpServers`, `enabledMcpjsonServers`, `disabledMcpjsonServers`는 개인 단위의 승인을 다루고, `allowedMcpServers`와 `deniedMcpServers`는 조직 정책을 강제한다. 누가 어느 층에서 통제하는지 알아야 설정이 꼬이지 않는다.
- **`.mcp.json`을 버전 관리에 커밋한다.** 한 사람이 어렵게 맞춘 설정이 팀 전체에 이득이 된다. 새 팀원도 같은 환경을 바로 얻는다.
- **3계층 구조로 토큰 비용을 줄인다.** AI 생성, 시각적 표시, 노코드 다듬기로 나누고 AI는 아이디어를 만드는 단계에만 쓴다. MCP는 그 계층에서 구조화된 데이터 접근을 맡는다. 반복 수정에 AI 토큰을 쓰지 않게 된다.
- **도구가 40개를 넘으면 규율이 필요하다.** 서버를 도메인별로 묶고, 지연 로딩을 쓰고, 이름 규칙을 엄격히 지키면 컨텍스트가 부풀거나 도구 이름이 충돌하는 일을 막는다.
- **규제 환경에서는 데이터 분류가 먼저다.** 민감한 데이터는 로컬 파일 시스템, 제한된 시스템 연동은 MCP, 민감하지 않은 조사 자료는 컨텍스트에 직접 넣는다. 분류를 먼저 하면 보안과 편의 사이에서 일관된 결정을 내릴 수 있다.
