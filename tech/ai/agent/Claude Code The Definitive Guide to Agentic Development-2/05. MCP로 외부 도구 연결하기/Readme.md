# MCP로 외부 도구 연결하기

MCP(Model Context Protocol)는 Claude Code가 파일 시스템 바깥의 데이터베이스, API, 클라우드 서비스, 사내 도구와 연결되는 표준 통로다. 이 장은 도구 정의가 컨텍스트에 어떻게 로딩되고 얼마나 비용이 드는지, 팀과 조직이 설정을 어떻게 공유하고 통제하는지, 어디서 조용히 깨지는지를 다룬다.

또한 훅으로 MCP 호출을 기록하고 검증하는 방법, 금융 분야의 대규모 운영 사례, 프롬프트 라우터와 3계층 구조 같은 설계 패턴, 그리고 curl 대신 MCP를 써야 하는 보안상 이유를 설명한다.

---

## 1. 핵심 요점

- MCP 서버를 붙이면 도구 정의(이름, 설명, 스키마)가 세션 시작 시 컨텍스트에 올라가 토큰을 쓴다. 도구 검색이 컨텍스트 용량의 약 10%까지만 즉시 로딩하고 나머지는 필요할 때 불러온다.
- `/mcp`로 서버별 토큰 비용과 연결 상태를 확인한다. 시작 전부터 컨텍스트의 15%를 쓰고 있다면 설정을 손봐야 한다.
- `.mcp.json`은 커밋해서 팀이 공유하고, 비밀 값은 환경 변수로 참조한다. 관리형 설정의 `allowedMcpServers`와 `deniedMcpServers`가 프로젝트 설정보다 우선한다.
- 서버 연결은 도중에 조용히 끊기거나 시작 단계에서 실패할 수 있다. 백그라운드 서브에이전트는 MCP를 쓸 수 없고 포그라운드 서브에이전트만 쓸 수 있다.
- 훅은 `mcp__서버__도구` 이름 규칙으로 MCP 도구를 잡는다. 로깅, 출력 변환, 입력 검증에 쓴다.
- 서버를 도메인별로 나누고, 지연 로딩을 쓰고, 도구 이름에 접두어를 붙이고, 스키마를 최소화하고, 시작 시 상태를 점검하면 도구 40개 이상도 운영할 수 있다.
- 프롬프트 라우터는 도구 후보를 5~8개로 줄이고, 3계층 구조는 AI 토큰을 생성 단계에만 쓰게 한다.
- 자격 증명은 대화 컨텍스트가 아니라 MCP 서버 환경에 둔다. 민감한 데이터에는 curl보다 MCP가 보안상 훨씬 낫다.
- 규제 환경에서는 데이터를 먼저 분류한다. 민감한 데이터는 로컬 파일, 제한된 시스템 연동은 MCP, 민감하지 않은 조사 자료는 컨텍스트에 직접 넣는다.
