# 요약과 핵심 개념

2장은 두 덩어리로 이뤄진다. 첫째는 프롬프트의 원리다. 좋은 프롬프트의 세 조건을 알아보고, 5W1H 질문 틀로 AI와 함께 제품 기획서(PRD)를 써서 그것을 프롬프트로 쓴다. 둘째는 그 원리를 적용한 실습이다. 4단계 전략으로 마케팅 포트폴리오 웹페이지를 만든다. 이 문서는 전체를 한 번에 되짚고 핵심 용어를 정리한다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 프롬프트의 중요성과 세 조건 | 명확성, 구체성, 맥락을 갖춘 요청이 좋은 결과를 낳는다는 기준 |
| 2 | 모호한 프롬프트의 한계 | "멋진 홈페이지" 같은 요청은 AI가 모든 것을 임의로 정하게 만든다 |
| 3 | 5W1H와 PRD | 여섯 질문으로 기획서를 AI와 함께 쓰고 그것을 프롬프트로 활용 |
| 4 | 1단계 프레임워크 | 섹션으로 나누고 고유 이름을 붙인 뼈대. 특정 섹션만 수정 가능 |
| 5 | 2단계 기능 | 실제 경력, 성과, 사례 데이터를 섹션별로 입력 |
| 6 | 3단계 디자인 | WordPress 테마를 참고로 전체 스타일 적용, 공개 링크로 확인 |
| 7 | 4단계 검증 | AI가 PRD와 링크를 점검하고 지적한 세 곳을 수정해 완성 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 프롬프트 | AI에 의도를 전하는 요청이며 결과의 질을 좌우한다 |
| 명확성, 구체성, 맥락 | 좋은 프롬프트의 세 조건 |
| 5W1H | Why, Who, What, When, Where, How 여섯 질문으로 만드는 기획의 뼈대 |
| PRD | 무엇을 왜 어떻게 만들지 정리한 제품 요구사항 문서. 소프트웨어에서는 What과 How를 강조 |
| 템플릿 | 효과적인 프롬프트를 쓰도록 돕는 재사용 질문 틀 |
| 섹션 | 하나의 주제를 담는 웹페이지 영역. 고유 이름을 붙이면 부분 수정이 쉽다 |
| 4단계 전략 | 프레임워크, 기능, 디자인, 검증 순서로 단계별 구현 |
| 요청, 생성, 검토, 수정 | 모든 단계에서 반복하는 짧은 순환 |
| 참고 자료 | 디자인 단계에서 AI에게 주는 구체적 예시. 이 책은 WordPress 테마 사용 |

## 3. 자주 놓치는 점

- 길고 화려한 프롬프트가 좋은 프롬프트가 아니다. 조건은 길이가 아니라 명확성, 구체성, 맥락이다.
- 1장에서는 Claude가 되물어 빈칸을 채워 줬지만, 복잡한 앱에서는 기대할 수 없다. 조건을 미리 정리해 처음부터 전한다.
- PRD 전체를 한꺼번에 코드로 바꾸라고 하지 않는다. 기능별로 쪼개 단계마다 확인한다.
- 2장의 4단계 전략과 Claude Code의 5단계 구현 프롬프트는 서로 다른 것이다.
- 페이지가 여러 파일로 갈려 미리보기에 디자인이 안 보이면 하나의 HTML 파일로 합쳐 달라고 한다.
- 디자인은 "예쁘게"가 아니라 참고 자료를 주고 요청한다. 참고를 고르기 어려우면 AI에게 추천을 부탁한다.
- 검증은 선택이 아니다. 링크가 깨지거나 내용이 빠지면 쓸 수 없는 페이지다.
- 2장부터는 Pro 이상의 유료 구독이 필요하다. 요금은 책이 쓰인 시점 기준이다.
