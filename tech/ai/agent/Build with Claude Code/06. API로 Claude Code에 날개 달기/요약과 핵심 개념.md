# 요약과 핵심 개념

6장은 두 덩어리다. 앞쪽은 AI 모델을 API로 쓰기 위한 준비(API 개념, OpenRouter, API 키, .env와 .gitignore, 연동 시험)이고, 뒤쪽은 그 준비 위에서 FridgeChef 앱을 세 단계로 만드는 실습이다. 이 문서는 흐름을 한 번에 되짚고 핵심 용어를 정리한다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | API 개념과 모델 선택 | 외부 AI를 부르는 다리로서 API를 이해하고, 통합 플랫폼 OpenRouter와 무료 모델 두 개를 고른다 |
| 2 | API 키 발급과 .env 저장 | 한 번만 보이는 키를 .env 파일로 안전하게 보관한다 |
| 3 | Claude Code 연동과 시험 | /init, .gitignore 생성, 두 모델 호출 성공, Activity에서 사용 내역 확인 |
| 4 | PRD 세 개 작성 | PRD_step1.md, PRD_step2.md, PRD_step3.md |
| 5 | 1단계 재료 인식 | Streamlit 화면에서 fridge.jpg의 재료를 알아본다 |
| 6 | 2단계 레시피 생성 | 재료를 고치고 요리 종류와 난이도를 골라 레시피를 받는다 |
| 7 | 3단계 프로필과 저장 | 데모 계정으로 로그인해 레시피를 저장하고 대시보드로 확인한다 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| API | 내 프로그램과 외부 서비스를 잇는 다리. 요청을 보내고 결과를 받는다 |
| API 키 | API 사용자를 확인하는 비밀 열쇠. 인증, 사용량 추적, 요금 청구에 쓰인다 |
| OpenRouter | 여러 회사의 AI 모델 API를 한곳에 모은 통합 플랫폼. 키 하나로 모델을 바꿔 쓴다 |
| 무료 모델 | 요청 수 한도가 있고, 입력이 학습에 쓰일 수 있어 개인정보 옵션을 켜야 쓸 수 있다 |
| .env 파일 | API 키 같은 설정 값을 코드와 따로 두는 파일 |
| .gitignore | 지정한 파일을 Git이 무시하게 하는 설정. .env 유출을 막는다 |
| Streamlit | 파이썬 파일 하나로 웹 화면을 만드는 웹 프레임워크. AI 시연에 많이 쓴다 |
| PRD 단계 분할 | 복잡한 앱을 작은 단계로 나눠 만들고, 단계마다 확인한다 |
| 로컬 환경 | 내 컴퓨터에서만 도는 환경. localhost 주소는 나만 접속한다 |
| 프로토타입 | 기능을 시험하려고 만든 초기 버전. 데이터가 사라질 수 있다 |

## 3. 자주 놓치는 점

- API 키는 발급 화면에서 한 번만 볼 수 있다. 창을 닫기 전에 복사해 두어야 한다.
- 키 값을 프롬프트에 직접 쓰지 않는다. 파일에 저장하고 Claude Code에게는 그 파일을 쓰라고만 말한다.
- 키가 든 파일은 공유 클라우드 폴더에 두지 않는다. 자동 수집 봇에 털릴 수 있다.
- 모델 이름은 한 글자도 틀리면 안 된다. 호출이 실패하면 키, 모델 이름, 일일 한도, 순서로 점검한다.
- 무료 모델은 책이 쓰인 시점 기준 예시이며 자주 바뀐다. 없으면 다른 무료 모델을 고른다.
- 무료 모델은 입력이 학습에 쓰일 수 있다. 민감한 내용은 넣지 않는 편이 안전하다.
- 앱 화면과 결과는 생성형 AI 특성상 실행마다 조금씩 다르다. 책의 그림과 똑같지 않아도 이상한 것이 아니다.
- 3단계의 로그인과 저장은 로컬 프로토타입이라 서버를 다시 켜면 데이터가 사라질 수 있다. 실서비스에는 배포, 클라우드 데이터베이스, 도메인과 보안 인증서가 더 필요하다.
