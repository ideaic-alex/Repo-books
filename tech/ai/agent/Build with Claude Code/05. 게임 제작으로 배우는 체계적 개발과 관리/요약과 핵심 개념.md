# 요약과 핵심 개념

5장은 상식 퀴즈 게임 하나를 세 걸음으로 키우며 두 가지를 배운다. 하나는 AI가 만든 내용을 검증해 환각을 막는 습관이고, 다른 하나는 커스텀 명령으로 반복 작업을 자동화하고 필요한 부분만 고치는 유지 보수 방식이다. 이 문서는 흐름을 되짚고 핵심 용어를 정리한다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | PRD 작성과 1단계 구현, 직접 테스트 | `index.html`로 돌아가는 4지선다 퀴즈 게임 |
| 2 | 환각 사례와 CLAUDE.md 검증 지침, `/clear` 재확인 | "가장 긴 강" 문제에 기준과 면책 문구가 붙음 |
| 3 | 2단계 확장, 커스텀 명령과 인수 | `/quiz-validate`, `/quiz-range`, `/quiz-add` |
| 4 | 3단계 랭킹 저장, 명령 연결, 통합 명령 | `/quiz-check`, `/quiz-stats`, `/quiz-leaderboard`, `/quiz-daily` |
| 5 | 교사 모드와 부분 수정 | `/teacher-dashboard`, 상대 평가 등급, `/export-report`로 CSV 출력 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 환각 | AI가 그럴듯하지만 사실이 아닌 내용을 만드는 현상 |
| 교차 검증 지침 | 신뢰할 문서와 비교하고 근거를 밝히도록 CLAUDE.md에 적는 규칙 |
| `/memory` | AI가 기억하는 프로젝트 정보와 메모리 파일을 열어 관리하는 명령 |
| `/clear` | 대화 기록과 컨텍스트를 완전히 초기화하고 CLAUDE.md는 남김 |
| `/compact` | 대화를 요약해 압축해서 유지하며 토큰을 줄임 |
| 전역 명령 | `~/.claude/commands/`에 두어 모든 프로젝트에서 쓰는 커스텀 명령 |
| 프로젝트 명령 | `.claude/commands/`에 두어 현재 프로젝트에서만 쓰는 커스텀 명령 |
| 인수와 자리 표시자 | 명령에 건네는 값과 그 값이 들어갈 자리(`$ARGUMENTS`, `$1`, `$2`) |
| 명령 연결 | 한 번의 요청으로 여러 명령을 순서대로 실행시키는 방식 |
| 통합 커스텀 명령 | 여러 단계를 한 md 파일에 묶고 실패 시 중단하는 명령(`/quiz-daily`) |
| 유지 보수 | 완성된 프로젝트를 계속 관리하고 개선하는 과정 |

## 3. 자주 놓치는 점

- 눈에 띄는 오류가 없다고 정확한 것은 아니다. "가장 큰" 같은 최상급 표현은 기준에 따라 답이 갈리므로 따로 점검해야 한다.
- 지침은 대화창이 아니라 CLAUDE.md에 적어야 `/clear` 뒤에도 남는다. `/clear`는 지침이 아니라 대화를 지운다.
- `/clear`는 기록을 비우고 `/compact`는 요약해 남긴다. 새 작업에는 `/clear`, 같은 작업의 최적화에는 `/compact`가 맞다.
- 새로 만들거나 고친 명령은 `/exit` 후 `claude`로 재시작해야 인식된다. 이 점을 놓쳐 "명령이 없다"고 오해하기 쉽다.
- 커스텀 명령은 파이썬이 아니라 마크다운(md) 파일이다. 보통 사람이 읽는 자연어로 쓴다.
- 커스텀 명령은 직접 입력해야 실행되고, 에이전트 스킬(8장)은 요청의 성격을 보고 자동으로 실행된다.
- AI 결과는 매번 달라진다. 책과 화면이 다르거나 같은 환각을 못 만나도 이상한 일이 아니다. 그래서 오류가 든 예제를 깃허브 저장소로 제공한다.
- 기능을 명령 파일 단위로 나눠 두면 한 파일만 고쳐 전체 구조를 지킬 수 있다. 통짜로 만들면 작은 수정도 전체 재작성이 된다.
