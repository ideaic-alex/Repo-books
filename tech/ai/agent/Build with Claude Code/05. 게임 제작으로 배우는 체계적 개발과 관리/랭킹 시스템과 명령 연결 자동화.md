# 랭킹 시스템과 명령 연결 자동화

게임은 문제를 계속 추가하고, 틀린 문제를 고치고, 난이도를 조정해야 오래 살아남는다. 이런 유지 보수를 매일 손으로 하면 금세 지친다. 이 문서는 3단계로 플레이 기록 저장과 순위표를 만든 뒤, 여러 커스텀 명령을 이어 붙이거나 하나로 묶어 매일 업데이트를 한 번에 끝내는 방법을 다룬다.

비유하면 식당의 마감 체크리스트다. 재고 확인, 청소, 매출 정리를 각각 따로 시키지 않고 "마감"이라는 한마디로 모두 순서대로 돌리는 것이다. 한 단계라도 문제가 생기면 거기서 멈추고 보고한다는 점도 비슷하다.

---

## 1. 3단계: 데이터 저장과 랭킹 시스템

앞서 만든 세 번째 프롬프트(3단계)를 Claude Code에 입력한다. 사용자 플레이 기록을 로컬에 저장하고, 이를 바탕으로 순위표(리더보드), 랭킹표, 개인 통계, 대시보드를 구현한다. 전체 프롬프트는 책 깃허브의 `PROMPTS.md`에 장별로 정리되어 있다.

실행이 끝나면 완료 메시지가 나온다. `Study-03`의 `index.html`을 열어 확인한다.

1. 퀴즈를 끝내면 상세한 통계와 최종 점수가 나온다.
2. 순위 확인 버튼을 누르면 리더보드가 보인다.
3. 상단의 통계 버튼을 누르면 통계 대시보드가 열린다.
4. 상단의 프로필 버튼을 누르면 사용자 프로필을 고칠 수 있다.

## 2. 명령 연결로 게임 관리 파이프라인 만들기

커스텀 명령은 하나로도 유용하지만 여러 개를 이으면 자동화가 강력해진다. 이번에 만드는 세 명령은 퀴즈 시스템의 정확성을 자동으로 유지하고 관리하는 핵심 도구다.

| 명령 | 하는 일 |
|---|---|
| `/quiz-check` | 모든 퀴즈의 정답이 올바른지 자동 검증 |
| `/quiz-stats` | 퀴즈 게임 데이터를 분석해 진행 상황과 난이도 분포를 수치로 정리 |
| `/quiz-leaderboard` | 플레이어 점수를 집계해 리더보드를 자동 갱신 |

세 파일을 한 번에 요청해서 만든다.

```text
.claude/commands/quiz-check.md를 만들어 줘. 모든 퀴즈 정답의 정확성을 검증한다.
.claude/commands/quiz-stats.md를 만들어 줘. 퀴즈 게임 통계를 관리한다.
.claude/commands/quiz-leaderboard.md를 만들어 줘. 랭킹 시스템을 관리한다.
세 커스텀 명령이 만들어졌는지 확인해 줘.
```

그다음 `/exit`와 `claude`로 재시작하고 `/help`로 새 명령이 목록에 있는지 확인한다. `/help` 화면은 `Esc`로 닫는다.

이제 세 명령을 한 문장으로 이어서 실행시킨다.

```text
/quiz-check로 전체 문제를 검증하고, /quiz-stats로 통계를 분석하고,
/quiz-leaderboard로 리더보드를 갱신해 줘. 한 번의 요청으로 모두 처리해 줘.
```

Claude Code는 세 명령을 차례로 실행한다. 먼저 `/quiz-check`가 모든 문제의 정답과 중복 여부를 확인하고, 경고와 오류를 분류해 문제 있는 문항을 다시 살핀다. 이어 `/quiz-stats`가 현재 진행 상황과 분야별, 난이도별 문제 분포를 숫자로 보여 준다. 마지막으로 `/quiz-leaderboard`가 점수를 집계해 순위표를 갱신한다. 끝나면 작업 요약이 나온다.

## 3. 통합 커스텀 명령 /quiz-daily

연결 실행도 방법이지만, 실제 프로젝트에서는 여러 명령을 한 파일에 묶은 통합 커스텀 명령이 더 실용적이다. 같은 퀴즈만 계속 나오면 플레이어가 금방 흥미를 잃으므로 정기 업데이트가 필요하다. 통합 명령 `/quiz-daily`는 아래 일곱 단계를 순서대로 돌린다.

1. 퀴즈 데이터 구조를 분석한다.
2. 문제 수와 분포를 확인한다.
3. 부족한 분야를 찾는다.
4. 추가 전에 중복을 검사한다.
5. 새 문제를 만들고 형식과 규칙을 검증한다.
6. 전체 데이터를 백업한다.
7. 결과 보고서를 출력한다.

각 단계는 검증과 오류 확인을 포함한다. 실패하면 즉시 멈추고 오류를 보고하며, 성공했을 때만 변경이 안전하게 적용된다.

통합 명령을 만들 때 지킬 주의점이 세 가지 있다. 파일 구조를 반드시 확인한다. 작은 단위로 테스트한다. 복잡한 작업은 단계로 쪼개고 각 단계를 검증한다. 이 조건으로 매번 새 문제를 올리고 환각 없이 결과를 확인하는 통합 코드를 만든다.

```text
.claude/commands/quiz-daily.md를 만들고 다음 작업을 순서대로 수행해 줘.
1. 퀴즈 파일 구조 파악  2. 문제 수와 분포 확인  3. 분야별 부족한 부분 파악
4. 추가 전 중복 확인  5. 추가 후 형식 검증  6. 전체 데이터 백업
7. 실행 결과 상세 보고
단계마다 확인하고 실패하면 즉시 중단하고 오류를 보고해 줘.
```

만든 뒤 재시작해 `/quiz-daily`를 실행하면 실행 완료 요약이 나온다. `index.html`을 열면 새 문제가 추가되어 있고, 평가 팝업도 새 문제에 맞게 나타난다.

## 4. Claude Code가 직접 설계한 명령: 교사 모드

지금까지는 플레이어의 시점이었다. 이번에는 여러 학생의 점수를 한눈에 보고 비교하는 교사 모드(Teacher Mode)를 더한다. 여러 플레이어의 결과를 자동으로 모으고, 분석하고, 비교하고, 보고서로 시각화하는 통합 관리 시스템이다.

특이한 점은 필요한 커스텀 명령이 무엇인지부터 Claude Code에 맡긴다는 것이다. 명령을 고안하고 만들고 하나로 묶는 일까지 AI가 한다.

```text
퀴즈를 푼 여러 학생의 점수를 한눈에 보고 비교하는 교사 모드를 만들고 싶어.
이 기능에 필요한 커스텀 명령을 고안해서 만들어 줘.
이 명령들을 모아 한꺼번에 실행하는 통합 명령도 만들어 줘.
모든 명령은 '.claude/commands/'에 md 파일로 저장해 줘.
실행 후 만든 명령과 기능을 목록으로 보고해 줘.
```

완료 후 보고서를 읽어 보면 통합 명령 `/teacher-dashboard`로 교사 모드를 자동 실행할 수 있다고 나온다. 재시작해 `/teacher-dashboard`를 입력하면 `Study-03` 폴더에 대시보드 파일 `teacher_report.html`이 만들어진다. 교사용 퀴즈 성적 보고서 페이지다.

명령을 하나씩 md 파일로 저장해 두는 이유가 있다. 각 명령의 동작과 수정 이력이 문서로 남아, 나중에 한 기능을 고치거나 개선할 때 해당 명령 파일만 손보면 된다. 그러면 전체 프로젝트를 유지한 채 기능을 안전하게 교체할 수 있어 유지 보수와 버전 관리가 효율적이다.

참고: Claude가 보고서를 매번 새로 만들기 때문에 학생 이름, 점수, 디자인이 책의 그림과 다를 수 있다. 저자의 결과물은 깃허브 `Study-03/Study-03-advanced`에 있다.
