# CLAUDE.md 검증 지침과 컨텍스트 초기화

앞 문서에서 "세계에서 가장 긴 강"처럼 기준에 따라 답이 갈리는 문제를 만났다. 이 문서는 그 해법을 다룬다. `/memory`로 프로젝트의 CLAUDE.md(프로젝트마다 두는 상시 지침 파일, Claude Code가 시작할 때마다 읽는다)를 열어 교차 검증 지침을 적고, `/clear`로 대화를 비운 뒤에도 지침이 지켜지는지 확인한다.

비유하면 CLAUDE.md는 사무실 벽에 붙인 업무 수칙이다. 직원(AI)이 바뀌거나 대화가 초기화돼도 수칙은 그대로 벽에 있다. 이 수칙에 "최상급 표현에는 근거를 밝혀라"를 적는 셈이다.

---

## 1. `/memory`로 검증 지침 저장하기

`/memory`는 AI가 기억하는 프로젝트 정보를 확인하고 관리하는 명령이다. 쉽게 말해 Claude Code에 지속적으로 주어지는 지침과 프로젝트 맥락의 메모리 파일을 열어 보고 고치는 통로다. 순서는 다음과 같다.

1. Claude Code에서 `/memory`를 입력한다.
2. 저장 위치를 묻는 화면에서 고른다. 선택지는 두 가지다. Project memory는 현재 프로젝트 폴더에만 적용되는 규칙을 담고, User memory는 모든 프로젝트에 적용되는 사용자 전체 규칙을 담는다. 퀴즈 검증 지침은 이 프로젝트에만 해당하므로 1번 Project memory를 고른다.
3. 현재 프로젝트의 CLAUDE.md가 시스템 편집기로 열린다. 이 책은 윈도우의 메모장을 쓴다. macOS는 텍스트 편집기, 리눅스는 gedit이나 nano를 쓴다.
4. 파일 맨 끝 줄에 교차 검증 지침을 붙여 넣는다.

책이 제시하는 지침은 퀴즈 정확성을 지키는 규칙 묶음이다. 앞 문서에서 본 문제를 막는 항목으로 "최상급 표현(가장, 최초 등)에 근거가 명시돼 있는가"가 들어 있고(이 항목은 뒤에서 `/quiz-validate` 명령이 다시 쓴다), 이미지 파일은 `/assets/images` 폴더에만 저장한다는 규칙도 함께 적는다. 지침 전문은 책에서 스크린샷으로만 제시되어 이 노트에서는 일부만 확인할 수 있다.

5. `File | Save` 또는 `Ctrl + S`로 저장하고 편집기를 닫는다.
6. Claude Code로 돌아오면 CLAUDE.md 파일이 열렸다는 메시지가 보인다.
7. 반영 여부는 "현재 프로젝트의 CLAUDE.md 내용을 확인해 줘"라고 요청해 본다. 방금 추가한 지침까지 전체가 나온다.

### CLAUDE.md 잘 쓰는 법

정해진 형식은 없다. 핵심은 간결하게, 사람이 읽기 쉬운 자연어로 쓰는 것이다. CLAUDE.md는 Claude의 프롬프트 일부로 작동하므로 자주 쓰는 프롬프트처럼 계속 다듬는 편이 좋다.

- 예를 들어 "프로젝트 개요"라는 제목 아래 이름, 목표, 쓰는 언어를 한두 줄씩 적는다. 책의 예는 이름 My Web App, 목표 간단한 블로그 서비스, 언어 Python 3.12와 JavaScript(React)다.
- 꼭 지켜야 할 규칙에는 '중요', '반드시' 같은 강조어를 붙이면 AI가 더 엄격히 따른다. 예로 "settings.json에 실제 API 키를 쓰지 않는다 → 반드시 .env 파일을 사용한다"가 나온다.

## 2. `/clear`로 컨텍스트 비우기

지침을 넣었으니 제대로 따르는지 시험해야 한다. 그런데 이전 대화에서 만든 문제와 맥락이 영향을 줄 수 있다. 이때 `/clear`를 쓴다. 대화 기록을 지우고 현재 세션의 컨텍스트(AI가 현재 기억하는 대화와 작업 정보의 범위)를 초기화하는 명령이다. CLAUDE.md처럼 파일에 저장된 지속 지침은 그대로 남는다.

쓸 때는 다음과 같다. 대화가 너무 길어져 불필요한 맥락이 작업을 방해할 때, 이전 프로젝트의 흔적을 지우고 완전히 새 일을 시작할 때, 잘못된 맥락 때문에 테스트 중 혼란이 생길 때다. 실행 후에는 대화 기록이 모두 사라졌는지 확인한다.

### `/clear`와 `/compact`의 차이

앞서 소개된 `/compact`도 컨텍스트를 정리하지만 방식이 다르다. 아래 표가 요약이다.

| 구분 | `/clear` | `/compact` |
|---|---|---|
| 동작 | 대화 기록을 완전히 초기화 | 대화 내용을 요약해 압축 |
| 컨텍스트 윈도우 | 완전히 비움 | 요약본으로 유지 |
| CLAUDE.md | 유지 | 유지 |

쓰는 때도 갈린다. `/clear`는 새 작업이나 기능을 시작할 때, 전혀 다른 주제로 바꿀 때, 엉뚱한 쪽으로 간 대화를 되돌릴 때 쓴다. `/compact`는 컨텍스트 윈도우가 가득 찼을 때, 같은 작업을 이어 가면서 최적화가 필요할 때, 토큰 사용을 줄일 때 쓴다.

## 3. 지침이 적용됐는지 확인하기

`/clear` 뒤에 다음 요청을 Claude Code에 입력한다.

```text
방금 저장한 지침을 참고해서 지금까지 만든 문제를 검토해 줘.
지침을 지키지 않은 문제나 답이 있으면 고쳐 줘.
```

AI는 지침에 맞게 문제를 점검하고 수정했다고 알려 준다. 이어서 `index.html`을 다시 실행한다. 이번에는 문제 문장에 "전통적 측정 기준으로"라는 조건이 붙어 나온다. 다시 나일강을 고르면 정답과 함께 추가 설명이 표시된다. 측정 기준에 따라 다른 주장도 있다는 면책 문구가 붙은 평가 화면이다.

정리하면 이 절에서 한 일은 세 가지다. 교차 검증 지침을 프로젝트 CLAUDE.md에 저장해 환각 위험을 줄였다. `/clear`로 작업 맥락을 비우고 지침이 정말 적용되는지 시험했다. 애매한 표현에 명확한 조건을 넣었다. 책의 깃허브가 완성 프로젝트의 라이브 데모(vibecoding-eng-ch05.vercel.app)를 제공한다.

참고(노트 작성자): AI 출력은 매번 달라서 지침을 넣어도 결과 문구가 책과 똑같이 나오지는 않는다. 의도한 변화는 문제에 기준이 붙고 해설에 면책이 붙는 방향이다.

## 4. 이 절의 핵심 3가지와 복습 문제

핵심은 환각이 그럴듯하지만 거짓인 정보를 만드는 현상이라는 것, `/memory`가 AI가 기억하는 프로젝트 정보를 확인하고 관리하는 명령이라는 것, `/clear`가 현재 세션의 대화와 작업 맥락을 모두 지운다는 것이다.

복습 문제는 앞 문서 끝에 정리해 두었다. 정답은 부록에 있다.
