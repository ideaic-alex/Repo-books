# 요약과 핵심 개념

7장은 두 덩어리다. 앞쪽은 서브에이전트가 무엇인지 배우고 리뷰어, 최적화, UX 에이전트 셋으로 FridgeChef를 개선하는 연습이다. 뒤쪽은 기획, 백엔드, 프런트엔드, QA, AI 통합 에이전트 다섯으로 팀을 꾸려 AI 공감 일기와 PDF 요약 AI를 만드는 실습이다. 이 문서는 흐름을 되짚고 핵심 용어를 정리한다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 에이전트와 서브에이전트의 개념 | 서브에이전트는 역할, 모델, 권한을 따로 정하는 독립 AI 전문가라는 점을 이해한다 |
| 2 | code-bug-analyzer 만들기 | 읽기 전용(Read, Grep, Glob)과 opus로 FridgeChef를 검토하고 버그 보고서를 받는다 |
| 3 | performance-optimizer, ux-design-advisor | 수정 도구(Edit, Write, Bash)를 가진 수정 담당과 화면 담당을 더한다 |
| 4 | 세 에이전트 협업 시험 | 직렬로 검토, 수정, 화면 개선을 하고 개선된 앱을 브라우저로 확인한다 |
| 5 | 작업 전 백업 | 충돌에 대비해 백업과 복원을 Claude Code에게 요청한다 |
| 6 | 다섯 에이전트 팀 구성 | PM, 백엔드, 프런트엔드, QA, AI 통합 에이전트를 sonnet으로 만든다 |
| 7 | AI 공감 일기 | 5W1H 요구사항으로 index.html 한 파일의 감정 분석 일기를 만든다 |
| 8 | PDF 요약 AI | PRD부터 시험까지 다섯 에이전트가 이어 달려 index_pdf.html을 만든다 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 에이전트 | 목표와 규칙에 따라 사람의 세부 지시 없이 스스로 판단해 일하는 AI |
| 서브에이전트 | Claude Code 안에서 특정 일을 전문으로 하는 독립 AI 보조자 |
| 정의 파일 | .claude/agents/ 폴더의 마크다운 파일. 위쪽 프런트매터와 아래쪽 지시문으로 이뤄진다 |
| 프런트매터 | name, description 필수, tools, model 선택으로 이뤄진 설정 블록 |
| tools 필드 | 에이전트가 쓸 도구. 비우면 메인 세션의 모든 도구를 쓴다 |
| model 필드 | 에이전트의 실행 모델. 비우면 메인 세션 모델을 물려받는다 |
| 읽기 전용 에이전트 | Read, Grep, Glob만 갖고 코드를 고치지 못하는 검토용 에이전트 |
| 직렬과 병렬 | 직렬은 앞 단계가 끝나야 다음이 시작되고, 병렬은 독립된 일을 동시에 한다 |
| 5W1H | 무엇, 왜, 언제, 어디서, 어떻게, 누가로 요구사항을 정리하는 틀 |
| @agent-이름 | 특정 에이전트가 꼭 실행되게 하는 지정 방식 |

## 3. 자주 놓치는 점

- 서브에이전트는 파일 하나다. 프로젝트 폴더의 .claude/agents/는 그 프로젝트에서만, 사용자 홈 폴더의 .claude/agents/는 모든 프로젝트에서 쓴다.
- 읽기 전용 에이전트는 버그를 찾아도 고치지 못한다. 수정은 Edit, Write, Bash 도구가 있는 에이전트가 맡는다.
- 프롬프트에 권한을 적지 않으면 Claude Code가 일에 필요한 도구를 판단해 준다. 만든 뒤 tools 줄을 열어 확인한다.
- 모델 이름은 소문자 fable, opus, sonnet, haiku로 쓴다. 비용이 걱정되면 sonnet으로 시작한다. 표의 모델과 성능은 책이 쓰인 시점 기준이다.
- 에이전트를 한 프롬프트에 여럿 적으면 Claude Code가 직렬과 병렬을 고른다. 백그라운드 에이전트가 하나면 직렬, 셋이면 병렬이다.
- QA 에이전트는 앞 에이전트의 결과에서 출발하므로 가장 늦게 끝나는 것이 정상이다.
- 에이전트가 많을수록 좋지 않다. 역할 정의와 맥락 관리가 복잡해지니 필요한 만큼만 만든다.
- 공감 일기와 PDF 요약 앱의 결과 화면은 생성형 AI 특성상 책과 다를 수 있다. 오류 메시지를 Claude Code에게 보내 하나씩 고친다.
- .env를 복사해 새 폴더에서 쓸 때, Git 저장소로 만들면 먼저 .gitignore에 .env를 추가한다.
