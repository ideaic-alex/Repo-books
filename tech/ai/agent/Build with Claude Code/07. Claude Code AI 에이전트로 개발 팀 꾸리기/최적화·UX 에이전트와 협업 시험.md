# 최적화 에이전트, UX 에이전트, 그리고 협업 시험

앞 문서의 코드 리뷰어는 읽기만 하고 고치지는 못한다. 이 문서는 코드를 실제로 수정하는 최적화 에이전트와 화면을 다듬는 UX 디자인 에이전트를 더 만들고, 세 에이전트를 한 프롬프트로 엮어 FridgeChef를 개선하는 협업을 시험한다. 직렬 처리와 병렬 처리의 차이, 작업 전 백업 요령도 함께 나온다.

공사 현장으로 보면 감리(검토), 시공(수정), 인테리어(화면)가 순서대로 또는 동시에 들어오는 것과 같다. 같은 벽을 두 사람이 동시에 칠하지 않도록 순서를 정하는 일이 협업의 핵심이다.

---

## 1. 최적화 에이전트: 고치는 담당

최적화(optimization)는 프로그램이 더 빠르고 효율적으로 돌도록 개선하는 일이다. 컴퓨터는 프로그램을 돌릴 때 시간, 메모리, 저장 공간 같은 자원을 쓴다. 최적화는 이 자원을 가장 알맞게 쓰는 방법을 찾는 것이다. 느린 코드를 빠르게 하고, 불필요한 연산을 줄여 CPU 사용을 낮추고, 데이터를 가져오는 시간을 줄이는 일이 예다.

코드 리뷰어는 검토만 맡았기에 코드를 고칠 수 없었다. 이번에는 FridgeChef의 주요 버그를 없애고 성능을 높이는 에이전트를 만든다. 만드는 방법은 같다. 에이전트를 프롬프트 하나로 설명하고, Claude Code가 쓴 파일을 승인하고, 에이전트를 쓰기 전에 파일의 프런트매터를 열어 확인한다. Study-04 폴더에서 Claude Code를 시작해 아래처럼 입력한다.

```text
Create a second subagent called performance-optimizer. It is a performance
engineer that speeds the app up and removes bottlenecks. Save it
as .claude/agents/performance-optimizer.md
```

리뷰어는 코드를 읽기만 하지만 이 에이전트는 코드를 바꾸고 실행해야 한다. 이번 프롬프트에는 권한을 적지 않았으므로 Claude Code가 일에 필요한 것을 판단해 파일 편집, 새 파일 작성, 명령 실행 도구를 준다. 초안을 확인하고 Yes를 고른다.

performance-optimizer.md를 열어 설정을 확인한다. tools 줄이 리뷰어보다 길다. 읽기용 Read, Grep, Glob에 더해 Edit, Write, Bash가 들어 있어 파일을 고치고 실행할 수 있다. 이것으로 최적화 에이전트가 준비되었다.

## 2. UX 디자인 에이전트: 화면 담당

UX 디자인(User Experience Design, 사용자 경험 설계)은 제품이나 서비스를 쓸 때 사용자가 겪는 모든 경험을 설계하는 일이다. 단순히 예쁘게 꾸미는 것이 아니라 사용자 관점에서 앱이 이해하기 쉽고 편리하도록 하는 중요한 과정이다. 예를 들어 앱을 열었을 때 필요한 기능을 쉽게 찾도록 메뉴를 눈에 띄는 위쪽에 두거나, 버튼을 눌렀을 때 분명한 반응을 주는 화면을 만드는 일이다.

만드는 과정은 같으므로 이번에는 빠르게 간다. Study-04 폴더에서 Claude Code를 시작해 UX 에이전트를 만든다.

```text
Create a third subagent called ux-design-advisor. It is a user experience
designer that reviews the layout and the interface and makes the app easier
to use. Save it as .claude/agents/ux-design-advisor.md
```

초안을 확인하고 Yes를 고르면 UX 디자인 서브에이전트 ux-design-advisor가 만들어진다.

## 3. 에이전트 협업 시험

세 에이전트를 따로 쓰는 것도 쓸모 있지만, 실제 개발 팀처럼 협업시키면 훨씬 좋은 결과가 나온다. 아래 프롬프트로 시험한다.

```text
Have code-bug-analyzer review the entire FridgeChef application code,
then have performance-optimizer fix the identified issues and optimize
performance, and finally have ux-design-advisor improve the user experience.
```

Claude Code는 세 서브에이전트를 줄 세운다. 각 단계가 앞 단계 결과를 필요로 하므로 차례대로 실행한다. 코드 리뷰어가 버그를 찾고, 최적화 에이전트가 고치고, UX 에이전트가 화면을 다듬는다. 책에 나온 대로, 에이전트가 일하는 동안 터미널 한 줄이 기다리는 에이전트 수를 알려 준다. 백그라운드 에이전트가 하나면 순서대로 진행되는 것이고, 셋이면 병렬로 진행되는 것이다.

### 직렬 처리와 병렬 처리

한 프롬프트에 에이전트 여러 개를 적으면 Claude Code가 실행 방식을 정한다. 각 에이전트가 할 일과 같은 파일을 건드릴 가능성을 따져 하나씩 차례로 돌리는 직렬 처리(serial processing)나 동시에 돌리는 병렬 처리(parallel processing)를 고른다.

| 방식 | 동작 | 장단점 |
|---|---|---|
| 직렬 | 앞 에이전트가 끝나야 다음이 시작한다 | 느리지만 안정적이다. 여러 단계를 거치는 파일을 두 에이전트가 동시에 고치지 않는다 |
| 병렬 | 에이전트들이 동시에 일한다 | 더 빠르다. 서로 다른 파일이나 독립된 부분을 다룰 때 이 방식을 쓴다 |

병렬은 여러 사람이 서로 다른 문서를 동시에 편집하는 것과 같다. Claude Code는 진행하면서 어느 길을 택했는지 알려 준다. 단계가 서로 의존하면 시작 전에 그렇게 말한다. 이번에는 버그 검토가 끝나야 최적화 에이전트가 그 결과로 일할 수 있기 때문에 직렬로 간다.

모든 서브에이전트가 일을 마치면 개선 요약이 터미널에 나온다. 각 서브에이전트가 무엇을 했고 어떤 파일이 바뀌었는지 볼 수 있다.

## 4. 개선된 앱 실행해 보기

```text
Run the improved app so I can check it in the browser
```

터미널에 나온 주소를 복사해 브라우저 주소창에 붙여 넣어 실행한다. 개선 내용을 보자.

1. 입구 화면이 하나의 행동 유도(call to action, 사용자가 눌러야 할 한 가지 버튼) 중심으로 다시 만들어졌다. 계정을 만들기 전에 먼저 둘러볼 수 있다.
2. Try it out (without logging in) 버튼을 누르면 메인 화면이 나온다. 사이드바 메뉴가 사라졌고, 세 단계가 한 페이지에 배치되어 진행 정도를 한눈에 볼 수 있다.
3. Browse files 버튼으로 fridge.jpg를 올리고 Start ingredient recognition 버튼으로 분석을 시작한다. fridge.jpg는 책의 GitHub 저장소 input-examples 폴더에서 받는다.
4. API로 재료가 올바르게 인식되었는지 확인한다.
5. 요리 종류, 난이도, 준비 시간, 인분 수를 정하고 Generate recipe를 누른다.
6. 추천 레시피 목록이 나오고 각 레시피의 준비 시간, 난이도, 칼로리가 표시된다.
7. 로그인하면 각 레시피 아래에 Save 버튼이 나타나 다시 해 먹고 싶은 레시피를 저장할 수 있다.

생성형 AI의 특성상 결과가 책과 다를 수 있다. 앱이 제대로 돌지 않으면 화면에 나온 경고나 오류 메시지를 Claude Code에게 보내 하나씩 해결한다. 자신만의 디자인이나 아이디어를 더해 봐도 좋다.

## 5. 더 알아보기: 작업 전 백업

여러 에이전트가 동시에 일하면 예기치 않은 충돌이나 중복 수정이 생길 수 있다. 이에 대비해 작업 전에 백업을 만들어 두는 것이 좋다. Claude Code에게 현재 상태를 백업하라고 요청한다.

```text
Back up the current state.
```

Claude Code가 프로젝트 폴더에 백업 디렉터리를 만들고 모든 파일을 복사한다. 예기치 않은 오류가 생기면 백업에서 복원하라고 하면 이전 상태로 돌아간다.

```text
Restore from backup.
```

## 6. 이 절의 핵심과 복습 문제

핵심 정리는 여섯 가지다.

- 에이전트는 목표와 규칙에 따라 사람의 직접 지시 없이 스스로 판단해 일하는 AI 프로그램이다.
- AI 서브에이전트는 특정 작업을 전문으로 하는 독립 AI 보조자이며 역할, 모델, 권한을 정할 수 있다.
- 서브에이전트는 .claude/agents 폴더의 마크다운 파일로 정의된다. Claude Code에게 써 달라고 하거나 직접 파일을 쓴다.
- 코드 리뷰는 코드의 버그와 규칙 위반을 점검하고 개선을 제안하는 품질 보증 과정이다.
- 최적화는 프로그램의 속도, 자원 사용, 효율을 높이는 과정이다.
- UX 디자인은 사용자가 쉽고 편하게 쓰도록 화면 배치와 인터페이스를 설계하는 과정이다.

**복습 문제**(정답은 09장)

1. 커스텀 명령과 에이전트의 올바른 기술적 차이를 고르시오. (1) 커스텀 명령은 .md로, 에이전트는 .json으로 저장된다 (2) 에이전트는 독립된 AI 모델을 고를 수 있지만 커스텀 명령은 메인 세션의 모델을 쓴다 (3) 커스텀 명령이 에이전트보다 복잡한 워크플로를 다룰 수 있다 (4) 에이전트는 변경을 반영하려면 재시작이 필요하지만 커스텀 명령은 바로 쓸 수 있다
2. 서브에이전트의 model 필드를 inherit로 하거나 파일에서 아예 뺐을 때의 올바른 동작을 고르시오. (1) 항상 가장 싼 모델을 자동 선택한다 (2) 메인 세션이 지금 쓰는 모델을 물려받는다 (3) 부모 에이전트가 쓴 모델을 복사한다 (4) 최신 Claude 모델로 자동 업그레이드한다
3. 에이전트에게 읽기 전용 권한을 주었을 때 할 수 없는 작업을 모두 고르시오. (1) 코드 파일 내용을 읽고 분석 (2) 버그 보고서 생성 (3) 발견한 버그 수정 (4) 새 테스트 파일 생성
