# AI 개발 팀 구성하기

스타트업이나 개인 프로젝트에서 가장 어려운 점은 모든 역할을 혼자 해야 한다는 것이다. 기획서를 쓰고, 서버를 세우고, 디자인하고, 테스트까지 해야 한다. 이 문서는 7장의 두 번째 절 앞부분으로, 실제 개발 팀의 구조를 본떠 기획, 개발, 디자인, 테스트, AI 연동을 맡는 서브에이전트 다섯 개를 만든다.

실제로 팀을 꾸리려면 사람을 뽑고 가르치고 관리하는 데 시간과 돈이 많이 든다. 서브에이전트를 쓰면 그 전문가들을 고용하지 않고도 AI들이 함께 프로젝트를 해 준다. 이 문서에서 만든 팀이 다음 문서의 두 앱 제작에 쓰인다.

---

## 1. 소프트웨어 개발 팀의 구성과 역할

소프트웨어 개발은 보통 여러 분야 전문가가 함께 일한다. 대표적인 역할은 다음과 같다.

- 제품 기획 담당(Product Manager, PM): PRD를 써서 제품의 목표, 기능, 사용자 요구를 정하고 전체 개발 일정을 관리한다.
- 백엔드 개발자: 서버를 만들고 데이터베이스를 설계하는 등 앱의 핵심 로직을 구현한다.
- 프런트엔드 개발자: 사용자가 만나는 화면과 인터페이스를 설계하고 만든다.
- 품질 보증 엔지니어(Quality Assurance, QA): 버그를 찾고 성능을 시험해 제품이 믿을 만하게 동작하게 한다.
- AI 통합 전문가: AI 모델을 개발하거나 기존 모델을 최적화해 프로젝트에 맞는 AI 솔루션을 구현한다.

책은 이 다섯 역할에 대응하는 AI 서브에이전트를 Claude Code에 만든다. 다만 모든 프로젝트에 다섯이 다 필요한 것은 아니다. 프로젝트 필요에 따라 필요한 에이전트만 골라 쓰면 된다.

## 2. 다섯 서브에이전트 한 번에 만들기

VibeCoding 폴더 안에 Study-05 폴더를 새로 만들고 그 위치에서 터미널을 열어 Claude Code를 실행한다. Claude Code가 처음 보는 폴더를 열면 믿을 만한지 묻는다. 이때 Yes, I trust this folder를 고른다. 그리고 다음 단계로 에이전트를 만든다.

1. 아래 프롬프트를 입력하고 엔터를 누른다. 이 프롬프트에는 다섯 에이전트의 이름과 역할, 모델, 저장 폴더가 모두 들어 있다. 원하는 에이전트를 모두 나열하고 .claude/agents/ 아래에 저장하라고 하면 Claude Code가 하나씩 쓴다.

```text
Create five subagents in the .claude/agents/ folder. product-manager-prd
writes the PRD and manages the schedule, backend-architect designs the
server and the APIs, frontend-developer builds the interface, qa-engineer
handles testing and code review, and ai-integration-specialist connects the
OpenRouter API. Set the model to sonnet for each of them.
```

2. Claude Code는 파일을 쓰기 전에 매번 묻는다. 그때마다 Yes를 고른다. 모두 다섯 번 묻고, 다섯 파일이 차례로 생긴다.
3. 다섯 개가 모두 쓰이면 Claude Code가 어떤 에이전트를 부르면 되고 각각 무엇을 위한 것인지 요약해 보여 준다. 읽어 보고 대화를 이어 간다.

생성된 다섯 서브에이전트의 역할과 모델을 책은 아래처럼 정리한다.

| 서브에이전트 | 기능과 역할 | 모델 |
|---|---|---|
| 백엔드 개발자 | 서버 구조 설계, API 개발, 데이터 처리, 외부 서비스 연동, 보안과 성능 최적화를 맡는 서버 쪽 전문가. 안정적이고 확장 가능한 백엔드를 만든다 | sonnet |
| 프런트엔드 개발자 | 사용자 인터페이스 설계와 구현, 반응형 디자인, 웹 접근성, 성능 최적화를 맡는 화면 쪽 전문가 | sonnet |
| 품질 보증 엔지니어 | 시스템 전체의 기능 시험, 오류 처리 확인, 성능 최적화, 코드 리뷰를 하는 품질 전문가. 버그를 찾고 사용성 개선을 제안한다 | sonnet |
| AI 통합 전문가 | LLM과 AI 서비스 연동, 프롬프트 최적화, AI 파이프라인 구축을 맡는 AI 전문가. 여기서는 OpenRouter API로 gpt-oss 모델을 연결해 텍스트 생성과 요약을 구현한다 | sonnet |
| 제품 기획 담당 | PRD 작성과 프로젝트 일정 관리를 맡는 제품 기획 전문가 | sonnet |

Study-05 폴더의 .claude/agents/ 를 열어 .md 파일 다섯 개가 있는지 확인한다. 파일 이름이 곧 에이전트 이름이다. 예를 들어 product-manager-prd.md를 열면 프롬프트에 쓴 이름과 역할이 name과 description 필드에 들어 있고, model 줄은 sonnet이다. 고칠 부분이 있으면 파일을 직접 고치거나 Claude Code에게 바꿔 달라고 하면 된다.

## 3. 에이전트는 많을수록 좋은가

서브에이전트는 여러 개 만들 수 있지만 많다고 늘 좋은 것은 아니다. 너무 많으면 역할 정의, 맥락 관리, 자원 배분 때문에 관리가 복잡해진다. 책의 팁은 필요한 만큼만 만들라는 것이다. 또 PM은 제품 기획을 맡은 사람을 가리키는 약어(Product Manager)라는 점을 풀이로 덧붙인다.

참고(노트 작성자): 7장 앞부분의 세 에이전트(리뷰어, 최적화, UX)는 파일 하나에 한 일을 맡기는 연습이었고, 여기서는 기획부터 시험까지 한 줄로 이어지는 팀을 만든다는 점이 다르다. 두 접근 모두 같은 .claude/agents/ 폴더의 마크다운 파일이다.
