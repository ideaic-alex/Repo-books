# 복습 문제와 정답

책의 부록은 1장부터 8장까지 각 절 끝에 있던 복습 문제의 정답을 한곳에 모았다. 이 문서는 그 정답을 장별로 다시 정리한 것이다. 문제 본문은 각 장 폴더의 문서 끝에 실려 있으니 먼저 스스로 풀고 여기서 확인하면 좋다. 시험 답안지를 채점하듯 맞춰 보되, 틀린 문제는 해당 장 문서로 돌아가 이유를 다시 읽는 것이 이 부록의 쓰임새다.

원서의 정답 쪽은 목록 번호가 쪽 경계에서 깨져 있고, 일부 문장은 문제 보기 없이 정답만 적혀 있다. 그래서 장 앞부분(1장과 2장)과 일부 문장은 문제 번호와 정확히 대응하지 않을 수 있고, 그 경우 아래에 그렇게 밝혔다. 3장은 문제와 정답을 순서대로 맞춰 확인했다. 명령 이름과 화면 문구는 책이 쓰인 시점 기준이다.

도구 이름 채우기 표의 정답은 아래와 같다.

| 구분 | 설명 | 대표 도구 |
|---|---|---|
| 웹 기반 챗봇 | 설치 없이 웹에서 바로 쓴다. 복사해서 붙여 넣어야 한다 | Claude, ChatGPT, Gemini |
| 모델 선택형 | 여러 언어 모델 중 고를 수 있다. 추가 비용이 들 수 있다 | Cursor, Antigravity |

알맞은 개념 채우기의 정답은 순서대로 바이브 코딩, AI 어시스턴트, 모델 선택형 도구, 전용 모델 기반 도구다. 참고(노트 작성자): 원서에서 번호가 쪽 경계에 걸려 있어 순서대로 읽은 것이다.

### 나의 첫 웹페이지 만들기

- 인공지능 발전 순서는 신경망, 딥러닝, 트랜스포머, LLM이다.
- 도구 사용료와 AI 모델 비용을 모두 내야 한다는 설명이 정답이다.

## 2. 2장 효과적인 프롬프트로 AI의 잠재력 끌어내기

### AI를 깨우는 프롬프트의 비밀

- 창의성: 결과물이 놀라워야 한다는 요구다.
- 5W1H 가운데 채울 항목은 What과 How다.
- 가장 좋은 프롬프트로 고른 문장은 "오늘의 날짜와 시간, 검색창이 들어간 나만의 홈페이지를 만들고 싶다"는 뜻의 영어 문장이다. 이유는 필요한 기능(날짜, 검색)을 구체적으로 적어서 AI가 무엇을 해야 하는지 분명히 이해하기 때문이다.

### 실전: 마케팅 포트폴리오 완성하기

- 단계 순서는 기본 틀 잡기, 핵심 기능 구현, 디자인 적용, 완성도 점검이다.
- 정답으로 적힌 두 문장은 "시간을 아끼려고 모든 기능을 한꺼번에 요청한다"와 "디자인은 자동으로 개선된다"이다. 4단계 전략과 어긋나는 설명이라 틀린 설명 고르기 유형으로 보이나, 원서에는 정정 문장이 없다. 확실한 유형은 2장 문서의 복습 문제에서 확인한다.

## 4. 4장 Claude Code 실전 활용

### AI를 깨우는 프롬프트의 비밀

- 명령 채우기(표 A.2): 프로젝트 구조를 분석해 CLAUDE.md를 만드는 명령은 /init, 현재 세션의 토큰 사용량과 남은 컨텍스트를 확인하는 명령은 /status, 쓸 AI 모델을 고르거나 기본값으로 되돌리는 명령은 /model, 사용 가능한 명령 목록과 설명을 보는 명령은 /help다. 설명과 명령은 책에 적힌 대로 옮겼다.
- 설명에 맞는 용어: CLAUDE.md, 제품 요구사항 문서(PRD), JSON 순서로 정답이다.

### 작업 재개와 효율 높이기

- Ctrl+R이 /context 명령의 단축키라는 문장이 정답 칸에 적혀 있다. 정정 문장이 없어서 틀린 설명 고르기 유형인지 불분명하다.
- 상황별 명령(표 A.3)은 아래와 같다.

| 상황 | 명령 또는 옵션 |
|---|---|
| 여러 대화 중 하나를 골라 이어 가기 | claude --resume 또는 /resume |
| 가장 최근 대화를 바로 이어 가기 | claude --continue 또는 claude -c |
| 현재 컨텍스트 사용량을 눈으로 확인 | /context |
| 대화가 길어 압축이 필요할 때 | /compact |
| 파일 수정 승인이 번거로울 때 | Shift + Tab |

### 프로젝트 개선과 작업 관리

- "/config는 Claude Code의 전역 설정만 바꿀 수 있다"는 문장이 정답 칸에 적혀 있다. 이 역시 정정 문장이 없다.
- 표 A.4: web_version 폴더 구조를 보려면 @web_version, script.js의 특정 함수를 찾으려면 @script.js, Claude Code 설치 상태를 확인하려면 /doctor를 쓴다. 대화 기록을 파일로 저장하려면 /export를 입력하고 Save to file을 고른다. 다크 모드로 바꾸려면 /config에서 테마를 바꾼다. 자동 압축을 끄려면 /config에서 Auto-compact를 false로 둔다.

- 퀴즈 게임의 검증 지침을 저장하고 싶을 때는 /memory를 선택한 뒤 Project memory를 고른다.
- 이전 대화가 새 작업에 영향을 줄 것 같을 때는 /clear를 실행한다.

- "세계에서 가장 긴 강"처럼 애매한 질문을 만나면 기준이나 시점을 밝히는 지침을 덧붙인다.

### 자동화로 개발 효율 높이기

- 커스텀 명령은 파이썬 파일로 저장된다는 문장은 틀렸다. 마크다운(.md) 형식으로 저장한다.
- 프로젝트 전용 커스텀 명령은 .claude/commands 폴더에 저장한다.
- 숫자 범위의 문제만 복습하려면 `$1`, `$2` 같은 자리표시자를 쓴다.
- 사용자 입력을 받으려면 `$ARGUMENTS` 같은 매개변수를 쓴다.
- 홈 디렉터리의 .claude/commands에 만든 명령은 모든 프로젝트에서 쓸 수 있다. 프로젝트의 .claude/commands에 만든 명령은 현재 프로젝트에서만 쓴다.

### 커스텀 명령으로 배운 유지 보수 전략

- 커스텀 명령을 파이썬 스크립트로 써야 한다는 문장은 틀렸다. 파일 형식은 md다.
- 커스텀 명령은 .md 파일로 저장하고, .claude/commands 폴더에 두고, 만든 명령 목록은 /help로 확인한다.

## 6. 6장 API로 Claude Code에 날개 달기

### Claude Code에서 API 설정하기

- Claude Code에서 API를 쓰려면 API 키와 모델 이름이 필요하다.
- API 키를 코드에 직접 박아 넣는 것은 피해야 할 방법이다(원서는 이 문장을 정답 칸에 적었으며 문제 유형은 6장 문서에서 확인).
- 호출되는 코드 내용을 묻는 항목이 있으나 원서 정답 문장이 짧고 불분명해 "Code content called"로만 적혀 있다.

### FridgeChef: Claude Code와 API로 만들기

- 하나의 API 키로 여러 회사의 AI 모델을 쓸 수 있다는 설명이 정답이다.
- 점검할 것은 .gitignore 파일의 존재 여부다.
- 올바른 보관법은 API 키를 .env 파일에 두고 그 파일을 .gitignore에 넣어 GitHub 업로드에서 제외하는 것이다.

## 7. 7장 Claude Code AI 에이전트로 개발 팀 꾸리기

### AI 에이전트 이해하기

- 에이전트는 독립적으로 AI 모델을 고를 수 있지만 커스텀 명령은 메인 세션의 모델을 공유한다.
- 모델을 따로 지정하지 않으면 메인 세션에서 지금 쓰는 모델을 물려받는다.
- 읽기 전용 에이전트로는 "발견한 버그 수정"과 "새 테스트 파일 만들기"를 할 수 없다. 읽기 전용은 코드, 설정, 파일 내용을 읽고 디렉터리 구조를 보는 권한만 준다. 버그를 고치려면 .py나 .js 같은 소스 파일을 수정해야 하고, 새 테스트 파일은 기존 디렉터리에 저장해야 하므로 쓰기 권한이 더 필요하다.

### AI 에이전트로 소프트웨어 개발 자동화하기

- QA 에이전트가 이전 에이전트들의 작업 결과를 모두 검토해야 하기 때문이라는 설명이 정답이다. 마지막에 실행하는 이유로 읽힌다.
- "PRD가 .claude/agents/ 폴더로 자동 복사되어 공유된다"는 문장도 정답 칸에 있으며 정정은 없다.

## 8. 8장 MCP, 스킬, 플러그인으로 Claude Code 확장하기

### MCP 이해하고 Claude Code에 연결하기

- API는 특정 기능을 요청하는 방법이고, MCP는 AI가 외부 시스템과 직접 소통하게 해 주는 프로토콜이다.
- 구분 기호는 Claude Code의 옵션과 MCP 서버 실행 명령을 나누는 역할을 한다.
- Sequential Thinking MCP는 문제를 순서대로 쪼개 체계적으로 분석한다. 목표, 구현 방법, 로드맵, 지표, 위험 완화 전략을 자세히 제시해 일반 추론보다 구조적이고 포괄적인 결과를 낸다.
- 플러그인과 스킬로 구현한 완전 자동화 개발 환경이라는 설명이 정답으로 적혀 있다.
- Playwright MCP가 만드는 폴더는 .playwright-mcp다.
- Git에 변경을 올리는 순서는 add, commit, push다.
- MCP 서버 주소를 찾는 방법은 두 가지다. MCP 이름을 구글에서 검색해 GitHub 저장소로 가서 서버 주소를 찾는 방법, 그리고 MCP 서버를 모아 둔 GitHub 저장소나 웹사이트에서 카테고리별로 둘러보는 방법이다.

### 데이터베이스를 연결해 진짜 서비스 만들기

- 데이터베이스는 여러 기기에서 데이터를 공유하게 해 준다.
- 오류 원인은 index.html 파일이 없는 것이고, 파일 이름을 바꿔야 한다.
- 데이터베이스 테이블과 엑셀의 비교로, 공통점은 행과 열로 이뤄진 표 형태로 데이터를 저장한다는 것이다. 차이점은 테이블은 여러 사용자가 동시에 접근하고, 실시간으로 동기화되고, 프로그램과 연동해 자동 처리할 수 있다는 것이다.
