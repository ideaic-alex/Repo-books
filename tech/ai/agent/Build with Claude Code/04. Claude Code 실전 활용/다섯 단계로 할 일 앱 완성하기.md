# 다섯 단계로 할 일 앱 완성하기

이 문서는 웹에서 만든 다섯 개의 단계별 프롬프트를 Claude Code에 차례로 붙여 넣어 할 일 관리 앱을 완성하는 실습을 다룬다. 마지막에는 프로젝트를 시작할 때 알아 두면 좋은 /status, /model, /help 명령을 정리한다.

집 짓기와 같다. 1단계에서 뼈대를 세우고, 2단계에서 방을 나누고, 3단계에서 계기판을 달고, 4단계에서 조명과 단축 스위치를 넣고, 5단계에서 마감과 점검을 한다. 매 단계가 끝날 때마다 브라우저에서 직접 열어 보며 확인하는 것이 핵심이다.

---

## 1. 실행 방식

Claude Code가 켜진 터미널에 각 단계 프롬프트를 Ctrl + V로 붙여 넣고 Enter를 누른다. 여러 줄을 직접 칠 때는 줄 끝에 \ 를 쓰고 Enter를 누르거나 Ctrl + J로 줄바꿈을 넣는다.

작업 중 권한 확인 창이 뜨면 1번 Yes를 고른다. 매번 누르기 번거로우면 2번 Yes, and don't ask again을 골라도 된다. 작업이 끝나면 완료 메시지가 나오고, 그러면 Study-02 폴더의 index.html을 탐색기에서 더블클릭해 기본 브라우저로 연다. 책과 다른 결과가 나와도 Claude Code가 안내하는 대로 확인하면 된다.

## 2. Step 1: 기본 구조와 핵심 기능

첫 프롬프트는 앱의 뼈대를 만든다. 핵심 요구사항을 줄이면 아래와 같다.

```text
Step 1: Implement basic structure and core functions
1. Consist of three files: index.html, style.css, script.js
2. HTML: title "My Tasks", input field + add button, list container
3. JavaScript: add (Enter key and button), delete (X button),
   toggle complete with checkbox, change style when completed
4. Store data in localStorage (auto-save, keep after refresh)
5. CSS: card-style layout, centered, max width 600px, hover effects
Store each to-do as { id, text, completed, createdAt }.
```

결과는 파일 세 개가 만들어지고 My Tasks라는 제목의 앱이 열리는 것이다. 입력창에 "Finish Chapter 4 of Vibe Coding"을 쓰고 추가 버튼을 누르면 목록에 들어간다. 체크박스로 완료 표시를 하고 X 버튼으로 지우는 동작도 확인한다. 새로고침해도 목록이 남는 것은 localStorage(브라우저에 데이터를 저장하는 기능) 덕분이다.

## 3. Step 2: 카테고리와 UI 개선

두 번째 프롬프트는 기존 코드에 카테고리를 더한다. 업무, 개인, 공부 세 가지이며 할 일을 추가할 때 드롭다운으로 고른다. 각 항목에는 색 태그가 붙고, 전체/업무/개인/공부 필터 버튼이 생긴다. 색은 업무가 파랑(#4A90E2), 개인이 초록(#27AE60), 공부가 보라(#8E44AD)다.

UI 쪽에서는 선택된 버튼에 테두리를 주고 배경을 강조하며, 항목에 "2시간 전" 같은 생성 시각을 보여 준다. 데이터 구조에는 category 필드를 더하고 필터 상태도 localStorage에 저장한다. 완료된 항목은 자동으로 목록 아래로 내려간다.

브라우저를 새로고침하면 카테고리가 한눈에 보인다. 카테고리별로 할 일을 넣어 보고 제대로 분류되어 기록되는지 확인한다.

## 4. Step 3: 진행률 대시보드와 인라인 편집

세 번째 프롬프트는 앱 위쪽에 통계 영역을 만든다. 전체 진행률을 "5/10 completed (50%)" 형식과 진행 막대로 보여 주고, 카테고리별로 완료와 전체 개수를 작은 막대로 보여 준다. 오늘 추가한 할 일 수도 나온다. 대시보드는 실시간으로 갱신되어야 한다는 조건이 붙는다.

인라인 편집(그 자리에서 바로 고치는 편집)도 들어간다. 항목을 더블클릭하면 입력창으로 바뀌고, Enter로 저장하고 ESC로 취소한다. 편집 중에는 카테고리도 바꿀 수 있다. 여기에 진행 막대의 부드러운 전환, 추가와 삭제 때의 페이드, 완료 체크 때의 슬라이드 같은 애니메이션이 더해진다.

더블클릭 편집이 잘 되는지 직접 시험해 본다.

## 5. Step 4: 다크 모드와 고급 기능

네 번째 프롬프트는 네 묶음의 기능을 넣는다.

- 다크 모드: 오른쪽 위에 다크/라이트 전환 스위치가 생긴다. 배경 #1A1A1A, 카드 #2D2D2D, 글자 #E0E0E0을 쓰고, 선택한 테마는 localStorage에 저장하며 전환 때 애니메이션이 있다.
- 추가 기능: 완료 항목 일괄 삭제 버튼(확인 대화상자 포함), 실시간 검색, 완료 후 삭제 버튼 표시, "할 일이 없습니다" 같은 빈 상태 메시지가 들어간다.
- 키보드 단축키: Alt+N은 새 할 일 입력창, Alt+1부터 4까지는 카테고리 필터, Alt+D는 다크 모드 전환이다.
- 반응형 디자인: 모바일(최대 너비 480px)에 맞추고 터치하기 쉬운 큰 버튼을 쓴다.

실행 후에는 다크 모드 버튼을 눌러 화면이 바뀌는지 보고, 완료된 항목에 체크한 뒤 일괄 삭제 버튼을 눌러 체크된 할 일이 모두 지워지는지 확인한다.

## 6. Step 5: 최종 완성과 최적화

마지막 프롬프트는 앱을 완성도 있게 다듬는다. 내용은 다섯 갈래다.

- 내보내기와 가져오기: 데이터를 JSON 파일로 내보내고 파일 업로드로 가져온다. 가져오기 전에 현재 데이터를 백업해 둔다.
- 정렬: 생성일, 카테고리, 완료 상태별로 정렬하고 상태를 저장한다. 드래그 앤 드롭으로 순서를 직접 바꿀 수도 있다.
- 성능: 항목이 100개가 넘어도 부드럽게 돌도록 디바운싱(입력이 멈춘 뒤에 한 번만 처리하는 기법)과 효율적인 DOM 조작을 쓴다.
- 접근성: ARIA 레이블, 포커스 관리, 스크린 리더 지원을 더한다.
- 기타: 중복 할 일 경고, 최근 삭제 되돌리기, 오늘의 명언, 완료율에 따른 격려 메시지가 있다.

프롬프트는 모든 예외 상황과 오류 처리, 상세한 코드 주석도 요구한다. 완료 후 브라우저에서 정렬 옵션이 생기고 오늘의 명언이 뜨는지 본다.

내보내기를 누르면 JSON 파일이 다운로드 경로에 저장된다. 메모장으로 열면 앱에 저장한 할 일 목록이 들어 있다. 앱에서 가져오기 버튼으로 이 파일을 불러오면 모든 항목이 복원된다. 백업과 이전이 가능해진 것이다.

## 7. 알아 두면 좋은 초기 설정 명령

4장의 첫 절은 /init 외에 프로젝트를 시작할 때 쓰는 명령 세 가지를 따로 소개한다.

| 명령 | 하는 일 |
|---|---|
| /status | 현재 세션 상태를 본다. 사용 중인 모델, 토큰 사용량, 남은 컨텍스트 용량이 나온다. 긴 작업에서는 주기적으로 확인하면 좋다 |
| /model | 현재 모델을 확인하고 고른다. 책이 쓰인 시점 기준으로 Max 요금제에서는 Sonnet과 Opus 중 복잡한 작업에 맞게 고를 수 있다 |
| /help | 사용 가능한 모든 명령과 설명을 보여 준다. 새 기능이 필요하거나 명령이 기억나지 않을 때 쓴다 |

이 절의 핵심을 다섯 개 키워드로 줄이면 이렇다. 단계별 프롬프트 전략은 PRD를 여러 단계로 나눠 단계마다 AI에게 구체적인 목표를 주는 방식이어서 체계적이고 예측 가능한 결과를 낸다. /init은 프로젝트 초기화와 CLAUDE.md 생성이고, /status는 현재 작업 상태 확인, /model은 AI 모델 선택과 변경, /help는 명령 목록 보기다.
