# 컨텍스트 관리

Claude Code에서 **컨텍스트 윈도우(Context Window)**는 에이전트의 CPU, RAM, 저장장치 역할을 모두 담당하는 가장 결정적인 제한 자원입니다. 대화가 길어지고 읽어들인 파일과 도구 실행 결과가 쌓여 버퍼가 가득 차면, 에이전트는 지침을 잊거나 이미 해결한 문제를 다시 푸는 등 성능이 급격히 저하됩니다.

따라서 프롬프트 작성 기술을 넘어 제한된 메모리 예산을 정밀하게 제어하는 **컨텍스트 엔지니어링(Context Engineering)** 관점에서, 슬래시 명령어인 `/context`, `/compact`, **`/rewind`**는 맥락 오염을 방지하고 실행 효율을 극대화하는 **실시간 수술적 진단·제어 도구**로 기능합니다.

---

## 1. `/context`: 컨텍스트 예산의 정밀 진단 (Diagnostic Tool)

- **시각적 예산 측정**: `/context` 명령어를 실행하면 현재 맥락 사용량이 **색상 그리드(colored grid)**로 시각화됩니다.
- **구성 요소별 점유율 분석**: 시스템 프롬프트, `CLAUDE.md` 파일, MCP 도구 정의, 대화 기록, 활성 작업 공간이 각각 컨텍스트 윈도우의 몇 %를 점유하고 있는지 명확하게 보여줍니다.
- **컨텍스트 엔지니어링상의 역할**: 에이전트의 답변 품질이 떨어질 때 원인을 파악하는 1차 진단 도구입니다. 예를 들어 질문을 시작하기도 전에 MCP 서버의 스키마가 맥락의 30%를 점유하고 있음을 확인하면, 불필요한 MCP 서버를 해제하거나 지연 로딩(Deferred Tool Search) 설정을 점검하여 상시 비용을 즉시 줄일 수 있습니다.

---

## 2. `/compact`: 선제적·의도적 맥락 축소 (Proactive Compaction)

- **초점 지침(Focus Instructions) 주입**: 수동으로 축소를 실행할 때 `/compact Focus on the API changes`와 같이 보존해야 할 핵심 주제를 직접 지정할 수 있습니다.
- **자동 축소(Auto-Compaction)의 한계 극복**: 컨텍스트 용량이 약 95%에 도달하면 시스템이 자동으로 대화 이력을 요약·축소하지만, 이는 중요한 세부사항을 손실할 위험이 있는 가비지 컬렉션 방식입니다.
- **컨텍스트 엔지니어링상의 역할**: 맥락이 한계에 다다르기 전(약 80% 시점)에 선제적으로 수동 요약을 실행함으로써, 요약 프로세스에 더 넓은 연산 유연성을 제공하고 손실되면 안 되는 핵심 맥락을 사용자가 직접 통제할 수 있습니다.

---

## 3. `/rewind`: 수술적 맥락 복원 및 부분 요약 (Surgical Cleanup)

- `Esc` 두 번 누르기 또는 `/rewind`: 단축키나 명령어로 체크포인트 메뉴를 호출하여 이전 프롬프트 시점으로 정밀하게 이동합니다.
- **4가지 복원 및 요약 모드**:
  1. **Restore code and conversation**: 선택한 시점으로 코드와 대화 이력을 모두 되돌립니다.
  2. **Restore conversation only**: 코드는 현재 구현 상태를 유지한 채, 대화 맥락만 이전으로 되돌립니다.
  3. **Restore code only**: 대화 맥락은 유지하고 코드 파일만 이전 체크포인트 상태로 복구합니다.
  4. **Summarize from here (수술적 요약)**: 선택한 체크포인트 이전의 성공적인 대화는 100% 원본으로 유지하고, 그 이후 발생한 시행착오나 막다른 길(dead end) 탐색 이력만 선택적으로 축소·요약합니다.
- **컨텍스트 엔지니어링상의 역할**: 대화 전체를 일괄 요약하는 대신, 비효율적인 탐색 과정만 수술적으로 잘라내어 유효 신호 대 잡음 비율(Signal-to-Noise Ratio)을 극대화합니다.

---

## 4. 컨텍스트 엔지니어링 체계에서의 종합적 위상

Claude Code의 맥락 관리 체계는 **설계(Design)**와 **운용(Runtime Control)**의 결합입니다:

- **`CLAUDE.md`**가 상시 유지되어야 하는 프로젝트의 신경망 지침을 담당하고,
- `Skills` 및 **`Subagents`**가 특정 작업 맥락을 독립된 버퍼로 격리하여 메인 맥락 오염을 막아준다면,
- **`/context`, `/compact`, `/rewind`**는 실제 세션 진행 중 발생하는 맥락 오염을 정밀하게 진단하고, 선제적으로 정리하며, 필요시 과거의 성공적인 시점으로 맥락을 복원하는 **실시간 관제 레이어**로 작동합니다.

---

💡 세션이 자동 축소(Auto-compaction)되더라도 절대 잊어버리면 안 되는 규칙을 지정하는 `CLAUDE.md` 내 `Compact Instructions` **헤더 작성법**에 대해서도 함께 알아보시겠어요?
