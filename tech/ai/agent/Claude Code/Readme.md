# Claude Code

출처에서 설명하는 **Claude Code(클로드 코드)**의 본질과 핵심 구조는 다음과 같이 종합할 수 있습니다.

---

## 1. 에이전틱 루프(Agentic Loop) 기반 패러다임

- **자율 순환 구조**: Claude Code는 단순히 질문에 답을 출력하는 일회성 챗봇(Request-Response)이 아니라, 맥락 읽기 → 계획 수립 → 행동 실행 → 결과 검증 과정을 끊임없이 순환하는 **에이전틱 루프(Loop)** 시스템입니다.
- **동료 방식의 브리핑**: 불과 350여 줄의 코드로 핵심 루프를 구현할 수 있을 만큼 직관적인 아키텍처를 가졌으나, 개발자의 코드베이스, 터미널, 테스트 수트 전체에 접근할 수 있는 자율적 동료처럼 동작합니다.

---

## 2. 컨텍스트 윈도우(Context Window) 중심의 자원 관리

- **최우선 제약 자원**: 컨텍스트 윈도우는 에이전트의 CPU, RAM, 저장장치 역할을 겸하는 유일하고 결정적인 희소 자원이며, 버퍼가 가득 차면 지침을 잊거나 성능이 급격히 저하됩니다.
- **컨텍스트 엔지니어링**: 상시 로드 지침인 `CLAUDE.md`, 필요할 때만 불러오는 **스킬(Skills)**, 맥락을 분리하는 **서브에이전트(Subagents)**, 실행 비용이 없는 **훅(Hooks)** 등을 통해 한정된 메모리 예산을 정밀하게 배분합니다.

---

## 3. 구조화된 4단계 워크플로우 (Explore - Plan - Implement - Commit)

- **단계별 실행 체계**: 안전한 탐색(Explore) → 계획 수립(Plan) → 실제 구현(Implement) → 커밋(Commit)의 4단계를 거칩니다.
- **저렴한 작업의 전면 배치**: 읽기 전용인 **Plan mode**에서 탐색과 계획을 먼저 수행하여, 비용이 비싼 구현 및 디버깅 단계에서의 오답과 맥락 낭비를 사전 차단합니다.

---

## 4. 반복적 생각 파트너(Thought Partner)와 80% 위임 협업

- **'80% 위임' 패러다임**: 개발자가 완전히 위임하여 손을 뗄 수 있는 작업 비율은 0~20% 수준에 불과하며, 에이전트가 80%를 자율 구현하면 나머지 20%의 도메인 판단과 미세 조정을 인간이 마무리하는 방식이 가장 효과적입니다.
- **생각 파트너(Thought Partner)**: 완벽한 단발성 답을 요구하는 '자판기'가 아니라 제약조건을 조율하고 피드백을 주며 정제해 나가는 대화형 생각 파트너로 활용됩니다.

---

## 5. 다중 에이전트, 도구 연동 및 생태계 (Multi-Agent, MCP, CI/CD, Surfaces)

- **맥락 격리형 다중 에이전트**: 서브에이전트(Subagents) 및 에이전트 팀(Agent Teams)을 활용하여 메인 세션의 맥락 오염 없이 대규모 작업을 병렬 또는 단계별로 분산 처리합니다.
- **외부 연동 및 자동화**: 외부 DB/API와 안전하게 연결되는 **MCP(Model Context Protocol)** 및 CI/CD 파이프라인에서 무두(Headless) 상태로 실행되는 `-p` 플래그 시스템을 제공합니다.
- **표면 독립적 엔진**: 동일한 Claude Code 엔진과 지침 설정이 터미널, IDE 확장, 데스크톱 앱, 웹, 모바일 등 다양한 인터페이스에서 동일하게 구동됩니다.
