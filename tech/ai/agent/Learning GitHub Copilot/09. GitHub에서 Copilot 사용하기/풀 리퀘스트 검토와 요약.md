# 풀 리퀘스트 검토와 요약

풀 리퀘스트(PR)는 여러 저장소 사이, 또는 같은 저장소의 브랜치 사이에서 병합을 관리하는 오래되고 검증된 방법이다. 변경을 모아 함께 검토하는 협업 수단이면서, 코드 리뷰와 GitHub Actions 워크플로 실행 같은 관문을 두어 병합 대상 브랜치를 나쁜 코드로부터 지켜 준다.

문제는 PR이 진행되는 동안 쌓이는 변경과 대화를 파악하고 이해하는 일이 만만치 않다는 점이다. Copilot은 이 부분을 도와준다. 이 문서는 앞 문서에서 만든 보안 수정 PR을 이어 가면서, Copilot을 리뷰어로 추가하는 방법과 PR 내용을 요약시키는 방법을 정리한다.

---

## 1. 상황: 수정 브랜치를 main에 합치기

앞 문서에서 Autofix로 만든 수정은 다른 브랜치에 있고, 초안 PR로 열려 있다. 이제 이 수정을 운영 브랜치(예시에서는 main)에 병합하려고 한다.

준비가 되면 "Ready for review" 버튼을 눌러 초안 PR을 검토 대기 상태로 바꾼다. 그다음부터는 평소처럼 리뷰어 추가 같은 일반 PR 절차를 밟는다.

## 2. Copilot을 리뷰어로 추가하기

Copilot은 자동 리뷰어가 되어 변경에 대한 피드백을 줄 수 있다.

1. PR의 Reviewers 영역에서 사용자 선택 부분을 클릭한다.
2. 목록에 리뷰어 후보로 Copilot이 나타나면 선택한다.
3. Copilot이 코드를 검토할 시간을 갖는다.
4. 검토가 끝나면 결과가 PR에 게시된다.

책의 예에서 Copilot은 남길 피드백이 없다고 답했다. 이 PR의 수정안을 처음에 만든 것도 Copilot이어서 납득할 만한 결과라고 책은 설명한다.

| 항목 | 내용 |
|---|---|
| 추가하는 곳 | PR의 Reviewers 영역 |
| 하는 일 | 변경을 자동으로 검토하고 PR 본문에 피드백과 제안을 남긴다 |
| 사람 리뷰어와 비교 | 사람 리뷰어가 하듯이 피드백과 제안을 게시한다 |
| 예시 결과 | 지적 사항 없음 |

이 표는 Copilot 리뷰를 팀원 한 명을 리뷰어로 지정하는 것과 같은 방식으로 쓸 수 있음을 보여 준다.

## 3. 병합 전 마지막 확인: PR 요약 요청

병합할 준비가 됐지만, 마지막으로 확인하고 싶거나 다른 사람에게 이 PR을 설명해야 한다면 Copilot에게 PR 요약을 시킬 수 있다.

PR 화면에는 Copilot 채팅을 여는 방법이 여러 가지 있다. 페이지 위쪽의 버튼과 보통 오른쪽 아래에 떠 있는 버튼이다. 어느 쪽이든 채팅 세션이 열리고, 열린 뒤 "Summarize this pull request" 같은 프롬프트를 보내면 된다.

Copilot은 PR 내용을 짧고 읽기 쉬운 요약으로 보여 준다. 변경과 대화를 일일이 따라가는 수고를 줄여 준다.

## 4. 앞으로의 흐름 정리

| 순서 | 하는 일 | 사용하는 것 |
|---|---|---|
| 1 | 초안 PR을 검토 가능 상태로 전환 | Ready for review 버튼 |
| 2 | Copilot을 리뷰어로 추가 | Reviewers 영역 |
| 3 | Copilot의 리뷰 결과 확인 | PR 본문에 게시된 피드백 |
| 4 | PR 내용 요약 요청 | 채팅 버튼과 "Summarize this pull request" |
| 5 | 병합 | 일반 PR 절차 |

Copilot의 리뷰 결과가 비어 있어도 사람이 꼭 필요한 검토가 사라지는 것은 아니다. 책도 일반적인 PR 절차(리뷰어 추가 등)를 그대로 거치는 흐름으로 설명한다. 다음 문서에서는 PR을 만드는 단계 자체를 Copilot으로 줄이는 방법을 본다.
