# 마켓플레이스에서 확장 설치하기

직접 만들기 전에 이미 공개된 확장을 설치해서 써 보는 것이 좋다. 이 문서는 GitHub Marketplace에서 PerplexityAI 확장을 설치하고 처음 호출하기까지의 과정을 따라간다. PerplexityAI 확장은 실시간 웹 검색으로 답을 모아 주는 확장이다. 원서의 화면 캡처는 쓰지 않고, 각 화면에서 하는 일을 글과 표로 풀어 쓴다.

---

## 1. 설치 흐름 한눈에 보기

| 단계 | 어디서 | 하는 일 |
| --- | --- | --- |
| 1 | GitHub Marketplace | 왼쪽 열에서 Copilot을 선택해 Copilot 확장 목록을 연다 |
| 2 | 확장 상세 페이지 | 확장이 무엇이고 무슨 일을 하는지 읽는다 |
| 3 | 확장 설치 구역 | 오른쪽 위의 Add 버튼을 누르거나 페이지 아래로 내려가 설치한다 |
| 4 | 소유자 선택(필요한 경우) | 확장을 쓸 사용자 또는 조직을 고른다 |
| 5 | GitHub 인증 | 확장에 딸린 GitHub App을 내 계정에 승인한다 |
| 6 | 앱 설정 페이지 | 권한과 접근할 저장소를 확인한다 |
| 7 | 재시작 | Copilot이 켜진 앱을 다시 시작한다 |
| 8 | 채팅 | @와 확장 이름을 입력해 호출하고, 첫 사용 때 한 번 더 승인한다 |

이 흐름에서 핵심은 "설치"와 "승인"이 별개라는 점이다. 마켓플레이스에서 설치하는 것만으로 끝나지 않고, GitHub App 승인과 작업 공간 승인이 따로 있다.

---

## 2. 마켓플레이스에서 확장 찾기

GitHub Marketplace에 들어가 왼쪽 열에서 Copilot을 고르면 Copilot 확장의 메인 화면이 나온다(그림 10-1). 여기서 PerplexityAI 확장을 골라 링크를 누르면 상세 페이지가 열린다. 이 페이지에는 확장이 무엇인지, 무엇을 할 수 있는지가 적혀 있다(그림 10-2).

오른쪽 위의 Add 버튼을 누르거나 스크롤을 내려 맨 아래로 가면 설치 구역이 나온다(그림 10-3). 이 확장은 무료다.

---

## 3. 소유자 선택이 필요한 경우

확장에 따라서는 그 확장을 쓸 수 있도록 승인할 사용자나 조직을 고르라고 한다. 원서는 Docker 확장을 설치할 때 이 화면이 나오는 예를 보여 준다(그림 10-4). 반면 PerplexityAI 확장은 일반 검색 기능이라서 설치한 사용자와 연결된 모든 저장소에서 쓸 수 있고, 따로 고를 것이 없다.

---

## 4. GitHub App이 하는 역할

대부분의 Copilot 확장은 GitHub App을 통해 저장소와 계정에 접근한다. GitHub App은 내 GitHub 계정에 설치되고 승인된, 저장소와 함께 일하는 백엔드 애플리케이션이다. 앱을 쓰는 확장에서는 앱이 채팅 창과 확장 기능을 구현한 코드 사이의 다리 역할을 한다. 다시 말해 Copilot과 확장 동작 사이의 접근과 통제 계층이다.

첫 설치를 마치면 앱과의 연결이 눈에 보인다. 먼저 GitHub에 로그인해서 이 앱을 계정에 승인하라는 요청이 뜨고, 승인하면 설치된 앱의 설정 페이지로 이동한다(그림 10-5).

| 설정 페이지에서 할 수 있는 일 | 설명 |
| --- | --- |
| 권한 선택 | 앱에 줄 구체적인 권한을 고른다 |
| 저장소 선택 | 앱이 접근할 저장소를 고른다 |
| 일시 중지 | 앱을 잠시 멈춘다 |
| 제거 | 앱을 삭제한다 |

PerplexityAI 앱은 모든 저장소에 적용되고 특별히 요구하는 권한이 없어서 그대로 두면 된다.

나중에 설정을 바꾸려면, 로그인한 상태에서 계정 설정의 애플리케이션(applications) 부분으로 가서 설치된 앱의 구성을 고치면 된다.

---

## 5. 처음 호출하기

설치와 승인이 끝나면 GitHub Copilot이 활성화된 모든 애플리케이션을 시작하거나 다시 시작한다. 그다음 채팅 창에 @를 입력하고 확장 이름을 쓰면 새로 설치한 확장을 쓸 수 있다(그림 10-6).

재시작 후 이 앱을 통해 확장을 처음 쓰려 하면, 선택한 작업 공간(workspace)에 대해서만 또는 모든 작업 공간에 대해 승인하라는 안내가 나올 수 있다(그림 10-7). 최초 승인과 비슷한 방식으로 진행하면 된다. 승인이 끝나면 프롬프트를 다시 입력하고 답을 받는다(그림 10-8).

| 승인 시점 | 대상 | 비고 |
| --- | --- | --- |
| 설치 직후 | 확장에 딸린 GitHub App을 내 계정에 | GitHub 인증 필요 |
| 첫 호출 때 | 선택한 작업 공간 또는 모든 작업 공간 | 승인 후 프롬프트를 다시 보낸다 |

---

## 6. 공개 확장을 쓸지, 직접 만들지

공개 Copilot 확장의 수는 꾸준히 늘고 있다. 쓰려는 앱이나 목적에 맞는 것이 있다면 좋은 선택이다. 하지만 아직 없는 기능이 필요하거나, 내 데이터와 업무 절차에 더 직접 연결되는 통합이 필요하다면 직접 확장을 만드는 쪽을 고려할 만하다. 직접 만들려면 먼저 확장의 두 가지 구현 유형(에이전트와 스킬셋)을 알아야 한다. 이어지는 「확장 유형과 구성 요소」 문서에서 다룬다.
