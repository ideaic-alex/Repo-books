# 확장이란 무엇인가

GitHub Copilot은 그대로 써도 쓸모가 많지만, 다른 도구와 연결하면 할 수 있는 일이 더 늘어난다. 직접 만든 도구까지 붙일 수 있는데, 이런 연결 수단을 확장(extension)이라고 부른다. 확장은 Copilot을 특정 용도나 환경에 맞게 다듬어 주고, 채팅 창을 통해 외부 앱이나 서비스를 부를 수 있게 해 준다. 예를 들어 Docker 확장을 설치하면 채팅에서 "@Docker, 이 프로젝트를 컨테이너로 만들려면 어떻게 해?" 같은 질문을 던질 수 있다.

이 문서는 확장이 정확히 무엇인지, 헷갈리기 쉬운 두 갈래(Copilot 확장과 VS Code용 확장)를 어떻게 구분하는지, 어떤 일에 쓰는지를 정리한다. 마켓플레이스에서 설치하는 과정은 다음 문서에서 이어서 다룬다.

---

## 1. 두 갈래의 확장: 용어부터 정리하기

Copilot의 기능을 넓히는 확장은 만드는 목표 환경에 따라 두 가지로 나뉜다.

- 플랫폼에 상관없이 Copilot Chat이 지원되는 곳이면 어디서든 돌아가는 것(IDE, GitHub.com 등)
- VS Code의 내부 기능을 활용하려고 VS Code에서만 돌아가는 것(다른 IDE로 옮겨 만들면 거기서도 가능)

이 장에서는 이름을 이렇게 구분해서 쓴다.

| 이 장의 호칭 | 뜻 | 어디서 동작하나 | 별도 GitHub App |
| --- | --- | --- | --- |
| Copilot 확장 | 플랫폼과 무관하게 만든 Copilot 고유 방식의 확장 | Copilot Chat이 있는 모든 곳(IDE, GitHub) | 필요함 |
| VS Code용 확장(채팅 참여자) | VS Code 플랫폼과 API로 만든 확장 | VS Code(이식하면 다른 IDE도 가능) | 필요 없음 |

두 경우 모두 사용자 눈에는 Copilot 채팅 창에서 기능이 나타난다는 점은 같다. 차이는 속을 들여다볼 때 드러난다. VS Code용 확장은 VS Code가 호스팅과 실행을 맡아 준다. 반면 Copilot 확장은 채팅 창과 백엔드 코드를 이어 주는 전용 GitHub App을 따로 설정해야 한다.

표를 읽는 법은 간단하다. 어디서든 쓰게 하려면 Copilot 확장, VS Code 안에서 깊게 통합하려면 VS Code용 확장이라고 기억하면 된다.

서버 기반과 클라이언트 기반이라는 비유로 이해해도 좋다. 공식 설명은 아니지만, Copilot 확장은 GitHub 쪽에서 돌아가는 앱과 통신해야 하므로 서버 기반으로, VS Code용 확장은 설치된 VS Code 클라이언트의 API를 쓰므로 클라이언트 기반으로 생각하면 이해가 쉽다.

## 2. Copilot 확장이 하는 일

Copilot 안쪽에는 사용자에게 보이는 기능 아래에 API와 하위 수준의 기능으로 된 틀(framework)이 깔려 있다. 제3자와 사용자는 이 틀을 이용해 Copilot의 능력을 넓힐 수 있다. 다른 애플리케이션이 자기 서비스를 Copilot Chat을 통해 사용자에게 직접 제공하는 구조다. 사용자는 Copilot AI와 대화하던 방식 그대로 다른 도구를 부르고 대화할 수 있다.

Copilot 문서가 소개하는 대표 사용 사례는 네 가지다.

| 사용 사례 | 하는 일 | 예 |
| --- | --- | --- |
| 문서 조회(Querying documentation) | 채팅이 제3자 문서 서비스에 물어 특정 주제의 정보를 찾는다 | 외부 문서 사이트에서 사용법 검색 |
| AI 보조 코딩(AI-assisted coding) | 제3자 AI 모델로 코드 제안을 받는다 | 다른 회사의 모델로 코드 제안 |
| 데이터 가져오기(Data retrieval) | 제3자 데이터 서비스에서 특정 주제의 정보를 가져온다 | 외부 데이터 서비스 조회 |
| 작업 실행(Action execution) | 채팅이 특정 작업을 실행한다 | 메시지 게시판에 글 올리기, 외부 시스템의 추적 항목 갱신 |

이 표에서 눈여겨볼 점은 앞의 세 가지는 "정보를 가져오는" 쪽이고 마지막 하나는 "행동을 일으키는" 쪽이라는 것이다. 확장은 읽기와 쓰기를 모두 할 수 있다.

쉽게 말하면 확장은 Copilot Chat에 다른 애플리케이션이나 데이터 집합에 대한 지식을 더해 주고, 필요할 때 불러 쓸 수 있는 전문 기술을 얹어 주는 일이다.

## 3. 확장의 성격과 공개 범위

Copilot 확장은 플랫폼을 가리지 않는 호환성, 앱 관리, 지원을 염두에 두고 만들어졌다. 채팅이 되는 곳이면 어디서든 동작한다. 공개 범위는 선택할 수 있다.

- 비공개(private): 조직이나 회사가 자체적으로 만들어 내부에서만 쓴다.
- 공개(public)와 공유: GitHub Marketplace에 올려 누구나 쓰게 할 수 있다.
- 직접 작성: 이 장 뒤쪽에서 보듯 사용자가 직접 만들 수도 있다.

이미 제3자 회사와 단체가 만든 공개 확장이 마켓플레이스에 올라와 있으므로, 확장을 처음 접한다면 마켓플레이스에서 둘러보는 것이 가장 좋은 출발점이다. 다음 문서인 「마켓플레이스에서 확장 설치하기」에서 설치 과정을 그대로 따라가 본다.
