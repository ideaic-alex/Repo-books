# Copilot Vision으로 이미지에서 코드 만들기

IDE에서 겪는 문제를 설명하기 어려워서 화면을 캡처해 동료에게 보낸 적이 있을 것이다. 마음에 드는 앱 화면을 보고 비슷한 모양으로 만들고 싶었던 적도 있을 것이다. Copilot Vision은 이런 상황을 위한 기능이다.

Copilot Vision은 특정 IDE의 Copilot Chat에 이미지를 직접 붙여 쓰게 해 주는 고급 기능이다. 이미지를 해석해 질문에 답할 수 있고, 이미지를 바탕으로 코드도 만들 수 있다. 이 문서는 쓸 수 있는 이미지 종류, 이미지를 붙이는 법, 분석과 코드 생성 예, 그리고 에이전트 모드와 결합해 계산기에 웹 화면을 붙이는 과정을 정리한다.

---

## 1. 어떤 이미지를 넣을 수 있나

| 용도 | 설명 |
|---|---|
| UI 모방 | 따라 하고 싶은 UI의 스크린샷이나 목업을 주고 비슷하게 만들게 한다 |
| 아키텍처 분석 | 아키텍처 다이어그램을 주고 분석과 설명을 받는다 |
| 디버깅 | IDE에서 겪는 문제의 스크린샷을 주고 디버깅을 돕게 한다 |
| 글자 추출 | 읽기 어려운 글자가 있는 이미지에서 텍스트를 뽑아 정리하게 한다 |
| 손그림 변환 | 손으로 그린 다이어그램을 코드로 바꾼다 |
| 스키마 검증 | 엔티티 관계 다이어그램(ERD)을 SQL과 대조해 검증한다 |

> 결과는 달라질 수 있다. 이미지 품질, 고른 모델 등에 따라 경험이 다르다. 다른 AI 결과처럼 입력을 고쳐 다시 줄 준비를 하고, 응답은 반드시 검토해야 한다.

---

## 2. 이미지 붙이는 법

책이 쓰인 시점에는 이미지를 채팅 입력 영역에 붙여야 한다. 특정 모드일 필요는 없다. 예제는 Ask 모드에서 시작한다. 방법은 세 가지다.

- 이미지를 끌어다 놓는다.
- 붙여넣기 한다.
- 평소 쓰는 컨텍스트 지정 방법으로 고른다.

---

## 3. 예제 1: 이미지 설명 듣기

예제 이미지는 파이썬 라이브러리 Gradio로 만들어 Hugging Face Spaces에서 호스팅한 웹 앱의 스크린샷이다. 이미지를 붙이고 "Tell me about this"라고 물으면 Copilot이 이미지를 보고 많은 정보를 뽑아낸다.

응답은 이 화면이 감성 분석(Sentiment Analysis) 앱이며 입력 텍스트의 감성을 긍정, 중립, 부정으로 분류하는 용도라고 알려 줬다. 주요 구성 요소를 짚은 내용은 다음과 같다.

| 요소 | Copilot이 설명한 내용 |
|---|---|
| 입력 필드 | "text"라는 입력 상자에 글을 입력하거나 붙여넣어 감성을 분석한다 |
| 출력 필드 | 분류 결과가 "output" 상자에 표시된다 |
| 버튼 | Clear는 입력을 지우고, Submit은 입력을 처리해 결과를 보여 준다 |
| 예시 | 입력 필드 아래 미리 준비된 문장이 있고, 누르면 입력 필드에 채워져 빠르게 테스트할 수 있다 |
| 상태 | 오른쪽 위의 초록색 "Running" 표시로 앱이 실행 중임을 알 수 있다 |

Copilot은 이 앱이 사전 학습된 머신러닝 모델, 예컨대 Hugging Face의 Transformers 라이브러리의 모델을 쓸 것이라고 추정했다.

### 코드 만들기

더 흥미로운 점은 이미지를 바탕으로 코드를 만든다는 것이다. "Can you write the code for this?"라고 하자 Copilot이 코드 한 벌을 내놓았다. 선택한 구현은 파이썬, Gradio, 그리고 감성 분석용 Hugging Face Transformers였다. 처음 앱을 만들 때 쓴 것과 같은 조합이다.

## 4. 예제 2: 에이전트 모드와 함께 계산기에 웹 화면 붙이기

현재 계산기에는 명령줄 인터페이스(CLI)만 있고 시각적 인터페이스가 없다. 마음에 드는 인터페이스 그림을 찾았다고 하고, 이를 컨텍스트로 삼아 웹 인터페이스를 만들게 해 보자. 동시에 거듭제곱 함수도 추가하고, 웹 화면이 생기니 실행이 간단하도록 CLI는 지운다. 프롬프트는 대략 다음과 같다.

```
Update the calculator files in this project as follows:
- Remove the CLI interface
- Add all necessary code to implement and test a function to compute exponents
- Create a web interface for all calculator functions to resemble the pasted image
- Include any new dependencies needed
- Explain how to run and test the web interface
```

변경 규모와 복잡도 때문에 다시 에이전트 모드로 바꿔서 실행했다. 제출하면 에이전트가 필요한 일을 판단하고 계획을 세워 변경을 제안하고 적용한다. 이때 에이전트가 처리한 여러 작업은 다음과 같다.

| 작업 | 내용 |
|---|---|
| Flask 설치 | 웹 프레임워크 의존성 설치 |
| 웹 인터페이스 구성 | 주 파일에 웹 인터페이스 부분을 넣고 모든 연산의 라우트를 갱신 |
| 새 파일 생성 | index.html 등 필요한 파일 |

---

## 5. 에이전트가 얼마나 알아서 하는가

프롬프트와 복잡도에 따라 Copilot은 멈추고 새 파일에 쓸 코드를 보여 줄 수도 있고, 파일을 직접 만들 수도 있다. 의존성 설치와 터미널 명령도 직접 실행하거나, 제안만 하고 내가 실행하게 할 수 있다. 기대만큼 자율적이지 않다면 프롬프트에서 처음부터 더 많은 일을 맡기고 허락한다고 알려 주면 된다. 예를 들어 필요한 파일을 만들라거나 requirements를 갱신하라고 말한다.

에이전트 모드로 원하는 결과를 얻으려면 여러 번 반복해야 할 때도 있다. 생성된 코드를 실행하다 문제가 나면, 에이전트 프롬프트에 문제를 알리고 추가 수정을 요청한다. 책의 예제를 처음 돌렸을 때 웹 앱에 결과가 제대로 표시되지 않았는데, 두 번 더 반복하자 Copilot이 원인을 찾아 고쳤다.

반복은 항상 같은 과정이다. 계획을 세우고, 제안한 변경을 인라인으로 반영하고, 명령을 실행한다. 결과물도 같아서, 실행해 보고 Keep/Undo로 검토할 수 있는 변경 묶음이다.

---

## 6. 최종 결과

완성된 웹 앱은 참고 이미지와 인상적으로 비슷했고 기대대로 동작했다. 요청한 대로 거듭제곱 함수가 추가되어, 원본 이미지에는 없던 거듭제곱(`**`) 버튼이 첫 줄 왼쪽에서 두 번째에 생겼다.

Copilot Vision은 NES, 에이전트 모드와 함께 코드 작성과 수정을 크게 단순화한다. 그러나 생성된 코드가 의도대로 안 돌 때 무엇이 틀렸는지 알아낼 수 있어야 한다. 다음 문서는 이럴 때 Copilot이 디버깅을 어떻게 돕는지 다룬다.
