# Copilot으로 테스트하기

Copilot은 시간이 많이 드는 반복 작업을 줄여 주고, 그만큼 더 복잡한 설계와 구현에 집중하게 해 준다. 이 장은 그중 테스트 생성을 다룬다. 테스트 방법 안내, 단위 테스트와 통합 테스트, 경계 케이스, 사용자 지정 테스트 지침, 프레임워크 선택, TDD, 에이전트 모드까지 이어진다.

생성된 테스트는 내용과 정확도가 매번 다를 수 있으므로 검토가 전제다. 장 전체가 "컨텍스트를 충분히 주고, 결과를 읽어 보고, 필요하면 프롬프트를 고쳐 다시 시도한다"는 흐름으로 되어 있다.

---

## 1. 핵심 요점

- 열린 파일이 없으면 Copilot은 일반론만 말한다. 테스트할 파일을 에디터에 열어 두거나 `#file`로 지정한다.
- 넓은 질문에는 기본값 `@workspace /setupTests`가 붙는다. 실험 기능이라 결과가 아쉬우면 "rerun without"이나 전송 옵션, 설정으로 기본값을 피한다.
- `/tests`가 가장 빠른 단위 테스트 생성 방법이다. 더 많은 케이스는 "다른 경계 케이스가 있나" 같은 후속 질문으로 얻는다.
- 주석 한 줄(`# Generate 10 simple test cases ...`)로 인라인 테스트를 만들 수 있고, 입력 검증 코드도 요청할 수 있다.
- 통합 테스트는 구체적 프롬프트, 외부 의존성 목, 상호작용 검증 요청 세 가지가 핵심이다.
- `github.copilot.chat.testGeneration.instructions`로 프레임워크와 규칙을 지정한다. 아직 실험 기능이다.
- TDD에서는 `only`로 범위를 좁혀 테스트만 먼저 만들고, 에이전트 모드가 의존성 설치와 구현, 테스트 재실행까지 오류를 고쳐 가며 처리한다.
- 모든 생성 테스트는 거짓 양성, 중복 검증, 잘못된 논리가 있는지 검토한다.
