# Copilot이란 무엇인가

GitHub Copilot은 클라우드에서 돌아가는 생성형 AI 코딩 도구다. 이 문서는 책이 이 도구를 어떤 말로 정의하는지, 'AI'와 '클라우드 기반', '생성형'이 각각 무엇을 가리키는지, 그리고 책 전체에서 지키는 약속(용어, 기본 IDE)을 정리한다.

저자는 책 전체를 통해 Copilot의 기능을 쓰는 법과 동작 원리, 기대와 다른 결과가 나오는 이유와 대처법까지 다루겠다고 밝힌다. 그 바탕이 되는 기초 지식이 이 장의 몫이다.

---

## 1. 이 책이 다루는 범위

저자는 ChatGPT 같은 AI 도구와 AI 에이전트가 사람이 소프트웨어와 상호작용하는 방식을 바꿔 왔듯, Copilot 같은 도구가 프로그래머의 개발 방식을 바꾸고 있다고 본다. 기존 코드나 자연어 프롬프트에서 컨텍스트(문맥)를 받아 쓰기 때문에 이전 도구보다 풍부한 코드 생성이 가능하다는 것이다.

책이 다루는 내용은 다음과 같다.

| 영역 | 책에서 다루는 내용 |
|---|---|
| 코드 작업 | 코드 생성과 완성, 테스트 작성, 코드 번역과 설명 |
| GitHub 작업 | 저장소, 풀 리퀘스트(PR), 이슈를 GitHub에서 직접 다루기 |
| 활용 범위 | 여러 분야와 여러 프로그래밍 언어의 예제 |
| 프롬프트 | 좋은 결과를 얻도록 프롬프트를 짜는 법 |
| 확장 | 자기만의 기능을 Copilot에 추가하는 법 |
| 동작 원리 | 왜 가끔 기대와 다른 결과가 나오는지, 그럴 때 줄이는 법 |

이 장은 그중에서도 출발점이다. Copilot의 큰 그림, 핵심 기술, 전체 흐름, 사용 시 주의점, ChatGPT와의 차이, 설치와 요금제 순서로 이어진다.

## 2. 'Copilot'이라는 말의 범위

copilot이라는 단어는 정보를 모아 프롬프트를 만들고 답과 제안을 돌려주는 AI 애플리케이션을 두루 가리키는 말로도 쓰인다. 예를 들어 Microsoft의 Office 365 Copilot은 Word, Teams, Outlook 같은 곳의 맥락을 분석해 요약이나 답장 제안 등을 해 준다.

이 책에서 'Copilot'은 GitHub Copilot만 뜻한다. 같은 이름을 쓰는 다른 시스템을 말할 때는 Office 365 Copilot처럼 정식 이름을 밝힌다. 이 노트도 같은 약속을 따른다.

## 3. 세 단어로 뜯어 보기

원문은 'cloud-based, generative AI tool'이라는 유행어 같은 표현을 하나씩 풀어 설명한다.

| 단어 | 뜻 | 풀어 쓰면 |
|---|---|---|
| AI(인공지능) | 예전에는 사람만 할 수 있다고 여겨진 추론과 기술이 필요한 일을 컴퓨터가 하는 것 | 최근에는 자연어 처리(NLP), 채팅 인터페이스, AI 에이전트의 자동 처리와 판단까지 포함한다 |
| 클라우드 기반 | 제안과 답이 돌아오는 경로 | GitHub가 관리하는 클라우드 환경이 AI 모델과의 상호작용을 중계한다 |
| 생성형 | 받은 컨텍스트에서 새로운 결과를 만들어 내는 능력 | 사용자 환경의 컨텍스트와 프롬프트를 바탕으로 개발용 응답과 제안을 만든다 |

세 단어를 합치면 내 컴퓨터가 아니라 GitHub 쪽 클라우드를 거쳐서 모델이 새 코드를 만들어 주는 도구라는 뜻이 된다. 얼마나 잘 만드느냐는 여러 요인에 달려 있고, 그 요인은 다음 문서들에서 다룬다.

## 4. AI에 대한 걱정

저자는 대중문화 속 이미지처럼 기계가 의식을 갖고 세상을 지배한다는 걱정은 현실적이지 않다고 본다. 다만 코딩 분야에서는 AI가 프로그래머의 일자리를 대체할 수 있다는 걱정이 있을 수 있다고 인정한다. 실제로 AI 때문에 일부 일자리가 줄어든 일이 있었을 것이라고 말한다.

그러나 Copilot의 의도는 대체가 아니다. 아무리 똑똑해 보여도 잘못되었거나 쓸 수 없는 코드를 만들 수 있고, 사람의 감독과 검토가 계속 필요하다. 책의 바람은 Copilot을 작업 도구함 속 유용한 도구 하나로 쓰게 돕는 것이다.

## 5. 책의 기본 환경

모든 IDE(통합 개발 환경)를 다 보여 줄 수는 없으므로 책은 IDE가 필요한 예제에서 VS Code 또는 GitHub Codespaces를 쓴다. 다른 IDE를 쓴다면 사용법과 조작 방식의 차이를 Copilot 문서에서 확인해야 한다.

| 항목 | 책의 기본값 | 다른 환경을 쓸 때 |
|---|---|---|
| IDE | VS Code, GitHub Codespaces | 해당 IDE의 Copilot 문서 참고 |
| 'Copilot' 표기 | GitHub Copilot | 다른 제품은 정식 이름으로 구분 |

VS Code에서 프로젝트를 열고 Copilot에 최적화 방안을 묻는 예가 이 장 첫 화면 예시로 나온다. 화면은 싣지 않고 그 의미만 정리하면, 열려 있는 프로젝트를 근거로 Copilot이 개선안을 제안하는 모습이다.
