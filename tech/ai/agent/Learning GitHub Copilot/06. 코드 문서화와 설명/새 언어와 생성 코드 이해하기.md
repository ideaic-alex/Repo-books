# 새 언어와 생성 코드 이해하기

Copilot은 코드를 만들어 줄 뿐 아니라 코드를 설명해 주는 도구이기도 하다. 책은 이 기능을 흔히 간과되지만 모든 수준의 개발자에게 큰 도움이 된다고 평가한다. 이 문서는 설명 기능이 쓰이는 여섯 가지 상황을 훑고, 그중 처음 두 가지인 낯선 언어 이해와 자동 생성 코드 이해를 자세히 다룬다.

---

## 1. 설명 기능이 쓰이는 여섯 가지 상황

| 상황 | 이 노트에서 다루는 문서 |
|---|---|
| 처음 접하는 언어의 코드를 이해 | 이 문서 |
| 생성된 코드와 관례를 이해 | 이 문서 |
| 코드의 로직을 요약 | 코드 로직 설명과 문제점 찾기 |
| 코드에서 잘못될 수 있는 점을 설명 | 코드 로직 설명과 문제점 찾기 |
| 터미널에서 실행한 일을 설명 | 터미널 설명 |
| 터미널에서 어떻게 하는지 설명 | 터미널 설명 |

모든 상황에 공통되는 요점이 둘 있다.

- 프롬프트가 열쇠다. 상황에 맞게 원하는 바를 분명히 적는 것이 설명을 잘 받는 가장 중요한 전제다.
- 핵심어로 explain을 주로 쓰지만 꼭 필요한 것은 아니다. "왜", "어떻게" 같은 다른 질문도 적절하게 쓰면 된다.

## 2. 낯선 언어 배우기

Python 개발자가 갑자기 Go로 새 프로젝트를 맡게 됐다고 하자. Copilot은 코드 작성뿐 아니라 Go의 핵심을 이해하는 데도 도움이 된다. 이렇게 물어본다.

```text
I'm a Python programmer. What are the most significant things I need to understand about how to write Go code?
```

저자가 이 장을 쓰던 때 Copilot은 12개 영역으로 답했다.

| 번호 | 영역 | 번호 | 영역 |
|---|---|---|---|
| 1 | 정적 타입(static typing) | 7 | 동시성(concurrency) |
| 2 | 컴파일(compilation) | 8 | 구조체와 메서드(structs and methods) |
| 3 | 문법 차이(syntax differences) | 9 | 포인터(pointers) |
| 4 | 패키지와 import | 10 | 표준 라이브러리(standard library) |
| 5 | 함수(functions) | 11 | 도구(tooling) |
| 6 | 오류 처리(error handling) | 12 | 인터페이스(interfaces) |

일부 영역에는 짧은 코드 조각이 붙었고, "이 차이점들을 이해하면 Python에서 Go로 더 부드럽게 넘어갈 수 있다"는 맺음말로 끝났다. 여기서 Python이라는 배경을 먼저 밝혔기 때문에 두 언어의 차이에 초점을 맞춘 답이 나왔다. 자신의 배경을 프롬프트에 적는 것이 요령이다.

선택한 코드 일부에 /explain 슬래시 명령을 쓰면 그 부분의 동작을 설명해 준다. 기존 코드를 새 언어로 옮겨 달라는 요청도 가능하다. 어느 경우든 Copilot의 제안이나 응답이 내 상황에 정확하고 적절한지는 직접 확인해야 한다.

## 3. Copilot을 선생님으로 쓰기

새 언어를 배우는 덜 흔한 방법이 있다. Copilot에게 문제를 내 달라고 하는 것이다.

```text
Explain how to code a function in Go by giving me a problem to complete.
```

응답에는 세 가지가 들어 있다.

- 문제 설명
- 문제를 푸는 단계
- 문제를 실제로 푸는 Go 코드

이 방식은 언어의 기본뿐 아니라 그 언어가 쓰는 관례와, 자동 생성 코드의 목적을 이해하는 데도 쓸 수 있다.

## 4. 자동 생성 코드와 관례 이해하기

Kubernetes와 Go가 모두 낯선 상황에서 커스텀 리소스를 관리하는 Kubernetes 오퍼레이터를 만든다고 하자. 보통 Operator SDK로 Go 프로젝트의 뼈대를 만든다. SDK는 `zz_generated.deepcopy.go`처럼 이름이 낯선 유틸리티 파일을 자동으로 만든다. 가장 먼저 궁금한 것은 이 파일이 무슨 용도인가이다. 파일을 가리켜 직접 묻는다.

```text
What is the code in #file:api/v1alpha1/zz_generated.deepcopy used for?
```

Copilot은 소개에 이어 용도를 항목별로 풀어 준다. 이런 응답은 대개 끝에 요약을 붙여 주어 핵심만 빨리 알 수 있다. 여기서의 요약은 이 파일이 Kubernetes의 커스텀 리소스 타입에 필요한 깊은 복사(deep copy) 함수를 제공하는 자동 생성 파일이라는 내용이다. 이 함수들 덕분에 리소스를 올바르게 다루고 조작할 수 있다.

이름이 왜 그런지도 물어볼 수 있다.

```text
Why is this file named starting with zz_?
```

이 질문에는 그 관례의 이유를 목록으로 정리한 대화체 답이 돌아온다. 정리하면 이렇다.

| 궁금한 것 | 프롬프트 방식 |
|---|---|
| 파일의 용도 | 파일을 #file로 지정해 "무엇에 쓰이는지" 묻기 |
| 이름 규칙의 이유 | 현재 파일을 두고 "왜 이렇게 시작하는지" 묻기 |
| 언어의 핵심 차이 | 내 배경 언어를 밝히고 중요한 점 묻기 |
| 연습 | 문제를 내 달라고 요청하기 |

읽는 법: 설명을 받는 질문은 "무엇", "왜", "어떻게"로 자유롭게 바꿔 쓸 수 있고, 대상이 파일이면 #file로 범위를 좁힌다.

## 5. 정리

- 낯선 언어는 내 배경을 알려 주고 차이점을 묻는다.
- 배우는 방법으로 Copilot에게 문제를 내 달라고 할 수 있다.
- 낯선 자동 생성 파일과 이름 규칙은 직접 물으면 용도와 이유를 설명해 준다.
- 어떤 경우든 답이 정확한지는 직접 검증한다.
