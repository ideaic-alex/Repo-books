# 코드 문서화와 설명

코드에 문서를 남기는 일은 품질과 유지보수에 꼭 필요하지만 번거로워서 뒤로 밀리기 쉽다. 이 장은 Copilot이 인라인과 채팅으로 주석, 프레임워크용 문서, API 문서, 기능 문서를 만들어 주는 방법을 다룬다.

또 하나의 축은 코드 설명이다. 낯선 언어와 자동 생성 코드를 이해하고, 로직을 요약하고, 잘못될 수 있는 곳을 찾고, 터미널의 명령과 출력을 해석하는 방법을 정리한다. 이 노트는 책이 쓰인 시점의 기능을 기준으로 하며 최신 Copilot에서는 화면과 동작이 달라졌을 수 있다.

---

## 1. 핵심 요점

- 인라인 채팅의 /doc은 빠르지만 대개 함수 머리말 주석만 만든다. 본문 주석까지 원하면 별도 채팅에서 자세히 달라고 시킨다.
- "verbosely comment"처럼 상세 수준을 프롬프트에 적으면 주석이 촘촘해지고, 머리말과 본문을 한 프롬프트로 합쳐도 잘 동작한다.
- 언어에 표준 문서화 도구(Javadoc, JSDoc 등)가 있으면 Copilot이 그 형식에 맞는 주석을 만든다.
- Swagger 문서나 기능 문서를 얻으려면 print-ready 같은 표현과 #file 파일 지정이 필요하다. @workspace로만 시키면 만드는 방법을 설명하는 데 그치기 쉽다.
- 채팅 내용은 Copy, Copy All, Chat: Export Chat으로 가져갈 수 있고, 복사본은 마크다운이다.
- 설명 기능은 낯선 언어, 자동 생성 코드와 관례, 로직 요약, 문제점 찾기에 쓸 수 있고 프롬프트가 성패를 좌우한다.
- #terminalLastCommand, #terminalSelection, @terminal로 터미널의 명령을 해석하고 방법을 물을 수 있다.
- Copilot의 지식은 훈련 데이터 시점에 묶이므로 결과는 반드시 검토한다.
