# 정리

6장은 Copilot이 코드를 문서화하고 설명하는 능력을 다뤘다. 이 문서는 장 전체를 한 번에 되짚고, 마지막에 책이 던지는 주의점과 다음 장으로 이어지는 연결을 적는다.

---

## 1. 기능별 한눈에 보기

| 영역 | 할 수 있는 일 | 요령 |
|---|---|---|
| 기본 문서화 | 소스 코드에 주석 삽입, /doc으로 머리말 주석 | 더 풍부한 주석은 "verbosely comment" 같은 구체적 지시 |
| 확장 문서화 | API 문서, 기능 문서 (검토 후 공유 가능) | 파일을 #file로 지정 |
| 설명: 개념과 관례 | 새 언어와 프레임워크의 원칙, 낯선 관례 | 내 배경과 궁금한 점을 적는다 |
| 설명: 로직 | 코드의 논리와 처리 과정 요약 | 특히 낯선 코드를 배우거나 유지보수할 때 유용 |
| 설명: 문제점 | 잘못될 수 있는 곳 지적 | 사실상 코드 리뷰, 취약한 부분 점검 |
| 설명: 터미널 | 마지막 명령, 선택한 출력 해석, 방법과 명령 안내 | #terminalLastCommand, #terminalSelection, @terminal |

## 2. 장에서 건진 실전 요령

- 기대한 결과가 안 나오면 더 자세하고 구체적인 프롬프트를 써 본다. 마음에 안 들면 제안된 변경을 거절하고 프롬프트를 고쳐 가며 반복한다.
- 문서화 범위는 프롬프트로 조절한다. 머리말만, 본문 전체, 둘 다 중에서 원하는 것을 말한다.
- 문서 결과물을 원하면 파일을 짚어 주고, 요약이나 개괄은 작업 공간 범위로 넓힌다.
- 설명 기능은 문서화만큼 중요하다. 로직 요약은 낯선 코드를 배우거나 유지보수하는 데 가장 의미가 크다.
- 터미널 설명은 두 갈래로 나뉜다. 출력이나 마지막 명령을 가리켜 의미를 묻는 방법과, 방법을 물어 실행할 명령을 받는 방법이다.

## 3. 주의할 점

Copilot은 부정확하거나 오래된 정보를 줄 수 있다. 기반 모델을 훈련한 데이터가 얼마나 최신이냐에 따라 지식의 신선도가 정해지기 때문이다. 그래서 문서나 설명을 그대로 믿지 말고, 특히 공유할 문서는 검토를 거친다.

다음 장은 Copilot이 오래된 정보를 근거로 제안하는 문제를 어떻게 다루고 우회하는지를 이야기한다.
