# 머리말과 이 책에 대하여

이 문서는 Brent Laster의 『Learning GitHub Copilot』 앞부분인 추천사(Foreword), 서문(Preface), 표기 규칙, 예제 코드 사용 안내, 감사의 글을 정리한 것이다. 본격적인 기능 설명에 들어가기 전에, 이 책이 누구를 위해 어떤 순서로 쓰였고 어떤 전제를 깔고 있는지 먼저 짚는다.

책은 서술 시점의 Copilot을 기준으로 쓰였다. Copilot은 화면 구성과 기능이 자주 바뀌므로, 이 학습 노트를 읽을 때도 그 점을 염두에 두면 좋다. 이 노트의 모든 장은 같은 기준으로 정리했다.

---

## 1. 책의 목적과 대상 독자

저자는 이 책을 "생성형 AI라는 큰 물결을 타는 법"을 안내하는 책이라고 소개한다. 인터넷, CI/CD, 컨테이너, 클라우드로 이어진 기술 변화를 여러 번 겪은 개발자의 눈으로 볼 때, 생성형 AI는 그중에서도 가장 큰 변화다. 새 도구, 새 모델, 새 기능이 쏟아지는 통에 개발자들이 휩쓸리듯 따라가고 있다는 것이 저자의 진단이다. 그래서 이 책의 목표는 Copilot의 기초부터 고급 주제까지 이해하게 해서 코딩 작업을 이전보다 쉽고 간단하게 만드는 것이다. 저자가 모든 질문에 답하겠다고 약속하지는 않고, 도구에 충분히 익숙해지는 것을 목표로 한다.

저자 본인의 경험도 책의 관점에 영향을 준다. 저자는 몇 년째 Copilot을 여러 방식으로 써 왔다. 개인 프로젝트에서 썼고, 데브옵스 책임자로서 기업 R&D 조직에 시범 도입했고, 여러 회사를 대상으로 Copilot 교육도 했다. 회의적인 입장과 열광하는 입장을 모두 거쳤다. 초기의 Copilot은 다른 도구보다 인상적이지 않았지만, 책을 쓰고 강의를 만드는 사이에 기능이 크게 좋아져 지금은 IDE와 GitHub에서 가장 자주 쓰는 도구 중 하나가 되었다고 한다.

### 전제 지식

이 책은 Copilot에 대해서는 아무것도 몰라도 읽을 수 있다. 다만 아래 두 가지는 이미 알고 있다고 가정한다.

- IDE에서 코드를 작성해 본 기본 경험
- Git과 GitHub의 기본 사용법

저자는 이 책이 코딩, IDE 사용법, GitHub 사용법을 가르치지 않는다고 분명히 말한다. 대신 이미 하고 있는 그 일들의 생산성을 Copilot으로 몇 배 높이는 방법을 다룬다. 독자 직군은 소프트웨어 개발자, 품질 엔지니어(QA), SRE는 물론 AI 어시스턴트가 어떤 도움이 되는지 알고 싶은 사람까지 넓게 잡았다. Copilot 전용 책이지만 예제와 작업 흐름의 상당수는 다른 AI 코딩 도구에도 비슷하게 적용된다.

### 저자가 염두에 둔 독자 유형

| 독자 유형 | 이 책에서 얻을 것 |
|---|---|
| AI 코딩 어시스턴트가 처음이거나 익숙하지 않은 사람 | AI 코딩 어시스턴트가 무엇이고 어떻게 쓰는 게 좋은지 |
| 개념과 작업 흐름은 알지만 Copilot은 처음인 사람 | GitHub Copilot이 제공하는 것이 무엇인지 |
| 조직이나 회사 단위의 도입을 검토하는 사람 | Copilot을 더 넓게 쓸 도구로 평가하는 기준 |
| 이미 Copilot을 써 본 사람 | 기능을 끝까지 활용하는 방법 |
| Copilot의 약점을 보완하고 싶은 사람 | 부족한 부분을 메우는 요령 |
| 새 기능, 특히 에이전트 모드가 궁금한 사람 | 새로 들어온 기능의 이해 |
| 자기만의 Copilot 확장을 만들고 싶은 사람 | 확장 제작 방법(10장) |
| GitHub를 주로 쓰고 거기서 Copilot을 쓰고 싶은 사람 | GitHub 안의 Copilot 통합(9장) |

이 표는 "나는 어느 장부터 읽어야 하나"를 정하는 데 쓰면 된다. 어느 유형이든 해당 장이 따로 있어서, 앞 장을 전부 읽지 않아도 필요한 부분으로 갈 수 있다. 저자는 대부분의 장이 독립해서 읽히도록 썼으니 필요와 숙련도에 따라 건너뛰며 읽어도 좋다고 안내한다.

## 2. 책의 구성(10개 장의 흐름)

책은 "Copilot이 무엇인가"라는 기초에서 시작해 "그 위로 어떻게 확장하는가"라는 고급 주제로 올라가는 흐름이다. 1~3장이 기초, 4장이 고급 상호작용, 5~6장이 테스트와 문서화, 7~10장이 활용 범위를 넓히는 주제다.

| 장 | 한국어 제목 | 한 줄 요약 |
|---|---|---|
| 1 | 기초 다지기 | Copilot이 무엇인지, 어떻게 동작하고 어떻게 시작하는지 다지는 기초 장 |
| 2 | Copilot으로 코딩하기 | Copilot의 두 주요 방식 중 하나인 코드 완성(인라인 제안)으로 코드를 쓰는 법 |
| 3 | IDE에서 Copilot과 채팅하기 | 또 다른 주요 방식인 대화형 채팅 인터페이스를 IDE에서 쓰는 법 |
| 4 | 고급 편집과 자율 워크플로 | 더 자율적인 편집과, 프롬프트부터 완료까지 변경을 자동으로 끌고 가는 에이전트 모드, 독특한 인터페이스의 Copilot Vision, 디버깅 |
| 5 | Copilot으로 테스트하기 | 풍부한 테스트 묶음을 Copilot으로 만드는 법 |
| 6 | 코드 문서화와 설명 | 여러 종류의 문서를 Copilot으로 만들고 코드를 설명받는 법 |
| 7 | Copilot을 최신 상태로 관련성 있게 유지하기 | 결과물이 최신이고 상황에 맞도록 품질을 높이는 법 |
| 8 | Copilot의 다른 활용법 | 흔하지는 않지만 쓸모 있는 여러 작업을 Copilot에 맡기는 법 |
| 9 | GitHub에서 Copilot 사용하기 | GitHub 웹의 Copilot 채팅과, 프로젝트 이해, 이슈와 풀 리퀘스트(PR) 작업 단순화 |
| 10 | Copilot 기능 확장하기 | GitHub 확장(Extensions)으로 기능을 넓히고, 직접 확장을 만드는 법 |

표에서 보듯 1~3장은 하나의 묶음이다. Copilot이 무엇인지 이해하고, 두 가지 주요 상호작용 방식인 코드 완성과 채팅(대화형 인터페이스)을 익힌다. 4장은 그 위에 한 단계 올라간 방식을 다룬다. 더 자율적으로 편집하는 방식, 프롬프트에서 완료까지 변경을 자동으로 끌고 가는 에이전트 모드, 독특한 인터페이스를 가진 Copilot Vision, Copilot을 이용한 디버깅이 여기에 들어 있다.

5~6장은 개발자가 흔히 미루는 일인 테스트와 문서화를 Copilot에 맡겨 "다른 코딩 작업에 집중할 시간"을 만드는 데 초점이 있다. 7장은 응답의 시의성과 관련성을 끌어올리는 방법이다. 8장은 SQL 쿼리, 정규식, YAML 파일처럼 시간을 잡아먹는 자잘한 작업을 다룬다(추천사에서 언급되는 예다). 9장은 IDE가 아니라 GitHub 웹 쪽 인터페이스이고, 10장은 확장으로 Copilot을 직접 넓히는 마지막 단계다.

| 상자 | 뜻 |
|---|---|

| NOTE | 일반적인 참고 사항 |

### 키보드 단축키 표기 Meta

Copilot은 Windows, Mac, Linux 어디서나 돌아가는 여러 IDE에 연동되므로, 단축키는 운영체제마다 다르다. 저자는 모든 단축키를 플랫폼별로 매번 적는 번거로움을 피하려고 **Meta**라는 표기를 쓴다. 이는 "자기 플랫폼에 맞는 해당 키를 넣으라"는 뜻의 기호다. 책의 예제와 화면은 Mac에서 만들었으므로, 화면에 보이는 창과 컨트롤도 Mac 스타일일 수 있다. Windows나 Linux에서 읽는다면 그에 맞는 키로 바꿔 읽어야 한다.

## 5. 추천사와 서문의 핵심

### 추천사(Andrew Stellman)

추천사는 『Learning Agile』, 『Head First C#』 등을 쓴 개발자이자 강사인 Andrew Stellman이 2025년 4월에 썼다. 핵심 메시지는 다음과 같다.

- **Copilot은 완벽하지 않고, 완벽하려 하지도 않는다.** 코드의 패턴과 문맥을 바탕으로 제안을 내놓아 앞으로 나아가도록 돕는 도구이며, 꽤 자주 "만족스러울 만큼 가까운" 결과를 준다. 그래도 도구를 잘 이끄는 법과 언제 속도를 늦추고 다시 확인해야 하는지를 알아야 한다.
- **통제권은 개발자에게 있다.** Copilot이 컴파일되고 실행되고 테스트까지 통과하는 코드를 써 줄 수 있다. 하지만 그 코드가 무엇이고 왜 동작하는지, 무엇보다 어떻게 그 결과를 끌어냈는지 모른다면 코드베이스에 들어가는 내용을 통제하는 것이 아니다. 이 책은 그 통제권을 되찾게 해 주는 책이라는 것이다.
- **Copilot이 특히 도움이 되는 순간.** 새 기술이나 API를 쓰는데 문서가 허술할 때, 팀 모두가 피하던 고약한 코드를 리팩터링할 때, 써야 하지만 지루하고 30분을 날릴 보일러플레이트를 쓸 때다. 완성 코드를 주기도 하고, 함께 다듬어 갈 출발점만 주기도 하지만 막힌 일을 다시 굴러가게 하는 데는 거의 늘 충분하다.
- **책의 접근.** 기능을 나열하는 책이 아니라, 지저분하고 비선형적이며 마감에 쫓기는 실제 업무에서 쓰는 방법을 보여 준다. 코드 설명과 테스트 작성 같은 기본 강점에서 출발해, SQL 쿼리, 정규식, YAML 파일 등 사소하지만 시간을 먹는 일로 나아간다.
- **누구에게 권하는가.** 처음 쓰는 사람에게는 좋은 출발점이고, 이미 쓰는 사람에게는 더 효과적이고 더 믿을 수 있게 만드는 기법을 준다. 회의적인 사람에게는 그 회의가 건강한 태도이며, 좋은 개발자를 만드는 요소를 포기하지 않고 도구를 최대한 쓰는 법을 보여 준다고 말한다.

### 서문(Brent Laster)

서문은 저자가 왜, 어떤 입장에서 책을 썼는지를 밝히고, 독자가 놀라지 않도록 미리 알려야 할 사항을 정리한다. 책의 목적과 이력은 1절에서 다뤘으므로 여기서는 책의 구성에 관한 부분만 덧붙인다.

- 책 전체는 "무엇인가"라는 기초에서 "어떻게 더 나아가는가"라는 고급으로 가도록 설계되었다.
- 대부분의 장은 단독으로 읽을 수 있다. 필요와 편안함의 정도에 따라 장을 건너뛰어도 된다.
- 독자의 의견은 리뷰나 향후 콘퍼런스, 교육 자리에서 환영한다고 한다.

### 감사의 글

감사의 글에서는 이 책이 저자의 네 번째 출간 도서라는 점, 편집과 제작에 O'Reilly의 여러 사람이 관여했다는 점이 나온다. 기획을 맡은 편집자 John Devins가 책을 밀어 주었고 이후 Louise Corrigan이 이어받았으며, 교정은 Sharon Wilkey와 Jonathon Owen, 그림은 Kate Dullea, 표지는 Susan Thompson, 내지 디자인은 David Futato가 맡았다. 이전 작 『Learning GitHub Actions』에서도 함께한 개발 편집자 Michele Cronin이 일정과 검토를 챙겼다. 검토자로는 Andrew Stellman, Steffen Bjerkenås, Chhaya Methani, Balaji Dhamodharan, Aditya Goel, Sundeep Katta, Jess Males, Tom Taulli가 참여했다고 한다. 저자는 이 밖에도 NFJS와 ATO 콘퍼런스에서 같은 주제로 발표한 경험이 책의 내용을 더 낫게 만들었다고 말한다. 마지막으로 가족과 독자에게 감사를 전한다. 기술 내용과는 무관한 부분이라 이 노트에서는 간단히만 적는다.

## 6. 책 내용이 서술 시점 기준이라 최신 기능과 다를 수 있다는 주의

저자는 서문에서 독자가 놀라지 않도록 몇 가지를 미리 알린다. Copilot은 변화가 빠른 도구라서, 이 책을 읽는 시점에는 달라진 부분이 있을 수 있다. 아래 표는 그 주의 사항을 정리한 것이다. 이 노트를 읽을 때도 같은 주의가 그대로 적용된다.

| 주의 사항 | 내용 | 읽을 때의 대응 |
|---|---|---|
| UI의 잦은 변경 | 지난 1년쯤 Copilot은 거의 모든 릴리스마다 대화상자나 컨트롤 중 적어도 하나의 모양이나 위치를 바꿨다. 저자는 집필 시점 기준으로 화면 캡처와 설명을 맞췄지만 일부는 이미 달라졌을 것이다. | 메뉴 위치나 버튼 이름이 다르면 비슷한 이름의 항목을 찾아본다. |
| 새 기능의 지속적 추가 | 새 기능이 꽤 규칙적으로 나오므로 시간이 지나면 책에 없는 기능이 생긴다. | 최신 기능은 공식 문서에서 확인한다. |
| 프리뷰, 실험 기능 | 집필 시점에 프리뷰나 실험 단계로 표시된 기능은 그사이 정식 기능이 되었을 수도, 채택되지 못해 사라졌을 수도 있다. | 해당 기능이 아직 있는지 먼저 확인한다. |
| IDE별 차이 | 여러 IDE에서 통합 방식, 모양, 심지어 기능까지 다르다. GitHub는 전통적으로 Visual Studio Code와 같은 인터페이스를 쓰는 환경(GitHub Codespaces 등)에 새 기능을 먼저 내놓고, 그쪽이 기능의 상위 집합이다. | 책의 화면과 예제는 모두 VS Code 또는 Codespace 기준이다. |
| VS Code 외 IDE | VS Code 이외의 IDE에서는 일부 기능이 아직 구현되지 않았을 수 있다. | Copilot 문서와 해당 IDE 문서에서 최신 정보를 확인한다. |
| 운영체제 차이 | IDE는 Windows, Mac, Linux에서 돌아가지만 모든 변형을 다룰 수 없어 예제는 Mac에서 만들었다. 창과 컨트롤이 Mac 스타일이고 단축키도 플랫폼마다 다르다. | 단축키는 Meta 표기를 자기 플랫폼의 키로 바꿔 읽는다. |

이 표의 공통된 결론은 "원리와 작업 흐름은 가져가고, 화면 위치와 세부 이름은 현재 버전에서 다시 확인하라"는 것이다. 특히 이 노트는 책의 서술 시점을 따라 정리했으므로, 프리뷰였던 기능이나 책에 나온 화면 구성이 지금의 Copilot과 다를 수 있다. 기능이 있는지 없는지 헷갈린다면 먼저 VS Code에서 확인하고, 다른 IDE를 쓴다면 그 IDE에서 지원하는지를 따로 확인하는 순서가 안전하다.
