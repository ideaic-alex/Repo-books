# 세션 관리와 프롬프트 요령

채팅은 한 번 묻고 끝나는 도구가 아니라 대화가 쌓이는 도구다. 그래서 대화(세션)를 어떻게 나누고 정리할지, 그리고 프롬프트를 어떻게 써야 원하는 답이 나오는지가 쓰는 데 큰 차이를 만든다.

이 문서는 채팅 창 맨 윗줄의 세션 관리 버튼, 세션이 맥락을 기억하는 방식, 그리고 Copilot Chat용 프롬프트 작성 요령을 정리한다.

---

## 1. 세션은 대화 하나의 단위다

한 채팅 세션 안에서 Copilot은 앞서 오간 프롬프트들을 포함한 대화 기록을 기억한다. 그래서 꼬리 질문이 가능하다.

책의 예로, 먼저 어떤 파일에 대한 테스트를 만들어 달라고 요청했다. 이어서 "그 밖에 고려할 사용 사례가 뭐가 있나" 같은 일반적인 질문을 했더니, 직전 요청의 맥락을 이어받은 답이 돌아왔다. 질문에 파일 이름이나 "테스트"라는 말을 다시 쓰지 않아도 된 것이다.

반대로 이 성질 때문에 주제가 바뀔 때는 조심해야 한다. 앞 대화의 맥락이 새 질문에 섞여 들어갈 수 있다. 그럴 때는 새 세션을 시작한다.

## 2. 상단 아이콘 정리

채팅 창 맨 윗줄에는 세션을 다루는 컨트롤이 모여 있다.

| 컨트롤 | 모양 | 하는 일 |
| --- | --- | --- |
| 이전/다음 화살표 | 좌우 화살표 (오른쪽에 위치) | 세션 사이를 앞뒤로 이동한다 |
| New Chat | 큰 + 기호 | 현재 대화를 이어 가지 않고 새 세션을 시작한다 |
| Show Chats | 원형 화살표 안의 시계 | 진행해 온 채팅 목록을 대화 상자로 보여 준다. 항목을 누르면 그 채팅으로 전환한다 |
| Views and More Actions | 점 세 개 | 현재 채팅을 에디터나 별도 창으로 열기, 피드백 보내기, 최신 릴리스 노트 열기 |
| 닫기 | 오른쪽 위 X | 채팅 뷰 전체를 닫는다 |

새 세션은 새로운 주제를 다루면서 이전 대화의 맥락을 Copilot이 가정해 버리는 위험을 피하고 싶을 때 쓴다.

## 3. 채팅 한 개만 지우기

개별 채팅 항목 위에 마우스를 올리면 그 항목 오른쪽 위에 "X"가 나타난다. 이것을 누르면 그 채팅 하나만 지워진다. 툴팁에는 Undo Requests라고 적혀 있어 표현이 어색하지만 현재 동작은 채팅 삭제다. 더 이상 관련 없는 대화를 정리하고 싶을 때 쓰면 된다.

채팅 내용을 내보내거나 저장하는 방법은 6장에서 다룬다.

## 4. Copilot Chat을 위한 프롬프트 작성

프롬프트 엔지니어링은 AI가 유용하고 정확한 답을 내도록 명확하고 목표가 분명한 지시를 쓰는 일이다. 프롬프트는 단순한 질문일 수도, 슬래시 명령 같은 지름길일 수도, 프로젝트에 대한 구체적인 지시일 수도 있다. Copilot은 프롬프트만 보지 않는다. 열려 있는 파일의 컨텍스트와 지금까지의 채팅 기록도 함께 참고해서 답한다.

### 4.1 일반에서 구체로

큰 작업이라면 먼저 목표를 넓게 말해 무대를 깐다. 그다음에 세부 요구나 제약을 더해 간다. 책의 예는 다음과 같다.

```text
Write a function that checks if a number is prime.
```

이 요청 뒤에 "소수면 true를 돌려주고, 입력이 양의 정수가 아니면 에러를 던져야 한다"는 식으로 요구를 덧붙인다. 큰 목적과 세부 조건을 단계적으로 알려 주면 Copilot이 둘 다 이해하고 더 정확하게 답한다.

### 4.2 예시를 준다

입력 예와 기대하는 출력, 또는 단위 테스트를 함께 주면 의도를 더 잘 짐작한다. 문자열에서 날짜를 뽑는 함수를 원한다면 예시 문자열과 기대하는 날짜 배열을 보여 주는 식이다.

### 4.3 컨텍스트를 넓히는 수단

| 수단 | 쓰임 |
| --- | --- |
| 코드 선택(하이라이트) | 질문 대상을 정확히 지정한다 |
| 키워드 | 프롬프트 안에서 대상을 짚는다 |
| 파일 끌어 놓기 | 채팅에 파일을 첨부해 컨텍스트로 준다 |
| 채팅 변수 | `#`으로 파일, 선택 영역 등을 지정한다 (이 장 뒤쪽에서 설명) |
| 채팅 참여자 | `@`로 영역을 지정한다 (이 장 뒤쪽에서 설명) |
| Copilot 확장 | 특정 도메인 작업을 연결한다 (10장에서 설명) |

표에서 보듯 방법이 여러 가지라서, 처음 답이 마음에 안 들면 프롬프트를 고치거나 컨텍스트를 바꿔 다시 시도하면 된다. 반복이 핵심이다.

### 4.4 대화처럼 다룬다

프롬프트 작성을 주고받는 대화로 받아들이면 코드 작성, 에러 디버깅, 테스트 생성, 프로젝트에 관한 질문을 효율적으로 처리할 수 있다. 의도를 분명히 전할수록 Copilot의 도움도 정확해진다. 더 자세한 내용은 Copilot 공식 문서의 프롬프트 엔지니어링 항목에 있다.

| 요령 | 한 줄 요약 |
| --- | --- |
| 일반에서 구체로 | 목표를 먼저, 제약은 나중에 덧붙인다 |
| 예시 제공 | 입력과 기대 출력, 테스트를 보여 준다 |
| 컨텍스트 보강 | 선택, 파일, 변수, 참여자로 범위를 좁힌다 |
| 반복 개선 | 답이 어긋나면 프롬프트나 컨텍스트를 고친다 |
