# 정리

이 장은 AI 도움이 가장 먼저 떠오르지는 않지만 실제로 쓸모가 있는 영역을 살펴보았다. 하나의 기능을 깊이 다룬 것이 아니라 서로 다른 대표 사례를 모아 놓은 장이었고, 각 영역에서 Copilot의 능력이 잘 쓰인다.

마지막으로 다섯 영역을 한눈에 비교하고, 9장으로 이어지는 내용을 짚는다.

---

## 1. 영역별 요약

| 영역 | Copilot이 해 주는 일 | 조심할 점 |
| --- | --- | --- |
| SQL | 일반 프로그래밍 언어처럼 코드 완성 제안과 전체 코드 생성. 특히 저장 프로시저 작성과 최적화에 유용 | 생성된 값과 날짜가 의도와 맞는지 확인 |
| 선언형 명세 (Kubernetes YAML) | 원하는 최종 상태를 기술하는 명세 생성. 표준 Kubernetes 오브젝트의 YAML 정의, 사용법 안내, API 호출 코드로의 변환 | 파일을 저장하고 실제 실행 전에 검토 |
| 정규식 | 필요한 문자 조합과 검증 예제를 만들어 줌 | 예제가 의도와 다르면 프롬프트를 구체화 |
| 테스트 데이터 | 프롬프트나 컨텍스트에서 정한 키와 값의 매핑 데이터를 생성 | 정확성과 최신성을 보장하지 않고 공개 예제와 일치할 가능성이 있어 추가 확인 필요 |
| GitHub CLI | `gh`를 통해 명령 제안과 명령 및 인자 설명 | 기능이 제한적이며 앞으로 확대될 것으로 예상 |

## 2. 영역별 핵심

- 데이터베이스를 다룰 때 Copilot은 SQL에 대해 코드 완성 제안과 전체 코드 생성을 해 준다. 저장 프로시저와 최적화에서 특히 도움이 된다.
- 시스템에 어떻게 할지 알려 주는 일반 코드뿐 아니라, 원하는 결과를 서술하는 선언형 명세도 생성한다. Kubernetes가 좋은 예이다. 알맞은 프롬프트를 주면 표준 Kubernetes 오브젝트의 YAML 정의를 만들 수 있다. 그 명세를 Kubernetes와 함께 쓰는 법을 알려 주고, API 호출 코드로 바꾸는 것도 해 준다. 이런 도움은 프레임워크와 그 YAML 표현의 복잡함을 크게 줄여 준다.
- 개발자를 자주 좌절시키는 정규식 만들기도 자동화한다. 필요한 매칭 문법에 맞는 문자 조합을 만들고 검증하는 예제도 함께 낸다.
- 기본 테스트나 시연을 위해 코드가 다룰 데이터 세트를 만들 수 있다. 프롬프트로 정한 키와 값, 또는 컨텍스트에서 정해진 매핑 데이터다. 데이터가 정확하고 최신이라는 보장은 없고, 공개 예제와 일치할 가능성이 더 크므로 결과를 쓸 때 추가로 신경 써야 한다.
- GitHub CLI(`gh`)에 Copilot 기능이 추가되어 있다. 애플리케이션 설치 같은 작업의 명령을 제안받고, 명령과 인자가 무슨 일을 하는지 설명받을 수 있다. 기능은 제한적이지만 다른 기능으로 확장될 가능성이 크다.
