# Copilot을 최신 상태로 관련성 있게 유지하기

GitHub Copilot의 답은 때로 최신이 아니거나 내 코드와 맞지 않는다. 이 장은 Copilot이 컨텍스트를 어디서 모으는지, 왜 낡았거나 틀린 답이 나오는지, 그럴 때 사용자가 방향을 잡아 주는 방법을 다룬다.

학습 시점 한계, 환각, 실시간 검증 부재, 엉뚱하거나 빠진 컨텍스트를 원인으로 짚고, 채팅 참여자와 채팅 변수, 모델 교체, 예시 제공, 스키마 파일 같은 대응법을 Go와 SQL 예시로 정리한다.

---

## 1. 핵심 요점

- Copilot은 열린 파일, 주석, 커서 앞뒤 코드, 저장소 인덱스에서 컨텍스트를 모은다. 인라인 제안은 속도를 위해 후보를 1~3개만 요청하고 캐시를 적극 쓴다.
- 채팅은 시간 여유가 있어서 채팅 변수와 채팅 참여자로 컨텍스트를 직접 가리킬 수 있다.
- 모델은 학습 시점까지만 최신이라 폐기된 코드가 나올 수 있다. 책의 예시는 Go 1.20에서 폐기된 rand.Seed다.
- 환각은 없는 식별자나 함수뿐 아니라 틀린 생성 데이터로도 나타난다. Copilot은 생성한 코드를 실행하거나 데이터를 대조해 확인하지 않으므로 테스트와 코드 리뷰가 필요하다.
- 열린 파일이 엉뚱하거나 아예 없으면 답이 어긋나거나 일반론으로 흐른다. @workspace, #file로 범위를 직접 지정한다.
- 더 최신 모델로 바꾸면 해결되는 경우가 있다. 다만 일부 고급 모델은 프리미엄 요청으로 집계된다.
- 모델을 못 바꿀 때는 최신 코드 예시를 파일이나 프롬프트에 임시로 넣어 가르친다. 스키마 파일 같은 정의를 열어 두면 프로젝트에 맞는 제안이 나온다.
- 파일을 추가하거나 고쳤다면 저장한 뒤에 질문한다. Copilot은 저장된 내용을 참고한다.
