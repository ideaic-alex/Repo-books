# 스키마로 컨텍스트 보강하기

폐기된 기능이나 빠진 신기능을 보완하는 것 말고도, 프로젝트와 관련된 정의나 코딩 예시를 더 자세히 주면 Copilot이 더 충실하고 풍부하며 관련성 높은 제안을 만든다. 책은 이를 SQL 예시로 보여 준다.

이 문서는 대학 수강 관리 시스템에서 같은 요청을 컨텍스트 없이 한 경우와 스키마 파일을 열어 둔 경우를 비교하고, 파일을 어떻게 넣을지에 대한 요령을 정리한다.

---

## 1. 컨텍스트가 없을 때

대학의 강좌, 학생, 강사, 수강 등록 등을 관리하는 시스템을 만든다고 하자. 아무 컨텍스트 없이 에디터에 SQL 주석으로 이렇게 요청한다.

```sql
-- define a select statement to get all the students enrolled in a course
```

이 지시만 있고 다른 컨텍스트가 없으면 Copilot은 합리적이고 일반적인 쿼리를 만든다.

```sql
SELECT * FROM students WHERE course_id = 1;
```

이 쿼리에 잘못은 없다. 제공된 컨텍스트가 적었던 만큼 유효한 결과다. 스키마에 맞는 테이블과 필드 이름이 있다면 이대로 동작할 수도 있다.

## 2. 이미 있는 데이터베이스에 맞추고 싶을 때

이미 테이블과 데이터 등을 갖춘 더 큰 데이터베이스가 있다면, Copilot이 이미 정의한 요소를 쓰는 제안을 내놓기를 원할 것이다. Copilot은 데이터 저장소, 인덱스, 저장 프로시저를 동적으로 살펴볼 수 없다. 대신 스키마 정의라는 정적인 표현을 줄 수 있다. 원래의 SQL 정의가 있으면 그것을, 없으면 기존 내용에서 스키마를 덤프한 것을 쓴다.

이 파일에는 작업 중인 영역의 구체적인 테이블과 관련 필드, 키 등이 정의되어 있다. 이 파일을 워크스페이스에 추가해 프로젝트의 일부로 만들고 에디터에서 연다. 그러면 Copilot이 참고할 컨텍스트가 늘어난다. 같은 주석을 다시 쓰면 이번에는 이런 결과가 나온다.

```sql
SELECT students.first_name, students.last_name, students.email,
 students.phone, students.city, students.state, students.zip_code
FROM courses.students
JOIN courses.registrations
ON students.student_id = registrations.student_id
JOIN courses.registration_items
ON registrations.registration_id = registration_items.registration_id
WHERE registration_items.course_id = 1;
```

## 3. 결과 비교

| 항목 | 스키마 없이 | 스키마 파일을 열어 둔 뒤 |
| --- | --- | --- |
| 조회 열 | `SELECT *` | first_name, last_name, email, phone, city, state, zip_code를 지정 |
| 사용한 테이블 | students 하나 | students, registrations, registration_items를 조인 |
| 조건 | `course_id = 1` | `registration_items.course_id = 1` |
| 테이블과 필드 이름 | 추측한 일반 이름 | 스키마 파일의 실제 이름 |

스키마를 읽은 Copilot은 훨씬 풍부하고 자세하며 관련성 높은 쿼리를 만들었고, 다른 파일에 있던 구체적인 테이블과 필드 이름을 썼다. 핵심은 Copilot이 IDE에서 사용 중인 컨텍스트를 코드 생성에서 우선한다는 것이다. 이 방식은 모델의 학습 데이터에만 의존할 때보다 훨씬 쓸모 있고 적절한 제안과 답을 얻는 간단하고 유용한 전략이다.

## 4. 파일을 넣는 요령

SQL 예시에서는 파일을 워크스페이스의 추가 파일로 넣고 IDE에서 열었다. 앞의 폐기 사례처럼 내용을 활성 파일에 붙여 넣지는 않았다. 붙여 넣어도 되지만 이번에는 필요하지 않았다.

| 방식 | 설명 |
| --- | --- |
| 같은 수준의 파일(peer file)로 열기 | 먼저 이 방법을 시도한다 |
| 활성 파일에 직접 넣기 | 기대한 결과가 나오지 않을 때 쓴다 |
| 채팅에 예시를 붙여 넣기 | 예시의 범위가 채팅에 맞을 때 쓴다 |

> 저장을 꼭 하자: IDE에 새 파일을 추가하거나 기존 파일에 내용을 넣었다면, Copilot에 질문하거나 프롬프트를 쓰기 전에 변경을 저장해야 한다. Copilot은 워크스페이스에 저장된 내용을 컨텍스트로 삼는다.

이런 풍부한 컨텍스트를 미리 주면 제안이나 코드 완성이 좋아진다. 위의 스키마 파일 같은 것을 만드는 데 시간이 더 걸릴 수 있다. 하지만 필요한 수준의 구체성에 이르도록 Copilot의 제안을 고치는 시간과 노력을 아낄 수 있으니 그만한 가치가 있다.

## 5. 그 밖의 방향 잡기 요령

다른 전략이 통하지 않고 기대와 다른 결과가 나올 때 쓸 만한 요령이 몇 가지 더 있다.

- 좋은 결과가 안 나오면 인라인 제안에서 채팅 프롬프트로(또는 반대로) 바꿔 본다.
- 생성된 코드가 계속 틀리면 일부(스텁)를 직접 쓴 뒤 Copilot이 이어서 완성하게 해 본다.
- 의도가 분명한 지시 주석을 더 구체적으로 달아 생성 방향을 잡는다.
- 코드를 임시로 별도 창에 분리해 방해가 되는 다른 컨텍스트를 없앤다.
- 생성시키는 대신 설명하도록 Copilot에게 요청한다.
- 파일 이름이나 파일 형식을 바꿔 컨텍스트를 갱신한다.
