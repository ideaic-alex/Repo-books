# IDE에서 Copilot 설정하기

Copilot을 설치하고 나면 내 작업 방식에 맞게 동작을 조절할 수 있다. 이 문서는 VS Code에서 Copilot을 다루는 컨트롤(하단 상태 표시줄, 상단 아이콘), 코드 완성 설정 메뉴, 설정 화면, 설정 파일 편집 방법을 정리한다. VS Code에 Copilot 확장을 설치하고 필요하면 인증을 마친 상태가 전제다.

---

## 1. 하단 상태 표시줄의 컨트롤

IDE 맨 아래 상태 표시줄에 Copilot 컨트롤이 있다. 이것을 누르면 코드 완성 제안을 모든 파일에 대해, 또는 지금 작업 중인 파일 형식에 대해서만 빠르게 끌 수 있다(그림 2-26). 책의 예시에서는 활성 파일이 파이썬이라서 파이썬 파일에 대해서만 끄는 옵션이 나왔다.

### 코드 완성을 왜 끄나

코드 완성은 Copilot의 기본 임무인데도 끄는 옵션이 있는 이유는 제안이 거슬리거나 방해가 될 때가 있기 때문이다. 급하게 많은 코드를 입력하거나, 이미 아는 코드를 만드는 데 집중하고 싶을 때는 제안이 뜨는 것이 오히려 산만하다.

이 대화상자의 Next Edit Suggestions 옵션은 일종의 자동 일괄 편집 기능이며 4장에서 다룬다.

---

## 2. 상단 Copilot 아이콘

IDE 상단에도 Copilot 아이콘이 있다(그림 2-27). 여기서는 다음을 할 수 있다.

| 메뉴 항목 | 하는 일 |
|---|---|
| 채팅 옵션 | 여러 채팅 인터페이스를 연다(3장에서 설명) |
| Manage Copilot | 로그인되어 있다면 GitHub의 내 Copilot 계정 설정 페이지로 이동 |
| Configure Code Completions | 코드 완성을 사용자화하는 옵션 모음을 연다(그림 2-28) |

---

## 3. Configure Code Completions의 옵션

일부는 이름만으로 뜻을 알 수 있다. 책은 그중 헷갈리기 쉬운 세 가지를 설명한다.

| 옵션 | 하는 일 | 참고 |
|---|---|---|
| Open Completions Panel | 현재 활성 코드에 대한 대안 완성 목록을 연다 | 앞서 `Ctrl-Enter`로 호출한 기능과 같다 |
| Change Completions Model | 기본값 말고 다른 AI 모델이 있으면 고를 수 있다 | 코드 완성에 쓰는 모델만 바뀌고 채팅 모델은 안 바뀐다 |
| Disable Completions | 코드 완성 제안을 켜고 끈다 | 앞의 하단 컨트롤의 옵션과 비슷하다 |

읽는 법: 모델을 바꿨다고 해서 채팅 답이 달라지지는 않는다. 완성용 모델과 채팅용 모델은 별개로 설정한다.

---

## 4. 설정 화면

Edit Settings 옵션은 더 깊은 설정으로 가는 입구다. 누르면 IDE 설정이 "GitHub Copilot"으로 검색된 상태로 열린다. 메인 화면의 톱니바퀴 아이콘을 눌러 설정에서 직접 "GitHub Copilot"을 검색해도 같다.

검색 결과 화면(그림 2-29)에는 왼쪽에 편집기, 기능, 그리고 더 넓은 확장 그룹의 하위 범주가 보인다. 확장 그룹에는 GitHub Copilot과 관련된 모든 확장의 설정이 모여 있다.

### 사용자 설정과 워크스페이스 설정

| 구분 | 적용 범위 |
|---|---|
| 사용자(User) 설정 | 워크스페이스와 관계없이 내 계정 전체에 적용 |
| 워크스페이스(Workspace) 설정 | 현재 작업 환경에만 적용 |

왼쪽 위의 탭으로 두 범주를 오간다.

### Experimental과 Preview 표시

설정을 파고들면 Experimental이나 Preview가 붙은 항목이 있다. 둘 다 아직 정식 출시 전이라는 뜻이지만 정도가 다르다.

| 표시 | 의미 |
|---|---|
| Preview | 정식 출시에 더 가깝다. 사용자가 선택하면 공개 테스트와 피드백 대상이 된다 |
| Experimental | 초기 구상 단계라 내 책임하에 써야 한다. 계속 진행되지 않거나 정식 출시 전에 크게 바뀔 수 있다 |

---

## 5. 설정 파일 바로 열기

설정이 `settings.json` 같은 파일에 저장될 수 있다면 대개 그 파일을 고치는 링크가 있다. 예를 들어 앞에서 본 사용자 정의 리뷰 규칙을 검색하면 화면 아래에 `settings.json`을 직접 편집하는 링크가 나온다(그림 2-30). 누르면 해당 파일이 열리고 초기 내용 제안이 함께 나온다(그림 2-31).

다른 IDE에도 Copilot 설정을 찾아 바꾸는 비슷한 방법이 있다. 책은 GitHub의 Copilot 블로그를 지켜보며 새로 생기거나 바뀐 설정을 확인하라고 권한다. 가끔 직접 옵션을 둘러보는 것도 좋은 습관이다. 몰랐던 설정이 눈에 띌 때가 있다.
