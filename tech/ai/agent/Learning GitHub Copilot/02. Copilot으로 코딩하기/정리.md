# 정리

이 문서는 2장에서 다룬 인라인 방식의 Copilot 사용법을 한곳에 모은다. 어떤 기능을 어디서 쓰는지, 제안의 품질은 무엇이 좌우하는지, 다음 장은 무엇을 다루는지를 짚는다.

---

## 1. 장 전체 요약

2장은 코드를 쓰는 중에 Copilot과 직접 소통하는 가장 빠른 방법을 다뤘다.

- 에디터에서 치는 동안 Copilot이 빠른 제안을 준다. 제안은 완성도와 맞는 정도를 보고 판단해야 한다. 적합도는 제각각이지만 시간을 아끼고 코드와 생각을 시작하는 데 도움이 된다.
- 제안의 품질은 Copilot이 현재 환경에서 참고할 컨텍스트의 양에 크게 좌우된다. 컨텍스트에는 파일 이름, 기존 코드, 다른 파일, 주석, 로컬 인덱스가 포함된다.
- 주석으로 Copilot이 할 일을 설명할 수 있고, 질문을 던지면 주석으로 답을 받는다.
- Copilot은 코드를 리뷰해 문제를 찾고 개선을 제안한다. 사용자 정의 지침 목록을 가리켜 두면 리뷰가 노리는 대상을 바꿀 수 있다.
- 기본 기능은 그대로 쓸 만하지만 동작을 조정하거나 기능을 켜고 끄고 싶을 때가 있다. IDE의 Copilot 컨트롤로 제한적인 변경을 하거나, 설정에서 개별 옵션을 검색해 바꿀 수 있다. 실험(Experimental)과 미리보기(Preview) 옵션도 포함된다.

## 2. 기능별 한눈에 보기

| 기능 | 호출 방법 | 메모 |
|---|---|---|
| 인라인 제안 수락 | Tab | 한 단어씩은 막대에 안내된 키 조합 |
| 제안 돌려 보기 | 막대의 `<`, `>` | `< 1/2 >`는 2개 중 1번이라는 뜻 |
| 대안 목록 | `Ctrl-Enter` | 수락 전에 쓰는 것이 가장 좋다 |
| 주석으로 지시 | `# create a function ...` | 코드가 아닌 지시의 답은 주석으로 온다 |
| 주석으로 질문 | `# What does the code above do?` | `q:`를 쓰면 `a:`로 답한다 |
| 코드 리뷰 | 우클릭 > Copilot > Review and Comment | 기본은 중요해 보이는 문제만 알려 준다 |
| 리뷰 규칙 | `settings.json` 또는 `.github/copilot-review-guidelines.md` | 파일로 지정하려면 `file:` 키 |
| 커밋 메시지 | 소스 제어 입력란 끝의 스파클 아이콘 | 사용자 지침도 설정 가능 |
| 명령 팔레트 | `Meta-P` 또는 `F1` | `Copilot`을 입력해 전체 명령 확인 |
| 완성 끄기 | 하단 상태 표시줄 컨트롤 | 전체 또는 현재 파일 형식만 |
