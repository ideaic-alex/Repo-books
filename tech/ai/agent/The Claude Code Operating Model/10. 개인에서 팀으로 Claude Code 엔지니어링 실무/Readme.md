# 개인에서 팀으로 Claude Code 엔지니어링 실무

이 장은 책의 마지막 장으로, Claude Code를 도입한 팀이 석 달 만에 맞닥뜨린 문제(청구서 폭등, 들쭉날쭉한 CLAUDE.md, 추적할 수 없는 블랙박스)를 풀어 가며 도구를 엔지니어링으로 바꾸는 법을 다룬다. 비용 통제, 디버깅, 보안, 대규모 코드베이스, 프롬프트 엔지니어링, 팀 도입의 여섯 주제를 차례로 보고, SDD 생태계와 아홉 가지 핵심 메커니즘의 오케스트레이션으로 책 전체를 묶는다.

원서의 그림 두 개(CLAUDE.md 6단계 로딩 순서, 온보딩 교육 프로그램)는 추출본에 내용이 없어 본문에 그 사실을 밝혔다.

---

## 1. 핵심 요점

- 비용은 토큰량 곱하기 모델 단가다. 모델 티어링, 서브에이전트 격리, 200줄 아래 CLAUDE.md, 캐싱, `--max-budget-usd`로 통제하고, 진짜 비용은 API 비용에 사람 시간을 더한 값이다.
- 디버깅 도구는 `--debug`, `stream-json`, PostToolUse 감사 로그, 세션 jsonl과 `--resume`이며, 이상 동작은 컨텍스트 누락, 지침 충돌, 권한 부족 순으로 의심한다.
- 보안은 최소 권한이 바닥이다. 권한 모드 5종, deny→ask→allow, `.claudeignore`와 `permissions.deny`의 이중 방어, 훅 스캔, MCP 서버 버전 고정, API 키 4겹 보호를 쓴다.
- 대형 코드베이스는 계층형 CLAUDE.md, `.claude/rules/`, 검색 유도, Explore와 모듈별 서브에이전트, `/compact`로 컨텍스트 한계를 넘는다.
- CLAUDE.md는 짧게 쓰고 수량화, 예시, 경계 명시, 단계별 확인으로 표현한다.
- 팀 도입은 공유 설정, CLAUDE.md의 PR 거버넌스, managed settings, 개인 탐색에서 조직 확대까지 4단계 로드맵, 온보딩 교육으로 이뤄진다.
- SDD 생태계는 4계층이며, 아홉 가지 메커니즘은 CLAUDE.md를 초석으로 각자의 층에서 맞물린다.
