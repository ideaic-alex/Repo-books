# 비용 통제와 토큰 경제

10장은 책의 마지막 장으로, 도구를 아는 것과 도구를 엔지니어링으로 운용하는 것이 다르다는 이야기로 시작한다. 팀이 Claude Code를 전면 도입한 지 석 달이 지났다. 처음에는 마법 같았다. 이틀 걸리던 기능이 하루에 끝나고 코드 리뷰에서 잡히는 낮은 수준의 오류도 크게 줄었다. 그러나 석 달이 지나자 문제가 드러났다. 청구서는 예상의 세 배였고(한 엔지니어가 데이터베이스 전체의 과거 로그를 분석하느라 한 세션을 거의 다섯 시간 돌렸다), 사람마다 CLAUDE.md 수준이 달라 신입이 길을 잃었으며, Claude가 틀린 결정을 해도 추적할 방법이 없는 블랙박스였다. CTO의 말은 이렇다. 도구가 있다는 것과 그에 걸맞은 엔지니어링 실무가 있다는 것은 전혀 다른 일이다.

Kage는 여섯 낱말을 적었다. 비용, 디버깅, 보안, 규모, 지침, 협업. 이 장은 이 여섯 가지를 차례로 다룬다. 이 문서는 첫 번째인 비용이다.

---

## 1. 가격 구조 이해하기

Claude Code의 API 비용은 토큰(모델이 처리하는 글자 조각 단위) 사용량으로 정해진다. 호출마다 보낸 프롬프트 토큰과 생성된 응답 토큰의 합에 모델별 단가를 곱한다. 사용자 요청 하나 뒤에서 파일 읽기, 검색, 추론, 코드 생성, 재검증 같은 API 호출이 열 번, 수십 번 일어날 수 있고 각각 과금된다.

2025년 말 기준 가격은 다음과 같다(원서 표 10.1, 단위는 100만 토큰당 미국 달러).

| 모델 | 입력 | 출력 | 캐시 쓰기 | 캐시 읽기 |
|---|---|---|---|---|
| Haiku 4.5 | 1.00 | 5.00 | 1.25 | 0.10 |
| Sonnet 4.6 | 3.00 | 15.00 | 3.75 | 0.30 |
| Opus 4.6 | 5.00 | 25.00 | 6.25 | 0.50 |

가격은 주기적으로 바뀌는 시점 값이므로 최신 값은 Anthropic 공식 가격 페이지(anthropic.com/pricing)를 확인하라고 원서가 거듭 당부한다. 표에서 읽어낼 세 가지는 다음과 같다.

- 출력이 입력보다 훨씬 비싸다. Opus는 출력 단가가 입력의 5배다. 그래서 입력을 줄이는 것보다 Claude의 출력 길이를 엄격히 제한하는 쪽이 비용을 더 크게 줄인다.
- 모델 간 가격 차이가 크다. Opus는 Haiku의 5배다. 모든 작업에 가장 강한 모델이 필요하지 않다.
- 캐시 읽기는 일반 입력 가격의 10분의 1이다. 캐시 적중률을 높일수록 절약된다.

### 1-1. 놓치기 쉬운 비용: 사고(thinking)

사고도 비용을 만든다. 이 장 가격표의 모델에서 쓸 손잡이는 노력 수준(effort level)이다. 기본값이 high이고 `/effort`나 `/config`로 바꾼다. 깊은 추론이 필요 없는 일에서 사고 비용을 줄이는 가장 직접적인 방법이다. 이 조절 수단은 인쇄보다 빨리 바뀌므로 자동화에 고정 토큰 예산을 넣기 전에 최신 모델 설정 문서를 확인하라는 당부가 붙어 있다. 깊은 추론이 필요 없는 경우 환경 변수 `MAX_THINKING_TOKENS=8000`으로 사고 예산을 제한해 비용을 크게 줄일 수도 있다.

## 2. 모델 선택 전략

작업 복잡도에 맞춘 단계별 전략이다(원서 표 10.2).

| 작업 | 추천 모델 | 이유 |
|---|---|---|
| 포맷팅, 이름 바꾸기 | Haiku | 규칙이 분명, 복잡한 추론 불필요 |
| 문서 생성, 간단한 테스트 | Haiku | 정해진 패턴, 비용 최적 |
| 기능 개발, 버그 수정 | Sonnet | 문맥 이해가 필요하나 범위가 한정적 |
| 코드 리뷰, 리팩터링 | Sonnet | 전문적 판단이 필요하나 따를 기준이 있다 |
| 아키텍처 설계, 보안 감사 | Opus | 깊은 사고와 전체적 시각 필요 |
| 어려운 문제 해결, 모듈 간 리팩터링 | Opus | 창의적 사고와 종합 추론 필요 |

헤드리스 모드에서는 `--model`로 모델을 지정한다. 단순 작업은 Haiku에 예산을 아주 낮게, 복잡한 작업은 Opus에 더 높은 예산을 준다.

```
claude -p "Check the variable names in this function" --model claude-haiku-4-5 --max-budget-usd 0.05
claude -p "Analyze the design issues of the entire payment system" --model claude-opus-4-6 --max-budget-usd 2.00
```

원서는 `--max-budget-usd`를 폭주를 막는 하드 리밋이라고 설명하며, CI/CD 자동화에서는 표준 설정으로 강제하라고 한다. 스크립트 논리가 잘못되어 무한 루프나 무한 재귀 호출이 생기면 하룻밤에 수백, 수천 달러가 나갈 수 있기 때문이다. 참고(노트 작성자): 8장 Agent SDK의 `max_budget_usd`는 "턴 사이에 검사하는 소프트 한도"로 설명되어 있다. 두 장의 표현이 다르므로, 한도에 닿는 시점에서 진행 중인 호출이 조금 더 비용을 쓸 수 있다고 여유를 두고 설정하는 편이 안전하다.

## 3. 컨텍스트 관리가 비용 통제의 핵심

서브에이전트와 컨텍스트 격리를 거듭 강조하는 이유에는 순수하게 경제적인 동기가 있다. Claude API는 무상태라서 호출마다 전체 대화 이력을 함께 보내야 한다. 5,000줄짜리 로그 파일을 메인 대화에 올리면 그 5,000줄이 이후 모든 API 호출에 다시 실린다. Claude가 판단할 때마다 그 로그 값을 또 내는 셈이다. 로그 분석을 서브에이전트에 맡기면 방대한 내용은 하위 프로세스 컨텍스트에 갇히고 메인 대화는 핵심 결론 몇 줄만 받는다. 서브에이전트는 사치스러운 부가 기능이 아니라 중요한 경제적 결정 도구다.

같은 논리가 CLAUDE.md 다듬기에도 적용된다. 공식 지침은 파일당 200줄 아래를 목표로 한다. 더 길면 컨텍스트를 더 먹고 준수도가 떨어진다. 그 안의 모든 줄은 세션의 모든 요청마다 비용을 낸다.

## 4. 프롬프트 캐싱

Claude Code는 프롬프트 캐싱(prompt caching, 반복되는 입력 앞부분을 저장해 두었다가 싸게 재사용하는 기능)을 기본으로 켠다. 현재 요청의 입력 접두부(보통 시스템 프롬프트, CLAUDE.md, 도구 정의)가 이전 요청과 같으면 그 부분을 캐시에서 일반 가격의 10분의 1로 재사용한다. 적중률을 높이는 전략은 세 가지다.

| 전략 | 이유 |
|---|---|
| CLAUDE.md를 안정적으로 유지 | 설정 파일이 자주 바뀌면 접두부가 달라져 캐시가 무효화된다 |
| 한 세션에 작업을 모음 | 관련 작업을 같은 세션에서 끝내고 작은 작업마다 새 세션을 열지 않는다 |
| 기존 세션을 이어 감 | `--resume`, `--continue`로 세션을 확장하고 매번 처음부터 시작하지 않는다 |

## 5. 비용 모니터링

헤드리스 모드의 JSON 출력은 정확한 비용 데이터를 주므로 자동 수집이 쉽다.

```
result=$(claude -p "review this PR" --output-format json)
cost=$(echo "$result" | jq -r '.total_cost_usd')
echo "PR_REVIEW_COST: $cost" >> /var/log/claude-costs.log
```

대화형 모드에서는 `/cost`를 입력하면 현재 세션의 상세 비용 통계가 나온다. 원서 예시 출력은 총 비용 0.55달러, API 시간 6분 19.7초, 벽시계 시간 6시간 33분 10.2초다. 이런 데이터를 팀 모니터링 대시보드에 모으면 프로젝트별, 엔지니어별, 작업 종류별 비용 분포가 보여 세밀한 자원 관리와 예산 통제가 가능하다.

## 6. 비용 통제의 목표는 절약이 아니라 효율 (Kage's notes)

Opus로 5분이면 끝날 일을 Haiku로 30분 동안 반복 디버깅한다면, Opus에 더 쓴 돈은 충분히 값어치가 있다. 진짜 비용은 API 비용에 사람 시간 비용을 더한 것이다. 시급 50달러 기준 원서의 계산은 다음과 같다.

| 방안 | 사람 시간 비용 | API 비용 | 합계 |
|---|---|---|---|
| Opus | 5분 × 50달러/시 = 4.17달러 | 약 1.33달러 | 약 5.50달러 |
| Haiku | 30분 × 50달러/시 = 25.00달러 | 약 0.03달러 | 약 25.03달러 |

결론은 Opus를 고르라는 것이다. 참고(노트 작성자): 원서 본문 문장은 "추가로 쓴 0.5달러"라고 하지만 표의 계산은 API 비용 약 1.33달러 대 0.03달러로, 두 수치가 어긋난다. 여기서는 계산 부분을 따랐다. 또 이 공식의 균형점은 팀마다 달라서 원서 맺음 질문으로도 남겨져 있다.

## 7. 핵심 정리

- 비용은 토큰량 곱하기 단가이며, 요청 하나 뒤에 API 호출이 여러 번 있다.
- 출력이 입력보다 비싸고, 모델 차이가 5배이며, 캐시 읽기는 입력의 10분의 1이다.
- 작업 난이도에 맞춰 Haiku, Sonnet, Opus를 나눠 쓰고 사고 노력 수준과 `MAX_THINKING_TOKENS`로 사고 비용을 줄인다.
- 무거운 출력은 서브에이전트에 격리하고 CLAUDE.md는 200줄 아래로 유지한다.
- CI에는 `--max-budget-usd`를 표준으로 두고, `total_cost_usd`와 `/cost`로 계측한다.
- 목표는 최저 비용이 아니라 사람 시간까지 합친 최저 총비용이다.
