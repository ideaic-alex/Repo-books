# 디버깅 블랙박스 열어 보기

"Claude는 왜 그렇게 했지?"는 AI 도구를 쓸 때 가장 답답한 질문이다. 같은 파일을 반복해서 읽거나, 시키지 않은 작업을 하거나, 출력도 없이 토큰만 잔뜩 쓰는 루프에 빠질 때, 중단점을 걸고 호출 스택과 변수 값을 보는 전통적 디버깅 감각은 거의 통하지 않는다. 그러나 이 블랙박스가 완전히 불투명한 것은 아니다. Claude Code는 여러 층의 디버깅 도구를 제공한다.

이 문서는 `--debug`, `stream-json`, PostToolUse 훅 감사 로그, 세션 보관 파일과 `--resume`, 그리고 이상 동작을 진단하는 세 가지 원인 분류를 정리한다.

---

## 1. --debug 모드: 실행 과정의 X선

`--debug`는 가장 기본이 되는 디버깅 도구다. Claude 실행 과정을 X선으로 찍듯이 매우 자세한 런타임 정보를 출력한다. 내용은 매 턴의 전체 컨텍스트, 도구 호출마다의 입력 매개변수와 반환 결과, 실시간 토큰 소비 통계, API 요청과 응답의 시점이다.

```
claude --debug -p "List the files in the current directory"
```

원서의 출력 예는 줄마다 `[DEBUG]`가 붙은 구조화 로그다. 세션 시작, 모델(`claude-sonnet-4-6`), `Turn 1`, 사용자 메시지, 토큰(입력 150, 출력 0), 도구 호출(`Glob`, 패턴 `*`, 경로 `.`), 도구 결과(파일 목록, 45ms), 턴 완료, 총 토큰 500, 추정 비용 0.0015달러 순이다. Claude의 사고와 행동 궤적이 그대로 복원된다.

### 1-1. 카테고리 필터링과 상세 모드 토글

- API 요청과 훅 실행 관련 로그만 보려면 `claude --debug "api,hooks"`
- 통계 신호와 파일 작업 로그를 숨기고 핵심 논리에 집중하려면 `claude --debug "!statsig,!file"`
- 대화형 세션에서 이상이 생기면 재시작이나 재실행 없이 `Ctrl + O`로 상세 모드(verbose mode)를 언제든 켜고 끈다. 켜면 훅 실행 진행, 도구 호출의 상세 매개변수와 반환 정보, 모델의 현재 사고 과정을 대화 중에 실시간으로 볼 수 있다.

## 2. stream-json: 사고의 흐름을 실시간으로

헤드리스 모드에서 `--output-format stream-json`은 Claude의 의사결정 과정을 기계가 읽을 수 있는 데이터로 바꾸는 열쇠다. 각 단계의 사고 과정과 도구 호출 내용을 NDJSON(줄바꿈으로 구분한 JSON)으로 실시간 내보낸다.

```
claude -p "Analyze the architecture issues in the src/ directory" --output-format stream-json | jq '.'
```

`--include-partial-messages`를 더하면 아직 생성 중인 텍스트 조각까지 포함한 더 잘게 쪼갠 스트리밍 데이터를 얻는다. "Claude가 왜 갑자기 멈췄나", "같은 내용을 무한 반복 생성하며 막힌 것 아닌가" 같은 의문에 특히 유용하다.

## 3. PostToolUse 훅: 지속되는 감사 로그

일회성 디버그 출력이 아니라 영속적이고 추적 가능한 감사 기록이 필요하면 PostToolUse 훅이 낫다. 두 단계다.

1. `.claude/hooks/audit-log.sh`를 만든다. 표준 입력 JSON에서 `jq`로 `.tool_name`을 꺼내고, UTC 시각과 도구 이름과 `.tool_input`(압축 JSON)을 `|`로 이어 `.claude/audit.log`에 덧붙이고 `exit 0` 한다.
2. `.claude/settings.json`의 `hooks.PostToolUse`에 matcher `"*"`와 `type: "command"`, 명령 `bash .claude/hooks/audit-log.sh`를 등록한다.

```bash
INPUT=$(cat)
TOOL=$(echo "$INPUT" | jq -r '.tool_name')
TIMESTAMP=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
echo "$TIMESTAMP | $TOOL | $(echo "$INPUT" | jq -c '.tool_input')" >> .claude/audit.log
exit 0
```

설정이 끝나면 Claude가 호출하는 모든 도구와 매개변수가 자동으로 기록된다. 사후 분석 때 이 로그로 Claude의 행동 순서를 복원할 수 있다. 원서 코드의 `echo` 줄은 지면 때문에 줄바꿈되어 있어 한 줄로 이어 복원했고, 설정 JSON의 명령 문자열도 줄바꿈이 끼어 있어 한 줄로 읽었다.

## 4. 세션 보관과 시점 복원 디버깅

Claude Code는 모든 세션 기록을 `~/.claude/projects/{project}/{sessionId}.jsonl`에 저장한다. 서브에이전트가 있으면 그들의 독립 기록은 `subagents/agent-{agentId}.jsonl`에 남는다. 이 파일들은 단순한 대화 이력이 아니라 전체 대화 컨텍스트, 도구 호출 상세, 실행 결과를 담은 권위 있는 데이터 원천이어서 사후 심층 분석의 단단한 기반이 된다.

`--resume`과 `--continue`는 작업을 편하게 재개하는 도구일 뿐 아니라 강력한 디버깅 도구다. 자동화 과정에서 오류가 났다면 `claude --resume <session-id>`로 문제가 일어난 순간으로 정확히 "시간을 되감을" 수 있다. 그 시점에 Claude가 받은 정보를 그대로 살피고, 그때 가능한 정보로 Claude가 한 추론과 도구 호출 논리를 되짚을 수 있다.

## 5. Claude의 이상 동작 진단

이상 동작의 대다수는 세 원인 중 하나로 거슬러 올라간다. 이 순서로 조사하면 대개 빠르게 뿌리에 닿는다.

| 원인 | 전형적 증상 | 진단 방법 | 해결 |
|---|---|---|---|
| 1. 컨텍스트 누락: 과업에 필요한 핵심 정보에 접근하지 못함 | 같은 파일 반복 읽기, 모호한 답, 근거가 분명히 부족 | `--debug`로 Claude가 실제로 받은 파일 내용과 컨텍스트 범위 확인 | CLAUDE.md에 프로젝트 탐색 안내를 분명히 쓰거나, 프롬프트에 필요한 정보와 코드 조각을 직접 제공 |
| 2. 지침 충돌: CLAUDE.md에 상충하는 규칙이 둘 이상 | 두 모드 사이를 오가거나, 정해진 규칙이 그냥 무시됨 | CLAUDE.md의 모든 규칙을 전수 검토해 논리 충돌 지점 찾기 | 우선순위를 명확히. 예: "규칙 X와 Y가 충돌하면 X가 우선한다" |
| 3. 도구 권한 부족: 작업을 하려는데 필요한 도구나 승인이 없음 | 특정 작업이 반복 실패, 부적절한 대체 도구로 억지로 해결 | `--allowedTools` 설정과 훅의 차단 로그로 막힌 요청 확인 | 필요한 도구 권한 부여, 또는 현재 가능한 대안을 쓰도록 작업 설명 조정 |

## 6. 디버깅의 근본 차이 (Kage's notes)

전통 코드는 결정적이다. 같은 입력은 항상 같은 출력을 낸다. 반면 Claude의 행동은 확률적이어서 같은 프롬프트도 맥락에 따라 전혀 다른 응답을 낼 수 있다. 그래서 "버그 재현" 접근으로는 풀 수 없다. 로그 분석, 감사 추적 검토, CLAUDE.md 규칙 점검으로 원인을 추정해야 한다.

---

## 7. 핵심 정리

- `--debug`는 컨텍스트, 도구 입출력, 토큰, 시점을 보여 주며 `"api,hooks"`나 `"!statsig,!file"`로 거르고, `Ctrl + O`로 상세 모드를 토글한다.
- `--output-format stream-json`(NDJSON)과 `--include-partial-messages`로 사고 흐름을 기계 가독 형태로 본다.
- 영속적 추적은 PostToolUse 훅 감사 로그로, 원본 증거는 `~/.claude/projects/` 아래 세션 jsonl로 남긴다.
- 진단 순서는 컨텍스트 누락, 지침 충돌, 도구 권한 부족이다.
- 확률적 동작이므로 재현이 아니라 로그와 규칙 점검으로 추론한다.
