# 요약과 핵심 개념

8장은 Claude Code를 터미널 도구에서 애플리케이션 부품으로 바꾸는 Agent SDK를 다뤘다. 두 축은 입구인 `query` 함수와 설정 객체인 `ClaudeAgentOptions`다. 그 위에 메시지 스트림 해석, 세션 이어 가기와 분기, 사용자 정의 도구, SDK 훅과 4계층 보안, 구조화된 출력이 쌓인다. 이 문서는 전체 흐름과 용어를 되짚는다.

원서의 요약은 이렇게 이어진다. `query`는 헤드리스의 `claude -p`와 기능적으로 같지만 비동기 제너레이터로 메시지 스트림을 돌려줘 Claude의 각 단계를 실시간으로 처리할 수 있다. 스트림은 system/init, assistant, user, result 네 종류다. `ClaudeAgentOptions`는 모델, 도구 권한, 권한 모드, 프롬프트, 세션, 구조화 출력을 아우르며, 명령줄 대비 핵심 장점은 동적 구성이다. 사용자 역할에 따라 권한 모드를 바꾸고, 작업에 따라 모델을 바꾸고, 앞 결과를 보고 다음 프롬프트를 다듬을 수 있다. 사용자 정의 도구는 `@tool`과 프로세스 내 MCP 서버로 만든다. 네 겹의 보안이 Claude가 앱 안에서 해야 할 일만 하게 한다. 다음 9장은 이런 능력을 포장하고 배포하는 플러그인 생태계다.

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | Agent SDK의 위치, 설치, `query` | 설정으로 쓰던 Claude Code를 코드로 호출. 스트림으로 실시간 처리 |
| 2 | 메시지 유형 | init, assistant, user, result와 `subtype`으로 상태 판독 |
| 3 | 옵션과 권한 모드 | 모델, 예산, 도구 허용 패턴, 네 가지 모드 |
| 4 | 세션과 사용자 정의 도구 | `resume`, `fork_session`, `@tool` 기반 프로세스 내 MCP 서버 |
| 5 | 훅과 4계층 보안, 구조화된 출력 | 실행 전후 가로채기, JSON Schema 강제 |
| 6 | 실습과 선택 기준 | 코드 분석 웹 서비스, SDK와 CLI 구분, 프로덕션 과제 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| Agent SDK | Claude Code 능력을 자기 앱에 넣는 Python/TypeScript 라이브러리 |
| `query()` | 무상태 비동기 제너레이터. 호출마다 새 세션 |
| `ClaudeSDKClient` | 세션을 유지하는 상태 있는 클라이언트 |
| `ClaudeAgentOptions` | 헤드리스 CLI 매개변수를 코드 객체로 바꾼 설정 |
| `system/init` | 첫 메시지. 모델, 도구, MCP 서버 상태 보고 |
| `result.subtype` | success, error_max_turns, error_max_budget_usd, error_during_execution, error_max_structured_output_retries |
| `max_budget_usd` | 턴 사이에 검사하는 소프트 비용 한도 |
| 권한 모드 | default, acceptEdits, plan, bypassPermissions |
| `resume` / `fork_session` | 세션 맥락 이어 가기 / 원본 보존 분기 |
| 사용자 정의 도구 | 프로세스 내 MCP 서버. 이름은 `mcp__서버__도구` |
| PreToolUse / PostToolUse | 도구 실행 전 차단 / 후 처리(포맷팅, 감사 로그) |
| 4계층 보안 | permission_mode, allowed_tools, canUseTool, PreToolUse 훅 |
| 구조화된 출력 | `output_format`으로 JSON Schema 강제. Pydantic/Zod와 함께 |

## 3. 자주 놓치는 점

- 옛 이름(`claude-code-sdk`, `ClaudeCodeOptions`)과 새 이름(`claude-agent-sdk`, `ClaudeAgentOptions`)을 혼동하지 않는다.
- 도구를 안 쓰면 init 메시지의 도구 목록부터 확인한다.
- `max_budget_usd`는 하드 스톱이 아니다. 진행 중인 턴은 끝까지 간다.
- Python에서 SessionStart/SessionEnd는 코드 콜백이 안 되고 설정 파일 셸 훅으로만 쓴다.
- `can_use_tool`(Python)과 `canUseTool`(TypeScript) 철자가 다르다.
- `bypassPermissions`는 컨테이너, 읽기 전용 파일 시스템, 네트워크 차단 같은 격리가 확실할 때만 쓴다.
- 삭제, 운영 쓰기, 메시지 발송, 결제처럼 되돌릴 수 없는 도구는 설명이 아니라 권한 게이트로 막는다.
- 원서 예제 코드에는 import 누락, 변수명 불일치(`entry`/`audit_entry`, `meta`) 등 인쇄 오류가 있어 복사 실행 전에 점검해야 한다.

## 4. 생각해 볼 질문 (원서 Questions for Reflection)

1. 요구사항을 입력하면 영향받는 코드 모듈 목록과 수정 난이도를 내놓는 사내 "코드 영향 분석" 도구를 만든다면 어떤 구조로 설계하고 Agent SDK의 어떤 기능을 강조할 것인가. 생각의 실마리는 이 장의 실습 서비스(스트리밍, plan 모드, 구조화된 출력, 비용 상한)다.
2. 사용자 정의 도구의 `description`은 Claude가 호출 여부를 정하기 전에 읽는 조작 안내서다. 좋은 설명은 도구가 하는 일, 쓸 때와 쓰지 말아야 할 때, 매개변수의 의미와 형식, 반환값, 부작용이나 선행 조건에 답해야 한다. 나쁜 설명의 비용은 작게는 잘못된 도구 호출, 형식이 틀린 인수, 써야 할 때 쓰지 않음이고, 크게는 호출하지 말았어야 할 호출이 만든 되돌릴 수 없는 부작용이다.
3. 4계층(권한 모드, 도구 허용 목록, canUseTool, PreToolUse 훅)의 관계는 무엇이며, 내 시나리오에서 필수와 생략 가능한 계층은 무엇인가. 힌트는 허용 목록과 권한 모드가 대부분의 무게를 진다는 원서의 설명이다.
