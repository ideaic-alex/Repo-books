# 요약과 핵심 개념

맺음말은 책 전체를 한 번 되돌아보는 짧은 글이다. 앞선 장들과 달리 원서에 Summary와 Reflection questions 절이 따로 없다. 이 문서는 맺음말의 흐름을 표로 정리하고, 책 전체의 논지를 한 줄로 거꾸로 훑어볼 수 있게 핵심 개념을 모았다.

맺음말의 논지는 이렇게 이어진다. 책의 구조가 곧 하니스이고, 업계의 초점은 모델에서 하니스로 옮겨 갔으며, 하니스의 핵심 루프인 에이전틱 루프에서 엔지니어가 설계하는 것은 행동이 아니라 경계 조건이다. 칼은 Claude Code, 소는 프로젝트이고 이 책은 뼈의 방향을 알려 준다.

---

## 1. 맺음말 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 책 구조의 우연한 발견 | 1~2장 맥락, 3~6장 도구, 7~9장 실행 환경, 10장 통제로 하니스와 겹침 |
| 2 | 패러다임 전환 | 경쟁 초점이 2025년 '모델'에서 2026년 '하니스'로 이동 |
| 3 | 오픈소스 증거 | Superpowers, Compound Engineering, grill-me, Trellis가 하니스 설계로 성과 |
| 4 | 부품과 조합 | 컴포넌트는 상수, 조합은 무한 |
| 5 | 에이전틱 루프 | 뫼비우스의 띠. 복잡한 행동이 루프에서 창발 |
| 6 | 경계 조건 설계 | 인지, 기억, 행동, 정지를 제약하는 것이 하니스 엔지니어링 |
| 7 | 더 읽을거리 | SDD in Practice, Designing AI Agents |
| 8 | 칼날의 비유 | 칼(Claude Code), 소(프로젝트), 뼈의 방향과 틈 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 하니스(harness) | 모델 바깥의 맥락, 도구, 실행 환경, 통제를 통틀어 부르는 말. 책의 장 구성 자체가 이 네 요소와 대응 |
| 패러다임 전환 | 경쟁이 '더 강한 모델'에서 '같은 모델을 더 잘 쓰는 하니스'로 옮겨 감 |
| 에이전틱 루프 | 추론, 도구 호출, 결과 피드백, 재추론의 순환. 복잡한 행동의 토대 |
| 창발(emergence) | 하드코딩하지 않아도 루프 구조에서 지능적 행동 패턴이 나타나는 현상 |
| 경계 조건 | 인지(도구 허용 목록), 기억(CLAUDE.md와 컨텍스트 관리), 행동(권한 시스템), 정지(max-turns와 훅) |
| 하니스 엔지니어링 | 행동을 프로그래밍하는 것이 아니라 행동을 제약하는 일 |
| 컴포넌트와 조합 | CLAUDE.md는 기억, 스킬은 지식, 서브에이전트는 작업 분해, 훅은 제약, MCP는 외부 연결 |
| 세 권의 축 | 하니스 엔지니어링(이 책), 사양 방법론(SDD in Practice), 설계 패턴 이론(Designing AI Agents) |
| 칼날의 길 | Claude Code는 칼, 프로젝트는 소. 도구보다 구조를 아는 숙련이 핵심 |

## 3. 자주 놓치는 점

- 맺음말의 '4요소'(맥락, 도구, 실행 환경, 통제)와 1장의 '4계층'(메모리, 확장, 통합, 프로그래밍)은 서로 다른 구분이다. 앞은 하니스의 구성 요소, 뒤는 Claude Code 기능을 쌓은 지도다.
- 오픈소스 사례의 별 개수와 설명(14개 스킬, 6줄 마크다운, 11개 플랫폼)은 저자가 쓴 시점의 수치이며 노트 작성자가 검증하지 않았다.
- SDD in Practice는 맺음말 시점에 중국어판만 있다고 적혀 있다. 영어로 읽을 수 있다고 오해하지 않는다.
- 맺음말은 새 기술 내용을 더하지 않는다. 앞 장의 메커니즘이 어떻게 한 줄로 이어지는지 정리하는 글이므로, 각 장을 읽은 뒤 돌아와서 읽을 때 가장 의미가 크다.
- 책의 비유가 포정해우와 닮았다는 설명은 노트 작성자의 보충이다. 원서는 출처를 따로 밝히지 않는다.
