# 04. 분할 정복: 서브에이전트와 작업 위임의 기술

이 장은 하나의 대화창에 로그, 테스트 출력, 코드 리뷰를 모두 쌓았을 때 Claude가 길을 잃는 컨텍스트 오염 문제에서 시작한다. 해법인 서브에이전트(독립된 컨텍스트 윈도를 가지고 위임받은 일을 하고 결론만 돌려주는 별도의 Claude 인스턴스)가 무엇인지, 마크다운 파일로 어떻게 정의하고 설정하는지, 어떤 모드로 쓰는지를 배운다.

이어서 스킬과 결합하는 두 방향, 토큰 소비의 경제학, 단일 책임과 벌크헤드와 MapReduce와 책임 연쇄 같은 소프트웨어 공학 개념과의 대응, 그리고 실무에서 놓치기 쉬운 세부 사항을 다룬다. 수치와 계산 예는 책의 가정을 따른다.

---

## 1. 핵심 요점

- 컨텍스트 윈도는 유한하고, 무관한 정보가 쌓이면 Claude는 잊는 것이 아니라 신호가 잡음에 묻힌다. 새 대화를 여는 것은 가치 있는 배경까지 버리는 거친 방법이다.
- 서브에이전트는 독립 컨텍스트, 제한된 도구, 명확한 작업 범위를 가진 인스턴스이고, 격리와 제약과 재사용이라는 세 가치를 준다.
- 정의는 `.claude/agents/`의 마크다운 파일이다. front matter의 name, description, tools, model, permissionMode와 본문 지침으로 구성하며, 읽기 전용을 믿고 맡길 수 있는 경계는 tools 화이트리스트다.
- 모드는 읽기 전용(안전한 관찰자), 실행(잡음을 요약으로 바꿈), 병렬(독립 작업을 동시에, MapReduce), 파이프라인(의존 단계를 계약으로 연결), 팀(실험적, 기본 비활성)이다.
- 스킬과는 서브에이전트가 skills 필드로 미리 로드하는 방향과, 스킬이 context: fork로 서브에이전트를 띄우는 방향이 있다. 정체성은 서브에이전트가, 방법과 표준은 스킬이 정의한다.
- 예시 계산에서 서브에이전트는 약 6.8%를 절감하지만 프롬프트 캐싱을 반영하면 1~2%로 줄어든다. 진짜 가치는 컨텍스트 윈도 보호와 응답 품질이며, 입력이 출력보다 훨씬 클 때 쓴다.
- 서브에이전트끼리는 직접 통신하지 못하고, 메인 에이전트가 전달하는 메시지로만 정보를 주고받는다. 중단에 대비해 중간 산출물을 파일에 남기고 중첩은 두 층 정도로 둔다.
