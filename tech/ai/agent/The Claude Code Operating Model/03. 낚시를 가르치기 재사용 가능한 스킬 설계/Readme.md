# 03. 낚시를 가르치기: 재사용 가능한 스킬 설계

이 장은 매번 같은 배경 지식을 Claude에게 다시 설명하는 비용을 없애는 방법으로 스킬(Skills, 작업별 절차와 지식을 폴더로 묶어 필요할 때만 불러오는 기능)을 소개한다. 상시 적용되는 CLAUDE.md와 필요할 때만 로드되는 스킬의 차이에서 시작해, 스킬 폴더와 frontmatter의 구조, 점진적 공개와 description 예산, 트리거 메커니즘, SKILL.md 본문과 권한 설계, 인자와 동적 주입, 저장 위치와 우선순위를 차례로 다룬다.

마지막으로 코드 리뷰, 커밋, 재무 분석 스킬 세 개를 직접 만들고, 네 가지 설계 패턴과 소프트웨어 공학 관점에서 본 스킬의 의미를 정리한다. 설정 필드 이름과 수치는 책 기준이며, 일부 한도는 버전에 따라 달라질 수 있다.

---

## 1. 핵심 요점

- CLAUDE.md는 모든 대화에 상주하는 공통 규칙이고, 스킬은 특정 직무의 표준 절차를 서류함에 두었다가 필요할 때 꺼내는 방식이다.
- 스킬 폴더의 필수 파일은 대문자 SKILL.md뿐이며, scripts/, reference/, templates/는 선택이다. 폴더 이름은 `[a-z0-9-]`, 64자 이하의 kebab-case다.
- 점진적 공개는 description 상주, 본문은 트리거 시, 참조 파일은 필요 시 로드하는 3층 구조이며 토큰을 50~98% 줄인다.
- description은 의미 매칭의 유일한 신호다. 기능, "Use when..." 트리거 문구, 핵심 능력, 선택적 "Not for..." 제외 조건으로 쓴다.
- 부작용이 큰 작업은 disable-model-invocation: true를 붙인 작업 스킬로 만들어 사용자만 실행하게 한다.
- SKILL.md는 저장소가 아니라 라우터다. 500줄 이내로 유지하고 계약형 참조로 보조 파일을 가리킨다.
- allowed-tools는 유형별 최소 권한으로 설계하고 `Bash(*)`는 피한다. 다만 이 필드는 허용과 자동 승인을 하는 것이며 진짜 차단은 disallowed-tools, 권한 설정, 훅이 맡는다.
- `$ARGUMENTS`와 `!`command``로 실행 시점의 인자와 상태를 주입할 수 있고, 같은 이름은 기업 > 개인 > 프로젝트 > 플러그인 순으로 우선한다.
