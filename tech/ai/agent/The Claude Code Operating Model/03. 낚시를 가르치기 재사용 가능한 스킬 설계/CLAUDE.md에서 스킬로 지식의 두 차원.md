# CLAUDE.md에서 스킬로 지식의 두 차원

3장은 샤오빙(Xiaobing)의 화요일 아침 장면으로 시작한다. 그녀는 새 Claude Code 세션을 열 때마다 같은 일을 반복한다. 결제 모듈의 API 문서를 만들려면 RESTful 규칙, OpenAPI 3.0 형식, 사내 오류 코드 기준, 실제로 유효한 예시 데이터, 중국어와 영어 병기 같은 전제를 3분 동안 다시 설명하고, 지난주 동료가 쓴 참고 문서까지 먹여야 한다. 같은 세션 안에서 작업이 "API 문서 작성"에서 "코드 품질 리뷰"로 바뀌어도 Claude는 작업 방식을 스스로 바꾸지 못해서, 리뷰 우선순위와 출력 형식과 심각도 등급을 다시 설명해야 한다. 책은 이것을 매일 기억을 잃는 임시 직원에게 입사 교육을 하는 일에 빗댄다.

동료 샤오쉐(Xiaoxue)도 같은 처지다. 재무 분석을 시킬 때마다 매출총이익률 공식, 업계 기준 수치, 보고서 서식을 다시 알려 준다. 이 장은 "프로젝트 전체 규칙을 담는 CLAUDE.md만으로는 왜 부족한가"라는 질문에서 출발해 스킬(Skills, 특정 작업의 절차와 지식을 폴더로 묶어 필요할 때만 불러오는 확장 기능)이라는 답에 이른다. 장 제목은 "고기를 주지 말고 낚시를 가르쳐라"라는 격언에서 따왔다.

---

## 1. 문제: 매번 다시 가르치는 비용

책이 짚는 불편은 두 갈래다.

- 세션이 바뀔 때마다 도메인 전제 지식을 다시 넣어야 한다.
- 한 세션 안에서도 작업 종류가 바뀌면 Claude가 새 작업 방식에 자동으로 맞추지 못한다.

샤오쉐가 스승 격인 카게(Kage)에게 던진 질문이 이 장의 목표를 정한다. "API 문서"라는 말만 꺼내면 실행 기준이 자동으로 적용되고, "재무 분석"이라고 하면 업계 기준과 보고서 서식이 자동으로 불려 오게 할 수 없느냐는 것이다. 단, CLAUDE.md 같은 프로젝트 공통 기억이 아니라 더 정밀한 맥락 인식을 원한다는 조건이 붙는다. 카게는 화이트보드에 "Skills"라고 적는 것으로 답한다.

## 2. CLAUDE.md가 더는 충분하지 않은 이유

카게는 CLAUDE.md를 회사의 "문화 핸드북"에 비유한다. TypeScript를 쓸지 Python을 쓸지, 들여쓰기는 탭인지 공백인지, PR 제목 형식은 무엇인지 같은 규칙이 여기에 들어간다. 이 규칙들은 모든 대화의 모든 순간에 적용되어야 하므로 항상 컨텍스트 윈도(모델이 한 번에 볼 수 있는 텍스트 범위)에 상주하고, 매번 전부 로드된다. 대가도 분명하다. 관련 작업을 하든 말든 상주하는 만큼 토큰(모델이 처리하는 텍스트의 단위, 비용과 한도의 기준)이 계속 소모된다.

여기에 API 문서 작성 지식을 넣는다고 생각해 보자. OpenAPI 3.0 표준, 오류 코드 규칙, 이중 언어 형식은 문서를 만들 때만 필요하다. 이것을 CLAUDE.md에 넣으면 버그를 잡을 때, 테스트를 돌릴 때, 설정 파일을 쓸 때도 수천 토큰의 문서 규칙이 컨텍스트를 차지한다. 귀한 공간이 낭비될 뿐 아니라 정말 중요한 정보의 비중이 희석된다.

## 3. 두 지식을 한 표로 비교하기

책의 표 3.1은 두 방식을 여러 차원에서 비교한다. 핵심만 추려 다시 정리했다.

| 차원 | CLAUDE.md | 스킬 |
|---|---|---|
| 담는 내용 | 프로젝트 공통 규범 | 전문 워크플로, 도메인 지식 |
| 적용 범위 | 현재 프로젝트 | 프로젝트와 세션을 가로지름 |
| 발동 방식 | 항상 적용 | 필요할 때 활성화 |
| 로딩 전략 | 매번 전체 로드 | 점진적 온디맨드 로드 |
| 대표 용도 | "TypeScript를 쓴다" | "코드 리뷰를 어떻게 하는가" |
| 에이전트와의 관계 | 모든 에이전트가 공유 | 특정 에이전트에 연결 가능 |
| 토큰 소비 | 고정 비용 | 쓸 때만 지불 |
| 기업에 비유하면 | 사내 문화 매뉴얼 | SOP(표준 운영 절차) 작업 설명서 |

책은 표의 마지막 줄, 기업 비유를 따로 풀어 준다. 성숙한 기업에는 성격이 다른 지식 자산이 두 종류 있다.

- 모두가 지켜야 하는 보편 규칙: 근태 규정, 안전 레드라인, 소통 규약. 사무실 벽에 붙은 표어처럼 누구에게나 보이고 언제나 유효하다. CLAUDE.md에 해당한다.
- 특정 직무의 표준 운영 절차: 재무팀의 월 마감, 운영팀의 장애 대응, 고객 서비스의 불만 처리. 벽에 붙이지 않고 부서 서류함에 정리해 두었다가 해당 직무자가 해당 작업을 할 때만 꺼내 본다. 스킬에 해당한다.

한 줄로 줄이면 "CLAUDE.md는 벽, 스킬은 서류함"이다. 코드를 쓰는 사람이 재무 매뉴얼을 들고 다닐 필요가 없고, 보고서를 쓰는 사람이 안전 수칙 전문을 들고 있을 필요도 없다. 필요한 순간에만 필요한 지식이 정확히 꺼내진다는 것이 요점이다.

## 4. 스킬의 정의에서 읽어야 할 두 단어

Claude Code가 내리는 스킬의 정의는 이렇다. 스킬은 지침을 담은 폴더이고, 단순한 디렉터리 구조로 포장되어 Claude에게 특정 작업이나 워크플로를 처리하는 법을 "가르치는" 데 쓰인다. 이 정의에서 책은 두 단어에 주목한다.

- 폴더: "문자열에서 공학으로". 스킬은 프롬프트 한 줄이나 설정 항목이 아니다. 복잡한 코드베이스, 상세한 도메인 문서, 여러 템플릿, 실행 가능한 스크립트까지 담을 수 있는 하나의 공학적 디렉터리다.
- 가르친다: "제약에서 내면화로". 정의가 "명령한다"나 "제한한다"가 아니라 "가르친다"를 쓴 것은 작동 방식의 근본적 전환을 암시한다. 스킬을 통해 Claude는 한 분야의 운영 논리를 이해하고, 시키는 대로만 하는 기계에서 그 분야의 숙련된 실무자로 바뀐다.

## 5. 핵심 정리

- 스킬이 푸는 문제는 "필요할 때 필요한 지식을 배달하는 것(on-demand knowledge delivery)"이다.
- CLAUDE.md는 상시 적용되는 공통 규칙이고 고정 비용이 든다. 스킬은 필요할 때만 로드되어 쓴 만큼만 비용을 낸다.
- 스킬은 모든 에이전트가 공유하는 규칙이 아니라 특정 에이전트에 묶을 수 있는 전문 절차 묶음이다.
- 참고(노트 작성자): 이 장은 뒤에서 이 비유를 확장한다. 장 마지막 요약에서는 SKILL.md를 부서 SOP의 첫 페이지, reference/를 사내 지식 베이스, templates/를 표준 출력 서식, scripts/를 자동화 도구함에 대응시킨다.
