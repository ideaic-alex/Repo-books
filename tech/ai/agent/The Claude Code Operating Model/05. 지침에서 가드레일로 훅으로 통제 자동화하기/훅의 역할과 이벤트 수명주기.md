# 훅의 역할과 이벤트 수명주기

이 문서는 훅(Hooks, 도구 실행 직전·직후 같은 정해진 시점에 자동으로 끼어드는 스크립트)이 지금까지 배운 CLAUDE.md, 스킬(Skills), 서브에이전트와 무엇이 다른지, 그리고 훅이 걸릴 수 있는 이벤트가 어떤 묶음으로 나뉘는지 정리한다. 장의 도입 사례는 이렇다. 야근하던 샤오장이 Claude Code로 코드를 쓰고 테스트까지 통과한 뒤 git push를 했는데, 그 안에 .env 파일이 들어 있었다. 세 환경의 DB 접속 문자열, 내부 API 키, 결제 게이트웨이 테스트 계정 비밀번호가 노출되어 팀이 반나절 동안 키를 폐기·재발급하고 접근 로그를 감사했다. 상사가 "왜 막는 장치가 없었느냐"고 묻자 케이지는 "지금까지의 장치는 모두 제안일 뿐이었다. CLAUDE.md는 제안, 스킬은 안내이고, 절대 하지 말라고 강제한 적이 없다. 훅은 제안이 아니라 강제다"라고 답한다.

비유는 웹 개발의 미들웨어 하나면 충분하다. Express 미들웨어 체인, Django 요청 처리 계층, Spring 인터셉터는 모두 동작 전후에 처리를 끼워 넣는다. 훅은 그 개념을 AI 에이전트 세계에 옮긴 것이다.

---

## 1. 확장 체계에서 훅의 자리

앞의 네 장에서 배운 세 장치는 영향력이 커지는 순서로 놓인다. CLAUDE.md는 프로젝트 규범을 담아 대화 시작 때마다 읽히고, 스킬은 도메인 작업 절차를 담아 필요할 때 자동 또는 수동으로 불러오며, 서브에이전트는 컨텍스트를 분리해 작업을 위임한다. 이 셋은 모두 Claude의 인지 층에서 작동한다. 무엇을 따를지, 어떻게 다룰지, 누구에게 맡길지를 말해 줄 뿐이라서 언어 모델인 Claude는 이론상 프롬프트의 제약을 무시할 수 있다.

훅은 층이 다르다. Claude의 생각을 설득하지 않고 실행 층에서 행동을 직접 가로챈다. Claude가 Bash 도구로 rm -rf /를 부르려 하면 PreToolUse 훅이 그 호출을 시스템 수준에서 막아 버려, Claude의 결정이 강제로 뒤집힌다. 소프트웨어 공학 용어로는 정책과 메커니즘의 분리다. CLAUDE.md와 스킬은 "무엇을 해야 하는가"라는 정책을 정하고, 훅은 정책이 어겨졌을 때 명령이 실행되기 전에 막는 메커니즘을 제공한다. 막는 대상은 프롬프트도, 사용자가 이루려는 과업도 아닌 개별 도구 호출 하나다. 운영체제의 파일 권한이 애플리케이션의 자율에 기대지 않듯, 훅의 제약도 프롬프트의 안내에 기대지 않는다.

표 5.1을 풀어 쓰면 다음과 같다(원서 표는 추출이 심하게 깨져 있어 본문과 문맥으로 복원했다).

| 비교 항목 | CLAUDE.md | 스킬 | 훅 |
|---|---|---|---|
| 작동 층 | 인지 층 | 인지 층 | 실행 층 |
| 발동 방식 | 항상 로드 | 의미 매칭 또는 명시적 호출 | 이벤트가 나면 자동 |
| 구속력 | 제안 | 안내 | 강제 |
| Claude에 대한 통제 | 행동 규범을 알림 | 작업 절차를 안내 | 가로채고 차단 |
| 비유 | 교통 표지판 | 운전 교본 | 방벽·속도 제한 장치 |

표지판은 "여기는 시속 60km"라고 알려 주고, 교본은 "커브에서는 감속하라"고 가르치고, 방벽·속도 제한 장치는 차가 물리적으로 120km에 못 가게 한다. 가장 좋은 결과는 셋을 함께 쓸 때 나온다. 규칙을 알려 주고, 조작법을 가르치고, 잊거나 판단을 잘못해도 안전 기준선을 시스템이 지킨다.

## 2. 이벤트는 스물네 개가 넘는다

훅 이벤트는 초기 7개에서 시작해 지금은 스물네 개 이상으로 늘었고 릴리스마다 늘고 있다. 원서는 숫자를 못 박지 않고 공식 훅 레퍼런스에서 최신 목록을 확인하라고 권한다. 중요한 것은 분류다. 세션 수준, 도구 호출, 서브에이전트, 완료, 그리고 뒤늦게 추가된 긴 꼬리(Setup, PermissionDenied, PostToolBatch, PreCompact, TaskCreated, FileChanged, Elicitation 등)로 나뉘고, 외울 필요 없이 묶음의 논리와 특징만 알면 된다.

참고(노트 작성자): 원서는 뒤쪽 절에서 "전체 17개 이벤트 중"이라고 쓰는데 이는 "스물네 개 이상"이라는 앞 문장과 맞지 않는다. 책이 개정되는 과정에서 남은 표현으로 보이며, 이 노트는 "스물네 개 이상, 계속 증가"를 기준으로 삼는다.

## 3. 세션 수준 이벤트

- **SessionStart**: 세션이 시작되거나 재개될 때 발동한다. 핵심 능력은 CLAUDE_ENV_FILE을 통한 환경 변수 주입이다. 훅 스크립트가 이 파일에 export 문을 쓰면 이후 모든 Bash 명령에 그 변수가 적용된다. 세션을 열 때 개발 환경을 자동으로 세팅할 수 있다는 뜻이다.
- **SessionEnd**: 세션이 끝날 때 발동한다. matcher로 종료 이유(clear = 사용자가 지움, logout = 로그아웃, prompt_input_exit = 입력창 종료)를 구분한다. 임시 자원 정리나 세션 통계 기록에 쓴다.
- **PreCompact**: 컨텍스트 압축 직전에 발동한다. matcher로 manual(사용자가 /compact 실행)과 auto(컨텍스트 창이 가득 차 자동 압축)를 구분한다. 압축 전에 전체 대화 기록을 백업하기에 알맞다.

SessionStart 예시는 아래와 같다. 원서 코드 그대로 핵심만 옮겼다.

```bash
#!/bin/bash
# session-init.sh — SessionStart Hook
if [ -n "$CLAUDE_ENV_FILE" ]; then
    echo 'export NODE_ENV=development' >> "$CLAUDE_ENV_FILE"
    echo 'export DEBUG_LOG=true' >> "$CLAUDE_ENV_FILE"
fi
exit 0
```

## 4. 도구 호출 이벤트

가장 중요한 묶음이며 Claude의 모든 도구 호출 수명주기를 덮는다.

- **PreToolUse**: 훅 체계에서 가장 강력한 이벤트다. Claude가 도구를 부르기로 결정한 뒤 실제 실행 전에 발동한다. permissionDecision 값은 allow(권한 검사를 건너뛰고 실행), deny(호출을 막고 이유를 알림), ask(결정을 사용자에게 넘김), defer(평소 권한 흐름에 맡김)이다. 인자 재작성은 네 번째 결정이 아니라 별도 메커니즘이다. hookSpecificOutput 아래에 updatedInput 객체를 넣으면 도구가 그 매개변수로 실행된다. 작업을 끊지 않고 보안 매개변수를 슬쩍 덧붙일 수 있어 특히 강력하다. 원서 예시는 위험한 `rm -rf /tmp/test`를 `rm -rf /tmp/test --dry-run`으로 조용히 바꿔 실제 삭제 위험을 피하면서 Claude가 작업을 이어 가게 한다.
- **PostToolUse**: 도구 실행 후에 발동한다. 이미 일어난 일을 되돌릴 수는 없지만 두 가지 핵심 용도가 있다. additionalContext로 추가 정보(예: lint 결과)를 Claude에게 되먹이는 것, 그리고 결과를 후처리하는 것(방금 쓴 파일 자동 포맷)이다. updatedToolOutput 필드를 돌려주면 도구 출력을 통째로 교체할 수도 있는데, MCP 도구뿐 아니라 모든 도구에 적용된다.
- **PostToolUseFailure**: 도구 실행이 실패한 뒤 발동한다. 오류 경고와 교정 피드백에 쓴다.
- **PermissionRequest**: 권한 대화상자가 뜨려는 순간 발동한다. PreToolUse와의 차이는 시점이다. PreToolUse는 모든 도구 호출 전에 무조건 발동하고, PermissionRequest는 사용자 수동 확인이 필요할 때만 켜진다. 이 이벤트로 권한 요청을 프로그램으로 승인하거나 거부한다(출력은 `decision.behavior`, `updatedPermissions` 형태, 자세한 내용은 3번 문서).
- **UserPromptSubmit**: 사용자가 입력을 제출한 뒤 Claude가 처리하기 전에 발동한다. 입력 전처리나 컨텍스트 주입에 쓰며, 메시지를 보낼 때마다 현재 Git 브랜치 정보를 덧붙이는 식이다.

## 5. 서브에이전트 이벤트와 완료 이벤트

서브에이전트 이벤트는 4장의 서브에이전트 메커니즘과 함께 쓴다.

- **SubagentStart**: 서브에이전트가 시작될 때 발동한다. matcher로 서브에이전트 유형 이름을 거를 수 있고, 내장 유형(Bash, Explore, Plan)과 `.claude/agents/` 디렉터리의 사용자 정의 서브에이전트(예: code-reviewer)를 모두 지원한다. 시작 자체를 막을 수는 없지만 additionalContext로 실행 시점에 중요한 컨텍스트를 주입한다. code-reviewer가 시작될 때마다 팀 코딩 표준을 자동 로드하는 식이다.
- **SubagentStop**: 서브에이전트가 작업을 마친 뒤 발동하며 논리는 전역 Stop 이벤트와 같다. 멈춤을 허용하거나, 요청을 가로채 특정 품질 기준을 채울 때까지 계속 일하게 강제할 수 있다. 입력에는 transcript_path(메인 세션 기록)와 agent_transcript_path(서브에이전트 자신의 대화 기록) 두 경로가 들어 있어 훅 스크립트가 작업 전 과정을 검토할 수 있다.
- **Stop**: Claude가 응답 한 사이클을 끝낼 때 발동한다. 품질 게이트(quality gating)의 핵심 장치로, 결과가 코딩 지침이나 보안 정책 같은 기준에 못 미치면 decision: "block"으로 세션 종료를 막고 요구 사항을 채울 때까지 수정하게 한다.
- **Notification**: Claude가 시스템 알림을 보낼 때 발동한다. matcher로 permission_prompt, idle_prompt, auth_success 같은 알림 종류를 구분한다. Slack, Discord로 중요한 알림을 넘기거나 데스크톱 팝업을 띄우는 데 쓴다.

## 6. 새로 추가된 이벤트

2025~2026년 사이에 더 복잡한 협업·운영 시나리오를 지원하려고 이벤트가 늘었다.

- **TeammateIdle, TaskCompleted**: 멀티 에이전트 팀(Agent Teams) 협업 전용이다. 앞의 것은 팀원 에이전트가 유휴 상태에 들어가려 할 때, 뒤의 것은 작업이 완료로 표시될 때 발동한다.
- **ConfigChange**: 설정 파일이 바뀔 때 발동한다. 설정 변경 이력 추적과 무단 변경 방지 등 감사·컴플라이언스에 쓴다.
- **WorktreeCreate, WorktreeRemove**: Git 워크트리 생성과 삭제에 각각 대응한다. 의존성 자동 설치 같은 초기화나 임시 빌드 산출물 삭제 같은 정리를 끼워 넣을 수 있다.

## 7. 차단 가능 여부, 가장 중요한 분류 축

이벤트를 나누는 가장 근본적인 기준은 막을 수 있느냐다. 이 축이 이벤트가 프로세스를 통제하는 용도인지, 관찰과 기록 용도인지를 결정한다.

| 구분 | 이벤트 |
|---|---|
| 차단 가능 | PreToolUse, PermissionRequest, UserPromptSubmit, UserPromptExpansion, Stop, SubagentStop, TeammateIdle, TaskCreated(exit 2면 작업 생성이 롤백됨), TaskCompleted, ConfigChange, PostToolBatch, PreCompact(exit 2면 압축 중단), Elicitation 이벤트 두 개 |
| 읽기 전용 | PostToolUse, Notification, SubagentStart 등 나머지. 컨텍스트 읽기, 정보 주입, 알림 같은 부수 효과는 가능하지만 Claude의 핵심 실행을 막거나 바꾸지 못한다 |

실무에서 가장 많이 쓰는 셋은 PreToolUse(도구 실행 전 문지기), PostToolUse(실행 후 품질 관리자), Stop(작업 종료 시 품질 관문)이다. 시간이 부족하면 이 셋부터 익혀도 튼튼한 자동화 순환을 만들 수 있다.

## 8. 핵심 정리

- CLAUDE.md, 스킬, 서브에이전트는 인지 층의 안내이고, 훅은 실행 층의 강제다. 정책과 메커니즘의 분리로 이해한다.
- 막는 대상은 프롬프트나 과업이 아니라 개별 도구 호출이다.
- 이벤트 묶음은 세션(SessionStart, SessionEnd, PreCompact), 도구 호출(PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, UserPromptSubmit), 서브에이전트(SubagentStart, SubagentStop), 완료(Stop, Notification), 신규 이벤트다.
- PreToolUse는 allow, deny, ask, defer 결정과 updatedInput 재작성이 가능하다. PostToolUse는 되돌릴 수 없고 additionalContext 피드백과 후처리를 맡는다.
- 차단 가능 여부가 이벤트의 성격(통제 대 관찰)을 가른다. 가장 먼저 익힐 셋은 PreToolUse, PostToolUse, Stop이다.
