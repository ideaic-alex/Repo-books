# 서브에이전트 훅과 비동기 훅

훅을 더 정밀하게, 그리고 더 가볍게 쓰는 두 가지 방법을 다룬다. 하나는 서브에이전트에 붙는 훅이다. 전역 설정 대신 서브에이전트 정의 파일(Frontmatter, 파일 맨 위의 메타데이터 블록) 안에 훅을 적고, SubagentStart와 SubagentStop 이벤트를 함께 써서 컨텍스트 주입부터 결과 검수까지 닫힌 품질 순환을 만든다. 다른 하나는 비동기 훅이다. 오래 걸리는 작업 때문에 Claude가 멈춰 서지 않도록 훅을 백그라운드로 돌린다.

---

## 1. 전역 설정과 Frontmatter: 정밀도의 문제

3장에서 배운 서브에이전트는 컨텍스트를 격리해 작업을 위임한다. 훅 체계는 이를 위해 SubagentStart, SubagentStop 이벤트를 따로 두지만, 더 중요한 세 번째 장치는 서브에이전트의 Frontmatter에 훅을 직접 정의하는 것이다.

예를 들어 SQL 조회만 실행하는 db-reader라는 서브에이전트가 있다고 하자. 이 서브에이전트가 실행하는 모든 Bash 명령을 SQL 인젝션 위험에서 감사하고 싶다. 전역 `settings.json`에 훅을 걸면 코드 컴파일, 테스트 실행, 의존성 설치처럼 DB와 무관한 Bash 명령까지 모조리 가로챈다. 자원이 낭비되고 오탐(false positive, 멀쩡한 작업을 잘못 막음) 위험도 크게 커진다. 더 나은 방법은 서브에이전트의 Frontmatter에 훅을 정의하는 것이다.

```yaml
---
name: db-reader
description: Read-only database analysis tool
tools: Read, Grep, Glob, Bash
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./.claude/hooks/check-sql-injection.sh"
  Stop:
    - hooks:
        - type: prompt
          prompt: "Check whether the query results contain PII ... reply with ok: false ..."
---
You are a database analysis expert. Only execute SELECT queries; ...
```

원서 코드는 들어쓰기가 모두 사라진 채 추출되었고, 맨 앞에 뒤 절(SubagentStop 예)의 `HAS_ISSUES`, `HAS_SUGGESTIONS` 두 줄이 섞여 들어와 있다. 이 두 줄은 조판 오류로 보아 제외했고, YAML 들여쓰기는 키 구조(hooks, 이벤트명, matcher, hooks, type)에 맞춰 복원했다. 프롬프트는 길어서 줄임표로 요약했다. 원서 프롬프트의 뜻은 조회 결과에 PII(이름, 이메일, 전화번호 등 개인 식별 정보)가 있으면 ok: false로 답해 데이터를 비식별화하도록 요구하라는 것이다. 본문의 지시는 SELECT 쿼리만 실행하고 데이터를 바꾸는 SQL은 엄격히 금지한다는 내용이다.

Frontmatter 훅의 장점은 두 가지다.

- 수명주기가 긴밀하게 묶인다. 서브에이전트가 시작될 때 훅이 켜지고 작업이 끝나면 자동으로 정리된다.
- 설정이 서브에이전트 정의와 같은 파일에 있어 .md 파일과 함께 배포된다. 사용자가 전역 `settings.json`을 고칠 필요가 없어 설정 복잡도가 크게 준다.

## 2. SubagentStart: 컨텍스트 자동 주입

전형적인 쓰임은 서브에이전트가 시작될 때 팀 지침을 동적으로 주입하는 것이다. code-reviewer 서브에이전트가 뜰 때마다 팀 코딩 표준을 자동으로 넣는다. matcher에 서브에이전트 유형 이름 `code-reviewer`를 쓰고, command 처리기가 `hookEventName: "SubagentStart"`와 additionalContext가 든 JSON을 echo한다. 원서 예시의 주입 내용은 "camelCase 이름 규칙, 한 줄 최대 100자, 모든 공개 API에 JSDoc 주석"이다. 시작 자체를 막지는 못하고 컨텍스트 주입만 가능하다는 점은 1번 문서에서 정리했다.

## 3. SubagentStop: 산출물 품질 검수 (verify-review-quality.sh)

SubagentStop 훅은 서브에이전트의 작업이 기준을 만족하는지 확인한다. agent_transcript_path로 서브에이전트의 전체 상호작용 기록을 읽어 정밀하게 검수한다. 스크립트의 흐름은 다음과 같다.

1. 입력에서 agent_type과 stop_hook_active를 꺼낸다.
2. agent_type이 code-reviewer가 아니면 바로 통과(exit 0). 이 서브에이전트만 검증한다.
3. stop_hook_active가 true면 통과. 무한 루프를 막는 검사이며 Stop 훅과 같은 원리다.
4. agent_transcript_path의 파일이 있으면 `grep -c`로 "issue|problem|bug"와 "suggest|suggestion|recommend"가 나온 줄 수를 센다.
5. 문제는 지적했는데(HAS_ISSUES > 0) 제안은 하나도 없으면(HAS_SUGGESTIONS = 0) `{"decision":"block","reason":"..."}`을 내고, 각 문제에 개선안을 보충하라고 요구한다.

원서 코드의 조건식은 `[ "$HAS_ISSUES" -gt0]&&["$HAS_SUGGESTIONS"-eq0]`처럼 공백이 없이 추출되었다. 문맥으로 `[ "$HAS_ISSUES" -gt 0 ] && [ "$HAS_SUGGESTIONS" -eq 0 ]`로 복원했다. 줄 수를 세는 단순한 키워드 방식이므로 정교한 의미 검수는 아니다(참고(노트 작성자): 이 평가는 원서에 없는 보충이다. 의미 판단이 필요하면 prompt나 agent 처리기로 올리라는 2번 문서의 원칙과 연결된다).

## 4. 세 겹의 보호

세 가지는 각자 역할이 있고 함께 완전한 품질 보증 피드백 순환이 된다.

| 장치 | 역할 | 비유 |
|---|---|---|
| Frontmatter 훅 | 내부 자체 점검 | 서브에이전트가 "내 산출물이 완전한가?"를 스스로 묻는다 |
| SubagentStart 훅 | 외부 주입 | 시작 때 필요한 배경 정보를 쥐여 준다 |
| SubagentStop 훅 | 외부 인수 검사 | 끝날 때 "기준을 만족하는가?"를 엄격히 확인한다 |

## 5. 비동기 훅: 막지 않고 백그라운드에서 실행

기본적으로 훅 스크립트는 동기(synchronous)로 실행되며 막는다. 스크립트가 결과를 돌려줄 때까지 Claude는 현재 흐름을 멈춘다. 패턴 매칭 같은 빠른 검사라면 몇 밀리초의 지연은 무시할 만하다. 그러나 테스트 스위트 실행, 외부 API 호출, 알림 전송 같은 오래 걸리는 작업은 동기 대기가 Claude의 응답 속도와 사용 경험을 크게 해친다. 이를 해결하려고 2026년 초 Claude Code에 비동기 훅 지원이 들어왔다.

```json
{ "type": "command",
  "command": "./.claude/hooks/run-tests-background.sh",
  "async": true,
  "timeout": 300 }
```

`async: true`를 쓰면 훅이 백그라운드에서 막지 않고 실행된다. Claude는 완료를 기다리지 않고 바로 다음 작업을 진행하고, 비동기 훅이 끝나면 그 출력이 다음 대화 턴에 자동으로 Claude에게 전달되어 참고나 처리에 쓰인다.

비동기 훅에는 적용 범위를 정하는 두 가지 제한이 있다.

- **유형 제한**: command 유형만 비동기로 돌릴 수 있다. prompt와 agent 유형은 반드시 동기로 실행된다.
- **차단 능력 제한**: 비동기 훅은 현재 작업을 막지 못한다. 훅이 발동하는 즉시 메인 프로세스가 계속 진행하므로, 작업이 일어나기 전에 개입할 기회를 잃는다.

따라서 비동기 훅은 로깅, 비동기 알림, 백그라운드 데이터 검증, 중요하지 않은 품질 감사 같은 "후처리"에 알맞다. 실시간으로 막아야 하는 보안 검사(SQL 인젝션 방어, 민감 정보 필터링)에는 맞지 않는다.

## 6. 핵심 정리

- 서브에이전트 전용 검사는 전역 설정이 아니라 Frontmatter에 둔다. 불필요한 가로채기와 오탐을 줄이고 서브에이전트 파일과 함께 배포된다. 훅은 서브에이전트가 시작될 때 켜지고 끝나면 정리된다.
- SubagentStart는 컨텍스트 주입, SubagentStop은 agent_transcript_path 기반 산출물 검수다. SubagentStop도 stop_hook_active로 루프를 방지한다.
- 비동기 훅은 `async: true`와 timeout으로 설정하며, command 유형만 가능하고 차단할 수 없다. 결과는 다음 턴에 전달된다.
- 느린 후처리에는 비동기, 실시간 보안 차단에는 동기를 쓴다.
