# 지침에서 가드레일로, 훅으로 통제 자동화하기

이 장은 Claude가 알아서 따르길 바라는 지침(CLAUDE.md, 스킬)을 넘어, 도구가 실행되는 순간 시스템이 직접 강제하는 훅(Hooks)을 다룬다. 야근 중 .env 파일을 푸시해 키가 유출된 사고를 출발점으로, 훅이 걸리는 이벤트와 차단 가능 여부, 설정 위치와 처리기 종류, 출력 프로토콜을 배운다.

이어서 보안 보호 체계와 자동 코드 품질 두 실습, 서브에이전트 훅과 비동기 훅, 환경 변수와 디버깅, 그리고 "먼저 관찰하고 그다음 통제한다"는 설계 방법론을 정리한다. 코드 예시는 핵심만 싣고 나머지는 말로 풀어 썼다.

---

## 1. 핵심 요점

- CLAUDE.md와 스킬은 인지 층의 제안이고, 훅은 실행 층의 강제다. 막는 대상은 프롬프트가 아니라 개별 도구 호출이다.
- 이벤트는 스물네 개 이상이며 세션, 도구 호출, 서브에이전트, 완료, 신규 이벤트로 묶는다. 차단 가능 여부가 가장 중요한 분류 축이고, 가장 먼저 익힐 셋은 PreToolUse, PostToolUse, Stop이다.
- 설정은 이벤트, matcher, 처리기 목록의 3단 중첩 JSON이다. 처리기는 command, prompt, agent 순의 사다리이고 가능하면 낮은 단계를 쓴다.
- command 훅은 stdin JSON을 받고 stdout JSON과 종료 코드(0 성공, 2 의도적 차단)로 답한다. PreToolUse의 permissionDecision은 allow, deny, ask, defer이고 updatedInput으로 입력을 고쳐 쓴다.
- 보안 실습은 위험 명령 차단, 민감 파일 보호, 감사 로그의 세 겹이고, 품질 실습은 자동 포맷, lint 피드백, Stop 테스트 관문이다. Stop 훅에는 stop_hook_active 검사가 필수다.
- 서브에이전트 전용 검사는 Frontmatter에, 오래 걸리는 후처리는 `async: true` 훅에 둔다. 비동기 훅은 차단하지 못한다.
- 설계는 PostToolUse 감사 로그로 관찰한 뒤 PreToolUse 차단 규칙을 만들고 점차 조이는 순서로 한다.
