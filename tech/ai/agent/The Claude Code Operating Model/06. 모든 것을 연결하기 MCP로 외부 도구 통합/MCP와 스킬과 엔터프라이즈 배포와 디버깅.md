# MCP와 스킬, 엔터프라이즈 배포, 디버깅

MCP로 연결만 해서는 부족하다. 연결된 도구를 어떻게 잘 쓸지는 스킬(Skills)이 알려 준다. 이 문서는 둘의 관계를 "주방과 레시피"로 설명하고, 수십~수백 명 규모 팀의 중앙 관리 방식(managed-mcp.json), 그리고 MCP를 디버깅하는 명령과 환경 변수, 흔한 문제 해결표를 정리한다.

---

## 1. MCP와 스킬: 주방과 레시피

앞 장들의 스킬과 이 장의 MCP는 문제의 다른 층을 맡는다. MCP는 Claude에게 외부 데이터와 도구에 대한 접근을 주고, 스킬은 그 능력을 어떻게 가장 잘 쓸지 안내한다. 둘을 합쳐야 완전한 해법이 된다.

Anthropic의 비유는 이렇다.

| 구성 | 비유 | 의미 |
|---|---|---|
| MCP | 전문 주방 | 냉장고(데이터베이스), 가스레인지(API 호출), 재료(데이터 소스), 칼(유틸리티 함수)이 다 갖춰져 있다. 주방이 있으면 요리사는 무슨 요리든 할 수 있지만, 무엇을 어떻게 만들지는 요리사의 즉흥에 달렸다. 새 요리사(새 사용자 요청)가 올 때마다 주방 사용법을 처음부터 파악해야 해 품질이 일정하기 어렵다 |
| 스킬 | 표준 레시피 | 필요한 재료, 단계, 불 조절, 조리 시간을 구체적으로 적어 둔다. 레시피가 있으면 미숙한 요리사도 좋은 요리를 안정적으로 재현할 수 있다. 하지만 주방 설비가 없으면 최고의 레시피도 실행할 수 없다 |

실전 협업 방식은 스킬의 SKILL.md 파일에서 MCP 도구를 언급해, Claude가 정해진 워크플로에 따라 그 도구를 효율적으로 부르도록 이끄는 것이다(원서 그림 6.3). 이 조합으로 Claude는 두 가지 이점을 얻는다. MCP로 실시간 데이터 능력을 얻고, 스킬로 일관된 방법론에 따라 데이터를 처리한다. 사용자의 상세한 지시나 Claude의 그때그때 판단에 기대지 않고 안정적이고 효율적인 자동 실행이 가능해진다.

## 2. 엔터프라이즈 배포

엔지니어가 수십~수백 명인 팀에서 각자가 MCP 서버를 설정하게 두는 것은 확장 가능한 방식이 아니다. Claude Code는 기업 수준의 중앙 관리 기능을 제공한다.

- 관리자는 `managed-mcp.json` 설정 파일(또는 Claude for Enterprise 관리 콘솔)로 조직 전체 사용자의 MCP 서버를 미리 구성할 수 있다. 서버는 구성원 모두에게 자동으로 적용되고 개인이 할 일이 없다.
- 관리자는 이 서버들을 사전 승인(pre-authorize)할 수 있어, 각 사용자가 처음 쓸 때 뜨는 승인 팝업 절차를 없앤다.

이 중앙 관리는 양쪽에 이득이다. 개발자는 회사의 Jira, Linear, 사내 지식 베이스, 데이터 웨어하우스 도구를 MCP로 연결해 두면 팀 전체가 "설정 없이 바로 쓰는(zero configuration, out-of-the-box)" AI 워크플로의 혜택을 본다. 보안팀은 모든 MCP 접근이 엄격히 검증된 서버를 거치게 되므로, 분산된 개인 설정보다 중앙의 감사와 통제로 보안이 크게 좋아진다.

## 3. 디버깅과 문제 해결

MCP 서버 디버깅은 프로세스 간 통신, 네트워크 연결, 복잡한 인증 과정이 얽혀 있어서 훅 스크립트보다 보통 더 어렵다.

### 3-1. 흔한 디버깅 방법

```bash
claude mcp list            # 설정된 모든 서버와 현재 상태
claude mcp test my-server  # 특정 서버의 연결 상태 시험
claude --mcp-debug         # MCP 디버그 모드
```

### 3-2. MCP 도구 출력의 토큰 관리

MCP 도구가 대량의 데이터를 돌려줄 수 있기 때문에(예: LIMIT 없는 DB 쿼리가 수만 건을 반환) Claude Code에는 토큰 관리 장치가 내장되어 있다.

| 구분 | 기준 | 동작 |
|---|---|---|
| 경고 임계값 | 출력이 10,000 토큰 초과 | 경고 표시 |
| 절단 임계값 | 출력이 25,000 토큰 초과 | 컨텍스트 넘침을 막으려고 자동으로 잘라냄 |
| 사용자 설정 | 환경 변수 MAX_MCP_OUTPUT_TOKENS | 업무 상황에 맞게 출력 한도를 조정 |

### 3-3. 흔한 문제 (표 6.4)

| 증상 | 가능한 원인 | 해결 |
|---|---|---|
| 서버가 시작되지 않음 | command나 경로 설정 오류 | 설정 파일의 command, args를 확인하고 터미널에서 명령을 직접 실행해 정상 시작되는지 본다 |
| 연결 시간 초과 | 불안정한 네트워크나 느린 서버 응답 | 환경 변수 MCP_TIMEOUT(밀리초)을 설정해 대기 시간을 늘린다 |
| 인증 실패 | 토큰 오류, 누락, 만료 | API_KEY 같은 관련 환경 변수가 올바른지, 토큰이 유효한지 확인하고 제때 갱신한다 |
| 출력이 잘림 | 반환 데이터가 토큰 한도 초과 | MAX_MCP_OUTPUT_TOKENS 상한을 올리고, 쿼리 논리를 개선(LIMIT 추가 등)해 서버가 더 간결한 데이터를 돌려주게 한다 |
| JSON 파싱 오류 | 서버 stdout이 로그로 오염됨 | 디버그 로그와 오류 메시지는 stderr로 쓰고 stdout은 순수 JSON 데이터 전용으로 남긴다 |

마지막 항목은 5장 훅의 "셸 설정 echo가 stdout을 오염시킨다"는 함정과 같은 뿌리다.

---

## 4. 핵심 정리

- MCP는 접근(주방), 스킬은 사용법(레시피)이다. SKILL.md에서 MCP 도구를 언급해 둘을 묶는다.
- 기업에서는 managed-mcp.json(또는 Claude for Enterprise 콘솔)으로 서버를 사전 구성하고 사전 승인해 개별 설정과 첫 승인 팝업을 없앤다. 보안팀은 검증된 서버로 접근을 중앙 통제한다.
- 디버깅은 `claude mcp list`, `claude mcp test <서버>`, `claude --mcp-debug`다.
- 출력 토큰은 10,000 초과 시 경고, 25,000 초과 시 자동 절단이며 MAX_MCP_OUTPUT_TOKENS로 조정한다. 연결 지연에는 MCP_TIMEOUT(밀리초)을 쓴다.
