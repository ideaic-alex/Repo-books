# 요약과 핵심 개념

이 장은 Claude를 사내망의 Jira나 데이터베이스 같은 바깥 세계와 잇는 MCP를 다룬다. 핵심은 연결 자체보다 연결의 표준화다. 조합마다 어댑터를 만들던 N×M 문제를 N+M으로 바꾼 것이 MCP의 가치다. 이 문서는 장 전체를 되짚고 용어와 흔한 실수를 정리한다.

원서의 요약은 이렇게 이어진다. MCP는 통일된 개방형 프로토콜로 다양한 AI 클라이언트와 데이터 소스를 이어, 조합마다 별도 어댑터 계층을 만들 필요를 없앤다. JSON-RPC 2.0 위에서 통신하고, 로컬 프로세스에는 stdio, 원격 서비스에는 HTTP가 맞으며(SSE 지원은 폐기), 환경 변수 치환 덕에 설정 파일을 버전 관리에 안전하게 둘 수 있다. 공학적 가치는 연결성보다 연결의 표준화에 있다. Claude와 통합된 MCP 서버는 이론상 이 표준을 따르는 어떤 AI 클라이언트와도 호환되고, 표준이 널리 채택될수록 Claude가 접근할 서버 생태계도 늘어난다. 2024년 11월 공개에서 2025년 12월 리눅스 재단 기부까지 13개월 만에 산업 표준이 되었다. 5장의 훅은 "Claude 행동의 경계를 정하고", 스킬은 "실행 전략을 안내하며", MCP는 "데이터와 서비스 접근의 경계를 넓힌다". 셋이 서로 보완해 연결(MCP), 호출 논리(스킬), 안전 장벽(훅)을 이룬다. 다음 7장은 대화형을 넘어 무인 환경에서의 헤드리스 모드와 CI/CD 통합을 다룬다.

## 1. 장 전체 흐름

| 순서 | 주제 | 핵심 결과 |
|---|---|---|
| 1 | N×M에서 N+M으로 | 어댑터 500개(5×100)를 105개(5+100)로 줄이는 표준 |
| 2 | 구조와 전송 | 클라이언트-서버, JSON-RPC 2.0, Tools/Resources/Prompts, stdio/HTTP |
| 3 | 설정 | claude mcp 명령, .mcp.json, 환경 변수 치환, 범위 |
| 4 | 실습 | Postgres 연결(읽기 전용 계정), 사용자 정의 todo 서버(TypeScript, Python) |
| 5 | 생태계와 보안 | 공식·서드파티 서버, 3겹 방어, 위험 세 가지 |
| 6 | 스킬 결합과 운영 | 주방과 레시피, managed-mcp.json, 디버깅, 토큰 한도 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| MCP | Model Context Protocol. AI 클라이언트와 외부 도구·데이터를 잇는 개방형 표준. "AI 통합의 USB-C" |
| N×M 대 N+M | 조합별 어댑터(곱) 대신 양쪽이 규약을 한 번씩만 구현(합) |
| MCP 클라이언트 / 서버 | Claude Code 내장의 호출 측 / 외부 서비스를 감싸 기능을 노출하는 독립 프로그램 |
| Tools / Resources / Prompts | 동작(부작용 가능) / 읽기 전용 데이터 / 재사용 프롬프트 템플릿. 실사용 대부분은 도구 |
| stdio | 로컬 자식 프로세스와 stdin/stdout으로 JSON-RPC를 주고받는 전송. 가장 안전하고 빠름 |
| HTTP | 원격 서버용 전송. OAuth 2.1과 PKCE 필수. SSE는 이것으로 대체 |
| `claude mcp add/list/test/remove` | MCP 서버 설정을 관리하는 CLI. `--transport http`, `--scope user`, `--header` 옵션 |
| .mcp.json | 프로젝트 루트의 설정 파일(mcpServers). 팀 공유용으로 보통 커밋 |
| `${VAR}` / `${VAR:-기본값}` | 환경 변수 치환. 비밀은 환경 변수에 두고 설정은 안전하게 커밋 |
| 3겹 방어 | 첫 연결 승인, 도구별 승인, OAuth 2.1 동적 인증 |
| 프롬프트 주입 / 도구 권한 남용 / 사칭 | 보고된 세 가지 위험. 신뢰 출처, 최소 권한으로 대응 |
| managed-mcp.json | 관리자가 조직 전체에 MCP 서버를 사전 구성·사전 승인하는 파일 |
| MAX_MCP_OUTPUT_TOKENS / MCP_TIMEOUT | 출력 토큰 한도(기본 경고 10,000, 절단 25,000) / 연결 대기 시간(ms) |

## 3. 자주 놓치는 점

- 서버가 stdout으로 일반 로그를 내면 JSON-RPC 파싱이 깨진다. 로그는 stderr로 보낸다(5장 훅과 같은 원칙).
- DB 연결에는 읽기 전용 계정을 쓴다. 쓰기는 되돌릴 수 없으니 허용 목록에서 뺀다.
- 설정 파일에는 비밀 값 대신 `${변수}` 참조만 쓴다. 개인 토큰은 `.claude/settings.local.json`으로 분리한다.
- 서버 전체를 승인했다고 모든 도구가 자동 통과하는 것이 아니다. 부작용 있는 도구는 한 번 더 확인한다.
- 개별 도구가 안전해 보여도 읽기와 전송 도구가 조합되면 유출 경로가 된다.
- 도구 설명 문자열이 Claude의 도구 선택 근거이므로 정확히 쓴다.
- 오래된 프로젝트의 SSE 설정은 HTTP로 옮긴다.
- 도구 출력이 25,000 토큰을 넘으면 잘리므로, 쿼리에 LIMIT를 걸어 서버가 간결하게 돌려주게 한다.
- 원서 코드(특히 TypeScript, Python 예시)는 추출 과정에서 줄이 섞이고 들여쓰기가 깨져 있다. 이 노트는 문맥으로 복원했다.

## 4. 토론 질문 (원서 Discussion questions)

1. 지금 내 워크플로에서 Claude가 실시간으로 접근할 수 있다면 효율이 크게 오를 데이터 소스나 도구는 무엇인가. 그 도구들을 위한 `.mcp.json`을 설계해 본다.
2. MCP와 데이터를 대화에 직접 붙여 넣는 방식(예: 내보낸 Jira CSV 전송)은 편의성 말고 본질적으로 무엇이 다른가. 직접 붙여 넣는 편이 더 나은 구체적 상황은 언제인가.
3. "주방과 레시피"(MCP는 주방, 스킬은 레시피) 구조에서 사내 도구 하나를 위한 완결된 통합안을 짠다면 어떻게 계획하겠는가. 힌트: MCP 서버 층에서 활용도를 극대화할 핵심 도구는 무엇인가. 스킬 안내 층에서 해당 스킬은 도구를 호출할 때 특정 업무 흐름을 따르도록 Claude에게 어떻게 지시해야 하는가.
