# N×M에서 N+M으로와 아키텍처와 전송 방식

MCP(Model Context Protocol, 모델 컨텍스트 프로토콜)는 AI와 외부 도구·데이터를 안전하고 표준화된 방식으로 잇는 개방형 규약이다. 이 문서는 MCP가 풀려는 문제(어댑터가 곱셈으로 늘어나는 N×M 문제), 그것을 덧셈(N+M)으로 바꾸는 표준화의 힘, 클라이언트-서버 구조와 서버가 내놓는 세 가지 기능, 그리고 연결 방식(전송 방식) 세 가지를 설명한다.

장은 이런 장면으로 시작한다. 제품 매니저가 "지난주 Jira의 P1 버그 분포를 Claude에게 분석시키자"고 한다. Jira는 사내망에 있고 Claude는 Anthropic 클라우드에서 돈다. 둘 사이에는 네트워크 격리 벽이 있어서, 데이터를 손으로 내보내 붙여 넣거나 가져오는 스크립트를 짜야 한다. 케이지는 "MCP를 쓰면 된다"고 답한다. MCP 이전에는 연결선의 양 끝을 매번 새로 이어야 했다. GitHub를 Claude에 붙이려면 어댑터를 짜고, Jira를 붙이려면 또 짜고, AI 플랫폼을 바꾸면 전부 처음부터 다시 만들어야 했다.

---

## 1. N×M에서 N+M으로

비유는 USB-C다. 하나의 커넥터가 자리 잡기 전에는 기기마다 전용 케이블이 필요해서 여행 갈 때 예닐곱 개를 챙겨야 했다. MCP는 "AI 도구 통합의 USB-C"다. 원서는 이 비유가 긴 역사를 단순화한 것임을 밝힌다. USB 자체도 이전 세대의 시리얼·병렬 포트를 대체한 것이다. 그래도 문제의 모양은 맞다.

MCP 이전에는 AI 도구 업체와 데이터 소스의 조합마다 전용 어댑터를 개발하고 유지해야 했다. GitHub를 Claude에 붙이는 어댑터와 같은 GitHub를 ChatGPT에 붙이는 어댑터가 따로 필요하다. AI 클라이언트가 5개, 데이터 소스가 100개라면 이론상 어댑터 500개를 관리해야 한다. 새 클라이언트나 소스가 하나 늘 때마다 중복 통합 작업이 크게 는다.

MCP의 핵심은 보편 표준 프로토콜을 정의하는 것이다. 각 AI 클라이언트(Claude, ChatGPT 등)는 MCP 클라이언트 규약을 한 번만 구현하고, 각 데이터 소스(Jira, GitHub, 데이터베이스 등)는 MCP 서버 규약을 한 번만 구현한다. 양쪽이 표준만 지키면 조합별 어댑터 없이 꽂기만 하면 연결된다(plug and play).

| 방식 | 5개 클라이언트 × 100개 소스 | 작업량 |
|---|---|---|
| MCP 이전(조합별 어댑터) | 5 × 100 | 500 |
| MCP 도입(각자 한 번 구현) | 5 + 100 | 105 |

### 생태계 현황(원서 기술)

- AAIF가 2025년 3월 MCP 채택을 발표했다. 지원은 OpenAI의 Agents SDK에 먼저 들어갔고 Responses API와 ChatGPT 데스크톱 앱이 뒤따른다고 한다. AAIF는 Anthropic, Block, OpenAI가 공동 창립했으며 각자 MCP, goose, AGENTS.md를 창립 프로젝트로 냈다. Google, Microsoft, Amazon Web Services, Cloudflare, Bloomberg가 플래티넘 회원·지지자로 참여했다.
- 공식 MCP SDK(Python, TypeScript)의 월간 다운로드가 9,700만 건을 넘었다.
- 요약 부분에서는 2024년 11월 공개부터 2025년 12월 리눅스 재단 기부까지 13개월 만에 한 회사의 프로젝트에서 컨소시엄이 관리하는 산업 표준이 되었다고 정리한다.

참고(노트 작성자): AAIF의 정식 명칭은 원서가 풀어 쓰지 않는다. 원서 문장 구성상 채택 발표 시점과 창립 구성이 서로 다른 시기의 서술이 섞여 있어 보이므로 연도 관계는 원서 표기를 그대로 옮기는 데 그쳤다.

## 2. 아키텍처: 클라이언트-서버와 JSON-RPC

MCP는 고전적인 클라이언트-서버 구조를 쓰고 JSON-RPC 2.0 프로토콜로 통신한다.

- **MCP 클라이언트**: Claude Code에 내장되어 있다. MCP 서버가 제공하는 기능을 발견하고, 도구 호출 요청을 만들고, 응답을 처리한다.
- **MCP 서버**: 독립된 프로그램이다. 데이터베이스, API, 파일 시스템 같은 외부 서비스에 연결하고 그 서비스의 기능을 MCP로 클라이언트에 노출한다.

원서는 공동 창안자인 David Soria Parra와 Justin Spahr-Summers가 Language Server Protocol(LSP)을 본떠 이 규약을 만들었고, Soria Parra가 인터뷰에서 LSP의 메시지 흐름 설계 철학을 빌렸다고 말했다고 전한다.

## 3. 서버가 내놓는 세 가지 핵심 기능

| 기능 | 성격 | 예 |
|---|---|---|
| Tools(도구) | Claude가 능동적으로 부르는 함수. 부작용이 있는 동작이 보통 | Jira에 새 티켓 만들기, 최근 7일 주문 조회, Slack 메시지 보내기 |
| Resources(리소스) | 필요할 때 읽는 데이터. "파일"과 비슷. 읽기 전용 | README.md 내용 가져오기 |
| Prompts(프롬프트) | 재사용 가능한 프롬프트 템플릿 | 코드 리뷰 전용 서버의 code-review 템플릿 |

**도구**는 가장 기본적이고 가장 많이 쓴다. 각 도구는 이름, 설명, 입력 매개변수 스키마, 반환값 형식을 명확히 정의한다. Claude가 호출이 필요하다고 판단하면 스키마에 맞는 요청을 자동으로 만들고, 서버가 동작을 수행한 뒤 구조화된 결과를 돌려준다. 도구와 리소스의 핵심 차이는 도구는 동작 수행(보통 부작용 있음), 리소스는 데이터 조회(읽기 전용)라는 점이다. "README.md 내용 가져오기"는 리소스 접근이고 "코드베이스에 커밋하기"는 도구 호출이다.

**프롬프트**는 특정 작업의 시작을 표준화하는 템플릿이다. 예컨대 코드 리뷰 전용 MCP 서버가 code-review 템플릿을 제공하면, 호출 시 표준 리뷰 형식과 중점 사항이 자동으로 로드된다. 스킬과 어느 정도 겹치고 실제로는 앞의 둘보다 덜 쓰이지만 작업 시작의 편한 경로가 된다.

세 기능 중 실사용의 대다수는 도구다. 사용자가 "Jira에서 P1 버그를 찾아 줘"라고 하면 Claude가 호출하는 것은 Jira MCP 서버가 노출한 list_issues 도구다.

## 4. 전송 방식: 연결의 세 가지 형태

전송 계층은 클라이언트와 서버 사이의 물리적 통신 방식을 정한다. 원서는 세 가지를 든다.

| 방식 | 용도와 특징 |
|---|---|
| stdio(표준 입출력) | 로컬 프로세스 통신 전용. Claude Code가 MCP 서버를 자식 프로세스로 띄우고 stdin/stdout으로 JSON-RPC 메시지를 주고받는다. 완전히 로컬이라 네트워크가 필요 없고 보안이 가장 높고 지연이 가장 낮다. 파일 시스템 접근, 로컬 DB 연결, 로컬 개발 도구 연동에 알맞다. npx로 띄우는 공식 MCP 서버 대부분이 이 방식이다 |
| SSE(Server-Sent Events) | 원격 전송의 초기 해법. MCP 규격에서 독립 SSE 전송은 Streamable HTTP로 대체되었다. 오래된 프로젝트에서 SSE 설정을 보면 HTTP로 옮겨야 한다 |
| HTTP(원격) | 원격 서버용. 규격은 OAuth 2.1과 필수 PKCE를 강제하며 기업 SSO(싱글 사인온)와 잘 맞는다 |

PDF 추출본에서 원서의 세 번째 항목(HTTP) 제목 줄이 빠져 있고, OAuth 2.1 설명 문단이 stdio 항목 안으로 끼어 있다. 이 노트는 문맥(뒤의 CLI 예시에 `--transport http`, 요약의 "HTTP는 원격"이라는 문장)을 근거로 그 문단을 HTTP 항목으로 옮겨 정리했다.

간단한 규칙은 "로컬은 stdio, 원격은 HTTP"다. 이것만 따라도 대부분의 필요를 채운다. 요약에서도 SSE 지원은 폐기되었다고 정리한다.

---

## 5. 핵심 정리

- MCP는 클라이언트와 서버가 각자 규약을 한 번씩만 구현하게 해 어댑터 수를 N×M에서 N+M으로 줄이는 표준이다. "AI 통합의 USB-C"로 비유한다.
- 구조는 Claude Code 내장 MCP 클라이언트와 외부 서비스를 감싼 독립 MCP 서버이며, JSON-RPC 2.0으로 통신한다.
- 서버의 기능은 Tools(동작, 부작용 가능), Resources(읽기 전용 데이터), Prompts(템플릿)이고 실사용 대부분은 도구다.
- 전송은 로컬 stdio, 원격 HTTP(OAuth 2.1과 PKCE)가 기본이고 SSE는 HTTP로 대체되었다.
