# 모든 것을 연결하기, MCP로 외부 도구 통합

이 장은 Claude를 사내 Jira나 데이터베이스 같은 외부 시스템과 안전하게 잇는 MCP(Model Context Protocol)를 다룬다. 먼저 조합마다 어댑터를 만들던 N×M 문제가 표준화로 N+M이 되는 원리와 클라이언트-서버 구조, 전송 방식을 배운다. 이어 claude mcp 명령과 .mcp.json 설정, 환경 변수 치환과 범위를 정리한다.

다음으로 Postgres 연결과 사용자 정의 서버 만들기 실습, 공식·서드파티 서버 생태계와 3겹 보안 방어, 스킬과의 결합과 엔터프라이즈 배포, 디버깅과 문제 해결을 다룬다. 코드는 핵심만 싣고 나머지는 말로 풀어 썼다.

---

## 1. 핵심 요점

- MCP는 "AI 통합의 USB-C"다. 클라이언트와 서버가 규약을 한 번씩만 구현해 어댑터를 5×100=500개에서 5+100=105개로 줄인다.
- 구조는 Claude Code 내장 MCP 클라이언트와 독립 MCP 서버이며 JSON-RPC 2.0으로 통신한다. 서버는 Tools, Resources, Prompts를 내놓고 실사용은 대부분 도구다.
- 전송은 "로컬은 stdio, 원격은 HTTP(OAuth 2.1, PKCE)"다. SSE는 HTTP로 대체되었다.
- 설정은 `claude mcp add/list/test/remove` 또는 `.mcp.json`으로 하고, `${VAR}`, `${VAR:-기본값}` 치환 덕에 비밀 없이 설정을 커밋할 수 있다.
- DB는 읽기 전용 계정으로 연결한다. 사용자 정의 서버는 도구 설명, Zod 스키마, stderr 로그 규칙이 핵심이다.
- 보안은 첫 연결 승인, 도구별 승인, OAuth 2.1의 3겹이며 위험은 프롬프트 주입, 도구 권한 남용, 사칭이다.
- MCP는 주방(접근), 스킬은 레시피(사용법)다. 기업은 managed-mcp.json으로 중앙 배포한다. 출력은 10,000 토큰에서 경고, 25,000 토큰에서 절단된다.
