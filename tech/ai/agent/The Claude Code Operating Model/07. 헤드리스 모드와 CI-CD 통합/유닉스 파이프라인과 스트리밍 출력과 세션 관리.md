# 유닉스 파이프라인과 스트리밍 출력, 세션 관리

헤드리스 모드의 가장 우아한 특징은 표준 입력(stdin)을 받는다는 점이다. 그래서 Claude Code를 유닉스 파이프라인(pipe, 앞 명령의 출력을 다음 명령의 입력으로 잇는 방식)의 한 부품으로 쓸 수 있다. 이 문서는 파이프 조합, 긴 작업을 실시간으로 지켜보는 stream-json 이벤트, 호출 사이에 맥락을 이어 주는 세션 관리 옵션(--resume, --continue, --fork-session, --no-session-persistence)을 정리한다.

---

## 1. 유닉스 파이프라인에 끼우기

유닉스 철학의 핵심은 "각 도구는 한 가지를 잘하고, 파이프로 조합한다"이다. Claude Code는 이 원칙을 그대로 따른다.

### 1-1. 입력으로 받기

```bash
cat server.log | claude -p "Find all 500 errors and summarize the root causes"
git diff HEAD~1 | claude -p "Summarize the changes in this commit and format them according to the Conventional Commits specification"
curl -s https://api.example.com/health | claude -p "Determine if the service is healthy"
```

로그 파일 분석, git 변경 요약(Conventional Commits 규격으로), API 응답 해석이 각각 한 줄이다.

### 1-2. 다단계 조합

Claude는 상류 데이터를 받을 뿐 아니라 처리 결과를 하류 도구에 넘길 수도 있다.

```bash
claude -p "Check for security vulnerabilities" --output-format json | jq -r '.result' | mail -s "Security Scan Report" security@company.com
grep -r "TODO" src/ | claude -p "Classify these TODO items by priority"
claude -p "Generate an Express health check route" --output-format text > routes/health.js
```

첫째는 Claude 분석, jq 추출, 메일 알림이고(원서는 줄 끝 `\`로 이어 쓴다), 둘째는 grep으로 먼저 거른 뒤 Claude가 깊이 분석하고, 셋째는 Claude가 만든 코드를 곧바로 파일에 쓴다. 메일 주소는 원서 예시 그대로이며 실제로는 사내 주소로 바꾸어 쓴다.

일괄 처리에서 이 파이프 능력은 Claude를 "의미를 아는 필터"로 만든다. grep, awk, sed 같은 고전 텍스트 도구는 정확한 패턴 매칭에 뛰어나지만 아무것도 이해하지 못한다. Claude는 텍스트를 이해하지만 기가바이트를 통째로 흘려보내도록 만들어지지 않았다. 둘을 파이프로 이으면 양쪽의 장점을 얻는다.

## 2. 스트리밍 출력: 긴 작업의 실시간 감시

오래 걸리는 분석에서는 `--output-format stream-json`으로 전체 작업이 끝나길 기다리지 않고 진행을 실시간으로 본다. 각 줄이 시간순으로 독립된 JSON 객체다. 원서가 보여 주는 이벤트 순서는 다음과 같다.

| 순서 | type(subtype) | 내용 |
|---|---|---|
| 1 | system(init) | session_id, 모델(예: claude-sonnet-4-6), 사용 가능한 도구 목록(Read, Grep, Glob) |
| 2 | assistant | 어시스턴트 메시지(예: "Analyzing...") |
| 3 | user | tool_result(도구 실행 결과) |
| 4 | assistant | 최종 응답(예: "Analysis complete.") |
| 5 | result(success) | total_cost_usd, 최종 result |

첫 줄 system/init 이벤트는 현재 세션의 모델 버전, 사용 가능한 도구 목록, MCP 서버 상태 등 초기화 정보를 알려 주므로 CI 설정 문제를 디버깅할 때 특히 유용하다.

### 실시간 처리 스크립트

원서 예시는 `claude -p "..." --output-format stream-json --allowedTools "Read,Grep,Glob"`의 출력을 `while read -r line`으로 한 줄씩 읽어 jq로 `.type`을 꺼낸 뒤 case로 나눈다.

| type | 처리 |
|---|---|
| system | `[INIT] Model: <.model>` 출력 |
| assistant | `.message.content[0].text`를 꺼내 비어 있지 않으면 `[CLAUDE] 텍스트` 출력 |
| result | `.total_cost_usd`, `.num_turns`로 `[DONE] Finished in N turns. Cost: $X` 출력 |

```bash
claude -p "..." --output-format stream-json --allowedTools "Read,Grep,Glob" | while read -r line; do
  TYPE=$(echo "$line" | jq -r '.type // ""')
  case "$TYPE" in "result") echo "[DONE] ... $(echo "$line" | jq -r '.total_cost_usd // 0')" ;; esac
done
```

참고(노트 작성자): 위 코드는 지면 때문에 result 분기만 남긴 요약이다. 원서의 system, assistant 분기 전체를 포함한 코드는 줄바꿈이 정상이지만 길어서 생략했다.

stream-json은 위의 system, assistant, user, result 외에 두 가지 특수 이벤트를 정의한다.

- **stream_event**(`--include-partial-messages` 필요): Claude 출력의 증분 데이터를 토큰 수준의 텍스트 조각까지 내보낸다. "타자기 효과"를 내는 UI에 알맞지만 CI 자동화에서는 보통 켤 필요가 없다.
- **system/compact_boundary**: 컨텍스트 압축 경계 이벤트다. 대화 기록이 모델의 컨텍스트 창 한계에 가까워지면 Claude가 앞부분을 압축해 공간을 비운다. 긴 분석 작업에서 이 이벤트가 보이면 현재 작업이 컨텍스트 자원을 많이 썼다는 뜻이므로 컨텍스트 손실 위험을 의식해야 한다.

## 3. 세션 관리: 단계 사이에 맥락 잇기

헤드리스에서 시스템은 기본적으로 세션 상태를 저장하지 않으며, 호출마다 완전히 새로운 컨텍스트로 취급한다. 하지만 여러 번의 호출에 걸쳐 맥락이 이어져야 하는 복잡한 시나리오가 있다.

### 3-1. --resume으로 이어 가기

핵심 절차는 세 단계다. (1) 첫 분석을 JSON 출력으로 받아 변수에 담는다. (2) jq로 `session_id`를 꺼낸다. (3) 다음 호출에 `--resume "$SESSION_ID"`를 준다.

```bash
RESULT=$(claude -p "Analyze module dependencies in src/" --output-format json --allowedTools "Read,Grep,Glob")
SESSION_ID=$(echo "$RESULT" | jq -r '.session_id')
claude -p "Based on the previous analysis, identify circular dependency issues" --resume "$SESSION_ID" --output-format text
```

각 단계가 반환하는 JSON 봉투에서 하류에 중요한 필드는 session_id(`--resume`에 넘길 값), result, total_cost_usd, num_turns, is_error다. 이후의 헤드리스 실행은 이것들을 암묵적으로 물려받지 않는다. 이전 result를 다음 프롬프트에 직접 넣거나, session_id를 `--resume`에 넘겨 모델이 맥락을 유지하게 해야 한다. `--resume`의 핵심 가치는 Claude가 이미 읽은 파일, 수행한 분석 단계, 도달한 중간 결론까지 그대로 "상속"하게 하는 것이다. 새 프롬프트에서 맥락을 손으로 다시 설명하는 것보다 상호작용 효율이 크게 오르고 모델 추론의 정확성과 일관성도 보장된다.

### 3-2. 고급 세션 옵션

| 옵션 | 동작 | 쓰임 |
|---|---|---|
| `--continue` | 현재 디렉터리에서 가장 최근 세션을 자동으로 이어 간다. session_id를 찾을 필요가 없다 | `claude -p "Continue the previous analysis" --continue` |
| `--resume "$SESSION_ID" --fork-session` | 기존 세션에서 새 분기를 만든다. 원래 세션은 그대로 두고 지정한 지점에서 새 탐색 경로를 파생 | `claude -p "What if we switch to a microservices architecture?" --resume "$SESSION_ID" --fork-session` |
| `--no-session-persistence` | 지속성 비활성화. 무상태 모드를 강제 | 완전히 격리된 CI/CD에서 세션 기록이 남지 않게 한다 |

`--fork-session`은 Git의 브랜치와 논리가 비슷하다. 지정 세션의 특정 시점에서 새 세션 인스턴스를 갈라낸다. 원래 세션(메인 브랜치)은 변하지 않고, 새 세션(브랜치)은 분기점에서 독립적으로 진행된다. "가정 분석"에 딱 맞다. 같은 코드 베이스의 기준 분석을 마친 뒤 여러 분기를 만들어 서로 다른 리팩터링 방향을 탐색할 수 있다.

---

## 4. 핵심 정리

- stdin을 받으므로 `cat`, `git diff`, `curl` 출력을 파이프로 넣을 수 있고, `--output-format json | jq -r '.result'` 식으로 하류에도 넘긴다. Claude는 grep류 도구와 결합한 "의미 필터" 역할이다.
- stream-json 이벤트는 system/init, assistant, user, result이고, 특수 이벤트로 stream_event(`--include-partial-messages`)와 system/compact_boundary가 있다.
- 세션은 기본 비저장이다. `--resume <session_id>`, `--continue`, `--fork-session`, `--no-session-persistence`로 맥락을 이어 가거나 분기하거나 끈다.
- 이어 가기에는 JSON 출력의 session_id가 필요하므로 첫 호출은 `--output-format json`으로 받는다.
