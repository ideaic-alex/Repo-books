# 요약과 핵심 개념

이 장은 Claude Code를 터미널 안의 똑똑한 비서에서 엔지니어링 워크플로에 끼워 넣을 수 있는 "프로그래밍 가능한 부품"으로 바꾸는 헤드리스 모드와 CI/CD 통합을 다룬다. 전환의 뼈대는 네 가지다. 진입점 -p, 데이터 인터페이스 `--output-format`, 보안 경계 `--allowedTools`, 비용 가드레일 `--max-turns`와 `--max-budget-usd`. 이 문서는 장 전체를 한 번에 되짚고 옵션과 환경 변수를 정리한다.

원서의 요약은 이렇게 말한다. 아키텍처 수준에서 헤드리스 모드의 가장 큰 가치는 Claude Code를 "CI/CD 생태계의 일급 시민"으로 만드는 것이다. 단위 테스트, 정적 분석, 컨테이너 이미지 빌드처럼 AI 코드 리뷰가 파이프라인의 표준 단계가 되고, 명확한 입력 정의, 결정적인 출력 형식, 수치화할 수 있는 비용 예산, 버전 관리에 넣을 수 있는 설정 파일이 필요하다. 도입 전략은 "관찰자 모드"에서 시작해 점차 "관문 모드"로 발전시킨다. 팀이 신뢰를 쌓고 실전 데이터를 모으고 설정을 다듬을 시간을 주기 위해서다. 서두르지 말고, AI 보조 리뷰의 핵심 가치는 "사람을 완벽히 대체"하는 것이 아니라 지능적 필터링으로 사람 리뷰어가 가장 중요한 의사결정에 귀한 에너지를 쏟게 하는 것이다. 다음 8장은 명령줄 매개변수에서 프로그래밍 인터페이스(Agent SDK)의 세계로 나아간다.

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 헤드리스 모드 | `-p`(`--print`)로 비대화형 실행. 결과를 출력하고 종료한다. 권한 플래그가 없으면 승인 대기로 멈춘다 |
| `--output-format` | text(사람용), json(기계용, 비용·세션 메타데이터 포함), stream-json(실시간 감시, NDJSON) |
| total_cost_usd / num_turns / cache_read_input_tokens | 비용 추적 / 라운드 감시 / 프롬프트 캐시 효과 |
| `--max-turns` | 에이전트 턴 수 상한. 도달 시 error_max_turns, 부분 텍스트가 나와도 완성 답이 아니다 |
| `--max-budget-usd` | 비용 상한. 도달 시 즉시 중단, error_max_budget_usd |
| `--allowedTools` / `--disallowedTools` | 화이트리스트(닫힌 세계) / 블랙리스트(열린 세계). 자동화는 화이트리스트 |
| `Bash(git log *)` | 별표 앞 공백이 필수. 없으면 `git log-something`까지 일치 |
| `--dangerously-skip-permissions` | 모든 권한 검사 생략. 엄격히 격리된 컨테이너가 아니면 금지 |
| `--model` / `--fallback-model` | 용도별 모델 / 주 모델 과부하 시 자동 대체 |
| `--system-prompt` / `--append-system-prompt` | 기본 프롬프트 덮어쓰기(위험) / 덧붙이기(권장). `--append-system-prompt-file`은 파일에서 읽기 |
| `--json-schema` | 출력 스키마 강제. 성공 시 structured_output, 재시도 한도 후 실패하면 오류 결과 |
| `--resume` / `--continue` / `--fork-session` / `--no-session-persistence` | 세션 이어 가기 / 최근 세션 자동 이어 가기 / 분기 / 저장 안 함 |
| claude_args | 공식 액션 v1이 모든 CLI 옵션을 전달하는 단일 필드 |
| 에이전트 모드 / 태그 모드 | `prompt`가 있으면 자동 리뷰 / PR 댓글의 `@claude`에 응답. 공존 가능 |
| `--mcp-config` / `--strict-mcp-config` | CI 전용 MCP 설정 지정 / 그 파일만 사용 |
| CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC | 자동 업데이트, 텔레메트리, 오류 보고를 한꺼번에 끄는 종합 스위치 |
| 다섯 겹 방어 | 최소 권한, 비밀 관리, 컨테이너 격리, 비용 보호, 감사 로그 |
| 4단계 도입 | 관찰자, 조언자, 관문(탈출구), 능동 수리(새 커밋) |

## 3. 자주 놓치는 점

- -p만으로는 무인 실행이 안 된다. `--allowedTools`를 같이 줘야 CI가 승인 대기로 매달리지 않는다.
- `--max-turns`에 걸리면 부분 텍스트가 돌아오지만 완성된 답이 아니다. 종료 상태와 result subtype(error_max_turns, error_max_budget_usd)을 확인하지 않으면 스크립트가 성공으로 읽는다.
- 턴 수는 도구 호출 수와 1 대 1이 아니다. num_turns는 도구 호출 수보다 낮게 읽힌다.
- 허용 패턴의 공백(`Bash(git log *)`)은 보안 설정이다.
- 판정은 "critical" 같은 흔한 단어를 grep하지 말고 `<VERDICT>` 같은 명시적 표식으로 한다.
- 리뷰 결과를 셸이나 JS 문자열에 끼워 넣지 말고 파일로 저장해 넘긴다.
- `RESULT=$(claude ...)`는 `set -e`에서도 실패를 숨긴다. `if ! claude ... > 파일; then`으로 종료 코드를 검사한다.
- `--system-prompt`는 도구 사용 방법까지 잊게 한다. 보통 `--append-system-prompt`를 쓴다.
- CI에서는 자동 업데이트를 끄고(`DISABLE_AUTOUPDATER=1` 또는 종합 변수), MCP는 `--strict-mcp-config`로 로컬 설정이 새어 들어오는 것을 막는다.
- 프롬프트로 모델에게 환경 변수나 키를 출력시키지 않는다. 모델이 쓴 텍스트는 GitHub의 자동 마스킹이 못 잡는다.
- 예산 상한과 모델 등급의 구체 수치는 책에서 베끼지 말고 실제 PR 열 개와 열 번 실행으로 직접 정한다.
- 원서의 YAML, 셸 코드는 추출 과정에서 들여쓰기와 줄바꿈이 많이 깨져 있다. 이 노트는 문맥으로 복원했고 각 문서에 그 사실을 적었다.

## 4. 토론 질문 (원서 Discussion questions)

1. 이미 필수 상태 점검이 있는 파이프라인에 Claude Code PR 리뷰를 추가하려 한다. 리뷰는 조언용이어야 하는가 차단용이어야 하는가, 승격 시점은 어떻게 정하는가. Claude가 린터가 할 수 없는 무엇을 맡아야 하며, 오탐은 어떻게 다루는가.
2. `--max-turns 5`와 `--max-budget-usd 0.50` 중 어느 쪽이 어떤 상황에서 먼저 걸리는가. 프로덕션 헤드리스 작업을 설계할 때 어느 지표를 우선해야 하는가, 이유와 함께 설명한다.
3. 이미 쓰는 CI(아직 없다면 코드가 호스팅된 곳의 CI. 리뷰 잡 하나 때문에 플랫폼을 옮길 가치는 없다)를 골라 워크플로 파일을 작성한다. 트리거, 권한, 도구 허용 목록, 두 한도(`--max-turns`, `--max-budget-usd`)를 포함하고, 둘 중 무엇이 먼저 걸릴지와 이유를 말한다.
