# 설치와 수명주기, 네임스페이스

플러그인을 만들었다면 이제 설치하고 관리하고 개발 중 테스트하는 방법, 그리고 여러 플러그인이 한 환경에 함께 설치되었을 때 이름 충돌을 해결하는 방식을 알아야 한다. 모든 관리는 `/plugin` 명령 하나로 통일되어 있다.

이 문서는 설치 출처 세 가지, 설치 시 시스템이 하는 일, 일상 관리 명령, 로컬 개발 방법, 저장 위치와 `CLAUDE_PLUGIN_ROOT`, 네임스페이스 규칙을 다룬다.

---

## 1. 설치 출처 세 가지

| 출처 | 명령 | 쓰는 때 |
|---|---|---|
| 커뮤니티 마켓플레이스 | `/plugin install react-workflow@community` | 공개 카탈로그에서 설치 |
| GitHub 저장소 | `/plugin install github.com/username/react-workflow` | 저장소 주소로 직접 설치 |
| 로컬 디렉터리 | `/plugin install ./path/to/my-plugin` | 개발과 디버깅 중. 재배포 없이 고친 코드를 바로 시험 |

마켓플레이스(marketplace)는 Git 저장소에 호스팅된 플러그인 카탈로그다. 먼저 `/plugin marketplace add`로 추가해야 그 안의 플러그인을 `이름@마켓플레이스`로 설치할 수 있다.

## 2. 설치할 때 일어나는 일

설치 명령을 실행하면 Claude Code는 플러그인 디렉터리의 `plugin.json`을 읽고 해석한 다음 네 가지를 한다.

1. Commands, Agents, Skills를 시스템에 등록한다.
2. 플러그인이 정의한 훅 설정을 현재 사용자의 훅 체인에 병합한다.
3. MCP 서버를 사용 가능한 목록에 추가한다.
4. 이 모든 변경은 완전히 되돌릴 수 있다. `/plugin uninstall <name>`을 실행하면 설치 때 한 모든 변경을 정확히 추적해 취소한다.

## 3. 일상 관리와 로컬 개발

```
/plugin list                    # 설치된 플러그인 목록
/plugin uninstall react-workflow  # 지정한 플러그인 제거
/plugin update react-workflow     # 최신 버전으로 갱신
claude --plugin-dir ./my-plugin-dev   # 로컬 디렉터리를 바로 로드
```

플러그인을 개발할 때는 `--plugin-dir` 옵션으로 로컬 디렉터리를 바로 로드해 표준 설치 과정을 건너뛴다. 코드를 고친 뒤 다시 시작하면 결과를 곧바로 시험할 수 있어 설치와 제거를 반복하지 않아도 된다. 개발과 디버깅 효율이 크게 오른다.

## 4. 저장 위치와 CLAUDE_PLUGIN_ROOT

플러그인은 기본적으로 `~/.claude/plugins/` 아래에 저장된다. 이 위치는 바꿀 수 없다. 설치할 때 플러그인이 캐시 디렉터리로 복사되고, 그 위치를 바꾸는 설정은 없다.

`CLAUDE_PLUGIN_ROOT`를 그런 설정으로 오해하는 일이 있지만 아니다. 이것은 Claude Code가 플러그인마다 자동으로 설정하는 런타임 변수이며, 그 플러그인 자신의 설치 디렉터리를 가리킨다. 목적은 플러그인 내부 경로 참조다. 훅 명령이나 MCP 서버 설정에 `${CLAUDE_PLUGIN_ROOT}/scripts/check.sh`처럼 적으면, 플러그인이 어디에 설치되든 자기 파일을 찾을 수 있다.

## 5. 네임스페이스: 여러 플러그인의 공존

같은 이름의 스킬이나 명령을 가진 플러그인이 여럿 설치되면 어떻게 될까. 플러그인 시스템은 네임스페이스 메커니즘으로 충돌을 자동으로 푼다. 플러그인으로 설치된 명령, 에이전트, 스킬에는 `플러그인이름:구성요소이름` 형태의 정규화된 이름이 자동 부여되어 전역에서 유일해진다.

| 원래 이름 | 종류 | 정규화된 이름 |
|---|---|---|
| `review` | 슬래시 명령 | `/react-workflow:review` |
| `code-reviewer` | 스킬 | `react-workflow:code-reviewer` |
| `security-scanner` | 에이전트 | `react-workflow:security-scanner` |

참고(노트 작성자): 원서 본문은 `code-reviewer`를 어떤 곳에서는 서브에이전트라 하고 어떤 곳에서는 스킬이라 부르는데, 위 표는 바로 뒤 목록의 표기(스킬)를 따랐다.

이름이 겹치지 않으면 `/review`처럼 짧은 이름을 그대로 써도 된다. Claude Code가 유일한 구성 요소로 자동 해석한다. 서로 다른 플러그인이 같은 이름의 구성 요소를 제공한다고 시스템이 감지했을 때만 `/plugin-a:review`처럼 전체 네임스페이스를 붙여 명시해야 한다.

이 메커니즘의 공학적 가치는 두 가지다.

- 협업 걱정이 사라진다. 팀이 사전 조율이나 이름 충돌 걱정 없이 여러 플러그인을 안심하고 설치하고 조합한다.
- 유지 비용이 줄어든다. 플러그인 개발자가 다른 플러그인의 이름을 피해 가며 만들 필요가 없다.

---

## 6. 핵심 정리

- 설치 출처는 마켓플레이스(`이름@마켓플레이스`), GitHub 저장소, 로컬 디렉터리 세 가지이며 관리는 `/plugin` 하나로 한다.
- 설치는 구성 요소 등록, 훅 병합, MCP 서버 추가이며 `/plugin uninstall`로 전부 되돌릴 수 있다.
- 개발 중에는 `claude --plugin-dir`로 설치 없이 시험한다.
- 저장 위치 `~/.claude/plugins/`는 바꿀 수 없다. `CLAUDE_PLUGIN_ROOT`는 저장 위치 설정이 아니라 플러그인 내부 경로 참조용 변수다.
- 구성 요소는 `플러그인이름:구성요소이름`으로 유일해지며, 충돌할 때만 전체 이름을 써야 한다.
