# 과거에서 배우기 메모리 시스템의 엔지니어링 실무

Claude는 세션이 바뀔 때마다 모든 것을 잊는다. 그래서 매번 Express, npm, JavaScript 같은 훈련 데이터의 '주류' 선택으로 쏠린다. 2장은 이 'AI 건망증'을 CLAUDE.md라는 입사 안내서로 푸는 방법을 다룬다. 파일을 어디에 두는지(5계층 메모리), 무엇을 어떻게 쓰는지(WHY, WHAT, HOW와 'Less is more'), 큰 프로젝트에서 규칙을 어떻게 쪼개 필요할 때만 불러오는지(`.claude/rules/`의 조건부 규칙)가 차례로 나온다.

마지막으로 React 프런트엔드, Node.js 백엔드, Python 데이터 프로젝트의 CLAUDE.md 실례를 보며 영역마다 강조점이 다름을 확인한다.

---

## 1. 핵심 요점

- 부족한 것은 모델의 능력이 아니라 맥락이다. 모델의 기본 선택은 프로젝트 표준이 아니라 훈련 데이터의 통계 패턴에서 나온다.
- CLAUDE.md는 시스템 프롬프트 뒤에 우선순위 높은 사용자 메시지로 주입되는 지침이며, 강제 설정이 아니다.
- 5계층은 엔터프라이즈 정책, 사용자(`~/.claude/CLAUDE.md`), 프로젝트(`./CLAUDE.md`), 규칙 디렉터리(`.claude/rules/`), 로컬(`CLAUDE.local.md`)이다. 공식 분류는 네 범위이고 규칙 디렉터리는 책이 따로 세운 층이다.
- 계층은 덮어쓰기가 아니라 누적된다. 충돌 시 구체적인 쪽이 우선하고 엔터프라이즈 정책만 절대적이다. `@path/to/file`로 최대 5단계까지 다른 파일을 불러올 수 있다.
- 파일 하나는 200줄 미만을 목표로 한다. 지시 밀도는 준수 확률에 반비례한다.
- 세 질문 틀 WHY(원리), WHAT(경계), HOW(절차)로 무엇을 쓸지 정한다. 대부분은 WHAT 한 문장이면 충분하다.
- `/init`은 초안을 만들고, `/memory`는 대화 중 갱신한다. 팀 관례 같은 암묵지는 사람이 채워야 한다.
- `.claude/rules/`의 규칙 파일은 `paths` 글롭이 맞을 때만 로딩된다. `paths`가 없으면 전역 규칙이 된다.
- 황금 시험: 지워도 Claude가 올바르게 행동한다면 그 규칙은 CLAUDE.md에 속하지 않는다.
