# 요약과 핵심 개념

이 장은 세 덩어리로 이뤄진다. Claude가 왜 매번 잊는지와 5계층 메모리 구조, 무엇을 어떻게 쓸지에 대한 작성 패러다임, 그리고 규칙을 쪼개 필요할 때만 불러오는 조건부 규칙 시스템이다. 마지막에 세 가지 프로젝트 구성 사례가 이를 통합한다. 이 문서는 전체를 한 번에 되짚고 핵심 용어와 반성 질문을 정리한다.

원서의 요약은 이렇게 이어진다. 시작 장면의 Express와 npm 문제는 모델 능력의 한계가 아니라 '입사 안내서'가 없어서 생긴 일이다. CLAUDE.md는 기술 선택, 코딩 표준, 프로젝트 구조, 자주 쓰는 명령을 기계가 읽는 문서로 굳혀 세션 시작 때 자동 로딩되게 한다. 다음 장은 스킬(Skills)로, CLAUDE.md가 '입사 안내서'라면 스킬은 Claude를 위한 '전문 교육 자료'다.

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | AI 건망증의 원인 | 세션 간 상태가 없고 기본값이 훈련 데이터에서 온다는 점 이해 |
| 2 | CLAUDE.md의 도입 | 시스템 프롬프트 뒤 사용자 메시지로 주입되는 '입사 안내서' |
| 3 | 5계층 메모리 | 정책, 사용자, 프로젝트, 규칙 디렉터리, 로컬 각각의 위치와 책임 |
| 4 | 충돌 처리와 @ 참조 | 누적 병합, 구체적인 쪽 우선, 정책은 절대, 모듈식 구성 |
| 5 | 작성 패러다임 | 'Less is more', WHY/WHAT/HOW, 나쁜 예와 좋은 예 |

| 7 | 조건부 규칙 | `.claude/rules/`와 `paths`로 필요할 때만 로딩 |
| 8 | 세 프로젝트 사례 | 프런트, 백엔드, 데이터 프로젝트별 강조점 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| AI 건망증 | 세션 사이 지속 상태가 없어 매 대화가 백지에서 시작되는 모델의 공통 성질 |
| 설정보다 관례 | 합리적 기본값을 두고 예외만 설정한다는 원칙. Claude의 기본값은 프로젝트가 아니라 훈련 데이터 분포에서 온다 |
| CLAUDE.md | 시작 시 자동 로딩되는 마크다운 지침 파일. 강제 설정이 아니라 지침으로 작동 |
| 엔터프라이즈 정책 계층 | IT 관리자가 시스템 경로나 관리 콘솔로 설정하며 우회 불가인 보안 레드라인 |
| 사용자 계층 | `~/.claude/CLAUDE.md`. 모든 프로젝트에 적용되는 개인 선호 |
| 프로젝트 계층 | 루트의 `CLAUDE.md`. Git에 커밋해 팀이 공유한다 |
| 규칙 디렉터리 계층 | `.claude/rules/`의 주제별 마크다운. `paths`로 조건부 로딩. 공식 분류에서는 프로젝트 범위 안의 기능 |
| 로컬 계층 | `CLAUDE.local.md`. 커밋하지 않는 개인 메모. 수동 생성 시 `.gitignore` 직접 추가 |
| @ 참조 | `@path/to/file`로 다른 파일을 포함. 최대 5단계 중첩 |
| 200줄 지침 | Anthropic 공식 권고. 더 길면 컨텍스트를 더 먹고 준수율이 떨어진다 |
| WHY / WHAT / HOW | 원리(유추 능력), 경계(레드라인), 절차(근육 기억)의 세 질문 |
| `/init` | 디렉터리와 의존성 파일을 스캔해 CLAUDE.md 초안을 생성 |
| `/memory` | 대화 중 메모리 파일을 골라 바로 편집 |
| 조건부 규칙 | `paths` 글롭이 맞는 파일을 다룰 때만 규칙을 컨텍스트에 주입. `paths`가 없으면 전역 |
| 결정 트리형 지침 | 시나리오에서 도구로 가는 매핑을 적어 아키텍처 표류를 막는 작성법 |

## 3. 반성 질문 정리

원서의 반성 질문(Reflection questions) 세 가지를 풀어 쓰면 다음과 같다.

1. 지금 프로젝트에서 Claude가 반드시 알아야 하는 핵심 정보를 가려내 WHY, WHAT, HOW로 분해하고, 30줄 이하의 CLAUDE.md 초안을 쓴다. 쓴 뒤 줄마다 '이 줄을 지우면 Claude가 어떤 실수를 하는가'를 묻는다. 답하지 못하면 그 줄은 불필요할 가능성이 크다.
2. 팀 협업에서 개발자들이 규칙(예: 들여쓰기 2칸 대 4칸)에 의견이 갈릴 때 5계층을 어떻게 활용해 풀 것인가. 통일된 표준을 강제하려면 프로젝트 계층에 둬야 할 규칙은 무엇이고, 개인의 선택 자유를 보존하려면 사용자 계층이나 로컬 계층에 맡길 선호는 무엇인지 구분한다.
3. 프로젝트에서 `/init`으로 CLAUDE.md를 자동 생성해 직접 쓴 버전과 깊이 비교한다. 기계가 정확히 추론하는 명시적 정보는 무엇이고, 사람이 보충해야 하는 '암묵지'는 어떤 종류인가.

참고(노트 작성자): 2번의 힌트는 본문에서 얻을 수 있다. 팀이 합의해 강제할 사항은 커밋되는 프로젝트 계층에, 개인 습관은 사용자 계층이나 `CLAUDE.local.md`에 두면 구체적인 쪽이 우선한다는 원칙에 따라 개인 선호가 팀 표준을 해치지 않는다. 책이 정답을 따로 제시하지는 않는다.

## 4. 자주 놓치는 점

- CLAUDE.md는 강제 설정이 아니라 지침이다. 시스템 프롬프트 안이 아니라 그 뒤의 사용자 메시지로 주입된다.
- `package.json`을 읽게 하는 것으로 대신할 수 없다. 능동 탐색은 도구 호출과 컨텍스트를 쓰고, 아키텍처 결정과 팀 관례는 의존성 목록에 없다.
- 5계층 구분은 책 고유의 정리이며 공식 문서는 Managed Policy, User, Project, Local 네 범위를 쓴다. 용어를 외부 문서와 맞출 때 주의한다.
- 계층은 덮어쓰기가 아니라 누적이다. 충돌은 모델이 구체적인 쪽을 우선해 판단하고, 엔터프라이즈 정책만 우회되지 않는다.
- `CLAUDE.local.md`는 `/init`에서 개인 옵션을 골랐을 때만 자동으로 `.gitignore`에 들어간다. 직접 만들었다면 직접 추가하고, 접속 문자열 같은 비밀 값은 아예 적지 않는 편이 안전하다.
- `.claude/rules/` 파일에 `paths`를 빼먹으면 전역 규칙이 되어 조건부 로딩의 이점이 사라진다.
- '모범 사례를 따르라', '잘 써라' 같은 모호한 지시와 팀 인원, 시작 시점 같은 메타데이터는 컨텍스트만 차지한다.
- `/init` 결과를 그대로 쓰지 않는다. 계층형 아키텍처 제약, 통일 응답 형식, 명명 규칙 같은 암묵지를 사람이 보충해야 한다.
- 원서의 표 2.1은 PDF 추출에서 칸이 흩어져 있어 이 노트의 표는 문맥으로 복원한 것이다.
