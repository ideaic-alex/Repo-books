# CLAUDE.md

**`CLAUDE.md`**는 Claude Code의 **컨텍스트 엔지니어링(Context Engineering)** 체계에서 프로젝트의 노하우를 세션 간 유지해 주는 **지속성 지식 레이어이자 신경망** 역할을 담당합니다.

컨텍스트 윈도우는 에이전트 작업에서 CPU, RAM, 하드드라이브 역할을 수행하는 유일하고 가장 결정적인 제약 자원이며, 모든 파일 및 대화 기록이 한정된 버퍼에 축적되므로 이를 희소 자원으로 관리하는 것이 컨텍스트 엔지니어링의 핵심입니다.

---

## 1. 상시 로드 파일(Always-On File)로서의 비용 구조

- **지속적인 컨텍스트 비용 발생**: `CLAUDE.md`는 단순한 참고용 README 문서가 아니라, **매 대화 요청(turn)마다 Claude의 프롬프트에 자동으로 주입되는 지침 파일**입니다. 따라서 파일에 작성된 모든 줄(line)은 대화 내내 컨텍스트 윈도우 공간을 지속적으로 점유하는 고정 비용을 발생시킵니다.
- **계층적 로딩 체계**: 홈 디렉토리(`~/.claude/CLAUDE.md`), 프로젝트 루트, 하위 디렉토리, 조직 관리(Managed) 경로 등 여러 위치에서 로드되며 **가산적(Additive)**으로 중첩하여 적용됩니다.

---

## 2. 500줄 가이드라인과 정보 필터링 (Context Budgeting)

- **500줄 가이드라인 (The 500-Line Guideline)**: `CLAUDE.md`가 500줄을 초과하면 지침 간의 주의력(attention) 경합이 발생하여 에이전트가 가장 중요한 규칙을 무시하거나 주의력이 분산됩니다. 따라서 파일의 간결함을 유지하는 것은 선택 사항이 아니라 **성능 요구사항(Performance Requirement)**입니다.
- **포함/제외 필터링 기준**: 작성 시 핵심 기준은 **"Claude가 코드를 스스로 읽고 추론할 수 없는 정보인가?"**입니다.
  - **포함 (Include)**: 추측하기 어려운 특정 빌드/테스트 명령어, 기본 표준과 다른 코딩 스타일 예외, 리포지토리 에티켓(브랜치 명명, PR 규칙), 프로젝트 아키텍처 결정 배경, 개발 환경의 특이점(포트 번호, 필수 환경변수), 알려진 데이터/코드 버그 이력.
  - **제외 (Exclude)**: 코드나 `package.json` 등 디펜던시 파일 파싱으로 알 수 있는 사실, 표준 언어 컨벤션, 장황한 외부 라이브러리 공식 문서 및 튜토리얼.

## 3. 컨텍스트 자원 배분 결정 매트릭스 (Decision Matrix)

출처에서는 컨텍스트 예산을 효율적으로 배분하기 위해 각 확장 메커니즘의 소모 비용을 다음과 같이 비교합니다:

| 기능 | 로드 시점 | 로드 대상 | 컨텍스트 비용 |
| --- | --- | --- | --- |
| `CLAUDE.md` | 세션 시작 | 전체 내용 | **매 turn 지속 소비** |
| 스킬 (Skills) | 세션 시작 + 호출 시 | 시작 시 요약 설명만, 호출 시 전체 | 낮음 (호출 전까지 설명만 로드) |
| 서브에이전트 (Subagents) | 생성(Spawn) 시 | 지정된 스킬이 포함된 독립 컨텍스트 | **메인 세션과 완전 격리** (요약만 반환) |
| 훅 (Hooks) | 트리거 시 | 없음 (외부 프로세스 실행) | **제로(0) 비용** |
| MCP 서버 | 세션 시작 | 모든 도구 정의 및 스키마 | **매 turn 지속 소비** |

- **스킬 최적화**: 스킬 프런트매터에 `disable-model-invocation: true`를 지정하면 세션 시작 시 설명 로드조차 차단하여 수동 호출 전까지 **컨텍스트 비용을 제로(0)**로 유지할 수 있습니다.

## 4. 모듈화, 자동 축소 대응, 및 오류 패치

- **`@path` 임포트 모듈화**: 루트 `CLAUDE.md`를 슬림하게 유지하면서 깊이 있는 가이드를 제공하기 위해 `@docs/architecture.md` 형태의 참조 임포트 문법을 활용합니다.
- **자동 축소 보호 (`Compact Instructions`)**: 컨텍스트 용량이 한계(약 95%)에 도달하여 자동 축소(Auto-compaction)가 실행될 때, `Compact Instructions` 헤더 하위에 작성된 지침은 요약 과정에서 손실되지 않고 온전히 보존됩니다.
- **반복 에러 직격 수선 (Targeted Error Patching)**: 에이전트가 특정 모듈 경로를 잘못 참조하는 등 반복 실수를 보일 때, 해당 관찰된 에러에 대한 직격 수선 규칙을 `CLAUDE.md`에 추가함으로써 동일 실수를 영구 차단합니다.

---

## 5. 제도적 기억(Institutional Memory)의 복리 효과

- **엔드오브세션(End-of-Session) 업데이트 루프**: 세션이 끝날 때마다 Claude에게 "이번 작업에서 새로 파악한 프로젝트 특이점이나 해결책을 `CLAUDE.md`에 추가할 지침으로 제안해달라"고 요청합니다.
- **복리 성장**: 한 개발자의 발견이 `CLAUDE.md`로 정제되어 리포지토리에 커밋(VCS)되면, 팀 전체와 향후 세션의 에이전트가 동일 실수를 반복하지 않아 **프로젝트 지식이 복리로 성장(Compounding)**하게 됩니다.
- **페르소나 적응 및 비개발 도메인 확장**: `CLAUDE.md`는 재무 분석 등 세션을 넘나드는 도메인 분석 상태를 보존하는 지속성 메모리로 기능하며, 사용자 역할(예: 비개발자 디자이너)에 맞춰 설명 수준과 작업 단위를 조절하는 페르소나 적응형 프롬프트로도 활용됩니다.
