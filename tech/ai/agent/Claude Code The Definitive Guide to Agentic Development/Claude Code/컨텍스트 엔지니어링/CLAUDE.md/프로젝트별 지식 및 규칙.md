# 프로젝트별 지식 및 규칙

출처에서 논의하는 **프로젝트별 지식 및 규칙(Project-Specific Knowledge & Rules)**은 Claude Code의 전체 `CLAUDE.md` **컨텍스트 엔지니어링 체계**에서 프로젝트의 고유한 맥락과 관습을 유지하는 **팀 공유형 지속성 지식 레이어(Persistent Knowledge Layer)** 역할을 담당합니다.

---

## 1. 프로젝트별 지식 및 규칙: 포함할 정보 vs 제외할 정보

출처에서는 프로젝트 `CLAUDE.md`에 담아두어야 할 최우선 필터링 기준으로 **"Claude가 코드를 스스로 읽고 추론할 수 없는 정보인가?"**를 제시합니다.

- **포함해야 할 정보 (Include)**:
  - **특정 빌드 및 테스트 명령어**: 프로젝트에서 사용하는 고유한 테스트 러너 실행 명령 및 빌드 플래그
  - **표준 가이드라인에서의 서식 예외**: 언어별 기본 코딩 가이드라인과 다른 서식예외(예: 탭 사용, 특정 import 순서)
  - **리포지토리 에티켓**: 브랜치 명명 규칙, PR 작성 가이드, 머지 방식(squash/rebase 등)
  - **아키텍처 결정 배경 및 제약**: 코드 구조에 숨겨진 설계 의도(예: "헥사고날 아키텍처 적용, 도메인 레이어는 인프라 레이어를 직접 참조 금지")
  - **개발 환경의 특이점(Traps)**: 테스트 DB 포트 번호, 필수 환경 변수 등 코드상으로 발견하기 어려운 환경 제약
  - **알려진 데이터/코드 버그 이력**: 특정 DB 컬럼의 마이그레이션 버그 배경 등 사전에 알지 못하면 탐색 시간을 허비하게 되는 트랩
- **제외해야 할 정보 (Exclude)**:
  - 언어나 프레임워크의 표준 컨벤션 및 기본 동작 방식
  - `package.json`이나 의존성 매니저 파일, 코드 구조 파싱으로 스스로 알 수 있는 사실
  - 외부 유명 라이브러리의 장황한 공식 문서 및 일반 튜토리얼

## 2. 팀 공유와 지식의 복리 효과 (Compounding Institutional Memory)

프로젝트 루트의 `CLAUDE.md`는 리포지토리 버전 관리 시스템(VCS/Git)에 커밋되어 팀원 전체에 동기화됩니다.

- **지식의 복리 성장**: 한 개발자가 작업 중 특정 모듈 참조 에러나 빌드 트랩을 발견하여 `CLAUDE.md`에 단 30초 만에 교정 지침을 추가하면, 해당 리포지토리에서 작업하는 모든 팀원과 향후 세션의 에이전트가 동일한 실수를 반복하지 않습니다.
- **제도적 기억(Institutional Memory) 형성**: 선임 엔지니어 머릿속에만 암묵적으로 존재하던 노하우와 예외 케이스가 명시적인 규칙으로 정제되어 프로젝트 자산으로 축적됩니다.

---

## 3. `CLAUDE.md`라는 더 큰 맥락에서의 구조적 위상

프로젝트별 지식은 전체 `CLAUDE.md` 컨텍스트 체계 안에서 다음과 같은 시스템 제약과 연계되어 관리됩니다.

1. **계층적 로딩 (Hierarchy)**: `~/.claude/CLAUDE.md`(사용자 개인 전역 설정) 위에 프로젝트 루트의 `CLAUDE.md`가 가산적(Additive)으로 얹히며, 하위 디렉터리별 `CLAUDE.md` 및 조직 단위의 Managed `CLAUDE.md`와 계층 구조를 이룹니다.
2. **상시 로드(Always-On) 비용과 500라인 가이드라인**: `CLAUDE.md`에 작성된 모든 규칙은 매 요청(turn)마다 주입되어 컨텍스트 윈도우(RAM) 공간을 상시 소비합니다. 주의력이 분산되어 핵심 규칙이 무시되는 것을 막기 위해 500라인 이내로 슬림하게 유지해야 합니다.
3. **`@path` 임포트를 통한 분산 관리**: 루트 `CLAUDE.md`를 얇게 유지하면서 깊이 있는 프로젝트 스펙을 제공하기 위해 `@docs/architecture.md` 형태의 파일 참조 임포트 문법을 활용합니다.
4. **스킬(Skills)과의 역할 분담**: 매번 필요하지 않고 특정 작업(예: DB 마이그레이션, 배포 절차) 시에만 필요한 참조 지침은 스킬로 분리하여 컨텍스트 예산을 절약합니다.
5. **자동 축소 보호 (`Compact Instructions`)**: 세션이 길어져 자동 컨텍스트 축소(Auto-Compaction)가 발생하더라도 반드시 보존되어야 하는 프로젝트 핵심 규칙은 `Compact Instructions` 헤더 하위에 배치합니다.
