# 스킬

Claude Code의 **컨텍스트 엔지니어링(Context Engineering)** 체계에서 **스킬(Skills)**은 한정된 **컨텍스트 윈도우(Context Window)** 자원을 보호하고 최적화하기 위한 핵심적인 **온디맨드 로딩(On-Demand Loading)** 메커니즘입니다.

---

## 1. 컨텍스트 엔지니어링 관점에서의 스킬(Skills)의 본질

Claude Code에서 컨텍스트 윈도우는 에이전트의 CPU, RAM, 하드드라이브 역할을 모두 담당하는 가장 희소하고 결정적인 제약 자원입니다. 대화 내용, 읽어들인 파일, CLI 실행 결과 등 모든 정보가 고정된 버퍼 크기를 점유하므로, 이를 효율적으로 배분하는 것이 컨텍스트 엔지니어링의 핵심입니다.

매 대화 요청(turn)마다 항상 로드되어 지속적인 컨텍스트 공간과 비용을 소모하는 `CLAUDE.md`(Always-On File)와 달리, **스킬**은 작업이 필요한 순간에만 본문을 불러오는 **지연 로딩/온디맨드 구조**를 통해 컨텍스트 예산(Context Budget)을 획기적으로 절약합니다.

---

## 2. 온디맨드 로딩(On-Demand Loading)의 작동 메커니즘

스킬의 온디맨드 로딩 방식은 2단계 로딩 구조를 가집니다:

1. **세션 시작 시 (Session Start - 경량화 로딩)**:
   - 세션이 구동될 때 스킬의 전체 본문이 아닌, 해당 스킬이 어떤 역할을 하는지 나타내는 짧은 **요약 설명(Description)**만 로드됩니다.
   - 따라서 스킬 내에 200줄 이상의 복잡한 절차서가 포함되어 있더라도, 실제로 호출되기 전까지는 매우 적은 설명 토큰 비용만 상시 발생합니다.
2. **작업 수행 시 (Invocation - 온디맨드 주입)**:
   - Claude가 자율적으로 해당 스킬이 필요하다고 판단하거나 사용자가 직접 `/skill-name` 명령어로 호출하는 순간, 비로소 **전체 스킬 본문**이 메인 컨텍스트 윈도우로 불러와집니다.
   - 필요한 특정 타임라인에만 상세 맥락을 주입하므로 대화 버퍼가 조기에 가득 차거나 자동 축소(Auto-compaction)로 인해 지침이 손실되는 현상을 막아줍니다.

---

## 3. 상시 컨텍스트 비용 제로(0) 최적화: `disable-model-invocation: true`

일부 스킬(예: 프로덕션 배포, 릴리스 체크리스트, 대규모 코드 리팩토링 등)은 Claude가 스스로 판단하여 실행하기보다 개발자가 수동으로 제어하는 것이 안전합니다.

- **수동 전용 스킬 설정**: 스킬 파일의 프런트매터(Frontmatter)에 `disable-model-invocation: true` 옵션을 선언합니다.
- **제로 비용(Zero Cost) 효과**: 이 옵션이 지정되면 세션 시작 시 요약 설명(Description)조차 로드되지 않으며, 모델의 사용 가능한 도구 목록에서도 완전히 감춰집니다.
- **작동 방식**: 오직 사용자가 `/skill-name`을 직접 실행할 때만 본문이 로드되므로, 수동 호출 전까지 해당 스킬의 **상시 컨텍스트 비용은 완전히 제로(0)**가 됩니다.

---

## 4. 컨텍스트 예산 배분 결정 매트릭스 (Skill vs. CLAUDE.md)

출처에서는 정보의 특성에 따라 로딩 메커니즘을 다음과 같이 엄격히 분리할 것을 권장합니다:

| 구분 | 로드 시점 | 컨텍스트 소모 구조 | 적합한 정보 유형 |
| --- | --- | --- | --- |
| `CLAUDE.md` | 매 대화 turn마다 | 상시 전체 내용 점유 (Always-On) | 매번 준수해야 하는 빌드/테스트 명령, 코딩 스타일 예외, 아키텍처 제약, 환경 특이점 |
| 일반 스킬 (Skill) | 세션 시작 + 호출 시 | 시작 시 요약 설명, 호출 시 전체 본문 로드 | DB 마이그레이션, API 연동 가이드, 배포 체크리스트 등 특정 작업 시에만 필요한 참조 지침 |
| **수동 스킬 (`disable-model-invocation`)** | 수동 호출 시 | 수동 실행 전까지 제로(0) 비용 | 프로덕션 배포, 릴리스 체크리스트 등 사용자가 직접 통제하려는 작업 |

- **오분류 시 발생하는 리스크**:
  - 매번 필요한 상시 규칙을 스킬로 분류하면, 스킬이 로드되지 않은 상태에서 Claude가 규칙을 위반하게 됩니다.
  - 반대로 특정 작업 시에만 필요한 장황한 매뉴얼을 `CLAUDE.md`에 집어넣으면, 매 요청마다 컨텍스트를 낭비하여 500줄 가이드라인을 초과하고 모델의 주의력을 분산시킵니다.

---

## 5. 단계적 공개(Progressive Disclosure)와 서브에이전트 격리

- **단계적 공개 (Progressive Disclosure)**: 스킬 구조를 `skill.md`(기본 지침), `scripts/`(실행 도구), `references/`(상세 참조 문서)로 분리하여 필요할 때만 참조 문서를 읽어들임으로써 컨텍스트 소모를 최소화합니다.
- **서브에이전트와의 결합 (Context Isolation)**: 대량의 파일 읽기나 조사가 수반되는 스킬을 서브에이전트에서 실행하거나 컨텍스트 포크(fork) 환경에서 구동하면, 중간 탐색 기록은 모두 버려지고 오직 최종 요약만 메인 세션으로 전달되어 메인 맥락을 깨끗하게 유지할 수 있습니다.
- **크로스 에이전트 표준 (Cross-Agent Standard)**: 스킬은 오픈 표준 형식으로 작성되어 `npx skills add` 명령을 통해 Claude Code뿐만 아니라 다양한 AI 코딩 에이전트 간에 손쉽게 공유할 수 있습니다.
