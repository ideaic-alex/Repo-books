# 핵심 정리

이 문서는 5부(19장부터 25장)의 요점을 한곳에 모은 복습용 정리다. 19장부터 22장은 각 장 끝의 장 요약과 핵심 용어를 바탕으로, 23장부터 25장은 본문 전체를 바탕으로 정리했다. 기능과 요금 같은 세부는 책이 쓰인 시점 기준이다.

---

## 1. 부 전체 흐름

| 장 | 다루는 것 | 한 줄 요점 |
|---|---|---|
| 19장 노코드 만들기 | 설명으로 도구와 웹페이지 만들기 | 명세에 경계 사례를 넣고, 구체적 피드백으로 고치고, 공유 전에 시험한다 |
| 20장 자동화 입문 | 스킬, 커넥터, 재사용 동작 | 빈도, 일관성, 판단 필요를 따지고 좁은 권한으로 작게 시작한다 |
| 21장 MCP | AI와 도구를 잇는 열린 표준 | 사용자는 표준이 아니라 그 위의 개별 커넥터를 쓴다 |
| 22장 코딩 입문 | 코딩을 시작하는 길 | 목표를 밝히고, 작은 완성품을 만들고, 실행 전에 설명을 받는다 |
| 23장 Claude Code | 코드 폴더에서 일하는 에이전트 | 범위, 버전 관리, 실제 변경 검토로 가드레일을 세운다 |
| 24장 디버깅 | 오류를 체계적으로 풀기 | 정보를 갖춰 묻고, 한 번에 하나씩 시험하고, 뿌리 원인을 이해한다 |
| 25장 Claude API | 채팅 창 너머의 연결 | 자동, 대규모, 제품 내 기능일 때 쓰고, 사용량으로 비용이 늘어난다 |

## 2. 핵심 개념 정리

| 개념 | 쉬운 설명 | 쓰이는 장 |
|---|---|---|
| 기능 명세(functional specification) | 도구가 해야 할 일, 입력, 출력, 동작을 적은 설계도 | 19장 |
| 경계 사례(edge case) | 빈 값, 극단값처럼 보통 범위를 벗어난 입력 | 19장, 24장 |
| 커넥터(connector) | Claude와 외부 도구나 서비스를 잇는 설정된 연결 | 20장, 21장 |
| 권한 범위(permission scope) | 자동 연결이 할 수 있는 접근과 행동의 한도 | 20장 |
| MCP(Model Context Protocol) | AI가 외부 도구와 연결되는 공통 방식의 열린 표준 | 21장 |
| 에이전트형(agentic) | 넓은 목표를 향해 여러 행동을 스스로 이어 가는 방식 | 23장 |
| 가드레일(guardrail) | 자율 작업을 검토 가능한 범위에 두는 한계와 점검 지점 | 23장 |
| 최소 재현(minimal reproduction) | 같은 버그가 나는 가장 작은 코드 | 24장 |
| 뿌리 원인(root cause) | 증상 밑의 실제 이유 | 24장 |
| 토큰 기반 요금 | 처리한 글의 양에 따라 매기는 요금 | 25장 |

## 3. 자주 놓치는 점

- 도구를 만들 때 정상 경로만 적고 빈 입력, 0, 중복 클릭 같은 경계 사례를 빠뜨려 공유 후에 깨진다.
- "더 좋게 해 줘" 같은 막연한 수정 요청은 소용이 없다. 어떤 문제가 어떤 조건에서 났는지 정확히 적는다.
- 자주 하는 일이라도 판단이 매번 달라야 하는 일은 자동화 후보가 아니다. 반복, 일관성이 있어야 한다.
- 커넥터에 "혹시 몰라서" 넓은 권한을 주고, 신뢰가 쌓이기도 전에 사람의 점검을 없앤다.
- MCP 자체를 이해해야 쓸 수 있다고 오해한다. 보통은 만들어진 커넥터를 쓰면 되고, 최신 기술 사항은 공식 문서로 확인한다.
- 모르는 코드를 설명 없이 바로 실행한다. 특히 현실에 영향을 주는 코드는 실행 전에 쉬운 말로 풀어 달라고 한다.
- Claude Code의 "작업 완료"와 "테스트 통과" 보고를 그대로 믿는다. 실제 변경을 읽고 테스트를 직접 돌린다.
- 간단한 질문에도 무거운 에이전트 작업을 쓴다. 작고 독립적인 일은 채팅이 더 빠르고 검토하기 쉽다.
- 오류 메시지를 기억으로 바꿔 쓰거나, 여러 곳을 한꺼번에 고쳐서 무엇이 효과였는지 알 수 없게 된다.
- 증상만 사라진 해결에 만족한다. 왜 고장 났는지 내 말로 설명할 수 있을 때까지 끝난 것이 아니다.
- 서비스에 Claude를 넣어야 하는 모든 일에 API가 필요하다고 단정한다. 잘 설정한 프로젝트로 충분할 수 있다.
- API 비용을 구독처럼 고정이라고 생각한다. 사용량에 따라 늘어나므로 약속 전에 대략적인 추정을 받는다.
- 개발자에게 넘기면 끝이라고 여긴다. 프롬프트 의도, 어조, 검증 기준은 내 전문성이 필요한 부분이다.
