## 2. 핵심 개념 정리

| 개념 | 쉬운 설명 | 관련 장 |
|------|-----------|---------|
| 프로젝트 지식 | 프로젝트 안 모든 대화가 쓰는 엄선한 파일과 문서 | 6장 |
| 사용자 지침 | 프로젝트 전체에 자동 적용되는 구체적 상시 안내 | 6장 |
| 메모리 | 일반 대화에 걸쳐 선호와 반복 사실을 간직하는 기능 | 7장 |
| 아티팩트 | 대화 옆 별도 패널에서 고쳐 가는 독립 결과물 | 8장 |
| 검색형 일과 추론형 일 | 사실을 찾는 일과 자료로 결론을 내는 일 | 9장 |
| 구간별 분석과 추출 | 긴 문서를 나눠 읽고 범주별로 뽑는 방법 | 10장 |

세 층의 기억 모형은 메모리가 넓은 선호를, 프로젝트 지식이 한 작업의 깊은 맥락을, 이번 프롬프트가 한 번의 지시를 맡는다는 것이다. 예를 들어 컨설턴트는 이름과 문체 선호를 메모리에, 고객 서류를 고객별 프로젝트에, 오늘의 요청을 프롬프트에 둔다.

## 3. 자주 놓치는 점

- 프로젝트 지식에 파일을 몽땅 넣으면 오히려 결과가 흐려진다. 엄선한 다섯 개가 거른 적 없는 쉰 개보다 낫다.
- 사용자 지침을 한 번 쓰고 다시 열지 않으면 바뀐 선호와 어긋난다.
- 프로젝트 사이와 일반 채팅으로 정보가 자동으로 흐르지 않는다. 격리는 결함이 아니라 설계다.
- 메모리의 낡은 항목은 대화마다 말로 우회하지 말고 설정에서 직접 고치거나 지운다.
- 메모리가 켜져 있어도 결과에 중요한 세부는 그 대화에 직접 적는다.
- 아티팩트를 막연히 "더 좋게" 고치라고 하면 잘된 부분까지 되돌아간다. 바꿀 곳과 둘 곳을 함께 말한다.
- 웹 검색은 저절로 쓰이지 않는다. 시간에 민감한 사실은 검색이 쓰였는지 확인한다.
- 일반 요약 하나는 세부를 압축한다. 필요한 범주는 전용 추출 패스로 뽑고, 중대한 문서는 원문과 대조한다.
