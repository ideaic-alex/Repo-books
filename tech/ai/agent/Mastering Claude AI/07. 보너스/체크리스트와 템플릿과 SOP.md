# 체크리스트와 템플릿과 SOP

보너스의 네 번째부터 여섯 번째 묶음은 체크리스트 20개, 템플릿 20개, SOP(Standard Operating Procedure, 표준 작업 절차) 20개다. 원서로는 447쪽부터 456쪽까지다. 세 가지는 쓰임이 다르다. 체크리스트는 빠뜨림을 잡는 점검표이고, 템플릿은 입력과 출력의 틀이며, SOP는 반복 업무를 같은 순서로 하게 하는 절차다. 이 문서는 세 묶음의 내용을 간추려 정리한다.

---

## 1. 체크리스트 20개

각 체크리스트는 네다섯 칸의 짧은 점검표이고, 대부분 본문 장 번호가 붙어 있다. 아래 표는 이름과 핵심 칸을 요약한다.

| 번호와 이름 | 핵심 점검 칸 |
|---|---|
| 1. 새 프로젝트 설정 | 이름이 분명한 프로젝트 만들기, 전부가 아닌 엄선한 지식 추가, 구체적 지침, 검증 등급 정의, 유지 담당자 지정 |
| 2. 이메일 보내기 전 | 첫 줄에 목적, 다음 행동 하나, 관계에 맞는 어조, 소리 내어 읽기, 검증 안 된 주장 없음 |
| 3. 대외 콘텐츠 게시 전 | 사실 확인 끝, AI 티 수정 패스, 실제 샘플과 어조 대조, 필요시 법무 검토, 사람의 최종 통독 |
| 4. 새 자동화 설정 | 좋은 자동화 후보인지 확인, 가장 좁은 권한, 사람 확인 지점, 저위험 실제 사례로 먼저 시험 |
| 5. 긴 문서 검토 | 접근 방식 선택, 길이에 맞는 절 단위 확인, 범주별 추출, 핵심 대목을 원문과 대조 |
| 6. 데이터 분석 검증 | 모호한 열 설명, 정리 패스와 판단 항목 검토, 계산 과정 노출, 상식 점검, 합계 교차 확인 |
| 7. 새 팀원 온보딩 | 공유 프로젝트 개요, 핵심 기준 문서, 예시 결과물, 연락 창구 |
| 8. 민감 정보 처리 | 민감도 등급 파악, 가능하면 대체 데이터, 현재 데이터 처리 설정 확인, 규제 분야의 전문 의무 확인 |
| 9. 노코드 도구 출시 전 | 엣지 케이스 포함 기능 명세, 이상한 입력 시험, 예상 입력 시험, 공유 전 직접 검토 |
| 10. 주간 작업 공간 점검 | 쓸 만한 대화 이름 정리, 컨텍스트 패킷에 추가할 것 메모, 월간 점검 표시 |
| 11. 월간 시스템 점검 | 컨텍스트 패킷 갱신, 프로젝트 지식의 낡음 점검, 필요 없는 것 정리 |
| 12. 분기 시스템 점검 | 메모리 항목 검토, 요금제 재평가, 팀 기준 검토, 새 기능 확인 |
| 13. 연간 시스템 점검 | 종합 품질 표본 점검, 가장 지렛대 큰 용도 재평가, 복잡도 증식 요소 제거, 처음 목표와 회고 재확인 |
| 14. 마케팅 캠페인 출시 | 브랜드 어조 브리프 참조, 개별 글 전에 핵심 메시지 확정, 안 사이의 진짜 다양성, 사실 확인, 글 사이 일관성 |
| 15. 조사 브리프 완료 | 결정과 연결된 좁은 질문, 출처 품질 메모와 다수 출처, 이견과 불확실성 보존, 핵심 주장 독립 검증 |
| 16. 병합 전 코드 검토 | 요약이 아닌 실제 차이(diff) 검토, 테스트 직접 재실행, 범위 확장 점검, 민감 영역 재확인 |
| 17. 디버깅 세션 | 버그 안정적 재현, 최소 재현 분리, 변경 전에 가설, 한 번에 하나씩 시험, 증상이 아닌 근본 원인 이해 |
| 18. 고객 납품물 최종 점검 | 합의 범위와 일치, 고객에 맞는 어조, 모든 숫자 검증, 형식과 구조 정돈 |
| 19. 새 커넥터와 권한 설정 | 읽는 것 이해, 할 수 있는 일 이해, 가장 좁은 범위만 허용, 실패 시나리오 고려 |
| 20. 개인 주간 회고 | 성과와 어려움 기록, 다음 주 우선순위, 위임과 자동화와 포기 후보, 반복 유지 일정 반영 |

여기서 눈에 띄는 것은 세 가지다. 첫째, 검증 항목(사실, 숫자, 원문 대조)이 거의 모든 점검표에 있다. 둘째, 주간, 월간, 분기, 연간 점검(10-13번)이 하나의 유지 리듬을 이룬다. 셋째, 권한을 다루는 점검표(4번, 19번)는 둘 다 "가장 좁은 권한"을 요구한다.

## 2. 템플릿 20개

템플릿은 대괄호를 채우는 짧은 양식이다. 용도별로 묶으면 이해가 쉽다.

- **맥락과 지침**: 컨텍스트 패킷(목표와 독자, 좋은 예시 2-3개, 피할 예시 1개, 반복되는 사실과 제약), 프로젝트 지침(이 프로젝트의 용도, 구체적이고 이름 붙일 수 있는 어조, 항상, 절대, 확실하지 않으면 가정하지 말고 질문), 브랜드 어조 브리프(성격 세 가지, 긍정 예시 2-3개, 이유를 단 부정 예시 1개, 항상과 절대의 어휘 규칙, 독자).
- **글과 소통**: 업무 이메일(목적 한 문장, 필요한 맥락 2-3문장, 분명한 다음 행동 하나), 사내 메모(요약 한 문장, 배경, 결정 또는 공지, 기대하는 행동), 회의록의 할 일(원문 메모에서 행동, 담당, 기한을 추출), 분기 사업 검토(진행, 위험, 요청의 세 단락 이내), 고객 제안서 개요(고객 목표, 접근법, 범위, 일정, 투자, 다음 단계).
- **만들기와 오류**: 기능 명세(하는 일, 입력, 출력과 동작, 처리할 엣지 케이스, 쓰는 방법), 디버깅 요청(정확한 오류 전문, 관련 코드, 기대 동작, 실제 동작, 이미 시도한 것).
- **조사와 결정**: 조사 브리프(질문, 정보를 줄 결정, 출처 메모가 달린 현재 발견, 열린 질문, 배제한 것과 이유), 의사결정 틀(결정, 10점 만점 가중치가 붙은 기준, 선택지, 점수와 근거 표, 가중 합계), 검증 기준(가벼운, 보통의, 엄격한, 최대(사람 전문가 검토 포함) 검증을 적용할 일의 유형).
- **데이터와 팀**: 데이터 정리 검토(데이터셋, 중복과 결측과 일관성 없는 범주 같은 확인할 문제, 항목별 처리안), 팀 온보딩 개요(공유 프로젝트, 핵심 기준, 예시 결과물, 연락 창구), 신규 입사자 패킷(직무, 첫 주 우선순위, 주요 연락처, 공유 자료, 무엇을 누구에게 물을지), 민감도 정책(낮음은 자유 공유, 보통은 가능하면 익명화, 높음은 최대 주의하고 최신 문서 확인).
- **자동화와 회고**: 자동화 안전장치(과제, 범위 경계, 가장 좁은 권한 수준, 사람 확인 지점, 감독을 줄일 근거), 개인 주간 회고(성과, 어려움, 다음 주 우선순위, 위임과 자동화와 포기 후보), 프로젝트 사후 회고(잘된 것, 안 된 것, 근본 원인, 다음에는).

예를 들어 자동화 안전장치 템플릿을 채우면 다음처럼 된다.

```text
과제: 연체 청구서 독촉 메일 초안 작성
범위 경계: 법적 조치 언급과 금액 협상은 하지 않음
권한 수준: 청구 내역 읽기만, 발송 권한 없음
사람 확인 지점: 모든 메일을 담당자가 읽고 직접 발송
감독을 줄일 근거: 10건 연속 수정 없이 승인되면 소액 계정만 재검토
```

## 3. SOP 20개

SOP는 반복 업무의 목적과 단계를 적은 것이다. 대부분 "초안은 Claude, 판단과 발송은 사람"이라는 구조이며, 아래 표는 이름과 단계 요약을 보여 준다.

| 번호와 이름 | 단계 요약 |
|---|---|
| 1. 신규 고객 프로젝트 | 이름 있는 프로젝트, 접수 문서를 지식에 추가, 접수 통화 노트로 지침 작성, 환영 자료와 첫 안건 생성, 발송 전 사람 검토, 지식 유지 담당자 지정 |
| 2. 주간 콘텐츠 게시 | 캘린더와 주제 확인, 개요 승인, 절 단위 작성, 일관성과 구체성과 어조 패스, 사실 확인, 최종 통독, 게시와 기록 |
| 3. 미납 청구서 | 단계에 맞는 독촉 초안, 계정 민감도에 맞춘 어조 검토, 발송, 응답 기록, X일 내 미해결이면 기준대로 상향 |
| 4. 신규 입사자 문서 준비 | 직무 양식, 직무별 내용 생성, 인사팀 맞춤 수정, 입사 전 발송, 첫날 수령 확인 |
| 5. 서명 전 계약 검토 | 절 단위 분석, 재무 조건과 기한과 해지 조항 추출, 갱신이면 이전 버전과 비교, 표시 항목 법무 검토, 승인 |
| 6. 월간 데이터 보고 | 최신 추출 확보, 판단 기록과 함께 정리, 표준 틀로 분석, 표본 점검과 과정 노출과 상식 점검으로 검증, 보고서 작성, 사람 검토, 배포 |
| 7. 부정적 공개 후기 대응 | 공감적이고 방어적이지 않은 답변 초안, 사실과 어조 검토, 공개 게시, 필요시 사적으로 후속 |
| 8. 새 자동화 도입 | 후보 확인, 좁은 범위, 최소 권한, X건 동안 사람 확인 병행, 실적 검토, 근거가 있을 때만 확대 |
| 9. 분기 팀 기준 검토 | 최근 결과 표본, 문서화된 기준과 대조, 격차 파악, 문서 갱신, 변경 공지 |
| 10. 운영 장애 디버깅 | 안정적 재현, 최소 재현 분리, 가설, 비운영 환경에서 단일 수정 시험, 근본 원인 해결 확인, 모니터링하며 배포 |
| 11. 이사회와 경영진 보고 준비 | 분기 데이터와 노트 수집, 발표자 승인 개요, 개요대로 초안, 모든 수치 사실 확인, 초안으로 리허설 |
| 12. 새 공급사 평가 | 검토 전에 기준과 가중치 정의, 다수 공급사 구조적 비교, 평판과 레퍼런스 확인, 최저점 선택지 최대 변호, 근거와 함께 결정 문서화 |
| 13. 민감한 인사 소통 | 실제 관계 맥락 제공, 여러 전략적 접근 요청, 사람이 고르고 다듬음, 필요시 관리자나 인사 검토, 후속 계획과 함께 전달 |
| 14. 고객 납품물 품질 관리 | 합의 범위대로 초안, 자체 편집 패스, 사실과 숫자 검증, 고객 선호 어조 점검, 사람의 최종 서명 |
| 15. 새 팀원 시스템 권한 | 직무에 맞는 권한 수준 결정, 관련 공유 프로젝트 접근, 온보딩 자료, 30일 점검 일정 |
| 16. 연간 종합 품질 검토 | 1년치 표본, 처음 기준과 대조, 격차의 근본 원인, 프로세스 갱신, 발견과 내년 계획 문서화 |
| 17. 조사 요청 접수 | 요청자와 정밀하고 결정과 연결된 질문 설정, 출처 품질 메모와 함께 수집, 이견 표시한 종합, 핵심 주장 검증, 조사 브리프로 전달 |
| 18. 마케팅 주장 승인 | 초안의 모든 구체적 사실 주장 표시, 각각 독립 검증, 규제 대상 주장은 법무 검토, 게시 전 승인 |
| 19. 개인 주간 시스템 유지 | 한 주의 대화 정리, 패킷에 추가할 것 메모, 월간 점검 항목 표시, 10분 상한 |
| 20. 새 Claude 기능 도입 평가 | 공식 문서로 이해, 가장 지렛대 큰 용도와의 관련성 평가, 저위험 실제 작업에서 시험, 가치가 입증된 뒤에만 표준 시스템에 편입 |

SOP 하나를 적용한 사례를 보자. 19번을 따르는 프리랜서 작가는 금요일 10분 동안 그 주의 쓸 만한 대화 제목만 정리하고, 컨텍스트 패킷에 추가할 항목을 한 줄 메모하며, 월간 점검 후보를 표시한다. 책은 이 작업이 또 하나의 부담이 되지 않도록 10분 상한을 못 박았다.

## 4. 흔한 실수와 문제 해결

| 실수 | 증상 | 대응 |
|---|---|---|
| 점검표를 형식으로 체크만 한다 | 칸은 채웠는데 실제로 확인하지 않았다 | 숫자와 사실은 원문과 직접 대조한다 |
| 템플릿의 빈칸을 비운다 | 일반론이 나오거나 항목이 비어 있다 | 사례와 숫자를 넣어 구체화한다 |
| SOP의 사람 단계를 생략한다 | 검토 없는 결과가 외부로 나간다 | 사람 확인 단계는 건너뛰지 않는다 |
| 유지 점검을 미룬다 | 지식이 낡고 복잡도가 쌓인다 | 10분 상한의 주간 점검부터 습관화한다 |

## 5. 장 요약

- 체크리스트 20개는 4-5칸의 점검표이며 검증과 가장 좁은 권한이 반복 주제다.
- 템플릿 20개는 맥락, 글, 만들기, 조사와 결정, 데이터와 팀, 자동화와 회고로 묶이는 빈칸 양식이다.
- SOP 20개는 초안은 Claude가, 판단과 발송은 사람이 맡는 반복 절차다.
- 주간, 월간, 분기, 연간 점검이 하나의 유지 리듬이 된다.

## 6. 실행 체크리스트

- [ ] 자주 하는 일 하나에 맞는 체크리스트를 골라 내 용어로 고쳤다.
- [ ] 템플릿 두 개(컨텍스트 패킷, 지침)를 먼저 채워 프로젝트에 올렸다.
- [ ] 가장 자주 반복하는 업무 하나를 SOP로 적고 사람 확인 지점을 표시했다.
- [ ] 금요일 10분 주간 점검을 일정에 넣었다.
