# 요금제와 인증, 슬래시 명령, IDE 연동

Claude Code를 쓰기 전에 먼저 정할 것이 있다. 누구에게 어떻게 요금을 낼지다. 자동차에 비유하면 주유 방식을 고르는 일이다. 쓴 만큼 넣는 방식이 있고, 월 정액으로 끊는 방식이 있으며, 회사 법인카드로 처리하는 방식도 있다. 이 문서는 세 가지 인증·결제 방식을 비교하고, 세션 안에서 Claude Code를 조종하는 슬래시 명령과 설정 구조, 그리고 IDE 연동까지 다룬다.

가격과 한도, 모델명은 모두 책이 쓰인 시점 기준이다. 요금제와 사용 한도, 결제 정책은 바뀔 수 있으므로 공식 가격 페이지(claude.com/pricing)에서 최신 내용을 확인해야 한다.

---

## 1. 인증 방식이 곧 결제 방식이다

Claude Code는 인증하는 방법에 따라 토큰 비용이 청구되는 방식이 달라진다. 크게 세 가지 방법이 있다.

| 방식 | 결제 형태 | 이럴 때 적합 |
|---|---|---|
| Anthropic API 키 | 사용량에 따라 내는 종량제 | 쓴 만큼만 내고 싶거나, 구독 전에 먼저 써 보고 싶을 때 |
| Claude 구독 | 월 정액(한도는 있음) | 매달 비용을 예측하고 싶을 때. 책은 이 방식을 계속 쓴다 |
| 서드파티 클라우드 | 클라우드 업체가 청구 | 중앙 청구, 규정 준수, 지역 배포가 필요한 기업 |

### 1.1 방식 1: Anthropic API 키

API 키 방식은 종량제다. 사용량은 Anthropic 콘솔에서 추적한다. 로그인 화면에서 API 키 인증을 고르고 Anthropic 조직으로 승인하면, Claude Code가 키를 만들어 터미널에 자동으로 설정해 준다. 그 뒤로는 쓴 만큼 청구된다.

이 방식에서는 `/cost` 명령으로 토큰 사용량을 볼 수 있다. 소비한 토큰 수와 그 분포가 나온다. 이 명령은 API 키로 인증했을 때만 쓸 수 있다. 처음에는 비용이 0으로 나오는데, 아직 토큰을 쓰지 않았기 때문이다. 아무 말이나 입력하고 응답을 받은 뒤 다시 `/cost`를 치면 숫자가 올라가 있다. 같은 정보는 Anthropic 콘솔에서도 볼 수 있다.

가격은 모델에 따라 다르다. 예를 들어 Opus는 다른 모델보다 토큰 비용이 높다.

주의할 점이 둘 있다.

- 키가 노출되면 남이 내 비용으로 토큰을 쓸 수 있다. 극단적으로는 예상치 못한 큰 청구서가 날아온다.
- 이 책은 에이전트, 서브에이전트, 오케스트레이션을 다룬다. 설정이 잘못되면 에이전트 여러 개가 동시에 돌면서 비용이 크게 늘 수 있다.

대비책은 Anthropic 콘솔 설정 페이지에서 지출 한도를 거는 것이다. 한도에 도달하면 이후 요청은 처리되지 않는다.

### 1.2 방식 2: Claude 구독

2장의 설정을 따라 했다면 이미 이 방식이다. 기존 Claude 구독을 Claude Code에 직접 연결하며, 월 요금이 일정해서 예측이 쉽다. 책이 쓰인 시점의 구독 등급은 다음과 같다.

- 무료: 월 0달러. Claude Code는 포함되지 않는다.
- Pro: 월 20달러
- Max 5x: 월 100달러
- Max 20x: 월 200달러

Claude Code는 Pro 이상에서 쓸 수 있다. 저자는 Pro보다 한도가 높으면서 일상 개발에는 부담이 덜한 Max 5x를 쓴다. 다만 취미로 쓰는 대부분의 사람에게는 Pro로 시작하기를 권한다. 한도가 모자랄 때 Max로 올리면 된다.

구독에서는 비용 추적 방식이 다르다. 사용량이 구독료에 포함되므로 `/cost`로 토큰 단위 비용을 볼 필요가 없다. 대신 `/usage` 명령으로 구독의 사용 현황을 본다. 요금은 고정이지만 사용 한도는 플랜에 따라 여전히 적용된다. 한도는 계정 공유나 남용을 막으려고 도입된 것이며 Pro와 Max에 모두 적용된다. 정확한 한도는 수치로 잡기 어렵다. 이는 Claude Code만의 문제가 아니라 AI 코딩 에이전트 업계 전체의 과제이고, 가격 정책 변경이 개발자 커뮤니티의 불만을 낳기도 했다.

### 1.3 모델 선택

`/models` 명령은 쓸 수 있는 모델을 보여 준다. 책이 쓰인 시점에는 Opus, Sonnet, Haiku를 지원한다.

- Opus: 가장 유능하다. 복잡한 작업과 깊은 추론에 맞는다. 컨텍스트 윈도우(모델이 한 번에 볼 수 있는 입력 분량)는 20만 토큰이며, 주로 깊은 계획이나 조사에 쓴다. 비싸서 대량의 코드 작성에는 보통 쓰지 않는다.
- Sonnet: 지능, 속도, 비용의 균형이 좋다. 컨텍스트 윈도우는 역시 20만 토큰이며, 이 책에서 코드 생성의 주력 모델이다. 코드를 쓰고 고치는 일의 대부분을 맡는다.
- Haiku: 가장 빠르고 가벼운 모델이다. 단순한 작업, 빠른 반복, 응답 속도가 중요한 흐름에 맞는다.

### 1.4 방식 3: 서드파티 클라우드

Amazon Bedrock, Microsoft Azure, Google Cloud Vertex AI 같은 클라우드를 통해서도 인증할 수 있다. 이 경우 구독이나 API 키 대신 선택한 클라우드 업체가 청구와 사용량을 관리한다. 모델 자체는 Anthropic이 호스팅하고 제공한다. 이 방식은 중앙 청구, 클라우드별 규정 준수, 지역 배포, 기존 클라우드 인프라를 통한 거버넌스가 필요한 조직이 주로 쓴다. 자세한 내용은 공식 문서의 서드파티 통합 항목을 참고하면 된다.

## 2. 슬래시 명령으로 세션 조종하기

슬래시 명령은 Claude Code 채팅 안에서 기능과 설정을 다루는 기본 수단이다. `/`를 입력하면 쓸 수 있는 명령 목록이 뜬다.

대화를 오래 하면 문제가 생긴다. 대화가 길어질수록 처리가 느려지고, 비용이 늘고, Claude가 기억할 것이 너무 많아져 헷갈린다. 이 현상을 컨텍스트 부패(context rot, 컨텍스트가 길어져 품질이 떨어지는 현상)라 부르며 뒤에서 다시 다룬다. 이를 풀어 주는 명령이 두 개다.

- `/clear`: 모든 것을 지우고 처음부터 시작한다. 깨끗한 백지와 같다.
- `/compact`: 중요한 내용만 짧게 요약해 핵심을 남기고 나머지 세부는 제거한다.

두 명령은 Claude가 오래 집중하도록 돕는다. 1장에서 본 컨텍스트 엔지니어링을 실제로 하는 일이다. 책의 실습도 `/clear`로 세션을 비우고 시작한다.

그 밖에 자주 쓰는 명령은 다음과 같다.

| 명령 | 하는 일 |
|---|---|
| `/agents` | 코드 리뷰어, 디버거, 아키텍트 같은 전문 서브에이전트를 관리한다. 서브에이전트는 자기만의 컨텍스트와 도구로 일하며 멀티 에이전트 워크플로에 쓰인다 |
| `/config` | 설정 패널을 연다 |
| `/cost` | API 키 인증일 때 토큰 사용량을 본다 |
| `/mcp` | MCP 서버를 추가, 삭제, 조회한다 |
| `/hooks` | 훅을 설정한다 |
| `/init` | 기존 코드베이스를 읽고 CLAUDE.md를 만든다 |
| `/rewind` | 세션 중 바뀐 파일과 대화를 되돌린다 |

### 2.1 설정 패널과 세 겹의 설정

`/config`를 실행하면 설정 패널이 열린다. 예를 들어 자동 압축(Auto-compact)이 켜져 있으면, 대화가 토큰 한도에 가까워지거나 Claude가 압축하기 좋은 시점이라고 판단할 때 `/compact`를 자동으로 돌린다. 할 일 목록 사용, 체크포인트 같은 설정도 있다. 전체 목록은 공식 문서의 설정 페이지에서 최신 내용을 볼 수 있다.

설정 하나하나보다 중요한 것은 설정이 어떻게 겹쳐 적용되느냐다. Claude Code의 설정은 세 층이다.

- 사용자 전체 설정: 홈 디렉터리의 `.claude` 아래에 두며 모든 Claude Code에 전역으로 적용된다.
- 프로젝트 설정: 프로젝트 디렉터리의 `.claude/settings.json`에 두며 그 프로젝트에만 적용된다. 팀과 공유할 수 있다.
- 로컬 설정: 공유 프로젝트 설정에 영향을 주지 않고 내 취향만 조정한다.

예를 들어 모든 프로젝트에서 켜 둘 기본값은 전역에, 팀 규칙은 프로젝트에, 나만 쓰는 임시 허용 목록은 로컬에 두면 된다. 이 구조 덕분에 전역 기본값, 프로젝트 지침, 개인 선호가 서로 부딪히지 않는다. 책에서 보여 주는 설정은 모두 이 파일들로 개인과 팀의 필요에 맞게 바꿀 수 있다.

## 3. IDE 안에서 Claude Code 쓰기

슬래시 메뉴에서 IDE를 고르면 Claude Code를 IDE에 연동한다. 책은 Cursor를 예로 든다. 선택하면 Claude Code 확장이 IDE에 바로 설치되고, 오른쪽 위에 Claude Code 아이콘이 나타난다.

이것이 실무에서 대부분의 개발자가 쓰는 모습이다. Claude Code가 편집기 안에서 돌아가므로 한 화면에서 작업하고, 코드 변경(diff)을 더 또렷하게 볼 수 있다. 책 전체가 이 구성으로 진행된다.
