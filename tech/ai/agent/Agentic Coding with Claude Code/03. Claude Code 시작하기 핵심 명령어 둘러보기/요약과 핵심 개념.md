# 요약과 핵심 개념

3장은 Claude Code를 처음 켜는 단계에서 일상적으로 쓰는 단계로 넘어가는 장이다. 요금과 인증을 고르고, 세션 안에서 슬래시 명령으로 조종하고, 설정을 사용자와 프로젝트 층으로 나누고, IDE 안에서 쓰는 법을 익힌다. 이어 긴 작업을 안전하고 일관되게 만드는 기능 넷, 곧 훅, 메모리, 되감기, 스킬을 하나씩 실습한다.

원서의 장 요약은 이렇다. 인증과 요금을 개괄하고, 슬래시 명령으로 Claude Code를 조종하고, IDE에 연동하고, 설정 옵션과 훅과 CLAUDE.md 메모리를 다루고, 체크포인트와 되감기로 안전하게 되돌리고, 스킬로 반복 워크플로를 도구 제한과 함께 담았다. 다음 장은 모델 컨텍스트 프로토콜(MCP)이 AI 애플리케이션과 외부 도구의 통합을 어떻게 표준화하는지 다룬다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 요금제와 인증 | API 키(종량제), 구독(월 정액), 서드파티 클라우드 중 선택. 방식에 따라 `/cost`와 `/usage`가 갈림 |
| 2 | 슬래시 명령과 설정 | `/clear`, `/compact`, `/config` 등으로 세션 관리. 설정은 사용자, 프로젝트, 로컬 세 층 |
| 3 | IDE 연동 | Cursor 확장으로 편집기 안에서 Claude Code 사용 |
| 4 | 훅 | Stop 이벤트에 알림음 스크립트를 연결해 자동 실행 |
| 5 | 메모리 | CLAUDE.md 계층과 위쪽 탐색, 아래쪽 지연 로딩, `#`와 `/init` |
| 6 | 되감기 | 체크포인트로 코드와 대화를 되돌림. Bash 명령과 외부 수정은 못 되돌림 |
| 7 | 스킬 기반 명령 | SKILL.md로 커밋 명령 작성, 인자 전달, 허용 도구 제한 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 종량제와 구독 | API 키는 쓴 만큼 내고, 구독은 월 정액이며 한도가 있다 |
| `/cost`와 `/usage` | 전자는 API 키 인증에서 토큰 비용을, 후자는 구독의 사용 현황을 본다 |
| 컨텍스트 부패 | 대화가 길어져 느려지고 헷갈리는 현상. `/clear`와 `/compact`로 완화한다 |
| 설정 세 층 | 사용자 전역, 프로젝트 공유, 로컬 개인 설정이 겹쳐 적용된다 |
| 훅 | PreToolUse, PostToolUse, Notification, UserPromptSubmit, Stop 시점에 자동 실행되는 명령 |
| 메모리(CLAUDE.md) | 세션 시작 때 불러오는 지침 파일. 관리형, 사용자, 프로젝트, 규칙, 로컬 순서로 우선한다 |
| 지연 로딩 | 하위 디렉터리의 메모리는 그 안의 파일을 다룰 때 비로소 불러온다 |
| 체크포인트와 되감기 | 코드를 바꾸는 프롬프트마다 저장되며 30일 보관된다. 코드, 대화, 둘 다 되돌릴 수 있다 |
| 스킬 | `.claude/skills/이름/SKILL.md`로 정의하는 재사용 프롬프트. 호출할 때 인자를 받는다 |
| 허용 도구 제한 | 스킬이 쓸 도구를 최소 권한으로 좁혀 컨텍스트 오염의 피해를 줄인다 |

## 3. 자주 놓치는 점

- 방식에 맞는 명령을 써야 한다. 구독으로 인증했다면 `/cost`는 의미가 없고 `/usage`를 본다.
- API 키 방식에서는 키 노출과 에이전트 동시 실행으로 비용이 불어날 수 있다. 콘솔에서 지출 한도를 미리 건다.
- 훅은 설정만 하면 끝나지 않는다. 설정을 읽도록 Claude Code를 다시 시작해야 하고, 보안 경고가 말하듯 신뢰할 수 있는 명령만 등록한다.
- 자주 도는 훅은 가볍게 만든다. 단순 알림에는 시스템 명령이 파이썬 런타임보다 빠르다.
- 메모리는 길고 모호할수록 해롭다. 간결하고 구체적으로 쓴다.
- 프로젝트 로컬 메모리는 Git이 자동으로 무시하므로 개인 재정의에 알맞고, 프로젝트 메모리는 커밋해서 팀과 공유한다.
- 되감기는 Git을 대신하지 않는다. Bash 명령의 결과와 Claude Code 밖의 수정은 체크포인트에 없다.
- 허용 도구를 지정하지 않은 스킬은 모든 도구를 쓸 수 있다. 공식 예처럼 `allowed-tools`로 좁히는 편이 안전하다.
