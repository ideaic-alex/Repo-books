# 요약과 핵심 개념

7장은 서브에이전트를 밑바닥부터 다룬다. 서브에이전트가 무엇이고 컨텍스트 격리가 왜 중요한 설계인지, 직접 만들어 보며 description과 시스템 프롬프트와 도구가 동작을 어떻게 바꾸는지, 그리고 여러 서브에이전트를 병렬로 돌리는 방법까지 이어진다. 이 문서는 장 전체를 되짚고 용어를 정리한다.

원서의 장 요약은 이렇다. 메인 대화가 끝없이 커지고 오염되는 대신 서브에이전트는 자기 컨텍스트 윈도우에서 돌고 압축된 결과 하나만 돌려준다. 이것이 토큰 사용을 통제하고 프로젝트가 커져도 성능을 유지하게 한다. 메인 에이전트가 서브에이전트에게 보내는 프롬프트와 서브에이전트 내부 로직을 모두 바꿔 볼 수 있다. 마지막으로 고차 프롬프트 하나가 서브에이전트 프롬프트를 여럿 만들어 병렬로 돌리는 인피니트 에이전틱 루프로 확장한다. 다음 장은 출력 스타일을 다룬다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 서브에이전트의 개념과 구조 | 자기 시스템 프롬프트, 격리 컨텍스트, 도구 제한, 재사용이라는 네 특징. Markdown 정의 파일 |
| 2 | 첫 서브에이전트 시험 | `/agents`로 만들고 `funny review @main.py`로 호출. 의심스러우면 순차 실행 |
| 3 | 컨텍스트 흐름 | 프롬프트 하나를 받고 응답 하나를 반환. 메인 컨텍스트가 가벼워짐 |
| 4 | Mermaid 서브에이전트 다듬기 | description과 본문과 도구를 조절하는 세 곳을 확인. 도구 오염과 보안 주의 |
| 5 | 동시 서브에이전트 | `/infinite`로 Hero 변형 6개를 병렬 생성하고 비교해 하나를 고름 |
| 6 | 인피니트 프롬프트 | 프롬프트가 프롬프트를 만드는 메타 프롬프팅. 4단계 구조와 배치 규칙 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 서브에이전트 | 자기 프롬프트와 컨텍스트와 도구를 가진 전문 보조 에이전트 |
| 컨텍스트 격리 | 서브에이전트는 메인 대화를 모르고, 받은 프롬프트만으로 시작한다 |
| 컨텍스트 오염 | 쌓인 컨텍스트 대부분이 당면한 일과 무관해져 결과 질이 떨어지는 현상 |
| 최소 권한 원칙 | 서브에이전트에게 일에 필요한 도구만 허용한다 |
| 도구 오염 | 필요 없는 도구를 줘서 컨텍스트와 보안 노출이 커지는 일 |
| description | 호출 시점과 메인 에이전트가 쓸 프롬프트를 정하는 설명 필드 |
| 프로젝트 수준 / 사용자 범위 | 프로젝트의 `.claude/agents/`와 홈 디렉터리의 `.claude/agents/`, 두 보관 위치 |
| 고차 프롬프트 | 프롬프트를 입력받아 서브에이전트용 프롬프트를 여럿 만들어 내는 프롬프트 |
| 무한 에이전트 루프 | 스펙과 출력 디렉터리와 개수를 받아 서브에이전트를 병렬로 돌리는 패턴 |

## 3. 자주 놓치는 점

- 서브에이전트가 가진 컨텍스트는 메인 에이전트가 만든 프롬프트 한 개뿐이다. 이전 대화가 따라가지 않으므로 프롬프트의 질이 결과를 좌우한다.
- 서브에이전트의 최종 응답은 하나이고 내부 컨텍스트는 사라진다. 코드 같은 산출물이 응답에 없으면 요약만 남으니, 마지막 단계에서 산출물을 그대로 반환하라고 정해 둬야 한다.
- `tools`를 비우면 모든 도구가 허용된다. 읽기만 하는 리뷰어에게는 필요한 도구만 나열한다.
- 서브에이전트 두 개를 부탁해도 의존성이 불확실하면 순차로 돈다. 병렬로 원한다면 요청에 독립적임을 드러내 적는다.
- description은 메인 에이전트의 시스템 프롬프트에 붙는다. 출처가 불분명한 서브에이전트를 내려받으면 악성 지시가 실행될 수 있다.
- 동시 서브에이전트는 토큰을 많이 쓴다. 책은 비용 추정을 주지 않으니, 쓰기 전에 사용량을 직접 관찰해야 한다.
- 변형 여섯 개를 비교한 뒤에는 컨텍스트를 비우고 정리하라고 책은 보여 준다. 부푼 컨텍스트는 이후 작업을 느리게 한다.
- 같은 브랜치에서 병렬 작업을 하는 6장의 방식과 달리, 이 실습의 서브에이전트는 각자 다른 파일을 만들어 충돌이 없다.
