# Claude Code 서브에이전트 활용

7장은 서브에이전트가 무엇이고 왜 컨텍스트 격리가 설계의 중심인지에서 출발한다. 직접 서브에이전트를 만들어 호출하고, 메인 에이전트와 서브에이전트 사이의 컨텍스트 흐름을 확인한다. Mermaid 서브에이전트를 단계적으로 다듬어 조절 지점을 익힌 뒤, 인피니트 에이전틱 루프로 여러 서브에이전트를 병렬로 돌려 변형을 만들고 가장 좋은 것을 고른다.

---

## 1. 핵심 요점

- 서브에이전트는 자기 시스템 프롬프트, 분리된 컨텍스트 윈도우, 개별 도구 권한을 가지며 한 번 만들어 재사용한다.
- 정의는 Markdown 파일이다. YAML 머리말의 `name`과 `description`이 필수이고, `tools`를 비우면 모든 도구가 허용된다.
- 프로젝트 수준 에이전트는 `.claude/agents/`, 사용자 범위 에이전트는 홈 디렉터리 아래 `.claude/agents/`에 둔다.
- 서브에이전트는 메인이 만든 프롬프트 하나만 받고 압축된 응답 하나를 돌려준다. 그래서 메인 컨텍스트가 가볍게 유지된다.
- 필요 없는 도구를 주면 토큰이 낭비되고 보안 노출이 커지므로 최소 권한 원칙을 따른다.
- description을 고치면 메인이 서브에이전트에게 쓰는 프롬프트가 바뀌고, 본문을 고치면 서브에이전트 내부 흐름과 응답 형식이 바뀐다.
- 출처가 불분명한 서브에이전트의 description에는 악성 지시가 들어 있을 수 있어 주의해야 한다.
- 고차 프롬프트인 `/infinite`는 스펙과 출력 디렉터리와 개수를 받아 서브에이전트를 병렬로 띄운다. 토큰을 많이 쓰므로 사용량을 지켜봐야 한다.
