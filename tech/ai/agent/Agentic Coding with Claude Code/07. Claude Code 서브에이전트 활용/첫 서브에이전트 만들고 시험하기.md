# 첫 서브에이전트 만들고 시험하기

처음 직원을 뽑을 때는 무슨 일을 맡길지, 어떤 열쇠를 줄지, 언제 부를지를 정한다. 서브에이전트도 같다. 이 문서는 `/agents` 명령으로 코드를 재밌게 평가하는 서브에이전트를 만들고, 파이썬 파일로 시험해 보는 과정을 따라간다. 화면과 메뉴 문구는 책이 쓰인 시점 기준이다.

목표는 완성도 높은 에이전트가 아니라, 서브에이전트가 만들어지고 호출되고 동작하는 모습을 직접 보는 것이다.

---

## 1. 만들기 시작: /agents

새 브랜치를 만들고 Claude를 연 뒤 `/agents` 명령으로 사용 가능한 에이전트 목록을 본다. 처음에는 프로젝트 수준 에이전트도 사용자 수준 에이전트도 없고, 내장된 범용 에이전트(general-purpose)만 보인다.

에이전트를 둘 범위는 둘 중에서 고른다. 책은 저장소에 커밋해 프로젝트와 함께 공유하도록 프로젝트 수준을 택한다. 만드는 방법도 두 가지다.

- Claude로 생성하기
- 직접 설정하기

가장 간단한 첫 번째 방법으로 시작한다.

## 2. 설명 쓰기와 시스템 프롬프트

첫 번째 방법을 누르면 에이전트 설명부터 쓰게 된다. 이 설명은 에이전트의 목표와 동작 방식을 정한다. 메인 에이전트가 이 설명을 보고 서브에이전트를 부를지 결정한다. 책은 이렇게 적었다. 재밌고 경력 많은 시니어 엔지니어가 주어진 코드를 리뷰하며, 입력에 "funny review"가 들어오면 이 에이전트를 쓴다.

여기서 키워드 트리거(keyword trigger)를 넣은 점이 눈에 띈다. 이 문구가 있으면 특정 상황에서만 에이전트가 불리고, 직접 에이전트를 호출할 때도 편리하다. 슬래시 명령으로도 부를 수 있다.

설명을 입력하면 "funny review", "funny code review" 같은 활성화 트리거가 표시되고, 이 문구가 호출 시점을 결정한다. 프롬프트가 너무 모호하다고 느껴지면 직접 다듬는 대신 별도의 Claude에게 서브에이전트 프롬프트를 개선해 달라고 맡길 수 있다. 원래 프롬프트를 주고 더 분명하게 해 달라고 하면 상세한 시스템 프롬프트가 나오고, 이를 그대로 복사해 쓴다. 에이전트를 Markdown 파일로 직접 쓰지 않는 이유는 CLI가 에이전트 디렉터리에 파일을 만들어 주기 때문이다.

## 3. 도구, 모델, 색 고르기

다음 단계는 에이전트가 쓸 도구를 고르는 것이다. 전체를 선택하거나 필요한 것만 고를 수 있다. 코드 리뷰 에이전트는 읽기 전용 도구가 중심이다. 필요하면 편집 도구와 실행 도구, MCP 도구도 켤 수 있다.

고급 옵션을 켜면 bash, glob, grep, ls, read, edit 등 Claude Code의 전체 도구 목록이 보인다. 앞서 설정해 둔 Context7의 MCP 도구도 붙어서 나온다. 선택이 끝나면 고급 옵션은 다시 숨겨진다.

이어서 모델을 고른다. 모델 선택은 책 뒷부분에서 자세히 다룬다고 하고, 여기서는 성능과 가격과 지연의 균형을 위해 Sonnet을 택했다. 화면에 표시할 색은 노란색을 골랐다. 저장 전에 설정 요약이 나오고 필요하면 수정할 수 있다. 이렇게 에이전트가 만들어진다.

## 4. 생성된 파일 확인

생성된 에이전트 파일을 열면 입력한 정보가 모두 들어 있다. 맨 위에 이름, 그다음 설명이 있다. 설명은 메인 에이전트가 언제 부를지 판단하는 데 쓰인다. 다음으로 쓸 수 있는 도구가 나열된다. 쓰기 도구는 켜지 않았다. 모델은 Sonnet이고 색은 노란색이다.

```yaml
---
name: code-comedy-carl
description: >
  유머러스하고 즐거운 코드 리뷰를 원할 때 쓴다.
  funny review, roast my code, Carl 을 언급하면 활성화한다.
tools: Glob, Grep, LS, Read, NotebookRead, WebFetch,
  TodoWrite, WebSearch, mcp__context7__resolve-library-id,
  mcp__context7__get-library-docs
model: sonnet
color: yellow
---
```

위는 책의 설정을 줄여 옮긴 것이다. 모든 값은 필요하면 나중에 바꿀 수 있다.

## 5. 시험: 피보나치 파일에 호출하기

에이전트가 의도대로 동작하는지 확인하려면 분석할 파일이 필요하다. 프로덕션 수준의 로직이 목적이 아니라 리뷰를 시험할 간단한 코드를 만드는 것이 목적이다. 먼저 피보나치 함수를 계산하는 파이썬 메인 파일을 만들도록 시킨다.

그다음 이 파일에 재밌는 리뷰를 요청한다. `funny review @main.py` 라고 쓰면, 앞서 만든 리뷰 에이전트가 표시되고 인스턴스 하나가 생성된다. 에이전트가 초기화되고 파일 내용을 읽고 작업을 시작한다.

다른 파일이 있다면 Claude를 다시 열어 같은 리뷰 에이전트의 인스턴스를 또 만들 수 있다. 에이전트가 쓸모 있는 이유가 여기 있다. 한 에이전트의 인스턴스를 여러 개 만들 수 있고, 각 인스턴스는 격리된 환경에서 돌아 서로 영향을 주지 않는다. 에이전트 보기를 펼치면(Windows와 Linux는 Ctrl+R, macOS는 Cmd+R) 에이전트 내부 활동이 모두 보인다.

## 6. 여러 인스턴스와 순차 실행의 함정

이번에는 리뷰 하나가 아니라 두 개를 요청한다. `create 2 funny code reviews of @main.py`라고 쓰면 리뷰 에이전트의 인스턴스 둘이 생성되고, 첫째와 둘째가 일하는 모습을 볼 수 있다.

여기서 중요한 점이 있다. 이 두 리뷰 에이전트는 동시에 돌지 않고 순차적으로 돌았다. Claude Code는 작업이 서로 독립적이라고 항상 가정하지 않는다. 의존성이 있을지 불확실하면 병렬 대신 하나씩 실행할 수 있다.

실제로는 요청 문장으로 이를 바꿀 수 있다. 병렬 실행을 원하면 프롬프트에 분명히 적는다. 예를 들어 "이 PR을 리뷰해 줘" 대신 "이 파일들을 병렬로 리뷰해 줘" 또는 "파일마다 별도 리뷰 에이전트를 만들어 줘"가 낫다. 일이 독립적임이 드러나게 요청을 구성하면 동시에 실행될 가능성이 높아진다. 병렬로 의도해서 돌리는 방법은 이 장 뒤에서 다룬다.

에이전트를 더 추가하려면 에이전트 디렉터리에 새 정의 파일을 만들면 된다.
