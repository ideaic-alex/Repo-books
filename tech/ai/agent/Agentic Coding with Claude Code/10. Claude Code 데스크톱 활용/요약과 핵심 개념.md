# 요약과 핵심 개념

10장은 Claude Code를 데스크톱과 모바일 앱에서 쓰면서 에이전트 여러 개를 동시에 돌리는 방법을 보여 준다. 줄거리는 네 덩어리다. 실행 모드와 워크트리의 원리, 로컬과 클라우드의 병렬 시연, 브랜치 병합과 검증, 모바일 실행과 병렬의 한계다. 이 문서는 그 흐름과 용어를 한 번에 되짚는다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 데스크톱 통합과 Code 탭 | 터미널 버전과 같은 엔진과 설정(CLAUDE.md, MCP 서버, 훅)을 그래픽으로 사용 |
| 2 | 로컬 워크트리와 클라우드 모드 | 폴더를 고르면 로컬, 저장소 권한을 주면 Anthropic 컨테이너에서 실행 |
| 3 | 깃 워크트리 원리 | 에이전트마다 별도 브랜치와 디렉터리. 마음에 안 들면 지우면 끝 |
| 4 | 병렬 시연 | 연구, 애니메이션, 히어로 재설계를 로컬과 클라우드에서 동시에 진행 |
| 5 | 병합과 검증 | 임시 통합 브랜치에서 충돌을 풀고, 로컬 시험 뒤 푸시 승인 |
| 6 | 모바일 실행과 한계 | 휴대폰에서 풀 리퀘스트까지 클라우드로 완주. 병렬이 맞지 않는 경우 다섯 가지 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| Code 탭 | Claude 데스크톱 앱 안에서 Claude Code를 그래픽으로 실행하는 곳 |
| 로컬 워크트리 모드 | 내 컴퓨터에서만 돌고, 에이전트마다 깃 워크트리를 만드는 방식 |
| 클라우드 모드 | Anthropic 서버의 컨테이너에서 복제, 수정, 커밋, 풀 리퀘스트까지 하는 방식 |
| 백그라운드 에이전트 | 내 화면과 상관없이 클라우드에서 따로 일하는 인스턴스 |
| 깃 워크트리 | 한 저장소의 여러 브랜치를 서로 다른 폴더에 동시에 꺼내 두는 기능 |
| 임시 통합 브랜치 | 본 브랜치에 넣기 전에 여러 브랜치를 먼저 합쳐 보는 브랜치(예: project/hookhub-merge) |
| 오케스트레이션 | 여러 작업 맥락과 브랜치와 과제를 개발자가 조율하는 일 |
| 병렬 개발 체크리스트 | 독립성 확인, 시작 브랜치 명시, 병합 결과 시험, 워크트리 정리 네 가지 |

## 3. 자주 놓치는 점

- 워크트리 안에서 만든 커밋은 원래 브랜치가 아니라 워크트리 브랜치에 쌓인다. 푸시해도 본 브랜치에 커밋이 안 보이는 것은 정상이다.
- 클라우드 에이전트는 시작 브랜치를 main으로 잡을 수 있다. 프롬프트에 대상 브랜치를 분명히 적어야 한다.
- 병합은 본 브랜치에 바로 하지 않고, 임시 브랜치에서 합친 뒤 로컬로 실행해 보고 푸시를 승인한다.
- 기본 클라우드 구성에는 MCP 서버, 사용자 지정 훅, 출력 스타일이 없다. 필요하면 따로 추가해야 한다.
- 모바일 세션은 로컬에서 코드를 실행하지 않는다. 복제, 체크아웃, 커밋 모두 원격이다.
- 풀 리퀘스트의 기준 브랜치가 main으로 잡힐 수 있으니 열어 보고 고친다.
- 병렬은 만능이 아니다. 얽힌 기능, 공유 상태, 작은 작업, 높은 조율 비용, 탐색적 작업에서는 순차가 낫다.
- 이 장의 시연은 동시 작업이 많아 한 단계씩 따라 치도록 쓰이지 않았다. 개념과 관찰이 목적이다.
