# 요약과 핵심 개념

1장은 세 덩어리다. 컨텍스트가 무엇이고 왜 커지며 어떤 문제를 일으키는지, Claude Code가 이 문제를 네 가지 전략으로 어떻게 푸는지, 그리고 시스템 프롬프트를 어느 수준으로 써야 하는지다. 이 문서는 세 덩어리를 한 번에 되짚고 핵심 용어를 정리한다.

원서의 장 요약은 이렇다. 컨텍스트는 정적인 프롬프트와 다르고, 관리하지 않으면 성능 저하, 환각, 일관성 없는 행동이 생긴다. Claude Code를 예로 써서 쓰기, 선택, 압축, 격리 네 전략을 보았고, 효과적인 시스템 프롬프트는 너무 경직되지도 너무 모호하지도 않은 균형을 잡는다. 다음 장은 HookHub 프로젝트로 Claude Code가 코드베이스와 어떻게 상호작용하는지 본다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 에이전트 하네스와 컨텍스트의 출처 | 엔지니어링의 중심은 모델 호출이 아니라 그 주변이며, 컨텍스트는 개발자, 사용자, 도구 결과에서 온다 |
| 2 | 프롬프트에서 컨텍스트 엔지니어링으로 | 프롬프트는 정적이고 컨텍스트는 동적이므로 동적인 시스템이 필요하다 |
| 3 | 컨텍스트가 커지는 문제 | 한도 초과, 비용과 지연 증가, 성능 저하. 오염, 혼란, 충돌 |
| 4 | 네 가지 전략 | 쓰기(CLAUDE.md, /memory), 선택(상위 폴더 탐색, 도구별 주의사항), 압축(/clear, /compact), 격리(서브에이전트) |
| 5 | 시스템 프롬프트 | 너무 구체적이어도, 너무 모호해도 실패한다. 중간 지대는 원칙과 사고 틀을 준다 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 에이전트 하네스 | LLM 바깥에서 도구 호출, 루프, 오류, 가드레일, 컨텍스트 선택을 맡는 조율 계층 |
| 컨텍스트 엔지니어링 | 모델에 보낼 컨텍스트를 동적으로 구성하고 관리하는 일. 프롬프트 엔지니어링의 진화형 |
| 컨텍스트 윈도우 | 모델이 한 번에 볼 수 있는 입력 분량. 도구 결과가 쌓이면 계속 커진다 |
| 컨텍스트 오염 | 환각이 컨텍스트에 들어가 이후 출력에 영향을 주는 현상 |
| 컨텍스트 혼란 | 관련 없는 컨텍스트가 응답에 영향을 주는 현상 |
| 컨텍스트 충돌 | 컨텍스트의 서로 다른 부분이 모순되는 현상 |
| 3층 메모리 | 프로젝트 CLAUDE.md, 사용자 홈 폴더의 CLAUDE.md, @로 가져오는 동적 메모리 파일 |
| /memory | 대화 중에 영속 메모리를 추가하고 저장 위치(프로젝트 또는 사용자)를 고르는 명령 |
| /clear, /compact | 대화 기록을 비우거나(메모리는 유지) 핵심만 남기고 요약하는 압축 명령 |
| 서브에이전트 | 자기만의 독립된 컨텍스트 윈도우로 일하는 전문 에이전트. 메인의 대화를 물려받지 않는다 |
| 골디락스 지대 | 시스템 프롬프트가 너무 구체적이지도 너무 모호하지도 않은 알맞은 수준 |

## 3. 자주 놓치는 점

- 에이전트가 단순한 껍데기라는 말은 반쯤만 맞다. 껍데기를 잘 만드는 데 많은 엔지니어링이 들고, 신뢰성은 모델 호출이 아니라 그 주변 시스템이 좌우한다.
- 컨텍스트가 많다고 좋은 것이 아니다. 오염, 혼란, 충돌 때문에 구조 없이 커진 컨텍스트는 성능을 오히려 떨어뜨린다.
- 컨텍스트 엔지니어링은 도구 개발자만의 일이 아니다. Claude Code 사용자도 CLAUDE.md, /memory, /clear, /compact로 모델이 받는 입력과 답을 바꿀 수 있다.
- 깃 브랜치에 맞춰 CLAUDE.md에 참조를 덧붙이는 스크립트는 중복 검사가 없으면 파일이 끝없이 커진다. 추가 전에 이미 있는지 확인하는 멱등성이 핵심이다.
- /clear는 대화만 지우고 프로젝트 메모리와 사용자 메모리는 남긴다. /compact는 모두 버리지 않고 요약한다. 둘은 목적이 다르다.
- 원서의 서브에이전트 호출 예시와 훅 설정 JSON은 개념을 보이려고 단순화한 것이다. 실제 형식을 그대로 쓰지 말고 이후 장과 공식 문서로 확인한다.
- 시스템 프롬프트가 길수록 좋은 것이 아니다. 모든 경우를 나열한 프롬프트는 유지보수가 어렵고, 모든 것이 정해져 있다면 에이전트 대신 고정 워크플로가 낫다.
