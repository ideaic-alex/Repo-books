# 4장. MCP 서버와 플러그인으로 Claude Code 확장하기

4장은 Claude Code가 기본 능력 밖의 도구와 데이터를 쓰게 만드는 두 가지 방법을 다룬다. 하나는 MCP 서버로, 외부 기능을 공통 규격으로 연결한다. 다른 하나는 플러그인으로, 슬래시 명령, 서브에이전트, MCP 서버, 훅을 묶어 팀이 같은 환경을 공유하게 한다. 동시에 MCP를 아무렇게나 켜면 컨텍스트 윈도우가 낭비된다는 점을 직접 재 보고 줄이는 법, 그리고 MCP의 한계와 대안을 짚는다.

---

## 1. 핵심 요점

- MCP는 에이전트마다 연동을 다시 만들던 문제를 해결하려고 생긴 간접 계층이다. 서버를 한 번 만들면 MCP를 지원하는 어느 호스트에서도 쓴다.
- 구조는 호스트, 클라이언트, 서버 세 부품이고, 클라이언트와 서버는 1대1이다.
- MCP 서버는 내 계정 권한으로 로컬 코드를 실행하므로 서드파티 의존성처럼 소스를 검토하고 믿을 만한 것만 설치한다.
- Claude Code에는 `claude mcp add`로 서버를 추가하고, 프로젝트, 사용자, 세션 세 범위 중 용도에 맞는 곳에 둔다.
- 서버 4개를 모두 로딩하면 첫 프롬프트 전에 MCP 도구 설명만 컨텍스트의 약 20%를 쓴다. `--mcp-config`와 `--strict-mcp-config`로 약 2.4%까지, 세션 중 비활성화로 약 3.2%까지 줄인다.
- MCP의 한계는 컨텍스트 오염, 핑퐁식 왕복의 비효율, JSON 호출 형식의 부자연스러움, 스키마가 사용 패턴을 못 담는 점이다.
- 클라우드플레어 코드 모드는 MCP 도구를 TypeScript API로 바꿔 LLM이 쓴 코드를 샌드박스에서 한 번 실행하게 하는 대안이다.
- 플러그인은 설정 묶음을 마켓플레이스로 나눠 팀을 표준화하며, 설치 전에 source 필드를 따라가 내용을 검토해야 한다.
