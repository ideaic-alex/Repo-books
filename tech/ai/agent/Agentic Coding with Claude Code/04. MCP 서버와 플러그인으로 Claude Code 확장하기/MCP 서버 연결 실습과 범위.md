# MCP 서버 연결 실습과 범위

이 문서는 MCP 서버를 실제로 붙이는 과정을 따라간다. 먼저 날씨 서버로 MCP가 어떻게 동작하는지 눈으로 확인하고, 이어서 Claude Code에 Context7 서버를 추가하고 쓰는 실습을 한다. 마지막에는 설정을 어디에 둘지 정하는 범위(scope) 기준을 표로 정리한다.

처음 연결한 서버가 어디에 저장되는지 모르면 나중에 팀원 설정과 섞이거나, 반대로 내 설정이 팀 저장소에 올라가 버린다. 범위는 그 사고를 막는 서랍 구분이라고 보면 된다.

---

## 1. 날씨 서버로 보는 MCP 동작

원서는 같은 날씨 MCP 서버를 Claude Desktop과 Cursor에 연결해 결과를 비교한다. 설정 방법보다 연결 뒤 동작에 초점을 둔다.

- 서버가 없을 때: Claude Desktop의 개발자 설정에 서버가 없는 상태에서 샌프란시스코 날씨를 물으면, 모델은 실시간 날씨 정보가 없다고 답한다. 가끔 검색 도구로 요약 정보를 찾으려 하기도 한다. MCP가 없으면 모델은 학습 데이터와 범용 내장 도구에 갇힌다.
- 서버를 연결한 뒤: 서버가 개발자 설정에 실행 정보와 함께 나타난다. 같은 질문을 하면 도구를 로컬에서 실행해도 되는지 권한을 묻는다. 로컬 코드를 돌릴 수 있기 때문이다.

권한을 주면 다음 순서로 진행된다.

1. 서버가 날씨 조회 로직을 갖고 있다.
2. 서버는 getForecast라는 함수를 노출한다.
3. 이 함수는 위도와 경도 두 인자를 받는다.
4. 언어 모델(책의 예시는 Claude Sonnet 3.7)이 샌프란시스코의 위도와 경도를 추론한다.
5. 모델이 getForecast에 MCP 호출을 보낸다.
6. 서버가 함수를 실행하고 응답을 돌려준다.
7. 모델이 응답을 읽고 최종 답을 만든다.

날씨는 단순한 예일 뿐이다. 서버 안에는 어떤 로직이든 넣을 수 있고, 프로토콜만 구현하면 호환 클라이언트가 도구 호출로 그 기능을 쓴다. Cursor의 에이전트 모드에서는 서버가 GetAlerts, GetForecast 두 도구를 보여 주고, 에이전트가 GetForecast를 부른 뒤 경보도 필요하겠다고 스스로 판단해 GetAlerts까지 호출한 다음 두 결과를 합쳐 답한다. 책이 쓰인 시점의 Cursor는 도구를 승인 없이 자동 실행하는 YOLO 모드였고, 편하지만 보안상 위험이 따른다고 원서는 경고한다.

### 보안 경고

원서는 노트 상자로 강하게 경고한다. MCP 서버는 사용자 계정과 같은 권한으로 내 컴퓨터에서 코드를 돌린다.

- 서버는 파일을 읽고 고치고 지울 수 있다.
- 악의적인 서버는 소스 코드, 환경 변수, API 키를 외부로 보낼 수 있다.
- 서버가 돌려주는 도구 응답에 모델의 행동을 바꾸는 숨은 지시가 들어 있을 수 있다.

그러므로 MCP 서버는 서드파티 의존성처럼 다룬다. 가능하면 소스를 검토하고, 믿을 만한 관리자의 서버만 설치하며, 높은 권한으로 실행하지 않는다.

## 2. Claude Code에 Context7 연결하기

실습은 빈 프로젝트에서 시작한다. `/mcp` 슬래시 명령을 치면 아직 서버가 하나도 없다고 나오고, 서버를 추가하는 방법을 설명하는 문서 링크가 보인다. 방법은 파일로 추가하는 것과 CLI로 추가하는 것 두 가지이고, 원서는 CLI를 권한다. CLI가 가장 최신 형식을 따라서 형식이나 API가 바뀌어도 호환성이 유지되기 때문이다.

Context7은 수많은 패키지의 최신 문서를 제공하는 서비스다. LangGraph처럼 변화가 빠른 AI 생태계 패키지는 최신 문서가 있어야 생성 코드가 최신 API에 맞는다. 책이 쓰인 시점 기준으로 약 3만 개 패키지를 색인했고 저장소 별은 약 4만 9천 개였다.

```bash
claude mcp add --transport http context7 https://mcp.context7.com/mcp
```

이 명령은 claude mcp add로 서버를 추가하면서 전송 방식을 HTTP로 정하고, 이름을 context7로 붙이고, 서버 URL을 준다. 원격 MCP 서버라서 서버는 내 컴퓨터가 아니라 Context7 쪽 서버에서 돈다. 호출마다 원격에 요청을 보내므로 쉽게 확장되고 여러 클라이언트에서 접근할 수 있다는 장점이 있다. 명령을 실행하기 전에 `--help`를 붙여 옵션을 확인하는 것도 좋은 습관이다. 도움말에는 범위를 정하는 옵션과, 환경 변수나 HTTP 헤더를 줄 수 있는 선택 값이 나온다.

실습에서는 프로젝트 범위로 추가했고, 그 결과 설정 파일이 새로 생겼다. 내용은 HTTP 전송 방식과 서버 URL뿐이다.

```json
{
  "mcpServers": {
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp"
    }
  }
}
```

원격 대신 로컬에서 돌리려면 `claude mcp add context7 -- npx -y @upstash/context7-mcp`를 쓴다. npx가 패키지를 내려받아 내 컴퓨터에서 실행한다. 참고(노트 작성자): 원서 본문의 명령 표기는 글자가 깨져 하이픈 두 개가 긴 줄표로 보인다. 위 두 명령은 하이픈 두 개로 복원한 것이다.

### 2.1 재시작과 활성화

서버를 설치했으면 Claude Code를 종료하고 터미널을 정리한 뒤 다시 시작해야 한다. 시작할 때 Claude가 프로젝트의 MCP 설정 파일을 감지하고 서버에 연결해도 되는지 묻는다. 첫 번째 선택지로 허용하면 현재 사용자 세션용 settings.local.json이 만들어지고, 열어 보면 Context7이 활성화된 것이 보인다. `/mcp`로 목록을 보면 Context7이 connected로 나오고, 항목을 열면 도구 두 개를 노출하는 것이 보인다.

- resolve-library-id: 라이브러리 이름에서 문서 ID를 찾는다.
- get-library-docs: 그 ID로 최신 문서를 가져온다.

이 도구 설명은 에이전트 컨텍스트에 들어가 에이전트가 필요할 때 알아서 부르게 한다. 최신 LangGraph 문서를 요청하면 에이전트가 먼저 resolve-library-id로 ID를 얻고 get-library-docs로 문서를 받는다.

### 2.2 질문과 영속화

"LangGraph의 최신 버전이 뭐야?"라고 묻고 Context7 서버를 쓰라고 지정하면, Claude Code가 도구 호출 권한을 묻는다. 승인하면 settings.local.json의 권한 목록이 갱신된다. 서버가 라이브러리 ID를 풀고 다시 문서를 요청한 끝에 최신 버전을 1.2라고 답했다. 참고로 LangGraph는 빠르게 바뀌므로 독자가 다른 버전을 보더라도 개념은 그대로 유효하다고 원서가 밝힌다.

매번 서버를 지정하기 번거로우므로 프로젝트 메모리에 지침을 남긴다. 그러면 CLAUDE.md에 다음 줄이 기록된다.

```markdown
When discussing LangGraph, always use context7 MCP
```

Claude를 다시 시작하고 세션을 비운 뒤 "LangGraph interrupt가 뭐야?"라고 물으면, 서버를 지정하지 않았는데도 Claude Code가 Context7을 자동으로 고른다. 라이브러리를 resolve하고 관련 문서와 코드 조각을 받아 설명한다. 최신 문서를 쓰니 생성 코드도 최신 사용법을 따른다. 마지막으로 생성된 파일을 `git commit -m "context7 mcp"`로 커밋해 저장소에 올린다.

## 3. MCP 범위 치트시트

범위를 제대로 고르면 환경이 정리되고 불필요한 설정이 무관한 프로젝트로 새지 않는다. 원서의 표 4.1을 옮기면 다음과 같다.

| 항목 | 프로젝트 범위 | 사용자 범위 | 세션 범위 |
|---|---|---|---|
| 설정 위치 | 프로젝트 루트의 .mcp.json | 사용자 홈 아래 .claude/settings.json(원서 표기) | --mcp-config 플래그나 세션 중 추가 |
| 보이는 사람 | 프로젝트의 모든 사람 | 나 혼자, 모든 프로젝트 | 현재 세션만 |
| git 커밋 | 한다 | 안 한다 | 안 한다 |
| 세션 간 유지 | 유지 | 유지 | 사라짐 |
| 팀과 공유 | 공유 | 공유 안 함 | 공유 안 함 |

용도는 이렇게 나눈다.

- 프로젝트 범위: 프로젝트 개발 환경의 일부일 때 쓴다. 프로젝트 전용 Postgres 같은 데이터베이스 도구, 사내 서비스나 스테이징 같은 프로젝트 전용 API, 배포 스크립트나 테스트 러너처럼 팀 전체가 쓰는 도구, 기술 스택에 맞춘 문서 서버가 예다.
- 사용자 범위: 개인용이거나 내 자격 증명에 묶인 도구다. Slack, Linear, Notion 같은 개인 생산성 도구, 내 PAT로 쓰는 GitHub나 이메일, 모든 프로젝트에서 쓰고 싶은 범용 서버(Tavily 검색, Context7 문서), 저장소에 올리고 싶지 않은 비밀이 필요한 서버가 여기에 든다.
- 세션 범위: 일시적이거나 실험적일 때 쓴다. 임시 프록시나 모의 API 같은 일회성 디버깅 서버, 평가 중인 검증 안 된 서버, OAuth 세션 같은 단명 토큰을 쓰는 서버, 실행 중에 서버를 동적으로 띄우는 CI/CD가 해당한다.

참고(노트 작성자): 책이 쓰인 시점 이후 설정 파일 위치나 저장 방식은 바뀔 수 있다. 정확한 위치는 공식 문서와 `claude mcp add --help` 출력을 우선한다.
