# 요약과 핵심 개념

4장은 MCP가 왜 생겼고 어떻게 생겼는지, Claude Code에 어떻게 붙이는지, 잘못 붙이면 컨텍스트가 어떻게 오염되는지, 그리고 플러그인으로 설정을 어떻게 묶어 나누는지를 차례로 다룬다. 이 문서는 장 전체를 한 번에 되짚고 용어를 정리한다.

원서의 장 요약은 이렇게 맺는다. MCP는 AI 시스템의 통합 문제를 풀려고 만들어졌고, 호스트와 클라이언트와 서버라는 구조로 도구를 플랫폼 간에 재사용하게 한다. 서투른 MCP 설정은 컨텍스트 윈도우를 오염시켜 성능을 떨어뜨리므로 컨텍스트 엔지니어링과 범위를 좁힌 설정으로 최적화해야 한다. MCP는 에이전트 기반 AI 개발의 기초 통합 계층이 되고 있으니, 효율적으로 쓰는 법과 의문을 던질 때를 아는 것이 중요하다. 다음 장은 GitHub 저장소 설정, 풀 리퀘스트와 이슈 자동화, GitHub Actions를 다룬다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | MCP가 필요한 이유 | 에이전트마다 연동을 다시 만드는 이식성 문제를 서버 한 번 구현으로 해결 |
| 2 | 핵심 구조 | 호스트, 클라이언트, 서버 세 부품과 클라이언트 1대1 서버 규칙 |
| 3 | 실습 | 날씨 서버로 동작 확인, Context7 추가, 메모리에 사용 지침 저장 |
| 4 | 범위 구분 | 프로젝트, 사용자, 세션 범위의 위치, 공유, 용도 구분 |
| 5 | 컨텍스트 엔지니어링 | 서버 4개 로딩 약 20%, 엄격 모드 약 2.4%, 세션 중 비활성 약 3.2% |
| 6 | MCP의 한계와 코드 모드 | 컨텍스트 오염, 핑퐁 비효율, JSON 한계, 코드로 도구를 부르는 대안 |
| 7 | 플러그인 | 슬래시 명령, 서브에이전트, MCP 서버, 훅을 묶어 마켓플레이스로 공유 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| MCP | AI 앱이 도구, 데이터, 서비스에 공통 규격으로 연결하는 프로토콜 |
| MCP 호스트 | MCP를 지원하는 AI 앱(Claude Code, Claude Desktop, Cursor) |
| MCP 클라이언트 | 호스트 안에서 서버 하나와 1대1로 통신하는 부품 |
| MCP 서버 | 도구, 자원, 프롬프트를 규격에 맞춰 내놓는 쪽. 로컬이나 원격 |
| Context7 | 수많은 패키지의 최신 문서를 주는 원격 MCP 서버 |
| 서버 범위 | 설정 저장 위치와 공유 범위. 프로젝트, 사용자, 세션 세 가지 |
| --strict-mcp-config | 기본 MCP 계층을 무시하고 지정한 파일의 서버만 로딩하는 플래그 |
| 컨텍스트 오염 | 쓰지 않는 도구 정의가 컨텍스트를 채워 성능을 떨어뜨리는 현상 |
| 코드 모드 | MCP 도구를 TypeScript API로 바꾸고 LLM이 쓴 코드를 샌드박스에서 한 번 실행하는 방식 |
| 플러그인 | 슬래시 명령, 서브에이전트, MCP 서버, 훅을 묶은 공유 단위 |
| 마켓플레이스 | 설치 가능한 플러그인을 적은 JSON 파일(marketplace.json) |

## 3. 자주 놓치는 점

- MCP 서버는 내 계정 권한으로 로컬 코드를 실행한다. 출처를 모르는 서버는 소스를 보고 설치하고, 높은 권한으로 돌리지 않는다.
- 클라이언트는 서버 하나당 하나다. 서버 수가 늘면 호스트 안의 클라이언트도 같은 수만큼 늘어난다.
- 원격 서버는 HTTP 전송 방식으로 URL만 주면 되고, 로컬 서버는 npx 같은 실행 명령으로 붙인다.
- 서버를 추가한 뒤에는 Claude Code를 재시작해야 하고, 시작할 때 연결 허용 여부를 묻는다.
- CLAUDE.md에 "이 주제에는 이 서버를 쓴다"고 적어 두면 세션을 바꿔도 에이전트가 서버를 알아서 고른다.
- `--mcp-config`만 쓰면 사용자 수준 설정의 서버가 같이 로딩된다. 정말 지정한 서버만 쓰려면 `--strict-mcp-config`를 함께 쓴다.
- 서버를 많이 켤수록 첫 프롬프트 전에 컨텍스트가 줄어든다. 설정 파일을 건드리기 싫으면 세션 안에서 `/mcp`로 필요 없는 서버를 끈다.
- 코드 모드도 MCP를 버리는 것이 아니다. MCP는 도구를 알아내고 연결하는 통일된 방법으로 남는다.
- 플러그인도 서드파티 코드다. 설치 전에 marketplace.json의 source 필드를 따라가 내용을 확인한다.
- 책이 쓰인 시점에는 플러그인 Uninstall이 제대로 동작하지 않았다. 지금은 달라졌을 수 있으니 직접 확인한다.
