# 딥 에이전트 이해하기

11장은 Claude Code 같은 코딩 에이전트가 어떻게 긴 작업을 해내는지를 구조 차원에서 설명한다. 먼저 현업 에이전트를 분류하고, 단순한 ReAct 에이전트가 왜 긴 작업에 약한지 보인 다음, 딥 에이전트를 깊게 만드는 네 가지 요소(계획 도구, 서브에이전트, 파일시스템, 시스템 프롬프트)를 하나씩 살핀다. 앞 장들에서 다룬 컨텍스트 엔지니어링과 서브에이전트를 한 틀로 묶어 주는 장이다.

---

## 1. 핵심 요점

- 에이전트 영역 안에 ReAct 에이전트가 있고, 저자는 이를 얕은 에이전트로 분류한다. 코딩 에이전트는 딥 에이전트의 특화된 부분집합이다.
- ReAct 순환은 반복마다 컨텍스트가 쌓여 컨텍스트 부패, 지연, 비용 증가를 부른다. 그래도 몇 번 안 도는 작업에는 충분히 쓸 만하다.
- 딥 에이전트는 분, 시간, 며칠 걸리는 장기 과제를 맡고, 멈췄다가 사용자 입력을 받고 이어 갈 수 있다.
- 혁신의 중심은 모델 자체보다 그 위의 응용 계층, 곧 에이전트 하니스를 만드는 하니스 엔지니어링에 있다.
- 계획 도구는 대기, 진행 중, 완료로 표시되는 마크다운 할 일 목록이며, Claude Code에서는 TodoWrite와 TodoRead로 드러난다.
- 서브에이전트는 자기 프롬프트와 도구와 컨텍스트로 일하고 최종 결과만 돌려줘서 메인 컨텍스트를 오염시키지 않는다.
- 파일시스템은 컨텍스트를 외부에 쓰고 glob과 grep으로 골라 읽게 해, 컨텍스트 엔지니어링의 두 원칙을 구현하는 엔진이다.
- 시스템 프롬프트는 정체성, 권한, 추론 틀, 휴리스틱 경계, 간결함을 갖춰야 하고 지나친 하드코딩과 모호함을 모두 피해야 한다.
