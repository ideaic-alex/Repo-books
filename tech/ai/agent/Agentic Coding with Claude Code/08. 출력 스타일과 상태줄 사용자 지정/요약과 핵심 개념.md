# 요약과 핵심 개념

8장은 Claude Code가 사용자와 소통하는 방식을 직접 설계하는 법을 다룬다. 출력 스타일로 응답의 모양과 워크플로를 정하고, 상태줄로 세션 상태를 눈에 보이게 하며, 이 둘을 합쳐 역할별 인스턴스를 운용하는 구상까지 나아간다. 이 문서는 그 흐름을 한 번에 되짚고 핵심 용어를 정리한다.

원서의 장 요약은 이렇다. 출력 스타일은 사용자나 프로젝트 범위로 만들고 적용하며, 선택하면 시스템 프롬프트 동작이 바뀐다. YAML과 HTML은 응답의 생성과 소비를 바꾼다. 스타일에 파일 생성을 넣고, 입력과 기록을 읽는 파이썬 상태줄을 구현한다. 다음 장은 에이전트 스킬이다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 출력 스타일 만들기(minimal-bullets) | 마크다운과 프런트매터 파일 하나로 응답 서식 지정. 사용자와 프로젝트 범위 |
| 2 | 동작 원리와 YAML 스타일 | 기본 지침이 스타일 지침으로 교체됨. 구조를 담는 YAML 응답 |
| 3 | HTML 스타일과 자동화 | 응답을 HTML로 만들고 저장과 브라우저 열기를 스타일에 포함 |
| 4 | 병렬 세션 | 세션마다 다른 스타일. 리뷰, 설명, 디버그 전용 세션 |
| 5 | 상태줄 | stdin의 JSON을 읽어 stdout으로 출력하는 스크립트. 현재 스타일, 마지막 프롬프트 표시 |
| 6 | 전문 에이전트 팀 | 이름, 스타일, 컨텍스트, 역할을 가진 여러 인스턴스 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 출력 스타일 | 응답의 구조, 어조, 워크플로를 정하는 마크다운 설정 파일 |
| `/output-style` | 사용 가능한 스타일을 보고 고르는 슬래시 명령 |
| 사용자 범위 스타일 | 홈 디렉터리의 `.claude/output-styles/`. 모든 프로젝트에 적용 |
| 프로젝트 범위 스타일 | 프로젝트의 `.claude/output-styles/`. 그 프로젝트에만 적용 |
| 시스템 프롬프트 교체 | 기본 소프트웨어 엔지니어링 지침이 스타일 지침으로 바뀌는 동작. 핵심 기능은 유지 |
| YAML 응답 | 들여쓰기와 키 구조로 의존 관계와 범위를 표현하는 형식 |
| 워크플로 내장 | 파일 저장, 브라우저 열기 같은 절차를 스타일 본문에 적는 방식 |
| 상태줄 | 터미널 아래에 항상 보이는 한 줄. 스크립트가 만든다 |
| `/statusline` | 자연어 설명으로 상태줄 스크립트를 생성하는 슬래시 명령 |
| `transcript_path` | 현재 세션의 JSONL 기록 파일을 가리키는 상태줄 입력 키 |

## 3. 자주 놓치는 점

- 출력 스타일은 말투 장식이 아니다. 시스템 프롬프트 자체를 바꾸므로 동작에도 영향을 준다.
- 스타일을 바꿔도 모델은 그대로다. 같은 모델이 다른 지침을 받을 뿐이다.
- 프로젝트 범위 스타일은 전역 스타일보다 우선한다는 설명이 YAML 응답 예시에 나온다.
- HTML 스타일만으로는 파일이 저장되지 않는다. 저장과 열기를 시키거나 스타일에 워크플로로 적어야 한다.
- 상태줄 스크립트는 입력을 stdin으로 받고 결과를 stdout으로 내보낸다. 이 두 길만 알면 된다.
- 책의 설정 예시와 본문 설명에서 상태줄 키 표기가 다르고(statusLine과 statusline), 기록 파일 코드도 설명과 완전히 일치하지 않는다. 실제 적용 전에 설치한 버전에서 직접 확인한다.
- 기본 스타일 이름이나 UI는 책이 쓰인 시점 기준이며 버전에 따라 바뀔 수 있다.
