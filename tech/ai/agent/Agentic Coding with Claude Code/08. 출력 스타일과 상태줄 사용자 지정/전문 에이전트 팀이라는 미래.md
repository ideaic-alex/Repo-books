# 전문 에이전트 팀이라는 미래

8장의 마지막 절은 지금까지 만든 도구를 조합해 앞날을 그려 본다. 출력 스타일과 상태줄을 합치면 Claude Code 세션 하나를 만능 비서로 쓰는 대신, 역할이 다른 여러 세션을 한 팀처럼 운용할 수 있다는 이야기다.

작은 스타트업을 떠올리면 쉽다. 직원 한 명이 모든 일을 하지 않고, 화면은 프런트엔드 담당이, 서버는 백엔드 담당이, 배포는 데브옵스 담당이 맡는다. 같은 일을 해도 담당자마다 말하는 방식이 다르다. 이 문서는 그 구조를 Claude Code 세션에 옮겨 본다.

---

## 1. 에이전틱 코딩과 여러 인스턴스

복잡한 작업에는 세션 하나로 부족한 경우가 많다. 에이전틱 개발이 발전하면 전문화된 여러 에이전트가 각자 맡은 역할이나 영역을 가지고 협업한다. 앞에서 배운 출력 스타일과 런타임 상태줄을 합치면 이 에이전트들을 범용 비서 하나가 아니라 조율된 시스템으로 구성할 수 있다.

저자가 말하는 에이전틱 코딩의 한 모습은 Claude Code 인스턴스를 동시에 여러 개 실행하는 것이다. 각 인스턴스는 세 가지를 가진다.

- 출력 스타일
- 컨텍스트
- 역할

책임이 여러 인스턴스에 나뉘어 배분되므로, 범용 세션 하나에 의존하지 않게 된다.

## 2. 스타트업 팀 비유

책의 그림은 작은 스타트업 팀 모델을 보여 준다. 작업 종류에 따라 담당 전문가가 다르다.

- UI 변경은 프런트엔드 엔지니어 Vinay가 맡는다.
- 백엔드 변경은 Rajesh가 맡는다.
- 배포 문제는 데브옵스 엔지니어 Alex가 맡는다.

각자 책임과 기술이 구분되고, 자기 일에 맞는 방식으로 소통하는 경향도 있다. 이 이름들은 모두 가상이며 역할 예시를 위해 쓴 것이라고 책은 밝힌다.

인스턴스에 이를 대응시킨 예는 다음과 같다.

- 데브옵스 인스턴스는 YAML 스타일의 출력을 쓸 수 있다.
- 백엔드 인스턴스는 OpenAPI 명세 형식을 쓸 수 있다.
- 문서화 인스턴스는 구조화된 학습 스타일 출력을 쓸 수 있다.

출력 스타일은 시스템 수준에서 설정되어 응답이 만들어지는 방식에 영향을 준다. 인스턴스마다 다른 명령, 에이전트, 맥락 제약을 연결할 수도 있다.

## 3. 이름과 역할 기반 컨텍스트

각 인스턴스에 이름을 붙이면 이름 붙은 팀원처럼 다룰 수 있다. 책이 드는 예는 `frontend-engineer`, `backend-engineer`, `devops`, `security-review` 네 가지다.

이름은 세 가지를 반영한다.

- 그 인스턴스의 출력 스타일
- 그 인스턴스의 컨텍스트
- 그 인스턴스가 다루는 작업 종류

터미널을 오가는 일이 곧 전문 팀원 사이를 오가는 일이 된다. 보안 관련 작업은 보안 중심 인스턴스에서, UI 작업은 프런트엔드 중심 인스턴스에서 처리한다. 이 구조는 통제된 컨텍스트 경계와 명확한 책임 분리를 가능하게 한다. 여러 전문 인스턴스가 개발 워크플로 안에서 조율된 에이전트처럼 일하는 셈이다.

여기에 앞 문서의 상태줄이 쓰인다. 어느 세션이 어떤 스타일인지 화면에 늘 보이게 하면 창을 헷갈리지 않는다. 같은 맥락의 그림은 앞의 병렬 세션 절에 실려 있다.

참고(노트 작성자): 원서는 이 구조를 "미래의 방향"으로 제시할 뿐 구현 절차나 설정 예시는 주지 않는다. 인스턴스 이름이 실제로 어떤 설정으로 정해지는지는 원서에 나오지 않아 여기서도 적지 않는다.

## 4. 이 절이 말하려는 것

마지막 절의 결론은 한 문장으로 모인다. Claude Code는 고정된 하나의 인터페이스가 아니라 설정 가능한 시스템이고, 작업에 특화된 에이전트로 빚을 수 있다. 디렉터리 단위 설정이 동작에 영향을 주고, 특화된 세션은 팀 안의 역할 분담을 닮는다.

## 5. 장 마무리

8장 요약은 이렇게 이어진다. 출력 스타일은 사용자 범위나 프로젝트 범위로 만들고 검토하고 적용할 수 있다. 스타일을 고르면 시스템 프롬프트가 바뀌며, YAML과 HTML 같은 구조화된 형식은 응답이 만들어지고 소비되는 방식을 바꾼다. 장은 이 설정을 워크플로 제어까지 넓혀서, 스타일에 파일 생성 동작을 넣고 입력과 기록을 읽는 파이썬 상태줄을 구현했다.

이 내용이 유용한 이유는 Claude Code가 무엇을 만들어 내는지가 아니라 어떻게 소통하는지를 직접 통제하게 해 주기 때문이다. 응답의 구조, 어조, 워크플로 동작을 개발 환경의 일부로 정의할 수 있다. 그래서 작업별로 맞춘 세션, 병렬로 도는 전문 세션, 버전 관리되는 반복 가능한 설정이 가능해진다. 다음 장은 에이전트 능력을 확장하는 방법인 에이전트 스킬을 다룬다.
