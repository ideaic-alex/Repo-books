# 에이전트 스킬 이해하기

9장은 에이전트 스킬(Agent Skills, 작업 방법과 스크립트를 폴더 하나에 묶어 에이전트에게 주는 확장 단위)을 다룬다. 같은 스타일링 작업을 스킬 없이, 그리고 스킬로 해 보며 차이를 확인하고, git-pushing 스킬을 프로젝트에 복제해 고쳐 보며 동작 원리를 배운다. 마지막에는 MCP 서버와 서브에이전트와 비교해 언제 무엇을 쓸지 기준을 세운다.

---

## 1. 핵심 요점

- 스킬은 2025년 10월에 소개된 확장 방식이며, 대화 맥락이 description과 맞으면 Claude가 자동으로 불러 쓴다.
- 핵심 원리는 점진적 공개다. 프런트매터만 상시 노출하고, 본문은 선택 후, 스크립트는 실행 결정 후에 로드한다.
- 스킬 없이 매번 요청하면 같은 정보를 반복 수집한다. 이를 CLAUDE.md에 넣으면 무관한 작업까지 컨텍스트가 커진다. 스킬은 이 둘의 중간 해법이다.
- 스킬 선택은 프런트매터의 name과 description만 근거로 한다. 본문에 트리거 문구를 더해도 소용이 없다.
- 스킬은 스크립트를 담을 수 있어 결정적 워크플로를 만들고, 스크립트가 `claude -p`를 호출하면 결정적 처리와 AI를 섞을 수 있다.
- 스킬은 포장 방식일 뿐이며 지능 수준은 스크립트가 정한다. 스크립트가 실패하면 Claude가 기본 추론으로 이어 간다.
- 스킬은 기본적으로 메인 컨텍스트 안에서 돌며, `context: fork`로 격리 실행할 수 있다.
- MCP는 외부 연결, 서브에이전트는 격리된 위임, 스킬은 반복 작업의 표준화로 역할이 구분된다.
