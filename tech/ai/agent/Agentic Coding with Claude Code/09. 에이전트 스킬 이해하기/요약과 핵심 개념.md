# 요약과 핵심 개념

9장은 에이전트 스킬을 세 단계로 설명한다. 먼저 스킬 없이 하는 작업과 스킬로 하는 작업을 비교하고, 다음으로 스킬을 직접 만들고 고쳐 보며 동작 원리를 확인하고, 마지막으로 MCP와 서브에이전트 같은 다른 구성 요소와 구분한다. 이 문서는 그 흐름을 한 번에 되짚고 핵심 용어를 정리한다.

원서의 장 요약은 이렇게 이어진다. 스킬은 점진적 컨텍스트 로딩으로 메인 컨텍스트 윈도우를 깨끗하게 지키고, 의견이 담긴 워크플로를 포장하며, 결정적 스크립트와 AI 호출을 섞을 수 있고, 스크립트가 실패해도 에이전트가 대체 동작으로 이어 간다. 다음 장은 데스크톱 앱이다.

---

## 1. 장 전체 흐름

| 순서 | 주제 | 결과 |
|---|---|---|
| 1 | 스킬 없이 vs 스킬로 스타일링 | 매번 다시 조사하는 비용과 CLAUDE.md에 넣을 때의 컨텍스트 낭비를 스킬이 피함 |
| 2 | 스킬 설치와 사용 | 마켓플레이스 추가, 승인 후 필요한 마크다운만 주입 |
| 3 | git-pushing 분석 | 프런트매터만 상시 노출, 본문과 스크립트는 선택 후 로드 |
| 4 | 프로젝트 스킬 만들기 | `.claude/skills/` 아래 SKILL.md와 scripts 구조 복제 |
| 5 | 동작 바꿔 보기 | 본문 수정은 선택에 무영향, 자동 승인, claude -p로 AI 커밋 메시지, 구조 훼손 실험 |
| 6 | 격리 실행과 비교 | context: fork, 스킬과 MCP와 서브에이전트의 차이 |

## 2. 핵심 개념 정리

| 개념 | 한 줄 설명 |
|---|---|
| 에이전트 스킬 | 지침, 스크립트, 자료를 폴더 하나에 묶은 확장 단위. 2025년 10월에 소개됨 |
| `SKILL.md` | 스킬의 본체 파일. 위쪽 프런트매터와 아래쪽 본문으로 나뉨 |
| 프런트매터 | `name`과 `description`이 든 머리말. 시스템 프롬프트에 상시 주입되고 스킬 선택의 유일한 근거 |
| 점진적 공개 | 프런트매터, 본문, 스크립트 순서로 필요할 때 단계적으로 컨텍스트에 올리는 방식 |
| 의견이 담긴 워크플로 | 특정 절차와 스크립트 사용을 강제하도록 포장한 작업 방식 |
| 자동 승인 | 스킬 활성화와 스크립트 실행의 확인을 없애는 설정. `settings.local.json`이 갱신됨 |
| `claude -p` | 질의를 보내고 응답을 출력한 뒤 종료하는 프롬프트 모드. 스크립트가 AI를 부를 때 사용 |
| `context: fork` | 스킬을 격리된 서브에이전트 컨텍스트에서 실행하는 프런트매터 설정 |
| `disable-model-invocation: true` | 자동 호출을 막고 슬래시 명령으로만 쓰게 하는 프런트매터 설정 |

## 3. 자주 놓치는 점

- 스킬을 고르는 근거는 프런트매터뿐이다. 본문의 When to Use에 문구를 더해도 선택에는 영향이 없고, 트리거를 바꾸려면 description을 고쳐야 한다.
- 스킬이 곧 AI 로직은 아니다. 스킬은 포장 방식이고, 지능 수준은 안에 든 스크립트가 정한다. 책의 smart_commit.sh는 처음에 파일 개수만 세는 정적 메시지를 썼다.
- 스크립트가 실패해도 Claude는 기본 추론으로 이어 간다. 이때의 결과는 스킬이 아니라 기본 동작의 산물이다.
- 경로가 틀려도 파일이 어딘가 있으면 에이전트가 찾아 실행한다. 파일이 없으면 실패한다.
- 스킬은 메인 컨텍스트 안에서 돈다. 격리가 필요하면 서브에이전트를 쓰거나 `context: fork`를 지정한다.
- MCP는 도구 정의가 세션 시작에 미리 올라가 컨텍스트 비용이 크고, 스킬은 이름과 설명만 올라가 비용이 작다. 수치는 책의 예시이며 시점에 따라 바뀔 수 있다.
- 책의 실습은 특정 저장소 커밋과 브랜치에 의존하므로, 따라 할 때는 책의 예제 저장소 안내를 먼저 확인한다.
