# Claude Code 계획 모드와 멀티 에이전트 워크플로

6장은 에이전트 코딩에 구조와 계획과 통제된 실행이 필요하다는 점에서 출발한다. 계획 모드로 읽기 전용 단계에서 스펙을 만들고 승인받은 뒤에 구현하는 방법을 보여 준다. 이어서 독립된 일을 Claude Code 여러 개에 나눠 맡겨 병렬로 처리하는 입문 예제와 그 한계를 다룬다.

---

## 1. 핵심 요점

- 계획 모드는 읽기 전용이다. 파일 읽기, 분석, MCP 호출, 설계는 되지만 편집, 생성, 삭제, 커밋, 설치는 못 한다.
- 작업 순서는 조사와 분석, 계획 작성, 사람의 검토, 승인 후 구현이다. 전략과 실행이 분리되어 안전하다.
- 잘 쓴 스펙은 모델에게 문제의 범위를 정해 주어 환각과 불필요한 파일 변경, 회귀를 줄인다.
- 완성된 스펙은 Markdown 파일로 내보내 저장소나 `.claude` 디렉터리에 두고 프로젝트 기억처럼 다시 쓴다.
- HookHub 실습에서 캐러셀을 없애고 이벤트 유형을 늘리는 식으로 피드백을 주며 스펙을 다듬었다.
- 병렬 실행은 서로 독립적인 일에만 맞다. 백엔드와 프런트엔드처럼 의존하는 일은 순서대로 한다.
- 두 터미널의 Claude Code에 수정할 파일을 각각 지정해 HookCard.tsx와 Hero.tsx를 충돌 없이 동시에 고쳤다.
- 같은 브랜치 병렬은 깨지기 쉬운 입문용이며, 실무 표준은 깃 브랜치나 워크트리 분리다.
