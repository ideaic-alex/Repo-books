# 6장. 문제 이해와 정의

이 장은 엣지 AI 프로젝트의 전체 워크플로를 소개하고, 풀려는 문제가 정말 엣지 AI에 맞는지 따져 보는 방법을 다룬다. 이어서 문제에 맞는 알고리즘과 하드웨어를 고르고 구현 계획을 세우는 과정까지 단계별로 살펴본다.

---

## 핵심 요점

- **워크플로**: 발견 단계와 테스트·반복 단계로 나뉜다. 피드백 루프, 위험 관리, 책임 있는 AI 검토는 모든 단계에 걸쳐 이어진다.
- **문제 서술과 BLERP**: 문제를 짧게 서술한 뒤, 대역폭, 지연 시간, 경제성, 신뢰성, 프라이버시 다섯 가지로 엣지 배포의 이점을 따져 본다.
- **엣지의 단점**: 개발·배포가 복잡하고, 인력 구하기가 어렵고, 연산 자원이 제한적이고, 비용도 든다. 이를 고려하면 클라우드가 나은 경우가 많다.
- **ML이 필요한가**: 규칙 기반 해법이 있으면 그것을 먼저 택한다. ML을 쓰면 데이터 요구, 설명 가능성, 편향이라는 대가를 치러야 한다.
- **타당성 검토**: 윤리, 비즈니스, 데이터셋, 기술 네 가지 관점을 모두 만족해야 한다. 오즈의 마법사 프로토타입은 이익을 증명하는 데 유용하다.
- **문제 틀짜기**: 해법을 여러 가지 브레인스토밍하고, 분류나 이상 탐지 같은 알고리즘 유형으로 문제를 쪼갠다.
- **계획**: 허용 가능한 성능을 먼저 정의한다. 처음부터 끝까지 동작하는 시스템을 빨리 만들어 반복 개선하고, 하드웨어 작업은 일찍 시작한다.
