# 데이터 포맷과 정리와 균형 조정

원시 데이터가 좋은 데이터셋이 되려면 형식을 통일하고, 오류를 찾아 고치고, 불균형을 바로잡고, 초기 특성 공학까지 거쳐야 한다. 이 문서는 데이터 포맷의 종류, 데이터 정리(cleaning) 절차와 수정 방법, 균형 문제 해결, 데이터셋 준비 단계의 특성 공학을 정리한다.

---

## 1. 데이터 포맷

데이터셋은 여정 중에 여러 포맷을 거친다. 서로 다른 출처에서 혼합 포맷으로 받아 모은 뒤 직접 접근 바이너리 형식으로 정리·가공하고, 필요하면 학습용으로 순차 바이너리 형식으로 바꾼다.

- **텍스트 형식**: CSV와 JSON. 텍스트 에디터로 읽고 고칠 수 있어 단순하지만 용량이 크고 처리 부담이 크다. 메모리에 다 올릴 수 있는 작은 데이터셋에는 괜찮고, 디스크에서 읽어야 하는 큰 데이터는 바이너리로 먼저 바꾸는 편이 낫다.
- **이미지·오디오 파일**: JPEG, WAV처럼 고유 형식을 쓰며, 파일별로 디스크에 두는 방식이 흔하다. 가장 빠르진 않지만 특별한 도구 없이 읽고 수정할 수 있어 충분한 경우가 많다. 보통 매니페스트 파일과 함께 쓴다. 의료 영상처럼 위치·방향 같은 메타데이터를 담는 전용 형식도 있다.
- **직접 접근 바이너리 형식(direct access binary)**: 데이터를 문자 인코딩 없이 본래의 이진 형태로 저장한다(숫자 1337이 텍스트에서는 훨씬 큰 비트열이 된다). 한 파일에 많은 레코드가 있고 필드 의미를 알려 주는 메타데이터가 들어 있어 임의의 레코드에 일정한 시간으로 접근한다. `NPY`(NumPy)와 Apache Parquet이 대표적이며 성능 트레이드오프가 다르다.
- **순차 바이너리 형식(sequential binary)**: `TFRecord` 같은 형식. 정해진 순서로 빠르게 읽도록 학습 등에 최적화돼 있고 매우 컴팩트하지만 탐색이 불편하다. 보통 학습 직전 마지막 단계에서 변환하며 효율 절감이 큰 대규모 데이터셋에서만 쓴다.
- **매니페스트 파일(manifest file)**: 데이터셋의 색인 역할을 하는 파일. 이미지 데이터셋이면 학습에 쓸 이미지 파일 이름 목록이며 CSV가 흔하다. 간단해서 관리하기 편하고, 데이터셋의 표본은 매니페스트에서 행을 무작위로 뽑으면 된다.

---

## 2. 데이터 정리 절차

오류는 수집·가공 어느 단계에서든 생긴다(결함 하드웨어의 이상치, 장치별 형식 불일치, 데이터 결합 중 결측, 특성 공학 버그로 인한 잘못된 값).

1. 샘플링으로 데이터를 감사(audit)해 오류 유형을 파악한다.
2. 오류를 고치거나 우회하는 코드를 작성한다.
3. 결과를 평가해 문제가 해결됐음을 증명한다.
4. 2단계를 자동화해 전체 데이터셋과 앞으로 추가될 샘플에 같은 수정을 적용한다.

- 데이터가 작지 않으면(대략 1GB 미만이 아니라면) 표본으로 작업하는 것이 피드백 루프를 줄인다. 표본에서 검증한 수정을 전체에 적용하되, 마지막에 전체를 다시 평가해 놓친 문제를 확인한다.

### 데이터 감사

- 데이터셋(또는 대표 표본)을 요약해서 보는 도구가 가장 강력하다. 필드별 기술 통계와 자료형 표, 값 분포 차트가 대표적이며 도메인 전문가가 기대에 맞는지 판단한다.
- 파이썬 `pandas`의 `DataFrame`과 `Matplotlib`이 탐색에 적합하다.

```python
frame.describe()          # count, mean, std, min, 25%, 50%, 75%, max
plt.hist(frame['value'])  # 값의 히스토그램
```

- 책의 예에서는 값이 평균 약 0.5, 표준편차 약 0.13으로 정규분포를 이루는데 몇 개 값이 1.5 부근에 있다. 전문가가 센서 문제로 인한 이상치인지 판단하고 원인을 파고든다.

## 3. 오류 수정 방법

- **값 수정(amending)**: 형식 불일치는 올바른 형식으로 변환하고, 결측값은 다른 출처에서 찾아 채우고, 특성 공학 코드 버그로 인한 값은 고친다. 원시 데이터가 어딘가 남아 있어야 완전 수정이 가능하다. 너무 낮은 주파수로 수집됐다면 원신호는 복구할 수 없고 근사만 가능하다.
- **값 대체(substituting)**: 고칠 수 없으면 합리적인 값으로 대체한다. 결측값을 필드 전체 평균으로 채우거나, 이상치를 합리적 값으로 클리핑하거나, 저주파·저해상도 데이터를 보간(interpolate)한다. 레코드를 살릴 수 있지만 잡음이 늘어나므로 득실은 응용에 따라 판단한다.
- **레코드 제외(excluding)**: 결측으로 쓸 수 없는 레코드, 수리 불가능한 센서 데이터, 보안 기준에 못 미치는 출처의 레코드는 버린다. 단순 삭제 대신 문제 있음으로 표시해 따로 보관하면 어떤 문제가 어느 레코드에 생기는지 추적할 수 있다.
- 오류의 상류 원인(upstream cause)도 해결해야 한다. 불량 레코드 비율이 높으면 피해를 복구하는 데 시간을 쓰기 전에 원인부터 고치는 것이 낫다.
- 어떤 방법이 맞는지는 맥락에 달려 있으며 도메인 전문성과 데이터 과학 경험이 함께 필요하다.

### 평가와 자동화

- 수정 후 다시 감사한다. 수정이 새로 만든 문제나 가려져 있던 문제(극단 이상치를 제거하니 덜 극단적인 이상치가 드러남)를 잡기 위해서다. 검증한 뒤 전체에 적용하고, 대규모는 데이터 파이프라인에 자동화한다.
- 수정 코드는 고품질로 작성하고 문서화하며 의존성 기록과 함께 소스 관리에 둔다. 이 코드는 데이터셋이 어떻게 만들어졌는지의 기록이자 앞으로의 자동 수정 수단이다.
- 원본(수정 전) 데이터셋의 사본을 보관해 롤백할 수 있게 한다.
- 오류가 어떤 유형의 레코드에 영향을 줬는지 추적한다. 특정 클래스의 레코드가 많이 버려지면 분류 성능에 영향이 있다. 수정 후에도 데이터셋 품질 기준이 유지되는지 확인한다.
- 초기 평가를 근거로 자동 단언(assertion)을 만든다. 예컨대 극단 이상치를 제거했다면 분산이 기대 수준인지 확인하는 자동 테스트를 새 레코드를 추가할 때마다 돌린다.

## 4. 균형 문제 해결

- 가장 흔한 문제는 하위 그룹별 레코드 수가 고르지 않은 불균형이다.
- **가장 좋은 방법**: 부족한 하위 그룹의 데이터를 더 수집하는 것. 항상 가능하지는 않다.
- **오버샘플링(oversampling)**: 부족한 그룹의 레코드를 복제해 개수를 맞춘다. **언더샘플링(undersampling)**: 많은 그룹의 레코드 일부를 버린다. 모델 학습은 전체 데이터의 합산 손실로 이끌리므로 적은 그룹은 영향력이 작은데, 개수를 맞추면 도움이 된다.
- 한계: 그 그룹의 실제 변이를 표현할 데이터 자체가 부족하면 오버샘플링은 소용없다(한 종의 이미지가 한 개체뿐이라면). 오버샘플링한 데이터로 시스템을 평가하면 해당 그룹의 평가 결과가 덜 믿을 만하므로 주의한다.
- **가중치(weighting)**: 하위 그룹마다 학습·평가에 기여하는 정도를 정하는 가중치를 주고, 부족한 그룹에 더 큰 값을 준다. 객체 인식처럼 객체 영역이 배경보다 본래 작아 리샘플링이 어려운 경우에도 흔히 쓴다.

### 이상 탐지와 균형

- 이상 탐지에서는 이상 사례가 한 번도 일어나지 않았을 수 있어, 데이터셋이 정상(nominal) 운영 샘플로만 구성된다. 정상 조건의 다양한 모드(일·계절에 따른 작업 변화)를 폭넓게 담아야 한다.
- 실제 이상 예제가 없으면 테스트가 어렵다. 장비를 일부러 이상하게 가동하거나 정상 입력을 변형한 합성 데이터로 변화를 시뮬레이션하며, 전문가의 입력이 필요하다.
- 실데이터로 검증하지 않은 시스템의 배포는 권장되지 않는다. 예지 정비처럼 범위가 엄격히 제한된 경우에만 하고, 이해관계자가 효능이 입증되지 않았음을 인지해야 하며 배포 후 집중 감시가 필요하다. 가능하면 알려진 고장 요인으로 문제를 쪼개 균형 잡힌 데이터를 얻는 방법을 찾는다.

## 5. 특성 공학의 위치

- 대부분의 엣지 AI 프로젝트는 특성 공학을 포함한다. 값 스케일링 같은 단순한 것부터 복잡한 DSP 알고리즘까지 다양하다. 본격적인 작업은 9장의 반복 개발 흐름에서 하지만, 데이터셋 준비 단계에서도 기준선을 마련해야 한다.
- 초기 특성 공학의 이유
  - 원시 데이터뿐 아니라 특성 관점에서 데이터셋을 탐색·이해하기 위해
  - 모델 입력에 맞게 값을 스케일링하기 위해
  - 센서 융합(sensor fusion) 등을 위해 값을 결합하기 위해
  - 학습을 빠르게 하려고 DSP 결과를 미리 계산해 두기 위해(학습 중 같은 데이터를 여러 번 보므로 캐싱하면 반복 계산을 피한다)
- 나중에 반복해서 개선할 것이지만 일찍 시작할수록 좋다.
