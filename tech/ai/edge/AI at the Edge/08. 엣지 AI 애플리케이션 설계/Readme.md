# 8장. 엣지 AI 애플리케이션 설계

엣지 AI 애플리케이션 설계는 문제 정의, 데이터셋, 기술 선택, 책임 있는 AI를 하나로 엮는 단계다. 제품 자체와 이를 구현하는 기술 아키텍처는 서로의 제약이 되기 때문에, 설계는 한 번에 끝나지 않고 반복해서 고쳐 나가야 한다. 이 장은 제품과 경험 설계, 범위와 목표 설정, 아키텍처와 설계 패턴, 설계 과정에서 생기는 편향을 차례로 다룬다.

---

## 핵심 요점

- 제품이 문제를 해결했다고 하려면 문제 자체, 사람의 사용 경험, 더 넓은 사회적 맥락을 모두 만족해야 한다.
- AI는 규모에서 힘을 얻는 만큼 결함도 규모만큼 커진다. 그래서 설계 원칙으로 책임을 미리 짜 넣어야 한다.
- 범위를 좁혀 최소 기능 제품(MVP)에서 시작하고, 폭포수 방식은 피한다.
- 평가를 먼저 정하는 접근으로, 기존 해법을 기준선 삼아 시스템 목표, 기술 목표, 가치 기반 목표를 세운다.
- 기본 흐름에서 시작해, 필요할 때만 앙상블, 병렬, 직렬, 캐스케이드, 센서 퓨전 흐름으로 복잡도를 높인다.
- 캐스케이드, 지능형 게이트웨이, 사람 개입, 점진적 성능 저하 대비가 대표적인 설계 패턴이다.
- 제품, 알고리즘, 배포에서 생기는 세 가지 편향을 인정하고 한계를 공개한다.
- 설계 산출물은 프로젝트와 함께 계속 갱신하는 살아 있는 문서다.
