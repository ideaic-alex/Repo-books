# 보드, 엣지 서버, 멀티 디바이스 구성

프로세서를 실제 제품으로 만드는 보드와 완제품 선택지, 서버급 장비, 여러 장치를 엮는 시스템 설계, 그리고 장치별 처리 가능 범위를 한눈에 정리한다.

---

## 1. 보드와 완제품 장치

- **개발 보드(development board, dev board)**: 프로세서에 전원, 센서, 커넥터 등 개발에 필요한 요소를 갖춰 파는 즉시 사용 가능한 장치다. 대량 생산 제품은 보통 맞춤 PCB를 쓰지만, 설계에 시간이 걸리므로 초기에는 개발 보드를 쓴다.
- **엣지 AI에서 특히 중요한 이유**: 알고리즘 선택과 하드웨어 선택이 서로 영향을 주기 때문이다. 보드 몇 개로 실제 프로세서에서 알고리즘을 시험해 성능, 에너지, 비용의 균형을 찾는다.
- **소량 생산**: 맞춤 PCB는 대량일 때만 경제적이므로, 사전 설계된 플랫폼(예: MCU 기반 Arduino Portenta)을 그대로 제품에 쓰기도 한다.
- **SoC와 가속기용 제품**: Raspberry Pi의 단일 보드 컴퓨터(SBC), Nvidia Jetson 가속기 등이 있다. 단일 보드 컴퓨터로 프로토타입을 만든 뒤 코드 변경 없이 자체 하드웨어에 넣을 수 있는 시스템 온 모듈(SOM)로 옮기는 흐름이 가능한 플랫폼도 많다.
- **산업용 IoT 게이트웨이**: SoC를 견고한 케이스, 표준 I/O, 네트워크, 전원과 함께 완제품으로 만든 것이다. 비싸지만 하드웨어를 직접 설계·제작하는 것보다 시간과 비용이 절약될 수 있다.
- **스마트폰**: 가장 흔한 기성 엣지 AI 장치다. 스마트폰 앱 AI는 이 책의 범위 밖이며, 대신 MCU와 DSP가 키워드 호출 같은 특정 기능을 맡는 부분이 범위에 든다. 배터리, 연결성이 좋아 초기 데이터 수집과 모델 시험용 프로토타이핑 도구로도 유용하다.

---

## 2. 엣지 서버

- **개념**: 데이터센터와 같은 서버 하드웨어를 네트워크 가장자리에 두는 방식이다. 서버 OS(Linux, Windows)를 돌리며 클라우드 서버처럼 다룬다. AI 가속은 보통 GPU다. 공장 바닥 같은 곳에 맞게 견고하게 만든 형태도 있다.
- **장점**: 클라우드의 장점을 누리면서 데이터를 현장에 둬 보안, 프라이버시, 편의를 지킨다. 고성능, 낮은 지연(latency), 데이터 유출 위험 감소, 대역폭 절약을 함께 얻는다. 일반 IT 인프라로 취급할 수 있어 기존 IT 부서의 절차와 역량에 맞는다.
- **단점**: 에너지를 많이 쓰고 크다. 공간과 안정적 전원이 있는 건물이나 공장 같은 고정 장소에 한정된다.
- 서버가 과하면 Linux SoC가 절충안이다. 표준 Linux 장비로 취급하면서도 작고 전력 효율이 좋은 형태가 있다.

## 3. 멀티 디바이스 아키텍처

- **개념**: 센서가 달린 장치에서 AI를 모두 처리하지 않고, 역할을 나눠 여러 장치로 구성한다. 예를 들어 운송 팔레트의 센서가 저전력 무선으로 트럭의 게이트웨이에 데이터를 보내고, 에너지 제약이 적고 여러 팔레트 데이터를 보는 게이트웨이가 판단을 내린다.
- 이종 연산이 더해지면 한 장치 안에 애플리케이션용·ML용 프로세서가 따로 있을 수 있고, 시스템 전체는 필요한 BLERP 이점에 따라 여러 지점에서 처리하며 클라우드 연산까지 포함할 수 있다.
- **사례, 스마트 스피커의 음성 비서**
  1. 저전력 상시 구동 칩이 DSP와 머신러닝 모델로 호출어(wake word) 후보를 계속 듣는다.
  2. 후보가 감지되면 애플리케이션 프로세서가 깨어나 더 정교한 모델로 오탐(false positive)을 걸러낸다.
  3. 호출어가 확인되면 오디오를 클라우드 서버로 보내 음성 인식과 자연어 처리를 수행한다.
  - 이 구조 덕분에 사적인 대화를 클라우드로 계속 흘리지 않고 호출어를 인식할 수 있다.
- **멀티 디바이스가 유용한 상황**
  - 많은 개체를 감시할 때: 모든 개체에 고성능 AI 하드웨어를 달면 비싸다.
  - 에너지를 줄일 때: 센서는 배터리로 오래 버텨야 한다.
  - 프라이버시를 지킬 때: 대형 장치나 클라우드로 곧바로 보내면 규범을 어길 수 있다.
  - 기존 장비와 통합할 때: 센서나 게이트웨이를 교체하지 않고 엣지 AI 장치를 보강한다.

---

## 4. 장치별 처리 가능 범위

- 책의 표 3-1은 장치 종류별로 데이터 유형을 처리할 수 있는 정도를 전체(Full), 제한(Limited), 불가(None)로 보여 준다. 각 범주 안에서도 개별 제품 차이가 크고 기술이 빨리 변하므로 낡을 수 있는 참고 자료다.

| 장치 | 저주파 시계열 | 고주파 시계열 | 오디오 | 저해상도 이미지 | 고해상도 이미지 | 비디오 |
|---|---|---|---|---|---|---|
| 저사양 MCU | 제한 | 제한 | 불가 | 불가 | 불가 | 불가 |
| 고사양 MCU | 전체 | 전체 | 전체 | 전체 | 제한 | 제한 |
| 고사양 MCU + 가속기 | 전체 | 전체 | 전체 | 전체 | 전체 | 제한 |
| DSP | 전체 | 전체 | 전체 | 전체 | 제한 | 제한 |
| SoC, SoC + 가속기, FPGA/ASIC, 엣지 서버, 클라우드 | 전체 | 전체 | 전체 | 전체 | 전체 | 전체 |

- **정리**: 처리할 데이터가 영상일수록 더 강한 장치가 필요하다. 반면 시계열과 오디오 정도는 고사양 MCU부터 충분하다.
