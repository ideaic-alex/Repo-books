# 데이터 작업과 알고리즘 개발 도구

데이터를 현장에서 확보하고 저장하고 가공하는 도구, 그리고 알고리즘을 설계하고 모델을 학습시키는 도구를 한데 묶어 본다. 알고리즘 개발은 도구의 복잡도가 가장 높은 영역이며 엣지 AI에 더 잘 맞는 도구와 덜 맞는 도구가 있다.

---

## 1. 데이터 확보와 장치 관리

- **데이터 로거(data logger)**: 현장 센서 데이터를 기록하는 소형 장치. 저장 용량이 크고 배터리나 상시 전원으로 동작한다. 자체 하드웨어를 만들기 전에 곧바로 수집을 시작할 수 있으나, 물리적으로 연결해 수동으로 데이터를 가져와야 한다.
- **모바일 브로드밴드 모뎀(mobile broadband modem)**: 주로 셀룰러(위성도 가능)로 무선 인터넷을 제공해 데이터를 즉시 쓸 수 있다. 데이터 요금이 비싸고 무선 통신이 전력을 많이 소모하며 지역 가용성에 좌우된다.
- **IoT 장치 관리 플랫폼**: 임베디드 소프트웨어에 라이브러리나 API를 통합하면 클라우드 서버와 연결해 장치를 제어하고 데이터를 모을 수 있다. 장치 관리 소프트웨어가 이미 쓰이는 브라운필드(brownfield) 배포에서 편리하다.

---

## 2. 데이터 저장과 포맷

- **단순함이 우선**: 엣지 AI는 보통 배치(batch) 방식으로 데이터를 다뤄 성능이 최우선 요소가 아니다. 데이터 유형에 맞는 단순한 해법을 택한다.
- **파일 시스템**: 데이터베이스 없이 파일 시스템에 저장하는 일이 흔하다. Unix 명령줄 도구와 Python 과학 계산 생태계로 효율적으로 다루고 시각화할 수 있다.
- **센서 값의 포맷**: 효율적이고 간결한 이진 표현으로 저장한다. `CBOR`, `NPY`, ML 학습 성능에 맞춘 `TFRecord`가 후보다.
- **메타데이터 분리**: 측정값에 대한 정보는 별도의 매니페스트 파일(manifest file)이나 간단한 데이터베이스에 두면, 큰 파일을 메모리에 올리지 않고도 데이터셋을 탐색·조작할 수 있다.

---

## 3. 데이터 파이프라인

- **정의**: 원시 데이터를 받아 학습 등 작업에 쓸 수 있게 변환하는 과정. 데이터 정제와 가공을 자동화한다. 예를 들어 센서 데이터를 필터링하고 다른 데이터와 결합해 학습용 형식으로 기록한다.
- **엣지 AI 파이프라인의 특징**: 단순하지만 매우 많은 양의 데이터를 다룬다. 관계형 DB 같은 정형 데이터용 도구보다는, 조회 기능보다 높은 처리량과 임의의 신호 처리 알고리즘을 돌릴 유연성을 가진 도구를 고른다.
- **제공 형태**: 클라우드 업체의 분산 인프라 기능, 센서 데이터에 맞춰 파이프라인을 핵심 기능으로 둔 엔드투엔드 플랫폼.

---

## 4. 수학·과학 계산 라이브러리 (Python)

- **NumPy**: Python 수치 계산의 고성능 토대. 큰 숫자 배열을 쉽게 다루는 API를 제공하며, 파일 형식 `NPY`는 센서 데이터 저장에 편리하다.
- **pandas**: 배열에 NumPy가 있다면 표 데이터에는 pandas. 행과 열로 정리되는 정보를 직관적 문법으로 조회·변환하며 센서 데이터 탐색에 쓰인다.
- **SciPy**: 과학 계산의 핵심 알고리즘을 빠르게 구현한 모음. DSP 알고리즘 개발에 많이 쓰이고 다른 도구의 바탕이 된다.
- **scikit-learn**: NumPy와 SciPy 위에서 머신러닝 알고리즘 구현과 데이터 처리·평가 도구를 제공한다. 구성 요소를 교체하며 조합할 수 있어 알고리즘 비교가 쉽다. 고전 ML의 표준이며 딥러닝 학습에서도 처리·평가 도구가 자주 쓰인다.

---

## 5. 시각화와 대화형 환경

- **시각화 필요성**: 특히 디지털 신호는 그래프로 봐야 이해된다.
- **Matplotlib와 seaborn**: Matplotlib는 방식이 매우 다양해 학술 논문 그림에 흔하지만 문법이 까다롭다. seaborn은 그 위에서 복잡도를 줄이고 pandas와 잘 어울린다. 둘 다 이미지 파일을 출력한다.
- **Plotly**: 동적으로 탐색할 수 있는 대화형 시각화를 만든다.
- **Jupyter Notebook**: 코드와 실행 결과, 그래프를 같은 문서에 나란히 둔다. 실험 도구이자 작업 증빙 문서가 된다. 흔한 흐름은 노트북에서 가장 좋은 후보를 찾은 뒤 일반 Python 스크립트로 옮기는 것이다.
- **호스팅 환경**: Google Colab, Amazon SageMaker는 무료로 쓸 수 있고 추가 연산은 유료다.
- **MATLAB**: 비슷한 대화형 환경과 자체 언어를 갖춘 상용 폐쇄형 제품. 학계·공학, 특히 DSP 엔지니어에게 익숙하지만 라이선스 비용으로 소프트웨어 엔지니어에게는 덜 인기다.
- **OpenMV IDE**: 엣지 AI 전용 오픈소스 대화형 환경. 카메라 장치에 연결해 알고리즘 실행 결과를 실시간으로 보여 주며 다른 대상에도 배포할 수 있다.

---

## 6. 신호 처리(DSP)와 딥러닝 프레임워크

- **DSP 개발 환경**: Python 또는 MATLAB. Python은 `scipy.signal` 모듈을, MATLAB은 signal processing, image processing 툴박스를 쓴다. MATLAB은 GUI 도구가 있지만, Python은 무료이고 ML 학습 툴체인과 직접 호환된다. 무료 오픈소스 대안으로 `GNU Octave`도 늘고 있다.
- **TensorFlow vs PyTorch**: 각각 Google과 Meta가 만든 Python용 오픈소스 프레임워크로, 모델 정의·학습·데이터 처리·분산 조율·배포를 아우르는 도구 모음이라는 점이 일반 라이브러리와 다르다.
- **산업과 연구의 분화**: TensorFlow는 산업용, PyTorch는 연구자용으로 자리 잡았다. 배포 옵션이 많은 TensorFlow 생태계가 엣지 AI에 특히 유리하다.
- **엣지 AI의 선택**: 모델 최적화·장치 배포 도구 대부분이 TensorFlow 생태계에 맞춰져 있고, 두 프레임워크의 모델 저장 형식 간 변환은 간단치 않다. 그래서 현재 엣지 AI의 ML 엔지니어 다수가 TensorFlow를 쓴다. 최신 모델 구조가 PyTorch로 먼저 나오는 불편은 있으나, 엣지용 소형 모델 연구는 TensorFlow 쪽에서 많이 이뤄진다. 비호환이 가장 아픈 곳은 학습 코드가 복잡한 객체 탐지다.
- **프레임워크 예시 키워드**: Keras는 TensorFlow의 고수준 API로 `Sequential`, `Dense`, `model.compile`, `model.fit` 등으로 모델을 정의하고 학습한다.

```python
model = Sequential()
model.add(Dense(units=64, activation='relu'))
model.compile(loss='categorical_crossentropy', optimizer='sgd')
model.fit(x_train, y_train, epochs=5, batch_size=32)
```
