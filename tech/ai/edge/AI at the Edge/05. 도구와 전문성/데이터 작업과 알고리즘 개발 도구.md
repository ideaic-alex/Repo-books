# 데이터 작업과 알고리즘 개발 도구

현장에서 데이터를 확보하고 저장하고 가공하는 도구, 그리고 알고리즘을 설계하고 모델을 학습시키는 도구를 한데 묶어 살펴본다. 알고리즘 개발은 도구가 가장 복잡한 영역이고, 엣지 AI에 더 잘 맞는 도구와 덜 맞는 도구가 있다.

---

## 1. 데이터 확보와 장치 관리

- **데이터 로거(data logger)**: 현장의 센서 데이터를 기록하는 소형 장치다. 저장 용량이 크고 배터리나 상시 전원으로 동작한다. 자체 하드웨어를 만들기 전에 바로 데이터 수집을 시작할 수 있다. 다만 장치를 물리적으로 연결해서 직접 데이터를 가져와야 한다.
- **모바일 브로드밴드 모뎀(mobile broadband modem)**: 주로 셀룰러(위성도 가능)로 무선 인터넷을 제공하므로 데이터를 바로 쓸 수 있다. 대신 데이터 요금이 비싸고, 무선 통신이 전력을 많이 쓰며, 지역에 따라 쓸 수 있는지가 달라진다.
- **IoT 장치 관리 플랫폼**: 임베디드 소프트웨어에 라이브러리나 API를 넣으면 클라우드 서버와 연결해서 장치를 제어하고 데이터를 모을 수 있다. 장치 관리 소프트웨어가 이미 쓰이고 있는 브라운필드(brownfield) 환경에 배포할 때 편리하다.

---

## 2. 데이터 저장과 포맷

- **단순함이 우선**: 엣지 AI에서는 보통 데이터를 배치(batch) 방식으로 다루므로 성능이 가장 중요한 요소는 아니다. 데이터 유형에 맞는 단순한 방법을 고른다.
- **파일 시스템**: 데이터베이스 없이 파일 시스템에 저장하는 경우가 흔하다. Unix 명령줄 도구와 Python 과학 계산 생태계를 쓰면 효율적으로 다루고 시각화할 수 있다.
- **센서 값의 포맷**: 효율적이고 간결한 이진 표현으로 저장한다. 후보로는 `CBOR`, `NPY`, 그리고 ML 학습 성능에 맞춘 `TFRecord`가 있다.
- **메타데이터 분리**: 측정값에 대한 정보는 별도의 매니페스트 파일(manifest file)이나 간단한 데이터베이스에 따로 둔다. 그러면 큰 파일을 메모리에 올리지 않고도 데이터셋을 탐색하고 다룰 수 있다.

---

## 3. 데이터 파이프라인

- **정의**: 원시 데이터를 받아 학습 같은 작업에 쓸 수 있게 변환하는 과정이다. 데이터를 정제하고 가공하는 일을 자동화한다. 예를 들어 센서 데이터를 필터링하고 다른 데이터와 합친 뒤 학습용 형식으로 기록한다.
- **엣지 AI 파이프라인의 특징**: 처리 과정은 단순하지만 데이터 양이 매우 많다. 그래서 관계형 DB 같은 정형 데이터용 도구보다는, 조회 기능보다 처리량이 높고 임의의 신호 처리 알고리즘을 돌릴 수 있을 만큼 유연한 도구를 고른다.
- **제공 형태**: 클라우드 업체의 분산 인프라 기능이 있고, 센서 데이터에 맞춰 파이프라인을 핵심 기능으로 둔 엔드투엔드 플랫폼도 있다.

---

## 4. 수학·과학 계산 라이브러리 (Python)

- **NumPy**: Python 수치 계산의 고성능 토대다. 큰 숫자 배열을 쉽게 다루는 API를 제공하고, 파일 형식인 `NPY`는 센서 데이터를 저장하기에 편리하다.
- **pandas**: 배열을 다룰 때 NumPy가 있다면 표 데이터는 pandas가 맡는다. 행과 열로 정리되는 정보를 직관적인 문법으로 조회하고 변환할 수 있어서, 센서 데이터를 탐색할 때 쓴다.
- **SciPy**: 과학 계산의 핵심 알고리즘을 빠르게 구현해 모아 놓은 라이브러리다. DSP 알고리즘을 개발할 때 많이 쓰고, 다른 도구의 바탕이 되기도 한다.
- **scikit-learn**: NumPy와 SciPy 위에서 머신러닝 알고리즘 구현과 데이터 처리·평가 도구를 제공한다. 구성 요소를 갈아 끼우면서 조합할 수 있어 알고리즘을 비교하기 쉽다. 고전 ML의 표준이고, 딥러닝 학습에서도 처리·평가 도구를 자주 가져다 쓴다.

---

## 5. 시각화와 대화형 환경

- **시각화가 필요한 이유**: 특히 디지털 신호는 그래프로 봐야 이해가 된다.
- **Matplotlib와 seaborn**: Matplotlib는 만들 수 있는 그래프가 매우 다양해서 학술 논문의 그림에 흔히 쓰이지만 문법이 까다롭다. seaborn은 Matplotlib 위에서 복잡도를 줄였고 pandas와 잘 어울린다. 둘 다 이미지 파일로 결과를 낸다.
- **Plotly**: 직접 움직이며 탐색할 수 있는 대화형 시각화를 만든다.
- **Jupyter Notebook**: 코드, 실행 결과, 그래프를 한 문서에 나란히 둔다. 실험 도구이면서 작업 과정을 보여 주는 문서도 된다. 보통은 노트북에서 가장 좋은 후보를 찾은 뒤 일반 Python 스크립트로 옮기는 흐름으로 쓴다.
- **호스팅 환경**: Google Colab과 Amazon SageMaker는 무료로 쓸 수 있고, 연산을 더 쓰면 요금을 낸다.
- **MATLAB**: 비슷한 대화형 환경과 자체 언어를 갖춘 상용 폐쇄형 제품이다. 학계와 공학 쪽, 특히 DSP 엔지니어에게 익숙하다. 하지만 라이선스 비용 때문에 소프트웨어 엔지니어에게는 인기가 덜하다.
- **OpenMV IDE**: 엣지 AI 전용 오픈소스 대화형 환경이다. 카메라 장치에 연결해 알고리즘 실행 결과를 실시간으로 보여 주고, 다른 대상에도 배포할 수 있다.

---

## 6. 신호 처리(DSP)와 딥러닝 프레임워크

- **DSP 개발 환경**: Python이나 MATLAB을 쓴다. Python은 `scipy.signal` 모듈을, MATLAB은 signal processing, image processing 툴박스를 쓴다. MATLAB에는 GUI 도구가 있다. 반면 Python은 무료이고 ML 학습 툴체인과 바로 호환된다. 무료 오픈소스 대안인 `GNU Octave`를 쓰는 사람도 늘고 있다.
- **TensorFlow vs PyTorch**: 각각 Google과 Meta가 만든 Python용 오픈소스 프레임워크다. 일반 라이브러리와 달리 모델 정의, 학습, 데이터 처리, 분산 조율, 배포까지 아우르는 도구 모음이다.
- **산업과 연구로 갈린 선택**: TensorFlow는 산업용으로, PyTorch는 연구자용으로 자리 잡았다. 배포 옵션이 많은 TensorFlow 생태계는 엣지 AI에 특히 유리하다.
- **엣지 AI에서의 선택**: 모델 최적화와 장치 배포 도구 대부분이 TensorFlow 생태계에 맞춰져 있다. 게다가 두 프레임워크의 모델 저장 형식을 서로 변환하기가 간단하지 않다. 그래서 지금은 엣지 AI를 하는 ML 엔지니어 다수가 TensorFlow를 쓴다. 최신 모델 구조가 PyTorch로 먼저 나와서 불편하긴 하지만, 엣지용 소형 모델 연구는 TensorFlow 쪽에서 많이 이뤄진다. 호환이 안 되는 문제가 가장 아픈 곳은 학습 코드가 복잡한 객체 탐지다.
- **프레임워크 코드 예시**: Keras는 TensorFlow의 고수준 API로, `Sequential`, `Dense`, `model.compile`, `model.fit` 등으로 모델을 정의하고 학습한다.

```python
model = Sequential()
model.add(Dense(units=64, activation='relu'))
model.compile(loss='categorical_crossentropy', optimizer='sgd')
model.fit(x_train, y_train, epochs=5, batch_size=32)
```
