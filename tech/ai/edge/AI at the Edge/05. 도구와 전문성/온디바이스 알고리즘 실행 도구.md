# 온디바이스 알고리즘 실행 도구

알고리즘을 설계하고 학습하는 도구와, 그것을 장치에서 효율적으로 돌리는 도구는 별개다. 장치 쪽에서는 범용 C++ 라이브러리와 특정 하드웨어에 최적화된 구현이 함께 쓰인다. 이 문서는 수학·DSP 라이브러리, 추론 실행 방식 여섯 가지, 최적화와 커널 지원의 관계, 온디바이스 학습의 한계를 정리한다.

---

## 1. 수학 및 DSP 라이브러리

- **필요성**: 기본 알고리즘을 처음부터 구현하면 시간이 많이 든다. DSP 알고리즘과 딥러닝 연산 모두에 쓰이는 수학 구현을 가져다 쓴다.
- **고속 푸리에 변환(FFT)**: DSP에서 많이 쓰이며 `KISS FFT`, `FFTW`가 대표적이다.
- **행렬 곱셈 라이브러리**: `gemmlowp`, `ruy`.
- **하드웨어 전용 라이브러리**: `CMSIS DSP Software Library`는 Arm Cortex-M과 Cortex-A용으로 많은 DSP 알고리즘을 최적화해 제공한다. 딥러닝 커널용으로는 `CMSIS NN Software Library`가 있으며, 여러 프로세서 구조에 비슷한 것이 있다.
- **하드웨어 선택 팁**: 최적화된 커널이 있는지 확인하라. 지연 시간(latency)에서 10~100배 차이를 만들 수 있다.

---

## 2. 추론을 실행하는 방법들

- **직접 구현의 한계**: 특정 모델을 대상 구조에 맞게 손으로 최적화해 코드로 짜면 시간이 오래 걸리고, 새 응용이나 다른 하드웨어에 재사용할 수 없으며 모델이 바뀌면 프로그램 전체를 고쳐야 한다.
- **인터프리터(interpreter, 런타임)**: 모델의 연산과 파라미터를 기술한 파일을 읽어, 미리 작성된 연산자(operator)로 차례로 실행한다. 몇 줄의 같은 코드로 어떤 모델이든 바꿔 돌릴 수 있는 유연함이 장점이다. 대신 해석 과정의 오버헤드로 RAM, ROM, CPU 사이클을 더 쓴다. 대표적으로 `TensorFlow Lite`(원래 휴대폰용이나 많은 SoC에서 동작)와 `TensorFlow Lite for Microcontrollers`(마이크로컨트롤러와 DSP에서 동작)가 있다. 둘 다 C++로 구현되고 전자는 Python, Java API도 제공하며, TFLite converter의 연산자 융합과 양자화 혜택을 받는다. 장치에 맞춰 커널을 교체할 수 있다.
- **코드 생성 컴파일러(code generation compiler)**: 모델 파일을 입력받아 이를 구현한 프로그램을 생성하고, 연산자는 미리 작성된 라이브러리를 호출한다. 인터프리터의 장점은 유지하면서 대부분의 오버헤드를 없앤다. Edge Impulse의 `EON Compiler`는 TFLite Micro 커널과 호환된다.
- **바이트코드 컴파일러(bytecode compiler)**: 대상을 아는 컴파일러가 모델을 구현하는 바이트코드를 직접 생성하며 실리콘의 성능 기능을 활용한다. 예: Synaptics의 `TENSAI Flow` 컴파일러(Katana Edge AI 프로세서용).
- **가상 머신(virtual machine)**: 장치마다 컴파일러를 만드는 어려움을 피하려고 하드웨어 위의 추상 계층을 대상으로 컴파일한다. 효율은 조금 떨어지지만 이점이 클 수 있고, 가상 머신 자체는 새 프로세서에 이식해야 한다. `Apache TVM`이 이 방식이며, 여러 구현을 반복 시험해 가장 효율적인 것을 찾는 온디바이스 런타임을 쓴다.
- **하드웨어 기술 언어(HDL)**: 프로세서 구조를 기술하고 FPGA·ASIC을 프로그래밍하는 코드를 컴파일러가 생성해 모델을 하드웨어로 직접 구현하는 신흥 흐름. 매우 효율적일 수 있으며 `CFU Playground`, `Tensil`이 맞춤 가속기 설계를 돕는 오픈소스 도구다.
- **기타 방식**: 일부 가속기 칩은 일반적인 코드 컴파일 워크플로 밖에서, 모델 가중치를 특수 메모리 버퍼에 직접 쓰는 인터페이스로 프로그래밍한다.

---

## 3. 추론 최적화와 모델 최적화의 관계

- **구분**: 특정 장치용 커널 최적화와, 압축 등 모델 자체의 최적화는 다르다. 모델 최적화는 자체 커널이나 하드웨어 지원을 필요로 하는 경우가 많다.
- **양자화**: 8비트 정수로 양자화한 모델은 그 정밀도를 지원하는 커널이 있어야 하고, `int8`, `uint8`, `int16` 같은 데이터 타입마다 전용 커널이 필요하다.
- **가지치기(pruning)**: 0이 많은 희소 모델이 되지만 그 자체로 실행 시간은 줄지 않는다. 희소성을 활용하는 커널이나 하드웨어가 있어야 하는데 아직 널리 보급되지 않아 현장 효용은 제한적이다.

---

## 4. 온디바이스 학습

- **현실**: 딥러닝 학습의 데이터·연산 요구 때문에 온디바이스 학습의 효용은 제한적이다. 보통 말하는 온디바이스 학습은 임베딩 벡터 사이의 거리를 계산해(예: 두 지문의 임베딩이 일치하는지) 판단하는 단순한 방식이다.
- **실제 딥러닝 학습**: 장치에서 하는 일은 매우 드물다. 저장과 연산이 충분한 장치(보통 SoC나 휴대폰)라면 TensorFlow Lite가 일부 기능을 제공한다.
- **근본 문제**: 장치에서 학습한 모델이 실제로 잘 동작하는지 파악하기가 매우 어렵다. 아주 좋은 이유가 없다면 온디바이스 딥러닝은 피하는 편이 낫다.
- **연합 학습(federated learning)**: 많은 사람이 관심을 갖지만 대부분의 문제에는 맞지 않고 도구도 아직 초보적·실험적이다. 파고들다 시간을 낭비하기 쉬우며 실제로 필요한 프로젝트는 극히 드물다. 더 알고 싶다면 `TensorFlow Federated`가 참고 자료다.
