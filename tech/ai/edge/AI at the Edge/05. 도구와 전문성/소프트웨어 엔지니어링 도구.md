# 소프트웨어 엔지니어링 도구

엣지 AI 개발의 상당 부분은 소프트웨어 개발이므로 현대적 소프트웨어 엔지니어링 도구가 중요하다. 운영체제, 프로그래밍 언어, 의존성 관리, 컨테이너, 분산 컴퓨팅, 클라우드가 핵심 축이다. 이 문서는 각 도구가 엣지 AI에서 어떤 역할을 하는지 정리한다.

---

## 1. 운영체제

- **개발 환경의 충돌**: 임베디드 전통은 Windows를 많이 쓰고 일부 도구도 그것을 전제로 한다. 반면 데이터 과학·ML 도구는 Linux나 macOS 같은 Unix 호환 환경에 맞춰져 있다.
- **큰 문제는 아니다**: 팀원 모두가 모든 도구를 돌릴 필요는 없다. ML 엔지니어가 Linux에서 모델을 학습·최적화해 Windows를 쓰는 임베디드 엔지니어에게 넘길 수 있고, `Windows Subsystem for Linux` 같은 혼용 도구도 있다. 최근 임베디드 툴체인은 Unix에서도 잘 동작한다.
- **배포 시 운영체제**: 장치에서는 임베디드 Linux(SoC용으로 컴파일한 경량 Linux 배포판), 실시간 운영체제(RTOS, 최소 오버헤드의 임베디드 전용 OS), 또는 OS 없음(마이크로컨트롤러에서 가장 흔함) 중 하나를 쓰며 모두 엣지 AI와 호환된다.

---

## 2. 프로그래밍 및 스크립팅 언어

- **Python**: 머신러닝의 사실상 표준 언어다. 방대한 수학·과학 계산 오픈소스 라이브러리와 연구 커뮤니티의 거의 전면적 채택 덕분이며, 범용 소프트웨어 개발에도 쓰여 R 같은 특화 언어를 앞선다. TensorFlow와 PyTorch도 Python으로 쓰였다. ML부터 DSP까지 엣지 AI 알고리즘 개발에 적합하다.
- **C++**: 현대 임베디드 개발의 보편 언어다. 엣지 AI에 쓰이는 고성능 임베디드 장치는 대개 C++로 프로그래밍하며, 대부분의 마이크로컨트롤러 기반 시스템에서는 사실상 유일한 선택지다. 하드웨어를 세밀하게 제어하고 Python보다 훨씬 빠를 수 있으나 숙련이 필요하다. 일부 플랫폼은 더 단순한 C만 지원한다.
- **Python 라이브러리의 속사정**: 수학 연산의 핵심은 내부에서 C++로 구현되고 Python은 편리한 포장 역할을 한다.
- **스크립팅 언어(Bash 등)**: 애플리케이션을 빌드하고 장치에 배포하는 복잡한 도구와 스크립트를 엮어 자동화한다.
- **대상별 선택**: 마이크로컨트롤러는 거의 항상 C++. SoC는 전체 OS를 돌려 Python 같은 고수준 언어도 가능하지만 훨씬 비싸고 전력을 더 쓴다.
- **이식 작업**: 대다수 대상이 C++을 요구하므로 Python으로 개발한 알고리즘은 이식해야 하며, 돕는 도구가 있지만 항상 간단하지는 않다.

---

## 3. 의존성 관리

- **의존성 지옥**: 데이터 과학·ML 도구는 막대한 서드파티 라이브러리를 끌고 온다. 임베디드 쪽에서도 신호 처리·ML용 최적화 수학 라이브러리, C++ 컴파일·배포용 복잡한 의존성이 문제다. 엣지 AI 개발에서 가장 까다로운 부분 중 하나다.
- **Python 도구**: `Poetry`는 여러 환경의 의존성을 지정·설치·격리하는 데 가장 도움이 된다. 흔한 도구로 `pip`, `Conda`도 있다.
- **OS 패키지 관리자**: Debian 계열의 `aptitude`, macOS의 `Homebrew`.
- **통합 시점의 위험**: 특정 버전의 딥러닝 프레임워크로 학습한 모델이 조금 뒤 나온 추론 프레임워크와 호환되지 않을 수 있다. 그래서 개발 초기에 시스템을 끝에서 끝까지 테스트해야 한다.

---

## 4. 컨테이너화(containerization)

- **개념**: OS 수준 기법으로 소프트웨어를 격리된 환경인 컨테이너(container) 안에서 실행한다. 컨테이너 안에서는 호스트와 완전히 다른 OS와 의존성을 가질 수 있고 시스템 자원 접근은 제한된다.
- **엣지 AI에서의 효용**: ML과 임베디드 개발 등 서로 의존성이 충돌하는 툴체인(예: 언어 인터프리터 버전이 다른 경우)을 한 기계에서 공존시킨다.
- **특성**: 컨테이너는 대체로 상태가 없고 이식성이 높아, 정성껏 구성한 기계 전체를 특정 작업을 하는 명령줄 프로그램처럼 다루고 서로 연결하거나 여러 기계에서 돌릴 수 있다.
- **장치에서의 사용**: 임베디드 Linux가 도는 SoC에서 컨테이너를 돌려 소프트웨어와 의존성을 패키징해 배포할 수 있지만 일부 오버헤드가 있다.
- **대표 도구**: `Docker`는 개발 워크스테이션에서 로컬로, `Kubernetes`는 분산 인프라에서 컨테이너 클러스터를 운영하는 데 주로 쓴다.

---

## 5. 분산 컴퓨팅과 클라우드

- **분산 컴퓨팅(distributed computing)**: 서로 다른 프로세스를 인터넷으로 연결된 여러 기계에서 돌리는 방식으로, 현대 컴퓨팅의 지배적 아키텍처다.
- **엣지 AI와의 관계**: 첫째, 엣지 AI 자체가 분산 컴퓨팅이다. 데이터가 생기는 엣지에서 계산하고 결과를 로컬에서 쓰거나 네트워크로 보낸다. 둘째, 데이터셋 관리·알고리즘 개발·모델 학습은 연산과 저장 부담이 커서 원격 서버를 빌려 쓰는 것이 흔하다.
- **오케스트레이션(orchestration)**: 분산 인프라를 조직하고 제어하는 일. `Kubeflow`는 여러 기계에서 머신러닝 작업을 돌리는 오케스트레이션 프레임워크다.
- **클라우드 제공자**: Amazon Web Services, Google Cloud, Microsoft Azure 같은 업체가 주문형 분산 컴퓨팅 자원을 제공한다. 물리 장비와 네트워크를 맡아 주고, 컨테이너를 적극 활용해 여러 워크로드를 한 인프라에 공존시킨다.
- **엣지 AI 프로젝트의 클라우드 용도**: 데이터셋 저장, 모델 학습, 장치와 데이터를 주고받는 백엔드. 클라우드 서버의 AI와 엣지 장치의 AI가 협력하는 경우도 있다.
