# 소프트웨어 엔지니어링 도구

엣지 AI 개발의 상당 부분은 소프트웨어 개발이어서, 현대적인 소프트웨어 엔지니어링 도구가 중요하다. 핵심은 운영체제, 프로그래밍 언어, 의존성 관리, 컨테이너, 분산 컴퓨팅, 클라우드다. 이 문서는 각 도구가 엣지 AI에서 어떤 역할을 하는지 정리한다.

---

## 1. 운영체제

- **개발 환경의 충돌**: 임베디드 쪽은 전통적으로 Windows를 많이 쓰고, 일부 도구도 Windows를 전제로 한다. 반면 데이터 과학과 ML 도구는 Linux나 macOS 같은 Unix 호환 환경에 맞춰져 있다.
- **큰 문제는 아니다**: 팀원 모두가 모든 도구를 돌릴 필요는 없다. ML 엔지니어가 Linux에서 모델을 학습하고 최적화한 뒤, Windows를 쓰는 임베디드 엔지니어에게 넘기면 된다. `Windows Subsystem for Linux`처럼 두 환경을 함께 쓰게 해 주는 도구도 있다. 최근 임베디드 툴체인은 Unix에서도 잘 동작한다.
- **장치에 배포할 때의 운영체제**: 장치에서는 임베디드 Linux(SoC용으로 컴파일한 경량 Linux 배포판), 실시간 운영체제(RTOS, 오버헤드가 최소인 임베디드 전용 OS), OS 없음(마이크로컨트롤러에서 가장 흔함) 중 하나를 쓴다. 모두 엣지 AI와 호환된다.

---

## 2. 프로그래밍 및 스크립팅 언어

- **Python**: 머신러닝에서 사실상 표준인 언어다. 수학·과학 계산용 오픈소스 라이브러리가 방대하고, 연구 커뮤니티가 거의 전부 Python을 쓰기 때문이다. 범용 소프트웨어 개발에도 쓸 수 있어서 R 같은 특화 언어보다 앞선다. TensorFlow와 PyTorch도 Python으로 쓰였다. ML부터 DSP까지 엣지 AI 알고리즘 개발에 두루 알맞다.
- **C++**: 현대 임베디드 개발에서 가장 널리 쓰이는 언어다. 엣지 AI에 쓰는 고성능 임베디드 장치는 대개 C++로 프로그래밍한다. 마이크로컨트롤러 기반 시스템 대부분에서는 사실상 유일한 선택지다. 하드웨어를 세밀하게 제어할 수 있고 Python보다 훨씬 빠를 수 있지만, 익히는 데 숙련이 필요하다. 일부 플랫폼은 더 단순한 C만 지원한다.
- **Python 라이브러리의 내부**: 수학 연산의 핵심은 내부에서 C++로 구현되어 있고, Python은 쓰기 편하게 감싸 주는 역할을 한다.
- **스크립팅 언어(Bash 등)**: 애플리케이션을 빌드해서 장치에 배포하려면 복잡한 도구와 스크립트를 이어 붙여야 한다. 스크립팅 언어로 이 과정을 자동화한다.
- **대상별 선택**: 마이크로컨트롤러는 거의 항상 C++를 쓴다. SoC는 전체 OS를 돌릴 수 있어서 Python 같은 고수준 언어도 쓸 수 있지만, 그만큼 훨씬 비싸고 전력도 더 쓴다.
- **이식 작업**: 대부분의 대상이 C++를 요구하므로, Python으로 개발한 알고리즘은 C++로 옮겨야 한다. 이를 돕는 도구가 있지만 항상 간단하지는 않다.

---

## 3. 의존성 관리

- **의존성 지옥**: 데이터 과학과 ML 도구는 서드파티 라이브러리를 엄청나게 많이 끌고 온다. 임베디드 쪽에서도 신호 처리와 ML용 최적화 수학 라이브러리, C++ 컴파일과 배포에 필요한 복잡한 의존성이 문제가 된다. 엣지 AI 개발에서 가장 까다로운 부분 중 하나다.
- **Python 도구**: `Poetry`는 여러 환경의 의존성을 지정하고 설치하고 격리하는 데 가장 도움이 된다. `pip`와 `Conda`도 흔히 쓴다.
- **OS 패키지 관리자**: Debian 계열의 `aptitude`, macOS의 `Homebrew`가 있다.
- **통합 단계의 위험**: 특정 버전의 딥러닝 프레임워크로 학습한 모델이, 조금 뒤에 나온 추론 프레임워크와 호환되지 않을 수 있다. 그래서 개발 초기에 시스템을 처음부터 끝까지 테스트해 봐야 한다.

---

## 4. 컨테이너화(containerization)

- **개념**: OS 수준의 기법으로, 소프트웨어를 격리된 환경인 컨테이너(container) 안에서 실행한다. 컨테이너 안에서는 호스트와 완전히 다른 OS와 의존성을 쓸 수 있고, 시스템 자원에 접근하는 것은 제한된다.
- **엣지 AI에서의 효용**: ML 개발과 임베디드 개발처럼 의존성이 서로 충돌하는 툴체인(예를 들어 언어 인터프리터 버전이 다른 경우)을 한 대의 기계에서 함께 쓸 수 있다.
- **특성**: 컨테이너는 대체로 상태가 없고 이식성이 높다. 그래서 정성껏 설정한 기계 전체를, 특정 작업을 하는 명령줄 프로그램처럼 다룰 수 있다. 컨테이너끼리 서로 연결하거나 여러 대의 기계에서 돌릴 수도 있다.
- **장치에서의 사용**: 임베디드 Linux가 도는 SoC에서 컨테이너를 돌리면 소프트웨어와 의존성을 패키징해서 배포할 수 있다. 다만 오버헤드가 조금 있다.
- **대표 도구**: `Docker`는 개발 워크스테이션에서 로컬로 쓰는 경우가 많다. `Kubernetes`는 분산 인프라에서 컨테이너 클러스터를 운영할 때 주로 쓴다.

---

## 5. 분산 컴퓨팅과 클라우드

- **분산 컴퓨팅(distributed computing)**: 서로 다른 프로세스를 인터넷으로 연결된 여러 대의 기계에서 돌리는 방식이다. 현대 컴퓨팅에서 가장 지배적인 아키텍처다.
- **엣지 AI와의 관계**: 첫째, 엣지 AI 자체가 분산 컴퓨팅이다. 데이터가 생기는 엣지에서 계산하고, 결과를 로컬에서 쓰거나 네트워크로 보낸다. 둘째, 데이터셋 관리, 알고리즘 개발, 모델 학습은 연산과 저장 부담이 커서 원격 서버를 빌려 쓰는 경우가 많다.
- **오케스트레이션(orchestration)**: 분산 인프라를 조직하고 제어하는 일이다. `Kubeflow`는 여러 대의 기계에서 머신러닝 작업을 돌리는 오케스트레이션 프레임워크다.
- **클라우드 제공자**: Amazon Web Services, Google Cloud, Microsoft Azure 같은 업체가 필요할 때 바로 쓸 수 있는 분산 컴퓨팅 자원을 제공한다. 물리 장비와 네트워크는 업체가 맡아 주고, 컨테이너를 적극 활용해 여러 워크로드를 한 인프라에서 함께 돌린다.
- **엣지 AI 프로젝트에서 클라우드의 용도**: 데이터셋 저장, 모델 학습, 장치와 데이터를 주고받는 백엔드로 쓴다. 클라우드 서버의 AI와 엣지 장치의 AI가 협력하는 경우도 있다.
