# 자전거 모니터링 데이터 수집

실습에서는 자전거 핸들바에 가속도 센서를 붙이고, 운전자의 움직임 이벤트를 분류하는 장치를 만든다. 이 문서는 클래스 설계, 충돌을 직접 겪지 않고 목표를 이루는 방법, 하드웨어, 데이터 수집과 정리를 다룬다.

---

## 1. 실습 개요

- **초기 클래스**: `idle`(정지), `sudden stop`(급정지), `nominal`(정상 주행)로 시작한다.
- **동작 방식**: 장치가 가속도 원시 샘플을 계속 읽으면서 정지, 회전, 급정지(충돌 가능성), 울퉁불퉁한 지형 주행 같은 움직임을 추론한다.
- **경고 처리**: 이상 점수(anomaly score)가 높거나 급정지가 감지되면 오디오 알림이나 LED로 바로 알려 준다. 이 정보를 네트워크로 보내거나 장치에 저장해 두면 사람이나 클라우드가 이어서 처리할 수 있다.
- **분류와 이상 감지를 함께 쓰는 이유**: 최종 목표는 자전거 충돌을 감지하는 것이다. 하지만 충돌 데이터를 일부러 만들어 낼 수는 없으므로, 분류(classification)와 이상 감지(anomaly detection) 두 기법을 함께 쓴다.

---

## 2. 클래스 설계 예시

사용 사례에 따라 학습 데이터와 클래스 라벨을 다음과 같이 잡을 수 있다.

| 사용 사례 | 학습 데이터 | 클래스 라벨 |
|---|---|---|
| 자전거 충돌 감지 | 가속도 | 정상, 이상(데이터가 있으면 별도 충돌 라벨) |
| 접근 교통 모니터링 | 카메라(바운딩 박스) | 자동차, 자전거, 오토바이 등 |
| 사각지대 모니터링 | 레이더 | 정상, 근접 물체 |
| 교통 소리 감지 | 오디오 | 배경, 소음, 차량 경보, 충돌음, 경적, 사람 목소리 |

---

## 3. 하드웨어와 데이터 확보

- **장치**: 스마트폰의 Edge Impulse 모바일 클라이언트와 Nordic Semi Thingy:53(nRF Edge Impulse 모바일 앱 사용)을 함께 쓴다.
- **센서 위치**: 보드에 달린 가속도 IMU(관성 측정 장치)나 스마트폰에 들어 있는 IMU를 자전거 앞 핸들바에 고정한다.
- **대안**: 같은 장치가 없으면 공식 지원 보드를 찾아 쓴다. 직접 만든 장치라면 Edge Impulse 데이터 포워더로 데이터를 올려서 실습을 따라갈 수 있다.
- **추가로 쓸 만한 센서**: 자이로스코프, 적외선·야간·열화상 카메라, 레이더, 오디오.
- **데이터 확보 전략**: 공개된 연구 데이터, Kaggle 같은 커뮤니티 데이터를 쓰거나 동료와 함께 수집한다.
- **공개 프로젝트**: 최종 데이터와 모델이 들어 있는 Edge Impulse 공개 프로젝트가 있다. Clone 버튼으로 내 계정에 복제할 수 있다.

---

## 4. 데이터 수집 방법

- **스마트폰**: 가장 쉬운 방법은 휴대폰을 프로젝트에 연결해서 내장 IMU의 가속도 데이터를 기록하는 것이다.
- **Thingy:53**: Edge Impulse 펌웨어를 플래시한 뒤, Edge Impulse CLI나 nRF Edge Impulse 앱(iPhone, Android)으로 프로젝트에 연결한다.
- **앱에서 샘플 기록**: 오른쪽 위 `+` 버튼을 누르고, 센서를 고르고, 라벨을 입력하고, 길이와 주파수를 지정한 다음 Start Sampling을 누른다.
- **주의**: 세 클래스 모두 실제 자전거에서 수집한다. 이때 주변을 잘 살피면서 안전에 신경 쓴다.

---

## 5. 데이터셋 정리와 법적 확인

- **샘플 분할**: 30초(30,000 ms) 샘플을 10초(10,000 ms) 하위 샘플로 나눈다. Split sample 화면에서는 보통 3개가 만들어지고, `+ Add Segment`로 구간을 더 늘릴 수 있다.
- **자르기(Crop sample)**: 샘플 메뉴에서 필요한 구간만 남기고 자를 수 있다.
- **라이선스**: 직접 수집한 데이터는 따로 확인할 것이 없다. 공개된 출처의 가속도 데이터를 섞어 쓴다면 사용 규칙과 출처 표기 조건을 먼저 확인한다.
