# 최적화와 온디바이스 학습

엣지 장치는 비용과 에너지를 줄이려고 설계해서 연산 자원이 작다. 그런데도 실시간 센서 데이터를 빠르게 처리해야 한다. 이 문서는 모델 성능과 자원 사용 사이에서 균형을 맞추는 방법, 그리고 기기 안에서 학습하는 경우를 정리한다.

---

## 1. 성능 대 자원의 균형

- 큰 모델은 용량이 커서 복잡한 작업을 더 잘한다. 하지만 ROM과 RAM을 더 쓰고, 계산 시간이 길어지고, 전력 소모도 커진다(듀티 사이클과 연결된다).
- **핵심 과제**: 과제 성능(task performance)과 계산 성능(computational performance) 사이의 균형을 잡는 일이다. 최소한으로 필요한 과제 성능을 만족하면서, 하드웨어가 정하는 메모리, 지연 시간, 에너지의 한계도 함께 지켜야 한다. 이런 이유로 AutoML 도구도 엣지용으로 다시 설계해야 한다.

---

## 2. 알고리즘 선택으로 줄이기

- 알고리즘마다 메모리와 연산 복잡도의 특성이 다르다. 그래서 대상 하드웨어의 제약에 맞춰서 고른다.
- 보통 고전 ML이 딥러닝보다 작고 효율적이다. 그런데 특징 공학 알고리즘이 둘보다 훨씬 많은 연산을 쓰는 경우가 흔하다. 그럴 때는 고전 ML과 딥러닝 중 무엇을 고르느냐가 덜 중요해진다. 예외는 이미지 데이터다. 특징 공학은 적게 쓰지만 비교적 큰 딥러닝 모델이 필요하다.
- **지연 시간과 메모리를 줄이는 방법**
  - 특징 공학의 복잡도를 낮춘다(연산이 많을수록 지연 시간이 길어진다).
  - AI 알고리즘에 들어가는 데이터 양을 줄인다.
  - 딥러닝 대신 고전 ML을 쓴다.
  - 장치에서 더 효율적으로 돌아가는 쪽으로, 특징 공학과 모델 사이에 복잡도를 나눠 맡긴다.
  - 딥러닝 모델의 크기(가중치와 층의 수)를 줄인다.
  - 선택한 장치의 가속기가 지원하는 모델 유형을 고른다.

---

## 3. 압축과 최적화 기법

| 기법 | 내용 | 손실 여부 |
|---|---|---|
| 양자화(quantization) | 수치 표현의 정밀도를 낮춤. 32비트 부동소수점 가중치를 8비트 정수로 바꾸면 크기가 1/4. 정수 연산은 더 빠르고 이식성이 좋아 FPU가 없는 장치에서도 동작 | 손실(낮은 정밀도로 학습해 보완 가능) |
| 연산자 융합(operator fusion) | 함께 쓰이는 연산자 묶음을 효율적으로 작성된 융합 구현 하나로 대체. 효과는 모델 구조에 크게 좌우됨 | 무손실 |
| 가지치기(pruning) | 학습 중에 많은 가중치를 0으로 만들어 희소(sparse) 모델을 만듦. 현재는 희소 가중치를 활용하는 하드웨어가 거의 없어, 주된 이점은 압축이 쉬워져 무선 업데이트에 유리한 것 | 손실 |
| 지식 증류(knowledge distillation) | 큰 "교사" 모델이 작은 "학생" 모델의 학습을 도와 기능을 재현. 가중치의 중복성을 활용. 까다로워서 아직 일반적이지 않으나 모범 사례가 될 전망 | 손실 |
| 이진 신경망(BNN) | 모든 가중치가 이진 숫자 하나. 이진 연산은 매우 빨라 효율적이지만 비교적 새로운 기술이라 도구가 널리 쓰이지 않음. 양자화와 비슷 | 손실 |
| 스파이킹 신경망(SNN) | 신호가 시간 성분을 갖는 뉴로모픽 신경망. 일부 작업에서 성능과 효율이 좋지만 이점을 얻으려면 가속기가 필요. 직접 학습하거나 기존 딥러닝 모델에서 변환(손실 가능) | 해당 없음 |

- **압축의 두 가지 단점**
  1. 압축한 모델을 실행하려면 특정 소프트웨어나 하드웨어가 필요하다. 그래서 배포할 수 있는 장치가 제한될 수 있다.
  2. 더 위험한 쪽은 손실 압축이 예측 성능을 미묘하게 떨어뜨리는데 이를 알아차리기 어렵다는 점이다. 정밀도가 줄면 흔한 경우에는 잘 맞고, 드문 입력(long tail)에서는 성능이 떨어지는 쪽으로 편향될 수 있다.
- **편향의 증폭**: 소수 집단의 사례가 적은 데이터로 건강 웨어러블 모델을 학습했다고 하자. 압축한 뒤 이 집단의 성능이 떨어져도 전체 정확도에는 거의 드러나지 않을 수 있다. 따라서 데이터셋의 모든 하위 집단별로 성능을 평가하는 것이 매우 중요하다. 책은 Sara Hooker 등의 논문 두 편을 참고 자료로 든다.

## 4. 온디바이스 학습(on-device training)

- 엣지 AI의 머신러닝 모델은 대부분 배포하기 전에 학습한다. 학습에는 레이블이 달린 대량의 데이터가 필요하고, 데이터 포인트 하나당 수백~수천 번의 추론에 해당하는 계산이 든다. 그런데 엣지는 메모리, 연산, 에너지, 연결성의 제약이 심하다.
- **온디바이스 학습이 의미 있는 경우**
  - **예지 정비(predictive maintenance)**: 정상 상태의 데이터로 작은 모델을 기기 안에서 학습하고, 신호가 기준에서 벗어나면 이를 알아차려서 대응한다. 이상 상태가 드물고 기계가 대체로 정상이라고 가정할 수 있어야 한다. 그래야 수집한 데이터에 암묵적으로 "정상"이라는 레이블을 붙일 수 있다.
  - **개인화(personalization)**: 사용자가 일부러 레이블을 제공하는 경우다. 스마트폰의 얼굴 인식 등록이 예다. 임베딩 모델이 원본을 압축된 숫자 표현으로 바꾸는데, 두 임베딩 사이의 유클리드 거리(Euclidean distance)가 유사도에 대응하도록 설계한다. 새 얼굴과 등록된 얼굴 사이의 거리가 충분히 가까우면 같은 얼굴로 본다. 판별 알고리즘은 거리 계산이나 최근접 이웃 정도로 단순해도 된다. 어려운 일은 임베딩 모델이 이미 해 놓았기 때문이다.
  - **암묵적 연관(implicit association)**: 연관 관계에서 레이블이 생기는 경우다. Optimized Battery Charging 같은 기능은 사용자가 기기를 쓸 시각을 예측하는 모델을 기기 안에서 학습한다. 백그라운드에서 사용 로그를 모으고 화면이 켜졌는지 같은 지표로 레이블을 붙이면, 기기 한 대에서도 학습 데이터를 쉽게 만들 수 있다.
- **연합 학습(federated learning)**: 여러 기기에서 프라이버시를 지키면서 분산 학습하는 방식이다. 원본 데이터 대신 부분적으로 학습된 모델을 기기와 중앙 서버 사이에서 주고받는다. 서버는 준비가 되면 이 모델들을 합쳐서 다시 배포한다. 현장에서 계속 좋아지는 것처럼 보이지만 한계가 크다.
  - 연산이 많고 데이터 전송량이 커서, 엣지 AI의 핵심 이점에 역행한다.
  - 학습이 복잡하고 기기 쪽과 서버 쪽 구성 요소가 모두 필요해서 프로젝트 위험이 커진다.
  - 데이터가 한곳에 저장되지 않으므로, 배포된 전체에서 모델이 잘 동작하는지 검증할 수 없다.
  - 기기에서 모델을 올려 보내므로 보안 공격 경로가 될 수 있다.
  - 가장 중요한 점은 레이블 문제를 해결하지 못한다는 것이다. 레이블이 달린 데이터가 없으면 소용이 없다.
- **무선 업데이트(over-the-air, OTA)**: 엄밀히 말하면 기기 안 학습은 아니지만, 현장에 있는 모델을 갱신하는 가장 흔한 방법이다. 현장에서 수집한 데이터로 실험실에서 새 모델을 학습하고, 펌웨어 업데이트로 배포한다. 네트워크 통신에 의존하고 레이블 확보 문제를 풀어 주지도 않는다. 그래도 시간이 지나도 모델을 최신으로 유지하는 가장 일반적인 방법이다.
