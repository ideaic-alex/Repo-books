# 최적화와 온디바이스 학습

엣지 장치는 비용과 에너지를 줄이도록 설계되어 연산 자원이 작지만, 실시간 센서 데이터를 빠르게 처리해야 한다. 이 문서는 모델 성능과 자원 사용 사이의 균형을 맞추는 방법, 그리고 기기 안에서 학습하는 경우를 정리한다.

---

## 1. 성능 대 자원의 균형

- 큰 모델은 용량이 커서 복잡한 작업을 더 잘 하지만, ROM과 RAM을 더 쓰고 계산 시간이 길어지며 전력 소모도 커진다(듀티 사이클과 연결).
- **핵심 과제**: 과제 성능(task performance)과 계산 성능(computational performance)의 균형이다. 최소한의 과제 성능 기준과 하드웨어가 정하는 메모리, 지연, 에너지의 한계를 동시에 만족해야 한다. 이 때문에 AutoML 도구도 엣지용으로 다시 설계해야 한다.

---

## 2. 알고리즘 선택으로 줄이기

- 알고리즘마다 메모리와 연산 복잡도 특성이 다르므로 대상 하드웨어의 제약에 맞춰 고른다.
- 보통 고전 ML이 딥러닝보다 작고 효율적이다. 그러나 특징 공학 알고리즘이 둘보다 훨씬 많은 연산을 쓰는 경우가 흔해서 고전 ML과 딥러닝의 선택은 덜 중요해지기도 한다. 예외는 이미지 데이터로, 특징 공학은 적게 쓰지만 비교적 큰 딥러닝 모델이 필요하다.
- **지연과 메모리를 줄이는 방법**
  - 특징 공학의 복잡도를 낮춘다(연산이 많을수록 지연이 커진다).
  - AI 알고리즘에 도달하는 데이터 양을 줄인다.
  - 딥러닝 대신 고전 ML을 쓴다.
  - 장치에서 더 효율적으로 도는 쪽으로 특징 공학과 모델 사이의 복잡도를 배분한다.
  - 딥러닝 모델의 크기(가중치와 층의 수)를 줄인다.
  - 선택한 장치의 가속기가 지원하는 모델 유형을 고른다.

---

## 3. 압축과 최적화 기법

| 기법 | 내용 | 손실 여부 |
|---|---|---|
| 양자화(quantization) | 수치 표현의 정밀도를 낮춤. 32비트 부동소수점 가중치를 8비트 정수로 바꾸면 크기가 1/4. 정수 연산은 더 빠르고 이식성이 좋아 FPU가 없는 장치에서도 동작 | 손실(낮은 정밀도로 훈련해 보완 가능) |
| 연산자 융합(operator fusion) | 함께 쓰이는 연산자 묶음을 효율적으로 작성된 하나의 융합 구현으로 대체. 효과는 모델 구조에 크게 의존 | 무손실 |
| 가지치기(pruning) | 훈련 중 많은 가중치를 0으로 만들어 희소(sparse) 모델을 만듦. 현재는 희소 가중치를 활용하는 하드웨어가 거의 없어, 주된 이점은 압축이 쉬워져 무선 업데이트에 유리한 것 | 손실 |
| 지식 증류(knowledge distillation) | 큰 "교사" 모델이 작은 "학생" 모델의 훈련을 도와 기능을 재현. 가중치의 중복성을 활용. 까다로워 아직 일반적이지 않으나 모범 사례가 될 전망 | 손실 |
| 이진 신경망(BNN) | 모든 가중치가 이진 숫자 하나. 이진 연산은 매우 빨라 효율적이지만 비교적 새로운 기술이라 도구가 널리 쓰이지 않음. 양자화와 비슷 | 손실 |
| 스파이킹 신경망(SNN) | 신호가 시간 성분을 갖는 뉴로모픽 신경망. 일부 작업에서 성능과 효율이 좋지만 이점을 얻으려면 가속기가 필요. 직접 훈련하거나 기존 딥러닝 모델에서 변환(손실 가능) | 해당 없음 |

- **압축의 두 가지 단점**
  1. 압축된 모델을 실행하려면 특정 소프트웨어나 하드웨어가 필요해 배포 가능한 장치가 제한될 수 있다.
  2. 더 위험한 쪽은, 손실 압축이 예측 성능을 미묘하게 떨어뜨리는데 알아차리기 어렵다는 점이다. 정밀도 감소는 흔한 경우에 잘 맞고 드문 입력(long tail)에서는 성능이 떨어지게 편향시킬 수 있다.
- **편향의 증폭**: 소수 집단의 사례가 적은 데이터로 훈련한 건강 웨어러블의 경우, 압축 후 이 집단의 성능이 떨어져도 전체 정확도에는 거의 드러나지 않을 수 있다. 따라서 데이터셋의 모든 하위 집단별로 성능을 평가하는 것이 매우 중요하다. 책은 Sara Hooker 등의 논문 두 편을 참고 자료로 든다.

## 4. 온디바이스 학습(on-device training)

- 엣지 AI의 머신러닝 모델은 대부분 배포 전에 훈련한다. 훈련에는 레이블이 달린 대량의 데이터와 데이터 포인트당 수백~수천 번의 추론에 해당하는 계산이 필요한데, 엣지는 메모리, 연산, 에너지, 연결성의 제약이 심하다.
- **기기 안 훈련이 의미 있는 경우**
  - **예지 정비(predictive maintenance)**: 정상 상태의 데이터로 작은 모델을 기기 안에서 훈련하고, 신호가 기준에서 벗어나면 알아차려 대응한다. 이상 상태가 드물고 기계가 대체로 정상이라고 가정할 수 있어야 하며, 그래야 수집 데이터에 암묵적인 "정상" 레이블을 붙일 수 있다.
  - **개인화(personalization)**: 사용자가 의도적으로 레이블을 제공하는 경우다. 스마트폰 얼굴 인식 등록이 예다. 임베딩 모델이 원본을 압축된 숫자 표현으로 바꾸고, 두 임베딩 사이의 유클리드 거리(Euclidean distance)가 유사도에 대응하도록 설계한다. 새 얼굴과 등록된 얼굴의 거리가 충분히 가까우면 같은 얼굴로 본다. 판별 알고리즘은 거리 계산이나 최근접 이웃 정도로 단순해도 되며, 어려운 일은 임베딩 모델이 이미 한 것이다.
  - **암묵적 연관(implicit association)**: 연관에 의해 레이블이 생기는 경우다. Optimized Battery Charging 같은 기능은 사용자가 기기를 쓸 시각을 예측하는 모델을 기기 안에서 훈련한다. 배경에서 사용 로그를 모으고 화면이 켜졌는지 같은 지표로 레이블을 붙이면 단일 기기에서도 쉽게 훈련 데이터를 만들 수 있다.
- **연합 학습(federated learning)**: 여러 기기에서 프라이버시를 지키며 분산 훈련하는 방식이다. 원본 데이터 대신 부분적으로 훈련된 모델을 기기와 중앙 서버 사이에서 주고받고, 준비되면 합쳐서 다시 배포한다. 현장에서 계속 개선되는 것처럼 보이지만 한계가 크다.
  - 연산이 많고 데이터 전송량이 커서 엣지 AI의 핵심 이점에 역행한다.
  - 훈련이 복잡하고 기기와 서버 구성 요소가 모두 필요해 프로젝트 위험이 커진다.
  - 데이터가 전역으로 저장되지 않아 배포 전체에서 모델이 잘 동작하는지 검증할 수 없다.
  - 기기에서 모델을 올리므로 보안 공격 경로가 될 수 있다.
  - 가장 중요하게, 레이블 문제를 해결하지 못한다. 레이블 데이터가 없으면 소용이 없다.
- **무선 업데이트(over-the-air, OTA)**: 엄밀히는 기기 안 훈련이 아니지만 현장의 모델을 갱신하는 가장 흔한 방법이다. 현장에서 수집한 데이터로 실험실에서 새 모델을 훈련하고 펌웨어 업데이트로 배포한다. 네트워크 통신에 의존하고 레이블 확보 문제를 풀지는 못하지만, 시간이 지나도 모델을 최신으로 유지하는 가장 일반적인 방법이다.
