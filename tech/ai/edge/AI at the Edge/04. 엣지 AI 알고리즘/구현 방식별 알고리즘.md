# 구현 방식별 알고리즘

같은 기능이라도 구현 방법은 수없이 많고, 엣지 하드웨어의 제약 때문에 각각의 장단점이 두드러진다. 이 문서는 조건문과 휴리스틱, 고전 머신러닝, 딥러닝 순서로 정리한다.

---

## 1. 조건문과 휴리스틱

- **조건문 기반 알고리즘**: 가장 단순한 AI로, `if` 문으로 결정을 내린다. 책의 예는 속도와 벽까지의 거리로 충돌까지 남은 시간을 계산해, 정지에 필요한 시간과 안전 여유를 넘지 않으면 브레이크를 거는 코드다.
- **이것도 AI인가**: 책은 단호히 그렇다고 답한다. 공학적 정의로 AI는 보통 인간의 지능이 필요한 일을 컴퓨터가 하게 하는 것이다. 결정 트리(decision tree)도 속을 보면 `if` 문이고, 이진 신경망도 본질은 조건 논리다. 지능은 구현이 아니라 응용에서 나온다.
- **휴리스틱(heuristic)**: 도메인 지식으로 사람이 만든 규칙이다. 단순한 상수 하나에도 많은 연구와 실험의 결과가 담겨 있을 수 있다. 신호 처리와 결합하면 꽤 정교해진다. 예를 들어 기계 소리를 푸리에 변환한 뒤, 고장 직전의 특징적인 고음이 나타나는지 `if` 문으로 판단해 알릴 수 있다.
- **장점**: 이해, 디버깅, 테스트가 쉽다. 모든 경로를 자동화 테스트로 검증할 수 있어 정의되지 않은 동작이 없고, 매우 빠르며 어떤 장치에서도 돌아간다.
- **단점 두 가지**
  - 도메인 지식과 효율적인 코드를 짜는 전문성이 필요하다.
  - **조합 폭발(combinatorial explosion)**: 변수가 많을수록 고전적 알고리즘으로 모델링하기 어렵다. 체스가 예이고, 이미지가 오렌지인지 바나나인지 손으로 규칙을 짜는 것은 단순한 장면을 넘어서면 사실상 불가능하다.
- **경험칙**: 다뤄야 할 데이터 값이 많을수록 손으로 짠 로직으로 만족스러운 해법을 얻기 어렵다.

## 2. 고전 머신러닝(classical machine learning)

- **기본 개념**: 휴리스틱이 알려진 규칙을 사람이 코딩하는 것이라면, 머신러닝은 알고리즘이 많은 데이터를 보고 규칙을 스스로 찾는다. 데이터로 **훈련(training)**해 **모델(model)**을 만들고, 모델에 데이터를 넣어 예측하는 과정이 **추론(inference)**이다.
- 앞서 본 모든 기능 유형을 수행할 수 있다. 필수 조건은 **데이터셋(dataset)**, 즉 실제 조건에서 모은 대규모 데이터다. 크고 다양한 데이터셋이 엣지 AI에서 특히 중요하다.
- 훈련은 계산량이 크고 데이터도 필요하므로 보통 배포 전에 하고 엣지에서는 추론만 한다. 기기 안 훈련도 가능하지만 데이터와 연산이 부족해 어렵다.
- **학습 방식**
  - **지도 학습(supervised)**: 전문가가 레이블을 붙인 데이터셋을 쓴다.
  - **비지도 학습(unsupervised)**: 사람 도움 없이 데이터의 구조를 찾는다.
- **주요 약점**: 입력이 훈련 데이터와 크게 다른 **분포 이탈(out-of-distribution)**일 때 쓸모없는 출력을 낸다. 출력만으로는 이를 알 수 없어 항상 위험이 있으므로, 이 문제를 피하는 것이 핵심 과제다.
- **해석 가능성(interpretability, explainability)**: 모델이 왜 그런 예측을 했는지 사람이 이해할 수 있는 성질이다. 의료 진단 보조처럼 중요한 경우도 있고, 해석 가능한 알고리즘은 디버깅도 쉽다.

| 알고리즘 | 학습 방식 | 특징 |
|---|---|---|
| 회귀 분석(regression analysis) | 지도 | 연속값 예측. 훈련 쉽고 빠르며 해석이 쉬우나 단순한 시스템만 학습 |
| 로지스틱 회귀(logistic regression) | 지도 | 범주 출력용 회귀. 비교적 단순한 시스템용 |
| 서포트 벡터 머신(SVM) | 지도 | 복잡한 관계 학습, 빠르지만 훈련이 어렵고 해석이 어려움 |
| 결정 트리와 랜덤 포레스트 | 지도 | `if` 문들을 만들어 예측. 해석이 쉽고 복잡한 시스템도 학습하나 데이터가 많이 필요할 수 있음 |
| 칼만 필터(Kalman filter) | 지도 | 측정 이력으로 다음 값 예측. 기기 안 훈련도 가능, 단순한 시스템만 모델링 |
| 최근접 이웃(nearest neighbors) | 비지도 | 알려진 데이터와의 유사도로 분류. 데이터가 많으면 느림 |
| 군집화(clustering) | 비지도 | 레이블 없이 유사도로 묶음. 기기 안 훈련 가능 |

- **장점**: 효율과 유연성의 범위가 넓고, 설명이 쉬우며, 데이터 요구량이 낮은 것도 있다.
- **단점**: 알고리즘이 수백 가지라 탐색이 어렵고, scikit-learn으로 쉽게 시험할 수 있어도 튜닝에 기술이 필요하다. MCU용 오픈소스 구현이 적어 직접 구현해야 할 수 있다. 모델링할 수 있는 복잡도에 상대적으로 낮은 한계가 있어 대개 무거운 특징 공학이 필요하고, 이미지 분류 같은 작업은 잘 못한다.

## 3. 딥러닝(deep learning)

- **정의**: 신경망 중심의 머신러닝이다. 원리는 같다. 데이터셋으로 모델을 훈련하고 기기에서 추론한다. 모델은 알고리즘과 **가중치(weight, parameter)**라는 숫자 모음이며 가중치는 훈련으로 생성된다.
- 책은 엔지니어링 관점에 집중하며, 내부 수학을 몰라도 현대 도구로 배포할 수 있다고 본다.
- **강점**: 범용 함수 근사기(universal function approximator)로서 거의 모든 입출력 관계를 모델링할 수 있다. 훈련 중 스스로 특징 공학을 배울 수 있어 개발자 부담이 줄지만, 특징 공학이 쓸모없어지는 것은 아니다. 파라미터가 많아 유연한 만큼 대량 데이터도 활용한다.
- **약점 두 가지**
  - 많은 파라미터의 최적값을 찾으려면 데이터가 많이 필요한데 데이터는 구하기 어렵고 비싸다.
  - **과적합(overfitting)**: 데이터셋을 지나치게 잘 학습해 일반 규칙이 아니라 데이터 자체를 외워 버리면 새 데이터에서 성능이 떨어진다. 파라미터가 많은 딥러닝에서 특히 위험하다.

### 주요 모델 유형

- **완전 연결 모델(fully connected)**: 뉴런 층을 쌓은 가장 단순한 구조. 입력을 긴 숫자열로 받아 공간 관계에 둔감하다. 시계열 통계값 같은 이산 특징에는 좋고 원본 시계열이나 이미지에는 덜 좋다. 임베디드 지원이 매우 좋다.
- **합성곱 모델(convolutional)**: 입력의 공간 정보를 활용한다. 이미지의 형태나 시계열의 구조를 학습하며 임베디드 지원도 매우 좋다.
- **시퀀스 모델(sequence)**: 시계열과 언어 같은 순서 데이터용이며 내부 기억을 가진다. 합성곱 모델을 대체할 것으로 보는 사람이 많지만 임베디드 지원은 아직 부족하다(기술보다는 관성의 문제).
- **임베딩 모델(embedding)**: 크고 지저분한 입력을 맥락에 맞는 작은 숫자 집합으로 줄이는 사전 훈련된 모델로, 다른 ML 모델이 해석할 특징을 만든다. 주 용도는 **전이 학습(transfer learning)**이며 합성곱 계열이 가장 흔하다.
- **모델 아키텍처**: 층(layer)과 연산(op)의 조합 방식이다. 엣지용으로 MobileNet과 EfficientNet(모바일 효율), YOLO(객체 검출), 트랜스포머(시퀀스 변환)가 언급된다.
- 모델 크기는 작은 모델이 몇 KB, 오디오 분류나 객체 검출 같은 작업은 최소 수십~수백 KB가 일반적이다. 서버용 모델이 수십 MB에서 수 TB인 것과 대비된다.

### 임베디드에서 딥러닝 실행하기

- **인터프리터(interpreter)**: TensorFlow Lite for Microcontrollers 같은 도구. 파일로 저장된 모델을 실행하며 유연하고 쉽지만 연산·메모리 오버헤드가 있고 모든 모델을 지원하지 않는다.
- **코드 생성(code generation)**: EON 같은 도구. 모델을 최적화된 소스 코드로 변환한다. 인터프리터보다 효율적이고 읽을 수 있어 디버깅도 되지만 지원 모델이 제한적이다.
- **컴파일러(compiler)**: microTVM 같은 도구. 최적화된 바이트코드를 생성한다. 효율이 높고 지원 모델이 넓지만 디버깅과 유지보수가 어렵다.
- **직접 코딩(handcoding)**: 훈련된 모델의 파라미터로 손수 구현한다. 어렵고 오래 걸리지만 최적화를 완전히 통제하고 어떤 모델이든 지원한다.
- **SoC와 MCU의 차이**: SoC는 정식 OS가 있어 서버용 도구 대부분이 통하므로 거의 모든 모델이 돌아가며, 지연만 아키텍처에 따라 달라진다. TensorFlow Lite 같은 SoC용 인터프리터는 GPU 등을 활용한다. 가속기가 있는 SoC는 벤더의 전용 컴파일러·인터프리터를 쓰며, 가속기는 일부 연산만 빠르게 하므로 모델 구조에 따라 효과가 다르다. MCU는 OS가 없어 표준 도구를 못 쓰고 TensorFlow Lite for Microcontrollers 같은 프레임워크에 의존하며, 연산자(operator) 지원이 다소 뒤처져 일부 모델은 못 돌린다. 고사양 MCU의 SIMD를 활용한 최적화 연산자 구현도 제공된다.
- **연산자(operator)와 커널(kernel)**: 엣지 ML에서는 딥러닝 실행에 쓰이는 특정 수학 연산의 구현을 뜻한다. 다른 분야에서는 의미가 다를 수 있다.

## 4. 딥러닝 대 고전 머신러닝

- 딥러닝의 핵심 이점은 유연성, 줄어드는 특징 공학, 많은 데이터를 활용하는 능력이다. 단점은 높은 데이터 요구량, 과적합 경향, 큰 크기와 연산량, 복잡한 훈련, 낮은 해석 가능성이다.
- **고전 ML이 더 나을 수 있는 경우**
  - **설명 가능성**: 결정 트리가 가장 뛰어나다.
  - **효율**: 연산이 훨씬 쉽다.
  - **이식성**: 저사양 MCU 같은 가장 기본적인 장치에도 배포할 수 있다.
  - **효과**: 데이터가 적을 때는 더 잘 동작하는 알고리즘이 있다.
  - **기기 안 훈련**: 현장에서 쉽게 훈련되는 것이 있다.
- 상황에 달린 문제이지만, 한 가지 기법만 깊이 파야 한다면 딥러닝이 합리적이라는 것이 책의 의견이다.
