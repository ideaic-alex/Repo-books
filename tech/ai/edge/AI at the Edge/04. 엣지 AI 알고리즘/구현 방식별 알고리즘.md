# 구현 방식별 알고리즘

같은 기능이라도 구현 방법은 수없이 많다. 엣지 하드웨어에는 제약이 많아서 방법마다 장단점이 뚜렷하게 드러난다. 이 문서는 조건문과 휴리스틱, 고전 머신러닝, 딥러닝 순서로 정리한다.

---

## 1. 조건문과 휴리스틱

- **조건문 기반 알고리즘**: 가장 단순한 AI로, `if` 문으로 결정을 내린다. 책의 예는 속도와 벽까지의 거리로 충돌까지 남은 시간을 계산하는 코드다. 이 시간이 정지에 필요한 시간과 안전 여유를 합친 값을 넘지 않으면 브레이크를 건다.
- **이것도 AI인가**: 책은 단호하게 그렇다고 답한다. 공학에서 AI는 보통 사람의 지능이 필요한 일을 컴퓨터가 하게 만드는 것을 뜻한다. 결정 트리(decision tree)도 속을 들여다보면 `if` 문이고, 이진 신경망도 본질은 조건 논리다. 지능은 구현 방식이 아니라 어떻게 응용하느냐에서 나온다.
- **휴리스틱(heuristic)**: 도메인 지식을 바탕으로 사람이 만든 규칙이다. 상수 하나에도 많은 연구와 실험의 결과가 담겨 있을 수 있다. 신호 처리와 결합하면 꽤 정교한 일도 할 수 있다. 예를 들어 기계 소리를 푸리에 변환한 뒤, 고장 직전에 나타나는 특징적인 고음이 있는지 `if` 문으로 판단해서 알릴 수 있다.
- **장점**: 이해하고, 디버깅하고, 테스트하기 쉽다. 모든 경로를 자동화 테스트로 검증할 수 있어서 정의되지 않은 동작이 없다. 또 매우 빠르고 어떤 장치에서도 돌아간다.
- **단점 두 가지**
  - 도메인 지식과, 효율적인 코드를 짜는 전문성이 필요하다.
  - **조합 폭발(combinatorial explosion)**: 변수가 많을수록 고전적인 알고리즘으로 모델링하기 어렵다. 체스가 대표적인 예다. 이미지가 오렌지인지 바나나인지 규칙을 손으로 짜는 일도, 단순한 장면을 넘어서면 사실상 불가능하다.
- **경험칙**: 다뤄야 할 데이터 값이 많을수록, 손으로 짠 로직으로는 만족스러운 해법을 얻기 어렵다.

## 2. 고전 머신러닝(classical machine learning)

- **기본 개념**: 휴리스틱은 이미 아는 규칙을 사람이 코드로 옮기는 방식이다. 반면 머신러닝은 알고리즘이 많은 데이터를 보고 규칙을 스스로 찾는다. 데이터로 **학습(training)**해서 **모델(model)**을 만들고, 모델에 데이터를 넣어 예측하는 과정을 **추론(inference)**이라고 한다.
- 앞에서 본 모든 기능 유형을 수행할 수 있다. 꼭 필요한 것은 **데이터셋(dataset)**, 즉 실제 사용 조건에서 모은 대규모 데이터다. 크고 다양한 데이터셋은 엣지 AI에서 특히 중요하다.
- 학습은 계산량이 크고 데이터도 많이 필요하다. 그래서 보통 배포하기 전에 학습하고, 엣지에서는 추론만 한다. 기기 안에서 학습하는 것도 가능하지만, 데이터와 연산 자원이 부족해서 어렵다.
- **학습 방식**
  - **지도 학습(supervised)**: 전문가가 레이블을 붙여 둔 데이터셋을 쓴다.
  - **비지도 학습(unsupervised)**: 사람의 도움 없이 데이터의 구조를 찾는다.
- **주요 약점**: 입력이 학습 데이터와 크게 다른 **분포 이탈(out-of-distribution)**일 때 쓸모없는 결과를 낸다. 출력만 봐서는 이 상황을 알 수 없으므로 항상 위험이 있다. 이 문제를 피하는 것이 핵심 과제다.
- **해석 가능성(interpretability, explainability)**: 모델이 왜 그런 예측을 했는지 사람이 이해할 수 있는 성질이다. 의료 진단 보조처럼 꼭 필요한 경우도 있고, 해석 가능한 알고리즘은 디버깅도 쉽다.

| 알고리즘 | 학습 방식 | 특징 |
|---|---|---|
| 회귀 분석(regression analysis) | 지도 | 연속값 예측. 학습이 쉽고 빠르며 해석이 쉬우나 단순한 시스템만 학습 |
| 로지스틱 회귀(logistic regression) | 지도 | 범주 출력용 회귀. 비교적 단순한 시스템용 |
| 서포트 벡터 머신(SVM) | 지도 | 복잡한 관계 학습, 빠르지만 학습이 어렵고 해석이 어려움 |
| 결정 트리와 랜덤 포레스트 | 지도 | `if` 문들을 만들어 예측. 해석이 쉽고 복잡한 시스템도 학습하나 데이터가 많이 필요할 수 있음 |
| 칼만 필터(Kalman filter) | 지도 | 측정 이력으로 다음 값 예측. 기기 안 학습도 가능, 단순한 시스템만 모델링 |
| 최근접 이웃(nearest neighbors) | 비지도 | 알려진 데이터와의 유사도로 분류. 데이터가 많으면 느림 |
| 군집화(clustering) | 비지도 | 레이블 없이 유사도로 묶음. 기기 안 학습 가능 |

- **장점**: 효율과 유연성의 폭이 넓고, 설명하기 쉬우며, 필요한 데이터가 적은 것도 있다.
- **단점**: 알고리즘이 수백 가지라서 고르기 어렵다. scikit-learn으로 쉽게 시험해 볼 수는 있지만 튜닝에는 기술이 필요하다. MCU용 오픈소스 구현이 적어서 직접 구현해야 할 수도 있다. 모델링할 수 있는 복잡도에 상대적으로 낮은 한계가 있어서 대개 특징 공학을 많이 해야 하고, 이미지 분류 같은 작업은 잘 못한다.

## 3. 딥러닝(deep learning)

- **정의**: 신경망 중심의 머신러닝이다. 기본 원리는 같다. 데이터셋으로 모델을 학습하고 기기에서 추론한다. 모델은 알고리즘과 **가중치(weight, parameter)**라는 숫자 모음으로 이루어지며, 가중치는 학습으로 만들어진다.
- 책은 엔지니어링 관점에 집중한다. 내부 수학을 몰라도 요즘 도구로 배포할 수 있다고 본다.
- **강점**: 범용 함수 근사기(universal function approximator)여서 거의 모든 입출력 관계를 모델링할 수 있다. 학습하는 동안 특징 공학을 스스로 익힐 수 있어서 개발자의 부담이 줄지만, 특징 공학이 쓸모없어지는 것은 아니다. 파라미터가 많아서 유연한 만큼, 대량의 데이터도 활용할 수 있다.
- **약점 두 가지**
  - 많은 파라미터의 최적값을 찾으려면 데이터가 많이 필요한데, 데이터는 구하기 어렵고 비싸다.
  - **과적합(overfitting)**: 데이터셋을 지나치게 잘 학습해서, 일반적인 규칙이 아니라 데이터 자체를 외워 버리는 현상이다. 이렇게 되면 새 데이터에서 성능이 떨어진다. 파라미터가 많은 딥러닝에서 특히 위험하다.

### 주요 모델 유형

- **완전 연결 모델(fully connected)**: 뉴런 층을 쌓은 가장 단순한 구조다. 입력을 긴 숫자열로 받기 때문에 공간 관계를 잘 구분하지 못한다. 시계열의 통계값처럼 따로 떨어진 특징에는 좋고, 원본 시계열이나 이미지에는 덜 좋다. 임베디드 지원은 매우 좋다.
- **합성곱 모델(convolutional)**: 입력의 공간 정보를 활용한다. 이미지의 형태나 시계열의 구조를 학습하며, 임베디드 지원도 매우 좋다.
- **시퀀스 모델(sequence)**: 시계열이나 언어처럼 순서가 있는 데이터용이며, 내부에 기억을 가진다. 합성곱 모델을 대체할 것으로 보는 사람이 많지만 임베디드 지원은 아직 부족하다(기술이 모자라서라기보다 관성 때문이다).
- **임베딩 모델(embedding)**: 크고 지저분한 입력을 맥락에 맞는 작은 숫자 집합으로 줄여 주는, 사전 학습된 모델이다. 이렇게 나온 숫자 집합은 다른 ML 모델이 해석할 특징이 된다. 주된 용도는 **전이 학습(transfer learning)**이며 합성곱 계열이 가장 흔하다.
- **모델 아키텍처**: 층(layer)과 연산(op)을 조합하는 방식이다. 엣지용으로는 MobileNet과 EfficientNet(모바일에서 효율적), YOLO(객체 검출), 트랜스포머(시퀀스 변환)가 언급된다.
- 모델 크기는 작은 모델이 몇 KB이고, 오디오 분류나 객체 검출 같은 작업은 최소 수십~수백 KB가 일반적이다. 서버용 모델이 수십 MB에서 수 TB에 이르는 것과 대조적이다.

### 임베디드에서 딥러닝 실행하기

- **인터프리터(interpreter)**: TensorFlow Lite for Microcontrollers 같은 도구다. 파일로 저장된 모델을 읽어서 실행한다. 유연하고 쉽지만 연산과 메모리 오버헤드가 있고, 모든 모델을 지원하지는 않는다.
- **코드 생성(code generation)**: EON 같은 도구다. 모델을 최적화된 소스 코드로 변환한다. 인터프리터보다 효율적이고 코드를 읽을 수 있어서 디버깅도 할 수 있지만, 지원하는 모델이 제한적이다.
- **컴파일러(compiler)**: microTVM 같은 도구다. 최적화된 바이트코드를 생성한다. 효율이 높고 지원하는 모델도 넓지만, 디버깅과 유지보수가 어렵다.
- **직접 코딩(handcoding)**: 학습이 끝난 모델의 파라미터를 가지고 직접 구현한다. 어렵고 오래 걸리지만 최적화를 완전히 통제할 수 있고, 어떤 모델이든 지원한다.
- **SoC와 MCU의 차이**: SoC에는 정식 OS가 있어서 서버용 도구 대부분이 통한다. 그래서 거의 모든 모델이 돌아가고, 아키텍처에 따라 달라지는 것은 지연 시간뿐이다. TensorFlow Lite 같은 SoC용 인터프리터는 GPU 등을 활용한다. 가속기가 있는 SoC는 벤더의 전용 컴파일러나 인터프리터를 쓴다. 가속기는 일부 연산만 빠르게 해 주므로, 모델 구조에 따라 효과가 다르다. MCU에는 OS가 없어서 표준 도구를 쓸 수 없고, TensorFlow Lite for Microcontrollers 같은 프레임워크에 의존한다. 이 프레임워크는 연산자(operator) 지원이 다소 뒤처져 있어서 일부 모델은 돌릴 수 없다. 사양이 높은 MCU에서는 SIMD를 활용한 최적화 연산자 구현도 제공된다.
- **연산자(operator)와 커널(kernel)**: 엣지 ML에서는 딥러닝을 실행할 때 쓰는 특정 수학 연산의 구현을 가리킨다. 다른 분야에서는 뜻이 다를 수 있다.

---

## 4. 딥러닝 대 고전 머신러닝

- 딥러닝의 핵심 이점은 유연성, 줄어드는 특징 공학, 많은 데이터를 활용하는 능력이다. 단점은 데이터가 많이 필요하고, 과적합되기 쉽고, 크기와 연산량이 크고, 학습이 복잡하고, 해석하기 어렵다는 것이다.
- **고전 ML이 더 나을 수 있는 경우**
  - **설명 가능성**: 결정 트리가 가장 뛰어나다.
  - **효율**: 연산이 훨씬 쉽다.
  - **이식성**: 저사양 MCU 같은 가장 기본적인 장치에도 배포할 수 있다.
  - **효과**: 데이터가 적을 때는 더 잘 동작하는 알고리즘이 있다.
  - **온디바이스 학습**: 현장에서 쉽게 학습할 수 있는 알고리즘이 있다.
- 상황에 따라 다르지만, 한 가지 기법만 깊이 파야 한다면 딥러닝이 합리적이라는 것이 책의 의견이다.
