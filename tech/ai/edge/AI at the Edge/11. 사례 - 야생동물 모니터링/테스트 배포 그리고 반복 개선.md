# 테스트, 배포 그리고 반복 개선

학습한 모델은 Edge Impulse의 테스트 도구로 검증하고, 상황에 맞는 배포 방식으로 기기에 올린다. 이후 클래스와 센서를 바꾸며 개선하는 방법, Lacuna Space 새소리 데모, 참고 자료까지 정리한다.

---

## 1. 모델 테스트

- **Live classification**: 테스트 샘플 하나를 모델에 넣어 보거나, 기기를 연결해 새 이미지를 실시간으로 찍어 특징과 분류 결과를 본다. 공식 지원 기기는 펌웨어나 CLI로 연결하며, 예로 Arduino Nano 33 BLE Sense는 `edge-impulse-daemon`을 실행해 프롬프트를 따른다.
- **Model testing**: Classify all로 테스트 데이터셋 전체를 한 번에 분류해 표로 본다.
- **신뢰도 임계값(confidence threshold)**: Set confidence thresholds로 정하며, 이 값보다 낮으면 샘플이 uncertain으로 표시된다. uncertain 샘플을 라벨링해 재학습·재배포하면 액티브 러닝이 된다.
- **성능 보정(performance calibration)**: 오디오 트랩을 만들었다면 이 기능으로 실환경 성능을 조정할 수 있다.
- **로컬 테스트**: Dashboard에서 블록 출력과 학습된 모델 정보를 내려받아 TensorFlow/Keras 방식의 파이썬 스크립트로 직접 시험할 수 있다.

---

## 2. 배포 옵션

- **라이브러리 생성(Create library)**: 비지원 플랫폼 대부분이 쓰는 방식이다. C++ 라이브러리는 외부 의존성이 없고 최신 C++ 컴파일러면 빌드된다. 커스텀 DSP 블록을 썼다면 같은 C++ 구현을 SDK에 통합해야 한다.
- **휴대폰·컴퓨터**: 오픈 소스 모바일 클라이언트가 WebAssembly 라이브러리를 만들어 기기 카메라로 바로 분류한다. Build 후 QR 코드를 휴대폰으로 스캔해 브라우저에서 열고 카메라 권한을 주면 되며, 코드가 필요 없어 빠른 프로토타입에 좋다.
- **사전 빌드 바이너리 플래싱**: 공식 지원 보드를 골라 Build 후 펌웨어를 끌어다 놓거나 플래시한다. EON Compiler를 쓰면 TensorFlow Lite for Microcontrollers 대비 RAM 25~55%, 플래시 최대 35%를 줄이면서 정확도는 같다.
- **OpenMV 배포(이 장의 선택)**: OpenMV Cam H7 Plus에서 실행한다.
- **Impulse runner**: Edge Impulse CLI로 USB 시리얼을 통해 지속 실행하거나, Linux runner로 Raspberry Pi 4 같은 Linux 기기에서 실행한다.

```
labels.txt, trained.tflite  ->  OpenMV Cam 파일시스템에 복사
ei_image_classification.py  ->  OpenMV IDE에서 실행
```

- **OpenMV 절차**: 소프트웨어 사전 요건을 설치하고 ZIP을 풀어 위 두 파일을 보드에 복사한 뒤, IDE에서 스크립트를 실행해 시리얼 터미널로 추론 결과를 확인한다.

## 3. 반복 개선

- **클래스 확장**: 다른 동물을 추가한다.
- **대상 변경**: 정원 가꾸기나 채집 용도의 침입 식물 트랩.
- **다른 센서**: 가스 센서 트랩, 또는 이미지 분류를 바운딩 박스 기반 객체 탐지로 전환.
- **재사용**: 같은 모델로 다른 목표나 환경에 쓰면서 unknown 클래스를 다듬는다.
- **센서 융합**: 카메라+오디오, 오디오+가스 등 여러 센서를 결합해 정확도를 높인다.
- **여러 프로젝트**: 기기 위치·데이터셋·대상 동물마다 별도 프로젝트를 만들고, 주 대상 종만 바꿔 같은 구성으로 재학습·재배포할 수 있다.

---

## 4. 심화: Lacuna Space 새소리 분류

- **구성**: Edge Impulse와 Lacuna Space가 만든 데모로, 새소리를 분류해 결과를 위성과 LoRaWAN으로 보내고 The Things Network 애플리케이션에서 확인한다. 웹 트래커로 위성이 지나는 시간을 알 수 있다.
- **출력 형태**: 종별 확률(예: housesparrow 0.91)과 noise 확률, 위성 수신 여부가 JSON으로 온다.
- **한계**: 일반적인 분류 결과만 받고 개체의 정확한 위치나 계수·추적 데이터는 얻지 못한다. 따라서 종 단위 추적, 이동 패턴, 계절별 식별에 적합하고 남획 방지나 침입 위협 영향 분석에는 덜 맞는다.

- **연구 문헌**: 카메라 트랩의 성능, 종류와 필요 대수, 조류 연구 활용, 위치 불변 동물 탐지 등을 다룬 논문과 도서가 장 끝에 정리되어 있다.
