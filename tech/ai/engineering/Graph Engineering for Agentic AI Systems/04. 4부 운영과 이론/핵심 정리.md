# 핵심 정리

이 문서는 4부(9장, 10장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 도구, 버전, 수치는 책이 쓴 시점(2026년경) 기준이며 노트가 검증하지 않았다.

---

## 1. 한눈에 보는 요점

- **프로덕션 버그는 대부분 모델이 아니다**: 상태, 리듀서, 재개, 예산, 버전에서 나온다.
  - *쉽게 말하면*: 요리가 두 번 나갔다면 요리사보다 주문서 관리를 의심하라.
  - → 자세히: [9장 프로덕션에서 그래프 운영하기](09%EC%9E%A5%20%ED%94%84%EB%A1%9C%EB%8D%95%EC%85%98%EC%97%90%EC%84%9C%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0.md)
- **재개는 노드를 처음부터 다시 돌린다**: 인터럽트 앞에는 멱등 연산만, 효과는 뒤의 별도 노드에 둔다. 재생은 효과가 나는 포크다.
  - *쉽게 말하면*: 승인 대기 중에 이미 결제해 두면, 승인할 때마다 또 결제된다.
  - → 자세히: [9장 프로덕션에서 그래프 운영하기](09%EC%9E%A5%20%ED%94%84%EB%A1%9C%EB%8D%95%EC%85%98%EC%97%90%EC%84%9C%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0.md)
- **사람 개입은 제품이다**: 안정된 페이로드, 기한, 해시 검사, 노드당 인터럽트 하나. 게이트는 되돌리기 비싼 곳에만 둔다.
  - *쉽게 말하면*: 모든 서류에 도장을 받으면 도장이 의미를 잃는다.
  - → 자세히: [9장 프로덕션에서 그래프 운영하기](09%EC%9E%A5%20%ED%94%84%EB%A1%9C%EB%8D%95%EC%85%98%EC%97%90%EC%84%9C%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0.md)
- **배포는 진행 중 스레드에 대한 마이그레이션이다**: `flow_version`을 찍고, 멈춰 있는 노드의 이름은 지우지 않는다. 권한은 노드 단위로 묶는다.
  - *쉽게 말하면*: 공사 중에도 이미 입장한 손님의 좌석은 그대로 둔다.
  - → 자세히: [9장 프로덕션에서 그래프 운영하기](09%EC%9E%A5%20%ED%94%84%EB%A1%9C%EB%8D%95%EC%85%98%EC%97%90%EC%84%9C%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EC%9A%B4%EC%98%81%ED%95%98%EA%B8%B0.md)
- **위상은 새롭지 않다**: DAG, 상태 기계, 페트리 넷, 워크플로 엔진, 액터, Pregel의 수학을 가져다 쓰면 된다.
  - *쉽게 말하면*: 레시피, 신호등, 금고는 이미 있다. 모아서 쓰면 된다.
  - → 자세히: [10장 에이전트 그래프의 컴퓨터 과학](10%EC%9E%A5%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%98%20%EC%BB%B4%ED%93%A8%ED%84%B0%20%EA%B3%BC%ED%95%99.md)
- **새로운 것은 세 가지다**: 모델이 엣지를 고르고, 실행 중 그래프가 바뀌고, 성공과 실패가 이진이 아니다.
  - *쉽게 말하면*: 일꾼이 가끔 딴소리를 한다는 것만 달라졌다.
  - → 자세히: [10장 에이전트 그래프의 컴퓨터 과학](10%EC%9E%A5%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%98%20%EC%BB%B4%ED%93%A8%ED%84%B0%20%EA%B3%BC%ED%95%99.md)
- **비결정성은 재생 가능한 상자에 가둔다**: 돌이킬 수 없는 일은 정적 엣지, 라우팅은 코드, 모델 라우터는 선언된 목록 안에서만.
  - *쉽게 말하면*: 모델이 고르게 하되 고를 수 있는 메뉴는 우리가 정한다.
  - → 자세히: [10장 에이전트 그래프의 컴퓨터 과학](10%EC%9E%A5%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%98%20%EC%BB%B4%ED%93%A8%ED%84%B0%20%EA%B3%BC%ED%95%99.md)

## 2. 4부를 관통하는 질문

| 질문 | 4부가 보여 주는 답 |
|------|-------------------|
| 그래프가 이상하게 행동하면 어디부터 보나? | 리듀서와 상태 스키마부터. 모델 탓은 마지막에 |
| 재시도해도 안전한 조건은? | 노드가 멱등할 때. 효과는 키와 기록으로 한 번만 |
| 팬아웃 합류에서 무엇을 정해야 하나? | 모두 기다릴지, 하나만 기다릴지(AND와 XOR) |
| 선언한 그래프와 실제 그래프가 다르면? | 트레이스와 조인해 관측하고, 도달 가능성과 순환을 양쪽에 검사 |
| 어떤 고전 정리가 더는 보장되지 않나? | 재시도 안전성, 발화 원자성, 데이터플로 결정성 |

---

> **4부 한 줄 요약**
> 그래프 운영은 상태와 재개와 버전을 다루는 일이고, 그 기반은 오래된 컴퓨터 과학이며, 확률적 노드가 만든 틈은 허용 목록, 멱등성, 재생 가능한 기록으로 메운다.
