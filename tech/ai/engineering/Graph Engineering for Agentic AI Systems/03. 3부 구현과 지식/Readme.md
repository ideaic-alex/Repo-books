# 3부 개요 (Part III) 구현과 지식

켄 황(Ken Huang)의 『Graph Engineering for Agentic AI Systems』 3부는 설계한 그래프를 실제로 올릴 곳과, 그 그래프가 읽고 쓰는 기억의 구조를 다루는 두 개 장이다. 7장은 에이전트 그래프를 실어 보낼 수 있는 프레임워크를 브랜드가 아니라 토폴로지(topology)로 비교한다. 8장은 시스템이 기억하는 것을 담는 지식 그래프(knowledge graph)를 실행 그래프와 구분해 정의하고, GraphRAG와 시간 모델, 검증 있는 쓰기까지 설명한다. 2부가 무엇을 그래프로 만들지 정했다면, 이 부는 어디서 돌리고 무엇을 기억시킬지를 정한다.

이 노트는 번역이 아니라 책의 내용을 이해한 뒤 풀어 다시 정리한 학습 노트다. 책이 소개하는 도구, 버전, 수치, 날짜는 2026년경 시점의 서술이며 노트 작성자가 검증하지 않았으니 도입 전에 공식 문서로 확인해야 한다.

> **이 부를 한 문장으로**
> 먼저 일의 모양(토폴로지)을 정하고 그에 맞는 런타임을 고르며, 기억은 실행 그래프와 분리된 지식 그래프로 두어 기억 질의 노드라는 하나의 문으로만 읽고 검증을 통과한 것만 쓴다.

---

## 0. 먼저 알아 둘 것

- **실행 그래프와 메모리 그래프**: 실행 그래프(G_A)는 일이 어떻게 흐르는지, 지식 그래프(G_K)는 무엇을 기억하는지를 나타낸다. 3부는 이 둘을 섞지 않는 것이 핵심이다.
- **고도(altitude)**: 프레임워크가 얼마나 많은 패턴에 이름을 붙여 감춰 주는지의 정도다. 높을수록 코드가 적고 낮을수록 직접 통제한다.
- **앞 장과의 연결**: 7장은 4~6장에서 설계한 모양을 런타임으로 옮기는 단계이고, 8장은 4장의 노드 유형 중 하나인 기억 질의 노드를 구체화한다.
- **다음 부와의 연결**: 4부 9장은 이렇게 구현한 그래프를 프로덕션에서 운영하는 이야기로 이어진다.

## 2. 3부 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 토폴로지 | 노드와 엣지가 이루는 모양. 브랜드가 바뀌어도 남는 비교 단위 |
| 체크포인트(checkpoint) | 실행 중간 상태를 저장해 두는 지점. 인터럽트 후 재개의 바탕 |
| 인터럽트(interrupt) | 실행을 멈추고 사람의 입력을 기다리게 하는 장치 |
| 크루(crew) | 역할을 가진 에이전트들이 순서나 매니저를 따라 협업하는 구성 |
| 고도 | 프레임워크가 패턴을 얼마나 이름 붙여 감춰 주는지의 정도 |
| 중력(gravity) | 특정 클라우드나 도구 생태계로 끌려가는 힘, 곧 잠금 |
| A2A | 서로 다른 팀의 에이전트끼리 대화하는 개방형 프로토콜 |
| 지식 그래프 G_K | 엔티티와 타입 있는 관계로 된, 실행하지 않는 기억 구조 |
| GraphRAG | 지식 그래프를 검색 경로에 쓰는 RAG. 그래프 엔지니어링과는 다르다 |
| 유효 시간·기록 시간 | 사실이 참이던 때와 시스템이 그것을 안 때. 서로 다른 시계 |
| 기억 질의 노드 | 실행 그래프가 지식 그래프를 읽는 유일한 문이 되는 노드 |

## 3. 이 부의 흐름 요약

7장은 그래프 엔지니어링이 곧 특정 제품이라는 오해를 풀고, 같은 일을 그릴 수 있는 다섯 토폴로지로 프레임워크를 비교한다. 선택은 고도와 클라우드 중력, 직접 짤 것과 가져다 쓸 것의 구분을 거쳐 설계 리뷰 기준으로 정리된다. 8장은 같은 낱말이 가리키는 두 번째 대상인 지식 그래프를 정의하고, 타입 엣지와 출처와 시간이 있어야 순회가 추론이 된다고 말한다. GraphRAG는 그 위의 검색 패턴이며 질문 유형별로 방식을 골라야 하고, 검증을 통과한 쓰기만 허용하는 문을 두는 것이 두 그래프를 함께 운영하는 방법이다. 두 장은 어디서 돌리고 무엇을 기억시킬지라는 하나의 구현 질문으로 이어지며, 이 결과는 4부의 운영 이야기의 전제가 된다.
