# 5부 개요 (Part V) 보안과 경계

Ken Huang의 『Graph Engineering for Agentic AI Systems』 5부는 "그래프를 어디까지 믿고, 어디서 선을 그을 것인가"를 다루는 두 개 장이다. 11장은 실행 그래프를 공격 표면이자 인가 구조로 읽고, 허용 목록·신원·도달 가능성·공급망·계보로 방어하는 방법을 설명한다. 12장은 반대편의 경계, 곧 GNN과 인과 그래프 같은 학습된 그래프를 런타임으로 착각하지 말라는 경고를 담고 있다. 앞의 부들이 그래프를 어떻게 짓고 운영하는지를 보여 줬다면, 이 부는 그래프가 책임질 일과 책임지지 말아야 할 일을 가른다.

이 노트는 번역이 아니라 책의 내용을 이해한 뒤 풀어 다시 정리한 학습 노트다. 보안 장은 방어 관점의 개념과 통제 항목 위주로 정리했다. 책이 소개하는 프레임워크, 문서, 날짜는 2026년경 시점 기준이며 노트 작성자가 검증하지 않았다.

> **이 부를 한 문장으로**
> 에이전트의 안전은 프롬프트의 문구가 아니라 그래프에 어떤 엣지와 권한이 없는가로 정해지고, 학습된 그래프는 점수와 순위만 맡을 뿐 허용 목록과 기억을 대신하지 못한다.

---

## 0. 먼저 알아 둘 것

- **허용 목록(allowlist)**: 어떤 노드가 어떤 노드로 갈 수 있고 어떤 도구를 쥘 수 있는지를 코드의 표로 정한 것이다(11장).
- **세 가지 그래프**: 실행 그래프(행동), 지식·메모리 그래프(사실), 학습된 계산 그래프(학습된 함수)를 섞지 않는다는 구분이 이 부의 전제다(12장). 2장과 8장을 떠올리면 좋다.
- **앞 장과의 연결**: 11장은 4장의 노드 유형과 9장의 체크포인트·멱등성, 10장의 도달 가능성과 사이클 이론을 보안 용도로 다시 쓴다. 12장은 8장의 출처(provenance) 규칙을 방패로 삼는다.
- **방어 중심**: 11장에는 공격 기법의 설명이 아니라, 설계 리뷰와 CI에서 확인할 통제 항목이 담겨 있다.

## 2. 5부 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 그림자 엣지(shadow edge) | 선언한 엣지 집합 밖으로 일이 흘러가는 모든 숨은 통로 |
| 허용 목록 | 노드-도구, 노드-라벨, 생성 규칙, 재개 정책을 담은 구조적 통제표 |
| 주체(principal) | 노드가 그 권한으로 실행되는 사람·서비스·에이전트 신원 |
| 신원 그래프 | 주체와 can_invoke, may_resume 같은 관계로 이루어진, 실행 그래프 옆의 두 번째 그래프 |
| 매개변수 결합 승인 | 금액·대상 등을 묶은 해시에 서명한 승인 |
| 폭발 반경 | 침해된 노드에서 도달 가능한 노드, 도구, 주체, 상태 키의 집합 |
| 계보(lineage) | 어떤 노드가 어떤 주체로 어느 체크포인트에서 어떤 상태 키를 썼는가의 기록 |
| 학습된 계산 그래프 | 손실로 학습된 가중치를 가진 GNN, 그래프 트랜스포머, 인과 그래프 |
| 메시지 패싱 | 노드가 이웃의 정보를 모아 자기 상태를 갱신하는 GNN의 기본 계산 |
| 교차점 | 학습된 그래프가 에이전트 시스템과 정당하게 만나는 두 곳(점수, 순위) |

## 3. 이 부의 흐름 요약

11장은 "엣지가 없으면 갈 수 없다"는 한 문장에서 출발해 구조적 통제를 쌓는다. 허용 목록 표로 경로와 도구를 막고, 신원을 별도 그래프로 분리해 권한을 따지고, 민감 작업으로 가는 모든 경로가 승인 노드를 지나는지를 CI에서 검사한다. 공급망과 계보로 무엇을 로드했고 누가 무엇을 썼는지 추적하며, 승인 노드가 있어도 피로·연극·우회로로 실패할 수 있음을 짚는다. 12장은 이 구조를 지키기 위해 선을 긋는다. 학습된 그래프는 실행 이력으로 위험을 점수화하거나 검색 결과를 재순위하는 정도만 허용되고, 허용 목록을 고치거나 출처를 대체해서는 안 된다. 두 장은 서로 "통제는 결정적이고 검사 가능해야 한다"는 한 원칙으로 연결되며, 이 원칙은 6부의 테스트·평가·검증으로 이어진다.
