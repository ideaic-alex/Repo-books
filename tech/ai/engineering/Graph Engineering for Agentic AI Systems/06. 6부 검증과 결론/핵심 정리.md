# 핵심 정리

이 문서는 6부(13장과 14장)의 요점을 모은 복습용 정리이며, 14장이 책 전체의 결론이므로 끝에 책 전체 14개 장을 한눈에 되돌아보는 표를 붙였다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 책이 소개하는 도구와 사례는 2026년경 기준이다.

---

## 1. 한눈에 보는 요점

- **평가의 대상은 문장이 아니라 걸음이다**: 최종 답이 매끄러워도 검토 노드를 건너뛴 실행은 실패다.
  - *쉽게 말하면*: 정답만 보지 말고 풀이 과정을 채점한다.
  - → 자세히: [13장 에이전트 그래프의 테스트·평가·검증](13%EC%9E%A5%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%98%20%ED%85%8C%EC%8A%A4%ED%8A%B8%C2%B7%ED%8F%89%EA%B0%80%C2%B7%EA%B2%80%EC%A6%9D.md)
- **합법 경로와 불법 경로를 모두 픽스처로 덮는다**: 워커 수 0, 1, 2, 상한과 순환의 상한까지 시험하고, 걸음 서명으로 금지 경로를 잡는다.
  - *쉽게 말하면*: 되는 길뿐 아니라 막혀야 하는 길도 시험한다.
  - → 자세히: [13장 에이전트 그래프의 테스트·평가·검증](13%EC%9E%A5%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%98%20%ED%85%8C%EC%8A%A4%ED%8A%B8%C2%B7%ED%8F%89%EA%B0%80%C2%B7%EA%B2%80%EC%A6%9D.md)
- **노드 점수는 계약이고 평균하지 않는다**: 쓰기 키, 도구 목록, 스키마, 앵커를 대조하며, 검토가 실패인데 apply가 초록이면 실패한 걸음이다. 중단 조건은 모델 없는 단위 테스트로 먼저 쓴다.
  - *쉽게 말하면*: 한 과목이 낙제면 평균이 높아도 진급하지 못한다.
  - → 자세히: [13장 에이전트 그래프의 테스트·평가·검증](13%EC%9E%A5%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%98%20%ED%85%8C%EC%8A%A4%ED%8A%B8%C2%B7%ED%8F%89%EA%B0%80%C2%B7%EA%B2%80%EC%A6%9D.md)
- **골든, 리플레이, 검증자 합의, 질의 가능성이 한 세트다**: 골든은 큐레이션해 토폴로지와 함께 버전을 올리고, 리플레이로 멱등성을 보며, 검증자는 만든 쪽의 스크래치를 가린 채 단독으로 잰다. 실행 기록에는 간선 라벨을 붙인다.
  - *쉽게 말하면*: 사고 현장을 그대로 다시 틀어 보고, 감독관은 답안 작성자와 따로 앉힌다.
  - → 자세히: [13장 에이전트 그래프의 테스트·평가·검증](13%EC%9E%A5%20%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%9D%98%20%ED%85%8C%EC%8A%A4%ED%8A%B8%C2%B7%ED%8F%89%EA%B0%80%C2%B7%EA%B2%80%EC%A6%9D.md)
- **이름은 날씨이고 구조는 기후다**: 유행어 소동에서 새 기술은 없었고, 완결된 루프가 노드 안에 들어갈 만큼 믿음직해졌다는 변화만 실재했다. 하네스 엔지니어링이 우산이고 나머지는 형제다.
  - *쉽게 말하면*: 단어가 바뀌어도 도면은 그대로 쓴다.
  - → 자세히: [14장 이름이 잊혀도 그래프는 남겨라](14%EC%9E%A5%20%EC%9D%B4%EB%A6%84%EC%9D%B4%20%EC%9E%8A%ED%98%80%EB%8F%84%20%EA%B7%B8%EB%9E%98%ED%94%84%EB%8A%94%20%EB%82%A8%EA%B2%A8%EB%9D%BC.md)
- **루프를 먼저, 그래프는 일이 강요할 때만**: 루프는 한 노드짜리 그래프이며, 팬아웃 뒤 합류처럼 루프가 못 하는 일이 있을 때 나눈다. 삭제가 설계의 본능이다.
  - *쉽게 말하면*: 한 사람이 할 수 있는 일에 부서를 만들지 않는다.
  - → 자세히: [14장 이름이 잊혀도 그래프는 남겨라](14%EC%9E%A5%20%EC%9D%B4%EB%A6%84%EC%9D%B4%20%EC%9E%8A%ED%98%80%EB%8F%84%20%EA%B7%B8%EB%9E%98%ED%94%84%EB%8A%94%20%EB%82%A8%EA%B2%A8%EB%9D%BC.md)
- **사람은 비싼 간선에, 거버넌스는 노드에**: 신원·예산·트레이스·정책을 첫 운영 루프부터 붙이고, 불변식은 코드에 변하는 절차는 스킬에 둔다. 실행은 검증된 루프, 압박받은 곳의 그래프, 메모리 그래프 또는 거절의 90일 순서로 간다.
  - *쉽게 말하면*: 결재는 큰돈이 나가는 자리에만 둔다.
  - → 자세히: [14장 이름이 잊혀도 그래프는 남겨라](14%EC%9E%A5%20%EC%9D%B4%EB%A6%84%EC%9D%B4%20%EC%9E%8A%ED%98%80%EB%8F%84%20%EA%B7%B8%EB%9E%98%ED%94%84%EB%8A%94%20%EB%82%A8%EA%B2%A8%EB%9D%BC.md)

## 2. 6부를 관통하는 질문

| 질문 | 6부가 보여 주는 답 |
|------|-------------------|
| 그래프가 약속대로 돌았는지 어떻게 아나? | 픽스처로 걸음을 만들어 경로 서명, 계약, 중단 사유를 접어서 판정한다 |
| 평가를 CI에 넣을 때 무엇을 조심하나? | 안쪽은 스텁으로 결정적으로, 통계 평가는 바깥 루프로, 부수 효과는 금지 |
| 새 유행어가 오면? | 새 제어 단위를 이름 붙이는지 걸러 보고 대개 용어집에만 올린다 |
| 처음 90일에 무엇을 하나? | 검증된 루프 하나, 압박받은 곳만 그래프, 메모리는 필요할 때만 |

## 3. 책 전체 한눈에 되돌아보기

14개 장을 6개 부로 나눈 이 책의 흐름을 한 줄씩 요약한다. 장별 상세는 각 부 폴더의 문서에서 볼 수 있다.

| 부 | 장 | 한 줄 요약 |
|:---:|----|-----------|
| 1부 기초 | 1장 그래프 엔지니어링은 당신이 소유하는 토폴로지다 | 에이전트 시스템의 구조는 설계하지 않으면 우연히 생기며, 노드·간선·상태를 설계하고 소유하는 일이 그래프 엔지니어링이다 |
| 1부 기초 | 2장 실행 그래프와 메모리 그래프 | 행동하는 실행 그래프와 기억하는 메모리(지식) 그래프는 서로 다른 객체이니 한 단어로 섞지 않는다 |
| 1부 기초 | 3장 하네스 아래의 그래프 | 프롬프트·컨텍스트·루프·그래프·메모리는 사다리의 칸이 아니라 한 공구함의 서로 다른 공구이며, 새 공구가 나와도 기존 공구를 버리지 않는다 |
| 2부 설계 | 4장 에이전트 그래프의 해부 | 노드 유형, 간선, 공유 상태와 리듀서, 팬아웃·합류, 게이트를 정찰-검토 다이아몬드로 해부한다 |
| 2부 설계 | 5장 그래프를 만들지 말아야 할 때 | 기본값은 루프이고, 전문성 충돌·팬아웃 합류·분리된 검토자·사람 게이트 같은 트리거가 있을 때만 그래프로 나눈다 |
| 2부 설계 | 6장 노드를 얻을 자격이 있는 패턴 | 분할, 병렬 수집, 합침, 새 창에서의 독립 검증으로 이루어진 다이아몬드를 중심으로, 노드를 더할 자격이 있는 조건을 따진다 |
| 3부 구현과 지식 | 7장 에이전트 그래프를 실어 보낼 수 있는 프레임워크 | 그래프 엔지니어링은 패턴이며 LangGraph, ADK, AutoGen 등 여러 런타임으로 구현할 수 있다 |
| 3부 구현과 지식 | 8장 메모리로서의 지식 그래프 | 일하는 방(실행 그래프)과 서류 보관실(지식 그래프)을 나누고, 문 하나로만 오가며, 타입·시간·출처가 붙고 검사를 통과한 사실만 저장한다 |
| 4부 운영과 이론 | 9장 프로덕션에서 그래프 운영하기 | 상태, 체크포인트, 인터럽트 재개, 예산, 버전, 런북으로 그래프가 살아남게 한다 |
| 4부 운영과 이론 | 10장 에이전트 그래프의 컴퓨터 과학 | DAG, 상태 기계, 페트리 넷, 액터, Pregel 같은 오래된 기계를 한 지붕 아래 모은 것이 에이전트 그래프이며, 각각의 의미와 한계를 안다 |
| 5부 보안과 경계 | 11장 에이전트 그래프의 보안·신원·거버넌스 | 권한이 낮은 노드에서 높은 권한 효과로 가는 경로와 신원, 권한 행렬을 통제한다 |
| 5부 보안과 경계 | 12장 그래프 인텔리전스는 런타임이 아니다 | GNN 같은 학습된 그래프와 실행 그래프를 구분하고 둘이 만나는 지점만 다룬다 |
| 6부 검증과 결론 | 13장 에이전트 그래프의 테스트·평가·검증 | 최종 문장이 아니라 걸음을 픽스처·계약·골든·리플레이로 시험한다 |
| 6부 검증과 결론 | 14장 이름이 잊혀도 그래프는 남겨라 | 이름은 사라져도 도식·스키마·예산·중단 조건·사람 게이트를 남기고, 루프부터 90일 경로로 시작한다 |

> **책 전체 한 줄 요약**
> 에이전트의 구조는 우연이 아니라 설계해서 소유하는 산출물이며, 루프로 충분하면 루프로 두고, 일이 강요할 때만 그래프로 나누어, 운영하고 지키고 시험하면서 이름이 사라진 뒤에도 그 구조를 남긴다.

> **6부 한 줄 요약**
> 최종 답이 아니라 지나간 길을 시험하고, 유행어가 아니라 도식과 예산과 중단 조건과 사람 게이트를 남긴다.
