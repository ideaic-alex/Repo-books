# 핵심 정리

이 문서는 1부(머리말과 1장부터 3장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 문서로 이동한다. 책이 소개하는 도구, 날짜, 수치는 책이 서술한 시점(2026년경) 기준이며 노트가 검증하지 않았다.

---

## 1. 한눈에 보는 요점

- **그래프 엔지니어링은 토폴로지를 소유하는 일이다**: 에이전트가 허용된 경로로만 돌도록 노드, 합법적 엣지, 공유 상태, 팬아웃과 조인, 게이트를 선언한다. 네 추천인은 구조가 암묵적이면 주인이 없다고 입을 모은다.
  - *쉽게 말하면*: 리뷰어가 환불 도구를 부를 수 있는지는 그림에서 정한다.
  - → 자세히: [머리말](%EB%A8%B8%EB%A6%AC%EB%A7%90.md)
- **루프는 노드 하나짜리 그래프다**: 루프는 목표와 기준만 정하고 경로는 에이전트가 고른다. 그래프는 경로를 엣지로 선언하고 자유는 노드 안에 둔다. 그래프는 루프를 품는다.
  - *쉽게 말하면*: 대체가 아니라 포함이다.
  - → 자세히: [1장 그래프 엔지니어링은 당신이 소유하는 토폴로지다](01%EC%9E%A5%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EC%97%94%EC%A7%80%EB%8B%88%EC%96%B4%EB%A7%81%EC%9D%80%20%EB%8B%B9%EC%8B%A0%EC%9D%B4%20%EC%86%8C%EC%9C%A0%ED%95%98%EB%8A%94%20%ED%86%A0%ED%8F%B4%EB%A1%9C%EC%A7%80%EB%8B%A4.md)
- **루프가 못 하는 동작은 팬아웃 후 조인이다**: 독립 가지가 동시에 돌거나 전문가가 인계하거나 사람이 부수 효과를 막아야 하면 그래프다. 대신 채팅 대비 약 15배의 토큰 같은 비용을 낸다고 책은 소개한다.
  - *쉽게 말하면*: PDF 한 건 요약에 노드 다섯 개는 조직도로 메일 한 통에 답하는 격이다.
  - → 자세히: [1장 그래프 엔지니어링은 당신이 소유하는 토폴로지다](01%EC%9E%A5%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EC%97%94%EC%A7%80%EB%8B%88%EC%96%B4%EB%A7%81%EC%9D%80%20%EB%8B%B9%EC%8B%A0%EC%9D%B4%20%EC%86%8C%EC%9C%A0%ED%95%98%EB%8A%94%20%ED%86%A0%ED%8F%B4%EB%A1%9C%EC%A7%80%EB%8B%A4.md)
- **세 그래프를 한 칠판에 섞지 않는다**: 실행 그래프 G_A는 일의 구조, 지식 그래프 G_K는 유형·시간·출처가 있는 기억, 학습된 그래프 G_L은 오프라인 모델이다. 트레이스는 따로 구분한다.
  - *쉽게 말하면*: 흐름도는 돌아가고 장부는 조회된다.
  - → 자세히: [2장 실행 그래프와 메모리 그래프](02%EC%9E%A5%20%EC%8B%A4%ED%96%89%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%99%80%20%EB%A9%94%EB%AA%A8%EB%A6%AC%20%EA%B7%B8%EB%9E%98%ED%94%84.md)
- **GraphRAG는 그래프 엔지니어링이 아니다**: 지식 그래프 위의 검색 패턴일 뿐이며 실행 그래프 노드 안에 합성할 수는 있지만 서로 대체하지 못한다.
  - *쉽게 말하면*: 걷는 쪽과 걸어 다니는 대상은 다른 물건이다.
  - → 자세히: [2장 실행 그래프와 메모리 그래프](02%EC%9E%A5%20%EC%8B%A4%ED%96%89%20%EA%B7%B8%EB%9E%98%ED%94%84%EC%99%80%20%EB%A9%94%EB%AA%A8%EB%A6%AC%20%EA%B7%B8%EB%9E%98%ED%94%84.md)
- **하네스는 우산, 나머지는 형제다**: 프롬프트, 컨텍스트, 루프, 그래프, 메모리는 서로를 은퇴시키지 않는다. 그래프는 토폴로지만 맡고 다른 형제는 노드, 엣지, 상태를 제약할 때 등장한다.
  - *쉽게 말하면*: 새 공구가 생겼다고 망치를 버리지 않는다.
  - → 자세히: [3장 하네스 아래의 그래프](03%EC%9E%A5%20%ED%95%98%EB%84%A4%EC%8A%A4%20%EC%95%84%EB%9E%98%EC%9D%98%20%EA%B7%B8%EB%9E%98%ED%94%84.md)
- **네 질문을 순서대로 묻는다**: 사람이 다 읽나, 끝을 기계가 판정하나, 한 컨텍스트에 들어가나, 독립 가지가 동시에 필요한가. 첫 번째 아니오가 대개 정답이다.
  - *쉽게 말하면*: 승급 사다리가 아니라 이 일을 위한 진단이다.
  - → 자세히: [3장 하네스 아래의 그래프](03%EC%9E%A5%20%ED%95%98%EB%84%A4%EC%8A%A4%20%EC%95%84%EB%9E%98%EC%9D%98%20%EA%B7%B8%EB%9E%98%ED%94%84.md)

## 2. 1부를 관통하는 질문

| 질문 | 1부가 보여 주는 답 |
|------|-------------------|
| 이 일에 그래프가 필요한가? | 팬아웃, 전문가 인계, 사람 게이트가 필요할 때. 아니면 루프 |
| 칠판의 그래프는 무엇인가? | 원이 일을 하면 실행, 사물이면 지식, 벡터면 학습된 그래프 |
| 어떻게 숫자를 믿나? | URL, 과제, 분모가 있을 때만 |
| 비용은 어떻게 보나? | 15배 같은 값은 계획 숫자. 가장 싼 수정은 오케스트레이터 프롬프트일 때가 많다 |
| 노드 사이에서 무엇이 넘어가나? | 데이터가 아니라 참조와, 조인이 볼 수 있는 결정 |

> **1부 한 줄 요약**
> 에이전트가 갈 수 있는 길을 그려 소유하되, 실행과 기억을 섞지 않고, 루프로 충분한 일은 루프로 끝내는 것이 그래프 엔지니어링의 출발점이다.
