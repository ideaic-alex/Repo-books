# 1부 개요 (Part I) 논증

Volodymyr Pavlyshyn의 『Graph Engineering — The Loop Memory Model』 1부는 책 전체의 논증을 세우는 머리말과 세 개 장이다. 머리말은 "결정의 이유가 증발한다"는 문제의 장면과 이 책의 시험을 제시하고, 1장은 기억이 루프의 부산물이 아니라 산출물이어야 한다는 핵심 메시지를, 2장은 에이전트 아키텍처를 다섯 칸의 사다리로 정리해 각 칸이 무엇을 바깥으로 꺼내는지를, 3장은 어떤 진지한 시스템에도 그래프가 둘(작업 그래프와 지식 그래프) 필요하다는 구분을 다룬다. 1시간 안에 쭉 읽도록 쓰인 부이며, 2부 이후의 모든 설계가 여기서 세운 구분에 기댄다.

이 노트는 번역이 아니라 책의 내용을 이해한 뒤 풀어 다시 정리한 학습 노트다. 책은 2026년경의 에이전트 워크플로를 전제로 하며 언급되는 도구, 사례, 수치는 책이 서술한 시점 기준이고 노트가 검증하지 않았다.

> **이 부를 한 문장으로**
> 루프는 결과물만 남기고 이유를 잊으므로, 기억을 루프의 산출물로 삼아 "작업 그래프"와 "지식 그래프" 두 개로 나누어 담고 브리지로 잇자는 주장이다.

---

## 0. 먼저 알아 둘 것

- **책의 어휘**: 래티스(lattice, `lat.md/` 지식 모음), 메타그래프(metagraph), 불변식(invariant), 스웜(swarm), 브리지(bridge) 등이 나온다. 래티스와 메타그래프는 2부에서 본격적으로 풀리므로 1부에서는 개념만 잡으면 된다.
- **전작 언급**: 책은 『The Clarity Forge』, 『Clarity Series』 같은 저자의 이전 작업을 자주 언급한다. 읽지 않아도 4장이 필요한 부분을 복습한다고 책은 밝힌다.
- **사전 지식**: 에이전트 루프, 서브에이전트, git 커밋 정도를 알면 충분하다.

## 2. 1부 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 루프 메모리(Loop Memory) | 루프가 반복을 넘어 남기는 기억. 책은 이것이 루프의 산출물이어야 한다고 본다 |
| 작업 상태, 추론 상태 | 무엇을 했는가와 왜 그렇게 했는가. 앞의 것만 저장소에서 복원된다 |
| 래티스(lattice) | ADR, 어휘, 불변식, 패턴, 원칙을 이름 붙은 관계로 엮은 `lat.md/` 지식 모음 |
| 불변식(invariant) | 항상 지켜져야 하는 조건. 예: 총액은 음수가 아니다 |
| 스웜(swarm) | 여러 에이전트가 병렬로 일하는 구조 |
| 작업 평면(work plane) | 무슨 일이 있었나를 담는 그래프. 커밋 DAG에 실행과 평가를 얹은 것 |
| 지식 평면(knowledge plane) | 무엇이 참인가를 담는 그래프. 승격된 래티스 |
| 브리지(bridge) | 두 평면을 잇는 간선. 책이 정의하는 것은 honors와 mints 둘뿐 |

## 3. 이 부의 흐름 요약

머리말이 월요일 아침의 사라진 결정을 보여 주면, 1장은 이것이 모델 성능이 아니라 기억의 위치 문제임을 논증하고 기억과 루프의 관계를 뒤집는다. 2장은 에이전트 아키텍처를 시간, 공간, 역사, 의미 순으로 올라가는 사다리로 놓고 건너뛸 수 없다는 점과 대부분의 팀이 더 낮은 칸에서 멈춰야 한다는 점을 보인다. 3장은 사다리의 끝에서 "하나의 그래프로는 부족하다"는 결론을 내리고, 작업 그래프와 지식 그래프를 분리하되 두 개의 브리지 술어로 잇는 구조를 제시해 2부의 구조 설계로 넘어간다.
