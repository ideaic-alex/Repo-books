# 4부 개요 (Part IV) 판단

볼로디미르 파블리신(Volodymyr Pavlyshyn)의 『Graph Engineering — The Loop Memory Model』 4부는 앞에서 세운 구조와 메커니즘을 "실제로 도입해도 되는가, 어떻게 잘못되는가, 어떤 순서로 짓는가"의 관점으로 되짚는 세 개 장이다. 12장은 층별 지표와 실패 양상, 그리고 그래프를 만들지 말아야 할 때를, 13장은 하나의 루프에서 그래프 기반 스웜까지 가는 여섯 단계의 구축 경로를, 14장은 더 읽을 자료를 정리한다. 책은 12장을 도입을 고민하는 사람이 7장보다 먼저 읽어도 좋은 장이라고 소개한다.

이 노트는 번역이 아니라 책의 내용을 이해한 뒤 풀어 다시 정리한 학습 노트다. 책은 2026년경 에이전트 워크플로를 전제로 하며, 소개하는 도구와 사례는 그 시점 기준이다.

> **이 부를 한 문장으로**
> 지표는 오독되고 개선 장치는 보이는 숫자만 올리며 거짓 병합은 조용히 퍼지므로, 그래프는 필요할 때만 종료 기준이 있는 작은 단계로 쌓아야 한다.

---

## 0. 먼저 알아 둘 것

- **추적성 시험**: 책 전체를 관통하는 질문이다. 중요한 출력이 목표, 계획, 산출물, 출처, 그래프 경로, 평가자 결정, 한정된 실행 기록까지 추적되는가를 묻는다. 12장과 13장 모두 이 시험으로 돌아온다.
- **래칫(ratchet)**: 개선은 남기고 후퇴는 버리는 장치로 2장에서 소개됐다. 12장은 래칫이 자기가 보는 지표만 올린다는 점을 경고한다.
- **거짓 병합**: 서로 다른 엔티티를 한 노드로 합치는 오류다. 눈에 띄지 않게 번지는 가장 위험한 실패로 다뤄진다.
- **앞 부와의 연결**: 12장은 2부 7장의 스키마와 3부 8장의 해소, 10장의 스웜을 전제로 하고, 13장은 2장의 사다리와 7장 9절의 이행 순서를 쓴다.

## 2. 4부 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 지표 벡터 | 단일 점수 대신 하한과 상한을 함께 두는 지표 묶음 |
| 거짓 병합 | 서로 다른 엔티티를 하나로 합쳐 조용히 오염을 퍼뜨리는 오류 |
| 종료 기준(exit criterion) | 한 단계가 끝났다고 인정하는 측정 가능한 조건 |
| 근거 기반 평가자(grounded evaluator) | 그래프의 지지 경로를 대며 승인 또는 수정을 결정하는 평가자 |
| 스웜(swarm) | 독립 하위 과업을 많은 일꾼이 병렬로 처리하는 방식 |
| 참조 아키텍처 | 제어, 실행, 산출물, 그래프, 평가의 다섯 평면으로 나눈 구성 |
| 스케치 | 제품이 아니라 방향만 보이는 시제품. 책은 스케치를 배포하지 말라고 한다 |

## 3. 이 부의 흐름 요약

12장은 도입 전의 비판적 점검이다. 지표는 층마다 두되 오독을 함께 적고, 개선 장치가 보이는 숫자만 올리는 것을 하한선으로 막고, 거짓 병합을 가장 큰 위험으로 다루며, 그래프가 만든 사람의 판단과 코퍼스를 그대로 증폭한다는 점을 인정한다. 그러고는 연결 질의, 변하는 관계, 출처, 공유 상태 중 셋 이상일 때만 그래프를 짓고 하나뿐이면 CLAUDE.md와 ADR이 낫다고 결론짓는다. 13장은 그 판단을 통과한 경우의 순서다. 하루짜리 반성 루프에서 시작해 도구, 계획, 멀티 에이전트, 지속 그래프, 스웜으로 올라가며 매 단계 종료 기준을 확인한다. 14장은 이어 읽을 자료와 출처 불명 문서에 대한 주의로 책을 닫는다.
