# 핵심 정리

이 문서는 2부(4장에서 7장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 책은 2026년경 에이전트 워크플로를 전제로 하며 도구와 폴더 이름은 책 시점 기준이다.

---

## 1. 한눈에 보는 요점

- **래티스는 장점이 분명하지만 엣지가 주석이다**: 추가만 하며 대체하기, 닫힌 술어 다섯 개, 노드 원자성은 지킬 가치가 있지만, 유사성, 출처, 예산 조회, 불확실성, 동시 쓰기, 충족 확인은 막힌다.
  - *쉽게 말하면*: 한 사람이 관리하는 문서 모음집은 잘 돌지만 에이전트 마흔 개가 쓰면 서로 모른다.
  - → 자세히: [4장 이미 가진 래티스](04%EC%9E%A5%20%EC%9D%B4%EB%AF%B8%20%EA%B0%80%EC%A7%84%20%EB%9E%98%ED%8B%B0%EC%8A%A4.md)
- **여섯 한계는 하나의 원인이다**: 엣지가 속성을 갖고 참조되고 추론되어야 하는데 그런 구조가 이미 메타그래프다.
  - *쉽게 말하면*: 선에 이름표를 달고 싶어지는 순간 선은 사물이다.
  - → 자세히: [4장 이미 가진 래티스](04%EC%9E%A5%20%EC%9D%B4%EB%AF%B8%20%EA%B0%80%EC%A7%84%20%EB%9E%98%ED%8B%B0%EC%8A%A4.md)
- **엣지는 필요할 때만 노드로 올린다**: 속성 추출, 관계의 관계, 맥락 곱셈의 세 재귀화 패턴을 쓰고, 미리 올리지 않는 점진적 재귀화가 규칙이다.
  - *쉽게 말하면*: 이름표가 필요한 선만 이름표를 단다.
  - → 자세히: [5장 래티스 메타그래프](05%EC%9E%A5%20%EB%9E%98%ED%8B%B0%EC%8A%A4%20%EB%A9%94%ED%83%80%EA%B7%B8%EB%9E%98%ED%94%84.md)
- **구현은 마크다운 정본에 파생 색인을 얹는다**: 인코딩 A(권장)는 새 인프라가 필요 없고 색인은 일회용이다. B(이분 투영)는 그래프 DB 사용자, C(RDF-Star)는 RDF 인프라 보유자용이다.
  - *쉽게 말하면*: 원본 파일은 지키고 검색용 색인은 망가지면 지우고 다시 만든다.
  - → 자세히: [5장 래티스 메타그래프](05%EC%9E%A5%20%EB%9E%98%ED%8B%B0%EC%8A%A4%20%EB%A9%94%ED%83%80%EA%B7%B8%EB%9E%98%ED%94%84.md)
- **래티스에는 유사성 관계가 없었다**: 시맨틱 시공간의 네 관계에 대 보면 다섯 술어 중 넷은 대응하고 NEAR만 비어, 중복 노드, 용어 표류, 예산 안 검색, 고아 불변식 판별이 막힌다.
  - *쉽게 말하면*: 의존 지도는 있는데 비슷함 지도가 없었다.
  - → 자세히: [6장 래티스를 위한 시맨틱 시공간](06%EC%9E%A5%20%EB%9E%98%ED%8B%B0%EC%8A%A4%EB%A5%BC%20%EC%9C%84%ED%95%9C%20%EC%8B%9C%EB%A7%A8%ED%8B%B1%20%EC%8B%9C%EA%B3%B5%EA%B0%84.md)
- **NEAR는 제안하고 저작된 술어가 결정한다**: NEAR는 계산되고 일회용이며 관문이 되지 않는다. 맥락(단계)마다 가중치가 다르므로 하나의 그래프가 일곱 단계에 맞는 이웃을 준다.
  - *쉽게 말하면*: 컴퓨터는 "여길 보라"고 가리키고 판정은 사람이 한다.
  - → 자세히: [6장 래티스를 위한 시맨틱 시공간](06%EC%9E%A5%20%EB%9E%98%ED%8B%B0%EC%8A%A4%EB%A5%BC%20%EC%9C%84%ED%95%9C%20%EC%8B%9C%EB%A7%A8%ED%8B%B1%20%EC%8B%9C%EA%B3%B5%EA%B0%84.md)
- **스키마는 두 평면과 두 브리지다**: 지식 평면과 작업 평면에 저작 술어를 다섯 개씩 두고, 평면을 잇는 것은 honors와 mints뿐이다. 파생(near, contradicts)과 구조(contains, expresses)는 저작되지 않는다.
  - *쉽게 말하면*: 사실 창고와 작업 일지를 나누고 두 곳을 두 가지 선으로만 잇는다.
  - → 자세히: [7장 스키마](07%EC%9E%A5%20%EC%8A%A4%ED%82%A4%EB%A7%88.md)
- **불변식 다섯이 관문이고 이행은 되돌릴 수 있다**: claim 출처, 산출물의 실행, 평가의 루브릭, 대체물 주소 유지, 에이전트 노드의 Provenance. 네 단계로 이행하며 다섯째는 마지막에 켠다.
  - *쉽게 말하면*: 출처 없는 말과 이름 없는 산출물은 받지 않는다.
  - → 자세히: [7장 스키마](07%EC%9E%A5%20%EC%8A%A4%ED%82%A4%EB%A7%88.md)

## 2. 2부를 관통하는 질문

| 질문 | 2부가 보여 주는 답 |
|------|-------------------|
| 래티스에서 무엇을 지켜야 하나? | 추가만 하며 대체, 닫힌 술어, 노드 원자성, 마크다운 정본 |
| 엣지에 출처와 확신도를 달려면? | 엣지를 assertion 노드로 올리는 재귀화, 필요한 것만 |
| 어떤 구현을 고르나? | 기본은 마크다운 + 파생 색인(인코딩 A) |
| 비슷한 노드는 어떻게 찾나? | 계산되는 NEAR, 임베딩은 첫 거름망, 판정은 차원 좌표와 모델 |
| 새 술어가 필요해 보이면? | 노드를 넓히거나 산문으로 둔다. 저작 술어는 늘리지 않는다 |
| 지식과 작업의 경계는? | 두 평면, 두 브리지, 나머지는 파생으로 얻는다 |
| 쓰기를 어떻게 통제하나? | 그래프 불변식 다섯, 특히 에이전트 노드의 Provenance |

---

> **2부 한 줄 요약**
> 래티스를 메타그래프로 인정하고 엣지를 필요한 만큼 객체로 올리며, 계산되는 NEAR를 더하고, 지식과 작업 두 평면에 닫힌 술어를 둔 스키마와 불변식 다섯으로 확정한다.
