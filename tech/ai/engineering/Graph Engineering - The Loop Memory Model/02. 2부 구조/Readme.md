# 2부 개요 (Part II) 구조

볼로디미르 파블리신(Volodymyr Pavlyshyn)의 『Graph Engineering — The Loop Memory Model』 2부는 "모델링 방식을 바꾸는 네 개 장"이다. 4장은 앞선 작업 방식이 남긴 래티스(lattice, 파일로 관리하는 지식 노드 묶음)가 무엇을 못 하는지 정확히 짚는다. 5장은 이 래티스가 처음부터 메타그래프(metagraph)였다고 인정하면 구현이 쉬워진다고 보인다. 6장은 시맨틱 시공간(Semantic Spacetime)의 네 관계를 대 보아 래티스에 빠진 단 하나의 관계, 곧 유사성을 찾아낸다. 7장은 이 모두를 린터를 쓸 수 있을 만큼 닫힌 스키마로 확정한다. 1부가 "왜 그래프가 필요한가"를 논증했다면, 이 부는 "그래프가 정확히 어떤 모양인가"를 정한다.

이 노트는 번역이 아니라 책의 내용을 이해한 뒤 풀어 다시 정리한 학습 노트다. 책의 코드와 스키마는 옮기지 않고 표로 재구성했다. 책은 2026년경의 에이전트 워크플로를 전제로 하고, 도구 이름과 버전은 책이 쓰인 시점 기준이다.

> **이 부를 한 문장으로**
> 이미 가진 래티스는 엣지를 주석으로만 다뤄서 한계에 부딪히며, 엣지를 객체로 올리고(메타그래프), 계산되는 유사성 관계를 더하고, 지식과 작업을 두 평면으로 나눠 닫힌 스키마로 확정하면 그 한계가 풀린다.

---

## 0. 먼저 알아 둘 것

- **래티스와 사이드카**: 래티스는 결정, 용어, 불변식, 패턴, 원칙 노드를 마크다운 파일로 모은 `lat.md/` 디렉터리이고, 본체인 `openspec/` 옆에 놓인다. 마크다운이 정본이라는 점이 이 부 전체에서 유지된다.
- **엣지를 객체로 올린다(재귀화)**: 선에 "누가, 언제, 얼마나 확신하며"를 붙이고 싶으면 그 선을 노드로 바꾼다. 필요한 선만 올린다.
- **저작과 파생의 구분**: 사람이나 심문을 거친 에이전트가 쓰는 관계(저작)와 컴퓨터가 계산하는 관계(파생)를 나눈다. 파생은 제안만 하고 결정하지 못한다.
- **1부와의 연결**: 3장의 두 평면(지식 평면, 작업 평면) 구분이 7장에서 구체적 노드 타입과 술어로 확정된다.
- **수식이 거의 없다**: 개념과 구조 중심이며 표를 많이 쓴다.

## 2. 2부 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 래티스(lattice) | 결정, 용어, 불변식, 패턴, 원칙을 파일로 모은 지식 묶음 |
| 불변식(invariant) | 여러 기능에 걸쳐 항상 성립해야 하는 성질 |
| 메타그래프(metagraph) | 엣지도 노드가 될 수 있고, 노드가 하위 그래프를 품는 그래프 |
| 재귀화(reification) | 엣지를 노드로 올려 속성을 붙이거나 다른 엣지가 가리키게 하는 일 |
| 노드 원자성 | 노드 하나에 사실 하나. 일부 참조 금지 |
| NEAR | 계산되는 유사성 관계. 제안만 하고 결정하지 않는다 |
| 실용적 근접성 | 같은 두 개체의 거리가 맥락(단계)에 따라 달라지는 것 |
| 지식 평면(knowledge plane) | 오래 남는, 선별된 사실이 사는 층 |
| 작업 평면(work plane) | 에이전트 실행과 산출물의 기록이 사는 층 |
| 브리지(bridge) | 두 평면을 잇는 두 술어, honors와 mints |
| 파생 색인 | 마크다운에서 다시 만드는 일회용 데이터베이스 |

## 3. 이 부의 흐름 요약

4장은 래티스의 장점 셋(추가만 하기, 닫힌 술어, 노드 원자성)을 지켜야 할 자산으로 확인하고, 에이전트가 여럿 쓸 때 막히는 여섯 가지를 모두 "엣지가 일급이 아니다"라는 한 원인으로 묶는다. 5장은 이를 받아 엣지를 노드로 올리는 세 패턴과 네 겹의 레이어를 제시하고, 데이터베이스 없이 마크다운과 파생 색인으로 구현하라고 권한다. 6장은 이렇게 얻은 표현력이 어떤 관계를 담을지 정해 주지 않는다는 점을 메우려고 시맨틱 시공간의 네 관계를 대 보고, 비어 있는 유사성 관계를 계산되는 NEAR로 채운다. 7장은 이 모두를 열한 개의 저작 술어, 두 개의 평면, 다섯 개의 불변식으로 구성된 하나의 닫힌 스키마로 확정하고, 기존 래티스에서 되돌릴 수 있는 네 단계로 이행하는 길을 안내한다. 이 스키마는 3부에서 그래프를 만들고 예산 안에서 조회하고 근거 기반으로 평가하고 스웜을 돌리는 바탕이 된다.
