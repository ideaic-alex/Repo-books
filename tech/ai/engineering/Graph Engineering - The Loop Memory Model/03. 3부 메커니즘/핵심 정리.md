# 핵심 정리

이 문서는 3부(8장부터 11장)의 요점을 한곳에 모은 복습용 정리다. 각 요점 끝의 **→ 자세히** 링크를 따라가면 해당 장으로 이동한다. 책은 2026년경 에이전트 워크플로를 전제로 하며 도구와 단계 이름은 집필 시점 기준이다.

---

## 1. 한눈에 보는 요점

- **파싱할 수 있는 것은 추출하지 않는다**: 스키마가 있는 소스는 파싱하고 진짜 산문만 싼 모델로 추출한다. 술어는 닫힌 집합으로 묶고 설명과 근거를 필수로 한다.
  - *쉽게 말하면*: 이미 정리된 표를 다시 읽혀 돈을 쓰지 않는다.
  - → 자세히: [8장 그래프 만들기](08%EC%9E%A5%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EB%A7%8C%EB%93%A4%EA%B8%B0.md)
- **해소는 추가적이고 되돌릴 수 있어야 한다**: 싸게 거르고 강한 모델이 판정하며 병합은 삭제가 아니라 대체 간선과 출처로 남긴다. 과잉 병합이 과소 병합보다 늦게 발견된다.
  - *쉽게 말하면*: 합치되, 언제든 풀 수 있게 끈을 남긴다.
  - → 자세히: [8장 그래프 만들기](08%EC%9E%A5%20%EA%B7%B8%EB%9E%98%ED%94%84%20%EB%A7%8C%EB%93%A4%EA%B8%B0.md)
- **그래프는 통째로 넣지 않고 작업마다 조금만 꺼낸다**: 일곱 단계 빌더에서 최근 검증 우선과 충돌 포함이 가장 자주 빠지고 가장 중요하다.
  - *쉽게 말하면*: 도서관 전체가 아니라 오늘 필요한 책 세 권만 건넨다.
  - → 자세히: [9장 컨텍스트 조립과 근거 기반 평가자](09%EC%9E%A5%20%EC%BB%A8%ED%85%8D%EC%8A%A4%ED%8A%B8%20%EC%A1%B0%EB%A6%BD%EA%B3%BC%20%EA%B7%BC%EA%B1%B0%20%EA%B8%B0%EB%B0%98%20%ED%8F%89%EA%B0%80%EC%9E%90.md)
- **평가자는 글이 아니라 간선을 본다**: 빠진 간선을 지목하는 구조화된 피드백은 재현되고 다음 디스패치로 이어진다. 중복과 모순은 평결이 아닌 질문이다.
  - *쉽게 말하면*: "그럴듯한가"를 "그 길이 실제로 있는가"로 바꾼다.
  - → 자세히: [9장 컨텍스트 조립과 근거 기반 평가자](09%EC%9E%A5%20%EC%BB%A8%ED%85%8D%EC%8A%A4%ED%8A%B8%20%EC%A1%B0%EB%A6%BD%EA%B3%BC%20%EA%B7%BC%EA%B1%B0%20%EA%B8%B0%EB%B0%98%20%ED%8F%89%EA%B0%80%EC%9E%90.md)
- **근거가 있다는 것은 옳다는 것이 아니다**: 그래프가 뒷받침한다는 말은 말뭉치의 사각지대만큼 약하고, 선택이 틀리면 빠르고 일관된 오류 기계가 된다.
  - *쉽게 말하면*: 자료가 한쪽으로 치우쳤다면 근거도 한쪽으로 치우친다.
  - → 자세히: [9장 컨텍스트 조립과 근거 기반 평가자](09%EC%9E%A5%20%EC%BB%A8%ED%85%8D%EC%8A%A4%ED%8A%B8%20%EC%A1%B0%EB%A6%BD%EA%B3%BC%20%EA%B7%BC%EA%B1%B0%20%EA%B8%B0%EB%B0%98%20%ED%8F%89%EA%B0%80%EC%9E%90.md)
- **스웜은 강제하지 말고 약속을 평가한다**: 쓰기 범위 선언으로 충돌을 사전에 집합 교집합으로 잡고, 발행, 검증, 버전 커밋의 프로토콜로 쓴다. 작업 트리는 파일만 격리한다.
  - *쉽게 말하면*: 각자 맡은 구역을 말하게 하고 지켰는지 본다.
  - → 자세히: [10장 하나의 그래프를 향한 스웜](10%EC%9E%A5%20%ED%95%98%EB%82%98%EC%9D%98%20%EA%B7%B8%EB%9E%98%ED%94%84%EB%A5%BC%20%ED%96%A5%ED%95%9C%20%EC%8A%A4%EC%9B%9C.md)
- **병렬 검증은 증거를 다르게 줄 때만 독립이다**: 같은 컨텍스트의 열 명은 한 명이다. 리듀서 계약을 미리 정하고, 조용한 절단과 예산 소진의 은폐를 하지 않으며, 해소처럼 장벽이 필요한 단계는 병렬화하지 않는다.
  - *쉽게 말하면*: 같은 자료로 열 번 확인해도 같은 실수를 열 번 확인한다.
  - → 자세히: [10장 하나의 그래프를 향한 스웜](10%EC%9E%A5%20%ED%95%98%EB%82%98%EC%9D%98%20%EA%B7%B8%EB%9E%98%ED%94%84%EB%A5%BC%20%ED%96%A5%ED%95%9C%20%EC%8A%A4%EC%9B%9C.md)
- **파이프라인에서 빠지는 단계는 없고 LINK와 불변식 점검이 더해진다**: 각 단계가 그래프를 읽고 쓰며, archive는 link와 check 두 단계를 추가해 보관 시점에 정합을 엄격히 요구한다. 목표, 대체, 게이트 1~2번은 사람의 일로 남긴다.
  - *쉽게 말하면*: 기계는 연결을 확인하고, 무엇이 옳은지는 사람이 정한다.
  - → 자세히: [11장 재배선된 파이프라인](11%EC%9E%A5%20%EC%9E%AC%EB%B0%B0%EC%84%A0%EB%90%9C%20%ED%8C%8C%EC%9D%B4%ED%94%84%EB%9D%BC%EC%9D%B8.md)

## 2. 3부를 관통하는 질문

| 질문 | 3부가 보여 주는 답 |
|------|-------------------|
| 모델에게 무엇을 시키고 무엇을 파싱하나? | 스키마가 있으면 파싱, 산문만 추출 |
| 같은 개체인지 어떻게 정하나? | 싸게 거르고 강한 모델이 판정, 병합은 대체 간선으로 기록 |
| 컨텍스트가 비대해지는 것을 어떻게 막나? | 유계 질의와 일곱 단계 빌더, 토큰 예산 |
| 결과가 맞는지 어떻게 점검하나? | 필요한 간선의 존재와 인용 간선 ID의 경로 확인 |
| 여러 에이전트가 함께 쓰면? | 약속 선언, 검증된 발행, 버전 커밋, 리듀서 계약 |
| 무엇을 자동화하지 말아야 하나? | 목표, 대체, 지속성과 슬러그 판단 |

---

> **3부 한 줄 요약**
> 형식 있는 것은 파싱하고 산문만 추출해 되돌릴 수 있게 그래프를 만들고, 작업마다 작은 조각과 간선 점검으로 컨텍스트와 평가를 처리하며, 여러 에이전트의 쓰기는 약속과 검증과 버전으로 통제하되 목표와 대체는 사람에게 남긴다.
