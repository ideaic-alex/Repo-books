# 3부 개요 (Part III) 메커니즘

볼로디미르 파블리신(Volodymyr Pavlyshyn)의 『Graph Engineering — The Loop Memory Model』 3부는 2부에서 세운 스키마를 실제로 읽고 쓰는 방법을 다루는 네 개 장이다. 책의 첫 문장대로 스키마는 누군가 읽고 쓰기 전까지 죽어 있다. 8장은 저장소에서 그래프를 만드는 네 단계를, 9장은 그래프에서 작업별 컨텍스트를 조립하고 결과를 간선으로 점검하는 방법을, 10장은 여러 에이전트가 그래프를 망가뜨리지 않고 함께 쓰는 방법을, 11장은 이 모두를 기존 파이프라인의 각 단계에 되꽂는 방법을 설명한다.

이 노트는 번역이 아니라 책의 내용을 이해한 뒤 풀어 다시 정리한 학습 노트다. 책은 2026년경 에이전트 워크플로를 전제로 하며, 언급되는 도구와 단계 이름, 비용 수치는 집필 시점 기준이다. 책의 코드와 YAML은 옮기지 않고 구조를 표와 말로 재구성했다.

> **이 부를 한 문장으로**
> 형식이 있는 것은 파싱하고 산문만 추출해 그래프를 만들고, 작업마다 작은 부분그래프를 꺼내 간선으로 결과를 점검하며, 쓰기는 약속과 검증과 버전으로 통제해 파이프라인 전체에 이어 붙인다.

---

## 0. 먼저 알아 둘 것

- **앞 장과의 연결**: 8장은 7장의 닫힌 어휘와 불변식, 5장의 층과 구체화, 6장의 near와 유효 기간을 실제 구축과 질의에 쓴다.
- **컨텍스트 덤핑 경계**: 9장은 그래프 전체를 프롬프트에 넣는 것을 대표적 실패로 규정한다. 핵심은 "작업마다 다른 작은 조각"이다.
- **기계, 모델, 사람의 분담**: 점검은 가능한 한 순회로(모델 없음), 판단은 그래프 증거와 함께 모델에게, 목표와 대체는 사람에게 둔다.
- **다음 부와의 연결**: 3부가 만든 메커니즘이 실제로 잘 돌아가는지, 어디서 실패하는지는 4부(12장)에서 지표와 실패 양상으로 다룬다.

## 2. 3부 용어

| 용어 | 쉬운 설명 |
|------|-----------|
| 추출(extraction) | 산문에서 개체와 관계를 스키마에 맞춰 뽑는 모델 호출 |
| 해소(resolution) | 표면 형태가 다른 같은 개체를 합치고 같은 이름의 다른 개체는 나누는 일 |
| 컨텍스트 조립(context assembly) | 작업별로 그래프에서 유계 부분그래프를 꺼내 직렬화하는 일 |
| 근거 기반 평가자(grounded evaluator) | 문장의 그럴듯함 대신 필요한 간선의 존재로 결과를 점검하는 평가자 |
| 스웜(swarm) | 하나의 그래프를 향해 동시에 일하는 에이전트 무리 |
| 약속 선언(promise declaration) | 작업자가 시작 전에 읽기와 쓰기 범위, 예산을 밝히는 그래프 객체 |
| 불변식(invariant) | 그래프가 언제나 지켜야 하는 규칙. 보관 시점에 다섯 가지를 점검 |
| 브리지(bridge) | 지식 평면과 작업 평면을 잇는 간선. LINK 단계가 기록 |
| 리듀서(reducer) | 여러 작업자의 결과를 합치는 팬인 단계 |

## 3. 이 부의 흐름 요약

8장은 이미 형식이 있는 저장소의 약 70%를 파싱으로 처리하고 나머지 산문만 싼 모델로 추출한 뒤, 강한 모델이 해소를 판정하고 모든 병합을 되돌릴 수 있게 남기는 구축 파이프라인을 세운다. 9장은 그렇게 만든 그래프를 컨텍스트 덤프로 쓰지 않도록 일곱 단계 빌더로 작업별 조각을 꺼내고, 평가자가 간선의 유무로 결과를 점검하게 한다. 10장은 작업자가 여럿이 되어 쓰기가 일어날 때 생기는 중복, 상관된 오류, 순서 문제를 약속, 검증된 쓰기, 리듀서 계약, 다양한 검증으로 다룬다. 11장은 이것을 forge 파이프라인의 모든 단계에 배선하고 LINK와 불변식 점검을 archive에 더하며, 목표와 대체는 자동화하지 않는다고 못 박는다.
