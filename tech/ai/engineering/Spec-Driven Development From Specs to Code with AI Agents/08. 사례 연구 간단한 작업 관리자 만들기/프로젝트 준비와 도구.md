# 프로젝트 준비와 도구

8장은 지금까지 배운 스펙 주도 개발을 AI 통합 프로세스(AIUP)와 Claude Code로 처음부터 끝까지 따라가 보는 실습 장이다. 예제는 Task Manager 저장소다. 일부러 작게 만들었고, 최고의 작업 관리자를 만들려는 것이 아니다. 스펙, 코드, 테스트가 서로 어긋나지 않고 함께 진화하는 모습을 보여 주는 것이 목적이다.

이 장의 목표는 단순하다. 읽고 나면 저장소를 복제하고, 같은 순서를 따라 하고, 약간의 조정만으로 자기 프로젝트에 같은 작업 흐름을 적용할 수 있어야 한다. 이 문서는 그 준비 단계, 곧 기술 스택, 로컬 환경, 열 단계 구성, 도구에 대한 입장, 저장소 구조를 정리한다.

---

## 1. 기술 스택

예제는 업무 애플리케이션에 잘 맞는 Java 스택을 쓴다.

| 요소 | 쓰임 |
|---|---|
| Spring Boot | 애플리케이션 프레임워크 |
| Vaadin | 프런트엔드 |
| jOOQ | 데이터베이스 접근 |
| PostgreSQL | 데이터베이스 |
| Testcontainers | 로컬 데이터베이스 준비 |

## 2. 로컬 환경 준비

실행에는 두 가지가 필요하다.

- Java 25 이상. 어떤 JDK 배포판이든 되고, Eclipse Temurin(adoptium.net)이 무난한 기본값이다. Linux와 macOS에서는 sdkman.io로 Java 버전을 설치하고 관리할 수도 있다.
- Docker. 애플리케이션을 시작하기 전에 Docker가 실행 중이어야 한다. Docker가 꺼져 있으면 Testcontainers가 PostgreSQL을 띄우지 못해 연결 오류로 실패한다.

### 코드 받기와 확인

저장소를 복제하고 폴더로 들어간 뒤 다음 명령으로 설정이 맞는지 확인한다.

```
git clone https://github.com/ai-unified-process/task-manager.git
cd task-manager
./mvnw spring-boot:test-run
```

마지막 명령은 테스트 클래스패스로 애플리케이션을 시작하고, Testcontainers로 PostgreSQL을 띄우고, 브라우저에서 애플리케이션을 연다. 정상이면 로그인 화면이 보인다(원서의 그림 8-1, 그림은 싣지 않는다).

## 3. 열 단계와 Git 태그

실습은 열 단계로 나뉜다. 각 단계는 저장소의 Git 태그와 대응하므로 `git checkout <태그>`로 그 시점의 프로젝트 상태를 정확히 볼 수 있다.

| 단계 | 태그 | 내용 |
|---|---|---|
| 1 | init | 비전과 초기 프로젝트 설정 |
| 2 | requirements | 요구사항 카탈로그 |
| 3 | entity_model | 엔터티 모델과 용어집 |
| 4 | use_cases_diagram | 유스케이스 개요 다이어그램 |
| 5 | scaffolding | 프로젝트 스캐폴딩 |
| 6 | database_migration | 데이터베이스 스키마 마이그레이션 |
| 7 | spec_UC-006 | 첫 유스케이스 스펙 |
| 8 | implement_UC-006 | 유스케이스 구현 |
| 9 | test_UC-006 | 브라우저리스 테스트 |
| 10 | e2e_UC-006 | 종단 간 테스트(Playwright) |

참고(노트 작성자): 원서 추출본의 7~10단계 태그는 `spec_uC-006`처럼 대소문자가 깨져 있다. 뒤쪽 본문의 `git checkout spec_UC-006` 같은 명령을 기준으로 UC를 대문자로 복원했다.

이 열 단계는 크게 네 묶음이다. 1~4단계는 스펙 문서를 쌓는 일이고, 5~6단계는 기술 기반을 만드는 일이며, 7~8단계는 첫 유스케이스를 스펙에서 코드로 옮기는 일이고, 9~10단계는 같은 스펙에서 테스트를 만드는 일이다. 이후 반복 절은 스펙을 먼저 바꾸는 방식을 보여 준다. 이어지는 문서들이 이 묶음 순서를 따른다.

## 4. 도구에 대한 입장

특별한 도구는 필요 없다. 유능한 AI 에이전트, Markdown 파일, Git, 명확한 스펙이면 충분하다. AIUP는 선택 도구와 슬래시 명령을 더하며, 문서는 `https://unifiedprocess.ai/tools.html`에 있다. 이 도구들은 작업 흐름을 바꾸지 않는다. 반복하기 쉽도록 템플릿, 구조, 가드레일을 제공한다.

이 장에서 슬래시 명령은 예시로 보여 줄 뿐이다. 규율 있는 작업 방식을 설명하려는 것이지 프로세스가 특정 명령 이름에 의존한다는 뜻이 아니다. 7장의 마켓플레이스 도구가 여기서 실제로 쓰이는 모습이다.

## 5. 저장소 구조

저장소에는 한 가지 중심 규칙이 있다. `/docs` 폴더가 시스템 행동에 대한 권위 있는 설명을 담는다.

```
/docs
├── vision.md
├── requirements.md
├── entity-model.md
└── use-cases
    ├── UC-001-create-task.md
    ├── UC-002-view-task-list.md
    └── ...
```

구현 코드와 테스트는 `src/main`과 `src/test` 아래에 둔다. 유스케이스 폴더에는 UC-001, UC-002처럼 번호가 붙은 파일이 놓이는데, 7단계에서 나오는 실제 파일 이름 형식은 약간 다르다(다음 문서들에서 다룬다).

---

## 6. 핵심 정리

- 스택은 Spring Boot, Vaadin, jOOQ, PostgreSQL, Testcontainers다. 필요한 것은 Java 25 이상과 Docker이며, Docker가 꺼져 있으면 연결 오류가 난다.
- `./mvnw spring-boot:test-run`으로 로컬 실행을 확인하고, 단계별 상태는 Git 태그로 확인한다.
- 열 단계는 스펙 문서(1~4), 기술 기반(5~6), 첫 유스케이스 스펙과 구현(7~8), 테스트(9~10) 순이다.
- 도구는 선택이고, `/docs`가 시스템 행동의 권위 있는 출처다.
