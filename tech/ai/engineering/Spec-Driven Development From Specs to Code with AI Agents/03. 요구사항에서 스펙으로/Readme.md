# 03. 요구사항에서 스펙으로

이 장은 대화와 워크숍에서 나온 날것의 아이디어를 검토하고 관리할 수 있는 스펙으로 바꾸는 방법을 다룬다. AI 통합 프로세스(AIUP)의 세 가지 핵심 산출물인 요구사항 카탈로그, 엔터티 모델, 시스템 유스케이스를 만드는 법과, AI 도구가 요약, 추출, 분류, 검증을 어떻게 돕는지 설명한다.

작업 관리 앱의 Assign Task 예제로 카탈로그 항목, 엔터티 속성, 유스케이스 구조를 구체적인 값으로 보여 주며, 어느 단계에서나 사람의 검토가 품질 관문이라는 점을 강조한다.

---

## 1. 핵심 요점

- 스펙 주도 개발의 첫 일은 이해관계자의 비공식 대화를 검토·버전 관리가 가능한 스펙으로 바꾸는 것이다.
- 세 핵심 산출물은 요구사항 카탈로그(무엇을, 어떤 제약으로), 엔터티 모델(공통 어휘), 시스템 유스케이스(관찰 가능한 동작)다.
- AI는 워크숍이 끝난 뒤 요약, 추출, 분류를 돕고, 기능 요구사항, 비기능 요구사항, 제약에 안정적인 ID를 붙인다.
- 사람의 검토는 생략할 수 없다. 건너뛰면 잘못된 확신, 숨은 모순, 모호한 동작, 어긋난 자동화, 공유된 이해의 소실이 생긴다.
- 엔터티 모델은 용어집을 대신한다. 유스케이스와 요구사항이 엔터티를 이름으로 참조해 용어가 일관된다.
- 유스케이스는 ID, 행위자, 목표, 사전 조건, 트리거, 주 흐름, 대안·예외 흐름, 사후 조건, 비즈니스 규칙, 연결된 요구사항으로 구성된다.
- 좋은 흐름은 관찰 가능한 단계, 능동태, 갈라지는 단계 번호 참조, 유스케이스당 목표 하나를 지킨다.
- 메타데이터와 ID 참조로 요구사항에서 코드와 테스트까지 추적성을 만들고, AI가 이를 이용해 검증과 일관성 점검을 돕는다.
