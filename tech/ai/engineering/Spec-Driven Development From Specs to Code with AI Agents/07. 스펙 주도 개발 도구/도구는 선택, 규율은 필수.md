# 도구는 선택, 규율은 필수

스펙 주도 개발에는 특별한 도구나 모델링 환경, 독점 플랫폼이 필요하다는 오해가 흔하다. 원서는 그렇지 않다고 못 박는다. 텍스트 편집기, Git, AI 에이전트면 충분하다. 핵심 산출물이 단순하고, 검토할 수 있고, 버전 관리가 되기 때문에 방법이 작동한다. 별도 형식도 없고, 대부분의 개발자가 이미 가진 것 외에 설치할 것도 없다.

그렇다고 도구가 쓸모없다는 말은 아니다. 도구는 작업 흐름을 더 쉽게 만들고, 업계도 따라오기 시작했다. 이 문서는 도구에 대한 기본 태도와 업계의 흐름을 정리한다. 이어지는 문서들이 Amazon Kiro, GitHub Spec Kit, AI 통합 프로세스(AIUP) 마켓플레이스를 차례로 살핀다.

---

## 1. 도구에 대한 기본 태도

원서의 7장 도입은 이 장의 구성을 알려 준다. 최근 몇 해 사이 스펙을 개발의 중심에 다시 놓는 도구가 여럿 나왔고, 이들은 같은 통찰을 공유한다. AI는 모호한 프롬프트보다 구조화된 산출물에서 출발할 때 더 믿을 만하다는 것이다. 새로운 생각은 아니지만 이제 상용 제품과 열린 워크플로에 들어가고 있다.

이 장이 다루는 것은 세 가지다.

- Amazon Kiro와 GitHub Spec Kit 두 도구가 AIUP와 어떤 관계인지.
- 저자가 실제 프로젝트용으로 직접 만든 구현인 AI 통합 프로세스 마켓플레이스. 스펙 주도 워크플로, 지침, 기술 스택별 기능을 묶어 둔 것이다.
- 도구를 고르는 기준과 앞으로의 도구가 갖춰야 할 성질.

## 2. 규모와 상관없이 성립하는 원칙

혼자 일하는 개발자도 Markdown 파일과 AI 에이전트만으로 AIUP를 적용할 수 있다. 규율을 제공하는 것은 스펙이다. 도구가 유용해지는 때는 팀이 커지고, AI 사용이 잦아지고, 불일치가 생기기 시작할 때다. 도구의 일은 방법을 대신하는 것이 아니라 방법을 일관되게 따르기 쉽게 만드는 것이다.

비유하면 달리기 규율은 매일 나가 뛰는 습관이고, 도구는 러닝 시계다. 시계가 없어도 달릴 수 있지만 여럿이 함께 뛰며 기록을 맞추려 할 때 시계가 도움이 된다. 시계가 습관을 만들어 주지는 않는다.

## 3. 업계의 변화

AI 보조 소프트웨어 개발에는 뚜렷한 흐름의 변화가 있다. 초기 도구는 주로 자동 완성과 코드 생성에 집중했다. 새로운 도구는 구조, 검토 가능성, 작업 흐름의 규율을 다시 중심으로 옮기고 있다. 대표 사례가 Amazon Kiro와 GitHub Spec Kit다. 둘은 스타일과 범위가 다르지만 핵심 생각이 같다. AI는 느슨한 프롬프트에서 행동을 지어내는 것이 아니라 스펙에서 일해야 한다는 것이다.

| 시기 | 도구의 초점 |
|---|---|
| 초기 | 자동 완성, 코드 생성 |
| 최근 | 구조, 검토 가능성, 워크플로 규율 |

---

## 4. 핵심 정리

- 스펙 주도 개발은 텍스트 편집기, Git, AI 에이전트만으로 가능하다. 산출물이 단순하고 검토 가능하며 버전 관리되기 때문이다.
- 규율은 스펙에서 나오고, 도구는 그 규율을 팀이 일관되게 따르도록 도울 뿐이다.
- 업계의 도구는 자동 완성 중심에서 구조와 워크플로 중심으로 옮겨 가고 있으며, 공통 통찰은 AI가 구조화된 산출물에서 더 믿을 만하다는 것이다.
