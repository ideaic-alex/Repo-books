# 스펙 주도 개발 도구

이 장은 스펙 주도 개발에 어떤 도구가 필요한지, 혹은 필요하지 않은지를 다룬다. 결론은 텍스트 편집기, Git, AI 에이전트만으로 충분하며 도구는 규율을 일관되게 지키도록 돕는 보조라는 것이다. 이어서 스펙을 중심에 둔 두 도구인 Amazon Kiro와 GitHub Spec Kit, 그리고 저자가 만든 AI 통합 프로세스 마켓플레이스를 살핀다.

마지막으로 상황별로 도구를 고르는 기준, 네 가지 선택지의 비교, 빠르게 변하는 도구 환경에서 눈여겨볼 네 가지 성질을 정리한다.

---

## 1. 핵심 요점

- 스펙 주도 개발에 특별한 도구는 필요 없다. 텍스트 편집기, Git, AI 에이전트면 된다. 규율은 스펙에서 나온다.
- Amazon Kiro는 Requirements.md, Design.md, Tasks.md의 세 산출물로 이뤄진 IDE 중심 워크플로다.
- GitHub Spec Kit은 specify CLI, .specify 디렉터리, 슬래시 명령으로 헌장, 스펙, 계획, 작업, 구현의 순서를 강제한다.
- AIUP 마켓플레이스는 코어 플러그인(aiup-core)과 스택 플러그인(aiup-vaadin-jooq 등), 스킬, 슬래시 명령, MCP 서버 연동으로 이뤄진 프로세스 계층이다.
- MCP 서버는 구현 단계에서 최신 API 지식을 제공해 학습 데이터의 낡음에서 오는 위험을 줄인다.
- 혼자나 소규모는 Markdown과 가이드라인 파일로 시작하고, 팀이 커지면 Spec Kit이나 Kiro를 고려하며, 마켓플레이스는 그 위에 얹는다.
- 좋은 도구의 성질은 열린 산출물 형식, 에이전트 독립성, 검토 가능성, 점진적 도입이다.
