# 규칙 기반 전문가 시스템

이 장은 범용 문제 해결기가 한계에 부딪힌 뒤 도메인 지식을 중심으로 등장한 전문가 시스템을 소개하고, 그중 가장 흔한 형태인 규칙 기반 전문가 시스템을 다룬다. 먼저 IF-THEN 규칙으로 지식을 표현하는 방법을 설명한다. 이어 추론 엔진이 정방향 연쇄와 역방향 연쇄로 규칙을 처리하는 과정과, 규칙끼리 부딪힐 때 쓰는 충돌 해결 전략을 신호등, 환율과 채권, 주식 선택이라는 예로 차례로 따라간다. 그다음에는 전문가 시스템 개발 도구인 CLIPS의 문법으로 같은 예를 코드로 구현하고, XCON 사례로 전문가 시스템을 도입한 효과를 살핀다. 마지막으로 일곱 가지 한계와 검증 문제를 짚는다. 이 한계 가운데 일부를 다이어그램 인터페이스로 풀 수 있으리라는 전망이 다음 장으로 이어진다.

---

## 이 장의 핵심

- 범용 문제 해결기는 장난감 문제에 머물렀고, 1970년대 이후 도메인 지식에 기반한 전문가 시스템이 현실의 복잡한 문제를 풀며 성공을 거두었다.
- 인간 전문가는 규칙(휴리스틱), 과거 사례, 분류 계층, 모델, 패턴 인식, 직관과 창의성의 여섯 방식으로 추론하며, 규칙 기반 시스템은 그중 첫째를 구현한다.
- 규칙은 `IF (조건) THEN (행동)` 형태이고, 객체-값 쌍과 변수, 관계 연산자, AND/OR/NOT으로 표현력을 높인다. MYCIN 규칙은 확신도로 불확실성을 다룬다.
- 기본 구성 요소는 지식 베이스, 추론 엔진, 작업 메모리, 사용자 인터페이스이며, 설명 모듈은 인터페이스의 일부로 본다.
- 정방향 연쇄는 사실에서 결론으로 나아가는 데이터 주도 방식이고, 역방향 연쇄는 가설에서 증거를 찾는 목표 주도 방식이다. 진단형 전문성과 집중된 탐색에는 후자가 유리하다.
- 규칙이 많아지면 서로 어긋나는 권고가 나올 수 있다. 이는 규칙 미세 조정, 우선순위, 제어 전략과 메타규칙, 규칙 특성 기준이라는 네 가지 방법으로 해결한다.
- CLIPS는 사실 목록, 규칙, 추론 엔진으로 이루어진 무료 도구이며 `assert`, `defrule`, `printout`, `bind`, `test`, `salience` 같은 요소로 규칙 기반 시스템을 구현한다.
- XCON은 오류율을 크게 낮추고 처리 시간을 줄인 상업적 성공 사례이며, 성공의 열쇠는 규칙의 수보다 시스템을 조직 안에 자리 잡게 하는 일이었다.
- 대표적인 한계로는 전문성을 끌어내기 어렵다는 점, 지식을 모두 담을 수 없다는 점, 스스로 배우지 못한다는 점, 융통성이 부족하다는 점, 신뢰와 설명이 부족하다는 점, 검증이 어렵다는 점이 있다.
