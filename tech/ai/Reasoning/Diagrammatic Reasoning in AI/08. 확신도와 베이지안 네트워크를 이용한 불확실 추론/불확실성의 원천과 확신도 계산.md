# 불확실성의 원천과 확신도 계산

이 문서는 8장의 도입부와 '확신도(Certainty Factors)' 절의 앞부분을 다룬다. 먼저 인간 전문가와 지능 시스템이 왜 불확실성을 다루어야 하는지, 그 불확실성이 어디서 오는지를 정리한다. 이어 MYCIN에서 비롯된 확신도의 표기법과 해석, 조건을 결합하는 최소·최대 규칙, 여러 규칙이 같은 가설에 영향을 줄 때 쓰는 세 가지 전파 공식을 수치 예제와 함께 따라간다. 저자의 논지는 불확실한 추론이 다이어그램의 도움을 받을 수 있다는 것이며, 이 문서는 그 다이어그램 이전의 계산 규칙에 해당한다.

---

## 1. 왜 불확실성을 다루어야 하는가

사람은 날마다 불확실한 상황에서 결정을 내린다. 문제를 풀 지식 자체가 모자랄 때도 있고, 가진 데이터에 잡음이 많거나 부정확할 때도 있으며, 심하면 데이터가 전혀 없을 때도 있다. 반대로 데이터는 충분한데 그것을 처리하고 분석할 정확한 방법이 없는 경우도 있다. 그런데도 사람은 직관, 창의성, 상상력의 도약, 끈기 같은 수단으로 대개 꽤 괜찮은 결론에 도달한다.

저자는 전문성의 상당 부분이 바로 이 능력, 즉 복잡하고 불확실한 문제에서도 합리적으로 좋은 결정을 내리는 능력이라고 본다. 의사가 좋은 예다. 검사 수치는 부정확할 수 있고, 어떤 증상은 특정 질병을 여러 정도의 확실성으로만 시사한다. 그래도 의사는 환자가 무엇을 앓는지 판단해 치료법을 정해야 한다.

따라서 전문가 시스템(expert system)을 비롯한 어떤 지능 시스템도 불확실한 데이터를 표현하고 처리할 수 있어야 한다. 현실의 데이터는 불완전하고, 모순되고, 잡음이 섞였거나, 아예 빠져 있는 경우가 흔하기 때문이다. 이 능력이 없으면 시스템이 감당할 수 있는 현실 문제의 범위가 크게 줄어든다.

---

## 2. 불확실성의 두 가지 원천

불확실성은 모든 전문 영역에 퍼져 있으며, 그 원천은 크게 두 가지로 나뉜다.

- **불완전한 도메인 지식(imperfect domain knowledge)**: 해당 분야의 이론 자체가 불완전한 경우다. 이때 전문가는 어쩔 수 없이 휴리스틱(heuristic), 곧 경험칙에 의존하며, 그 결과는 만족스럽지만 반드시 최적은 아니다.
- **불완전한 사례 데이터(imperfect case data)**: 지금 다루는 개별 사례의 정보가 부정확하거나 믿기 어려운 경우다.

### 2.1 도메인 지식의 불완전성

규칙 기반(rule-based) 전문가 시스템은 전문 지식을 IF-THEN 규칙의 모음으로 담는다. 지식 엔지니어(knowledge engineer, 시스템을 설계·구현하는 사람)는 각 규칙의 전제와 결론 사이에 명확한 상관관계를 정해 주어야 한다. 그러나 많은 분야에서 이 상관관계는 약하거나 충분히 이해되지 않았다. 과학은 계속 발전하므로 더 강한 경험적 연관이 끊임없이 발견되고 수정된다. 또 같은 문제를 두고 전문가들의 의견이 엇갈리는 분야도 많아서, 여러 전문가의 견해를 하나의 합의된 지식 베이스(knowledge base)로 합치는 일은 큰 과제가 된다.

### 2.2 사례 데이터의 불완전성

데이터가 부정확해지는 이유는 여러 가지다.

1. 센서가 믿을 만하지 않아 정밀한 측정이 불가능하다.
2. 검사 결과가 근사치일 뿐이다.
3. 보고가 주관적이고 모호하다.
4. 증거끼리 서로 모순된다.
5. 사람의 오류와 편향이 있어, 아무리 꼼꼼한 전문가라도 판단이 흐려질 수 있다.

더 정밀한 데이터를 얻을 수 있더라도 현실적으로 그렇게 하기 어려울 때가 있다. 의사가 수술적 방법으로 더 좋은 환자 정보를 얻을 수는 있지만 비용이 크고 환자의 건강을 위협한다. 또 데이터를 더 모으려면 시간이 드는데, 위기 상황에서는 불완전한 정보만으로 빨리 결정해야 하고 엄밀한 분석을 할 여유가 없다.

## 3. 불확실한 추론의 형식과 이 장의 방향

거의 모든 흥미로운 영역에 불확실성이 있으므로 좋은 전문가 시스템은 이를 다룰 수 있어야 한다. 이를 위해 여러 형식이 개발되었다. 퍼지 논리(fuzzy logic), 신뢰 함수 이론(belief function theory, 곧 Dempster-Shafer 증거 이론), 주관적 확률론(베이지안 추론 포함), 그리고 확신도가 대표적이다.

이 장은 그중 널리 쓰이는 두 가지, 확신도와 베이지안 추론에 집중한다. 이 논의를 관통하는 주제는 불확실한 추론이 다이어그램 표현의 도움을 받을 수 있다는 점이다. 저자는 영향 다이어그램과 인과 다이어그램이 확신도 방식과 베이지안 네트워크(Bayesian network) 양쪽에서 추론 과정을 보여 주고, 불확실성이 시스템 안에서 어떻게 전파되는지를 밝혀 준다고 예고한다.

## 4. 확신도의 기원과 규칙 형식

확신도는 두 방식 중 이해하기 쉬운 쪽이라 먼저 소개된다. 이것은 1970년대 MYCIN 개발자들이 불확실한 데이터와 결론을 처리하기 위해 만든 편의적 방법이며, 수학적으로 엄밀히 옳은 방식은 아니라는 점이 처음부터 강조된다. MYCIN은 5장에서 본 규칙 기반 전문가 시스템으로, 세균 감염을 진단하고 치료를 권고했다.

MYCIN의 규칙은 다음 꼴이다. 조건 1이 확신도 x1로 성립하고 조건 2가 x2로 성립하며 ... 조건 n이 xn으로 성립하면, 결론 1이 확신도 y1으로 성립하고 ... 결론 n이 yn으로 성립한다.

- **조건의 확신도 x**: 조건은 보통 검사 결과나 환자 증상 같은 증거를 뜻한다. x는 그 증거가 참이라고 믿는 정도로, 0에서 1 사이의 값이다.
- **결론의 확신도 y**: 결론은 증거가 주어졌을 때의 가설(예: 환자의 병)이다. y는 증거로부터 결론이 따라 나오는 정도이며 -1에서 +1 사이의 값을 가질 수 있다. +1은 모든 조건이 충족되면 결론이 확실히 참이라는 뜻이고, -1은 같은 조건에서 결론이 확실히 거짓이라는 뜻이다.

### 4.1 확신도의 해석 척도

표 8.1은 전문가와의 면담에서 얻은 말을 수치로 옮기는 한 방법을 제시한다.

| 표현 | 확신도 |
|---|---|
| 확실히 아니다 (Definitely not) | -1.0 |
| 거의 확실히 아니다 | -0.8 |
| 아마 아니다 | -0.6 |
| 아닐 수도 있다 | -0.4 |
| 모름(중립) | -0.2 ~ +0.2 |
| 그럴 수도 있다 | +0.4 |
| 아마 그렇다 | +0.6 |
| 거의 확실히 그렇다 | +0.8 |
| 확실히 그렇다 | +1.0 |

예를 들어 심장 전문의가 환자의 HDL·LDL 콜레스테롤 수치와 다른 위험 요인을 보면 콜레스테롤 저하제의 혜택을 볼 것이 거의 확실하지만 100%는 아니라고 말했다고 하자. 지식 엔지니어는 이 발언을 근거로 저하제 권고 규칙에 +0.8을 부여할 수 있다.

## 5. 조건 결합과 규칙 확신도 계산

증거가 불확실하거나 데이터에 잡음이 있을 때 시스템은 어떻게 계산하는가. 저자는 MYCIN 규칙에 가상의 확신도를 붙인 예를 든다.

- 조건 1: 균의 염색 반응이 gramneg (0.9)
- 조건 2: 균의 형태가 rod (0.7)
- 조건 3: 균의 호기성이 aerobic (0.4)
- 결론: 균의 분류가 enterobacteriaceae라는 강하게 시사하는 증거 (0.8)

### 5.1 AND 결합은 최소값

조건들이 AND로 묶이면 확신도의 최솟값을 취한다. 위 예에서는 min(0.9, 0.7, 0.4) = 0.4다. 이유는 연결된 조건 전체에 대한 우리의 확신이 그중 가장 약한 요소만큼만 성립하기 때문이다. 사슬은 가장 약한 고리만큼만 강하다는 비유가 쓰인다.

규칙 전체의 확신도는 전제의 확신도와 결론의 확신도를 곱해 얻는다.

```
CF(규칙의 결과) = CF(전제) × CF(결론)
CF(enterobacteriaceae) = 0.4 × 0.8 = 0.32
```

### 5.2 OR 결합은 최대값

같은 규칙의 조건을 OR로 묶으면 최댓값을 쓴다. 논리합(disjunction)으로 묶인 조건은 그중 가장 강한 요소만큼은 확신할 수 있기 때문이다. 따라서 max(0.9, 0.7, 0.4) = 0.9이고 결과는 다음과 같다.

```
CF(enterobacteriaceae) = 0.9 × 0.8 = 0.72
```

같은 조건 값이라도 AND이면 0.32, OR이면 0.72가 되어 결합 방식에 따라 결론의 확신이 크게 달라짐을 알 수 있다.

## 6. 여러 규칙이 같은 가설에 영향을 줄 때

때로는 둘 이상의 규칙이 하나의 가설에 영향을 준다. 저자는 가설 H에 대한 세 규칙을 가정한다.

```
규칙 1: IF A and B and C   THEN H (CF 0.8)
규칙 2: IF D or E          THEN H (CF 0.9)
규칙 3: IF F               THEN H (CF -1.0)   <- H에 대한 불신
```

규칙 3은 H를 부정하는 증거이므로 확신도가 -1.0이다. 모든 증거 A~F가 제각기 다른 정도로 관찰되었을 때 확신도를 어떻게 합칠까. 한 규칙이 만든 확신도 cf1과 다른 규칙이 만든 cf2를 합치는 데 세 공식이 쓰인다.

### 6.1 세 가지 전파 공식

- **전파식 1 (믿음이 증가할 때, cf1 > 0이고 cf2 > 0)**: `cf = cf1 + cf2 × (1 - cf1)`
- **전파식 2 (불신이 증가할 때, cf1 < 0이고 cf2 < 0)**: `cf = cf1 + cf2 × (1 + cf1)`
- **전파식 3 (모순되는 결론, 두 값의 부호가 반대)**: `cf = (cf1 + cf2) / (1 - min(|cf1|, |cf2|))`

전파식 3에서 |cf1|과 |cf2|는 각각의 절댓값이다. 전파식 1과 2는 같은 방향의 증거가 쌓일수록 확신이 한계값(1 또는 -1)에 가까워지되 넘지는 않도록 만든다. 전파식 3은 상반된 증거가 서로를 상쇄하도록 합을 구하고, 그 크기를 덜 약한 쪽에 맞게 조정하는 역할을 한다.

### 6.2 단계별 계산 예

A(0.8), B(0.4), C(0.6)을 먼저 관찰한다. 규칙 1이 실행되어 다음 값이 나온다.

```
min(0.8, 0.4, 0.6) × 0.8 = 0.4 × 0.8 = 0.32
```

다음으로 D(0.8)와 E(0.9)를 관찰하면 규칙 2가 발화한다.

```
max(0.8, 0.9) × 0.9 = 0.9 × 0.9 = 0.81
```

두 값이 모두 양수이므로 전파식 1로 합친다.

```
0.32 + 0.81 × (1 - 0.32) = 0.87
```

두 규칙이 함께 H에 대한 믿음을 점진적으로 높여 확신도가 약 0.87이 되었다. 끝으로 F(0.6)를 관찰하면 규칙 3이 실행된다.

```
0.6 × (-1.0) = -0.6
```

이 값은 앞의 0.87과 부호가 반대이므로 전파식 3을 적용한다.

```
(0.87 + (-0.6)) / (1 - min(0.87, 0.6)) = 0.27 / 0.4 = 0.675
```

예상대로 반대 증거가 들어와 H의 확신도가 0.87에서 0.675로 내려갔다. 이 세 규칙 예제는 다음 문서에서 다이어그램으로 다시 표현된다.
