# 불확실성과 확신도 기초

인간 전문가는 지식이 부족하거나 데이터가 부정확해도 그럴듯한 결정을 내려야 한다. 전문가 시스템도 같은 상황에 놓이므로 불확실한 정보를 표현하고 처리하는 능력이 필요하다. 이 문서는 불확실성이 어디서 생기는지, 이를 다루는 기법에는 무엇이 있는지, 그중 가장 단순한 확신도가 어떻게 정의되는지를 정리한다.

---

## 1. 불확실성의 두 가지 원천

- **불완전한 영역 지식(imperfect domain knowledge)**: 영역의 이론 자체가 미완성이라서 전문가가 휴리스틱(경험칙)에 기대야 하는 경우이다. 규칙 기반 전문가 시스템에서 지식 엔지니어는 규칙의 전제와 결론 사이에 확정적인 상관관계를 부여해야 하지만, 실제로는 그 상관관계가 약하거나 불분명하다.
- **의견 충돌**: 전문가마다 해법이 달라 여러 전문가의 견해를 하나의 합의된 지식 베이스로 합치기 어렵다.
- **불완전한 사례 데이터(imperfect case data)**: 센서의 부정확성, 근사치에 불과한 검사 결과, 주관적이고 모호한 보고, 서로 모순되는 증거, 사람의 오류와 편향 등이 원인이다.
- **더 정확한 데이터를 얻기 어려운 현실**: 침습적 검사처럼 비용과 위험이 크거나, 위기 상황처럼 시간이 없어서 불완전한 정보로 빠르게 결정해야 하는 경우가 많다.

---

## 2. 불확실 추론의 여러 형식

- **주요 형식(formalism)**: 퍼지 논리(fuzzy logic), 믿음 함수 이론(Dempster-Shafer 증거 이론), 주관적 확률론(베이지안 추론 포함), 확신도(certainty factor)가 개발되어 있다.
- **이 장의 초점**: 이 가운데 널리 쓰이는 확신도와 베이지안 추론 두 가지를 다룬다.
- **다이어그램의 역할**: 두 방식 모두 영향 다이어그램과 인과 다이어그램으로 추론 과정을 보여 줄 수 있고, 불확실성이 시스템 안에서 어떻게 전파되는지를 눈으로 확인하게 해 준다.

---

## 3. 확신도의 정의

- **기원**: 확신도는 1970년대 MYCIN 개발자들이 만들었다. MYCIN은 세균 감염을 진단하고 치료를 권고한 규칙 기반 전문가 시스템이며, 확신도는 수학적으로 엄밀하지는 않지만 편리한 방법으로 고안되었다.
- **규칙 형식**: 규칙의 조건부는 증거(검사 결과, 증상)를, 결론부는 가설(예: 환자의 질병)을 나타낸다. 조건과 결론 각각에 확신 정도가 붙는다.
- **조건의 값(`x`)**: 증거가 참이라고 믿는 정도로, 0에서 1 사이의 값이다.
- **결론의 값(`y`)**: 증거가 모두 충족될 때 결론이 따르는 정도로, -1에서 +1 사이의 값이다. +1은 결론이 확실히 참, -1은 확실히 거짓을 뜻한다.
- **값의 부여**: 도메인 전문가를 면담하여 값을 정한다. 예를 들어 심장 전문의가 "거의 확실하지만 100%는 아니다"라고 말하면 지식 엔지니어는 콜레스테롤 약물 권고 규칙에 +0.8을 부여할 수 있다.

---

## 4. 확신도 해석 표

| 해석 | 확신도 |
|---|---|
| 확실히 아님 | -1.0 |
| 거의 확실히 아님 | -0.8 |
| 아마 아님 | -0.6 |
| 어쩌면 아님 | -0.4 |
| 알 수 없음(중립) | -0.2 ~ +0.2 |
| 어쩌면 그렇다 | +0.4 |
| 아마 그렇다 | +0.6 |
| 거의 확실히 그렇다 | +0.8 |
| 확실히 그렇다 | +1.0 |

- **중립 구간의 활용**: 확신도가 -0.2에서 +0.2 사이이면 의미가 없는 구간으로 보아, 해당 목표를 탐색 공간에서 제외하는 근거로 쓰기도 한다.
