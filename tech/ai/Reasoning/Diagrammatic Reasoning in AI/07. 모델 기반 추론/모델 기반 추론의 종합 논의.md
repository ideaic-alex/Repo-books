# 모델 기반 추론에 대한 종합 논의

이 문서는 7장의 결론에 해당하는 절이다. 저자는 진단과 네트워크 설계라는 두 응용을 비교해 공통 기반을 짚고, 규칙 기반 전문가 시스템과 달라서 얻는 이점 세 가지를 정리한다. 이어서 모델 기반 추론이 만능이 아니라는 한계, 규칙 기반 추론과 결합할 가능성, 응용 사례와 의학 진단의 전망을 다룬다.

---

## 1. 두 응용의 비교와 공통 기반

이 장은 모델 기반 추론의 두 가지 응용을 차례로 다루었다.

- **진단 응용**: 다이어그램을 이용해 여러 구성 요소 중 어느 것이 기기나 시스템의 오작동을 일으켰는지 찾는다. 예측한 동작과 실제 동작 사이의 불일치에서 출발해 구성 요소를 체계적으로 훑으며 원인을 찾으므로, 뒤로 거슬러 가는 방식이다.
- **네트워크 설계 응용**: 더 동적이다. 새 다이어그램을 만들어 내고, 모델 기반 추론이 이를 벤치마크로 평가한다. 로그넷에서 벤치마크는 네트워크 비용과 고객 서비스 수준이다. 설계 공간을 탐색해 더 나은 설계를 찾으므로 앞으로 나아가는 방식이다(로그넷에서는 통합과 분산 후보를 탐색한다). 휴리스틱이 없으면 네트워크가 커질수록 설계 공간이 급격히 커져서 계산을 감당할 수 없게 된다.

두 응용은 성격이 다르지만 바탕에는 같은 것이 있다. 둘 다 어떤 종류의 다이어그램에서 출발하고, 다이어그램이 나타내는 구조를 가지고 추론한다. 다이어그램은 구조를 서술하는 데 그치지 않고 어려운 문제의 해를 추론하는 데 쓰인다. 저자는 이것을 모델 기반 추론이 존재하는 이유로 본다. 시스템 구조를 나타내는 다이어그램이 문제 풀이를 돕는다는 것이다.

---

## 2. 규칙 기반 접근과의 차별점

이 장 첫머리에서 모델 기반 추론은 규칙 기반 전문가 시스템과 다른 접근이라고 했다. 어떤 문제 부류에서는 도메인 지식과 전문성을 담은 IF-THEN 규칙을 일일이 나열하기가 매우 어렵다.

- 규칙 기반 진단 시스템의 설계자는 도메인의 모든 경우를 놓치기 쉽다. 가능한 모든 증상과 고장의 조합을 미리 생각해서 규칙으로 부호화해야 하기 때문이다.
- 모델 기반 추론의 중요한 이점은 모든 가능성을 미리 열거하지 않고도 도메인을 더 포괄적으로 다룰 수 있다는 점이다.
- 실제로 많은 모델 기반 시스템이 설계자가 예상하지 못한 새로운 고장을 찾아내고 새로운 해법을 내놓는다.

---

## 3. 모델 기반 추론의 주요 이점

1. **시스템의 일관성 증대**: 모델 기반 추론은 복잡한 전문가 시스템을 하나로 묶는 기반이 될 수 있다. 다이어그램으로 표현한 도메인 모델을 중심으로 시스템을 구성하면 더 조직적이고 일관되게 개발할 수 있고, 관련된 여러 문제를 하나의 공통 틀로 묶을 수 있다.
2. **일반성의 힘**: 구조와 행동의 한 부류 전체에 적용된다. 문제 영역의 개별 사례마다 규칙을 따로 쓸 필요 없이, 큰 부류의 구조와 행동에 대한 규칙을 쓸 수 있다. 이 점은 전문가 시스템이 능력을 확장하려 할 때 원래 문제와 매우 가까운 문제에서도 무너지는 취약성(brittleness) 문제를 일부 해소할 수 있다.
3. **그래픽 사용자 인터페이스 지원**: 모델 기반 시스템은 복잡한 도메인을 여러 층위로 기술할 수 있는 강력한 그래픽 인터페이스를 활용하는 경우가 많다. 사용자는 그래픽 모델의 구성 요소를 눌러 더 세밀한 설명을 보거나, 한 단계 올라가 상위 수준의 시스템 설명을 볼 수 있다. 그만큼 지능형 시스템과의 상호작용이 사람에게 자연스러워진다.

---

## 4. 모델 기반 추론의 한계

모델 기반 추론이 항상 우월하며 규칙 기반 추론에서 한 단계 진화한 것이라고 결론짓기 쉽다. 그러나 저자는 그런 쉬운 결론을 경계한다. 모델 기반 추론은 모든 문제와 도메인에 맞지 않고, 경우에 따라서는 오히려 해롭다. 전문성이 필요한 모든 문제를 푸는 만병통치약이 아니다. 문제 부류에 따라 잘 맞지 않는 경우가 두 가지 있다.

- **모델링하기에 너무 어려운 시스템**: 여러 구성 요소 사이에 미묘한 상호작용 효과가 있어서, 모델 구조만으로는 시스템 동작을 예측하기가 불가능할 수 있다. 이때는 지식을 IF-THEN 규칙으로 담는 편이 훨씬 쉽다.
- **너무 단순한 도메인**: 모델을 쓰는 것이 과잉이 된다. 규칙을 열거하는 편이 전문성을 훨씬 쉽고 간결하게 담는다.

---

## 5. 두 접근의 결합과 현재의 추세

이 장과 앞 장들에서는 모델 기반 추론과 규칙 기반 전문가 시스템을, 전문가 지식을 표현하는 서로 구분되는 두 기법으로 소개했다. 하지만 둘을 통합한 전문가 시스템을 만들 수도 있다. 한쪽을 개발한다고 해서 다른 쪽이 배제되는 것은 아니다.

- 예를 들어 설계자는 문제 영역의 기본 사례에는 모델 기반 추론을 쓰고, 그 사례들에 규칙을 더해 다듬을 수 있다.
- 결합한 시스템은 한 기법만 쓴 시스템보다 강력하다.
- 이는 오늘날 AI의 추세이기도 하다. 여러 AI 기법을 한 프로그램 안에 넣어 더 강력한 응용을 만든다.

---

## 6. 응용 사례와 의학 진단의 전망

이 장에서 다루지 못한 모델 기반 추론의 가능성은 매우 넓다. 최근에는 다양한 영역에서 문제 풀이용 응용이 개발되었다. 원문이 드는 예는 다음과 같다.

- 산업용 가스터빈의 고장 진단
- 제1형 당뇨병 관리 지원
- VHDL 프로그램의 소프트웨어 버그 위치 파악
- 자동 교육 시스템에서 학습자 행동의 모니터링과 진단

이런 시스템은 모델 기반 추론만 쓰지 않고 사례 기반 추론, 시간 추론, 확률적 추론 등을 함께 쓰는 경우가 많다. 이는 모델 기반 추론이 더 큰 지능형 시스템 안에 내장되는 일이 잦다는 것을 다시 보여 준다.

저자가 가장 매력적인 가능성으로 꼽는 것은 의학의 질병 진단이다. 모델 기반 추론은 의사가 질병의 밑바탕에 있는 인과 메커니즘을 더 잘 이해하도록 도울 수 있다. 환자의 병을 설명하는 인과 다이어그램과 모델을 쓰는 그래픽 인터페이스도 만들 수 있다. 예를 들어 모델 기반 추론으로 다음과 같은 프로그램을 생각할 수 있다.

- 질병 과정의 세부를 추론한다.
- 한 질병이 다른 질병을 어떻게 바꾸는지 파악한다.
- 치료와 약물이 환자에게 미치는 효과를 이해한다.
- 질병 자체의 원인이 무엇인지 가려낸다.

저자는 모델 기반 추론의 가능성이 무궁무진하고 유망하며, 혁신적인 AI 응용을 개발하고 확산하는 데로 이어질 수 있다고 맺는다.

## 7. 장 전체의 정리표

### 7.1 진단 응용과 설계 응용

| 비교 항목 | 모델 기반 진단 | LogNet 네트워크 설계 |
|---|---|---|
| 출발점 | 예측과 관찰 사이의 불일치 | 현재 네트워크 다이어그램과 사용자 목표 |
| 추론 방향 | 결과에서 원인으로 거슬러 감 | 설계 공간에서 후보를 앞으로 생성 |
| 핵심 연산 | 용의자 생성, 면죄, 교집합, 검증 | 통합과 분산 후보 생성, 벤치마크 평가 |
| 판단 기준 | 어느 컴포넌트가 원인인가 | 네트워크 비용과 고객 서비스 수준 |
| 계산 부담 | 용의자 집합이 규칙으로 빨리 줄어듦 | 후보 수가 커져 휴리스틱이 필요 |
| 공통점 | 다이어그램이 나타내는 구조로 추론함 | 다이어그램이 나타내는 구조로 추론함 |

### 7.2 규칙 기반과 모델 기반

| 비교 항목 | 규칙 기반 | 모델 기반 |
|---|---|---|
| 지식의 형태 | 증상과 고장을 잇는 IF-THEN 연상 | 구조와 행동에 대한 모델 |
| 커버리지 | 미리 열거한 경우에 한정 | 열거하지 않은 경우까지 체계적으로 다룸 |
| 새로운 고장 | 놓치기 쉬움 | 찾아낼 가능성이 있음 |
| 적합한 상황 | 모델링이 너무 어려운 시스템, 너무 단순한 도메인 | 구조가 분명하고 상호작용을 예측할 수 있는 시스템 |

- 두 표가 보여 주듯, 저자는 모델 기반 추론을 규칙 기반의 대체물이 아니라 보완재로 본다. 그래서 기본 사례는 모델로 다루고 예외는 규칙으로 다듬는 결합 설계를 말한다.
- 이 장 전체의 흐름은 이렇다. 구조와 행동을 함께 표현하는 모델에서 출발해, 거꾸로 추적하는 진단과 앞으로 탐색하는 설계라는 두 응용을 거쳐, 장점과 한계를 함께 짚는 균형 잡힌 결론에 이른다.
