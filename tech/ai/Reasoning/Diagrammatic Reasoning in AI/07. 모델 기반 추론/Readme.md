# 모델 기반 추론

7장은 시스템의 구조와 행동을 함께 표현하는 모델로 문제를 푸는 모델 기반 추론(model-based reasoning)을 다룬다. 저자는 IF-THEN 규칙만으로 만든 전문가 시스템이 경험에서 얻은 연관에 갇혀 새로운 고장을 놓친다는 점에서 출발한다. 그래서 구조에서 행동을 끌어내는 접근이 더 체계적이고 포괄적이라고 주장한다. 응용은 두 가지를 차례로 보인다. 하나는 예측과 관찰이 어긋나는 곳에서 거꾸로 원인 컴포넌트를 찾는 진단이다. 다른 하나는 물류 네트워크 설계 시스템 LogNet이 후보 설계를 앞으로 만들어 가며 평가하는 설계다. 장의 끝에서는 휴리스틱 탐색으로 조합 폭발을 줄이는 방법을 설명하고, 모델 기반 추론의 이점과 한계를 논의한다.

---

## 이 장의 핵심

- **구조와 행동의 결합**: 다이어그램은 구조만, 휴리스틱은 행동만 기술한다. 모델 기반 추론은 이 둘을 함께 기술한다.
- **모델의 구성요소**: 시스템을 재료(materials), 컴포넌트(components), 도관(conduits)으로 기술한다. 인접성 원리에 따라 직접 연결된 컴포넌트끼리만 서로 작용한다.
- **규칙 기반의 빈틈 메우기**: 증상과 고장을 짝지은 규칙은 열거된 경우만 다룬다. 구조 기반 추론은 새로운 고장과 기기 변형에도 대응할 수 있다.
- **진단의 두 단계**: 첫째는 가설 생성(규칙 1~5)으로, 불일치에서 용의자를 만든다. 둘째는 가설 검증으로, 탐침이나 다른 입력으로 용의자를 가려낸다. 이때 고장 은폐(fault masking)를 조심해야 한다.
- **LogNet의 벤치마크**: 네트워크 비용(운송비, 창고비, 제곱근 규칙 기반 재고 유지비)과 고객 서비스 수준(가중 평균 고객-창고 거리)으로 설계를 평가한다.
- **통합과 분산의 일곱 절차**: 통합 1~3과 분산 1~4는 비용과 서비스의 상충 관계에 각기 다른 비중을 두고 후보를 추천한다.
- **시각적 대화형 모델링**: 사용자가 다이어그램을 직접 고치고 벤치마크를 요청하며 설계를 반복해서 다듬는다.
- **휴리스틱 탐색**: 가까운 창고만 통합하기, 수요 중심지 근처에 창고 두기, 소량 고객 근처 창고 정리하기로 후보를 줄인다. 다만 최적해는 보장되지 않는다.
- **이점과 한계**: 일관성, 일반성, 그래픽 인터페이스 지원이 이점이다. 모델링이 너무 어렵거나 너무 단순한 도메인에는 맞지 않으며, 규칙 기반 방식과 결합할 수도 있다.
