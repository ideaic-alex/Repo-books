# 모델의 역할과 쓰임새

이 책은 시맨틱 웹의 모델링을 다룬 책이다. 그렇다면 큰 그림 안에서 모델은 무슨 일을 할까. 이 문서는 책의 표지 그림을 빗댄 설명, RDF·RDFS·OWL의 부품을 조립하는 기술로서의 모델링, 그리고 이미 성숙 단계에 들어선 실제 활용 사례를 정리한다.

---

## 1. 웹 페이지 뒤에는 더 많은 데이터가 있다

우리가 매일 보는 웹은 주로 사람이 브라우저로 읽는 하이퍼텍스트 페이지로 이루어져 있다. 그런데 많은 페이지 뒤에는 화면에 보이는 것보다 훨씬 많은 정보를 담은 데이터베이스가 있다. 이 정보 중 중요한 양을 전 세계적으로 통합된 하나의 전체로 쓰려면, 한곳의 정보가 다른 곳의 정보와 어떻게 관련되는지를 밝혀 주는 방법이 필요하다.

시맨틱 웹에서 모델이 맡는 일이 바로 그것이다. 모델은 여러 출처의 정보 사이의 관계를 설명하는 중개자 역할을 한다.

| 구분 | 사람이 보는 웹 | 모델이 있는 웹 |
|---|---|---|
| 보이는 것 | 화면에 나온 페이지 | 페이지 뒤의 데이터와 그 관계 |
| 읽는 주체 | 사람 | 사람과 기계 |
| 출처 간 연결 | 사람이 직접 비교 | 모델이 관계를 기술 |

---

## 2. 표지 그림이 말하는 것: 설계 편람

책은 독자에게 표지를 보라고 한다. 표지는 대수층(aquifer)을 다루는 공학 편람이다. 이 편람은 수로 계통을 조절하는 관, 덕트, 수로 같은 요소에 대한 정보를 주어서, 기술자가 동적인 유체 시스템의 부품을 이해하게 해 준다. 편람이 최종 설계를 알려 주지는 않지만, 부품들을 어떻게 끼워 맞추면 특정 공학 목표를 이룰 수 있는지에 대한 통찰은 준다. 창의적인 기술자는 이 정보를 써서 자기 필요에 맞는 흐름 시스템을 만든다.

이 책도 같다. 표준 언어인 RDF, RDFS, OWL은 기술자가 동적인 행동을 하는 모델을 만들 때 쓰는 부품의 틀을 준다.

| 부품 | 모델 안에서 하는 일 |
|---|---|
| subClassOf, subPropertyOf | 정보가 모델 안에서 어떻게 흘러가는지 지정한다 |
| owl:Restriction | 모델의 다른 부분들 사이의 복잡한 관계를 지정한다 |

읽는 법: 앞의 것은 정보를 위아래로 흘려보내는 배관, 뒤의 것은 복잡한 연결을 만드는 정교한 부속품에 해당한다. 이는 책의 비유를 풀어 쓴 해석이다.

"실전(in the wild)" 장들의 사례는 현업 온톨로지 전문가들이 이 부품을 조립해 특정 목표를 이루는 복잡한 동적 모델을 만든 모습을 보여 줬다. 책은 이것을 시맨틱 웹 모델링의 기술(craft)이라고 부른다. 구성 요소를 쓸모 있게 조합해서 시맨틱 웹의 데이터가 흘러 지나가는 동적 시스템을 만드는 일이다.

---

## 3. 이미 쓰이고 있다

시맨틱 웹 표준은 이미 방대한 출처의 데이터를 잇고 다양한 응용으로 모으는 데 쓰이고 있다. 책은 이 기반 시설이 성숙 단계에 이르러, 많은 산업이 분산 그래프 데이터 시스템을 장기 정보 시스템의 중추로 믿고 쓸 수 있게 되었다고 본다.

| 사례 | 내용 |
|---|---|
| 검색 엔진의 지식 그래프(knowledge graph) | 한 주제에 대해 아는 모든 정보를 모아 사용자 서비스를 개선한다 |
| 각국 정부의 공개 데이터 | 수백만 개의 데이터셋을 공개했고, 상당수는 재사용과 연결을 위해 이미 RDF로 변환되었다 |
| DBpedia와 성장하는 Wikidata | 도서관, 박물관, 그 밖의 소장품 관리 기관이 방대한 지식을 공유하게 한다 |

읽는 법: 세 사례는 각각 기업의 서비스, 공공 데이터, 문화 기관의 지식 공유라는 서로 다른 영역이다. 같은 기술이 여러 영역에서 쓰인다는 점이 요지다.

---

## 4. 투명성과 함께 오는 숙제

모든 강력한 기술처럼 웹과 그 하위 기능들도 새로운 가능성과 함께 이해하고 피하거나 극복하거나 감수해야 할 어려움을 가져온다. 시맨틱 웹은 전례 없는 규모의 정보 공유와 투명성을 가능하게 했다. 다만 이 투명성이 다음 문서에서 다룰 데이터 소유와 사생활 문제와 맞닿아 있다.
