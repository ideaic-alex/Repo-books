# 규칙과 RIF

OWL 2를 써도 OWL의 표현력에는 여전히 한계가 있다. 그 한계 중 일부는 데이터 관리 목적이라면 규칙(rules)으로 푸는 편이 낫다. 웹을 위한 규칙 언어가 RIF(Rule Interchange Format)다. 이 문서는 규칙이 무엇을 잘하는지, 그렇다면 왜 규칙만 쓰지 않고 OWL 같은 모델링 언어를 따로 두는지, 둘을 어떻게 이어 붙이는지 정리한다.

---

## 1. 규칙이 잘하는 일

규칙 기반 시스템은 전문가 시스템(Expert System) 시절부터 이어진 오랜 전통이 있고, 지금도 업무 로직 응용에서 흔히 쓰인다. 규칙으로 데이터를 처리하는 유용한 알고리즘들이 오래전부터 알려져 있고, 상당수는 아주 효율적으로 다듬어졌다.

이 장에서 본 OWL의 한계 중 많은 것을 규칙으로 해결할 수 있다.

| OWL의 어려움 | 규칙으로는 |
|---|---|
| 다중 부분 속성(삼촌의 정의 등) | 쉽게 표현된다 |
| 복수 키(여러 속성 조합으로 동일성 판단) | 규칙으로도 표현할 수 있다 |
| 불확실성(같은 사람일 가능성이 높다 정도의 정보) | 규칙에서 불확실성을 다루는 여러 접근이 있고, 연구와 실용 사례가 많아 비교적 잘 알려진 문제다 |

표를 읽는 법은, OWL이 표준으로 정하지 못한 부분을 규칙 쪽에서는 이미 다룬 경험이 쌓여 있다는 것이다.

## 2. 그런데 왜 규칙만 쓰지 않는가

이쯤에서 자연스러운 질문이 생긴다. 규칙 기술이 성숙하고 잘 알려졌다면 왜 시맨틱 웹 모델링에서 규칙이 더 큰 역할을 맡지 않는가. OWL 같은 모델링 언어가 왜 필요한가. 더 크게 물으면, 왜 소프트웨어 시스템 일반이 규칙으로 더 많이 작성되지 않는가.

책은 이 문제를 충분히 다룰 수 없다고 하면서 OWL과 시맨틱 웹에 관련된 답의 윤곽을 제시한다.

### 2.1 규칙 기반 개발은 생산성이 낮았다

규칙 기반 시스템의 역사에서 얻은 교훈은, 이런 시스템에서 소프트웨어 공학을 하기가 모듈화된 절차적 언어에서보다 어렵다는 것이다. 이것이 규칙 기반 시스템의 본질적 성질인지는 분명하지 않다. 하지만 규칙 기반 프로그래머가 기존 방식의 프로그래머만큼 생산성을 내지 못했다는 점은 부정할 수 없다.

### 2.2 시맨틱 웹에서 이것이 문제가 되는 이유

앞 문서에서 OWL 2 DL이 아닌 하위 집합을 쓰는 것을 옹호하는 근거는, 소프트웨어 공학의 규율 덕분에 판정 가능성이 모델 설계에서 사실상 중요하지 않다는 것이었다. 프로그램을 디버깅하듯 모델도 디버깅하면 된다는 논리다. 규칙 기반 시스템에서는 소프트웨어 공학이 이 같은 뒷받침을 해 주지 못한다. 제약 없는 규칙 시스템은 FORTRAN이나 Java 같은 범용 언어와 똑같이 판정 불가능하다.

| 비교 | OWL(실행 가능한 하위 집합) | 제약 없는 규칙 시스템 |
|---|---|---|
| 판정 가능성 | 실행 가능한 방식에서는 보장을 요구하지 않는다 | 판정 불가능하다 |
| 이를 메워 주는 것 | 소프트웨어 공학 규율로 모델을 디버깅 | 규칙 개발에서는 이 공학적 뒷받침이 약했다 |
| 개발 생산성 | 모델을 프로그램처럼 다듬어 가며 쓴다 | 절차적 언어보다 낮았다 |

표의 요점은, 판정 가능성이 없어도 공학 규율이 받쳐 주면 쓸 수 있는데 규칙 기반 개발은 그 규율을 충분히 갖추지 못했다는 것이다.

## 3. 둘의 장점을 모두 얻는 길

양쪽의 장점을 다 취할 수는 없을까. 웹 지향 규칙 언어가 OWL과 잘 어우러질 수 있을까. 책의 답은 가능하다는 것이며, OWL 2 RL과 RIF의 개발에서 바로 그것을 볼 수 있다고 한다. 둘이 함께 OWL과도, 더 넓은 규칙 기반 기술과도 일관성 있는 틀을 제공한다.

| 구성 | 역할 |
|---|---|
| OWL 2 RL | 규칙 시스템이 충실히 처리할 수 있는 OWL의 하위 집합 |
| RIF | 규칙 기반 시스템들이 서로 정보를 주고받는 시맨틱 웹의 표준 형식 |
| 둘을 합친 틀 | OWL과 더 넓은 규칙 기술 모두와 일관성을 이룬다 |

## 4. 정리

- OWL 2를 써도 남는 한계는 규칙으로 보완한다. 다중 부분 속성, 복수 키, 불확실성이 대표적이다.
- 규칙은 오래된 기술이어서 알고리즘과 사례가 풍부하다.
- 하지만 규칙 기반 개발은 생산성이 낮았고 제약 없는 규칙은 판정 불가능하다. 그래서 OWL 같은 모델링 언어가 따로 필요하다.
- OWL 2 RL과 RIF가 둘을 잇는 다리다.
