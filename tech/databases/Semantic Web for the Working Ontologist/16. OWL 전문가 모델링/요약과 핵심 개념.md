# 요약과 핵심 개념

이 장은 지금까지 배운 OWL 모델링으로 부족할 때 꺼내 쓰는 고급 기능과 그 배경을 다뤘다. 마지막으로 장 전체를 한 번에 정리하고, 이 장에서 새로 나온 개념을 표로 모은다.

---

## 1. 장 요약

OWL은 살아 있는 언어로 볼 수 있다. 웹과 상거래에서 쓰이는 방식에 맞춰 계속 자란다. 언어의 부족한 점이 드러나면 그것을 수용하도록 체계가 성장한다. 성장은 세 가지 모습으로 나타난다.

| 성장 방식 | 예 |
|---|---|
| 언어에 구성 요소를 더한다 | 다중 부분 속성 |
| 다른 시스템과 연결한다 | 규칙 |
| 언어의 하위 집합을 정한다 | OWL 2 프로파일 |

표를 읽는 법은, 언어가 부족하다고 해서 모든 것을 언어 안에 밀어 넣지 않고 기능 추가, 외부 연결, 부분 집합 정의라는 서로 다른 길로 대응한다는 것이다.

## 2. 장의 흐름 다시 보기

1. OWL 2는 OWL 1.0과 하위 호환이라서 지금까지 배운 모델링이 모두 유효하다.
2. 네 하위 집합은 같은 구성 요소를 쓰며, 모델링 철학이 다르다. 하나는 증명 가능한 모델, 다른 하나는 실행 가능한 모델이다.
3. 판정 가능성을 지키려는 OWL DL은 타블로 알고리즘으로 모든 함의를 유한 시간 안에 찾는다.
4. 실행 가능한 모델에서는 모델을 프로그램처럼 디버깅하므로, 규칙 시스템, 데이터로그, 데이터베이스, SPARQL 같은 다양한 처리기를 쓸 수 있다.
5. 메타모델링은 펀닝보다 클래스-개체 거울 패턴을 권한다.
6. 다중 부분 속성과 owl:hasKey는 OWL 2의 새 기능이고, 불확실성은 아직 표준이 없다.
7. 규칙과 RIF는 OWL의 한계를 보완하며, OWL 2 RL이 둘을 잇는다.

## 3. 핵심 개념

| 개념 | 뜻 |
|---|---|
| OWL | Web Ontology Language. 이 책의 모든 구성 요소와 그 이상을 포함한다 |
| OWL 2 DL | 판정 가능성을 보장하도록 제한한 OWL의 하위 집합. 모든 구성 요소를 허용하되 쓰는 방법에 제한을 둔다 |
| OWL 2 EL | 계산 복잡도를 개선하도록 제한한 OWL의 하위 집합 |
| OWL 2 RL | 규칙 처리기와 호환되도록 제한한 OWL의 하위 집합 |
| OWL 2 QL | 데이터베이스 질의와 호환되도록 제한한 OWL의 하위 집합 |
| RIF | 규칙 교환 형식(Rule Interchange Format). 규칙 기반 시스템끼리의 상호 운용을 위한 시맨틱 웹의 표준 형식 |
| 메타모델링 | 모델을 설명하는 모델. 보통 클래스를 개체로 다뤄야 한다 |
| 다중 부분 속성 | 속성들을 줄줄이 이어 붙여 새 속성을 만드는 것 |
| 복수 역함수 속성(Multiple Inverse Functional Properties) | 여러 속성의 값이 일치하는 것으로 개체를 유일하게 식별하는 것 |

표의 마지막 줄에서 보듯, 복수 역함수 속성은 앞 문서에서 owl:hasKey로 다룬 기능이다. 같은 클래스의 두 구성원이 지정한 속성 값을 모두 공유하면 같은 개체로 판단한다.

## 4. 이 장에서 기억할 한 가지

고급 기능을 새로 배운다고 해서 기존 지식을 바꿀 필요는 없다. 모든 프로파일은 같은 자원을 쓰고, OWL 2는 OWL 1.0과 호환된다. 처리 기술이 정해졌다면 그 기술에 맞는 프로파일을 고르고, OWL로 표현하기 어려운 것은 규칙으로 보완한다.
