# 웹의 온톨로지 전체 종합

이 장은 지금까지 배운 RDF, RDFS-Plus, OWL의 도구가 실제 웹의 큰 온톨로지에서 어떻게 함께 쓰이는지 보여 주는 종합편이다. 모든 온톨로지를 나열하는 대신 단위를 다루는 QUDT, 생물과 생의학을 다루는 OBO(그중 CHEBI), 금융을 다루는 FIBO 세 가지를 골라 설계 방식과 쓰임새를 자세히 본다. 그 전에 큰 모델을 쪼개 관리하는 owl:Ontology와 owl:imports부터 짚는다.

세 사례는 분야가 달라도 표준 개체에 모호하지 않은 이름을 주고 여러 시스템의 정보를 맞춰 준다는 점이 같다. 다만 데이터를 얼마나 담는지, 구조를 얼마나 풍부하게 서술하는지는 서로 크게 다르다.

---

## 1. 핵심 요점

- owl:Ontology와 owl:imports는 추론 의미가 없고, 사람이 큰 모델을 모듈로 나눠 관리하게 하는 도구다. 순환 import는 이미 읽은 파일을 건너뛰면 안전하다.
- QUDT는 수량 종류, 단위, 차원을 분리해 단위에 전 세계 공통 URI를 주고, 변환과 차원 검증을 가능하게 한다.
- 단위 변환은 곱셈값과 오프셋으로 SPARQL 쿼리를 만들 수 있고, SHACL 확장으로 함수처럼 이름을 붙이면 Schema.org 가격 비교에 쓸 수 있다.
- 차원 분석은 차원 벡터를 더해 공식 양변이 같은지 보는 것이며, FILTER NOT EXISTS와 GROUP BY를 써서 하나의 ASK 쿼리로 만들 수 있다.
- CHEBI는 모든 개념을 클래스로 두고 someValuesFrom 제약으로 잇는다. 이 덕에 OWL 추론이 복잡한 질의를 대신 풀지만, 샘플 식별에는 쓸 수 없다.
- 같은 정보를 SKOS로 단순하게 옮기면 모델은 쉬워지고 쿼리는 어려워진다. 모델과 쿼리 중 어디에 일을 맡길지는 맞교환이다.
- BridgeDb는 데이터셋 사이의 대응을 링크 세트로 공개한다. 화학에서 "같다"는 말은 어렵고 때로는 연구가 필요하다.
- FIBO는 200개가 넘는 온톨로지를 11개 도메인으로 나누고 URI와 접두어에 계통을 담으며, 보지 못한 데이터셋과의 매핑을 위해 일부러 구분을 세밀하게 둔다.
