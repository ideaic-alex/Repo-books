# 요약과 핵심 개념

RDFS-Plus는 OWL 구성 요소의 일부를 RDFS에 더한 묶음이고, 시맨틱 웹에서 유연한 모델링을 가능하게 한다. 이 문서는 장 전체를 한 번에 되짚을 수 있도록 구성 요소를 표로 모은다. 각 구성 요소가 무슨 일을 하는지, 어떤 도전 과제에서 나왔는지, 어떤 조합으로 쓰였는지를 정리한다. 다음 장(10장)에서는 RDFS-Plus가 대규모 시맨틱 웹 프로젝트에서 어떻게 쓰이는지 사례를 본다.

---

## 1. 이 장에서 복습한 RDFS 개념

앞 장들에서 배운 개념이 이 장에서 다시 쓰였다.

| 구성 요소 | 의미 |
|---|---|
| `rdfs:subClassOf` | 하위 클래스의 멤버는 상위 클래스의 멤버이기도 하다 |
| `rdfs:subPropertyOf` | 하위 속성으로 기술된 관계는 상위 속성으로도 성립한다 |
| `rdfs:domain` | 트리플의 주어는 서술어의 도메인 클래스로 분류된다 |
| `rdfs:range` | 트리플의 목적어는 서술어의 범위 클래스로 분류된다 |
| `rdfs:label` | 추론 의미가 없는 어노테이션, 출력용 이름 |
| `rdfs:comment` | 추론 의미가 없는 어노테이션, 모델을 읽는 사람을 위한 설명 |

`rdfs:label`과 `rdfs:comment`는 추론에 쓰이지 않는 어노테이션 속성(annotation property)이다.

## 2. 이 장에서 새로 소개한 OWL 구성 요소

### 같음(equality)

| 구성 요소 | 의미 | 관련 문서 |
|---|---|---|
| `equivalentClass` | 각 클래스의 멤버는 다른 클래스의 멤버이기도 하다 | 같음을 표현하는 세 가지 방법 |
| `equivalentProperty` | 한 속성으로 성립하는 관계는 다른 속성으로도 성립한다 | 같음을 표현하는 세 가지 방법 |
| `sameAs` | 한 개체에 대한 모든 진술은 다른 개체에도 성립한다 | 같음을 표현하는 세 가지 방법 |

### 속성의 특성(property characteristics)

| 구성 요소 | 의미 | 관련 문서 |
|---|---|---|
| `inverseOf` | 주어와 목적어를 맞바꾼다 | RDFS-Plus 소개와 inverseOf |
| `TransitiveProperty` | 관계의 연쇄가 하나의 관계로 합쳐진다 | 추이적 속성 |
| `SymmetricProperty` | 자기 자신이 inverse인 속성 | 대칭 속성과 어휘 확장 |
| `FunctionalProperty` | 값(목적어)이 하나만 허용된다 | 함수형 속성과 역함수형 속성 |
| `InverseFunctionalProperty` | 주어가 하나만 허용된다(같은 값을 가지면 같은 개체) | 함수형 속성과 역함수형 속성 |
| `ObjectProperty` | 목적어로 리소스를 가질 수 있다 | 데이터 타입 속성과 클래스 선언 |
| `DatatypeProperty` | 목적어로 데이터 값을 가질 수 있다 | 데이터 타입 속성과 클래스 선언 |

원서의 요약은 `TransitiveProperty`를 "관계의 연쇄가 하나의 관계로 합쳐진다"고 풀고, `FunctionalProperty`는 "목적어로 허용되는 값이 하나", `InverseFunctionalProperty`는 "주어로 허용되는 값이 하나"라고 적는다. 위 표는 그 뜻을 옮겼다.

## 3. 도전 과제와 해법 모아 보기

| 과제 | 문제 | 쓴 구성 요소 |
|---|---|---|
| 13 | 방향이 뒤집힌 속성(`hasSon`)을 `hasParent`로 모으기 | `inverseOf` + `subPropertyOf` |
| 14 | 도메인과 범위가 반대인 `signedTo`와 `borrows` 합치기 | `inverseOf` + `subPropertyOf` |
| 15 | `superClassOf` 만들기 | `inverseOf` (`rdfs:subClassOf`의 inverse) |
| 16 | 결혼을 양방향으로 추론하기 | 자기 자신의 `inverseOf` |
| 17 | inverse 선언을 양방향으로 추론하기 | `inverseOf`를 `SymmetricProperty`로 선언 |
| 18 | 부모에서 조상 추론하기 | `subPropertyOf` + `TransitiveProperty` |
| 19 | 추이적/비추이적 `partOf` 함께 두기 | 상위 속성만 `TransitiveProperty` |
| 20 | 선행 단계와 후행 단계 전체 구하기 | `subPropertyOf` + `TransitiveProperty` |
| 21 | 같은 레시피의 단계 모으기 | 상위 속성을 추이적으로(`inSameRecipe`) |
| 22 | 자신을 뺀 다른 단계 구하기 | 추이적 속성 둘 위에 비추이적 상위 속성(`otherStep`) |
| 23 | 외래 키 없는 두 표 합치기 | `owl:sameAs` |
| 24 | `sameAs`를 자동으로 추론하기 | `InverseFunctionalProperty` + `equivalentProperty` |
| 25 | 식별 번호 모델링 | `FunctionalProperty` + `InverseFunctionalProperty` |

모든 과제가 같은 재료를 조합해서 풀렸다는 점이 이 장의 핵심 교훈이다. 새로 배운 구성 요소 몇 개와 RDFS의 `subPropertyOf`만으로 매우 다양한 모델링 요구를 처리했다.

## 4. 장 전체에서 기억할 점

- 구성 요소의 의미는 그것이 나올 때 할 수 있는 추론 규칙으로 정해진다. 이 장은 그 규칙을 SPARQL CONSTRUCT로 적었다.
- `inverseOf`는 단독으로는 쿼리를 다르게 쓰는 것과 별 차이 없어 보이지만, `subPropertyOf`와 조합하면 방향이 다른 속성을 합칠 수 있다.
- OWL의 구성 요소는 서로를 정의하는 데 쓸 수 있다. `equivalentClass`, `equivalentProperty`, `sameAs`, `inverseOf` 자신까지, 대칭 속성과 하위 속성 선언으로 규칙 수를 줄였다.
- 추이성은 상위 속성에 붙이고, 하위 속성은 직접 관계를 그대로 둔다. 이것이 부모와 조상, 부분과 전체, 선행과 후행에서 반복되는 패턴이다.
- 같음 판단 자체는 시맨틱 웹의 주 업무가 아니다. 판단 결과를 정확하고 분산된 방식으로 기록하고 재사용하게 하는 것이 시맨틱 웹의 역할이다.
- `ObjectProperty`, `DatatypeProperty`, `owl:Class`는 추론 의미를 더하지 않지만 도구가 모델을 잘 다루게 한다.
