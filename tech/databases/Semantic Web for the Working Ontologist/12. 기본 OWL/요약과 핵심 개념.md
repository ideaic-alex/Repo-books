# 요약과 핵심 개념

이 문서는 장의 끝에 있는 Summary와 Fundamental Concepts를 정리하고, 장 전체에서 나온 제한의 쓰임새를 한 번에 모아 본다. 다음 장에서 이어지는 주제도 함께 짚는다.

---

## 1. 장의 요약

OWL의 핵심 기능은 제한 클래스(restriction class)를 정의하는 능력이다. 제한 클래스는 이름이 없는 클래스이고, 클래스에 속하는 개체가 가진 속성 값에 거는 조건으로 정의된다. 이 방법으로 "클래스의 구성원은 이런 속성을 가져야 한다"는 상황을 모델링할 수 있다.

RDFS의 domain과 range로는 한 클래스의 모든 구성원에 대한 추론을 할 수 있다. 예를 들어 playsFor로 야구 선수와 팀을 이어 주는 것이다. OWL의 제한은 한발 더 나아가 다음을 가능하게 한다.

- 클래스의 모든 구성원에게 해당하는 경우와 일부 구성원에게 해당하는 경우를 구별한다.
- 클래스의 모든 구성원이 어떤 속성에 특정한 값을 갖도록 요구한다.

제한을 RDFS의 구성 요소(특히 rdfs:subPropertyOf와 rdfs:subClassOf)와 함께 쓰고, 제한이 다른 제한을 가리키도록 겹쳐 쓰면 속성, 클래스, 개체 사이의 복잡한 관계를 모델링할 수 있다. 이렇게 모델로 관계를 적어 두는 것이 비형식적인 설명보다 나은 점은, 여러 명세가 서로 영향을 주는 방식을 이해할 수 있고 자동으로 처리까지 할 수 있다는 것이다.

OWL에는 onProperty를 쓰는 다른 종류의 제한도 있다. 다음 장에서 다룬다.

| 이 장의 주제 | 핵심 내용 |
|---|---|
| 제한 클래스 | 속성 값 조건으로 정의되는 이름 없는 클래스 |
| 세 종류의 제한 | someValuesFrom, allValuesFrom, hasValue |
| 제한과 RDFS의 결합 | subClassOf, equivalentClass, subPropertyOf와 함께 써서 복잡한 관계 표현 |
| 제한의 이점 | 모델의 상호작용을 이해하고 자동 처리할 수 있음 |

## 2. 핵심 개념(Fundamental Concepts)

장 끝에서 다섯 가지 개념을 정리한다.

| 개념 | 한국어 풀이 |
|---|---|
| owl:Restriction | 특정 속성에 허용되는 값을 제한해서 클래스를 묘사하는 OWL의 구성 요소 |
| owl:hasValue | 속성의 값으로 하나의 특정한 값을 가리키는 제한 |
| owl:someValuesFrom | 속성의 값 중 일부가 어떤 집합(클래스)에서 와야 한다는 제한 |
| owl:allValuesFrom | 속성의 모든 값이 어떤 집합(클래스)에서 와야 한다는 제한 |
| owl:onProperty | 제한에서 그 제한이 걸리는 속성으로 이어 주는 연결 |

## 3. 장 전체 복습 표

### 제한 세 종류

| 항목 | someValuesFrom | allValuesFrom | hasValue |
|---|---|---|---|
| 조건 | 값 중 최소 하나가 C의 구성원 | 값이 모두 C의 구성원 | 값으로 A를 가진다 |
| 값의 존재 | 존재해야 한다 | 보장하지 않는다 | 존재한다 |
| 이 장의 예 | q:AnsweredQuestion | 선택된 답이 여는 질문, Vegetarian의 음식 | q:HighPriorityItem, 제품 라인 |
| 흔한 연결 방식 | equivalentClass | subClassOf | equivalentClass |

### 질문지 예시에서 만든 요소

| 요소 | 종류 | 역할 |
|---|---|---|
| q:hasSelectedOption | 속성(hasOption의 하위 속성) | 사용자가 고른 답 기록 |
| q:AnsweredQuestion | 클래스(someValuesFrom) | 답이 선택된 질문 |
| q:SelectedAnswer | 클래스(Answer의 하위 클래스) | 선택된 답 |
| q:EnabledQuestion | 클래스 | 지금 물을 수 있는 질문 |
| q:enablesCandidate | 속성 | 답이 후보로 만드는 질문 |
| q:hasPrerequisite | 속성 | 질문의 선행 답 |
| q:hasPriority | 속성 | 우선순위 수준 |
| q:HighPriorityItem 등 | 클래스(hasValue) | 우선순위별 항목 |

### 도전 문제 한눈에

| 도전 | 문제 | 해법의 핵심 |
|---|---|---|
| 27 | 선행 답이 모두 선택된 질문만 열기 | allValuesFrom 제한을 EnabledQuestion의 하위 클래스로. 열린 세계 때문에 개수를 알아야 완결된다(다음 장) |
| 28 | 채식주의자만 채식 음식을 먹게 하기 | Vegetarian subClassOf allValuesFrom 제한 |
| 29 | 표에서 열 값으로 타입 구분하기 | 문제 제기 |
| 30 | OWL만으로 자동 분류하기 | hasValue 제한 + equivalentClass |
| 31 | 클래스와 개체 연결, 정책 표현 | 클래스-개체 거울 패턴 |
| 32 | FOAF 관계 전달 | inverseOf + hasValue 제한 + equivalentClass |

### 용어 대응

| 선언 | 문헌의 표현 |
|---|---|
| A rdfs:subClassOf B | 필요 조건, 부분 정의 |
| A owl:equivalentClass B | 필요충분 조건, 완전 정의 |
| B rdfs:subClassOf A | 이름이 없음(충분 조건이라고 잘 부르지 않음) |

## 5. 다음 장으로 이어지는 이야기

이 장 끝에서 책은 13장으로 이어진다. 13장 도입부는 다음을 예고한다.

- OWL이 교집합, 합집합, 여집합을 갖춘 집합 이론 언어를 더해 준다는 점. 이로써 제한을 서로 결합할 수 있다(예: 태양 둘레를 돌고 달이 적어도 하나 있는 행성). 제한에 쓰이는 클래스끼리 결합할 수도 있다(예: Vegetarian은 Meat이 아닌 음식을 먹는 사람).
- 기수(cardinality, 개수 제약) 제한이 있다는 점. 예로 "달이 세 개 이상인 행성"이나 "올스타 선수가 둘 이상인 팀"을 쓴다.
- OWL에서 기수를 따지는 추론이 의외로 미묘하다는 점. 한 개체가 이름(URI)을 여러 개 가질 수 있고, 몰랐던 새 개체에 대한 이야기가 언제든 들어올 수 있기 때문에 기수 추론은 매우 보수적인 결론만 낸다.

이 장에서 남은 숙제, 즉 도전 27의 "선행 조건을 모두 충족했는지 어떻게 아는가"가 바로 이 기수 제한과 닫는 방법으로 이어진다.
