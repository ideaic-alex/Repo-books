# 채식주의자 문제와 로컬 범위 제한

이 문서는 12.2절 도전 문제 중 첫 번째인 채식주의자 문제를 다룬다. rdfs:domain과 rdfs:range는 속성을 쓰는 모든 곳에 똑같이 적용되는 "전역" 규칙이라서, 특정 클래스 구성원에게만 적용하고 싶은 규칙은 표현하지 못한다. 이때 owl:Restriction으로 "로컬" 범위 제한을 거는 방법을 배운다.

---

## 1. 문제 상황: 누가 무엇을 먹는가

앞에서 본 질문지와 별개로, 식생활 모델을 만든다. 12.2절 도입은 OWL의 클래스 생성 도구들이 여러 방식으로 결합되어 강력해진다고 말하고, 이어지는 도전 문제들이 실제 모델링 프로젝트에서 자주 만난 상황이라고 소개한다.

기본 모델은 간단하다.

```turtle
:Person a owl:Class .
:Food a owl:Class .
:eats rdfs:domain :Person .
:eats rdfs:range :Food .
```

여기에 다음 데이터를 더한다.

```turtle
:Maverick :eats :Steak .
```

domain과 range 덕분에 두 가지가 추론된다.

```turtle
* :Maverick a :Person .
* :Steak a :Food .
```

앞의 추론은 domain에서, 뒤의 추론은 range에서 나온다.

## 2. 더 세밀하게 정의하고 싶다

이제 여러 식단을 더 자세히 정의하고 싶다. Person의 하위 클래스로 Vegetarian을, Food의 하위 클래스로 VegetarianFood를 둔다.

```turtle
:Vegetarian a owl:Class ;
  rdfs:subClassOf :Person .
:VegetarianFood a owl:Class ;
  rdfs:subClassOf :Food .
```

그리고 다음 데이터를 넣는다.

```turtle
:Jen a :Vegetarian ;
  :eats :Hummus .
```

원하는 추론은 다음과 같다.

| 데이터 | 원하는 결론 | 원치 않는 결론 |
|---|---|---|
| Jen은 Vegetarian이고 Hummus를 먹는다 | :Hummus a :VegetarianFood | 없음 |
| Maverick은 Steak를 먹는다 | Maverick은 Person, Steak는 Food | Maverick이 Vegetarian이거나 Steak가 VegetarianFood라는 결론 |

Maverick의 스테이크는 누군가 그가 채식주의자라고 말하기 전까지는 VegetarianFood라고 추론되지 않아야 한다.

## 3. 도전 28: owl:Restriction으로 범위 제한하기

### 흔한 실수

domain과 range를 더 구체적인 클래스로 바꾸고 싶은 유혹이 든다.

```turtle
:eats rdfs:domain :Vegetarian .
:eats rdfs:range :VegetarianFood .
```

하지만 domain과 range의 의미 때문에 의도하지 않은 추론이 따라 나온다.

```turtle
* :Maverick a :Vegetarian .
* :Steak a :VegetarianFood .
```

이는 Maverick에게도 채식주의자들에게도 놀라운 결과다. domain과 range는 :eats를 쓰는 모든 트리플에 무조건 적용된다. "먹는 사람은 누구나 채식주의자"라는 문장이 되어 버리기 때문이다.

### 해법

"오직 VegetarianFood만 먹는 것들"을 owl:allValuesFrom 제한으로 정의하고, 모든 Vegetarian이 이 조건을 만족한다고 rdfs:subClassOf로 선언한다.

```turtle
:Vegetarian rdfs:subClassOf
  [ a owl:Restriction ;
    owl:onProperty :eats ;
    owl:allValuesFrom :VegetarianFood ] .
```

이 제한은 Vegetarian 구성원에게만 걸리는 조건이다. 속성 :eats의 전역 규칙이 아니라 특정 클래스 안에서만 통하는 규칙이라서 "로컬"이라고 부른다.

### 추론 과정

Jen이 Vegetarian이므로 위 하위 클래스 관계에 따라 제한 클래스의 구성원이기도 하다.

```turtle
:Jen a [ a owl:Restriction ;
  owl:onProperty :eats ;
  owl:allValuesFrom :VegetarianFood ] .
:Jen :eats :Hummus .
```

allValuesFrom은 Jen의 :eats 값을 모두 VegetarianFood로 추론하게 하므로 다음 결론이 나온다.

```turtle
:Hummus a :VegetarianFood .
```

| 단계 | 사실 | 출처 |
|---|---|---|
| 1 | :Jen a :Vegetarian | 입력 |
| 2 | :Jen이 allValuesFrom 제한의 구성원 | subClassOf에서 추론 |
| 3 | :Jen :eats :Hummus | 입력 |
| 4 | :Hummus a :VegetarianFood | allValuesFrom에서 추론 |

Maverick은 어떻게 되는가. Maverick을 Vegetarian이라고 말한 적이 없다. 알려진 것은 Person이라는 사실뿐이고, Maverick과 Vegetarian 사이에는 선언된 관계가 없으므로 더 이상의 추론은 나오지 않는다. 스테이크는 그냥 Food로 남고 VegetarianFood가 되지 않는다. 책의 그림 12.9가 이 모델 전체와 추론을 보여 준다.

## 4. 전역 규칙과 로컬 규칙 비교

| 비교 항목 | rdfs:domain / rdfs:range | owl:Restriction (allValuesFrom) |
|---|---|---|
| 적용 범위 | 그 속성을 쓰는 모든 트리플 | 제한 클래스의 구성원에게만 |
| 규칙의 모양 | 속성에 직접 붙는다 | 클래스에 붙는다(subClassOf 등으로 연결) |
| 이 문제에서의 결과 | Maverick이 Vegetarian, Steak가 VegetarianFood로 잘못 추론 | Jen의 음식만 VegetarianFood로 추론 |
| 쓰기 좋은 상황 | 모든 경우에 성립하는 규칙 | 특정 클래스에만 성립하는 규칙 |

표의 요점은 같은 속성이라도 누가 쓰느냐에 따라 다른 규칙을 적용하려면 제한이 필요하다는 것이다. domain과 range는 속성이 누구에게든 같은 의미를 갖는다고 선언하는 도구이고, 제한은 클래스별로 다른 의미를 입히는 도구다.

## 5. 정리

- domain과 range는 전역 규칙이라서 특정 클래스에만 해당하는 조건을 담지 못한다.
- allValuesFrom 제한을 클래스의 상위 클래스로 걸면 그 클래스 구성원의 속성 값에만 조건을 걸 수 있다.
- 제한은 한 방향으로만 작동한다. Jen이 채식주의자면 Jen이 먹는 것은 VegetarianFood가 되지만, 채식 음식만 먹는다고 해서 사람이 Vegetarian으로 추론되지는 않는다. 이 방향은 subClassOf로 연결했기 때문이다.
- 가장 직관적인 경우처럼 보여도 domain과 range를 좁히는 방식은 이 문제에서 부작용이 크므로 피한다.
