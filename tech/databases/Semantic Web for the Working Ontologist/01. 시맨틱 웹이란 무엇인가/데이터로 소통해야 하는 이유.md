# 데이터로 소통해야 하는 이유

이 문서는 책이 1.2절에서 늘어놓는 여러 사례를 정리한다. 식당 영업시간 같은 사소한 일부터 약물 실험 결과, 금융 상품 비교까지 모두 "내가 아는 정보를 필요한 사람에게 정확히 전달하고 싶다"는 같은 문제를 안고 있다. 이어서 소셜 네트워크와 데이터 과학에서 데이터가 어떤 역할을 하는지도 살핀다.

사례들이 하나같이 사람이 눈으로 읽는 페이지로는 해결되지 않고, 기계가 읽고 합칠 수 있는 데이터가 필요하다는 결론을 가리킨다는 점을 잡고 읽으면 된다.

---

## 1. 일곱 가지 사례

각 사례는 "사람은 해결하지만 기계는 못 한다", 또는 "누구의 일인지 모른다"는 불편으로 끝난다.

| 사례 | 상황 | 드러나는 문제 |
|---|---|---|
| 식당 Copious | 개인 비서에게 영업시간을 물었더니 모른다고 한다. 웹 페이지에는 주소, 오늘의 메뉴, 영업시간이 다 있다. | 웹마스터가 페이지의 내용을 비서에게 알려 줄 방법이 없다. 알려 줬다면 시간뿐 아니라 오늘의 메뉴도 알 수 있었다. |
| 호텔 Mongotel | 국립공원 근처 호텔 목록에 좋아하는 호텔이 없다. 호텔 사이트에는 지점 목록이 있고 일부는 공원 근처다. | 공원 사이트가 그 정보를 몰랐다. 호텔이 지점을 공원 사이트가 찾을 수 있게 공개할 방법이 없다. |
| 지도 비교 | 공원과 호텔 지점 중 가장 가까운 곳을 찾으려 한다. 지도 서비스에는 Mongotel 지점이 다 있지는 않다. 주소를 복사해 지도에 붙여 넣는다. | 왜 내가 정보를 옮겨야 하는가, 이 정보를 최신으로 유지하는 것은 누구의 일인가. Mongotel도 지도의 데이터가 최신이길 원한다. |
| 천문 사이트 | 태양계 천체별 페이지를 운영하고 기준 데이터는 국제천문연맹(IAU)에서 가져온다. 2006년까지 행성이던 Pluto가 "왜소행성(dwarf planet)"이라는 새 범주로 바뀐다. | 정보뿐 아니라 분류 체계가 바뀐다. 행성 페이지가 IAU 기준으로 올바른 8개 행성을 알아서 보여 줄 방법이 있다면 재구성이 필요 없다. |
| 치과 찾기 | 거리 이름(East Long Street)과 의사 이름만 기억한다. 치과로 검색하는데 안 나오고, 알고 보니 "구강 외과의(oral surgeon)"로 올라 있다. | 의사가 자신을 부를 수 있는 모든 방식을 아는 일은 누구의 몫인가. |
| 의학 연구 | 대사 과정이 잘 알려진 질환을 연구한다. 관련 화합물이 여럿이다. 전 세계 연구자가 인체 대사와 연결된 유기 화합물 실험 결과를 발표했다. | 내 관심 화합물에 관한 실험이 있는가, 무엇을 측정했는가. 연구자들이 데이터를 어떻게 공개해야 찾을 수 있는가. |
| 은행 대출 맞교환 | Tigerbank와 Makobank가 주택담보대출을 한다. 고정금리도 있고 공시 지수에 따라 변동하는 것도 있다. 금융 엔지니어가 Tigerbank의 고정 상환과 Makobank의 변동 상환을 맞바꾸는 거래를 설계한다. | 좋은 거래인지 알려면 두 대출의 조건을 비교해야 한다. 은행들이 대출을 참여자가 비교할 수 있는 말로 어떻게 기술하는가. |
| 소셜 네트워크 | 수십억 명이 삶의 데이터를 올린다. | 아래 3절에서 따로 다룬다. |

표를 읽는 핵심은 마지막 열이다. 모든 문제가 "정보가 어딘가에 분명히 있는데, 기계가 이해해서 다른 곳과 잇지 못한다"로 모인다.

## 2. 사례들의 공통점

모든 사례에서 누군가는 공유하고 싶은 지식을 가지고 있다. 영업시간과 지점, 업종 같은 사업 정보일 수도 있고, 화합물 실험 데이터나 행성 분류 같은 과학 데이터일 수도 있으며, 금융 상품처럼 복잡하게 설계한 도구에 대한 정보일 수도 있다.

데이터를 가진 쪽은 이 정보를 가능한 한 많은 소비자에게 알리고 싶어 한다. 웹 페이지만이 아니라 검색 엔진, 개인 비서, 매시업(mash-up), 리뷰 사이트, 지도 등 여러 경로로 퍼지길 바란다. 하지만 그 데이터는 너무 특이하거나, 너무 상세하거나, 너무 복잡해서 글로 설명만 해서는 전달되지 않는다. 오히려 이익이 크기 때문에, 자신의 데이터가 필요한 사람을 찾고 그들이 어떻게 쓸 수 있을지 고민하는 데 기꺼이 노력을 들인다.

## 3. 소셜 데이터: 통제의 균형

사람들이 자기 데이터를 공유하려는 특수한 경우가 소셜 네트워킹이다. 개인 생활과 직업 생활을 모두 올려서 새 친구를 찾고, 옛 친구와 연락하고, 업무 인맥을 만드는 등의 이득을 얻는다.

책은 소셜 네트워킹이 분산되지 않은 방식으로 이루어진다고 지적한다. 사람이 웹 서비스(책이 든 예는 Facebook, LinkedIn, Instagram, WeChat이며 사라진 서비스도, 새로 나올 서비스도 있다)에 가입하고 계정을 만들어 일상 업데이트, 사진, 다녀온 장소와 함께한 사람의 태그, 시작하거나 끝낸 프로젝트, 해 온 일 같은 데이터를 올린다. 이 데이터는 친구와 동료, 경우에 따라 완전한 타인에게까지 검색되고 보인다.

| 구분 | 내용 |
|---|---|
| 데이터의 소유 | 서비스가 소유하며 여러 목적으로 사용할 수 있다 |
| 흔한 경험 | 소셜 네트워크에서 어떤 말을 했더니 다음 날 관련 광고가 뜬다 |
| 광고 | 돈이 되지만 대체로 해가 적은 용도다 |
| 심각한 사례 | 2018년, 수백만 사용자의 Facebook 데이터가 2016년 미국 대통령 선거와 영국의 "브렉시트" 국민투표를 포함한 여러 주목도 높은 선거에 영향을 주는 데 쓰였다는 사실이 드러났다 [Meredith 2018] |
| 사용자의 반응 | 많은 사용자가 놀랐다. 자신이 통제할 수 없는 중앙 저장소에 데이터를 공유했기 때문이다 |

이 사례가 보여 주는 것은 통제의 균형이다. 1.2절의 사례들처럼 데이터를 공유하고 싶지만, 특정한 사람에게만 공유하고 다른 사람에게는 공유하고 싶지 않을 수 있다. 이 두 바람을 어떻게 함께 관리할까. 저자들은 이것을 분산 데이터의 문제로 본다. 통제하려면 데이터를 내가 가지고 있어야 하지만, 공개하는 이유를 채우려면 전 세계의 데이터와 연결되어야 한다.

## 4. 데이터에서 배우기: 데이터 과학

데이터 과학(Data Science)은 마케팅, 수요, 위험 평가 등 여러 분야에서 사람의 행동이나 제품의 성과를 예측하는 가장 생산적인 방법 중 하나가 되었다.

은행이 쉬운 예다. 은행은 주택담보대출, 자동차 대출, 소상공인 대출 등을 한다. 대출 신청 과정에서 차용인에 대해 많은 정보를 얻고, 수십 년 동안 대출을 해 왔기 때문에 최종 결과(연체했는가, 일찍 갚았는가, 갈아탔는가)에 관한 데이터도 많다. 이런 데이터를 대량으로 모으면 머신러닝으로 초기 정보만 보고 대출의 최종 결과를 예측할 수 있다. 은행은 대출을 더 가려서 해 시장에서 더 효과적으로 움직인다.

같은 접근이 다른 분야에도 적용된다.

| 분야 | 예측 대상 |
|---|---|
| 마케팅 | 판매 가능성이 높은 잠재 고객 찾기 |
| 제품 개발 | 어떤 기능이 잘 팔릴지 |
| 고객 유지 | 문제가 심해지기 전에 파악 |
| 의료 | 영상과 혈액 검사 패턴으로 질병 식별 |
| 경로 계획 | 항공기의 최적 경로 |
| 스포츠 | 어떤 선수를 언제 기용할지 |

모든 성공 사례의 바탕에는 의미 있는 데이터가 있었다. 마케팅, 영업, 제조는 데이터가 한 회사의 고객 행동이라는 단일 출처에서 나온다. 스포츠의 통계는 팬들이 오랜 세대에 걸쳐 표준화해 왔고, 이미 하나의 표현으로 정렬되어 있다. 이 정렬이 머신러닝 알고리즘이 데이터를 일반화하는 데 중요한 단계다.

목록에서 데이터가 분산된 경우는 의료뿐이다. 진단이 전 세계 병원과 의원에서 나오지만, 질병과 치료 코드가 수십 년 전부터 있어서 여러 출처의 데이터를 맞춰 준다. 이것은 우연이 아니다.

그래서 저자들은 의료의 머신러닝 성공을 다른 산업으로, 기업 수준에서 산업 수준으로 넓히려면 무엇이 필요한지 묻는다. 답은 산업 전체에 흩어진 데이터를 서로 연결하는 방법이다.

## 5. 정리

| 영역 | 데이터가 원하는 것 |
|---|---|
| 일상 정보(영업시간, 지점) | 기계가 읽고 다른 서비스가 가져가게 하는 것 |
| 과학과 금융 | 복잡한 데이터를 비교 가능한 말로 공개하는 것 |
| 소셜 | 공유하면서도 내가 통제하는 것 |
| 데이터 과학 | 여러 출처의 데이터를 같은 형태로 정렬하는 것 |

네 영역의 요구를 한 문장으로 줄이면 "흩어진 데이터를 연결하되 주인이 통제권을 잃지 않게 한다"가 된다. 이것이 다음 문서에서 다룰 분산 데이터 웹의 출발점이다.
