# 개념 체계와 권장 관행

개념(concept)이 책의 낱장이라면 개념 체계(concept scheme)는 그 낱장을 묶은 책 한 권이다. 어느 시소러스에 속한 개념인지 알려 주는 꼬리표 역할을 한다. 이 문서는 개념 체계가 무엇인지, 개념과 어떻게 연결하는지, 그리고 원서가 제안하는 다섯 가지 권장 관행과 `owl:sameAs` 대신 `skos:exactMatch`를 쓰는 이유를 다룬다.

---

## 1. 개념 체계란

개념 체계(skos:ConceptScheme)는 개념들의 비교적 느슨한 모음이다. 대략 특정 시소러스나 지식 조직 체계 하나에 대응한다. 형식적 정의는 거의 없지만 하나 이상의 시소러스를 발행하는 쪽의 의도를 전달하는 데 유용하다.

실제 관행은 제각각이다.

| 발행 기관 | 개념 체계를 나누는 방식 |
|---|---|
| AGROVOC | 어휘 전체를 하나의 개념 체계로 발행 |
| 미국 의회도서관(Library of Congress) | 어휘마다 별도 개념 체계. 어휘별 라이선스 통제가 다른 점이 일부 이유 |
| NAL | 최상위 표제어마다 하나씩, 여러 개 사용 |

개념 체계는 개념의 집합으로 볼 수 있다. 한 체계에 속하는지 여부가 `skos:broader`, `skos:narrower`, `skos:related` 같은 의미 관계와 연결되어야 한다는 조건은 없다. 어떤 개념은 한 체계에 있고 그 상위·하위 개념은 다른 체계에 있어도 된다.

---

## 2. 개념과 체계를 잇는 속성

| 속성 | 의미 |
|---|---|
| `skos:inScheme` | 개념이 이 체계에 속한다 |
| `skos:hasTopConcept` | 이 체계의 최상위 개념이다 |
| `skos:topConceptOf` | 이 개념은 그 체계의 최상위 개념이다(`hasTopConcept`의 역) |

앞 문서의 두 개념 NAL:38846("sheep")과 AGROVOC:c_7030("Sheep")은 서로 다른 체계에 있다.

```turtle
AGROVOC:c_7030 skos:inScheme <http://www.fao.org/aos/agrovoc> .
NAL:38846 skos:inScheme NAL:S .
```

URI가 다르니 두 개념을 다른 기관이 관리한다는 것은 이미 알 수 있다. 하지만 체계 소속을 명시하면 이 관계가 분명한 데이터가 되고 SPARQL로 질의할 수도 있다.

---

## 3. 최상위 개념

`skos:broader`와 `skos:narrower`는 개념의 트리 구조를 만든다. 트리의 꼭대기는 SPARQL 질의로도 찾을 수 있지만, 전용 속성으로 표시해 두면 편하다. 이것이 `skos:hasTopConcept`와 `skos:topConceptOf`의 목적이다. 둘의 관계는 두 트리플이 정한다.

```turtle
skos:topConceptOf rdfs:subPropertyOf skos:inScheme .
skos:topConceptOf owl:inverseOf skos:hasTopConcept .
```

이 두 줄의 결과는 다음과 같다.

- 체계의 최상위 개념은 반드시 그 체계에도 속한다(`topConceptOf`가 `inScheme`의 하위 속성이므로).
- `topConceptOf`와 `hasTopConcept`는 서로 역관계다.

---

## 4. 관행이 제각각인 현실

실제로 이 속성들을 쓰는 방식은 다양하다.

- 아예 쓰지 않고 체계 소속을 암묵적으로 두는 어휘가 있다.
- `inScheme`만 쓰고 최상위 개념은 표시하지 않는 어휘가 있다.
- 최상위 개념을 표시하는 경우에도 `hasTopConcept`를 쓰는 쪽과 `topConceptOf`를 쓰는 쪽으로 갈린다.

모두 SKOS 표준에서는 허용된다. 하지만 허용되는 방식이 너무 많으면 어휘를 쓰는 작성자는 편해도 어휘를 가져다 쓰는 쪽은 길을 찾기 어려워진다. 그래서 원서가 SKOS 표현을 표준화하자는 취지로 권장 관행 다섯 가지를 제안한다.

---

## 5. 다섯 가지 권장 관행

| 번호 | 권장 사항 | 이유 또는 취지 |
|---|---|---|
| 1 | 개념 체계를 자기 조직의 거버넌스에 맞춘다. 하나의 작업 절차가 통제하는 어휘마다 개념 체계 하나를 둔다 | 체계가 권한과 작업 절차를 반영하게 한다 |
| 2 | 체계 소속을 `skos:broader`, `skos:narrower`를 따라 전파한다 | 같은 체계의 개념이 한 트리에 모이게 한다 |
| 3 | `broadMatch`, `narrowMatch`, `exactMatch`, `closeMatch`는 서로 다른 체계의 개념을 매핑할 때만 쓴다 | 체계 안의 관계와 체계 사이의 관계를 구분한다 |
| 4 | 모든 `skos:broader` 트리의 꼭대기를 `skos:hasTopConcept`로 표시하고, 트리 중간의 개념은 표시하지 않는다 | 어디서 시작할지 바로 알 수 있게 한다 |
| 5 | 한 체계의 최상위 개념 수를 적게 유지한다(여섯 개 미만) | 탐색을 쉽게 한다 |

2번 관행은 다음 SPARQL CONSTRUCT로 참이 되어야 한다고 표현된다.

```sparql
CONSTRUCT { ?c skos:inScheme ?S }
WHERE { ?a skos:inScheme ?S .
        ?a skos:broader ?c . }
```

`?a`가 체계 `?S`에 속하고 `?a`의 broader가 `?c`라면 `?c`도 `?S`에 속해야 한다는 뜻이다. `skos:narrower`에도 비슷한 규칙이 적용된다.

이 지침은 표준이 아니다. 여러 기관이 만든 어휘를 읽으며 얻은 경험에서 나왔다. 어길 만한 이유가 있을 수 있지만, 지키면 시소러스 표현이 예상 밖이 되지 않고(예를 들어 한 체계의 개념이 같은 broader/narrower 트리에 함께 있다), 어휘를 찾는 사람이 어디서 시작할지 쉽게 안다. 일부는 상식에 가깝다(트리 중간 노드를 "최상위"로 표시하지 않기). 일부는 다소 자의적이다(`topConceptOf`가 아니라 `hasTopConcept`를 정한 데 뚜렷한 이유는 없다).

---

## 6. exactMatch가 따로 필요한 이유

`owl:sameAs`가 이미 있는데도 `skos:exactMatch`를 따로 둔 이유를 개념 체계가 잘 보여 준다.

- `owl:sameAs`는 두 리소스가 모든 문장에서 서로 바꿔 쓸 수 있다는 뜻이다.
- 두 개념이 `sameAs`이면 반드시 같은 개념 체계에도 속하게 된다.
- 개념 체계는 권한과 작업 절차를 반영한다. 그러니 서로 다른 기관의 개념을 `sameAs`로 묶는 것은 맞지 않는다.
- `skos:exactMatch`는 훨씬 약하다. 한 개념이 정보 검색 환경에서 다른 개념처럼 동작한다는 것만 나타낸다.

| 비교 | `owl:sameAs` | `skos:exactMatch` |
|---|---|---|
| 의미 | 모든 문장에서 바꿔 쓸 수 있음 | 정보 검색에서 바꿔 쓸 수 있음 |
| 같은 개념 체계 소속 | 같아야 함(추론됨) | 강제하지 않음 |
| 서로 다른 기관의 용어 연결 | 부적절 | 적절 |

표를 읽으면, 기관이 다른 두 용어가 비슷하다고 말할 때는 `exactMatch`가 권한 경계를 허물지 않는 안전한 선택이다.
