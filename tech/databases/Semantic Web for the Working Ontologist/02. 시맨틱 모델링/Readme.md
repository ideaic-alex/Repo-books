# 시맨틱 모델링

이 장은 시맨틱 웹에서 "모델링"이 무엇이고 왜 필요한지를 다룬다. 누구나 무엇이든 말할 수 있는 웹은 혼란스러울 수밖에 없는데, 그 혼란에서 공동체의 지식을 뽑아내는 도구가 모델이다. 모델이 하는 일을 소통, 설명과 예측, 여러 관점의 조율 세 가지로 나누고, 명왕성 사례로 그 차이를 보여 준다.

뒷부분에서는 모델링 언어마다 표현력이 다르다는 점을 물 분자 모델에 빗대어 설명하고, RDF, SHACL, RDFS, RDFS-Plus, OWL이 어떤 역할과 시기를 가졌는지 소개한다. 이후 장에서 각 언어를 자세히 배우기 위한 지도에 해당하는 장이다.

---

## 1. 핵심 요점

- 모델은 어떤 세부는 감추고 어떤 세부는 드러내는 추상적인 설명이다. 소통을 돕고, 설명과 예측을 하고, 여러 관점을 조율한다.
- 법률, 쇼핑몰 카테고리, 태그처럼 사람의 해석에 기대는 모델은 비형식이다. 해석 위에 해석이 쌓이기 쉽고, 태그는 인기가 높을수록 뜻이 퍼져 구별력이 떨어진다(#rpi 예).
- 형식 체계가 있으면 설명과 예측이 듣는 사람과 무관하게 평가된다. 시맨틱 웹의 이 측면이 추론이다.
- 한 입장만 허용하는 방식은 AAA 슬로건에 맞지 않고, 각자 따로 두는 방식은 현재 웹처럼 공통점 파악을 독자에게 떠넘긴다.
- 클래스 계층은 공통점을 위쪽에, 차이를 아래쪽에 두는 방식이다. 명왕성 예에서 SSB 아래 astro:Planet, horo:Planet, IAU:Planet을 배치했다.
- 출처가 제각각이면 모델을 층으로 쌓아 합친다. 대신 prefSymbol처럼 값이 하나여야 하는 속성의 불일치를 기계가 알 수 있게 형식으로 알려 줘야 한다.
- 표현력이 높다고 더 좋은 것은 아니다. 물의 화학식, 화학 구조, 물리 구조처럼 용도가 다른 도구다.
- 시맨틱 웹 언어는 RDF, SHACL, RDFS, RDFS-Plus, OWL 순으로 소개되며, SHACL만 닫힌 세계 가정을 쓴다.
