# 요약과 핵심 개념

이 문서는 7장 전체를 되짚는다. 여러 출처의 데이터를 하나처럼 쓰려면 어떤 추론이 필요한지, 시맨틱 웹 표준이 추론 수준을 어떻게 나누는지, 그리고 이 장에서 새로 나온 개념을 한눈에 정리한다.

---

## 1. 장 요약

RDF는 여러 출처의 정보를 모아 하나의 출처에서 온 것처럼 다룰 수 있게 해 준다. 그런데 막상 데이터를 쓰려고 하면 출처마다 다른 점이 드러난다. 예를 들어 통합한 모든 데이터 출처에서 관련 데이터를 한 번에 가져오는 쿼리 하나를 쓰고 싶어진다.

시맨틱 웹은 이 문제를 데이터 출처 사이의 관계를 기술할 수 있는 모델링 언어로 푼다. 모델링 구성 요소의 의미는 그것에서 끌어낼 수 있는 추론 패턴으로 정해진다. 쿼리 전이나 쿼리 도중에 추론을 일으키면 정보 통합이 이루어진다. 쿼리는 직접 적힌 데이터뿐 아니라 추론된 정보도 돌려주고, 그 정보는 둘 이상의 데이터 출처에 걸칠 수 있다.

아주 단순한 추론만으로도 데이터 통합에 가치가 있다는 것을 봤다. 그렇다면 정확히 어떤 추론이 필요한가. 원서는 이 물음에 하나의 보편적 답은 없다고 말한다. 시맨틱 웹 표준은 표현력 수준을 여러 단계로 나누고, 각 단계는 서로 다른 추론을 지원하며, 시맨틱 웹의 데이터 통합 정교함 수준에 맞춰 쓰인다.

## 2. 세 가지 추론 수준

원서는 다음 장들에서 세 가지 추론 수준을 살펴본다고 예고한다. 이들은 지원하는 추론에서만 다르다.

| 수준 | 누가 정하나 | 특징 |
|---|---|---|
| RDFS | W3C 권고안 | 소수의 추론 규칙으로, 주로 클래스와 하위 클래스, 그리고 속성과 클래스의 관계를 다룬다 |
| RDFS-Plus | 이 책이 정의한 모드 | 교육적으로(OWL의 더 복잡한 추론 패턴으로 가는 부드러운 입문), 실용적으로(그 자체로 쓸모 있는 통합 도구) 도움이 되는 추론 패턴 모음. RDFS 위에 속성에 대한 제약과 동등성 개념을 더한다 |
| OWL | W3C 권고안 | 더 나아가 속성이 가질 수 있는 값에 따라 클래스를 기술하는 규칙까지 포함한다 |

세 표준 모두 추론으로 모델의 의미를 설명한다. 다만 지원하는 추론이 다르다. 원서의 이 대목은 RDFS를 6장, RDFS-Plus를 7장, OWL을 9장과 10장이라고 적었는데, 이 장의 다른 곳에서는 RDFS를 8장, OWL을 12장이라고 한다. 장 번호가 서로 맞지 않으므로 여기서는 번호 없이 "이후 장들"이라고 부른다.

## 3. 이 장의 두 흐름 비교

| 항목 | 추론(RDFS) | 기대(SHACL) |
|---|---|---|
| 방향 | 본 데이터에서 새 데이터를 만든다 | 보지 못한 데이터에 조건을 건다 |
| 핵심 개념 | 추론 규칙, 타입 전파 | 셰이프, 제약 |
| 결과 | 추론된 트리플, 더 풍부한 쿼리 결과 | 검증 결과(위반과 그 이유), 폼 내용 |
| 쓰는 곳 | 여러 출처 통합, 쿼리 정합성 | 데이터 검증, 폼 생성, 입력 검증 |

두 흐름은 반대 방향처럼 보이지만 모두 RDF 위에서 모델을 RDF로 쓴다는 공통점이 있다.

## 4. 핵심 개념

| 개념 | 정의 |
|---|---|
| 추론(inferencing) | 기존 트리플의 패턴에 따라 새 트리플을 체계적으로 그래프에 추가하는 과정 |
| asserted 트리플 | 어떤 데이터 출처가 제공한, 그래프 안의 트리플 |
| inferred 트리플 | 체계적인 추론 패턴에 따라 모델에 더해진 트리플 |
| 추론 규칙(inference rules) | 어떤 트리플을 추론해야 하는지 정하는 체계적인 패턴 |
| 추론 엔진(inference engine) | 추론 규칙에 따라 추론을 수행하는 프로그램. 흔히 쿼리 엔진과 통합되어 있다 |
| SHACL 셰이프 | RDF 데이터가 만족해야 하는 제약을 제공함으로써 구조 수준에서 데이터를 검증하는 수단 |

## 5. 이 장에서 얻은 것

| 주제 | 기억할 점 |
|---|---|
| 타입 전파 규칙 | A가 B의 하위 클래스이고 x가 A의 개체면 x는 B의 개체 |
| 추론 규칙 표기 | SPARQL CONSTRUCT, 모델에 붙일 때는 sh:rule |
| 추론 시점 | 캐시(구체화) 추론은 단순하지만 폭발 위험, 적시 추론은 저장이 적지만 반복 계산 |
| 모델의 역할 | 추론을 안 해도 쿼리와 프로그램이 옳은지 판정하는 명세 |
| SHACL 검증 | 셰이프와 데이터로 위반 여부와 이유를 자동으로 알아낸다 |
| 셰이프 재사용 | 같은 셰이프로 데이터 검증, 폼 생성, 입력 검증을 모두 한다 |

원서 7장에는 연습문제가 없고, 요약과 핵심 개념이 장의 끝이다. 같은 이유로 이 문서도 별도 연습문제를 두지 않았다.
