# RDF 확장하기 RDFS와 SHACL

RDF는 데이터를 그래프로 표현하고, URI로 웹 전체에 엮을 수 있게 한다. 이 장은 그 위에 시맨틱 웹 표준이 더하는 두 가지 능력을 소개한다. 하나는 이미 있는 데이터에서 새 사실을 끌어내는 추론이고, 다른 하나는 아직 보지 못한 데이터가 어떤 모습이어야 하는지 말하는 기대다. 추론은 RDFS가, 기대는 SHACL이 맡는다.

앞부분은 쇼핑몰 카탈로그 예제로 rdfs:subClassOf의 의미를 추론 규칙으로 정의하는 방식을 설명하고, 추론 엔진이 구조의 어디에 있으며 추론을 언제 하는지 다룬다. 뒷부분은 SHACL 셰이프로 데이터를 검증하고, 폼을 만들고, 사용자 입력을 다시 검증하는 흐름을 하나의 Account 예제로 보여 준다.

---

## 1. 핵심 요점

- RDF 위의 두 확장은 추론(RDFS)과 기대(SHACL)다.
- rdfs:subClassOf의 의미는 타입 전파 규칙 하나다. A가 B의 하위 클래스이고 x가 A의 개체면 x는 B의 개체이기도 하다.
- 시맨틱 웹은 OOP와 달리 하위 클래스의 재정의를 허용하지 않는다. 의미는 프로그램 동작이 아니라 추론으로 정해진다.
- 추론 규칙은 SPARQL CONSTRUCT로 적을 수 있고, SHACL-Rules의 sh:rule로 모델에 붙일 수 있다.
- 추론 엔진은 애플리케이션과 RDF 저장소 사이에서 쿼리 엔진과 함께 동작한다. 직접 적은(asserted) 트리플과 추론된(inferred) 트리플은 논리적으로 구별되지 않는다.
- 추론 시점은 구현이 정한다. 캐시(구체화) 추론은 단순하지만 트리플이 폭발할 수 있고, 적시 추론은 저장이 적지만 추론을 반복한다.
- 추론을 안 하는 쿼리도 모델이 옳음을 보증하는 명세 역할을 한다.
- SHACL 셰이프는 RDF로 쓰이며, 같은 셰이프로 데이터 검증, 폼 생성, 사용자 입력 검증을 모두 할 수 있다.
