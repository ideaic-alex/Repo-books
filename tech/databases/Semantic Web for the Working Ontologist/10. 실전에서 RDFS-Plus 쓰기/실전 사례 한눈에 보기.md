# 실전 사례 한눈에 보기

앞 장까지는 RDFS-Plus(RDFS에 OWL의 일부 구성 요소를 더한 모델링 도구 묶음)를 예제 위주로 배웠다. 이 장은 눈을 밖으로 돌려, 실제 사용자 집단이 있는 서비스들이 이 도구를 어떻게 쓰는지 본다. 다루는 사례는 Schema.org, 미국 정부의 Data.gov, FOAF, 그리고 Facebook의 Open Graph Protocol(OGP) 네 가지다.

이 문서는 사례 전체를 훑는 지도 역할을 한다. 각 사례가 무엇이고, 어떤 구성 요소를 어디에 쓰는지 먼저 잡아 두면 뒤 문서를 읽기 쉽다.

---

## 1. 이 장이 보여 주려는 것

원서는 이 장의 첫머리에서 세 가지 응용(Schema.org, Data.gov, FOAF)을 소개하고, 끝에서 OGP까지 더한다. 공통점이 몇 가지 있다.

- 모두 RDFS-Plus의 구성 요소를 핵심 부분에 쓴다. 쓰는 방식은 제각각이다.
- 모두 처음부터 RDF, RDFS, OWL 기술을 쓰겠다고 정하고 시작한 프로젝트는 아니다. 다만 RDF 응용으로 구상된 것은 맞다.
- 모두 웹에 흩어져 있는 데이터를 모델(RDFS로 쓴 설명)로 묶고, 그 데이터를 쓰는 응용이 사용자 집단에 가치 있는 서비스를 준다.

개발자 입장에서 비유하자면, 앞 장들이 문법 책이었다면 이 장은 오픈소스 프로젝트 코드를 읽어 보는 단계다. 문법을 아는 것과 실제 프로젝트가 그 문법을 어떻게 쓰는지 아는 것은 다르다.

## 2. 네 가지 사례 요약

| 사례 | 누가 만들었나 | 무엇을 하나 | 데이터가 있는 곳 |
|---|---|---|---|
| Schema.org | Google, Microsoft, Yahoo, Yandex | 웹 페이지에 구조화된 데이터를 심기 위한 공용 어휘를 제공한다 | 수많은 웹 사이트의 페이지 안 |
| Data.gov | 미국 정부 | 공공 정보를 데이터셋으로 공개한다 | 정부 사이트의 데이터셋 |
| FOAF | 커뮤니티 프로젝트 | 사람, 사람 사이의 관계, 사람이 만든 것을 기계가 읽는 홈페이지로 설명한다 | 개인 홈페이지 등 웹 곳곳 |
| OGP | Facebook | 아무 웹 페이지나 Facebook의 "좋아요" 대상으로 만든다 | 웹 페이지의 헤더 |

표를 보면 데이터가 한곳에 모여 있는 경우가 없다. 전부 웹에 분산되어 있다. 이런 분산 환경이 RDF가 어울리는 자리다.

## 3. 어떤 구성 요소가 어디에 쓰이나

이 장에서 눈에 띄는 RDFS-Plus 구성 요소를 사례별로 모으면 다음과 같다.

| 구성 요소 | 쓰이는 곳 | 하는 일 |
|---|---|---|
| rdfs:subClassOf | Schema.org, FHEO 데이터, FOAF | 클래스 계층을 만든다 |
| rdfs:subPropertyOf | FOAF(이름, 별명, 홈페이지) | 속성 계층을 만든다 |
| rdfs:domain, rdfs:range | FOAF, 금융 예시 | 속성이 어떤 클래스와 이어지는지 알린다 |
| owl:equivalentProperty | FOAF의 surname과 family_name | 같은 쓰임의 두 속성을 하나로 묶는다 |
| owl:inverseOf | FOAF의 made와 maker | 방향만 반대인 두 속성을 잇는다 |
| owl:InverseFunctionalProperty | FOAF의 mbox 등 | 속성 값이 곧 신원 식별자임을 알린다 |
| rdfs:seeAlso | OGP | 다른 어휘를 느슨하게 가리킨다 |
| SPARQL CONSTRUCT | Data.gov | 원자료를 원하는 모양으로 바꾸는 사용자 규칙이다 |

이 표에서 읽을 점은, 앞 장에서 배운 구성 요소가 대부분이라는 것이다. 새로 보이는 것은 Schema.org가 따로 만든 domainIncludes, rangeIncludes 정도다. 이미 배운 도구를 조합해서 큰 서비스가 돌아간다.

## 4. 각 사례를 읽는 관점

각 사례마다 다른 질문에 답한다고 생각하면 정리가 쉽다.

- Schema.org: 가격이나 재고처럼 "단순 값 하나"로 안 끝나는 정보는 어떻게 모델링하나. 그리고 왜 RDFS의 domain, range를 그대로 쓰지 않았나.
- Data.gov: 제각각인 "야생의" 데이터를 RDFS와 SPARQL로 어떻게 길들이나.
- FOAF: 아무나 무엇이든 말할 수 있는 열린 환경에서 처음부터 모든 것을 정하지 않고 어떻게 점점 키워 가나. 사람을 어떻게 식별하나.
- OGP: 단순함을 위해 새 어휘를 따로 만들어도 기존 어휘와 연결할 수 있나.

각 질문의 답은 이어지는 문서에서 설명한다.
