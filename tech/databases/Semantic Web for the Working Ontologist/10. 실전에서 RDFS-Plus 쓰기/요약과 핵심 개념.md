# 요약과 핵심 개념

이 문서는 10장 전체를 마무리한다. 네 사례를 한 번에 비교하고, Data.gov 요약에서 빠진 이야기를 보충하고, 원서가 장 끝에 정리한 핵심 개념을 풀어서 적는다. 앞 문서를 읽지 않아도 장의 줄기를 잡을 수 있게 썼다.

---

## 1. Data.gov 사례의 마무리

지금까지 본 Data.gov 매시업(여러 데이터셋을 섞어 새 결과를 만드는 일)은 열린 정부 데이터로 해 온 일의 빙산의 일각이다. 영국의 RDF 데이터를 쓰는 응용은 개발 커뮤니티가 많이 만들었다. 미국에서는 Rensselaer Polytechnic Institute(RPI) 연구자들이 이 접근으로 정부 데이터를 쓰는 다양한 응용을 만들었고, 일부는 공식 Data.gov 페이지(`http://data.gov/semantic`)에 소개되어 있다.

정부 데이터를 RDF로 제공하면 데이터셋을 섞고 맞추기가 쉬워진다. 여러 데이터셋의 정보를 섞은 시각화, 응용, 보고서가 가능해지고, Wikipedia, 뉴스 기사, Google 검색 결과 같은 다른 웹 데이터와 정부 데이터를 합칠 수도 있다. 시맨틱 웹 이전의 기술로는 훨씬 어렵고 비용이 컸을 일이다.

이 모든 매시업에서 핵심 기술은 SPARQL이다. SPARQL은 분석가가 보고서나 화면에 필요한 정보만 뽑아내는 패턴 매칭 도구가 된다. 집계, 필터, 서브쿼리, UNION 같은 고급 기능도 여기서 잘 쓰인다. `http://logd.tw.rpi.edu`에는 데모 매시업이 여럿 있고, 각각 만들 때 쓴 SPARQL 쿼리를 보여 주는 페이지로 연결된다.

## 2. 원서의 장 요약

OGP와 FOAF는 비교적 단순한 모델링 구성 요소 묶음으로 확장 가능한 분산 정보 네트워크를 만들 수 있음을 보여 준다. 둘 다 RDF의 분산 성질을 이용해 정보 네트워크의 확장이 웹 전역에 퍼지게 한다.

- FOAF는 진화적인 접근으로 정보를 확장한다. 한 개념에 용어가 여럿 있다(앞에서 본 "이름"의 여러 변형). 새 기능이 필요해지면 FOAF를 확장하면 된다. 예컨대 `foaf:weblog`는 블로깅이 유행하기 전에는 덜 중요했지만 이제는 전통적인 `foaf:homepage`보다 중요해졌다.
- OGP는 아마도 가장 성공한 시맨틱 웹 모델이다. 도입 후 1년이 채 안 되어 웹에서 쓰임이 널리 퍼졌고, 2010년 말 기준으로 웹의 "like" 버튼 중 약 10~15%가 RDFa 방식을 썼다. Yahoo! 쇼핑 페이지, New York Times 기사, CNN 뉴스마다 "like" 버튼이 있고 버튼당 트리플이 최소 네 개이므로 OGP 때문에 생기는 RDF 트리플이 얼마인지는 가늠하기 어렵다. 성공은 Facebook 자체의 거대한 성공 덕이 크겠지만, 설계에서 단순함을 지킨 덕도 있다. OGP에는 단순한 타입 스물네 개 안팎과 그와 비슷한 수의 속성만 있다.
- OGP는 시맨틱 웹 원칙이 작동하는 분명한 예이기도 하다. 소셜 네트워킹 모델은 이미 많고(FOAF도 그중 하나), 웹에서는 누구도 하나로 합의하기를 기대할 수 없다. 응용마다 필요가 다르다. Facebook은 단순함이 중요하다고 판단해서 다른 곳에 이미 있는 개념 몇 가지를 다시 만들었다. 그렇다고 OGP가 뚫고 들어갈 수 없는 또 하나의 정보 사일로가 된 것은 아니다. 처음부터 다른 시스템과의 연결이 기계가 읽고 질의할 수 있는 형태로 모델에 들어 있었다. 출발부터 소셜 네트워크 개체를 설명하는 메타데이터 망의 일부였다.

## 3. 네 사례 비교

| 사례 | 모델링의 성격 | 핵심 도구 | 다른 어휘와의 연결 |
|---|---|---|---|
| Schema.org | 웹 마스터가 쓰기 쉬운 단일 대형 어휘. 클래스 약 600개, 속성 약 900개(원서 집필 시점) | rdfs:subClassOf, domainIncludes, rangeIncludes | QUDT, FIBO 같은 외부 자원을 가리킨다 |
| Data.gov (FHEO) | 날것 데이터를 클래스로 바꾸고 검증한다 | rdfs:subClassOf, SPARQL CONSTRUCT, ASK | 카운티 이름과 주로 지리 데이터와 조인한다 |
| FOAF | 점진적으로 자라는 분산 어휘 | subPropertyOf, equivalentProperty, inverseOf, InverseFunctionalProperty | 새 어휘와 옛 어휘를 RDFS-Plus로 잇는다 |
| OGP | 단순함을 우선한 작은 어휘 | RDFa(단순화), rdfs:seeAlso | FOAF, 지리 어휘를 seeAlso로 가리킨다 |

이 표는 네 사례가 "얼마나 엄밀하게 의미를 못 박는가"에서 서로 다른 선택을 했음을 보여 준다. FOAF는 필요하면 형식 규칙을 더하고, OGP는 약한 연결로 충분하다고 보고, Schema.org는 합집합 의미를 위해 자체 속성을 만들었다.

## 4. 이 장에서 배운 구성 요소와 용도

| 구성 요소 | 이 장의 사용 예 | 기억할 점 |
|---|---|---|
| rdfs:subClassOf | DaySpa, FHEO 요인, foaf:Agent | 하위 클래스 구성원은 상위 클래스 구성원이기도 하다 |
| rdfs:subPropertyOf | foaf:name과 rdfs:label, 채팅 ID와 foaf:nick | 하위 속성 트리플은 상위 속성 트리플로도 성립한다 |
| rdfs:domain, rdfs:range | foaf:made, foaf:knows, 금융 예시 | 여러 개 선언하면 교집합 의미가 된다 |
| schema:domainIncludes, schema:rangeIncludes | schema:unitCode | 합집합 느낌. 이 선언만으로 타입 결론은 못 낸다 |
| owl:equivalentProperty | foaf:surname과 foaf:family_name | 같은 쓰임임을 확정할 때 쓴다 |
| owl:inverseOf | foaf:made와 foaf:maker | 방향만 반대인 속성 쌍 |
| owl:InverseFunctionalProperty | foaf:mbox 등 | 값이 같으면 같은 개체 |
| owl:SymmetricProperty | foaf:knows에는 일부러 쓰지 않았다 | 의견이 갈릴 관계에는 선언하지 않는다 |
| rdfs:seeAlso | og:email에서 foaf:mbox | 의미 약속 없이 참고만 가리킨다 |
| SPARQL CONSTRUCT | "1"을 클래스 구성원으로 변환 | 맞춤형 추론 규칙으로 쓸 수 있다 |

## 5. 핵심 개념 정리

원서는 장 끝에 다음 개념을 핵심으로 꼽는다.

- **Data.gov**: 미국 정부의 데이터를 RDF로도 제공하려는 프로젝트다. 원서의 이 항목은 정부 지출 데이터를 RDF로 제공하는 프로젝트라고 적는다.
- **FOAF**: 소셜 네트워크 정보를 표현하는 체계의 네임스페이스다. "Friend of a Friend"의 줄임말이다.
- **메타모델링(metamodeling)**: 대체로 다른 모델을 설명하는 모델을 만드는 기술이다. 구체적인 예는 한 모델의 클래스를 다른 클래스의 개체로 표현하는 방식이다. FOAF는 `foaf:membershipClass`로 이를 명시한다. 이 속성은 `foaf:Group` 타입의 개체를 그 그룹 구성원 전체의 클래스에 연결한다.
- **RDFa**: RDF 데이터를 웹 페이지에 심는 체계다.
- **OGP**: Facebook 사용자가 Facebook 밖의 페이지에 링크할 수 있게 하는 Open Graph Protocol이다.

## 6. 이 장에서 가져갈 것

- 큰 서비스도 RDFS-Plus의 작은 구성 요소를 조합해서 돌아간다.
- 모델의 엄밀함은 상황에 맞게 고른다. 분산 환경에서는 열린 세계 가정에서도 참인 선언이 유리하고, 한곳에서 관리하는 환경에서는 느슨한 선언이 실용적이다.
- 모든 사람이 같은 이름을 쓰게 만들 수 없다. 서로 다른 어휘가 공존하되, 그 사이를 RDFS-Plus로 잇는 것이 시맨틱 웹의 방식이다.
- 데이터가 엉망이어도 클래스로 바꾸고, 관계를 선언하고, SPARQL로 검증하면 쓸 수 있는 형태로 길들일 수 있다.
