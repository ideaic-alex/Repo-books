# 요약과 핵심 개념

이 문서는 장 끝의 요약과 핵심 개념 목록을 정리한다. 여기서 말하는 요약은 15장의 모든 안티패턴 분석을 관통하는 한 가지 생각으로 모인다. 모델이 쓸모 있는지는 그 모델이 내놓는 추론이 쓸모 있고 의미 있는지로 판단한다.

---

## 1. 왜 세 가정을 따라야 하나

5장에서 본 것처럼 링크드 데이터를 웹 규모로 지원하려면 시맨틱 웹의 기본 가정, 곧 AAA, 열린 세계, 이름 중복 허용은 바람직한 정도가 아니라 필수다. 이 가정이 없으면 링크드 데이터가 존재할 수 없다. 좋든 싫든 링크드 데이터 시스템이 갖게 되는 성질이다. 따라서 이 가정과 어울리는 모델을 정의해야 하고, 가정은 모델링 언어와 관행에 매우 구체적인 제한을 건다.

RDF의 구조는 주어, 서술어, 목적어라는 익숙한 문법 요소로 된 문장이다. OWL의 구조에는 클래스, `subClassOf`, 속성 같은 익숙한 개념이 있다. 그러나 모델의 의미를 정하는 것은 OWL의 추론 규칙이고, 그 규칙에 시맨틱 웹의 가정이 녹아 있다. 가정에 맞는 쓸모 있는 모델을 만들었는지 알려면 그 모델이 지원하는 추론이 쓸모 있고 의미 있는지 확인하면 된다.

---

## 2. 오류인가, 아닌가

AAA 때문에 이 장의 습관들을 "오류"라고 부를 수는 없다. 모두 RDF/OWL의 유효한 표현이다. 다만 모델러가 만들면서 의도한 바를 이루지 못한다는 뜻에서 잘못된 것이다. 각각 모델이 내놓는 추론을 꼼꼼히 살피면 어긋남이 드러난다.

| 유형 | 사례 | 성격 |
|---|---|---|
| 요구사항 자체가 가정과 충돌 | 객체화 오류 | 모델을 고쳐서 해결할 수 없다 |
| 요구사항은 가정과 맞고 모델이 서툰 경우 | 배타성 오류 | 간단한 패턴(교집합)으로 쉽게 고칠 수 있다 |

---

## 3. 핵심 개념

장이 소개하거나 다듬은 개념을 정리한다.

| 개념 | 뜻 |
|---|---|
| 시맨틱 웹의 가정 | AAA(누구든 무엇이든 어떤 주제에 대해서든 말할 수 있다), 열린 세계, 이름 중복 허용 |
| 추론(inferencing) | OWL의 추론은 시맨틱 웹 가정을 존중하도록 조율되어 있다. 그래서 초보 모델러를 오해하게 하는 미묘함이 생긴다 |
| 역량 질문 | 모델의 요구사항 범위를 정하는 질문 |
| 완전성(completeness) | 모델이 시나리오를 얼마나 덮는가 |
| 구체성(specificity) | 시나리오의 구체적 용어를 모델이 얼마나 담는가 |
| 세밀도(granularity) | 모델의 용어가 얼마나 정밀하게 정의되었는가 |
| 형식성(formality) | 정의가 얼마나 형식화되었는가 |
| 재사용성(reusability) | 온톨로지가 계속 쓸모 있는 답을 내는 상황의 범위 |
| 변화를 위한 모델링(modeling for variability) | 모델이 공통점뿐 아니라 변이도 기술해야 한다는 요구. 시맨틱 웹 모델링의 특징 |
| 재사용을 위한 모델링(modeling for reuse) | 완전히 예측할 수 없는 용도를 위해 모델을 설계하는 기술 |
| 희망적 이름 붙이기(wishful naming) | 이름만 보고 리소스가 모델이 공식적으로 보장하는 것 이상을 뜻한다고 믿는 모델러의 경향 |
| 모델 테스트(model testing) | 모델의 경계를 시험해서 모델이 끌어낼 수 있는 추론의 한계를 알아내는 과정 |

---

## 4. 이 장에서 기억할 순서

1. 시작은 웹의 모델, 조직의 기존 자산, 처음부터 설계 중 하나로 한다.
2. 시나리오에서 역량 질문을 뽑아 범위를 잡는다.
3. 말하려는 것이 추론으로 따라 나오게 모델을 쓰고, 경계 사례로 시험한다.
4. 이름은 읽히는 쪽과 불투명한 쪽의 장단점을 따져 고르고, 읽히는 쪽이면 관습을 따른다.
5. 클래스와 개체는 구성원을 상상할 수 있는지, 속성의 구체적 값을 아는지로 가른다.
6. 안티패턴을 만나면 클래스 사이의 속성, 펀닝, 후보 범위 가정, 객체 시스템의 기대, 빈 클래스 증식을 점검한다.
