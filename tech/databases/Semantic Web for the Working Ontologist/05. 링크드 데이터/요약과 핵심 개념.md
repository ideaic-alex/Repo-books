# 요약과 핵심 개념

5장 전체를 한 번에 되짚는 문서다. 링크드 데이터 세 가지 규칙, 이 장에서 배운 도구들, 그리고 장 끝에 정리된 핵심 개념 네 가지를 묶어서 본다.

---

## 1. 장 요약

데이터의 웹을 엮으려면 세 가지 규칙을 지켜야 한다.

1. 모든 것에 HTTP URI로 이름을 붙인다.
2. 그 URI에 접근할 때마다 해당 리소스에 대한 설명을 알맞은 형식으로 제공한다.
3. 그 설명 안에 다른 것들의 HTTP URI로 가는 링크를 넣는다.

이 장은 이 규칙을 실천하는 데 필요한 내용을 순서대로 보여 주었다.

| 배운 것 | 한 줄 요약 | 상세 문서 |
|---|---|---|
| URI 만들기 | 안정적이고 구현 세부가 없는 HTTP URI, 기존 유일 ID 활용, CURIE를 위한 알파벳 시작 | [HTTP URI 만들기](HTTP%20URI%20%EB%A7%8C%EB%93%A4%EA%B8%B0.md) |
| 웹의 세 기둥 | DNS, 콘텐츠 협상, 리디렉션(303 See Other) | [HTTP와 웹의 세 기둥](HTTP%EC%99%80%20%EC%9B%B9%EC%9D%98%20%EC%84%B8%20%EA%B8%B0%EB%91%A5.md) |
| 해시 대 슬래시 | 작은 묶음은 해시, 조각 단위 전송은 슬래시, 절충은 `#this` | [해시 URI와 슬래시 URI](%ED%95%B4%EC%8B%9C%20URI%EC%99%80%20%EC%8A%AC%EB%9E%98%EC%8B%9C%20URI.md) |
| 실제 사례 | DBLP, UniProt, DBpedia, Wikidata | [실제 링크드 데이터 둘러보기](%EC%8B%A4%EC%A0%9C%20%EB%A7%81%ED%81%AC%EB%93%9C%20%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EB%91%98%EB%9F%AC%EB%B3%B4%EA%B8%B0.md) |
| 외부 링크 | URI 재사용, 표준으로 URI 조립, 스키마 링크, LOV | [데이터셋 사이에 링크 걸기](%EB%8D%B0%EC%9D%B4%ED%84%B0%EC%85%8B%20%EC%82%AC%EC%9D%B4%EC%97%90%20%EB%A7%81%ED%81%AC%20%EA%B1%B8%EA%B8%B0.md) |
| 5스타와 LOD 클라우드 | 5단계 누적 체계, 약 3000개 데이터셋과 1500억 트리플(2017) | [5스타 원칙과 LOD 클라우드](5%EC%8A%A4%ED%83%80%20%EC%9B%90%EC%B9%99%EA%B3%BC%20LOD%20%ED%81%B4%EB%9D%BC%EC%9A%B0%EB%93%9C.md) |
| LDP | HTTP 동사로 링크드 데이터 리소스를 읽고 쓰는 표준 | [5스타 원칙과 LOD 클라우드](5%EC%8A%A4%ED%83%80%20%EC%9B%90%EC%B9%99%EA%B3%BC%20LOD%20%ED%81%B4%EB%9D%BC%EC%9A%B0%EB%93%9C.md) |

링크드 데이터를 게시하는 쪽은 이 모든 것을 합쳐서, 웹 표준만으로 링크드 데이터를 찾고 읽고 쓸 수 있는 구조를 갖추게 된다.

---

## 2. 핵심 개념

장 끝에서 정리한 네 가지 핵심 개념은 다음과 같다.

| 개념 | 뜻 | 풀이 |
|---|---|---|
| HTTP URI | 무엇이든 이름을 붙이되 HTTP 프로토콜을 쓰는 URI | 이름이자 곧바로 접속할 수 있는 주소 |
| 디레퍼런싱(dereferencing) | HTTP URI를 풀어서 그것이 가리키는 리소스의 정보를 찾는 과정 | 이름으로 설명서를 찾아오는 일 |
| 콘텐츠 협상(content negotiation) | 같은 HTTP URI를 풀 때 HTTP 서버가 클라이언트의 요구에 따라 다른 형식의 콘텐츠를 주는 과정 | 같은 주소에서 사람에게는 HTML, 프로그램에는 RDF |
| 링크드 데이터 플랫폼(LDP) | 웹 애플리케이션이 HTTP로 리소스를 게시, 편집, 삭제하는 방법에 대한 권고 모음 | REST 방식으로 링크드 데이터를 읽고 쓰는 표준 |

## 3. 이 장에서 자주 헷갈리는 구분

| 헷갈리는 쌍 | 구분 |
|---|---|
| 웹 위의 데이터 대 데이터의 웹 | 파일을 올려 둔 것과, 데이터 항목끼리 링크로 이어진 것 |
| URL 대 URI | URL은 웹에 있는 문서의 주소, URI는 웹에 없는 것까지 이름 붙이는 식별자 |
| 대상의 URI 대 설명의 URI | 고양이와 그 고양이에 관한 문서는 다른 것이므로 URI도 달라야 한다 |
| 200 대 303 | 웹에 있는 문서는 200, 웹에 없는 대상의 URI는 설명 문서로 303 안내 |
| 해시 URI 대 슬래시 URI | 파일 하나로 묶어 한 번에 받음 대 대상별로 303 거쳐 받음 |
| LOD 클라우드의 "클라우드" | 클라우드 컴퓨팅이 아니라 링크된 데이터셋의 그래프 |
