# RDF 시맨틱 웹의 기초

이 장은 시맨틱 웹의 바닥을 이루는 RDF를 다룬다. 표 데이터를 여러 서버에 나눠 담는 세 가지 방법에서 출발해, RDF가 칸 하나를 트리플로 표현하는 방식을 택한 이유, URI로 노드의 정체를 가려 그래프를 합치는 방법, 표를 RDF로 옮기는 규칙을 차례로 설명한다. 이어서 진술에 대한 진술, 이름 있는 그래프, 여러 직렬화 형식, 빈 노드와 목록을 다룬다.

RDF가 하는 일은 분산 데이터를 표현하는 것 하나뿐이다. 이 장을 읽고 나면 이후 장에서 나오는 RDFS, OWL, SPARQL이 모두 이 트리플 위에 올라간다는 점이 분명해진다.

---

## 1. 핵심 요점

- 시맨틱 웹은 문서와 문서가 아니라 세상의 대상(리소스)과 대상을 잇는다. RDF는 누구나 어떤 대상에 대해서든 말할 수 있게 하는(AAA) 분산 데이터 모델이다.
- 표를 행, 열, 칸 단위로 나눌 수 있으며, RDF는 칸 단위를 택했다. 칸 하나가 주어·서술어·목적어로 이루어진 트리플이다.
- 트리플 집합은 방향 그래프로 볼 수 있다. 여러 출처의 그래프는 트리플을 모두 모아 병합하며, 같은 URI를 가진 노드끼리 같은 노드로 본다.
- URI는 웹의 전역 식별자이고, 책의 예시는 줄임 표기인 CURIE(네임스페이스:이름)를 쓴다. rdf, rdfs, skos, owl은 W3C가 정한 표준 네임스페이스다.
- rdf:type은 개체와 타입을, rdf:Property는 서술어로 쓰이는 식별자를 나타낸다. 표를 바꿀 때는 행과 열에 URI를 주고 칸마다 트리플을 만들며 행마다 타입 트리플을 더한다.
- 진술에 대한 진술(리이피케이션)은 행 모델링 방식이나 rdf:subject, rdf:predicate, rdf:object로 하고, 트리플 집합에 URI 이름을 붙이는 이름 있는 그래프(쿼드)로도 할 수 있다.
- 같은 트리플을 N-Triples, Turtle, RDF/XML, JSON-LD로 적을 수 있고, 이름 있는 그래프는 N-Quads나 TriG로 적는다.
- 빈 노드는 "그런 것이 존재한다"를 뜻하며 일반적으로는 쓰지 않기를 권한다. RDF의 순서는 rdf:first, rdf:rest, rdf:nil로 이루어진 목록으로 표현한다.
