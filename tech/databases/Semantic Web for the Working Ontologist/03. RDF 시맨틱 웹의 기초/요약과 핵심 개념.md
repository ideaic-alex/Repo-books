# 요약과 핵심 개념

이 문서는 3장의 결론과 핵심 개념을 한곳에 모은다. 앞의 문서를 읽지 않고도 장 전체의 흐름을 잡을 수 있게 구성했다.

---

## 1. 장의 결론

RDF는 단순한 표준이다. 맡은 일은 웹에 분산된 데이터를 모델링하는 것이고, 그 일만 한다. 데이터를 분산해서 모델링하려면 RDF를 쓰거나, 쓰지 않더라도 결국 RDF를 다시 발명하게 된다. 그만큼 들어 있는 것이 적다.

RDF의 기본 생각은 다음 세 가지로 요약된다.

1. 분산 환경에서는 언급하는 모든 것에 전역 식별자가 필요하다.
2. 어떤 것을 다른 것과 연결하려면 연결의 이름도 필요하다.
3. 그 이름들은 모두 전역이어야 한다.

전역 식별자는 하이퍼텍스트 웹이 이미 제공해 왔다. 웹 인프라가 이 식별자를 어떻게 처리하는지는 뒤에서 자세히 보겠지만, 그것은 시맨틱 웹의 일이 아니라 우리가 매일 쓰는 웹의 일이다. RDF는 분산된 정체성 문제를 푼 것이 아니라, 웹이 푼 해법을 다시 쓰는 것이다.

따라서 웹에 분산된 데이터를 표현하는 데 필요한 최소한은 한 웹 식별자(URI)를 다른 식별자에 잇는 것이고, 그 연결 이름도 URI여야 한다. 이것이 RDF 트리플의 바탕이다. 나머지는 모두 배관 공사에 가깝다.

| 분산 데이터에 필요한 것 | RDF가 제공하는 것 |
| --- | --- |
| 데이터를 저장하는 방법 | 직렬화 형식(N-Triples, Turtle, RDF/XML, JSON-LD 등) |
| 표처럼 분산되지 않은 형태에서 바꾸는 방법 | 표를 트리플로 바꾸는 규칙(행 URI, 열 URI, 칸마다 트리플) |
| 여러 출처를 합치는 방법 | 트리플 집합의 합집합과 URI 기반 노드 동일성 |

데이터 모델로서의 RDF는 여러 출처의 정보를 병합할 때 무슨 일이 일어나야 하는지를 분명히 규정한다. 그러나 그 과정을 구현하는 알고리즘이나 기술은 제공하지 않는다. 그런 기술은 다음 장들의 주제다.

## 2. 핵심 개념 표

| 개념 | 설명 |
| --- | --- |
| RDF(Resource Description Framework) | 웹에 데이터를 분산하는 방법 |
| 트리플(triple) | RDF의 기본 데이터 구조. 주어, 서술어, 목적어로 이루어진다 |
| 그래프(graph) | RDF 데이터를 노드와 링크의 구조로 본 것 |
| 병합(merging) | 두 그래프를 하나인 것처럼 다루는 과정 |
| URI | URL(Uniform Resource Locator)의 일반화. 웹의 전역 이름 |
| 네임스페이스 | 한 권한 아래 속한 이름의 집합. 서로 다른 주체가 같은 단어를 다르게 쓸 수 있게 한다 |
| CURIE | URI의 줄임 표기. 네임스페이스 식별자와 이름을 콜론으로 잇는다 |
| rdf:type | 개체와 그 타입 사이의 관계 |
| rdf:Property | RDF에서 모든 속성의 타입 |
| 리이피케이션(reification) | 다른 진술에 대해 진술하는 일. RDF에서는 rdf:subject, rdf:predicate, rdf:object로 한다 |
| N-Triples, Turtle, RDF/XML | RDF의 직렬화 문법 |
| 빈 노드(blank node) | URI가 없어 전역으로 가리킬 수 없는 RDF 노드. 이름 없는 대상을 대신한다 |

원서의 핵심 개념 목록은 URI를 "Uniform Resource Indicator"로 풀어 쓰고 있다. 본문에서는 Uniform Resource Identifiers라고 불렀으며 이 노트도 본문을 따랐다.

## 3. 장에서 배운 다른 개념

핵심 개념 목록에는 없지만 장에서 중요하게 다룬 개념도 함께 정리한다.

| 개념 | 한 줄 설명 | 문서 |
| --- | --- | --- |
| 리소스(resource) | 누군가 말하고 싶어 하는 모든 대상 | RDF와 분산 데이터 |
| AAA 슬로건 | 누구나 어떤 주제에 대해서든 무엇이든 말할 수 있다 | RDF와 분산 데이터 |
| IRI | 모든 언어의 문자를 쓸 수 있는 URI의 일반화 | URI와 네임스페이스 |
| 역참조 | URI를 따라 웹의 파일이나 위치를 찾아가는 일 | URI와 네임스페이스 |
| 이름 있는 그래프 | URI 이름이 붙은 트리플 집합 | 진술에 대한 진술과 이름 있는 그래프 |
| 쿼드 | 트리플에 그래프를 더한 네 값의 묶음 | 진술에 대한 진술과 이름 있는 그래프 |
| N-Quads, TriG | 이름 있는 그래프를 쓰는 직렬화 형식 | RDF 직렬화 형식 |
| JSON-LD | JSON으로 쓰는 RDF 직렬화 형식 | RDF 직렬화 형식 |
| rdf:first, rdf:rest, rdf:nil | RDF 목록을 이루는 속성과 끝 표시 | 빈 노드와 순서 있는 목록 |

## 4. 장의 흐름 한눈에 보기

```text
표 데이터를 웹에 분산 → 칸 단위로 쪼개 트리플로 표현
  → 합칠 때 같은 노드는 같은 URI로 판단 → CURIE로 줄여 쓰고 네임스페이스로 구분
  → 표를 트리플로 바꾸는 규칙 → 진술에 대한 진술(리이피케이션, 이름 있는 그래프)
  → 직렬화 형식(Turtle 등) → 이름 없는 대상(빈 노드)과 순서(목록)
```

| 절 | 질문 | 답 |
| --- | --- | --- |
| 분산 | 표를 어떻게 나눌까 | 칸 단위(트리플) |
| 병합 | 합칠 때 같은 노드란 | 같은 URI |
| 식별자 | URI를 어떻게 줄여 쓸까 | CURIE와 네임스페이스 |
| 변환 | 표를 어떻게 RDF로 | 행·열 URI와 칸마다 트리플 |
| 확장 | 진술에 대해 말하려면 | rdf:subject 등, 이름 있는 그래프 |
| 표기 | 텍스트로 어떻게 쓸까 | N-Triples, Turtle, RDF/XML, JSON-LD |
| 예외 | 이름 없는 대상은 | 빈 노드 |
