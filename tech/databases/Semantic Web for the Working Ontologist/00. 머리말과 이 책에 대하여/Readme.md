# 머리말과 이 책에 대하여

이 문서는 『Semantic Web for the Working Ontologist』 3판의 머리말과 앞표지, 판권, 차례를 한국어로 정리한 노트다. 본문에 들어가기 전에 이 책이 어떤 책인지, 누가 무엇을 바라고 썼는지, 17개 장이 어떤 순서로 이어지는지를 먼저 잡아 두는 것이 목적이다. 여행 전에 지도를 한 번 훑어 두는 것과 비슷하다.

책의 정식 제목은 부제까지 포함해 "Semantic Web for the Working Ontologist: Effective Modeling for Linked Data, RDFS, and OWL"이다. 저자는 Dean Allemang, Jim Hendler, Fabien Gandon 세 사람이고, ACM Books 시리즈의 33번째 책으로 2020년에 나왔다. 이 노트는 책의 서술 시점을 따르므로, 표준이나 데이터셋의 상태가 이후 바뀌었을 수 있다.

---

## 1. 책의 목적과 대상 독자

시맨틱 웹(Semantic Web)은 데이터를 웹 규모로 흩어져 있는 공유 자원으로 다루는 기술 묶음이다. 앞표지 소개글은 요즘 기업이 자기 데이터로 고객, 시장, 제품을 예측하고 이해하는 데 큰 성과를 냈지만, 비즈니스가 서로 더 촘촘히 연결되고 세계화될수록 기업 데이터는 혼자 서 있는 덩어리가 아니라 거대한 데이터 웹의 일부가 된다고 설명한다. 그래서 세계 규모로 데이터를 관리하는 능력이 지금 기업의 핵심 역량이라는 것이다.

시맨틱 웹은 이 문제를 설계 단계부터 염두에 둔다. 데이터가 엄청나게 넓게 분산되어 있다는 전제를 기본으로 깔고 만든 기술이기 때문이다.

앞표지 소개글에 따르면 1판과 2판의 목표이자 3판이 이어받은 목표는 세 가지로 정리할 수 있다.

- 시맨틱 웹 기술 묶음을 처음부터 끝까지 하나의 흐름으로 설명한다.
- 표준이 무엇이고 어떻게 동작하는지뿐 아니라, 표준이 무엇을 목표로 하는지와 왜 그렇게 설계되었는지까지 말한다.
- 이를 통해 전 세계에 분산된 지식의 웹을 의미 있게 관리하는 방법을 일관된 이야기로 들려준다.

제목의 "Working Ontologist"는 "일하는 온톨로지 전문가", 곧 현업에서 온톨로지를 실제로 만들고 쓰는 사람을 뜻한다. 이론 교과서가 아니라 모델링 실무서라는 성격이 제목에 들어 있다. 부제의 Linked Data(링크드 데이터), RDFS, OWL은 이 책이 다루는 세 기둥이다.

| 구분 | 내용 |
|---|---|
| 책 제목 | Semantic Web for the Working Ontologist |
| 부제 | Effective Modeling for Linked Data, RDFS, and OWL |
| 저자 | Dean Allemang, Jim Hendler, Fabien Gandon |
| 시리즈 | ACM Books 33번 |
| 판 | 3판 (저작권 표기 2020년) |
| 이 노트의 독자 | 온톨로지와 시맨틱 웹을 처음 공부하는 개발자 |

표를 읽는 법은 간단하다. 이 책의 핵심 주제는 "데이터를 웹처럼 분산된 자원으로 보고, 그 의미를 모델로 표현하는 일"이고, 그 도구가 링크드 데이터, RDFS, OWL이라는 것이다.

## 2. 3판에서 달라진 점과 저자 소개

### 2.1 왜 3판이 늦게 나왔나

2판이 나온 지 거의 10년이 지나서야 3판이 나왔다. 1판은 3판 시점에서 12년 전 책이다. 저자들은 오랫동안 3판을 내 달라는 질문을 받았고, 처음에는 표준이 충분히 진전하지 않았다고 답했다. 그러다 RDF용 Shapes Constraint Language(SHACL, 도형 제약 언어)가 승인되고, Schema.org가 나오고, 웹에서 데이터를 공유하는 프로토콜(Linked Data Protocol)이 자리를 잡으면서 그 답은 더 이상 맞지 않게 되었다. 솔직한 이유는 두 저자가 다른 프로젝트로 옮겨 가 있었고 개정할 기운이 없었다는 것이다.

계기를 만든 사람은 Fabien Gandon이다. 그가 3판 이야기를 꺼냈고, Jim Hendler가 둘 다 일정이 꽉 찼으니 새 시각과 에너지를 가진 세 번째 저자가 필요하다고 넌지시 말했다. 설득 끝에 Fabien이 합류했고, 저자들은 그의 에너지와 주도가 없었다면 이 프로젝트는 없었을 것이라고 적는다.

### 2.2 시간이 흐르며 바뀐 환경

그사이 저자들은 정부, 산업계, 대형 학술 네트워크의 실제 프로젝트에서 좋은 경험과 나쁜 경험을 모두 쌓았다. 그 결과 시맨틱 웹 기술 묶음이 훨씬 큰 규모의 프로젝트에서 어떤 역할을 할 수 있는지 더 성숙하게 이해하게 되었다고 한다. 또 웹에서 시맨틱의 역할이 커지는 데 그치지 않고, 인공지능, 대규모 전자상거래, 지식 그래프 시스템이 퍼지는 현대 웹 생태계에서 필수가 되었다고 본다.

새 예시와 모델링 기법은 서로 다른 여러 데이터셋을 묶거나, 정리되지 않은 웹 텍스트에서 뽑아낸 정보에 구조를 입히는 프로젝트에서 나왔다. 이런 일은 오늘날 기업이 쓰는 기계 학습 기법의 바탕이기도 하다.

### 2.3 3판의 변경 사항 정리

| 영역 | 달라진 점 |
|---|---|
| 구성 | 링크드 데이터를 다루는 장이 통째로 추가되었다. 주로 Fabien이 맡았고, 시맨틱 웹의 바탕인 웹 아키텍처에 무게를 둔다. |
| 예시 전반 | 모든 예시를 다시 검토하고 필요한 곳은 최신으로 고쳤다. |
| CHEBI, QUDT | 2판 이후 새 버전이 나와 반영했다. |
| Good Relations | 더 큰 Schema.org 활동에 흡수되었다. 14장에서 다룬다. |
| data.gov 예시 | 데이터 공개 방식이 바뀌었다. 예전에 RDF로 공개되던 일부 데이터셋이 더는 RDF가 아니다. |
| 표 형식 데이터의 RDF 변환 | 이전 판에서 설명한 방법이 이제 웹 서비스로 제공되어, 데이터 공개자가 직접 RDF로 변환할 필요가 없어졌다. |
| 모델링 조언 | 15장과 16장을 실무 경험과 Fabien의 통찰을 반영해 갱신했다. |
| BridgeDB | 링크드 데이터 원칙을 생명 과학에 간단히 적용한 사례로 작은 절을 새로 넣었다. |
| 11장(SKOS) | 2판 이후 바뀐 AGROVOC 어휘집 내용을 반영했다. |
| 예제 데이터와 쿼리 | 모든 데이터셋과 쿼리를 온라인에서 내려받고 실행할 수 있다. |

표에서 가장 눈에 띄는 변화는 두 가지다. 하나는 링크드 데이터 장의 신설이고, 다른 하나는 예제 데이터를 단순히 내려받는 수준을 넘어 쿼리까지 바로 돌려 볼 수 있게 한 것이다. 나머지는 대체로 "세상이 바뀐 만큼 예시와 조언을 최신으로 맞춘" 변화다.

## 3. 책의 구성

책은 17개 장으로 되어 있고, 뒤에 참고 문헌, 저자 약력, 색인이 붙는다. 흐름을 크게 보면 "시맨틱 웹이 무엇이고 왜 필요한가(1~2장) → 데이터를 표현하고 다루는 기초인 RDF, 아키텍처, 링크드 데이터, SPARQL(3~6장) → RDFS와 RDFS-Plus로 의미를 얹기(7~11장) → OWL로 더 정밀하게 모델링하기(12~13장) → 실제 온톨로지 사례와 모델링 실무 지침(14~16장) → 정리와 앞으로의 과제(17장)"다.

아래 표의 한 줄 요약은 책의 차례에 나온 절 제목을 바탕으로 이 노트가 정리한 것이다.

| 장 | 한국어 제목 | 한 줄 요약 |
|---|---|---|
| 1 | 시맨틱 웹이란 무엇인가 | 웹이란 무엇인지, 데이터로 소통한다는 것이 무슨 뜻인지, 분산된 데이터가 왜 문제인지를 소개한다. |
| 2 | 시맨틱 모델링 | 사람 사이의 소통, 설명과 예측, 변이(다양성) 중재, 표현력이라는 관점에서 모델링이 무엇인지 다룬다. |
| 3 | RDF 시맨틱 웹의 기초 | 웹에 데이터를 분산하고 여러 출처의 데이터를 합치는 방법, URI와 네임스페이스, 직렬화 형식, 빈 노드를 설명한다. |
| 4 | 시맨틱 웹 애플리케이션 아키텍처 | RDF 파서와 직렬화기, RDF 저장소, 애플리케이션 코드, 데이터 연합으로 이루어진 구조를 보여 준다. |
| 5 | 링크드 데이터 | 데이터 웹을 짜는 방법, HTTP와 웹 아키텍처, 해시 방식과 슬래시 방식, 직접 확인하는 실습을 다룬다. |
| 6 | SPARQL로 시맨틱 웹 질의하기 | 질의 언어 SPARQL의 기본, CONSTRUCT 쿼리, 규칙으로 쓰기, 전이 쿼리, 고급 기능을 설명한다. |
| 7 | RDF 확장하기 RDFS와 SHACL | RDFS로 추론하는 방법, 추론의 위치와 시점, RDF의 기대(제약) 표현을 다룬다. |
| 8 | RDF 스키마 | 스키마 언어의 기능, RDFS 언어, 모델링 조합과 패턴, 도메인과 레인지 모델링을 설명한다. |
| 9 | RDFS-Plus | 역관계, 의존 관계 네트워크, 동등성, 데이터베이스 병합, 함수형 속성을 통한 동일성 계산을 다룬다. |
| 10 | 실전에서 RDFS-Plus 쓰기 | Schema.org, 공개 정부 데이터, FOAF, Facebook Open Graph Protocol에서 쓰이는 모습을 본다. |
| 11 | SKOS로 어휘 관리하기 | SKOS의 개념, 의미 관계, 개념 체계, 무결성, 실제 활용을 다룬다. |
| 12 | 기본 OWL | 제약(restriction)과 도전 문제, 제약의 다른 서술 방식을 설명한다. |
| 13 | OWL의 개수 세기와 집합 | 합집합과 교집합, 개수 제약, 여집합, 서로소 집합, 모순, 충족 불가능한 클래스, 클래스 관계 추론을 다룬다. |
| 14 | 웹의 온톨로지 전체 종합 | 온톨로지 아키텍처, 양과 단위, 생물학 온톨로지, 금융 산업 온톨로지 FIBO 사례를 본다. |
| 15 | 좋은 모델링과 나쁜 모델링 | 시작하는 법, 좋은 이름 짓기, 흔한 모델링 오류를 정리한다. |
| 16 | OWL 전문가 모델링 | OWL의 부분 집합과 모델링 철학, OWL 2의 모델링 기능을 다룬다. |
| 17 | 맺음말과 앞으로의 과제 | 책 전체를 맺고 앞으로의 과제를 이야기한다. |

표에서 보듯 RDF에서 RDFS, RDFS-Plus, SKOS를 거쳐 OWL로 표현력이 점점 커지는 순서로 배치되어 있다. 이 점진적 구성이 이 책의 특징이다. 앞 장의 기능으로 해결되지 않는 문제를 만나면 다음 장의 더 강한 도구를 소개하는 식이다.

### 3.1 도구의 표현력이 커지는 순서

| 단계 | 장 | 이 단계의 도구 |
|---|---|---|
| 데이터 표현 | 3~5 | RDF, 링크드 데이터 원칙 |
| 질의 | 6 | SPARQL |
| 가벼운 의미 | 7~11 | RDFS, SHACL, RDFS-Plus, SKOS |
| 정밀한 의미 | 12~13, 16 | OWL |
| 실전 | 10, 14, 15 | Schema.org, FOAF, FIBO 같은 사례와 모델링 지침 |

이 표는 책의 개념 지도다. 처음에는 "데이터를 어떻게 표현하나"를 묻고, 다음에 "어떻게 꺼내나"를 묻고, 그다음에 "데이터에 의미를 얹으면 무엇이 가능해지나"를 점점 깊게 묻는다.

## 4. 읽는 순서 안내

차례의 흐름이 앞 장의 내용 위에 쌓는 구조이므로 기본은 1장부터 순서대로 읽는 것이다. 다만 목적에 따라 건너뛸 수 있는 길을 아래처럼 정리했다. 이 경로는 차례의 구성에서 이 노트가 추론한 제안이며, 저자가 지정한 읽기 순서는 아니다.

| 읽는 목적 | 추천 경로 | 이유 |
|---|---|---|
| 처음부터 제대로 배운다 | 1장부터 17장까지 순서대로 | 각 장이 앞 장의 개념을 전제로 한다. |
| 데이터를 연결하고 질의하는 데만 관심 있다 | 1, 3, 4, 5, 6장 | RDF, 아키텍처, 링크드 데이터, SPARQL이 데이터 쪽 핵심이다. |
| 가벼운 모델링으로 충분하다 | 1~3장, 7~11장 | RDFS, RDFS-Plus, SKOS로 실무 모델링의 상당 부분을 다룬다. |
| 정밀한 온톨로지를 만들어야 한다 | 앞의 기초에 이어 12, 13, 16장 | OWL의 제약, 개수와 집합, 전문가 기능을 다룬다. |
| 실제 사례부터 보고 싶다 | 10장과 14장 | Schema.org, FOAF, QUDT, 생물학 온톨로지, FIBO가 나온다. |
| 모델링 실수를 줄이고 싶다 | 15장 | 이름 짓기와 흔한 오류를 모았다. |

표는 "내 목적에 필요한 장이 어디인가"를 찾는 용도로 쓰면 된다. 단, 개념 사이에 의존이 있으므로 건너뛰다가 용어가 낯설면 앞 장의 해당 부분으로 돌아가는 편이 빠르다.

## 5. 책에서 쓰는 표기 규칙과 예제 안내

### 5.1 그림

3판의 모든 그림은 오픈 소스 Cytoscape 플랫폼으로 만들었다. data.world용 플러그인을 사용했고, 저자들은 이 연결을 책의 필요에 맞게 다듬어 준 data.world 쪽에 고마움을 표했다. 이 노트는 원서의 그림을 싣지 않고, 그림이 보여 주는 구조를 글과 표, 짧은 코드로 풀어 설명한다.

### 5.2 코드와 예제 데이터

책의 예제는 RDF를 직렬화한 Turtle, 질의 언어 SPARQL, OWL 정의 같은 코드를 중심으로 한다. 이 노트에서는 코드와 키워드, 접두어가 붙은 이름(`rdf:type` 같은 것)을 영어 그대로 두고, 코드 속 설명은 코드블록 아래 본문에서 푼다.

2판 때 가장 많이 받은 요청이 예제 뒤의 데이터를 보여 달라는 것이었다. GitHub에 올리는 방법도 제안받았지만, 그러면 쿼리를 돌리려고 학생이 각자 시맨틱 데이터베이스를 설치해야 해서 재미가 없다고 저자들은 판단했다. 3판은 그 대신 데이터셋과 쿼리를 모두 온라인에 올려 두었다.

| 항목 | 안내 |
|---|---|
| 데이터셋 | 내려받을 수 있다. |
| 쿼리 | 책에 나온 쿼리를 찾아 데이터에 대고 바로 실행하면 책과 같은 답이 나온다. |
| 변형 실험 | 쿼리를 자기 사본으로 만들어 조금씩 바꿔 가며 동작을 확인할 수 있다. |
| 위치 | 앞표지에는 data.world/swwo로, 머리말에는 workingontologist.org 웹사이트로 안내되어 있다. 정확한 현재 주소는 확인이 필요하다. |
| 답의 검증 | data.world가 데이터와 쿼리를 호스팅하여 저자들이 모든 답이 맞는지 확인했다. |

표의 핵심은 책을 읽기만 하지 말고 직접 쿼리를 돌려 보라는 것이다. 저자들의 표현대로 책의 예시가 살아 움직이게 된 셈이고, 독자가 데이터를 자기 것으로 만들어 새 쿼리, 새 아이디어, 새 데이터를 더해 가는 학습자 공동체가 생기기를 바란다.

### 5.3 책이 자주 쓰는 실제 사례

| 사례 | 어디서 | 간단한 설명 |
|---|---|---|
| Schema.org | 10장, 14장 | 웹 페이지에 구조화된 의미를 넣는 어휘. Good Relations가 흡수되었다. |
| QUDT | 14장 | 양, 단위, 차원, 유형을 다루는 온톨로지 |
| CHEBI | 14장 | 생물학 온톨로지의 하나 |
| FIBO | 14장 | 금융 산업 비즈니스 온톨로지 |
| AGROVOC | 11장 | FAO 등이 관리하는 농업 분야 어휘집 |
| FOAF | 10장 | 사람과 관계를 표현하는 어휘 |
| BridgeDB | 책에서 새로 추가된 작은 절 | 링크드 데이터 원칙을 생명 과학에 적용한 사례 |

위 표에서 FOAF, CHEBI 등의 한 줄 설명은 차례의 절 제목과 머리말이 알려 주는 범위까지만 적었다. 자세한 내용은 해당 장 노트에서 다룬다.

## 6. 이 노트의 읽는 법

이 노트는 책을 장별로 나눠 한국어로 다시 정리한 학습 노트다. 번역서가 아니라 설명서에 가깝다.

- 한 장이 폴더 하나이고, 폴더 안에 장 소개(Readme)와 주제별 문서가 들어 있다. 이 문서는 책 앞부분을 다룬 0장 격의 Readme다.
- 문서는 독립적으로 읽히도록 썼다. 장 순서를 지키면 더 좋지만, 한 문서만 열어도 이해되게 용어를 처음 나올 때 풀어 두었다.
- 용어는 통일해서 쓴다. 트리플(주어, 서술어, 목적어 세 쌍으로 이루어진 문장 하나), 온톨로지, 추론, 어휘, 네임스페이스처럼 한국어 풀이를 정해 두고 영어는 처음에만 병기한다. RDF, RDFS, OWL, SPARQL, SHACL, SKOS, URI, Turtle 같은 이름과 코드는 영어 그대로다.
- 원서의 문장을 그대로 옮기지 않고 자기 말로 다시 구성했다. 책의 예시와 규칙, 경고, 이유는 빠뜨리지 않으려 했다.
- 표를 많이 썼다. 비교나 정리가 필요한 곳은 표로 묶고, 표 아래에 읽는 법을 한두 문장 붙였다.
- PDF에서 추출한 글자가 깨진 코드는 문맥으로 복원했고, 불확실하면 그렇다고 밝혔다.

| 문서 | 한 줄 안내 |
|---|---|
| 이 Readme | 책의 소개, 3판의 변화, 17개 장 지도, 읽는 순서 |
| 1장~17장 폴더 | 각 장의 요점과 주제별 상세 문서 |
| 장 끝 문서 | 해당 장의 요약과 핵심 개념 |

마지막으로 책 앞쪽에는 ACM Books 시리즈 소개와 같은 시리즈의 다른 책 목록, 판권 정보, DOI 목록이 실려 있다. 이들은 시맨틱 웹 내용과 직접 관련이 없으므로 이 노트에서는 다루지 않는다.
