# 합집합과 교집합

12장에서 본 제약(restriction)은 "이런 속성에 이런 값을 가진 개체들"이라는 클래스를 만들어 준다. 이 장에서는 OWL이 여기에 집합 연산까지 얹어 준다는 점을 먼저 짚는다. 합집합, 교집합, 여집합으로 클래스와 제약을 서로 조합하면 훨씬 세밀한 설명을 만들 수 있다. 이 문서는 그중 합집합과 교집합을 다룬다.

개념을 먼저 일상에 빗대어 보자. "축구를 좋아하는 사람"과 "서울에 사는 사람"이라는 두 모임이 있다고 하자. 둘 중 어느 한쪽이라도 해당되는 사람을 모으면 합집합이고, 둘 다 해당되는 사람만 모으면 교집합이다. OWL은 이 연산을 클래스에 그대로 적용한다.

---

## 1. 집합 연산으로 새 클래스 만들기

OWL에서는 이미 정의된 클래스들을 합집합이나 교집합으로 묶어 새 클래스를 정의할 수 있다. 이 연산은 이름 있는 클래스뿐 아니라 제약에도 똑같이 쓸 수 있다. 그래서 아주 다양한 조건을 조합해서 표현할 수 있다. 각 연산의 의미는 이름이 같은 집합 연산의 의미와 그대로 일치한다.

문법은 RDF의 리스트 구조를 이용한다. 괄호 안에 클래스를 나열하면 된다.

```turtle
U1 a owl:Class ;
   owl:unionOf ( ns:A ns:B ... ) .
I1 a owl:Class ;
   owl:intersectionOf ( ns:A ns:B ... ) .
```

| 키워드 | 만드는 클래스 | 일상 비유 |
|---|---|---|
| owl:unionOf | 나열한 클래스 중 어느 하나라도 속하는 개체 | 동호회 A 또는 B 회원 |
| owl:intersectionOf | 나열한 모든 클래스에 동시에 속하는 개체 | 동호회 A 회원이면서 B 회원 |
| owl:complementOf | 해당 클래스에 속하지 않는 모든 것 | 동호회 A 회원이 아닌 모든 것 |

표에서 보듯 앞의 두 가지는 여러 클래스를 받는 목록형이고, 여집합은 클래스 하나만 받는다. 여집합은 「여집합과 서로소 집합」 문서에서 자세히 다룬다.

교집합으로 만든 클래스는 두 가지 방식으로 표현할 수 있다. 하나는 위 예처럼 클래스에 이름을 붙이는 방식이다. 다른 하나는 owl:Class 타입의 이름 없는 클래스(빈 노드)에 owl:intersectionOf를 붙여 정의하는 방식이다. 이름 없는 클래스는 owl:equivalentClass로 이름 있는 클래스와 연결하면 모델 안에서 다시 쓸 수 있다.

```turtle
bb:MajorLeagueBaseballPlayer owl:equivalentClass
  [ a owl:Class ;
    owl:intersectionOf
      ( bb:MajorLeagueMember bb:Player bb:BaseballEmployee )
  ] .
```

이 예는 메이저 리그 야구 선수를 "메이저 리그 구성원이면서, 선수이면서, 야구 직원인 개체"로 정의한다. 세 조건을 모두 만족해야 이 클래스의 개체가 된다.

## 2. 제약과 함께 쓰는 교집합

합집합과 교집합 자체는 어렵지 않다. 시맨틱 웹 모델링에서 이 연산이 빛나는 때는 제약과 같이 쓸 때다. 이유는 우리가 말로 하는 설명에 이미 교집합이 숨어 있는 경우가 많기 때문이다.

- "태양 주위를 도는 모든 행성"은 사실 "태양 주위를 도는 것들(hasValue 제약)"과 "행성들"의 교집합이다.
- "메이저 리그 야구 선수"는 "메이저 리그 팀에서 뛰는 것들(someValuesFrom 제약)"과 "야구 선수들"의 교집합이다.

이 둘을 그대로 코드로 옮기면 다음과 같다.

```turtle
:SolarPlanet a owl:Class ;
  owl:intersectionOf (
    :Planet
    [ a owl:Restriction ;
      owl:onProperty :orbits ;
      owl:hasValue :TheSun ]
  ) .
```

```turtle
:MajorLeagueBaseballPlayer a owl:Class ;
  owl:intersectionOf (
    :BaseballPlayer
    [ a owl:Restriction ;
      owl:onProperty :playsFor ;
      owl:someValuesFrom :MajorLeagueTeam ]
  ) .
```

첫 예는 :Planet 클래스와 "orbits 속성의 값으로 :TheSun을 가지는 제약"의 교집합이다. 둘째 예는 :BaseballPlayer 클래스와 "playsFor의 값 중 :MajorLeagueTeam에 속하는 것이 있는 제약"의 교집합이다. 교집합 목록에는 이름 있는 클래스와 대괄호로 쓴 이름 없는 제약을 함께 넣을 수 있다는 점을 눈여겨보자.

## 3. 예제 15: 우선순위가 높은 후보 질문

12장에서는 선택된 답변이 다음에 물을 수 있는 질문을 활성화하는 모델을 만들었다. 이번에는 집합 연산으로 이 모델에 질문의 우선순위를 결합한다. 목표는 "지금 물어볼 준비가 된 질문"이라는 클래스다. 이런 모델을 쓰는 애플리케이션은 지금까지의 답으로 활성화되었고 우선순위가 높은 질문만 물어본다.

먼저 12장의 정의를 다시 떠올린다. SelectedAnswer는 enablesCandidate 속성의 값이 모두 EnabledQuestion인 개체의 클래스에 포함된다.

```turtle
q:SelectedAnswer rdfs:subClassOf
  [ a owl:Restriction ;
    owl:onProperty q:enablesCandidate ;
    owl:allValuesFrom q:EnabledQuestion ] .
```

이제 후보 질문은 두 조건, 곧 활성화되어 있고 우선순위가 높다는 조건의 교집합으로 정의한다.

```turtle
q:CandidateQuestion owl:equivalentClass
  [ a owl:Class ;
    owl:intersectionOf
      ( q:EnabledQuestion q:HighPriorityQuestion )
  ] .
```

이 정의에서는 q:hasPriority 값이 q:High인 질문만 후보가 될 수 있다. 조건을 조금 느슨하게 해서 중간 우선순위 질문까지 후보에 넣고 싶다면 교집합 안에 합집합을 중첩하면 된다.

```turtle
q:CandidateQuestion owl:equivalentClass
  [ a owl:Class ;
    owl:intersectionOf
    ( q:EnabledQuestion
      [ a owl:Class ;
        owl:unionOf ( q:HighPriorityQuestion q:MediumPriorityQuestion ) ]
    )
  ] .
```

읽는 순서는 안쪽부터다. 안쪽 합집합이 "높음 또는 중간 우선순위 질문"을 만들고, 바깥 교집합이 여기에 "활성화된 질문" 조건을 더한다. 원서의 이 코드는 "a owl:Class ;" 없이 "a owl:intersectionOf"로 적혀 있는데, 오타로 보여 앞의 예와 같은 형태로 고쳐 적었다.

| 정의 | 후보가 되는 질문 |
|---|---|
| EnabledQuestion ∩ HighPriorityQuestion | 활성화된 질문 중 우선순위가 높은 것 |
| EnabledQuestion ∩ (High ∪ Medium) | 활성화된 질문 중 우선순위가 높거나 중간인 것 |

표처럼 같은 CandidateQuestion이라도 어떤 집합 연산으로 정의하느냐에 따라 범위가 달라진다. 정책이 바뀌면 정의 한 곳만 고치면 된다.
