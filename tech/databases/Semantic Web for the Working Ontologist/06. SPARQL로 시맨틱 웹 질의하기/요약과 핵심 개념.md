# 요약과 핵심 개념

6장은 RDF 데이터 그래프에서 정보를 꺼내는 질의 언어 SPARQL을 다뤘다. 이 문서는 장 전체를 한 번에 돌아보도록 요약하고, 원서가 정리한 핵심 개념을 표로 모은 뒤, 뒷부분에서 배운 질의 도구를 한눈에 비교한다.

---

## 1. 장 요약

SPARQL의 일꾼은 그래프 패턴이다. 그래프 패턴은 자원과 변수를 함께 담은 작은 그래프이며, 데이터 그래프에 맞춰 본다. 패턴은 어떤 정보를 가져올지, 그리고 변수에 매칭된 대상들이 서로 어떻게 연결되는지를 정한다.

SPARQL 질의는 두 가지 일에 쓰인다. 하나는 SQL처럼 정보를 가져오는 일이고, 다른 하나는 규칙처럼 그래프를 새로운 모양으로 바꾸는 일이다. 두 경우 모두 원하는 정보를 지정하는 방법은 같은 그래프 패턴이다. 가져오는 일은 주로 SELECT가, 바꾸는 일은 CONSTRUCT가 맡는다.

---

## 2. 핵심 개념

| 개념 | 한 줄 정의 |
|---|---|
| 그래프 패턴(graph pattern) | 와일드카드를 가진 그래프. 데이터 그래프에 맞춰 보고 원하는 결과를 지정한다 |
| 변수(variable, 질문 단어) | 그래프 패턴 속 와일드카드. 어떤 자원에도 매칭될 수 있다 |
| SELECT 질의 | 그래프에서 변수에 대한 바인딩(묶인 값)을 가져오는 질의 형태 |
| CONSTRUCT 질의 | 데이터 그래프의 매칭과 그래프 틀(template)로 새 그래프를 만드는 질의 형태 |
| 규칙으로서의 질의 | CONSTRUCT 질의로 규칙("이걸 보면 저걸 결론으로")을 표현하는 방식 |
| 연합 질의(federated query) | 하나의 질의로 여러 데이터 소스에 질의하는 방식 |

읽는 법: 앞의 세 가지(패턴, 변수, SELECT)는 가져오기의 기초고, CONSTRUCT와 규칙은 변환의 기초며, 연합 질의는 질의를 웹 규모로 넓히는 개념이다.

---

## 3. 장 후반에서 다룬 도구 한눈에 보기

| 하고 싶은 일 | 쓰는 도구 | 핵심 예 |
|---|---|---|
| 결론을 새 트리플로 만든다 | CONSTRUCT를 규칙으로 | 남자 자식을 hasSon으로, 삼촌 정의 |
| 제각각인 관계를 통일한다 | CONSTRUCT 여러 개(또는 UNION) | hasMother, hasFather, hasSon, hasDaughter를 hasParent로 |
| 몇 단계든 따라간다 | `*`, `+` (SPARQL 1.1) | Joe의 모든 후손 |
| 같은 대상을 기록한다 | CONSTRUCT와 skos:exactMatch | 감독 Clint Eastwood와 배우 Clint Eastwood |
| 군더더기를 걷어 낸다 | FILTER(`!=`, 사전순 비교) | 자기 자신과의 일치 제거 |
| 일부만 복사한다 | CONSTRUCT 세 가지 패턴 | Unforgiven의 주어, 목적어, 관련 대상 |
| 순서와 개수를 정한다 | ORDER BY, DESC, LIMIT | 가장 이른 James Dean 영화 |
| 요약값을 계산한다 | COUNT, MIN, MAX, AVG, SUM | 영화 편수, 전체 매출 |
| 그룹별로 나누고 거른다 | GROUP BY, HAVING | 연도별 회사별 매출, 5000 초과 |
| 독립된 부분을 비교한다 | 서브쿼리 | 2009년과 2010년 매출 비교 |
| 이거 또는 저거 | UNION | Giant 또는 Rebel의 배우 |
| 계산한 값을 변수에 둔다 | BIND, CONCAT | 전체 이름 만들기 |
| 질의에 값을 적는다 | VALUES | 저자 이름 세 쌍 |
| 원격 데이터와 묶는다 | SERVICE, GRAPH | DBpedia에서 배우의 본명 |

읽는 법: 왼쪽에 하고 싶은 일을 정하고 오른쪽 도구를 고르면 된다. 같은 일에도 여러 도구가 맞을 수 있다(예: hasParent 통일은 CONSTRUCT 네 개 또는 UNION 하나).

---

## 4. 헷갈리기 쉬운 쌍 비교

| 쌍 | 차이 |
|---|---|
| `*` 대 `+` | `*`는 0번 이상(자기 자신 포함), `+`는 1번 이상(자기 자신 제외) |
| FILTER 대 HAVING | FILTER는 패턴 안의 변수를, HAVING은 집계 결과를 거른다 |
| DISTINCT 대 FILTER(`!=`) | DISTINCT는 완전히 같은 결과 행의 중복을 없애고, `!=`는 값이 같은 매칭 자체를 걸러 낸다 |
| UNION 대 점(.)으로 잇기 | UNION은 OR, 점은 AND다 |
| SERVICE 대 GRAPH | SERVICE는 원격 엔드포인트, GRAPH는 이름 있는 그래프에 쓴다 |
| ORDER BY 없는 LIMIT 대 있는 LIMIT | 없으면 아무 n개, 있으면 정렬된 앞쪽 n개다 |
