# RDF 스키마

이 장은 RDF 데이터에 "의미"를 붙이는 언어인 RDFS를 다룬다. 스키마 언어가 원래 무슨 일을 하는지 XML, 관계형 DB, 객체지향과 견주어 본 뒤, RDFS의 클래스와 속성의 계층, domain과 range가 어떤 추론 규칙으로 정의되는지 차례로 익힌다. 이어서 하위 클래스와 하위 속성만으로 교집합과 합집합을 흉내 내는 패턴, 용어 조정과 데이터 연합, 쓰임새로 개체를 자동 분류하는 과제를 풀어 본다.

핵심 메시지는 RDFS가 데이터를 검사하는 울타리가 아니라 새 사실을 끌어내는 추론 규칙이라는 점이다. 그래서 domain과 range는 객체지향의 감각과 다르게 동작하고, 속성을 섣불리 합치면 뜻밖의 추론이 나온다. 이 장은 그런 함정과 피하는 방법까지 함께 정리한다.

---

## 1. 핵심 요점

- RDFS는 RDF의 스키마 언어이고, 스키마 정보도 전부 RDF 트리플로 적는다. 그래서 SPARQL 질의, SHACL 검증, 링크드 데이터 공개 같은 RDF 도구를 그대로 쓸 수 있다.
- RDFS 구성 요소의 의미는 추론으로 정해진다. "이런 트리플이 있으면 저런 트리플을 새로 만든다"가 곧 정의다.
- rdfs:subClassOf는 구성원 자격을, rdfs:subPropertyOf는 관계를 아래에서 위로 전파한다. 추론된 트리플도 다음 추론의 재료가 된다.
- rdfs:domain은 주어의, rdfs:range는 목적어의 rdf:type을 추론한다. 틀려 보이는 사용도 오류가 되지 않고 새 타입 정보가 된다.
- RDFS에는 교집합과 합집합 키워드가 없지만, 공통 하위 클래스와 공통 상위 클래스 패턴으로 한 방향 추론을 얻을 수 있다. 서로를 하위 클래스로 두면 동치가 된다.
- 속성 한 줄(subPropertyOf)로 구형 속성을 표준 속성에 맞추거나 rdfs:label로 연결할 수 있어서, 데이터 전체를 찾아 바꾸는 작업을 피한다.
- domain을 여러 번 선언하면 교집합처럼 동작하고, 서로 비슷한 두 속성을 맞물려 합치면 황당한 추론이 나온다. 합칠 때는 중립적인 제3의 속성을 쓴다.
- rdfs:label, rdfs:seeAlso, rdfs:isDefinedBy, rdfs:comment에는 추론 의미가 없고 사람과 도구를 위한 정보를 담는다.
