# 요약과 핵심 개념

이 문서는 8장 전체를 한 번에 돌아보는 정리다. RDFS가 무엇이고 어떻게 의미를 정하며, 어떤 구성 요소가 어떤 추론을 만드는지 표로 모아 둔다. 그리고 원서가 장 끝에서 강조하는 교훈, 곧 RDFS는 IF/THEN으로 정보를 흘려보내는 틀이고 합칠 때는 신중해야 한다는 점을 정리한다.

---

## 1. 8장 요약

- RDFS는 RDF의 스키마 언어다. 객체의 종류(클래스), 종류 사이의 관계(하위 클래스), 객체를 설명하는 속성, 속성 사이의 관계(하위 속성)를 다룬다.
- RDFS의 클래스 체계는 집합 포함에 기반한 단순하고 우아한 상속 개념을 가진다. 한 클래스가 다른 클래스의 하위 클래스라는 말은 앞 클래스의 인스턴스가 뒤 클래스의 인스턴스이기도 하다는 뜻이다.
- RDFS는 RDF 자체로 표현되기 때문에 RDF의 분산 성질과 모든 도구의 혜택을 받는다. 클래스, 하위 클래스, 하위 속성, domain, range 같은 스키마 정보가 전부 RDF 트리플이다. 그래서 스키마 정보도 데이터처럼 AAA 슬로건(누구나 어떤 주제에 대해서든 무엇이든 말할 수 있다)의 적용을 받는다. 스키마에 대해서도 누구든 말할 수 있다.
- RDFS의 의미는 추론으로 표현된다. 각 구성 요소의 의미는 거기서 나오는 추론이다. 하위 클래스와 하위 속성의 짧고 우아한 정의도 이 간단하고 강력한 방식 덕분이다.
- rdfs:domain과 rdfs:range는 속성과 클래스의 관계를 서술한다. 규칙은 아주 단순하지만 파급은 미묘하고 넓다. 규칙은 단순해도 주장은 강력하다.
- 구성 요소가 적고 규칙이 단순한데도 RDFS로 다양한 통합 문제를 풀 수 있다. 구조화된 데이터에서 전역 찾아 바꾸기를 하고 싶어질 때는 rdfs:subPropertyOf나 rdfs:subClassOf를 대신 고려해 보라는 것이 원서의 권고다.
- 여러 출처에서 온 개체를 합칠 때는 중요한 차이가 없는 것만 합쳐야 한다. 말은 당연해 보이지만, RDFS 추론 메커니즘을 쓰면 합쳤을 때 정확히 무슨 일이 생기는지 알아내어 결과가 바람직한지 위험한지 판단할 수 있다.
- RDFS에는 합집합이나 교집합 같은 논리 기본 요소가 없지만, subClassOf와 subPropertyOf의 특정 패턴으로 원하는 추론을 얻는 경우가 많다.
- RDFS는 정보가 흐르는 틀이다. subClassOf와 subPropertyOf는 시맨틱 모델링의 IF/THEN 장치라고 생각할 수 있다. 이 쓰임은 OWL로 넘어가도 이어지며, 실제로 이런 식의 subClassOf는 OWL 모델링의 초석이다.
- 신중하게 조합하면 RDFS의 구성 요소는 서로 다르게 구조화된 정보를 균일한 방식으로 함께 쓰는 방법을 정의하는 데 특히 효과적이다.

## 2. 핵심 개념 정리

원서가 8장에서 새로 소개했다고 꼽은 개념은 다음 네 가지다.

| 개념 | 원서의 설명을 풀어 쓴 뜻 |
|---|---|
| rdfs:subClassOf | 클래스 사이의 관계. 한 클래스의 구성원이 다른 클래스의 구성원에 포함된다 |
| rdfs:subPropertyOf | 속성 사이의 관계. 한 속성으로 이어진 쌍이 다른 속성으로 이어진 쌍에 포함된다 |
| rdfs:domain과 rdfs:range | 속성을 서술해 그 속성으로 이어진 개체들의 클래스 소속을 정하는 것 |
| RDFS의 논리 연산(합집합, 교집합 등) | RDFS 구성 요소로 집합과 속성의 어떤 논리적 조합을 흉내 낼 수 있다 |

## 3. 구성 요소와 추론 규칙 총정리

| 구성 요소 | 선언 모양 | 읽는 법 | 추론 규칙 |
|---|---|---|---|
| rdfs:Class | `:X rdf:type rdfs:Class` | X는 집합(클래스)이다 | 규칙 자체는 없고 클래스임을 밝힌다 |
| rdfs:subClassOf | `:C rdfs:subClassOf :D` | C의 구성원은 D의 구성원이다 | `?x rdf:type :C`이면 `?x rdf:type :D` |
| rdfs:subPropertyOf | `:q rdfs:subPropertyOf :r` | q로 이어진 쌍은 r로도 이어진다 | `?x :q ?y`이면 `?x :r ?y` |
| rdfs:domain | `:P rdfs:domain :D` | P를 쓰면 주어는 D의 구성원이다 | `?x :P ?y`이면 `?x rdf:type :D` |
| rdfs:range | `:P rdfs:range :R` | P를 쓰면 목적어는 R의 구성원이다 | `?x :P ?y`이면 `?y rdf:type :R` |
| domain과 subClassOf의 결합 | domain이 D이고 D가 C의 하위 클래스 | 상위 클래스도 domain이 된다 | `:P rdfs:domain :C`가 추론된다(range도 동일) |
| rdfs:label | `:X rdfs:label "이름"` | 출력용 이름 | 없음 |
| rdfs:seeAlso | `:X rdfs:seeAlso <URI>` | 보충 자료의 위치 | 없음 |
| rdfs:isDefinedBy | `:X rdfs:isDefinedBy <URI>` | 정의 자료의 위치 | seeAlso의 하위 속성 |
| rdfs:comment | `:X rdfs:comment "설명"@en` | 사람이 읽는 설명 | 없음 |

이 표의 규칙 열만 보면 RDFS의 전부가 나열된다. 추론 규칙은 세 줄 남짓이고, 나머지는 이 규칙들의 조합이다.

## 5. 꼭 기억할 주의점

- domain과 range는 검사가 아니라 추론이다. 틀려 보이는 사용도 오류가 되지 않고 새 타입이 된다.
- domain이 여러 개면 주어는 모두의 구성원이다. 합집합이 아니라 교집합처럼 동작한다.
- 비슷해 보인다는 이유로 속성을 서로 하위 속성으로 묶으면 domain과 range가 함께 작용해 황당한 추론이 나올 수 있다. 합칠 때는 중립적인 상위 속성을 쓰는 편이 안전하다.
- 교집합과 합집합은 한 방향만 흉내 낼 수 있다. 역방향이 필요하면 OWL을 써야 한다.
- 속성은 클래스에 소속되지 않는다. OOP의 상속 감각으로 domain을 읽으면 어긋난다.
- domain과 range는 지식 발견 도구이므로 필터링이나 분류 같은 분명한 의도가 있을 때 쓴다.
