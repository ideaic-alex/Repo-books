# 추론 없는 속성들

RDFS의 구성 요소가 모두 추론을 일으키는 것은 아니다. 몇몇 속성은 추론 의미가 아예 정해져 있지 않다. 그 속성에서 새 트리플이 나오지 않는다는 뜻이다. 그래도 쓸모는 있다. 사람이 읽을 이름을 붙이고, 참고 문서를 가리키고, 설명을 남기는 일은 모델이 다른 사람과 도구에게 읽히려면 꼭 필요하기 때문이다. 이 문서는 rdfs:label, rdfs:seeAlso, rdfs:isDefinedBy, rdfs:comment를 정리한다.

---

## 1. 의미는 없지만 관례는 있다

rdfs:label은 이미 앞에서 봤다. 이 속성에서는 어떤 추론도 나오지 않으므로 그런 뜻에서 의미(semantics)가 없다. 그렇지만 관례상 표시 에이전트가 모델과 상호작용하는 방식을 알려 주는 운영상의 의미는 있다. 화면에 이름을 보여 줄 때 label을 찾아 쓴다는 합의가 그것이다.

| 속성 | 용도 | 추론 의미 | 관례상의 동작 |
|---|---|---|---|
| rdfs:label | 리소스의 출력용 이름 | 없음 | 표시 엔진이 화면에 이름으로 보여 준다 |
| rdfs:seeAlso | 참고가 될 보충 자료 가리키기 | 없음 | 도구가 링크로 노출한다 |
| rdfs:isDefinedBy | 리소스를 정의한 원본 자료 가리키기 | seeAlso의 하위 속성이라는 선언만 있다 | 정의가 있는 곳을 알려 준다 |
| rdfs:comment | 사람이 읽을 설명 | 없음 | 문서화에 쓴다 |

표의 isDefinedBy가 유일하게 다른 속성과 맺은 정의상 관계(seeAlso의 하위 속성)를 가진다. 나머지는 추론 규칙이 붙어 있지 않다.

## 2. 참고 자료 연결 rdfs:seeAlso

시맨틱 웹 모델의 모든 리소스는 URI로 지정되고, 이 URI는 참조를 따라가 URL로 쓸 수 있다. 이 URL이 실제 문서로 연결된다면 리소스의 정의 정보를 거기 저장할 수 있다.

어떤 맥락에서는 리소스에 대한 보충 정보를 함께 두면 유용하다. 보통 그 개체를 설명하는 데 도움이 될 다른 문서를 말한다. 예를 들어 위키백과 항목을 가리키거나, 관련 데이터를 가리킬 수 있다. 그 리소스가 데이터베이스의 한 표에 해당한다면 보충 정보로 같은 데이터베이스의 다른 표를 가리킬 수도 있고, 관련 정보를 담은 다른 RDF나 RDFS 파일을 가리켜도 된다.

이런 경우를 위해 rdfs:seeAlso는 보충 정보의 웹 위치를 지정하는 방법을 제공한다. 값은 URI여야 하고 사람이 읽는 속성값(글)이 아니다. rdfs:seeAlso는 형식적인 의미가 없어서, 처리기가 이 속성을 만났을 때 정확히 어떻게 동작할지는 정해져 있지 않다. 일반적으로는 RDFS 문서를 쓰는 브라우저나 응용 화면에 이 링크를 보여 주는 동작이 흔하다.

## 3. 어휘를 정돈하는 rdfs:isDefinedBy

rdfs:seeAlso가 리소스의 보충 정보를 가리킨다면, rdfs:isDefinedBy는 그 리소스에 대한 일차 정보 출처를 가리킨다. 정의에 해당하는 설명을 어디서 찾을 수 있는지 모델러가 지정하게 해 준다. RDF 사양에서 rdfs:isDefinedBy는 rdfs:seeAlso의 하위 속성(rdfs:subPropertyOf)으로 정의되어 있다.

```turtle
rdfs:isDefinedBy rdfs:subPropertyOf rdfs:seeAlso .
```

앞서 본 하위 속성 규칙에 따라, isDefinedBy로 이어진 모든 쌍은 seeAlso로도 이어진다. 그러므로 "이 리소스의 정의가 여기 있다"고 적으면 "여기도 참고하라"는 사실이 함께 따라온다. 이 속성은 어휘를 정리해 둘 때 쓸모가 있다. 어떤 용어가 어느 어휘 문서에서 정의되었는지 용어마다 적어 둘 수 있다.

## 4. 모델 문서화 rdfs:comment

어떤 컴퓨터 언어(모델링 언어든 마크업 언어든 프로그래밍 언어든)에서나 그렇듯, 문서 작성자가 나중에 읽을 사람을 위해 자연어 주석을 남기면 도움이 된다. RDFS는 전부 RDF로 구현되므로 주석 기능도 RDF로 구현되어 있다. 모델의 일부에 주석을 달려면 rdfs:comment를 서술어로 하는 트리플을 하나 쓰면 된다.

좋은 습관은 데이터, 응용, 인터페이스의 다국어 지원을 위해 사용한 자연어도 함께 표시하는 것이다. 원서의 예는 영어와 프랑스어 두 가지로 달았다.

```turtle
sales:nextDeparture rdfs:comment
  "This indicates the next planned departure date for a salesperson."@en ,
  "Ceci indique la prochaine date de départ prévue pour un vendeur."@fr .
```

따옴표 뒤의 @en과 @fr는 언어 태그로, 같은 속성에 서로 다른 언어의 설명을 나란히 붙이는 방법이다. 원서에는 줄바꿈과 따옴표 일부가 추출 중에 깨져 있어서 문맥에 맞춰 복원했다.

| 질문 | 답 |
|---|---|
| 주석을 달 때 쓰는 서술어 | rdfs:comment |
| 언어를 구분하려면 | 문자열 뒤에 @en, @fr 같은 언어 태그를 붙인다 |
| 주석이 추론에 영향을 주는가 | 주지 않는다 |

## 5. 정리 표

| 하고 싶은 일 | 쓸 속성 | 값의 종류 |
|---|---|---|
| 화면에 사람이 읽을 이름을 보여 주고 싶다 | rdfs:label | 문자열 |
| 관련 문서나 보충 데이터를 가리키고 싶다 | rdfs:seeAlso | URI |
| 정의가 있는 원본 위치를 가리키고 싶다 | rdfs:isDefinedBy | URI |
| 모델에 설명을 남기고 싶다 | rdfs:comment | 문자열(언어 태그 권장) |

이 네 속성은 모델이 만들어 내는 새 사실이 아니라, 모델을 읽는 사람과 도구를 위한 정보다. 앞에서 본 과제 9처럼 rdfs:label은 다른 속성을 하위 속성으로 연결해 활용하는 경우도 많다.
