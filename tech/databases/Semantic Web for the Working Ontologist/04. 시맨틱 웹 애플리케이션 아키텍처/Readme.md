# 시맨틱 웹 애플리케이션 아키텍처

이 장은 시맨틱 웹 애플리케이션이 어떤 부품으로 이루어지고 어떻게 맞물려 돌아가는지를 큰 그림으로 보여 준다. RDF 파서와 시리얼라이저, RDF 스토어, 쿼리 엔진, 애플리케이션 코드를 차례로 살피고, 관계형 데이터베이스 기반 애플리케이션과 무엇이 같고 다른지 비교한다. 특정 제품은 다루지 않고 부품의 종류와 역할에 집중한다.

핵심 메시지는 두 가지다. 어떤 출처의 데이터든 트리플로 바꿔 한 스토어에 합친 뒤 질의하는 것이 RDF 애플리케이션의 기본 전략이고, 이 부품들은 의미 모델이 아니라 의미 모델을 올려 쓰기 위한 바탕이라는 점이다.

---

## 1. 핵심 요점

- 시맨틱 웹 애플리케이션은 RDF 파서/시리얼라이저, RDF 스토어, 쿼리 엔진, 애플리케이션, 추론 엔진으로 이루어진다.
- 관계형 DB 기반 애플리케이션과 대부분 대응하지만, 의미 변화 없이 옮길 수 있는 표준 직렬화는 RDF에만 있어서 스토어 간 이전이 쉽다.
- 파서는 파일을 트리플로 읽고 시리얼라이저는 트리플을 파일로 쓴다. 트리플에서 시작한 왕복은 같지만 파일에서 시작한 왕복은 글자 단위로 같지 않을 수 있다.
- 관계형 DB는 R2RML로, 웹 페이지는 Microdata, RDFa, JSON-LD로 RDF에 들여온다. 리치 스니펫이 대표적인 활용이다.
- RDF 스토어는 병합이 기본 기능이다. URI가 같은 자원은 병합 후 같은 것으로 취급한다.
- SPARQL 쿼리 엔진은 SQL과 달리 그래프 패턴을 기술하며, 엔드포인트로 웹 서비스가 될 수 있다.
- 원천을 먼저 합쳐 연합 그래프를 만든 뒤 질의하므로, 쿼리가 출처를 몰라도 되고 원천을 늘려도 쿼리를 고칠 필요가 없다.
- 부품은 의미 모델이 아니다. 의미 모델은 RDFS와 OWL로 만들어 스토어에 담고, 출처 사이의 의미 충돌을 풀어 주는 접착제 역할을 한다.
