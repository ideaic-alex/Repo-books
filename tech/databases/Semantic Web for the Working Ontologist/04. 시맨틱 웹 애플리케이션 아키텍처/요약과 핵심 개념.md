# 요약과 핵심 개념

이 문서는 4장의 마무리를 정리한다. 앞서 본 파서, 시리얼라이저, 스토어, 쿼리 엔진은 의미 모델 자체가 아니라 의미 모델을 만들고 쓰기 위한 부품이라는 것, 그리고 의미 모델이 이 구조 안에서 어디에 놓이는지를 설명한다. 이어서 이 장에서 소개한 핵심 개념을 표로 정리한다.

---

## 1. 부품은 의미 모델이 아니다

이 장에서 설명한 RDF 파서, 시리얼라이저, 스토어, 쿼리 엔진은 그 자체로 의미 모델이 아니다. 의미 모델을 포함할 시스템의 구성 요소일 뿐이다. 심지어 RDF로 표현된 정보도 반드시 의미 모델인 것은 아니다. 이들은 의미 모델을 만들고 쓰는 데 들어가는 빌딩 블록이다.

모델은 분명히 RDF로 표현된다. 앞으로 보겠지만 W3C의 의미 모델링 언어인 RDFS와 OWL은 전부 RDF 위에 만들어져 있어서, 다른 RDF 데이터처럼 연합할 수 있다.

---

## 2. 의미 모델은 어디에 들어가나

의미 모델은 그림 4.3의 애플리케이션 구조 안에서 어디에 놓일까. RDF로 표현된 데이터이므로 다른 데이터와 똑같이 RDF 스토어에 보관된다.

하지만 의미 모델은 쿼리에 답하는 데 쓰이는 데이터(셰익스피어가 쓴 희곡 목록, 종이 기계가 놓인 장소 등)를 담는 데서 그치지 않는다. 메타데이터, 즉 다른 데이터를 조직하는 데 도움을 주는 데이터도 담는다.

### 연합만으로는 의미 충돌이 풀리지 않는다

여러 출처의 정보를 연합할 때 RDF 데이터 모델은 모든 데이터를 하나의 균일한 방식으로 표현하게 해 준다. 그러나 출처 사이의 의미 충돌은 해결해 주지 않는다. 원서는 두 가지 질문을 던진다.

- 두 주(state)가 "결혼"을 같은 뜻으로 정의하는가?
- 희곡을 "쓴다"는 개념이 노래를 "쓴다"는 개념과 같은가?

이런 질문에 답을 주는 것이 의미 모델이다. 의미 모델은 흩어진 연합 데이터 원천 사이를 이어 주는 접착제 역할을 해서 서로 어떻게 맞물리는지를 기술하게 해 준다.

| 구분 | 데이터 모델(RDF) | 의미 모델 |
|---|---|---|
| 하는 일 | 모든 데이터를 하나의 균일한 방식으로 표현 | 출처 사이의 의미를 맞추고 연결 방법을 기술 |
| 의미 충돌 | 해결하지 않는다 | 답을 준다 |
| 담는 내용 | 질의의 대상이 되는 데이터 | 메타데이터를 포함한다 |

---

## 3. 모델에 대해서도 누구나 말할 수 있다

누구나 어떤 주제에 대해서든 무엇이든 말할 수 있듯이, 모델에 대해서도 누구나 무엇이든 말할 수 있다. 정보 원천 사이의 정의와 매핑에 누구나 기여할 수 있다는 뜻이다. 그래서 연합된 RDF 기반 시맨틱 애플리케이션은 정보를 여러 곳에서 얻을 뿐 아니라 여러 출처의 정보를 어떻게 합칠지에 대한 지침까지 여러 곳에서 얻을 수 있다.

이런 의미에서 시맨틱 웹은 진정한 의미의 웹, 즉 웹의 정보가 무엇을 뜻하는지를 여러 출처가 설명하는 웹이다.

## 4. 핵심 개념 정리

| 개념 | 설명 |
|---|---|
| RDF parser/serializer | 여러 파일 형식 중 하나로 RDF를 읽고 쓰는 시스템 구성 요소 |
| RDF store | RDF로 일하는 데이터베이스. 주요 연산 하나가 RDF 그래프의 병합이다 |
| RDF query engine | SQL 엔진이 관계형 저장소에 접근하게 해 주듯 RDF 스토어에 접근하게 해 준다 |
| SPARQL | RDF를 위한 W3C 표준 쿼리 언어 |
| SPARQL endpoint | SPARQL 쿼리에 답할 수 있는 애플리케이션. 정보의 원래 인코딩이 RDF가 아닌 경우도 포함한다 |
| Application interface | RDF 스토어의 내용을 어떤 사용자와의 상호작용에 쓰는 애플리케이션의 부분 |
| Converter | 어떤 형태(예: 표)의 데이터를 RDF로 바꾸는 도구 |
| RDFa | HTML 페이지에서 RDF 메타데이터를 인코딩하고 가져오기 위한 표준 |

이 표는 이 장 끝의 핵심 개념 목록을 한국어로 다시 구성한 것이다. 이 장 본문에서 함께 나온 R2RML, 리치 스니펫, 연합 그래프, Microdata, JSON-LD도 함께 기억해 두면 좋다.

---

## 5. 한눈에 보는 4장

| 질문 | 답 |
|---|---|
| 트리플은 어디서 오나 | RDF 파일, 관계형 데이터베이스(R2RML), 웹 페이지(Microdata, RDFa, JSON-LD) |
| 어디에 저장하나 | RDF 스토어. 병합이 기본 기능이다 |
| 어떻게 꺼내나 | SPARQL 쿼리 엔진. 엔드포인트로 웹 서비스도 가능하다 |
| 데이터를 어떻게 합치나 | 먼저 하나의 스토어로 병합하고, 합쳐진 연합 그래프에 질의한다 |
| 의미는 누가 맞추나 | RDFS와 OWL로 만든 의미 모델이 접착제 역할을 한다 |
